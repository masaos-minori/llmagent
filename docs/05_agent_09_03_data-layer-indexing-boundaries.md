# Agent Data Layer

- State and Persistence → [05_agent_04_01_state-and-persistence-state-model.md](05_agent_04_01_state-and-persistence-state-model.md)

## Purpose

Documents the Context Manager pattern for DB access, FTS5 indexing, and the role of the Workflow SQLite database.

## Design Intent

### Context Manager Pattern for DB Access

`SQLiteHelper` (used throughout the Agent/RAG layers):

```python
with SQLiteHelper().open(write_mode=True, row_factory=True) as db:
    db.execute(...)
```

- `write_mode=True` → Enables WAL mode + Foreign Keys.
- `row_factory=True` → Enables column-based access (`row["column"]`).
- Opens per query (not a connection pool). `DB_PATH` and `SQLITE_VEC_SO` are lazily initialized.

### FTS5 Indexing

The FTS5 virtual table `chunks_fts` in `rag.sqlite` is synchronized via triggers:
- `chunks_ai` (after INSERT): Inserts into `chunks_fts(COALESCE(normalized_content, content))`.
- `chunks_au` (after UPDATE): Delete + Re-insert.
- `chunks_ad` (after DELETE): Deletes from `chunks_fts`.

`/session rag-rebuild-fts` rebuilds the FTS5 index from the `chunks` data. Use this if `SELECT COUNT(*) FROM chunks_fts` ≠ `SELECT COUNT(*) FROM chunks`.

### Workflow SQLite (`workflow.sqlite`)

Managed by `agent/workflow/state_store.py`:

| Table | Contents |
|---|---|
| `tasks` | One row per turn attempt |
| `attempts` | Retry attempts within a task |
| `processed_events` | Idempotency enforcement |
| `approvals` | Post-execution approval records |
| `artifacts` | URIs generated by stage callbacks |

**Design judgment:** Used if `config/workflows/default.json` exists. If it does not exist, startup fails (Workflows are mandatory).

### Non-Message Persistence Boundaries

| Store | Role | Visible to LLM? | Contents |
|---|---|---|---|
| `messages` | Conversation history (Source of Truth) | Yes | Message sequence passed to LLM |
| `session_diagnostics` | Diagnostic events only | No | LLM transfer errors, guard hints |
| `workflow.artifacts` | Workflow artifact references | No | URIs generated by workflow stage callbacks |
| `audit.log` | Operational trace | No | Audit events in JSONL format |

**Design judgment:** Using `messages` for purposes other than the conversation flow visible to the LLM is prohibited — diagnostic, artifact, and audit data belong to the non-message stores listed above.

## Responsibility Boundary

- **Canonical Source**: `shared/sqlite_helper.py` (`SQLiteHelper`), `agent/workflow/state_store.py` (`StateStore`)
- **Schema**: `schema_sql.py` (authority)

## Key Constraints

- Valid roles for the `messages` table: `user` / `assistant` / `tool` / `system` — `diagnostic` is **NOT** valid.
- Using `messages` for purposes other than the conversation flow visible to the LLM is prohibited.
- `workflow.sqlite` is mandatory for workflows — startup fails if the configuration file is missing.
