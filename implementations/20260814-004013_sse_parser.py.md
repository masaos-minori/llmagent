# Implementation Procedure: sse_parser.py

## Goal
Close two small correctness/robustness gaps in `RobustSSEParser` (`scripts/shared/sse_parser.py`):
narrow `_is_valid_json`'s overly broad except clause to `except ValueError:`, and add
constructor-time validation to `RobustSSEParser.__init__` that rejects negative
`malformed_retry` / `heartbeat_timeout` values.

## Scope
In scope:
- `_is_valid_json` (line 89): narrow `except (orjson.JSONDecodeError, ValueError):` to
  `except ValueError:`.
- `RobustSSEParser.__init__` (before the existing `self._decoder = ...` assignment on line 29):
  add `>= 0` validation for `malformed_retry` and `heartbeat_timeout`, raising `ValueError` on
  violation.

Out of scope:
- `_parse_line`, `feed`, `check_heartbeat`, `_is_keepalive`, `_mark_activity`, `_anext_or_done`,
  or any SSE frame-parsing / heartbeat-timing / malformed-budget behavior beyond the two items
  above.
- `scripts/agent/services/config_reload.py` (`_apply_sse_reload_params`) — read-only reference
  only; not modified.
- `scripts/agent/config_dataclasses.py` / `scripts/agent/services/config_validators.py` — not
  modified.

## Assumptions
- `orjson.JSONDecodeError` is a subclass of `ValueError` in the currently pinned orjson version
  (`orjson.JSONDecodeError.__mro__` includes `ValueError`), so narrowing the except clause is
  behavior-neutral for the currently pinned dependency version.
- Zero is a valid boundary for both `malformed_retry` and `heartbeat_timeout`, matching
  `config_validators.py`'s existing `>= 0` boundary (see `validate_llm_sse_heartbeat_timeout`,
  `validate_llm_sse_malformed_retry` in `scripts/agent/services/config_validators.py:71-84`) and
  `check_heartbeat`'s own `<= 0` short-circuit for `heartbeat_timeout`.
- No current call site passes a negative value today (sole production caller:
  `scripts/shared/llm_sse_stream.py:65`, values sourced from `LLMConfig`), so the new validation
  is additive-only.

## Design decisions
- Message convention `f"{param} must be >= 0, got {value}"` matches the existing pattern in
  `scripts/agent/services/config_validators.py` (e.g. line 75:
  `f"sse_heartbeat_timeout must be >= 0, got {cfg.sse_heartbeat_timeout}"`), so the new
  constructor guard reads as a consistent belt-and-suspenders pair rather than a new convention.
- The constructor check is placed at the very top of `__init__`, before any state assignment, so
  a rejected construction leaves no partially-initialized instance.
- The check validates at parser-construction time, covering the hot-reload path
  (`config_reload.py::_apply_sse_reload_params` mutates `ctx.cfg.llm.*` directly without
  re-running `LLMConfig.__post_init__`), which the config-layer validators cannot cover.

## Compatibility considerations
- Both edits are behavior-neutral for all currently exercised call sites: no production or test
  call site passes a negative `malformed_retry`/`heartbeat_timeout` today, and the except-clause
  narrowing catches an identical exception set given the currently pinned orjson version's MRO.
- Reverting the two edits alone (this file only) fully restores prior behavior; no other file
  needs to change for a revert.

## Security considerations
- The constructor guard closes a validation gap on the hot-reload path
  (`config_reload.py::_apply_sse_reload_params`), which could otherwise write negative
  `sse_heartbeat_timeout`/`sse_malformed_retry` values into `ctx.cfg.llm.*` bypassing
  `LLMConfig.__post_init__`'s validators. Rejecting at parser-construction time turns a silently
  accepted bad value into an explicit `ValueError` at `stream_once` construction time.
- No new external input handling, no new I/O, no new dependency surface.

## Rollback considerations
- Revert is a single-file, two-hunk change; no data migration, no config schema change, no
  deploy.sh change (per plan, `scripts/` is deployed as a whole-directory `cp -r`, not a
  per-file list, so no deploy script edit is needed either way).
