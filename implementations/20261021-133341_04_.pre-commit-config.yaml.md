## Goal
Add a pre-commit hook that runs `tools/check_metadata_field_policy.py` (GV-016) when the owner decides to automate the check via pre-commit.

## Scope
- Add exactly one hook entry to `.pre-commit-config.yaml` that runs `check_metadata_field_policy.py`.
- Set the gate (warning vs blocking) per the owner's decision.
- Do not modify any existing hook, the hook ordering, or files outside `.pre-commit-config.yaml`.

## Assumptions
- The owner's trigger + gate decision is recorded before this executes (Plan REQ-001); this procedure documents the warning-automation and blocking-automation branches.
- The live corpus has 0 findings, so a new hook will not fail on existing content.
- If the owner does NOT choose pre-commit automation, this file is not modified (the routing.md row or keep-manual state covers the trigger).

## Design decisions
- Add one hook; do not reorder or alter existing hooks.
- Prefer the warning (non-blocking) path: the checker is report-only by default and always exits 0 on warnings, so a warning hook needs no tool change.
- A blocking hook requires `--strict`, which the checker does not implement (registers only `--root`; unknown flags exit 2) and which needs explicit owner sign-off per `rules/coding.md` before any hook depends on it.

## Alternatives considered
- Inferring the owner's decision and wiring a hook: rejected, REQ-001 makes the recorded decision a hard gate.
