# Implementation procedure: scripts/agent/tool_runner.py

## Goal

Wire the existing, currently-dead `validate_tool_arguments()` (in
`scripts/agent/tool_arg_validator.py`) into `execute_one_tool_call()` so every tool
call is schema-validated against its `RuntimeTool.input_schema` immediately after JSON
parsing and before dispatch (gateway or direct executor), with lenient fallback
preserved when no registry/tool/schema is available. Includes the companion test
fixture fixes and new gateway-path test needed to land this safely.

## Scope

- In scope:
  - `scripts/agent/tool_runner.py::execute_one_tool_call()` — add a validation step
    between `orjson.loads()` and the dispatch `if/else`.
  - New private helper `_validate_tool_args()` in the same file.
  - `tests/test_tool_runner.py::_make_ctx()` — add
    `ctx.services_required.runtime_tools = None` baseline default.
  - `tests/test_tool_approval_preflight.py::_make_ctx()` — same fixture fix.
  - One new test exercising the gateway/write dispatch path (validation rejection must
    prevent `gateway.execute()` from being called).
- Out of scope (per plan):
  - Any change to `scripts/agent/repository_gateway.py::_gate_write()`'s
    policy/approval logic.
  - Any change to `scripts/agent/tool_arg_validator.py`'s validation logic itself
    (already correct, covered by `tests/test_tool_arg_validator.py`).
  - Any change to `RuntimeToolRegistry` wiring/population (`agent/startup.py`,
    `McpToolDiscoveryService`).

## Assumptions

- `ctx.services_required.runtime_tools: RuntimeToolRegistry | None` is the sole source
  of per-tool `input_schema` (per plan Assumption 1, confirmed against
  `agent/startup.py:293`).
- `RuntimeToolRegistry.get(name)` raises `KeyError` for unregistered names (confirmed,
  `scripts/shared/runtime_tool_registry.py:87-97`); this is the sole exception type to
  catch as "fall through to lenient behavior."
- `tests/test_tool_runner.py::TestExecuteOneToolCallValidation` (lines 693-854) already
  exists in the test file as a pre-written, currently-failing acceptance spec for this
  exact feature (verified: the file's `_make_ctx()` at line 70-90 does not set
  `runtime_tools`, and the new test class explicitly sets
  `ctx.services_required.runtime_tools = MagicMock()` / `= None` per test, confirmed by
  grep at lines 707/721/725/742/743/764/790/816/842/843). Implementation must satisfy
  this class's exact expectations rather than redesigning the contract.
- `ToolCallResult` (defined in `scripts/shared/transport_dto.py:8-16`) has fields
  `output, is_error, request_id, server_key, source="", error_type=""` — matches the
  synthetic result construction needed for a validation rejection.
- Current `execute_one_tool_call()` (lines 113-165) has no import of
  `validate_tool_arguments` or `ToolCallResult` yet; both need adding.

## Design decisions

- Validation runs once, before the existing `if ctx.services_required.gateway is not
  None: ... else: ...` dispatch block (currently lines 138-141) — not duplicated into
  each branch, and not pushed into `repository_gateway.py` (explicitly forbidden by the
  plan/requirement — keeps validation a single chokepoint in `tool_runner.py`).
- New `_validate_tool_args(ctx, name, args) -> ToolCallResult | None` helper:
  returns `None` for every lenient-fallback case (no registry, tool not found via
  `KeyError`, schema absent/passes), and a synthetic error `ToolCallResult` only on an
  actual validation failure.
- Set `source="validation"` (non-empty) on the synthetic rejection `ToolCallResult` so
  `audit_tool_exec()`'s early-return guard (`if not mcp_request_id and not source:
  return`, `scripts/agent/tool_audit.py:172-173`) does not suppress the audit event for
  a rejected call. Set `error_type="validation"` to distinguish from `"transport"`/`"tool"`.
  This lets the synthetic result flow through the rest of the unchanged function body
  (audit call, transport-diagnostics branch — skipped since `error_type != "transport"`
  — and `llm_text` truncation) with no other special-casing needed.
- Only `except KeyError` around `registry.get(name)` — no broad `except Exception` —
  matching `RuntimeToolRegistry.get()`'s documented contract and the pre-written test
  `test_validation_passes_for_unknown_tool`.
- Import `validate_tool_arguments` as a normal top-of-file import (not a deferred/local
  import): `tool_arg_validator.py` has no `agent`-layer imports (only
  `jsonschema`/`logging`), so no circular-import risk exists, unlike the deferred-import
  pattern already used elsewhere in this file for `agent.tool_approval`.

## Alternatives considered

- Validating inside each dispatch branch separately (gateway vs. direct executor):
  rejected — duplicates logic and risks the two branches drifting; a single
  pre-dispatch check is simpler and matches the plan's explicit design.
- Raising an exception from `_validate_tool_args()` on failure instead of returning a
  synthetic `ToolCallResult`: rejected — would require a new exception type and a new
  catch site, and would not naturally flow through the existing audit/truncation code
  path the way a `ToolCallResult` does; also would diverge from the pre-written
  acceptance test's expectations (tests assert on returned tuple contents, not a raised
  exception).
- Widening `_check_type_validation()` in `tool_arg_validator.py` to also catch
  `jsonschema.SchemaError` as part of this change: rejected — `tool_arg_validator.py`
  internals are explicitly out of scope per the plan; flagged only as a residual risk
  for a future follow-up.

2. **Add imports to `tool_runner.py`**: `from agent.tool_arg_validator import
   validate_tool_arguments` and `from shared.transport_dto import ToolCallResult` (verify
   `ToolCallResult` is not already imported under a different alias before adding).
3. **Add `_validate_tool_args()` helper** (new, private, placed near
   `execute_one_tool_call()`, e.g. directly above it):
   ```python
   def _validate_tool_args(ctx: AgentContext, name: str, args: dict) -> ToolCallResult | None:
       registry = ctx.services_required.runtime_tools
       if registry is None:
           return None
       try:
           runtime_tool = registry.get(name)
       except KeyError:
           return None
       result = validate_tool_arguments(
           tool_name=name,
           args=args,
           input_schema=runtime_tool.input_schema,
           allow_extra_fields=runtime_tool.allow_extra_fields,
       )
       if result.success:
           return None
       logger.warning("tool_arg_validation_rejected tool=%r reason=%s", name, result.reason)
       return ToolCallResult(
           output=result.reason,
           is_error=True,
           request_id="",
           server_key="",
           source="validation",
           error_type="validation",
       )
   ```
4. **Insert the call in `execute_one_tool_call()`** between the existing
   `orjson.loads()` try/except (lines 131-136) and the dispatch `if/else` (lines
   138-141):
   ```python
   validation_error = _validate_tool_args(ctx, name, args)
   if validation_error is not None:
       result = validation_error
   elif ctx.services_required.gateway is not None:
       result = await ctx.services_required.gateway.execute(ctx, name, args)
   else:
       result = await ctx.services_required.tools.execute(name, args)
   ```
   The rest of the function (lines 142-165: `text, is_error, x_request_id = ...`,
   `audit_tool_exec(...)`, transport-diagnostics branch, `llm_text` truncation, return)
   stays unchanged.

## Compatibility considerations

- Fully backward compatible for any caller where `ctx.services_required.runtime_tools`
  is `None` (the production default until `RuntimeToolRegistry` is wired) — validation
  is a no-op, identical to current behavior.
- No change to `execute_all_tool_calls()`'s public signature or to any of its three
  internal callers (`_run_group_calls()`, `_execute_with_dag()`, `_execute_standard()`).
- No change to `audit_tool_exec()`'s signature.

## Security considerations

- This wiring makes schema validation an actual enforcement point for the first time
  (previously dead code) — tightens security posture by rejecting malformed/extra-field
  tool-call arguments before they reach any executor or gateway, for any tool that has a
  registered schema.
- Residual risk (documented, not fixed here per scope): a structurally invalid schema
  from an MCP server would raise `jsonschema.SchemaError`, which
  `_check_type_validation()` does not catch — this would propagate uncaught through
  `_validate_tool_args()`. Out of scope for this file per the plan (belongs to
  `tool_arg_validator.py`, untouched); flagged for a possible follow-up.

## Rollback considerations

- Single function change plus one new helper, gated entirely behind
  `ctx.services_required.runtime_tools is None` short-circuiting to `None` (no-op).
  Revert is a straightforward removal of the helper, the two new imports, and the
  inserted `validation_error = ...` line, restoring the original `if/else` dispatch.
- Test fixture changes (`runtime_tools = None`) are safe to leave in place even if the
  production wiring is reverted (they only affect an attribute the reverted code no
  longer reads).
