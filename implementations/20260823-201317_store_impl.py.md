## Goal

In `scripts/db/store_impl.py`: add a mandatory `chunking_strategy: str` parameter
to `SQLiteDocumentStore.doc_upsert()`, alongside the `fetched_at: str` parameter
that the prerequisite plan `plans/20260820-095054_plan.md` adds to the same
method, so that both columns are supplied explicitly by the caller on every
call — INSERT and ON CONFLICT branches alike — with no database-level
`DEFAULT` fallback and no internally-computed value.

## Scope

- In scope: `scripts/db/store_impl.py`'s `SQLiteDocumentStore.doc_upsert()`
  method — signature and SQL body only.
- Out of scope: `scripts/db/store_protocols.py`'s `DocumentStore.doc_upsert()`
  Protocol declaration (see Risks/Compatibility below — this file is not in
  this plan's Related target files list even though it is affected in
  practice). Out of scope: `tests/db/test_db_store_impl.py`'s call sites
  (companion plan's own target file, not one of the two files assigned to
  this document).
- Out of scope: `doc_get()`, `doc_list()`, `doc_delete()`, `chunk_insert()`,
  `chunk_count()`, `_row_to_document()` — none of these construct or bind
  `chunking_strategy`; they read/write unrelated columns.

## Assumptions

- **Current state, confirmed by reading the file at authoring time**:
  `doc_upsert(self, url: str, title: str | None, lang: str, etag: str | None,
  last_modified: str | None) -> int` — no `fetched_at`/`chunking_strategy`
  parameters exist yet; the `INSERT` omits both columns; the `ON CONFLICT`
  branch recomputes `fetched_at = strftime('%Y-%m-%dT%H:%M:%SZ', 'now')`.
  This is the pre-dependency shape, not the shape this document's procedure
  actually starts from (see next bullet).
- **Sequencing dependency (plan's own Assumptions section)**: this plan's
  `store_impl.py` change must land after `plans/20260820-095054_plan.md`,
  which adds a mandatory `fetched_at: str` parameter to this same method
  (INSERT column + `ON CONFLICT ... fetched_at = excluded.fetched_at`,
  removing the `strftime` recompute entirely — confirmed by reading that
  plan's own implementation document,
  `implementations/20260823-200056_store_impl.py.md`). This document's
  procedure therefore assumes `doc_upsert()` already has `fetched_at`
  wired this way by the time this document's steps execute; it only adds
  `chunking_strategy` on top. Falsifiable: re-check `doc_upsert()`'s
  signature for `fetched_at` before starting; if it is still absent, the
  095054 dependency has not landed and this document's Phase-2 step is
  blocked (per the plan's own Phase 3 precedent for its ingester.py work).
- **UNK-02 resolution (given premise for this task)**: both `fetched_at`
  and `chunking_strategy` are caller-supplied, mandatory, with no internal
  `datetime.now()`/`strftime('now')` computation inside `doc_upsert()`.
  This supersedes a stray phrase in the plan's Design step 6 ("the ON
  CONFLICT branch keeps its existing `fetched_at = strftime(...)`
  recompute-on-update behavior") — that phrase describes the
  pre-095054 code shape and is inconsistent with both UNK-02's resolution
  and the already-written 095054 implementation document's
  `fetched_at = excluded.fetched_at`. Treated here as a plan-internal
  drift, resolved in favor of UNK-02 + the sequencing dependency, not the
  literal Design-step-6 sentence.
- `chunking_strategy`'s `ON CONFLICT` behavior is `chunking_strategy =
  excluded.chunking_strategy` (overwrite with caller-supplied value) —
  this is the plan's own "Gap found during implementation-procedure
  review" resolution in Design step 6, stated as final (not a fallback).
- Zero production callers of `doc_upsert()` today (plan's Affected areas
  table, consistent with the sibling 095054 document) — only
  `tests/db/test_db_store_impl.py` exercises it, and that file is a
  separate target of the companion plan, not this document.

## Design decisions

- Add `chunking_strategy: str` as a new mandatory parameter (no default),
  positioned immediately after `fetched_at` in the parameter list — mirrors
  `schema_sql.py`'s `documents` table column order (`... fetched_at, etag,
  last_modified, chunking_strategy`) is not followed literally for
  parameter order since `etag`/`last_modified` are already earlier in the
  existing signature; instead `chunking_strategy` is appended last,
  immediately after `fetched_at`, keeping the two new caller-supplied,
  no-default parameters grouped together at the end of the signature. Exact
  position must still be cross-checked against whatever
  `store_protocols.py`'s Protocol declares once that file is next edited
  (see Risks) — this is a documented open dependency, not a resolved one.
- INSERT column list gains `chunking_strategy`; bound as a plain `?`
  parameter, same trust boundary as every other bound value in this query.
- `ON CONFLICT` gains `chunking_strategy = excluded.chunking_strategy`,
  following the same `excluded.<column>` pattern already used for `title`,
  `lang`, `etag`, `last_modified` (and, per the sequencing dependency,
  `fetched_at`) in this method — no special-casing, per the plan's Design
  step 6 reasoning ("`chunking_strategy` is not a 'first-seen' timestamp
  like `fetched_at`").

## Alternatives considered

- Keep the pre-dependency `fetched_at = strftime(...)` recompute-on-update
  behavior literally as Design step 6's prose states, and only add
  `chunking_strategy` — rejected: contradicts UNK-02's resolution (caller-
  supplied, no internal `datetime.now()`) and would silently reintroduce a
  non-canonical `fetched_at` on every re-upsert immediately after the
  095054 dependency removed that exact behavior; the two plans' target
  files must be describing one consistent end state, not two.
- Give `chunking_strategy` an in-Python fallback default (e.g. `"text"`,
  matching `schema_sql.py`'s current `DEFAULT 'text'`) instead of a
  mandatory parameter — rejected: this plan removes the DDL `DEFAULT`
  clause for `chunking_strategy` in `scripts/db/schema_sql.py` in the same
  change set, so neither the DB nor the caller would have a fallback;
  UNK-02 explicitly resolves this as caller-supplied.
- Bind `chunking_strategy` via a duplicated `?` placeholder in the `ON
  CONFLICT` clause instead of `excluded.chunking_strategy` — functionally
  equivalent in SQLite; rejected for style consistency with the four (soon
  five) sibling columns already written as `excluded.<column>` in this
  method.

## Implementation

### Target file

`scripts/db/store_impl.py`

### Procedure

1. Before editing, verify `doc_upsert()` already has the `fetched_at: str`
   parameter and `fetched_at = excluded.fetched_at` wired per the 095054
   dependency (Assumptions above). If not yet landed, stop — this
   document's diff is not applicable to the pre-dependency shape.
2. Add `chunking_strategy: str,` to `doc_upsert()`'s signature, positioned
   immediately after `fetched_at`.
3. In the `INSERT INTO documents (...)` column list, append
   `chunking_strategy`; add a matching `?` placeholder to `VALUES (...)`;
   append `chunking_strategy` to the bound parameter tuple in the same
   position.
4. In the `ON CONFLICT(url) DO UPDATE SET` clause, append a line
   `chunking_strategy = excluded.chunking_strategy` after the
   `fetched_at = excluded.fetched_at` line (or wherever the 095054 change
   places it).
5. Leave `RETURNING doc_id`, the `cur.fetchone()` guard, and the
   `RuntimeError` on a missing row unchanged.

### Method

Direct signature and SQL-string edit; no new imports required.

### Details

- After the edit, `rg -n "strftime" scripts/db/store_impl.py` must return
  zero matches for the `documents` table's `fetched_at`/`chunking_strategy`
  handling (the plan's Phase 5 verification pattern extends to this file).
- Because `scripts/db/schema_sql.py`'s `documents.chunking_strategy`
  column is losing its `DEFAULT 'text'` clause (companion change in this
  same plan, different target file), `doc_upsert()`'s `INSERT` has no
  DB-level fallback for either new column after this change lands — every
  caller must supply non-empty `fetched_at` and `chunking_strategy` strings
  or the statement raises `sqlite3.IntegrityError` (`NOT NULL constraint
  failed`).
- **Compatibility gap not covered by this plan's file list**:
  `scripts/db/store_protocols.py`'s `DocumentStore.doc_upsert()` Protocol
  (confirmed by direct read) declares only `url, title, lang, etag,
  last_modified` — it does not yet declare `fetched_at` even after the
  095054 dependency (that plan's own `implementations/
  20260823-200056_store_protocols.py.md` document is presumably where
  `fetched_at` gets added to the Protocol, but this was not verified as
  part of this document's scope). This plan (`20260820-095542_plan.md`)
  does not list `scripts/db/store_protocols.py` in its Related target
  files at all, so `chunking_strategy` has no assigned home in the
  Protocol. Implementing this document's change alone will make
  `SQLiteDocumentStore` structurally non-conforming to `DocumentStore` for
  any code that type-checks against the Protocol (an extra required
  positional parameter the Protocol does not declare). Flagged for the
  implementer to escalate — either treat `store_protocols.py` as an
  implied companion edit outside this plan's stated scope, or confirm via
  `uv run mypy scripts/` that no call site actually depends on structural
  conformance at the Protocol type (only concrete calls through
  `SQLiteDocumentStore` directly).

## Rollback considerations

- Revert this file's diff independently of `schema_sql.py`'s `DEFAULT`
  removal is possible in principle, but doing so leaves `doc_upsert()`
  supplying a `chunking_strategy` value while the DDL still silently
  defaults it — not harmful, just redundant. Reverting `schema_sql.py`'s
  `DEFAULT` removal while keeping this file's mandatory parameter is safe
  (caller still always supplies a value).
- Reverting this file alone while `store_protocols.py`'s Protocol (if ever
  updated for `chunking_strategy`) still declares it mandatory would leave
  a structural-typing mismatch `mypy` would flag, not a runtime failure.
- No data migration is implied — this file makes no schema change on its
  own.
