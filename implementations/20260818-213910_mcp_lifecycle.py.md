## Goal

Standardize MCP server lifecycle definitions across the project and automate the generation of the active MCP service inventory to eliminate information drift between documentation and actual configuration.

## Scope

**In-Scope:**
- Formally define the three startup modes (`none`, `persistent`, `subprocess`) including their properties (ownership, health checks, tool discovery, routing, etc.).
- Reconcile all existing documentation to use these standardized definitions.
- Implement an automation mechanism to generate the active MCP service inventory from the current configuration.
- Integrate stale-output detection into the CI pipeline to detect outdated generated documentation.
- Replace all manual service value tables with the generated output.

**Out-of-Scope:**
- Changes to MCP server implementations themselves (only documentation/lifecycle).
- Changes to the `StartupMode` enum definition (already exists in `mcp_config.py:33-38`).
- Changes to the `McpServerConfig` dataclass (already exists in `mcp_config.py:48-59`).

## Assumptions

- The `StartupMode` enum already defines the three modes correctly (verify enum values match documented behavior).
- The `McpServerConfig` dataclass captures all necessary lifecycle metadata (check if additional fields like health_check_url are needed).
- The automation should read from the same config sources that the runtime uses (verify config loading paths).
- CI integration should flag stale output but not block builds (determine if blocking is appropriate based on team workflow).

## Design decisions

- Add lifecycle property methods to `StartupMode` enum and `McpServerConfig` dataclass — provides a clean API for querying lifecycle state without relying on string comparisons.
- Generate inventory as Markdown table — matches existing documentation format and is human-readable.
- Use timestamp-based comparison for CI stale-output detection — avoids false positives from content diffs during normal development.
- Keep original attributes accessible — prevents breaking existing code that relies on direct attribute access.

## Alternatives considered

- Modify `StartupMode` enum to include lifecycle properties — rejected because enums don't support mutable state well; adding methods is cleaner.
- Generate inventory as YAML/JSON — rejected because Markdown tables are more readable in documentation.
- Block CI on stale output — rejected because stale docs are not critical path; warning is sufficient.
- Make automation a CLI tool only — rejected because CI integration ensures freshness automatically.

### Method

Part C — Inventory generation script:

```python
#!/usr/bin/env python3
"""Generate the active MCP service inventory from current configuration."""

import sys
from pathlib import Path

# Add scripts to path for imports
sys.path.insert(0, str(Path(__file__).parent.parent / "scripts"))

from shared.mcp_config import StartupMode, McpServerConfig
from shared.config_loader import load_mcp_configs

def generate_inventory() -> str:
    """Generate Markdown table of active MCP services."""
    configs = load_mcp_configs()
    
    lines = [
        "| Server | Mode | Disabled | Health Check | Command |",
        "|--------|------|----------|--------------|---------|",
    ]
    
    for config in configs:
        lines.append(
            f"| {config.name} | {config.startup_mode.value} | "
            f"{config.is_disabled} | {config.needs_health_check} | "
            f"`{' '.join(config.command)}` |"
        )
    
    return "\n".join(lines)

if __name__ == "__main__":
    print(generate_inventory())
```

### Details

- Script reads from the same config sources the runtime uses — ensures consistency.
- Output is a Markdown table — matches existing documentation format.
- No dependencies beyond existing packages — no new requirements needed.

### Method

Part E — CI step for stale-output detection:

```yaml
- name: Check MCP inventory freshness
  run: |
    GENERATED=$(python tools/generate_mcp_inventory.py > /tmp/inventory.md)
    COMMITTED=$(git show HEAD:mcp_service_inventory.md)
    if ! diff -q /tmp/inventory.md <(echo "$COMMITTED") > /dev/null; then
      echo "::warning::MCP inventory is stale. Run 'tools/generate_mcp_inventory.py' to regenerate."
    fi
```

### Details

- Timestamp-based comparison would be simpler but content-based comparison is more reliable — detects any change, not just timing issues.
- Warning level — doesn't block builds but alerts developers.
- No new CI dependencies — uses existing Python environment.
