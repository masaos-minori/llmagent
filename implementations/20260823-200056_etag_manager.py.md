## Goal

In `scripts/rag/ingestion/etag_manager.py`: make `ETagManager.update()`'s
`new_fetched_at` parameter a mandatory, non-nullable `str`, and rewrite the
freshness-comparison path (`_is_stale_update()`, `_update_with_freshness()`)
to be fail-closed instead of fail-open, per the "single canonical
non-nullable `fetched_at`" requirement in
`plans/20260820-095054_plan.md`. Delete `_update_null_fill()` and its
dispatch branch, which become permanently unreachable once `new_fetched_at`
can no longer be `None`.

## Scope

- In scope: `ETagManager.update()`, `ETagManager._is_stale_update()`,
  `ETagManager._update_with_freshness()`, `ETagManager._update_null_fill()`
  (deleted) — all within `scripts/rag/ingestion/etag_manager.py` only.
- Out of scope: `document_manager.py` (the sole caller of `update()`;
  widening its own `fetched_at`/`new_fetched_at` parameters is a separate
  target file/implementation procedure), `ingester.py`, `crawler.py`,
  `pipeline_utils.py`, `chunk_splitter.py`, `models_data.py` (upstream
  generation/propagation, separate procedures), `store_protocols.py` /
  `store_impl.py` / `schema_sql.py` (downstream store layer, separate
  procedures), and `tests/rag/ingestion/test_ingester_etag_guard.py` (test
  migration is a separate procedure per the plan's Phase 5).

## Assumptions

- `ETagManager` is instantiated only from `document_manager.py`'s
  `_update_etag()` (per the plan's Affected areas table); no other caller
  of `update()` exists in `scripts/` or `tests/` outside the one test file
  named above.
- `document_manager.py`'s widening of `new_fetched_at` to mandatory `str`
  (a separate target file in this same plan) lands together with this
  change — `update()`'s new mandatory parameter is otherwise a breaking
  change with only one call site to fix.
- `datetime.fromisoformat(x.replace("Z", "+00:00"))` remains the parsing
  strategy for both incoming and stored timestamps; only the response to a
  parse failure or a naive result changes (raise instead of log-and-treat-
  as-non-stale).

## Design decisions

- **UNK-01 (equal-timestamp behavior)**: treat `new_dt == stored_dt` as
  "fresh" (update proceeds), not "stale". `_is_stale_update()` keeps its
  existing strict `<` comparison (`return new_dt < stored_dt`) unchanged —
  no new branch is needed, only the docstring is updated to state explicitly
  that an equal timestamp is not stale and results in an (idempotent)
  re-write of `fetched_at`.
- **UNK-02 (malformed *stored* value exception type)**: checked
  `scripts/rag/exceptions.py`. `ChunkFormatError` is rejected — it is
  documented as "a chunk document does not match expected structure" (a
  data-shape concern for crawl/chunk JSON, not a DB-row consistency
  concern). No DB-consistency-specific exception exists in the repo.
  Decision: raise `PipelineValidationError` (`RagLayerError`, `RuntimeError`)
  for a malformed **stored** `fetched_at`, since it is already the closest
  existing type for "a pipeline stage encountered invalid input it cannot
  proceed on," and sibling ingestion files (`chunk_splitter.py`,
  `pipeline_utils.py`) already import from `rag.exceptions`, so this stays
  consistent with the package's existing error hierarchy rather than adding
  a new one-off class. For a malformed **incoming** value, let the
  underlying `ValueError` from `datetime.fromisoformat()` propagate
  unchanged (no catch-log-return-False) — this keeps the two failure modes
  distinguishable by exception type: `ValueError` = bad input from the
  caller, `PipelineValidationError` = bad data already in the database.
- Tz-naive incoming timestamps raise `ValueError` explicitly (no silent
  `.replace(tzinfo=UTC)`); this applies the same fail-closed principle to
  "parseable but ambiguous" input as to genuinely malformed input.
- **Overrides `plans/done/20260819-183436_plan.md`'s prior KEEP decision**
  for `_update_null_fill()`: that plan kept the method/its `COALESCE(...)`
  pair reasoning that it is needed "when the caller has no freshness signal
  at all" (`new_fetched_at is None`). This plan removes that precondition
  entirely (`new_fetched_at` becomes mandatory), so the method's only
  reachable call condition disappears. Per the source plan's Risks section,
  this procedure's decision supersedes 183436's Decision #2 for this method
  specifically; if 183436's comment-only change lands first, delete the
  method and its comment together in the same commit and note in the commit
  message that this intentionally reverses 183436's Decision #2 because its
  underlying precondition no longer holds. 183436's unrelated Decision #1
  (`COALESCE(normalized_content, content)` in `maintenance.py`) is
  unaffected.

## Alternatives considered

- Defining a brand-new dedicated exception class (e.g. `EtagConsistencyError`)
  for the malformed-stored-value case — rejected: the plan's UNK-02
  resolution path explicitly frames this as "implementer's judgment, not a
  design fork," and `PipelineValidationError` already covers "invalid input
  reaching a pipeline stage" without adding a new type to the hierarchy for
  a single call site.
- Keeping `_update_null_fill()` in place as unreachable dead code (guarded
  by a defensive `if new_fetched_at is None` that can never be true under
  the new mandatory-`str` type) — rejected: the plan's Design section calls
  this out explicitly as "a correctness cleanup, not a behavior change to
  any reachable path," so leaving dead code in place would contradict the
  plan's own stated intent.
- Silently coercing a naive incoming timestamp to UTC (current behavior) —
  rejected: contradicts the fail-closed requirement; a naive timestamp
  reaching this layer indicates an upstream generation bug (crawler.py is
  being changed in this same plan to always emit canonical UTC), and
  masking it here would hide that bug instead of surfacing it.

## Implementation

### Target file
`scripts/rag/ingestion/etag_manager.py`

### Procedure

1. In `update()`: change the `new_fetched_at` parameter from
   `new_fetched_at: str | None = None` to `new_fetched_at: str` (mandatory,
   no default).
2. In `update()`: remove the early-return guard
   `if etag is None and last_modified is None: return` — with
   `new_fetched_at` now always present, a newer `fetched_at` alone must
   still be able to trigger `_update_with_freshness()` even when both HTTP
   metadata fields are `None`.
3. In `update()`: collapse the `if new_fetched_at is not None: ... else:
   self._update_null_fill(...)` dispatch into an unconditional call to
   `self._update_with_freshness(etag, last_modified, new_fetched_at)` after
   the staleness check passes (the `else` branch is now unreachable and is
   removed, not merely disabled).
4. Delete `_update_null_fill()` in its entirety (method body and its
   `COALESCE(etag, ?)` / `COALESCE(last_modified, ?)` SQL).
5. Rewrite `_is_stale_update(new_fetched_at: str) -> bool`:
   - Narrow the parameter type to mandatory `str`; remove the
     `if new_fetched_at is None: return False` guard at the top (no longer
     reachable).
   - Parsing the incoming timestamp: on `ValueError` from
     `datetime.fromisoformat()`, do not catch-log-return-`False`; let the
     `ValueError` propagate (optionally after a `logger.error(...)` call for
     operational visibility, but without swallowing the exception).
   - If the parsed incoming `datetime` is timezone-naive (`tzinfo is None`),
     raise `ValueError` explicitly instead of silently calling
     `.replace(tzinfo=UTC)`.
   - Parsing the stored timestamp (read via the existing `SELECT fetched_at
     FROM documents WHERE doc_id = ?` query): on `ValueError`, raise
     `PipelineValidationError` (imported from `rag.exceptions`) instead of
     catch-log-return-`False` — a malformed value already persisted in
     `documents.fetched_at` is a data-integrity signal, not a normal input
     to tolerate, since the write path now guarantees validity.
   - Keep the `if not stored_fetched_at: return False` branch for the case
     where no row/no stored value exists at all (distinct from "stored
     value present but malformed") — this case is not a data-integrity
     violation, and the plan does not redefine it.
   - Keep the final `return new_dt < stored_dt` comparison unchanged (see
     UNK-01 above); update the docstring to state the equal-timestamp
     behavior explicitly.
6. In `_update_with_freshness()`: change the SQL from
   `"UPDATE documents SET etag = ?, last_modified = ?, fetched_at =
   COALESCE(?, fetched_at) WHERE doc_id = ?"` to `"UPDATE documents SET
   etag = ?, last_modified = ?, fetched_at = ? WHERE doc_id = ?"` — the
   `fetched_at: str` parameter is already non-optional in this method's own
   signature, so only the SQL literal changes.
7. Add `from rag.exceptions import PipelineValidationError` to the imports
   (consistent with the existing `from datetime import UTC, datetime`
   import block); this mirrors the import pattern already used by sibling
   files `chunk_splitter.py` and `pipeline_utils.py`.
8. Update `update()`'s docstring to describe the new fail-closed contract:
   raises on timezone-naive or malformed incoming input, raises
   `PipelineValidationError` on a malformed stored value, and treats an
   equal timestamp as fresh (not stale).

### Method

Incremental in-place edit of the existing file — narrow one parameter's
type, delete one now-dead method and its call-site branch, replace two
catch-log-return-`False` blocks with raises, and change one SQL literal.
Not a rewrite of the class; `__init__()`, `_log_updated()`, and the
overall call sequence in `update()` (stale-check -> write -> log) are
unchanged.

### Details

- Confirmed current state (via direct read): `update()`'s early return is
  `if etag is None and last_modified is None: return`; the dispatch is
  `if new_fetched_at is not None: self._update_with_freshness(...) else:
  self._update_null_fill(...)`; `_is_stale_update()` currently catches
  `ValueError` in two places (incoming parse, stored parse) and both
  `return False` after `logger.error(...)`; `_update_with_freshness()`'s
  SQL currently reads `fetched_at = COALESCE(?, fetched_at)`.
- No other method in this file references `_update_null_fill()`; deleting
  it does not require touching `_log_updated()` or `__init__()`.
- `PipelineValidationError` is a subclass of both `RagLayerError` and
  `RuntimeError`, so any caller-side `except RuntimeError` handling
  upstream (if present) still catches it; verify at implementation time
  whether `document_manager.py` or `ingester.py` wrap `ETagManager.update()`
  calls in a broad `except Exception`/`except RuntimeError` that would need
  its handling reviewed for this new raise path.

## Compatibility considerations

- Breaking signature change: `update()`'s `new_fetched_at` loses its
  default and becomes positionally/keyword mandatory. The sole caller
  (`document_manager.py`'s `_update_etag()`) must be widened to pass a
  mandatory `str` in the same change set, or the call becomes a `TypeError`
  at runtime (no `Protocol` covers this class, so `mypy` alone will not
  catch a caller that still passes `None` unless `document_manager.py`'s
  own parameter is also narrowed).
- This procedure's deletion of `_update_null_fill()` overrides
  `plans/done/20260819-183436_plan.md`'s KEEP decision for that same method
  (see Design decisions) — anyone re-reading 183436 in isolation would
  expect the method to still exist; this override must be stated in the
  implementation commit message, not just here.
- Any test that directly calls `_update_null_fill()` or asserts on the
  `COALESCE(...)` SQL text will fail after this change; migrating those
  assertions is covered by the separate `test_ingester_etag_guard.py`
  procedure, not this one.

## Security considerations

- Fail-closed handling of a malformed *stored* `fetched_at` (raising
  `PipelineValidationError` instead of silently continuing) turns a
  potential silent data-corruption/tampering condition into a surfaced,
  loggable failure, which is a data-integrity control rather than a purely
  cosmetic error-handling change.
- N/A beyond the above: no secrets, auth, or external-input trust boundary
  is touched by this file — `new_fetched_at` originates from the crawler's
  own generation logic (a separate target file), not from untrusted
  external input at this layer.

## Rollback considerations

- Revert this file together with `document_manager.py`'s widening and
  `tests/rag/ingestion/test_ingester_etag_guard.py`'s migration as one unit
  — the three-way signature dependency (`update()` <- `_update_etag()` <-
  test call sites) means a partial revert reintroduces the
  `TypeError`/assertion-mismatch this change set fixes.
- No schema or persisted-data migration is involved in this file alone, so
  rollback is a pure code revert with no data backfill concern at this
  layer (the schema-level `NOT NULL`/`DEFAULT` change is tracked in the
  separate `schema_sql.py` procedure).
