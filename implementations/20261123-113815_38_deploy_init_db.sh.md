## Goal

Make the dedup store verification in the deploy script follow the schema module's `_USER_VERSION` instead of a hard-coded 1, so a deploy on a fresh version-2 store passes.

## Scope
**Release unit**: N/A: not part of a release unit

In scope: the embedded Python in the dedup store section (the import line, the `user_version != 1` check and message, the success message) and the comment that states `user_version = 1`.

## Assumptions

- Verified: the script already imports `_INSTALL_MARKER_NAME` from `shared.mcp_dedup_schema`, and compares `user_version != 1` with the message `expected 1`.
- The script never mutates or archives a database; a refused pre-existing store still aborts the run and the operator follows the documented `resolve_store` runbook.

## Design decisions

- Import `_USER_VERSION` alongside `_INSTALL_MARKER_NAME` and use it in the check and both messages.

## Alternatives considered

Rejected: bumping the literal to 2 (it would drift again at the next bump).
