## Assumptions
- `RegisteredDocument` has zero callers outside its own definition — confirmed by
  `rg -n "RegisteredDocument" scripts tests` returning only
  `scripts/rag/models_data.py:62` (its own `class` line). Safe to remove.
- `CrawlDocument` fields are all mandatory (no defaults), consistent with the same
  no-defaults intent applied to `ChunkDocument`'s four fields (plan's UNK-02,
  non-blocking; resolved this way per the plan's own stated resolution path).
- `ChunkDocument`'s current defaults (confirmed by reading the file, lines 39-46):
  `code_blocks: list[str] = field(default_factory=list)`, `etag: str | None = None`,
  `last_modified: str | None = None`, `chunking_strategy: str = "text"`,
  `normalized_content: str | None = None`, `chunk_index: int = 0`,
  `source_file: str = ""`, `chunk_type: str = ""`. The plan calls out removing defaults
  from `chunk_type`/`source_file`/`chunk_index`/`chunking_strategy` only —
  `code_blocks`, `etag`, `last_modified`, `normalized_content` keep their current
  defaults (they are legitimately nullable/optional at the DTO level even though the
  new JSON readers require the *keys* to be present in the source file).

## Design decisions
- Field order in `CrawlDocument` should list mandatory (no-default) fields together;
  since `@dataclass` requires all no-default fields before any defaulted field, and
  none of `CrawlDocument`'s fields have defaults, ordering is unconstrained — use the
  Required Crawl Payload order: `url, title, lang, fetched_at, content, code_blocks,
  etag, last_modified`.
- `frozen=True` to match every other DTO in this module (`ChunkDocument`,
  `CrawlTarget`, etc. are all `@dataclass(frozen=True)`).

## Alternatives considered
- Giving `CrawlDocument.code_blocks` a `field(default_factory=list)` default like
  `ChunkDocument` — rejected because the requirement's no-omission intent applies to
  every field in the Required Crawl Payload list, and `code_blocks` is one of them
  (the plan's UNK-02 resolution explicitly says mandatory, no defaults, for every field
  in that list).
