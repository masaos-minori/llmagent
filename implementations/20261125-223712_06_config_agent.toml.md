## Goal

Declare `GITHUB_TOKEN` as a credential for the `github` and `cicd` servers only, so no other shipped server inherits it (REQ-007 designated-server credentials).

## Scope
**Release unit**: R1-launch-spec

## Assumptions

- Only `scripts/mcp_servers/github/github_service_init.py:22` and `scripts/mcp_servers/cicd/cicd_service_init.py:26` read `GITHUB_TOKEN` (`rg environ.get("GITHUB_TOKEN") scripts/mcp_servers`), so exactly these two tables need the declaration.
- The key is accepted only after row 1 adds `credential_env` to `_MCP_SERVER_KEYS`; before that, `reject_unknown_keys` (`scripts/shared/mcp_config.py:368`) rejects the table.

## Design decisions

- One line per table, written as a TOML array of literal variable names (`credential_env = ["GITHUB_TOKEN"]`), matching REQ-006's "names variables, not patterns".
- No other shipped server gets the key, including `rag_pipeline` (UNK-03 is resolved by the real-child startup gate, not by pre-emptively adding variables).

## Alternatives considered

N/A: the alternative (keeping the `GITHUB_TOKEN` wildcard pattern) is what REQ-006 removes.

## Implementation
### Target file
`config/agent.toml`
### Procedure
Add the `credential_env` key to the two designated server tables.

### Method
- Add `credential_env = ["GITHUB_TOKEN"]` to `[mcp_servers.github]` (`:293-300`) and to `[mcp_servers.cicd]` (`:302-309`), aligned with the existing key alignment style in those tables.
- Add no `credential_env` line to any other `[mcp_servers.*]` table (`:239-327`).

### Details
- Keep the existing `auth_token` and `control_auth_token` `${ENV:...}` lines unchanged: the derived per-server tokens are still how each server authenticates to the Agent.

## Compatibility considerations

The key is unknown to the parser until row 1 lands, so this change and row 1 belong to the same commit as the rest of R1-launch-spec.

## Security considerations

`GITHUB_TOKEN` reaches only the two children that read it; every other child loses it (AC-3).
