## Goal
Record the ADR-008 amendment/approval in the ADR index `docs/10_adr/adr_01_index.md` so the amended decision status is discoverable rather than a silent edit (REQ-008 approval record).

## Scope
- In scope: the ADR List table row for ADR-008 and a dated amendment note adjacent to that table in `docs/10_adr/adr_01_index.md`.
- Out of scope: the ADR-008 body text itself (row 20), all other ADR rows, the invariant verification matrix, the dependency graph.

## Assumptions
- The ADR List table (`docs/10_adr/adr_01_index.md:52`) currently reads `| ADR-008 | Separating SQLite into Four Databases | Accepted | 05 db | ...adr_02_05_008_db-sqlite-4db-separation.md |`; the status column is the single discoverable status marker for each ADR.
- The amendment is landed in-place on ADR-008 by row 20 (amended status inside the ADR body); this row mirrors it in the index. adrauth001's own index row for ADR-008 lands first (overlap adjudication: adrauth001 before dbmig001 on this file), so this row edits the shape that adrauth001 produced, not the pre-adrauth001 shape.
- Amendment date equals the approval date recorded in the ADR-008 body header by row 20; the index note must use the same date.

## Design decisions
- Amend the ADR-008 row in place: set the status cell to `Accepted (amended <approval date>: forward-only migration contract for workflow/eventbus)` — one row, one status, no duplicate rows for the same ADR.
- Add a short dated amendment note directly below the ADR List table, parallel in style to the existing unassigned-ADR-011 note (`adr_01_index.md` text after the table): one bullet naming ADR-008, the approval date, the approving issue/planning artifact (dbmig001), and the amended subject (migration contract for `workflow.sqlite`/`eventbus.sqlite`; recreate policy kept for `rag.sqlite`/`session.sqlite`). No new section heading is introduced.
- No change to the ADR Dependency Graph or the Invariant Verification Matrix: the amendment adds a migration contract, not a new invariant or dependency edge; if row 20's amended ADR defines new invocations/INVs, that matrix update belongs to row 20's validation, not here.

## Alternatives considered
- Supersede ADR-008 with a new ADR number — rejected: the Plan and adrauth001's authority model amend in place; supersession would orphan the dependency rows at `adr_01_index.md:75` and the matrix rows referencing ADR-008 INV-01..INV-05.
- Adding a separate "Amendment Log" section — rejected: a new heading changes the document-class structure governed by docs checkers; a note adjacent to the table keeps the index machine-checkable.

## Compatibility considerations

- None beyond documentation integrity: the index must not overstate approval — the note is added only after row 20's body amendment exists.

## Rollback considerations
- Reverting row 20 without this row leaves the index advertising an amendment that the ADR body does not carry; rollback order is this row first, then row 20.
