## Goal
Make `build_db_config()` raise `ValueError` naming `sqlite_vec_so` when it is empty or absent, and stop calling the key optional (`REQ-005`, `REQ-006` / `AC-5`, `AC-6`).

**Release unit**: N/A: not part of a release unit

## Assumptions
- Current code (checked): module docstring says `sqlite_vec_so is optional; empty string means vec extension is not required`; `DbConfig.sqlite_vec_so` defaults to `""`; `build_db_config()` passes `cfg.get("sqlite_vec_so", "")` through. `config/agent.toml` and `config/ingester.toml` set the key.
- The check goes in `build_db_config()` only, not in `DbConfig.__post_init__`: tests and explicit-`db_path` helpers construct `DbConfig` directly with the empty default (for example `TestSQLiteHelperVecExtensionLoading`), and the EventBus does not use it.
- `SQLiteHelper(target)` wraps a `build_db_config()` `ValueError` as `RuntimeError("DbConfig load failed ...")` (`scripts/db/helper.py`), so no new import or handler is needed.
- UNK-05/UNK-06: run `tests/db`, `tests/agent`, `tests/rag`, `tests/mcp_servers`, `tests/eventbus`; many tests patch `build_db_config` or `ConfigLoader`; update only fixtures that fail for the missing key. Trace the ingester and crawler paths: `config/ingester.toml` sets the key; add no check beyond `build_db_config()` unless an empty value can reach a vec load by another route.
- Code change in `scripts/` (`Requires deploy`): commit and push first; deployment is the user's decision.

## Design decisions
