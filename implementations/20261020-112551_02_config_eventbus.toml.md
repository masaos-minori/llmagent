## Goal
Ship `config/eventbus.toml` with `auth_token` supplied through the environment instead of a literal empty
secret, so the repository copy of the Event Bus configuration carries no credential value and the operator
sets the token in one documented place.

## Scope
- Replace the value of `auth_token` (line 13) with `"${ENV:EVENTBUS_AUTH_TOKEN}"`.
- Add a comment line naming the variable and where to set it.
- No change to the five per-role token lines (24-28) and no change to any other file under `config/`.

## Assumptions
- `scripts/eventbus/config.py` resolves the reference before validating (seq 01); without that row this value
  would ship as an unusable literal, which is why seq 01 must land first.
- `deploy/deploy.sh` copies this file to `/opt/llm/config/eventbus.toml` on every deploy, so the deployed copy
  inherits the reference rather than a secret.

## Design decisions
- Only `auth_token` is indirect in the shipped file: it is the required credential the health probe uses,
  while the per-role tokens stay optional and empty (`UNK-03` records the wider choice).
- The variable name follows the existing convention of a prefix plus role plus purpose, mirroring the
  `${ENV:MCP_*_AUTH_TOKEN}` form in `config/agent.toml`.

## Alternatives considered
- Keep the literal empty value and require operators to edit the deployed TOML: rejected — the file is
  overwritten on every deploy and a literal secret in a repository file is what the issue reports.
- Indirect every token key in the shipped file now: deferred to `UNK-003`/`UNK-03`; the code already supports
  both forms, so no rework is needed later.

## Implementation
### Target file
`config/eventbus.toml`

### Procedure
1. Extend the comment block above `auth_token` so the variable name and its location are stated.
2. Change the value to the environment reference.

### Method
- One comment line and one value line; the surrounding comment block keeps its wording.
- Quoting stays TOML-escaped: the reference is a double-quoted string whose inner quotes are escaped.

### Details
```toml
# Before:
# Shared token (required). It is a control-plane credential: it holds only the
# operator, monitoring, and admin roles. It holds no publisher or consumer role,
# so it cannot publish, subscribe, ACK, or NACK.
auth_token = ""
# After:
# Shared token (required). It is a control-plane credential: it holds only the
# operator, monitoring, and admin roles. It holds no publisher or consumer role,
# so it cannot publish, subscribe, ACK, or NACK.
# The value is read from the environment at config load: set EVENTBUS_AUTH_TOKEN
# in /opt/llm/.env (or <repo>/.env). An unset variable stops the Event Bus at startup.
auth_token = "${ENV:EVENTBUS_AUTH_TOKEN}"
```

## Compatibility considerations
- The file stays parseable by `tomllib` and by the loader's key and type checks; the value remains a `str`.
- `tests/agent/test_http_lifecycle_env_allowlist_integration.py` scans `config/*.toml` for environment
  references; seq 09 narrows that scan to the configurations a subprocess server reads and adds the assertion
  that this variable stays outside the subprocess allowlist. Seq 02 and seq 09 land in the same commit cycle so
  the suite never sits in a failing state.

## Security considerations
- No literal credential value is stored under `config/` (`AC-3`).
- The reference is resolved only inside the Event Bus process, and `AC-7` locks that it is not inherited by
  MCP subprocess servers.

## Rollback considerations
Single-path revert: `git checkout HEAD -- config/eventbus.toml`. A host that already set the environment
variable keeps working after the revert because a literal empty value simply fails the non-empty check.
