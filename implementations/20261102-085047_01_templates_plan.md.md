## Goal
- Add the release-unit declaration to the Plan template (`REQ-001`: a Plan declares phases that must land together, with the reason).

## Scope
- In scope: a `### Release units` block at the end of the `## Implementation steps` section inside the template's fenced skeleton, with one-line format guidance in the section's intro prose. Out of scope: any `##` heading, the `Scope` block, and any notes section.

## Assumptions
- Step 3a: `tools/generate_workitem.py` copies the first ```` ```markdown ```` fence verbatim, so the block reaches every generated Plan; `tools/check_workitem_structure.py` and `tools/check_metadata_field_policy.py` read only `^## ` headings (checked in Step 3a), so a `###` block adds no required section.

## Design decisions
- Entry format: `**Unit**: {name} | **Phases**: {N, N} | **Reason**: {reason}`, one line per unit; default text `N/A: no release unit`, so an untouched generated Plan stays valid.
- Intro prose states when to declare one: a phase breaks existing callers or tests until another lands (the schema `NOT NULL` case).
