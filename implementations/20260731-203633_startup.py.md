# Implementation Procedure: startup.py

## Goal
Improve observability of memory initialization failures by classifying exceptions and using appropriate log levels.

## Scope
- **In scope**:
    - Adding `_classify_memory_failure` helper method to `scripts/agent/startup.py`.
    - Refactoring `_setup_prompt` to use categorized logging.
- **Out of scope**:
    - Modifying the core control flow of memory initialization.
    - Adding new state variables.

## Assumptions
- The agent must always start even if memory services fail (graceful degradation).
- Logging is the primary mechanism for observability in this change.

## Design decisions
- Categorize exceptions into `DATABASE_OR_IO`, `NETWORK_TRANSIENT`, and `UNKNOWN`.
- Assign log levels to categories: `ERROR` for IO issues, `WARNING` for network transients, and `INFO` for unknown errors.

## Alternatives considered**
- Single error category for all non-fatal errors (rejected due to insufficient diagnostic value).

## Rollback considerations**
- Revert `_setup_prompt` to its original generic exception handling.
- Remove the `_classify_memory_failure` method.

## Implementation
- **Target file**: `scripts/agent/startup.py`
- **Procedure**:
    1. Define `_classify_memory_failure(self, exc: Exception) -> str` within `StartupAgent` class.
    2. Update the `except Exception as exc:` block in `_setup_prompt` to call the classifier and branch logging.
- **Method**:
    - Use `isinstance` for exception type checking.
    - Use standard `logging` module methods (`error`, `warning`, `info`).
- **Details**:
    - `sqlite3.Error` or `OSError` $\rightarrow$ `DATABASE_OR_IO` $\rightarrow$ `logger.error`
    - `TimeoutError` or `ConnectionError` $\rightarrow$ `NETWORK_TRANSIENT` $\rightarrow$ `logger.warning`
    - Other $\rightarrow$ `UNKNOWN` $\rightarrow$ `logger.info`

## Validation plan
- Verify `_classify_memory_failure` returns correct strings for given exception types.
- Verify `_setup_prompt` logs the correct level for simulated exceptions.
- Ensure `ctx.conv.memory_disabled` remains set to `True` on any exception.
