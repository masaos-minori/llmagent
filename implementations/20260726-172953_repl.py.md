## Goal

Fix the WAL file backup path traversal vulnerability in `AgentREPL._wal_backup_sync()` /
`_close_resources()` (`scripts/agent/repl.py`) by validating the resolved database path
against an allowed base directory, verifying backup-directory writability, and using a
collision-resistant, session-based backup filename instead of a timestamp.

## Scope

**In-Scope:**
- Resolve symlinks in `db_path` via `os.path.realpath()` before any filesystem operation.
- Validate the resolved path is contained within the allowed base directory.
- Verify the backup directory exists and is writable before attempting `shutil.copy2()`.
- Replace the timestamp-based backup filename with a session ID-based name.

**Out-of-Scope:**
- WAL checkpoint logic (`_wal_checkpoint_sync()`) — unrelated, unchanged.
- New configuration options for allowed directories (reuse existing config, see below).
- Changing the unconditional "always attempt backup" strategy.

## Assumptions

1. The allowed base directory is `self._ctx.cfg.approval.allowed_root` (already defined
   in `config/agent.toml` as `allowed_root = "/opt/llm"` and consumed via
   `AgentConfig.approval.allowed_root` in `scripts/agent/config_dataclasses.py` /
   `config_builders.py`) — no new config key is introduced. This resolves the plan's
   UNK-01 without adding a new `ALLOWED_BACKUP_DIR` env var (rejecting the approach used
   in the stale draft doc `implementations/done/20260725-154245_wal_backup.md`, which
   invented a new env var and a hardcoded `/opt/llm/db` fallback).
2. `PRAGMA database_list` returns the actual on-disk file path at column index 2 — this
   is already relied upon and tested (`tests/test_repl.py::test_pragma_database_list_reads_db_path_from_column_index_2`);
   UNK-02 is therefore not a new unknown, it is already resolved in the existing code/tests.
3. `self._ctx.session.session_id` is populated before `_close_resources()` runs (it is
   read the same way elsewhere in `repl.py`, e.g. lines 142/157/571); if it is `None`
   (init failed before a session was created), fall back to a UUID.
4. Per UNK-03: on validation failure, log a warning and skip the backup rather than
   raising — consistent with the existing `errors` accumulation pattern in
   `_close_resources()`.

## Design decisions

- Reuse `self._ctx.cfg.approval.allowed_root` as the allowed base directory rather than
  introducing new configuration, since this is the same directory-jail concept already
  used for tool-path approval in `scripts/agent/tool_policy.py::check_allowed_root()`
  (`Path(cfg.approval.allowed_root).resolve()` + `is_relative_to(root)`). This keeps one
  source of truth for "what directory is the agent allowed to touch."
- Use `os.path.realpath()` (matching the plan's stated method and the existing `os`-based
  style of `repl.py`, which does not import `pathlib`) rather than switching the whole
  file to `pathlib.Path`, to keep the diff minimal.
- Avoid a naive `str.startswith(allowed_base_dir)` containment check (used in the stale
  draft doc) because it has a prefix-injection bug: `/opt/llmx/...` would incorrectly
  match an allowed root of `/opt/llm`. Compare with an explicit separator boundary:
  `resolved == allowed_root or resolved.startswith(allowed_root + os.sep)`.
- Keep the fail-safe behavior: on validation/permission failure, log and skip backup
  (append to the existing `errors` list) — do not raise, since shutdown must not crash.

## Alternatives considered

- Add a new `ALLOWED_BACKUP_DIR` env var (stale draft doc's approach) — rejected: adds a
  second, redundant path-restriction knob when `cfg.approval.allowed_root` already exists
  and is wired through `AgentConfig`.
- Switch to `pathlib.Path.resolve()` / `is_relative_to()` for consistency with
  `tool_policy.py` — considered but deferred: would require adding a `pathlib` import to
  a file that is currently `os`-only; the plan explicitly specifies `os.path.realpath()`,
  and the containment check can be made equally correct with `os.path` primitives.
- Reject symlinked paths outright (no resolution) — rejected per the plan's own risk
  mitigation: resolve-then-validate is required so legitimate symlink-based deployments
  still work as long as the target stays inside the allowed root.

## Implementation

### Target file

`scripts/agent/repl.py`

### Procedure

1. In `_wal_backup_sync()` (current lines 302-324), after reading `db_path` from
   `PRAGMA database_list` (line 311), resolve symlinks with
   `resolved_db_path = os.path.realpath(db_path)`.
2. Validate `resolved_db_path` is contained in `self._ctx.cfg.approval.allowed_root`
   (skip validation — treat as allowed — only if `allowed_root` is empty, matching
   `check_allowed_root()`'s existing "unset means unrestricted" convention).
3. If validation fails, log a warning, append an error tuple (e.g.
   `("wal_backup_path_rejected", ...)`), and return `(None, errors)` without attempting
   the copy.
4. Before `shutil.copy2()`, verify `backup_dir` exists and `os.access(backup_dir, os.W_OK)`
   is true; on failure, log and skip (same error-accumulation pattern).
5. Replace the filename template at line 317
   (`f"{os.path.basename(db_path)}-wal-backup-{int(time.time())}"`) with a session
   ID-based name, e.g.
   `f"{os.path.basename(db_path)}-wal-backup-{session_id}-{int(time.time())}"`
   (keep the timestamp suffix too, since Assumption/Risk 3 requires a fallback when
   `session_id` is unavailable, and the timestamp also aids operators scanning backups
   chronologically).
6. Run the standard validation sequence from `rules/toolchain.md` (ruff, mypy,
   lint-imports, ast-grep, bandit, targeted + full pytest).

### Method

- Edit `_wal_backup_sync()` (currently, lines 302-324):
  ```python
  def _wal_backup_sync(self) -> tuple[str | None, list[tuple[str, str]]]:
      errors: list[tuple[str, str]] = []
      wal_backup_path: str | None = None
      try:
          with SQLiteHelper("session").open(write_mode=True) as db:
              db_path = db.execute("PRAGMA database_list").fetchone()[2]
              if db_path:
                  wal_file = f"{db_path}-wal"
                  backup_dir = os.path.dirname(db_path) or "/tmp"
                  wal_backup_path = os.path.join(
                      backup_dir,
                      f"{os.path.basename(db_path)}-wal-backup-{int(time.time())}",
                  )
                  shutil.copy2(wal_file, wal_backup_path)
                  logger.warning("WAL file backed up to %s", wal_backup_path)
      except Exception as backup_err:
          logger.error("Failed to backup WAL file: %s", backup_err)
          errors.append(("wal_backup", f"{type(backup_err).__name__}: {backup_err}"))
      return wal_backup_path, errors
  ```
  Change to resolve `db_path` via `os.path.realpath()`, validate containment against
  `self._ctx.cfg.approval.allowed_root` (separator-safe check, see Design decisions),
  verify `os.access(backup_dir, os.W_OK)`, and build the filename with
  `self._ctx.session.session_id` (falling back to `uuid.uuid4().hex[:8]` if unset). On
  any validation failure, append a descriptive error to `errors` and return
  `(None, errors)` before reaching `shutil.copy2()` — do not change the outer
  `try/except Exception` wrapper or the `_close_resources()` caller contract
  (`(path_or_None, errors)`).
- `_close_resources()` itself (lines 326-391) needs no structural change: it already
  calls `_wal_backup_sync()` via executor with a timeout and extends `errors` — only the
  called function's internal logic changes.

## Compatibility considerations

- Existing deployments with `db_path` already inside `/opt/llm` are unaffected.
- A symlinked database path whose resolved target is inside `allowed_root` continues to
  back up normally; only a resolved target outside `allowed_root` newly skips backup
  (logged, not fatal) — matches the plan's stated blast radius.
- Backup filenames change shape (append `session_id`); any external tooling that parses
  the old `{basename}-wal-backup-{timestamp}` filename pattern needs updating, per the
  plan's Risks section.

## Security considerations

- Directly addresses the path-traversal/symlink-escape vulnerability named in the plan:
  without containment validation, a maliciously symlinked `db_path` could cause a backup
  write outside the intended directory.
- Reuses the existing `allowed_root` trust boundary rather than adding a new,
  independently-configured boundary that could drift out of sync with it.
- Pre-check with `os.access()` plus the existing `except Exception` wrapper around
  `shutil.copy2()` together handle the TOCTOU race (directory removed between check and
  write) without crashing shutdown.

## Rollback considerations

- Change is confined to `_wal_backup_sync()` in one file; revert via `git checkout` on
  `scripts/agent/repl.py` or a targeted revert commit.
- No schema, on-disk format, or persisted-state change; a rolled-back build simply
  resumes writing unvalidated, timestamp-named backups (the pre-existing behavior).
- No feature flag needed given the small, single-function blast radius.
