## Goal

Extract the ordered gate-check sequence currently inlined in
`ToolExecutor._raw_execute` (`scripts/shared/tool_executor.py:109-145`) —
`_check_startup_mode` → `_check_health` → `_ensure_lifecycle_ready` — into a
single reusable helper method `_run_gate_chain(server_key)`, and change
`_raw_execute` to call the inherited `_invoke_and_record` method (added to
`ToolTransportInvoker` by a companion change) instead of reimplementing its
own try/except + `_record_success`/`_record_transport_error` block. Both
changes are pure, behavior-preserving refactors with no change to public
signatures or observable outcomes.

## Scope

In scope:
- Add `_run_gate_chain(self, server_key: str) -> ToolCallResult | None` as a
  new method on `ToolExecutor`, containing exactly the three gate checks
  currently inlined at `tool_executor.py:118-128`, in the same order, with
  the same short-circuit-on-first-error behavior.
- Update `_raw_execute` (`tool_executor.py:109-145`) to call
  `_run_gate_chain` once and short-circuit on a non-`None` result, replacing
  the three separate inline `if`/`await` blocks.
- Update `_raw_execute`'s tail (`tool_executor.py:140-145`, the
  `try: ... _execute_with_semaphore ... _record_success / except
  TransportError: _record_transport_error` block) to call the inherited
  `_invoke_and_record(server_key, transport, tool_name, args, sem)` method
  instead of its own local try/except.

Out of scope:
- `ToolTransportInvoker._invoke_and_record` itself — implemented in a
  companion procedure for `scripts/shared/tool_transport_invoker.py`.
- `invoke()`'s own lifecycle block (`tool_transport_invoker.py:185-191`) —
  a separate, intentionally-untouched code path (catches only
  `ServerCooldownError`, no `record_failure` call), distinct from
  `ToolExecutor._ensure_lifecycle_ready` (catches `OSError`/`RuntimeError`,
  calls `self._health_registry.record_failure`).
- The semaphore ensure/get step (`self._ensure_semaphores()` then
  `(self._semaphores or {}).get(server_key)`, `tool_executor.py:137-138`) —
  stays inline at the `_raw_execute` call site, is not moved into
  `_run_gate_chain` or `_invoke_and_record`.
- Any public method signature change on `ToolExecutor`.
- `scripts/agent/` callers (`factory.py`, `tool_runner.py`, `repl.py`,
  `context.py`, `repository_gateway.py`, `commands/cmd_mdq.py`) — none call
  `.invoke(` or `_raw_execute` directly.

## Assumptions

- `_check_startup_mode` (`tool_executor.py:82-89`) and
  `_ensure_lifecycle_ready` (`tool_executor.py:91-103`) both depend on
  `self._server_configs` / `self._health_registry`, and `_server_configs` is
  set only in `ToolExecutor.__init__` (`tool_executor.py:64`), not on the
  base `ToolTransportInvoker`. `_run_gate_chain` must therefore live on
  `ToolExecutor`, not be lifted to the base class.
- `tests/shared/test_tool_executor_order.py::test_transport_success_full_path`
  is the primary behavior-lock: it asserts
  `call_order == ["resolve", "health", "lifecycle", "transport"]` via a
  `ToolExecutor` built through `_make_executor()` with mocked internals.
- `ToolTransportInvoker._invoke_and_record` (companion change) exists and is
  override-safe (single-underscore, no `@final`) by the time this change's
  final step runs.

## Design decisions

- Keep `_run_gate_chain` returning `ToolCallResult | None` (matching each
  individual gate check's existing return type) so `_raw_execute` can use
  the same `if err := ...: return err` idiom already used for
  `_check_startup_mode` and `_check_health` at lines 118 and 122.
- Do not fold the transport-resolution `None` check
  (`tool_executor.py:131-135`) into `_run_gate_chain` — the plan and current
  code treat "no transport configured" as a distinct step from the
  startup/health/lifecycle gate trio, and the requirement names only those
  three as "the gate chain."
- Land the two extractions (gate chain, then invoke/record merge) as
  separate, independently revertable edits, matching the plan's Phase 2
  step ordering.

### Details
Current `_raw_execute` (`tool_executor.py:109-145`):
```python
async def _raw_execute(
    self,
    tool_name: str,
    args: dict[str, Any],
) -> ToolCallResult:
    """Execute tool via the appropriate transport; applies per-server-key Semaphore when configured."""
    server_key = self._resolver.resolve(tool_name)

    # Startup mode gate (startup_mode=none is disabled by design)
    if err := self._check_startup_mode(server_key):
        return err

    # Health check
    if err := self._check_health(server_key):
        return err

    # Lifecycle ensure_ready
    lifecycle_err = await self._ensure_lifecycle_ready(server_key)
    if lifecycle_err is not None:
        return lifecycle_err

    # Transport resolution
    transport = self._resolve_transport(server_key)
    if transport is None:
        return self._error_result(
            server_key, self._transport_missing_msg(server_key), error_type="tool"
        )

    self._ensure_semaphores()
    sem = (self._semaphores or {}).get(server_key)

    try:
        result = await self._execute_with_semaphore(transport, tool_name, args, sem)
        self._record_success(server_key, result)
        return result
    except TransportError as e:
        return self._record_transport_error(server_key, e)
```

Target shape after both extractions:
```python
def _run_gate_chain(self, server_key: str) -> ToolCallResult | None:
    """Run the startup-mode, health, and lifecycle gates in order; return the first error, or None if all pass."""
    if err := self._check_startup_mode(server_key):
        return err
    if err := self._check_health(server_key):
        return err
    return None  # lifecycle check is async; see _raw_execute for its await

async def _raw_execute(
    self,
    tool_name: str,
    args: dict[str, Any],
) -> ToolCallResult:
    """Execute tool via the appropriate transport; applies per-server-key Semaphore when configured."""
    server_key = self._resolver.resolve(tool_name)

    if err := self._run_gate_chain(server_key):
        return err
    lifecycle_err = await self._ensure_lifecycle_ready(server_key)
    if lifecycle_err is not None:
        return lifecycle_err

    transport = self._resolve_transport(server_key)
    if transport is None:
        return self._error_result(
            server_key, self._transport_missing_msg(server_key), error_type="tool"
        )

    self._ensure_semaphores()
    sem = (self._semaphores or {}).get(server_key)
    return await self._invoke_and_record(server_key, transport, tool_name, args, sem)
```
Note: because `_ensure_lifecycle_ready` is `async` and the other two gates
are synchronous, `_run_gate_chain` as a plain (sync) method can only cover
`_check_startup_mode` + `_check_health`; the lifecycle await stays in
`_raw_execute` immediately after it, preserving exact call order
(`resolve → health(startup) → health → lifecycle → transport`). If an
async `_run_gate_chain` is preferred instead (covering all three gates
including the lifecycle await), that is an equally valid implementation of
the same requirement — either way, the call order and each gate's
return/exception behavior must be byte-for-byte identical to today's, and
`tests/shared/test_tool_executor_order.py::test_transport_success_full_path`'s
`call_order == ["resolve", "health", "lifecycle", "transport"]` assertion
is the concrete check that decides between the two shapes.
