## Goal

Move `ResourceShutdownCoordinator.close_resources()` out of the `finally` wrapping
`startup.run()` in `AgentREPL.run()` so it runs only after the REPL input loop returns
(success) or via `StartupOrchestrator`'s own rollback (failure), never ahead of the
input loop on a successful startup. Implements `REQ-001`/`REQ-002`/`REQ-003`
(close_resources must not precede the input loop; awaited once after it; absent on the
failure path).

## Scope

Only the control flow of `AgentREPL.run()` in `scripts/agent/repl.py` (lines 110-143).
No other file is modified. No public-contract, persistence, or security change.

## Assumptions

- The `_spawned_subprocesses` return value remains an unused assignment after the move
  (pre-existing dead assignment); keeping it minimizes the diff. Subprocess termination
  is delegated to `lifecycle.shutdown_all()`, not done directly by `repl.py`.
- The failure path needs no separate `close_resources()` call: cleanup is performed by
  `StartupOrchestrator.run()`'s own `shutdown_all()` rollback (`startup.py:80-88`). No
  WAL checkpoint is required at startup failure (no session/WAL state exists before the
  input loop's `session.start()` — see Plan `UNK-01`).

## Design decisions

- Replace the `finally` around `startup.run()` with: keep the `except` block that writes
  the fatal message and re-raises, and add a single `await self._shutdown.close_resources()`
  after `await self._input_loop.run(...)`. Rationale: satisfies `REQ-001`/`REQ-002`/`REQ-003`
  with the smallest possible control-flow change and matches the existing test contract
  (subprocess termination is delegated to `lifecycle.shutdown_all()`, never done by
  `repl.py`).
- Do NOT add a `finally` around the input loop. Rationale: matches current behavior and
  the issue's stated contract ("normal user exit"); turn-level errors are handled by the
  input-loop/turn error handling, not by this cleanup.

## Alternatives considered

`N/A: a single control-flow move within one function; no viable alternative satisfies
`REQ-001`/`REQ-002`/`REQ-003` with less risk or smaller blast radius.`

### Procedure

Current `run()` (lines 124-143):

```python
        try:
            self._cmds, self._orchestrator, _spawned_subprocesses = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        finally:
            await self._shutdown.close_resources()

        # Show memory disabled warning immediately after startup if applicable
        if self._ctx.conv.memory_disabled and not self._ctx.conv.memory_warning_shown:
            self._ctx.conv.memory_warning_shown = True
            self._view.write_warning(
                f"{OutputTag.NON_FATAL} Memory is disabled for this session."
            )

        # Delegate to input loop
        await self._input_loop.run(
            lambda: self._banner.print_startup_banner(self._orchestrator),
            self._persist_after_loop,
        )
```

1. Delete the `finally:` block (the two lines `finally:` and
   `await self._shutdown.close_resources()`) that wraps the `try` around `startup.run()`.
   Keep the `except` block intact (writes the fatal message, then `raise`). This satisfies
   `REQ-001` (no `close_resources()` before the input loop) and `REQ-003` (failure path
   still writes the fatal message and re-raises, and does not call `close_resources()`).
2. After the `await self._input_loop.run(...)` call (currently ending at line 143),
   insert exactly one line:

   ```python
           await self._shutdown.close_resources()
   ```

   This satisfies `REQ-002` (`close_resources()` awaited exactly once, after the loop
   returns).
