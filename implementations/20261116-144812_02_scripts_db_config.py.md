## Goal

Add a resolve_unique_path helper to `scripts/db/config.py` that turns a second-granularity generated name into a collision-safe one by appending a counter suffix (`_2`, `_3`, ...). This is the single new primitive the four name-generation call sites (rows 3-6) route through (REQ-003, AC-6).

## Assumptions
- Anchors re-verified 2026-11-16 against the git repo. `format_timestamp` is at `config.py:59-61` (`_TIMESTAMP_FMT` at `:56`); `Path` is already imported (`:17`); no resolve_unique_path exists in the repo.
- `format_timestamp` stays `YYYYMMDD_HHMMSS` (second resolution); uniqueness comes from the counter suffix, not from sub-second timestamps (maintainer decision).

## Design decisions
- Counter suffix appended to the stem (`{stem}_2{suffix}`), capped at 10000 iterations with a `RuntimeError`, so pathological contention cannot loop forever; the original name (no suffix) is returned unchanged when free, so existing name ordering and readers are unaffected.
- The helper takes and returns a `Path` and checks `Path.exists()`, so it works uniformly for files (`rotation.py`, `recovery.py` archives, drill JSON, drill isolated copy) and for the quarantine directory path (`recovery.py:426`); directory creation stays with the caller.

## Alternatives considered
- Sub-second timestamps or failing on collision — rejected by maintainer decision.

## Implementation
### Target file
`scripts/db/config.py`

### Procedure
1. Add `resolve_unique_path` (new) below `format_timestamp` (`:61`), leaving `format_timestamp` and `DbConfig` untouched. Signature: `resolve_unique_path(path: Path) -> Path`.

### Method
- If `not path.exists()`: return `path` unchanged.
- Else loop `n` from 2 to 10000 building `path.with_name(f"{path.stem}_{n}{path.suffix}")`; return the first candidate that does not exist.
- If none is free within the cap, raise `RuntimeError` naming `path`.

### Details
- Works for names produced by `db_path.with_name(...)` (recovery) and `dir / f"...{suffix}"` (rotation, drill): callers pass the already-constructed candidate `Path`.
- No new imports; `Path` is already imported. No changes to `build_db_config` or the `__post_init__` validators.
