## Goal

In `scripts/rag/ingestion/ingester.py`: make `fetched_at` a mandatory, non-nullable
`str` end-to-end through this file's document-write path. Read it as a required key
from the chunk JSON dict (no `.get()` default), and widen it from `str | None` to `str`
in `_get_or_create_document()`, `_insert_document()`, and `_commit_url_transaction()`.
Delete `_insert_document()`'s `cursor2` fallback branch that omits the `fetched_at`
column from the INSERT statement, leaving a single, always-`fetched_at`-including
INSERT.

## Scope

- In scope: `scripts/rag/ingestion/ingester.py` only — the `fetched_at` read site in
  `ingest_url_group()`, and the three function signatures/bodies named in Goal.
- Out of scope (separate documents/files per the source plan): `document_manager.py`
  (`handle_existing_document()`/`_update_etag()` — see the sibling procedure document
  for that file), `etag_manager.py`, `store_protocols.py`/`store_impl.py`,
  `schema_sql.py`, `pipeline_utils.py`, `chunk_splitter.py`, `crawler.py`,
  `models_data.py`, and all test files listed in the plan's Affected areas.

## Assumptions

- Verified by reading the current source: `first_data = self._read_chunk_json(...)` in
  `ingest_url_group()` returns a `ChunkJsonRaw` (a raw `TypedDict`/dict), and
  `fetched_at = first_data.get("fetched_at")` is a plain dict `.get()` call with no
  default value (evaluates to `None` when absent).
- Verified by reading the current source: `ChunkJsonRaw`, `_read_chunk_json_raw`,
  `_validate_artifact()`, and `_normalize_chunk_index()` are all still present and
  in use in this file today — the sibling plan `plans/20260820-094150_plan.md`
  (which would replace `ChunkJsonRaw`/dict access with a `ChunkDocument` returned by
  a new `read_chunk_json()`, per an existing but unapplied procedure document
  `implementations/20260821-123341_ingester.py.md`) has **not** been applied to this
  file's source as of this writing. This procedure therefore targets
  `first_data["fetched_at"]` as plain dict subscript access. If `094150` lands first,
  re-verify at implementation time: the target becomes attribute access
  (`first_data.fetched_at`) on a `ChunkDocument` instead, per this plan's own
  UNK-03/Risks guidance.
- Verified by reading the current source: `_get_or_create_document()`'s parameter list
  is `(self, doc_mgr, db, url, title, lang, force, etag: str | None = None,
  last_modified: str | None = None, chunking_strategy: str = "text",
  fetched_at: str | None = None)` — `fetched_at` is the last parameter and currently
  carries a default, following three other defaulted parameters. Simply dropping its
  default (making it a bare `fetched_at: str` in the same trailing position) is a
  `SyntaxError: non-default argument follows default argument` at import time, because
  it would still follow `etag`/`last_modified`/`chunking_strategy`, all of which keep
  their defaults. This ordering conflict is not called out in the source plan for this
  specific function (the plan's field-ordering note in Assumptions only addresses
  `models_data.py`'s `ChunkDocument` dataclass) — flagged here from direct code
  reading.
- Verified by reading the current source: `_insert_document()`'s and
  `_commit_url_transaction()`'s parameter lists have no `=`-defaulted parameters at
  all (`fetched_at: str | None` is already positionally mandatory, just
  `Optional`-typed) — widening these two signatures is a pure type change with no
  reordering concern.

## Design decisions

- Treat the dict-subscript read in `ingest_url_group()` as the single point where this
  file asserts the "mandatory key" contract, rather than re-validating `fetched_at`
  inside each of the three downstream functions — the upstream boundary
  (`pipeline_utils.py::read_json_file()`/chunk JSON producer) already guarantees a
  non-empty value once this plan's earlier phases land, so re-checking it three more
  times inside this file would be redundant defensive coding at a non-boundary layer.
- Delete the `cursor2` fallback branch outright rather than keep it as unreachable
  dead code behind an `assert fetched_at is not None` — an unreachable branch left in
  place is exactly the kind of thing that can be silently reawakened by a future edit
  that reintroduces a `None` default; removing it lets mypy's `str | None` → `str`
  narrowing be the actual enforcement mechanism, per the plan's own Risk mitigation for
  this file.
- Resolve the `_get_or_create_document()` ordering conflict by moving `fetched_at: str`
  to immediately after `force: bool` (ahead of the three still-defaulted parameters),
  and update its one call site in `ingest_url_group()` to pass `fetched_at` as an
  explicit keyword argument rather than relying on positional order — keyword-passing
  is more robust against this kind of reordering than renumbering a long positional
  call.

## Alternatives considered

- Making `fetched_at` keyword-only in `_get_or_create_document()` (via a bare `*`
  separator before it) instead of reordering — rejected: it would force the existing
  positional call in `ingest_url_group()` to be rewritten regardless, and reordering
  keeps the parameter list's "which values are truly optional" grouping intact (all
  remaining defaulted params stay adjacent at the end).
- Keeping `_insert_document()`'s two-branch shape but making the `else` branch raise
  instead of insert without the column — rejected: the plan explicitly calls for
  deleting the branch outright, not converting it to a redundant runtime guard; a
  missing/`None` value should already be impossible once the upstream read is
  mandatory, so an extra raise here would be defensive code for an unreachable state.

## Implementation

### Target file

`scripts/rag/ingestion/ingester.py`

### Procedure

1. In `ingest_url_group()`, change `fetched_at = first_data.get("fetched_at")` to
   `fetched_at = first_data["fetched_at"]` (re-verify against the `094150` landing
   status per Assumptions before editing).
2. In `_get_or_create_document()`: move the `fetched_at` parameter to immediately after
   `force: bool`, change its annotation from `str | None = None` to `str` (drop the
   default), and update its single call site inside `ingest_url_group()` to pass
   `fetched_at=fetched_at` as a keyword argument.
3. In `_insert_document()`: change the `fetched_at: str | None` parameter annotation to
   `fetched_at: str`.
4. In `_insert_document()`'s body: delete the `if fetched_at is not None: ... else: ...`
   branching entirely; keep only the single `INSERT INTO documents (... fetched_at)`
   statement (the current `cursor` branch's SQL and tuple), using the now-mandatory
   `fetched_at` parameter directly; return that single cursor.
5. In `_commit_url_transaction()`: change the `fetched_at: str | None` parameter
   annotation to `fetched_at: str`.
6. Run `rg -n "fetched_at" scripts/rag/ingestion/ingester.py` after editing and confirm
   no remaining `str | None` annotation or `.get("fetched_at"` call remains in this
   file.

### Method

Signature widening plus deletion of one dead-value branch; no new classes, no new
abstractions. Rely on `mypy`'s `str | None` → `str` narrowing (already planned as this
file's specific risk mitigation) to surface any remaining call path that still supplies
`None`, rather than adding new runtime `assert`/`raise` guards inside this file.

### Details

- `_insert_document()`'s surviving INSERT statement's column list and parameter tuple
  are unchanged in shape — only the branch that produced the six-column,
  `fetched_at`-omitting variant is removed; the SQL text of the remaining branch is not
  otherwise modified by this procedure.
- `_commit_url_transaction()` passes `fetched_at` straight through to
  `_insert_document()` unchanged; no logic inside `_commit_url_transaction()` itself
  branches on `fetched_at`, so this step is a signature-only change.
- Do not touch `_read_chunk_json()`, `_validate_artifact()`, `_normalize_chunk_index()`,
  or any other method — those belong to the separate `094150` plan/procedure and are
  out of scope here (see Assumptions).

## Compatibility considerations

- This file's mandatory-`fetched_at` change assumes `schema_sql.py`'s Phase 1 change
  (dropping `documents.fetched_at`'s `DEFAULT` clause, a separate target file in this
  plan) lands in the same overall change set — Python type hints are not enforced at
  runtime, so until the schema `DEFAULT` is also removed, a stray runtime `None`
  reaching the surviving INSERT would still be masked by SQLite's default rather than
  failing fast; `mypy` is the only enforcement mechanism at this file's own boundary.
- The only caller of `_get_or_create_document()`, `_insert_document()`, and
  `_commit_url_transaction()` is `ingest_url_group()` in this same file (per the plan's
  Affected-areas Blast Radius note) — no external module needs updating solely because
  of this file's signature changes.
- `tests/rag/ingestion/test_ingester.py`, `test_rag_ingester.py`, and
  `test_rag_ingester_callback.py` (separate documents/out of scope here) must supply
  `fetched_at` in their fixtures/call sites once these signatures no longer accept
  `None`.

## Rollback considerations

- This file is the highest-churn file in the plan's Affected areas (60 commits total,
  single effective author across name-casing variants) — per the plan's own Risk
  mitigation, implement this file's changes as their own independently revertable
  commit, separate from `document_manager.py`/`etag_manager.py` (Phase 3) and from

  this file can be reverted without discarding unrelated changes.
- If reverted, restore both the `cursor2` branch and the `.get("fetched_at")` read

  `None`-tolerant behavior inconsistently (e.g. a `None` passed into a
  no-longer-nullable `_insert_document()` signature).
