## Goal

Add `--no-namespace-packages` flag to myPy invocations to eliminate the "Source file found twice under different module names" error caused by `shared.tool_constants` being detected via both `mypy_path = scripts` and `files = ["scripts/"]`. (REQ-001; REQ-002; REQ-003)

## Scope

- Modify `pyproject.toml`: add `--no-namespace-packages` to myPy invocation (via CLI option in `[tool.mypy]` section or wrapper script)
- Modify `.github/workflows/ci.yml`: add `--no-namespace-packages` to CI myPy step
- Modify `tox.ini`: add `--no-namespace-packages` to local typecheck command

## Assumptions

- `--no-namespace-packages` does not break myPy's ability to handle other namespace packages in the project
- The flag can be added via CLI option without requiring changes to `pyproject.toml`'s `[tool.mypy]` section
- `--no-namespace-packages` is available in the myPy version used by CI (confirmed: myPy 2.1.0 supports it)
- Runtime imports (`from shared.tool_constants import ...`) continue to work with `PYTHONPATH=scripts`

## Design decisions

- Add `--no-namespace-packages` as a CLI option rather than modifying `pyproject.toml`'s `[tool.mypy]` section, because:
  1. The conflict is specific to how myPy resolves `shared.tool_constants`, not a general package resolution issue
  2. Adding it as a CLI option avoids polluting the config with a workaround for a single known conflict
  3. Both CI and local workflows can adopt the same approach consistently

## Alternatives considered

- Modifying `pyproject.toml`'s `[tool.mypy]` section directly: rejected because the flag is a CLI-only option, not a TOML setting
- Removing `mypy_path = scripts`: rejected during adversarial verification — `files = ["scripts/"]` still detects `shared` as top-level package
- Adding `shared/` to myPy's ignore list: rejected during adversarial verification — does not resolve the conflict
- Using `--explicit-package-bases`: rejected during adversarial verification — does not resolve the conflict

## Compatibility considerations

- Backward-compatible: `--no-namespace-packages` disables PEP 420 namespace package support, which prevents myPy from treating directories without `__init__.py` as namespace packages. In this case, it prevents myPy from finding `shared` as a top-level package when scanning `scripts/`, eliminating the duplicate detection.
- Runtime behavior is unchanged — this is purely a static analysis fix.

## Security considerations

No new secrets exposure or unsafe operations introduced. The flag only affects myPy's internal package resolution logic.

## Rollback considerations
