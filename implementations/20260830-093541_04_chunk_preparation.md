## Goal

Isolate chunk creation logic from `ingester.py` into `scripts/rag/ingestion/chunk_preparation.py`, creating `ChunkFactory` as the single source of truth for preparing chunks for insertion.

## Scope

- Create `scripts/rag/ingestion/chunk_preparation.py` with `ChunkFactory` class
- Move `_prepare_chunks` method to `ChunkFactory.prepare()`
- Update imports in `ingester.py` to use `ChunkFactory`
- Write tests in `tests/test_ingester_chunk_preparation.py`

## Assumptions

- `PreparedChunk` DTO remains in `ingester.py` (consumed by transaction commit downstream)
- `IngestionFailureReason` enum values are shared across modules
- `EmbeddingService` is injected via dependency injection rather than owned by `ChunkFactory`
- `ThreadPoolExecutor` is created within `ChunkFactory.prepare()` (not passed in)
- `read_chunk_json` is called internally by `ChunkFactory`

## Design decisions

- `ChunkFactory` owns the parallel embedding orchestration — it creates the executor, dispatches work, and collects results
- `prepare()` returns `(prepared_chunks, prepared_paths, failed_paths_with_reasons, embed_failed_count)` — same contract as current `_prepare_chunks`
- Thread pool size (`max_workers`) is configurable via constructor
- Failure categorization (parse vs embedding vs unexpected) is preserved exactly as-is

## Alternatives considered

- **Pass executor into ChunkFactory**: Would allow caller to manage thread pool but couples caller to threading details. Rejected — factory should own its execution model.
- **Async chunk preparation**: Would improve throughput but changes the public contract. Deferred to a later refactor.
- **Separate ChunkPreparer for single-chunk work**: Would isolate single-chunk embedding but adds unnecessary abstraction layer. Rejected — batch operation is the primary use case.
