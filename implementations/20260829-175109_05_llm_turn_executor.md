# Implementation Procedure: scripts/agent/llm_turn_executor.py

## Goal

Create `llm_turn_executor.py` with the LlmTurnExecutor class owning `_handle_llm_turn`, `_call_on_llm_wait_end`, `_call_on_turn_end`, `_call_on_error`, and related LLM streaming and result processing logic extracted from Orchestrator.

## Scope

- Create `scripts/agent/llm_turn_executor.py` only. No other source file is modified by this document.
- The LlmTurnExecutor class owns exactly one concern: LLM streaming and result processing.
- Methods moved from orchestrator.py lines 491, 496, 501, 506.

## Assumptions

- LlmTurnExecutor receives AgentContext via constructor injection (same as Orchestrator).
- `LLMTurnRunner` ownership remains in Orchestrator; LlmTurnExecutor does not own it.
- `ToolLoopGuard` ownership remains shared between Orchestrator and LLMTurnRunner.
- `DiagnosticStore` ownership remains in Orchestrator.
- Callbacks (`on_turn_start`, `on_turn_end`, `on_error`, `on_llm_wait_start`, `on_llm_wait_end`) are passed through to LlmTurnExecutor rather than consumed directly by Orchestrator.

## Design decisions

1. **LlmTurnExecutor owns LLM streaming and result processing**: The class encapsulates all methods related to LLM turn execution, including callback invocation and result handling.
2. **Constructor injection for dependencies**: AgentContext, callbacks, and required services are injected via `__init__`. This enables independent instantiation and testing.
3. **No circular imports**: LlmTurnExecutor depends only on shared types (AgentContext, TurnResult, etc.) and never imports Orchestrator itself.
4. **Callback delegation**: Callback helpers (`_call_on_*`) are moved here because they are tightly coupled to LLM lifecycle events.

## Alternatives considered

1. **Merge LlmTurnExecutor + TurnCoordinator**: Would reduce the number of new files but violates the Single Responsibility Principle that motivated this refactor. Rejected per plan's design intent.
2. **Keep `_handle_llm_turn` in Orchestrator**: Would reduce refactoring effort but leaves the file at > 700 lines. Rejected because it defeats the purpose of the refactor.
3. **Make LlmTurnExecutor a mixin or base class**: Would introduce inheritance complexity without benefit. Composition is simpler and more testable. Rejected.

```python
class LlmTurnExecutor:
    """Owns LLM streaming and result processing: turn execution, callback invocation, error handling.

    Extracted from Orchestrator to isolate LLM lifecycle management.
    """

    def __init__(
        self,
        ctx: AgentContext,
        *,
        llm_runner: LLMTurnRunner,
        guard: ToolLoopGuard,
        diagnostic_store: DiagnosticStore,
        tracer: Any = None,
        on_llm_wait_start: Callable[[], Any] | None = None,
        on_llm_wait_end: Callable[[], None] | None = None,
        on_turn_start: Callable[[], None] | None = None,
        on_turn_end: Callable[[], None] | None = None,
        on_error: Callable[[Exception], None] | None = None,
    ) -> None:
        self._ctx = ctx
        self._llm_runner = llm_runner
        self._guard = guard
        self._diagnostic_store = diagnostic_store
        self._tracer = tracer
        self._on_llm_wait_start = on_llm_wait_start
        self._on_llm_wait_end = on_llm_wait_end
        self._on_turn_start = on_turn_start
        self._on_turn_end = on_turn_end
        self._on_error = on_error

    def call_on_llm_wait_end(self) -> None:
        """Invoke on_llm_wait_end if configured."""
        ...

    def call_on_turn_end(self) -> None:
        """Invoke on_turn_end if configured."""
        ...

    def call_on_error(self, exc: Exception) -> None:
        """Invoke on_error with exc if configured."""
        ...

    async def handle_llm_turn(self, llm_url: str) -> TurnResult:
        """Execute an LLM streaming turn with wait/start/end callbacks and error handling."""
        ...
```
