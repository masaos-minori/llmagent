## Goal

Make `deploy/init_db.sh` deterministically initialize the dedup store (identity row, `user_version` stamp, installation marker) through the shared loader path at deploy time, and document the operator-resolution step (REQ-005, REQ-007, REQ-011; AC-5, AC-10).

## Assumptions
- Row 01 provides the loader/creation path (`load_dedup_config` + store open creating identity, stamp, marker in one sequence); the script only invokes it and verifies creation.
- `deploy.sh` already copies `config/mcp_dedup.toml` (verified: deploy.sh:153-154 file-level copy); no deploy.sh change is in this Plan's scope.
- Existing `tests/deploy/` gate tests must keep passing; if they cannot cover the new step without modification, that is an additional-target-file discovery — stop and report Blocked for a Plan amendment (`tools/amend_plan.py`), do not edit unlisted test files.

## Design decisions
- Initialize via a short `uv run python -c` (or module `__main__`) invocation against `LLMAGENT_CONFIG_DIR`/`/opt/llm/config/mcp_dedup.toml` rather than raw `sqlite3` DDL in the shell — the script must not duplicate canonical DDL (ADR-008 schema authority).
- The script's sandbox contract (honors `DEPLOY_SCRIPTS`/`DEPLOY_DB`/`LLMAGENT_CONFIG_DIR`, as the existing schema-gate tests rely on) extends to the dedup step.

## Alternatives considered
- Lazy first-use creation only: rejected by REQ-011 — deploy must prove creation deterministically, and first initialization is the only state where creation is legal.

## Implementation

### Procedure

### Method

Add an init step that opens (and thereby creates, when first initialization) the dedup store through the shared loader with the resolved config; fail the script if the state is anything but `first_initialization` or `healthy` (e.g. `legacy_or_unverified` on an old pre-change file must abort with the archive-and-recreate message).

## Compatibility considerations
- A pre-existing pre-change store file causes an explicit abort (legacy gate), never a silent mutation (ADR-008: the software never mutates/archives/deletes databases; the operator does).

## Security considerations
- Deterministic creation at deploy time removes the race where the first tool call under load creates the store mid-dispatch.
