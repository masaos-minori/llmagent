## Goal

Install one total exit bracket in `AgentREPL.run()`: the session-persist step is
reached on every exit path, from one `finally`, **before** `close_resources()`
(REQ-001, REQ-010); remove the `persister_callback` indirection so `ReplInputLoop.run()`
owns no persistence step (REQ-002); and guard the persist call so a persistence
failure cannot replace the exception the process was already propagating
(REQ-004).

## Scope

Production behavior change to `scripts/agent/repl.py` only. Reference reads:
`scripts/agent/repl_input_loop.py` (the parameter/`finally` being removed, row 2),
`scripts/agent/session_persister.py` (the gate added in row 3). Dependent test:
`tests/agent/test_repl.py`.

## Assumptions

- `_persist_after_loop` (`repl.py:104-107`) is called only via the second positional
  argument of `self._input_loop.run(...)` (`:154-157`); no other caller exists
  (`grep -rn "_persist_after_loop" tests/` is empty — confirm before renaming).
- `ReplInputLoop.run()` keeps its remaining `banner_callback` parameter and every
  other statement; only the `persister_callback` parameter and its `finally` go
  (REQ-002, row 2).
- The persist methods read `ctx.services.*` clients that `close_resources()`
  releases, so persist must run **before** `close_resources()` (Design → invariant).

## Design decisions

- Replace the `finally` at `:158-159` (`await self._shutdown.close_resources()`) with
  a `finally` that first awaits `self._persist_session_state()` guarded by a
  `try/except` that reports via `self._view.write_warning(...)` with
  `OutputTag.NON_FATAL` and swallows, then awaits `close_resources()`. The guard is
  what makes REQ-004 hold: a persist raise no longer replaces the in-flight
  exception.
- Delete the `persister_callback` argument from the `run()` call site (`:154-157`),
  leaving only the `banner_callback` positional argument.
- Rename `_persist_after_loop` → `_persist_session_state`; the old name states a
  control-flow position (`after the loop`) that no longer exists once the step lives
  in `run()`'s outer `finally`.
- Replace the nesting comment at `:122-124` with a comment stating the order the
  bracket now enforces (persist, then close) and why (persist reads clients that
  close releases; REQ-009).

## Alternatives considered

- Keeping persist in `ReplInputLoop.run()`'s `finally` — rejected: that is the exact
  asymmetry REQ-001 removes (persist unreachable when the loop is never entered).
- Guarding inside `_persist_session_state` instead of in `run()`'s `finally` — the
  guard belongs where the in-flight exception lives, i.e. `run()`'s `finally`, so the
  AC-4 witness (persist raises while the loop raises) is tested at the bracket.

### Procedure

   update its docstring from "after the REPL loop ends" to a position-neutral

2. **Delete** the `persister_callback` argument at the call site (`:154-157`):
   ```python
   await self._input_loop.run(
       lambda: self._banner.print_startup_banner(self._orchestrator),
   )
   ```
3. **Rewrite** the `finally` (`:158-159`) to persist-then-close, guarded:
   ```python
   finally:
       # Persist before closing resources: persistence reads ctx.services clients
       # that close_resources releases. Contain failures so a persist error cannot
       # replace the exception the process was already propagating (REQ-004).
       try:
           await self._persist_session_state()
       except Exception as e:  # noqa: BLE001 — persist is non-fatal; never mask the in-flight exception
           self._view.write_warning(
               f"{OutputTag.NON_FATAL} Session persistence failed: {type(e).__name__}: {e}"
           )
       await self._shutdown.close_resources()
   ```
4. **Replace** the nesting comment at `:122-124` with the order the bracket now
   enforces (see Details).

### Details

- The `try/except` around persist uses a broad `Exception` guard deliberately:
  REQ-004 requires that *any* persist failure be contained, not just DB errors, so
  the payload-building body (row 3 widens `session_persister`'s own guard) cannot
  escape either. Keep the `# noqa: BLE001` annotation consistent with the file's
  existing shutdown-path suppression style.
- New comment replacing `:122-124`:
  ```python
  # One finally for the whole session: persist session state, then close resources.
  # Both run on every exit path (startup failure/interrupt, normal exit); persist is
  # first because it reads ctx.services clients that close_resources releases, and it
  # is contained so a persist failure cannot replace the in-flight exception.
  ```
