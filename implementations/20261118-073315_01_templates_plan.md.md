## Design decisions

- Use one canonical wording, copied verbatim into the three places (this template, `skills/issue-to-plan/workflow.md`, and the `tools/TOOL_DESCRIPTIONS.md` row — sibling procedure documents): "A Plan that must wait for another Plan or Issue records it as a structured `Depends on` bullet. The prose `Dependencies` line never names another Plan or Issue by path; a compatible overlap or a sequencing-only note names the other Plan by title or id, because `tools/plan_dependency_order.py` reads every `plans/` or `issues/` `.md` path in that line as a dependency on phase `all`." (Plan Implementation Intent, one rule)
- Copying the Issue's Dependencies stays allowed, with the transformation stated: each ordering dependency becomes a `Depends on` bullet; each non-ordering mention is written by title or id. (Plan Implementation Intent)
- The guidance stays in the existing bracket notes of the two Scope lines rather than in a new section, so the Plan shape and the checker's heading set are unchanged.

## Alternatives considered

- Marker-free prose (keep "copy the Issue's Dependencies" and warn elsewhere). Rejected: the copy instruction is where the path gets written; the rule must sit at the point of writing (Plan Problem).
