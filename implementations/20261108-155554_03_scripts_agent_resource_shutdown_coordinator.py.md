## Goal
Give `ResourceShutdownCoordinator` a close-hook registration API and run registered hooks last in `close_resources`, so the workflow store is closed after every turn-processing shutdown step in the correct order (`REQ-003`).

## Scope
**Release unit**: wfaudit006-full

- Covers Plan `plans/20261108-084008_wfaudit006_state-store-lifecycle-ownership.md` row 3 only: `scripts/agent/resource_shutdown_coordinator.py`.

## Assumptions
- The registration itself is performed by sibling procedure 04 in `scripts/agent/repl.py` after startup: the coordinator is constructed at `repl.py` L88, before the orchestrator exists, and cannot reach it through `AgentContext` (plan Notes 2026-11-08). This procedure adds only the coordinator-side API and execution point.
- Hooks are synchronous zero-argument callables: the orchestrator `close` added by sibling procedure 02 is synchronous (a SQLite close); an async hook would need a different contract and none exists today.
- Sibling procedures 134201_* and 135741_* (wfaudit001/wfaudit007) do not edit this file; line numbers refer to HEAD `ad48bfa28`.

## Design decisions
- Generic registered hooks (a name plus a synchronous callable list) rather than an orchestrator-specific setter: the coordinator stays agnostic about which component it hosts, and future closable owners register the same way (plan Design: "adding the workflow store as a registered resource").
- Hooks run at the end of `close_resources`, after background-task cancellation and service lifecycle/http shutdown: this pins the plan's Risk mitigation ordering (turn-processing resources close before the store).
- Hook failures follow the file's existing record-and-continue shutdown policy: the error is appended to the `errors` list and logged; it never propagates and never skips the remaining hooks.

## Alternatives considered
- Closing the store directly in `repl.py`'s finally before `close_resources`: rejected — it would close the store while background tasks and services are still being settled and would bypass the coordinator that owns shutdown ordering (plan Design "Shutdown wiring").
- Extending the constructor signature with an orchestrator parameter: rejected — the orchestrator does not exist when `AgentREPL.__init__` builds the coordinator, and a post-construction registration is the only order-preserving option.

### Method
1. Add `from collections.abc import Callable` (new) to the import block.
2. In `__init__`, initialize `self._close_hooks` (new) as an empty list of `(name, hook)` pairs typed `list[tuple[str, Callable[[], None]]]`.
3. Add `register_close_hook` (new): `def register_close_hook(self, name: str, hook: Callable[[], None]) -> None:` appending `(name, hook)` to `self._close_hooks`.
4. In `close_resources`, after the service-shutdown block (the `svc` gather / `else: logger.debug` branch) and before the `if errors:` summary, iterate `self._close_hooks` in registration order: call each hook; on exception append an error tuple labeled "close_hook" (the new label string, paired with `f"{name}: {type(e).__name__}: {e}"`) to `errors` and `logger.error` the same failure, then continue with the next hook.
