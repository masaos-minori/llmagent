## Goal

Make `fetched_at` generation in `scripts/rag/ingestion/crawler.py` canonical UTC
(`YYYY-MM-DDTHH:MM:SSZ`) at both `CrawlPayload` construction sites, and make the
local `file://` source path derive `fetched_at` from the file's `stat.st_mtime`
instead of wall-clock `datetime.now()`, so that `fetched_at` is a single,
non-nullable, UTC-normalized value at its point of origin.

## Scope

- In scope: `scripts/rag/ingestion/crawler.py` only — the two `fetched_at`
  value-generation expressions inside `crawl_file()` (local `file://` path) and
  `_save_crawl_file()` (HTTP path), and the `datetime` import statement that
  supports them.
- Out of scope: `CrawlPayload`'s field declarations (already a required `str`,
  no widening needed — see Assumptions), and any consumer of the generated
  value (`pipeline_utils.py`, `chunk_splitter.py`, `ingester.py`, etc. — each
  has its own implementation document).

## Assumptions

- `CrawlPayload` (a `TypedDict` defined in this file) already declares
  `fetched_at: str` as a plain required field, not `NotRequired[...]` — this
  is confirmed by reading the class body; only the *value*-generation logic
  changes, not the type declaration.
- `crawler.py` currently imports only `from datetime import datetime` (no
  `UTC`); this import must be widened to `from datetime import UTC, datetime`.
- `crawl_file()` already computes `stat = path.stat()` earlier in the function
  body (used today to build `mtime_iso` for the `last_modified` field) — the
  same `stat` object can be reused for the new `fetched_at` derivation without
  a second filesystem call.
- Per the plan's UNK-03 / Risks, a sibling plan
  (`plans/20260820-094150_plan.md`) may already have replaced `CrawlPayload`
  with `CrawlJsonPayload` by the time this document is executed. The
  implementer must check this before starting and, if so, retarget the same
  two-line edits to the renamed type's construction sites.

## Design decisions

- Generate `fetched_at` at each of the two existing construction sites
  independently (no shared helper) — both sites already have direct access to
  everything needed (`datetime.now(UTC)` for the HTTP path, the local `stat`
  object for the file path), and introducing a helper for two call sites is
  not justified (YAGNI).
- Derive the local `file://` case from `stat.st_mtime` rather than wall-clock
  time — this makes `fetched_at` and `last_modified` both mtime-derived for
  file sources, removing the latent inconsistency the plan's Goal explicitly
  calls out (today `fetched_at` uses `now()` while `last_modified` uses
  `mtime`).
- Widen the import to `from datetime import UTC, datetime` (not
  `datetime.timezone.utc`) — matches the existing import pattern already used
  in `scripts/rag/ingestion/etag_manager.py`, keeping timestamp-handling style
  consistent across the `rag` package.

## Alternatives considered

- Using `datetime.now(UTC).isoformat()` (produces a `+00:00` suffix) instead
  of `.strftime("%Y-%m-%dT%H:%M:%SZ")` — rejected because the plan's canonical
  form explicitly specifies a literal `Z` suffix, matching the format already
  used elsewhere in the schema (e.g. `schema_sql.py`'s prior
  `strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` default).
- Deriving the HTTP path's `fetched_at` from an HTTP response header (e.g.
  `Date`) instead of local wall-clock time — rejected: `fetched_at` is meant
  to represent when the crawler acquired the resource, not a server-reported
  time, and the HTTP path already has a separate `last_modified` field for
  server-reported freshness.

## Implementation

### Target file

`scripts/rag/ingestion/crawler.py`

### Procedure

1. Widen the datetime import from `from datetime import datetime` to
   `from datetime import UTC, datetime`.
2. In `crawl_file()` (the local `file://` path): replace the `fetched_at`
   assignment currently using `datetime.now().isoformat(timespec="seconds")`
   with a UTC value derived from the already-computed `stat` object's
   `st_mtime`, formatted as
   `datetime.fromtimestamp(stat.st_mtime, UTC).strftime("%Y-%m-%dT%H:%M:%SZ")`.
3. In `_save_crawl_file()` (the HTTP path): replace the `fetched_at`
   assignment currently using `datetime.now().isoformat(timespec="seconds")`
   with `datetime.now(UTC).strftime("%Y-%m-%dT%H:%M:%SZ")`.
4. Before starting steps 2-3, confirm whether `plans/20260820-094150_plan.md`
   has already landed (per UNK-03 / Risks in the source plan); if `CrawlPayload`
   has been replaced by `CrawlJsonPayload`, apply the same two edits at the
   renamed type's construction sites instead.
5. Do not touch `CrawlPayload`'s `fetched_at: str` field declaration — it is
   already a required field (see Assumptions); no widening is needed.

### Method

- Treat this as a minimal, localized value-generation substitution at each of
  the two existing assignment expressions — not a refactor of the surrounding
  function bodies, signatures, or the `CrawlPayload` type itself.
- Reuse existing local state (`stat`, `datetime`) rather than introducing new
  parameters, helper functions, or class attributes.

### Details

- `crawl_file()`: the `stat = path.stat()` call already present earlier in the
  function (used to build `mtime_iso` for `last_modified`) must be reused for
  `st_mtime` — do not call `path.stat()` a second time.
- `crawl_file()`'s `mtime_iso` variable (used for the `last_modified` field)
  keeps its current naive-local `isoformat(timespec="seconds")` format —
  this document changes only the `fetched_at` expression, not `mtime_iso` or
  `last_modified`.
- `_save_crawl_file()` has no `stat`/mtime available — it is the HTTP path,
  so `fetched_at` here correctly represents crawl wall-clock time via
  `datetime.now(UTC)`; no mtime derivation applies to this call site.
- Neither function's signature, parameters, or return type changes; both
  continue to construct the same `TypedDict` shape with the same key set.

## Compatibility considerations

- `CrawlPayload.fetched_at`'s declared type is unchanged (`str`); only the
  runtime value's format changes, from a naive-local ISO string (no timezone
  marker) to canonical UTC (`...Z`). Any downstream code parsing this value
  with a format string that lacks the `Z` suffix would need adjustment — the
  only such consumer is `pipeline_utils.py::read_json_file()`, updated in its
  own implementation document.
- Per the source plan's Assumptions, no on-disk `rag-src/*.json` file from a
  prior crawl needs to remain readable after this change — no legacy-data
  compatibility constraint applies.
