## Design decisions

- Resolve UNK-01 by evidence rather than by choosing a label in advance: the postcondition paragraph is
  written after reading `scripts/mcp_servers/mdq/indexer.py` refresh path and
  `scripts/mcp_servers/mdq/mdq_security_validation.py::_index_check`.
- Distinguish a consistency check from a postcondition verification: a check that flags an index holding
  no rows while documents exist is not a comparison of one operation's resulting state with its expected
  state, and the document must not claim the latter from the former.

## Alternatives considered

- Record postcondition verification as implemented because a refresh summary and an index check exist:
  rejected — the Plan's UNK-01 entry explicitly forbids claiming implemented without a comparison.
- Record it as absent: rejected — it would erase the reporting that does exist.
