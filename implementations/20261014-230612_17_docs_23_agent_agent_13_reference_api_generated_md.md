## Assumptions

- The doc is auto-generated by `python tools/generate_reference_table.py --type agent`, which crawls `scripts/agent/*.py` (non-recursive) top-level **public** classes/functions via `ast.parse` (no import/execution needed) and writes a table between the `<!-- AUTO-GENERATED: generate_reference_table.py agent-class-function-reference -->` / `<!-- END AUTO-GENERATED -->` guards.
- It extracts only top-level symbols; methods inside class bodies are NOT individually listed. So method-signature changes (e.g. `AgentSession.fetch_messages`, `undo_last_turn`) are not captured here — only top-level symbol changes are.

## Design decisions

- Regenerate mechanically from live code after the code changes (rows 01-16) are applied; do not hand-edit the guarded section.
- Rely on the generator's existing behavior; the changed top-level symbols will appear automatically.

## Alternatives considered

- **Hand-edit the reference table** — rejected: the doc is machine-generated between guards; hand edits would be overwritten on the next generation and violate the doc's own "do not hand-edit" notice.

### Method

- Run the generator. It rewrites the guarded section in place.
- Inspect the diff to confirm the changed top-level symbols are reflected:
  - `UndoResult` (models.py): now carries `block_reason: str | None` (row 06).
  - `ConversationState` (context.py): now has `undo_floor: int = 0` (row 04).

### Details

- Because the generator skips class methods, method-level changes (rows 02/03/05) are NOT reflected here by design. If method signatures must be documented, they belong elsewhere (not this auto-generated table).
- The generator uses `ast.parse`; it does not import `scripts/agent/*`, so it runs even without runtime deps. Prefer `uv run` for environment consistency.
- Do not touch any other doc or the non-guarded portion.
