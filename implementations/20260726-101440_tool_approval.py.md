# Implementation procedure: scripts/agent/tool_approval.py

## Goal

Remove the dead `skip_in_workflow_mode` parameter (and its early-return
branch) from `tool_approval.run_approval_checks()`, since it is confirmed
unused by any real caller and is not being repurposed as part of the
companion `RepositoryGateway._gate_write()` de-duplication change.

## Scope

- In scope:
  - `scripts/agent/tool_approval.py::run_approval_checks()` — remove the
    `skip_in_workflow_mode: bool = False` parameter and the
    `if skip_in_workflow_mode: ... return tool_calls, []` block at the top
    of the function body.
  - `tests/test_tool_approval_paths.py` — delete
    `TestRunApprovalChecksSkipInWorkflowMode` (2 tests: lines ~187-223)
    which call `run_approval_checks(..., skip_in_workflow_mode=True/False)`
    directly.
- Out of scope:
  - `check_approval()`, `_prompt_user_approval()`, risk classification
    (`tool_policy.py`) — unchanged.
  - The two call sites of `run_approval_checks()`
    (`tool_runner.py:486`, `repository_gateway.py:106` prior to its
    removal there) — neither passes `skip_in_workflow_mode` today, so no
    other production code needs updating.
  - `docs/*.md` updates (document-only phase; not permitted in this cycle).

## Assumptions

1. `skip_in_workflow_mode` is never set to `True` by any caller anywhere
   in the codebase (confirmed by the source plan's U2 via
   `grep -rn "run_approval_checks(" scripts/agent`: exactly two call
   sites, neither passes the keyword, so both use the default `False`).
2. `run_approval_checks` is an internal `agent.*` module function with
   only two production call sites, both inside `scripts/agent/`, and is
   not re-exported via any `__init__.py` public API surface — so removing
   the parameter cannot break an external/plugin caller.

## Design decisions

- Remove the parameter outright rather than repurpose it as the
  deduplication mechanism for the companion `_gate_write()` change: the
  chosen fix (Option (b) in the source plan) eliminates the redundant
  call site instead, so `skip_in_workflow_mode` has no remaining purpose
  and should not be left as dead configuration surface (ruff/vulture
  would otherwise flag it, and it actively misleads readers about a
  "workflow-mode skip" feature that was never wired up).

## Alternatives considered

- **Keep the parameter but stop calling it with a truthy value anywhere**:
  rejected — leaves dead, confusing signature surface; the source plan's
  Implementation Instructions explicitly call for removal once confirmed
  unused.
- **Repurpose `skip_in_workflow_mode` as the single-gate signal itself**
  (i.e. have `RepositoryGateway` pass `skip_in_workflow_mode=True`):
  rejected in favor of deleting the redundant call site entirely (Option
  (b)), which removes more code and more failure surface than keeping a
  flag that must always be `True` from one caller.

## Implementation

### Target file

`scripts/agent/tool_approval.py` (plus `tests/test_tool_approval_paths.py`)

### Procedure

1. In `run_approval_checks()`'s signature (currently line 190-194), delete
   the `skip_in_workflow_mode: bool = False` parameter (and its trailing
   comment `# When True, skip per-tool approval (workflow-level approval
   is active)`).
2. Delete the `if skip_in_workflow_mode: logger.debug(...); return
   tool_calls, []` block (currently lines 200-202) from the top of the
   function body, leaving the existing per-call loop
   (`approved_calls`/`denied_ids` construction) as the sole behavior.
3. Update the function's docstring if it references the parameter (it
   currently does not describe `skip_in_workflow_mode` explicitly beyond
   the inline comment on the parameter itself, so no separate docstring
   line is expected to need editing — verify at implementation time).
4. In `tests/test_tool_approval_paths.py`, delete the
   `TestRunApprovalChecksSkipInWorkflowMode` class in its entirety
   (both `test_run_approval_checks_skips_when_workflow_mode_active` and
   `test_run_approval_checks_not_skipped_by_default`, currently lines
   187-223), and the preceding section comment
   `# ── run_approval_checks(): skip_in_workflow_mode ──...` if it becomes
   orphaned.
5. Confirm no other test in `test_tool_approval_paths.py` or elsewhere
   (`test_tool_approval_preflight.py`, `test_tool_approval_risk.py`,
   `test_tool_approval_repos.py`) passes `skip_in_workflow_mode` as a
   keyword argument — a targeted grep for the string across `tests/`
   should return no remaining matches after this change.

### Method

Direct signature simplification (drop one parameter and its guard
clause) plus deletion of the two tests that exercise it. No new
abstractions.

### Details

- Post-change signature:
  `async def run_approval_checks(ctx: AgentContext, tool_calls: list[dict]) -> tuple[list[dict], list[str]]:`
- The remaining body is unchanged (plan-mode block check, per-call
  `check_approval()` loop, masked-args preview, denied-id accumulation).

## Compatibility considerations

- Public-signature change: any caller passing `skip_in_workflow_mode` as
  a keyword argument would now raise `TypeError`. Per Assumptions 1-2,
  no such caller exists in production or test code outside the two tests
  being deleted here.
- A full-suite `pytest -q` run (validated jointly across all three docs
  in this cycle) would surface any missed caller as an immediate
  `TypeError` failure.

## Security considerations

- N/A — this is a dead-parameter removal with no behavioral or
  policy-enforcement change; the remaining approval logic (plan-mode
  block, `check_approval()` per call) is untouched.

## Rollback considerations

  deletion: re-add the `skip_in_workflow_mode` parameter, its guard
  clause, and the deleted test class. No data migration, no config, no
