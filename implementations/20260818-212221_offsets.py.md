## Goal

Guarantee that `write_offset()` never lowers a consumer's committed offset, preventing duplicate message delivery caused by out-of-order acknowledgments.

## Scope

**In-Scope:**
- Modify `write_offset()` in `scripts/eventbus/offsets.py` to enforce non-decreasing offset semantics.
- Add regression unit test in `tests/eventbus/test_eventbus_offsets.py`.

**Out-of-Scope:**
- Changes to the SSE subscribe loop or replay logic.
- Changes to the `/publish` or `/ack` HTTP endpoints.
- Migration of existing offset files.

## Assumptions

- `read_offset()` always returns a valid integer (0 on missing/invalid file) — verified by existing callers.
- The offset file is single-writer per consumer_id — confirmed by the app-level singleton broker pattern.
- Existing integration tests (`test_ack_writes_offset`, `test_reconnect_resume_via_consumer_id`) will continue to pass since they only exercise forward-progress scenarios.

## Design decisions

- Enforce monotonicity at write time by comparing against current offset before writing — simplest approach, no schema changes needed.
- Skip out-of-order writes silently except for logging — avoids blocking the consumer while maintaining audit trail.
- Use `logger.warning()` for skipped writes — provides operator visibility without changing behavior for normal flow.

## Alternatives considered

- File locking for concurrent access — rejected because the plan assumes single-writer per consumer_id; adding file locks adds complexity without solving the core issue (out-of-order acks within same writer).
- Atomic compare-and-swap via file locking — deferred to future if multi-process consumers become necessary; not needed now.
- Rejecting out-of-order writes with an error — rejected because it would break the consumer; skipping is safer and preserves data integrity.

```python
class TestOffsetMonotonicity:
    def test_write_offset_prevents_backward_jump(self, tmp_path):
        """Verify write_offset() does not lower a consumer's committed offset."""
        offsets_dir = str(tmp_path / "offsets")
        os.makedirs(offsets_dir)
        
        # Write a higher offset first
        write_offset(offsets_dir, "consumer_1", 100)
        assert read_offset(offsets_dir, "consumer_1") == 100
        
        # Attempt to write a lower offset — should be ignored
        write_offset(offsets_dir, "consumer_1", 50)
        assert read_offset(offsets_dir, "consumer_1") == 100
```

### Details

- `read_offset()` returns 0 for missing/invalid files, so the first write always succeeds.
- Monotonicity check happens BEFORE the write — prevents partial state corruption.
- Warning log includes both values for easy debugging of out-of-order scenarios.
- Test uses `tmp_path` fixture for deterministic isolation.
