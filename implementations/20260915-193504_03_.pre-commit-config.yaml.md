- Sibling procedure 01's script is importable as `python -m
  tools.check_adr_structure` (module-level `main()` guarded by `if __name__
  == "__main__":`), matching the two precedent hooks' invocation style.

## Design decisions
- New hook id: `adr-structure` (short, matches the `adr-*` naming family).
- `name`: "Check ADR Known Deviations heading and Implementation Notes/References drift" — describes both checks (a) and (b) concisely, mirroring how `adr-reference-scoped`'s name describes its one check.
- Insert immediately after the `adr-reference-scoped` hook (end of the `repo: local` hooks list) — new entries in this file have consistently been appended at the end of the relevant block across this session's prior docqa work.
- `types_or: [python, markdown]` — copied verbatim from both precedent hooks, even though this checker only reads `docs/adr/*.md` (markdown): keeping the same trigger set as its two closest siblings avoids a narrower, inconsistent trigger surface, and re-running on unrelated python changes is cheap (pure read, no I/O beyond `docs/adr/`).

## Alternatives considered
- Narrow `types_or` to `[markdown]` only, since the checker never reads `.py` files — rejected: `adr-invariant-matrix`/`adr-reference-scoped` both keep `[python, markdown]` despite similarly reading mostly-markdown content, for consistency with how ADR citations can appear in either file type; deviating here would be an unexplained inconsistency in the hook family.
