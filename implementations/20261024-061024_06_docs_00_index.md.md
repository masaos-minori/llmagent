## Design decisions

- **Add both the `related:` entry and the task-scope row.** `related:` is the structured cross-reference store
  (`governance_02_documentation-metadata.md:30-32`) that the change-impact tooling reads, while the `#### Agent` table
  is the human navigation surface the frozen row names ("no row that names history compression"). A table row alone
  leaves the chapter absent from the cross-reference graph; a `related:` entry alone leaves the stated gap open.
- **Insert the `related:` entry after `:32`, next to the `agent_04_01` state-and-persistence sibling.** `related:` order
  carries no semantics: `governance_02_documentation-metadata.md:30-42` constrains self-references and duplicates, not
  ordering, and `tools/manage_frontmatter.py`'s `merge-related` preserves existing entry order (`plan_related_merge`,
  `:565-596`). Measured: `merge-related docs/00_index.md --dry-run` reports `0 file(s) would change` at HEAD, so no
  migration tool rewrites this block.
- **Bare basename in `related:`, path form in the table.** `_validate_related_format`
  (`tools/check_docs_structure.py:215-231`) rejects a `related:` entry containing `/` or `#` and requires `.md`, while
  every existing task-scope row cites the domain-folder path (`23_agent/agent_04_01_state-and-persistence-state-model.md`
  at `:142`). Using the path form in `related:` would be a new structural finding.
- **Append the new row after `:153` rather than grouping it with a related row.** The existing rows carry no ordering
  rule, and appending leaves all 12 existing rows byte-identical, which keeps the diff to two added lines.
- **Reference one document only.** Frozen row 6 names `agent_04_02`; `agent_04_01` (`:142`, `:149`) and
  `agent_12_reference-api.md` (`:147`) are already reachable, so adding them here would invent relationships the Plan
  did not establish.

### Details

- The new row's backticked names are class names without parentheses. `check_function_references` matches only
  `name()`-shaped references (`_FUNC_REF_RE`, `tools/_docs_consistency_lib.py:425`) and is not run for the overview

  `scripts/agent/` regardless.

  header row, so a stray pipe inside the scope label would be an ERROR. Keep the label to `(`, backticks, `/` and
  spaces.
- `check_content_similarity` flags section pairs whose Jaccard token overlap exceeds 0.85
  (`tools/check_docs_quality.py:238-241`); the new row's tokens (`conversation`, `history`, `compression`,
  `historymanager`, `historyselectionpolicy`) do not approach any existing row's token set, which is why the scope
  label must not reuse `Session / DB persistence` (`:151`) or `Memory layer` (`:142`) wording.
- The `related:` entry adds no duplicate finding: `check_related_links` counts duplicates only within `related:` and
  `source` (`tools/check_docs_structure.py:334-366`), and `agent_04_02_state-and-persistence-history-compression.md`
  appears nowhere in `docs/00_index.md` at HEAD (`grep -n "agent_04_02" docs/00_index.md` is empty); the table row uses
