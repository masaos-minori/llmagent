# Implementation Procedure: scripts/shared/otel_tracer.py

## Goal
Extract a shared private helper, `_attach_console_processor(...)`, that performs the duplicated
"construct `_ConsoleProcessor`, call `provider.add_span_processor`, log a message" sequence
currently duplicated between `_attach_console_exporter` (lines 100-104) and the OTLP-unavailable
fallback branch inside `_attach_otlp_exporter` (lines 110-115), without changing the exact log
text or log level emitted at either call site.

## Scope
- In scope: `scripts/shared/otel_tracer.py` — add the new helper; update
  `_attach_console_exporter` and the fallback branch of `_attach_otlp_exporter` to call it; add
  `Callable` to the existing `typing` import on line 20.
- Out of scope: the OTLP-available success path inside `_attach_otlp_exporter` (lines 117-123,
  which logs at `logger.info` with different args and does not duplicate the console-processor
  pattern); `build_tracer()`'s public signature/behavior; `_import_sdk`/`_import_otlp`;
  `_ConsoleProcessor`'s delegation methods (`on_start`/`on_end`/`shutdown`/`force_flush`) —
  all unchanged.

## Assumptions
- "Byte-identical" behavior means the fully `%`-substituted log message text is unchanged, not
  object identity of the template string (per the source plan's Assumptions section).
- The helper takes a bound logger callable (`logger.info` / `logger.warning`) rather than a
  `logging` level int, per the source requirement's explicitly allowed alternative form; this
  avoids a `getattr(logger, ...)` dispatch and keeps mypy satisfied without an overload.
- Characterization tests in `tests/shared/test_otel_tracer.py` are added/tightened *before* this
  extraction (tracked separately — see the companion procedure document for that file) so the
  refactor in this file is provably behavior-preserving.

## Design decisions
- New helper sits at the same internal layer as `_attach_console_exporter` /
  `_attach_otlp_exporter` (both call it), introducing no new import-boundary crossing — everything
  stays inside `scripts/shared/`, so `PYTHONPATH=scripts uv run lint-imports` contracts are
  unaffected.
- Message/args stay as explicit, required call-site parameters (no defaults, nothing hardcoded
  inside the helper) — this structurally discourages a future contributor from coupling the two
  call sites' log wording back together.
- Keep the existing `%`-style lazy logging calls (do not convert to f-strings), matching this
  file's pre-existing convention and preserving `logging`'s lazy-evaluation contract.

## Alternatives considered
- Passing a `logging` level int (e.g. `logging.INFO`) instead of a bound callable, requiring
  `logger.log(level, message, *args)` inside the helper. Rejected: the source requirement
  explicitly offers the bound-callable form as an equally valid alternative, and the callable form
  avoids an extra `getattr`/dispatch step.

## Implementation

### Target file
`scripts/shared/otel_tracer.py`

### Procedure
1. Add `Callable` to the existing `typing` import on line 20:
   ```python
   from typing import Any, Callable, Protocol, cast
   ```
2. Add the new private helper, placed immediately above `_attach_console_exporter` (i.e. before
   line 100):
   ```python
   def _attach_console_processor(
       provider: Any, log_fn: Callable[..., None], message: str, *args: Any
   ) -> None:
       """Attach a ConsoleSpanExporter-backed processor and log the given message."""
       processor = _ConsoleProcessor()
       provider.add_span_processor(processor)
       log_fn(message, *args)
   ```
3. Replace the body of `_attach_console_exporter` (currently lines 100-104):
   ```python
   def _attach_console_exporter(provider: Any, service_name: str) -> None:
       """Attach ConsoleSpanExporter to the given provider."""
       processor = _ConsoleProcessor()
       provider.add_span_processor(processor)
       logger.info("OTel tracer configured: ConsoleSpanExporter service=%s", service_name)
   ```
   with:
   ```python
   def _attach_console_exporter(provider: Any, service_name: str) -> None:
       """Attach ConsoleSpanExporter to the given provider."""
       _attach_console_processor(
           provider,
           logger.info,
           "OTel tracer configured: ConsoleSpanExporter service=%s",
           service_name,
       )
   ```
4. Replace the fallback branch inside `_attach_otlp_exporter` (currently lines 110-115):
   ```python
       otlp = _import_otlp()
       if otlp is None:
           provider.add_span_processor(_ConsoleProcessor())
           logger.warning(
               "opentelemetry-exporter-otlp not installed; falling back to ConsoleSpanExporter"
           )
           return
   ```
   with:
   ```python
       otlp = _import_otlp()
       if otlp is None:
           _attach_console_processor(
               provider,
               logger.warning,
               "opentelemetry-exporter-otlp not installed; falling back to ConsoleSpanExporter",
           )
           return
   ```
5. Leave `_attach_otlp_exporter`'s OTLP-available success branch (lines 117-123), `_import_sdk`,
   `_import_otlp`, and `_ConsoleProcessor` untouched.

### Method
Structural extract-method refactor: two duplicated 2-3 line sequences become calls into one new
3-line private helper. No control-flow, signature, or logging-level/text change at either call
site — verified by the characterization tests in `tests/shared/test_otel_tracer.py` run
before and after this edit.
