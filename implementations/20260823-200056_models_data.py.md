## Goal

Add a mandatory, non-nullable `fetched_at: str` field (no default) to the
`ChunkDocument` dataclass in `scripts/rag/models_data.py`, positioned
immediately after `content` and before `code_blocks`, so every constructed
`ChunkDocument` instance is required to carry the canonical acquisition
timestamp with no silent default.

## Scope

- In scope: `scripts/rag/models_data.py`, the `ChunkDocument` dataclass
  definition only.
- Out of scope: every other dataclass in this file (`EmbeddingResponse`,
  `CrawlTarget`, `ChunkRecord`, and any dataclasses below it); the call site
  that constructs `ChunkDocument` (`pipeline_utils.py::read_json_file()` —
  separate implementation document); and any further propagation of the
  field downstream.

## Assumptions

- `ChunkDocument` is `@dataclass(frozen=True)` with `code_blocks: list[str] =
  field(default_factory=list)` as its first field carrying a default. Any new
  field without a default must be declared before `code_blocks`, or the class
  definition raises `TypeError: non-default argument follows default
  argument` at import time — confirmed by reading the current field order
  (`url`, `title`, `lang`, `content`, `code_blocks=...`, `etag=None`,
  `last_modified=None`, `chunking_strategy="text"`,
  `normalized_content=None`, `chunk_index=0`, `source_file=""`,
  `chunk_type=""`).
- `ChunkDocument` is constructed at exactly one production call site,
  `pipeline_utils.py::read_json_file()`, and that call site already uses
  all-keyword arguments (`ChunkDocument(url=..., title=..., ...,
  chunk_type=...)`) — confirmed by reading the call. No test file constructs
  `ChunkDocument` directly (confirmed via repository-wide search), so no test
  fixture requires updating for this specific field-insertion change.

## Design decisions

- Position `fetched_at` immediately after `content` and before `code_blocks`
  — this is both the plan's explicit ordering requirement and the only
  placement that satisfies Python's dataclass no-default-after-default field
  ordering, since `code_blocks` is the first field with a default.
- Give `fetched_at` no default value — enforces fail-closed construction: any
  caller not yet updated to supply `fetched_at` fails immediately at
  object-construction time (`TypeError`), consistent with the plan's overall
  "propagate unchanged, fail closed" design rather than tolerating a missing
  value.
- Keep `frozen=True` and every other existing field unchanged — this is a
  pure additive field insertion, not a restructuring of `ChunkDocument`'s
  identity, equality, or immutability semantics.

## Alternatives considered

- Giving `fetched_at` a default of `""` or `None` and validating it later —
  rejected: the entire point of the source plan is eliminating
  optional/nullable defaults for `fetched_at` end-to-end; adding a default
  here would reintroduce the exact "silent null" pattern the plan removes.
- Appending `fetched_at` at the end of the field list (after `chunk_type`) —
  rejected: it would violate dataclass field-ordering rules (a non-default
  field cannot follow `code_blocks`'s default), and the plan explicitly
  specifies placement directly after `content`.

## Implementation

### Target file

`scripts/rag/models_data.py`

### Procedure

1. Locate the `ChunkDocument` dataclass definition (fields in order: `url`,
   `title`, `lang`, `content`, `code_blocks`, `etag`, `last_modified`,
   `chunking_strategy`, `normalized_content`, `chunk_index`, `source_file`,
   `chunk_type`).
2. Insert a new field `fetched_at: str` immediately after `content: str` and
   before `code_blocks: list[str] = field(default_factory=list)` — no default
   value assigned.
3. Leave every other field, the `@dataclass(frozen=True)` decorator, the
   class docstring, and every other dataclass in the file unchanged.

### Method

- Single-line field insertion into an existing dataclass body; no new import
  is required (`str` is a builtin already used by sibling fields such as
  `url`, `title`, `lang`, `content`).
- No change to the `field`/`default_factory` import already used by
  `code_blocks` — this insertion does not use either.

### Details

- Before: `content: str` is directly followed by
  `code_blocks: list[str] = field(default_factory=list)`.
- After: `content: str` is followed by `fetched_at: str` (no default), which
  is followed by `code_blocks: list[str] = field(default_factory=list)`.
- This reorders `ChunkDocument`'s positional-argument sequence for any
  hypothetical positional-argument caller. The sole production call site
  (`pipeline_utils.py::read_json_file()`) already passes every field as a
  keyword argument, so no positional misalignment occurs there; this document
  does not need to (and does not) modify that call site.

## Compatibility considerations

- The sole production construction site
  (`pipeline_utils.py::read_json_file()`) already uses all-keyword arguments
  — no positional-argument misalignment risk from this field's insertion.
- No test file constructs `ChunkDocument` directly (confirmed via
  repository-wide search), so this document alone does not require any test
  fixture changes.
- This change alone does not leave the codebase in a runnable end-to-end
  state: until `pipeline_utils.py::read_json_file()` is updated (its own
  implementation document) to pass `fetched_at`, every call to
  `read_json_file()` raises `TypeError: __init__() missing 1 required
  keyword-only argument: 'fetched_at'` — this is the intended fail-closed
  sequencing dependency, not a defect in this document's scope.

## Security considerations

N/A: `models_data.py` defines internal DTOs only; `ChunkDocument` is not a
system boundary and performs no input validation itself.

## Rollback considerations

- Reverting this field addition alone (without reverting
  `pipeline_utils.py`'s corresponding update, if that has already landed)
  reintroduces a broken build: `pipeline_utils.py` would pass an unexpected
  keyword argument (`fetched_at`) to a `ChunkDocument` that no longer accepts
  it. Revert both files together as one unit.
- Because `frozen=True` is retained and no default is added, this is a
  single-line, additive diff — reverting is a clean one-line removal with no
  other structural cleanup required.

## Validation plan

- `uv run pytest tests/rag/ingestion/test_ingester.py -v` — expected outcome
  (per the source plan): `ChunkDocument()` constructed without `fetched_at`
  raises `TypeError`; once combined with `pipeline_utils.py`'s own
  `read_json_file()` update, a chunk JSON file missing `fetched_at` raises
  `ChunkFormatError` instead of defaulting.

## Out of scope

- Populating `fetched_at` at the `ChunkDocument` construction call site
  (`pipeline_utils.py::read_json_file()`) — separate implementation document.
- Any other dataclass in this file (`EmbeddingResponse`, `CrawlTarget`,
  `ChunkRecord`, etc.).
- Threading `fetched_at` further downstream into `chunk_splitter.py`,
  `ingester.py`, `document_manager.py`, `etag_manager.py`, or the store layer
  — each has its own implementation document.
