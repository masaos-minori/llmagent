## Goal

Isolate chunk destination routing from `ingester.py` into `scripts/rag/ingestion/file_routing.py`, creating `FileRouter` as the single source of truth for routing chunk files based on success/failure.

## Scope

- Create `scripts/rag/ingestion/file_routing.py` with `FileRouter` class
- Move `_route_chunk_files` method to `FileRouter.route()`
- Move `_write_error_metadata` method to `FileRouter.write_error_metadata()`
- Update imports in `ingester.py` to use `FileRouter`
- Write tests in `tests/test_ingester_file_routing.py`

## Assumptions

- `shutil.move` is used for file moves (same as current implementation)
- `orjson.dumps` is used for error metadata serialization (same as current implementation)
- `datetime.datetime.now(datetime.UTC)` is used for timestamps (same as current implementation)
- `read_chunk_json` is called internally by `FileRouter`
- `ChunkFormatError` exception is caught and handled within `FileRouter`

## Design decisions

- `FileRouter` owns the routing decisions — successful chunks go to `registered/`, failed chunks go to `retry/` or `failed/` based on failure reason
- `route()` accepts separate lists of successful and failed paths — same contract as current `_route_chunk_files`
- `write_error_metadata()` returns `dict | None` — same contract as current `_write_error_metadata`
- Directory creation (`mkdir(parents=True, exist_ok=True)`) is done within `FileRouter`

## Alternatives considered

- **Pass directory paths as constructor arguments**: Would allow caller to control paths but couples caller to filesystem layout. Rejected — router should own its paths.
- **Return routing result object**: Would be cleaner than void return but adds ceremony. Deferred until proven necessary.
- **Separate RetryRouter and FailedRouter**: Would isolate retry logic but adds unnecessary abstraction layer. Rejected — routing decision is a single concern.
