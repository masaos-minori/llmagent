# Implementation procedure: scripts/agent/orchestrator.py

## Goal

Route `orchestrator.py`'s three history-construction call sites —
`_handle_memory_injection()`, `_sync_system_prompt()`, and
`_append_user_message()` — through `ConversationState`'s new validated
`append_message()` (added in the companion `context.py` procedure doc) instead
of raw `ctx.conv.history.append(...)` / `.insert(...)`.

## Scope

- In scope:
  - `_handle_memory_injection()` (~L385-391): the `ctx.conv.history.append({...
    "_memory_injected": True})` call.
  - `_sync_system_prompt()` (~L563-565): the `ctx.conv.history.insert(0, {...})`
    branch (the sibling `ctx.conv.history[0]["content"] = ...` in-place
    mutation branch is untouched — see Details).
  - `_append_user_message()` (~L571): the `ctx.conv.history.append({"role":
    "user", "content": line})` call.
- Out of scope (confirmed unchanged by design):
  - `_clear_previous_turn_ephemeral_messages()` (L542-553) — stays a pure
    list-comprehension filter; no `validate_message()` call added here.
  - `_handle_history_compression()` (~L393-405) — the
    `ctx.conv.history, result = await ctx.services_required.hist_mgr.compress(...)`
    bulk reassignment is **not** routed through `replace_history()` in this
    plan; the returned history's only new content is `history.py`'s
    `_build_summary_message()` output, which is role/content-only and already
    schema-conformant, and the existing code comment already documents why
    ephemeral messages are not re-filtered here. Leave as-is.

## Assumptions

- All three call sites construct fresh dicts in-repo (not passed through from
  provider JSON), matching the plan's Assumption 3 category — confirmed by
  direct read of lines 375-410 and 555-575.
- `_sync_system_prompt()` has two branches: an in-place `history[0]["content"] =
  ...` mutation (no key-set change, does not need validation) and an
  `history.insert(0, {...})` branch that constructs a brand-new dict (does need
  validation). Confirmed at `scripts/agent/orchestrator.py:555-565`.

## Design decisions

- `_handle_memory_injection()`: replace the raw `.append(...)` with
  `ctx.conv.append_message({"role": "system", "content": memory_block,
  "_memory_injected": True}, source="memory_injection")`. `TRUSTED_SOURCES`
  authorizes exactly `_memory_injected` for `"memory_injection"`, so this
  message passes validation unchanged.
- `_append_user_message()`: replace with `ctx.conv.append_message({"role":
  "user", "content": line})` — no `source` needed; a plain user message has no
  ephemeral keys and passes `ROLE_KEY_WHITELIST["user"]` unchanged.
- `_sync_system_prompt()`'s `insert(0, ...)` branch: `ConversationState` only
  exposes `append_message()`/`extend_messages()`/`replace_history()` (append or
  full-replace semantics), none of which perform a positional insert. Two
  compliant options, either acceptable:
  1. Validate the constructed dict via a direct `message_schema.validate_message()`
     call (or a small `ConversationState._check(msg)` helper reused by
     `append_message()`) before `ctx.conv.history.insert(0, msg)`, keeping the
     insert itself in `orchestrator.py`.
  2. Since this message is always `{"role": "system", "content": ...}` with no
     ephemeral keys, validation will always succeed today — the simplest
     compliant option is (1), reusing the existing check rather than adding a
     fourth public method to `ConversationState` for a single call site.
  Do not add a new `insert_message()` public method to `ConversationState`
  unless a second insert-at-position call site emerges — YAGNI given the
  audit found only this one.
- No `source` is needed for `_sync_system_prompt()`'s message (plain
  system/content, no ephemeral keys).

## Alternatives considered

- **Add `ConversationState.insert_message()` for the `_sync_system_prompt()`
  case.** Rejected for now: only one call site needs insert-at-0 semantics;
  reusing the existing validation check directly avoids growing the public
  surface of `ConversationState` for a single caller. Revisit if a second
  insert-position call site appears.
- **Route `_handle_history_compression()`'s bulk reassignment through
  `replace_history()`.** Rejected per plan: the compression path's output is
  already schema-conformant by construction (role/content only), and
  `_clear_previous_turn_ephemeral_messages()` already runs before every turn,
  so adding `replace_history()` here would be redundant validation of
  already-trusted content, not a new safety win.

## Implementation

### Target file

`scripts/agent/orchestrator.py`

### Procedure

1. In `_handle_memory_injection()` (~L385-391), replace
   `ctx.conv.history.append({...})` with
   `ctx.conv.append_message({...}, source="memory_injection")`, keeping the
   same dict literal.
2. In `_sync_system_prompt()` (~L563-565), keep the `history[0]["content"] = ...`
   in-place branch unchanged; in the `else` branch, validate the constructed
   `{"role": "system", "content": ctx.conv.system_prompt_content}` dict (via
   the shared check used by `append_message()`) before
   `ctx.conv.history.insert(0, msg)`.
3. In `_append_user_message()` (~L571), replace
   `ctx.conv.history.append({"role": "user", "content": line})` with
   `ctx.conv.append_message({"role": "user", "content": line})`.
4. Leave `_clear_previous_turn_ephemeral_messages()` (L542-553) and
   `_handle_history_compression()` (~L393-405) unchanged; add a one-line
   comment at `_handle_history_compression()` (if not already sufficiently
   documented) noting why it is intentionally not routed through
   `replace_history()`.

### Method

Line-level substitution at three call sites; no change to method signatures,
call order, or the surrounding control flow (`handle_turn()`'s sequencing of
`_clear_previous_turn_ephemeral_messages()` → `_handle_memory_injection()` →
`_append_user_message()` → `_handle_history_compression()`, L473-477, is
unaffected).

### Details

- Confirmed call order via `scripts/agent/orchestrator.py:473-477`:
  `_clear_previous_turn_ephemeral_messages()` runs first, then
  `_handle_memory_injection()`, then `_append_user_message()` (which itself
  calls `_sync_system_prompt()` first), then `_handle_history_compression()`.
  This item does not reorder any of these calls.
- `import agent.context` (or equivalent) is already available in
  `orchestrator.py` since it holds `ctx: AgentContext`; no new import should be
  required beyond what `context.py` itself needs.

## Compatibility considerations

- No change to `AgentContext`/`ConversationState` public shape beyond what the
  `context.py` item adds. `handle_turn()`'s external behavior (turn ordering,
  memory injection content, user-message echo) is unchanged for well-formed
  input; only forged/malformed dicts are affected, and none of these three call
  sites construct forgeable dicts (all are literal, in-repo constructed).

## Security considerations

- Closes the two `orchestrator.py`-owned gaps named in the requirement: memory
  injection content and the user-echo path now flow through the same validated
  entry point as every other history mutation, so a future edit to either
  method cannot silently reintroduce an unvalidated append.
- No security change to `_clear_previous_turn_ephemeral_messages()` — it
  remains a pure filter; its correctness now rests on every append path (this
  file and its four companion docs) being validated, not on re-validating at
  filter time.

## Rollback considerations

- Each of the three substitutions is independent and reversible line-by-line;
  reverting restores the prior raw `.append()`/`.insert()` calls with no data
  migration needed (message shape stored is unchanged for well-formed input).

## Validation plan

- Extend `tests/test_orchestrator.py` with one regression test per routed call
  site: `_handle_memory_injection()` still appends `_memory_injected: True`
  content unchanged; `_append_user_message()` still appends the user line
  unchanged; `_sync_system_prompt()`'s insert-branch still inserts a
  role=system message unchanged when `history[0]` is not already `system`.
- Add/confirm a `_clear_previous_turn_ephemeral_messages()` regression test:
  history containing legitimately-inserted ephemeral/memory-injected messages
  plus normal messages — only the intended messages are stripped, matching
  current behavior exactly (no `validate_message()` call added to this
  method).
- `pytest tests/test_orchestrator.py -q` — all pass.
- `pytest -k "orchestrator" -q` — all pass (per plan's Regression tests row).
- `ruff check scripts/agent/orchestrator.py`, `mypy scripts/agent/orchestrator.py`
  — no new errors.

## Out of scope

- `_clear_previous_turn_ephemeral_messages()` logic change (explicitly ruled
  out by the plan).
- `_handle_history_compression()` / `history.py`'s `_build_summary_message()`
  (no code change; already schema-conformant by construction).
- Adding a new `ConversationState.insert_message()` public method (see
  Alternatives considered).
