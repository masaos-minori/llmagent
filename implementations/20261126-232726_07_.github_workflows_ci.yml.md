## Goal

Report the two suites separately in CI from one pytest run and set the failure policy (REQ-005 — CI reports
the suites from one run; REQ-006 — a characterization failure does not fail the job, a contract failure does).

## Scope
**Release unit**: taxonomy mechanism

## Assumptions

- Confirmed in Step 3a: the `lint` job steps are at `.github/workflows/ci.yml:23-31` and the test job runs
  `uv run pytest -v -n logical --cov=scripts --cov-report= tests/` at `:87`.
- Precondition (Plan UNK-02): the governance owner must confirm that a characterization failure may be
  non-blocking before this step is written. The exemption is limited to the characterization marker and the
  baseline entry names the owning issue.
- The coverage and `diff-cover` steps after `:87` are unchanged, so the run must stay single.

## Design decisions

- The pytest step becomes `continue-on-error` and writes `report.xml`; the exit decision moves to the report
  step, which reads the JUnit XML. Without this, a characterization failure fails the job at the pytest step
  and the report step never runs.
- The report step's exit code is the CI gate: non-zero only when the contract section has failures.

## Alternatives considered

- Two pytest runs with `-m` selections — rejected: `pytest-cov` combines xdist workers only within one run,
  and `diff-cover --fail-under=90` reads one data file.

## Implementation
### Target file
`.github/workflows/ci.yml`
### Procedure

- Add a `Test taxonomy` step to the `lint` job: `uv run python tools/check_test_taxonomy.py`.
- Add `--junitxml=report.xml` to the test job's pytest command and mark that step `continue-on-error: true`.
- Add a report step after it: `uv run python tools/check_test_taxonomy.py --junit-xml report.xml`.

### Method

- The report step prints a characterization section and a contract section grouped by module, then exits
  according to REQ-006.

### Details

- `report.xml` stays inside the job workspace; no artifact upload is added.
