# Implementation Procedure: `scripts/agent/workflow/task_ops.py` — unconditional UUID4 task idempotency key

## Goal

Make `create_task()` generate `idempotency_key` as a per-insert UUID4 so that a retained
`workflow.sqlite` cannot abort the first turn of a new process with
`sqlite3.IntegrityError` (`REQ-001` — key is generated by `create_task()` alone, never derived
from caller-supplied fields; `REQ-002` — the scope is stated in the docstring).

## Scope

- One function in `scripts/agent/workflow/task_ops.py`: the derivation branch at `:21-24` and the
  docstring at `:20`.
- Everything else in the file stays byte-identical: the INSERT block `:27-45`, `db.commit()` `:46`,
  the `TaskRecord` return `:47-57`, `update_task_status()` `:60`, `_row_to_task()` `:69`,
  `get_task_by_id()` `:85`, `get_task_by_idempotency_key()` `:93`, `get_task_by_session()` `:101`.
- No new import: `uuid` is already imported at `:5`.

## Assumptions

- The two tests that pin the new behavior (`REQ-007`) are authored in
  `tests/agent/workflow/test_workflow_state_store.py` by the sibling procedure
  `implementations/20261024-101738_02_tests_agent_workflow_test_workflow_state_store.py.md` and are
  observed red before this edit (plan step 1 precedes plan step 2).
- `session_id` stays the constant `""` on the only production path (`REQ-009`); this procedure does
  not touch the caller.

## Design decisions

- Fix identity at construction, not at the error site: the branch is deleted rather than wrapped in
  `try/except` (`REQ-006`), so the UNIQUE constraint remains as a backstop and the collision class
  cannot be reintroduced silently.
- The docstring's first line `"""Create a new task record."""` (`:20`) is kept byte-identical and the
  scope text starts on the following line, so the generated-API guard (`AC-5`) has nothing to drift.

## Alternatives considered

- Session-scoped key plus a DB-seeded turn counter (plan Option A): rejected — adds persisted state
  and changes the `execute_turn` contract for a lookup no production code performs.
- Composite key with a UUID fallback (plan Option C): rejected — keeps a key that means different
  things across restarts and still relies on the fallback to avoid the crash.
