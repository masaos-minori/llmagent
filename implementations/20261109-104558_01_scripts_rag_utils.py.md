## Goal
Make the `[RAG_CONTEXT_START]` / `[RAG_CONTEXT_END]` boundary unforgeable by crawled text. In `scripts/rag/utils.py`: define the two marker strings once (`REQ-005`), neutralize them in `sanitize_document` and `sanitize_document_full` so every content site is covered by one mechanism (`REQ-001`, `REQ-004`), and add a single-line field sanitizer for title and url (`REQ-002`).

## Design decisions
- The marker strings live in `rag.utils`, the lowest layer of the `rag` package, as public constants `RAG_BLOCK_START` (new) and `RAG_BLOCK_END` (new); `rag.stages.augment` keeps its private names as imports of them (`REQ-005`).
- Marker neutralization is a separate compiled pattern `_MARKER_PATTERN` (new) applied after `_INJECTION_PATTERNS`. It is case-insensitive and tolerates whitespace inside the brackets. Its alternation is derived from the two constant names so one definition drives both.
- `sanitize_field` (new) is the title/url variant: collapse control characters and line breaks (including Unicode line and paragraph separators) to single spaces, then apply `sanitize_document`, then strip. Content keeps its line structure, so it never goes through the collapse.
- `sanitize_document_full` records a marker match in `patterns_detected` and sets `was_sanitized`, so its audit trail stays truthful.

## Alternatives considered
- Escape markers only in `_format_chunks`: rejected, the refiner and rerank prompts would stay forgeable (Plan Design).
- Put the marker regex into `_INJECTION_PATTERNS`: rejected, that list is the documented five-category contract and marker handling is a structural rule, not a phrase blocklist entry.
- Reuse `sanitize_document` for title and url without the collapse: rejected, a newline in a title could start a line that mimics a header or marker.

## Implementation
### Target file
`scripts/rag/utils.py`

### Procedure
1. Add `RAG_BLOCK_START` (new) and `RAG_BLOCK_END` (new) with the existing literal values `[RAG_CONTEXT_START]` and `[RAG_CONTEXT_END]`.
2. Add `_MARKER_PATTERN` (new): a case-insensitive pattern matching the bracketed marker names with optional whitespace inside the brackets.
3. In `sanitize_document`, after the loop over `_INJECTION_PATTERNS`, substitute `_MARKER_PATTERN` (new) matches with `[REMOVED]`; update the docstring to state that markers are neutralized.
4. In `sanitize_document_full`, apply the same substitution and record the pattern in `patterns_detected` when it matches.
5. Add `sanitize_field` (new) with the semantics in Design decisions and a docstring.

### Method
- `sanitize_field` (new) order: replace every control character and every line or paragraph separator with a space, collapse runs of whitespace to one space, run `sanitize_document` on the result, strip.
- Accept a plain `str`; the callers pass an empty string for an absent title and decide the url fallback after sanitizing (see the `scripts/rag/stages/augment.py` procedure).

### Details
- Keep `sanitize_document`'s return type and its behavior for text without markers unchanged: clean text is returned as is.
- Comments and docstrings in English; no logging of field content.
- The module stays far below the size gate (`tools/check_module_size.py`).

## Compatibility considerations
`sanitize_document` and `sanitize_document_full` gain one behavior: bracketed marker strings in the text become `[REMOVED]`. Text that does not contain a marker is unchanged. Production callers are the three `scripts/rag/` sites; their output differs only for forged or marker-bearing content. The marker constants' values are unchanged (`REQ-005`). The documentation procedures state the changed contract (`REQ-006`).

## Security considerations
The boundary markers are a trust boundary for retrieval-augmented prompts and crawled text is untrusted. This change makes the structural boundary hold regardless of page content, within the limit that look-alike characters are not normalized. The phrase blocklist remains best-effort. No secret or credential is involved; no content is logged.
