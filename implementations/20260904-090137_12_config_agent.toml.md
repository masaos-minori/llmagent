## Assumptions
- Must execute after rows 1-11's code changes land, and be followed by a

## Design decisions
- Delete the key entirely rather than commenting it out — per REQ-009's own
  wording ("reject the key entirely... no silent compatibility alias"), a
  commented-out key would not test the actual rejection behavior
  `config_builders.py` (row 3) now enforces for an unrecognized/invalid
  value.

## Alternatives considered
- Leaving the key present but changing its value to `"production"`:
  rejected — the key no longer serves any purpose once `SecurityProfile` has
  a single member (row 1); leaving it, even set correctly, retains a
  vestigial config surface REQ-009 asks to remove.
