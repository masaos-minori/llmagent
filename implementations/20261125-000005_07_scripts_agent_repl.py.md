## Goal

Move session persistence inside the bounded machine: register the snapshot-persist step with the coordinator and remove the unbudgeted `_persist_session_state()` call from the `finally`, so persistence is one reported step with a deadline instead of an unbounded call before the machine runs (REQ-001: one owner and sequence; REQ-007: persistence is bounded and single-snapshot; AC-1, AC-3).

## Assumptions

- `_persist_session_state()` (`scripts/agent/repl.py:94-102`) already feeds one snapshot to both persist calls, so the gap this row closes is that the call sits outside the coordinator with no deadline and no step record, not that two snapshots are taken.
- The coordinator is built in `__init__` before the orchestrator exists, which is why `register_close_hook` at `scripts/agent/repl.py:136-143` is the post-startup registration point; the persist step is registered at the same point because the persister is present there.

## Design decisions

- Persistence becomes a coordinator step rather than staying a `finally` call: only the coordinator can give it a deadline and a record, and a step that fails is reported rather than printed as a warning from the REPL.
- The `finally` keeps exactly one call: `close_resources()`. Removing the persist call from it is what makes the sequence single-owner (REQ-001).
- The budget is constructed here, unarmed, and handed to the coordinator, the input loop, and the signal handler, so all consumers read one object (Plan Design, "One budget, many consumers").
- Compatibility impact: the shutdown output changes (a persist step record replaces the `Session persistence failed` warning path), which row 32 asserts.

## Alternatives considered

- keep the persist call in the `finally` and wrap it in a timeout — rejected: it would still run outside the sequence, so its time would not be counted against the deadline and its outcome would not appear in the report.

## Implementation
### Target file
`scripts/agent/repl.py`

### Procedure
1. Construct the budget in `__init__` from the configured deadline (row 17) and pass it to `ResourceShutdownCoordinator`, `ReplInputLoop`, and `SignalHandler` (`scripts/agent/repl.py:85-92`).
2. Register the snapshot-persist step with the coordinator at the same point where the workflow-store hook is registered (`scripts/agent/repl.py:136-143`).
3. Delete the `_persist_session_state()` call and its warning handler from the `finally` (`scripts/agent/repl.py:157-171`), leaving `close_resources()` as the only shutdown call.
4. Remove `_persist_session_state()` (`scripts/agent/repl.py:94-102`) once nothing calls it, moving its one-snapshot body into the step callable registered in step 2.

### Method
- The step callable captures one snapshot and passes it to both persist calls, so the snapshot the step records and the snapshot the persister writes are the same object (REQ-007).

### Details
- The step is registered before `bind()` so every exit path that reaches the `finally` already carries it, matching the comment at `scripts/agent/repl.py:136-143`.

## Compatibility considerations

- Exit paths that previously persisted without a deadline now persist inside the budget; a persist step that cannot start is recorded `not_started` (row 5) instead of running unbounded.
- The `Session persistence failed` warning line disappears from the REPL output; the step record carries the outcome instead (row 32).
