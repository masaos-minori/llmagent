## Goal

Extend the CI `lint` job in `.github/workflows/ci.yml` to actually execute the pytest node ids
cited in the ADR Invariant Verification Matrix (`docs/10_adr/adr_01_index.md`), failing on any
missing, skipped (without the skip annotation), or failing citation. This strengthens GV-012 from
structural (path exists) to behavioral (test passes) without changing the matrix schema or the
existing path-existence check.

## Scope

- **In-Scope**:
  - Extract the cited pytest node ids from the ADR Invariant Verification Matrix.
  - Run them in the CI `lint` job, failing on missing, skipped, or failing citations.
  - Preserve the existing path-existence verification in `check_adr_invariant_matrix.py`.
  - Reuse the existing `integration` marker as the skip-annotation convention.
- **Out-of-Scope**:
  - Changing the ADR Invariant Verification Matrix schema.
  - Extending to non-matrix-cited tests.
  - Changing `check_adr_invariant_matrix.py`'s path-existence behavior.

## Assumptions

- The `integration` marker is registered in `pyproject.toml` (deselect with `-m "not integration"`);
  cited integration-only tests carry `@pytest.mark.integration`.
- The extraction mechanism can reuse `check_adr_invariant_matrix.py`'s compiled `_TEST_PATH_RE`
  and `ADR_INDEX` via import; if import-linter forbids cross-tool imports, duplicate the node-id
  regex under a pinned comment plus a regression test pinning them equal.
- The `lint` job is the correct home (it already runs tool checks as discrete steps); cited tests
  are unit tests runnable in the base CI environment.

## Design decisions

- Additive: insert a new step into the existing `lint` job; do not add a new workflow or change
  existing steps.
- Single source of truth for citation extraction: import `check_adr_invariant_matrix.py`'s
  `_TEST_PATH_RE` / `ADR_INDEX`; fall back to pinned duplication if import-linter blocks it.
- Run each cited node id with `-m "not integration"` so integration-only tests are intentionally
  deselected (not failed, not silently ignored).

## Alternatives considered

- Adding a separate workflow/job — rejected: the plan routes this through the existing `lint`
  job; a separate job would fragment the governance linting.

## Implementation

### Target file

`.github/workflows/ci.yml`

### Procedure

1. Read the existing `lint` job to locate the discrete tool-check steps (e.g.
   `tools/check_db_separation.py` and `tools/generate_reference_table.py --check`).
2. Add a new step, after the path-existence check, named something like "Run cited ADR invariant
   tests".
3. In that step, extract the cited node ids from `docs/10_adr/adr_01_index.md` using
   `check_adr_invariant_matrix.py`'s node-id definition, then run each with
   `pytest <nodeid> -m "not integration"`, failing if any collects to zero tests, fails, or
   remains skipped after deselection.
4. Do not touch `check_adr_invariant_matrix.py` (REQ-005).

### Method

- **Citation extraction (UNK-01).** Prefer importing `check_adr_invariant_matrix.py`'s
  `_TEST_PATH_RE` (matches `` `path.py::NodeID` ``) and `ADR_INDEX` in a small CI helper script
  committed alongside the workflow, so the source of truth stays single. If import-linter forbids
  the cross-tool import, duplicate the node-id regex in the helper under a pinned comment
  referencing the checker and add a regression test asserting the two patterns are equal.
- **Run per node id.** For each cited node id run `pytest <nodeid> -m "not integration"`
  (UNK-03: a class citation such as `...::TestWorkflowLoadFailureIsFatal` runs the whole class and
  must pass). Fail the step if any node id collects to zero tests (missing), fails, or remains
  skipped after deselection (UNK-02).
- **Skip convention (REQ-003).** Cited tests marked `@pytest.mark.integration` are deselected by
  `-m "not integration"` — not failed, not silently ignored.
- **Preserve path-existence (REQ-005).** Leave the existing `check_adr_invariant_matrix.py` step
  unchanged.

### Details

- `REQ-001`: the `lint` job extracts every cited node id and runs it.
- `REQ-002`: a missing/failing/skipped-without-annotation citation fails the build.
- `REQ-003`: integration-marked cited tests are intentionally deselected.
- `REQ-004`: current cited tests pass in CI without false failures.
- `REQ-005`: the path-existence check still runs unchanged.
- **UNK-01:** reuse the module's `_TEST_PATH_RE` / `ADR_INDEX` via import; fall back to pinned
  duplication + equality regression test if import-linter blocks the import.
- **UNK-02:** deselect `integration`-marked tests first; a remaining skip/empty collection is
  treated as missing (fails).
- **UNK-03:** a class citation runs the class; run the node id as-is per pytest semantics.
