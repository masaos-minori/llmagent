## Goal
Migrate all 10 `[mcp_servers.*]` `auth_token` entries from empty literals to
environment-variable references.

## Scope
- **In-Scope**: the 10 `auth_token       = ""` lines (verified 2026-09-04:
  lines 299, 308, 320, 329, 338, 347, 356, 373, 382, 391, under
  `[mcp_servers.shell]`, `[mcp_servers.git]`, `[mcp_servers.web_search]`,
  `[mcp_servers.file_delete]`, `[mcp_servers.file_write]`,
  `[mcp_servers.file_read]`, `[mcp_servers.github]`, `[mcp_servers.cicd]`,
  `[mcp_servers.rag_pipeline]`, `[mcp_servers.mdq]` respectively).
- **Out-of-Scope**: every other key in each `[mcp_servers.*]` section
  (`transport`, `url`, `startup_mode`, `role`, `tool_names`, `cmd`) and every
  other section of `config/agent.toml`.

## Assumptions
- Must execute after rows 1-6's code changes land, and be followed by a
  deploy step (Plan Phase 3) that sets the actual environment variables —
  this is the live deployed configuration file; per the Plan's Risks
  section, migrating this file's values before the environment variables
  are set in the deployment environment would make every MCP server fail to
  start (by design, per REQ-001).
- Uses the `${ENV:MCP_<SERVER_KEY>_AUTH_TOKEN}` naming convention
  established in row 1's document (resolves `UNK-01`).

## Design decisions
- Set each `auth_token` value to
  `"${ENV:MCP_<SERVER_KEY_UPPER>_AUTH_TOKEN}"`, where `<SERVER_KEY_UPPER>`
  is the `[mcp_servers.{key}]` section's key, uppercased with underscores
  preserved (e.g. `mcp_servers.web_search` → `MCP_WEB_SEARCH_AUTH_TOKEN`) —
  applies uniformly across all 10 sections for the one-consistent-convention
  requirement in the Plan's Risks section.

## Alternatives considered
- A single shared environment variable for all 10 servers (e.g.
  `MCP_AUTH_TOKEN`): rejected — per-server tokens allow independent
  rotation/revocation and match this repository's existing per-server
  config structure; a shared token would also make REQ-004's "which
  server(s) lack a token" startup error (row 3) less informative if a
  single shared variable's absence broke all 10 servers indistinguishably
  from a per-server misconfiguration.

## Implementation
### Target file
`config/agent.toml`

### Procedure
Replace each of the 10 `auth_token       = ""` lines with
`auth_token       = "${ENV:MCP_<KEY>_AUTH_TOKEN}"`, substituting each
section's own uppercased key.

### Method
Direct `Edit`, one substitution per section (10 total), preserving the
existing column alignment (`auth_token       = `).

### Details
Current (verified 2026-09-04, representative example, `[mcp_servers.shell]`):
```toml
[mcp_servers.shell]
transport        = "http"
url              = "http://127.0.0.1:8009"
startup_mode     = "subprocess"
auth_token       = ""
role             = "execute"
```
After:
```toml
[mcp_servers.shell]
transport        = "http"
url              = "http://127.0.0.1:8009"
startup_mode     = "subprocess"
auth_token       = "${ENV:MCP_SHELL_AUTH_TOKEN}"
role             = "execute"
```
Apply the equivalent substitution to the other 9 sections using each
section's own key: `MCP_GIT_AUTH_TOKEN`, `MCP_WEB_SEARCH_AUTH_TOKEN`,
`MCP_FILE_DELETE_AUTH_TOKEN`, `MCP_FILE_WRITE_AUTH_TOKEN`,
`MCP_FILE_READ_AUTH_TOKEN`, `MCP_GITHUB_AUTH_TOKEN`, `MCP_CICD_AUTH_TOKEN`,
`MCP_RAG_PIPELINE_AUTH_TOKEN`, `MCP_MDQ_AUTH_TOKEN`.

Note: `MCP_GIT_AUTH_TOKEN` and `MCP_CICD_AUTH_TOKEN` must resolve to the
*same* secret value the standalone `config/git_mcp_server.toml` (row 8) and
`config/cicd_mcp_server.toml` (row 9) also reference — this file's
`[mcp_servers.git/cicd].auth_token` is the Agent's client-side credential
for calling that server; the standalone file's `auth_token` is the server's
own credential for validating incoming requests; both sides of the same
Bearer-token check must use the identical environment variable so the
values match at deploy time.
