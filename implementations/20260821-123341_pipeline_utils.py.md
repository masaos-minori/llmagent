## Goal
Add two independent strict TypedDict/reader pairs (`CrawlJsonPayload`/`read_crawl_json()`
and `ChunkJsonPayload`/`read_chunk_json()`) to `scripts/rag/ingestion/pipeline_utils.py`,
then remove the permissive `ChunkJsonRaw`/`read_json_file()`/`_read_chunk_json_raw()`/
`_get_str_with_default()`/`_get_int_with_default()` family once no production caller
remains.

## Scope
- In scope: `scripts/rag/ingestion/pipeline_utils.py` only.
- Out of scope: `crawler.py`, `chunk_splitter.py`, `ingester.py` migrations (separate
  implementation documents); DB schema; embedding/search logic.

## Assumptions
- Both readers raise the existing `rag.exceptions.ChunkFormatError` for every rejection
  reason (missing key, wrong type, unknown key, cross-field rule violation) — confirmed
  by reading `scripts/rag/exceptions.py`: `ChunkFormatError(RagLayerError, ValueError)`
  is the only chunk/crawl-format-specific exception defined there; no more specific
  subtype exists today, so introducing one would be speculative. (Plan's UNK-01,
  non-blocking, resolved this way.)
- `CrawlDocument` fields mirror the Required Crawl Payload list minus the
  `schema_version`/`artifact_type`/`created_by` envelope fields, matching how
  `ChunkDocument` already omits those three fields (confirmed by reading
  `models_data.py`).
- This file currently keeps `ChunkJsonRaw`/`read_json_file()`/`_read_chunk_json_raw()`/
  `_get_str`/`_get_list`/`_get_str_with_default`/`_get_int_with_default` (all present,
  confirmed by reading the full 147-line file). All are removable once
  `chunk_splitter.py` and `ingester.py` no longer import them — this is a two-step
  change (add-new-then-remove-old) spanning this file and its two callers.

## Design decisions
- Two separate TypedDicts (`CrawlJsonPayload`, `ChunkJsonPayload`) instead of one shared
  permissive shape, per the plan's stated policy: unknown-field rejection and exact
  mandatory-key sets are incompatible with a single shared/reused shape.
- `etag`, `last_modified` (`CrawlJsonPayload`) and `etag`, `last_modified`,
  `normalized_content` (`ChunkJsonPayload`) are mandatory keys with `str | None` values
  (not `NotRequired`) — this is the mechanism that forces producers to always emit the
  key.
- Validation order inside each reader: (1) `orjson.loads` parse, (2) top-level dict type
  check, (3) exact key-set check, (4) per-field type/value validation, (5) cross-field
  rule (crawl only: empty `content` requires non-empty `code_blocks`).

## Alternatives considered
- A single shared strict-JSON-validation helper library for both readers — rejected as
  speculative generalization beyond what these two readers need (explicit Out-of-Scope
  item in the plan).
- Keeping `NotRequired` for `etag`/`last_modified` and defaulting at the reader —
  rejected because it reintroduces the exact silent-defaulting behavior this change
  removes.

## Implementation
### Target file
`scripts/rag/ingestion/pipeline_utils.py`

### Procedure
1. Add `CrawlJsonPayload` (all keys mandatory) and `ChunkJsonPayload` (mandatory keys
   including nullable `etag`/`last_modified`/`normalized_content`) TypedDicts.
2. Add `read_crawl_json(path: Path) -> CrawlDocument` performing the 5-step validation
   above; raise `ChunkFormatError` on any failure.
3. Add `read_chunk_json(path: Path) -> ChunkDocument` performing the equivalent
   validation for chunk payloads (no cross-field rule).
4. Keep the existing `ChunkJsonRaw`/`read_json_file()`/`_read_chunk_json_raw()`/
   `_get_str_with_default()`/`_get_int_with_default()` in place until callers in
   `chunk_splitter.py`/`ingester.py` are migrated (tracked in those files' own
   implementation documents).
5. After migration confirmed (via
   `rg -n "ChunkJsonRaw|read_json_file|_read_chunk_json_raw|_get_str_with_default|_get_int_with_default" scripts`
   returning zero matches outside this file's own definitions), remove the five
   symbols and any now-unused `_get_str`/`_get_list` helpers (keep `_get_str`/`_get_list`
   only if still referenced elsewhere — re-check with `rg` before removing).

### Method
- Import `orjson`, `Path`, `ChunkFormatError` (already imported), `ChunkDocument` and
  new `CrawlDocument` from `rag.models_data`.
- Implement validation as straight-line functions, not a class, matching the existing
  module style (`_read_chunk_json_raw`, `read_json_file` are plain functions today).

### Details
- Current file has no `CrawlDocument` import (only `ChunkDocument` from
  `rag.models_data`, line 12) — add `CrawlDocument` to that import once it exists in
  `models_data.py`.
- Mandatory-key check should compare `set(data.keys())` against the exact required key
  set for each payload type (no missing key, no extra key) — this is what
  "unknown-field rejection" requires; a plain `for key in required: ...` loop would miss
  the unknown-key case.
- `chunk_index` validation: `isinstance(x, bool)` must be checked and rejected **before**
  `isinstance(x, int)` (Python's `bool` is an `int` subclass), then require
  non-negative.

## Compatibility considerations
- Breaking change by design: any on-disk crawl/chunk JSON file missing a now-mandatory
  key, or carrying an unknown key, or with a wrong-typed value, will raise instead of
  being silently defaulted — matches the requirement's "no legacy data supported"
  stance.
