## Goal
In `scripts/rag/ingestion/ingester.py`: remove `_validate_artifact()` (and its
`strict` parameter/call sites) and `_normalize_chunk_index()`; require `chunk_index`
to already be a valid non-negative int with an explicit `bool` rejection; route
`_read_chunk_json()` through the new `read_chunk_json()`.

- Out of scope: `pipeline_utils.py`'s `read_chunk_json()` itself (own document);

## Assumptions
- **Correction from adversarial review of the source plan (2026-08-21):** the plan's
  Scope text for this file originally said "remove now-unverified `typing.cast()`
  calls." `rg -n "cast" scripts/rag/ingestion/ingester.py` finds zero matches — there
  is no `typing` import and no `cast()` call anywhere in this file today. That clause
  described work that does not exist; no `cast()` cleanup is needed here. This
  correction was also applied to `plans/20260820-094150_plan.md` itself.
- `_read_chunk_json()` (lines 552-554) currently returns `ChunkJsonRaw | None`, a raw
  dict. Once it is switched to call `read_chunk_json()` (which returns `ChunkDocument`,
  raising `ChunkFormatError` instead of returning `None` on failure), every downstream
  `.get(...)` call on its result must become attribute access. Confirmed by reading the
  full file, the affected methods are: `ingest_url_group()` (lines 212-217, e.g.
  `first_data.get("title", "")`), `_embed_and_store()` (lines 570-578), and the
  `.get("url", "")` calls in `_group_chunks_by_url()` (line ~702), `_move_to_registered()`
  (line ~753), `_route_chunk_files()` (line ~782), `_write_error_metadata()` (uses
  `_read_chunk_json`, needs the `None`-check replaced by an exception-catch), and
  `_log_ingest_failure()` (uses `_read_chunk_json_raw` directly, line 405 — must be
  repointed to the new reader as well, catching `ChunkFormatError`).
- `_read_chunk_json()` is called at 6 sites in this file (lines 203, 560, 698, 754,
  783, 828, confirmed by `rg -n "_read_chunk_json(" scripts/rag/ingestion/ingester.py`)
  — the plan's Affected-areas table originally said "5 call sites" while listing 6 line
  numbers; corrected to 6 in the plan.
- Since `read_chunk_json()` raises `ChunkFormatError` rather than returning `None`,
  every one of those 6 call sites' `if data is None: ...` guard becomes a
  `try/except ChunkFormatError` guard (or the exception propagates and is caught one
  level up, depending on each method's existing error-handling shape — decide
  per-call-site during implementation, preserving each method's current
  skip-and-log-and-continue vs. skip-and-return-failure behavior).

## Design decisions
- `chunk_index` handling: replace `idx_raw = data.get("chunk_index", 0); idx =
  self._normalize_chunk_index(doc_id, path.name, idx_raw)` (lines 575-576) with direct
  use of `data.chunk_index` (already validated as a non-negative, non-`bool` int by
  `read_chunk_json()` at the boundary) — no runtime re-validation needed in
  `_embed_and_store()` itself, since the reader already rejected any invalid value
  before `_embed_and_store()` ever sees it.
- `_validate_artifact()` removal: since `read_chunk_json()` already enforces the exact
  mandatory-key set (which subsumes the old `schema_version`/`artifact_type`/
  `created_by` presence checks) and rejects unknown fields, the separate
  `artifact_type == expected_type` check (the one piece of `_validate_artifact()`'s
  logic not otherwise covered by key-set validation) must be preserved somewhere —
  add it as an explicit equality check right after the `read_chunk_json()` call at each
  of the two structurally-checking call sites (`ingest_url_group()` line 209,
  `_embed_and_store()` line 563), since `read_chunk_json()` itself has no
  `expected_type` parameter (it validates shape, not "was this a chunk vs. crawl
  file").

## Alternatives considered
- Giving `read_chunk_json()` an `expected_type` parameter so it also enforces
  `artifact_type == "chunk"` internally — rejected to keep `pipeline_utils.py`'s reader
  a pure shape-validator; the "is this artifact type appropriate for this call site"
  check is call-site-specific business logic that belongs in `ingester.py`, not in the
  shared I/O utility (matches this plan's general "no speculative generalization"
  principle applied to `pipeline_utils.py`).

## Implementation
### Target file
`scripts/rag/ingestion/ingester.py`

### Procedure
1. Change the import (line 32, currently `from rag.ingestion.pipeline_utils import
   ChunkJsonRaw, _read_chunk_json_raw`) to `from rag.ingestion.pipeline_utils import
   read_chunk_json` (add `from rag.exceptions import ChunkFormatError` if not already
   imported — check first).
2. Rewrite `_read_chunk_json(self, path: Path) -> ChunkJsonRaw | None` (lines 552-554)
   to call `read_chunk_json(path)` and change its return type to `ChunkDocument`
   (propagate `ChunkFormatError` rather than catching it here, or catch-and-re-raise
   with added context — decide based on what the 6 call sites need).
3. Remove `_normalize_chunk_index()` (lines 357-373) entirely.
4. Remove `_validate_artifact()` (lines 377-400) entirely; remove all `strict=True`/
   `strict=False` call sites (`ingest_url_group()` line 209, `_embed_and_store()` line
   563).
5. At each of the 6 `_read_chunk_json()` call sites, convert `.get(...)` dict access on
   the result to attribute access on the returned `ChunkDocument`, and convert the
   `if data is None: ...` failure branch to a `try/except ChunkFormatError` (or let it
   propagate, matching each method's existing error contract).
6. `_log_ingest_failure()` (lines 402-417): change `chunk_data =
   _read_chunk_json_raw(path)` / `chunk_url = chunk_data.get("url", "") if chunk_data
   else ""` to use the new reader with an exception guard.

### Method
- Preserve every method's existing external behavior contract (return types like
  `IngestionFailureReason`, `IngestUrlResult`) — only the internal data-access pattern
  changes from dict-`.get()` to dataclass-attribute, and failure detection changes from
  `is None` to `except ChunkFormatError`.

### Details
- `PreparedChunk` construction in `_embed_and_store()` (lines 596-604) already builds
  from local variables (`content`, `normalized_content`, `idx`, `chunk_type`,
  `source_file`) — only the assignment lines above it change source (from `data.get(...)`
  to `data.<attr>`), not the constructor call itself.
- `ingest_url_group()`'s use of `first_data.get("title", "")` /
  `.get("lang", "en")` / `.get("etag")` / `.get("last_modified")` /
  `.get("chunking_strategy", "text")` (lines 212-215, 217) all become `first_data.title`
  / `.lang` / `.etag` / `.last_modified` / `.chunking_strategy`.
- **Gap found during adversarial review, not called out in the source plan:**
  `fetched_at = first_data.get("fetched_at")` (line 216) is threaded through
  `_get_or_create_document()` → `_insert_document()` (lines 423-482), which only
  inserts a `documents.fetched_at` column value when not `None`. `ChunkDocument`
  (`models_data.py`) has **no `fetched_at` field**, and `chunk_splitter.py`'s
  `_extract_chunk_metadata()` (chunk_splitter.py:289-301) never writes a `fetched_at`
  key into chunk JSON output either — confirmed by reading both files. So
  `first_data.get("fetched_at")` has always evaluated to `None` in production for this
  call path (dict `.get()` on a missing key silently returns `None`); this is
  pre-existing, unrelated-to-this-plan behavior, not something this migration should
  change. Once `first_data` becomes a `ChunkDocument` with no `.get()` method and no
  `fetched_at` attribute, the correct fix is to **replace this line with a hardcoded
  `fetched_at = None`** (or drop the local variable and pass `None` literally at the
  two call sites, lines 229 and 257) — this preserves the exact current runtime value
  without inventing new behavior. Do not attempt to add a `fetched_at` field to
  `ChunkDocument`/`ChunkJsonPayload` to "fix" this, since that would be scope creep
  beyond this plan's Required Chunk Payload list.
