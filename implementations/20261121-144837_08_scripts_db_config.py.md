## Goal

Make `build_db_config()` take the caller-supplied configuration mapping instead of loading `agent.toml` itself, so `scripts/db/` has no implicit config load (REQ-003, REQ-004, AC-004, AC-005).

## Scope
**Release unit**: RU-2

## Assumptions
- `tests/db/test_db_config.py` is not a companion of this row: it is named by two rows (this row and `config/agent.toml`), so it keeps its own document (Plan row 25).
- The function keeps its name (the Plan's Design D3) so `patch("db.config.build_db_config")` targets in `tests/` stay valid; test files that only patch it are expected to need no modification.
- Session and Workflow path keys stay in `config/agent.toml` (the Plan's Assumption 1); the typed-manifest option is UNK-01 and is not decided here.

## Design decisions
- The signature becomes `build_db_config(mapping)` taking the caller's raw configuration mapping; the caller is the process that owns the file, so the owner relationship is preserved rather than moved into `db`.
- `DbConfig` stays the typed result, with its existing validation (`sqlite_vec_so` rejection, non-empty path checks) unchanged — only the source of the values changes.

## Alternatives considered
- Import `AgentConfig` into `scripts/db/` to receive typed configuration: blocked by the `.importlinter` `db-only-uses-shared` contract (the Plan's Design D2 and Risk list).

## Implementation
### Target file
`scripts/db/config.py`
### Procedure
- Remove the `ConfigLoader().load("agent.toml")` call (line 87) and accept the caller's mapping as an argument.
- Keep the `sqlite_vec_so` empty-value rejection and the `workflow_db_path` conditional handling, now evaluated on the supplied mapping.
- Update the docstring so the contract states that values are supplied by the owning process.
### Method
- `shared.config_utils.get_typed` remains the validation path for typed reads (the Plan's Reference Files row).
- No module-level cache is introduced; the function stays a pure function of its argument.
