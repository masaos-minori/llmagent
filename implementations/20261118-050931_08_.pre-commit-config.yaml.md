## Goal
Widen the `archived-procedure-status` hook in `.pre-commit-config.yaml` so it also runs when files under `plans/done/` change, matching the checker's new coverage of archived plans.

## Scope
**Release unit**: N/A: not part of a release unit

## Assumptions
- The checker already reports status-value findings for archived plans after `implementations/20261118-050931_03_tools_check_workitem_structure.py.md` lands; without that, widening the trigger would only re-run the unfinished-row check over plans, which it does not perform.
- The hook entry point (`uv run python -m tools.check_workitem_structure --archived-status`) and hook id stay exactly as they are; only the `files` pattern changes.

## Design decisions
- Change the hook's `files` pattern from `^implementations/done/.*\.md$` to `^(implementations|plans)/done/.*\.md$`: one hook id runs one command over both archived directories, instead of adding a second hook entry.
- UNK-02 stays open until execution: measure the `--archived-status` run time over both directories in the Plan's Phase 4; if it is slow for commits touching `plans/done/`, a separate hook id pinned to `plans/done/` is the recorded alternative — this document then changes to add that entry instead of widening the pattern.

## Alternatives considered
- A second hook id for plans from the start: rejected for now — the value check is one command with one report, and two hooks would duplicate the unfinished-row scan; kept as the UNK-02 fallback if measurement shows a slowdown.
- Leaving the trigger as is and relying on the whole-repo gate: rejected by REQ-006 — an archived-plan edit must fail at commit time, not only in the batch gate.

## Implementation
### Target file
`.pre-commit-config.yaml`

### Procedure
1. Edit only the `files` value of the hook `archived-procedure-status` to the widened pattern.
2. Measure: run `uv run python -m tools.check_workitem_structure --archived-status` and time it (UNK-02); record the time in this document's Execution Status Notes.
3. Confirm parity: `uv run python tools/run_validation_gates.py drift` reports no finding (the routing rows and hook stay in sync per the Plan's row evidence).

### Method
One regex value edit; no new hook, no entry or language changes.

### Details
- The pattern anchors at the repository root like the current one; `plans/done/` and `implementations/done/` match, active directories do not.
- The structure gate's own row mapping (Run cells of `routing.md`) is untouched; the routing row update is the sibling procedure and must be landed in the same phase so drift stays clean (UNK-03: re-read the shared rows before editing).

## Compatibility considerations
- Every commit touching `plans/done/` now runs the archived-status scan; the Plan's recorded risk and mitigation (UNK-02 measurement, separate hook id allowed) apply.

## Rollback considerations
