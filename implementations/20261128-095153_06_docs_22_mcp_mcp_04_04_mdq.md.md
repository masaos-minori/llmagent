## Design decisions

- Keep the criteria as prose bullets grouped by dimension, not as a table: a per-file description table is what `tools/check_docs_content_policy.py` reports, and the criteria are statements about areas rather than about files.
- Name the contract modules as evidence only, following the precedent in the same document (`Proven by tests/mcp_servers/mdq/test_mdq_stale_detection.py` in Guard and postcondition coverage), so the criteria remain traceable without becoming an implementation-location mapping.
- Record recovery as unmeasured with the reason instead of asserting it, because the mdq store is not a recovery-drill domain.

- Move the fence decision into a new design document: rejected, the plan records that the existing table and the parser docstring already carry the subset, and no new document is needed.
- State performance criteria as numeric thresholds: rejected, the thresholds are an owner decision (`UNK-02`) and no measurement exists yet.
