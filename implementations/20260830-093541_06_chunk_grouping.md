## Goal

Isolate URL-based chunk aggregation from `ingester.py` into `scripts/rag/ingestion/chunk_grouping.py`, creating `ChunkGroupingStrategy` as the single source of truth for grouping chunks by URL.

## Scope

- Create `scripts/rag/ingestion/chunk_grouping.py` with `ChunkGroupingStrategy` class
- Move `_group_chunks_by_url` method to `ChunkGroupingStrategy.group()`
- Update imports in `ingester.py` to use `ChunkGroupingStrategy`
- Write tests in `tests/test_ingester_chunk_grouping.py`

## Assumptions

- `read_chunk_json` is called internally by `ChunkGroupingStrategy`
- `validate_url` utility is called internally by `ChunkGroupingStrategy`
- `ChunkFormatError` exception is caught and handled within `ChunkGroupingStrategy`
- `defaultdict(list)` is used for grouping (same as current implementation)

## Design decisions

- `ChunkGroupingStrategy` owns the URL-based grouping logic — it reads chunk JSON files and groups them by the `url` field
- `group()` returns `dict[str, list[Path]]` — same contract as current `_group_chunks_by_url`
- Invalid URLs are logged and skipped (not raised as exceptions)
- Missing `url` field in chunk JSON is logged and skipped

## Alternatives considered

- **Pass chunk data directly (already-parsed)**: Would avoid re-reading JSON but couples caller to parsing details. Rejected — grouping should own its input format.
- **Return grouped `ChunkDocument` objects**: Would be cleaner than paths but adds memory overhead. Deferred until proven necessary.
- **Separate URL validator module**: Would isolate validation but couples it to grouping domain. Rejected — URL validation is a grouping invariant.
