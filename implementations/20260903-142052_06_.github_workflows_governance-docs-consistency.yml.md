- **Out-of-Scope**: `tools/check_dependency_graph_cycles.py` itself (seq 04),

## Design decisions
- **A new, separate step** (`Run dependency graph cycle check`) is added after the
  existing "Run Needs Confirmation inventory checks" step, rather than appending the
  new tool invocation to the existing step's `run:` block. A separate step gives an
  independently-named, independently-failing CI check in the GitHub Actions UI —
  useful for quickly identifying which of the two checks failed — and matches this
  workflow's own existing one-step-per-tool granularity (there is currently exactly
  one step for exactly one tool).
- **`tools/check_dependency_graph_cycles.py` is added to both `push.paths` and
  `pull_request.paths`**, mirroring the existing `tools/check_needs_confirmation_inventory.py`
  entry in both lists — without this, a change to only the new tool's own source
  (e.g. fixing a bug in `find_cycle`) would not trigger this workflow at all, since
  `docs/**/*.md` alone would not match a `tools/*.py` file change.
- **`docs/00_governance_01_documentation-policy.md` needs no new `paths` entry**:
  it is already covered by the existing `docs/**/*.md` glob, so no addition is
  needed for the new check to trigger on changes to the graph text itself.

## Alternatives considered
- **Combine both tool invocations into one step's `run:` block** (e.g. `python
  tools/check_needs_confirmation_inventory.py && python
  tools/check_dependency_graph_cycles.py`) — rejected: a combined step reports only
  one pass/fail status for two independent checks, making failure triage in the
  GitHub Actions UI slower; the separate-step approach costs one extra step
  definition (a few lines of YAML) for a clear UI benefit, and matches the existing
  file's own one-step-per-tool convention (there is exactly one step for exactly one
  tool today, not a combined step for multiple future checks).
- **Do not add `tools/check_dependency_graph_cycles.py` to the `paths` trigger
  lists**, relying only on `docs/**/*.md` changes to trigger the workflow — rejected:
  this would leave a bug fix to the cycle-detection tool itself silently untested by
  CI on the PR that introduces it, contradicting REQ-009's intent that this check
  actually runs.
