## Goal

Isolate embedding logic from `ingester.py` into `scripts/rag/ingestion/embedding.py`, creating `EmbeddingService` as the single source of truth for embedding generation and caching.

## Scope

- Create `scripts/rag/ingestion/embedding.py` with `EmbeddingService` class
- Move `_get_embedding` method to `EmbeddingService.get_embedding()`
- Move `_embed_and_store` method to `EmbeddingService.embed_and_store()`
- Update imports in `ingester.py` to use `EmbeddingService`
- Write tests in `tests/test_ingester_embedding.py`

## Assumptions

- `_VALID_LANGS` constant remains in `ingester.py` (not moved to embedding module)
- `PreparedChunk` DTO remains in `ingester.py` (consumed by chunk preparation downstream)
- `IngestionFailureReason` enum values used by embedding are shared across modules
- HTTP client instance (`self._client`) is injected via constructor rather than owned by `EmbeddingService`
- Embedding retry/backoff logic is preserved exactly as-is

## Design decisions

- `EmbeddingService` owns the embed URL, retry count, worker count, and HTTP client — these are configuration concerns, not orchestration concerns
- `embed_and_store()` returns `PreparedChunk | IngestionFailureReason` (same contract as current `_embed_and_store`)
- Caching is not added yet — the current code has no embedding cache; adding one would be scope creep
- Thread safety: `ThreadPoolExecutor` usage pattern is preserved; no new concurrency primitives needed since the caller manages the executor

## Alternatives considered

- **Singleton embedding service**: Would reduce HTTP client duplication but couples callers to global state. Rejected — dependency injection is preferred.
- **Async embedding API calls**: Would improve throughput but changes the public contract. Deferred to a later refactor.
- **Embedding cache with TTL**: Would reduce redundant API calls but adds complexity. Deferred until proven necessary.
