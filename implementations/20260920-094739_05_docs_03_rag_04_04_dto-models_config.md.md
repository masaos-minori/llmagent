## Assumptions
- The "Implementation Notes" section already states that this file's
  dataclasses have a documented mismatch with the actual runtime contract
  (Known Issue CI-017), and "Related Documents" already names
  `shared/types.py`'s `RagConfig` Protocol as "the configuration contract
  actually used at runtime" — this existing caveat means the replacement
  pointer to `scripts/rag/models_config.py` documents what these specific
  dataclasses contain, not a claim that they are the live runtime contract;
  no change to this existing caveat is needed or in scope.
- The bold DTO-name lines immediately above each table (e.g. "**MqeConfig**
  — MQE query expansion settings.") are one-sentence, retained design-intent
  descriptions of what each config group is for — keep them unchanged;
  only the table beneath each is replaced.

## Design decisions
- Replace each of the 7 tables with a one-line pointer to the corresponding
  dataclass in `scripts/rag/models_config.py`, keeping the bold DTO-name
  description line directly above it unchanged. Use one shared pointer
  format across all 7 for consistency, e.g. "See `MqeConfig` in
  `scripts/rag/models_config.py` for exact fields, types, and defaults."
- For `PipelineConfig` (line 71) specifically, since its table lists nested
  DTO types (not primitives) as "Type," the pointer notes that its 4 fields
  are themselves the other 4 DTOs already described above, rather than
  independent primitive fields — this is a one-clause addition to the
  pointer sentence, not a table.

## Alternatives considered
- Leave `FusionConfig` (1 row) and `PipelineConfig` (no Default column) as
  hand-maintained tables since the automated tool does not flag them —
  rejected: they are the same DTO-field-table category REQ-005 targets;
  leaving 2 of 7 tables in place would be an inconsistent partial
  remediation of the same file for the same reason, discovered via this
  row's own adversarial verification (Plan corrected accordingly).
