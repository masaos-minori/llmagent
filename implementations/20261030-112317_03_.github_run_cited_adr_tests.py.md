# Implementation Procedure: run_cited_adr_tests.py skip/xfail result handling

## Goal

Extend the cited-node runner so a cited node that is SKIPPED or XFAIL is reported
non-passing unless an approved exception is recorded in the matrix row (REQ-003:
runner exits non-zero on skipped/xfailed citations without an exception; plan AC-2).

## Scope

**In scope:**
- Outcome classification in `evaluate_citation` (`.github/run_cited_adr_tests.py:85`):
  distinguish SKIPPED and XFAIL from passed by parsing pytest output.
- Approved-exception allowlist: reuse the checker's exception marker parsing
  (`Exception: <id>` per doc 02) through the already path-imported `_CHECKER`
  (`:33-44`) so the grammar stays single-sourced.
- Report lines (`:124`) gain the new reasons; failure summary (`:128-131`) unchanged shape.

**Out of scope:**
- Marker detection inside test files (doc 02 owns that).
- The `-m "not integration"` deselection handling (`:97-103`) — keep as-is.

## Assumptions
- Verified at HEAD `124e340b4`: runner is 139 lines; `_PYTEST_EXIT` map at `:49-55`;
  `_run_pytest` at `:71` runs subprocess without capturing output; checker import by
  path at `:30-44`; CI step at `.github/workflows/ci.yml:43`.
- Needs Confirmation: matrix cites for environment-gated skips (e.g. sqlite-vec
  `tests/agent/memory/test_memory_vec_session.py`) are decided in Phase 1 per doc 01
  (exception-recorded default); the runner only consumes the recorded markers.
- pytest prints a `SKIPPED`/`XFAIL` short summary with `-rs`; capturing output is the
  classification vehicle (no new pytest plugin dependency).

## Design decisions
- Classify per-invocation: each cited node runs in its own pytest process, so parsing
  that process's summary lines (SKIPPED / XFAIL / XPASS) attributes outcomes without
  a machine-readable report plugin.
- Exception allowlist is keyed by the cited `file::node` string and harvested from the
  same matrix lines `extract_cited_node_ids` (`:58`) already reads — no second parse
  pass and no new config file (plan: matrix is the single authority).

## Alternatives considered
- pytest JSON report plugin for outcome parsing: rejected — new dependency and a
  plugin registered per test dir; the summary-line parse is sufficient for one node per
  process.
- Separate exception config file: rejected — duplicates the matrix and violates the
  single-source rule the runner already models with `_CHECKER`.

### Procedure
1. Change `_run_pytest` (`:71`) to capture stdout+stderr (`capture_output=True,
   text=True`) and return `(returncode, output)`; update both call sites
   (`_node_id_exists :79`, `evaluate_citation :92`).
2. Add `_classify_outcome(rc, output, node_id)` (new): `rc==0` with a `XFAIL` summary
   line for the node → `xfailed`; `rc==0` with a `SKIPPED` line → `skipped`; otherwise
   keep the current mapping (`:93-104`).
3. Add `_cited_exceptions(lines)` (new): for each cited `(file_part, node_id)`, scan
   the matrix lines containing that citation for the checker's exception marker via a
   helper imported from `_CHECKER` (doc 02); return the set of node ids with an
   approved exception.
4. In `main` (`:107-135`): `skipped`/`xfailed` count as failure unless the node id is
   in the exception set, in which case report `PASS` with reason
   `skipped-approved-exception` / `xfailed-approved-exception`.

### Method
Refactor in place; keep the module's existing "load checker by path" single-source
pattern (`:30-44`) for the exception grammar.

### Details
- Run pytest with `-rsq` so skip/xfail reasons appear in the short summary; match
  summary lines by the node id suffix to avoid cross-talk between the two pytest calls.
- Exit codes stay: `2` setup problems, `1` citation failures, `0` all passed — CI step
  (`.github/workflows/ci.yml:43`) needs no change.
