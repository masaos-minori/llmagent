# Implementation procedure: scripts/agent/context.py

## Goal

Add validated history-mutation entry points to `ConversationState`
(`append_message()`, `extend_messages()`, `replace_history()`, plus a private
`_sanitize_message()` helper) so every later call site can route
`ctx.conv.history` mutations through `agent.message_schema.validate_message()`
instead of raw `list.append()`/`list.extend()`/direct reassignment.

## Scope

- In scope: the three new public methods and one private helper on
  `ConversationState` (`scripts/agent/context.py`, class body ~L56-72); the new
  `from agent.message_schema import validate_message` import.
- Out of scope: routing any of the eight call sites in other files (covered by
  companion procedure docs); any change to `message_schema.py`'s public API,
  `ROLE_KEY_WHITELIST`, or `TRUSTED_SOURCES` values.

## Assumptions

- `ConversationState` is a plain `@dataclass` (no `slots=True`, no frozen) with a
  bare `history: list[LLMMessage] = field(default_factory=list)` field and no
  methods today (confirmed: `scripts/agent/context.py:56-72`) — adding instance
  methods to it is a straightforward, additive change.
- `message_schema.py` has zero internal `agent.*` imports (only `logging` and
  `dataclasses`, confirmed), so `context.py` importing from it introduces no
  import cycle; `context.py` already imports several `agent.*` modules.
- `source` is validation-only metadata per the plan (Assumption 2): it is never
  persisted onto the stored message dict, because `"source"` is not a member of
  any `ROLE_KEY_WHITELIST` entry and `ctx.conv.history` is passed to
  `ctx.services_required.llm.stream()` verbatim (no stripping in between).
- `message_schema.py` itself needs no functional change for this item; its
  existing `logger` may be reused, or `context.py` may use its own
  module-level `logger` for the `append_message()` warning/error logs — either
  is acceptable, pick whichever matches the file's current logging pattern.

## Design decisions

- Single validated append helper lives on `ConversationState`, not as a free
  function in `orchestrator.py`, because every downstream call site already
  holds `ctx` (and thus `ctx.conv`) — this makes every call site's fix a
  one-line substitution and structurally prevents new call sites from bypassing
  validation.
- `append_message(msg, *, source="")` builds a **transient check-only view**
  (`dict(msg, source=source)` when `source` is truthy) for the
  `validate_message()` call; the stored message is always the original `msg`
  (or the sanitized replacement), never the check view — this is what keeps
  `"source"` out of persisted history / the LLM payload.
- On validation failure: sanitize (strip disallowed/unauthorized keys) rather
  than raise. Never crash the turn on a malformed message — log at `warning`
  with the role and `result.reason` so any stripping is visible in logs, per
  the plan's explicit failure-mode requirement.
- If sanitization would leave the message without `role` or `content`, drop the
  message entirely (log at `error`) rather than append a partially-valid dict.
- `extend_messages()` and `replace_history()` are thin wrappers implemented in
  terms of `append_message()` (loop / clear-then-loop) so there is exactly one
  place that calls `validate_message()`.

## Alternatives considered

- **Free function in a new `history_utils.py` instead of a `ConversationState`
  method.** Rejected: every call site already has `ctx.conv`, so a method keeps
  call sites to a one-line change and avoids a new import at each of the eight
  call sites.
- **Raise `ValueError` on validation failure instead of sanitize-and-log.**
  Rejected: per plan Design point 1 and the requirement doc, a forged/odd key
  from LLM-influenced content must never crash the turn; sanitize+log is the
  documented failure mode.
- **Validate inside `_clear_previous_turn_ephemeral_messages()` instead of at
  append time.** Rejected — explicitly out of scope per the plan (Design point
  4): that filter must stay a pure, cheap check and already only needs to trust
  keys set through this validated append path; adding validation there would
  reintroduce the double-validation pattern consolidated away in commit
  `7c7bbe47d`.

## Implementation

### Target file

`scripts/agent/context.py`

### Procedure

1. Add `from agent.message_schema import validate_message` to the imports.
2. Add a module-level (or `context.py`-local) `logger = logging.getLogger(__name__)`
   if one does not already exist in this file — check before adding a duplicate.
3. Implement `_sanitize_message(msg, *, source="")` (module-level private
   function or `ConversationState` staticmethod — either is fine, pick
   whichever is more idiomatic for this file): drop any key not in
   `ROLE_KEY_WHITELIST.get(role, {"role", "content"})` plus any ephemeral key
   not authorized for `source`. Return `None` if `role`/`content` themselves
   are missing after sanitization (signals "drop the message entirely").
4. Implement `ConversationState.append_message(msg, *, source="")`: build the
   check view, call `validate_message()`, log+sanitize on failure, drop
   entirely (log `error`, do not append) if sanitization yields `None`,
   otherwise `self.history.append(msg_or_sanitized)`.
5. Implement `ConversationState.extend_messages(msgs, *, source="")`: loop over
   `msgs` calling `self.append_message(m, source=source)`.
6. Implement `ConversationState.replace_history(msgs, *, source="")`: set
   `self.history = []` then call `self.extend_messages(msgs, source=source)`.

### Method

Additive-only change: new imports + new methods on an existing dataclass. No
existing method signatures change; no existing call site is touched by this
item (that is the job of the companion procedure docs for `orchestrator.py`,
`tool_runner.py`, `llm_turn_runner.py`, `mode_classification.py` +
`cmd_skill.py`, and `startup.py` + `session_restore.py`).

### Details

- `ROLE_KEY_WHITELIST` and `TRUSTED_SOURCES` (from `message_schema.py`) are
  imported alongside `validate_message` wherever `_sanitize_message()` needs
  them, or accessed via `message_schema.ROLE_KEY_WHITELIST` /
  `message_schema.TRUSTED_SOURCES` to avoid re-declaring the whitelist logic in
  `context.py`.
- Type the new methods with `msg: LLMMessage` / `msgs: list[LLMMessage]` to
  match the existing `history: list[LLMMessage]` field annotation.

## Compatibility considerations

- Purely additive: no existing `ConversationState` field or method changes
  shape. `history` remains a plain `list[LLMMessage]`, so any code that still
  reads `ctx.conv.history` directly (rather than through the new helpers)
  continues to work unchanged during the migration.
- No signature change to `ConversationState.__init__` (dataclass-generated);
  callers that construct `ConversationState()` are unaffected.

## Security considerations

- This is the file that makes the requirement's core security property
  possible: every message reaching `ctx.conv.history` via the new methods is
  checked against `ROLE_KEY_WHITELIST`/`TRUSTED_SOURCES` before storage, so a
  forged `_ephemeral`/`_memory_injected`/`_skill_ephemeral` key from
  LLM-influenced content cannot survive into history through these entry
  points.
- The check-then-store-original pattern (never persisting `source`) prevents a
  new field leaking into the LLM API payload or DB persistence layer.
- Sanitization always logs (never silently drops keys) so a future regression
  (e.g. a legitimate field falling outside `ROLE_KEY_WHITELIST`, see plan
  Risks) is observable rather than silently degrading behavior.

## Rollback considerations

- Low risk: revert the single commit adding these methods; since no call site
  in this item uses them yet, reverting is a clean no-op for runtime behavior.
- If a later call-site migration surfaces an unexpected sanitization (per the
  Risks section of the plan — `pinned`/`importance`/`name` not covered by
  `ROLE_KEY_WHITELIST`), the fix is local to `_sanitize_message()`/
  `ROLE_KEY_WHITELIST`, not a rollback of this item.

## Validation plan

- New unit test file `tests/test_context_append_message.py` (no existing
  `tests/test_context.py` covers `ConversationState`; confirmed via directory
  listing) covering:
  - well-formed message appends unchanged, `source` never persisted;
  - well-formed message with `source="memory_injection"` and
    `_memory_injected: True` appends with the ephemeral key intact;
  - forged `_ephemeral`/`_memory_injected` key with no/untrusted `source` is
    stripped before reaching `.history`, and a `warning` is logged;
  - message missing `role`/`content` after sanitization is dropped entirely
    (not appended), and an `error` is logged;
  - `extend_messages()` validates each message independently (one bad message
    among several good ones only affects the bad one);
  - `replace_history()` clears prior history before extending.
- `pytest tests/test_context_append_message.py -q` — all pass.
- `pytest tests/test_message_schema.py -q` — unchanged, still passes (no
  functional change to `message_schema.py` in this item).
- `ruff check scripts/agent/context.py` and `mypy scripts/agent/context.py` —
  no new errors.
