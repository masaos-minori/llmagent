# Implementation Procedure: Add GitPolicyError subclass

## Goal

Add `GitPolicyError(GitServiceError)` subclass in `scripts/mcp_servers/git/errors.py` to distinguish policy rejections from execution failures (REQ-005). This enables `call_tool()` to classify rejections as `is_error=True` responses (not HTTP 500) while keeping genuine execution failures as HTTP 500.

## Scope

- Modify `scripts/mcp_servers/git/errors.py`: add `GitPolicyError(GitServiceError)` subclass.

## Assumptions

- The two rejections currently raised as `GitServiceError` (`_authorize_remote` remote-not-allowed, `format_commit` nothing-staged) are the only `GitServiceError`-raised rejections to reclassify.
- All other `GitServiceError` instances are genuine execution failures and should remain HTTP 500.
- `call_tool()`-level conversion of `GitPolicyError` is sufficient to keep the shared `dispatch.py` untouched.

## Design decisions

- **Inheritance**: `GitPolicyError` inherits from `GitServiceError` so existing `except GitServiceError` handlers still catch it, but `call_tool()` can distinguish it via `isinstance(exc, GitPolicyError)`.
- **Minimal class**: Only a class definition; no additional methods or fields needed.

## Alternatives considered

- Adding a `rejection` attribute to `GitServiceError`: rejected because it would require changing every `GitServiceError` raise site and complicates the error hierarchy.
- Using a separate exception hierarchy entirely: rejected because `GitPolicyError` needs to be caught by existing `GitServiceError` handlers (e.g., `_wrap_git_op`).
