# Implementation Procedure: Unify outcome, wrap dispatch_tool(), add health counter

## Goal

Three changes to `scripts/mcp_servers/git/git_server.py`:
1. Replace `"success"` with `"ok"`/`"rejected"` in the `call_tool()` audit call (REQ-002).
2. Wrap the `dispatch_tool()` call in `call_tool()` with try/except/finally so an exception still records exactly one audit record with `outcome="error"`, and a policy rejection produces `outcome="rejected"` (REQ-003).
3. On audit write failure, log at ERROR, increment a per-process counter, and expose the counter in `/health` details (REQ-004).

## Scope

- Modify `scripts/mcp_servers/git/git_server.py`:
  - Line 263: replace `"success"` with `"ok"`/`"rejected"`.
  - Lines 246-273: wrap `dispatch_tool()` in try/except/finally.
  - Lines 107-112: add audit-failure counter to `_audit_log_safe()`.
  - Lines 276-287: expose counter in `/health` details.

## Assumptions

- `GitPolicyError` (from REQ-005) is raised by `format_output.py` and caught at the `call_tool()` level.
- The `/health` audit-failure counter is process-local; acceptable because audit logging is itself process-local.
- `make_health_response()` passes `details` through unchanged (confirmed in `health_response.py` lines 25-52).

## Design decisions

- **Outcome unification (REQ-002)**: Replace `outcome="rejected" if result.is_error else "success"` with `outcome="rejected" if result.is_error else "ok"`.
- **Exactly-one-record invariant (REQ-003)**: try/except/finally around `dispatch_tool()`:
  - `GitPolicyError` → `is_error=True` result + `outcome="rejected"` (no re-raise).
  - `GitServiceError` → `outcome="error"` then re-raise (so FastAPI's `_on_git_service_error` returns 500).
  - `finally` block ensures exactly one audit record regardless of path.
- **Audit-failure counter (REQ-004)**: Add a module-level `int` counter incremented in `_audit_log_safe()` on exception; expose in `/health` details dict.

## Alternatives considered

- Catching `Exception` broadly in `call_tool()`: rejected because only `GitPolicyError` and `GitServiceError` should be handled differently; other exceptions should propagate.
- Using a class-level counter: rejected because a simple module-level `int` is sufficient for process-local tracking.
- Adding a separate `/health` endpoint for the counter: rejected because the plan requires exposing it in the existing `/health` details.
