## Goal
Wire the ADR authority model into CI: add `tools/check_adr_authority.py` and `tools/generate_adr_authority.py --check` steps to `.github/workflows/ci.yml` (REQ-004, REQ-006).

## Scope
- In scope: two new CI steps.
- Out of scope: registration docs (rows 08–10), tool code (rows 03–05).

## Current shape (facts)
- The lint job already runs docs/governance steps before `Pre-commit` and `Run cited ADR invariant tests` (verified steps at `.github/workflows/ci.yml:25-42`, including `Generated reference docs drift check` running `uv run python tools/generate_reference_table.py --check` at `:35`).
- `tools/check_adr_reference.py` and `tools/check_adr_structure.py` run in CI today (plan Tests section lists them; exact step lines located during implementation).

## Assumptions
- Placement: new steps adjacent to the existing ADR-check steps in the same job, following the existing `run: uv run python tools/<tool>` one-liner style; the generator drift step mirrors the `generate_reference_table.py --check` step's naming style ("ADR index generated sections drift check").
- Both steps blocking (no `continue-on-error`), matching every existing governance step.

## Design decisions
- Two steps, not one combined `&&`: CI step granularity keeps failure attribution per check, matching this file's existing one-tool-per-step pattern.
- Order within the job: `check_adr_authority.py` (model semantics) before `generate_adr_authority.py --check` (rendering), so semantic findings are reported before drift findings.

## Alternatives considered
- Running the checks only in a separate `test` job — rejected: precedent governance checks (reference-table drift, ADR invariant tests) live in this job; splitting families invites partial enforcement.
