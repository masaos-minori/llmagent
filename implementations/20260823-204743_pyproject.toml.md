# Implementation Procedure: pyproject.toml

## Goal

Restore `check-mcp-docs` and `check-agent-docs` as `[project.scripts]` console-script
entries pointing at the new `tools.check_docs_consistency:main_mcp`/`:main_agent`
wrapper functions.

## Scope

**In-Scope**
- Add two lines to `[project.scripts]`:
  ```toml
  check-mcp-docs = "tools.check_docs_consistency:main_mcp"
  check-agent-docs = "tools.check_docs_consistency:main_agent"
  ```

**Out-of-Scope**
- The other two existing entries (`check-needs-confirmation`, `check-tool-descriptions`)
  — confirmed correct and unrelated (UNK-01, resolved).
- Restoring `check-deployment-docs`, `check-overview-docs`, or `check-rag-docs` — not
  requested by the source requirement; out of this plan's scope.

## Assumptions

- **Critical finding**: `check-mcp-docs`/`check-agent-docs` do not currently exist in
  `[project.scripts]` at all — confirmed by direct read of the current file, which
  lists only `check-needs-confirmation` and `check-tool-descriptions`. `git log -p --
  pyproject.toml` shows these two entries (plus three domain siblings) were removed
  entirely in commit `dfe33fa21` ("docs: apply Context Loader Pattern per
  prompts/05_skills.md"), a broad documentation-cleanup commit that post-dates this
  plan's source requirement. This means the change described here is an *addition* to
  the table, not an in-place edit of a stale line, contrary to this plan's original
  framing ("Update pyproject.toml's [project.scripts] entry points").
- The two remaining `[project.scripts]` entries both resolve to existing modules —
  confirmed (`tools/check_needs_confirmation_inventory.py`,
  `tools/check_tool_descriptions_sync.py` both present).
- The target functions `tools.check_docs_consistency:main_mcp`/`:main_agent` will exist
  once the companion `tools/check_docs_consistency.py` implementation procedure is
  applied — this procedure's entries are only valid after that one lands; do not apply
  this procedure first in isolation (the resulting console-script would fail to
  resolve).

## Design decisions

- Add the two entries back exactly where they were removed from (top of
  `[project.scripts]`, before `check-needs-confirmation`), matching the table's
  original ordering as seen in git history — a cosmetic choice, not a functional one,
  since TOML table key order has no runtime significance here.

## Alternatives considered

- Add the entries at the end of the table instead of restoring original position —
  either is functionally equivalent; original-position restoration was chosen only for
  minimizing unrelated diff noise against the pre-removal history, not for any
  functional reason.

## Implementation

### Target file
`pyproject.toml`

### Procedure
1. **Before this step**: confirm `tools.check_docs_consistency:main_mcp` and
   `:main_agent` exist (i.e., the companion `check_docs_consistency.py` procedure has
   been applied) — otherwise the resulting console-script entries will fail to resolve
   at install/run time.
2. In `[project.scripts]`, add:
   ```toml
   check-mcp-docs = "tools.check_docs_consistency:main_mcp"
   check-agent-docs = "tools.check_docs_consistency:main_agent"
   ```
3. Run `uv sync` (or equivalent) to regenerate the installed console-script shims so
   `uv run check-mcp-docs`/`check-agent-docs` become available.

### Method
Two-line TOML table addition.

### Details
- No other `pyproject.toml` section needs a change — `[tool.pyright]`,
  `[tool.mutmut]`, and other tool configs immediately following `[project.scripts]`
  are unaffected.

## Compatibility considerations

- Restoring these two commands changes nothing for existing callers of `uv run python
  tools/check_docs_consistency.py --domain <domain>` (the underlying `main()` and its
  argument contract are untouched) — this only adds two new, more convenient entry
  points on top.

## Security considerations

N/A: no security-relevant logic; this is a build/packaging configuration change.

## Rollback considerations

- Trivially revertable: removing these two lines returns to the current
  (commands-absent) state. Since these are pure additions restoring previously-existing
  functionality (not modifications to any currently-relied-upon line), reverting has no
  ripple effect beyond re-breaking `uv run check-mcp-docs`/`check-agent-docs`.
