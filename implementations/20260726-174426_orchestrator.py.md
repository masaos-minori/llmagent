# Implementation: `orchestrator.py` — Threshold Notification and Opt-in Pause on Background Task Failure

## Goal

At `BG_FAILURE_THRESHOLD` consecutive first-turn background-task failures, guarantee the
user is notified (even if `_on_error` itself raises), optionally pause further turn
processing for that task type, and log the specific task name instead of a generic label.

## Scope

**In scope:**
- `scripts/agent/orchestrator.py`:
  - `Orchestrator.__init__()` — add opt-in `pause_on_critical_failure` parameter and
    `_bg_pause_state` tracking dict.
  - `_append_user_message()` — attach an explicit task name to the first-turn background
    task at creation time.
  - `_discard_and_log()` — resolve the task name, log it instead of a generic label, and
    add a guaranteed-delivery notification + optional pause when the threshold is reached.
  - `handle_turn()` — block turn processing while any tracked task type is paused.

**Out of scope (per plan):**
- New config surface beyond the one opt-in flag needed for pause behavior.
- Changing the `_on_error` callback signature/contract.
- Changing how background tasks are created/scheduled otherwise.
- A `/resume` command or any persistence of pause state across process restarts — the
  plan's own `UNK-01`/`UNK-03` mark the pause mechanism and persistence as open and
  explicitly non-blocking; this doc implements the minimal in-memory version the plan's
  Implementation Steps actually list (no resume step is listed). Restarting the process is
  the only way to clear pause state today; a follow-up plan should add `/resume` if that is
  needed operationally.

## Assumptions

- `_on_error` is the only user-facing notification channel available on `Orchestrator`
  (confirmed: no other `_on_*` callback in `__init__` sends user-visible text); reuse it
  rather than adding a new callback, per the plan's "do not modify the `_on_error`
  contract" constraint.
- Per Assumption 3 in the plan, task type is intended to be identified by callback name
  (`_generate_session_title`). Relying on `task.get_coro()` introspection is fragile
  (flagged as a risk in the plan), so instead pass the name explicitly via
  `asyncio.create_task(..., name=...)` at creation and read it back with
  `task.get_name()` — this satisfies the plan's own mitigation ("pass task metadata
  explicitly instead of relying on introspection").
- Only one background-task type exists today (first-turn session-title generation via
  `self._on_first_turn`, scheduled from `_append_user_message`); `_bg_pause_state` is a
  `dict[str, bool]` so the mechanism generalizes if a second task type is added later,
  matching Assumption 2 ("pause option should be per-task-type, not global").
- Pause state is in-memory only (`Orchestrator` is a long-lived singleton per
  `startup.py:117`), consistent with UNK-03's resolution path ("start with in-memory pause
  state").

## Design decisions

- Notify exactly once when the counter *reaches* `BG_FAILURE_THRESHOLD`
  (`== BG_FAILURE_THRESHOLD`), not on every failure `>= BG_FAILURE_THRESHOLD` — avoids the
  duplicate-notification risk called out in the plan's Risks section, while leaving the
  existing `>= BG_FAILURE_THRESHOLD` log-level branch (`logger.error`) unchanged.
- New `_notify_bg_failure_threshold()` method wraps the `_on_error` call in `try/except`
  and falls back to `logger.critical()` on failure — same guaranteed-delivery pattern
  already used for the first-failure notification at lines 649-656, reused for consistency
  rather than introducing a different fallback mechanism.
- Pause check is placed at the very top of `handle_turn()`, mirroring the existing
  `ctx.workflow.approval_pending` early-return guard (lines 183-196) — this is the
  shallowest safe point that blocks all turn processing without touching
  `_handle_workflow_engine` internals, resolving UNK-01 with the lowest-risk option.

## Alternatives considered

- **Coroutine-name introspection (`task.get_coro().cr_code.co_name`)** — rejected per the
  plan's own risk note: unreliable across Python versions/coroutine wrapping. Explicit
  `name=` at `create_task()` is the standard library's supported mechanism for this.
- **Global pause flag instead of per-task-type dict** — rejected; plan Assumption 2
  explicitly requires per-task-type granularity.
- **Raising from `_notify_bg_failure_threshold()` instead of catching** — rejected; would
  defeat the "notification always reaches the user even if `_on_error` fails" requirement.
- **Pausing inside `_handle_workflow_engine` instead of `handle_turn`** — rejected; `handle_turn`
  is the outer entry point and already has a precedent guard for exactly this kind of
  early-return blocking behavior.

3. `_discard_and_log()` (lines 624-672):
   - Resolve `task_name = task.get_name()` once at the top.
   - Replace the generic `"Background task failure #%d"` / `"Consecutive background task
     failures (%d)"` log messages with versions that include `task_name`.
   - Add, inside the `elif self._consecutive_bg_failures >= BG_FAILURE_THRESHOLD:` branch:
     ```python

         self._notify_bg_failure_threshold(task_name, self._consecutive_bg_failures)
     ```
4. Add a new method `_notify_bg_failure_threshold(self, task_name: str, count: int) -> None`
   near `_discard_and_log`:
   ```python
   def _notify_bg_failure_threshold(self, task_name: str, count: int) -> None:
       """Guarantee the user is notified when a background task hits the failure threshold."""
       message = RuntimeError(
           f"Background task '{task_name}' has failed {count} consecutive times "
           f"(threshold: {BG_FAILURE_THRESHOLD})."
       )
       if self._on_error is not None:
           try:
               self._on_error(message)
           except Exception as notif_err:
               logger.critical(
                   "Failed to notify user of threshold breach for '%s': %s",
                   task_name, notif_err,
               )
       else:
           logger.critical(str(message))
       if self._pause_on_critical_failure:
           self._bg_pause_state[task_name] = True
           logger.warning("Background task type '%s' paused after reaching threshold.", task_name)
   ```
5. `handle_turn()` (line 179): add a guard immediately after the existing
   `approval_pending` block:
   ```python
   if any(self._bg_pause_state.values()):
       paused = [name for name, is_paused in self._bg_pause_state.items() if is_paused]
       logger.warning("Turn blocked: agent paused due to background task failures: %s", paused)
       if self._on_error:
           self._on_error(
               RuntimeError(
                   f"{OutputTag.WORKFLOW} Agent paused due to repeated failures in: {paused}. "
                   "Restart the process to clear pause state."
               )
           )
       return
   ```

## Compatibility considerations

- `pause_on_critical_failure` defaults to `False` — existing callers of `Orchestrator(...)`
  (e.g. `startup.py`) are unaffected until they opt in.
- Adding `name=` to `create_task()` has no behavioral effect beyond `task.get_name()`
  (default names like `"Task-N"` are only used for debugging/logging elsewhere).
- The new `handle_turn()` guard only triggers when `_bg_pause_state` has a `True` entry,
  which is impossible unless `pause_on_critical_failure=True` was explicitly passed — no
  effect on current deployments.

## Security considerations

- N/A — no new external input; task names are internal (`__name__` of an internally-wired
  callback), not attacker-controlled. No change to trust boundaries.

## Rollback considerations

- Single-file change; revert by removing the new parameter/attribute, the `name=` kwarg,
  the new method, and the `handle_turn()` guard. No persisted/DB state involved (pause
  state is in-memory only), so rollback has no data-migration impact.
- Because there is no `/resume` command in this scope, an operator who unintentionally
  turns on `pause_on_critical_failure` and hits the threshold has no in-process way to
  unpause other than restarting — flagged here since it's a real operational rollback path
  (process restart), not a code rollback.
