## Goal
Make `SQLiteHelper` load sqlite-vec by default for the `session` target as well as `rag`, so Memory vector writes and KNN work on a default-opened session connection (`REQ-003`), without changing any other target or the failure semantics (`REQ-008`).

## Scope
- The single assignment of `_default_load_vec` in `SQLiteHelper.__init__` for named targets, and the `open()` docstring line that describes the default.
- The explicit `db_path` branch, `_load_vec_extension`, and the `if use_vec and self._vec_so` guard stay as they are.

## Assumptions
- Parity with `rag` is the intended failure behavior: an empty `sqlite_vec_so` skips the load and a load error raises (Plan UNK-01).
- The real-DB test in `tests/agent/memory/test_memory_vec_session.py` is written first and fails before this change (Plan Phase 1).

## Design decisions
- Use an inline membership test (`resolved in ("rag", "session")`) rather than a new module constant, so the check tool can pin the exact expression and no new public name is introduced.
- Do not add `load_vec=True` at Memory call sites: one default covers every `session` connection.

## Alternatives considered
Passing `load_vec=True` at each Memory call site was rejected: it needs several edits, adds sanctioned call sites to the check tool, and misses any new `session` caller. A module-level set constant was rejected for the same pinning reason.

## Implementation
### Target file
`scripts/db/helper.py`

### Procedure
1. Change the `_default_load_vec` assignment in `SQLiteHelper.__init__` from `resolved == "rag"` to `resolved in ("rag", "session")`.
2. Update the `open()` docstring line "None = use instance default (True for rag, False for session)" to state `True` for `rag` and `session`, `False` for `workflow` and `eventbus`.
3. Run the helper and Memory real-DB tests, then the check tool.

### Method
- `self._default_load_vec = resolved == "rag"` appears once, after `self._target = resolved`; replace only that expression.
- Keep the explicit `db_path` branch (`self._default_load_vec = bool(sqlite_vec_so)`) unchanged.
- Apply together with the `tools/check_db_separation.py` change in the same commit: `tests/tools/test_check_db_separation.py::test_live_repository_has_no_violations` fails between the two edits because the tool pins the old expression.

### Details
- Measure `open()` latency for `session` with and without the extension load once (Plan UNK-02) and record it in the commit message or the Plan's Execution Status notes; the implementer does not add code for it.
- No change to `_load_vec_extension` or to `scripts/db/create_schema.py` (its explicit `load_vec=True` stays valid and sanctioned).

## Compatibility considerations
Behavior change for every `session` connection (many call sites in `scripts/`): the extension is now loaded when `sqlite_vec_so` is configured. With `sqlite_vec_so` empty (tests that use an explicit `db_path` or a `DbConfig` without it) nothing changes. `workflow` and `eventbus` are unchanged.

## Security considerations
The extension path is the configured `sqlite_vec_so`; `_load_vec_extension` still disables extension loading immediately after loading. No new path or user input is introduced.

## Rollback considerations
Revert the commit; the real-DB tests then fail again on `no such module: vec0`, which is the intended regression signal. Revert together with the check-tool change.
