## Goal

Distinguish a user-initiated startup shutdown (`StartupInterrupted`) from a real startup failure in `AgentREPL.run()` so an intentional shutdown is not labeled "Startup failed" (`REQ-002`). Preserve the existing re-raise and `finally` resource cleanup (`REQ-003`).

## Scope

Two small changes in `scripts/agent/repl.py`: extend the `agent.startup` import to also import `StartupInterrupted`, and add an `except StartupInterrupted` branch before the generic `except Exception` in `run()`. No other changes.

## Assumptions

- `StartupInterrupted` is a `RuntimeError` subclass raised during startup (by the MCP starter and the retry helper on a SIGINT/SIGTERM shutdown request), so it currently flows through the generic `except Exception` branch in `run()`.
- The non-fatal shutdown message should be emitted via `write_warning` (non-fatal), consistent with how SKIPPED outcomes are reported elsewhere.

## Design decisions

- Insert an `except StartupInterrupted as e:` branch immediately before the existing `except Exception as e:` so the specific type is caught first while the generic handler still covers all other failures. Re-raise inside the new branch so shutdown proceeds; the outer `finally` still runs `close_resources()`.

## Alternatives considered

- Handle `StartupInterrupted` at the raise sites (`startup_mcp_starter.py`, `retry_helper.py`): rejected — the user-facing message belongs in `AgentREPL.run()`, which owns the startup-failure messaging, and the exception is raised through multiple sites. `N/A: centralize the message in run()`.

## Implementation
### Target file
`scripts/agent/repl.py`

### Procedure
In `AgentREPL.run()`, catch `StartupInterrupted` before the generic handler and emit a non-fatal, shutdown-appropriate message, then re-raise. Extend the `agent.startup` import accordingly.

### Method
1. Extend the existing `from agent.startup import StartupOrchestrator` import to also import `StartupInterrupted`.
2. Inside the outer `try` in `run()`, add an `except StartupInterrupted as e:` branch directly before the existing `except Exception as e:` branch. Emit a non-fatal warning via `self._view.write_warning` and then `raise`; leave the generic branch and the outer `finally` (`close_resources()`) untouched.

### Details
- `run()` wraps `await startup.run()` in a nested `try`; the inner `except Exception as e:` calls `self._view.write_fatal(f"Startup failed: {e}")` then `raise`. `StartupInterrupted` (a `RuntimeError` subclass) currently matches this generic branch and is reported identically to a real failure.
- Add `except StartupInterrupted as e:` before that generic branch. Prefix the warning with `OutputTag.NON_FATAL` and word the message as a shutdown/interrupt rather than a failure (e.g. a non-fatal "Startup interrupted" style message). Re-raise so the outer `finally` still closes resources and the interrupt propagates.
- The re-raise preserves the behavior already asserted in `tests/agent/test_startup_rollback.py` (that a startup interrupt propagates) and AC-004 (re-raise + `finally` unchanged).
- Confirm `StartupInterrupted` is raised during the startup path (before the input loop), so this branch only intercepts startup failures.
