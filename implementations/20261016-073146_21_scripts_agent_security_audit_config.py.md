## Design decisions

- Delete the module rather than empty it: every symbol in it exists to serve the audit, and a
  docstring-only module would keep a name that claims a capability the Agent no longer has.
- The Plan's frozen table lists this row's action as `Modify`; the correct action is `Delete`, and the
  Plan row is amended before execution.
- The four audit DTOs are not replaced by Agent-side mirrors. The posture DTOs from rows `02`-`03` are
  the Agent's only view of server security state, and they are built from a server's published posture,
  never from a server's config model.
- The `ImportError -> None` "server not installed" behavior disappears with the module. Each server's
  own validator (rows `7`-`16`) runs inside the server process, where its config model is always
  importable, so the conditional-import dance has no remaining purpose.
- The `RuntimeError` wrapping (`:57-60`, `:72-73`, `:89-92`, `:105-107`) disappears too. Config-load
  failure inside a server process is that server's own startup failure, and the Agent learns about it
  through the server's `/health` response or its unreachability (row `18` classification).

## Alternatives considered

- Keep the DTOs as Agent-side mirrors of server config for shadow comparison — rejected: `REQ-017`
  removes the cross-config read, and row `05` (`shared/security/shadow_validation.py`) compares
  published postures, not config mirrors.
- Keep the module but restrict it to reading `agent.toml` — rejected: `agent.toml` is already read by
  the Agent's own config layer, and the module's only content is server config access.
- Keep the loaders during Phase 1/2 to compare old audit warnings with new postures — rejected: that
  is exactly what row `05` provides, in `shared`, with an explicit removal phase; keeping two
  cross-config paths would make the import-linter exception (row `25`) impossible to remove.
