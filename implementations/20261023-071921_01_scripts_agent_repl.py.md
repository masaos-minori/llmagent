## Goal

Give `AgentREPL` sole ownership of the single shutdown `asyncio.Event` and construct every shutdown consumer from that one object, so no consumer ever holds `None`. Moves the event creation out of `run()` into `__init__` and deletes the `SignalHandler.set_shutdown_event()` rebinding call, leaving everything else byte-identical.

## Scope

Only `scripts/agent/repl.py`: the `_shutdown_event` field declaration and construction order in `__init__` (`:81`, `:84`, `:91`) and the event re-creation plus signal rebinding in `run()` (`:112`, `:113`, `:120`). No other source file, and no `docs/*.md` edit.

## Assumptions

- `AgentREPL` is instantiated once per process (`main()`, `repl.py:170-172`); the event lifetime is therefore the instance lifetime.
- Cancelling a `run_in_executor` `Future` cannot interrupt a worker already inside `input()` — measured, not assumed — so this change only guarantees the loop stops waiting for the read, not that the blocked worker releases the interpreter (that is `repl002`'s half).
- `loop.add_signal_handler()` is available in production (Linux, `deploy/start_agent.sh`); the Windows fallback is untouched.

## Design decisions

- One owner, constructed first. `__init__` creates the event before `ReplInputLoop` (`:84`) and `SignalHandler` (`:91`), passing the same instance to both. Rejected alternative: add `ReplInputLoop.set_shutdown_event()` beside `SignalHandler`'s at `:113-114`. That keeps two initialization states for one object and makes correctness depend on every future consumer remembering to rebind — exactly how this defect arose. The rebinding hook is deleted rather than duplicated (`REQ-005`).
- Keep `asyncio.Event | None` in both consumer signatures and keep the `None`-fallback read branch. Tightening to `asyncio.Event` would delete a defensive path `test_repl.py:674-680` deliberately covers and that `startup.py:53` and `http_lifecycle.py:290` also accept. The guarantee added is narrower and testable: no production call site passes `None` (AC-1).
- Bound the unwind in the sibling row (`repl_input_loop.py`); this row only fixes ownership so the bound becomes reachable.

## Alternatives considered

- Passing the event via a setter on `ReplInputLoop` as well as `SignalHandler`: rejected because it reintroduces the two-state initialization that caused the defect.
- Creating the event lazily on first `run()` instead of in `__init__`: rejected because a consumer could be constructed before `run()` and hold `None`; `AC-1` asserts identity at construction time.
