# Implementation Procedure: Update mcp_tool_discovery.py to use unified required field

## Goal

Replace environment-based branching logic (`cfg.required_in_production if is_prod else cfg.required_in_local`) with unified `cfg.required` field, and remove `FailurePolicy` comparison against non-FAIL_FAST values.

## Scope

- Replace `is_prod` conditional on lines 131-136 with single `cfg.required` access
- Remove `cfg.failure_policy == FailurePolicy.FAIL_FAST` comparison — since only FAIL_FAST remains, any unreachable server that is required should always produce FATAL
- Simplify the status determination logic accordingly

## Assumptions

- After Plan 2 Step 1 completes, `FailurePolicy` will contain only `FAIL_FAST`, making the comparison redundant
- After Plan 2 Step 1 completes, `McpServerConfig` will have a single `required` field replacing both `required_in_production` and `required_in_local`
- No external consumers depend on `required_in_production` or `required_in_local` field names (verified by inspecting `config/agent.toml`)

## Design decisions

- Since only `FAIL_FAST` remains as a valid policy value, the condition `is_required and cfg.failure_policy == FailurePolicy.FAIL_FAST` simplifies to just `is_required` — any required unreachable server must produce FATAL
- Drop the `is_prod` variable entirely; the unified `required` field applies uniformly across all environments per ADR-004 Principle #3

## Alternatives considered

- Could keep the `failure_policy` comparison for forward compatibility if new policies are added later — but ADR-004 requires Fail-Fast only, so adding future-proofing here contradicts the design intent
- Could add a deprecation warning when non-FAIL_FAST values are compared — unnecessary since no config entries use those values
