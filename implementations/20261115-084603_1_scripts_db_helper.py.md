## Goal
- Add a read-only open mode to `SQLiteHelper` so probes can verify databases without side effects.

## Scope
**Release unit**: N/A: not part of a release unit (plan Phase 1 is independently validatable — additive Helper parameter, default behavior unchanged)

- In scope: `scripts/db/helper.py` — `read_only` open mode, ro-URI connect branch, read-only pragma path (REQ-001).

## Assumptions
- `sqlite3.connect("file:...?mode=ro", uri=True)` raises `OperationalError` (does not create) for absent files — standard SQLite behavior; the Plan's mechanism assumption, behaviorally asserted by the companion unit tests in `implementations/20261115-084603_4_tests_db_test_sqlite_helper.py.md` (AC-1).
- Extension loading (`load_vec`) is connection-local and legal on read-only connections (Plan Design); vec behavior stays unchanged.
- `scripts/agent/services/*` and all production opens keep the default read-write path untouched (Issue AI Instruction: production pragma policy unchanged).

## Design decisions
- `open()` gains a `read_only` (new) keyword defaulting to `False`; the ro branch is extracted into `_connect_read_only` (new) rather than deepening `open`, keeping `open` at radon B(8) (plan Validation plan row).
- Pragma gating through a `read_only` (new) keyword on `apply_connection_pragmas`: when true it applies only `busy_timeout` and skips `journal_mode`/`synchronous`/`foreign_keys`. Chosen over a sibling apply_read_only_pragmas function (Plan Design allows either): one function keeps the pragma vocabulary in one place for Plan 005's teardown work on this file.

## Alternatives considered
- Separate ProbeHelper class: rejected in the Plan Design — duplicates lifecycle, config boundaries, and vec loading for one flag.
- Making `mode=ro` the default for all opens: rejected — the Issue Constraint keeps normal write connections on the current pragma policy.

## Implementation
### Target file

### Procedure
1. `apply_connection_pragmas` (`:32-42`): add the keyword `read_only` (new) `bool = False`; when true, execute only `PRAGMA busy_timeout` and return before the `journal_mode`/`synchronous`/`foreign_keys` statements (`:38-42`) (REQ-001).
2. Add `_connect_read_only` (new) next to `_connect` (`:134-149`): connect with `sqlite3.connect(f"file:{pathname2url-escaped path}?mode=ro", uri=True, timeout=self._sqlite_timeout, check_same_thread=self._check_same_thread)`; escape the path with `urllib.request.pathname2url` so exotic paths stay valid URIs; on failure log and re-raise like `_connect` — a missing path must surface `sqlite3.OperationalError`, never create a file (REQ-001, AC-2 mechanism).
3. `open()` (`:180-187`): add the keyword `read_only` (new) `bool = False`; when set, obtain the connection via `_connect_read_only` (new) and pass `read_only=True` through `_apply_connection_pragmas` (`:169-176`, which forwards to `apply_connection_pragmas`) and the `open` call site (`:211`); when unset, behavior is byte-for-byte the current path (REQ-001).
4. Keep `load_vec` handling (`:207-210`) unchanged in both branches (vec loading on a ro connection is legal).
