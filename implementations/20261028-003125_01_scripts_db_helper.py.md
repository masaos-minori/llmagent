## Goal

Add a `check_same_thread` pass-through to `SQLiteHelper` so a connection created by the
turn-boundary can legally be used (sequentially) from `asyncio.to_thread` worker threads
(REQ-002). Default behavior stays `True` (sqlite3 default) for every existing caller.

## Scope

- Only `scripts/db/helper.py`:
  - `SQLiteHelper.__init__` (L62-87): new keyword `check_same_thread: bool = True`
    (new), stored as `self._check_same_thread`.
  - `SQLiteHelper.open` (L166-196): new keyword `check_same_thread: bool | None = None`
    (new); `None` = use the instance default; an explicit value applies to this open
    only (mirrors the existing `load_vec` override pattern L171/L185).
  - `_connect` (L128-138): pass `check_same_thread=self._check_same_thread` into
    `sqlite3.connect` (currently no such argument at L135 — verified against current
    source).
- No change to `reuse_connection`, PRAGMA application, `_load_vec_extension`, or `close`.

## Assumptions

- Shipped-vs-plan discrepancy (Step 2 verification): the frozen row cites the turn001
  Plan Design "one reused write connection per turn", but the shipped
  `scripts/agent/turn_persistence.py` delegates to `SessionMessageRepository` methods
  that open one connection per call. The knob is still required by REQ-002 for the
  boundary-side offload document (`..._02_...`) and is validated by the probe test
  (`..._08_...`); with the per-call pattern the knob stays at its default and no
  existing caller behavior changes.
- `check_same_thread=False` relaxes only the same-thread assertion; the plan's safety
  argument is sequential use guaranteed by sequential `await` of boundary phases
  (REQ-003), never concurrent use.
- No config plumbing: this is a code-level knob only; `agent.toml`/`DbConfig` gain no
  new keys (Plan out-of-scope: no WAL/busy_timeout changes).
- Batch overlap scan (`tools/check_plan_target_overlaps.py`, this pass): no finding
  names `scripts/db/helper.py` in this Plan; no sequencing dependency against sibling
  plans in the batch.

## Design decisions

- Two-level knob (instance default + per-open override) mirrors the existing `load_vec`
  design in the same class; a single constructor-only knob would force every
  boundary-opened helper instance to be constructed differently from all others.
- Type `bool | None = None` on `open` (not plain `bool`) so that not passing the
  argument cannot silently flip the instance default to `True` for a helper configured
  with `False`.

## Alternatives considered

- Open-only knob (no `__init__` parameter): rejected — the frozen row's Change
  Responsibility explicitly names `__init__`/`open` pass-through.
- Default `check_same_thread=False` globally: rejected — REQ-002 states all other
  usage keeps `True`; the sqlite3 default is the safe choice for single-thread callers.

## Implementation

### Target file

`scripts/db/helper.py`

### Procedure

Thread the new keyword from `__init__` through `open` into `_connect` without touching
any existing parameter.

### Method

1. `__init__`: add `check_same_thread: bool = True` after `sqlite_busy_timeout_ms`;
   set `self._check_same_thread = check_same_thread` before both the `db_path`
   early-return branch (L80-87) and the config branch, so both paths initialize it.
2. `open`: add `check_same_thread: bool | None = None`; after the `reuse_connection`
   short-circuit (L183-184), set
   `if check_same_thread is not None: self._check_same_thread = check_same_thread`
   before calling `self._connect()`.
3. `_connect`: change L135 to
   `sqlite3.connect(self._db_path, timeout=self._sqlite_timeout, check_same_thread=self._check_same_thread)`.
4. Update the class/method docstrings to state the default (`True`) and that `False`
   is only for sequential cross-thread use.

### Details

- The `reuse_connection and self.conn is not None` short-circuit (L183-184) returns
  before `_connect` runs; a `check_same_thread` override on a reused connection cannot
  re-configure the already-open connection — document this in the `open` docstring.
- `sqlite3.connect` accepts `check_same_thread` as a keyword; no vendor-specific
  handling needed (stdlib sqlite3, CPython 3.13).

  already owns. Misuse (concurrent cross-thread use) is guarded by convention:
  sequential awaits only (recorded in docs row `..._15_...`).
