## Assumptions

- `drift_report` compares `{id for gate in ROUTING_GATES}` (`actual`) against the ids
  derived from every `routing.md` "Run" cell (`expected`). Adding a routing gate makes
  `actual` contain `uv`; without a matching row `actual - expected` is non-empty and the
  check exits non-zero.
- `_checker_id_from_cell` strips backticks/escaping and splits on whitespace, then applies
  the same id rule as `Gate.checker_id`: with no `tools/<name>.py` token it returns the
  first token. So `` `uv run ruff format --check <changed files>` `` derives to `uv`.
- The ruff hooks in `.pre-commit-config.yaml` stay remote/entry-less, so
  `parse_precommit_hooks` skips them and no `COMMIT_ONLY_HOOKS` entry is needed; the
  hook-parity half of the drift check is unchanged.

## Design decisions

- **One row, "Run" cell deriving to `uv`.** The Situation column states the trigger
  (a `scripts/` Python file changed); the Run cell shows the command with a `<changed
  files>` placeholder for readability. The placeholder does not affect id derivation (only
  the first token `uv` matters), so `expected` gains `uv` and `actual == expected`.

## Alternatives considered

- **Deriving `uv` from a different first token.** Rejected: the gate's command starts with
  `uv`, so the Run cell must start with `uv` too; any other first token would make
  `actual != expected` and fail the drift check.
