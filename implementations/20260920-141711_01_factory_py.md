## Goal

Refactor `scripts/agent/factory.py` to reduce complexity by splitting `_ServerLifecycleRouter`, removing dead code, standardizing builder function patterns, and improving type safety — while preserving the `LifecycleManagerProtocol` contract and public behavior.

## Scope

- Remove unused `_COOLDOWN_TIMEOUT_SEC` constant (REQ-001)
- Split `_ServerLifecycleRouter` into two classes: coordinator (`_ServerLifecycleRouter`) + subprocess manager (`_SubprocessLifecycleManager`) (REQ-002)
- Replace private `_http_procs` access with `verify_running()` call (REQ-003)
- Standardize builder function return types using dataclass wrappers (REQ-004)
- Fix `object` type annotations in memory builders with proper generics (REQ-005)

## Assumptions

- `LifecycleManagerProtocol` contract must be preserved — no breaking changes to the protocol interface. Confirmed by reading `lifecycle_protocol.py:22-64`.
- Both `_ServerLifecycleRouter` and `_SubprocessLifecycleManager` should implement `LifecycleManagerProtocol`. Stated in Plan Implementation Intent #2.
- `AppServices` constructor signature compatibility must be maintained. Confirmed by reading `context.py:248-282`.
- No other callers consume tuple returns from `_build_llm_client`, `_build_tool_executor`, or `_build_history_manager` outside `factory.py`. Verified via grep.
- `RuntimeToolRegistry` on `AppServices` is populated post-construction via `startup_validation.py:85`; no additional wiring needed.

## Design decisions

1. **Two-class split**: Extract subprocess lifecycle methods (`ensure_ready`, `start_http_subprocess`, `restart`, `shutdown_idle`) into `_SubprocessLifecycleManager`. Keep state/cooldown logic in `_ServerLifecycleRouter` as coordinator. Both implement `LifecycleManagerProtocol`. Rationale: SRP violation identified — six distinct responsibilities in one class; subprocess operations are conceptually separate from state management.

2. **Use existing `verify_running()` method**: Replace private `_http_procs` access with `self._http_mgr.verify_running(server_key)` — no new method needed. Adversarial validation confirmed `HttpServerLifecycleManager` already has a public `verify_running(server_key: str) -> bool` at line 134.

3. **Dataclass wrappers for multi-return builders**: Introduce named dataclasses for `_build_llm_client`, `_build_tool_executor`, `_build_history_manager` instead of returning tuples. Tuple returns make it impossible to track which caller consumes which element.

4. **Generic type bounds for memory builders**: Replace `object` with `TypeVar` constraints where possible. `_build_retriever[T]` already uses generics properly; other builders like `_build_embedding_client` and `_build_jsonl_store` return `-> object` which loses type information.

## Alternatives considered

- **Single narrower sub-protocol for `_SubprocessLifecycleManager`**: Instead of having both classes implement `LifecycleManagerProtocol`, create a narrower `_SubprocessLifecycleProtocol` that only includes subprocess-relevant methods. Trade-off: clearer delegation pattern but adds another protocol to maintain. Decision: follow Plan's stated intent (both implement full protocol).
- **Return typed dicts instead of dataclasses**: Simpler syntax but less IDE support and runtime introspection. Decision: use dataclasses for explicit field names and better type safety.

#### Step 2: Split _ServerLifecycleRouter

**Why**: SRP violation — six distinct responsibilities in one class identified by Plan.

**Actions**:
