## Goal

Fix `StartupOrchestrator._recover_pending_approvals()` in `scripts/agent/startup.py` so it selects the most recent (newest `created_at`, tie-broken by highest `rowid`) pending approval on restart, instead of the oldest. Add regression test that pins this behavior.

## Scope

**In-Scope:**
- `scripts/agent/startup.py:518-519` — change `results[-1]` to `results[0]` (since `find_all_pending_approvals()` returns rows `ORDER BY a.created_at DESC, a.rowid DESC`, `results[0]` is the newest).
- Verify comment at `scripts/agent/startup.py:518` and log/warning text at `scripts/agent/startup.py:529-540` still accurately describe the selection after the fix.
- Update existing test `tests/test_startup.py::TestStartupOrchestratorRecoverPendingApprovals::test_startup_recovery_shows_last_of_multiple_pending_approvals` — flip mock ordering to `[("task-new", approval2), ("task-old", approval1)]` (newest first, matching real DESC-ordered contract).
- Add new regression test in `tests/test_startup.py` asserting newest (first element of DESC-ordered list) is selected; includes comment noting test fails against pre-fix `results[-1]` code path.

**Out-of-Scope:**
- `scripts/agent/workflow/approval_ops.py::find_all_pending_approvals()` — no change.
- `find_latest_pending_approval()` — already correctly uses `LIMIT 1` with `DESC`.
- Any other approval/workflow command handling (`/approve`, `/reject`).
- Broader refactor of `StartupOrchestrator` or `approval_ops.py`.

## Assumptions

1. `find_all_pending_approvals()` will continue to return rows ordered `DESC` by `created_at` then `rowid`.
2. No caller other than `scripts/agent/startup.py:513` invokes `find_all_pending_approvals()`.
3. Test runner is `pytest` via `uv run pytest`.

## Design decisions

- **Option 1 chosen**: Fix the consumer index (`results[-1]` → `results[0]`) rather than flipping `ORDER BY` to `ASC` in `find_all_pending_approvals()`. Rationale: minimal change, no impact on any future callers of `find_all_pending_approvals()`.

## Alternatives considered

- Option 2: Flip `ORDER BY` to `ASC` in `find_all_pending_approvals()` and keep `results[-1]`. De-prioritized because option 1 is sufficient and no other caller depends on `DESC` ordering.
