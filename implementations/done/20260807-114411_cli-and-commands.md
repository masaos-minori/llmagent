# Implementation Procedure: docs/05_agent_07_*_cli-and-commands*.md

## Goal

Reduce `docs/05_agent_07_*_cli-and-commands*.md` documents to canonical sources for CLI operation and command-usage caveats by removing full argument tables and handler/mixin detail, while preserving operational judgments and deprecated-command information.

## Scope

**In-Scope**:
- Restructure all 11 files in `docs/05_agent_07_*_cli-and-commands*.md` to preserve: what the CLI provides, the `CommandRegistry`/`CLIView`/REPL responsibility split, `/reload`'s reflected scope and what requires a restart, deprecated-command migration judgment, how `/mcp tools`/`/mcp status` are used operationally, where the command-list source of truth lives, commonly-misunderstood behaviors (`/reload` does not reflect all settings, `/mcp status` shows currently-running server state only, `/diff` depends on current history).
- Remove: full per-command argument tables, plain side-effect enumeration, handler names and mixin composition, readline/prompt-string UI implementation detail, full old-command sub-command mapping tables.
- **CRITICAL**: Never drop deprecated-command judgment (status/successor/compatibility) during trimming. After trimming, explicitly re-verify: all deprecated-command entries still have their status, successor, and compatibility information intact.
- When in doubt about whether a detail is safety-relevant, keep it and mark for human review rather than deleting.
- Replace full argument tables with a pointer to `command_defs_list.py` (the authoritative source) rather than re-transcribing.
- Rephrase operational concepts as judgments (why), not just mechanical descriptions.
- Reformat using the template: Purpose / Design Intent / Responsibility Boundary / Key Constraints / Operational Notes / Known Limitations / Related Docs.
- Mark unrecoverable design rationales as `Needs Confirmation`.

**Out-of-Scope**:
- Modifying other documents in the `05_agent_*.md` set.
- Adding new content beyond what exists in the current documents.
- Changing the doc set directory structure.

## Assumptions

1. The `memo-doc-agent-review.md` referenced in acceptance criteria existed during the original review but may have been moved or deleted since then.
2. `tools/check_agent_docs_consistency.py` is available and functional for post-edit verification, including the slash-command drift check against `command_defs_list.py`.
3. `command_defs_list.py` exists and serves as the authoritative source for command definitions.
4. All 11 target files form a coherent logical unit (CLI reference + CLIView + CommandRegistry + purpose + REPL + hot-reload + migration + slash commands for session/MCP/context-db/workflow-debug/memory-other).

## Design decisions

- CLI documentation should answer "what can I do" and "how do I use it correctly," not "which handler class implements which command."
- Full argument tables and handler enumerations are visible in code and add no operational value.
- Canonical Source Rule applies: when a fact is mechanically derivable from code, point to the source rather than transcribing it.
- Unrecoverable design rationales must be explicitly marked `Needs Confirmation` rather than silently dropped.
- Deprecated-command judgment must never be silently dropped — when in doubt, keep and mark for human review.

## Alternatives considered

- Keep current format: violates the principle that mechanical inventories should not be maintained manually.
- Replace with auto-generated API reference: would reduce maintenance burden but loses human-curated narrative. Not pursued without explicit request.
