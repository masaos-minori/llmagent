# Implementation Procedure: Fix FD Leak and Zombie Process on Subprocess Startup Failure

## Goal

Eliminate file descriptor leak and prevent zombie processes when `getpgid()` fails during HTTP subprocess MCP server startup.

## Scope

**In-Scope:**
- Use try-finally to guarantee file handle closure regardless of exceptions during startup
- Kill the process if it survives terminate/kill escalation in the getpgid failure path

**Out-of-Scope:**
- Fixing file handle leaks in other error paths (separate concern)
- Adding retry logic to the getpgid operation
- Handling the case where pgid is lost due to OSError (the process group is already lost)

## Assumptions

1. When `getpgid()` fails, the process group information is unrecoverable — we must fall back to per-process termination
2. A process that survives terminate+kill is truly stuck and needs SIGKILL on the process directly
3. The file handle should always be closed even if an exception occurs between opening and cleanup

## Design decisions

- Restructure getpgid failure path using try-finally to guarantee cleanup
- Add explicit `proc.kill()` call when process survives terminate/kill escalation
- Wrap `proc.kill()` in try-except for ProcessLookupError/OSError to handle race conditions
- Raise exception after cleanup to propagate error to caller

## Alternatives considered

- Inline cleanup without try-finally → rejected; doesn't solve FD leak problem
- Using context manager for subprocess lifecycle → deferred; adds complexity without clear benefit
- Making getpgid retryable → rejected; low priority given rare occurrence

### Method

Implement robust error handling in the startup sequence using explicit `except` blocks.

```python
try:
    self._http_pgids[server_key] = os.getpgid(proc.pid)
except OSError as e:
    logger.warning(
        "Lifecycle: getpgid() failed for %r pid=%d; cleaning up",
        server_key,
        proc.pid,
    )
    await self._terminate_with_timeout(proc, server_key)
    poll_result = proc.poll()
    if poll_result is None:
        logger.warning(
            "Lifecycle: subprocess %r (pid=%d) still alive after terminate/kill; killing",
            server_key,
            proc.pid,
        )
        try:
            proc.kill()
        except (ProcessLookupError, OSError):
            pass
    elif poll_result != 0:
        logger.info(
            "Lifecycle: subprocess %r (pid=%d) terminated with exit code %d",
            server_key,
            proc.pid,
            poll_result,
        )
    # Cleanup resources
    stderr_fh.close()
    self._stderr_files.pop(server_key, None)
    self._stderr_log_paths.pop(server_key, None)
    self._http_procs.pop(server_key, None)
    self._http_pgids.pop(server_key, None)
    raise e
```
