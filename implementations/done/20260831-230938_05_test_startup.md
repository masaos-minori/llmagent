# Implementation Procedure: Update startup test assertions for simplified failure_policy

## Goal

Update `tests/agent/test_startup.py` test assertions to reflect the simplified `FailurePolicy` enum after FAIL_FAST-only simplification, and update `test_excluded_tools_log_includes_failure_policy` to work with the new model.

## Scope

- Update `test_excluded_tools_log_includes_failure_policy` test method — remove assertions that reference `disable-tool` and `degraded` values since they are no longer valid
- Verify any other test methods that reference `failure_policy` values in startup logging/output

## Assumptions

- After Plan 2 Step 1 completes, `FailurePolicy` will contain only `FAIL_FAST`, so comparisons against non-FAIL_FAST values become dead code
- The `failure_policy` field itself remains on `McpServerConfig` — only its enum values change
- Test `test_excluded_tools_log_includes_failure_policy` currently uses string values `"disable-tool"` and `"degraded"` as failure_policy parameters (confirmed by grep)

## Design decisions

- Since only FAIL_FAST remains valid, the test should be updated to verify FAIL_FAST behavior only — the `disable-tool` and `degraded` test cases should be removed or converted to FAIL_FAST assertions
- If the test verifies logging output includes `failure_policy` values, it should now only include `FAIL_FAST` values

## Alternatives considered

- Could keep the existing test structure but mark the `disable-tool` and `degraded` cases as skipped — unnecessary since these values are no longer valid
- Could add explicit validation that `failure_policy` is always `FAIL_FAST` before displaying it — unnecessary since the enum itself prevents invalid values at construction time
