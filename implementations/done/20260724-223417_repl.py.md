## Goal

Ensure WAL checkpoint failure does not result in silent data loss during shutdown.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL._close_resources())
**Out**: Changes to SQLiteHelper internals, other database maintenance operations

## Assumptions

1. `db.checkpoint("TRUNCATE")` can fail due to exclusive access requirements
2. `PRAGMA wal_checkpoint(PASSIVE)` may succeed where `TRUNCATE` fails because it doesn't require exclusive access
3. `SQLiteHelper("session").open(write_mode=True)` creates a new connection each time

## Design decisions

- Add PASSIVE checkpoint as a pre-check before TRUNCATE — minimal change surface, leverages existing `db.checkpoint()` method
- Retry TRUNCATE with exponential backoff only — avoids unnecessary complexity of full retry framework
- Copy WAL file to backup location before closing connection — preserves data even if checkpoint fails entirely
- Use `asyncio.sleep` for backoff — consistent with async context of `_close_resources()`

## Alternatives considered

- Only add PASSIVE checkpoint without TRUNCATE retry: simpler but loses the benefit of TRUNCATE's aggressive WAL truncation
- Implement full retry with jitter: adds complexity for marginal improvement over fixed exponential backoff
- Delete WAL file instead of copying: risks data loss if WAL contains uncommitted writes

## Implementation

### Target file

`scripts/agent/repl.py`

### Procedure

1. Before attempting `db.checkpoint("TRUNCATE")`, first try `db.checkpoint("PASSIVE")` at line 264. If PASSIVE succeeds, log and skip TRUNCATE.
2. If PASSIVE fails, wrap `db.checkpoint("TRUNCATE")` in a retry loop with up to 3 attempts and exponential backoff (1s, 2s, 4s).
3. After retries are exhausted, change the log level from WARNING to ERROR at line 29-30.
4. Before closing the connection in the finally block, copy the WAL file (`{db_name}-wal`) to a backup location so data can be recovered manually.
5. Ensure the session connection is properly closed regardless of checkpoint outcome.

Replace with:

```python
        # WAL checkpoint before closing connections
        wal_backup_path: str | None = None
        try:
            with SQLiteHelper("session").open(write_mode=True) as db:
                wal_mode = db.execute("PRAGMA journal_mode").fetchone()[0]
                if wal_mode.lower() != "wal":
                    logger.debug("WAL checkpoint skipped: journal mode is %r", wal_mode)
                    continue
                # Try PASSIVE checkpoint first (no exclusive lock required)
                try:
                    db.checkpoint("PASSIVE")
                    logger.info("WAL checkpoint completed (PASSIVE) on shutdown")
                    continue
                except sqlite3.Error as passive_err:
                    logger.warning("WAL PASSIVE checkpoint failed, falling back to TRUNCATE: %s", passive_err)
                # Retry TRUNCATE checkpoint with exponential backoff
                truncated = False
                for attempt in range(3):
                    try:
                        db.checkpoint("TRUNCATE")
                        logger.info("WAL checkpoint completed (TRUNCATE) on shutdown after %d retries", attempt + 1)
                        truncated = True
                        break
                    except sqlite3.Error as truncate_err:
                        if attempt < 2:
                            logger.warning("WAL TRUNCATE checkpoint attempt %d failed, retrying: %s", attempt + 1, truncate_err)
                            asyncio.sleep(2 ** attempt)
                        else:
                            logger.error("WAL TRUNCATE checkpoint failed after 3 attempts: %s", truncate_err)
                            errors.append(("wal_checkpoint_truncate", f"{type(truncate_err).__name__}: {truncate_err}"))
                if not truncated:
                    # Copy WAL file to backup location before closing connection
                    try:
                        import shutil
                        db_path = db.execute("PRAGMA database_list").fetchone()[1]
                        if db_path:
                            wal_file = f"{db_path}-wal"
                            backup_dir = os.path.dirname(db_path) or "/tmp"
                            wal_backup_path = os.path.join(backup_dir, f"{os.path.basename(db_path)}-wal-backup-{int(time.time())}")
                            shutil.copy2(wal_file, wal_backup_path)
                            logger.warning("WAL file backed up to %s", wal_backup_path)
                    except Exception as backup_err:
                        logger.error("Failed to backup WAL file: %s", backup_err)
        except sqlite3.Error as e:
            errors.append(("wal_checkpoint", f"{type(e).__name__}: {e}"))
            logger.error("WAL checkpoint failed on shutdown: %s", e)
```

Key points:
- PASSIVE checkpoint tried first; if successful, skip TRUNCATE entirely
- TRUNCATE retried up to 3 times with exponential backoff (1s, 2s, 4s)
- On final TRUNCATE failure, WAL file copied to backup location using `shutil.copy2`
- Log level changed from `WARNING` to `ERROR` for final checkpoint failure
- Import statements for `shutil`, `os`, `time` added at top of function scope

## Compatibility considerations

- No API changes — internal behavior change only
- Existing callers of `_close_resources()` unaffected
- WAL backup files created with timestamp suffix to avoid name collisions across rapid restarts

## Security considerations

- WAL backup written to same directory as original DB — no cross-directory permission issues expected
- Backup filename includes timestamp to prevent accidental overwrite of previous backups
- `shutil.copy2` preserves file metadata — useful for forensic analysis

## Rollback considerations

- If WAL backup creation causes issues, revert by removing the WAL copy logic and keeping only the PASSIVE pre-check + TRUNCATE retry
- If exponential backoff delays shutdown too much, reduce retry count from 3 to 2
- No data loss risk — original WAL file remains intact regardless of backup operation
