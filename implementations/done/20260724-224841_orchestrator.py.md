## Goal

Ensure the allowed_tools override is scoped to the turn lifecycle and always restored, regardless of where exceptions occur within the turn processing pipeline.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._process_turn())
**Out**: Changes to AgentConfig internals, other configuration override patterns

## Assumptions

1. `_process_turn()` is called sequentially per turn (no concurrent turns)
2. The context manager approach is acceptable for scoping configuration changes
3. `ctx.cfg.tool.allowed_tools` is a mutable reference that can be safely overridden

## Design decisions

- Use `@contextmanager` decorator for `_tool_override` — standard Python pattern, ensures guaranteed cleanup via finally block
- Keep `_tool_override` as an internal method rather than exposing it publicly — scoped to Orchestrator only
- No additional concurrency guards needed — `_process_turn` is called sequentially per turn by design

## Alternatives considered

- Keep existing try/finally pattern: works but less idiomatic; context manager makes the intent clearer
- Use a separate config snapshot/restore mechanism: overkill for a single-field override
- Add a `__enter__/__exit__` to the Orchestrator class: too broad scope for a narrow concern
