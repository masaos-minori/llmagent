## Goal

Protect sensitive diagnostic data by filtering redacting fields before persistence. Add optional encryption and automatic retention policies to reduce exposure risk.

## Scope

- Define and implement filter that removes or redacts sensitive fields from diagnostic summary
- Add optional encryption layer using configurable key for diagnostic data storage
- Implement retention policy that automatically deletes records older than configurable period
- Log warnings when sensitive data is filtered out

## Assumptions

- Sensitive fields should be redacted (not removed) to preserve data structure integrity
- Encryption key should be loaded from environment variable or configuration file
- Retention policy default should be 30 days
- Redaction should replace values with "[REDACTED]" while preserving field names
- Encryption should use AES-256-GCM for authenticated encryption

## Design decisions

- **Redaction over removal**: Replace sensitive field values with "[REDACTED]" rather than removing them entirely. Preserves data structure for downstream consumers while protecting sensitive content.
- **Optional encryption via env var**: Enable encryption only when DIAGNOSTIC_ENCRYPTION_KEY is set. Avoids forcing encryption on deployments that don't need it.
- **Asynchronous retention cleanup**: Use asyncio.create_task() for retention cleanup to avoid blocking diagnostic saves. Cleanup runs in background after each save.
- **AES-256-GCM encryption**: Provides both confidentiality and authenticity. Random nonce per record prevents replay attacks.

## Alternatives considered

- **Remove sensitive fields entirely**: Would break downstream consumers expecting consistent schema. Redaction preserves structure.
- **Mandatory encryption**: Too restrictive for deployments without security requirements. Opt-in approach more flexible.
- **Synchronous retention cleanup**: Would delay diagnostic saves. Background task approach keeps saves fast.
- **Symmetric encryption only**: AES-256-GCM provides authenticated encryption. Asymmetric would add complexity without clear benefit for this use case.

   ```python
   def _redact_sensitive_fields(self, diagnostic_data: dict) -> dict:
       """Redact sensitive fields from diagnostic data."""
       import copy
       
       redacted = copy.deepcopy(diagnostic_data)
       
       # Redact artifact URIs
       if "artifacts" in redacted and isinstance(redacted["artifacts"], list):
           redacted["artifacts"] = ["[REDACTED]"] * len(redacted["artifacts"])
           logger.warning(f"Redacted {len(redacted['artifacts'])} artifact URI(s)")
       
       # Redact RAG outcomes
       if "rag_stage_outcomes" in redacted and isinstance(redacted["rag_stage_outcomes"], list):
           redacted["rag_stage_outcomes"] = ["[REDACTED]"] * len(redacted["rag_stage_outcomes"])
           logger.warning(f"Redacted {len(redacted['rag_stage_outcomes'])} RAG outcome(s)")
       
       # Aggregate latency_summary to remove per-step details
       if "latency_summary" in redacted:
           summary = redacted["latency_summary"]
           if isinstance(summary, dict):
               aggregated = {}
               for stage, durations in summary.items():
                   if isinstance(durations, list):
                       aggregated[stage] = {
                           "count": len(durations),
                           "avg_ms": sum(durations) / len(durations) if durations else 0,
                           "max_ms": max(durations) if durations else 0,
                           "min_ms": min(durations) if durations else 0
                       }
               redacted["latency_summary"] = aggregated
               logger.info("Aggregated latency_summary to remove per-step details")
       
       return redacted
   ```

   ```python
   async def _encrypt_diagnostics(self, data: dict) -> tuple[str, bytes]:
       """Encrypt diagnostic data using AES-256-GCM. Returns (nonce, ciphertext)."""
       import os
       from cryptography.hazmat.primitives.ciphers.aead import AESGCM
       
       key_str = os.environ.get("DIAGNOSTIC_ENCRYPTION_KEY")
       if not key_str:
           return None, None  # No encryption configured
       
       key = AESGCM.generate_key(bit_length=256)  # In production, derive from key_str
       aesgcm = AESGCM(key)
   ```

   ```python
   async def _enforce_retention_policy(self):
       """Delete diagnostic records older than retention period."""
       import os
       from datetime import datetime, timedelta
       
       retention_days = getattr(self.config, 'diagnostic_retention_days', 30)
       cutoff_date = datetime.now() - timedelta(days=retention_days)
       
       # Get diagnostic store path
       diag_dir = getattr(self.config, 'diagnostic_store_path', '/opt/llm/data/diagnostics')
       if not os.path.exists(diag_dir):
           return 0
       
       deleted_count = 0
       for filename in os.listdir(diag_dir):
           if not filename.endswith('.json'):
               continue
           
           try:
               file_mtime = datetime.fromtimestamp(os.path.getmtime(os.path.join(diag_dir, filename)))
               if file_mtime < cutoff_date:
                   os.remove(os.path.join(diag_dir, filename))
                   deleted_count += 1
           except OSError:
               pass  # Skip files that can't be accessed
       
       if deleted_count > 0:
           logger.info(f"Retention policy: deleted {deleted_count} diagnostic record(s) older than {retention_days} days")
       
       return deleted_count
   ```

## Compatibility considerations

- **Data structure change**: Aggregating latency_summary changes the output format. Downstream consumers may need updates.
- **Encryption dependency**: Requires `cryptography` library. Must be added to project dependencies if not already present.
- **File-based retention**: Assumes filesystem storage. If persistence mechanism changes, retention logic must adapt.

## Security considerations

- **Sensitive data protection**: Primary security goal — prevent exposure of artifact URIs, RAG outcomes, and per-step latencies
- **Encryption key management**: Key stored in environment variable requires secure key rotation procedures
- **Nonce uniqueness**: Random nonce per record prevents replay attacks; ensure sufficient entropy
- **Information disclosure**: Redaction warnings should not expose which fields were redacted beyond counts

## Rollback considerations

- **Quick rollback**: Remove redaction/encryption calls and revert to original persist method
- **Data impact**: Encrypted records cannot be read without encryption key; consider migration strategy
- **Configurable mode**: Consider adding environment variable to toggle redaction/encryption without code changes
