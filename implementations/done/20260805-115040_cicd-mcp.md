# Implementation Procedure: conf.d/cicd-mcp

## Goal
- Remove the stale `--reload-mcp` reload instruction from `conf.d/cicd-mcp` and replace it
  with an accurate way to apply `GITHUB_TOKEN` changes (restart the agent process).

## Scope
- In scope: the comment block in `conf.d/cicd-mcp` that describes how to apply a config
  change after editing `GITHUB_TOKEN`.
- Out of scope: adding an automated config-reload mechanism; changing the `GITHUB_TOKEN=""`
  value line itself; any other `conf.d/*` file (tracked separately per file).

## Assumptions
- Same operational model as `conf.d/github-mcp`: no hot-reload path exists; the operator must
  restart the agent process for a new `GITHUB_TOKEN` to take effect (per source issue
  `issues/20260802-080732_deploy_github_token_setup_procedure_confirmation.md`).
- Spot check of the current file (`grep -n "reload-mcp\|再起動" conf.d/cicd-mcp`) shows the
  file already contains the line `設定を反映するには、エージェントプロセスを再起動してください。`
  and no `--reload-mcp` / `agent.py` reference. If this remains true at implementation time,
  this procedure is a verification-only no-op; re-check before editing in case the file was
  reverted.

## Design decisions
- Keep the fix as a plain-text comment edit; mirror the wording used in `conf.d/github-mcp`
  and `conf.d/web-search-mcp` so the three `conf.d/*` files stay consistent.
- Preserve the file's existing `[トークンの取得方法]` block, which is `cicd-mcp`-specific
  (Actions read/write scope), and only replace the "apply changes" instruction line.

## Alternatives considered
- Add an automated `--reload-mcp` CLI flag to `scripts/agent.py`: rejected — explicitly
  out of scope per the source plan.
- Remove the "apply changes" line entirely: rejected — operators need explicit guidance;
  silence would reintroduce the ambiguity the source issue raised.

## Implementation
### Target file
- `conf.d/cicd-mcp`

### Procedure
1. Re-run `grep -n "reload-mcp\|再起動" conf.d/cicd-mcp` to confirm current state before editing.
2. If a `--reload-mcp` / `agent.py --reload-mcp` line is present, replace it with:
   `設定を反映するには、エージェントプロセスを再起動してください。`
3. If the corrected line is already present (as observed at procedure-authoring time), make
   no edit and record the verification result instead.
4. Diff the file (`git diff conf.d/cicd-mcp`) to confirm only the comment line changed, if
   any change was made.

### Method
- Plain text edit via the standard editor tool (no code generation, no build step); this is a
  `conf.d` comment file, not Python source, so none of `rules/toolchain.md`'s
  lint/type/test/security steps apply.

### Details
- Current file (16 lines) already contains, at line 14:
  `# 設定を反映するには、エージェントプロセスを再起動してください。`
  and no `GITHUB_TOKEN` reload-script reference anywhere (verified via
  `grep -n "reload-mcp\|GITHUB_TOKEN\|agent.py" conf.d/cicd-mcp`).
- The `[トークンの取得方法]` block for this file lists Actions (read/write) and Contents
  (read) scopes specific to CI/CD workflow triggering — keep that block intact.
