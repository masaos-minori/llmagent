# Implementation: rules/coding.md — Phase 1: suppression governance documentation update

## Goal

Bring `rules/coding.md` §Suppression governance into agreement with the new
`pyproject.toml` select-list decision (`BLE001` active, `PLC0415` intentionally
excluded) and with the new automated enforcement tool, and fix the documented `rg`
examples so the `noqa` and `type: ignore` checks require an em-dash justification just
like the existing `nosec` check does.

## Scope

**In-Scope:**
- Record `BLE001` as active and `PLC0415`/`PLC` as an intentionally-inactive, documented
  exception (with a pointer to the evidence in the source plan).
- Fix the asymmetry in the `rg` one-liners at `rules/coding.md` lines 34-36: today only
  the `nosec` example (`grep -v ' — '`) checks for the em-dash; the `noqa` example
  (`grep -v '# noqa:'`) and `type: ignore` example (`grep -v '\['`) only check for a
  rule/error code being present. Update all three to also require the em-dash.
- Replace the "Constraint checks (run before every commit)" framing for suppression
  governance with a reference to the new automated pre-commit hook
  (`tools/check_suppression_justification.py` via `.pre-commit-config.yaml`).

**Out-of-Scope:**
- Any other section of `rules/coding.md` (Mandatory conventions, Tool configuration,
  Bandit priority findings, Key library choices, mypy note, Documentation notes,
  Prohibited behavior) — unchanged.
- `docs/*.md` updates — out of scope for this document-only phase per workflow
  constraints, and out of scope for the source plan itself.

## Assumptions

- Current `rules/coding.md` §Suppression governance (lines 28-37) reads:
  ```markdown
  ## Suppression governance

  Every `# noqa`, `# type: ignore`, and `# nosec` requires an inline justification.
  Suppressions without explanation are prohibited.

  ​```bash
  rg '# noqa' scripts/ | grep -v '# noqa:'        # noqa without rule code
  rg '# type: ignore' scripts/ | grep -v '\['      # ignore without error code
  rg '# nosec' scripts/ | grep -v ' — '           # nosec without comment
  ​```
  ```
- Per the plan's UNK-05 (resolved): this is a genuine documentation gap — the `noqa`/
  `type: ignore` examples never tested for the em-dash, only for a rule/error code being
  present. The plan requires fixing this in the same Phase-1 commit as the
  `pyproject.toml` change, not treating it as a separate follow-up.
- Per `rules/coding.md`'s own §Documentation notes classification table: this is a
  "Documentation fix required" case (the doc's own example is wrong), not an
  "Implementation fix required" issue-filing case — fixed directly here.

## Design decisions

- Keep the three example one-liners in the same `bash` block/format as today (minimal
  diff), only correcting the `grep` patterns and updating the surrounding tool-reference
  sentence — no restructuring of the section.
- Point to the automated check as the authoritative enforcement mechanism going forward;
  keep the manual `rg` one-liners as human-readable illustrations of what the automated
  check enforces, not as the sole enforcement mechanism (per plan Implementation Steps
  Phase 4: "Confirm `rules/coding.md` §Suppression governance now references the
  automated check ... rather than 'run before every commit'").

## Alternatives considered

- Remove the manual `rg` examples entirely now that an automated check exists — rejected:
  the examples remain useful as a quick, tool-free way for a human to spot-check
  suppression compliance in a specific file; the plan only asks to fix their asymmetry
  and add a reference to the automated check, not to delete them.

## Implementation

`rules/coding.md`

### Procedure

   `.pre-commit-config.yaml`'s new `check-suppression-justification` hook) as the
