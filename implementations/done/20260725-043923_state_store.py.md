## Goal

Route all workflow table queries through StateStore's public API instead of bypassing it with direct SQLiteHelper connections.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL._persist_session_diagnostics()), `scripts/agent/workflow/state_store.py` (StateStore)
**Out**: Changes to StateStore API surface, other workflow query patterns

## Assumptions

1. StateStore has access to the same workflow database connection that repl.py currently uses
2. Adding diagnostic query methods to StateStore is acceptable — these are legitimate read operations
3. The StateStore instance available during `_persist_session_diagnostics()` reflects any pending writes

## Design decisions

- Add four new methods to StateStore for diagnostic queries:
  - `count_tasks_by_session(session_id)` — returns task count
  - `count_workflows_by_session(session_id)` — returns distinct workflow count
  - `count_approvals_by_session(session_id)` — returns approval event count
  - `count_retries_by_session(session_id)` — returns execute-stage retry count
  - `list_artifacts_by_session(session_id)` — returns artifact URIs
- Replace the direct SQLiteHelper connection in `_persist_session_diagnostics()` with calls to these new StateStore methods

## Alternatives considered

- **Add a single aggregate diagnostic method to StateStore**: Would require complex query composition; separate methods are simpler and more testable
- **Create a dedicated DiagnosticService**: Over-engineered for five simple queries; StateStore already owns the workflow schema
- **Keep the direct SQLiteHelper connection but add logging**: Defeats the purpose of routing through StateStore; would leave the architectural violation intact

## Implementation

### Target files

`scripts/agent/workflow/state_store.py`

### Procedure

#### Step A: Add diagnostic query methods to StateStore

Current StateStore has task-related methods (`get_task_by_id`, `get_task_by_idempotency_key`, `get_task_by_session`, `get_latest_task`, `list_tasks`) but lacks the aggregate/diagnostic queries needed by `_persist_session_diagnostics()`.

Add after existing Task section methods:

```python
# ── Diagnostics ───────────────────────────────────────────────────────────────

def count_tasks_by_session(self, session_id: str) -> int:
    """Return the number of tasks for a given session."""
    rows = self._db.fetchall(
        "SELECT COUNT(*) as cnt FROM tasks WHERE session_id=?",
        (session_id,),
    )
    return int(rows[0]["cnt"]) if rows else 0

def count_workflows_by_session(self, session_id: str) -> int:
    """Return the number of distinct workflows for a given session."""
    rows = self._db.fetchall(
        "SELECT COUNT(DISTINCT workflow_id) as cnt"
        " FROM tasks WHERE session_id=? AND workflow_id IS NOT NULL",
        (session_id,),
    )
    return int(rows[0]["cnt"]) if rows else 0

def count_approvals_by_session(self, session_id: str) -> int:
    """Return the number of approval events for a given session."""
    rows = self._db.fetchall(
        "SELECT COUNT(*) as cnt FROM approvals"
        " WHERE task_id IN (SELECT task_id FROM tasks WHERE session_id=?)",
        (session_id,),
    )
    return int(rows[0]["cnt"]) if rows else 0

def count_retries_by_session(self, session_id: str) -> int:
    """Return the number of execute-stage retries for a given session.

    Retries are counted as attempts where stage_id='execute' minus the number
    of tasks (since each task gets exactly one initial attempt).
    """
    rows = self._db.fetchall(
        "SELECT COUNT(*) as cnt FROM attempts"
        " WHERE task_id IN (SELECT task_id FROM tasks WHERE session_id=?)"
        " AND stage_id='execute'",
        (session_id,),
    )
    task_count = self.count_tasks_by_session(session_id)
    raw_attempts = int(rows[0]["cnt"]) if rows else 0
    return max(0, raw_attempts - task_count)

def list_artifacts_by_session(self, session_id: str) -> list[str]:
    """Return artifact URIs for a given session."""
    rows = self._db.fetchall(
        "SELECT uri FROM artifacts WHERE task_id IN (SELECT task_id FROM tasks WHERE session_id=?)",
        (session_id,),
    )
    return [dict(r)["uri"] for r in rows]
```

Key points:
- All methods use parameterized queries — no SQL injection risk
- Return types match the original raw SQL results (int counts, list of strings)
- `count_retries_by_session` reuses `count_tasks_by_session` — avoids duplicate query
- Empty result sets handled consistently across all methods

### Method

Extract ownership of workflow query execution into the data access layer (`StateStore`). Add diagnostic query methods to StateStore's public API. Route all workflow table reads through StateStore to maintain consistency and prevent silent data loss from uncommitted writes.

### Details

The core issue is that `_persist_session_diagnostics()` bypasses StateStore entirely by creating its own SQLiteHelper("workflow") connection. This creates two problems:
1. Architectural violation — workflow queries should go through StateStore
2. Data visibility risk — if StateStore has pending writes that haven't been committed, the diagnostics will miss them

By adding diagnostic query methods to StateStore:
- All workflow queries route through a single code path
- Pending writes are visible because StateStore shares the same DB connection
- Query logic is centralized — easier to audit and maintain
