# Implementation Procedure: Improve LifecycleState transition error messages with valid targets

## Goal

Enhance `assert_valid_transition()` error messages to include valid target states, reducing debugging friction when invalid transitions occur.

## Scope

- Modify `assert_valid_transition()` in `scripts/agent/lifecycle.py` only

## Assumptions

1. `_VALID_TRANSITIONS` dictionary is always populated for known states; the `frozenset()` default on line 50 handles unknown states gracefully
2. Enum member names (`t.name`) are stable identifiers suitable for display (e.g., "STARTING", "FAILED")
3. Backward compatibility of the original error format prefix is required per the require document's instruction #4

## Design decisions

- Append valid targets as `f"Valid targets from {from_state!r}: {', '.join(t.name for t in valid_targets)}"` after the original error message
- For UNKNOWN state, list all 5 enum members since UNKNOWN allows any transition
- Handle edge case: if `from_state` is not in `_VALID_TRANSITIONS`, display `(none)` instead of empty string after join
- Keep original error format prefix: `"Invalid lifecycle transition: {from_state!r} -> {to_state!r}."`

## Alternatives considered

1. **Replace entire error message**: Would lose backward compatibility with any code parsing the old format. Appending preserves the original prefix.
2. **Use `repr(t)` instead of `t.name`**: Would show `<LifecycleState.STARTING: 'starting'>` which is verbose. Enum `.name` is cleaner and sufficient.
3. **Add a separate method for validation info**: Unnecessary — the function already has access to `_VALID_TRANSITIONS`.

## Compatibility considerations

- No callers explicitly parse the error message string — they catch via `except ValueError`. Adding text after the original format does not change exception type or behavior.
- The UNKNOWN state's special handling (line 42: `frozenset(LifecycleState)`) means it will never trigger an error, so listing all 5 enum members is harmless.

## Security considerations

N/A — no security implications. Only changes error message formatting.

## Rollback considerations

- No database or config changes to revert

New function:
```python
def assert_valid_transition(
    from_state: LifecycleState, to_state: LifecycleState
) -> None:
    """Raise ValueError when the transition from_state -> to_state is not legal."""
    valid_targets = _VALID_TRANSITIONS.get(from_state, frozenset())
    if to_state not in valid_targets:
        targets_str = ", ".join(t.name for t in valid_targets) if valid_targets else "(none)"
        raise ValueError(
            f"Invalid lifecycle transition: {from_state!r} -> {to_state!r}. "
            f"Valid targets from {from_state!r}: {targets_str}"
        )
```

Key changes:
- Line 50: Extract `valid_targets` lookup before the condition check (avoids duplicate lookup)
- Line 51: Use extracted `valid_targets` variable in the condition
- Line 52: Add logic to handle empty valid_targets — display "(none)" instead of empty string
- Lines 53-55: Update error message to append valid targets information after the original format
