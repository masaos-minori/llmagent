**since_seq/offset Precedence Note:**
Quote exact logic from `subscribe_route.py` lines 32-34:
```
start_seq = since_seq
if consumer_id and start_seq == 0:
    start_seq = read_offset(cfg.offsets_dir, consumer_id)
```
Rule: an explicit `since_seq=0` and an omitted `since_seq` (which defaults to 0 per the `Query(default=0)` declaration) are indistinguishable once `consumer_id` is supplied — both resolve to "read from stored offset." A client that wants a genuine full replay while also passing `consumer_id` cannot currently express that intent.

**Unknown/Mismatched Consumer Note:**
No consumer/event ownership column exists in `schema.sql`. `consumer_id` is accepted as any string and used only for `write_offset`/`read_offset`. Both `/subscribe` and `/events/{event_id}/ack` accept any string without validation against an event ownership registry. Document as explicitly unenforced (per Implementation instructions #1/#3), not silently omitted.
