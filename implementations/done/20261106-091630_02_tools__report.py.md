## Design decisions
- `ReportFinding` (new): frozen dataclass with required `message` and optional `file`, `line_no`, `severity`, `code`, `location` (all default empty or zero), so both styles and the traceability style fit without loss.
- `ReportProfile` (new): frozen dataclass of ordered `(output_key, record_field)` pairs, an optional sort key (a tuple of record fields, `None` keeps input order), and a `sort_output_keys` (new) flag. The three profiles `PROFILE_ISSUE` (new), `PROFILE_AUTHORITY` (new), and `PROFILE_WORKITEM` (new) reproduce the current outputs; the workitem profile maps `category` to `code`, `file` to `file`, `detail` to `message`, keeps input order, and sorts output keys.
- Renderers: `render_json(findings, profile)` (new) returns `orjson.dumps(..., option=OPT_INDENT_2 [| OPT_SORT_KEYS]).decode()`; `render_csv(findings, profile)` (new) uses `csv.DictWriter` with the profile's output keys and the default dialect; `render_text(findings)` (new) produces the grouped layout above, which only the traceability tool uses.
- `add_format_argument` (new), with the signature `(parser, choices, default)`, adds `--format` with the given choices and default and the current help text `Machine-readable output format (default: human-readable text)`.
- Converters `from_issue` (new) and `from_authority_finding` (new) accept any object with the matching attributes (typed with small `Protocol` classes), so this module imports neither `_docs_consistency_lib` nor `_adr_authority_core`.

### Method
- Sorting: when the profile has a sort key, sort a copy with `sorted(..., key=lambda f: tuple(getattr(f, name) for name in sort_key))`; never mutate the input list.
- JSON payload: a list of dicts built in profile key order; empty input renders `[]`.
- CSV: write rows as dicts keyed by output key; the writer's default line terminator keeps `\r\n`.

### Details
- No `print` and no logging in the module; renderers return strings so each tool keeps its own printing and exit-code logic.
- Unicode is written unescaped by `orjson`; the tests assert a non-ASCII message round-trips.
