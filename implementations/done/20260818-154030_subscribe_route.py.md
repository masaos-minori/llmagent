# Implementation Procedure: Fix `replay_ceil` Possibly-Unbound pyright Finding in subscribe_route.py

## Goal

Make `replay_ceil` unconditionally bound in `scripts/eventbus/subscribe_route.py`'s `_sse_gen()` async generator so `uv run pyright scripts/` reports 0 errors for this file, with no change to SSE replay/live-delivery behavior. This document **supersedes and corrects** `implementations/done/20260727-025628_subscribe_route.py.md`, whose fix (moving `replay_ceil = start_seq` before the `for` loop, and refining the runtime guard from `"replay_ceil" in dir()` to `locals().get("replay_ceil") is not None`) was implemented in commit `98f99309f` (2026-07-28) but did **not** resolve the pyright finding — it is still reproducing today (re-verified via `uv run pyright scripts/eventbus/subscribe_route.py`, 2026-08-18, exact same `reportPossiblyUnboundVariable` error at the same line). Do not treat this document's existence-check ("already implemented" test file exists for `subscribe_route.py`) as satisfied by the 2026-07-27 document — that prior fix addressed the runtime guard and return-type annotation but never moved the initialization earlier than `await run_with_db_lock(_fetch_replay)`, which is exactly where the remaining exposure is.

## Scope

- Initialize `replay_ceil = start_seq` unconditionally before the code path that can raise `asyncio.CancelledError` — specifically, before the `await run_with_db_lock(_fetch_replay)` call, not merely before the `for row in rows:` loop (the insufficient placement from the prior fix).
- Simplify the `except asyncio.CancelledError` handler's `logger.info(...)` call to reference `replay_ceil` directly, removing the `locals().get("replay_ceil") is not None else start_seq` workaround.
- Add a test in `tests/eventbus/` exercising the "cancelled before any replay row is read" edge case.
- Out of scope: replay/live-delivery semantics, SSE payload format, topic filtering, offset-recovery logic, the pre-existing `B101`/`B608` bandit findings in this file, any other file under `scripts/eventbus/`.

## Design decisions

- Initialize `replay_ceil = start_seq` at the earliest point after `start_seq` is known (immediately before/at the top of the `try:` block in `_sse_gen()`), so it is bound on every code path that can reach the `except asyncio.CancelledError` handler, including cancellation during the `await run_with_db_lock(_fetch_replay)` call itself.
- Once unconditionally bound, drop the `locals().get("replay_ceil") is not None else start_seq` ternary and reference `replay_ceil` directly in the log call — the workaround becomes unnecessary and its removal is what actually satisfies pyright's flow analysis (pyright cannot follow `locals()` regardless of guard correctness).
- Keep a short inline comment at the initialization site explaining why it must be unconditional, so a future refactor does not reintroduce the bug by moving it back inside the loop (as happened once already).

## Alternatives considered

1. **Suppress with `# type: ignore[reportPossiblyUnboundVariable]`**: Rejected — `rules/coding.md` prohibits suppression without justification, and a root-cause fix is available and minimal; suppressing would leave real (if currently harmless) fragility in place.
2. **Keep the `locals().get(...)` guard and only add a `# noqa`/pyright suppression comment**: Rejected for the same reason — root cause is fixable without suppression.
3. **Restructure `_sse_gen()` to avoid the `try/except CancelledError` pattern entirely (e.g. context manager)**: Rejected as out of scope — a much larger change with higher risk, not justified by a static-analysis-only finding.

## Implementation

### Target file: `scripts/eventbus/subscribe_route.py`

#### Procedure

1. Read `scripts/eventbus/subscribe_route.py` to reconfirm current line numbers before editing (they may have shifted since this document was written).
2. Move `replay_ceil = start_seq` from its current position (line 62, after `rows = await run_with_db_lock(_fetch_replay)`) to immediately after `sub = broker.subscribe(list(topic))` and before the `try:` block starts — i.e. unconditionally, before any `await` that can raise `CancelledError`.
3. Add a short inline comment at the new initialization site: `# must be set before any await below, so the except CancelledError handler below always has a value`.
4. Remove the now-redundant assignment at the old location (line 62) — do not duplicate it.
5. In the `except asyncio.CancelledError` handler, change the third `logger.info(...)` argument from `replay_ceil if locals().get("replay_ceil") is not None else start_seq` to plain `replay_ceil`.
6. Run `uv run ruff format scripts/eventbus/subscribe_route.py` to normalize formatting.

#### Method

Hoist the `replay_ceil` initialization above the `try:` block (not merely above the `for` loop, which is where the 2026-07-27 fix left it), then simplify the except-handler log call now that the binding is unconditional.

#### Details

Current code (lines 36-65, abbreviated):
```python
async def _sse_gen() -> AsyncGenerator[str]:
    sub = broker.subscribe(list(topic))
    try:
        def _fetch_replay() -> list[Any]:
            ...

        rows = await run_with_db_lock(_fetch_replay)
        replay_ceil = start_seq          # <- still inside try, after the await
        for row in rows:
            ...
            replay_ceil = row["seq"]
        ...
    except asyncio.CancelledError:
        logger.info(
            "subscribe disconnected consumer=%s seq=%d",
            consumer_id,
            replay_ceil if locals().get("replay_ceil") is not None else start_seq,
        )
    finally:
        broker.unsubscribe(sub)
```

Target code:

### Target file: `tests/eventbus/test_eventbus_subscribe_transition.py`

#### Procedure

1. Read the current file in full (already reviewed: `TestReplayToLiveTransition` class, `client` fixture from `eventbus_helpers.make_eventbus_client`, `_event()` helper).
2. Add a new test method (`test_cancelled_before_replay_logs_start_seq`) that:
   a. Monkeypatches `eventbus.subscribe_route.run_with_db_lock` with an async function that immediately raises `asyncio.CancelledError` — this deterministically simulates cancellation during the replay DB fetch, with no timing dependency and no need to publish an event first (the DB is never actually queried once `run_with_db_lock` is replaced).
   b. Obtains the `subscribe()` coroutine's result directly rather than through `TestClient`'s HTTP layer, per the constraint documented in `tests/eventbus/test_eventbus_replay_subscribe.py:84-88` (`httpx.ASGITransport` blocks on infinite SSE generators).
   c. Drives the generator with `await gen.__anext__()`, wrapped in `pytest.raises(StopAsyncIteration)` — **not** `athrow()` on an un-started generator. Verified experimentally (2026-08-18) that calling `athrow()` before any `asend()`/`__anext__()` propagates the exception directly to the caller without entering the generator body at all (confirmed via a minimal async-generator repro), so it would never reach the `except asyncio.CancelledError` handler. Driving with `__anext__()` after monkeypatching `run_with_db_lock` correctly enters the function body, executes up to the mocked `await`, and lets the exception raise from inside the `try:` block where the handler catches it.
   d. Uses `caplog` (pytest's built-in fixture) to capture the `logger.info(...)` call and asserts `"seq=0" in caplog.text` (start_seq is 0 for a fresh subscriber with no offset).
3. Run `uv run pytest tests/eventbus/test_eventbus_subscribe_transition.py -v` to confirm the new test passes against the fixed source.
4. **Correction to this document's original plan**: do not expect this test to fail against the pre-fix source as a "regression test" in the strict sense — verified experimentally (2026-08-18, via `git stash` of the source fix) that this exact test **also passes unchanged against the pre-fix code**, because the pre-fix `locals().get("replay_ceil") is not None else start_seq` guard was already runtime-correct in this scenario. The pyright `reportPossiblyUnboundVariable` finding was a static-analysis-only false positive with no runtime failure mode — `pytest` cannot detect it either way. This test's actual value is locking in the invariant that `replay_ceil` stays unconditionally bound going forward (it would catch a *future* regression that removes the safety net entirely, e.g. moving initialization back inside the `for` loop **and** removing the `locals()`-style fallback in the same change), not reproducing the original finding. Document this distinction in the test's docstring instead of calling it a "regression test for the pyright finding."

#### Method

Monkeypatch `run_with_db_lock` to raise `CancelledError` immediately, then drive `_sse_gen()` (obtained via `subscribe()`'s returned `StreamingResponse.body_iterator`) with `__anext__()` inside `pytest.raises(StopAsyncIteration)`, and assert on the captured log record — mirroring the direct-internals testing convention `test_subscribe_yields_matching_event` already established in this codebase for cases `TestClient` cannot exercise.

#### Details

Verified, working implementation (actually run via `uv run pytest`, not an illustrative sketch):
```python
import asyncio
import logging

import pytest
from fastapi import Request


async def test_cancelled_before_replay_logs_start_seq(
    self,
    client: TestClient,
    monkeypatch: pytest.MonkeyPatch,
    caplog: pytest.LogCaptureFixture,
) -> None:
    from eventbus import app as eb_app
    from eventbus import subscribe_route

    async def _raise_cancelled(_func: Any) -> Any:
        raise asyncio.CancelledError

    monkeypatch.setattr(subscribe_route, "run_with_db_lock", _raise_cancelled)

    scope = {
        "type": "http",
        "app": eb_app.app,
        "method": "GET",
        "path": "/subscribe",
        "query_string": b"",
        "headers": [],
    }
    request = Request(scope)

    with caplog.at_level(logging.INFO, logger="eventbus.subscribe_route"):
        response = await subscribe_route.subscribe(
            request, topic=[], since_seq=0, consumer_id=""
        )
        gen = response.body_iterator
        with pytest.raises(StopAsyncIteration):
            await gen.__anext__()

    assert "seq=0" in caplog.text
```

Confirmed via `uv run python3 -c "..."` that a minimal `Request(scope={"type": "http", "app": ..., ...})` correctly exposes `request.app` (Starlette's `HTTPConnection.app` property just returns `self.scope["app"]`), so no `client`/`server` scope keys are needed for this handler's code path.
