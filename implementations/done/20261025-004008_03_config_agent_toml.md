# Implementation Procedure: config/agent.toml

## Goal

Update the explicit `masked_fields` value in the local `config/agent.toml` from the inert
`["file_content"]` to `["content", "old_text", "new_text"]`, and record the corrected
deployed-copy state for the confirmation-gated Phase 4 sync.

## Scope

In scope:
- One value change in `config/agent.toml`.
- The conditional deploy step defined by the plan (blocked on user confirmation).

Out of scope:
- The code defaults (procedures 01-02) — this file sets the explicit value that overrides
  both fallbacks.
- Test updates (procedures 04-06).
- Docs (procedure 07).

## Assumptions

- Assumption: `masked_fields = ["file_content"]` appears exactly once in the file, in the
  flat Security region before the first table region. Verified: single occurrence at `:98`
  (`masked_fields = ["file_content"]`), first table region `[diagnostics]` starts at `:230`.
- Assumption (corrected 2026-10-25, plan Revalidation record row 4): the deployed
  `/opt/llm/config/agent.toml` is NOT byte-identical to the local file. It differs in three
  unrelated places — `embed_url` host (`:10`: local `...228`, deployed `...238`), one
  `startup_mode` block (`:413-414`: deployed `none` plus `required = false`), and the local
  `[[tool_definitions]]` sections (`553-1124`, absent in the deployed copy). The
  `masked_fields` line itself is identical at `:98` in both files.

## Design decisions

- Decision: keep the key present with the explicit fixed value rather than deleting it to
  rely on the new defaults — an explicit config documents intent (AC-3). If the explicit
  value were removed, the new defaults (procedures 01-02) must land first or masking stays
  unset; the plan froze keeping the key.
- Decision: TOML list formatting stays on one line, matching the current style.
- Decision (from the revalidation correction): the Phase 4 deploy must be a targeted
  single-line edit of the deployed file's `:98`, never a whole-file rsync/copy — a whole-file
  copy would overwrite the deployed host's `embed_url` and `startup_mode` values and inject
  local `tool_definitions`.

## Alternatives considered

- Alternative: remove the line entirely and let the code defaults apply. Rejected: AC-3
  requires the shipped config to show the fixed names explicitly; deleting also couples
  config correctness to procedures 01-02 landing first.
- Alternative: sync the deployed copy with the project's normal whole-file config rsync
  (`deploy.sh`). Rejected by the 2026-10-25 revalidation: the known three-way drift makes a
  whole-file sync unsafe for this change; a targeted edit changes exactly one line.

## Implementation

### Target file

`config/agent.toml`

### Procedure

1. Locate the Security region (the line `masked_fields = ["file_content"]` at `:98`).
2. Replace the list value.
3. (Conditional, user-confirmation-gated) apply the same one-line edit to the deployed
   copy per plan Phase 4.

### Method

Change from (verified at `:98`):

```toml
masked_fields = ["file_content"]
```

to:

```toml
masked_fields = ["content", "old_text", "new_text"]
```

No other lines in the file change. The identical before/after applies to the deployed copy's
`:98` when (and only when) Phase 4 is confirmed.

### Details

- Deploy step (plan Phase 4 / Execution Status step 4): the deployed file is what the
  running services read. Deploying the new value activates masking of
  `content`/`old_text`/`new_text` in production. The plan marks this step Blocked pending
  explicit user confirmation — procedure execution must stop before any write to
  `/opt/llm/config/` or service restart (`sudo systemctl restart llmagent*`) without that
  confirmation, and record Partial with the deploy state stated.
- Pre-existing drift between the two copies (embed_url, startup_mode, tool_definitions) is
  out of this procedure's scope; do not "fix" it as a side effect. If the user wants the
  drift resolved, that is a separate task.

## Compatibility considerations

- Compatibility risk: production behavior changes only when the deployed copy is updated;
  until then repo config has the fixed value while production keeps the inert value (config
  drift). The plan Execution Status records this state; resolve it in one direction (deploy
  or revert) rather than leaving it split.
- User-supplied overrides (`masked_fields` set elsewhere, env-var override paths) are
  untouched (REQ-006).
- Key type unchanged: TOML array of strings (AC-3).

## Security considerations

- Security improvement: the shipped config now names the real payload fields, so masking is
  active for out-of-the-box deployments once deployed (REQ-001).
- Blast radius: deploying masks tool arguments in events and logs whose paths are denied by
  path security; it does not change what is executed (AC-1 semantics).
- Leaving the deployed copy stale is itself a finding: production keeps a config line that
  matches no argument name.

## Rollback considerations

- Rollback: restore `masked_fields = ["file_content"]` at `:98` (local, and deployed if it
  was synced), or restore the pre-change file from git. The value is read at config load,
  so a rollback needs a service restart to take effect (same as deploy).
- Rollback has no data-migration implications and must also stay a single-line edit for the
  deployed copy (same drift-safety rule as deploy).

## Validation plan

1. `uv run python -c "import sys; sys.path.insert(0, 'scripts'); from agent.config_builders import build_agent_config, load_config; print(build_agent_config(load_config()).tool.masked_fields)"`
   prints `['content', 'old_text', 'new_text']` — `AgentConfig.tool` (`config_dataclasses.py:391`)
   carries the value read from the flat Security region.
2. `grep -c file_content config/agent.toml` prints `0`.
3. If Phase 4 proceeds: `grep -n masked_fields /opt/llm/config/agent.toml` shows the new
   value at `:98`, the three known drift regions are unchanged from their pre-deploy state,
   and services were restarted. `diff` against the local file will still show the three
   known drift hunks — that is expected, not a failure.
4. Docs gate: `uv run python tools/check_docs_consistency.py --domain agent` stays green
   (procedure 07 updates the docs that state this value).

## Completion criteria

- `config/agent.toml` contains `masked_fields = ["content", "old_text", "new_text"]` and no
  remaining `file_content`.
- Loading the config yields the fixed list.
- Deploy state is explicitly recorded: deployed via targeted one-line edit (with `grep`
  proof and drift regions untouched) or deliberately undeployed pending user confirmation.

## Out of Scope

- Code defaults (procedures 01-02), tests (procedures 04-06), docs (procedure 07).
- Any other `security.*` keys or the deployed/local drift regions (`embed_url`,
  `startup_mode`, `tool_definitions`).
- Restarting services without explicit user confirmation.
