# Implementation Procedure: Document extract_llm_content behavior for unexpected LLM response formats

## Goal

Document the behavior of `SessionTitleService.extract_llm_content` when LLM returns a valid response with unexpected content format, ensuring users understand why title generation fails in such cases. Specifically: update the docstring of `extract_llm_content` to clarify empty string handling, and improve the error message in `session_title.py`.

## Scope

- `scripts/shared/json_utils.py`: `extract_llm_content` docstring update
- `scripts/agent/services/session_title.py`: error message improvement on line 55

## Assumptions

1. `extract_llm_content` never returns `None` — it either returns a stripped string or raises `ValueError`. The require document's claim about "returns None" appears to conflate empty string with None.
2. The existing error handling in `session_title.py` (lines 54-55) correctly distinguishes empty content from other failures
3. Users benefit from knowing whether failure was due to empty content vs malformed response

## Design decisions

- Add docstring note to `extract_llm_content` clarifying that empty string content is valid input and the function returns stripped empty string (not None)
- Change error message on `session_title.py` line 55 from `"LLM returned empty title"` to something more specific like `"LLM returned empty content — try adjusting your prompt"`
- Keep existing control flow unchanged (no new validation logic)

## Alternatives considered

1. **Add explicit empty-content validation inside `extract_llm_content`**: Would centralize the check but changes the function's contract — currently it returns whatever the API gives after stripping. Adding a non-empty assertion would be a behavioral change.
2. **Use separate exception types for empty content vs malformed response**: Would allow callers to distinguish cases programmatically. But adds complexity and no caller currently needs this distinction.
3. **Update all 4 callers to handle empty content differently**: Overkill — only 2 callers (session_title.py, history.py) already check for empty content; the other 2 (rag/llm_client.py x2) do not validate.

## Compatibility considerations

- Changing error message text could break tests that assert exact error message strings
- If `content` can be `null` in some API versions, `isinstance(content, str)` check on line 130 would raise ValueError — need to confirm API contract
- No callers currently depend on the exact error message text "LLM returned empty title" (they catch via `except SessionTitleGenerationError`)

## Security considerations

N/A — no security implications. Only changes documentation and error message text.

## Rollback considerations

- Revert `extract_llm_content` docstring to original
- Revert error message on line 55 to `"LLM returned empty title"`
- No database or config changes to revert

## Validation plan

- Unit test verifying `extract_llm_content("")` returns `""` (not None, not ValueError)
- Integration test verifying session title generation fails with appropriate error when LLM returns empty content
- Manual review confirming error message improvement is actionable
- Check that no existing test assertions depend on the old error message text

## Out of scope

- Changes to `extract_llm_content` control flow or validation logic
- Changes to any caller beyond what is necessary for this feature
- Changes to error handling in `rag/llm_client.py` (only 2 callers checked for empty content; the other 2 are not in scope)
- Changes to `HistoryManager.compress()` error handling (separate concern)

```python
def extract_llm_content(data: dict[str, Any]) -> str:
    """Extract and validate content text from an OpenAI-compatible chat completion response.

    Validates the nested structure: choices → choices[0] → message → content.

    Empty string content is valid input — the function returns ``""`` (stripped empty
    string), not ``None``. Callers should check for empty content if they consider it
    an error condition.

    Args:
        data: Raw LLM response dict.

    Returns:
        Stripped content string. May be empty if the API returned empty content.

    Raises:
        ValueError: If the response is malformed, missing expected fields, or
            ``content`` is not a string type (e.g., null).
    """
```

Key changes:
- Line 110: Add paragraph explaining empty string behavior
- Line 115: Update Returns description to mention empty string possibility
- Line 118: Clarify that ValueError also raised when content is not a string type (e.g., null)
