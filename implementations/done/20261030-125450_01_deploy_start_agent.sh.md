## Goal

Add a fail-fast pre-flight check to `deploy/start_agent.sh` that verifies the compiled agent binary `/opt/llm/bin/agent` exists and is executable before launch, replacing the terse bash ENOENT with a clear, actionable rebuild/redeploy message. Implements `REQ-001` (hard-fail on a missing/non-executable binary) and adds the optional `REQ-002` stale-binary warning and `REQ-003` missing-dict warning.

## Scope

Modifies `deploy/start_agent.sh` only:
- Add a `check_agent_binary (new)("<path>")` function that exits non-zero with an actionable message when the binary is missing or non-executable (`REQ-001`).
- Invoke it before the launch line (line 197), after the workflow-validation check (`REQ-001`).
- Optionally add a best-effort stale-binary warning reusing `tools/manage_binaries.py check`, gated by a strictness env var (`REQ-002`).
- Optionally add a warn-only notice when `/opt/llm/dict/system.dic` is missing (`REQ-003`).
- Add a minimal source guard so the script can be sourced by a subprocess test without running the main body.

All other checks (`.env` parsing, required-env-var listing, uv/pyproject/deployed-files/workflow gates) are unchanged.

## Assumptions

- Line 197 currently reads `UV_SYSTEM_CERTS=true /opt/llm/bin/agent` with no existence/executable check beforehand.
- The script is not currently sourceable: it has no `BASH_SOURCE (new)` guard, so sourcing it today executes the whole body.
- The script runs from the repository root; `deploy/build_binaries.sh`, `deploy/deploy.sh`, and `tools/manage_binaries.py` are reachable by relative path from `REPO_ROOT`.
- The existing `[FATAL] ... exit 1` fail-fast style lives at lines 120-137 and is the model to match.
- `DEPLOY_STRICT_BINARIES=1` is the existing strictness convention in `deploy/deploy.sh` (lines 114-118); the startup check reuses the same env var name.
- `tools/manage_binaries.py check` reports each binary `ok`/`stale`/`unknown`/`mismatch`/`invalid` and exits non-zero on `mismatch`/`invalid`, and on `stale`/`unknown` only with `--strict` (see `tools/manage_binaries.py` `check()` at lines 238-256).
- `/opt/llm/dict/system.dic` is placed by `deploy/deploy.sh`; the resolver already fails fast at runtime if it is absent (exported as `LLMAGENT_SUDACHI_DICT` at line 189), so a missing dict is already a hard failure at launch — the new notice is an earlier, friendlier signal.

## Design decisions

- **Parameterized pre-flight function.** `check_agent_binary (new)("<path>")` returns non-zero with the actionable message when the binary is missing or non-executable. Parameterizing the path lets a subprocess test drive it against a controlled temp directory without depending on the hardcoded `/opt/llm` upstream checks.
- **Source guard for testability.** `deploy/start_agent.sh` runs top-to-bottom and is not currently sourceable. A minimal `[[ "${BASH_SOURCE (new)[0]}" != "${0}" ]]` guard around the main body makes it sourceable for the test. The guard MUST NOT change the direct-launch path (when run directly `${BASH_SOURCE (new)[0]}` equals `${0}`, so the body still runs). The `check_agent_binary (new)` function MUST be defined OUTSIDE the guard (near the top) so it is callable when the script is sourced.
- **Best-effort stale/dict warnings.** The `REQ-002` call into `manage_binaries.py check` degrades to a warning and skips gracefully when invoked outside the repo or when rev/context is unavailable; it never hard-fails without `DEPLOY_STRICT_BINARIES=1`. The `REQ-003` dict notice is warn-only.

## Alternatives considered

- **End-to-end run in the test.** Rejected: the upstream deployed-files checks (lines 151-171) hardcode `/opt/llm` paths and the workflow gate runs `uv run python -m agent.workflow.validate`, so a full run requires production paths and network — impractical for a unit test.
- **Extract the pre-flight into a separate library (e.g. `deploy/preflight.sh`).** Rejected: that file is not in the Plan's `Implementation Target Files`, so adding it is an additional-target-file discovery (Blocked). Keep the change in `deploy/start_agent.sh` only.

## Implementation

### Target file

`deploy/start_agent.sh`

### Procedure

1. Define `check_agent_binary (new)()` near the top of the script (outside any source guard).
2. Add a minimal source guard after the function definition.
3. Invoke `check_agent_binary (new) "/opt/llm/bin/agent"` before the launch block.
4. Add the optional `REQ-002` stale warning and `REQ-003` dict warning before the launch.

### Method

1. **Define the function (Phase 1, `REQ-001`).** Insert after the `UV_PROD_FLAGS` variable (line 13) and before the `if [[ -f "/opt/llm/pyproject.toml" ]]` block (line 15):
   ```bash
   # Pre-flight: fail fast with an actionable message when the compiled agent
   # binary is missing or not executable, instead of a bare bash ENOENT.
   check_agent_binary (new)() {
       local bin_path="$1"
       if [[ ! -x "${bin_path}" ]]; then
           echo "" >&2
           echo "[FATAL] Agent binary not found or not executable: ${bin_path}" >&2
           echo "Rebuild and redeploy the binaries:" >&2
           echo "  1) deploy/build_binaries.sh            # rebuild from current source" >&2
           echo "  2) deploy/build_binaries.sh --rollback # restore a prior deployed set" >&2
           echo "  3) deploy/deploy.sh                     # deploy the resulting binaries" >&2
           exit 1
       fi
   }
   ```
2. **Add the source guard** immediately after the function definition (before line 15):
   ```bash
   # Allow the script to be sourced by tests without running the main body.
   # When launched directly ${BASH_SOURCE (new)[0]} == ${0}, so behavior is unchanged.
   if [[ "${BASH_SOURCE (new)[0]}" != "${0}" ]]; then
       return 0
   fi
   ```
3. **Invoke before launch (Phase 1).** Insert `check_agent_binary (new) "/opt/llm/bin/agent"` right before the launch section (after the workflow-validation check ends at line 183, immediately before the resolver exports at lines 188-189). With `set -euo pipefail` a non-zero exit stops the script.
4. **Optional stale warning (Phase 2, `REQ-002`).** Insert before the launch, reusing `deploy/deploy.sh`'s strictness pattern (lines 114-123):
   ```bash
   # REQ-002: best-effort stale-binary warning. Never hard-fails without the
   # strictness flag; degrades to a warning when run outside the repo.
   if [[ "${DEPLOY_STRICT_BINARIES:-0}" == "1" ]]; then
       if ! python3 "${REPO_ROOT}/tools/manage_binaries.py" check \
            --bin-dir /opt/llm/bin --rev auto --repo "${REPO_ROOT}" --strict 2>/dev/null; then
           echo "[FATAL] Strict binary freshness check failed." >&2
           exit 1
       fi
   else
       python3 "${REPO_ROOT}/tools/manage_binaries.py" check \
            --bin-dir /opt/llm/bin --rev auto --repo "${REPO_ROOT}" >/dev/null 2>&1 \
       || echo "[WARN] Deployed agent binary may be stale or unverifiable; consider deploy/build_binaries.sh + deploy/deploy.sh." >&2
   fi
   ```
5. **Optional dict warning (Phase 2, `REQ-003`).** Insert before the launch:
   ```bash
   # REQ-003: warn-only notice when the Sudachi dictionary was not deployed.
   if [[ ! -f "/opt/llm/dict/system.dic" ]]; then
       echo "[WARN] Sudachi dictionary not found: /opt/llm/dict/system.dic (deploy via deploy/deploy.sh)." >&2
   fi
   ```

### Details

- Match the existing `[FATAL]` style: messages go to stderr, end with `exit 1`.
- The recovery message names the three recovery commands exactly as they exist in the repo.
- The `REQ-002` call is wrapped so a non-zero exit (or a missing tool / unreachable repo) becomes a warning unless `DEPLOY_STRICT_BINARIES=1`; it does not mask the `REQ-001` hard-fail, which precedes it.
- `bash -n deploy/start_agent.sh` must stay clean after the edit.
