## Risks

- Adding a `PREMATURE_EOF` raise when `finish_reason is None` on stream exhaustion could produce false positives if some upstream LLM backend legitimately ends a stream without an explicit `finish_reason` field but the response is otherwise complete → Mitigation: gate the raise on the absence of *both* a `[DONE]` sentinel/terminal signal *and* any content, or add a config/behavior check against real backend traces before enabling by default; cover both "genuine premature EOF" and "backend omits finish_reason but sends `[DONE]`" cases explicitly in the new tests.
- Switching `sse_parser.py`'s decoder from `"replace"` to `"strict"` could cause previously-tolerated byte-boundary-split multi-byte UTF-8 sequences to newly raise hard errors → Mitigation: this plan explicitly recommends **not** making that change; if a future requirement demands strict UTF-8 validation, it should ship behind a config flag and be monitored via a new stat counter before becoming default.
- Editing `docs/05_agent_05_llm-and-streaming-part2.md`'s kind/cause table risks introducing further citation-tag inconsistencies across the *other* seven rows if only the two flagged kinds are touched → Mitigation: implementation phase should audit every row's citation tag against its actual raise site in the same edit pass.
- NC-001's governance template requires an 11-field structure — an incomplete update could leave the entry non-conformant → Mitigation: copy the exact field set already used for NC-001/NC-002 when writing the resolved entry.
