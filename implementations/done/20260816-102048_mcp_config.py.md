# Implementation Procedure: Make MCP Server Health Timeout Configurable Per-Server

## Goal

Replace the global `MCPSERVER_HEALTH_TIMEOUT` constant with per-server configurable `health_timeout` on `McpServerConfig`, falling back to 5.0 seconds when not specified.

## Scope

- `scripts/shared/mcp_config.py`: Add `health_timeout` field to `McpServerConfig`, add `get_effective_health_timeout()` helper, update `_build_single_server()`
- `scripts/agent/services/mcp_tool_discovery.py`: Replace direct import of `MCPSERVER_HEALTH_TIMEOUT` with `get_effective_health_timeout()`
- `scripts/agent/services/mcp_status.py`: Replace direct import of `MCPSERVER_HEALTH_TIMEOUT` with `get_effective_health_timeout()`
- `scripts/agent/http_lifecycle.py`: Keep `MCPSERVER_HEALTH_TIMEOUT` as documented default reference only

## Assumptions

1. The default value of 5.0 seconds is acceptable; no operator requests a different default
2. `McpServerConfig` is only used by HTTP-transport servers (verified: TransportType.HTTP is the only transport type defined)
3. No other code path reads `MCPSERVER_HEALTH_TIMEOUT` besides the two identified consumers
4. The `_build_single_server()` function in `mcp_config.py` will need updating to pass `health_timeout` from TOML config
5. `MCPSERVER_HEALTH_TIMEOUT` in `http_lifecycle.py` is only consumed by `mcp_tool_discovery.py` and `mcp_status.py` (verified: grep confirms exactly 5 references across the repo)

## Design decisions

- Add `health_timeout: float | None = None` field to `McpServerConfig` dataclass
- Provide module-level helper `get_effective_health_timeout(cfg: McpServerConfig) -> float` that resolves effective timeout (None → 5.0, explicit value → use it)
- Reject negative values for `health_timeout` in `_validate_timeouts()` method
- Keep `MCPSERVER_HEALTH_TIMEOUT` in `http_lifecycle.py` as documented default reference
- Use `float | None` type to distinguish between "not configured" (None) and "configured to zero" (0.0)

## Alternatives considered

1. **Use a sentinel class instead of None**: Would add complexity without clear benefit over simple None default.
2. **Add validation in `__post_init__` instead of `_validate_timeouts`**: `_validate_timeouts` is the established pattern in this class for timeout fields.
3. **Make health_timeout required (no default)**: Would break backward compatibility — existing configs don't specify this field.
4. **Use a separate configuration layer**: Over-engineering. A single dataclass field + helper function is sufficient.

## Compatibility considerations

- Adding `health_timeout: float | None = None` preserves backward compatibility — existing configs without this field continue working
- Default fallback to 5.0 seconds means no runtime behavior change for existing deployments
- Negative value rejection in `_validate_timeouts` is a breaking change for configs that previously had negative values (none exist currently)
- No database or config changes to revert

## Security considerations

N/A — no security implications. Only adds a configuration option for timeout values.

def _build_single_server(key: str, v: dict[str, Any]) -> McpServerConfig:
    """Construct McpServerConfig from a raw dict, applying defaults.

    All TOML string values are converted to enum types here so that
    McpServerConfig runtime instances use normalized enum values.
    """

    transport = v.get("transport", "http")
    if not isinstance(transport, str):
        raise ValueError(
            f"mcp_servers[{key!r}].transport must be str, got {type(transport).__name__}"
        )
    cmd = list(v.get("cmd", []))
    env = dict(v.get("env", {}))
    health_timeout_raw = v.get("health_timeout")
    health_timeout: float | None = None
    if health_timeout_raw is not None:
        try:
            health_timeout = float(health_timeout_raw)
        except (TypeError, ValueError):

                f"mcp_servers[{key!r}].health_timeout must be numeric or null, "
                f"got {type(health_timeout_raw).__name__}"

        transport=TransportType(transport),

        startup_mode=StartupMode(v.get("startup_mode", "none")),

    )
