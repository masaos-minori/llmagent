## Goal

Eliminate the 2 pyright `reportAttributeAccessIssue` false positives on
`git.exc.InvalidGitRepositoryError` (line 56) and `git.exc.GitError` (line 62) in
`scripts/shared/git_helper.py` by adding an explicit `import git.exc` alongside the existing
lazy, function-local `import git` (line 39), without changing any exception-handling
behavior.

## Scope

- In scope: add one new line, `import git.exc`, immediately after the existing
  `import git  # lazy import keeps startup fast when gitpython is unused` line inside the
  `try` block of `get_repo_info()`. No other line changes.
- Out of scope: the `except ImportError` handling, any exception clause bodies, the
  `RepoInfoResult`/`FailureReason` contracts, and any change to which exceptions are caught
  or their order. Also out of scope: `# type: ignore` suppression (an import-based fix is
  confirmed to resolve the issue, so no suppression is needed) and any change to
  `scripts/mcp_servers/git/git_service.py` (covered by a separate implementation document).

## Assumptions

- Installed `gitpython` is 3.1.50 (per `uv.lock`); its `git/__init__.py` does not itself
  `import git.exc` or re-export it, which is why pyright cannot statically resolve
  `git.exc.*` attribute access without an explicit import at the call site.
- Adding `import git.exc` inside the same lazy, function-scoped `try` block preserves the
  "fast startup when gitpython is unused" property documented in the module's docstring —
  a top-level `import git.exc` would defeat that guard, so the import must stay
  function-local here.

## Design decisions

- Place `import git.exc` immediately after `import git` inside the existing `try` block,
  not in a separate `try`/`except` — `git.exc` is a submodule of the already-imported `git`
  package, so if `import git` succeeds, `import git.exc` will not raise `ImportError`
  independently; no new failure mode is introduced.
- Do not touch the `except ImportError:` clause — it already covers the case where
  `gitpython` itself is absent, which also covers `git.exc` being unavailable.

## Alternatives considered

N/A — the plan already evaluated and rejected `# type: ignore[attr-defined]` suppression
(tried in an earlier, superseded implementation effort that was never actually landed in the
current source) in favor of the import-based fix, which was empirically verified via a probe
file to fully resolve the pyright error with zero errors/warnings.
