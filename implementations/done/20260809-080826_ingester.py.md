# Implementation Procedure: Phase 6 — DocumentManager Cleanup

## Goal

Remove `delete_existing_document()` method from `DocumentManager` (now delegated to `_commit_url_transaction()`), keep `delete_document_chain()` helper function, and update `handle_existing_document()` to not delegate deletion.

## Scope

### In-Scope
- Remove `delete_existing_document()` method from `DocumentManager` class
- Keep `delete_document_chain()` helper function (may be reused elsewhere)
- Update `handle_existing_document()` to not delegate deletion — just return skip flag

### Out-of-Scope
- Changes to cache invalidation logic (Phase 5)
- Database schema changes
- Changes to `_commit_url_transaction()` (Phase 3)

## Assumptions

1. `delete_existing_document()` is only called from `ingester.py` (confirmed by inspecting current code)
2. `delete_document_chain()` is used elsewhere and should be preserved (confirmed by inspecting current code)
3. `handle_existing_document()` currently delegates deletion to `doc_mgr.delete_existing_document()` (confirmed by inspecting current code)

## Design decisions

- `delete_existing_document()` removed because its responsibility now belongs in `_commit_url_transaction()` — the transaction boundary ensures atomicity
- `delete_document_chain()` kept because it may be reused elsewhere (e.g., cleanup operations)
- `handle_existing_document()` returns skip flag without delegating deletion — caller decides whether to delete

## Alternatives considered

- Keeping `delete_existing_document()` but marking it deprecated: rejected because it creates confusion about which method should be used
- Moving `delete_document_chain()` into `DocumentManager`: rejected because it's a standalone utility function that doesn't require class context
- Removing both methods: rejected because `delete_document_chain()` may be needed for other purposes

    def __init__(self, db: SQLiteHelper):
        self.db = db
    
    def delete_existing_document(self, doc_id: int) -> None:
        """Delete existing document and related data."""
        # Delete chunks_vec rows first

            "DELETE FROM chunks_vec WHERE chunk_id IN (SELECT chunk_id FROM chunks WHERE doc_id = ?)",

            (url,),

        if existing_doc:
            if force:
                self.delete_existing_document(existing_doc[0])

#### Step 3: Update `handle_existing_document()` to not delegate deletion

Modify the method to return skip flag without deleting:
```python
def handle_existing_document(self, url: str, force: bool) -> tuple[int | None, bool]:
    """Handle existing document case.
    
    Returns:
        Tuple of (existing_doc_id_or_None, skip_flag)
    """
    existing_doc = self.db.execute(
        "SELECT doc_id FROM documents WHERE url = ?",
        (url,),
    ).fetchone()
    
    if existing_doc:
        if force:
            return existing_doc[0], False  # Don't skip — deletion handled by caller
        else:
            return existing_doc[0], True   # Skip
    
    return None, False  # No existing document
```

Key points:
- When `force=True`, return `existing_doc_id` so caller knows what to delete
- Caller (`_get_or_create_document()`) now handles deletion via `_commit_url_transaction()`
- No delegation to `delete_existing_document()` — caller has full control

### Method

### Details

**File locations**: 
- `scripts/rag/ingestion/document_manager.py` — remove method, update interface
- `scripts/rag/ingestion/ingester.py` — update caller to use new interface

**Key changes**:
1. Remove `delete_existing_document()` method from `DocumentManager`
2. Update `handle_existing_document()` to return `existing_doc_id` when `force=True`
3. Update `_get_or_create_document()` to not call `db.commit()` before chunk processing
4. Deletion now happens inside `_commit_url_transaction()` via `BEGIN IMMEDIATE`

**Critical insight**: By moving deletion into the transaction boundary, we ensure atomicity — either ALL chunks are committed OR NONE are. The old approach allowed partial commits where some chunks were stored while others weren't.

**Thread safety**: Since workers no longer hold DB connections, there's no risk of connection conflicts. The main thread handles all DB writes sequentially.

**Memory consideration**: `PreparedChunk.embedding_blob` stores raw bytes — memory pressure for large documents is acceptable since URLs are processed sequentially; memory is freed after commit.
