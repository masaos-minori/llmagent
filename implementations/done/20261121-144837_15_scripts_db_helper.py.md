## Goal

Remove `scripts/db/helper.py`'s implicit `agent.toml` load: path resolution and the `sqlite_vec_so` default come from the injected typed configuration (REQ-003, AC-004).

## Scope
**Release unit**: RU-2

## Assumptions
- `tests/db/test_sqlite_helper.py` is run as an affected test and is not a target row; no assertion changes were proven.
- The explicit-path constructor path (`db_path` supplied) keeps bypassing configuration, as documented in the current docstring.

## Design decisions
- `SQLiteHelper` receives the typed configuration defined by Plan row 8 at construction; the error wording that currently says "not configured in agent.toml or DB config" is reworded to name the supplied configuration, because the file is no longer read here.
- The fail-closed behaviour is preserved: a configuration that cannot supply a path raises before any connection is opened.

## Alternatives considered
- Keep `build_db_config()` as a zero-argument fallback inside `helper.py`: rejected by AC-004, which allows no config load inside `scripts/db/`.

## Implementation
### Target file
`scripts/db/helper.py`
### Procedure
- Change the `build_db_config()` call (line 126) to the injected-configuration signature defined by Plan row 8.
- Update the docstring (lines 92-96) so it describes the supplied typed configuration rather than an `agent.toml` load.
- Keep the `RuntimeError` wrapper that turns a configuration `ValueError` into a helper-level error.
### Method
- Argument-based read; no new state, no change to the connection handling or the read-only residue behaviour.
### Details
- Verified 2026-11-21: `_default_load_vec` is derived from the target name, not from configuration, so only the path and the extension path source change.
- `tests/db/test_schema_validation_per_database.py` patches `db.helper.build_db_config`; the patch target stays valid because Plan row 8 keeps the function name.
- Finding (2026-11-22, execution): that patch target is no longer valid, because this module no longer calls `build_db_config()` at all; `tests/db/test_schema_validation_per_database.py` supplies `DbConfig` to the constructor instead. Plan Design D3's assumption that the `patch("db.*.build_db_config")` targets stay valid does not hold for a module that stops calling the builder. `tools/check_mock_patch_targets.py` reports no findings after those targets were removed.
- Finding (2026-11-22, execution): the `RuntimeError` wrapper was not kept. It existed only to turn a configuration `ValueError` into a helper-level error, and with no config read inside the constructor there is nothing to convert, so a missing configuration now raises `ValueError` at construction ("{target}_db_path is not configured: db_config must be supplied by the process that owns the configuration file"). The docstring line that said "failure raises RuntimeError immediately" was updated to `ValueError`. The only `RuntimeError` that remains in this module is the "DB not open" guard.
- Finding (2026-11-22, execution): the Assumption "no assertion changes were proven" for `tests/db/test_sqlite_helper.py` is not correct. That file's patch-based fixtures were rewritten to pass `db_config=`, the `match="agent.toml"` assertion became `match="supplied DbConfig"`, and the empty/absent `sqlite_vec_so` cases now call `build_db_config({...})` with a supplied mapping, which is the contract Plan row 25 asserts. `db_path` keeps working as the documented exception path: explicit-path callers (including the MCP servers) bypass configuration, and both routes raise when neither a path nor a typed configuration is available.
