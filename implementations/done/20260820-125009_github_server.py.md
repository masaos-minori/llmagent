# Implementation Procedure: Add availability check and gating to github-mcp

## Goal
Add `enabled`/`disabled_reason` fields to every tool in the `GET /v1/tools` response of github-mcp and gate `POST /v1/call_tool` so a disabled tool is rejected before dispatch.

## Scope
- Target file: `scripts/mcp_servers/github/github_server.py`
- Add availability check function `_github_tool_availability()`
- Replace `list_tools()` to return hand-built annotated response (bypassing `build_tools_response()`)
- Add server-side gate in `call_tool()` before dispatch

## Assumptions
- Follow the existing pattern from git-mcp and file servers
- All github-mcp tools are `config_dependent: True` and gated on `_GITHUB_TOKEN`
- Availability function uses the same `_GITHUB_TOKEN` signal that `/health` endpoint uses
- Must bypass `build_tools_response()` with default `include_disabled=False`
- Place call_tool gate before dispatch to avoid audit log misclassification

## Design decisions
- Mirror `git_server.py`'s `_git_tool_availability` pattern but with module-level `_GITHUB_TOKEN`
- All tools share the same availability check (all are `config_dependent: True`)
- Hand-build the `/v1/tools` response dict with `enabled`/`disabled_reason` for each tool
- Gate in `call_tool()` computes availability and returns `CallToolResponse(result=f"Tool disabled: {reason}", is_error=True)` before dispatch
- Keep `MCP_TOOL_SCHEMA_VERSION` at "1.0"
