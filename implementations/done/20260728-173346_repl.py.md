## Goal

Anchor `_repl_loop()`'s `_GRACEFUL_TIMEOUT` bound to shutdown-signal-arrival time (not
turn-dispatch time), so a turn already in flight when SIGTERM/SIGINT arrives is force-cut
off no later than `_GRACEFUL_TIMEOUT` seconds after the signal, instead of being left to
run indefinitely under `timeout=None`.

## Scope

**In-Scope:**
- `scripts/agent/repl.py` `_repl_loop()` (currently lines 462-502): replace the single
  `asyncio.wait_for(self._dispatch_line(line, ctx), timeout=... )` call with a
  task-based race against `self._shutdown_event`, so the grace-period timer starts when
  the shutdown event fires rather than when `wait_for` was originally called.
- `scripts/agent/repl.py` `_sigterm_handler()` comment (currently lines 676-680): correct
  the inaccurate claim that `_repl_loop()` "already checks shutdown_requested after each
  turn and applies the `_GRACEFUL_TIMEOUT` wait" — this is only true for turns that start
  after the signal, not the one already in flight.

  inside `_repl_loop()`, line 470) to a class-level attribute so tests can override it

## Assumptions

1. `self._shutdown_event` is always a live `asyncio.Event()` by the time `_repl_loop()`
   runs in production, because `run()` (`scripts/agent/repl.py` line 663) sets it before
   `_run_repl_loop()` → `_repl_loop()` is ever awaited (line 642). It is `None` only in
   test doubles that bypass `run()`/`__init__` (`tests/test_repl.py` `_make_bare_repl()`,
   line 56 sets `repl._shutdown_event = None`).
2. The fix must therefore keep a `None`-safe fallback branch (behave exactly as today:
   `timeout=_GRACEFUL_TIMEOUT if ctx.conv.shutdown_requested else None`) so existing
   `TestReplLoop` tests that construct a bare `AgentREPL` with `_shutdown_event = None`
   keep passing unchanged.
3. `asyncio.wait_for()`'s existing auto-cancel-on-timeout semantics (it cancels the
   awaited task/coroutine when the timeout fires) is acceptable to keep for the
   second-stage bounded wait — this matches current behavior exactly (today's
   `wait_for(self._dispatch_line(...), timeout=_GRACEFUL_TIMEOUT)` already cancels
   `_dispatch_line` on timeout), so no new cancellation-safety risk is introduced.
4. The class attribute name for the hoisted timeout should follow the file's existing
   `_TIMEOUT_S` suffix convention (e.g. `_GRACEFUL_TIMEOUT_S`) rather than keeping the
   bare `_GRACEFUL_TIMEOUT` name, for consistency with `_WAL_CHECKPOINT_TIMEOUT_S` /
   `_WAL_BACKUP_TIMEOUT_S`. This is a naming choice, not a behavior change.

## Design decisions

- Replace `asyncio.wait_for(self._dispatch_line(line, ctx), timeout=...)` with a task-based
  race using `asyncio.wait({dispatch_task, shutdown_task}, return_when=FIRST_COMPLETED)`.
- When shutdown event fires while dispatch_task is still pending, apply `asyncio.wait_for(dispatch_task, timeout=self._GRACEFUL_TIMEOUT_S)` from that point forward.
- Hoist `_GRACEFUL_TIMEOUT` to a class attribute (`_GRACEFUL_TIMEOUT_S`) following the
  existing naming convention (`_WAL_CHECKPOINT_TIMEOUT_S`, `_WAL_BACKUP_TIMEOUT_S`).
- Keep a `None`-safe fallback branch for test-double compatibility.

## Alternatives considered

- Use `asyncio.wait_for()` with a dynamic timeout calculated from the signal arrival time.
  Rejected — would require tracking the signal arrival timestamp separately; the task-race
  approach is cleaner and mirrors the existing `_read_input()` pattern.
- Add a separate shutdown-aware context manager. Rejected — over-engineered for a single
  conditional; the task-race approach achieves the same result with less complexity.

```python
# After (fixed) — scripts/agent/repl.py:462-502
class AgentREPL:
    _WAL_CHECKPOINT_TIMEOUT_S: float = 30.0
    _WAL_BACKUP_TIMEOUT_S: float = 10.0
    _GRACEFUL_TIMEOUT_S: float = 10.0  # hoisted from local variable

    async def _repl_loop(self):
        ...
        while True:
            line = await self._read_input(ctx)
            if line is None:
                break
            try:
                dispatch_task = asyncio.ensure_future(self._dispatch_line(line, ctx))
                if self._shutdown_event is not None and not self._shutdown_event.is_set():
                    shutdown_task = asyncio.ensure_future(self._shutdown_event.wait())
                    done, pending = await asyncio.wait(
                        {dispatch_task, shutdown_task},
                        return_when=asyncio.FIRST_COMPLETED,
                    )
                    for t in pending:
                        t.cancel()
                    if dispatch_task in done:
                        dispatch_task.result()  # propagate exception if any
                        continue
                    # shutdown_task completed first — grace period starts now
                    try:
                        await asyncio.wait_for(dispatch_task, timeout=self._GRACEFUL_TIMEOUT_S)
                    except TimeoutError:
                        warnings.warn(...)
                        break
                else:
                    # _shutdown_event is None or already set — use original logic
                    await asyncio.wait_for(
                        self._dispatch_line(line, ctx),
                        timeout=self._GRACEFUL_TIMEOUT_S if ctx.conv.shutdown_requested else None,
                    )
            except TimeoutError:
                if ctx.conv.shutdown_requested:
                    warnings.warn(...)
                    break
                raise
```

Exception path behavior:
- On shutdown signal during turn: `dispatch_task` is force-cut off within `_GRACEFUL_TIMEOUT_S` seconds of the signal.
- On shutdown signal before turn start: existing behavior preserved via the `else` fallback branch.
- Normal completion without signal: no behavioral change — `dispatch_task` completes normally.
