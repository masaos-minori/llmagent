# Implementation Procedure: scripts/db/store_protocols.py

## Goal

Widen `DocumentStore.doc_upsert()`'s `Protocol` signature with the same
`chunking_strategy: str` parameter being added to `SQLiteDocumentStore.doc_upsert()`
(the `Protocol`'s only implementation), so the `Protocol` and its implementation stay
type-consistent under `mypy`.

## Scope

**In-Scope**
- `DocumentStore.doc_upsert()`'s signature in `scripts/db/store_protocols.py`.

**Out-of-Scope**
- `fetched_at` widening on this same method — already covered by sibling plan
  `plans/done/20260820-095054_plan.md` (see
  `implementations/20260823-200056_store_protocols.py.md`). This document covers only
  the `chunking_strategy` addition that plan did not include.
- Any other `DocumentStore` method — none of them touch `chunking_strategy`.

## Assumptions

- This file was omitted from `plans/20260820-095542_plan.md`'s original Scope/Affected
  areas — verified during implementation-procedure review that adding
  `chunking_strategy` to `SQLiteDocumentStore.doc_upsert()` (this plan's Design step 6)
  without updating the `Protocol` it implements would make `mypy` report a signature
  mismatch between `DocumentStore` and `SQLiteDocumentStore`. The source plan has been
  corrected in place to add this file to Scope.
- `DocumentStore` has exactly one implementation, `SQLiteDocumentStore` — confirmed by
  the class docstring ("Implementation: SQLiteDocumentStore (db/store_impl.py)") and by
  `rg -n "DocumentStore\b"` finding no second implementing class — so this widening has
  no other implementer to update in step.
- The `fetched_at` parameter is added ahead of `chunking_strategy` in the final
  signature (per the companion `plans/done/20260820-095054_plan.md` procedure, which
  runs first per that plan's own sequencing) — this document adds `chunking_strategy`
  after `fetched_at` in the parameter list, matching `store_impl.py`'s corresponding
  procedure for this plan.

## Design decisions

- Add `chunking_strategy: str` (no default — mandatory, matching `fetched_at`'s
  mandatory-parameter treatment and `skills/DESIGN.md` Pythonic safety constraints on
  typed, explicit data) as the last parameter in `doc_upsert()`'s signature, after
  `fetched_at`.
- Keep the `Protocol`'s docstring (`"""Insert or update a document record; return
  doc_id."""`) unchanged — it does not enumerate parameters today, so no wording update
  is needed for the added parameter.

## Alternatives considered

- Add `chunking_strategy` as a keyword-only parameter with `*` separator — rejected: the
  existing signature has no keyword-only separator today (all parameters are
  positional-or-keyword), and introducing one here would be a separate, unrequested
  interface-style change beyond this plan's scope.

  `mypy` static-type level, which is exactly what this change fixes (prevents type
  drift between `Protocol` and implementation).
