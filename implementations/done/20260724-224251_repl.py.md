## Goal

Provide a Windows-compatible mechanism for signal-driven shutdown or document the limitation with a documented workaround.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run())
**Out**: Changes to asyncio internals, cross-platform signal handling libraries

## Assumptions

1. `loop.add_signal_handler()` raises NotImplementedError on Windows consistently
2. Adding third-party dependencies (e.g., pywin32) is acceptable for Windows support
3. The primary use case is developer-facing REPL, not production deployment

## Design decisions

- Implement pywin32-based console control handler as Option A — provides native Windows signal handling without polling overhead
- Fall back to documenting the limitation as Option B if pywin32 is unavailable — avoids hard dependency on Windows-specific library
- Keep existing try/except for NotImplementedError — ensures graceful degradation on any platform that doesn't support asyncio signal handlers

## Alternatives considered

- Remove signal handling entirely on Windows: too aggressive; loses shutdown capability for Windows users
- Always require pywin32: adds unnecessary installation burden for non-Windows users who don't need it
- Polling-based approach: introduces latency in shutdown detection; worse UX than native signal handling

4. Document the Windows limitation clearly in code comments above the signal handler registration block.
5. Ensure the signal handler does not perform any blocking operations regardless of platform.

```python
        def _sigterm_handler() -> None:
            """Handle SIGTERM by cancelling input and setting shutdown flag."""
            self._ctx.conv.shutdown_requested = True
            if self._shutdown_event is not None:
                self._shutdown_event.set()
            # Cancel the current input coroutine to wake up the wait loop immediately
            if self._input_coro is not None and not self._input_coro.done():
                try:
                    self._input_coro.cancel()
                except RuntimeError:
                    pass  # Task already cancelled or not running
            logger.info("SIGTERM received; graceful shutdown initiated")

        import signal as _signal

        for sig in (signal.SIGTERM, signal.SIGINT):
            try:
                loop.add_signal_handler(sig, _sigterm_handler)
            except NotImplementedError:
                # asyncio.add_signal_handler is not supported on Windows.
                # Try pywin32 console control handler as fallback.
                try:
                    import win32con
                    import win32api
                    import sys

                    # Only register if we're running in a console window
                    if hasattr(sys, "frozen") or sys.stdout.isatty():
                        def _console_ctrl_handler(ctrl_type: int) -> bool:
                            if ctrl_type == win32con.CTRL_CLOSE_EVENT:
                                _sigterm_handler()
                            return True
                        win32api.SetConsoleCtrlHandler(_console_ctrl_handler, True)
                        logger.debug(
                            "Registered Windows console control handler for %s",
                            sig,
                        )
                    else:
                        # Not in a console — no signal mechanism available on Windows
                        logger.warning(
                            "Signal handling not available on Windows outside console; "
                            "use Ctrl+C or close the terminal to shut down"
                        )
                except ImportError:
                    # pywin32 not installed — cannot provide Windows signal handling
                    logger.warning(
                        "pywin32 not available; signal handling disabled on Windows. "
                        "Install pywin32 for Ctrl+C/Ctrl+Break support."
                    )
                except Exception as e:
                    logger.error("Failed to set Windows console control handler: %s", e)
```

Key points:
- Added detailed docstring comment explaining the Windows limitation
- pywin32 import attempted only when `NotImplementedError` is caught
- Console control handler registered only for console windows (not frozen apps)
- Graceful degradation with informative warnings at each failure level
- No blocking operations in signal handler — consistent with Unix behavior

## Compatibility considerations

- Warning messages inform users about missing functionality without breaking execution

## Security considerations
