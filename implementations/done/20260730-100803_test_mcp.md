## Goal

Connect MCP `/health` schema, probe model, and status interpretation so the Agent can consistently interpret and display dependency failures, readiness state, restart recommendations, and operator-action requirements.

## Scope

**In-Scope:**
- Add health body interpretation helpers for McpHealthProbeResult.body
- Define health reason extraction with priority order (reason → message → dependencies → details → operator_action_required → restart_recommended)
- Support structured dependencies alongside legacy string dependencies
- Distinguish server self-reported health from Agent observed health
- Surface interpreted health fields to /mcp status, startup summary, operational logs, and runbooks

**Out-of-Scope:**
- Changes to MCP transport layer (SSE/HTTP)
- Changes to MCP authentication protocol itself
- Changes to make_health_response() in mcp_servers

## Assumptions

1. The common /health schema from make_health_response() is stable and will not change frequently.
2. Structured dependencies should be preferred over legacy string dependencies but both must be supported.
3. Parse failures should never crash the Agent — they should be logged and surfaced as warnings.

2. Test: health reason extraction follows the defined priority order
   ```python
   def test_extract_health_reason_priority_order(self) -> None:
       """extract_health_reason should follow defined priority order."""
       from agent.shared.health_models import extract_health_reason
       
       # Priority 1: reason field
       body = {"reason": "database down"}
       assert extract_health_reason(body) == "database down"
       
       # Priority 2: message field (when reason absent)
       body = {"message": "service degraded"}
       assert extract_health_reason(body) == "service degraded"
       
       # Priority 3: dependencies (when reason/message absent)
       body = {"dependencies": [{"name": "db", "status": "down", "required": True}]}
       reason = extract_health_reason(body)
       assert reason is not None and "Dependency failure" in reason
       
       # Priority 4: details (when dependencies also absent)
       body = {"details": [{"component": "cache", "status": "slow"}]}
       reason = extract_health_reason(body)
       assert reason is not None and "Issue:" in reason
       
       # Priority 5: operator_action_required
       body = {"operator_action_required": True}
       assert extract_health_reason(body) == "Operator action required"
       
       # Priority 6: restart_recommended
       body = {"restart_recommended": True}
       assert extract_health_reason(body) == "Restart recommended"
       
       # No reason when nothing present
       body = {}
       assert extract_health_reason(body) is None
   ```

3. Test: structured dependencies are handled correctly

   def test_structured_dependencies_handled_correctly(self) -> None:
       """Structured dependencies should be summarized correctly."""
       from agent.shared.health_models import summarize_dependencies
       
       deps = [
           {"name": "db", "status": "down", "required": True, "reason": "connection refused"},

   ```

   def test_health_perspectives_distinguished(self) -> None:
       """Server self-reported health should be distinguished from Agent observed health."""
       from agent.shared.health_models import McpHealthProbeResult
       
       # Server reports healthy but Agent observes it unreachable
       result = McpHealthProbeResult(
           reachable=False,
           status_code=None,
           restart_recommended=False,
           operator_action_required=False,
           body={"status": "ok", "ready": True},
       )
       
       assert result.reachable is False  # Agent observed unreachable
       assert result.body.get("status") == "ok"  # Server reported ok
       assert result.status_code is None  # No HTTP response received
   ```
