# Implementation Procedure: scripts/rag/ingestion/document_manager.py

## Goal

Delete the dead, duplicate `_handle_existing_file()` method, leaving
`handle_existing_document()` as the single authoritative file-URL SHA-256
skip/replace decision path.

## Scope

**In-Scope**
- Delete `_handle_existing_file()` from `DocumentManager`.

**Out-of-Scope**
- `handle_existing_document()` — unchanged; it already contains the complete, correct
  file-URL SHA-256 logic (same `_is_file_unchanged()` call, same two log messages).
- `_is_file_unchanged()` — unchanged, still used by both the surviving method and its
  own direct unit tests (`TestIsFileUnchanged`).
- `_update_etag()` — unchanged; unrelated to the file-URL branch being deleted.

## Assumptions

- Zero callers of `_handle_existing_file()` outside its own definition — confirmed via
  `rg -n "_handle_existing_file" scripts/ tests/` (excluding `mutants/`), which returns
  only the method's own `def` line in this file and one comment-only reference in
  `tests/rag/ingestion/test_rag_ingestion_pipeline.py` (handled by that file's own
  implementation procedure).
- `_handle_existing_file()`'s logic (SQL query, `_is_file_unchanged()` call, both log
  messages) is a subset of `handle_existing_document()`'s file-URL branch, confirmed by
  reading both methods in full side by side — the only difference is return shape
  (`bool` vs. the 3-tuple `handle_existing_document()` returns), which is irrelevant
  since nothing calls the private method.

## Design decisions

- Straight deletion, no replacement code — `handle_existing_document()` already
  subsumes this method's behavior for every real caller.
- No change to the class's public interface — `_handle_existing_file()` was already
  private (leading underscore) and uncalled, so removing it is not a breaking change to
  any consumer.

## Alternatives considered

- Keep `_handle_existing_file()` as a thin wrapper delegating to
  `handle_existing_document()` — rejected: the source plan's stated goal is removing the
  duplicate entirely, and a zero-caller wrapper would still be dead code carrying
  maintenance cost for no benefit.

## Implementation

### Target file
`scripts/rag/ingestion/document_manager.py`

### Procedure
1. Re-run `rg -n "_handle_existing_file" scripts/ tests/` (excluding `mutants/`) to
   reconfirm zero callers immediately before editing (catches any drift since this plan
   was written).
2. Delete the `_handle_existing_file()` method definition from `DocumentManager`.
3. Confirm `handle_existing_document()` and `_is_file_unchanged()` are untouched.

### Method
Direct deletion of one method; no other code in this file changes.

### Details
- No import changes needed — nothing else in this file exists solely to support the
  deleted method.
- This procedure must run only after the companion `tests/rag/ingestion/
  test_ingestion_freshness.py` procedure's new regression test is added and passing
  against the pre-deletion code (per the source plan's Phase 1 ordering) — this
  guarantees the replace-path behavior stays covered by a real-object test once the
  duplicate method that could theoretically diverge from it is gone.

## Compatibility considerations

- No behavior change for any real caller — `ingester.py` only ever called
  `handle_existing_document()`, never the deleted private method.
- The generated `mutants/scripts/rag/ingestion/document_manager.py` mutation-testing
  artifact does not need manual editing — it is regenerated by the mutation-testing
  tool, not hand-maintained source (per the source plan's own Assumptions).

## Security considerations

N/A: pure dead-code removal, no security-relevant logic touched.

## Rollback considerations

- Trivially revertable: restoring the deleted method from version control has no
  ripple effect, since nothing depends on it.
