## Goal

Replace unreliable `locals().get("task")` with explicit `None` initialization in the finally block of `_handle_workflow_engine()`.

## Scope

**In-Scope**:
- Initialize `task = None` before the try block
- Replace `locals().get("task")` with direct `task` reference in the finally block

**Out-of-Scope**:
- Any other changes to `_handle_workflow_engine()` logic
- Modifying `_init_workflow_task()` behavior
- Adding new configuration options

## Assumptions

1. The existing check `if _task is not None and _task.task_id:` correctly handles the case where `task` was never assigned.
2. No other parts of the method rely on `task` being undefined when `_init_workflow_task()` fails.

## Design decisions

- **Initialize `task = None` before try block**: Standard Python pattern — ensures the variable always exists regardless of which path the code takes. More reliable than `locals().get()`.
- **Use direct `task` reference instead of `locals().get("task")`**: Eliminates the subtle bug where `locals()` may not reflect variables from enclosing function scopes. Direct reference is the idiomatic approach.
- **Keep existing `if _task is not None and _task.task_id:` guard**: Preserves the double-check — first checks if task was created, then checks if it has a valid task_id.

## Alternatives considered

- **Catch `_init_workflow_task()` failure separately**: Would add another except clause but would make the failure explicit. Chose simpler init-before-try approach since the finally block already guards against None.
- **Move task creation outside the try block**: Would require restructuring the method significantly. Rejected because it would change the error handling semantics.
- **Use `globals().get("task")`**: Even less reliable than `locals().get()` for local scope variables. Rejected.
