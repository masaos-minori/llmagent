## Goal

Make RAG ingestion safe under partial failure: ensure consistency checks run against an open DB connection, keep failed embedding chunks retryable, and provide operators with clear visibility into ingestion failures.

## Scope

**In-Scope:**
- Move `check_consistency()` inside the active DB context in `RagIngester.ingest_all()`
- Treat failed consistency checks as explicit error states
- Only move successfully ingested chunk files to `registered/`
- Keep embedding-failed chunks in `chunk/` or move them to `retry/`
- Optionally move invalid, non-retryable chunks to `failed/`
- Emit structured logs for failed chunks with URL, chunk_index, source_file, failure reason
- Consider writing `.error.json` metadata for failed chunks
- Ensure `embed_failed > 0` is visible in ingestion summary and operational logs

**Out-of-Scope:**
- Changes to existing successful ingestion behavior
- Changes to embedding service itself
- Changes to document parsing logic
- Changes to the SQLite schema

## Assumptions

1. Chunk files that fail embedding should remain in `chunk/` so they can be retried on the next ingestion run.
2. Invalid chunks (parse errors, validation failures) should be moved to `failed/` since they cannot be retried without manual intervention.
3. The `.error.json` metadata format should include: URL, chunk_index, source_file, failure reason, timestamp.
4. Consistency check failure should cause the entire ingestion to report an error state but not crash the process.

## Design decisions

- **Consistency check timing**: Move `check_consistency()` inside the DB context to prevent using a closed connection. Return boolean from `check_consistency()` rather than raising an exception — this allows the caller to handle the error gracefully.
- **Chunk file routing**: Separate successful chunks (`registered/`) from failed chunks (`retry/` or `failed/`). Embedding-failed chunks go to `retry/`; invalid chunks go to `failed/` with `.error.json` metadata.
- **Structured logging**: Use structured log fields (URL, chunk_index, source_file, failure reason) for all failure paths to enable operator debugging.
- **Batch `.error.json` writes**: Write `.error.json` files after all chunk processing completes, rather than per-chunk, to minimize filesystem overhead.

## Alternatives considered

- **Raise exception on consistency check failure**: Could raise instead of returning boolean. Rejected because the caller needs to continue ingestion even when consistency fails — the error should be reported, not fatal.
- **Move all chunks to `retry/` on failure**: Could move all chunks to `retry/` regardless of failure type. Rejected because invalid chunks cannot be retried without manual intervention and should be isolated in `failed/`.
- **Per-chunk `.error.json` writes**: Could write `.error.json` immediately when a chunk fails. Rejected because batch writes reduce filesystem I/O overhead during ingestion.

### Procedure

#### Phase 1: Fix consistency check DB context

1. In `RagIngester.ingest_all()`, locate the `with SQLiteHelper(...) as db:` block.
2. Move `doc_mgr.check_consistency()` call inside this block so it uses the open connection.
3. Pass the `db` instance to `check_consistency()` instead of relying on a closed connection.
4. Treat `check_consistency()` returning falsy value as an explicit error state — log warning and set error flag.

```python
# Before:
with SQLiteHelper(db_path) as db:
    # ... other operations ...
# After: db connection closed here
consistency_ok = doc_mgr.check_consistency()

# After fix:
with SQLiteHelper(db_path) as db:
    # ... other operations ...
    consistency_ok = doc_mgr.check_consistency(db)
if not consistency_ok:
    logger.warning("Consistency check failed")
    self._consistency_error = True
```

#### Phase 2: Separate successful and failed chunk file routing

1. Modify `_ingest_chunk_files()` to track which chunk files succeeded and which failed:
   ```python
   def _ingest_chunk_files(self, ...) -> Tuple[List[str], List[str], List[str]]:
       """Return (success_paths, embed_failed_paths, parse_failed_paths)."""
   ```

2. Modify `_move_to_registered()` to accept a list of paths to move (only successful ones):
   ```python
   def _move_to_registered(self, paths: List[str]) -> None:
       """Move only successfully ingested chunk files to registered/."""
   ```

3. Add `_move_to_retry(paths)` method — move embedding-failed chunks back to `chunk/` or to `retry/` subdirectory.

4. Add `_move_to_failed(paths)` method — move invalid/non-retryable chunks to `failed/` subdirectory.

5. Write `.error.json` metadata for each failed chunk containing: URL, chunk_index, source_file, failure reason, timestamp.

```python
def _move_to_failed(self, paths: List[str]) -> None:
    """Move invalid/non-retryable chunks to failed/ with .error.json metadata."""
    failed_dir = Path(self.chunk_dir) / "failed"
    failed_dir.mkdir(exist_ok=True)
    
    for path in paths:
        try:
            error_meta = {
                "url": ...,  # from chunk metadata
                "chunk_index": ...,
                "source_file": ...,
                "failure_reason": ...,
                "timestamp": datetime.utcnow().isoformat(),
            }
            error_file = failed_dir / f"{path.stem}.error.json"
            error_file.write_text(orjson.dumps(error_meta).decode())
            
            # Move original chunk file
            dest = failed_dir / path.name
            shutil.move(str(path), str(dest))
        except Exception as e:
            logger.error(f"Failed to move chunk to failed/: {e}")
```

## Compatibility considerations

- Existing successful ingestion flow is unchanged — only failure paths are affected.
- Callers that read from `registered/` will now see fewer files (failed chunks are excluded) — update any assumptions about `registered/` containing all processed chunks.
- The new `retry/` and `failed/` directories are optional and created on-demand.

## Security considerations

- No new secrets or credentials introduced.
- `.error.json` metadata contains failure reasons — ensure no sensitive data leaks through these files (e.g., API keys embedded in URLs).
- File move operations use standard library functions — no external dependencies added.

## Rollback considerations

- If the file routing changes cause issues, revert the `_move_to_retry()` and `_move_to_failed()` methods and restore the previous single-directory approach.
- Removing the `.error.json` metadata logic is straightforward — delete the metadata write code.
- The consistency check fix is low-risk — reverting means going back to using a closed DB connection.
