## Goal

Make the RAG pipeline resilient to LLM-side failures by adding explicit fallback paths: MQE failure falls back to original query; rerank failure falls back to RRF-ranked results.

## Scope

**In-Scope:**
- Update stage status reporting to distinguish disabled vs failed-with-fallback
- Ensure AugmentStage always receives usable reranked hits when search and fusion succeed

**Out-of-Scope:**
- Changes to SQLite schema
- Changes to embedding service
- Changes to RRF fusion logic
- Changes to augment formatting

## Assumptions

1. MQE fallback uses the original query unchanged — no attempt to retry or modify the query.
2. Rerank fallback applies deduplicate_chunks() + rag_top_k slicing to ctx.merged (same as _rerank_fallback()).
3. Fallback reasons are recorded as distinct strings: "mqe_exception" and "rerank_exception".
4. Both fallbacks should be logged at INFO level for observability.
5. The fallback behavior should apply only on LLM exceptions, not on configuration errors.

## Design decisions

- **Status distinction**: Use "fallback" status for both MQE and rerank failures where fallback was applied, distinguishing them from "disabled" (feature not configured) and "failure" (no fallback available).
- **AugmentStage safety**: Verify AugmentStage handles empty ctx.reranked gracefully; if needed, add additional fallback to raw chunks.

## Alternatives considered

- **Single "degraded" status**: Could use a single "degraded" status for all fallback cases. Rejected because "fallback" provides more specific information about what happened.
- **Remove AugmentStage on rerank failure**: Could skip AugmentStage entirely when rerank fails. Rejected because AugmentStage may still produce useful output from RRF-ranked results.

## Implementation

### Target file

`scripts/rag/pipeline.py`

### Procedure

#### Phase 3: Update stage status reporting

1. Modify `_mqe_status()` to return "fallback" with reason "mqe_exception" when MQE failed but fallback was applied:
   ```python
   def _mqe_status(self) -> str:
       if not self.config.use_mqe:
           return "disabled"
       if self.ctx.queries == [self.ctx.query]:
           return "fallback"  # MQE failed, used original query
       return "enabled"
   ```

2. Modify `_rerank_status()` to return "fallback" with reason "rerank_exception" when rerank failed but fallback was applied:
   ```python
   def _rerank_status(self) -> str:
       if not self.config.use_rerank:
           return "disabled"
       if self.ctx.reranked is not None and self.ctx.reranked != []:
           # Check if reranked came from fallback (deduplicated merged)
           if hasattr(self.ctx, '_rerank_fallback_applied') and self.ctx._rerank_fallback_applied:
               return "fallback"
           return "enabled"
       return "fallback"  # Rerank failed, used RRF fallback
   ```

3. Keep existing "use_mqe=False" / "use_rerank=False" fallback reasons unchanged

#### Phase: Ensure AugmentStage receives usable reranked hits

4. In `AugmentStage.run()`, verify ctx.reranked is not empty before proceeding:
   ```python
   async def run(self, ctx: RagContext) -> StageResult:
       if not ctx.reranked:
           # AugmentStage cannot handle empty ctx.reranked
           # Fall back to raw chunks
           logger.warning("AugmentStage: empty reranked list, using raw chunks")
           return StageResult(
               status="fallback",
               reason="empty_reranked",
               hits=ctx.merged[:cfg.rag_top_k],
           )
       # ... normal augment flow ...
   ```

### Method

- Update `_mqe_status()` and `_rerank_status()` methods in Pipeline class
- Add empty ctx.reranked check in AugmentStage

### Details

1. `_mqe_status()` update:
   - Return "fallback" when MQE failed and original query was used
   - Distinguish from "disabled" (MQE not configured) and "enabled" (normal operation)

2. `_rerank_status()` update:
   - Return "fallback" when rerank failed and RRF-ranked results were used
   - Track fallback state via `ctx._rerank_fallback_applied` flag set by RerankStage
   - Distinguish from "disabled" (rerank not configured) and "enabled" (normal operation)

3. AugmentStage update:
   - Check if ctx.reranked is empty before proceeding
   - If empty, fall back to raw chunks with appropriate logging
