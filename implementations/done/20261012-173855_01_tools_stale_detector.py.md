## Goal
- Let a procedure declare its target file as new with the marker (new) after the target path, and handle such a target without the existence abort, while an unmarked absent target is still reported `source_missing` (`REQ-001`, `REQ-002`, `REQ-003`).

## Scope
- `from_procedure`, `_check_line_refs`, one new private helper, and the module docstring of `tools/stale_detector.py`. The symbol, import, and Before-block check functions, the allowlist, and the command-line entry point are untouched.

## Assumptions
- The target section pattern `_TARGET_FILE_SECTION_RE` ends right after the closing backtick of the path, so `_is_marked_new` called with the end offset of that match sees the marker; the captured path stays marker-free.
- The mismatch collection accepts any type string, so two new type strings need no schema change.
- A declared-new target has no content, so the content checks run against an empty source text.
- The detector stays regex-based and dependency-free.

## Design decisions
- Decide the target's state before any content check, in this order: containing directory missing, then file already present, then proceed. Each of the first two returns immediately with one mismatch, because checking content against a file the procedure says it creates would add noise.
- Extract the declared-new handling into a small private helper so `from_procedure` gains one branch only and its complexity does not grow past its current grade.
- Add a keyword flag to `_check_line_refs`, default off: when on, a citation for which `_find_scoped_path` returns no path is skipped, while a scoped citation is validated as today. With the flag off the function behaves exactly as before.
- The marker applies only to the section-level target; the fallback path that picks any backticked absolute path when no section exists is never declared new.

## Alternatives considered
- Reading the Plan to infer that a row is new: rejected by the Plan scope (adds a dependency on the Plan's wording).
- Accepting an already-existing declared-new file and checking it normally: rejected by the user decision recorded in the Plan (it contradicts the procedure's premise).

## Implementation
### Target file
`tools/stale_detector.py`

### Procedure
1. Apply procedure 02 first and confirm its new-policy tests fail against the current code; do not edit this file before that.
2. In `from_procedure`, after the target path is taken from the section match, compute whether the target is declared new: the section match exists and `_is_marked_new` is true at the end offset of that match. Keep `result.target_file` as the bare path.
3. Add a private helper that takes the result, the source directory and the target path and returns true when the target is acceptable as new. It records one mismatch of type new_target_dir_missing (message naming the directory) when the parent directory of the target does not exist under the source directory, and one mismatch of type new_target_exists (message naming the file) when the file already exists; in both cases it returns false.
4. In `from_procedure`, where the code currently reports `source_missing` for an absent file, branch first: if the target is declared new, call the helper and return the result when it returns false; otherwise continue with an empty source text and an empty list of source lines. If the target is not declared new, keep the existing `source_missing` report unchanged.
5. Give `_check_line_refs` a keyword-only boolean parameter, default false, that skips a citation when no scoped path was resolved for it; pass true from `from_procedure` only for a declared-new target. Update its docstring to describe the flag.
6. Leave the symbol, import, and Before-block checks as they are: they already receive the source text and work with an empty one.
7. Extend the module docstring with two sentences: a target path followed by the marker (new) declares the file as created by the procedure, which skips the existence check, requires an existing containing directory, and reports a file that already exists; and line citations that resolve to such a target are skipped.

### Method
- Edit only these places; keep the dataclass, the other check functions, and the command-line entry point as they are.
- Keep type annotations consistent with the module and keep the new helper private.

### Details
- A declared-new procedure's Before-block is reported by the existing check against the empty source; this is intended, because a new file has no prior content.
- Symbols cited by a declared-new procedure that exist elsewhere in the repository are not reported, through the existing repository-wide presence check; unmarked names that exist nowhere are still reported.
- Do not change `_TARGET_FILE_SECTION_RE`, `_SYMBOL_RE`, or `_NON_SYMBOL_ALLOWLIST`.
