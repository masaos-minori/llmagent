# Implementation Procedure: Clean Up Obsolete Dimension References in Test Fixtures

## Goal

Remove references to `embedding_dim`, `embedding_dims`, and `vec_dim` from test fixtures that are no longer relevant after dimension validation removal. Dimensions are now hardcoded to 1024 via `get_embedding_dims()` in `store_protocols.py`.

## Scope

- **In scope**: Update test fixtures in `tests/db/test_db_maintenance.py` that set `cfg.embedding_dims`.
- **Out of scope**: Tests that verify `get_embedding_dims()` constant behavior, SemanticCache dimension mismatch tests, startup orchestrator dimension checks.

## Assumptions

- `DbConfig` dataclass does not have an `embedding_dims` field (verified: fields are `rag_db_path`, `session_db_path`, `workflow_db_path`, `eventbus_db_path`, `sqlite_vec_so`, `sqlite_timeout`, `sqlite_busy_timeout_ms`).
- Setting `cfg.embedding_dims = 384` on a `MagicMock(spec=DbConfig)` is either dead code or a bug (would raise AttributeError due to spec constraint).
- Other test files (`test_embedding_dimension.py`, `test_rag_cache.py`, `test_startup.py`) test different concerns and should NOT be modified.

## Design decisions

- Remove `cfg.embedding_dims = 384` line from the test fixture since DbConfig has no such field.
- Keep other test files unchanged — they test different concerns:
  - `test_embedding_dimension.py`: verifies `get_embedding_dims()` returns 1024 constant.
  - `test_rag_cache.py`: tests SemanticCache dimension mismatch behavior.
  - `test_startup.py`: tests startup orchestrator dimension comparison logic.

## Alternatives considered

- Leave `cfg.embedding_dims = 384` as-is: rejected because it contradicts the DbConfig schema and violates the plan's scope of removing all dimension key references.
- Add `embedding_dims` to DbConfig: rejected because dimensions are hardcoded constants, not configurable.
