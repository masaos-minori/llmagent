# Implementation Procedure: scripts/agent/startup.py

## Goal
Make `StartupOrchestrator` accept an optional `shutdown_event`, add a shared
`_interruptible_sleep()` race helper, and wire it into `_start_servers()` and
`_verify_mcp_health()` so a `SIGINT`/`SIGTERM` fired during the stagger delay, either
retry delay, or between per-server loop iterations raises `StartupInterrupted` promptly
instead of waiting out the full delay/timeout.

## Scope
- In scope: module-level `StartupInterrupted` exception (new); `StartupOrchestrator.__init__()`
  (add `shutdown_event` param); new `_interruptible_sleep()` method; `_start_servers()`
  (pre-loop check, stagger-delay race, retry-delay race, forward `shutdown_event=` into
  `start_http_subprocess()` calls); `_verify_mcp_health()` (pre-loop check, retry-delay race).
- Out of scope: `run()`'s rollback/`_servers_started`/`_spawned_subprocesses` handling
  (owned by the sibling procedure, see Assumptions); `_check_services()`,
  `_recover_pending_approvals()`, `_setup_prompt()`, and all other `StartupOrchestrator`
  methods not named above.

## Design decisions
- Store `shutdown_event: asyncio.Event | None = None` as a plain constructor parameter with a
  `None` default (not a required arg) — preserves all 20+ existing
  `StartupOrchestrator(ctx, view)` construction sites in `tests/agent/test_startup.py` with zero
  edits, per the skill's "validate only at system boundaries" and YAGNI guidance (no new
  abstraction needed beyond an optional attribute).
- Factor the race into one `_interruptible_sleep()` method (reusing the exact
  `asyncio.wait({...}, return_when=FIRST_COMPLETED)` pattern already proven in
  `AgentREPL._repl_loop()`, `scripts/agent/repl.py:544-547`) instead of inlining
  `asyncio.wait` at each of the 3 call sites — keeps each call site to one `if await
  self._interruptible_sleep(delay): raise StartupInterrupted(...)` line, bounding the
  cyclomatic-complexity growth of `_start_servers()`/`_verify_mcp_health()` to roughly one
  branch per race point.
- `StartupInterrupted(RuntimeError)` is a plain `RuntimeError` subclass, not a new
  control-flow mechanism — it flows through `run()`'s existing `except Exception as
  setup_err:` unchanged, so no second rollback path is introduced.

## Alternatives considered
- Inline a full `asyncio.wait()` block at each of the 3 sleep call sites instead of extracting
  `_interruptible_sleep()`: rejected — triples near-identical boilerplate and pushes CC higher
  than the shared-helper approach at both affected methods.
- Use `asyncio.CancelledError`/task cancellation to interrupt the whole coroutine instead of a
  checked-return-value helper: rejected — the requirement this plan derives from explicitly
  asks to reuse the `_repl_loop()` task-race pattern, not introduce a new cancellation
  abstraction; a checked return value keeps the failure path an explicit `raise`, not an
  implicit cancellation propagating through unrelated `try/except` blocks.

## Implementation

### Target file
`scripts/agent/startup.py`

### Procedure
1. Add `class StartupInterrupted(RuntimeError):` at module level, near
   `HEALTH_CHECK_RETRY_DELAY_SEC` (current line 44).
2. In `__init__()` (current lines 60-65, or as already modified by the sibling procedure), add
   parameter `shutdown_event: asyncio.Event | None = None` and store `self._shutdown_event =
   shutdown_event`.
3. Add method `async def _interruptible_sleep(self, delay: float) -> bool:` on
   `StartupOrchestrator`, per Design decisions — race `asyncio.sleep(delay)` against
   `self._shutdown_event.wait()` using `asyncio.wait({...}, return_when=FIRST_COMPLETED)`;
   cancel the losing task; return `True` iff the shutdown task fired first; if
   `self._shutdown_event is None`, plain `await asyncio.sleep(delay)` then return `False`.
4. In `_start_servers()` (current lines 133-204):
   - At the top of the `for key, cfg in ctx.cfg.mcp.mcp_servers.items():` loop (current line
     149), add: `if self._shutdown_event is not None and self._shutdown_event.is_set(): raise
     StartupInterrupted(f"shutdown requested before starting MCP subprocess {key!r}")`.
   - Replace `await asyncio.sleep(stagger_delay)` (current line 158) with
     `if await self._interruptible_sleep(stagger_delay): raise StartupInterrupted(f"shutdown
     requested during startup stagger delay for {key!r}")`.
   - Replace `await asyncio.sleep(HEALTH_CHECK_RETRY_DELAY_SEC)` (current line 179) with the
     same pattern, message referencing the retry delay for `key`.
   - Add `shutdown_event=self._shutdown_event` as a keyword argument to both
     `start_http_subprocess()` calls (current lines 164-166 and 181-184).
5. In `_verify_mcp_health()` (current lines 206-252):
   - At the top of the `for server_key, cfg in subprocess_servers:` loop (current line 221),
     add the same pre-loop shutdown check as step 4, raising `StartupInterrupted` referencing
     `server_key`.
   - Replace `await asyncio.sleep(HEALTH_CHECK_RETRY_DELAY_SEC)` (current line 231) with the
     `_interruptible_sleep()` pattern.

  cancel-the-loser).

### Details
- New import: none required beyond the already-imported `asyncio`.
- `_interruptible_sleep()` return contract: `True` = shutdown fired before `delay` elapsed
  (caller must raise); `False` = full delay elapsed normally or no `shutdown_event` configured
  (caller proceeds).
- All new `StartupInterrupted(...)` messages should be plain, non-secret strings (server key
  names only) — no `_mask_secrets()` needed since no credential-bearing config value is
  interpolated.
