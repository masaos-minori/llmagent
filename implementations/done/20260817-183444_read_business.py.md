## Goal

Remove two dead `except PermissionError` handlers around `rglob()` calls in `scripts/mcp_servers/file/read_business.py` since they are unreachable under all supported Python versions (3.13+).

## Scope

- **In-Scope**:
  - Confirm the two `except PermissionError` handler contexts in `search_files` (~line 222) and `_collect_grep_matches` (~line 256)
  - Remove both handlers
  - Add inline comments documenting the Python 3.13+ rglob() swallowing behavior
  - Verify `tests/mcp_servers/file/test_read_service.py` passes
- **Out-of-Scope**:
  - Changes to any other MCP server's file handling
  - Adding new tests beyond verifying existing ones pass
  - Changes to `rglob()` behavior or semantics

## Assumptions

- Python 3.13+ `glob.py` wraps `scandir()` errors in `except OSError: pass`, which includes `PermissionError`
- Empirical test on Python 3.14 confirms rglob() swallows PermissionError when encountering a chmod-000 subdirectory
- The two characterization tests (`test_search_files_permission_error_during_traversal_is_swallowed`, `test_grep_files_permission_error_during_traversal_is_swallowed`) assert observable behavior, not coverage of the specific `except` block

## Design decisions

- Keep the two characterization tests as-is; they validate observable behavior (silent skip of unreadable subtrees), not the internal `except` block
- Add inline comments referencing this plan entry for future maintainers

## Alternatives considered

- Leave the handlers in place with deprecation comments — rejected because the code is provably unreachable and adds noise
- Replace with `except OSError: pass` — rejected because it duplicates what rglob() already does

## Compatibility considerations

- Requires Python 3.13+ (already enforced by pyproject.toml `target-version = "py313"`)
- No behavioral change for users; error suppression is identical before and after

## Security considerations

- N/A — no security-relevant behavior change; PermissionError was already swallowed

## Rollback considerations
