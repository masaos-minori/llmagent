## Goal
In `scripts/rag/ingestion/ingester.py`: fix broken code caused by partial application of
the migration from dict-based `ChunkJsonRaw` to dataclass `ChunkDocument`. Specifically:
remove calls to nonexistent `_validate_artifact()` and `_normalize_chunk_index()`, convert
all `.get()` dict access on `ChunkDocument` to attribute access, remove dead `is None`
checks (since `read_chunk_json` raises `ChunkFormatError`), and define `fetched_at` in
`ingest_url_group()`.

## Scope
- In scope: `scripts/rag/ingestion/ingester.py` only.
- Out of scope: `pipeline_utils.py`'s `read_chunk_json()` itself (own document);
  `store_protocols.py`/`store_impl.py` (unrelated to this file's actual DB-write path —

## Design decisions
- `chunk_index` handling: replace `idx_raw = data.get("chunk_index", 0); idx =
  self._normalize_chunk_index(doc_id, path.name, idx_raw)` (lines 533-534) with direct
  use of `data.chunk_index` (already validated as a non-negative, non-`bool` int by
  `read_chunk_json()` at the boundary) — no runtime re-validation needed in
  `_embed_and_store()` itself, since the reader already rejected any invalid value
  before `_embed_and_store()` ever sees it.
- `_validate_artifact()` removal: since `read_chunk_json()` already enforces the exact
  mandatory-key set (which subsumes the old `schema_version`/`artifact_type`/
  `created_by` presence checks) and rejects unknown fields, the separate
  `artifact_type == expected_type` check (the one piece of `_validate_artifact()`'s
  logic not otherwise covered by key-set validation) must be preserved somewhere —
  add it as an explicit equality check right after the `read_chunk_json()` call at each
  of the two structurally-checking call sites (`ingest_url_group()` line 205,
  `_embed_and_store()` line 518), since `read_chunk_json()` itself has no
  `expected_type` parameter (it validates shape, not "was this a chunk vs. crawl
  file").
- `fetched_at` in `ingest_url_group`: add `fetched_at: str | None = None` as a parameter
  to preserve the existing runtime value (always `None` for this call path since
  `ChunkDocument` has no `fetched_at` field yet — see the gap found during adversarial
  review below).

## Alternatives considered
- Giving `read_chunk_json()` an `expected_type` parameter so it also enforces
  `artifact_type == "chunk"` internally — rejected to keep `pipeline_utils.py`'s reader
  a pure shape-validator; the "is this artifact type appropriate for this call site"
  check is call-site-specific business logic that belongs in `ingester.py`, not in the
  shared I/O utility (matches this plan's general "no speculative generalization"
  principle applied to `pipeline_utils.py`).
