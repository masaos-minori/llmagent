## Goal

Harden `delete_models.py` request validation and config immutability across three sub-changes: path validation, description text unification, and config immutability.

## Scope

- **In-Scope**:
  - Sub-change A: Add path validation to reject empty strings and relative paths
  - Sub-change B: Create shared mixin for `repo_path` field description text unification
  - Sub-change C: Add `frozen=True` to `FileDeleteConfig` dataclass and `extra="forbid"` to Pydantic request models
- **Out-of-Scope**:
  - Runtime behavior changes beyond validation enforcement
  - Changes outside `scripts/mcp_servers/file/`

## Assumptions

- All callers send absolute paths (confirmed via Phase 1 investigation)
- The description text difference ("file" vs. "directory") is intentional but inconsistent
- `FileDeleteConfig` should be immutable once created
- Pydantic request models should reject unexpected fields

## Design decisions

- Use Pydantic `model_validator` for path validation (reject empty strings and relative paths)
- Create a shared mixin class for `repo_path` field to unify description text across models
- Add `frozen=True` to dataclass and `extra="forbid"` to Pydantic models for strictness

## Alternatives considered

- Keep current permissive behavior — rejected because it allows invalid inputs
- Leave description text inconsistent — rejected because inconsistency misleads maintainers

## Compatibility considerations

- Option A: Rejecting relative paths may break callers that rely on relative path resolution
- Option C: `frozen=True` and `extra="forbid"` may break callers that mutate objects or send extra fields
- Phase 1 must confirm all callers before proceeding with any sub-change

## Security considerations

- Path validation prevents potential directory traversal attacks from user-supplied input

## Rollback considerations

- Revert the diff; no data loss or service impact

# BEFORE:
from pydantic import BaseModel

class DeleteFileRequest(BaseModel):
    repo_path: str
    file_path: str

class DeleteDirectoryRequest(BaseModel):
    repo_path: str
    dir_path: str

# AFTER:
import os
from pydantic import BaseModel, model_validator

class RepoPathMixin:
    """Mixin providing shared repo_path field with unified description."""
    repo_path: str = Field(description="Absolute path to the repository root.")

class DeleteFileRequest(RepoPathMixin, BaseModel):
    file_path: str
    
    @model_validator(mode="after")
    def validate_paths(self) -> Self:
        if not self.repo_path:
            raise ValueError("repo_path must not be empty")
        if not os.path.isabs(self.repo_path):
            raise ValueError(f"repo_path must be an absolute path, got: {self.repo_path}")
        if not self.file_path:
            raise ValueError("file_path must not be empty")
        return self

class DeleteDirectoryRequest(RepoPathMixin, BaseModel):
    dir_path: str
    
    @model_validator(mode="after")
    def validate_paths(self) -> Self:
        if not self.repo_path:
            raise ValueError("repo_path must not be empty")
        if not os.path.isabs(self.repo_path):
            raise ValueError(f"repo_path must be an absolute path, got: {self.repo_path}")
        if not self.dir_path:
            raise ValueError("dir_path must not be empty")
        return self

# In scripts/mcp_servers/file/delete_models.py, Sub-change C (immutability):

# BEFORE:
@dataclass
class FileDeleteConfig:
    repo_path: str
    dry_run: bool = False

class DeleteFileRequest(BaseModel):
    repo_path: str
    file_path: str

# AFTER:
@dataclass(frozen=True)
class FileDeleteConfig:
    repo_path: str
    dry_run: bool = False

class DeleteFileRequest(BaseModel, extra="forbid"):
    repo_path: str
    file_path: str

class DeleteDirectoryRequest(BaseModel, extra="forbid"):
    repo_path: str
    dir_path: str
