## Goal

Ensure all resources acquired during the startup phase are released regardless of whether startup succeeds or fails.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _close_resources()), `scripts/agent/startup.py` (StartupOrchestrator._start_servers())
**Out**: MCP subprocess management logic, HTTP client lifecycle outside startup path

## Assumptions

1. `_close_resources()` is only called from `AgentREPL.run()` finally block
2. `self._ctx.services` can be None when `build_agent_context()` never completed
3. MCP subprocess cleanup requires tracking spawned processes from `_start_servers()`

## Design decisions

- Use try/finally pattern in `AgentREPL.run()` rather than refactoring into a context manager — minimal change surface, preserves existing control flow
- Return subprocess list from `StartupOrchestrator._start_servers()` instead of modifying `StartupOrchestrator.run()` — keeps the public API unchanged
- Terminate subprocesses before calling `_close_resources()` — ensures lifecycle service is not shut down while subprocesses still reference it

## Alternatives considered

- Context manager wrapping entire `run()` body: adds complexity for marginal benefit given the single call site
- Raising subprocess cleanup to `StartupOrchestrator.run()`: would require changing the return type and all callers

## Implementation

### Target file

`scripts/agent/repl.py`

### Procedure

1. Add try/finally block around the startup call in `AgentREPL.run()`.
2. Modify `_close_resources()` to handle the case where services were never initialized.
3. Update `StartupOrchestrator._start_servers()` to collect spawned subprocess PIDs.
4. Pass subprocess list through `StartupOrchestrator.run()` to `AgentREPL.run()`.
5. In the finally block, terminate subprocesses before calling `_close_resources()`.

### Method

#### Step A: Modify `AgentREPL.run()` — add try/finally

Replace the current try/except structure (lines 507-511):

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        await self._run_repl_loop()
```

With:

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        _spawned_subprocesses: list[subprocess.Popen] = []
        try:
            self._cmds, self._orchestrator, _spawned_subprocesses = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        finally:
            # Terminate any subprocesses started during partial startup
            for proc in _spawned_subprocesses:
                if proc.poll() is None:
                    proc.terminate()
            await self._close_resources()
        await self._run_repl_loop()
```

Key points:
- `_spawned_subprocesses` is declared before the try so it survives into the finally block
- `proc.poll() is None` checks if process is still running before terminating
- `_close_resources()` is always called in the finally block

#### Step B: Modify `StartupOrchestrator._start_servers()` — collect subprocesses

Change the method signature and return type:

```python
    async def _start_servers(self) -> list[subprocess.Popen]:
```

Inside the loop, after each successful `start_http_subprocess` call, append the result:

```python
                try:
                    proc = await ctx.services_required.lifecycle.start_http_subprocess(
                        key, cfg
                    )
                    if proc is not None:
                        spawned.append(proc)
                except (OSError, RuntimeError) as e:
                    ...
```

Also update the exception handling branch — if an exception occurs in production mode, the caller will handle cleanup via the subprocess list.

Return the collected list at the end:

```python
        return spawned
```

Initialize `spawned: list[subprocess.Popen] = []` at the start of the method.

#### Step C: Modify `StartupOrchestrator.run()` — propagate subprocess list

Change the return type:

```python
    async def run(self) -> tuple[CommandRegistry, Orchestrator, list[subprocess.Popen]]:
```

Update the success return:

```python
        return self._cmds, self._orchestrator, []  # empty list on success
```

Update the exception handler to pass subprocess list back:

```python
        except Exception as setup_err:
            if _servers_started:
                try:
                    await self._ctx.services_required.lifecycle.shutdown_all()
                except Exception as shutdown_err:
                    logger.error(
                        "CRITICAL: Startup rollback FAILED — subprocesses may be orphaned: %s",
                        shutdown_err,
                    )
            # Pass subprocess list to caller for termination
            raise setup_err
```

Note: The subprocess list must be accessible in the exception path. Consider storing it as `self._spawned_subprocesses` instance variable instead of a local variable.

## Compatibility considerations

- `StartupOrchestrator.run()` return type changes from `tuple[CommandRegistry, Orchestrator]` to `tuple[CommandRegistry, Orchestrator, list[subprocess.Popen]]` — only one caller (`AgentREPL.run()`)
- Subprocess termination is safe: `proc.terminate()` sends SIGTERM which the process can catch; if it doesn't respond within timeout, `proc.kill()` could be added as a follow-up

## Security considerations

- Only terminate PIDs explicitly tracked in the subprocess list — no blind process killing
- `proc.terminate()` is less aggressive than `proc.kill()` — allows graceful shutdown

## Rollback considerations

- If subprocess termination causes issues, revert to the original behavior by removing the finally block subprocess cleanup
- `_close_resources()` already handles idempotent close via `svc is not None` check — no risk of double-close
