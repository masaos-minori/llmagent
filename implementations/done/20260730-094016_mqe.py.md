## Goal

Make the RAG pipeline resilient to LLM-side failures by adding explicit fallback paths: MQE failure falls back to original query; rerank failure falls back to RRF-ranked results.

## Scope

**In-Scope:**
- Add MQE failure fallback: when expand_queries() raises, set ctx.queries = [ctx.query]

**Out-of-Scope:**
- Changes to SQLite schema
- Changes to embedding service
- Changes to RRF fusion logic
- Changes to augment formatting

## Assumptions

1. MQE fallback uses the original query unchanged — no attempt to retry or modify the query.
2. Rerank fallback applies deduplicate_chunks() + rag_top_k slicing to ctx.merged (same as _rerank_fallback()).
3. Fallback reasons are recorded as distinct strings: "mqe_exception" and "rerank_exception".
4. Both fallbacks should be logged at INFO level for observability.
5. The fallback behavior should apply only on LLM exceptions, not on configuration errors.

## Design decisions

- **Exception-specific fallback**: Catch LLM exceptions specifically, not all exceptions. This prevents masking configuration errors or other bugs.
- **Original query fallback**: Use the original query unchanged rather than attempting to retry or modify it.
- **INFO-level logging**: Log fallback events at INFO level for observability without alarming operators unnecessarily.

## Alternatives considered

- **Catch all exceptions**: Could catch all exceptions during MQE. Rejected because it would mask configuration errors and other bugs that should surface.
- **Retry before fallback**: Could retry the LLM call before falling back. Rejected because the requirement specifies immediate fallback without retry.
- **WARN-level logging**: Could log fallback events at WARN level. Rejected because INFO is more appropriate for expected degradation scenarios.

## Implementation

### Target file

`scripts/rag/stages/mqe.py`

### Procedure

#### Phase 1: Add MQE failure fallback

1. Modify `MqeStage.run()` to catch LLM exceptions during `_run_mqe()`:
   ```python
   async def run(self, ctx: RagContext) -> StageResult:
       try:
           result = await self._run_mqe(ctx)
           return result
       except LLMException:
           # MQE failed — fall back to original query
           ctx.queries = [ctx.query]
           logger.info("MQE failed, using original query as fallback")
           return StageResult(
               status="fallback",
               reason="mqe_exception",
               queries=[ctx.query],
           )
   ```

### Method

- Wrap `_run_mqe()` call in try/except to catch LLM exceptions
- On exception, set `ctx.queries = [ctx.query]` and return a fallback StageResult

### Details

1. `MqeStage.run()` update:
