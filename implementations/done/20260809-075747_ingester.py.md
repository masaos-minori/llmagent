# Implementation Procedure: Phase 1 — DTO and Enum Definition

## Goal

Introduce `PreparedChunk` frozen dataclass DTO, `IngestionFailureReason` enum, and extend `IngestUrlResult` with `failure_reason` field to replace the `(chunk_ok, embed_ok)` tuple semantics used in `_embed_and_store()`.

## Scope

### In-Scope
- Define `PreparedChunk` frozen dataclass in `scripts/rag/ingestion/ingester.py` with fields: `doc_id` (int), `chunk_index` (int), `content` (str), `normalized_content` (str | None), `embedding_blob` (bytes — result of `floats_to_blob()`), `chunk_type` (str), `source_file` (str)
- Define `IngestionFailureReason` Enum in `scripts/rag/ingestion/ingester.py` with values: `PARSE_FAILED`, `VALIDATION_FAILED`, `EMBEDDING_FAILED`, `STORAGE_FAILED`
- Extend `IngestUrlResult` with `failure_reason: IngestionFailureReason | None = None` field

### Out-of-Scope
- Any changes to `_embed_and_store()` logic
- Any changes to callers of `IngestUrlResult`
- Database schema changes
- Transaction boundary changes
- Changes to `document_manager.py` beyond removing `delete_existing_document()` delegation

## Assumptions

1. `PreparedChunk` fields match exactly what `_insert_chunk()` expects as positional parameters (confirmed: `doc_id`, `chunk_index`, `content`, `normalized_content`, `embedding_blob`, `chunk_type`, `source_file`)
2. `floats_to_blob()` from `rag.utils` produces deterministic float32 BLOB output (confirmed by existing usage)
3. `IngestUrlResult` can be extended with `failure_reason` field without breaking callers (confirmed: downstream consumers inspect `n_success`, `n_failed`, `n_embed_failed`, `skipped`; `failure_reason` is additive)
4. `PreparedChunk` does not need pickle serialization support (no evidence of pickle/dill usage in ingestion pipeline)
5. `SQLiteHelper.begin_immediate()` context manager properly handles nested transaction boundaries (RESOLVED: No nested transactions found in current codebase)
6. sqlite-vec extension works with single connection approach (RESOLVED: Confirmed — `_load_vec_extension()` in `helper.py:145-158` loads vec extension once per connection)
7. `IngestUrlResult.n_embed_failed` field IS actively used by downstream aggregators — 5 usages in `ingester.py` (lines 48, 121, 129, 219, 523) and 5 assertions in `tests/rag/ingestion/test_ingester.py` (lines 667, 775, 818, 853, 883). Must preserve and repurpose.

## Design decisions

- `PreparedChunk` is a frozen dataclass because it represents immutable intermediate state between embedding workers and the atomic transaction commit. No mutation after creation.
- `IngestionFailureReason` is an Enum (not a string literal) for type safety and IDE autocomplete. Values map directly to failure modes: `PARSE_FAILED`, `VALIDATION_FAILED`, `EMBEDDING_FAILED`, `STORAGE_FAILED`.
- `IngestUrlResult.failure_reason` uses `IngestionFailureReason | None` because success cases have no failure reason.
- `PreparedChunk.embedding_blob` type is `bytes` (result of `floats_to_blob()`), not `list[float]`, since the blob format is required for SQLite INSERT.
- `n_embed_failed` semantics change from "individual chunk embedding failure count" to "URL-group-level embedding failure indicator" (all-or-nothing due to atomicity).

## Alternatives considered

- Using `TypedDict` instead of frozen dataclass for `PreparedChunk`: rejected because dataclass provides `__repr__`, `__eq__`, and IDE support out of the box.
- Using string constants instead of Enum for failure reasons: rejected because Enum provides type safety and prevents typos.
- Adding `failure_reason` to `IngestUrlResult` as a string instead of `IngestionFailureReason`: rejected because Enum preserves type information through the pipeline.

```python
class IngestionFailureReason(StrEnum):
    """Reason why a chunk ingestion failed."""
    PARSE_FAILED = "parse_failed"
    VALIDATION_FAILED = "validation_failed"
    EMBEDDING_FAILED = "embedding_failed"
    STORAGE_FAILED = "storage_failed"
```

Use `StrEnum` (Python 3.11+) for string comparison compatibility while preserving enum semantics.

#### Step 3: Define `PreparedChunk` frozen dataclass

Place after `IngestionFailureReason`:
```python
@dataclass(frozen=True)
class PreparedChunk:
    """Immutable DTO representing a prepared chunk ready for atomic insertion."""
    doc_id: int
    chunk_index: int
    content: str
    normalized_content: str | None
    embedding_blob: bytes  # Result of floats_to_blob()
    chunk_type: str
    source_file: str
```

Key points:
- `frozen=True` ensures immutability after embedding worker produces it
- `embedding_blob` is `bytes` — must be result of `floats_to_blob()` call before storage
- `normalized_content` is `str | None` — matches `_insert_chunk()` signature
