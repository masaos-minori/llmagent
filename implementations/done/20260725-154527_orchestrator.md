## Goal

Add user notification when background task failures reach the threshold. Provide options to pause agent operation for critical background tasks. Ensure error notifications always reach the user regardless of callback behavior.

## Scope

- Display warning message to user when BG_FAILURE_THRESHOLD is reached
- Add configurable option to pause agent operation on critical background task failures
- Improve error notification propagation to ensure user always receives notification
- Include specific background task name in failure logs

## Assumptions

- User notification should use existing notification mechanism (if available) or fall back to logging
- Agent pause should be opt-in via configuration flag
- Background task name should be extracted from task metadata or passed explicitly
- Notification delay should be minimal (< 1 second) to ensure timely user awareness

## Design decisions

- **Threshold-based notification**: Notify user only when failure count reaches configurable threshold (default: 5). Prevents notification spam for transient failures.
- **Opt-in agent pause**: Pause functionality is disabled by default (`pause_on_critical_bg_failure=False`). Requires explicit configuration to enable.
- **Fallback notification chain**: Try notification mechanism first (WebSocket, HTTP callback), then fall back to logging. Ensures user always sees the notification.
- **Task-specific failure tracking**: Track failures per background task name rather than globally. Allows distinguishing between isolated failures and systemic issues.

## Alternatives considered

- **Immediate notification on any failure**: Would overwhelm users with notifications. Threshold-based approach balances alerting with noise reduction.
- **Mandatory agent pause on threshold**: Too aggressive; some deployments may prefer monitoring without automatic intervention. Opt-in approach more flexible.
- **Global failure counter instead of per-task**: Would conflate unrelated failures. Per-task tracking provides actionable insights.
- **Async notification delivery**: Could delay notification but allows non-blocking operation. Minimal delay (< 1s) acceptable for synchronous delivery.

   async def _discard_and_log(self, exc: Exception, task_name: Optional[str] = None):
       """Discard failed task and log with enhanced context."""
       # Get task name from task metadata or use provided name
       if task_name is None:
           task_name = getattr(exc, 'task_name', 'unknown')
       
       # Increment failure counter for this task
       self._bg_failure_counts[task_name] = self._bg_failure_counts.get(task_name, 0) + 1
       count = self._bg_failure_counts[task_name]
       
       # Log failure with task name and count
       logger.warning(f"Background task '{task_name}' failure #{count}: {exc}")
       
       # Check if threshold reached
       bg_threshold = getattr(self.config, 'BG_FAILURE_THRESHOLD', 5)
       if count >= bg_threshold:
           await self._notify_user_of_critical_failure(task_name, count)
   
   async def _notify_user_of_critical_failure(self, task_name: str, count: int):
       """Notify user of critical background task failure threshold."""
       message = (
           f"CRITICAL: Background task '{task_name}' has failed {count} times consecutively. "
           f"This exceeds the threshold of {self.config.BG_FAILURE_THRESHOLD}. "
           f"The task will be discarded."
       )
       
       # Try notification mechanism first
       notification_sent = False
       if hasattr(self, '_on_notification'):
           try:
               await self._on_notification(message)
               notification_sent = True
           except Exception as e:
               logger.error(f"Notification callback failed: {e}")
       
       # Fallback to logging if notification failed
       if not notification_sent:
           logger.critical(message)
       
       # Optionally pause agent operation
       if getattr(self.config, 'pause_on_critical_bg_failure', False):
           await self._pause_agent_for_critical_failure(task_name, count)
   
   async def _pause_agent_for_critical_failure(self, task_name: str, count: int):
       """Pause agent operation due to critical background task failure."""
       self.agent_paused = True
       self.pause_reason = f"Critical background task '{task_name}' failed {count} times"
       logger.warning(f"Agent paused: {self.pause_reason}")
       
       # Notify user about pause
       pause_message = (
           f"AGENT PAUSED: {self.pause_reason}. "
           f"Use '/resume' command to resume operations."
       )
       
       if hasattr(self, '_on_notification'):
           try:
               await self._on_notification(pause_message)
           except Exception:
               logger.critical(pause_message)
   ```

       """Wrap _on_error callback with fallback notification."""
       try:

           # Ensure user sees the notification
           if hasattr(self, '_on_notification'):

                   await self._on_notification(fallback_message)
               except Exception:
                   pass  # Last resort: just log
   ```

## Compatibility considerations

- **Notification mechanism dependency**: Deployments without notification callbacks will see only log messages. May reduce visibility compared to other deployment configurations.
- **Agent pause opt-in**: Existing deployments won't experience unexpected pauses since feature is disabled by default.
- **Per-task failure counting**: New data structure (_bg_failure_counts) requires initialization during session startup.

## Security considerations

- **Information disclosure**: Error messages sent to users should not expose internal system details beyond what's necessary for troubleshooting.
- **Denial of service**: Agent pause could be triggered by attacker-induced background task failures. Consider rate limiting pause triggers.
- **Callback injection**: If _on_error callback can be set by untrusted parties, it could execute arbitrary code. Validate callback sources.

## Rollback considerations

- **Quick rollback**: Remove notification logic and revert to original _discard_and_log behavior
- **Data impact**: No database changes; rollback does not affect persisted state
- **Configurable mode**: Consider adding environment variable to toggle notification/pause features without code changes
