## Goal
Register the orchestrator's store close with the REPL's shutdown coordinator after startup, so the workflow state store is closed exactly once through `close_resources` on every exit path (`REQ-003`).

## Scope
**Release unit**: wfaudit006-full

- Covers Plan `plans/20261108-084008_wfaudit006_state-store-lifecycle-ownership.md` row 4: `scripts/agent/repl.py`.

## Assumptions
- The REPL is the only orchestrator host: `Orchestrator(` is constructed only at `startup_component_init.py` L121, reached only via `repl.py` (plan `UNK-01`, resolved 2026-11-08); no other hosting path needs registration.
- `register_close_hook` (new) exists by the time this procedure runs — it is added by sibling procedure `20261108-155554_03` (earlier row 3); this procedure is invalid without it.
- `self._orchestrator.close` (new method, sibling procedure `20261108-155554_02`) is a synchronous zero-argument callable matching the hook contract.
- Line numbers refer to HEAD `ad48bfa28`; no sibling procedure edits `repl.py`.

## Design decisions
- Registration happens in `run()` immediately after `await startup.run()` returns the orchestrator and before `self._input_loop.bind(...)`: the coordinator is built in `__init__` (L88) before the orchestrator exists and cannot reach it through `AgentContext`, so post-startup registration in `run()` is the only point where both objects exist (plan Notes 2026-11-08).
- Registering before `bind` means every exit path that reaches the finally block — normal exit, input-loop crash, or a post-startup exception — already carries the hook; a startup failure never assigns `self._orchestrator`, so nothing is registered and nothing is closed (the store never existed).
- The hook name is the literal label "workflow_store" so shutdown error summaries identify the failing resource by role, not by object.

## Alternatives considered
- Closing the store directly in `repl.py`'s finally before `close_resources`: rejected — it would bypass the coordinator's ordering (sibling procedure 03 runs hooks last, after services stop writing state).
- Passing the orchestrator into `ResourceShutdownCoordinator.__init__` after startup by rebuilding the coordinator: rejected — the existing coordinator instance already holds task/service references; replacing it mid-session would orphan them.

### Procedure

### Method

- The finally block at L150-152 already calls `await self._shutdown.close_resources()`; the hook execution itself is procedure 03's terminal step, so `repl.py` gains only the one registration line.

## Compatibility considerations
- `AgentREPL.__init__`, the startup failure/interrupt handlers, and the finally block are unchanged; sessions that never reach the registration line behave exactly as today.
- Existing `tests/agent/test_repl.py` harness `_make_bare_repl` (hand-built instance, real `ResourceShutdownCoordinator`) keeps working: it never calls `run()`, so no hook is registered there.

## Security considerations
- Shutdown must stay complete even if the store close fails: failures are recorded by the coordinator's record-and-continue policy (procedure 03), never raised into the REPL finally.

## Rollback considerations
- Revert the commit: the single registration line disappears; the coordinator API (procedure 03) can remain harmlessly unused. No persisted state.
