## Goal

Resolve the undocumented asymmetry in `audit_security_defaults()` (`scripts/agent/repl_health.py`) where the firejail-binary-missing check unconditionally raises `RuntimeError` regardless of `production_mode`, unlike every other check in the same function (which only raises when `production_mode=True` and otherwise logs a warning). Make the intent self-evident to future readers/maintainers.

## Scope

**In-Scope:**
- `scripts/agent/repl_health.py` lines 516-521 — the `shell_cfg.sandbox_backend == "firejail" and not _shutil.which("firejail")` check inside `audit_security_defaults()`.
- Adding a one-to-two line explanatory code comment directly above the check (Option A, per analysis below).

**Out-of-Scope:**
- Any other check in `audit_security_defaults()` (auth_token, `sandbox_backend == "none"`, non-firejail backend warning, `command_allowlist`, cicd/github checks) — these remain unchanged.
- `scripts/mcp/shell/service_static_helpers.py` / `init_sandbox()` — a related but separate firejail-availability check in a different module; not part of this requirement's target files.
- Test changes — Option A is comment-only, so no new test is required (per the requirement's own Tests section).
- Any change to `config/shell_mcp_server.toml` or documentation files.

## Assumptions

1. Git history and the existing test suite constitute a stronger signal that the unconditional raise is deliberate, so Option A is selected.
2. `tests/test_repl_health.py::test_firejail_binary_missing_raises` (lines 494-504) already asserts `RuntimeError` is raised with `production_mode=False`, and this test is treated as an intentional, currently-passing specification of behavior — not something to change under this requirement.
3. No other module (docs, config) documents the rationale for this asymmetry, so a code comment is the only artifact needed to close the gap.

## Design decisions

- Implement Option A (document intent, no behavior change) based on:
  1. Commit `3fa720e5` introduced both the unconditional-raise check AND the warning-only sibling check in the same diff, distinguishing them deliberately.
  2. Prior design plan (`plans/done/20260623-091312_plan.md`) explicitly states a firejail-configured-but-binary-missing state is a "design bug" that must hard-error independent of `production_mode`.
  3. Existing test `test_firejail_binary_missing_raises` locks in the `production_mode=False` raising behavior.

## Alternatives considered

- Option B (align with `production_mode` gating): Rejected — git history and existing test indicate the unconditional raise is deliberate, not an oversight.
