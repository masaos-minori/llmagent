# Implementation Procedure: conf.d/github-mcp

## Goal
- Remove the stale `--reload-mcp` reload instruction from `conf.d/github-mcp` and replace it
  with an accurate way to apply `GITHUB_TOKEN` changes (restart the agent process).

## Scope
- In scope: the comment block in `conf.d/github-mcp` that describes how to apply a config
  change after editing `GITHUB_TOKEN`.
- Out of scope: adding an automated config-reload mechanism; changing the `GITHUB_TOKEN=""`
  value line itself; any other `conf.d/*` file (tracked separately per file).

## Assumptions
- The operator edits `conf.d/github-mcp` manually and is expected to restart the agent
  process to pick up the new value; no hot-reload path exists (per source issue
  `issues/20260802-080732_deploy_github_token_setup_procedure_confirmation.md` referenced by
  the source plan).
- Spot check of the current file (`grep -n "reload-mcp\|再起動" conf.d/github-mcp`) shows the
  file already contains the line `設定を反映するには、エージェントプロセスを再起動してください。`
  and no `--reload-mcp` / `agent.py` reference. If this remains true at implementation time,
  this procedure is a verification-only no-op; re-check before editing in case the file was
  reverted.

## Design decisions
- Keep the fix as a plain-text comment edit (no scripting) — the file is a small,
  human-edited `conf.d` env file, not a Python module, so no code-design machinery applies.
- Preserve the existing Japanese comment style and structure of the file; only replace the
  one inaccurate instruction line.

## Alternatives considered
- Add an automated `--reload-mcp` CLI flag to `scripts/agent.py` instead of fixing the doc/
  comment: rejected — out of scope per the source plan (Out-of-Scope: "Implementing a new
  automated loading mechanism for `conf.d/*` files").
- Remove the "apply changes" line entirely: rejected — operators need explicit guidance on
  how to apply the change; silence would reintroduce the ambiguity the source issue raised.

## Implementation
### Target file
- `conf.d/github-mcp`

### Procedure
1. Re-run `grep -n "reload-mcp\|再起動" conf.d/github-mcp` to confirm current state before editing.
2. If a `--reload-mcp` / `agent.py --reload-mcp` line is present, replace it with:
   `設定を反映するには、エージェントプロセスを再起動してください。`
3. If the corrected line is already present (as observed at procedure-authoring time), make
   no edit and record the verification result instead.
4. Diff the file (`git diff conf.d/github-mcp`) to confirm only the comment line changed, if
   any change was made.

### Method
- Plain text edit via the standard editor tool (no code generation, no build step); this is a
  `conf.d` comment file, not Python source, so none of `rules/toolchain.md`'s
  lint/type/test/security steps apply.

### Details
- Current file (14 lines) already contains, at line 12:
  `# 設定を反映するには、エージェントプロセスを再起動してください。`
  and no `GITHUB_TOKEN` reload-script reference anywhere (verified via
  `grep -n "reload-mcp\|GITHUB_TOKEN\|agent.py" conf.d/github-mcp`).
- If a future regression reintroduces the old `--reload-mcp` wording, replace it in place,
  keeping the surrounding `[トークンの取得方法]` block and blank line before `GITHUB_TOKEN=""`
  unchanged.
