# Implementation Procedure: Policy rejection, postcondition message, config injection, marker cleanup

## Goal

Four changes to `scripts/mcp_servers/git/format_output.py`:
1. Raise `GitPolicyError` in `_authorize_remote()` (remote not allowed) and `format_commit()` (nothing staged) — REQ-005.
2. Enrich the checkout postcondition failure message with resulting state — REQ-006.
3. Pass-through `_cfg` and drop `GitConfig.load()` fallback in `format_pull()`/`format_push()` — REQ-007.
4. Remove the stdout push-rejection marker check — REQ-008.

## Scope

- Modify `scripts/mcp_servers/git/format_output.py`:
  - Line 173: raise `GitPolicyError` instead of `GitServiceError` in `_authorize_remote()`.
  - Line 120: raise `GitPolicyError` instead of `GitServiceError` in `format_commit()`.
  - Lines 158-161: enrich checkout postcondition message with resulting state.
  - Lines 182, 206: drop `cfg or GitConfig.load()` fallback; make `cfg` required.
  - Lines 211-216: remove stdout push-rejection marker check.
- Import `GitPolicyError` from `mcp_servers.git.errors`.

## Assumptions

- `GitPolicyError` is defined in `scripts/mcp_servers/git/errors.py` (covered in its own document).
- `GitService._pull_op`/`_push_op` pass `self._config` to the format functions (covered in its own document).
- The checkout postcondition failure remains an execution failure (HTTP 500) — only the message is enriched.

## Design decisions

- **Policy rejection (REQ-005)**: Replace `raise GitServiceError(...)` with `raise GitPolicyError(...)` in `_authorize_remote()` and `format_commit()`.
- **Postcondition message (REQ-006)**: Change the message from `"checkout postcondition failed: expected branch {req.branch!r}, got {state}"` to include "state already changed" wording and the resulting state.
- **Config injection (REQ-007)**: Change `cfg or GitConfig.load()` to require `cfg`; callers must pass the startup config.
- **Marker removal (REQ-008)**: Remove the `_rejection_markers` tuple and the `any(m in result for m in _rejection_markers)` check; rely on GitPython raising `git.exc.GitError` on non-zero exit.

## Alternatives considered

- Making `cfg` optional with a warning: rejected because ADR-002 requires config loaded once at startup; no runtime divergence is acceptable.
- Keeping the stdout marker check as a fallback: rejected because git reports push results on stderr, not stdout; the check is ineffective.
