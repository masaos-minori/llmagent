## Design decisions

- Remove the "Cache Behavior" section heading and all five bullets — no cache
  exists to describe.
- Rewrite the `is_side_effect()` purpose sentence to state its actual current use
  (referenced from `agent/tool_scheduler.py` for serial-execution batching, per
  Assumptions) rather than the now-false "TTL cache bypass" claim — do not simply
  delete the sentence, since `is_side_effect()` itself is still a live, documented
  symbol in this file's code block.
- Rewrite the `ToolResultCache`/stampede-protection bullet (line 115) to state that
  `ToolExecutor` no longer has any internal cache at all — `ToolResultCache`
  remains a standalone, unused utility as before, but the comparison point ("used
  instead of ToolResultCache because tightly coupled with stampede protection") no
  longer applies since neither exists in `ToolExecutor`.

  exists) was considered and rejected — the sentence specifically claims a
  now-false runtime behavior ("used ... for bypassing the TTL cache"), which is a
  factual inaccuracy independent of whether the function itself still exists.
