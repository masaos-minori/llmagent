# Implementation Procedure: `scripts/shared/route_resolver.py`

## Goal
Give `build_discovery_map`'s `server_tool_lists` parameter a `TypedDict`-based element type
instead of `dict[str, list[dict[str, Any]]]`, closing the raw `dict[str, Any]` type-safety gap
called out in `skills/DESIGN.md`, with zero runtime behavior change.

## Scope
In scope:
- Add a `TypedDict` (`ToolDescriptor`) describing one tool-descriptor entry, with fields `name`
  and `server_key`, both optional via `total=False`.
- Retype `build_discovery_map`'s `server_tool_lists` parameter from
  `dict[str, list[dict[str, Any]]]` to `dict[str, list[ToolDescriptor]]`.
- Remove the now-unused `Any` from the `typing` import on line 18; add `TypedDict` to that same
  import line.

Out of scope (per plan):
- Any change to `build_discovery_map`'s function body, control flow, logging, or return shape.
- Any change to `ToolRouteResolver` (its `discovery_map: dict[str, str] | None` parameter
  consumes this function's *return value*, not its input, so it is unaffected).
- Any change to `scripts/shared/tool_executor.py` (verified: it does not call
  `build_discovery_map`).

## Assumptions
- `ToolDescriptor` is defined locally in this file (not in `scripts/shared/types.py`), since it
  has exactly one production consumer (`build_discovery_map` itself) and mypy structurally checks
  dict literals at test call boundaries without requiring the test files to import the type.
- `total=False` is correct for the whole `TypedDict` because both `name` and `server_key` are
  absent-or-present across existing call-site literals (confirmed by the plan's repo-wide `rg`
  search: exactly 3 callers, all in test files, using only `name` and optionally `server_key`).

## Design decisions
- Place `ToolDescriptor` directly above `build_discovery_map` (not above `ToolRouteResolver`) to
  keep the type adjacent to its sole consumer.
- Keep the field set minimal (`name`, `server_key`) — do not add fields absent from all observed
  call sites, per the plan's explicit instruction not to invent fixture values.

## Alternatives considered
N/A — the plan already resolved the placement/field-set questions (see Assumptions); no
competing design was left open.

## Implementation

### Target file

### Procedure
1. Read lines 1-56 (module header, imports, `build_discovery_map`) — already done; current state
   confirmed:
   - Line 18: `from typing import TYPE_CHECKING, Any, NoReturn`
   - Line 28: `server_tool_lists: dict[str, list[dict[str, Any]]],`
   - Function body (lines 36-56) uses `tool.get("name")` and
     `if not isinstance(name, str) or not name: continue` — must remain byte-for-byte identical.
2. Edit the import line (18) to drop `Any` and add `TypedDict`:
   `from typing import TYPE_CHECKING, NoReturn, TypedDict`
3. Insert the new `TypedDict` immediately above `def build_discovery_map(` (currently line 27):
   ```python
   class ToolDescriptor(TypedDict, total=False):
       """One tool-descriptor entry from a server's /v1/tools discovery payload."""

       name: str
       server_key: str  # present in some fixtures; ignored by build_discovery_map (outer dict key is authoritative)
   ```
4. Change the parameter annotation on line 28 from
   `server_tool_lists: dict[str, list[dict[str, Any]]],` to
   `server_tool_lists: dict[str, list[ToolDescriptor]],`.
5. Leave everything else in the file untouched — function body, `ToolRouteResolver` class, module
   docstring.

### Method
Direct, minimal in-place edit of a single function signature and its adjacent imports. No
refactor tooling required.

### Details grounded in real code
Current signature (verified by reading the file):
```python
def build_discovery_map(
    server_tool_lists: dict[str, list[dict[str, Any]]],
) -> tuple[dict[str, str], dict[str, list[str]]]:
```
becomes:
```python
def build_discovery_map(
    server_tool_lists: dict[str, list[ToolDescriptor]],

```
The body's `tool.get("name")` continues to type-check against `ToolDescriptor` because
`total=False` makes every key optional-to-read.

## Compatibility considerations

  `TypedDict` has no runtime representation (it erases to `dict` at runtime).
- Callers passing plain `dict[str, Any]`-shaped data at runtime continue to work unchanged; only
  mypy/pyright's static view changes.
