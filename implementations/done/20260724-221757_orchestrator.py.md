## Goal

Make `_on_llm_wait_end` invocation consistent across both LLMTransportError error paths.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._handle_llm_turn())
**Out**: LLMTurnRunner behavior changes, other callback invocations

## Assumptions

1. `_on_llm_wait_end` is a valid callback reference that may be None
2. `LLMTurnRunner.run()` either returns a result with `exception` set OR raises `LLMTransportError`, never both
3. Callback order matters: `_on_llm_wait_end` must fire before `_on_error`

## Design decisions

- Move `_on_llm_wait_end` from unconditional pre-check into each branch of the `if result.exception is not None:` conditional — ensures explicit, predictable callback ordering in both paths
- Preserve existing callback order: `_on_llm_wait_end` → `_on_error` in error path; `_on_llm_wait_end` → `_on_turn_end` in success path

## Alternatives considered

- Leave `_on_llm_wait_end` as unconditional call before the exception check: does not resolve the ordering inconsistency between the two error paths
- Add a boolean flag to track whether `_on_llm_wait_end` was already called: adds state complexity for marginal benefit

## Implementation

### Target file

`scripts/agent/orchestrator.py`

### Procedure

1. Identify the `if result.exception is not None:` branch where `_on_llm_wait_end` is currently missing.
2. Add `if self._on_llm_wait_end: self._on_llm_wait_end()` before calling `_on_error` in that branch.
3. Ensure the call order matches the raise path: `_on_llm_wait_end` → `_on_error` → return.
4. Verify no double-invocation occurs if `LLMTurnRunner.run()` both sets `result.exception` and raises (which would be a bug in `LLMTurnRunner`).

#### Step A: Modify `Orchestrator._handle_llm_turn()` — add `_on_llm_wait_end` in result.exception path

Current code (lines 424-432):

```python

                handle_llm_transport_error(
                    result.exception, ctx, self._diagnostic_store

                    self._on_error(result.exception)
```

Change to:

```python
            if result.exception is not None:
                # run() caught LLMTransportError internally; propagate callbacks
                if self._on_llm_wait_end:
                    self._on_llm_wait_end()
                handle_llm_transport_error(
                    result.exception, ctx, self._diagnostic_store
                )
                if self._on_error:
                    self._on_error(result.exception)
            else:
                if self._on_llm_wait_end:
                    self._on_llm_wait_end()
                if self._on_turn_end:
                    self._on_turn_end()
```

Key points:
- Remove the unconditional `_on_llm_wait_end` call at line 424-425
- Add `_on_llm_wait_end` explicitly in both branches of the if/else
- In the error branch, `_on_llm_wait_end` fires BEFORE `handle_llm_transport_error` and `_on_error` — matching the except path order
- In the success branch, `_on_llm_wait_end` fires BEFORE `_on_turn_end` — preserving existing semantics
