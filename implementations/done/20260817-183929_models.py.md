## Goal

Introduce typed schemas (TypedDict) for MCP `TOOL_LIST` definitions across `scripts/mcp_servers/**/*_tools.py` to replace `dict[str, Any]` with static shape-checking.

## Scope

- **In-Scope**:
  - Phase 1: Enumerate all `*_tools.py` modules with `TOOL_LIST` entries and derive the actual field set from real usage
  - Phase 2: Define `McpToolProperty`, `McpInputSchema`, and `McpTool` TypedDicts in a shared location
  - Phase 3: Apply the new types to all `*_tools.py` modules and verify type-checking passes
- **Out-of-Scope**:
  - Runtime behavior changes (TypedDict is erased at runtime)
  - Adding new tools or modifying existing tool schemas
  - Changes outside `scripts/mcp_servers/`

## Assumptions

- All `*_tools.py` modules follow the same `TOOL_LIST` pattern (confirmed by `git_tools.py`'s Proposals note mentioning ~13+ modules sharing the same pattern)
- The TypedDict definitions will be placed in `scripts/mcp_servers/models.py` or a new `scripts/mcp_servers/tool_schema_types.py`
- `Required`/`NotRequired` annotations can be used to distinguish fields present in all vs. some `TOOL_LIST` entries

## Design decisions

- Use `Required`/`NotRequired` to distinguish fields present in all vs. some `TOOL_LIST` entries
- Place TypedDict definitions in `models.py` if it already exists and is the natural home for shared types; otherwise create `tool_schema_types.py`
- Derive the exact field set empirically from actual TOOL_LIST entries rather than guessing

## Alternatives considered

- Add TypedDict to each `*_tools.py` individually — rejected because it duplicates definitions across modules
- Use `Protocol` instead of TypedDict — rejected because TypedDict better matches the data-class nature of TOOL_LIST entries
- Keep `dict[str, Any]` — rejected because the goal is static shape-checking

## Compatibility considerations

- TypedDict is erased at runtime — no behavioral change
- Requires Python 3.13+ (already enforced by pyproject.toml `target-version = "py313"`)
- mypy and pyright must both pass after changes

## Security considerations

- N/A — type-only change with no runtime impact

## Rollback considerations

- Revert the diff; no data loss or service impact
