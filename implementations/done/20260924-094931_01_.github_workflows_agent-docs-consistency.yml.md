## Assumptions

- Both `on.push.paths` and `on.pull_request.paths` currently list the
  identical two `docs/`-prefixed entries verbatim — confirmed via Read

  line 35) uses a `--domain` flag, not a hardcoded glob — confirmed via Read
  — so it needs no change here; `tools/check_docs_consistency.py`'s
  `--domain agent` dispatch was already made subfolder-aware by the
  companion Plan `plans/done/20260923-152824_plan.md` (docsreorg02, REQ-003).
- No `tests/` file covers GitHub Actions workflow YAML — confirmed via
  `rg -l "docs-consistency\|docs-quality" tests/` returning no match — so no
  test file needs updating for this row.

## Design decisions

- Literal string replacement of the two `paths:` entries, keeping their
  existing filename-prefix specificity rather than widening to a bare
  `"docs/23_agent/**"` / `"docs/41_db/**"` recursive pattern — per the Plan's
  Design section, `docs/41_db/` will (per `docsreorg10`) hold only the
  `90_shared_04_*` prefix group, not every `90_shared_*` file, so a bare
  recursive pattern would over-trigger this workflow once other
  `90_shared_*` files land elsewhere.

## Alternatives considered

- Widening both entries to recursive subfolder globs (`"docs/23_agent/**"`,
  `"docs/41_db/**"`): rejected per Design decisions above — `docs/41_db/`
  is not exclusively `90_shared_04_*` content once other DB-adjacent docs
  reorg issues land, so this would silently broaden this workflow's trigger
  scope beyond its intended domain.
