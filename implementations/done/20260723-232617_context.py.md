## Goal

Add `memory_disabled` and `memory_warning_shown` flags to `ConversationState` to persist memory injection failure state across sessions.

## Scope

**In-Scope**:
- Add `memory_disabled: bool = False` to `ConversationState`
- Add `memory_warning_shown: bool = False` to `ConversationState`

**Out-of-Scope**:
- Setting the flags (covered in separate startup.py document)
- Displaying warnings (covered in separate repl.py document)
- Modifying memory injection logic itself

## Assumptions

1. The dataclass pattern used in `ConversationState` supports adding new boolean fields without breaking existing code.
2. Both flags are independent — `memory_disabled` indicates the condition, `memory_warning_shown` tracks whether the warning was already displayed.

## Design decisions

- **Two separate flags instead of one**: Using two flags (`memory_disabled` + `memory_warning_shown`) allows the warning to be displayed exactly once rather than every turn. A single flag would require additional tracking logic.
- **Default values of `False`**: Both flags default to `False` — memory is enabled by default, and no warning has been shown yet. No special initialization needed.
- **No type annotation changes elsewhere**: Adding fields to an existing dataclass doesn't break backward compatibility — callers that don't reference these fields won't notice.

## Alternatives considered

- **Single flag `memory_disabled` with warning always displayed**: Simpler but would spam the user with warnings on every turn. Chose two-flag approach for better UX.
- **Store timestamp of last warning instead of boolean**: Would allow re-displaying the warning after some time. Rejected because the requirement specifies "one-time" display per session.
- **Use string flag like `memory_status: str = "enabled"`**: More extensible but overkill for a binary state. Chose booleans for simplicity.
