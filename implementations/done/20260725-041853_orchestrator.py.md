## Goal

Surface first-turn background task exceptions to the user immediately, regardless of whether subsequent tasks also fail.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._append_user_message(), _discard_and_log())
**Out**: Changes to first-turn behavior, other background task handling

## Assumptions

1. `self._on_error` callback is available in `_discard_and_log` — it's set during Orchestrator initialization
2. Calling `_on_error` from a synchronous callback (`_discard_and_log`) is safe — no async context needed
3. Session should continue operating after first-turn failure — degrade gracefully rather than crash

## Design decisions

- Call `self._on_error(exc)` in `_discard_and_log` at first failure — reuses existing error notification mechanism; no new methods or flags needed
- Place the call before the log warning — ensures user sees the error message immediately

## Alternatives considered

- **Add a dedicated first-failure callback**: Would require changing the Orchestrator API surface and adding new configuration; over-engineered for this specific fix
- **Raise an exception instead of calling _on_error**: Would break session continuity; contradicts the graceful degradation intent
- **Use a separate notification channel (e.g., WebSocket push)**: Adds infrastructure complexity; unnecessary when _on_error already exists

        exc = task.exception()

Key points:
- Added `if self._on_error: self._on_error(exc)` at the first-failure branch
- Call happens before logging — user sees the error message immediately
- Idempotent by design — only fires once because `_consecutive_bg_failures` increments past 1
- Reuses existing `_on_error` callback — no new methods or flags needed

### Method

Extract ownership of error notification into the caller (`_discard_and_log`). Use the existing `_on_error` callback to surface first-turn failures to the user without introducing new abstractions.

### Details

The core issue is that first-turn background task exceptions are silently logged but never surfaced to the user. The `_discard_and_log` method currently only calls `logger.warning()` for the first failure, which is insufficient for user-facing visibility.

By adding `self._on_error(exc)` at the first-failure branch, we achieve:
- Immediate user notification via the existing error callback mechanism
- Consistent error handling — same callback used for all error paths in the orchestrator
- No additional state or configuration needed — leverages existing infrastructure
