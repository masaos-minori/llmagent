## Scope
- Add one new `## Notes on Path A collapse` section after the existing `## Notes on filling "Affected areas"` section (end of file). The fenced skeleton (22 `##` headings, lines 9-160) stays byte-identical.

## Assumptions
- Confirmed 2026-10-24: 22 `##` headings inside the fence; notes sections follow it at lines 162 and 172. `tools/check_workitem_structure.py` (`_extract_template_headings`) and `tools/check_metadata_field_policy.py` (`"plans": "plan.md"`) read headings from the fenced block only, so a notes section does not change required headings.
- The Plan's consumer audit is preliminary; this procedure re-runs it first and records the result. The candidate collapsible set comes from the re-run, not from the Plan's preliminary list, and the note records the exact grep set used.
- Overlap: `templates/plan.md` is targeted by no other Frozen Plan (`tools/check_plan_target_overlaps.py`, 2026-10-24).
- Caveat (non-blocking, Plan UNK-01): whether the single-template body-collapse mechanism is accepted stays owner-revisable.

## Design decisions
- One template, all headings kept; collapse is a body-level rule for Path A only.
- Each collapsible section cites audit evidence ("no consumer found by name"); each must-stay-filled section names its consumer.

## Alternatives considered
- A variant template file or conditional headings were rejected in the Plan Design (checker and generator changes, weaker heading validation).

## Implementation
### Target file
`templates/plan.md`

### Procedure
1. Re-run the audit: for each of the 22 section names, `rg` over `skills/plan-to-implementation-procedure/`, `prompts/02_plan-to-implementation-procedure.md`, `skills/code-implementation/`, `rules/`, and `tools/*.py`; record per section its consumer or "no consumer found".
2. Append `## Notes on Path A collapse` listing (a) collapsible sections, each with its evidence, and (b) must-stay-filled sections with the consumer that reads each. Preliminary must-stay set from the Plan: `Implementation Target Files`, `Reference Files`, `Unknowns`, `Scope` (Dependencies), `Traceability` and `Requirement Traceability`, `Execution Status`, `Risks`, `Requirements`, `Acceptance Criteria`. Preliminary collapse candidates: `Problem`, `Reason for Change`, `Implementation Intent`, `Documentation Impact`, `Affected areas`, `Design`, `Tests`, `Priority`, the Plan's own `Validation plan`.
3. State the collapse condition once: the Issue has no content for the section or its content is carried in a named other section, and the collapsed line keeps any statement the workflow requires of that section (for example the `deploy.sh Impact` value).

### Method
- Use backticks around section names; keep the note under about 30 lines.
- Reference `skills/issue-to-plan/workflow.md` Step 4, Step 5, Step 8a by name only; do not duplicate the rule text.
