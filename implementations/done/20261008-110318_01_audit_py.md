# Implementation Procedure: Add `requested_target`/`canonical_target` to audit schema

## Goal

Add optional `requested_target` and `canonical_target` fields to the shared `_build_audit_record()`, `_audit_log()`, and `AuditRecord` TypedDict so that git-mcp's `_audit_log_safe()` calls at `git_server.py` lines 202, 239, and 267-268 no longer raise `TypeError`. New params default empty; existing consumers (`scripts/eventbus/audit.py`, other MCP servers) are unaffected.

## Scope

- Modify `scripts/mcp_servers/audit.py`: add `requested_target`/`canonical_target` to `AuditRecord`, `_build_audit_record()`, and `_audit_log()`.
- Add additive-schema test in `tests/mcp_servers/git/test_git_service_dispatch.py`.

## Assumptions

- `requested_target` / `canonical_target` carry already-sanitized (redacted) strings from `git_server.py`, so no secret leakage into audit records.
- The eventbus `AuditRecord` consumer (`scripts/eventbus/audit.py`) uses a separate TypedDict definition (not imported from `mcp_servers.audit`), so adding fields to the MCP server's `AuditRecord` does not affect it.
- The eventbus `log_auth_failure` / `log_privileged_action` functions do not pass `requested_target`/`canonical_target` — they will continue working because the new params default to `""`.

## Design decisions

- **Additive change**: new params default to `""` (empty string), preserving backward compatibility with all existing callers.
- **`NotRequired[str]` field**: `canonical_target` is added to `AuditRecord` as `NotRequired[str]`; `requested_target` is passed as a kwarg to `_build_audit_record()` but not stored in the TypedDict (it is captured via `detail` or handled separately).
- **Redaction preserved**: `git_server.py` already sanitizes both values via `_sanitize_for_audit()` before passing them.

## Alternatives considered

- Adding both fields to `AuditRecord` TypedDict: rejected because `requested_target` is already redacted by `_sanitize_for_audit()` and is not part of the canonical record shape — keeping it out of the TypedDict avoids conflating the two concepts.
- Making `canonical_target` required: rejected because path-containment rejections (lines 202, 239) pass an empty string for `canonical_target` since no repo was resolved.

### Details
- `requested_target` carries the raw (redacted) repo path before resolution; it is not stored in the TypedDict because it is already captured via `_sanitize_for_audit()` in `git_server.py`.
- `canonical_target` carries the resolved repo path; it is stored in the TypedDict as `NotRequired[str]` so existing consumers are unaffected.
- The eventbus `AuditRecord` (in `scripts/eventbus/audit.py`) uses a separate TypedDict definition — no cross-import risk.

- `scripts/eventbus/audit.py` defines its own `AuditRecord` TypedDict (mirrors MCP server's style per import-linter contract); adding fields to the MCP server's version does not break it.
- `scripts/eventbus/auth.py` imports `log_auth_failure` from `eventbus.audit`, not `mcp_servers.audit`; no cross-import risk.
- Other MCP servers calling `_audit_log()` without the new params will continue working (params default to `""`).

## Security considerations

- No new secrets exposed: `requested_target` is already redacted by `_sanitize_for_audit()` before being passed.
- `canonical_target` carries the resolved (sanitized) repo path — same level of exposure as the existing `target` field.

## Rollback considerations

- Reverting the change removes the `requested_target`/`canonical_target` params from the audit functions, restoring the `TypeError` behavior. This is acceptable because the rollback is a simple revert of the three function signatures and TypedDict addition.
