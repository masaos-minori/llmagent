## Goal

Ensure signal-induced shutdown is detected immediately by the event loop without relying on the asyncio.Event mechanism that introduces latency through the event loop scheduling cycle.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _sigterm_handler())
**Out**: Changes to asyncio internals, signal handling in other modules

## Assumptions

1. `loop.add_signal_handler()` is available on Unix-like systems and raises NotImplementedError on Windows
2. Cancelling `input_coro` causes `asyncio.wait()` to return immediately via FIRST_COMPLETED
3. Signal handlers must not perform blocking operations

## Design decisions

- Cancel `input_coro` directly from the signal handler instead of setting an Event — eliminates the event loop scheduling delay between signal receipt and shutdown detection
- Store `input_coro` as instance variable accessible from signal handler scope — allows cancellation even when `_read_input` is mid-execution
- Keep existing `shutdown_event` mechanism as fallback — ensures compatibility with any external code that may set the event independently

## Alternatives considered

- Remove `shutdown_event` entirely: breaks backward compatibility with callers that may use the event; also loses the ability to detect non-signal shutdown requests
- Use `os.kill(os.getpid(), signal.SIGTERM)` after setting event: adds complexity for marginal improvement over direct cancellation
- Add a separate `_shutdown_flag` boolean checked in `_read_input`: same latency problem as Event-based approach

Change to:

```python
        def _sigterm_handler() -> None:
            """Handle SIGTERM by cancelling input and setting shutdown flag."""
            self._ctx.conv.shutdown_requested = True
            if self._shutdown_event is not None:
                self._shutdown_event.set()
            # Cancel the current input coroutine to wake up the wait loop immediately
            if self._input_coro is not None and not self._input_coro.done():
                try:
                    self._input_coro.cancel()
                except RuntimeError:
                    pass  # Task already cancelled or not running
            logger.info("SIGTERM received; graceful shutdown initiated")
```

Key points:
- `_shutdown_event.set()` kept as-is for compatibility with external event setters
- Added `_input_coro.cancel()` call with guard checks (`is not None`, `not done()`)
- Wrapped in try/except to handle edge cases where task is already cancelled

## Compatibility considerations

- `_shutdown_event.set()` retained for backward compatibility with any external code that sets the event
- `_input_coro` is only used internally within the REPL lifecycle — no public API impact
- On Windows (where `add_signal_handler` is unavailable), the lambda fallback still works correctly

## Security considerations

- No security impact — shutdown behavior change only
- `RuntimeError` caught in signal handler prevents unhandled exceptions during shutdown

## Rollback considerations

- If cancelling `input_coro` causes terminal corruption issues, revert by removing the cancel call and keeping only `_shutdown_event.set()`
- No data loss risk — original shutdown flow preserved via `_shutdown_event`
