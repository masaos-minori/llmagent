# Implementation Procedure: Include StartupFailure details in HttpStartupError message

## Goal

Override `__str__` or `__repr__` on `HttpStartupError` so that printing the exception displays full `StartupFailure` details (server_key, reason, stderr_full) instead of just the reason string.

## Scope

- Add `__str__` method to `HttpStartupError` class in `scripts/agent/http_lifecycle.py`
- Ensure the output includes server_key, reason, and a truncated stderr_tail for readability

## Assumptions

1. `StartupFailure.stderr_full` can be large; truncating to a reasonable tail (e.g., last 512 chars) keeps the message readable
2. The existing `.failure` attribute on `HttpStartupError` is always populated after initialization
3. No downstream code currently relies on the RuntimeError message containing only the reason string

## Design decisions

- Use `__str__` over `__repr__`: `__str__` is used by `print(exc)` and `str(exc)`, while `__repr__` is used by `repr(exc)` and interactive REPL. For user-facing messages, `__str__` is appropriate.
- Truncate `stderr_full` to last 512 characters using `_mask_secrets` for readability and security.
- Format: `f"{server_key}: {reason} (stderr_tail: ...)"` — clear separation between structured fields and raw output.

## Alternatives considered

1. **Use `__repr__` instead**: Would affect `repr(exc)` output but not `str(exc)`. Since logging/printing uses `__str__`, `__str__` is the right choice.
2. **Format as JSON**: More machine-readable but less human-friendly. A simple colon-separated format is sufficient for debugging.
3. **Mask secrets in stderr_tail**: Yes — use `_mask_secrets` from `agent.secrets_masker` which is already imported at line 27.

## Compatibility considerations

- No consumers explicitly catch `HttpStartupError` and parse `str(exc)` — they catch via `except RuntimeError` (since `HttpStartupError` inherits from `RuntimeError`). Adding fields to `__str__` does not change the inheritance hierarchy or exception catching behavior.
- The `self.failure` attribute remains unchanged — programmatic access to full data is preserved.

## Security considerations

- `stderr_full` may contain sensitive information (API keys, tokens). Apply `_mask_secrets` to the truncated stderr_tail before inclusion in the message.
- `server_key` and `reason` are not sensitive — they are derived from configuration and deterministic error conditions.

## Rollback considerations

- Remove `__str__` method from `HttpStartupError` class definition
- Restore original `super().__init__(failure.reason)` behavior where the RuntimeError message contains only the reason string
- No database or config changes to revert

## Validation plan

- Unit test: `str(HttpStartupError(failure))` contains server_key, reason, and stderr_tail
- Unit test: stderr_tail truncation when stderr_full > 512 bytes
- Unit test: no trailing separator when stderr_full is empty
- Integration test: verify error messages in logs show full context when HttpStartupError is caught and logged
- Manual verification: no consumer parses `str(exc)` expecting only the reason string

## Out of scope

- Changes to `StartupFailure` dataclass structure
- Adding `__repr__` method (only `__str__` needed per plan)
- Modifying how `startup_timeout_sec` parameter affects error formatting
- Changes to other modules unless they catch and re-format the exception

```python
class HttpStartupError(RuntimeError):
    """Raised when an HTTP subprocess MCP server fails to start."""

    def __init__(self, failure: StartupFailure) -> None:
        """Initialize with the startup failure details."""
        self.failure = failure
        super().__init__(failure.reason)

    def __str__(self) -> str:
        """Return a human-readable representation including all failure details."""
        parts = [f"{self.failure.server_key}: {self.failure.reason}"]
        if self.failure.stderr_full:
            tail = self.failure.stderr_full[-512:]
            masked = _mask_secrets(tail)
            parts.append(f"(stderr_tail: {masked})")
        return " ".join(parts)
```

Key changes:
- After line 50 (end of `__init__`), add `__str__` method
- `__str__` formats: `"server_key: reason (stderr_tail: <truncated+masked>)"` when stderr exists
- `__str__` formats: `"server_key: reason"` when stderr is empty
- Uses `_mask_secrets` (already imported at line 27) on the stderr content
- Takes last 512 characters of stderr_full for readability
