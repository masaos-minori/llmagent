## Goal

Show the memory disabled warning immediately after startup completes, rather than waiting for the first user input.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _run_repl_loop()), `scripts/agent/startup.py` (StartupOrchestrator._setup_prompt())
**Out**: Changes to memory injection logic, other startup warnings

## Assumptions

1. `ctx.conv.memory_disabled` is set during startup by `_setup_prompt()` when memory injection fails
2. `memory_warning_shown` flag prevents duplicate warnings within the same session
3. CLIView.write_warning writes to the terminal regardless of whether REPL loop has started

## Design decisions

- Add warning check in `AgentREPL.run()` after startup success — minimal change surface; shows warning before any user interaction
- Keep existing check in `_run_repl_loop()` as safety net — idempotency guard (`memory_warning_shown`) ensures no duplicate warnings even if both paths fire

## Alternatives considered

- **Move the warning into `_setup_prompt()`**: Would couple the startup orchestrator to REPL-level concerns; violates separation of responsibilities
- **Remove the `_run_repl_loop()` check entirely**: Would lose the safety net for edge cases where startup didn't set `memory_disabled` but the REPL loop detects it later
- **Use a dedicated startup notification mechanism**: Over-engineered; existing `_view.write_warning` is sufficient

## Implementation

### Target file

`scripts/agent/repl.py`

### Procedure

#### Step A: Modify AgentREPL.run() — add post-startup memory warning check

Current code (lines 506-512):

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        await self._run_repl_loop()
```

Change to:

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        # Show memory disabled warning immediately after startup if applicable
        if self._ctx.conv.memory_disabled and not self._ctx.conv.memory_warning_shown:
            self._ctx.conv.memory_warning_shown = True
            self._view.write_warning(
                f"{OutputTag.NON_FATAL} Memory is disabled for this session."
            )
        await self._run_repl_loop()
```

Key points:
- Warning emitted right after successful startup, before entering REPL loop
- `memory_warning_shown` set atomically with the warning emission — prevents race condition
- Existing `_run_repl_loop()` check kept as safety net — idempotency guard prevents duplicates

### Method

Extract ownership of warning visibility into the outer scope (`AgentREPL.run`). Use the existing `memory_disabled` flag and `memory_warning_shown` guard to emit the warning immediately after startup without introducing new abstractions.

### Details

The core issue is that the memory disabled warning only appears on the first user input, which means users may start interacting with the system without knowing memory is unavailable. By adding the warning check in `AgentREPL.run()` after startup success, we ensure users see the warning before any conversation begins.

The dual-check approach (both in `run()` and `_run_repl_loop()`) provides defense-in-depth:
- Primary path: `run()` catches the case where `_setup_prompt()` already set `memory_disabled`
- Safety net: `_run_repl_loop()` catches edge cases where the flag wasn't set until later
