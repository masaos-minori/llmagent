## Design decisions

- Record the `RUF100` defer-decision as its own comment line/block, distinct from (but
  adjacent to) the sibling's `PLC0415`-exclusion comment — each rule family's rationale is
  independently readable, per this plan's Scope: "Explicit cross-reference in
  `pyproject.toml`'s inline comments... tying the `BLE001` decision (sibling plan) and the
  `PLC0415`/`RUF100` decisions (this plan) together as one coherent, evidence-backed
  configuration state."
- Cross-reference both this plan (`plans/done/20260806-134805_plan.md`, after Step 4 of
  this workflow moves it there) and the sibling plan
  (`plans/done/20260806-133908_plan.md`) by path in the comment text, so a future reader
  lands on the correct evidence trail for each decision without re-deriving it.
- Do not touch the `select` list itself for this item — `RUF100` stays unselected; only a
  comment is added.

## Alternatives considered

- Fold the `RUF100` rationale into the sibling's existing `PLC0415`-exclusion comment as
  one combined paragraph — rejected: the two decisions have independent evidence (1193
  findings for `PLC0415` vs. 167 for `RUF100`) and independent future-reconsideration
  triggers; merging them risks a future partial edit (e.g. enabling `PLC0415` only)
  leaving stale text about `RUF100` or vice versa. Keeping them as separate, adjacent
  comment lines is safer to maintain.
- Enable `RUF100` now and triage its 167 findings in this same batch — rejected per the
  source plan's explicit decision (Unknowns UNK-04): disproportionate scope for this
  increment; deferred as its own future, dedicated requirement.
