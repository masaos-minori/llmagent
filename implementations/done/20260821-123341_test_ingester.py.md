## Design decisions
- Replace `TestValidateArtifact` (the whole class) with a new test class exercising
  `read_chunk_json()`'s rejection paths directly: missing each mandatory key one at a
  time, wrong-typed value per field, an unknown extra key, and the `artifact_type`
  mismatch case that `ingest_url_group()`/`_embed_and_store()` now check inline (see
  `ingester.py`'s implementation document's Design decisions) — write the
  `artifact_type` mismatch test against whichever `ingester.py` call site retains that
  check, not against a since-removed `_validate_artifact()`.
- Add explicit `chunk_index` rejection tests: `bool` value, negative int, string value —
  each should raise (whatever exception `read_chunk_json()`/the call site surfaces),
  per the requirement document's Tests section referenced by the plan.

## Alternatives considered
- Keeping `TestValidateArtifact` as a thin wrapper delegating to the new reader —
  rejected: `_validate_artifact()` no longer exists as a method to test; the class name
  and its assumptions (a `strict` bool toggle) no longer map to the new one-behavior
  boundary.
