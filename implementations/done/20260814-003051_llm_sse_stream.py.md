## Goal

Extract the per-chunk processing loop body inside
`LlmSseStreamHandler.stream_once` (`scripts/shared/llm_sse_stream.py:47-132`, loop body at
lines 85-115) into a new private static helper (e.g. `_process_next_chunk`) on the same
class, so `stream_once` drops from cyclomatic-complexity grade C (score 12) to grade B or
better, with zero observable behavior change.

## Scope

**In-scope:**
- `scripts/shared/llm_sse_stream.py`: add a new private static helper on
  `LlmSseStreamHandler` and move the current `while True:` loop body (lines 85-115) into it
  verbatim; update `stream_once` to call the helper once per iteration and act on its return
  value.

**Out-of-scope (no change):**
- `read_next_chunk` (lines 24-44), `_handle_status` (lines 134-140), `_build_payload`

  `scripts/shared/sse_parser.py`, `scripts/shared/llm_sse_helpers.py` — called by
  `stream_once`/the new helper but not modified; source requirement forbids behavior
  changes here.
- `docs/*.md` — document-only phase, no doc edit permitted.

## Design decisions

- Name the new helper `_process_next_chunk` (leading underscore, matching the existing
  `_handle_status`/`_build_payload` private-method convention on this class) and document in
  its docstring that it must only be called from inside `stream_once`'s existing `try` block
  (so `httpx` exceptions it does not itself catch still get translated by the enclosing
  `except` clauses at lines 117-128).
- Because Python closures cannot mutate `stream_once`'s `finish_reason` local by side effect
  alone, the helper returns `(finish_reason, should_break)`; it raises `LLMTransportError`
  directly for the `PREMATURE_EOF` case (this exception type is already re-raised unchanged
  by `stream_once`'s `except LLMTransportError: raise` at line 117-118, so no new catch site
  is needed).
- `content_parts`, `tool_calls_map`, and `stat_parse_errors_ref` continue to be mutated in
  place (passed by reference) rather than returned, matching how `stream_once` already
  treats them as mutable accumulators today.

## Alternatives considered

- Returning a dedicated result/signal object instead of a `(finish_reason, should_break)`
  tuple — rejected as unnecessary ceremony for a two-field return in a private helper used
  from exactly one call site.
- Making the helper a generator that `stream_once` iterates — rejected: it would change the
  loop's control-flow shape more than a mechanical extraction warrants and complicate the
  `PREMATURE_EOF` raise timing.

## Implementation

### Target file
`scripts/shared/llm_sse_stream.py`

### Procedure
1. Add `_process_next_chunk` as a new `@staticmethod` on `LlmSseStreamHandler`, placed next
   to `read_next_chunk`/`_handle_status`/`_build_payload` (e.g. directly after
   `stream_once`).
2. Give it an explicit docstring listing inputs (`parser`, `byte_iter`, `url`,
   `heartbeat_timeout`, `llm_stream_retry_on_heartbeat_timeout`, `content_parts`,
   `tool_calls_map`, `stat_parse_errors_ref`, `on_token`, `on_usage`, current
   `finish_reason`) and outputs (`(finish_reason, should_break)`), plus the "only call from
   within `stream_once`'s try block" constraint.
3. Move the current loop body (lines 85-115) into the helper verbatim:
   - the `await LlmSseStreamHandler.read_next_chunk(...)` call and its `exhausted` check;
   - the `PREMATURE_EOF` raise (`exhausted and not is_done and finish_reason is None`);
   - the `parser.feed(raw_chunk)` call and `stat_parse_errors_ref` accumulation
     (including the `parser.stat_parse_errors = 0` reset);
   - the `LlmSseHelpers.process_sse_payloads(...)` call and `finish_reason` update;
   - the `is_done` break check.
4. Update `stream_once`'s `while True:` loop (lines 85-115) to call
   `LlmSseStreamHandler._process_next_chunk(...)` once per iteration, updating its local
   `finish_reason` from the returned tuple and `break`-ing when `should_break` is true.
   Everything outside the loop (payload build at lines 74-79, `_handle_status` call at
   line 81, the `except LLMTransportError`/`except (TimeoutError, httpx.ConnectError, ...)`
   translation block at lines 117-128, and the final `parse_errors` bookkeeping at
   lines 130-132) stays unchanged.

### Method
Mechanical extract-method refactor: no new control-flow branch, no new import, no change to
any exception `kind`/`retryable` value.

### Details
- Preserve the exact order of checks: `exhausted` first, then (inside the `exhausted`
  branch) `not is_done and finish_reason is None` for `PREMATURE_EOF`, else `break`; then (in
  the non-exhausted path) `parser.feed` → `stat_parse_errors_ref` accumulation →
  `process_sse_payloads` → `finish_reason` update → `is_done` break check — matching current
  lines 92-115 one-for-one.
- `is_done` is currently a local in `stream_once` initialized at line 84 (`is_done = False`)
  before the loop, then reassigned from `parser.feed(raw_chunk)` at line 103 inside the loop,
  and read again at line 93 on the *next* iteration's `exhausted` check. The helper must
  either take the previous iteration's `is_done` as an input parameter and return the new
  `is_done` alongside `(finish_reason, should_break)`, or fold the `exhausted`-branch check
  entirely inside the helper by passing in the last-known `is_done` — either way, `stream_once`
  must keep tracking `is_done` across iterations exactly as today (currently it is not reset
  once true; the loop breaks on the same iteration `is_done` becomes true or subsequently
  when `exhausted` fires with `is_done` already true).
