## Goal
- Make the `test` job of `.github/workflows/ci.yml` run pytest on `tests/` once, as one coverage-collecting run in the step `Run tests`, with the `Coverage report` step keeping `coverage xml` and `diff-cover` unchanged (`REQ-001`: one run with `-v` kept; `REQ-002`: gate untouched; `REQ-003`: failure and gate still enforced; `REQ-005`: record durations).

## Scope
**Release unit**: N/A: not part of a release unit

- In scope: the two steps `Run tests` and `Coverage report` of the `test` job.
- Not in scope: the `lint` job, triggers, runners, other steps, parallel workers, `-m` filters, the `diff-cover` threshold or compare branch.

## Assumptions
- Today `Run tests` runs `uv run pytest -v` (verbosity 2, because `addopts` already holds `-v`) and `Coverage report` runs `uv run coverage run -m pytest tests/` (verbosity 1) before `coverage xml` and `diff-cover`. Both select the whole `tests/` tree through `testpaths`.
- `coverage run -m pytest` returns pytest's exit status (measured on a scratch test: 1 for a failing test, 5 for an empty selection), and a failing step stops the later steps of the job, so a failing test still fails the job before the gate.
- Nothing depends on the step names `Run tests` and `Coverage report` (`tools/check_ci_results.py` reads `FAILED <nodeid>` lines only), and they stay.
- Falsifier: a test that fails only under coverage tracing would now be the first failure seen on a red build (Plan `UNK-03`).

## Design decisions
- Keep `-v` in the merged command so verbosity 2, with unabridged assertion diffs, is preserved.
- Keep the step names and the gate lines byte-identical.

## Alternatives considered
N/A: dropping `-v` would reduce the CI failure output; adding `-n auto` is out of scope because coverage would report 0% for worker code.

## Implementation
### Target file
`.github/workflows/ci.yml`

### Procedure
1. In the step named `Run tests`, change `run: uv run pytest -v` to `run: uv run coverage run -m pytest -v tests/`.
2. In the step named `Coverage report`, remove the line `uv run coverage run -m pytest tests/` from its `run: |` block, leaving `uv run coverage xml` and `uv run diff-cover coverage.xml --compare-branch=origin/master --fail-under=90` exactly as they are.
3. Review the diff: no other job or step changed, no `-m` or `-n` added.

### Method
Edit only the `test` job; the two steps stay in the same order, so `diff-cover` still reads the data written by the single `coverage run`.

### Details
- Run `uv run yamllint .github/workflows/ci.yml` (`actionlint` is not installed: record `Not available` and review the diff by reading).
- Run the local equivalent once: `uv run coverage run -m pytest -v tests/ && uv run coverage xml && uv run diff-cover coverage.xml --compare-branch=master --fail-under=90`, and compare its pass or fail result with a plain `uv run pytest` (three `tests/mcp_servers` failures are pre-existing on this host, so both must show the same ones).
- Run `uv run python tools/check_tool_descriptions_sync.py` (the pre-commit hook runs on workflow files).
- Do not push a failing test to verify the failure path; the exit-status measurement above is the evidence.
