## Goal

In `scripts/rag/ingestion/ingester.py`: make `ingest_url_group()` validate every
chunk file in a URL group — not just `chunk_files[0]` — before any embedding call
or database read/write, rejecting the whole group on any cross-file field
mismatch or on a non-contiguous-from-zero / duplicate `chunk_index` set. Remove
the `except sqlite3.IntegrityError: pass` block in `_insert_chunks_batch()` so
integrity failures propagate and roll back the whole URL transaction via
`_commit_url_transaction()`'s `db.begin_immediate()` context manager. Add
`sqlite3.IntegrityError` to `_process_url_groups()`'s caught exception tuple so
one failed URL group does not abort the whole batch run.

## Scope

- In scope: `ingest_url_group()` (add a full-group validation pass before
  `_get_or_create_document()`/`_prepare_chunks()`), `_insert_chunks_batch()`
  (remove the swallowed `IntegrityError`), `_process_url_groups()` (extend its
  caught exception tuple). Failure routing reuses the existing
  `_route_chunk_files()` / `_write_error_metadata()` / `_validation_failure_result()`
  helpers already present in this file — no new routing mechanism.
- Out of scope: `scripts/db/schema_sql.py` (separate document, this batch),
  `scripts/db/store_impl.py`'s `doc_upsert()`, `tests/rag/ingestion/test_ingester.py`
  and `test_rag_ingester.py`, and `RagIngester._insert_chunk()` (singular) — the
  source plan confirms this method has zero call sites in `scripts/`/`tests/` and
  is left as-is (flagged as a risk in the plan, not fixed by this document).
- Out of scope: `_normalize_chunk_index()` and `_validate_artifact()` themselves —
  owned by the dependency plan `plans/20260820-094150_plan.md`, not modified here.

## Design decisions

- Perform the cross-file group validation as a single upfront read pass over
  all of `chunk_files` (via the existing `_read_chunk_json()`) before
  `_get_or_create_document()` is called — matches the plan's Design step 1 and
  the plan's own stated ordering risk ("a mistake ... could silently reintroduce
  a partial-DB read before validation completes").
- Compare `url`, `title`, `lang`, `fetched_at`, `etag`, `last_modified`,
  `source_file`, `chunking_strategy`, `schema_version`, `artifact_type`,
  `created_by` from every file against `chunk_files[0]`'s value; any mismatch,
  plus any duplicate or non-contiguous-from-zero `chunk_index`, fails the whole
  group via the existing `_validation_failure_result()` / `_route_chunk_files()`
  path — no partial group ever reaches embedding or a DB write.
- Route `IntegrityError` propagation through the pre-existing
  `begin_immediate()` rollback mechanism rather than adding a new
  try/except-and-manual-rollback inside `_insert_chunks_batch()` itself — the
  transaction boundary already owns rollback; the fix is only to stop
  swallowing the exception before it reaches that boundary.

## Alternatives considered

- Validating each chunk file lazily as it's embedded in `_prepare_chunks()`
  (inside the existing `ThreadPoolExecutor`) instead of an upfront pass —
  rejected: it would let some files in a mismatched group reach the embedding
  service (network cost) before the mismatch is detected, defeating the plan's
  stated goal of failing "before embedding/mutation."
- Enforcing uniqueness-only on `chunk_index` (no contiguity check) — rejected
  per the plan's Assumptions as the default choice; documented above as the
  fallback if `chunk_splitter.py` is found to legitimately produce gaps.
- Catching `sqlite3.IntegrityError` inside `_insert_chunks_batch()` and
  returning a partial `inserted` count instead of propagating — rejected: this
  is exactly today's swallowing behavior the plan requires removing, and would
  leave a partially-inserted, non-atomic group.

## Implementation

### Target file

`scripts/rag/ingestion/ingester.py`

### Procedure

1. Re-verify the Assumptions check (`_normalize_chunk_index`/`_validate_artifact`
   absence) before proceeding; treat their presence as a hard stop.
2. In `ingest_url_group()`, after sorting `chunk_files` and before the existing
   `first_data = self._read_chunk_json(chunk_files[0])` / single-file
   `_validate_artifact(first_data, "chunk")` check is applied to the rest of the
   group: read every file in `chunk_files` via `_read_chunk_json()`, run
   `_validate_artifact()` on each, and compare the eleven fields listed in
   Design decisions against `chunk_files[0]`'s values. Collect every file's
   `chunk_index`; reject if any value repeats or if the sorted set is not
   exactly `range(len(chunk_files))`.
3. On any failure found in step 2, call `_route_chunk_files([], [(p,
   "group_validation_failed: <detail>") for p in chunk_files])` for every file
   in the group (mirroring the existing single-file failure call already made
   when `_validate_artifact(first_data, "chunk")` fails) and return
   `self._validation_failure_result(url, chunk_files)` — do not proceed to
   `_get_or_create_document()` or `_prepare_chunks()`.
4. Ensure the success/inserted counters used to build the returned
   `IngestUrlResult` (`n_success`, `n_failed`) reflect 0 successes when the
   group fails validation — `_validation_failure_result()` already returns
   `n_success=0, n_failed=len(chunk_files)`, so no further counter change is
   needed once step 3 returns early.
5. In `_insert_chunks_batch()`, delete the `except sqlite3.IntegrityError:
   pass` block so the exception propagates out of the function and out of the
   `with db.begin_immediate():` block in `_commit_url_transaction()`.
6. In `_process_url_groups()`, add `sqlite3.IntegrityError` to the existing
   `except (OSError, RuntimeError, ValueError, sqlite3.OperationalError):`
   tuple so a propagated integrity failure from one URL group logs via the
   existing `logger.exception(...)` call and is recorded as a failed
   (`n_success=0`) result for that group, without aborting the loop over the
   remaining `url_groups`.
7. Run `rg -n "except sqlite3\.IntegrityError" scripts/rag/ingestion/ingester.py`
   and confirm it now only appears in `_process_url_groups()`'s tuple, not as a
   standalone swallow.

### Method

Pure addition of a validation pass plus removal of one exception-swallowing
branch and one exception-tuple extension — no new classes, no new abstraction
layers, no change to `IngestUrlResult`'s shape. Reuse existing helpers
(`_read_chunk_json`, `_validate_artifact`, `_route_chunk_files`,
`_write_error_metadata`, `_validation_failure_result`) rather than introducing
new ones.

### Details

- The eleven-field comparison and `chunk_index` contiguity check both operate
  on the raw dicts returned by `_read_chunk_json()` (type `ChunkJsonRaw | None`)
  — a `None` return for any file in the group (parse failure) must also fail
  the whole group, not just that one file, consistent with the "whole group or
  nothing" goal.
- Do not remove or alter the existing single-file
  `_validate_artifact(first_data, "chunk")` check at the top of
  `ingest_url_group()` — the new all-file pass is additive; the plan does not
  ask for restructuring the existing first-file check, only extending
  validation to the remaining files and to `chunk_index`.
- `_process_url_groups()`'s change is a one-line addition to an existing
  tuple; it does not change the `except` block's body (`logger.exception(...)`
  plus appending an `IngestUrlResult` with `failure_reason=IngestionFailureReason.UNEXPECTED_FAILURE`).
  Per the plan's Design step 4, confirm whether a more specific failure reason
  than `UNEXPECTED_FAILURE` is warranted for the `IntegrityError` case at
  implementation time; the plan does not mandate a new enum value, so keeping
  the existing reason is acceptable if no dedicated one exists.

## Rollback considerations

- Per the plan's own Risk mitigation, Phase 3 (group validation in
  `ingest_url_group()`) and Phase 4 (`IntegrityError` propagation in
  `_insert_chunks_batch()` / `_process_url_groups()`) must be implemented as
  two independently revertable commits, not combined into one. This lets a
  regression traced to one phase (e.g. an overly strict field-mismatch check
  causing false-positive group failures) be reverted without also reverting
  the unrelated integrity-propagation fix, and vice versa.
- If Phase 4 is reverted, restore the `except sqlite3.IntegrityError: pass`
  block in `_insert_chunks_batch()` and remove `sqlite3.IntegrityError` from
  `_process_url_groups()`'s tuple together — reverting only one half would
  either leave an unreachable exception-tuple entry or reintroduce silent
  swallowing without restoring the previous partial-success counting behavior.
- If Phase 3 is reverted, restore `ingest_url_group()` to validating only
  `chunk_files[0]` — no other function's signature changes in this document, so
  reverting Phase 3 alone does not affect Phase 4's changes.
