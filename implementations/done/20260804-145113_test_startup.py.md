# Implementation Procedure: tests/agent/test_startup.py

## Goal
Update `TestStartupRollback.test_no_rollback_on_start_servers_failure` — which currently
asserts the buggy pre-fix behavior (`shutdown_all()` NOT called when `_start_servers()`
raises) — to assert the corrected behavior, and add coverage for the multi-server
partial-failure scenario the fix is meant to close.

## Scope
- In scope: `tests/agent/test_startup.py`, class `TestStartupRollback` (current lines
  557-onward) and its `_make_rollback_startup()` helper (current lines 546-554).
- Out of scope: `TestStartupOrchestratorStartServers` (current lines 64-115) and other
  test classes in this file — verified unaffected, not modified.

## Assumptions
- `_make_rollback_startup()` (current lines 546-554) already patches `_initialize` to a
  no-op and supplies an `AsyncMock` `lifecycle`, so new tests can reuse it unchanged.
- Companion fix in `scripts/agent/startup.py` (see
  `implementations/20260804-145038_startup.py.md`) lands first or alongside — these test
  changes assume the `run()`/`_start_servers()` behavior described there.

## Design decisions
- Rename `test_no_rollback_on_start_servers_failure` to
  `test_rollback_on_start_servers_failure` and change its final assertion from
  `mock_lifecycle.shutdown_all.assert_not_awaited()` to
  `mock_lifecycle.shutdown_all.assert_awaited_once()` — the rename makes the behavior
  inversion self-documenting rather than silently flipping an assertion under an
  unchanged, now-misleading name.
- Add a new parametrized test (`SecurityProfile.PRODUCTION` and a non-production profile)
  with 2 configured MCP servers where the 2nd server's `start_http_subprocess` raises
  `RuntimeError` on both the first attempt and the retry, asserting
  `shutdown_all()` is awaited exactly once — this exercises the exact "raises mid-loop
  after one subprocess already started" scenario from the plan's Goal, which the existing
  single-server tests do not cover.
- Add a regression test confirming `run()` still succeeds when `shutdown_all()` is called
  as a safe no-op (zero subprocesses started, `_start_servers` raises before any server
  starts) — guards the idempotency assumption the design relies on.

## Alternatives considered
- Add the multi-server test to `TestStartupOrchestratorStartServers` (which calls
  `_start_servers()` directly) instead of `TestStartupRollback` (which exercises `run()`):
  rejected as the sole test — the plan's Goal is specifically about `run()`'s rollback
  behavior when `_start_servers()` raises mid-loop, so the assertion on
  `lifecycle.shutdown_all()` must go through `run()`, not a direct `_start_servers()` call.
  A direct `_start_servers()`-level test (asserting `self._spawned_subprocesses` contains
  the first server's `Popen` after the raise) belongs to the companion `startup.py`
  procedure's validation, not to a new test class here.
- Delete the old test outright instead of renaming: rejected — renaming preserves the
  git-blame/history link to the original locked-in-bug test, per the plan's Risk section
  guidance to make the inversion traceable to a reviewer.
