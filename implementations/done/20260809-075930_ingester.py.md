# Implementation Procedure: Phase 2 — Embedding Worker Refactor (No DB Access)

## Goal

Refactor `_embed_and_store()` to produce embeddings without DB access, returning `PreparedChunk | IngestionFailureReason` instead of `(bool, bool)` tuple. Workers only produce embeddings; no DB connections opened.

## Scope

### In-Scope
- Modify `_embed_and_store()` to return `PreparedChunk | IngestionFailureReason` instead of `(bool, bool)` tuple
- Remove `SQLiteHelper` instantiation from `_embed_and_store()` — workers no longer open DB connections
- Convert embedding results to `PreparedChunk` with `floats_to_blob()` applied
- Return appropriate `IngestionFailureReason` value for each failure mode

### Out-of-Scope
- Changes to `_commit_url_transaction()` (Phase 3)
- Changes to `ingest_url_group()` flow orchestration (Phase 4)
- Database schema changes
- Changes to `document_manager.py` beyond removing `delete_existing_document()` delegation

## Assumptions

1. Current `_embed_and_store()` opens a NEW `SQLiteHelper` connection per thread (confirmed by code inspection)
2. sqlite-vec extension works with single connection approach (RESOLVED: Confirmed — `_load_vec_extension()` in `helper.py:145-158` loads vec extension once per connection)
3. HTTP client (`self._client`) lifecycle is unaffected by transaction refactoring
4. Thread pool executor shutdown is unaffected — workers no longer hold DB connections, simplifying cleanup
5. `floats_to_blob()` from `rag.utils` produces deterministic float32 BLOB output

## Design decisions

- `_embed_and_store()` returns `PreparedChunk | IngestionFailureReason` — a union type indicating either success (prepared chunk ready for insertion) or failure (reason for failure)
- Workers no longer open DB connections — this eliminates the race condition where some chunks commit while others fail
- The main thread (in `ingest_url_group()`) becomes the sole DB writer via `_commit_url_transaction()` using `BEGIN IMMEDIATE`
- Failure modes map directly: `PARSE_FAILED` (chunk JSON parse error), `VALIDATION_FAILED` (content validation error), `EMBEDDING_FAILED` (HTTP/embedding service error), `STORAGE_FAILED` (other unexpected error)

## Alternatives considered

- Keeping per-worker DB connections but adding retry logic: rejected because it doesn't solve the fundamental inconsistency problem — partial commits still possible
- Using a shared connection pool: rejected because it adds complexity without solving the atomicity problem
- Returning a dict instead of `PreparedChunk`: rejected because dataclass provides type safety and IDE support

## Implementation

### Target file
`scripts/rag/ingestion/ingester.py`

### Procedure

#### Step 1: Locate current `_embed_and_store()` method

Find the method in `ingester.py`. Current signature:
```python
def _embed_and_store(self, doc_id: int, path: Path) -> tuple[bool, bool]:
```

Current behavior:
1. Opens NEW `SQLiteHelper` connection per thread
2. Calls HTTP embedding service
3. If successful: inserts chunk into DB (via new connection), commits
4. Returns `(True, True)` on success, `(False, False)` on failure

#### Step 2: Modify method signature

Change return type from `tuple[bool, bool]` to `PreparedChunk | IngestionFailureReason`:
```python
def _embed_and_store(self, doc_id: int, path: Path) -> PreparedChunk | IngestionFailureReason:
```

#### Step 3: Remove SQLiteHelper instantiation

Remove the line(s) that create a new `SQLiteHelper` connection inside `_embed_and_store()`. This is the critical change — workers no longer have DB access.

#### Step 4: Replace DB insert operations

Instead of inserting into DB directly, construct a `PreparedChunk` object:
```python
# After successful embedding:
return PreparedChunk(
    doc_id=doc_id,
    chunk_index=idx,
    content=content,
    normalized_content=normalized_content,
    embedding_blob=floats_to_blob(embedding),
    chunk_type=chunk_type,
    source_file=source_file,
)
```

#### Step 5: Handle failure modes

For each failure case, return the appropriate `IngestionFailureReason`:
```python
try:
    # ... embedding logic ...
except SomeParseError:
    logger.error("parse failed", extra={"url": url})
    return IngestionFailureReason.PARSE_FAILED
except SomeValidationError:
    logger.warning("validation failed", extra={"url": url})
    return IngestionFailureReason.VALIDATION_FAILED
except SomeEmbeddingError:
    logger.error("embedding failed", extra={"url": url})
    return IngestionFailureReason.EMBEDDING_FAILED
except Exception:
    logger.exception("storage failed", extra={"url": url})
    return IngestionFailureReason.STORAGE_FAILED
```

#### Step 6: Update caller expectations

The caller (`ingest_url_group()`) must be updated to handle both `PreparedChunk` and `IngestionFailureReason` return types. This is done in Phase 4.

### Details

**File location**: `scripts/rag/ingestion/ingester.py`

**Key changes**:
1. Remove `SQLiteHelper` instantiation — workers no longer open DB connections
2. Change return type from `tuple[bool, bool]` to `PreparedChunk | IngestionFailureReason`
3. Replace `db.execute(...)` calls with `PreparedChunk` construction
4. Add exception handlers mapping to `IngestionFailureReason` values
5. Keep HTTP client usage unchanged — embedding service calls remain parallel

**Critical insight**: The main thread (in `ingest_url_group()`) becomes the sole DB writer. All DB operations happen within `_commit_url_transaction()` using `BEGIN IMMEDIATE`. This ensures atomicity — either ALL chunks for a URL are committed, or NONE are.

**Thread safety**: Since workers no longer hold DB connections, there's no risk of connection conflicts. The main thread handles all DB writes sequentially.

**Memory consideration**: `PreparedChunk.embedding_blob` stores raw bytes — memory pressure for large documents is acceptable since URLs are processed sequentially; memory is freed after commit.
