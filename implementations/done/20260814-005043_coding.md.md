# Implementation: rules/coding.md — document module-level logger-declared-ahead-of-use convention

## Goal

Add a new `## Logging convention` subsection to `rules/coding.md` that explicitly states a
module-level `logger = logging.getLogger(__name__)` declared before any call site is accepted,
intentional boilerplate — not dead code — so future refactor cycles and dead-code passes (vulture,
manual review) stop flagging or removing it. This is a documentation-only change; no `scripts/*.py`
file content changes.

## Scope

**In-Scope:**
- Insert one new `## Logging convention` section into `rules/coding.md`, placed after the existing
  `## Key library choices` section (line 84) and before `## mypy note` (line 89).
- The section must state, as a bullet list:
  1. A module-level `logger = logging.getLogger(__name__)` may be declared ahead of the module
     having any call site for it — accepted, intentional boilerplate anticipating near-future use,
     not dead code.
  2. Dead-code tooling (`vulture`, manual review, refactor passes) must not flag or remove an
     unused module-level `logger` declaration on this basis alone.
  3. The exemption is scoped narrowly to the exact `logger = logging.getLogger(__name__)` pattern —
     it does not extend to other unused module-level names (imports, constants, functions), which
     remain subject to normal dead-code review.

**Out-of-Scope:**
- Any change to `scripts/shared/token_estimation.py`, `scripts/shared/llm_client.py`,
  `scripts/shared/llm_sse_stream.py`, `scripts/shared/mcp_config.py`,
  `scripts/shared/tool_registry.py`, or any other `scripts/*.py` file — these five files are
  reference-only in the source plan (confirmed unused, single `logger` declaration each, no edits
  planned).
- Any change to `docs/*.md` files.
- Any change to lint configuration (`pyproject.toml` vulture/ruff settings) — vulture already does
  not flag this pattern (verified empty output in the source plan), so no suppression config or
  whitelist entry is needed.
- Any other existing section of `rules/coding.md` (`Mandatory conventions`, `Tool configuration`,
  `Suppression governance`, `Constraint checks`, `Bandit priority findings`, `Key library choices`,
  `mypy note`, `Documentation notes`, `Prohibited behavior`).
