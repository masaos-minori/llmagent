## Goal

Replace text-based "no such table" detection with structured error code inspection across both affected files.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL._run_repl_loop()), `scripts/agent/session.py` (AgentSession.start())
**Out**: Changes to SQLite error handling in other modules, schema migration logic

## Assumptions

1. SQLite error code for "no such table" is accessible via `e.args[0]` in sqlite3.OperationalError
2. Extended error code 1017 (SQLITE_NOTFOUND) uniquely identifies "no such table" errors
3. The sqlite_master table exists even when user tables don't, allowing pre-flight checks

## Design decisions

- Create a custom `SchemaMissingError(RuntimeError)` exception class in session.py for precise error classification
- Use sqlite_master pre-flight check combined with error code inspection — more reliable than text matching alone
- Catch SchemaMissingError directly in repl.py instead of parsing RuntimeError messages — eliminates text-based fragility

## Alternatives considered

- **Use only error code inspection without pre-flight check**: Would rely solely on SQLite error codes which may differ between versions; pre-flight check is more robust
- **Add a dedicated schema validation method**: Over-engineered for this specific fix; adds unnecessary abstraction layer
- **Remove the sqlite_master check entirely**: Would lose the primary defense-in-depth mechanism; keep both approaches for reliability

class SchemaMissingError(RuntimeError):

This provides precise error classification — callers can distinguish schema issues from other RuntimeErrors.

#### Step B: Modify AgentSession.start() — structured error detection

Current code (lines 96-109):

```python
    def start(self) -> None:
        """Create a new session record in DB and store its ID. Raises sqlite3.Error on failure."""
        with SQLiteHelper("session").open(write_mode=True) as db:
            try:
                cur = db.execute("INSERT INTO sessions (title) VALUES (NULL)")
            except Exception as e:
                if "no such table" in str(e):
                    raise RuntimeError(
                        "Session schema missing. Run: bash deploy/init_db.sh to initialize the database."
                    ) from e
                raise
            self.session_id = cur.lastrowid
            db.commit()
        logger.info("Session started: id=%s", self.session_id)
```

Change to:

```python
    def start(self) -> None:
        """Create a new session record in DB and store its ID. Raises SchemaMissingError on missing schema."""
        with SQLiteHelper("session").open(write_mode=True) as db:
            try:
                # Pre-flight check: verify required table exists before attempting INSERT
                cursor = db.execute(
                    "SELECT name FROM sqlite_master WHERE type='table' AND name=?",
                    ("sessions",),
                )
                if cursor.fetchone() is None:
                    raise SchemaMissingError(
                        "Session schema missing. Run: bash deploy/init_db.sh to initialize the database."
                    )
                cur = db.execute("INSERT INTO sessions (title) VALUES (NULL)")
            except SchemaMissingError:
                raise
            except sqlite3.OperationalError as e:
                # Fallback: check extended error code for SQLITE_NOTFOUND (1017)
                err_code = e.args[0] if e.args else None
                if err_code == 1017:
                    raise SchemaMissingError(
                        "Session schema missing. Run: bash deploy/init_db.sh to initialize the database."
                    ) from e
                raise
            self.session_id = cur.lastrowid
            db.commit()
        logger.info("Session started: id=%s", self.session_id)
```

Key points:
- Pre-flight sqlite_master check catches missing table before INSERT — avoids relying on error messages entirely
- Error code fallback (1017 = SQLITE_NOTFOUND) handles edge cases where sqlite_master check might fail
- SchemaMissingError replaces generic RuntimeError — precise exception type for callers

### Method

Extract ownership of schema validation into the data access layer (`AgentSession.start`). Use pre-flight sqlite_master check combined with error code inspection for defense-in-depth. Replace generic RuntimeError with SchemaMissingError for precise error classification.

### Details

The core issue is text-based detection of "no such table" errors, which is fragile because:
1. Error message text varies by SQLite version and locale
2. Text matching doesn't catch all "no such table" scenarios (e.g., corrupted sqlite_master)
3. Callers must parse RuntimeError messages to distinguish schema errors from other RuntimeErrors

By adding a pre-flight sqlite_master check and using SQLite error code 1017 as a fallback, we achieve:
- Locale-independent detection — no reliance on error message text
- Defense-in-depth — two independent mechanisms for catching missing tables
- Precise error classification — SchemaMissingError allows callers to handle schema issues specifically
