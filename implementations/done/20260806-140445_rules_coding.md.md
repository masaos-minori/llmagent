## Design decisions

- Place the `RUF100` note in §Tool configuration (the `**ruff:**` bullet), not in
  §Suppression governance — `RUF100` is a `select`-list activation question (like
  `BLE001`/`PLC0415`), while §Suppression governance concerns justification-text format
  for existing suppressions. This mirrors the sibling's own placement choice (its
  `BLE001`/`PLC0415` decisions also live in the `select`-list context, though the sibling
  document placed its note inside §Suppression governance since it was primarily fixing
  that section's `rg` asymmetry — this document's note is narrower in purpose and belongs
  next to the `select` value it describes).
- Keep the note to one sentence, per plan Implementation Steps Phase 1: "Add a
  corresponding one-sentence note to `rules/coding.md` §Tool configuration."
- Cross-reference this plan (`plans/done/20260806-134805_plan.md`, after Step 4 moves it)
  by path so a future reader can find the full evidence trail.

## Alternatives considered

- Append the `RUF100` note to the sibling's §Suppression governance edit instead of
  §Tool configuration — rejected: `RUF100` is a `select`-list decision like `BLE001`/
  `PLC0415`, not a justification-format concern; §Tool configuration is the section that
  already documents `select`'s contents, making it the more accurate location.
- Skip documenting `RUF100` in `rules/coding.md` and rely solely on the `pyproject.toml`
  inline comment — rejected: the plan's acceptance criteria explicitly requires the
  decision recorded in both `pyproject.toml` and `rules/coding.md` (Goal: "a `RUF100`
  ... decision is formally recorded with evidence... completing this requirement's
  acceptance criteria").
