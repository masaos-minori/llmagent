## Goal
- Add a read-only open mode to `SQLiteHelper` so probes can verify databases without side effects.

## Scope
**Release unit**: N/A: not part of a release unit (plan Phase 1 is independently validatable — additive Helper parameter, default behavior unchanged)

- In scope: `scripts/db/helper.py` — `read_only` open mode, ro-URI connect branch, read-only pragma path (REQ-001).

## Assumptions
- `sqlite3.connect("file:...?mode=ro", uri=True)` raises `OperationalError` (does not create) for absent files — standard SQLite behavior; the Plan's mechanism assumption, behaviorally asserted by the companion unit tests in `implementations/20261115-084603_4_tests_db_test_sqlite_helper.py.md` (AC-1).
- Extension loading (`load_vec`) is connection-local and legal on read-only connections (Plan Design); vec behavior stays unchanged.
- `scripts/agent/services/*` and all production opens keep the default read-write path untouched (Issue AI Instruction: production pragma policy unchanged).

## Design decisions
- `open()` gains a `read_only` (new) keyword defaulting to `False`; the ro branch is extracted into `_connect_read_only` (new) rather than deepening `open`, keeping `open` at rank B (plan Validation plan row; the landed branch is a one-line ternary — radon counts it as one decision, B(8) -> B(9) expected, rank unchanged).
- Pragma gating through a `read_only` (new) keyword on `apply_connection_pragmas`: when true it applies only `busy_timeout` and skips `journal_mode`/`synchronous`/`foreign_keys`. Chosen over a sibling apply_read_only_pragmas function (Plan Design allows either): one function keeps the pragma vocabulary in one place for Plan 005's teardown work on this file.
- Verification finding (2026-11-15, whole-suite fallout triage): a ro open of a WAL-mode database whose sidecars are absent still makes SQLite create empty `-wal`/`-shm`, and a read-only connection cannot checkpoint, so the sidecars survive close. The vec0 restore tests and `test_recover_dry_run_corrupt_file_unchanged` failed because those residues leaked into staging and directory listings — REQ-006 ("no created `-wal`/`-shm`") is a Helper-level contract, not just a probe behavior. Decision: `_connect_read_only` records a pre-open snapshot (`_ro_residue`), `close()` unlinks only the sidecars that snapshot shows were absent and that stayed empty (hot-WAL guard `_wal_is_hot`); pre-existing or concurrently written sidecars are never touched. Extracted `_cleanup_read_only_residue` and `_configure_connection` keep `open` at B(9).

## Alternatives considered
- Separate ProbeHelper class: rejected in the Plan Design — duplicates lifecycle, config boundaries, and vec loading for one flag.
- Making `mode=ro` the default for all opens: rejected — the Issue Constraint keeps normal write connections on the current pragma policy.

### Procedure

2. Add `_connect_read_only` (new) next to `_connect` (`:134-152`): connect with `sqlite3.connect(f"file:{pathname2url(self._db_path)}?mode=ro", uri=True, timeout=self._sqlite_timeout, check_same_thread=self._check_same_thread)`; escape the path with `urllib.request.pathname2url` so exotic paths stay valid URIs; on failure log and re-raise like `_connect` — a missing path must surface `sqlite3.OperationalError`, never create a file (REQ-001, AC-2 mechanism). Keep the same `_db_path`-empty `ValueError` guard as `_connect`.
3. `open()` (signature `:180-188`, body `:202-218`): add the keyword `read_only` (new) `bool = False`; when set, obtain the connection via `_connect_read_only` (new) and pass `read_only=True` through `_apply_connection_pragmas` (verification correction: this method's landed signature is `(conn, *, write_mode)` — it also gains a `read_only` (new) keyword forwarded to `apply_connection_pragmas` at the `:211` call site); when unset, behavior is byte-for-byte the current path (REQ-001).
4. Keep `load_vec` handling (`:207-210`) unchanged in both branches (vec loading on a ro connection is legal); the landed shape routes both through a new `_configure_connection` (new) helper so the new failure-cleanup try/except keeps `open` at B(9).
5. Sidecar-residue cleanup (REQ-006): `_connect_read_only` records the `-wal`/`-shm` names that do not exist before the connect into `_ro_residue`; `_cleanup_read_only_residue` (new) unlinks only recorded names that stayed empty, skipping everything while a hot (non-empty) `-wal` exists (`_wal_is_hot` (new) — stat failure reports hot and preserves everything); `close()` calls it after closing the connection, and `open()`'s ro failure path closes the connection and calls it before re-raising. A write-path `_connect` resets `_ro_residue` to empty so write opens are unaffected.
