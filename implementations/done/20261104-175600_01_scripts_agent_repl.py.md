## Goal

Make `agent.repl.main` end the process quietly (exit status 0, no traceback) when startup is interrupted by a shutdown request (SIGTERM or SIGINT), while a genuine startup failure keeps its non-zero exit and visible fatal message (REQ-001 catch-and-return, REQ-003 failure propagation).

## Scope
**Release unit**: N/A: not part of a release unit

In-scope: wrap the `asyncio.run` call inside `main` in a `StartupInterrupted` handler that returns normally.

## Assumptions

- Exit status 0 for an interrupted startup is the owner's decision for both SIGTERM and SIGINT (Plan `Scope` / `Assumptions`); no signal-specific status is implemented.
- `asyncio.run` cleans up pending tasks before the exception leaves it, so catching outside `asyncio.run` is safe (Plan `Assumptions`).
- The compiled-binary launcher (`from agent.repl import main` + `main()`, return value discarded) means a normal return from `main` yields status 0 for the binary as well (verified against `deploy/build_binaries.sh` in this cycle).
- Overlap judgment (`tools/check_plan_target_overlaps.py`): `tests/agent/test_repl.py` is also targeted by `plans/20261104-115736_partialcount001_partial-completion-counter-dead.md`, which adds `_dispatch_line` warning tests in a separate class while this Plan adds entry-function tests; judged compatible, no ordering needed.

## Design decisions

- Handle the exception in the single process entry function `main`, after `AgentREPL.run` has already warned and cleaned up (Plan Design Decision 1, option c); `main` keeps its name and signature so the generated launcher keeps importing it.
- Catch only `StartupInterrupted`; every other exception keeps propagating (REQ-003).

## Alternatives considered

- Catch inside `AgentREPL.run` — rejected: it would break the contract that `run()` re-raises after cleanup (pinned by `test_startup_interrupted_warns_and_reraises`).
- Add a new entry module or function — rejected: the Plan rejects a new module for a three-line function (Plan Design Decision 1).

## Implementation
### Target file
`scripts/agent/repl.py`

### Procedure

- In `main`, wrap the existing `asyncio.run(AgentREPL().run())` call in a `try` block with a single `except StartupInterrupted:` clause that returns normally (returns `None`); no log or message here — `AgentREPL.run` has already printed the non-fatal warning.

### Method

- `StartupInterrupted` is already imported in this module (`from agent.startup import StartupInterrupted, StartupOrchestrator` — Explicit in code); no new import is needed.
- The handler MUST name `StartupInterrupted` explicitly. `StartupInterrupted` is a `BaseException` subclass (by design), so a broad `except Exception` would not catch it and MUST NOT be used.
- Do not touch `AgentREPL.run`, its `finally` cleanup order, or the module's own `if __name__ == "__main__": main()` block.

### Details

- `AgentREPL.run` keeps its warn, clean up, re-raise contract unchanged: it writes the `Startup interrupted by shutdown request:` warning and re-raises; `main` is the new catch point (REQ-001).
- A genuine failure (any exception other than `StartupInterrupted`) still propagates out of `main`, keeping the traceback and status 1 that signal a real crash (REQ-003).

## Compatibility considerations

- `main` keeps its name and signature; the launcher generated by `deploy/build_binaries.sh` (`from agent.repl import main` then `main()` with the return value discarded) works unchanged — a normal return yields status 0.
- Existing `AgentREPL.run` contract tests (`TestRunStartupInterrupted`) pass unchanged (AC-2).

## Security considerations

- Catching only `StartupInterrupted` keeps fail-closed behavior for genuine startup errors: they remain visible as tracebacks with a non-zero status.

## Rollback considerations

- Revert the commit; the pre-change behavior (traceback, exit status 1 on interrupted startup) is fully restored. The binary in production is unaffected until it is rebuilt.
