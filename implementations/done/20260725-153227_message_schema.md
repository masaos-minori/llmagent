## Goal

Add schema validation for all messages added to the conversation history. Prevent LLM from manipulating ephemeral message filtering by injecting/removing keys like `_ephemeral`, `_memory_injected`, or `_skill_ephemeral`. Restrict ephemeral key injection to trusted sources only (command handlers).

## Scope

- Define strict schema for valid conversation messages (required fields: role, content; allowed optional keys per role)
- Validate all messages against schema before adding to conversation history
- Restrict ephemeral key injection (`_ephemeral`, `_memory_injected`, `_skill_ephemeral`) to trusted command handlers only
- Add whitelist of allowed keys for each message role

## Assumptions

- Message schema validation should be enforced at the point of insertion into `ctx.conv.history`
- Trusted sources are limited to command handlers and memory injection service
- Ephemeral keys should only be set by code that explicitly marks messages as temporary
- Schema validation errors should log warnings but not crash the session

## Design decisions

- **Trusted-source model over key-based filtering**: Replace ephemeral key detection with explicit source tracking. Messages carry a `source` field indicating who created them, and only trusted sources can set ephemeral keys.
- **Strict schema enforcement**: Require all messages to have `role` and `content` fields. Optional fields must be in the allowed whitelist for that role.
- **Validation at insertion point**: Enforce schema at `ctx.conv.history.append()` boundary rather than modifying individual callers. Single point of enforcement.
- **Graceful degradation**: Log warnings for validation failures but don't crash the session. Invalid messages are silently dropped to prevent disruption.

## Alternatives considered

- **Key-based ephemeral filtering**: Continue using `_ephemeral*` key detection. Vulnerable to LLM manipulation via key removal/injection. Rejected due to security concern.
- **Pydantic models for messages**: Would provide rich type validation but adds dependency weight. Dataclass + manual validation sufficient for this scope.
- **Validate on read vs. write**: Could validate when reading messages from history. However, write-time validation prevents corrupted state from entering the system entirely.
- **Per-message source tracking vs. global trusted list**: Per-message tracking allows fine-grained control but requires changing every caller. Global trusted list simpler to implement initially.

#### Phase 2: Core Logic

3. Create `scripts/agent/message_schema.py`:
   ```python
   # Allowed ephemeral keys per trusted source
   TRUSTED_SOURCES = {
       "cmd_handler": {"_ephemeral"},
       "memory_injection": {"_memory_injected"},
       "skill_mixin": {"_skill_ephemeral"},
   }
   
   # Allowed keys per message role
   ROLE_KEY_WHITELIST = {
       "system": {"role", "content", "priority"},
       "user": {"role", "content"},
       "assistant": {"role", "content", "tool_calls"},
       "tool": {"role", "content", "tool_call_id"},
   }
   
   @dataclass
   class ValidationResult:
       success: bool
       reason: str = ""
   
   def validate_message(msg: dict) -> ValidationResult:
       """Validate message against schema."""
       if "role" not in msg:
           return ValidationResult(False, "Missing 'role' field")
       if "content" not in msg:
           return ValidationResult(False, "Missing 'content' field")
       
       role = msg["role"]
       if role not in ROLE_KEY_WHITELIST:
           return ValidationResult(False, f"Unknown role: {role}")
       
       allowed_keys = ROLE_KEY_WHITELIST[role]
       extra_keys = set(msg.keys()) - allowed_keys
       if extra_keys:
           return ValidationResult(False, f"Unexpected keys: {extra_keys}")
       
       return ValidationResult(True)
   
   def is_trusted_source(source_id: str) -> bool:
       """Check if source is authorized to inject ephemeral keys."""
       return source_id in TRUSTED_SOURCES
   
   def get_allowed_ephemeral_keys(source_id: str) -> Set[str]:
       """Get ephemeral keys allowed for a trusted source."""
       if source_id in TRUSTED_SOURCES:
           return TRUSTED_SOURCES[source_id]
       return set()
   ```

4. Modify `_clear_previous_turn_ephemeral_messages()` in `orchestrator.py`:
   ```python
   async def _clear_previous_turn_ephemeral_messages(self):
       """Remove ephemeral messages from previous turn using trusted-source filtering."""
       # Instead of checking for _ephemeral key, check source field
       current_history = self.ctx.conv.history
       filtered = []
       for msg in current_history:
           source = msg.get("source", "unknown")
           if source == "llm":
               # LLM-generated messages should not be ephemeral
               continue
           ephemeral_keys = set(msg.keys()) & {"_ephemeral", "_memory_injected", "_skill_ephemeral"}
           if ephemeral_keys:
               # Check if source is trusted to use these keys
               allowed = get_allowed_ephemeral_keys(source)
               if not ephemeral_keys.intersection(allowed):
                   continue  # Untrusted source, remove ephemeral message
           filtered.append(msg)
       self.ctx.conv.history = filtered
   ```

5. Update ephemeral key injection in `cmd_skill.py`:

## Compatibility considerations

- **Schema strictness**: Existing messages may not conform to new schema. Start with logging-only mode and switch to reject after validation period.
- **Source field addition**: Adding `source` field to messages is backward-compatible (optional field), but callers must be updated to include it.
- **Ephemeral key behavior change**: Messages without ephemeral keys from untrusted sources will now be treated differently. Verify no legitimate ephemeral messages are lost.

## Security considerations

- **Prompt injection prevention**: Primary security goal — prevent LLM from manipulating ephemeral message filtering
- **Source spoofing**: Ensure `source` field cannot be set by untrusted parties. Validate source field in schema.
- **Ephemeral key bypass**: LLM cannot add ephemeral keys because they're not in the assistant role's allowed keys whitelist
- **Information disclosure**: Validation error messages should not expose internal schema details

## Rollback considerations

- **Quick rollback**: Remove import of message_schema and bypass validation calls
- **Data impact**: No database changes; rollback does not affect persisted state
- **Configurable mode**: Consider adding environment variable to toggle strict/lenient mode without code changes
