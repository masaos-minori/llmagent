## Design decisions
- **The key must be registered before it is readable.** Adding `pending_timeout_minutes` to `agent.toml` is NOT sufficient on its own: `ProductionConfigValidator` rejects unknown top-level keys (`production_config_validator.py` L168 maintains a `valid_keys` set that includes `agent_memory_max_startup_snippets`). If the key is present in `agent.toml` but absent from `valid_keys`, startup/reload validation fails. Therefore the edit couples to:
  - `production_config_validator.py`: add `"pending_timeout_minutes"` to `valid_keys` — **NOT a frozen target** (additional-target-file discovery).
  - `config_dataclasses.py`: add the `pending_timeout_minutes` field to `AgentConfig` and wire it in `_assemble_agent_config()` (`config_builders.py` L142-144) — **NOT a frozen target** (additional-target-file discovery).
- Resolve the coupling in Design: either expose it on `AgentConfig` (requires the two non-frozen edits above) or keep it file-only and read it via a dedicated `agent.toml` reader (avoids those edits but is less consistent). Prefer the path the maintainer selects; expand scope via additional-target-file discovery if needed.

## Alternatives considered
- **Delete `config/mcp_dedup.toml`.** Rejected: the dispatcher remains a reader (single owner), so the file is reduced, not deleted (Plan Out-of-Scope).
