# Implementation Procedure: scripts/agent/factory.py

## Goal
Forward an optional `shutdown_event` parameter through
`_ServerLifecycleRouter.start_http_subprocess()` to `HttpServerLifecycleManager.start()`, so
`StartupOrchestrator._start_servers()` (companion procedure) can propagate its shutdown signal
down to the poll loop that actually blocks for up to `startup_timeout_sec`.

## Scope
- In scope: `_ServerLifecycleRouter.start_http_subprocess()` (current lines 174-197), the
  `self._http_mgr.start(server_key, cfg)` call inside it (current line 190).
- Out of scope: `_ServerLifecycleRouter.ensure_ready()` (current lines ~125-165, including its
  own `self._http_mgr.start(server_key, cfg)` call at current line 144) and `restart()` (current
  line 199+) — neither accepts or forwards `shutdown_event`; both are runtime/ensure-ready paths
  outside the startup-time scope of this plan.

## Assumptions
- `HttpServerLifecycleManager.start()` accepts a new optional `shutdown_event` keyword
  parameter after `implementations/20260804-151108_http_lifecycle.py.md` (companion, this same
  batch) is applied. This edit must not be applied before that one, or the forwarded keyword
  argument will raise `TypeError` against the pre-change `start()` signature.
- `rg -l "LifecycleManagerProtocol" scripts/ tests/` shows only `factory.py` (defines
  `_ServerLifecycleRouter`, the sole production implementer) and `lifecycle_protocol.py`
  (defines the Protocol) reference it by name — confirmed via the source plan's UNK-02
  analysis; no other implementer needs updating.
- Test files construct `MagicMock()`/`AsyncMock()` stand-ins for
  `LifecycleManagerProtocol`/`_ServerLifecycleRouter` rather than concrete implementers, so a
  new optional (default `None`) parameter is additive and does not break existing test doubles.

## Design decisions
- Add `shutdown_event: asyncio.Event | None = None` as a new trailing keyword parameter on
  `start_http_subprocess()`, matching the additive pattern used throughout this plan
  (`StartupOrchestrator.__init__()`, `HttpServerLifecycleManager.start()`).
- Forward it explicitly as `shutdown_event=shutdown_event` into
  `self._http_mgr.start(server_key, cfg, shutdown_event=shutdown_event)` — a pure pass-through,
  no new branching or state introduced in `_ServerLifecycleRouter`.
- Deliberately do not add the parameter to `ensure_ready()`'s or `restart()`'s call sites — both
  are outside this plan's startup-path scope (per Assumptions and the source plan's UNK-04).

## Alternatives considered
- Add `shutdown_event` to `ensure_ready()` as well, for symmetry: rejected — `ensure_ready()` is
  invoked from arbitrary runtime tool-call paths, not the startup sequence; threading a
  startup-specific shutdown signal through it would be a scope-creeping, unused parameter on
  every non-startup call site.
- Store `shutdown_event` as a `_ServerLifecycleRouter` instance attribute (set once, read by all
  methods) instead of passing it per-call: rejected — the router is constructed once and reused
  across the process lifetime (including runtime `ensure_ready()`/`restart()` calls happening
  long after startup completes), so a per-call parameter correctly scopes the signal to the
  startup-time call only, avoiding a stale reference to a startup-only event object.
