## Goal
- Stop `_check_import_refs` from reporting prose as an import citation, and skip the existence check for a symbol or import statement written with the (new) marker, while every genuinely stale reference is still reported (`REQ-001`, `REQ-002`).

## Scope
- The import pattern `_IMPORT_RE`, the function `_check_import_refs`, the function `_check_symbol_refs`, one small helper, and the module docstring of `tools/stale_detector.py`. Line references, Before blocks, the allowlist and the symbol-shape rules are untouched.

## Assumptions
- Prototyped on sample texts before planning: a line-anchored pattern keeps every line-leading citation the old pattern matched and drops only matches that began mid-sentence; it also strips the closing backtick of a wrapped statement.
- The marker convention reuses the existing practice of writing a backticked path followed by (new) for new files, so the helper only has to look at the text right after a backticked token.
- The detector stays regex-based and dependency-free.

## Design decisions
- Narrow, do not broaden: after the change the detector reports a subset of what it reported before; a line-leading import followed by ordinary text is still not reported (that coverage gap is a separate decision, Plan UNK-02).
- Put the marker test in a small helper so `_check_symbol_refs` (already complexity grade C) gains one decision point at most.

Replace the definition of `_IMPORT_RE` with the line-anchored pattern given in the Plan Design section: it starts at the beginning of the text or after a newline, allows indentation, an optional list marker (a dash, an asterisk, or a number with a period) and one optional opening backtick; then the import statement with the module and the imported names captured non-greedily; then an optional closing backtick; then an optional marker group (spaces followed by the literal (new)) captured as a third group; and finally the existing terminator (end of text, or whitespace followed by a hash). Keep the case-insensitive flag and update the comment above it to say it matches line-leading statements only.
3. In `_check_import_refs` read three values from each match (module, names, marker); skip the statement when the marker is non-empty; keep the message format and the existence check for the rest.
4. Add a small helper (a private function named for testing whether a (new) marker follows a position in the text) that returns true when the text starting at the given position begins with at most one space and then the literal (new).
5. In `_check_symbol_refs`, right after the token passes the identifier and shape filters and before the file lookups, skip the token when the helper reports the marker after the end of the matched backtick span.
6. Extend the module docstring with two sentences: an import is recognized only as a line-leading statement, and a symbol or import written with the (new) marker is treated as created by the procedure and not checked.
