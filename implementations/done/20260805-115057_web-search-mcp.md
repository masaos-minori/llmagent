# Implementation Procedure: conf.d/web-search-mcp

## Goal
- Remove the stale `--reload-mcp` reload instruction from `conf.d/web-search-mcp` and replace
  it with an accurate way to apply search-provider API key changes (restart the agent
  process).

## Scope
- In scope: the comment block in `conf.d/web-search-mcp` that describes how to apply a config
  change after editing `BRAVE_API_KEY` / `BING_API_KEY`.
- Out of scope: adding an automated config-reload mechanism; changing the
  `BRAVE_API_KEY=""` / `BING_API_KEY=""` value lines; the provider fallback logic in
  `config/web_search_mcp_server.json`; any other `conf.d/*` file (tracked separately per
  file).

## Assumptions
- Same operational model as `conf.d/github-mcp` and `conf.d/cicd-mcp`: no hot-reload path
  exists; the operator must restart the agent process for new API keys to take effect (per
  source issue `issues/20260802-080732_deploy_github_token_setup_procedure_confirmation.md`).
- Spot check of the current file (`grep -n "reload-mcp\|再起動" conf.d/web-search-mcp`) shows
  the file already contains the line
  `設定を反映するには、エージェントプロセスを再起動してください。` and no `--reload-mcp` /
  `agent.py` reference. If this remains true at implementation time, this procedure is a
  verification-only no-op; re-check before editing in case the file was reverted.

## Design decisions
- Keep the fix as a plain-text comment edit; mirror the wording used in `conf.d/github-mcp`
  and `conf.d/cicd-mcp` so the three `conf.d/*` files stay consistent.
- Preserve the file's existing per-provider guidance blocks (`[Brave Search]`,
  `[Bing Web Search]`, `[DuckDuckGo]`) and only replace the "apply changes" instruction line.

## Alternatives considered
- Add an automated `--reload-mcp` CLI flag to `scripts/agent.py`: rejected — explicitly
  out of scope per the source plan.
- Remove the "apply changes" line entirely: rejected — operators need explicit guidance;
  silence would reintroduce the ambiguity the source issue raised.
