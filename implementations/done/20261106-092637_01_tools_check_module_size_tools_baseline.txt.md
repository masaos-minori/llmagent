## Assumptions
- Verified on 2026-11-06 (Step 3a): `tools/check_module_size.py` already accepts `--scripts-dir`, `--baseline`, `--limit`, `--no-baseline`, and `--update-baseline`, measures every `.py` file under the directory with `rglob` (skipping `SKIP_DIRS`), writes baseline entries as `<relpath>`, tab, byte size relative to that directory, and prints `scripts/` in its messages for any directory (cosmetic, unchanged); `tools/check_module_size_baseline.txt` is empty; `tools/` has no subdirectory with Python files; at planning time 15 files exceed 24576 B.
- The baseline is created from the actual sizes at execution time with `--update-baseline`, because the earlier `tools/` Plans' procedures change file sizes; the executor records the list and count (Plan Assumption, Needs confirmation, non-blocking).
- `tests/tools/test_check_module_size.py` exists and uses a directory named `scripts`; a test file is a valid companion here because only this row names it in `Related Tests`.
- No other open Plan targets these files.

## Design decisions
- The baseline file is generated by the tool, never hand-edited, and entries only shrink afterwards (`REQ-007`).
- The companion tests build a temporary directory named `tools` with a separate baseline file, so the real `scripts/` baseline is never touched.

## Alternatives considered
- Extending the checker to take two directories: rejected, the existing options suffice (Plan Design).
