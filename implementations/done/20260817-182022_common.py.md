## Goal
Consolidate three structurally identical exception handlers into a factory pattern and add exception chaining to two `OSError` → `FileValidationError` re-raises in `scripts/mcp_servers/file/common.py`.

## Scope
- **In-Scope**:
  - Part A: Search for handler `__name__` dependencies; if none found, extract `_make_error_handler(status_code: int)` factory and replace the three handlers
  - Part B: Add `from e` to both `OSError` re-raise sites in `resolve_safe` and `check_size_limit`
- **Out-of-Scope**:
  - Changes to any other MCP server's exception handling
  - Adding new tests beyond verifying existing ones pass
  - Changes to `FileValidationError` definition or behavior

## Assumptions
- No external system relies on the exact `__name__` values of `_on_auth_error`, `_on_not_found`, `_on_validation_error`
- No test asserts on `__cause__` or traceback text in `tests/mcp_servers/file/test_file_common.py`
- The three handlers differ only by HTTP status-code literal

## Design decisions
- Factory pattern reduces duplication while preserving per-handler status codes via closure capture.
- Exception chaining (`from e`) preserves the original OSError context for debugging.

## Alternatives considered
- Leave handlers as-is — preserves current structure but maintains unnecessary duplication.
- Use FastAPI's built-in exception handlers — would require wiring changes across multiple servers.

def _make_error_handler(status_code: int) -> Callable[[Request, Exception], Awaitable[JSONResponse]]:
    async def handler(_req: Request, exc: Exception) -> JSONResponse:

    return handler
