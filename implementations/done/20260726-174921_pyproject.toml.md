## Goal

Remove the stale `"scripts/db/migrate.py"` entry from the `omit` list in the
`[tool.coverage.run]` section of `pyproject.toml`, since that file no longer
exists in the repository.

## Scope

**In-Scope:**
- Delete the line `"scripts/db/migrate.py",` from the `omit` list in
  `pyproject.toml` (currently line 118, inside `[tool.coverage.run]`).

**Out-of-Scope:**
- Any other coverage configuration changes (other omit entries, source list,
  etc.).
- Restoring or recreating `scripts/db/migrate.py`.

## Assumptions

1. `scripts/db/migrate.py` was intentionally deleted and will not be restored.
2. No other part of the repo references this path (verified below).

## Design decisions

- Pure deletion, no replacement text needed — an `omit` entry for a
  nonexistent path is dead configuration with no functional effect other than
  minor clutter, so no alternative representation is required.
- Leave the adjacent `"scripts/db/create_schema.py"` entry and its shared
  comment (`# Schema/migration DDL scripts — executed at deploy time, not
  during tests`) untouched, since `create_schema.py` still exists under
  `scripts/db/`.

## Alternatives considered

- **Leave the entry in place**: rejected — it is dead config referencing a
  deleted file and provides no value; `rules/coding.md` favors removing stale
  declarative cruft.
- **Replace with a comment noting the file was removed**: rejected as
  unnecessary overhead for a single stale line; git history already records
  the deletion.

## Implementation

### Target file

`pyproject.toml`

### Procedure

1. Open `[tool.coverage.run]` → `omit` list (currently lines 115-129+ in
   `pyproject.toml`).
2. Remove the line `    "scripts/db/migrate.py",` (line 118).
3. Confirm the preceding line `"scripts/db/create_schema.py",` still ends with
   a trailing comma (it does, independent of the removed line) and the list

### Method

- Direct text edit (single-line deletion) in `pyproject.toml`; no code
  changes elsewhere are needed since `omit` entries are simple path/glob
