# Implementation Procedure: scripts/agent/startup.py

## Goal
Make `StartupOrchestrator` call `lifecycle.shutdown_all()` unconditionally on any setup
failure in `run()`, and make `_start_servers()` record spawned subprocesses on
`self._spawned_subprocesses` incrementally, so no MCP subprocess outlives a failed startup
attempt — including when `_start_servers()` itself raises partway through its loop.

## Scope
- In scope: `StartupOrchestrator.__init__()`, `StartupOrchestrator.run()` (current lines
  67-94), `StartupOrchestrator._start_servers()` (current lines 133-204), all in
  `scripts/agent/startup.py`.
- Out of scope: `scripts/agent/repl.py` (verification only, no edit expected per plan
  Design §4 — `AgentREPL.run()`'s `hasattr(startup, "_spawned_subprocesses")` fallback
  and `proc.poll()` guard already tolerate this change); `scripts/agent/factory.py` and
  `scripts/agent/http_lifecycle.py` (reference only); any retry/stagger/security-profile
  logic change in `_start_servers()` beyond the append target.

## Assumptions
- `ctx.services_required.lifecycle` is fully constructed and non-None by the time
  `_start_servers()` is invoked in `run()`, because `_initialize()` (called before the
  `try` block) unconditionally builds it via `build_agent_context()`. Confirmed by the
  source plan's Assumption 1 analysis of `factory.py`.
- `HttpServerLifecycleManager.shutdown_all()` / `_ServerLifecycleRouter.shutdown_all()`
  are idempotent and safe with zero tracked subprocesses (source plan's Assumption 2,
  backed by existing tests `test_repeated_shutdown_all_is_idempotent`,
  `test_shutdown_all_twice_is_safe`, `test_shutdown_all_noop_when_no_procs`).
- No other code reads the function-local `_servers_started` flag; it is safe to delete
  outright (source plan's Assumption 4, `rg "_servers_started"` scoped to `run()` only).

## Design decisions
- Initialize `self._spawned_subprocesses: list[subprocess.Popen] = []` in `__init__()`
  rather than only in `run()`, so the attribute exists immediately after construction and
  `_start_servers()` can mutate it directly even when called in isolation (as
  `TestStartupOrchestratorStartServers` in `tests/agent/test_startup.py` does, bypassing
  `run()`).
- Remove the `_servers_started` gating flag entirely (plan's option (b)) instead of
  keeping it and widening its condition — a straight deletion, not a new branch, keeps
  `run()`'s cyclomatic complexity at or below its current grade-B (CC 6) rating.
- In `_start_servers()`, replace the local `spawned: list[subprocess.Popen]` accumulator
  with direct appends to `self._spawned_subprocesses` at both the first-attempt (current
  line ~168) and retry-success (current line ~187) append sites, and change the final
  `return spawned` to `return self._spawned_subprocesses`. This is a pure rename of the
  append target — no new conditional — so `_start_servers()`'s CC stays at its current
  grade-C (14) rating, not pushed to CC ≥ 15.

## Alternatives considered
- Keep `_servers_started` but broaden it to also cover "at least one append happened
  before the raise": rejected — requires threading a mutable flag through the loop body
  in `_start_servers()`, adding a new branch and increasing CC beyond the grade-C(14)
  ceiling the plan explicitly protects.
- Have `_start_servers()` return the list only on success and let `run()` catch a partial
  list via an out-parameter or exception attribute: rejected — more invasive than a direct
  instance-attribute append, and breaks the existing return-type contract used by 4
  passing tests in `TestStartupOrchestratorStartServers`.

## Implementation

### Target file
`scripts/agent/startup.py`

### Procedure
1. In `__init__()` (current lines 60-65), add
   `self._spawned_subprocesses: list[subprocess.Popen] = []` after
   `self._orchestrator: Orchestrator | None = None`.
2. In `run()` (current lines 67-94):
   - Delete `_servers_started = False` (current line 70).
   - Delete the now-redundant `self._spawned_subprocesses: list[subprocess.Popen] = []`
     line (current line 71) — superseded by step 1's `__init__` initialization.
   - Delete `_servers_started = True` (current line 74).
   - In the `except Exception as setup_err:` block (current lines 79-89), remove the
     `if _servers_started:` guard (current line 80) so
     `await self._ctx.services_required.lifecycle.shutdown_all()` (current line 82) and
     its surrounding `try/except Exception as shutdown_err: logger.error(...)` run
     unconditionally on every exception, then `raise setup_err` unchanged.
3. In `_start_servers()` (current lines 133-204):
   - Delete `spawned: list[subprocess.Popen] = []` (current line 147).
   - Change `spawned.append(proc)` at the first-attempt success site (current line 168)
     to `self._spawned_subprocesses.append(proc)`.
   - Change `spawned.append(proc)` at the retry success site (current line 187) to
     `self._spawned_subprocesses.append(proc)`.
   - Change `return spawned` (current line 204) to
     `return self._spawned_subprocesses`.

### Method
- Located exact line numbers via `grep -n "_servers_started\|_spawned_subprocesses\|def __init__\|def run\|def _start_servers\|shutdown_all" scripts/agent/startup.py`, then read
  lines 55-204 directly to confirm current control flow before editing.
- Confirmed via source read that the bug is currently live: `_servers_started` gate
  (lines 70, 74, 80) still gates the `shutdown_all()` call, and `_spawned_subprocesses`
  is currently assigned only inside `run()` (line 71), not `__init__()`.

### Details
- No new imports required; `subprocess.Popen` is already imported/used in this file's
  return-type annotations.
- `_start_servers()`'s signature (`async def _start_servers(self) -> list[subprocess.Popen]`)
  is unchanged — it still returns a `list[subprocess.Popen]`, just now the same object as
  `self._spawned_subprocesses` rather than a fresh local list.
- `run()`'s success-path assignment `self._spawned_subprocesses = await self._start_servers()`
  (current line 73) is retained unchanged — it now assigns the same list object back onto
  the attribute it was already mutating in place, which is a harmless no-op re-assignment.

## Compatibility considerations
- `AgentREPL.run()` (`scripts/agent/repl.py` lines 829-842) reads `startup._spawned_subprocesses`
  via a `hasattr()` fallback and merges it into `all_procs`, then guards each entry with
  `proc.poll() is None` before acting — this continues to work unchanged; duplicates from a
  process already terminated by the now-unconditional `shutdown_all()` are a safe no-op
  (`Popen.terminate()` on an already-signaled process is idempotent). No edit to `repl.py`
  required — verification only, per plan Design §4.
- No public API / CLI signature changes; `run()`'s return type
  `tuple[CommandRegistry, Orchestrator, list[subprocess.Popen]]` is unchanged.
