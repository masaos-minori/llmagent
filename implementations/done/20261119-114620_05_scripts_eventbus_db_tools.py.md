## Goal
- Remove the always-zero `schema_version()` and the `version` subcommand from `db_tools` (REQ-006: no dead accessor, consistent with ADR-008 Decision Details 22 where version stamping is not supported).

## Scope
**Release unit**: eventbus-supervision-and-cleanup

- In scope: `schema_version`, its CLI branch, and the import that only it uses, in `scripts/eventbus/db_tools.py`; the two tests that call it in the companion file.

## Assumptions
- `schema_version()` applies the DDL in memory and returns `PRAGMA user_version`, which stays at the SQLite default because the DDL stamps no version (verified in Step 3a).
- Its only consumers are `tests/eventbus/test_eventbus_db_tools.py` and the generated reference; no deploy script, document, or rule calls `db_tools version` (verified in Step 3a).
- The generated manifest and reference block change as a result and are regenerated by the seq 11 and seq 12 documents.

## Design decisions
- Remove rather than fix: a version command has no meaning when version stamping is not supported.
- After the removal the last branch of `main` serves the `path` command.

## Alternatives considered
- Stamp a version so the command becomes meaningful: rejected, it contradicts ADR-008 Decision Details 22.
