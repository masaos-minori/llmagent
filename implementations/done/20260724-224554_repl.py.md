## Goal

Route all workflow table queries through StateStore's public API instead of bypassing it with direct SQLiteHelper connections.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL._persist_session_diagnostics()), `scripts/agent/workflow/state_store.py` (StateStore)
**Out**: Changes to workflow table schema, other workflow query patterns outside diagnostics

## Assumptions

1. StateStore holds uncommitted writes that should be visible to diagnostic queries
2. Adding methods to StateStore does not violate architecture boundaries (agent → db layer)
3. The diagnostic queries are: task count, workflow count, approval events, retry count, artifacts

## Design decisions

- Add diagnostic query methods to StateStore rather than passing a StateStore instance to repl.py — minimizes cross-module coupling; each method opens its own connection via `SQLiteHelper(target="workflow")`
- Each diagnostic method follows the existing StateStore pattern: open connection, execute query, return result, close connection
- Keep raw SQL in StateStore methods rather than building ORM-like abstractions — diagnostic queries are simple COUNT/FETCH operations that don't warrant additional abstraction

## Alternatives considered

- Pass StateStore instance from Orchestrator to REPL: adds dependency injection complexity for a single usage site
- Add a single `get_workflow_diagnostics(session_id)` method returning all stats at once: couples unrelated query logic; harder to test individually
- Use StateStore.get_connection() to expose the internal SQLiteHelper: defeats the purpose of routing through the public API

### Method

#### Step A: Add diagnostic query methods to StateStore

Add the following methods to the StateStore class after the existing CRUD methods:

```python
    # ── Diagnostic Queries ───────────────────────────────────────────────

    def get_task_count(self, session_id: str) -> int:
        """Return the number of tasks associated with a session."""
        with self._db.execute(
            "SELECT COUNT(*) as cnt FROM tasks WHERE session_id=?",
            (session_id,),
        ).fetchone() as row:
            return int(row["cnt"]) if row else 0

    def get_workflow_count(self, session_id: str) -> int:
        """Return the number of distinct workflows for a session."""
        with self._db.execute(
            "SELECT COUNT(DISTINCT workflow_id) as cnt"
            " FROM tasks WHERE session_id=? AND workflow_id IS NOT NULL",
            (session_id,),
        ).fetchone() as row:
            return int(row["cnt"]) if row else 0

    def get_approval_count(self, session_id: str) -> int:
        """Return the number of approval events for tasks in a session."""
        with self._db.execute(
            "SELECT COUNT(*) as cnt FROM approvals"
            " WHERE task_id IN (SELECT task_id FROM tasks WHERE session_id=?)",
            (session_id,),
        ).fetchone() as row:
            return int(row["cnt"]) if row else 0

    def get_execute_attempt_count(self, session_id: str) -> int:
        """Return the number of execute-stage attempts for tasks in a session."""
        with self._db.execute(
            "SELECT COUNT(*) as cnt FROM attempts"
            " WHERE task_id IN (SELECT task_id FROM tasks WHERE session_id=?)"
            " AND stage_id='execute'",
            (session_id,),
        ).fetchone() as row:
            return int(row["cnt"]) if row else 0

    def get_artifact_uris(self, session_id: str) -> list[str]:
        """Return artifact URIs for tasks in a session."""
        rows = self._db.fetchall(
            "SELECT uri FROM artifacts WHERE task_id IN (SELECT task_id FROM tasks WHERE session_id=?)",
            (session_id,),
        )
        return [dict(r).get("uri") for r in rows if dict(r).get("uri")]
```

Key points:
- Each method uses `self._db` which is already opened in write mode during `__init__`
- Methods follow existing StateStore patterns (raw SQL, row_factory=True)
- Return types match what repl.py expects (int for counts, list[str] for URIs)
