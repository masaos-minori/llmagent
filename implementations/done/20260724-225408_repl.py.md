## Goal

Show the memory disabled warning immediately after startup completes, rather than waiting for the first user input.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _run_repl_loop()), `scripts/agent/startup.py` (StartupOrchestrator._setup_prompt())
**Out**: Changes to memory injection logic, other startup warnings

## Assumptions

1. `ctx.conv.memory_disabled` is set during startup by `_setup_prompt()` when memory injection fails
2. `memory_warning_shown` flag prevents duplicate warnings within the same session
3. CLIView.write_warning writes to the terminal regardless of whether REPL loop has started

## Design decisions

- Add warning check in `AgentREPL.run()` after startup success — minimal change surface, shows warning before any user interaction
- Keep existing check in `_repl_loop` as a safety net — idempotency guard (`memory_warning_shown`) ensures no duplicate warnings even if both paths fire
- No changes to `_setup_prompt()` — it already sets `ctx.conv.memory_disabled` correctly

## Alternatives considered

- Move the warning check into `_setup_prompt()`: would require passing `_view` and `OutputTag` through the startup chain — adds coupling
- Remove the `_repl_loop` check entirely: loses the safety net for edge cases where startup doesn't set `memory_disabled`

## Implementation

### Target file

`scripts/agent/repl.py`

### Procedure

1. In `AgentREPL.run()`, after `StartupOrchestrator.run()` succeeds (line 508), add a check for `self._ctx.conv.memory_disabled and not self._ctx.conv.memory_warning_shown`.
2. If both conditions are true, emit the warning using `self._view.write_warning(f"{OutputTag.NON_FATAL} Memory is disabled for this session.")` and set `self._ctx.conv.memory_warning_shown = True`.
3. Remove or keep the existing check in `_repl_loop` (lines 309-313) as a safety net — the idempotency guard (`memory_warning_shown`) ensures no duplicate warnings.
4. Verify the warning is displayed even if the user closes the REPL immediately via SIGTERM or /exit.

### Method

#### Step A: Modify `AgentREPL.run()` — add post-startup memory warning check

Current code (lines 506-512):

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        await self._run_repl_loop()
```

Change to:

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        # Show memory disabled warning immediately after startup if applicable
        if self._ctx.conv.memory_disabled and not self._ctx.conv.memory_warning_shown:
            self._ctx.conv.memory_warning_shown = True
            self._view.write_warning(
                f"{OutputTag.NON_FATAL} Memory is disabled for this session."
            )
        await self._run_repl_loop()
```

Key points:
- Warning emitted right after successful startup, before entering REPL loop
- `memory_warning_shown` set atomically with the warning emission — prevents race condition
- Existing `_repl_loop` check kept as safety net — idempotency guard prevents duplicates

#### Step B: Keep existing check in `_repl_loop` as safety net

No changes needed — current code (lines 309-313) remains:

```python
            # Warn once about disabled memory
            if ctx.conv.memory_disabled and not ctx.conv.memory_warning_shown:
                ctx.conv.memory_warning_shown = True
                self._view.write_warning(
                    f"{OutputTag.NON_FATAL} Memory is disabled for this session."
                )
```

This serves as a fallback for edge cases where startup didn't set `memory_disabled` but the REPL loop detects it later.
