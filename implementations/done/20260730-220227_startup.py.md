# Implementation Procedure: Fail Fast on Tool Discovery Failure Even in Development Mode

## Goal

Treat tool discovery failures as fatal errors regardless of production mode, improving error messaging to clearly indicate the root cause.

## Scope

**In-Scope:**
- Remove dev/prod distinction for tool discovery failures in `_check_services()`
- Update error message to be more accurate ("No MCP tools will be available this session")
- Ensure logging uses ERROR level for this condition

**Out-of-Scope:**
- Modifying the tool discovery mechanism itself
- Adding retry logic to tool discovery
- Changing the security audit or readiness check behavior

## Assumptions

1. Developers prefer to fail fast rather than start with zero tools and debug later
2. The error message should clearly state the consequence (no tools available) rather than the symptom (tool calls will fail)
3. A remediation hint helps developers resolve the issue quickly

## Design decisions

- Remove `if production_mode:` conditional in tool discovery exception handler
- Always call `pipeline.add_fatal()` for tool discovery failures
- Update error message format to be more actionable
- Add remediation hint for developer guidance

## Alternatives considered

- Making dev/prod distinction configurable → rejected; adds complexity without clear benefit
- Logging at WARNING level but still failing → rejected; inconsistent with prod behavior
- Silent failure in dev mode → rejected; defeats purpose of fail-fast approach

### Details

**Current code (lines 310-319):**
```python
except Exception as exc:  # noqa: BLE001
    msg = f"MCP tool discovery failed - ALL tool calls will fail this session: {exc}"
    if production_mode:
        pipeline.add_fatal(
            "mcp_tool_discovery",
            msg,
            remediation="Investigate MCP server connectivity/discovery failure before restarting.",
        )
    else:
        pipeline.add_skipped("mcp_tool_discovery", msg)
```

**New code:**
```python
except Exception as exc:  # noqa: BLE001
    msg = f"MCP tool discovery failed: {exc}. No MCP tools will be available this session."
    pipeline.add_fatal(
        "mcp_tool_discovery",
        msg,
        remediation="Check MCP server connectivity and configuration.",
    )
```

**Key differences from current code:**
1. Removed `if production_mode:` conditional — always treat as fatal
2. Changed error message from "ALL tool calls will fail this session" to "No MCP tools will be available this session"
3. Simplified remediation message from "Investigate MCP server connectivity/discovery failure before restarting." to "Check MCP server connectivity and configuration."
4. Removed `else` branch that called `add_skipped()` in dev mode

## Compatibility considerations

- Dev mode startup behavior changes — previously silent failure now becomes fatal
- Prod mode behavior unchanged
- Existing single-server deployments unaffected unless they have MCP servers that fail discovery

## Security considerations

- No new secrets or sensitive data exposed through log messages
- Error message includes exception text which may contain sensitive information — consider masking if needed

## Rollback considerations

- Simple rollback: revert to original dev/prod conditional
- No data migration or schema changes required
- If regression detected, temporarily restore `if production_mode:` conditional
