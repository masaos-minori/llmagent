## Goal
- Give each xdist worker its own isolation root, with processes spawned by a worker reusing that worker's root and serial runs unchanged (`REQ-003`).

## Scope
**Release unit**: N/A: not part of a release unit

- In scope: `_setup_isolation` and the `_ISOLATION_ENV_VARS` tuple.
- Not in scope: the per-test guard `_forbid_production_paths`, the session fingerprint fixture `_guard_production_db_files`, the root layout, `_provision_databases`.

## Assumptions
- Today `_setup_isolation` reuses `LLMAGENT_TEST_ROOT` when it names an existing directory, and a probe with `-n 2` showed `gw0` and `gw1` using one root, so the isolated databases, logs, and storage are shared between concurrent tests. Falsifier: after the change two workers still print the same root.
- A worker process has PYTEST_XDIST_WORKER (`gw0`, `gw1`) already when `tests/conftest.py` is imported; the controller has none (measured with an import-time plugin probe). A child of a worker inherits the variable.
- `tools/check_conftest_integrity.py` requires only the four autouse fixtures it lists; none is renamed or removed here.
- Blast radius: every one of the 558 test files loads this module, so the full suite runs serially and in parallel after the change.

## Design decisions
- Record the owner of a root in a new environment variable `LLMAGENT_TEST_ROOT_OWNER` (new): the value of PYTEST_XDIST_WORKER, or empty when it is not set. A process reuses an inherited root only when the directory exists and the recorded owner equals its own worker id; otherwise it builds a root and records itself as owner.
- Serial behavior is identical: both values are empty, so the inherited root is reused as today. Descendants of a worker see the same worker id and owner and reuse the worker's root.

## Alternatives considered
- Keep the shared root and audit every writer: rejected (558 test files, no cheap proof of absence).
- A root per test: rejected (database provisioning per test is too costly).

## Implementation
### Target file
`tests/conftest.py`

### Procedure
1. Read `_setup_isolation` and its use of `LLMAGENT_TEST_ROOT` (`rg -n "LLMAGENT_TEST_ROOT" tests/conftest.py`).
2. Change the reuse condition: compute the process's worker id from PYTEST_XDIST_WORKER (empty string when unset), read `LLMAGENT_TEST_ROOT_OWNER` (new), and set `created` to true unless the inherited directory exists and the owner equals the worker id.
3. When a root is created, set `LLMAGENT_TEST_ROOT_OWNER` (new) to the worker id next to `LLMAGENT_TEST_ROOT`, and keep `_CREATED_ROOT`, the `atexit` registration, and `_provision_databases()` for the created case.
4. Add `LLMAGENT_TEST_ROOT_OWNER` (new) **and `PYTEST_XDIST_WORKER`** to `_ISOLATION_ENV_VARS` so `isolated_subprocess_env` forwards both. Both are required: the reuse rule compares the child's owner against its own worker id, so a child that inherits the owner (`gw0`) but loses the worker id (empty) would fail the equality check and build a new root instead of reusing the worker's root. Forwarding both keeps `owner == worker_id` true for a worker's descendants. In a serial run neither variable names a distinct worker (`PYTEST_XDIST_WORKER` is unset and thus not forwarded by the `if name in os.environ` guard), so serial behavior is unchanged.
5. Run `uv run python tools/check_conftest_integrity.py`, then the isolation tests serially and with `-n auto` (the new test belongs to the sibling procedure for `tests/test_production_isolation.py`).

### Method
A small edit inside `_setup_isolation`; no new function is required. Keep the module docstring accurate: it says the root is created once per process tree, which becomes once per process tree and worker.
