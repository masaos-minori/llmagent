## Goal
- Stop reporting a symbol as missing when it is a built-in or dunder name, a rule code, a sibling-procedure number, a documentation chapter id that prefixes a docs file name, or a configuration key in key position, while a genuinely stale Python symbol is still reported (`REQ-001`, `REQ-002`, `REQ-003`).

## Scope
- The function `_check_symbol_refs`, one new private predicate with small helpers and compiled patterns, one import, and the module docstring of `tools/stale_detector.py`. The line, import, and Before-block checks, the allowlist, the shape filter, and the command-line entry point are untouched.

## Assumptions
- Every new rule runs only at the existing report point, after the name is already absent from the target, the scoped file, and every Python file, so a name that is found is never affected.
- Shapes: a rule code is one to four capital letters followed by two to four digits; a sibling number is an underscore followed only by digits; a chapter id is a lowercase word followed by one or more underscore-digit groups.
- Key position is recognized by line-based patterns: an assignment at the start of a line (optionally after the word export), a table header in square brackets split on dots, a JSON key followed by a colon, and a table name after a create-table statement. Comment lines (first non-blank character is a hash) are skipped entirely.
- The detector stays regex-based and dependency-free.

## Design decisions
- One predicate, `_is_non_python_name` (new), called from the report branch with the symbol, the source directory, and a small cache dictionary; `_check_symbol_refs` gains one boolean condition only, so its complexity stays at its current grade.
- Cheapest checks first and no file-system access until a rule needs it: built-in or dunder, rule-code shape, sibling-number shape, chapter id (shape, then the docs file names), then configuration key (the keys).
- The docs file names and the configuration keys are built lazily on first use and stored in the cache dictionary, which is created once per call of `_check_symbol_refs` next to the symbol-presence cache, so each location is read at most once per run.
- A chapter id is accepted only when some docs file name starts with the id followed by an underscore or a dot, never by a broad pattern.
- Comments and documentation text are never searched for the existence of a name.

## Alternatives considered
- A word-anywhere search of the configuration directories: rejected because comments there mention removed settings and Python names, which would hide genuinely stale citations (Plan Problem).
- Searching docs text for chapter ids: rejected, documentation keeps the names of removed code.

7. Extend the module docstring with two sentences: names that cannot appear in Python source (built-in and dunder names, rule codes, sibling numbers, chapter ids that prefix a docs file name, and configuration keys in key position) are not reported, and comments are never treated as keys.
