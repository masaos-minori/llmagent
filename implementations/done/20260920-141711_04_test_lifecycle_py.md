## Assumptions

- Both `_ServerLifecycleRouter` and `_SubprocessLifecycleManager` implement `LifecycleManagerProtocol` per Plan's stated intent
- `_SubprocessLifecycleManager` receives `server_configs` and `tool_executor` in its constructor (same as current `_ServerLifecycleRouter`)
- `_SubprocessLifecycleManager` has an `_http_mgr` attribute pointing to `HttpServerLifecycleManager`
- `_ServerLifecycleRouter` retains state/cooldown logic and delegates subprocess calls to `_SubprocessLifecycleManager`

## Design decisions

1. **New class import**: Add `from agent.factory import _SubprocessLifecycleManager` alongside existing `_ServerLifecycleRouter` import.
2. **Two-phase test update**: First update existing tests to use the new architecture; then add new tests specifically for `_SubprocessLifecycleManager`.
3. **Preserve test structure**: Keep existing test class/method names and assertions where possible — only change what breaks due to the split.

## Alternatives considered

- **Keep single test file**: Could keep all lifecycle tests together. Trade-off: clearer separation of concerns between coordinator vs. subprocess manager testing. Decision: separate into distinct sections within the same file for simplicity.
- **Create entirely new test file for `_SubprocessLifecycleManager`**: Would require cross-file imports and coordination. Too disruptive for a refactor that doesn't change public API.
