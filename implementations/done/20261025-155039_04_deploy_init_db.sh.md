## Goal

Make `deploy/init_db.sh` prove the EventBus database is in the canonical shape (not merely present) before reporting success, so a malformed EventBus database is rejected at deployment time alongside the other required databases (`REQ-003`).

## Scope

- Modify `deploy/init_db.sh` only: replace the bare `.tables` print for the EventBus database (line 60) with a shape check via the shared validator; keep the Workflow table-presence check (lines 41-58) and the `create_schema.py` invocation (line 31).
- Make `DEPLOY_SCRIPTS`/`DEPLOY_DB` honor environment overrides (`${VAR:-/opt/llm/...}`) so the sandboxed integration tests can run the real script without touching `/opt/llm/db`; production invocations set neither variable and are unchanged.
- Do not touch `scripts/db/create_schema.py`, `scripts/eventbus/schema.py`, the shared validator, or `deploy/setup_services.sh` here — those are the sibling deployment strict-validation, runtime, and fingerprint procedures (`REQ-003`, `REQ-002`, `REQ-001`).

## Assumptions

- The shared validator (`scripts/shared/eventbus_schema_fingerprint.py`, created by the sibling procedure) exposes a shape-comparison entry point that raises on any deviation from `schema.sql`, even when the database version stamp matches.
- The Workflow database keeps its existing table-presence check; this procedure adds a shape-level check for the EventBus database and mirrors the same fail-closed abort pattern.
- Only a malformed EventBus database aborts; a canonical EventBus database passes unchanged.

## Design decisions

- **Replace the bare `.tables` print with a shared-validator call.** `init_db.sh` prints `sqlite3 "${DEPLOY_DB}/eventbus.sqlite" ".tables"` at line 60 purely for visibility. Insert a shared-validator shape check against `${DEPLOY_DB}/eventbus.sqlite` between the EventBus block and the completion banner so a malformed, already-stamped database aborts.
- **Invoke the shared validator through the same `uv run` harness used elsewhere in the script.** The shared validator reads `schema.sql` as text and derives the fingerprint via `PRAGMA` on a fresh in-memory apply, so the deployment comparison is apples-to-apples with the runtime and `create_schema.py` paths.
- **Environment-overridable `DEPLOY_SCRIPTS`/`DEPLOY_DB` (verification finding).** The original hardcoded paths make `tests/deploy/test_init_db_eventbus_schema.py` provision malformed databases at the production path `/opt/llm/db/eventbus.sqlite`, destroying production EventBus state. The verification pass changed the constants to `${DEPLOY_SCRIPTS:-/opt/llm/scripts}` / `${DEPLOY_DB:-/opt/llm/db}` so the tests point them at a throwaway sandbox while production behavior stays identical.
- **Existence check before the shape gate.** The gate would otherwise `sqlite3.connect` a missing path into an empty file before failing; an explicit `[ -f ]` check aborts with a clear `[FATAL]` message first.

## Alternatives considered

- **Keep the bare `.tables` print and add a separate table-presence loop for EventBus.** Rejected: table presence does not prove shape; the defect is a correctly-versioned but malformed database, which a shape check catches and a table list does not.
- **Reuse the Workflow table-presence loop for EventBus.** Rejected: it checks only table names, not columns/indexes/constraints/FKs/triggers; the shared validator is the canonical shape comparison and belongs in one place.

### Method

- Invoke the shared validator via the same harness used at line 31 (`PYTHONPATH="${DEPLOY_SCRIPTS}" UV_SYSTEM_CERTS=true uv run ...`), so the shared module resolves identically to the `create_schema.py` call.
- On any deviation the shared validator raises `RuntimeError`; surface it as a `[FATAL]` message to stderr and `exit 1`, matching the Workflow failure pattern at lines 52-57.
- Echo the validated object set on success, preserving the visibility the bare `.tables` print provided.

### Details

- The shared validator compares tables/columns/types/nullability/defaults/pk, indexes, table-level constraints, foreign keys, and triggers-if-any against `schema.sql`.
- No new shell function is introduced beyond the inline shared-validator invocation; the change is localized to the EventBus verification block.

## Compatibility considerations

- `init_db.sh` is the deployment entry point run once after `deploy.sh`; only a malformed, already-stamped EventBus database now aborts, so fresh canonical creation is unaffected.
- The shared-validator call uses the same production `uv run` flags as line 31.

## Security considerations

- Fail-closed: a malformed, correctly-stamped database aborts before services start. Only object metadata is compared; no secrets or token values are read.

## Rollback considerations

- Revert the single replaced block in `deploy/init_db.sh` (or `git checkout` the parent commit); the Workflow check, the `create_schema.py` call, and the module imports are untouched.
