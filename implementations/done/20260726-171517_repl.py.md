## Goal

Eliminate the race between the SIGTERM/SIGINT handler and the active REPL turn in
`scripts/agent/repl.py`: the handler currently cancels `self._input_coro`
unconditionally, and `_close_resources()` skips all service cleanup as a single unit
when `self._ctx.services` is `None`, without regard to `self._turn_active`.

## Scope

**In-Scope:**
- `_sigterm_handler()` (inside `AgentREPL.run()`): check `self._turn_active` before
  cancelling `self._input_coro`; still set `shutdown_requested` and `_shutdown_event`
  unconditionally so the idle input-wait loop wakes up.
- `_close_resources()`: make the two service-dependent cleanup calls
  (`svc.lifecycle.shutdown_all()`, `svc.http.aclose()`) independently guarded so a
  partially-populated `services` object (or a `None` sub-attribute) does not block the
  other cleanup call or the WAL checkpoint/backup that already run unconditionally above it.
- Add a log line in `_sigterm_handler()` noting the Unix (`add_signal_handler`) vs.
  Windows (`call_soon_threadsafe` / console-ctrl) dispatch difference.

**Out-of-Scope:**
- New signal types beyond SIGTERM/SIGINT.
- Subprocess termination behavior (`_spawned_subprocesses` handling in `run()`).
- WAL checkpoint/backup logic in `_close_resources()` (already unconditional, lines 332-374).
- Cross-platform signal registration mechanism itself (Unix `add_signal_handler` vs.
  Windows fallback) — only documenting the difference, not changing it.
- Introducing a new `scripts/agent/repl_signals.py` module (the plan lists this as only
  a "potentially" needed file under Affected Areas, not a committed implementation step;
  no such file exists in the codebase today and none is required to satisfy the stated
  Implementation Steps).

## Assumptions

1. Signal handlers execute on the same thread as the asyncio event loop on both the
   Unix (`loop.add_signal_handler`) and Windows (`loop.call_soon_threadsafe`) paths, so
   no additional locking is needed around `self._turn_active` / `shutdown_requested`.
2. `self._input_coro` is only meaningful while `_read_input()` is awaiting user input
   (i.e., while `self._turn_active` is `False`); once a turn starts, cancelling it is a
   no-op at best and could interfere with a completed future at worst.
3. Per UNK-02 in the source plan: the handler must not block waiting for the turn to
   finish — it sets the shutdown flag/event and returns immediately; `_repl_loop()`
   already checks `ctx.conv.shutdown_requested` after each turn and applies the
   `_GRACEFUL_TIMEOUT` wait via `asyncio.wait_for`.
4. `self._ctx.services` sub-attributes (`lifecycle`, `http`) are set together at startup
   and are not individually unset at runtime (per UNK-03), so the "more robust check" is
   about isolating failure/absence of one call from blocking the other, not about a
   currently-observed partial-population scenario.

## Design decisions

- Keep the fix minimal and localized to the two functions named in the plan; do not
  restructure `run()` or introduce a new module, since the plan's Affected Areas only
  lists a new file as "potentially" needed and the concrete Implementation Steps do not
  require one.
- Guard the input-coroutine cancellation with `if not self._turn_active:` rather than
  inverting existing control flow, to keep the diff small and the intent explicit at the
  call site.
- Split the single `if svc is not None:` block in `_close_resources()` into two
  independently-try/excepted calls, each re-checking `svc is not None` (or checking the
  narrower attribute), so a `None` `services` object — or a failure in one call — cannot
  prevent the other cleanup call from running.

## Alternatives considered

- Blocking the signal handler until the turn completes (rejected per UNK-02 resolution
  in the source plan — non-blocking is required so the handler returns immediately and
  lets `_repl_loop()` own the wait/timeout logic).
- Introducing a dedicated `repl_signals.py` abstraction module now (rejected: no such
  file exists today, the plan marks it as only a possibility, and the fix is small
  enough to stay inline in `repl.py` without a new module boundary).
- Using a `threading.Lock` / `asyncio.Lock` around `_turn_active` (rejected: per
  Assumption 1, handler and loop share the same thread, so no cross-thread mutation is
  possible; a lock would add complexity with no correctness benefit).

### Method

- Edit `_sigterm_handler()` (currently):
  ```python
  def _sigterm_handler() -> None:
      """Handle SIGTERM by cancelling input and setting shutdown flag."""
      self._ctx.conv.shutdown_requested = True
      if self._shutdown_event is not None:
          self._shutdown_event.set()
      # Cancel the current input coroutine to wake up the wait loop immediately
      if self._input_coro is not None and not self._input_coro.done():
          try:
              self._input_coro.cancel()
          except RuntimeError:
              pass  # Task already cancelled or not running
      logger.info("SIGTERM received; graceful shutdown initiated")
  ```
  Change to: only cancel `self._input_coro` when `not self._turn_active` (i.e., no turn
  is in flight, so any live `_input_coro` is genuinely the idle input wait); when a turn
  is active, skip cancellation and rely on `_repl_loop()`'s post-turn
  `shutdown_requested` check plus the `_GRACEFUL_TIMEOUT` wait in `asyncio.wait_for` to
  end the turn. The `shutdown_requested` flag and `_shutdown_event.set()` calls remain
  unconditional so the idle-wait branch of `_read_input()` still wakes immediately when
  no turn is active.
- Edit `_close_resources()`'s service-cleanup block (currently lines 375-387):
  ```python
  svc = self._ctx.services
  if svc is not None:
      try:
          await svc.lifecycle.shutdown_all()
      except Exception as e:
          errors.append(("lifecycle_shutdown", f"{type(e).__name__}: {e}"))
          logger.error("Lifecycle shutdown failed: %s", e)
      try:
          await svc.http.aclose()
      except Exception as e:
          errors.append(("http_close", f"{type(e).__name__}: {e}"))
          logger.error("HTTP client close failed: %s", e)
  ```
  Change to two separate `if svc is not None:` (or attribute-level) guards around each
  try/except so a future partial-availability scenario (or an exception raised while
  evaluating one branch) cannot skip the other call. Keep both calls under the existing
  outer `errors` list and logging pattern — no change to the WAL checkpoint/backup code
  above this block (lines 332-374), which already runs unconditionally regardless of
  `svc`.

### Details

- `self._turn_active` is already declared and maintained correctly elsewhere
  (`__init__` line 101 sets it `False`; `_repl_loop()` sets it `True` before dispatch at
  line 417 and resets it to `False` in the `finally` at line 431) — no changes needed to
  that lifecycle, only to how `_sigterm_handler()` reads it.
- Confirmed via `grep -n "_turn_active" scripts/agent/repl.py` that the signal-handler
  block (lines 597-652) currently contains no reference to `_turn_active` — the guard
  described above does not exist yet in the current source.
- The Windows fallback path (`call_soon_threadsafe(_sigterm_handler)`, lines 616-644)
  invokes the same `_sigterm_handler()` closure, so the `_turn_active` guard applies
  uniformly to both platforms; only the log message needs to note that Unix uses
  `loop.add_signal_handler` while Windows uses `call_soon_threadsafe` from a console
  control handler thread.

## Compatibility considerations

- No public API/CLI surface changes; `_sigterm_handler` and `_close_resources` are
  private methods on `AgentREPL`.
- Shutdown timing changes slightly: SIGTERM/SIGINT during an active turn no longer
  cancels `_input_coro` immediately (it was already effectively inert during an active
  turn since `_input_coro` only tracks the idle input wait, so behavioral impact is
  minimal in practice, but the explicit guard removes ambiguity).
- No change to on-disk formats, config schema, or `_ctx.services` construction.

## Security considerations

- No new external inputs or trust boundaries; both changes only affect internal control
  flow during shutdown.
- Splitting the service-cleanup try/except blocks preserves existing exception handling
  (`except Exception as e:` + logged, appended to `errors`) rather than widening or
  narrowing what is caught.
- No secrets, credentials, or user-supplied data touched by this change.

## Rollback considerations

- Change is localized to two methods in one file; revert via `git checkout` on
  `scripts/agent/repl.py` or a follow-up commit reverting the specific hunks.
- No data migration, schema, or persisted-state change — rollback has no residual effect.
- No feature flag needed given the small blast radius; standard code revert is sufficient.
