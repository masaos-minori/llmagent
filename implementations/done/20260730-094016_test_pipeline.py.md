## Goal

Make the RAG pipeline resilient to LLM-side failures by adding explicit fallback paths: MQE failure falls back to original query; rerank failure falls back to RRF-ranked results.

## Scope

**In-Scope:**
- Add comprehensive tests for both fallback scenarios

**Out-of-Scope:**
- Changes to SQLite schema
- Changes to embedding service
- Changes to RRF fusion logic
- Changes to augment formatting

## Assumptions

1. MQE fallback uses the original query unchanged — no attempt to retry or modify the query.
2. Rerank fallback applies deduplicate_chunks() + rag_top_k slicing to ctx.merged (same as _rerank_fallback()).
3. Fallback reasons are recorded as distinct strings: "mqe_exception" and "rerank_exception".
4. Both fallbacks should be logged at INFO level for observability.
5. The fallback behavior should apply only on LLM exceptions, not on configuration errors.

## Design decisions

- **Test isolation**: Mock LLM calls specifically to raise exceptions, ensuring tests don't depend on actual LLM availability.
- **Comprehensive coverage**: Test both individual fallback scenarios and their interaction with downstream stages.

## Alternatives considered

- **Integration tests only**: Could rely solely on integration tests. Rejected because unit tests provide faster feedback and clearer failure diagnostics.
- **Parametrized tests**: Could use pytest parametrization for both fallback scenarios. Rejected because separate test functions provide better error messages.

### Method

- Add new test functions for each fallback scenario
- Use pytest fixtures and mocks to simulate LLM failures

### Details

1. `test_mqe_exception_uses_original_query()`:
   - Configure MQE enabled
   - Mock `RagLLM.expand_queries()` to raise LLMException
   - Run pipeline
   - Verify ctx.queries == [original_query]

2. `test_mqe_exception_returns_fallback_status()`:
   - Same setup as above
   - Verify StageResult.status == "fallback" and StageResult.reason == "mqe_exception"

3. `test_mqe_exception_search_still_runs()`:
   - Same setup as above
   - Mock SearchStage to track which queries it received
   - Verify SearchStage ran with original query

4. `test_rerank_exception_uses_rrf_fallback()`:
   - Configure rerank enabled
   - Mock `RagLLM.cross_encoder_rerank()` to raise LLMException
   - Run pipeline
   - Verify ctx.reranked == deduplicate_chunks(ctx.merged[:cfg.rag_top_k])

5. `test_rerank_exception_returns_fallback_status()`:
   - Same setup as above
   - Verify StageResult.status == "fallback" and StageResult.reason == "rerank_exception"

6. `test_rerank_exception_augment_produces_output()`:
   - Same setup as above
   - Mock AugmentStage to verify it receives usable hits
   - Verify AugmentStage produced valid output

7. `test_diagnostics_distinguishes_disabled_from_fallback()`:
   - Configure MQE disabled, rerank enabled but failing
   - Get diagnostics
   - Verify mqe_status == "disabled" and rerank_status == "fallback"

8. `test_normal_path_unaffected_by_fallback_code()`:
   - Configure MQE and rerank normally (no exceptions)
   - Run pipeline
   - Verify results match expected values for normal operation
