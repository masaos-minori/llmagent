## Goal

Make signal handler operations consistent across platforms and ensure shutdown state remains synchronized regardless of turn activity status. Prevent race conditions between signal handlers and main loop that could cause inconsistent shutdown behavior.

## Scope

- Modify `_sigterm_handler()` to check and clear `self._turn_active` flag before setting shutdown flags
- Document behavioral differences between Unix (`add_signal_handler`) and Windows (`call_soon_threadsafe`) signal handlers
- Add guard in `_close_resources()` that verifies `self._turn_active` is False before skipping service-dependent cleanup
- Use atomic operations where possible for shared state updates

## Assumptions

- Signal handlers should always set shutdown flags regardless of turn activity status
- The `_turn_active` flag should be checked before setting shutdown flags to prevent double-shutdown scenarios
- Resource cleanup should complete even when services become unavailable during shutdown
- Atomic operations can be achieved using asyncio.Event instead of boolean flags for some shared state

## Design decisions

- **Deferred shutdown model**: When signal arrives during an active turn, defer shutdown until the turn completes. This prevents abrupt interruption of in-progress work while ensuring shutdown eventually happens.
- **Boolean flags over asyncio.Event**: Start with simple boolean flags for shared state. asyncio.Event adds complexity and may not be necessary since asyncio is single-threaded (no true race conditions within event loop).
- **Platform-aware documentation**: Document Unix vs Windows signal handler differences rather than trying to unify them. Each platform has different constraints that make unification impractical.
- **Force cleanup override**: In `_close_resources()`, if shutdown was requested but `_turn_active` is unexpectedly True, force cleanup completion rather than silently skipping.

## Alternatives considered

- **Immediate shutdown regardless of turn**: Would interrupt in-progress work, potentially causing data loss. Deferred approach preserves work integrity.
- **asyncio.Event for all shared state**: More robust but adds complexity. Boolean flags sufficient for single-threaded asyncio event loop.
- **Unified signal handler across platforms**: Different platforms have fundamentally different signal handling models. Better to document differences than force unification.
- **Signal masking during turns**: Could mask SIGTERM during turns and re-enable afterward. However, this would delay shutdown indefinitely if turn never completes.

       """Handle SIGTERM/SIGINT with deferred shutdown support."""
       # Always set shutdown flag regardless of turn status
       self.shutdown_requested = True
       
       # If turn is active, defer immediate shutdown
       if getattr(self, '_turn_active', False):
           if not hasattr(self, 'deferred_shutdown'):
               self.deferred_shutdown = True
           logger.info("Shutdown deferred until current turn completes")

           # Turn not active, proceed with immediate shutdown

## Compatibility considerations

- **Deferred shutdown timing**: Users may notice delayed shutdown when signals arrive during turns. Document this behavior clearly.
- **Boolean vs Event**: If upgrading to asyncio.Event, callers must change from `if self.shutdown_requested:` to `if self.shutdown_event.is_set():`.
- **Windows signal limitations**: Windows handlers must return immediately; blocking operations in signal handler will hang the process.

## Security considerations

- **Signal injection**: Ensure signal handlers don't expose sensitive state information
- **Denial of service**: Deferred shutdown could allow attacker to keep session alive indefinitely by sending signals during long turns
- **Resource exhaustion**: Force cleanup override prevents resource leaks during forced shutdown

## Rollback considerations

- **Quick rollback**: Remove deferred_shutdown logic and revert to immediate shutdown
- **Data impact**: No database changes; rollback does not affect persisted state
- **Configurable mode**: Consider adding environment variable to toggle deferred/immediate shutdown without code changes
