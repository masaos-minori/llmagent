## Goal

Evaluate whether to hoist `shell_server.py`'s local `shutil` import in `health()` to module level, aligning with the sibling `git_server.py` convention.

## Scope

- **In-Scope**:
  - Phase 1: Investigate whether other `*_server.py` files have the same inconsistent pattern
  - Phase 2: Decide Option A (hoist) or Option B (leave as-is) based on investigation findings
- **Out-of-Scope**:
  - Changes outside `scripts/mcp_servers/`
  - Modifying other import patterns beyond `shutil` in `health()` endpoints

## Assumptions

- `git_server.py` uses a top-level `import shutil` (confirmed by require doc)
- The `try/except (ImportError, OSError)` around `shutil` import is defensive boilerplate that adds complexity without meaningful benefit
- `shutil` is a stdlib module that cannot fail to import under normal circumstances

## Design decisions

- If Option A (hoist), remove the `try/except (ImportError, OSError)` wrapper entirely — it provides no practical value for a stdlib import
- If Option B (leave as-is), add a comment explaining why the defensive pattern is retained despite theoretical impossibility

## Alternatives considered

- Leave as-is (Option B) — acceptable if the defensive pattern serves a documented purpose
- Hoist and add characterization test (Option A) — preferred if no evidence of intentional degradation exists

## Compatibility considerations

- No runtime behavior change if Option A (stdlib import cannot fail)
- Import order must not introduce circular dependencies
