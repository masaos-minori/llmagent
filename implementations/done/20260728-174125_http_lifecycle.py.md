## Goal

In `HttpServerLifecycleManager.start()`, when `os.getpgid(proc.pid)` raises `OSError`, terminate (and, if needed, kill) the spawned subprocess before dropping its tracking entries, so a live process can never be silently orphaned outside `_http_procs`/`_http_pgids`.

**In-Scope:**

- Adding a bounded terminate/kill attempt on `proc` directly (no pgid is available in this branch) before popping `_stderr_files` / `_stderr_log_paths` / `_http_procs` / `_http_pgids`.
- Adding a follow-up log line reporting the termination outcome (already exited / terminated / force-killed / still alive after kill).
- Updating the existing test `TestStartHttpSubprocess.test_getpgid_failure_cleans_up_resources` (`tests/test_lifecycle.py:346-366`) so it also asserts the subprocess was terminated, not just that bookkeeping was cleared.

## Assumptions

1. `_terminate_with_timeout(proc, server_key, timeout=3.0)` (lines 111-146) is safe to call directly in the `except OSError:` branch: it reads `self._http_pgids.get(server_key)`, and since the failing line is the very assignment `self._http_pgids[server_key] = os.getpgid(proc.pid)`, `server_key` is guaranteed to be absent from `_http_pgids` at this point — so the method's `pgid is None` branch (plain `proc.terminate()` / `proc.kill()`) executes, which is exactly the behavior the requirement asks for. Reusing this helper avoids duplicating the terminate/escalate logic inline. Falsifiable: if any future code path populates `_http_pgids[server_key]` before this line moves, this assumption breaks.
2. A default timeout of 3.0s (the existing default of `_terminate_with_timeout`) is an acceptable bound for this branch; the requirement does not specify a different value and no caller currently threads a custom timeout through `start()`.
3. `self._http_procs[server_key] = proc` (line 256) is only reached on the non-exception path, i.e. `_http_procs` never contains `server_key` while this except-branch runs — confirmed by reading the surrounding code — so no extra pop-guard is needed there beyond what already exists.
4. The requirement's "before popping" ordering only requires termination to happen before the four `.pop()` calls in this branch; it does not require blocking `start()`'s return beyond the existing bounded timeout.

## Design decisions

- Reuse `_terminate_with_timeout(proc, server_key)` instead of duplicating terminate/escalate logic inline.
- After the termination attempt, inspect `proc.poll()` to compose a follow-up log line reporting the outcome.
- Update existing test to assert termination was attempted, using the `side_effect` mock pattern to avoid real-timeout waits.

## Alternatives considered

- Duplicate terminate/wait/kill inline in the `except OSError:` branch. Rejected — `_terminate_with_timeout` already operates on `proc` directly whenever no pgid is registered (verified lines 120-127, 134-141), so calling it directly is behaviorally identical to a hand-written duplicate and is DRY.

```python
except OSError as e:

        try:
            stderr_file.close()
        except Exception:
            pass

    self._http_pgids.pop(server_key, None)
    raise RuntimeError(...) from e

# After (fixed) — scripts/agent/http_lifecycle.py:242-255
except OSError as e:
    logger.warning("Lifecycle: getpgid() failed for %r pid=%d; cleaning up", server_key, proc.pid)
    # Terminate the subprocess since we have no pgid to track it.
    await self._terminate_with_timeout(proc, server_key)
    # Report termination outcome
    poll_result = proc.poll()
    if poll_result is None:
        logger.warning("Lifecycle: subprocess %r (pid=%d) still alive after terminate/kill; will be orphaned", server_key, proc.pid)
    elif poll_result == 0:
        logger.info("Lifecycle: subprocess %r (pid=%d) already exited cleanly", server_key, proc.pid)
    else:
        logger.info("Lifecycle: subprocess %r (pid=%d) terminated with exit code %d", server_key, proc.pid, poll_result)
    # Close stderr file handle if open
    stderr_file = self._stderr_files.pop(server_key, None)
    if stderr_file is not None:
        try:
            stderr_file.close()
        except Exception:
            pass
    self._stderr_log_paths.pop(server_key, None)
    self._http_procs.pop(server_key, None)
    self._http_pgids.pop(server_key, None)
    raise RuntimeError(...) from e
```

Exception path behavior:
- On `OSError` from `os.getpgid()`: subprocess is terminated (or killed after timeout), then tracking entries are cleaned up.
- If subprocess survives terminate/kill: logged as warning, but tracking entries are still dropped (orphaned process).
- If subprocess exits cleanly after terminate: logged as info.
