## Assumptions
- Verified on 2026-11-06 (Step 3a): `_cmd_compare` runs `git show {old_rev}:{old_src}` with `capture_output=True, text=True, check=True` in the process working directory, so a failure raises `CalledProcessError` uncaught; the file has no root constant and no bootstrap; `subprocess` is used only there. The tool is called by path from skills (`module_nodes.py measure|extract|compare`), not from pre-commit or CI.
- Plan Gap closed by amendment (2026-11-06, fallout): `tests/tools/test_module_nodes.py` replaces the `module_nodes.subprocess` attribute with a `types.SimpleNamespace` in the autouse `_no_real_git` fixture and in `_fake_git`. Once the call goes through the helper that attribute no longer exists (or no longer intercepts), so the fixture would fail with `AttributeError` or let a real git run. The test file is therefore a companion of this document: it is a row of this Plan under `tests/`, only this row names it in `Related Tests`, and no design decision is needed beyond the seam below.
- Overlap judgment: the `toolwrite001` Plan also targets this file (`extract` and `--dry-run`, different functions) and depends on this Plan's phase 3, so it is a sequencing dependency, compatible.

## Design decisions
- Import by name (`from tools._tool_common import run_git`) so the seam is `module_nodes.run_git`, the correct patch target per `tools/check_mock_patch_targets.py` (patch where the symbol is used).
- Call `run_git("show", f"{args.old_rev}:{args.old_src}", check=True)` with `cwd` left as `None` (the tool relies on the caller's directory).

## Alternatives considered
- Patch `tools._tool_common.subprocess` in the test: rejected, it patches the origin module while the tool imports the symbol at module level, which the mock-patch checker reports as ineffective.
