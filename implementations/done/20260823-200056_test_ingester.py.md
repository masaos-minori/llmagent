## Goal
In `tests/rag/ingestion/test_ingester.py`: add a mandatory `fetched_at: str` field to
the file's `_ChunkSpec` fixture dataclass (the source of every on-disk chunk-JSON
fixture this file writes), so every fixture the file already produces carries a
`fetched_at` value once `ingester.py`'s `_get_or_create_document()` reads
`first_data["fetched_at"]` as a mandatory key instead of `.get("fetched_at")`; and add
one new test asserting the `documents` row's `fetched_at` column is always populated
from that source value after `ingest_url_group()`, not left to the schema's
`DEFAULT (datetime('now'))`.

## Scope
- In scope: `tests/rag/ingestion/test_ingester.py` only — the `_ChunkSpec` dataclass,
  and one new test method in `TestIngestUrlGroup`.
- Out of scope: `scripts/rag/ingestion/ingester.py`'s `first_data.get("fetched_at")` ->
  `first_data["fetched_at"]` change and its `_get_or_create_document()` /
  `_insert_document()` / `_commit_url_transaction()` signature widening (own
  implementation document; this file's fixture change depends on it landing, since a
  chunk JSON fixture without `fetched_at` would otherwise still work today via the
  `.get()` fallback); `scripts/rag/models_data.py`'s `ChunkDocument.fetched_at` field
  (own implementation document; not constructed anywhere in this file — this file
  writes raw JSON dicts via `dataclasses.asdict(_ChunkSpec)`, not `ChunkDocument`
  instances); `tests/rag/ingestion/test_rag_ingester.py` (explicitly covers
  `_read_chunk_json()` field preservation per this file's own module docstring; own
  implementation document).

## Assumptions
- Confirmed by reading the full file: this file never constructs `ChunkDocument`
  directly. Every chunk fixture is built by `_write_chunk()`, which serializes
  `dataclasses.asdict(spec)` (a `_ChunkSpec` instance) straight to a `.json` file on
  disk; `ingester.py`'s `_read_chunk_json()` / `_read_chunk_json_raw()` then reads that
  file back as a plain dict (`ChunkJsonRaw`-shaped, but read at runtime with no
  dataclass validation). Adding `fetched_at` to `_ChunkSpec` is therefore sufficient to
  make every fixture in this file satisfy `first_data["fetched_at"]` once that line's
  own implementation change lands — no other fixture-construction path exists in this
  file to update.
- Confirmed by `grep -n "fetched_at" tests/rag/ingestion/test_ingester.py`: exactly one
  existing reference, the `_SCHEMA_SQL` constant's
  `fetched_at TEXT NOT NULL DEFAULT (datetime('now'))` column definition — matching the
  plan's Affected-areas count for this file. No test currently asserts on a
  `fetched_at` value.
- `_ChunkSpec` is a fully-defaulted `@dataclasses.dataclass(frozen=True)` (every field
  already carries a default value), so adding one more defaulted field does not risk
  the "non-default field after a defaulted field" `TypeError` that applies to
  `ChunkDocument` in `scripts/rag/models_data.py`; field position within `_ChunkSpec`
  is a style choice, not a correctness constraint, for this specific dataclass.
- `_ChunkSpec` fields are consumed positionally-by-name only (via
  `dataclasses.asdict()` then `orjson.dumps()`, and via
  `dataclasses.replace(_DEFAULT_CHUNK, ...)` with keyword arguments at every call
  site in this file) — confirmed by reading every `dataclasses.replace(...)` call in
  the file; none pass `_ChunkSpec` fields positionally, so inserting a new field
  anywhere in the dataclass body cannot break an existing call site.
- `DocumentRow`/the raw `documents` table row exposes `fetched_at` as a plain column
  already selectable via `conn.execute("SELECT fetched_at FROM documents ...")` against
  this file's own `_SCHEMA_SQL`-backed in-memory connection — no new schema column is
  needed for the new test to read it back.

## Design decisions
- Add `fetched_at: str = "2026-01-01T00:00:00Z"` as a new field on the shared
  `_ChunkSpec` dataclass (used by `_DEFAULT_CHUNK` and every
  `dataclasses.replace(_DEFAULT_CHUNK, ...)` call in the file) rather than editing each
  of the many individual chunk-fixture call sites — because every call site already
  derives from `_DEFAULT_CHUNK` via `dataclasses.replace()`, a single new defaulted
  field on the dataclass propagates `fetched_at` into every existing fixture in this
  file with no other line changed.
- Add exactly one new test, in `TestIngestUrlGroup` (the class already covering
  end-to-end document + chunk insertion via `ingest_url_group()`), asserting the
  inserted `documents.fetched_at` equals the fixture's supplied value — this directly
  exercises the plan's target behavior ("INSERT always includes the `fetched_at`
  column", "populated from the source value") through the same public entry point
  (`ingest_url_group()`) every other test in that class already uses, rather than
  reaching into `_insert_document()` directly.
- Use a fixture value distinguishable from the schema's own
  `DEFAULT (datetime('now'))` format (an explicit UTC `...Z`-suffixed literal, not a
  `datetime('now')`-shaped string) so the new test cannot pass by coincidence if the
  `DEFAULT` clause were still silently in effect for some code path.

## Alternatives considered
- Passing `fetched_at` explicitly at each `dataclasses.replace(_DEFAULT_CHUNK, ...)`
  call site across the file instead of giving `_ChunkSpec` a default — rejected: this
  file has dozens of `_write_chunk()`/`dataclasses.replace()` call sites across two
  test classes; a shared default on the dataclass is the same fix with one field
  instead of dozens of edited call sites, and matches how the file already handles
  every other fixture field (`schema_version`, `artifact_type`, `created_by`, `etag`,
  `last_modified`) via defaults on `_ChunkSpec`.
- Constructing a `ChunkDocument` instance somewhere in this file to more directly
  mirror the plan's DTO description — rejected: this file never uses `ChunkDocument`
  today (it writes raw dicts to disk and lets `ingester.py` read them back), and
  introducing one now would be an unrelated architectural change to a test file whose
  job is to exercise `ingester.py`'s JSON-reading path, not `pipeline_utils.py`'s
  `ChunkDocument`-constructing path (that path's own tests already live in this
  module's sibling `test_rag_ingester.py`, per this file's own docstring).
- Skipping the new column-population test on the reasoning that every existing test in
  `TestIngestUrlGroup` will incidentally exercise the INSERT with a non-null
  `fetched_at` once the fixture default exists — rejected: none of the existing tests
  in that class assert on `fetched_at`'s stored value, so nothing would fail if
  `_insert_document()`'s deleted `cursor2` fallback branch (or an equivalent omission)
  regressed; the plan's own Validation plan row explicitly calls for this assertion.

## Implementation
### Target file
`tests/rag/ingestion/test_ingester.py`

### Procedure
1. In the `_ChunkSpec` dataclass definition, add a new field:
   `fetched_at: str = "2026-01-01T00:00:00Z"`. Position it after `content` (mirroring
   where the source plan places the equivalent field in `ChunkDocument` — see the
   `models_data.py` implementation document — for readability consistency across the
   two files, though `_ChunkSpec`'s field order carries no correctness constraint of
   its own per Assumptions above).
2. No change to `_write_chunk()`, `_make_ingester()`, `_fake_embed_resp()`, or any
   existing `dataclasses.replace(_DEFAULT_CHUNK, ...)` call site — the new field's
   default value flows through all of them automatically.
3. In `TestIngestUrlGroup`, add a new test method, e.g.
   `test_inserts_document_with_correct_fetched_at`: write a chunk fixture via
   `_write_chunk()` using `dataclasses.replace(_DEFAULT_CHUNK, fetched_at="2026-03-15T09:00:00Z")`
   (a value distinct from `_ChunkSpec`'s own default, so the assertion cannot pass by
   coincidentally matching the dataclass default), call `ingester.ingest_url_group(...)`
   the same way `test_inserts_document_with_correct_chunking_strategy` does, then
   `conn.execute("SELECT fetched_at FROM documents").fetchone()` and assert the row's
   `fetched_at` equals `"2026-03-15T09:00:00Z"`.

### Method
- Pure test-fixture edit plus one additive test method; no new test infrastructure,
  no new schema, no new mock/patch pattern beyond what `TestIngestUrlGroup`'s existing
  tests already use (`patch.object(ingester._client, "post", ...)`,
  `patch("rag.ingestion.ingester.SQLiteHelper", return_value=fake_db)`).

### Details
- Place the new test directly after
  `test_inserts_document_with_correct_chunking_strategy` in `TestIngestUrlGroup`,
  since it follows the identical `_setup()` / `_write_chunk()` / `ingest_url_group()` /
  `conn.execute(...)` shape and reads naturally as a sibling assertion on the same
  inserted row.
- Do not assert on `fetched_at`'s value in every other existing test in the file —
  only the one new test needs to; adding a blanket assertion to unrelated tests
  (chunk-index tests, retry tests, partial-failure tests) would couple those tests'
  pass/fail to a fixture field their own names and purposes do not concern.
- Re-run `rg -n "dataclasses\.replace\(_DEFAULT_CHUNK" tests/rag/ingestion/test_ingester.py`
  at implementation time to confirm no call site passes `_ChunkSpec` fields
  positionally (which would break if a new field changed positional order) — per
  Assumptions above, none currently do, but this is a fast, cheap re-check before
  editing.

## Rollback considerations
- Revert this file's diff together with `scripts/rag/ingestion/ingester.py`'s
  `first_data.get("fetched_at")` -> `first_data["fetched_at"]` change (own
  implementation document) as one unit — if `ingester.py` reverts to `.get(...)`
  (tolerating a missing key) while this file's fixtures still include `fetched_at`,
  nothing breaks (harmless extra key); but if this file's `_ChunkSpec.fetched_at`
  field is reverted while `ingester.py` still does the mandatory-subscript read, every
  test in this file that reaches `_get_or_create_document()` fails with `KeyError:
  'fetched_at'` — so keep both changes together to avoid that asymmetric failure mode.
- No schema/data migration is involved (in-memory SQLite, recreated per test via
  `_make_db()`); rollback is a pure code revert with no cleanup step.
