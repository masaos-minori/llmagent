## Goal

Extend RAG consistency checks to detect document-level and URL-level integrity problems: documents with zero chunks, chunks without vector rows, duplicate chunk_index values, and URL-level mismatches between chunks/vectors/FTS.

## Scope

**In-Scope:**
- Add `documents_without_chunks_count` — documents that have no chunks
- Add `chunks_without_vec_count` — chunks without corresponding vector rows
- Add `duplicate_chunk_index_count` — duplicate chunk_index values within the same document
- Add URL-level counts: document URL, chunk count, vector count, FTS count per URL
- Include affected doc_ids and URLs where possible
- Update `summarize_issues()` with clear severity and repair guidance for new checks
- Update `is_consistent()` to consider new checks

**Out-of-Scope:**
- Adding UNIQUE(doc_id, chunk_index) constraint (deferred to later migration)
- Changes to SQLite schema
- Changes to ingestion logic itself

## Assumptions

1. A document is considered "without chunks" only if it exists in the documents table but has no corresponding rows in chunks.
2. A chunk is considered "without vector" if it exists in chunks but has no row in chunks_vec.
3. Duplicate chunk_index means the same chunk_index value appears multiple times within the same doc_id.
4. URL-level inconsistency means a URL has different chunk counts across chunks/chunks_vec/chunks_fts tables.
5. All new checks should use read-only queries (no writes).

## Design decisions

- **Strict is_consistent()**: Make `is_consistent()` stricter — all checks must pass for True. This prevents silent degradation from previously undetected issues.
- **Read-only queries**: All new checks use read-only queries (no writes), consistent with existing consistency check patterns.
- **LIMIT 10 for affected identifiers**: Follow existing convention of limiting affected identifiers to 10 to avoid excessive memory usage on large datasets.
- **Severity classification**: Use `[CRITICAL]` for data integrity issues (orphan vectors, duplicate chunks) and `[WARNING]` for informational issues (documents without chunks, URL mismatches).

## Alternatives considered

- **Lenient is_consistent()**: Keep is_consistent() lenient by only checking original conditions. Rejected because silently ignoring new issues defeats the purpose of adding them.
- **No LIMIT on affected identifiers**: Could return all affected identifiers. Rejected because this could cause excessive memory usage on large datasets.
- **Separate consistency report types**: Could create separate reports for document-level vs URL-level issues. Rejected because a unified report provides better operational visibility.

### Procedure

#### Phase 2: Add document-level consistency checks

1. In `RagConsistencyChecker.check()`, add three new queries after existing orphan-vector and FTS-gap checks:

```python
# Documents without chunks
docs_without_chunks = db.execute(
    "SELECT COUNT(*) FROM documents WHERE doc_id NOT IN (SELECT DISTINCT doc_id FROM chunks)"
)[0][0]

# Chunks without vectors
chunks_without_vec = db.execute(
    "SELECT COUNT(*) FROM chunks WHERE chunk_id NOT IN (SELECT chunk_id FROM chunks_vec)"
)[0][0]

# Duplicate chunk_index within same doc_id
dup_chunk_indices = db.execute(
    "SELECT doc_id, chunk_index FROM chunks GROUP BY doc_id, chunk_index HAVING COUNT(*) > 1"
).fetchall()
```

2. Collect affected identifiers (LIMIT 10):
   ```python
   affected_docs_without_chunks = db.execute(
       "SELECT doc_id FROM documents WHERE doc_id NOT IN (SELECT DISTINCT doc_id FROM chunks) LIMIT 10"
   ).fetchall()

   affected_chunks_without_vec = db.execute(
       "SELECT chunk_id FROM chunks WHERE chunk_id NOT IN (SELECT chunk_id FROM chunks_vec) LIMIT 10"
   ).fetchall()

   affected_dup_chunk_indices = [(row[0], row[1]) for row in dup_chunk_indices[:10]]
   ```

#### Phase 3: Add URL-level consistency checks

1. Query URL → chunk count mapping:
   ```python
   url_chunk_counts = db.execute(
       "SELECT d.url, COUNT(c.chunk_id) FROM documents d LEFT JOIN chunks c ON d.doc_id = c.doc_id GROUP BY d.url"
   ).fetchall()
   ```

2. Query URL → vector count mapping:
   ```python
   url_vec_counts = db.execute(
       "SELECT d.url, COUNT(cv.chunk_id) FROM documents d LEFT JOIN chunks c ON d.doc_id = c.doc_id LEFT JOIN chunks_vec cv ON c.chunk_id = cv.chunk_id GROUP BY d.url"
   ).fetchall()
   ```

3. Query URL → FTS count mapping:
   ```python
   url_fts_counts = db.execute(
       "SELECT d.url, COUNT(cf.rowid) FROM documents d LEFT JOIN chunks c ON d.doc_id = c.doc_id LEFT JOIN chunks_fts cf ON c.chunk_id = cf.rowid GROUP BY d.url"
   ).fetchall()
   ```

4. Compare mappings and identify URLs where counts differ:
   ```python
   url_level_mismatches = {}
   for url, chunk_count in url_chunk_counts:
       vec_count = dict(url_vec_counts).get(url, 0)
       fts_count = dict(url_fts_counts).get(url, 0)
       if chunk_count != vec_count or chunk_count != fts_count:
           url_level_mismatches[url] = {
               "chunk_count": chunk_count,
               "vec_count": vec_count,
               "fts_count": fts_count,
           }
   ```

5. Store mismatched URLs with their counts in `url_level_mismatches` dict.

#### Phase 4: Update summarize_issues()

1. Add `[WARNING]` issue for documents_without_chunks_count > 0 with repair guidance:
   ```python
   if report.documents_without_chunks_count > 0:
       issues.append(f"[WARNING] {report.documents_without_chunks_count} documents without chunks")
       if report.affected_docs_without_chunks:
           issues.append(f"  Affected doc_ids: {report.affected_docs_without_chunks}")
   ```

2. Add `[CRITICAL]` issue for chunks_without_vec_count > 0 with repair guidance:
   ```python
   if report.chunks_without_vec_count > 0:
       issues.append(f"[CRITICAL] {report.chunks_without_vec_count} chunks without vector rows")
       if report.affected_chunks_without_vec:
           issues.append(f"  Affected chunk_ids: {report.affected_chunks_without_vec}")
   ```

3. Add `[CRITICAL]` issue for duplicate_chunk_index_count > 0 with repair guidance:
   ```python
   if report.duplicate_chunk_index_count > 0:
       issues.append(f"[CRITICAL] {report.duplicate_chunk_index_count} duplicate chunk_index values")
       if report.affected_duplicate_chunk_indices:
           issues.append(f"  Affected (doc_id, chunk_index): {report.affected_duplicate_chunk_indices}")
   ```

4. Add `[WARNING]` issue for URL-level mismatches with repair guidance:
   ```python
   if report.url_level_mismatches:
       issues.append(f"[WARNING] {len(report.url_level_mismatches)} URLs with chunk/vector/FTS count mismatches")
       for url, counts in list(report.url_level_mismatches.items())[:10]:
           issues.append(f"  {url}: chunks={counts['chunk_count']}, vecs={counts['vec_count']}, fts={counts['fts_count']}")
   ```

#### Phase 5: Update is_consistent()

1. Add new conditions:
   ```python
   def is_consistent(self) -> bool:
       return (
           self.orphan_vectors == 0
           and self.fts_gaps == 0
           and self.documents_without_chunks_count == 0
           and self.chunks_without_vec_count == 0
           and self.duplicate_chunk_index_count == 0
           and (self.url_level_mismatches is None or not self.url_level_mismatches)
       )
   ```

## Compatibility considerations

- New fields have default values (0 or None) to maintain backward compatibility with existing RagConsistencyReport consumers.
- Making `is_consistent()` stricter may break existing callers that expect lenient behavior — review callers before deploying.
- The new URL-level aggregation queries are read-only and follow existing query patterns.

## Security considerations

- No security implications from this change — all operations are read-only queries.
- No new secrets or credentials introduced.

## Rollback considerations

- If the strict `is_consistent()` breaks existing callers, revert to lenient mode by removing the new conditions.
- Removing the URL-level checks is straightforward — delete the three aggregation queries and the comparison logic.
- The new fields can be removed from RagConsistencyReport if they cause serialization issues.
