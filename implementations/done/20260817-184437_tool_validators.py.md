## Goal

Narrow `register_validator`'s Callable parameter type from `dict[str, Any]` to `dict[str, object]` to align with the existing docstring example.

## Scope

- **In-Scope**:
  - Phase 1: Verify no external module defines a validator via `@register_validator`; confirm all 4 existing validators use `isinstance` narrowing
  - Phase 2: Change `register_validator`'s Callable annotation and `_VALIDATORS`'s value-type annotation
  - Phase 3: Verify type-checking passes for all validators
- **Out-of-Scope**:
  - Runtime behavior changes (pure type annotation change)
  - Changes outside `scripts/mcp_servers/tool_validators.py`

## Assumptions

- The docstring in `tool_validators.py` uses `dict[str, object]` as an example, which is the intended convention
- All 4 existing validators (`_validate_git_commit`, `_validate_git_push`, `_validate_trigger_workflow`, `_validate_shell_run`) use `isinstance` narrowing internally before accessing typed values
- `Any` was used out of convenience, not necessity

## Design decisions

- Use `object` instead of `Any` to enforce stricter typing — callers must narrow before accessing specific types
- Align with the existing docstring example which already uses `dict[str, object]`

## Alternatives considered

- Keep `Any` — rejected because the goal is stricter static checking
- Use a custom Protocol — overkill for this simple case; `object` is sufficient

## Compatibility considerations

- No runtime behavior change — pure type annotation update
- Validators that access dict values without prior `isinstance` checks may fail type-checking under `object`
