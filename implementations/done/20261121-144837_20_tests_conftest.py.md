## Goal

Make the test fixture construct `DbConfig` through the injected-configuration signature instead of letting it load `agent.toml` (REQ-003, REQ-004, AC-004).

## Scope
**Release unit**: RU-2

## Assumptions
- `tests/conftest.py` is a target row, not a companion: it is named by no other row, so it keeps this document.
- The isolation-root behaviour is unchanged: the fixture still creates the same schemas in the same place.

## Design decisions
- The fixture supplies the mapping it already knows about the isolation root; it does not read the production `config/agent.toml`.
- `build_db_config()` keeps its name, so patch targets in `tests/db/` continue to resolve (the Plan's Design D3).

## Alternatives considered
- Keep the fixture's implicit load: rejected by AC-004, which forbids a config load inside `scripts/db/` and makes the fixture the place the argument must be supplied.

## Implementation
### Target file
`tests/conftest.py`
### Procedure
- Change the `build_db_config()` call (line 105) to the injected-configuration signature defined by Plan row 8.
- Keep the `create_workflow_schema()` and `db_tools.ensure()` order unchanged.

### Method
- Build the mapping from the isolation-root paths the fixture already uses; no new fixture, no new helper.

### Details
- Verified 2026-11-21: the fixture uses `cfg.session_db_path` and `cfg.rag_db_path` for schema creation, so the values it supplies must be the isolation-root paths, not the production paths.
- Finding (2026-11-22, execution): the Method as written ("build the mapping from the isolation-root paths the fixture already uses") was not the shape implemented. `_provision_databases()` calls `ConfigLoader().load("agent.toml")`, which resolves to the isolated config copy the fixture already created, and passes that mapping to `build_db_config()`; the isolation-root paths come from `DbConfig.__post_init__` redirecting the `/opt/llm/db/` values to the isolation root. The design decision's intent holds — the production file is not read — but the mapping is loaded, not hand-built, which keeps the fixture aligned with the shipped keys instead of duplicating them.
- Finding (2026-11-22, execution): the Design decision that `build_db_config()` keeps its name so `tests/db/` patch targets continue to resolve is no longer relied on. No `tests/db/` file patches it any more (rows 15 and 26 removed those targets); the fixture passes the typed configuration to `create_schema.create_*_schema(cfg)`. The name is kept only because the typed builder is still the place a supplied mapping becomes a `DbConfig`.
