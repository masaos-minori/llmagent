# Implementation Procedure: Phase 8 — Validation

## Goal

Run full validation suite: lint, type check, architecture, security, coverage, pre-commit, and integration tests.

## Scope

### In-Scope
- Run `uv run ruff format scripts/ && uv run ruff check scripts/ --fix`
- Run `uv run mypy scripts/` — fix type errors
- Run `PYTHONPATH=scripts uv run lint-imports`
- Run `uv run bandit -r scripts/ -c pyproject.toml`
- Run `uv run pytest tests/rag/ingestion/ -v`
- Run `uv run pytest tests/integration/test_ingestion_e2e.py -v`
- Run `uv run pre-commit run --all-files`

### Out-of-Scope
- Changes to cache invalidation logic beyond using cached URL
- Database schema changes
- Changes to `_commit_url_transaction()` (Phase 3)

## Assumptions

1. All previous phases completed successfully
2. Test suite passes before changes (baseline established)
3. Pre-commit hooks configured correctly
4. Coverage thresholds defined in CI configuration

## Design decisions

- Run lint first — fixes formatting issues automatically
- Run type check second — catches static errors early
- Run architecture check third — ensures import structure preserved
- Run security scan fourth — catches potential vulnerabilities
- Run unit tests fifth — verifies behavioral correctness
- Run integration tests sixth — verifies end-to-end behavior
- Run pre-commit seventh — final quality gate

## Alternatives considered

- Running all validations in parallel: rejected because failures cascade and make debugging harder
- Skipping lint/type check: rejected because they catch errors that would cause test failures anyway
- Running only unit tests: rejected because integration tests catch edge cases not covered by unit tests

### Details

**Key validation steps**:
1. Format: `uv run ruff format scripts/`
2. Lint: `uv run ruff check scripts/ --fix`
3. Type check: `uv run mypy scripts/`
4. Architecture: `PYTHONPATH=scripts uv run lint-imports`
5. Security: `uv run bandit -r scripts/ -c pyproject.toml`
6. Unit tests: `uv run pytest tests/rag/ingestion/ -v`
7. Integration tests: `uv run pytest tests/integration/test_ingestion_e2e.py -v`
8. Pre-commit: `uv run pre-commit run --all-files`

**Critical insight**: Each step must pass before proceeding to the next. If a step fails, fix the errors and re-run ALL previous steps — errors can cascade across validation stages.

**Thread safety**: Since workers no longer hold DB connections, there's no risk of connection conflicts. The main thread handles all DB writes sequentially.

**Memory consideration**: `PreparedChunk.embedding_blob` stores raw bytes — memory pressure for large documents is acceptable since URLs are processed sequentially; memory is freed after commit.

## Compatibility considerations

- Existing callers of `_embed_and_store()` expect `(bool, bool)` tuple — must be updated in Phase 4
- Test mocks that patch `_embed_and_store()` must return `PreparedChunk | IngestionFailureReason` instead
- `n_embed_failed` field semantics change: from "individual chunk embedding failure count" to "URL-group-level embedding failure indicator" (all-or-nothing due to atomicity)

## Security considerations

No security implications. No new credentials or secrets introduced. HTTP client usage unchanged.

## Rollback considerations

If this phase causes issues:
- Revert `_embed_and_store()` to original implementation
- Restore `SQLiteHelper` instantiation in worker threads
- Restore `(bool, bool)` return type
- No database state changes (workers already had independent commits)
