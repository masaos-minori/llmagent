# Implementation Procedure: scripts/agent/http_lifecycle.py

## Goal
Add an optional `shutdown_event` parameter to `HttpServerLifecycleManager.start()` and race its
internal 0.5s health-poll-loop sleep against it, so a shutdown signal fired while a server is
mid-health-poll aborts within roughly one poll interval instead of waiting up to the full
`cfg.startup_timeout_sec` (default 30s).

## Scope
- In scope: `HttpServerLifecycleManager.start()` (current lines 286-464), specifically the
  poll loop (`while time.monotonic() < deadline:`, current lines 418-448) and its
  `await asyncio.sleep(0.5)` (current line 448).
- Out of scope: `restart()` (current lines 466-481) — does not accept or forward
  `shutdown_event`; `shutdown_all()` (current line 495+) and its SIGINT-absorption behavior;
  the `_terminate_with_timeout()` / `_wait_exited()` helpers; all pre-poll-loop subprocess-spawn
  logic in `start()` (current lines 296-409, e.g. command whitelist checks, env filtering,
  `getpgid()` handling) — unchanged.

## Assumptions
- All 10 currently configured MCP servers use `startup_mode="subprocess"` + `transport="http"`
  with the default 30s `startup_timeout_sec` (per the source plan's Assumption 3) — this is why
  the plan expands scope into this file despite the underlying requirement listing it as
  conditional: without this change, worst-case shutdown latency during an in-progress poll is
  bounded by up to 30s, not "a few seconds."
- `self._http_procs[server_key] = proc` is already set (current line 409) *before* the poll
  loop begins — confirmed by reading lines 280-464 in this session. A shutdown fired mid-poll
  therefore still leaves the subprocess reachable through `_http_procs` for the caller's
  `shutdown_all()` rollback (once the sibling `startup.py` fix's unconditional-rollback change
  has landed, per `implementations/20260804-145038_startup.py.md`) — no separate termination
  call is added inside `start()`'s interruption path itself.
- `restart()` (current line 481: `await self.start(server_key, cfg)`, no `shutdown_event`
  argument) continues to work unchanged once `start()`'s new parameter is added with a
  `None` default — `restart()` intentionally does not thread `shutdown_event` through, since it
  is a runtime operation outside the startup-interruption scope of this plan.

## Design decisions
- Add `shutdown_event: asyncio.Event | None = None` as a new keyword parameter on `start()`,
  matching the additive, default-`None` pattern used in `StartupOrchestrator.__init__()`
  (companion `implementations/20260804-151105_startup.py.md`).
- Implement the poll-loop race with a private, method-local helper mirroring
  `StartupOrchestrator._interruptible_sleep()`'s exact pattern, kept as a **separate** copy in
  this class rather than extracted into one shared cross-module function — a 6-line helper does
  not justify adding a new coupling between `agent.startup` and `agent.http_lifecycle`; this
  mirrors how `_repl_loop()`'s original race pattern was itself inlined, not extracted, before
  this plan touched anything.
- On shutdown-fire inside the poll loop, raise the existing `HttpStartupError` (used elsewhere
  in this method for both "exited early" and "timeout" failures) with a `StartupFailure` whose
  `reason="shutdown requested"` — callers that already catch `HttpStartupError` need no new
  `except` clause.

## Alternatives considered
- Accept the un-raced 0.5s poll loop as a "few seconds" latency bound, per the underlying
  requirement's own fallback option: rejected — Assumption above (all 10 servers at the 30s
  default, no override) falsifies that this bound is actually "a few seconds"; it is up to the
  full `startup_timeout_sec`.
- Directly terminate the subprocess inside `start()`'s interruption branch (instead of letting
  the caller's `shutdown_all()` rollback handle it): rejected — `_http_procs[server_key]` is
  already populated (Assumption above), so the existing rollback path already reaches this
  process; adding a second termination call here would risk a double-terminate race with
  `shutdown_all()`.

## Implementation

### Target file
`scripts/agent/http_lifecycle.py`

### Procedure
1. Add `shutdown_event: asyncio.Event | None = None` to `start()`'s signature (current lines
   286-290).
2. Add a private helper (e.g. `async def _interruptible_poll_sleep(self, delay: float,
   shutdown_event: asyncio.Event | None) -> bool`) near the top of the class or immediately
   above `start()`, implementing the same `asyncio.wait({asyncio.ensure_future(asyncio.sleep(
   delay)), asyncio.ensure_future(shutdown_event.wait())}, return_when=
   asyncio.FIRST_COMPLETED)` race as `StartupOrchestrator._interruptible_sleep()`; return
   `False` immediately (after a plain `await asyncio.sleep(delay)`) if `shutdown_event is None`.
3. In the poll loop (current lines 418-448), replace `await asyncio.sleep(0.5)` (current line
   448) with:
   ```python
   if await self._interruptible_poll_sleep(0.5, shutdown_event):
       stderr_full = self._cleanup_server_resources(server_key)
       failure = StartupFailure(
           server_key=server_key,
           reason="shutdown requested",
           stderr_full=stderr_full,
       )
       self._http_procs.pop(server_key, None)
       self._http_pgids.pop(server_key, None)
       raise HttpStartupError(failure)
   ```
   Do not call `_terminate_with_timeout()` here (Assumption above: the caller's rollback handles
   termination) — only pop the tracking dicts and raise, mirroring the existing "exited early"
   branch's dict-cleanup shape (current lines 419-434) minus the terminate call.

### Method
- Located exact line numbers via `grep -n "def start(\|_http_procs\[\|while time.monotonic\|
  asyncio.sleep\|def restart" scripts/agent/http_lifecycle.py`, then read lines 280-464 directly
  to confirm the poll loop's exact structure, the "exited early" branch's cleanup shape, and the
  `restart()` call site before drafting this procedure.

### Details
- No new imports required — `asyncio` is already imported (current line 11).
- `start()`'s three call sites (`factory.py` first-attempt, `factory.py` retry per the sibling
  `startup.py` fix, `http_lifecycle.py:481` via `restart()`) all continue to omit
  `shutdown_event` except the two `factory.py` sites updated by the companion
  `implementations/20260804-151109_factory.py.md` procedure — `restart()` itself is
  deliberately not changed (Assumptions).
- `StartupFailure`'s `reason` field is a plain string; no `_mask_secrets()` call needed since
  "shutdown requested" carries no interpolated config value.
