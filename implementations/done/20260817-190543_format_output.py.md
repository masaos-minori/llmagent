## Goal

Consolidate output-truncation and dry-run message templates in `git/format_output.py` via two independent sub-tasks: truncation consolidation and dry-run message consolidation.

## Scope

### In-Scope
- Sub-task A: Truncation consolidation — enumerate all truncation-limit constants, add boundary tests, extract shared utility
- Sub-task B: Dry-run message consolidation — get sign-off on unifying 5 wordings, extract shared `_dry_run_or()` helper

### Out-of-Scope
- Runtime behavior changes beyond consolidation
- Changes outside `scripts/mcp_servers/`

## Assumptions

- The same truncation concern exists elsewhere in `scripts/mcp_servers/` (confirmed by require doc)
- The 5 dry-run wordings may or may not need to be unified (requires explicit maintainer sign-off)
- Any consolidation risks silently altering the exact truncation boundary or wording that callers/tests may depend on verbatim

## Design decisions

- Process truncation consolidation and dry-run consolidation as independent sub-tasks — they address different concerns and have different risk profiles
- Require explicit maintainer sign-off before unifying dry-run wordings — callers may depend on exact wording
- Verify byte-for-byte identical output at all truncation boundaries before applying any consolidation

## Alternatives considered

- Keep separate truncation constants per module — rejected because duplication increases maintenance burden
- Unify dry-run wordings without sign-off — rejected because it risks breaking caller expectations

## Compatibility considerations

- Truncation boundaries must remain byte-for-byte identical — any change would break test assertions and possibly caller expectations
- Dry-run wording changes require explicit sign-off — callers may parse or display these messages

## Security considerations

- None identified — this is purely a refactoring of output formatting, no security-sensitive code paths involved

## Rollback considerations

- Revert the diff; no data loss or service impact

## Implementation

### Target files

- `scripts/mcp_servers/git/format_output.py` — shared utilities for truncation and dry-run messaging
- Potentially other MCP server formatter modules with similar truncation logic
- `tests/mcp_servers/git/test_format_output.py` — boundary tests + wording updates

### Procedure

1. **Phase 1: Preparation / Enumeration**
   - Run `rg "GIT_SHOW_OUTPUT_MAX_CHARS|max_chars|byte_limit" scripts/mcp_servers/**/format*.py scripts/mcp_servers/**/*formatter.py` to identify all truncation sites
   - Read each truncation site to understand the exact boundary logic

2. **Sub-task A: Truncation consolidation**
   - Add boundary characterization tests (at/over/under the limit) for each truncation site found
   - Extract a shared truncation utility
   - Verify byte-for-byte identical truncated output at all tested boundaries for every consolidated call site

3. **Sub-task B: Dry-run message consolidation**
   - Get explicit maintainer sign-off on whether the 5 current dry-run wordings should be unified
   - If confirmed, extract a shared `_dry_run_or(...)` helper
   - Update all 32 existing `test_format_output.py` characterization tests to match the (deliberately changed) wording
   - Call out the wording changes in the PR description

4. **Phase 3: Deployment & Verification**
   - Run `uv run pytest tests/mcp_servers/git/test_format_output.py -v` — verify all pass
   - Run full `tests/mcp_servers/` regression if other formatter tests are affected

### Method

Refactoring — consolidate duplicated truncation logic and dry-run message patterns into shared utilities.

### Details

```python
# In scripts/mcp_servers/git/format_output.py:

# BEFORE (multiple locations):
def truncate_output(text: str, max_chars: int = GIT_SHOW_OUTPUT_MAX_CHARS) -> str:
    """Truncate text to max_chars bytes."""
    encoded = text.encode("utf-8")[:max_chars]
    return encoded.decode("utf-8", errors="ignore")

# AFTER (shared utility):
from typing import Final

TRUNCATION_MAX_CHARS: Final[int] = 10000  # or whatever value is used across modules

def truncate_output(text: str, max_chars: int = TRUNCATION_MAX_CHARS) -> str:
    """Truncate text to max_chars bytes, preserving UTF-8 boundaries."""
    encoded = text.encode("utf-8")[:max_chars]
    return encoded.decode("utf-8", errors="ignore")

# Dry-run message consolidation (after sign-off):
_DRY_RUN_MESSAGES: Final[dict[str, str]] = {
    "status": "Dry-run: git status would show no changes.",
    "diff": "Dry-run: git diff would show no changes.",
    "commit": "Dry-run: commit would succeed without writing anything.",
    "push": "Dry-run: push would succeed without sending anything.",
    "checkout": "Dry-run: checkout would switch branches without modifying working tree.",
}

def _dry_run_or(message_key: str, actual_result: str) -> str:
    """Return dry-run message or actual result based on mode."""
    if _DRY_RUN_MODE:
        return _DRY_RUN_MESSAGES.get(message_key, f"Dry-run: operation completed.")
    return actual_result
```
