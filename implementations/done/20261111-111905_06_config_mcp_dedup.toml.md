## Goal

Reduce `config/mcp_dedup.toml` to the dispatcher's single-owner configuration by removing `pending_timeout_minutes` (which moves to `config/agent.toml`), so that no process other than the shared MCP dispatcher reads this file (`REQ-004`). Keep `db_path`, `retention_days`, and the `[retry_class]` map unchanged.

## Scope
**Release unit**: N/A: config-isolation change; independent of the Empty-store fail-closed release unit (Plan Implementation steps, Phase 3).

## Assumptions
- After seq 03 (`workflow_engine.py` reads `pending_timeout_minutes` from `agent.toml`) and seq 04 (`tool_runner.py` stops importing the dispatcher's `retry_class`), the dispatcher is the sole remaining reader of `mcp_dedup.toml`, so the file is reduced rather than deleted (Plan Assumptions).
- Removing the key does not break the loader: `load_dedup_config()` reads it via `dedup.get("pending_timeout_minutes", DEFAULT_PENDING_TIMEOUT_MINUTES)` (`mcp_dedup.py` L115-117), so a missing key falls back to the default (10) instead of raising.
- Open (flag, do not fabricate): confirm no hidden reader (a startup script, deploy hook, or other `*.py`/`*.sh`) consumes `mcp_dedup.toml` or `resolve_config_dir` before deleting the key (UNK-05). `grep` all consumers at implementation.

## Design decisions
- **Reduce, do not delete.** One reader (the dispatcher) remains, so the file is kept and trimmed, not removed (Plan Out-of-Scope: "Deleting `config/mcp_dedup.toml` outright when a single reader remains").
- **Keep the `[retry_class]` map.** It is the REQ-006 owner classification (dispatch-capable HTTP tools `retryable`; external-side-effect tools `non_retryable`) and is still consumed by the dispatcher's `load_dedup_config()` → `retry_class()`.
- **Drop only the one key.** Keep `db_path` and `retention_days` as-is; do not relocate `pending_timeout_minutes` into another section.

## Alternatives considered
- **Delete `config/mcp_dedup.toml` entirely.** Rejected: the dispatcher is still a reader, and the plan explicitly keeps the single-owner file.
- **Move `pending_timeout_minutes` into `[retry_class]` or another section.** Rejected: it is a dedup timing setting consumed by the Agent, not a retry classification; it belongs in `agent.toml`, not the dispatcher's config.
