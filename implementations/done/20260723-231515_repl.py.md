## Goal

Improve SQLite error visibility by including the error class name in session start error messages.

## Scope

**In-Scope**:
- Modify error message format in `AgentREPL.run()` to include `sqlite3.Error` subclass name

**Out-of-Scope**:
- Any other error handling changes
- Adding new configuration options
- Modifying test infrastructure

## Assumptions

1. `e.__class__.__name__` reliably returns the error class name (e.g., "OperationalError", "DatabaseError").
2. The existing error message structure is acceptable; only the addition of the class name is needed.

## Design decisions

- **Use `e.__class__.__name__` directly in f-string**: No intermediate variable needed — inline expression keeps the diff minimal.
- **Place class name after "unavailable" keyword**: Format follows pattern `"Message (ClassName): detail"` which clearly separates the category from the specific error.

## Alternatives considered

- **Intermediate variable `err_type = e.__class__.__name__`**: Cleaner readability but adds an extra line. Chose inline approach for minimal diff since the expression is short and clear.
- **Format as `"ClassName: Message"` instead of `"Message (ClassName): detail"`**: Would require restructuring the entire message. Chose to keep the existing message order and append class name parenthetically.
