## Goal

Add an application-level (HTTP `/health`) liveness re-check to the HTTP MCP server
reuse path, so that a subprocess whose OS process is alive but whose application
layer has hung (deadlocked event loop, exhausted worker threads, etc.) is detected
and triggers an automatic restart, instead of being silently reused forever by
`ensure_ready()`.

## Scope

**In-Scope:**
- `scripts/agent/http_lifecycle.py`: add a per-`server_key` "last health-checked at"
  timestamp store; add a rate-limited async liveness check that performs a
  short-timeout HTTP GET to `{cfg.url}/health` when the OS-level check passes and
  the re-check interval has elapsed; clear the timestamp entry on `start()`,
  `restart()`, `shutdown_all()`.
- `scripts/agent/factory.py`: update `_ServerLifecycleRouter.ensure_ready()` to call
  the new async liveness check, and to route to `HttpServerLifecycleManager.restart()`
  (terminate + start) instead of `start()` alone when the process is OS-alive but
  app-unhealthy (since `start()` is a no-op for a still-alive process).
- Logging additions distinguishing "OS-exited restart" from "app-unhealthy restart".
- Unit tests for the new check and the updated `ensure_ready()` branching (added
  during the implementation phase, not this planning phase).

**Out-of-Scope:**
- Adding a new configurable interval field to `shared/mcp_config.py`
  (`McpServerConfig`) — the requirement's "suggested approach" mentions this as one
  option but treats it as subject to design confirmation; this plan selects a
  class-level constant instead (see Assumptions) to keep the change contained to the
  two target files named in the requirement.
- Adding a mutex/lock around `ensure_ready()`/`restart()` to fully close concurrent
  double-restart races — flagged as a residual risk (see Risks), not fixed here, since
  it is a pre-existing gap not scoped by this requirement.
- Any change to `start()`'s own startup health-poll logic (`http_lifecycle.py:258-295`).
- Any change to stdio-transport server lifecycle handling.
- Persistent-mode (non-subprocess) HTTP servers — `ensure_ready()` already returns
  early for `startup_mode != SUBPROCESS`.

## Assumptions

1. The re-check interval will be implemented as a class-level constant on
   `HttpServerLifecycleManager` (e.g. `_HEALTH_RECHECK_INTERVAL_SEC: float = 10.0`),
   not a new `McpServerConfig` field, to avoid touching `shared/mcp_config.py`, which
   is outside this requirement's named Target Files. This is a scope-reduction
   assumption, not a hard requirement from the ticket ("e.g. a class-level constant
   or a field sourced from `McpServerConfig`" — both are explicitly acceptable).
2. The short HTTP check timeout will use `httpx.Timeout(timeout=1.5)` (within the
   ticket's suggested "1-2 seconds" bound), separate from the existing
   `MCPSERVER_HEALTH_TIMEOUT = 5.0` module constant used elsewhere, since the ticket
   asks for a shorter bound specifically for the reuse-time check to avoid stalling
   `ensure_ready()` callers.
3. `verify_running()`'s existing synchronous signature and OS-only semantics are kept
   unchanged for any other current caller; a new async method
   `verify_running_async()` is added for the app-level check, called only from
   `ensure_ready()`. (Confirmed via grep: `verify_running` is called only from
   `_ServerLifecycleRouter.ensure_ready()` in `factory.py:136` in current code — no
   other call sites exist in `scripts/agent/` or `scripts/shared/`.)
4. When the new check finds the process OS-alive but app-unhealthy, `ensure_ready()`
   will call `self._http_mgr.restart(server_key, cfg)` (existing method, already
   terminates then calls `start()`) rather than `start()` directly, since `start()`
   is a no-op when `proc.poll() is None` (`http_lifecycle.py:211-217`).
5. `_last_health_check` timestamps are cleared for a `server_key` on `restart()` (so
   the freshly-restarted process is not immediately re-checked) and on
   `shutdown_all()` (so no stale entries linger); `start()` also clears/initializes
   the entry for a genuinely-new process on first successful startup.
6. No existing test in `tests/test_agent_factory.py` or `tests/test_lifecycle.py`
   currently mocks/awaits `verify_running` as a coroutine (confirmed:
   `mock_mgr.verify_running = MagicMock(return_value=False)` at
   `tests/test_agent_factory.py:139,399` is a plain sync `MagicMock`), so introducing
   a separate `verify_running_async()` avoids breaking these existing tests' mock
   setup; those tests will still need small updates to also mock/await the new
   method when `ensure_ready()` starts calling it (implementation-phase task, tracked
   in Validation Plan below, not performed in this document-only phase).

## Design decisions

- Add a class-level constant `_HEALTH_RECHECK_INTERVAL_SEC: float = 10.0` for the re-check interval.
- Add a class-level constant `_HEALTH_RECHECK_TIMEOUT_SEC: float = 1.5` for the short HTTP timeout.
- Add `self._last_health_check: dict[str, float] = {}` in `__init__` to track last health-check timestamps.
- Add `async def verify_running_async(self, server_key, cfg)` that performs a rate-limited HTTP GET to `/health`.
- Update `ensure_ready()` to branch: OS-alive + app-unhealthy → `restart()`; OS-dead → `start()` (unchanged).
- Distinguish logs for "OS-exited restart" vs "app-unhealthy restart".

## Alternatives considered

- Use a `McpServerConfig` field for per-server-configurable re-check interval. Rejected — keeps the change contained to the two target files named in the requirement; can be promoted later if needed.
- Add a mutex/lock around `ensure_ready()`/`restart()`. Rejected — pre-existing gap not scoped by this requirement; documented as a residual risk.

```python
# New method — scripts/agent/http_lifecycle.py (after verify_running)
async def verify_running_async(self, server_key: str, cfg: McpServerConfig) -> bool:
    """Check liveness via HTTP /health endpoint, rate-limited by re-check interval."""
    # First, OS-level check — if the process is dead, skip the HTTP check entirely
    if not self.verify_running(server_key):
        return False
    # Rate-limit: only do HTTP check if enough time has passed since last one
    last_check = self._last_health_check.get(server_key, 0.0)
    if time.monotonic() - last_check < self._HEALTH_RECHECK_INTERVAL_SEC:
        return True
    # Perform the HTTP health check
    try:
        async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=self._HEALTH_RECHECK_TIMEOUT_SEC)) as client:
            resp = await client.get(cfg.url.rstrip("/") + "/health")
            self._last_health_check[server_key] = time.monotonic()
            return resp.status_code == 200
    except (httpx.HTTPError, OSError):
        self._last_health_check[server_key] = time.monotonic()
        return False
```

```python
# After — scripts/agent/factory.py:114-148
async def ensure_ready(self, server_key: str, cfg: McpServerConfig) -> None:
    ...
    os_alive = self._http_mgr.verify_running(server_key)
    if not os_alive:
        logger.info("HTTP MCP server %r is down; starting", server_key)
        await self._http_mgr.start(server_key, cfg)
        self._set_state(server_key, State.RUNNING)
    else:
        # Process is alive at OS level — check application-layer health
        app_healthy = await self._http_mgr.verify_running_async(server_key, cfg)
        if not app_healthy:
            logger.warning("Lifecycle: %r OS-alive but app-unhealthy; restarting", server_key)
            await self._http_mgr.restart(server_key, cfg)
            self._set_state(server_key, State.RUNNING)
        else:
            self._set_state(server_key, State.RUNNING)
    ...
```

Exception path behavior:
- On OS-level death: unchanged behavior — `start()` called.
- On app-layer unhealthiness: new branch — `restart()` called instead of `start()`.
- On rate-limited check (interval not elapsed): returns `True` without making an HTTP call.
