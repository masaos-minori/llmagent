## Goal

Make `StartupOrchestrator._spawned_subprocesses` (and the third element of `run()`'s return tuple) actually reflect the subprocesses spawned by `_start_servers()`, on both the success and exception paths, so the existing `repl.py` fallback-termination loop can do real work when `lifecycle.shutdown_all()` fails.

## Scope

**In-Scope:**
- `scripts/agent/startup.py` — `StartupOrchestrator.run()`:
  - Line 68: capture return value of `await self._start_servers()` into `self._spawned_subprocesses` instead of discarding.
  - Line 89: return `self._spawned_subprocesses` instead of hardcoded `[]` on success path.
- Regression test in `tests/test_startup.py` (near `TestStartupRollback`) injecting failure in later startup step and `lifecycle.shutdown_all()`, asserting `self._spawned_subprocesses` populated with fake processes after `run()` raises.
- Success-path test asserting `run()`'s third return value equals list of processes actually spawned by `_start_servers()`.

**Out-of-Scope:**
- `scripts/agent/repl.py` — no code changes. The `finally` block's termination loop left as-is. Note: this is a separate, already-tracked bug.
- Any change to `lifecycle.shutdown_all()` or `_ServerLifecycleRouter._http_procs`.
- Any change to which processes get spawned or how `_start_servers()` builds its `spawned` list.
- Any change to other startup steps (`_verify_mcp_health`, `_check_services`, etc.).

## Assumptions

1. `_start_servers()` already returns the correct `spawned` list of `subprocess.Popen` objects.
2. No other caller depends on `run()`'s third tuple element always being `[]` on success. Only production call site is `scripts/agent/repl.py:736-739` which unpacks generically.
3. **CRITICAL**: This plan MUST NOT be deployed independently of the corresponding plan for `requires/20260727-132720_require.md` (sibling requirement fixing `AgentREPL.run()`'s `finally` block). Deploying this fix alone will cause `AgentREPL.run()` to terminate every just-spawned, healthy MCP HTTP subprocess after every successful startup, breaking all HTTP-subprocess-mode MCP tools.
4. Existing tests in `tests/test_startup.py::TestStartupRollback` stub `orch._start_servers = AsyncMock()` with no explicit `return_value`; after fix, `self._spawned_subprocesses` will be set to `AsyncMock`'s default return value but since none assert on it, tests won't break.
5. `tests/test_repl.py` mocks `agent.startup.StartupOrchestrator` directly and hardcodes `run()`'s return tuple, unaffected by this change.

## Design decisions

- Capture `_start_servers()` return value in `self._spawned_subprocesses` during `try` block execution (line 68), using existing `[]` as pre-call default (line 66).
- Return `self._spawned_subprocesses` on success path (line 89) instead of `[]`.
- On exception path, `self._spawned_subprocesses` retains whatever was captured (or `[]` if `_start_servers()` raised before returning).

## Alternatives considered

- Initialize `self._spawned_subprocesses` outside the `try` block as `[]` and only update inside `try`. Chosen approach matches existing pattern and requirement spec.
- Add `finally` clause to guarantee cleanup tracking regardless of where exception occurs. Out of scope per requirement.
