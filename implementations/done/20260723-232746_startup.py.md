## Goal

Set `memory_disabled` flag in `ConversationState` when memory injection fails during startup.

## Scope

**In-Scope**:
- Set `ctx.conv.memory_disabled = True` in `StartupOrchestrator._setup_prompt()` when memory injection fails

**Out-of-Scope**:
- Adding the flag to ConversationState (covered in separate context.py document)
- Displaying the warning (covered in separate repl.py document)
- Modifying memory injection logic itself

## Assumptions

1. Setting `ctx.conv.memory_disabled = True` in `_setup_prompt()` propagates correctly to the REPL loop.
2. The flag is accessible from the same `ctx` object used throughout the method.

## Design decisions

- **Set flag immediately after warning display**: Placing the flag assignment right after the existing warning ensures the flag is set regardless of whether the view write succeeds or fails.
- **Use same exception handler**: Leverages the existing `except Exception as exc:` block — no new exception handling needed.

## Alternatives considered

- **Set flag before the try block**: Would indicate memory is disabled even if injection actually succeeded. Rejected because it's misleading.
- **Set flag in a separate finally block**: Unnecessary complexity — the existing except block already handles the failure case cleanly.
- **Raise a custom exception instead of setting flag**: Would require changing the caller's error handling. Chose simple flag-setting approach.
