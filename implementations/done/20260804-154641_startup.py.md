# Implementation Procedure: Bind and surface the RAG consistency check exception

## Goal

In `StartupOrchestrator._check_services()`, bind the exception caught by the RAG-consistency
`except` block (`scripts/agent/startup.py:358-359`), log it via `logger.warning(...)`, and
include its content in the `pipeline.add_skipped(...)` message, so the exception's
class/message reaches both the log file and the console — matching the pattern already used
by the other five checks in the same method — with no change to control flow or to the broad
`Exception` catch type.

## Scope

**In scope**
- `scripts/agent/startup.py`, lines 358-359 only (the RAG consistency `except` block):
  - bind the exception: `except Exception as exc:`
  - add inline justification text to the retained `# noqa: BLE001`
  - add `logger.warning("RAG consistency check failed: %s", exc)`
  - update `pipeline.add_skipped("rag_consistency", ...)` message to include `exc`

**Out of scope**
- `RagMaintenanceService.consistency()` itself.
- The other five `except` blocks in `_check_services()` (lines 299, 320, 336, 343, and the
  post-startup-health block at line 229) — untouched.
- Narrowing the caught exception type or changing SKIPPED to FATAL.
- Adding inline justification to the other four bare `# noqa: BLE001` comments (lines 299,
  320, 336, 343) that also lack one — pre-existing gap, tracked separately
  (`issues/20260804-144205_risks.md`), not fixed here.

## Assumptions

- `logger` (module-level, `scripts/agent/startup.py:50`) supports `%s` lazy formatting via
  stdlib `logging.Logger` delegation — confirmed by the existing call site
  `logger.error("Workflow schema preflight failed: %s", result.error)` at line 268.
- `pipeline.add_skipped(source: str, message: str = "")` accepts an arbitrary string, so an
  f-string with `{exc}` is a drop-in replacement for the current fixed string.
- Current source (confirmed by direct read, 2026-08-04) still has the unbound form at line
  358: `except Exception:  # noqa: BLE001` / line 359:
  `pipeline.add_skipped("rag_consistency", "RAG consistency check skipped")` — this document
  describes the change relative to that observed state.

## Design decisions

- Use `logger.warning` (not `logger.error`) for severity, for consistency with the sibling
  `routing_drift`/`routing_safety_tiers` checks in the same method, which also only ever
  produce a non-fatal WARNING/SKIPPED outcome on exception; `logger.error` in this file is
  reserved for checks that can escalate to FATAL (e.g. the workflow-schema preflight at line
  268).
- Call `logger.warning("RAG consistency check failed: %s", exc)` using the `%s`-arg calling
  convention (two positional args), not a pre-formatted f-string passed as a single arg — this
  matches every other `logger.*` call in this file and is what the updated test asserts against.

## Alternatives considered

- `logger.error` instead of `logger.warning` — rejected: this check remains non-fatal
  (`add_skipped`), so `warning` is the closer severity match to the check's actual outcome
  class, consistent with the two structurally similar checks in the same method.
- Narrowing `except Exception` to a more specific exception type — rejected: out of scope per
  the plan (this task changes only exception binding/logging, not the catch type), and the
  underlying `RagMaintenanceService().consistency()` call can fail in multiple ways (DB lock,
  I/O, etc.) that don't share a common narrower base beyond `Exception`.

## Implementation

### Target file
`scripts/agent/startup.py`

### Procedure
1. Locate the RAG consistency block (currently lines 348-359, confirmed by grep):
   ```python
           # 6. RAG consistency
           try:
               rag_check = RagMaintenanceService().consistency()
               if rag_check.is_consistent:
                   pipeline.add_ok("rag_consistency")
               else:
                   for issue in rag_check.issues:
                       pipeline.add_warning(

               logger.warning("RAG consistency check failed: %s", exc)
               pipeline.add_skipped(
                   "rag_consistency", f"RAG consistency check skipped: {exc}"
               )
   ```
3. Do not touch any other line in `_check_services()`.
