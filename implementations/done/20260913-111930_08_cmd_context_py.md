## Goal

Use `write_warning()` instead of `write_no_data(f"[warn] ...")` pattern in cmd_context.py.

## Scope

- Modify `scripts/agent/commands/cmd_context.py`: Use `write_warning()` instead of `write_no_data(f"[warn] ...")` pattern

## Assumptions

- cmd_context.py:L152 contains `self._out.write_no_data(f"{OutputTag.WARN} {result.warning}")` which is a warning message using the anti-pattern
- `OutputPort.write_warning(text)` exists on the unified Protocol and handles warning styling consistently
- The `write_no_data()` method is being replaced as part of the protocol merge (handled in output_port.py document)

## Design decisions

- Replace `self._out.write_no_data(f"{OutputTag.WARN} {result.warning}")` with `self._out.write_warning(result.warning)`
- This eliminates the `[warn]` prefix duplication — `write_warning()` already applies the warning tag internally
- `OutputTag.WARN` prefix becomes redundant when using `write_warning()` directly

## Alternatives considered

- Keeping `write_no_data()` but adding a `write_warning()` alias: rejected because it perpetuates the fragmentation problem
- Creating a new `write_warn()` method: rejected because `write_warning()` is more consistent with existing naming conventions
