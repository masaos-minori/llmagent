## Goal

Extend RAG consistency checks to detect document-level and URL-level integrity problems: documents with zero chunks, chunks without vector rows, duplicate chunk_index values, and URL-level mismatches between chunks/vectors/FTS.

## Scope

**In-Scope:**
- Add `documents_without_chunks_count` — documents that have no chunks
- Add `chunks_without_vec_count` — chunks without corresponding vector rows
- Add `duplicate_chunk_index_count` — duplicate chunk_index values within the same document
- Add URL-level counts: document URL, chunk count, vector count, FTS count per URL
- Include affected doc_ids and URLs where possible
- Update `summarize_issues()` with clear severity and repair guidance for new checks
- Update `is_consistent()` to consider new checks

**Out-of-Scope:**
- Adding UNIQUE(doc_id, chunk_index) constraint (deferred to later migration)
- Changes to SQLite schema
- Changes to ingestion logic itself

## Assumptions

1. A document is considered "without chunks" only if it exists in the documents table but has no corresponding rows in chunks.
2. A chunk is considered "without vector" if it exists in chunks but has no row in chunks_vec.
3. Duplicate chunk_index means the same chunk_index value appears multiple times within the same doc_id.
4. URL-level inconsistency means a URL has different chunk counts across chunks/chunks_vec/chunks_fts tables.
5. All new checks should use read-only queries (no writes).

## Design decisions

- **is_consistent() strictness**: Make is_consistent() stricter — all checks must pass for True result
- **URL-level aggregation**: Use LEFT JOINs with GROUP BY for URL-level counts; compare mappings to find mismatches
- **Severity levels**: WARNING for documents_without_chunks and URL mismatches; CRITICAL for chunks_without_vec and duplicate_chunk_index

## Alternatives considered

- **Lenient is_consistent()**: Keep backward compatibility by only checking original conditions. Rejected because new checks represent real data integrity issues that should be surfaced.
- **Separate report types**: Create separate reports for document-level vs URL-level issues. Rejected because single report provides complete picture.

#### Phase 2: Add document-level consistency checks

1. Query for documents without chunks:
   ```python
   docs_without_chunks = db.execute(
       "SELECT COUNT(*) FROM documents WHERE doc_id NOT IN (SELECT DISTINCT doc_id FROM chunks)"
   ).fetchone()[0]
   ```

2. Collect affected doc_ids for documents without chunks (LIMIT 10):
   ```python
   if docs_without_chunks > 0:
       id_rows = db.execute(
           "SELECT doc_id FROM documents WHERE doc_id NOT IN (SELECT DISTINCT doc_id FROM chunks)"
           " ORDER BY doc_id LIMIT 10"
       ).fetchall()
       affected_docs_without_chunks = tuple(r[0] for r in id_rows)
   ```

3. Query for chunks without vectors:
   ```python
   chunks_without_vec = db.execute(
       "SELECT COUNT(*) FROM chunks WHERE chunk_id NOT IN (SELECT chunk_id FROM chunks_vec)"
   ).fetchone()[0]
   ```

4. Collect affected chunk_ids for chunks without vectors (LIMIT 10):
   ```python
   if chunks_without_vec > 0:
       id_rows = db.execute(
           "SELECT chunk_id FROM chunks WHERE chunk_id NOT IN (SELECT chunk_id FROM chunks_vec)"
           " ORDER BY chunk_id LIMIT 10"
       ).fetchall()
       affected_chunks_without_vec = tuple(r[0] for r in id_rows)
   ```

5. Query for duplicate chunk_index values:
   ```python
   dup_chunk_indices = db.execute(
       "SELECT doc_id, chunk_index FROM chunks"
       " GROUP BY doc_id, chunk_index HAVING COUNT(*) > 1"
   ).fetchall()
   duplicate_chunk_index_count = len(dup_chunk_indices)
   ```

6. Collect affected (doc_id, chunk_index) pairs for duplicates (LIMIT 10):
   ```python
   if duplicate_chunk_index_count > 0:
       limited_dups = db.execute(
           "SELECT doc_id, chunk_index FROM chunks"
           " GROUP BY doc_id, chunk_index HAVING COUNT(*) > 1"
           " ORDER BY doc_id, chunk_index LIMIT 10"
       ).fetchall()
       affected_duplicate_chunk_indices = tuple((r[0], r[1]) for r in limited_dups)
   ```

#### Phase 3: Add URL-level consistency checks

1. Query to get URL → chunk count mapping:
   ```python
   url_chunk_counts = dict(db.execute(
       "SELECT d.url, COUNT(c.chunk_id) FROM documents d"
       " LEFT JOIN chunks c ON d.doc_id = c.doc_id"
       " GROUP BY d.url"
   ).fetchall())
   ```

2. Query to get URL → vector count mapping:
   ```python
   url_vec_counts = dict(db.execute(
       "SELECT d.url, COUNT(cv.chunk_id) FROM documents d"
       " LEFT JOIN chunks c ON d.doc_id = c.doc_id"
       " LEFT JOIN chunks_vec cv ON c.chunk_id = cv.chunk_id"
       " GROUP BY d.url"
   ).fetchall())
   ```

3. Query to get URL → FTS count mapping:
   ```python
   url_fts_counts = dict(db.execute(
       "SELECT d.url, COUNT(cf.rowid) FROM documents d"
       " LEFT JOIN chunks c ON d.doc_id = c.doc_id"
       " LEFT JOIN chunks_fts cf ON c.chunk_id = cf.rowid"
       " GROUP BY d.url"
   ).fetchall())
   ```

4. Compare mappings and identify URLs where counts differ:
   ```python
   url_level_mismatches: dict[str, dict[str, int]] = {}
   all_urls = set(url_chunk_counts.keys()) | set(url_vec_counts.keys()) | set(url_fts_counts.keys())
   for url in all_urls:
       chunk_count = url_chunk_counts.get(url, 0)
       vec_count = url_vec_counts.get(url, 0)
       fts_count = url_fts_counts.get(url, 0)
       if chunk_count != vec_count or chunk_count != fts_count or vec_count != fts_count:
           url_level_mismatches[url] = {
               "chunk_count": chunk_count,
               "vec_count": vec_count,
               "fts_count": fts_count,
           }
   ```

5. Store mismatched URLs with their counts in url_level_mismatches dict

           f"[WARNING] URL-level inconsistency detected (mismatched URLs={len(report.url_level_mismatches)}).{detail}"

       )
