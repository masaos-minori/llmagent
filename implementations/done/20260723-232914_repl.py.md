## Goal

Display a one-time warning when memory is disabled for the session, shown on the first tool call after memory injection failure.

## Scope

**In-Scope**:
- Add warn-on-first-use check in `_repl_loop()` to display warning once per session

**Out-of-Scope**:
- Adding flags to ConversationState (covered in separate context.py document)
- Setting the flag on memory injection failure (covered in separate startup.py document)
- Modifying memory injection logic itself

## Assumptions

1. The "warn-on-first-use" approach (displaying warning only on first tool call) is acceptable — it avoids spamming the user with warnings on every turn.
2. The warning should be displayed via `self._view.write_warning()` with `OutputTag.NON_FATAL`.

## Design decisions

- **Check in `_repl_loop()` rather than tool execution path**: Simpler — one check location instead of scattering across multiple tool invocations. The first turn always goes through `_repl_loop()`, so the warning will appear early enough.
- **Use boolean flag `memory_warning_shown`**: Prevents duplicate warnings — once displayed, the flag prevents re-display even if the user makes multiple tool calls.
- **Place check after input reading but before dispatch**: Ensures the warning appears before any tool output, giving the user context before seeing results.

## Alternatives considered

- **Check in tool execution path**: Would require adding the check to every tool invocation. Rejected because it adds complexity and risk of missing some paths.
- **Check in `ensure_ready()`**: Only applies to MCP server readiness, not general tool execution. Rejected because it's too narrow.
- **Always display on first turn regardless of memory status**: Would show unnecessary warning when memory works fine. Chose conditional check based on `memory_disabled` flag.
- **Display during `_check_services()` readiness summary**: Would require modifying the readiness report which has different semantics. Chose dedicated check in REPL loop instead.
