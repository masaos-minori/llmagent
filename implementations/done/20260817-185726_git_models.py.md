## Goal

Establish a consistent type-coercion strictness policy across all `*_models.py` config loaders in `scripts/mcp_servers/`. Adopt the stricter approach (explicit `isinstance` checks via `_get_typed` helper) as the codebase standard. Backport `_get_typed`-style validation to the currently-loose loaders (`write_models.py`, `read_models.py`, `web_search_models.py`).

## Scope

### In-Scope
- Audit all `*_models.py` config loaders' current type-coercion behavior
- Decide and document the target strictness policy
- Apply `_get_typed`-style validation to `write_models.py`, `read_models.py`, `web_search_models.py`
- Add characterization tests for accepted and newly-rejected value shapes per file
- Verify every existing `config/*.toml` file still loads successfully

### Out-of-Scope
- Changes to Pydantic request/response models (only config-loading boundary)
- Changes to `shared/config_loader.py` or `shared/config_utils.py` (unless needed for the shared helper)
- Changes to MCP server business logic

## Assumptions

- The stricter approach (explicit `isinstance` checks) is preferable because it catches malformed config early with clear error messages rather than silently accepting wrong types.
- Existing valid TOML configs will continue to pass after the change (no legitimate use of float values where int is expected, etc.).
- The `_get_typed` helper in `git_models.py` can be extracted to a shared utility or duplicated per-file depending on whether other MCP servers already reference it.

## Design decisions

- Use `_get_typed(d, key, type_fn, description)` as the standard pattern — raises `ValueError` with a clear message when the value doesn't match the expected type
- Extract `_get_typed` to a shared location if other MCP servers could benefit; otherwise keep local to `git_models.py`
- Document the strictness policy in `rules/coding.md` or `rules/env.md`

## Alternatives considered

- Keep loose coercion (bare `int()`, `float()`) — rejected because silent type coercion hides bugs
- Use Pydantic for all config loading — rejected because it would require significant refactoring beyond scope

## Compatibility considerations

- Strict mode rejects values that were previously silently coerced (e.g., `1048576.0` → `1048576`)
- Must audit all existing TOML configs before applying changes
- Exception messages must be clear and actionable

def _get_typed(d: dict[str, Any], key: str, type_fn: type, description: str) -> object:
    """Validate and coerce a value from d[key] to the expected type."""
    val = d.get(key)
    if val is None:
        return None
    if not isinstance(val, type_fn):
        raise ValueError(f"{key} must be {description}, got {type(val).__name__}: {val!r}")
    return val
