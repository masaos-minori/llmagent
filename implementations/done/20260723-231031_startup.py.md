## Goal

Add post-startup health verification for MCP subprocess servers to provide immediate feedback about server health before the REPL begins accepting tool calls.

## Scope

**In-Scope**:
- Add `_verify_mcp_health()` method to `StartupOrchestrator` class
- Iterate over all HTTP MCP subprocess servers started during `_start_servers()`
- Send GET request to `{url}/health` endpoint for each server
- Log errors/warnings for unhealthy servers
- Respect `security_profile` setting (PRODUCTION blocks startup, others warn)

**Out-of-Scope**:
- Modifying the health-poll logic during initial start (already exists in `HttpServerLifecycleManager.start()`)
- Adding periodic health checks during operation
- Changing the `/health` endpoint contract
- Adding health check configuration options
- Adding public API for listing subprocess configs (covered in separate factory.py document)

## Assumptions

1. All HTTP MCP subprocess servers expose a `/health` endpoint returning HTTP 200 when healthy.
2. The `security_profile` setting applies equally to post-startup health checks as it does to startup failures.
3. A single failing server should not block other servers from starting (partial failure tolerance).
4. Health check timeout should be configurable but default to a reasonable value (e.g., 5 seconds per server).
5. Phase 1 from the plan (adding public API in factory.py) must be completed before this phase.

## Design decisions

- **Use short-lived httpx.AsyncClient**: Same pattern as `HttpServerLifecycleManager.start()` — creates a new client per health check rather than sharing a global client.
- **Include zero-timeout servers**: Servers with `startup_timeout_sec=0` were never verified during startup, so they must be included in the post-startup check.
- **Retry once with 1s delay**: Before declaring failure, retry the health check once to avoid false positives from transient network issues.
- **PRODUCTION mode blocks startup**: If any server fails the health check and `security_profile == PRODUCTION`, raise RuntimeError to prevent the agent from running in an unverified state.

## Alternatives considered

- **Shared httpx client**: Would require exposing an httpx client from `AgentContext`. Rejected because it adds coupling and lifecycle management complexity.
- **No retry on failure**: Simpler but more prone to false positives from transient network issues. Chose to retry once.
- **Async health check with concurrent requests**: Could speed up startup by checking multiple servers concurrently. Rejected because sequential checks are simpler and the number of servers is expected to be small (typically 1-3).

         return [

2. **Phase 2: Implement `_verify_mcp_health()` method**
   - [ ] Add method to `StartupOrchestrator` class after `_start_servers()`:
     ```python
     async def _verify_mcp_health(self) -> None:
         """Verify health of all MCP subprocess servers after startup."""
         ctx = self._ctx
         if ctx.services_required.tools is None:
             raise RuntimeError("tools service not initialized")
         if ctx.services_required.lifecycle is None:
             raise RuntimeError("lifecycle service not initialized")

         # Get subprocess server configs from the lifecycle router
         subprocess_servers = ctx.services_required.lifecycle.get_subprocess_server_configs()

         for server_key, cfg in subprocess_servers:
             url = cfg.url.rstrip("/") + "/health"
             try:
                 async with httpx.AsyncClient(timeout=5.0) as client:
                     resp = await client.get(url)
                     if resp.status_code != HTTPStatus.OK:
                         raise RuntimeError(f"HTTP {resp.status_code}")
                     logger.info(
                         "Post-startup health check passed for %r", server_key
                     )
             except Exception as e:
                 # Retry once
                 try:
                     await asyncio.sleep(1.0)
                     async with httpx.AsyncClient(timeout=5.0) as client:
                         resp = await client.get(url)
                         if resp.status_code != HTTPStatus.OK:
                             raise RuntimeError(f"HTTP {resp.status_code}")
                         logger.info(
                             "Post-startup health check passed for %r (after retry)",
                             server_key,
                         )
                 except Exception as retry_err:
                     if ctx.cfg.mcp.security_profile == SecurityProfile.PRODUCTION:
                         msg = f"{OutputTag.FATAL} MCP subprocess {server_key!r} failed post-startup health check: {retry_err}"
                         logger.error(msg)
                         raise RuntimeError(msg) from retry_err
                     logger.warning(
                         "Post-startup health check failed for %r: %s",
                         server_key,
                         retry_err,
                     )
                     self._view.write_warning(
                         f"{OutputTag.NON_FATAL} MCP subprocess {server_key!r} failed post-startup health check: {retry_err}"
                     )
     ```

3. **Phase 3: Wire into startup sequence**

## Security considerations

- Health check URLs constructed from trusted config values (`cfg.url`) — no injection risk
- Short-lived httpx clients prevent connection pool exhaustion
- No credentials or sensitive data exposed in health check responses

## Rollback considerations

- If the health check causes unexpected startup failures, the rollback path in `run()` already handles shutdown of successfully started servers
- Non-PRODUCTION mode provides graceful degradation: warnings displayed but agent continues
- No database or persistent state changes — purely runtime behavior
