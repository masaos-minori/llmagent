## Goal

In `scripts/db/store_protocols.py`: add a mandatory `fetched_at: str`
parameter to `DocumentStore.doc_upsert()`'s Protocol signature, so the
contract requires every caller to supply the canonical, non-nullable
acquisition timestamp instead of letting the implementation substitute
"now" internally.

## Scope

- In scope: `DocumentStore.doc_upsert()`'s method signature (and docstring,
  if one is added/updated) in `scripts/db/store_protocols.py` only.
- Out of scope: `SQLiteDocumentStore.doc_upsert()`'s implementation in
  `scripts/db/store_impl.py` (matching INSERT/`ON CONFLICT` SQL change is a
  separate target file/procedure in this plan), `schema_sql.py`'s
  `DEFAULT` clause removal (separate procedure), and
  `tests/db/test_db_store_impl.py`'s 12 call sites (separate procedure per
  the plan's Phase 5). Other `Protocol`s in this same file (`VectorStore`,
  `SessionStore`, `MemoryDeleteStore`, and `DocumentStore`'s own
  `chunk_insert()`/`doc_get()`/`doc_list()`/`doc_delete()`) are untouched —
  the plan scopes only `doc_upsert()`.

## Assumptions

- `SQLiteDocumentStore.doc_upsert()` has zero production callers today
  (confirmed by the source plan via `rg -n "doc_upsert\(" scripts/ tests/`
  — matches only the `Protocol`/implementation definitions here and in
  `store_impl.py`, plus 12 direct calls in `tests/db/test_db_store_impl.py`).
  The live ingestion path writes documents through
  `Ingester._insert_document()`'s own raw SQL instead, bypassing this
  `Protocol` entirely. Widening this signature is therefore required by the
  plan's acceptance criteria but carries no live-path regression risk.
- All 12 existing `doc_upsert()` calls in `tests/db/test_db_store_impl.py`
  pass their five current arguments (`url, title, lang, etag,
  last_modified`) positionally, with no `fetched_at` argument today
  (confirmed by direct read of that file) — this determines where the new
  parameter can be inserted without silently reordering existing positional
  arguments (see Design decisions).

## Design decisions

- Add `fetched_at: str` as a new, mandatory (no default) parameter,
  appended after `last_modified` at the end of `doc_upsert()`'s parameter
  list. Appending (rather than inserting earlier) preserves every existing
  positional-call test site's first five arguments unchanged, requiring
  only "add a 6th argument" at each of the 12 call sites rather than a
  reorder — matching the plan's own Affected areas description of the test
  change ("add explicit `fetched_at` arg to all 12 `doc_upsert()` calls").
- No default value for `fetched_at`, matching the plan's "single canonical
  non-nullable value" goal and the pattern already used by
  `chunk_insert()`'s domain-meaningful required parameters
  (`doc_id`, `index`, `content`) in this same file.
- `Protocol` method bodies stay `...` (no logic); only the signature and,
  if present, the one-line docstring change.

## Alternatives considered

- Inserting `fetched_at` earlier in the parameter list (e.g. immediately
  after `url`, mirroring its conceptual role as a core identity-adjacent
  field) — rejected: this would silently reorder every existing positional
  call in `tests/db/test_db_store_impl.py`, turning what should be a clear
  "missing required argument" `TypeError` into a much harder-to-spot
  wrong-argument-in-wrong-slot bug (e.g. a `title` string landing in the
  `fetched_at` slot) until a type-checker or runtime error surfaces it.
- Giving `fetched_at` a default of `None` (keeping it Optional at the
  `Protocol` level while only the implementation enforces non-null) —
  rejected: this contradicts the plan's explicit goal of a single
  non-nullable value propagated through every signature in the pipeline,
  and would let a future second `DocumentStore` implementation silently
  accept `None` without a type error.

## Compatibility considerations

- This is a `Protocol` definition, not a runtime enforcement point: adding
  a mandatory parameter here does not by itself break anything at import
  time. The actual breakage surfaces at each concrete call site
  (`SQLiteDocumentStore.doc_upsert()`'s own signature in `store_impl.py`,
  and the 12 calls in `tests/db/test_db_store_impl.py`) once those are
  updated to match — or as a `mypy` mismatch if they are not. This
  `Protocol` edit and the `store_impl.py` implementation edit must land in
  the same commit/change set; a `Protocol` provides no runtime guarantee
  that an implementation's default-value or parameter-count parity is kept
  in sync, so a partial edit here alone would silently desynchronize the
  two signatures without any test failure until `mypy` runs.
- No change to `VectorStore`, `SessionStore`, `MemoryDeleteStore`, or
  `DocumentStore`'s other methods (`doc_get`, `doc_list`, `doc_delete`,
  `chunk_insert`, `chunk_count`) — this edit is scoped to `doc_upsert()`
  only, so no other `Protocol` consumer in the codebase is affected.

## Security considerations

N/A: this is a `Protocol` (interface) definition with no executable logic,

## Rollback considerations

- Revert together with `store_impl.py`'s matching `doc_upsert()` edit and
  `tests/db/test_db_store_impl.py`'s 12 updated call sites as one unit —
  reverting this file alone while `store_impl.py` still expects the extra
  argument (or vice versa) produces an immediate `mypy` signature mismatch
  and/or `TypeError` at every test call site.
- No schema or persisted-data migration is tied to this file; rollback is a
  pure code revert with no data backfill concern.
