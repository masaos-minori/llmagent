## Goal
In `scripts/db/store_protocols.py`: remove the `chunk_type: str = ""` /
`source_file: str = ""` defaults from `DocumentStore.chunk_insert()`.

## Scope
- In scope: `scripts/db/store_protocols.py`'s `chunk_insert()` Protocol method
  signature only.
- Out of scope: any change to `ingester.py`'s ingestion path (see Assumptions —
  verified unrelated).

## Assumptions
- **Correction from adversarial review of the source plan (2026-08-21):** the plan's
  Affected-areas table originally described this Protocol as "used by `ingester.py`
  and any other `DocumentStore` consumer." This is false. `rg -n "chunk_insert"
  scripts` shows `chunk_insert()` is defined in `store_protocols.py`/`store_impl.py`
  but has zero callers anywhere in `scripts/` — `ingester.py` writes chunks via its
  own raw `INSERT INTO chunks (...)` SQL in `_insert_chunk()`/`_insert_chunks_batch()`
  (`ingester.py:493-542`), bypassing this Protocol entirely. The only caller of
  `chunk_insert()` in the whole repository is `tests/db/test_db_store_impl.py`. This
  correction was applied to `plans/20260820-094150_plan.md` itself.
- Given the above, this change is low-risk and self-contained: it only affects this
  Protocol, its one implementation (`store_impl.py`), and that one test file.

## Design decisions
- Remove the default values from the Protocol's `...`-bodied method signature only;
  `Protocol` bodies carry no logic to update.

## Alternatives considered
- Leaving the Protocol's defaults in place while only tightening
  `SQLiteDocumentStore.chunk_insert()` — rejected: `mypy` does not require default-value
  parity between a `Protocol` and its implementation at the type level, but leaving a
  default here would keep advertising an incorrect optional-parameter contract to any
  future second `DocumentStore` implementation, defeating the purpose of removing the
  default at all (matches the plan's stated intent: no permissive defaults surviving
  anywhere in this boundary).

## Implementation
### Target files
1. `scripts/db/store_protocols.py` — Protocol method signature
2. `scripts/db/store_impl.py` — implementation method signature
3. `tests/db/test_db_store_impl.py` — test updates for removed defaults

### Procedure
1. In `store_protocols.py` `chunk_insert()` (starts at line 107): change
   `chunk_type: str = "",` / `source_file: str = "",` to `chunk_type: str,` /
   `source_file: str,` (drop the `= ""` defaults; keep parameter order and the
   preceding `normalized: str | None = None` unchanged).
2. Update the docstring's "Defaults to \"\"" wording for both parameters in step 1,
   since they are no longer defaulted.
3. In `store_impl.py` `chunk_insert()` (starts at line 144): apply the same signature
   change — drop `= ""` defaults from `chunk_type` and `source_file`, keeping
   `normalized: str | None = None` unchanged.
4. In `tests/db/test_db_store_impl.py`:
   - `test_chunk_insert_increments_count` (line 123-129): add explicit `chunk_type=""` and
     `source_file=""` keyword arguments to both `chunk_insert()` calls on lines 126 and 128.
   - `test_chunk_insert_defaults_to_empty_strings` (line 144-153): replace with a test
     that verifies `chunk_insert()` raises `TypeError` when called without the now-required
     `chunk_type` and `source_file` arguments.
   - `test_chunk_insert_stores_chunk_type_and_source_file` (line 131-142): no changes needed
     — already passes both args explicitly.

### Method
- Signature edits in two files; test update for removed defaults.

### Details

  def chunk_insert(
      self,

## Compatibility considerations
- Must land in the same commit as `store_impl.py`'s matching edit — a `Protocol`
  does not enforce default-value parity with its implementation at runtime (only
  `mypy` catches drift), so a partial edit here alone would silently desynchronize the
  two signatures without any test failure until `mypy` runs.
