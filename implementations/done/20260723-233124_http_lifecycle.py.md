## Goal

Fix stale `_http_procs` and `_http_pgids` entries that remain after MCP subprocess startup failures by adding explicit cleanup before raising `HttpStartupError`.

## Scope

**In-Scope**:
- Add cleanup of `_http_procs[server_key]` and `_http_pgids[server_key]` before raising `HttpStartupError` in both error paths ("exited early" and "timeout")

**Out-of-Scope**:
- Modifying `_terminate_with_timeout()` behavior
- Changing rollback logic in `StartupOrchestrator.run()`
- Adding new configuration options

## Assumptions

1. The existing `fh.close()` calls properly close stderr file handles — no additional cleanup needed there.
2. Option A (explicit pop before each raise) is preferred over Option B (try-finally) for minimal diff.
3. Both error paths need the same cleanup since they share the same internal state.

## Design decisions

- **Use `dict.pop(key, None)` instead of `del dict[key]`**: Safe even when the key is already absent — prevents KeyError from double-cleanup if another code path also removes the entry.
- **Pop both dicts independently**: Order doesn't matter since they're independent data structures. No atomicity concern.
- **Place cleanup immediately before each raise**: Minimal diff — only two lines added per error path. Clear cause-and-effect relationship between cleanup and exception.

## Alternatives considered

- **Try-finally block around health-poll loop**: Would ensure cleanup regardless of how the loop exits but adds indentation and complexity. Rejected because it changes more code than necessary.
- **Cleanup in caller (`StartupOrchestrator`)**: Would require changing the rollback logic which has different semantics. Chose local cleanup where the failure occurs.
- **Remove entries from `_failed_starts` as well**: Not needed — `_failed_starts` is intentionally left with the failed start timestamp for cooldown tracking.
