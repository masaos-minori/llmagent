# Implementation Procedure: Remove fallback mode from Orchestrator

## Goal

Treat a workflow load failure as a fatal startup error instead of continuing in a fallback mode with no approval or stage control, and align the Orchestrator's documentation with its real structure.

## Scope

- Remove the try/except in `Orchestrator.__init__` that catches `WorkflowLoadError`/`FileNotFoundError` and falls back to `_FALLBACK_WORKFLOW_DEF`.
- Raise `WorkflowLoadError` as `RuntimeError` with the file path and cause.
- Remove `_FALLBACK_WORKFLOW_DEF`, `_fallback_mode`, and the fallback branch in `handle_turn()`.
- Remove backward-compatibility delegation wrappers from `Orchestrator` (confirmed unused by tests).
- Update module/class docstrings to remove stale references to `turnd_coordinator.py`/`TurnCoordinator` if applicable.

## Assumptions

- No external callers depend on the backward-compatibility delegation wrappers (confirmed via `rg` against tests/ and scripts/ — zero matches).
- `turnd_coordinator.py` is a real file (confirmed via filesystem check), so the Issue's claim about it being a typo is outdated.
- The startup preflight check (if one exists) already validates the workflow file's existence before `Orchestrator.__init__` is called; the fallback is reached only for malformed content.

## Design decisions

The fix replaces the silent fallback path with a hard failure. When `WorkflowLoader().load()` raises `WorkflowLoadError` or `FileNotFoundError`, the Orchestrator propagates the error as a `RuntimeError` with the file path and cause, causing the Agent to exit during startup rather than continuing in a degraded state.

The backward-compatibility delegation wrappers are safe to remove because `rg` confirmed zero test callers.

## Alternatives considered

- **Keep fallback mode but add approval guard**: Would require changes to workflow_engine_adapter.py and workflow/engine.py to inject approval checks into the execution path. More invasive, higher risk of bypassing approval.
- **Add startup preflight check**: Would require changes to startup.py. The Issue notes this may already exist; adding another layer would be redundant.
- **Remove fallback mode entirely**: Chosen approach — simplest, most aligned with ADR-001 INV-01/05 and ADR-004 fail-closed.
