# Implementation: pyproject.toml — Phase 1: select-list decision and documentation

## Goal

Activate `BLE001` (flake8-blind-except) in ruff's `[tool.ruff.lint] select` list, and
document — inline, at the point of decision — the intentional exclusion of
`PLC0415`/`PLC` from `select`, so the decision is visible to future readers of
`pyproject.toml` without needing to consult the plan document.

## Scope

**In-Scope:**
- Add `"BLE001"` to `select = ["E", "W", "F", "I", "UP"]` at `pyproject.toml` line 89.
- Add an inline comment near `select` recording that `PLC0415`/`PLC` is intentionally
  excluded, with the measured blast radius, referencing the source plan for evidence.

**Out-of-Scope:**
- Adding `PLC0415`/`PLC` (or any other rule family) to `select` — explicitly out of
  scope per the source plan (measured ~1193 net-new findings).
- Enabling `RUF100` or any other `RUF` rule — noted as a candidate in the plan's
  Assumptions but not part of this change.
- Any change to `[tool.ruff.format]`, `[tool.mypy]`, `[tool.bandit]`, or other
  `pyproject.toml` sections.

## Assumptions

- Current `pyproject.toml` `[tool.ruff.lint]` section (lines 88-91) reads:
  ```toml
  [tool.ruff.lint]
  select = ["E", "W", "F", "I", "UP"]
  # E501 is not auto-fixable in string literals; ruff format handles code line length
  ignore = ["E501"]
  ```
- Ruff resolved version 0.15.16 (`uv run ruff --version`, per the source plan) recognizes
  both `BLE001` and `PLC0415` as valid rule codes today, though neither is currently
  selected — confirmed by the plan's UNK-01 evidence (`uv run ruff check scripts/ tests/`
  under default config: exit 0, zero BLE/PLC findings; `--select BLE,PLC0415`: 1255
  findings).
- `BLE001` is the sole member of the `BLE` family with findings in this repo (measurement:
  `--select BLE` and `--select BLE001` both report 62), so selecting the exact code
  `"BLE001"` (not the family shorthand `"BLE"`) is equivalent in effect and more explicit.

## Design decisions

- Select the exact rule code `"BLE001"`, not the `"BLE"` family shorthand — matches the
  plan's Assumption 2 (equivalent in this repo, more explicit for future readers).
- Record the `PLC0415` exclusion as an inline TOML comment (not only in `rules/coding.md`)
  so the decision is visible at the point where a future contributor might otherwise
  "helpfully" add it to `select`.

## Alternatives considered

- Select the `"BLE"` family instead of `"BLE001"` — rejected: no behavioral difference
  today (both report 62 findings) but less explicit; per plan Assumption 2, the exact
  code is preferred for minimal, explicit footprint.
- Add `PLC0415` alongside `BLE001` — rejected: measured blast radius (~1193 net-new
  findings) makes it a disproportionate, separate effort (see plan Scope/Out-of-Scope
  and Risks).
