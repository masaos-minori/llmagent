# Implementation Procedure: scripts/agent/startup.py

## Goal
Delete the unreachable `if ctx.workflow is None: return` guard at the top of
`StartupOrchestrator._recover_pending_approvals()` (`scripts/agent/startup.py:518-519`),
since `AgentContext.__init__()` (`scripts/agent/context.py:276`) unconditionally assigns
`self.workflow = WorkflowState()` and no code path anywhere in the codebase reassigns
`ctx.workflow` to `None`.

## Scope
**In scope**
- `scripts/agent/startup.py` — delete the two-line dead guard (current lines 518-519:
  `if ctx.workflow is None:` / `return`) inside `_recover_pending_approvals()`.

**Out of scope**
- `scripts/agent/context.py` / `WorkflowState` / `AgentContext.__init__()` — reference only,
  no change.
- Any new flag, config option, or alternate gating condition in place of the removed check.
- Any other line of `_recover_pending_approvals()` (approval fetch, selection, warning
  messages, store lifecycle) — unchanged.
- `tests/agent/test_startup.py` — no new test added; existing
  `TestStartupOrchestratorRecoverPendingApprovals` tests are regression-verified unmodified
  (a "workflow is None" test would exercise a state that cannot occur).

## Assumptions
1. `AgentContext.__init__()` (`scripts/agent/context.py:271-276`) remains the sole
   construction path for `ctx.workflow`; confirmed via `rg -n "\.workflow\s*=" scripts/agent/`
   returning a single hit at `context.py:276`.
2. No test in `tests/agent/test_startup.py` relies on the removed `None` branch; all 8
   methods in `TestStartupOrchestratorRecoverPendingApprovals`
   (`tests/agent/test_startup.py:121-379`) set `ctx.workflow = MagicMock()` (a non-`None`
   object) before calling `_recover_pending_approvals()` — confirmed for the first method at
   lines 127-128 and structurally consistent across the class.
3. Removing the guard is a pure dead-code deletion with no observable behavior change for
   any currently reachable code path (the guard's body — a bare `return` — never executes
   today).

## Design decisions
- Delete the guard outright rather than replacing it with an assertion or a differently
  worded check: the field's declared type was never `WorkflowState | None`, so no
  type-safety net is lost by removing it — the check was inconsistent with its own type,
  not a defensive boundary.
- No new abstraction (e.g. a `Protocol` or helper) is introduced; this is a two-line
  deletion inside an existing private method, consistent with "use abstractions only when
  justified."

## Alternatives considered
- **Keep the guard, add a code comment explaining it is unreachable** — rejected: dead code
  with a comment is still dead code; it does not reduce reader confusion as effectively as
  removal, and the class docstring (`context.py:206-211`) already documents that
  `WorkflowState` is populated at startup.
- **Change `ctx.workflow` to `Optional[WorkflowState]` to make the guard meaningful** —
  rejected: no code path needs `ctx.workflow` to ever be `None`; introducing optionality
  would force defensive `is None` checks at every other of the many unconditional
  `ctx.workflow.*` access sites across `scripts/agent/`, which is a net regression in type
  safety and clarity for no behavioral benefit.
