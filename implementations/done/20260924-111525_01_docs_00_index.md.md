## Goal

Implement REQ-001 (`plans/20260924-105359_plan.md`) in `docs/00_index.md`: add
the correct new reorg-subfolder path to every specific `docs/*.md` filename
reference across all 5 sections that contain one (Categories, Recommended
Reading Order, Known Issues, Document References by Task, Related
Documents).

## Scope

Modify only `docs/00_index.md`. Every specific, currently-valid `docs/*.md`
filename reference in the file's 5 reference-bearing sections gets its
mapped subfolder prepended, per the Plan's Design mapping table (reproduced
in Details below). Two references are explicitly left untouched: line 72's
pre-existing broken `tools/01_overview.md` (out of scope, unrelated defect —
see Plan Problem) and line 50's `` `routing.md` `` mention (not a `docs/`
file). Line 63's two parenthetical glob-pattern mentions
(`01_overview-arch-*.md`, `01_overview-files-*.md`) are also left unchanged
— per the Plan's Assumptions, a glob pattern is not a "specific filename"
this Requirement targets.

## Assumptions

- Every filename in this file that appears in the Plan's confirmed 11-way
  folder-classification mapping is globally unique in `docs/` (re-confirmed
  by this cycle's own verification, not merely assumed from the Plan) — so a
  whole-file, backtick-anchored (`` `filename.md` ``) or Markdown-link-anchored
  (`(filename.md)`) string replacement cannot cross-match an unrelated file.
- `docs/00_index.md` itself moves to `docs/00_governance/00_index.md` (per
  `docsreorg05`) — its self-reference row in "Document References by Task"
  (`` `00_index.md` ``, line 73) is treated the same as every other filename
  reference: updated to `` `00_governance/00_index.md` ``.
- `tools/01_overview.md` (line 72) is a distinct, already-broken reference
  (confirmed via `test -f tools/01_overview.md` returning not-found, and via
  `git log` showing no file has ever existed under that name) — left
  untouched, out of scope per the Plan.

## Design decisions

- Applied as one mechanical, whole-file pass keyed off the Plan's Design
  mapping table (prefix → subfolder), rather than per-line manual edits —
  the sheer count (53 distinct filenames, ~85 total occurrences across 5
  sections) makes a scripted, table-driven replacement materially safer
  against a missed or mistyped occurrence than dozens of individual `Edit`
  calls, and every resulting occurrence was independently re-verified (see
  Validation plan) before being accepted as correct.
- Two replacement anchors are used, matching the file's two citation styles:
  backtick-quoted bare filenames (`` `filename.md` `` → `` `subfolder/filename.md` ``,
  used by the "Document References by Task" table, "Related Documents", and
  the file's own self-reference) and Markdown-link parenthetical targets
  (`(filename.md)` → `(subfolder/filename.md)`, used by "Categories",
  "Recommended Reading Order", and "Known Issues"). Anchoring to the
  backtick/paren delimiter is what safely excludes `tools/01_overview.md`
  from an `01_overview.md` replacement — the character immediately before
  `01_overview.md` in that citation is `/`, not a backtick, so the
  backtick-anchored pattern `` `01_overview.md` `` never matches inside it.

## Alternatives considered

- Per-occurrence manual `Edit` calls: rejected — at ~85 occurrences across 5
  sections, this is both slower and a materially higher risk of a missed or
  inconsistent occurrence than a single table-driven pass verified
  afterward by a full-file scan (see Validation plan).
- Widening every reference to a recursive glob or restructuring the tables:
  out of scope — the Plan's Requirements call for adding a directory prefix
  only, not restructuring content.

## Implementation

### Target file

`docs/00_index.md`

### Procedure

1. Build the prefix → subfolder mapping table (identical to the Plan's
   Design section) as an explicit `{filename: subfolder}` dict covering
   every filename this Requirement's Problem section identifies.
2. For each `(filename, subfolder)` pair, replace every occurrence of
   `` `filename` `` with `` `subfolder/filename` ``, and every occurrence of
   `(filename)` with `(subfolder/filename)`, across the whole file.
3. Separately replace the file's own self-reference,
   `` `00_index.md` `` → `` `00_governance/00_index.md` ``.
4. Re-scan the whole file for any remaining un-prefixed occurrence of a
   known reorg-relevant filename prefix (`00_governance`, `00_security`,
   `01_overview`, `02_deployment`, `03_rag`, `04_mcp`, `05_agent`,
   `06_eventbus`, `90_shared`, `adr-index`) to confirm no occurrence was
   missed, and separately scan for any accidental double-prefixing (a
   subfolder name immediately followed by itself).

### Method

A single Python pass (via `Bash`, `python3 -c` / a short scratch script) is
the method of choice here — not `Edit` — because step 2 above is the same
mechanical operation repeated ~85 times across a single file, which is
exactly the class of task `rules/ai-execution.md` Repository Tool Usage's
"minimal permitted fallback" language anticipates when no narrower
repository tool exists for it (`tools/` has no "add a directory prefix to a
Markdown reference" utility). Record the fallback and reason here per that
rule. After running it, verify via `git diff docs/00_index.md` line-by-line
against the Details section below — do not treat the script's exit code
alone as evidence (`rules/ai-execution.md` Repository Tool Usage #8).
