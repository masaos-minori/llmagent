## Goal

Deduplicate `session_id`/`request_id` header-extraction boilerplate across `scripts/mcp_servers/**/*_server.py` by introducing a shared helper function.

## Scope

- **In-Scope**:
  - Phase 1: Enumerate all `*_server.py` files with the duplicate pattern and write characterization tests
  - Phase 2: Create `extract_request_context()` shared helper in `scripts/mcp_servers/server.py`
  - Phase 3: Replace inline extraction in each `*_server.py` with calls to the shared helper
- **Out-of-Scope**:
  - Runtime behavior changes (pure extraction, no semantic changes)
  - Changes outside `scripts/mcp_servers/`
  - Modifying other request-context fields beyond session_id and request_id

## Assumptions

- `scripts/mcp_servers/server.py` exists and is the shared base module for MCP servers
- All `*_server.py` files use the exact same 4-line pattern: `request.headers.get("x-session-id", "")` + `getattr(request.state, "request_id", request.headers.get("x-request-id", ""))`
- The `Request` type is available from Starlette/FastAPI (standard in these servers)

## Design decisions

- Place the shared helper in `scripts/mcp_servers/server.py` (the common base module) rather than creating a new module
- Use `Required`/`NotRequired` annotations on the extracted values to clarify contract
- Keep the helper signature simple: takes `Request`, returns `(str, str)` tuple

## Alternatives considered

- Create a separate `request_context.py` module — rejected because `server.py` is the natural home for shared server-side utilities
- Wrap the extraction in a FastAPI dependency — overkill for a simple header extraction; adds unnecessary complexity
- Use a context manager — unnecessary indirection for a synchronous operation

## Compatibility considerations

- No runtime behavior change — pure extraction logic preserved
- Requires the `Request` type from Starlette/FastAPI (already used in all affected servers)
- Import order must not introduce circular dependencies

## Security considerations

- N/A — no security-relevant behavior change; same headers accessed, just via a shared function

## Rollback considerations

- Revert the diff to restore inline extraction in each server file; no data loss or service impact

### Method

Refactoring — extract shared helper function and replace inline code in multiple modules.

### Details

```python
# In scripts/mcp_servers/server.py, add:

from starlette.requests import Request

def extract_request_context(request: Request) -> tuple[str, str]:
    """Extract session_id and request_id from request headers/state.
    
    Returns:
        Tuple of (session_id, request_id), defaulting to empty string if not present.
    """
    session_id = request.headers.get("x-session-id", "")
    # request_id may be in state (set by middleware) or fall back to header
    request_id = getattr(request.state, "request_id", request.headers.get("x-request-id", ""))
    return session_id, request_id
```

Example replacement in `scripts/mcp_servers/git/git_server.py`:

```python
# BEFORE:
session_id = request.headers.get("x-session-id", "")
request_id = getattr(request.state, "request_id", request.headers.get("x-request-id", ""))

# AFTER:
session_id, request_id = extract_request_context(request)
```
