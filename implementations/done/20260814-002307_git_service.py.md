## Assumptions

- Installed `gitpython` is 3.1.50 (per `uv.lock`); its `git/__init__.py` does not itself
  `import git.exc` or re-export it, which is why pyright cannot statically resolve
  `git.exc.GitError` in the `_GIT_ERRORS` tuple without an explicit import.
- `git_service.py` is only loaded when the git MCP server is active, so there is no
  lazy-import/startup-cost concern here (unlike `git_helper.py`); a top-level import is
  appropriate and mirrors the existing top-level `import git`.

## Design decisions

  import ordering isort/ruff-`I`-compatible (`git` sorts before `git.exc` alphabetically).
- Do not restructure the `_GIT_ERRORS` tuple — only the name resolution changes, not its
  value, order, or the `# All git tool handlers catch this union...` comment above it.
