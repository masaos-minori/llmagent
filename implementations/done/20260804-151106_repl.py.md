# Implementation Procedure: scripts/agent/repl.py

## Goal
Pass `AgentREPL`'s existing `self._shutdown_event` into the `StartupOrchestrator(...)`
constructor call so the startup sequence can be interrupted by the same SIGINT/SIGTERM signal
that already interrupts `_repl_loop()`.

## Scope
- In scope: the single `StartupOrchestrator(self._ctx, self._view)` construction call inside
  `AgentREPL.run()` (current line 829).
- Out of scope: `AgentREPL._repl_loop()`'s own shutdown handling (already implemented,
  unchanged); the `_sigterm_handler()` closure and signal-registration block (current lines
  757-827, unchanged); any other `AgentREPL` method.

## Assumptions
- `self._shutdown_event = asyncio.Event()` is constructed at current line 755, strictly before
  the `StartupOrchestrator(...)` call at current line 829 — confirmed by reading
  `scripts/agent/repl.py:743-829` in this session (both lines fall inside the same `run()`
  method, with the `Event()` construction preceding the constructor call in source order).
- `StartupOrchestrator.__init__()` accepts an optional `shutdown_event` keyword parameter after
  the companion `implementations/20260804-151105_startup.py.md` procedure is applied. This
  `repl.py` edit must not be applied before that one, or the added keyword argument will raise
  `TypeError` against the pre-change constructor signature.

## Design decisions
- Pass `shutdown_event=self._shutdown_event` as a keyword argument (not positional) — matches
  the keyword-capable, optional-default parameter added to `StartupOrchestrator.__init__()`,
  and keeps the call site self-documenting.
- No new attribute, method, or signal-handling logic added to `repl.py` — this is a pure
  one-line additive change forwarding an already-existing object.

## Alternatives considered
- Construct a second, separate `asyncio.Event()` dedicated to startup interruption instead of
  reusing `self._shutdown_event`: rejected — the same signal (SIGINT/SIGTERM) should abort both
  startup and the REPL loop; a second event would require duplicating the signal-handler wiring
  in `_sigterm_handler()` for no behavioral benefit.
