## Goal

In `scripts/db/store_impl.py`: add a mandatory `fetched_at: str` parameter to
`SQLiteDocumentStore.doc_upsert()`, use it directly in the `INSERT` column
list and the `ON CONFLICT(url) DO UPDATE SET fetched_at = ...` clause, and
remove the `strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` current-time substitution
entirely.

## Scope

- In scope: `scripts/db/store_impl.py`'s `doc_upsert()` method — signature
  and SQL body only.
- Out of scope: `scripts/db/store_protocols.py`'s `DocumentStore.doc_upsert()`
  Protocol declaration and `tests/db/test_db_store_impl.py`'s 12 call sites
  (each has its own implementation document in this plan's batch).
- Out of scope: `doc_get()`, `doc_list()`, `doc_delete()`, `_row_to_document()`
  — none of these construct or bind `fetched_at`; they only read the existing
  column, so no change is needed.

## Assumptions

- `SQLiteDocumentStore.doc_upsert()` has zero production callers today
  (plan Assumptions, confirmed via `rg -n "doc_upsert\(" scripts/ tests/`):
  matches are only the `Protocol`/implementation definitions and 12 direct
  calls in `tests/db/test_db_store_impl.py`. The live ingestion path writes
  through `Ingester._insert_document()`'s raw SQL instead, so widening this
  signature carries no live-path regression risk.
- The `fetched_at` value passed in is already canonical UTC
  (`YYYY-MM-DDTHH:MM:SSZ`) by the time it reaches this method — generation
  and validation happen upstream (crawler, `pipeline_utils.py`, `ingester.py`,
  per the plan's Design section). `doc_upsert()` itself does not reformat or
  validate the string; it binds it as-is.
- Current implementation, confirmed by reading the file:
  `doc_upsert(self, url: str, title: str | None, lang: str, etag: str | None,
  last_modified: str | None) -> int`, with an `INSERT INTO documents (url,
  title, lang, etag, last_modified) VALUES (...) ON CONFLICT(url) DO UPDATE
  SET title = excluded.title, lang = excluded.lang, etag = excluded.etag,
  last_modified = excluded.last_modified, fetched_at =
  strftime('%Y-%m-%dT%H:%M:%SZ', 'now') RETURNING doc_id`.

## Design decisions

- Add `fetched_at` as a new mandatory parameter, positioned to match
  `store_protocols.py`'s `DocumentStore.doc_upsert()` Protocol exactly (see
  that file's own implementation document for the agreed position) — a
  positional mismatch between Protocol and implementation is a `mypy`-only
  failure, not a runtime one, so the two must be read together before editing.
- On `INSERT`, add `fetched_at` to the column list and bind it as a normal
  parameter; on conflict, set `fetched_at = excluded.fetched_at`, following
  the same `excluded.<column>` pattern already used for `title`, `lang`,
  `etag`, and `last_modified` in this method, rather than introducing a
  differently-shaped clause for just this one column.

## Alternatives considered

- Keep `strftime('now')` for the update branch and only add `fetched_at` to
  the `INSERT` — rejected: the plan explicitly requires `ON CONFLICT ... DO
  UPDATE SET fetched_at = ?` and full removal of the current-time
  substitution; leaving it on the update path would silently reintroduce a
  non-canonical value on every re-upsert.
- Bind `fetched_at` as an extra `?` placeholder duplicated into the update
  clause instead of using `excluded.fetched_at` — both are functionally
  equivalent in SQLite; `excluded.fetched_at` was chosen for consistency with
  the four sibling columns already written that way in this method, avoiding
  a mixed style and an extra positional parameter to keep in sync.

## Implementation

### Target file

`scripts/db/store_impl.py`

### Procedure

1. Locate `SQLiteDocumentStore.doc_upsert()`'s signature; add `fetched_at:
   str,` in the position agreed with `store_protocols.py`'s corresponding
   Protocol edit.
2. In the `INSERT INTO documents (...)` column list, add `fetched_at`; add a
   matching `?` placeholder to `VALUES (...)`; add `fetched_at` to the bound
   parameter tuple in the same position.
3. In the `ON CONFLICT(url) DO UPDATE SET` clause, replace the line
   `fetched_at = strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` with `fetched_at =
   excluded.fetched_at`.
4. Leave `RETURNING doc_id`, the `cur.fetchone()` guard, and the
   `RuntimeError` on a missing row unchanged.

### Method

Direct signature and SQL-string edit; no new imports required.

### Details

- After the edit, `rg -n "strftime" scripts/db/store_impl.py` must return
  zero matches (the plan's Phase 6 validation pattern).
- Because `schema_sql.py`'s `documents.fetched_at` column is losing its
  `DEFAULT` clause (this batch's companion document), `doc_upsert()`'s
  `INSERT` no longer has any DB-level fallback — every caller must now
  supply a non-empty `fetched_at` string or the statement raises
  `sqlite3.IntegrityError` (`NOT NULL constraint failed`) at the SQL layer.
- The Protocol and this implementation must land together; Python does not
  enforce `Protocol` conformance at runtime, so a signature mismatch would
  surface only via `uv run mypy scripts/`, not via a failing test, if a
  caller happens to pass matching arity to one but not the other.

## Compatibility considerations

- Zero production callers today (Assumptions above) — no live ingestion path
  is affected by this signature widening.
- All 12 existing calls in `tests/db/test_db_store_impl.py` break at call
  time (missing required argument) until that file's own implementation
  document updates them — the two changes must land in the same change set.
- Must be edited in lockstep with `store_protocols.py`'s Protocol
  declaration to avoid a structural-typing drift that only `mypy` — not the
  test suite — would catch.

## Security considerations

N/A: `fetched_at` is bound via the existing parameterized query (`?`), the
same trust boundary already applied to `url`/`title`/`lang`/`etag`/
`last_modified`; no string interpolation into SQL text and no new external
input path is introduced by this change.

## Rollback considerations

- Revert this file's diff together with `store_protocols.py` and
  `tests/db/test_db_store_impl.py` as one unit; reverting `store_impl.py`
  alone while the Protocol still declares `fetched_at` mandatory leaves a
  structural-typing mismatch `mypy` would flag.
- No data migration is implied by reverting — this file makes no schema
  change on its own (the `DEFAULT` clause removal lives in `schema_sql.py`'s
  own document); the two can be reverted independently without corrupting
  existing data.

## Validation plan

- `uv run mypy scripts/` — confirms `doc_upsert()`'s implementation matches
  the `DocumentStore` Protocol's `fetched_at` position and type.
- `uv run pytest tests/db/test_db_store_impl.py -v` — the 12 call sites
  (updated per that file's own implementation document) exercise both the
  insert and conflict-update paths.
- `rg -n "strftime\('%Y-%m-%dT%H:%M:%SZ'" scripts/db/store_impl.py` — zero
  matches after the change.
- Manual smoke check: call `doc_upsert(...)` twice for the same `url` with
  two different `fetched_at` values and confirm `doc_get(url)` returns the
  second value, not a `strftime('now')`-derived timestamp.

## Out of scope

- `tests/db/test_db_store_impl.py`'s 12 call-site updates (own

- `doc_get()`, `doc_list()`, `doc_delete()` — unaffected by this change.
