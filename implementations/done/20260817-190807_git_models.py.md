## Goal

Introduce a shared base class/mixin carrying the `repo_path` field across all 10 Pydantic request models in `git_models.py`, reducing remaining duplication while ensuring byte-identical JSON Schema output before and after the change.

## Scope

### In-Scope
- Introducing a mixin/base class for `repo_path` field in git_models.py's 10 request models
- Schema-diff verification against baseline
- Validation of downstream consumers

### Out-of-Scope
- Changing any model's runtime validation behavior (field name, type, requiredness)
- Modifying git_server.py or git_tools.py beyond what's necessary for schema compatibility
- Extending to other MCP servers' models

## Assumptions

- The existing `_REPO_PATH_DESC` constant (`"Absolute path to the git repository"`) will remain unchanged
- Pydantic v2's `model_json_schema()` behavior with inheritance can be controlled via `model_config` settings (e.g., `populate_by_name`)
- The `TOOL_LIST` in `git_tools.py` is the primary consumer of these models' schemas and must not change shape
- No caller relies on the exact structure of `model_fields` ordering for any of the 10 models

## Design decisions

- Use a mixin class pattern rather than a base class — avoids MRO complications with Pydantic's BaseModel
- Require explicit sign-off if schema restructuring ($defs/wrapping) is detected — MCP clients may parse schema structure
- Verify both `model_json_schema()` output AND `model_fields` key ordering — two independent baselines

## Alternatives considered

- Inline `repo_path` in each model — rejected because it duplicates the field definition across 10 models
- Use a base class instead of mixin — rejected because Pydantic v2 MRO with multiple BaseModel subclasses is fragile; mixin avoids this
- Skip schema-diff verification — rejected because structural changes could break MCP client consumers

## Compatibility considerations

- Byte-identical JSON Schema output is the goal — any structural change requires explicit sign-off
- `model_fields` key ordering must remain stable — downstream consumers may rely on it
- MCP clients consuming git-mcp tool schemas must not break

## Security considerations

- None identified — this is a refactoring of model definitions, no security-sensitive code paths involved

## Rollback considerations

- Revert the diff; no data loss or service impact

### Method

Refactoring — extract shared `repo_path` field into a mixin to reduce duplication across 10 Pydantic models.

### Details

```python
# In scripts/mcp_servers/git/git_models.py:

# BEFORE (each of 10 models repeats repo_path):
_GitStatusRequest(BaseModel):
    repo_path: str = Field(..., description=_REPO_PATH_DESC)
    
    class Config:
        populate_by_name = True

class GitDiffRequest(BaseModel):
    repo_path: str = Field(..., description=_REPO_PATH_DESC)
    
    class Config:
        populate_by_name = True

# AFTER (mixin eliminates duplication):
class RepoPathMixin:
    """Mixin providing the common repo_path field."""
    repo_path: str = Field(..., description=_REPO_PATH_DESC)

class GitStatusRequest(RepoPathMixin, BaseModel):
    class Config:
        populate_by_name = True

class GitDiffRequest(RepoPathMixin, BaseModel):
    class Config:
        populate_by_name = True

# Phase 1: Baseline generation
import json
from pathlib import Path

def generate_baseline():
    """Generate baseline schemas for comparison."""
    baseline_dir = Path("baseline_schemas")
    baseline_dir.mkdir(exist_ok=True)
    
    from scripts.mcp_servers.git.git_models import *
    
    models_to_check = [
        GitStatusRequest, GitDiffRequest, GitCommitRequest,
        GitPushRequest, GitPullRequest, GitCheckoutRequest,
        GitBranchRequest, GitTagRequest, GitLogRequest,
        GitShowRequest,
    ]
    
    for model_cls in models_to_check:
        schema = model_cls.model_json_schema()
        fields = list(model_cls.model_fields.keys())
        
        (baseline_dir / f"{model_cls.__name__}_schema.json").write_text(
            json.dumps(schema, indent=2, sort_keys=True)
        )
        (baseline_dir / f"{model_cls.__name__}_fields.txt").write_text("\n".join(fields))

# Phase 2: Schema diff verification
def compare_schemas(baseline_dir: Path) -> dict[str, dict]:
    """Compare current schemas against baseline."""
    results = {}
    
    for schema_file in baseline_dir.glob("*_schema.json"):
        model_name = schema_file.stem.replace("_schema", "")
        # Import the model class dynamically
        model_cls = globals()[model_name]
        
        baseline = json.loads(schema_file.read_text())
        current = model_cls.model_json_schema()
        
        # Compare field ordering
        baseline_fields = (baseline_dir / f"{model_name}_fields.txt").read_text().strip().split("\n")
        current_fields = list(model_cls.model_fields.keys())
        
        if baseline_fields != current_fields:
            results[model_name]["field_order_changed"] = True
        
        # Compare schema structure
        if json.dumps(baseline, sort_keys=True) != json.dumps(current, sort_keys=True):
            results[model_name]["schema_changed"] = True
    
    return results
```
