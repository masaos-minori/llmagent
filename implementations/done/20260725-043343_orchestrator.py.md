## Goal

Consolidate ephemeral message filtering into a single location (`_clear_previous_turn_ephemeral_messages`) to eliminate redundant work.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._handle_history_compression())
**Out**: Changes to message filtering logic, other history manipulation paths

## Assumptions

1. `_clear_previous_turn_ephemeral_messages()` always runs before any path that modifies `ctx.conv.history`
2. The filter condition `not m.get("_ephemeral") and not m.get("_memory_injected")` is identical in both locations
3. Removing the filter from `_handle_history_compression()` will not break history compression logic

## Design decisions

- Remove duplicate filter from `_handle_history_compression()` — pass full history to `replace_messages()` without filtering
- Add explicit comment explaining why ephemeral/memory-injected filtering is NOT applied here — because `_clear_previous_turn_ephemeral_messages()` handles it before every turn
- No changes needed to `_clear_previous_turn_ephemeral_messages()`

## Alternatives considered

- **Add an assertion in _handle_history_compression that ephemeral messages are absent**: Would catch bugs but adds runtime overhead; could be added later if needed
- **Move the filter into replace_messages()**: Would require changing the session API contract; too invasive for this fix
- **Keep both filters for defense-in-depth**: Defeats the purpose of consolidation; unnecessary duplication

```python
    async def _handle_history_compression(self) -> None:
        """Compress conversation history and replace messages if compression occurred.

        Note: ephemeral/memory-injected messages are NOT filtered here because
        _clear_previous_turn_ephemeral_messages() already strips them before every
        turn. Passing the full history avoids double-filtering.
        """
        ctx = self._ctx
        with self._llm_runner._span_ctx("compress"):
            ctx.conv.history, result = await ctx.services_required.hist_mgr.compress(
                ctx.conv.history
            )
            if (
                result.compressed_count > 0
                or result.summary_added
                or result.is_fallback
            ):
                ctx.session.replace_messages(ctx.conv.history)
```

Key points:
- Removed the list comprehension filter — passes full history directly
- Added docstring comment explaining why filtering is skipped
- Same behavior as before — ephemeral/memory-injected messages were already removed by `_clear_previous_turn_ephemeral_messages()`

### Method

Extract ownership of ephemeral message cleanup into the data access layer (`_clear_previous_turn_ephemeral_messages`). Eliminate duplicate filtering in `_handle_history_compression()` by passing full history to `replace_messages()`. Add explanatory comment to prevent future regression.

### Details

The core issue is that ephemeral/memory-injected messages are filtered twice:
1. First in `_clear_previous_turn_ephemeral_messages()` — called at the start of every turn
2. Second in `_handle_history_compression()` — when replacing messages after compression

This redundancy exists because `_handle_history_compression()` was written defensively, assuming it might receive a history containing ephemeral messages. However, since `_clear_previous_turn_ephemeral_messages()` runs before every turn processing path, this assumption is incorrect.

By removing the duplicate filter:
- Eliminates unnecessary list comprehension on every compression
- Makes the filtering responsibility explicit via docstring
- Reduces cognitive load — one source of truth for ephemeral message handling
