## Goal
In `scripts/rag/ingestion/crawler.py`: retire `CrawlPayload`; align all payload dicts to
`CrawlJsonPayload` shape (exact key set: `url`, `content`, `title`, `lang`, `code_blocks`,
`etag`, `last_modified` — **no extra keys** like `schema_version`/`artifact_type`/
`created_by`/`fetched_at`); always emit `etag`/`last_modified` keys (value `None` when
unavailable) instead of conditional insertion; enforce `lang in {"ja","en"}` and
`code_blocks: list[str]`; allow empty `content` only when `code_blocks` is non-empty.

## Scope
- In scope: `scripts/rag/ingestion/crawler.py` only.
- Out of scope: `pipeline_utils.py`'s `CrawlJsonPayload`/`read_crawl_json()` themselves
  (own implementation document) — this file becomes a producer that emits payloads
  conforming to that shape, but does not define or import the reader in this step
  (import wiring can reuse `CrawlJsonPayload` as the payload's type annotation).

## Adversarial review findings
### Finding #1 — `read_crawl_json()` enforces exact key set
`pipeline_utils.py:116-131` performs an **exact key-set check**:
```python
required_keys = {"url","content","title","lang","code_blocks","etag","last_modified"}
missing = required_keys - actual_keys
extra = actual_keys - required_keys
if missing: raise ChunkFormatError("Missing keys")
if extra:   raise ChunkFormatError("Unknown keys")
```
This means any payload dict written with extra keys (like `schema_version`, `artifact_type`,
`created_by`, `fetched_at`) will fail validation at read time. The original procedure did
not account for this — removing `CrawlPayload` TypedDict alone is insufficient; all payload
dict literals must also drop those four extra keys.

### Finding #2 — `CrawlPayload` TypedDict shape mismatch
`CrawlPayload` (crawler.py:44-57) has fields `schema_version`, `artifact_type`, `created_by`,
`fetched_at` that `CrawlJsonPayload` does NOT have. Simply replacing the type annotation from
`CrawlPayload` to `CrawlJsonPayload` would cause mypy errors because the dict literals include
those extra keys. Both TypedDicts must converge to the same shape.

### Finding #3 — `title` type difference
`CrawlPayload.title` is `str` but `CrawlJsonPayload.title` is `str | None`. When
`_save_crawl_file()` passes `title=None` (possible via `orjson.dumps` serialization of
`None`), mypy would flag this against `CrawlPayload` but not against `CrawlJsonPayload`.

### Finding #4 — `etag`/`last_modified` null values are accepted at read side
`test_pipeline_utils_strict.py:test_null_etag_accepted` and
`test_null_last_modified_accepted` confirm that `None` values ARE accepted for these fields
at the reader side. However, the current crawler conditionally omits the KEY entirely when
value is `None` (lines 339-342), which fails `read_crawl_json()`'s exact key-set check.
The fix is to always write the key (even with `None` value), matching the approach already
taken in `crawl_file()` (lines 132-133).

## Assumptions
- Only `_save_crawl_file()` (currently `crawler.py:315-348`, conditional insertion at
  lines 339-342) has the conditional-key bug. `crawl_file()` (the local-file path,
  lines 100-142) already unconditionally sets both `etag` (SHA-256) and
  `last_modified` (mtime ISO string) — confirmed by reading the full function body.
  No change needed there beyond the `CrawlPayload` → `CrawlJsonPayload` type-annotation
  swap AND removal of the four extra keys (`schema_version`, `artifact_type`, `created_by`,
  `fetched_at`).
- `_SUPPORTED_LANGS` (`frozenset({"en", "ja"})`, defined in
  `rag/ingestion/crawler_utils.py:22`) is the existing source of truth for the
  `lang in {"ja","en"}` rule — reuse it rather than hardcoding a new literal set.
- The async URL-fetch path (`_process_crawl_url_async`, line ~439) already skips saving
  when `resolved_lang not in _SUPPORTED_LANGS` — so by the time `_save_crawl_file()` is
  called from that path, `lang` is already valid. `crawl_file()` (local-file path) has
  **no equivalent check** before building its payload — `resolved_lang` from
  `_resolve_lang()` is used directly. This is a real gap: enforcing
  `lang in {"ja","en"}` uniformly means either (a) adding the same guard to
  `crawl_file()` before it writes, or (b) enforcing the check inside the payload
  construction/write path shared by both callers. Choose (a) unless a shared
  write-path helper is introduced, to keep this change minimal and match the async
  path's existing pattern.

## Design decisions
- Enforce `lang`/`code_blocks`/empty-content-requires-code-blocks validity in Python
  before constructing the payload dict (raise or skip-and-log on violation), rather
  than deferring to `read_crawl_json()` on the reader side — the crawler is the
  producer and should never emit a payload its own reader would reject.
- Replace `CrawlPayload`'s `NotRequired[str | None]` for `etag`/`last_modified` with
  `CrawlJsonPayload`'s mandatory nullable-value fields; drop the two
  `if x is not None: payload["etag"] = x` conditionals (lines 339-342) in favor of
  always assigning `etag=etag, last_modified=last_modified` (which may be `None`)
  directly in the dict literal.
- Remove the four extra keys (`schema_version`, `artifact_type`, `created_by`,
  `fetched_at`) from ALL payload dict literals — they violate `read_crawl_json()`'s
  exact key-set enforcement (Finding #1/#2 above).
- Align `CrawlPayload` TypedDict to `CrawlJsonPayload` shape: remove the four extra
  keys, change `title: str` → `title: str | None`, change `etag: NotRequired[str | None]`
  → `etag: str | None`, change `last_modified: NotRequired[str | None]` →
  `last_modified: str | None` (Finding #2/#3 above).

## Alternatives considered
- Raising immediately inside `_save_crawl_file()` on an invalid `lang` (instead of
  skip-and-log) — rejected for the local-file (`crawl_file()`) path to keep behavior
  consistent with the existing async path's skip-and-log-then-continue pattern (a
  single bad local file should not crash a batch `crawl()` run); reconsider only if the
  requirement document mandates hard failure here.

## Implementation
### Target file
`scripts/rag/ingestion/crawler.py`

### Procedure
1. Rewrite `class CrawlPayload(TypedDict)` (lines 44-57) to match `CrawlJsonPayload`
   exactly: remove `schema_version`, `artifact_type`, `created_by`, `fetched_at`; change
   `title: str` → `title: str | None`; change `etag: NotRequired[str | None]` →
   `etag: str | None`; change `last_modified: NotRequired[str | None]` →
   `last_modified: str | None`. Import `CrawlJsonPayload` from
   `rag.ingestion.pipeline_utils` and use it as the payload type annotation instead of
   `CrawlPayload` (adjust the `from typing import NotRequired, TypedDict` import if no
   longer needed after removal — re-check with `rg` for other `TypedDict`/`NotRequired`
   usage in this file first).
2. In `_save_crawl_file()` (lines 315-348): change the payload dict literal to always
   include `"etag": etag, "last_modified": last_modified` (both possibly `None`);
   delete the two `if etag is not None: ...` / `if last_modified is not None: ...`
   conditionals (lines 339-342).
3. In `crawl_file()` (lines 100-142): remove the four extra keys (`schema_version`,
   `artifact_type`, `created_by`, `fetched_at`) from the payload dict literal (lines
   122-134). Add a lang-guard right after `resolved_lang` is computed (line 112-114),
   before the `sha256`/`mtime_iso` computation, mirroring the async path's existing
   `if resolved_lang not in _SUPPORTED_LANGS: logger.debug(...); return` pattern at
   line 439. Validate `code_blocks` is a `list[str]` and that `content` is non-empty
   unless `code_blocks` is non-empty (skip + log on violation).
4. In `_save_crawl_file()`: validate `lang` against `_SUPPORTED_LANGS` and validate
   `code_blocks` is a `list[str]` and that `content` is non-empty unless `code_blocks`
   is non-empty (skip + log on violation).
5. Update the payload dict's type annotation from `CrawlPayload` to `CrawlJsonPayload`
   at both construction sites (lines 122, 328).

### Method
- Keep validation as small guard clauses (`if`/`return`/`continue`) matching the
  existing skip-and-log style already used elsewhere in this class (e.g. the
  `resolved_lang not in _SUPPORTED_LANGS` guard at line 439), not a raised exception —
  this file is a producer/batch job, not a strict boundary reader.

### Details
- `crawl_file()`'s payload (lines 122-134) must lose the four extra keys
  (`schema_version`, `artifact_type`, `created_by`, `fetched_at`) — these violate
  `read_crawl_json()`'s exact key-set enforcement. After removal, the payload has
  exactly 7 keys matching `CrawlJsonPayload`. The lang-guard goes right after
  `resolved_lang` is computed (line 112-114), before the `sha256`/`mtime_iso` computation.
- `_save_crawl_file()`'s signature (`etag: str | None = None, last_modified: str | None
  = None`, lines 322-323) stays the same — only the payload-dict construction changes.
  Always write `"etag": etag, "last_modified": last_modified` even when `None`.
- `_process_crawl_url_async()` already guards `lang` before calling
  `_save_crawl_file()` (line 439), so no duplicate guard is needed on that call path;
  only `crawl_file()`'s call path needs the new guard.
