# Implementation Procedure: Clean Up Health Check Timestamps When Servers Are Removed

## Goal

Ensure `_last_health_check` entries are cleaned up when an MCP server key is removed from configuration, preventing bounded memory leak.

## Scope

**In-Scope:**
- Identify where server keys are removed from `ctx.cfg.mcp.mcp_servers` during hot-reload
- Add cleanup of corresponding `_last_health_check` entry alongside existing cleanup operations

**Out-of-Scope:**
- Adding hot-reload support (this is about cleaning up after removal that already happens)
- Cleaning up other dictionaries that may also leak (`_stderr_files`, `_stderr_log_paths`)
- Modifying shutdown/restart paths (those already clean up correctly)

## Assumptions

1. Hot-reload removes server keys from `ctx.cfg.mcp.mcp_servers` dict
2. The same cleanup method used for `_stderr_files` and `_stderr_log_paths` should also clear `_last_health_check`
3. A dedicated cleanup method would be cleaner than scattered cleanup calls

## Design decisions

- Add `_last_health_check.pop(server_key, None)` call alongside existing cleanup operations
- Use `.pop(key, None)` pattern which is safe for missing keys
- Cleanup location determined by hot-reload path analysis

## Alternatives considered

- Dedicated `_cleanup_server_resources()` method → deferred; overlaps with separate dedup plan
- Periodic garbage collection of stale entries → deferred; low priority given current usage
- Making `_last_health_check` use weak references → rejected; adds complexity without clear benefit

### Procedure

   - Ensure that when a server is marked as `(removed server)`, a cleanup call is made to `HttpServerLifecycleManager`.

2. **Phase 2: Core Logic Implementation**
   - Add `_cleanup_server_resources(self, server_key: str) -> str` method that:
     - Reads stderr tail via `self._read_stderr_tail(server_key)`

     - Pops the log path from `self._stderr_log_paths`
     - Pops the health check timestamp from `self._last_health_check`
     - Returns the stderr content string
   - Call this method wherever server keys are removed from `ctx.cfg.mcp.mcp_servers` during hot-reload
   - Also consider replacing inline cleanup in `start()` with calls to this method (addresses DRY issue simultaneously)

3. **Phase 3: Deployment & Verification**

   - Run `pytest tests/test_lifecycle*.py -v` to verify existing tests pass
   - Verify no new mypy errors introduced

### Method

Add `_last_health_check.pop(server_key, None)` call in the hot-reload cleanup path. 

Based on code analysis, `HttpServerLifecycleManager.restart()` already performs necessary cleanup for `_last_health_check`, `_stderr_files`, and `_http_pgids`. 

Therefore, the implementation should focus on ensuring that `ConfigReloadService` triggers `restart()` for any server identified as removed during the configuration reload process.

If a dedicated `_cleanup_server_resources(self, server_key: str)` method is created as part of the deduplication plan, it should encapsulate the following:

```python
def _cleanup_server_resources(self, server_key: str) -> str:
    """Read stderr tail, close stderr file handle, and remove tracking data for a server."""
    stderr_content = self._read_stderr_tail(server_key)
    fh = self._stderr_files.pop(server_key, None)
    if fh is not None:
        fh.close()
    self._stderr_log_paths.pop(server_key, None)
    self._last_health_check.pop(server_key, None)
    return stderr_content
```
