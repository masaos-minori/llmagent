## Design decisions
- Extend the existing `Contents` cell of the `implementations/done/` row rather than adding
  a new row: the table is one-row-per-directory, and a new row would duplicate the
  directory and break the table's invariant.
- State the rule as a short clause ("only executed procedures; moved here by
  `code-implementation` Step 7") so it mirrors the two workflow-file statements without
  restating the full rule.

## Alternatives considered
- Adding a separate sentence block above the table: rejected; the table is the canonical
  place the pipeline documents directory ownership, and a standalone block would drift from
  the row it describes.
- Referencing the two workflow files by name: rejected; the clause names the owning phase
  (`code-implementation` Step 7), which is stable, whereas a filename link would need a
  backtick reference and an extra checker.
