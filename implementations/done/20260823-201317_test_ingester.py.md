## Goal
Add real-database, real-file-routing regression coverage in
`tests/rag/ingestion/test_ingester.py` for the plan's URL-group-atomicity behavior:
group validation must reject a chunk-file group whose files disagree on any of the 11
shared fields (`url`, `title`, `lang`, `fetched_at`, `etag`, `last_modified`,
`source_file`, `chunking_strategy`, `schema_version`, `artifact_type`, `created_by`),
must reject a group with a duplicate or non-contiguous-from-zero `chunk_index` set, and
`_insert_chunks_batch()` must let a genuine `sqlite3.IntegrityError` propagate (no
partial commit) instead of silently swallowing it — each case verified against a real
in-memory SQLite connection so row counts and `failed/`-directory routing are asserted
against actual behavior, not mocks.

## Scope
- In scope: `tests/rag/ingestion/test_ingester.py` only — new tests in
  `TestIngestUrlGroup` / `TestPartialFailureHandling` (or a new test class in this file
  for group-validation cases), plus a required correctness fix to this file's own
  `_FakeSQLiteHelper.begin_immediate()` fixture (see Design decisions) needed for the
  new IntegrityError test to be meaningful.
- Out of scope: the production changes themselves —
  `scripts/rag/ingestion/ingester.py`'s new group-validation pass in
  `ingest_url_group()`, its removal of `except sqlite3.IntegrityError: pass` in
  `_insert_chunks_batch()`, and `_process_url_groups()`'s exception-tuple change (own
  implementation documents; this document only adds the tests that pin down the
  required behavior). `tests/rag/ingestion/test_rag_ingester.py` (own implementation
  document; that file is used for the mocked-boundary "validation runs before any DB
  call" assertions using `mock_db`/`mock_doc_mgr`, per the call-order pattern already
  established there). `scripts/db/schema_sql.py`, `scripts/db/store_impl.py`, and the
  `tests/db/*.py` files (own implementation documents; unrelated file).

## Assumptions
- Per the source plan's own Assumptions/Risks: this plan's `ingester.py` changes are
  sequenced after `plans/20260820-094150_plan.md` and `plans/20260820-095054_plan.md`.
  Confirmed by direct read of the current `scripts/rag/ingestion/ingester.py`:
  `_normalize_chunk_index()` and `_validate_artifact()` are still present today (the
  094150 dependency has not landed in this codebase yet), and `TestValidateArtifact` in
  this same test file still directly exercises `RagIngester._validate_artifact()`. The
  new tests in this document must not be written until that dependency lands; if
  `_normalize_chunk_index`/`_validate_artifact` are still present at implementation
  time, re-verify this plan's Design section still matches the then-current
  `ingest_url_group()` shape before adding tests.
- Confirmed by direct read: this file's `_make_db()` already runs
  `conn.execute("PRAGMA foreign_keys=ON")` against a real `sqlite3.Connection`, and the
  `chunks` table's DDL already declares
  `doc_id INTEGER NOT NULL REFERENCES documents(doc_id) ON DELETE CASCADE`. This makes
  it possible to trigger a genuine `sqlite3.IntegrityError` (foreign-key violation)
  without any schema change, by calling `_insert_chunks_batch()` with a
  `PreparedChunk.doc_id` that has no matching row in `documents` — no CHECK/UNIQUE
  constraint needs to be added to `_SCHEMA_SQL` for this test.
- Confirmed by direct read: this file's `_FakeSQLiteHelper.begin_immediate()` currently
  always calls `self._conn.commit()` in a `finally` block, regardless of whether the
  wrapped block raised — it does **not** roll back on exception. This differs from the
  real `SQLiteHelper._begin_transaction()` in `scripts/db/helper.py`, which executes
  `COMMIT` only on success and `ROLLBACK` (then re-raises) on any `Exception`. As
  written today, `_FakeSQLiteHelper` cannot distinguish "committed" from "rolled back"
  in a test, so a new IntegrityError test asserting "no partial commit" would pass
  trivially even if the real rollback-on-exception mechanism were broken. This gap must
  be fixed in this file's fixture before the new test is meaningful (see Design
  decisions).
- `_ChunkSpec` (this file's fixture dataclass) already carries all 11 fields the plan's
  Design step 1 compares (`url`, `title`, `lang`, `chunking_strategy`, `schema_version`,
  `artifact_type`, `created_by`, `etag`, `last_modified`) except `fetched_at` and
  `source_file`, confirmed by reading the dataclass body. `fetched_at` is added to
  `_ChunkSpec` by the separate `20260823-200056_test_ingester.py.md` implementation
  document (a different, already-landed-or-pending plan); this document assumes that
  field exists on `_ChunkSpec` by the time these new tests are written, and adds
  `source_file: str = ""` as this document's own new field if not already present.

## Design decisions
- Add one parametrized test function covering all 11 fields, rather than 11 separate
  test methods — the assertion shape (write two chunk files differing in exactly one
  field, call `ingest_url_group()`, assert zero DB rows and all files routed to
  `failed/`) is identical for every field; a `@pytest.mark.parametrize("field,
  mismatched_value", [...])` list keeps the 11 cases visible and independently
  reportable in `pytest -v` output without duplicating the test body 11 times.
- Fix `_FakeSQLiteHelper.begin_immediate()` to mirror
  `SQLiteHelper._begin_transaction()`'s real semantics (commit on success, rollback and
  re-raise on exception) rather than leaving it as an always-commits fixture — this is
  a correctness fix to existing shared test infrastructure in this file, required so
  the new IntegrityError test actually exercises "no partial commit," not an
  unconditional commit that happens to look like one.
- Trigger the genuine `sqlite3.IntegrityError` via a foreign-key violation
  (`PreparedChunk.doc_id` pointing at a non-existent `documents` row) rather than
  adding a new UNIQUE/CHECK constraint to `_SCHEMA_SQL` — this needs no schema change
  in this file and exercises a constraint the real `schema_sql.py` already declares
  (`chunks.doc_id REFERENCES documents(doc_id)`), keeping the fixture schema
  consistent with production DDL shape rather than adding a test-only constraint that
  does not exist in `scripts/db/schema_sql.py`.
- Route the "does group validation actually run and reject" tests through the public
  `ingest_url_group()` entry point (as every existing test in `TestIngestUrlGroup`
  already does) rather than calling a private validation helper directly — the plan's
  Design step 1 has no proposed public name for the validation helper yet, so testing
  through `ingest_url_group()` is stable against how that helper ends up named/shaped
  internally.

## Alternatives considered
- Writing the IntegrityError test purely against a mocked `db.execute` (patch it to
  raise `sqlite3.IntegrityError` on the second call) instead of a real foreign-key
  violation — rejected: this file's whole value proposition versus
  `test_rag_ingester.py` is exercising a *real* `sqlite3.Connection`; a mocked-raise
  test here would duplicate what `test_rag_ingester.py`'s fully-mocked `TestAtomicity`
  class already covers instead of adding the real-DB proof this file is positioned to
  provide.
- Adding a `UNIQUE(doc_id, chunk_index)` constraint to `_SCHEMA_SQL` to force the
  IntegrityError via a duplicate-index insert — rejected: duplicate `chunk_index` is
  already rejected by the new group-validation pass *before* any DB write per Design
  step 1, so by the time `_insert_chunks_batch()` runs, `chunk_index` values are already
  guaranteed unique for that group; a FK violation is the more realistic real-world
  channel for still reaching `_insert_chunks_batch()` with an integrity problem (e.g. a
  stale/deleted `doc_id`) after validation passes.
- Leaving `_FakeSQLiteHelper.begin_immediate()` unconditionally committing and instead
  asserting only "the exception propagates" (no row-count assertion) — rejected: the
  plan's Validation plan row for `_insert_chunks_batch()` explicitly requires "no
  partial rows" to be asserted, which is unverifiable with the fixture's current
  always-commit behavior.

## Implementation
### Target file
`tests/rag/ingestion/test_ingester.py`

### Procedure
1. **Fix `_FakeSQLiteHelper.begin_immediate()`** to roll back on exception: wrap the
   `yield` in a `try`/`except Exception`, calling `self._conn.execute("ROLLBACK")` (or
   `self._conn.rollback()`) and re-raising in the `except` branch, and moving the
   existing `self._conn.commit()` call so it only runs on the success path (mirroring
   `SQLiteHelper._begin_transaction()` in `scripts/db/helper.py`). Keep
   `self._in_transaction = False` running in a `finally` block in both outcomes.
2. **Add 11-field mismatch coverage** as a new parametrized test method in
   `TestIngestUrlGroup` (or a new `TestGroupValidation` class placed after
   `TestIngestUrlGroup`, if the count of new tests makes a dedicated class more
   readable): for each of `url`, `title`, `lang`, `fetched_at`, `etag`,
   `last_modified`, `source_file`, `chunking_strategy`, `schema_version`,
   `artifact_type`, `created_by`, write two chunk files via `_write_chunk()` — the
   first from `_DEFAULT_CHUNK`, the second via `dataclasses.replace(_DEFAULT_CHUNK,
   **{field: mismatched_value}, chunk_index=1)` — call `ingester.ingest_url_group(...)`
   with both paths, and assert: `result.n_success == 0`; `SELECT COUNT(*) FROM
   documents` and `SELECT COUNT(*) FROM chunks` are both `0`; neither file exists at
   its original path; both files exist under `failed/`; no embedding POST was issued
   (`ingester._client.post.assert_not_called()`, requires mocking `_client.post` with a
   `MagicMock` instead of `patch.object(..., return_value=_fake_embed_resp())` for this
   test so the "no embedding call" assertion is meaningful).
3. **Add a duplicate-`chunk_index` test**: two chunk files both with `chunk_index=0`
   (otherwise identical, e.g. differing only in `content` so they are not
   byte-identical), same assertions as step 2.
4. **Add a non-contiguous-`chunk_index` test**: two chunk files with `chunk_index=0`
   and `chunk_index=2` (skipping 1), same assertions as step 2 — this pins down the
   plan's "contiguous-from-zero required" resolution of UNK-01/the Assumptions section,
   not merely "unique."
5. **Add an IntegrityError-propagation test**, e.g.
   `test_insert_chunks_batch_propagates_integrity_error`, in
   `TestPartialFailureHandling` or a new dedicated test class: call
   `ingester._insert_chunks_batch(fake_db, [PreparedChunk(doc_id=<nonexistent_id>, ...)])`
   directly inside `fake_db.begin_immediate()` (mirroring how
   `_commit_url_transaction()` uses it), with `<nonexistent_id>` an integer with no
   matching row in the `documents` table constructed by `_make_db()`. Assert
   `pytest.raises(sqlite3.IntegrityError)` around the call, and assert
   `conn.execute("SELECT COUNT(*) FROM chunks").fetchone()[0] == 0` afterward (proving
   the fixed `begin_immediate()` rolled back, not partially committed).
6. **Add an end-to-end routing test** for the same IntegrityError scenario through
   `ingest_url_group()`: patch `ingester._insert_chunks_batch` with
   `side_effect=sqlite3.IntegrityError("...")` (simplest way to force the propagation
   at the `ingest_url_group()` level without depending on the FK-violation setup),
   and assert the group's chunk file(s) end up under `failed/` with a corresponding
   `.error.json` written (mirroring the assertion style of
   `test_mixed_success_and_failure_routes_correctly`), and that `result.n_success == 0`.

### Method
- Reuse this file's existing `_write_chunk()` / `_ChunkSpec` /
  `dataclasses.replace(_DEFAULT_CHUNK, ...)` fixture pattern for every new test — no
  new fixture-construction helper is needed beyond the `_FakeSQLiteHelper` fix in step
  1.
- Reuse the existing `patch.object(ingester._client, "post", ...)` /
  `patch("rag.ingestion.ingester.SQLiteHelper", return_value=fake_db)` mocking pattern
  already used throughout `TestIngestUrlGroup`.
- New tests read real inserted-row state via `conn.execute(...)` (the same `conn`
  returned by `_make_db()`), and real filesystem state via `Path.exists()` against
  `tmp_path / "chunk"`, `tmp_path / "registered"`, `tmp_path.parent / "retry"`/`"failed"`
  — consistent with how `TestPartialFailureHandling` already asserts file routing.

### Details
- Use two-chunk (not single-chunk) groups for every new mismatch/duplicate/
  non-contiguous test, since the comparison logic in Design step 1 compares
  `chunk_files[1:]` against `chunk_files[0]` — a one-file group can never exhibit a
  cross-file mismatch and would not exercise the new code path.
- For the 11-field parametrize list, use a value for each field that is a plausible
  but different value of the same type/domain (e.g. `lang="en"` vs the default `"ja"`,
  not an invalid `lang` value) — the point of these tests is cross-file *mismatch*
  detection, not the existing per-file `CHECK`-constraint/artifact-validation coverage
  already exercised by `TestValidateArtifact`.
- Do not reuse `_write_chunk()`'s default filename collision — give the two files in
  each new test distinct names (e.g. `"c0.json"`, `"c1.json"`) as the file already does
  in `test_inserts_chunks_with_correct_indices`.
- When asserting "no embedding call," confirm the mock is a plain `MagicMock()` (not
  `_fake_embed_resp()`-returning) so `assert_not_called()` is a real assertion, not one
  that would pass regardless because the response payload is never inspected.
- After changing `_FakeSQLiteHelper.begin_immediate()`, re-run every existing
  `TestIngestUrlGroup`/`TestPartialFailureHandling` test in this file once before
  adding the new tests, to confirm the rollback-on-exception fix does not change
  behavior for any currently-passing (non-exception) case.

## Rollback considerations
- This document's test additions have no production-behavior dependency of their own
  beyond the target `ingester.py` changes (own implementation document) — if that
  production change is reverted, these new tests should fail loudly (group validation
  no longer rejects mismatches; `_insert_chunks_batch()` no longer propagates
  `IntegrityError`), which is the intended regression signal, not a reason to revert
  this test file.
- The `_FakeSQLiteHelper.begin_immediate()` fix is a standalone fixture correctness fix
  and can be reverted independently without affecting any test added by the other
  implementation documents in this file, since it only changes behavior on the
  exception path.
- No schema/data migration is involved (in-memory SQLite, recreated per test via
  `_make_db()`); rollback is a pure code revert with no cleanup step.
