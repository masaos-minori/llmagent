## Goal

Make the RAG pipeline resilient to LLM-side failures by adding explicit fallback paths: MQE failure falls back to original query; rerank failure falls back to RRF-ranked results.

## Scope

**In-Scope:**
- Add rerank failure fallback: when cross_encoder_rerank() raises, use ctx.merged directly

**Out-of-Scope:**
- Changes to SQLite schema
- Changes to embedding service
- Changes to RRF fusion logic
- Changes to augment formatting

## Assumptions

1. MQE fallback uses the original query unchanged — no attempt to retry or modify the query.
2. Rerank fallback applies deduplicate_chunks() + rag_top_k slicing to ctx.merged (same as _rerank_fallback()).
3. Fallback reasons are recorded as distinct strings: "mqe_exception" and "rerank_exception".
4. Both fallbacks should be logged at INFO level for observability.
5. The fallback behavior should apply only on LLM exceptions, not on configuration errors.

## Design decisions

- **Exception-specific fallback**: Catch LLM exceptions specifically, not all exceptions. This prevents masking configuration errors or other bugs.
- **RRF fallback**: Apply deduplicate_chunks() + rag_top_k slicing to ctx.merged, same as the existing _rerank_fallback() method.
- **INFO-level logging**: Log fallback events at INFO level for observability without alarming operators unnecessarily.

## Alternatives considered

- **Catch all exceptions**: Could catch all exceptions during rerank. Rejected because it would mask configuration errors and other bugs that should surface.
- **Retry before fallback**: Could retry the LLM call before falling back. Rejected because the requirement specifies immediate fallback without retry.
- **WARN-level logging**: Could log fallback events at WARN level. Rejected because INFO is more appropriate for expected degradation scenarios.

## Implementation

### Target file

`scripts/rag/stages/rerank.py`

### Procedure

#### Phase 2: Add rerank failure fallback

1. Modify `RerankStage.run()` to catch LLM exceptions during `_rerank()`:
   ```python
   async def run(self, ctx: RagContext) -> StageResult:
       try:
           result = await self._rerank(ctx)
           return result
       except LLMException:
           # Rerank failed — fall back to RRF-ranked results
           ctx.reranked = deduplicate_chunks(
               ctx.merged[:cfg.rag_top_k]
           )
           logger.info("Rerank failed, using RRF-ranked results as fallback")
           return StageResult(
               status="fallback",
               reason="rerank_exception",
               hits=ctx.reranked,
           )
   ```

### Method

- Wrap `_rerank()` call in try/except to catch LLM exceptions
- On exception, compute fallback from ctx.merged and return a fallback StageResult

### Details

1. `RerankStage.run()` update:
   - Catch LLM exceptions during `_rerank()` execution
   - Compute fallback from `ctx.merged`: slice to cfg.rag_top_k, then apply deduplicate_chunks()
   - Set `ctx.reranked` to the deduplicated merged results
   - Log INFO message: "Rerank failed, using RRF-ranked results as fallback"
   - Return StageResult with status="fallback" and reason="rerank_exception"
   - Do NOT catch non-LLM exceptions — let them propagate
