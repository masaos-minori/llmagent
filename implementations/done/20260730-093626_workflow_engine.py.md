## Goal

Make the distinction between Workflow approval and Tool approval explicit through configuration and documentation, eliminating ambiguity about which approval mechanism `/approve` and `/reject` apply to.

## Scope

**In-Scope:**
- Update docstrings/comments in `workflow_engine.py` to clarify Workflow vs Tool approval

**Out-of-Scope:**
- Changes to Workflow approval logic itself
- Changes to Tool approval logic itself
- Changes to the interaction between the two approval mechanisms beyond documentation

## Assumptions

1. The intended default for `require_approval` is `false` (no workflow-level approval gate), matching the current implicit behavior.
2. Tool approval denial already appears as a tool message in conversation history — this behavior is correct and does not need code changes.
3. Documentation updates should follow the existing doc structure; new docs should reference existing ones rather than duplicating content.

## Design decisions

- **Consistent terminology**: Use "Workflow approval" and "Tool approval" consistently throughout all documents; avoid standalone "approval" without qualifier.
- **Docstring-first approach**: Update docstrings first, then ensure inline comments are also updated where needed.

## Alternatives considered

- **Inline comments only**: Could update inline comments instead of docstrings. Rejected because docstrings provide better discoverability and IDE support.
- **New doc file**: Could create a new doc file for approval systems. Rejected because updating existing docs is cleaner and avoids duplication.

### Procedure

#### Phase 2: Update Workflow approval documentation

1. Update `WorkflowEngine` class docstring to clarify that Workflow approval is task-level, occurs between execute and verify stages, and uses workflow storage:
   ```python
   class WorkflowEngine:
       """Execute workflow tasks with optional Workflow-level approval gates.
       
       Note: This module handles Workflow approval only (task-level approval
       gates). Tool approval (per-tool-call authorization) is handled separately
       by the tool execution layer. Do not confuse these two independent systems.
       """
   ```

2. Update `_gate_approval()` method docstring to document its role in the Workflow approval flow:
   ```python
   def _gate_approval(self, ...) -> bool:
       """Check Workflow-level approval gate for the current task.
       
       Note: This is Workflow approval only, not Tool approval.
       Workflow approval operates at the task level (between execute
       and verify stages) and uses workflow storage. Tool approval
       operates at the individual tool-call level and is handled
       separately.
       """
   ```

### Method
