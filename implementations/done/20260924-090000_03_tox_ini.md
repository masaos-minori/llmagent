## Goal

Add a lint step to `tox.ini` that runs the new chunks_fts invariant lint script as part of the CI pipeline.

## Scope

- **In-Scope**: Modify `tox.ini` to add a new lint command that invokes the chunks_fts invariant checker.
- **Out-of-Scope**: Modifying other tox environments; changing the ruff configuration; modifying the CI pipeline YAML files directly.

## Assumptions

- The project uses `tox` for CI pipeline management (confirmed by `tox.ini` existence).
- The lint script will exist at `tools/check_chunks_fts_invariant.py` before this modification.
- Existing tox lint commands use `uv run ruff format --check scripts/` and `uv run ruff check scripts/` patterns.

## Design decisions

- Add the chunks_fts invariant check as a separate tox environment under `[testenv:lint-chunks-ft]` rather than modifying the existing `[testenv:lint]` environment. This avoids breaking existing lint behavior and allows incremental rollout.
- Use `uv run python tools/check_chunks_fts_invariant.py` to invoke the script, consistent with how other tox environments invoke Python tooling.

## Alternatives considered

- Adding the chunks_fts invariant check to the existing `[testenv:lint]` environment instead of creating a separate one. This was rejected because it would change the behavior of the existing lint environment, potentially causing regression if the new script produces unexpected output. A separate environment allows incremental rollout — the new check can be enabled in CI independently of the existing lint pipeline. It also makes it easier to track whether the new check is passing or failing without affecting the existing lint results.

```ini
    typecheck: uv run pyright scripts/
```

#### Modification:

Add a new section after the existing `[testenv:lint]`:

```ini
[testenv:lint-chunks-ft]
description = Check for direct chunks_fts INSERT/UPDATE outside sanctioned paths
skip_install = true
deps =
    rg  # ripgrep must be available in PATH
commands =
    uv run python tools/check_chunks_fts_invariant.py
```

#### Alternative approach considered:

Adding the check to the existing `[testenv:lint]` environment instead of creating a separate one. This was rejected because:
- It would change the behavior of the existing lint environment, potentially causing regression if the new script produces unexpected output.
- A separate environment allows incremental rollout — the new check can be enabled in CI independently of the existing lint pipeline.
- It makes it easier to track whether the new check is passing or failing without affecting the existing lint results.

## Compatibility considerations

- The new tox environment depends on `rg` (ripgrep) being installed and available in PATH. This is already confirmed by its use throughout the codebase.
- The new environment does NOT modify the existing `[testenv:lint]` environment, so existing CI pipelines remain unaffected.
- The new environment uses `uv run python` to invoke the script, consistent with other tox environments in the project.

## Security considerations

- The tox modification only adds a new environment — no security impact beyond what the lint script itself introduces.
- The lint script reads source files using `Path.read_text()` which could expose sensitive information if the repository contains secrets in source files — this is acceptable since the script only scans for SQL patterns, not for secret detection.

## Rollback considerations

- If the new tox environment causes CI pipeline failures, it can be removed by deleting the `[testenv:lint-chunks-ft]` section.
- If the lint script produces false positives after deployment, the whitelist can be updated (see `tools/check_chunks_fts_invariant.py` procedure doc).
