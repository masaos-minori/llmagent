## Design decisions

- `index_paths`/`refresh_index` get `resource_scope_kind="mdq_store"`,
  `resource_scope_keys=["paths"]` — scoped by their actual mutating argument
  (the list of paths being indexed/refreshed), unlike `rag_delete_document`'s
  fixed empty-keys store scope. This is a deliberate difference from the RAG
  file's `rag_delete_document`: `index_paths`/`refresh_index` mutate specific
  named paths, so `resource_scope_keys=["paths"]` lets the future
  `resolve_resource_scopes()` (in `scripts/shared/resource_scope.py`) build a
  path-derived scope per the plan's filesystem ancestor/descendant overlap
  logic, rather than serializing every index mutation globally regardless of
  which paths are touched.
- Keep `MCPToolSchema`'s new fields `NotRequired` at the static-type level.
  Runtime *requirement* enforcement is `McpToolDiscoveryService`'s job (a
  different file, per the plan's Design section — "It becomes a hard
  requirement check"), not this dict's `TypedDict` declaration. Making them
  required in the `TypedDict` itself would force every entry literal to
  repeat all 4 keys textually with no functional benefit over the discovery
  service's runtime check, and would diverge from this file's existing
  precedent (`is_write`/`requires_serial` are already `NotRequired` even
  though 2 of 7 entries already set them).
- 5 read-only tools: `resource_scope_kind=""`, `resource_scope_keys=[]`
  uniformly — no per-tool differentiation needed since none mutates state.

## Alternatives considered

- Scoping `outline`/`grep_docs` by their `path`/`paths` filter arguments
  (treating reads as scoped, not blanket-unscoped): rejected — read/read
  pairs never create scheduling edges under the plan's conflict-graph design
  (`Design`: "Read/read pairs are never edges ... so read-only calls stay in
  the trailing parallel group exactly as today"), so scoping reads has no
  observable scheduling effect and only adds unused metadata.
- Making `MCPToolSchema`'s new fields required (dropping `NotRequired`):
  rejected per Design decisions above — would force unrelated literal
  repetition without runtime benefit; the plan's actual enforcement point is
  `mcp_tool_discovery.py`'s validator, not this file's type declaration.

## Implementation

### Target file: `scripts/mcp_servers/mdq/mdq_tools.py`

### Procedure

1. Extend the `MCPToolSchema` `TypedDict` (lines 12-20) with 2 new
   `NotRequired` keys: `resource_scope_kind: NotRequired[str]`,
   `resource_scope_keys: NotRequired[list[str]]`.

3. Backfill `"resource_scope_kind": "mdq_store", "resource_scope_keys":

### Method

Direct literal-dict edit plus one `TypedDict` extension; no new imports
beyond what `NotRequired`/`TypedDict` already provide (already imported at
line 9).

### Details

```python
class MCPToolSchema(TypedDict):
    name: str
    description: str
    inputSchema: dict[str, Any]
    status: str
    is_write: NotRequired[bool]
    requires_serial: NotRequired[bool]
    resource_scope_kind: NotRequired[str]
    resource_scope_keys: NotRequired[list[str]]
```

For `index_paths` (backfill onto existing write-tool entry):
```python
    {
        "name": "index_paths",
        ...
        "status": "production",
        "is_write": True,
        "requires_serial": True,
        "resource_scope_kind": "mdq_store",
        "resource_scope_keys": ["paths"],
    },
```
Identical backfill shape for `refresh_index`.

For each of the 5 read-only entries (`search_docs`, `get_chunk`, `outline`,
`stats`, `grep_docs`):
```python
    {
        "name": "search_docs",
        ...
        "status": "production",
        "resource_scope_kind": "",
        "resource_scope_keys": [],
    },
```

## Compatibility considerations

- `TypedDict` extension with `NotRequired` keys is fully backward compatible
  — no existing literal needs to change shape to satisfy the type checker.
- Backfilling 2 already-partially-declared entries and adding to 5 previously
  bare entries is additive; no removed or renamed keys.
- Once `mcp_tool_discovery.py`'s validator makes all 4 fields required at
  discovery time (sibling doc), this backfill is what keeps all 7 of this
  server's tools registrable — without it, discovery would reject
  `index_paths`/`refresh_index` (missing 2 of 4 required fields) and the 5
  read-only tools (missing all 4).

## Security considerations

- No behavior change to the write-serialization already declared for
  `index_paths`/`refresh_index` (`requires_serial=True` unchanged); the
  backfilled scope fields make the *existing* write intent more precise for
  the scheduler once `resource_scope.py`/`tool_scheduler.py` consume them,
  rather than loosening it.

## Rollback considerations

- Revert is a pure removal of the appended keys (2 per read-only entry, 2 per
  already-partial write entry) plus reverting the `TypedDict` back to its
  prior 6-key shape; no runtime state or persisted data is affected.
