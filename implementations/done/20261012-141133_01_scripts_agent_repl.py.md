## Goal
- Make the run method of the REPL class call close_resources exactly once, from one outer finally that covers startup, the post-startup warning, and the input loop (`REQ-001`, `REQ-002`, `REQ-003`).

## Scope
- Only the run method in `scripts/agent/repl.py`. No other method, file, or the shutdown coordinator itself.

## Assumptions
- A probe on the current code recorded the order close_resources then input loop on success, and close_resources then fatal message then re-raise on failure.
- The input loop's own finally runs only the persister callback, so putting cleanup after the loop keeps persistence before resources close.
- close_resources records and logs its own checkpoint, backup, task, and service errors instead of raising them.

## Design decisions
- One outer try/finally for the whole session rather than a single call after the loop: startup rollback does not cover a failure while initializing components, and an interrupt during startup is not an Exception, so only an outer finally keeps cleanup on every path.
- The inner handler that writes the fatal message and re-raises stays exactly as it is.
