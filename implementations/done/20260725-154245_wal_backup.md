## Goal

Prevent path traversal vulnerabilities during WAL file backup by validating database paths and ensuring backups are written only within allowed directories. Eliminate filename collision risks through unique naming.

## Scope

- Resolve symlinks using `os.path.realpath()` before filesystem operations
- Validate resolved path is within allowed base directory
- Verify backup directory exists and has write permissions
- Replace timestamp-based filenames with session_id-based unique names

## Assumptions

- Allowed base directory should be configurable via environment variable (default: project data directory)
- Session IDs are guaranteed to be unique per session
- Backup directory verification should use `os.access(path, os.W_OK)` for permission check
- Symlink resolution should fail safely (prevent backup) rather than follow symlink blindly

## Design decisions

- **Symlink resolution before validation**: Use `os.path.realpath()` to resolve all symlinks before checking path containment. This prevents bypassing directory restrictions via symlink manipulation.
- **Strict path containment**: Require resolved path to start with allowed base directory prefix. Reject any path outside this boundary.
- **Session-based naming over timestamps**: Use `session_id` combined with UUID for filename generation. More predictable and avoids timestamp collision issues.
- **Fail-safe symlink handling**: When symlink points outside allowed directory, prevent backup entirely rather than following it. This is the safe default.

## Alternatives considered

- **Allow symlinked paths with logging**: Would preserve backward compatibility but leaves attack surface open. Rejected due to security concern.
- **Use pathlib.Path.resolve() instead of os.path.realpath()**: pathlib is more modern but realpath is simpler and sufficient for this use case.
- **Timestamp-based naming with collision detection**: Timestamps can collide under rapid concurrent shutdown. UUID adds uniqueness guarantee.
- **Permission check before write vs. catch during write**: Pre-check is faster but has TOCTOU vulnerability. Catching during write is safer but less informative. Use both: pre-check + try/catch.

   ```python
   async def _close_resources(self):
       """Close resources with path validation for WAL backup."""
       # ... existing cleanup logic ...
       
       # WAL backup path validation
       wal_backup_result = await self._backup_wal_safe(db_path)
       if wal_backup_result.success:
           logger.info(f"WAL backed up to {wal_backup_result.backup_path}")
       elif wal_backup_result.skipped:
           logger.warning(f"WAL backup skipped: {wal_backup_result.reason}")
       else:
           logger.error(f"WAL backup failed: {wal_backup_result.reason}")
   
   @dataclass
   class WalBackupResult:
       success: bool
       skipped: bool = False
       backup_path: Optional[str] = None
       reason: str = ""
   
   async def _backup_wal_safe(self, db_path: str) -> WalBackupResult:
       """Safely backup WAL file with path validation."""
       # Resolve symlinks
       resolved_db_path = os.path.realpath(db_path)
       
       # Check if path was modified by symlink resolution
       if resolved_db_path != db_path:
           logger.warning(f"Database path resolved via symlink: {db_path} -> {resolved_db_path}")
       
       # Validate path is within allowed base directory
       allowed_base_dir = self._get_allowed_backup_directory()
       if not resolved_db_path.startswith(allowed_base_dir):
           return WalBackupResult(
               success=False,
               skipped=True,
               reason=f"Database path {resolved_db_path} is outside allowed directory {allowed_base_dir}"
           )
       
       # Verify backup directory exists and has write permissions
       backup_dir = os.path.dirname(resolved_db_path)
       if not os.path.exists(backup_dir):
           return WalBackupResult(
               success=False,
               skipped=True,
               reason=f"Backup directory does not exist: {backup_dir}"
           )
       
       if not os.access(backup_dir, os.W_OK):
           return WalBackupResult(
               success=False,
               skipped=True,
               reason=f"No write permission for backup directory: {backup_dir}"
           )
       
       # Generate unique filename
       filename = f"{self.session_id}-wal-backup-{uuid.uuid4().hex[:8]}"
       backup_path = os.path.join(backup_dir, filename)
       
       # Perform backup (existing logic)
       # ... copy WAL file to backup_path ...
       
       return WalBackupResult(success=True, backup_path=backup_path)
   
   def _get_allowed_backup_directory(self) -> str:
       """Get allowed base directory for WAL backups."""
       import os
       env_dir = os.environ.get("ALLOWED_BACKUP_DIR")
       if env_dir:
           return env_dir
       # Default to project data directory
       return "/opt/llm/data"
   ```

## Compatibility considerations

- **Symlink behavior change**: Deployments with symlinked databases will now have their paths validated. May break existing deployments relying on symlinked paths.
- **Path validation strictness**: New validation may reject previously working configurations. Provide configuration option to allow symlinked paths during transition period.
- **Filename format change**: Existing monitoring tools parsing WAL backup filenames may need updates.

## Security considerations

- **Path traversal prevention**: Primary security goal — prevent attackers from writing WAL backups to arbitrary locations via symlink manipulation
- **Symlink attack mitigation**: Resolving symlinks before validation prevents bypassing directory restrictions
- **Information disclosure**: Error messages should not expose internal directory structures beyond what's necessary
- **Denial of service**: Permission checks prevent attackers from causing errors by pointing to non-existent directories

## Rollback considerations

- **Quick rollback**: Remove path validation calls and revert to original WAL backup logic
- **Data impact**: No database changes; rollback does not affect persisted state
- **Configurable mode**: Consider adding environment variable to toggle strict/lenient path validation without code changes
