## Goal

Improve config loading error messages by wrapping them with user-friendly framing including the config file path and error class name.

## Scope

**In-Scope**:
- Wrap `build_agent_config()` call in `AgentContext.__init__()` with try/except
- Re-raise with formatted message containing config file path and error class name

**Out-of-Scope**:
- Modifying `ConfigLoadError` or `build_agent_config()` itself
- Adding new configuration options
- Changing other startup error handling

## Assumptions

1. `ConfigLoadError` wraps the original exception as `cause`; `e.__class__.__name__` returns "ConfigLoadError".
2. The config file path should be derived dynamically from the same logic as ConfigLoader rather than hardcoded.
3. The error message format follows the pattern: `"Failed to load agent config ({path}): {error_class}: {message}"`.

## Design decisions

- **Derive config path from ConfigLoader logic**: Instead of hardcoding `/opt/llm/config/agent.toml`, use the same path derivation logic as ConfigLoader (`Path(__file__).resolve().parent.parent.parent / "config"`). This ensures accuracy regardless of installation location.
- **Use `from None` to suppress traceback chain**: Prevents confusing nested tracebacks from appearing to users when the config load fails.
- **Catch `Exception` broadly**: Since `ConfigLoadError` is a subclass of `RuntimeError` which is a subclass of `Exception`, catching `Exception` covers all possible config-related errors without needing to know the exact exception hierarchy.

## Alternatives considered

- **Hardcode config path**: Simpler but fragile — breaks if install location changes. Chose dynamic derivation instead.
- **Catch specific `ConfigLoadError` only**: Would miss other potential errors during config loading. Chose broad Exception catch for robustness.
- **Log then re-raise instead of wrapping**: Less information loss but keeps the raw exception visible. Chose wrapping for consistent error formatting across all config failures.
