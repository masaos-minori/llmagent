## Goal

Add a non-blocking `--check-doc-symbols` step to `.github/workflows/backward-compat-check.yml` and register `tools/compat_exceptions.toml` in both path filters so CI reacts to manifest changes (REQ-005; AC-6).

## Scope

- Modify `.github/workflows/backward-compat-check.yml` only.
- Add one symbol-stage step and extend the two `paths` filters.

## Assumptions

- The removed-name step stays blocking (`set -euo pipefail`); only the new symbol step is non-blocking.
- The symbol step runs the same command form: `python tools/check_compat_shims.py --check-doc-symbols`.

## Design decisions

- Make the symbol step non-blocking with `continue-on-error: true` so its Warnings never fail the gate (the stage is report-only until UNK-03 is decided).
- Add the manifest to the `paths` filters alongside the existing globs so a manifest edit re-runs the workflow.

## Alternatives considered

- Folding the symbol check into the existing removed-name step — rejected: the two have different blocking semantics and different triggers.

## Implementation

### Target file

`.github/workflows/backward-compat-check.yml`

### Procedure

1. Add `tools/compat_exceptions.toml` to both the `push` and `pull_request` `paths` filters.
2. Add a second step after "Run backward compatibility check" that runs `--check-doc-symbols` with `continue-on-error: true`.

### Method

- Extend each `paths` block:

  ```yaml
  paths:
    - "scripts/**/*.py"
    - "docs/**/*.md"
    - "tests/**/*.py"
    - "tools/check_compat_shims.py"
    - "tools/compat_exceptions.toml"
  ```

- Add the step inside the `check` job:

  ```yaml
      - name: Report stale doc symbol references
        continue-on-error: true
        run: |
          set -euo pipefail
          python tools/check_compat_shims.py --check-doc-symbols
  ```

### Details

- Evidence in-file: the workflow currently has a single "Run backward compatibility check" step running `python tools/check_compat_shims.py --check-removed-names` under `set -euo pipefail`, with identical `paths` filters on `push` and `pull_request`.
