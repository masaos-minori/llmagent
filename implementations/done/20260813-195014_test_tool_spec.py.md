## Goal

Add `tests/shared/test_tool_spec.py` (no test file exists for `ToolSpec` today),
covering `ToolSpec`'s default construction (including the new
`resource_scopes: tuple[str, ...] = ()` field) and an explicit multi-scope construction,
per the plan's Phase 1 bullet.

## Scope

In scope: creating `tests/shared/test_tool_spec.py` with minimal unit tests for the
`ToolSpec` dataclass only. Out of scope: any test of `RuntimeToolRegistry`'s production
of `ToolSpec` instances (covered by `test_runtime_tool_registry.py`) or of
`resolve_resource_scopes()` (covered by `test_resource_scope.py`).

## Assumptions

- `ToolSpec` (per the companion `tool_spec.py` doc) has fields `call_id: str`,
  `name: str`, `args: dict[str, Any] = field(default_factory=dict)`,
  `resource_scopes: tuple[str, ...] = ()`, `requires_serial: bool = False`,
  `is_write: bool = False`, and is `@dataclass(frozen=True)`.
- Since this is a brand-new test file, its structure should follow this directory's
  established conventions (module docstring naming the file + one-line purpose summary;
  a `TestX` class wrapping scenario methods) rather than bare top-level test functions,
  for consistency with `test_runtime_tool.py`/`test_runtime_tool_registry.py`.

## Design decisions

- **Minimal, not exhaustive** — the plan's Phase 1 bullet explicitly scopes this new file
  to "the default and an explicit multi-scope construction," not a full field-by-field
  suite; keep it small (this is a plain, un-derived dataclass with no custom
  `__post_init__`/validation, unlike `RuntimeTool`'s `build_runtime_tool()` factory which
  warrants its own larger suite).
- **Also assert immutability**, matching the sibling `test_runtime_tool.py`'s
  `test_is_frozen` pattern (lines 74–78) — since `ToolSpec` is likewise
  `@dataclass(frozen=True)` and has never had a dedicated test file before, this is a
  reasonable minimum addition alongside the two scenarios the plan names explicitly,
  without expanding beyond "minimal."

## Alternatives considered

Testing `ToolSpec` only implicitly through `RuntimeToolRegistry`'s tests (never
constructing it directly). Rejected: the plan explicitly calls for a dedicated
`test_tool_spec.py`, and `ToolSpec` is directly constructible/importable on its own
(no factory function like `build_runtime_tool()` gates its construction), so it merits
its own minimal direct-construction test file.

## Implementation

### Target file: `tests/shared/test_tool_spec.py` (new)

### Procedure

1. Create the file with a module docstring:
   `"""tests/shared/test_tool_spec.py\nUnit tests for ToolSpec: default construction and
   multi-scope construction.\n"""`, matching the style of
   `tests/shared/test_runtime_tool.py`'s header (lines 1–3).
2. Add imports: `from __future__ import annotations`; `import dataclasses`; `import
   pytest`; `from shared.tool_spec import ToolSpec`.
3. Implement `TestToolSpec` with:
   - `test_default_construction_has_empty_resource_scopes_and_safe_defaults` —
     construct `ToolSpec(call_id="c1", name="read_file")` (only the two required
     positional/no-default fields supplied); assert `spec.args == {}`,
     `spec.resource_scopes == ()`, `spec.requires_serial is False`,
     `spec.is_write is False`.
   - `test_explicit_multi_scope_construction` — construct `ToolSpec(call_id="c2",
     name="move_file", args={"source": "/a", "destination": "/b"},
     resource_scopes=("filesystem:/a", "filesystem:/b"), requires_serial=True,
     is_write=True)`; assert `spec.resource_scopes == ("filesystem:/a", "filesystem:/b")`
     and the other fields round-trip correctly.
   - `test_args_default_factory_not_shared_across_instances` — construct two `ToolSpec`s
     with no `args` supplied; assert both have `args == {}` and `a.args is not b.args`
     (mirrors `test_runtime_tool.py`'s
     `test_input_schema_and_raw_definition_default_to_empty_dict_not_shared_object`
     pattern, lines 80–90, applied to `ToolSpec.args`'s own `field(default_factory=dict)`).
   - `test_is_frozen` — construct a `ToolSpec`, attempt
     `spec.name = "changed"`, assert it raises `dataclasses.FrozenInstanceError` (mirrors
     `test_runtime_tool.py`'s `test_is_frozen`, lines 74–78).

### Method

New self-contained pytest file; each test constructs its own `ToolSpec` inline (no shared
fixture needed given the small scope). No mocking — `ToolSpec` has no behavior beyond
field storage.

### Details

- File location: `tests/shared/test_tool_spec.py`, alongside `test_runtime_tool.py`/
  `test_runtime_tool_registry.py`/`test_resource_scope.py` in the same directory.
- Approximately 35–45 lines total including imports and docstrings.
- No `build_*()` factory exists for `ToolSpec` (unlike `RuntimeTool`'s
  `build_runtime_tool()`) — the dataclass constructor itself is the only construction
  path, so tests call `ToolSpec(...)` directly throughout.
