## Goal

Ensure all resources acquired during the startup phase are released regardless of whether startup succeeds or fails.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _run_repl_loop()), `scripts/agent/startup.py` (StartupOrchestrator.run())
**Out**: Changes to resource lifecycle management outside the startup path

## Assumptions

1. `_close_resources()` already handles partial startup correctly — `self._ctx.services` is None when `build_agent_context()` hasn't completed
2. `httpx.AsyncClient.aclose()` is safe to call multiple times
3. `lifecycle.shutdown_all()` is idempotent — safe to call even if subprocesses were already terminated

## Design decisions

- Add finally block in `AgentREPL.run()` rather than modifying `_close_resources()` or `StartupOrchestrator.run()` — minimal surface area change; caller owns the outer lifecycle
- Use unconditional finally block rather than conditional try/except — cleaner semantics for "always clean up"

## Alternatives considered

- **Modify `_close_resources()` to be called from more places**: Would require changing every caller site; risk of double-cleanup without careful coordination
- **Add cleanup logic inside `StartupOrchestrator.run()`**: Would couple the orchestrator to REPL-level concerns; violates separation of responsibilities
- **Use context manager protocol on AgentREPL**: Would require refactoring the entire class to support async context manager; over-engineered for this specific fix

## Implementation

### Target file

`scripts/agent/repl.py`

### Procedure

#### Step A: Modify AgentREPL.run() — add finally block

Current code (lines 506-512):

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        await self._run_repl_loop()
```

Change to:

```python
        startup = StartupOrchestrator(self._ctx, self._view)
        try:
            self._cmds, self._orchestrator = await startup.run()
        except Exception as e:
            self._view.write_fatal(f"Startup failed: {e}")
            raise
        finally:
            await self._close_resources()
        await self._run_repl_loop()
```

Key points:
- Finally block ensures `_close_resources()` runs regardless of startup outcome
- Covers both success path (REPL loop entered normally) and failure path (exception caught and re-raised)
- No changes to `_close_resources()` needed — already handles partial startup via `if svc is not None:` check

### Method

Extract ownership of resource cleanup into the outer scope (`AgentREPL.run`). Use Python's finally block to guarantee execution regardless of control flow path.

### Details

The core issue is that `StartupOrchestrator.run()` acquires resources (HTTP client, subprocesses) but only cleans them up on success. On failure, these resources leak because the exception propagates out of `run()` without triggering cleanup.

By adding `finally: await self._close_resources()` after the try/except, we ensure:
1. Success path: `_close_resources()` runs before entering REPL loop
2. Failure path: `_close_resources()` runs before the exception propagates further
3. Partial startup: `_close_resources()` safely handles None services via existing guards
