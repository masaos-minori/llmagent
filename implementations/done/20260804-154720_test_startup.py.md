# Implementation Procedure: Extend RAG consistency exception test for logger + message

## Goal

Extend `tests/agent/test_startup.py::test_rag_consistency_skipped_on_exception`
(currently lines 1109-1118) to assert that when the RAG consistency check's `except` block
runs, the bound exception is (a) logged via `logger.warning` and (b) included in the
`pipeline.add_skipped(...)` outcome message — covering the corresponding production change in
`scripts/agent/startup.py` (companion doc:
`implementations/20260804-154641_startup.py.md`).

## Scope

**In scope**
- `tests/agent/test_startup.py::test_rag_consistency_skipped_on_exception` only: wrap the
  existing `_run_check_services(...)` call in `with patch("agent.startup.logger") as
  mock_logger:`, then assert on `mock_logger.warning.call_args_list` and on
  `outcomes[0].message`.

**Out of scope**
- `test_rag_consistency_ok` / `test_rag_consistency_warning_per_issue` — untouched (success and
  warning-per-issue paths are not affected by this change).
- The `_run_check_services()` shared helper (`tests/agent/test_startup.py:689-745`) — not
  modified; patching is scoped locally to this one test via a `with` block, following the
  existing pattern at lines 287 and 323.

## Assumptions

- Current source (confirmed by direct read, 2026-08-04) has the test at lines 1109-1118:
  ```python
      async def test_rag_consistency_skipped_on_exception(self) -> None:
          ctx = _make_startup_ctx()
          pipeline, exc = await _run_check_services(
              ctx,
              RagMaintenanceService=MagicMock(side_effect=RuntimeError("db locked")),
          )
          assert exc is None
          outcomes = [o for o in pipeline.outcomes if o.source == "rag_consistency"]
          assert len(outcomes) == 1
          assert outcomes[0].status == StartupCheckStatus.SKIPPED
  ```
  No existing assertion on `logger` or on `outcomes[0].message` — this document adds both.
- `patch("agent.startup.logger")` scoped to a `with` block reaches through the helper's
  internal call to `_check_services()` regardless of call depth — confirmed by the existing,
  structurally identical pattern at `tests/agent/test_startup.py:287-298` (patches
  `agent.startup.logger`, then asserts on `mock_logger.warning.call_args_list` after a call
  to `startup._recover_pending_approvals()`, a sibling method on the same object).
- `RuntimeError("db locked")` stringifies to `"db locked"` via `str()`/`%s` — standard Python
  behavior, no custom `__str__` override.

## Design decisions

- Assert on `mock_logger.warning.call_args_list` (list of calls, filtered by message content)
  rather than a single `call_args`, mirroring the exact pattern at lines 291-296 in this same
  file, for consistency with existing test style in the module.
- Assert the exception content in `mock_logger.warning`'s formatting args (second positional
  arg, i.e. `%s`-arg convention) rather than a single pre-formatted string, since the
  companion production-code change calls `logger.warning("RAG consistency check failed: %s",
  exc)` with `exc` as a separate positional argument, not an f-string.
- Additionally assert `outcomes[0].message` contains `"db locked"` (replacing the previous
  implicit assumption of a fixed string), since the companion change updates the
  `add_skipped(...)` message to include `exc`.

## Alternatives considered

- Asserting on the fully-rendered log string (e.g. via `mock_logger.warning.call_args[0][0] %
  mock_logger.warning.call_args[0][1]`) — rejected in favor of the simpler, existing
  project-idiom of checking `"db locked"` is present among the call's positional args, matching
  lines 291-298's style rather than introducing a new assertion idiom.
- Adding a brand-new test instead of extending the existing one — rejected: the plan explicitly
  scopes this to extending `test_rag_consistency_skipped_on_exception`, since the exception
  path and message content are the same scenario, just asserting more of the observable
  outcome.
