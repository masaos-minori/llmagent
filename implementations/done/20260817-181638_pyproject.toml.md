## Goal
Reconcile `pyproject.toml` coverage `omit` list with current MCP server filenames to eliminate stale glob entries referencing non-existent files.

## Scope
- **In-Scope**:
  - Assess current coverage for 4 MCP server files (shell, web_search, github, rag_pipeline) using `uv run coverage run -m pytest tests/mcp_servers/` + `uv run coverage report`
  - Decide between Direction 1 (re-omit with updated globs) and Direction 2 (remove stale entries, keep measured)
  - Update `pyproject.toml` `[tool.coverage.run] omit` accordingly
  - Update inline comment above the omit list if Direction 2 is chosen
- **Out-of-Scope**:
  - Changes to `rules/toolchain.md` or `skills/python-refactoring/workflow.md` unless they contain stale references to the old filenames
  - Adding new tests for the 4 MCP server files
  - Coverage threshold changes

## Assumptions
- TestClient endpoint-level tests exist for all 4 MCP servers (shell, web_search, github, rag_pipeline) as stated in the require doc
- Coverage ≥ 70% for these files would justify Direction 2; < 70% would justify Direction 1
- The inline comment above the omit list currently reads "FastAPI server entry points ... not unit-testable" which is inaccurate for Direction 2

## Design decisions
- Stale entries must be resolved — leaving them in place silently includes files in coverage measurement, contradicting the documented intent ("not unit-testable").
- Direction 2 (remove stale entries) is preferred when coverage justifies it, as it restores accurate coverage instrumentation scope.
- Direction 1 (re-omit with updated globs) is the fallback when coverage is below acceptable threshold.

## Alternatives considered
- Leave stale entries as-is — violates accuracy of coverage instrumentation scope.
- Remove all stale entries without assessing coverage — risks under-measuring critical code paths.

`pyproject.toml`

### Procedure
1. Run `uv run coverage run -m pytest tests/mcp_servers/` + `uv run coverage report` to assess coverage for shell, web_search, github, rag_pipeline server files
2. Check `rules/toolchain.md` and `skills/python-refactoring/workflow.md` for stale references to old filenames
3. Based on coverage result:
   - **If coverage ≥ 70% (Direction 2)**: Remove 4 stale entries from `pyproject.toml` omit list, update inline comment
   - **If coverage < 70% (Direction 1)**: Update 4 entries to current filenames (`shell_server.py`, `github_server.py`, `web_search_server.py`, `rag_pipeline_server.py`)
4. Verify no stale paths remain: `for p in <omit-list-entries>; do ls $p 2>/dev/null || echo "STALE: $p"; done`
5. Run `uv run coverage run -m pytest tests/` + `uv run coverage report` after change to confirm expected behavior
