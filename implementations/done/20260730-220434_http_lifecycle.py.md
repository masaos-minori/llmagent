# Implementation Procedure: Implement Log Rotation for MCP Server Stderr Logs

## Goal

Add built-in log rotation support to prevent unbounded growth of MCP server stderr log files that can exhaust disk space.

## Scope

**In-Scope:**
- Add configuration parameters `max_stderr_log_size_mb` and `max_stderr_log_files` to `McpServerConfig`
- Check log file size before opening and rotate if exceeding max size
- Keep up to configured number of rotated copies, delete oldest when limit exceeded

**Out-of-Scope:**
- Configuring external logrotate integration (separate concern)
- Rotating logs during runtime (only at open time)
- Compressing rotated log files

## Assumptions

1. Default max log size of 100 MB provides reasonable protection without frequent rotation
2. Default of 3 rotated files balances retention needs with disk usage
3. Atomic rename (os.replace) ensures no data loss during rotation

## Design decisions

- Field names: `max_stderr_log_size_mb` and `max_stderr_log_files` following naming convention
- Default values: `100.0` MB max size, `3` rotated files for backward compatibility
- Validation: `> 0` for size, `>= 1` for file count in `__post_init__()`
- Rotation uses numbered suffixes (.1, .2, etc.) which is standard convention
- Rotation only checked at open time, not during runtime

## Alternatives considered

- Using Python's logging module with RotatingFileHandler → rejected; adds complexity without clear benefit for this use case
- Making rotation configurable globally → deferred; per-server granularity more flexible
- Adding compression to rotated files → deferred; low priority given current usage
