## Goal
Add boundary tests for the new `RobustSSEParser.__init__` `>= 0` validation
(`scripts/shared/sse_parser.py`) so the negative-rejects / zero-accepts behavior introduced by
that change is covered by an executable regression test.

## Scope
In scope:
- `tests/agent/test_llm_client.py`: add tests covering constructor validation, placed near the
  existing `TestRobustSSEParserFeed` (line 62) / `TestRobustSSEParserHeartbeat` (line 165)
  classes, which already own the full `RobustSSEParser` behavior suite in this file.
  - `RobustSSEParser(malformed_retry=-1, heartbeat_timeout=0.0)` raises `ValueError` mentioning
    `malformed_retry` and `-1`.
  - `RobustSSEParser(malformed_retry=0, heartbeat_timeout=-1.0)` raises `ValueError` mentioning
    `heartbeat_timeout` and `-1.0`.
  - `RobustSSEParser(malformed_retry=0, heartbeat_timeout=0.0)` (the boundary) constructs
    successfully.

Out of scope:

## Assumptions
- Zero is a valid boundary for both parameters (matches the source change's `>= 0` check and
  `config_validators.py`'s existing `>= 0` boundary convention).
- `pytest.raises(ValueError, match=...)` (or an equivalent string-containment assertion on
  `str(exc_info.value)`) is sufficient to verify the error message mentions the parameter name and
  offending value, consistent with how this file already asserts on `exc_info.value.kind` for
  `LLMTransportError` (e.g. line 135, line 182).

## Design decisions
- Placed as new test methods appended to `TestRobustSSEParserFeed` (per the plan's explicit

  than splitting coverage across `tests/agent/test_llm_client.py` and
  `tests/shared/test_llm_sse_helpers.py`.
- Reuses the file's existing `_parser` helper pattern (`TestRobustSSEParserFeed._parser`, lines
  63-68) where convenient, but constructs `RobustSSEParser` directly for the negative-value cases
  since those are testing the constructor itself, not routing through a default-args helper that

```python
    def test_malformed_json_exceeds_budget_raises(self) -> None:
        parser = self._parser(malformed_retry=1)
        bad = b"data: {broken}\n\n"
        parser.feed(bad)  # count = 1, budget = 1, not yet exceeded
        with pytest.raises(LLMTransportError) as exc_info:
            parser.feed(bad)  # count = 2, exceeds budget (> 1)
        assert exc_info.value.kind == "MALFORMED_SSE_FRAME"
    ...
    def test_incomplete_line_without_newline_returns_empty(self) -> None:
        parser = self._parser()
        payloads, is_done = parser.feed(b'data: {"key": 1}')
        assert payloads == []
        assert is_done is False
        payloads2, is_done2 = parser.feed(b"\n")
        assert len(payloads2) == 1
        assert is_done2 is False
```
`pytest.raises(...) as exc_info` with an assertion on the exception's contents is the
established pattern in this class (e.g. `test_malformed_json_exceeds_budget_raises`, lines
129-135); the new tests follow the same idiom but assert on the standard `ValueError` message via
`match=` instead of a custom `.kind` attribute, since the constructor raises a plain `ValueError`,
not `LLMTransportError`.
