# Implementation Procedure: scripts/agent/history.py

## Goal
Ensure that original messages are preserved when history compression fails (either by returning `None` or raising an exception).

## Scope
- **In-Scope:**
  - Modify `CompressResult` to support error reporting.
  - Update `HistoryManager.compress()` to handle `None` return values and exceptions from `_get_summary_text`.
  - Ensure fallback truncation occurs if compression fails but character limit is exceeded.
- **Out-of-Scope:**
  - Modifying caller behavior (to be addressed in a separate item).
  - Changing compression logic itself.

## Assumptions
1. `_call_compress_llm` may return `None` on empty response.
2. `HistoryCompressionError` is the standard exception for LLM failures during compression.

## Design decisions
- **Update `CompressResult`**: Add an `error: str | None = None` field to allow callers to distinguish between successful compression, no-op, and failure.
- **Defensive handling in `compress()`**:
  - If `summary_text` is `None`, check `_is_over_char_limit`.
  - If over char limit, proceed with `_fallback_truncate` to prevent context overflow.
  - Otherwise, return `CompressResult` with `error="compression returned None"`.
