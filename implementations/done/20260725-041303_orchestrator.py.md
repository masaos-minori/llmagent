## Goal

Ensure only one StateStore instance is used per workflow execution, eliminating duplicate database connections.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._handle_workflow_engine(), _init_workflow_task())
**Out**: Changes to StateStore internals, other callers of create_task/get_task_by_id outside this code path

## Assumptions

1. Only `_handle_workflow_engine` calls `_init_workflow_task`
2. The store passed to `_init_workflow_task` must remain open until after `create_task()` or `get_task_by_id()` completes
3. `store.close()` at line 249 is the single cleanup point for the main store

## Design decisions

- Pass the outer `store` from `_handle_workflow_engine` into `_init_workflow_task` rather than modifying StateStore internals — minimal surface area change
- Make `store` parameter optional with default `None` to maintain backward compatibility if other callers exist

## Alternatives considered

- **Modify StateStore to use singleton pattern**: Would require changes to StateStore internals and could introduce hidden coupling across the codebase
- **Use context manager protocol on StateStore**: Would require changing StateStore API surface; more invasive than necessary for this specific fix

### Method

Extract ownership of StateStore lifecycle from `_init_workflow_task` into the caller (`_handle_workflow_engine`). Use a `close_store` boolean flag to determine which scope owns the store's lifetime.

### Details

The core issue is two separate StateStore instances opened in the same execution path:
1. One in `_handle_workflow_engine` at line 183
2. Another in `_init_workflow_task` at line 257 (if branch) or line 276 (else branch)

By passing the outer store into `_init_workflow_task`, both operations share the same connection. The `close_store` flag prevents double-close: when the caller provides the store, only the caller closes it; when `_init_workflow_task` creates its own store, it closes it.
