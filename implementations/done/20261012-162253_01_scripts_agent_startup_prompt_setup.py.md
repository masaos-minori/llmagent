## Goal
- Classify a programming error during the startup memory injection as PROGRAMMING_ERROR, log it at error level with the traceback, and show a distinct internal-error warning, while startup still completes without memory (`REQ-001`, `REQ-002`, `REQ-003`).

## Scope
- Only the classifier method and the exception handler of the setup method in `scripts/agent/startup_prompt_setup.py`, plus one module-level constant.

## Assumptions
- The catch stays as it is: startup must complete, and the call site in the startup orchestrator treats a propagated exception as a startup failure.
- The standard logger behind the module logger accepts the exc_info keyword (already used in `scripts/agent/diagnostic_store.py`).
- The five listed types are not subclasses of OSError or sqlite3.Error, so checking them after the network and database cases changes no existing result.

## Design decisions
- Classify by isinstance on an explicit tuple of AttributeError, NameError, TypeError, LookupError and AssertionError; ValueError and RuntimeError stay UNKNOWN by decision, and UNKNOWN keeps its info log because an existing test pins it.
- Keep the [non-fatal] tag and the words Memory injection failed in the view warning so existing expectations hold; the distinction comes from the text and the error-level log.
