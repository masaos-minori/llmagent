## Goal

Replace direct `print()` calls in cli_view.py with Protocol method invocations and remove `Writer` Protocol definition after merging into `OutputPort`.

## Scope

- Replace 15 `print()` calls in cli_view.py with `OutputPort` method invocations
- Remove `Writer` Protocol definition (already handled in output_port.py document)
- Preserve `WriterBase` inheritance for test double compatibility

## Assumptions

- The 15 print calls referenced in the Plan (cli_view.py:186-260) are still present and need replacement
- `WriterBase` ABC (cli_view.py:27-69) has no subclasses outside CLIView — verified by rg search returning no results
- Test doubles (`PartialWriter`, `FullWriter` in tests/test_cli_view.py) depend on `WriterBase` inheritance

## Design decisions

- `CLIView` delegates to `OutputPort` instance rather than implementing `Writer` directly — this allows the Protocol to handle routing while CLIView focuses on view logic
- `WriterBase` inheritance preserved for test double compatibility — cannot be removed even if redundant for production code
- Each `print()` call maps to the appropriate `OutputPort` method based on message type (token, progress, error, table, etc.)

## Alternatives considered

- Having CLIView implement both `Writer` and `OutputPort`: rejected because it defeats the purpose of consolidation
- Creating a new adapter class between CLIView and OutputPort: rejected because unnecessary indirection — delegation through composition is cleaner
