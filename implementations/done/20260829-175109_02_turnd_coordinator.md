# Implementation Procedure: scripts/agent/turnd_coordinator.py

## Goal

Create `turnd_coordinator.py` with the TurnCoordinator class owning turn lifecycle methods extracted from Orchestrator, including `_handle_turn_start`, `_handle_turn_end`, `_clear_previous_turn_ephemeral_messages`, `_sync_system_prompt`, and `_append_user_message`.

## Scope

- Create `scripts/agent/turnd_coordinator.py` only. No other source file is modified by this document.
- The TurnCoordinator class owns exactly one concern: turn lifecycle coordination.
- Methods moved from orchestrator.py lines 427, 445, 466, 589, 629, 642, 663.

## Assumptions

- TurnCoordinator receives `AgentContext` as a per-call method argument rather than via constructor injection (corrected during Step 3 adversarial verification: the constructor instead receives the shared `background_tasks` set plus the `on_first_turn`, `discard_and_log`, and `build_turn_end_event` callables, since `ctx` is already available at every call site inside `Orchestrator.handle_turn`/`_process_turn` and threading it through `__init__` would add no value).
- Callbacks (`on_turn_start`, `on_turn_end`, `on_error`, `on_first_turn`, `on_llm_wait_start`, `on_llm_wait_end`) are passed through to TurnCoordinator rather than consumed directly by Orchestrator.
- `_EPHEMERAL_KEYS` constant is already owned by ConversationStateManager (REQ-012).
- Background task management (`_background_tasks`, `_consecutive_bg_failures`) remains in Orchestrator for now -- they bridge to BgTaskMonitor's `_discard_and_log` callback.
- `LLMTurnRunner` ownership remains in Orchestrator; TurnCoordinator does not own it.
- ToolLoopGuard ownership remains shared between Orchestrator and LLMTurnRunner.

## Design decisions

1. **TurnCoordinator owns turn lifecycle only**: The class encapsulates all methods related to turn start/end processing, ephemeral message cleanup, system prompt synchronization, and user message appending.
2. **Constructor injection for dependencies**: AgentContext, callbacks, and any required services are injected via `__init__`. This enables independent instantiation and testing.
3. **No circular imports**: TurnCoordinator depends only on shared types (AgentContext, LLMMessage, etc.) and never imports Orchestrator itself.
4. **Ephemeral key usage**: `_clear_previous_turn_ephemeral_messages` uses `_EPHEMERAL_KEYS` from ConversationStateManager (not its own copy).

## Alternatives considered

1. **Merge TurnCoordinator + ConversationStateManager**: Would reduce the number of new files but violates the Single Responsibility Principle that motivated this refactor. Rejected per plan's design intent.
2. **Keep `_handle_turn_start` and `_handle_turn_end` in Orchestrator**: Would reduce refactoring effort but leaves the file at > 700 lines. Rejected because it defeats the purpose of the refactor.
3. **Make TurnCoordinator a mixin or base class**: Would introduce inheritance complexity without benefit. Composition is simpler and more testable. Rejected.

### Method

The TurnCoordinator class structure:

```python
class TurnCoordinator:
    """Owns turn lifecycle coordination: start, end, ephemeral cleanup, system prompt sync, user message append.

    Extracted from Orchestrator to isolate turn-level state machine logic.
    """

    def __init__(
        self,
        ctx: AgentContext,
        *,
        on_turn_start: Callable[[], None] | None = None,
        on_turn_end: Callable[[], None] | None = None,
        on_error: Callable[[Exception], None] | None = None,
        on_first_turn: Callable[[str], Any] | None = None,
        on_llm_wait_start: Callable[[], Any] | None = None,
        on_llm_wait_end: Callable[[], None] | None = None,
        tracer: Any = None,
    ) -> None:
        self._ctx = ctx
        self._on_turn_start = on_turn_start
        self._on_turn_end = on_turn_end
        self._on_error = on_error
        self._on_first_turn = on_first_turn
        self._on_llm_wait_start = on_llm_wait_start
        self._on_llm_wait_end = on_llm_wait_end
        self._tracer = tracer

    async def handle_turn_start(self, line: str) -> None:
        """Assign a turn ID and emit a turn_start audit event."""
        ...

    async def handle_turn_end(
        self,
        line: str,
        answer: str,
        turn_started_at: float,
        error_kind: str | None,
        is_partial: bool = False,
    ) -> None:
        """Emit a turn_end audit event and clear the current turn ID."""
        ...

    def clear_previous_turn_ephemeral_messages(self) -> None:
        """Strip ephemeral/memory-injected system messages left over from the previous turn."""
        ...

    def sync_system_prompt(self) -> None:
        """Sync history[0] from ctx.conv.system_prompt_content before each turn."""
        ...

    async def append_user_message(self, line: str) -> None:
        """Append user message to history, sync system prompt, and increment turn counter."""
        ...
```

Key points:
- Public method names use snake_case without underscore prefix (cleaner API for Orchestrator delegation).
- `_tool_override` stays in Orchestrator because it modifies `_ctx.cfg.tool.allowed_tools` which is an Orchestrator-specific concern.
- `_append_user_message` references `self._background_tasks` and `self._discard_and_log` -- these remain in Orchestrator. The method body needs adjustment: the background task creation should be delegated back to Orchestrator after the user message is appended. Consider adding a separate `create_background_task` method or keeping the background task creation in Orchestrator.
