## Goal

Merge `Writer` Protocol (cli_view.py) into `OutputPort` Protocol (output_port.py), rename `CliOutputPort` to be the sole concrete implementation, add `write_stderr()` method, and merge `ExportOutputPort` Protocol (io_ports.py).

## Scope

- Modify `scripts/agent/commands/output_port.py`: Add `Writer` Protocol methods (`write_token`, `write_turn_start`, `write_progress`, `clear_progress`) to `OutputPort` Protocol; merge `ExportOutputPort` Protocol; update `CliOutputPort` to implement the merged Protocol; add `write_stderr(text: str)` method
- Modify `scripts/agent/cli_view.py`: Remove `Writer` Protocol definition; update imports; have `CLIView` delegate to `OutputPort` instance instead of implementing `Writer`; preserve `WriterBase` inheritance for test double compatibility

## Assumptions

- Visual output format (spacing, prefixes, alignment) remains unchanged — this is structural consolidation, not UX redesign
- `Workflow` tag (`[workflow]`) is already covered by `OutputTag.WORKFLOW` and needs no additional handling
- `WriterBase` ABC cannot be simply removed — it serves as a base class for test doubles (`PartialWriter`, `FullWriter` in tests)
- After merging protocols, `CLIView` should delegate to an `OutputPort` instance while keeping `WriterBase` inheritance intact for test double compatibility
- `orchestrator.py` does NOT have logging/screen-display duplication

## Design decisions

- `OutputPort` Protocol is chosen as canonical interface because it covers slash commands (most diverse output domain), has consistent method names, and its streaming methods are a narrower concern that can be added without conflict
- Streaming methods (`write_token`, `write_progress`, `clear_progress`) and structured methods (`write_table`, `write_kv`, `write_error`) share the same Protocol but may have different flush behaviors — acceptable since Protocol defines contract, not implementation detail
- `write_stderr(text: str)` replaces ad-hoc `print(..., file=sys.stderr)` in validate.py; default implementation writes to `sys.stderr`
- `WriterBase` preserved as base class for test doubles even if redundant for production code

## Alternatives considered

- Keeping both `Writer` and `OutputPort` Protocols separate: rejected because it perpetuates the fragmentation problem
- Merging into `Writer` Protocol instead: rejected because `OutputPort` has broader scope and more consistent naming
- Removing `WriterBase` entirely: rejected because it breaks test doubles used in tests
