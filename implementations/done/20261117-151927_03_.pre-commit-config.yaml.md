## Goal

Add the `workitem-structure` pre-commit hook so a raw `git commit` runs the structure check on staged top-level work item files (REQ-004).

## Scope
**Release unit**: N/A: not part of a release unit

## Assumptions

- pre-commit appends staged filenames to an entry whose `pass_filenames` is left at its default (true) — the shape the plan's Assumption records; the precedent hook `workitem-traceability` shows the same `files`-filter shape but deliberately sets `pass_filenames: false`.
- The hook can only pass after the seq 01 document (multi-path `--file`) and the seq 02 document (gate id becomes `check_workitem_structure:--file`) land.

## Design decisions

- The entry ends at `--file` with no positional token so `_hook_checker_id` derives `check_workitem_structure:--file`, equal to the gate id after Decision 6 (AC-6).

## Alternatives considered

- `pass_filenames: false` plus a directory scan: rejected, REQ-004 mirrors the gate trigger (changed files only), and a full scan on every commit repeats work the gate already scopes.

## Implementation
### Target file
`.pre-commit-config.yaml`

### Procedure

- Add a hook entry named `workitem-structure` (new) under the `repo: local` section, after `archived-procedure-status`: name "Check structure of changed top-level work item documents", `entry: uv run python tools/check_workitem_structure.py --file`, `language: system`, `files: ^(issues|plans|implementations)/[^/]+\.md$`, and no `pass_filenames` key (default true).

### Method

N/A: single YAML entry; the regex mirrors the seq 02 gate patterns so `done/` never triggers the hook.

### Details

- No `COMMIT_ONLY_HOOKS` entry is added: the hook id maps to the gate (AC-6).

## Compatibility considerations
