## Goal

Add validation to detect and report unexpected keys during dict-to-HistoryMessage conversion, preventing silent data loss.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL._persist_session_memories()), `scripts/agent/memory/models.py` (HistoryMessage)
**Out**: Changes to message schema validation, other serialization paths

## Assumptions

1. Only `_persist_session_memories()` needs this validation in scope
2. The expected keys are exactly `{"role", "content"}` based on HistoryMessage fields
3. Warnings should be logged rather than raising errors — silent discard is a bug but not a crash

## Design decisions

- After extracting `role` and `content`, compute `extra_keys = set(m.keys()) - expected_keys`
- If non-empty, log a warning with the extra keys
- This makes schema mismatches visible during testing and production use

## Alternatives considered

- **Raise an error instead of logging a warning**: Would break existing workflows; warnings are better for detection without disruption
- **Pass extra keys as metadata to HistoryMessage**: Would require changing the HistoryMessage schema; too invasive for this fix
- **Remove the keys entirely before conversion**: Would hide the problem; logging preserves visibility

```python
async def _persist_session_memories(self, ctx: AgentContext) -> None:
    """Extract and persist session memories before compression or resource close."""
    if ctx.services is not None and ctx.services.memory is not None:
        try:
            expected_keys = {"role", "content"}
            history = []
            for m in ctx.conv.history:
                extra_keys = set(m.keys()) - expected_keys
                if extra_keys:
                    logger.warning(
                        "Unexpected keys in history message: %s (message id=%s)",
                        extra_keys,
                        getattr(m, "id", None),
                    )
                history.append(
                    HistoryMessage(role=m["role"], content=m.get("content") or "")
                )
            await ctx.services.memory.on_session_stop(
                session_id=ctx.session.session_id,
                history=history,
                turn_id=ctx.turn.current_turn_id,
            )
        except (RuntimeError, sqlite3.Error, OSError):
            logger.exception(
                "Memory on_session_stop failed; session data may be incomplete"
            )
```

Key points:
- Added `expected_keys` constant defining valid message dict keys
- Compute `extra_keys` per message and log warning if non-empty
- Include message identifier in warning for easier debugging
- Same behavior as before — extra keys are still discarded, but now they're reported

### Method

Extract ownership of message schema validation into the REPL class (`AgentREPL`). Validate message dict keys against expected schema before converting to HistoryMessage. Log warnings for unexpected keys to prevent silent data loss.

### Details

The core issue is that when converting dict messages to HistoryMessage objects, any extra keys beyond `role` and `content` are silently discarded. This can mask bugs where:
1. New fields are added to message dicts but not to HistoryMessage
2. Message dicts contain stale or incorrect metadata
3. Schema drift between components causes data loss

By adding key validation:
- Unexpected keys are detected and reported immediately
- Developers get actionable warnings during testing and production
- Silent data loss becomes visible — enabling faster diagnosis

The validation uses set difference (`set(m.keys()) - expected_keys`) which is O(n) and efficient even for large histories.
