## Goal

Ensure `ROLE_KEY_WHITELIST` includes all valid optional fields declared in the `LLMMessage` TypedDict (`name`, `importance`, `pinned`) so that `validate_message()` does not strip them from conversation-history messages.

## Scope

**In-Scope:**
- Add `name`, `importance`, and `pinned` to appropriate `ROLE_KEY_WHITELIST` entries in `message_schema.py`

**Out-of-Scope:**
- Changes to `LLMMessage` TypedDict in `types.py`
- Changes to `classify_importance()` logic
- Changes to history compression behavior

## Assumptions

1. `name` is only meaningful on tool-role messages (it identifies the tool that produced the result).
2. `importance` and `pinned` can appear on any message type in conversation history (used by `classify_importance()` for compression priority).

## Design decisions

- **Selective `name` addition**: Add `name` only to the `"tool"` role whitelist because it is only meaningful on tool-role messages.
- **Universal `importance`/`pinned` addition**: Add `importance` and `pinned` to all four role whitelist entries because they are used by `classify_importance()` regardless of message role.

## Alternatives considered

- **Add `name` to all roles**: Could add `name` to all roles instead of just `"tool"`. Rejected because `name` is only meaningful on tool-role messages.
- **Add `importance`/`pinned` only to specific roles**: Could add `importance`/`pinned` only to specific roles based on usage patterns. Rejected because they are explicitly declared in `LLMMessage` TypedDict as valid optional fields for all message types.

## Implementation

### Target file

`scripts/agent/message_schema.py`

### Procedure

#### Phase 1: Extend ROLE_KEY_WHITELIST

1. In `message_schema.py`, update `ROLE_KEY_WHITELIST`:
   ```python
   # Before:
   ROLE_KEY_WHITELIST = {
       "system": {"role", "content"},
       "user": {"role", "content"},
       "assistant": {"role", "content"},
       "tool": {"role", "content", "tool_call_id"},
   }
   
   # After:
   ROLE_KEY_WHITELIST = {
       "system": {"role", "content", "importance", "pinned"},
       "user": {"role", "content", "importance", "pinned"},
       "assistant": {"role", "content", "importance", "pinned"},
       "tool": {"role", "content", "tool_call_id", "name", "importance", "pinned"},
   }
   ```

### Method

- Update `ROLE_KEY_WHITELIST` dictionary in `message_schema.py`

### Details

1. `ROLE_KEY_WHITELIST` update:
   - Add `"name"` to the `"tool"` role whitelist entry (tool results include the tool name)
   - Add `"importance"` and `"pinned"` to all four role whitelist entries (system, user, assistant, tool) — these fields are used by `classify_importance()` regardless of message role

## Compatibility considerations

- Existing messages without `name`, `importance`, or `pinned` will continue to work — these are optional fields
- The change aligns the validator with the `LLMMessage` TypedDict type contract
