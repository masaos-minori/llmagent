## Goal

Ensure signal-induced shutdown is detected immediately by the event loop without relying on the asyncio.Event mechanism that introduces latency through the event loop scheduling cycle.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _read_input(), _sigterm_handler())
**Out**: Changes to signal handling outside the REPL, other async event patterns

## Assumptions

1. Signal handlers must remain synchronous — cannot use async operations inside them
2. Canceling a Future from a signal handler is safe — it just sets a flag on the Future object
3. Windows doesn't support `loop.add_signal_handler()` — already handled with fallback

## Design decisions

- Replace the asyncio.Event-based shutdown detection with direct `input_coro.cancel()` from the signal handler
- When the signal arrives, cancel the pending input future so `asyncio.wait()` returns immediately
- Remove the `_shutdown_watcher` coroutine entirely since it's no longer needed
- Track input_coro via instance variable for signal handler access

## Alternatives considered

- **Keep asyncio.Event but reduce event loop latency**: Would require changes to asyncio internals — not feasible
- **Use asyncio.CancelledError propagation instead of Future.cancel()**: More complex; Future.cancel() is simpler and well-understood
- **Remove _shutdown_watcher entirely**: Would break backward compatibility with existing shutdown paths; keep for now

### Method

Extract ownership of input lifecycle into the REPL class itself (`AgentREPL`). Track the input coroutine via instance variable for signal handler access. Cancel the pending input task directly from signal handler instead of relying on asyncio.Event which introduces event loop scheduling latency.

### Details

The core issue is that when a signal arrives during input waiting, the asyncio.Event mechanism introduces latency because:
1. Signal handler sets the event
2. Event loop must wake up and process the event callback
3. Only then does `_shutdown_watcher` detect the event and complete

By canceling the input task directly from the signal handler, we eliminate this intermediate step:
- Input task cancellation causes `asyncio.wait()` to return immediately
- No event loop scheduling delay
- Shutdown proceeds synchronously within the signal handler context

The `_shutdown_watcher` coroutine is retained for backward compatibility — it still sets `shutdown_done` for any existing consumers.
