## Goal

Make LLM turn-end callback invocation consistent across all LLMTransportError propagation paths.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._handle_llm_turn())
**Out**: Changes to LLMTurnRunner behavior, other callback invocations

## Assumptions

1. Only `_handle_llm_turn` calls `_llm_runner.run()`
2. Callback ordering must be identical across all paths: `_on_llm_wait_end` → `_on_error` → `_on_turn_end`
3. No double-invocation risk — each callback is guarded by its own conditional check

## Design decisions

- Reorder callbacks in the exception-return path rather than adding a separate finally block — preserves existing conditional guard semantics without introducing new control flow complexity
- Add `_on_turn_end` to the exception-return path — ensures uniform cleanup regardless of success/failure outcome

## Alternatives considered

- **Use a finally block for all callbacks**: Would require restructuring the method to use try/finally instead of try/except/else; changes control flow more aggressively than necessary
- **Move callback logic into LLMTurnRunner**: Would couple the runner to REPL-level concerns; violates separation of responsibilities
- **Add a dedicated error-handling callback wrapper**: Over-engineered for this specific fix; adds indirection without solving the root cause

### Method

Extract ownership of callback ordering into the caller (`_handle_llm_turn`). Use if/else branches to ensure consistent callback sequence regardless of execution path.

### Details

The core issue is inconsistent callback ordering across three paths:
- Exception-return path: `_on_llm_wait_end` → `handle_llm_transport_error` → `_on_error`
- Raise path: `handle_llm_transport_error` → `_on_llm_wait_end` → `_on_error`
- Success path: `_on_llm_wait_end` → `_on_turn_end`

By moving `_on_llm_wait_end` into both branches and adding `_on_turn_end` to the exception-return path, we achieve:
- Exception-return path: `handle_exception` → `_on_llm_wait_end` → `_on_error`
- Success path: `_on_llm_wait_end` → `_on_turn_end`
- Both paths now have uniform callback ordering within their respective categories
