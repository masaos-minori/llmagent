# Implementation Procedure: Align McpServerConfig failure model with ADR-004 Production-only

## Goal

Replace `required_in_production`/`required_in_local` with a single `required` field on `McpServerConfig`, and simplify `FailurePolicy` enum to FAIL_FAST only per ADR-004 Decision #1 and Decision #3.

## Scope

- Replace `required_in_production` and `required_in_local` fields with unified `required` field on `McpServerConfig` dataclass
- Simplify `FailurePolicy` StrEnum to contain only `FAIL_FAST` value
- Update `_build_single_server()` to use `required` instead of both deprecated fields
- Remove `DISABLE_TOOL` and `DEGRADED` enum values from `FailurePolicy`

## Assumptions

- No production config entries override `required_in_production`, `required_in_local`, or `failure_policy` (confirmed by inspecting `config/agent.toml`)
- The `required` field defaults to `True` to maintain backward compatibility with current default behavior
- `FailurePolicy.FAIL_FAST` is the only meaningful value after alignment — removing other values has zero runtime impact since they are never used

## Design decisions

- Single `required` field replaces both `required_in_production` and `required_in_local`. Default value is `True` to maintain backward compatibility with the current default behavior
- `FailurePolicy` enum simplifies to contain only `FAIL_FAST`. The other two values (`DISABLE_TOOL`, `DEGRADED`) were added during the pre-revision period and contradict ADR-004 Decision #3
- Since no config entries currently use `DISABLE_TOOL` or `DEGRADED` values, removing them has zero runtime impact

## Alternatives considered

- Could keep `DISABLE_TOOL` and `DEGRADED` as deprecated aliases that emit warnings — but ADR-004 requires Fail-Fast only, so keeping dead values adds maintenance burden
- Could add a migration path that maps old values to `FAIL_FAST` at load time — unnecessary since no config entries use those values
