matching `SessionConsistencyReport`'s field name, type, and default exactly. Placing
it with a default value (rather than a required positional field) keeps every

consistent with this dataclass's existing pattern of defaulted fields (e.g.

## Alternatives considered

- Making `read_smoke_test_ok` a required (non-defaulted) field — rejected: `dataclass`
  field ordering rules require all fields after the first defaulted field to also have
  defaults, and `RagConsistencyReport` already has multiple defaulted fields before
  the end of its definition; a required field would need to be inserted before all
  existing defaulted fields, forcing every existing positional-argument construction
  call (if any) to be updated. A defaulted field avoids this entirely and matches the
  Plan's "additive dataclass field" characterization in `Affected areas`.
