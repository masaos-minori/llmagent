## Goal

Make a test-suite run fail, naming each file, when any file under `/opt/llm/db` changed during the session, including through a subprocess the per-test guard cannot see (`REQ-001`: session fingerprint; `REQ-002`: silent skip and opt-out). Also add an isolated-subprocess-environment fixture (`REQ-004`: subprocess inherits the isolation variables).

## Design decisions

- Module constant `_PRODUCTION_DB_DIR` (new) is read at call time, so a test can monkeypatch it to a temporary stand-in directory; nothing under `/opt/llm` is touched by the tests.
- The comparison logic lives in plain helpers; the fixture only calls them, so unit tests need not drive pytest fixture machinery.
- Opt-out semantics: after a test carrying `production_paths_allowed` finishes, the baseline is refreshed (rejected alternative per the Plan: skip the whole check when any selected test has the marker).
- The environment fixture returns a builder function so the caller passes extras per call; it is not autouse and not session-scoped.

## Alternatives considered

- Hook-based detection in `pytest_sessionfinish` with a checker extension: kept as the UNK-01 fallback only (the checker inspects autouse fixtures, not hooks).
- A SQLite read-only connection to compare schemas: rejected, a connection can create `-wal`/`-shm` sidecars and would itself be a production touch (A1).
- Returning a ready dict from the environment fixture: rejected, callers need to merge extras and the dict would be shared mutable state.

## Implementation
### Target file
`tests/conftest.py`

### Procedure
1. Add the constant `_PRODUCTION_DB_DIR` (new) = `Path(_PRODUCTION_ROOT) / "db"` after `_CREATED_ROOT`, and module state `_db_baseline` (new), a dict of fingerprints or `None`.
2. Add `_fingerprint_directory` (new) taking a `Path` and returning `dict[str, tuple[int, int, str]]` keyed by the path relative to the directory (size, `st_mtime_ns`, sha256 hex of the bytes).
3. Add `_changed_files` (new) taking two such maps and returning a sorted list of strings, each naming the relative path and `changed`, `added`, or `removed`.
4. Add `_refresh_db_baseline` (new): if `_PRODUCTION_DB_DIR` (new) is not a directory set `_db_baseline = None`, else set it to `_fingerprint_directory(_PRODUCTION_DB_DIR)`.
5. Add `_assert_production_db_unchanged` (new): return silently when `_db_baseline is None` or the directory is now absent; otherwise compare and call `pytest.fail` with a message naming every changed file and stating that the session touched production database files.
6. Add the session-scoped autouse fixture `_guard_production_db_files` (new): call `_refresh_db_baseline()`, `yield`, then `_assert_production_db_unchanged()`.
7. In `_forbid_production_paths`, in the opt-out branch change `yield` then `return` into `yield`, `_refresh_db_baseline()`, `return`, so a marked test's own changes are not attributed to the session.
8. Add the non-autouse fixture `isolated_subprocess_env` (new), returning a builder `build(extra=None) -> dict[str, str]`.

### Method
- Walk with `Path.rglob("*")`, keep `is_file()` entries, read bytes with `read_bytes()` (no SQLite connection, no `open` for writing); sidecars are ordinary files and therefore counted (`REQ-001`).
- A file that disappears between listing and reading is recorded as absent for that scan, not an error (a real service may rotate a sidecar); the next compare reports the difference if it persists.
- `build(extra)` returns `PATH` and `HOME` from `os.environ` (same defaults the deploy tests use), the five isolation variables copied from `os.environ`, then `extra` last so a caller can override.
- Use `pytest.fail(msg, pytrace=False)` for the teardown failure so the report is the message only.

### Details
- Message format example: `session changed production database files: workflow.sqlite (changed), workflow.sqlite-wal (added)`.
- Place the new helpers directly after `_is_production_path`; place the fixtures after `_forbid_production_paths` so the autouse order in the file stays readable.
- The module docstring paragraph on isolation gains one sentence about the session fingerprint.
- Do not import `hashlib` lazily inside loops; import it once at the top with the other standard-library imports.
- Plan row `Related Tests`: `tests/test_production_isolation.py` (procedure 04).

## Compatibility considerations

- Every test loads this file (blast radius high): on a host without `/opt/llm/db` (CI) the fixture does nothing, and otherwise only reads files.
- The per-test guard and all existing fixtures are unchanged; the opt-out branch gains one call.
- Under `pytest-xdist` each worker runs its own session fixture (A4); duplicate reports for one change are acceptable.
- A real service writing to `/opt/llm/db` during a run surfaces as a failure naming the file (Plan Risks); the opt-out marker covers legitimate cases.

## Security considerations

- The check never opens a database connection and never writes, so it cannot modify or create production files; hashes are computed in memory from bytes already readable by the test user.
- The environment fixture copies only the named isolation variables, not the whole environment, so secrets in `os.environ` are not forwarded to subprocesses.

## Rollback considerations

- Revert the commit; no persisted state, schema, or production file is involved. After a revert, procedure 02's manifest entry must also be reverted or `check_conftest_integrity.py` reports the fixture missing.
