# Implementation Procedure: scripts/agent/services/context_view.py

## Goal

Remove the duplicated character-to-token ratio constants (`_RATIO_TEXT`, `_RATIO_TOOL_CALL`,
`_RATIO_SYSTEM`) currently redefined inside `_token_breakdown` and import the canonical
`RATIO_TEXT`, `RATIO_TOOL_CALL`, `RATIO_SYSTEM` constants from `scripts/shared/token_estimation.py`
instead, with no change to observable behavior.

## Scope

In scope: `scripts/agent/services/context_view.py` — add one module-level import, delete three
local constant definitions inside `_token_breakdown`, substitute four usages.

Out of scope: any change to the numeric ratio values; any change to
`scripts/shared/token_estimation.py`; any change to `ContextBudget`'s field names/shape or to
`budget_breakdown`'s character-counting logic; routing `_token_breakdown`'s inline
`int(len(text) / ratio)` expressions through `estimate_tokens_for_text` (bucket-key mismatch
between this function's `sys_tokens`/`hist_tokens`/`tool_tokens` accumulators and
`token_estimation.py`'s `"text"`/`"tool_calls"`/`"system"` breakdown keys — see plan Design
section for the full reasoning).

## Assumptions

- The two ratio-constant sets are value-identical today: `_RATIO_TEXT = 4.0` /
  `RATIO_TEXT = 4.0`, `_RATIO_TOOL_CALL = 2.5` / `RATIO_TOOL_CALL = 2.5`,
  `_RATIO_SYSTEM = 3.5` / `RATIO_SYSTEM = 3.5` — confirmed by direct source reading of both files
  (`scripts/agent/services/context_view.py:108-110` and `scripts/shared/token_estimation.py:14-16`)
  during this documentation pass. This is a pure identifier substitution, not a bugfix.
- `context_view.py`'s existing imports from `shared.git_helper`, `shared.json_utils`, and
  `shared.types` (lines 14-16) establish that `agent/services/` importing from `shared/` is
  already the file's convention; the new import follows the same pattern and the same
  `.importlinter` direction (shared → agent is forbidden; agent → shared is not).

## Design decisions

- Add the new import to the existing `from shared...` import group (lines 14-16), immediately
  after `from shared.json_utils import ...` and before `from shared.types import ...`, keeping
  the group alphabetically ordered by module name (`git_helper` < `json_utils` <
  `token_estimation` < `types`) so `ruff`'s isort-compatible `I` rules do not need to reorder it.
- Delete the three local constants (`_token_breakdown`'s lines 108-110) rather than aliasing them,
  since no other function in the file references `_RATIO_TEXT`/`_RATIO_TOOL_CALL`/`_RATIO_SYSTEM`
  (confirmed by the grep below — the only occurrences are the three definitions and the four
  usages inside `_token_breakdown`).

## Alternatives considered

N/A — the plan's Design section already ruled out the one alternative (routing through
`estimate_tokens_for_text`) with a concrete signature/bucket-key mismatch; no further alternative
exists for a pure constant-dedup change.

keeps its existing signature `(messages: list[LLMMessage]) -> tuple[int | None, int | None, int |
None]` and its existing per-role routing logic untouched.
