## Goal

In `scripts/db/schema_sql.py`: remove the `documents.fetched_at` column's
`DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))` clause, keeping the
existing `NOT NULL` constraint, so `fetched_at` becomes a mandatory,
caller-supplied value at the SQL layer with no timestamp fallback.

## Scope

- In scope: the `fetched_at` column definition line inside the `documents`
  table DDL within `_RAG_SCHEMA_TEMPLATE`.
- Out of scope: every other column on `documents` (`etag`, `last_modified`,
  `chunking_strategy` keep their current definitions unchanged) and every
  other table/template in this file (`chunks`, `sessions`, `messages`,
  `memories`, `memory_links`, `session_diagnostics`, `tasks`, `attempts`,
  `processed_events`, `artifacts`, `approvals`, `workflow_schema_version`,
  `events`) — none carry a `fetched_at` column.

## Assumptions

- This schema is applied via `create_rag_schema`/`create_schema.py` (plan
  Affected areas table); once the `DEFAULT` is removed, every `INSERT` path
  against `documents` must supply `fetched_at` explicitly. Per the plan,
  that is `SQLiteDocumentStore.doc_upsert()` (this batch's companion
  document) and `Ingester._insert_document()` (separate document, same
  plan, out of scope here).
- No on-disk migration for already-created database files is required in
  this phase — the plan's Scope/Assumptions state no legacy-data
  compatibility constraint is claimed, and the DDL uses `CREATE TABLE IF NOT
  EXISTS`, so this text change only takes effect for databases created
  fresh after the change; an existing `rag.sqlite` file's column default
  (baked in at its original creation time) is untouched by editing this
  template.
- Confirmed current definition, by reading the file: `fetched_at TEXT NOT
  NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))` inside the
  `documents` table in `_RAG_SCHEMA_TEMPLATE`.

## Design decisions

- Remove only the `DEFAULT (strftime(...))` clause text; keep `TEXT NOT
  NULL` unchanged so the column stays mandatory, now with no fallback value.
- Leave `chunking_strategy`'s `DEFAULT 'text'` on the same table untouched —
  that default is unrelated to this requirement and explicitly out of the
  plan's scope.

## Alternatives considered

- Keep a `DEFAULT` but change it to an obviously-invalid sentinel (e.g. an
  empty string) as a soft warning signal — rejected: the plan calls for
  fail-closed behavior (a `NOT NULL constraint failed` error), not a value
  that would silently satisfy `NOT NULL` while remaining semantically wrong.
- Add a `CHECK` constraint validating the `fetched_at` string format —
  rejected as scope creep: the plan only specifies removing `DEFAULT` and
  keeping `NOT NULL`; it does not request new format validation at the SQL
  layer, and AGENTS.md Global Rule 4 prohibits speculative additions beyond
  what was asked.

## Implementation

### Target file

`scripts/db/schema_sql.py`

### Procedure

1. In `_RAG_SCHEMA_TEMPLATE`, locate the `documents` table's `fetched_at`
   column line.
2. Change `fetched_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ',
   'now')),` to `fetched_at TEXT NOT NULL,`.
3. No other line in `_RAG_SCHEMA_TEMPLATE`, and no other part of the module,
   changes.

### Method

Direct string-literal edit inside the triple-quoted SQL template constant;
no change to `build_rag_schema_sql(dims)`'s own logic (it only substitutes
the `DIMS` placeholder and is unrelated to this column).

### Details

- After the edit, confirm the diff is confined to this one column line —
  `chunking_strategy`'s separate `DEFAULT 'text'` clause on the same table
  is a different, unrelated pattern and must remain.
- This is a template-string change: it takes effect only for databases
  created fresh after the change (`CREATE TABLE IF NOT EXISTS` does not
  alter an existing table's column defaults). No `ALTER TABLE` migration is
  included in this document's scope (see Out of scope).

## Compatibility considerations

- Fail-closed by design, and intentional: after this change, any future
  `INSERT` into `documents` that omits `fetched_at` (or supplies `NULL`)
  fails immediately at the SQL layer with `NOT NULL constraint failed:
  documents.fetched_at`, instead of silently receiving the current
  wall-clock time as before. The plan's Risks section states this
  explicitly ("this is the desired outcome, not a defect") — it is a
  deliberate fail-closed design choice, not a regression, and must not be
  "fixed" by re-adding a `DEFAULT` clause if it is later observed in
  production logs.
- Existing, already-created SQLite database files are unaffected by this
  DDL text change (`CREATE TABLE IF NOT EXISTS` is a no-op when the table
  already exists) — only newly initialized databases pick up the
  `DEFAULT`-less column definition.
- Every writer of `documents.fetched_at` loses its DB-level fallback: per
  the plan, this is `SQLiteDocumentStore.doc_upsert()` (this batch's
  companion document, which the plan states already supplies `fetched_at`
  explicitly) and `Ingester._insert_document()` (separate document, same
  plan) — both must be verified to always pass a non-null value once this
  lands.

## Security considerations

N/A: pure schema DDL text change to a `NOT NULL`/`DEFAULT` clause; no
user-controlled input handling and no injection surface is introduced or
removed here — the change affects which values can pass validation at the
SQL layer, not how values are escaped or bound.

## Rollback considerations

- Revert by restoring the `DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))`
  clause text on the `documents.fetched_at` column line. Safe to revert
  independently of `store_impl.py`'s change: a caller that already supplies
  `fetched_at` explicitly is unaffected by the mere presence of a `DEFAULT`
  clause (a `DEFAULT` is only consulted when a column is omitted from the
  `INSERT`'s column list).
- Because `CREATE TABLE IF NOT EXISTS` only applies to freshly created
  databases, reverting this file does not retroactively change any
  already-created database's column default in either direction — no data
  migration is needed for rollback.

  documents.fetched_at`).
- `uv run pytest tests/db/test_db_store_impl.py -v` — exercises
  `doc_upsert()` against the updated schema end-to-end, once that file's own

  document.
- Plan's Phase 6 regression command: `rg -n
  "fetched_at|_update_null_fill|new_fetched_at.*None|COALESCE\(\?,
  fetched_at\)|strftime\('%Y-%m-%dT%H:%M:%SZ'" scripts tests` — zero matches
  for the removed `DEFAULT`/`strftime` pattern once every affected file in
  the plan has landed.

## Out of scope

- An `ALTER TABLE` migration path for already-created database files — not
  requested by the plan (no legacy-data compatibility constraint claimed).
- `SQLiteDocumentStore.doc_upsert()` and `Ingester._insert_document()`
  caller updates (own implementation documents in this plan).
- Any other column's `DEFAULT` clause on `documents` (`etag`,
  `last_modified`, `chunking_strategy`) or any other table in this file —
  unrelated to this requirement.
