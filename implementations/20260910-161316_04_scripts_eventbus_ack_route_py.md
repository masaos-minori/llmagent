## Goal

Replace `scripts/eventbus/ack_route.py`'s two-call pattern (`_ack_event()` then `write_offset()`) with a single call into the new transactional `eventbus.db` function (`ack_event_for_consumer`), ensuring the delivery write and offset advancement commit or roll back together in one SQLite transaction.

## Scope

- Replace the body of `_ack_and_offset()` to call `ack_event_for_consumer()` instead of `_ack_event()` + `write_offset()`.
- Remove the `from eventbus.offsets import write_offset` import (no longer needed).
- Keep the existing return value structure `(found, newly_acked, seq)` for API compatibility.

## Assumptions

- `ack_event_for_consumer()` always returns `(found, newly_acked, seq)` matching the current return type.
- The `consumer_id` parameter is already validated as non-empty before calling `ack_event_for_consumer()`.
- The `now` timestamp is still generated by `now_iso()` within `_ack_and_offset()`.

## Design decisions

- **Single function call**: Replace the two independent calls with one atomic call. This eliminates the gap where `ack_event()` commits but `write_offset()` fails.
- **No try/except addition**: The new `ack_event_for_consumer()` handles its own transaction rollback internally; `_ack_and_offset()` does not need additional error handling.
- **Preserve existing behavior**: When `newly_acked` is False, the response includes `"already_acked": True` — this behavior is preserved.

## Alternatives considered

- **Keep both calls but wrap in try/except**: Would require catching the `ValueError` from `write_offset()` and rolling back the ACK manually. Rejected because this duplicates logic that `ack_event_for_consumer()` already handles atomically.
- **Remove the `seq` return value**: Since the offset is now tracked in SQLite, the caller doesn't need the raw `seq` for offset purposes. However, `seq` may be used elsewhere for logging/debugging, so it's kept for backward compatibility.

```python
def _ack_and_offset() -> tuple[bool, bool, int | None]:
    """Acknowledge an event atomically (delivery + offset in one transaction)."""
    from eventbus.db import ack_event_for_consumer  # noqa: PLC0415

    now = now_iso()
    found, newly_acked, seq = ack_event_for_consumer(
        db, event_id, consumer_id, now
    )
    return (found, newly_acked, seq)
```

### Details

The key changes are:

1. **Import removal**: `write_offset` is no longer imported since the new transactional function handles offset advancement internally.

2. **Function replacement**: The two-step process (`_ack_event` → `write_offset`) is replaced by a single call to `ack_event_for_consumer`. The new function:
   - Performs the per-consumer delivery-state UPSERT atomically.
   - Only advances the offset when `newly_acked` is True.
   - Uses atomic monotonic enforcement via `ON CONFLICT(consumer_id) DO UPDATE SET offset = excluded.offset WHERE excluded.offset > consumer_offsets.offset`.
   - Commits once at the end, or rolls back on any exception.

3. **Return value preservation**: The `(found, newly_acked, seq)` return type is unchanged, maintaining API compatibility with the outer `_do_ack()` function.

4. **Conditional offset tracking**: The `if consumer_id and newly_acked:` guard is preserved — the offset is only advanced when a consumer has newly acknowledged an event.

## Compatibility considerations

- The return type `(found, newly_acked, seq)` is unchanged, so `_do_ack()` continues to work without modification.
- The `already_acked` response path is preserved when `newly_acked` is False but the event exists.
- The `seq` return value is preserved even though the offset is now tracked in SQLite — it may be used for logging/debugging.

## Security considerations

- No new authentication or authorization boundaries introduced.
- No user input flows directly into SQL — all values are bound via `?` placeholders.
- The `consumer_id` parameter is validated as non-empty by `ack_event_for_consumer()`.

## Rollback considerations

- To rollback: restore the original two-call pattern (`_ack_event` + `write_offset`).
- The rollback restores the pre-change state where the ACK and offset writes are independent operations.
