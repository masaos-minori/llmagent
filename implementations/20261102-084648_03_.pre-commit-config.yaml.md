## Assumptions
- Source plan A1 and Design Self-check: the hook runs `python -m tools.run_validation_gates drift`, the same module form every other hook uses; `tools/__init__.py` exists.
- Step 3a: the drift hook is skipped by the hook parser through the `_SELF_CHECKER_ID` rule (row 01), so adding it does not create a drift error.
- Step 3a: no hook id `drift` or similar exists today; the new id is `gates-hook-parity`.
- Depends on the row 01 procedure (the extended `drift`) landing first; the hook run in Validation plan fails before it.
- Overlap (Step 2): `.pre-commit-config.yaml` is targeted by no other open Plan.

## Design decisions
- Mirror the existing local hook shape (`entry: python -m tools.<name>`, `language: system`, `pass_filenames: false`) with a `files` filter instead of `always_run`, so the check runs only when its inputs change.

## Alternatives considered
- `always_run: true`: rejected, it would add a run to every commit for a check whose inputs change rarely.
- Add `tools/check_*.py` to the `files` filter: rejected, mapping drift is only caused by the config, `routing.md`, or the runner itself.
