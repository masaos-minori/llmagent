## Design decisions

- Add `interrupt_when(self, stop: threading.Event | None, *, check_every: int = 1000) -> None` (new): with an event, install the sqlite3 connection progress handler API with a callable that returns a non-zero value while `stop.is_set()`; with `None`, remove the handler. SQLite then aborts the running statement and Python raises `sqlite3.OperationalError` (message `interrupted`).
- The method requires an open connection (`_require_conn`), raises `ValueError` for `check_every < 1`, and touches no other connection state. `check_every` (new) is the number of SQLite VM steps between handler calls; the default is a starting value to be measured in the helper test.

## Alternatives considered

- Calling `Connection.interrupt()` from the event-loop thread: rejected, it needs a handle to the worker's connection across threads and races with close.
- A cooperative flag inside `check_rag_consistency`: rejected in the Plan (shared with recovery verification).
