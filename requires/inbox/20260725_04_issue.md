## [repl] Ephemeral message filtering relies on trust

### Summary

`_clear_previous_turn_ephemeral_messages()` は `_ephemeral` および `_memory_injected` キーに基づくフィルタリングを行う。これらのキーの設定は信頼に依存しており、スキーマ検証がない。

### Problem

`orchestrator.py:542-553` で ephemeral メッセージのフィルタリングが行われる：

```python
def _clear_previous_turn_ephemeral_messages(self) -> None:
    ctx = self._ctx
    ctx.conv.history = [
        m
        for m in ctx.conv.history
        if not m.get("_ephemeral") and not m.get("_memory_injected")
    ]
```

`cmd_skill.py:47-56` でも同様のフィルタリングが行われる：

```python
ctx.conv.history = [
    m for m in ctx.conv.history if not m.get("_skill_ephemeral")
]
```

これらのフィルタリングは、メッセージに特定のキーが含まれているかどうかに依存している。もし LLM がこれらのキーを持つ偽の system メッセージを生成した場合、フィルタリングが誤動作する可能性がある。

また、`_ephemeral` キーを持たないメッセージはフィルタリング対象外となるため、LLM が意図的にこれらのキーを省略して永続的なメッセージとして残すことができる。

### Affected Files

- `scripts/agent/orchestrator.py:542-553` — `_clear_previous_turn_ephemeral_messages()`
- `scripts/agent/commands/cmd_skill.py:47-56` — ephemeral フィルタリング

### Attack Scenario

1. LLM が `_ephemeral` キーを持たない偽の system メッセージを生成
2. このメッセージはフィルタリング対象外となり、会話履歴に残る
3. 次のターンでこのメッセージがシステムコンテキストとして再利用される
4. LLM の振る舞いが意図せぬ方向に操作される

### Severity

Medium — ephemeral メッセージのフィルタリングがキーの有無に依存しており、LLM がこれらのキーを操作できる可能性がある。

### Mitigation

- メッセージの role と content の構造を検証するスキーマバリデーションを追加
- ephemeral メッセージの生成を信頼できるソース（コマンドハンドラのみ）に限定
- フィルタリング前にメッセージの正当性を確認するチェックを追加
