## [repl] WAL checkpoint PASSIVE mode may block indefinitely

### Summary

`repl.py:256-257` で WAL checkpoint に PASSIVE モードを使用している。PASSIVE モードは他の接続がアクティブな場合、完了しないことがある。シャットダウン時に長時間ブロックし、リソースリークの原因になる。

### Problem

`repl.py:256-257` で定義：

```python
# WAL checkpoint logic using PASSIVE mode
```

PASSIVE チェックポイントが完了しない場合、TRUNCATE モードにフォールバックするが、TRUNCATE モードも失敗する場合、WAL ファイルのバックアップが試みられる。

### Affected Files

- `scripts/agent/repl.py:256-257` — WAL チェックポイントの定義
- `scripts/agent/repl.py:297-306` — WAL ファイルのバックアップ先パス生成

### Attack Scenario

1. シャットダウン中に WAL チェックポイントが実行される
2. PASSIVE モードで他の接続がアクティブな場合、チェックポイントが完了しない
3. TRUNCATE モードにも失敗した場合、WAL ファイルのバックアップが試みられる
4. シャットダウン時に長時間ブロックし、リソースリークの原因になる

### Severity

Medium — PASSIVE チェックポイントにタイムアウトを設定し、一定時間経過したら強制的にフォールバックする必要がある。

### Mitigation

- PASSIVE チェックポイントにタイムアウトを設定し、一定時間経過したら強制的にフォールバックする
