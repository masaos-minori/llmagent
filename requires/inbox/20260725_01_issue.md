## [repl][tool_runner] Tool arguments injection via LLM-generated tool calls

### Summary

LLMが生成したツール呼び出しの引数（arguments）に追加のフィールドや値を注入可能。`orjson.loads()` でパースされた後、MCPサーバーに直接送信され、サンドボックス化されていない。

### Problem

`tool_runner.py:132` で `orjson.loads(args_str)` が実行され、LLMが生成したツール引数がパースされる。この引数はその後 `ctx.services_required.gateway.execute(ctx, name, args)` または `ctx.services_required.tools.execute(name, args)` に渡される。LLMが意図的に悪意のある引数を生成した場合、その引数はそのままMCPサーバーに送信され、実行される。

### Affected Files

- `scripts/agent/tool_runner.py:132` — `orjson.loads(args_str)`
- `scripts/agent/tool_runner.py:139-141` — MCP tool execution
- `scripts/shared/tool_executor.py:209-218` — `ToolExecutor.execute()`

### Attack Scenario

1. ユーザーが LLM に特定のツール呼び出しを誘導するプロンプトを送信
2. LLM が追加の引数フィールド（例: `{"filename": "target.txt", "force_overwrite": true}`）を含むツール呼び出しを生成
3. これらの引数はバリデーションなしで MCP サーバーに送信され、実行される

### Severity

High — LLM が生成したツール呼び出しの引数に追加のフィールドや値を注入可能。MCP サーバーへの送信前にバリデーションがない。

### Mitigation

- MCP ツール呼び出し送信前に引数のホワイトリストバリデーションを追加
- 予期せぬフィールドを拒否するスキーマ検証を追加
- MCP サーバー側でも引数のバリデーションを行う
