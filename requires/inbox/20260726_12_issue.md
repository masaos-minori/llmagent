## [tool_runner] Missing schema validation for LLM-generated tool call arguments

### Summary

`execute_one_tool_call()` で LLM 生成のツール呼び出し引数が `orjson.loads()` でパースされた後、スキーマ検証が行われない。読み取り操作（READツール）ではスキーマ検証が行われないため、不正なパラメータによる情報漏洩やエラー誘導が可能。

### Problem

`tool_runner.py:131-136` でツール呼び出し引数がパースされるが、スキーマ検証は行われない：

```python
args_str = func.get("arguments", "{}")
try:
    args = orjson.loads(args_str)
except orjson.JSONDecodeError as e:
    raise ToolArgumentsDecodeError(
        f"Invalid JSON in tool arguments for {name!r}: {args_str!r}"
    ) from e
```

ツール呼び出し引数のスキーマ検証は `repository_gateway.py:90` の `_gate_write()` 内でのみ行われ、読み取り操作（READツール）ではスキーマ検証が行われない。

### Affected Files

- `scripts/agent/tool_runner.py:131-136` — `execute_one_tool_call()` 内の `orjson.loads()` 呼び出し
- `scripts/agent/repository_gateway.py:90` — `_gate_write()` 内のスキーマ検証
- `scripts/agent/tool_arg_validator.py` — スキーマ検証ロジック

### Attack Scenario

1. LLM が誤ったツール呼び出し引数を生成する
2. 読み取りツール（例: `read_text_file`）に対して不正な引数（例: `path="/etc/shadow"`）が渡される
3. スキーマ検証が行われないため、不正なパラメータが通過する
4. 情報漏洩やエラー誘導が発生する

### Severity

High — 読み取りツールでもスキーマ違反の引数が通過し、不正なパラメータによる情報漏洩やエラー誘導が可能。

### Mitigation

- すべてのツール呼び出しに対して `validate_tool_arguments()` を適用する
- `execute_one_tool_call()` の `orjson.loads()` 直後に呼び出す
