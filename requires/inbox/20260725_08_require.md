# WAL file backup path traversal vulnerability

## Priority

Low

## Target Files

- `scripts/agent/repl.py` — WAL file backup logic in `_close_resources()`

## Background

During shutdown, `_close_resources()` attempts to back up the SQLite WAL file before closing connections. The backup path is constructed from the database file path obtained via `PRAGMA database_list`.

## Problem

In `repl.py:296-314`:

```python
db_path = db.execute("PRAGMA database_list").fetchone()[1]
if db_path:
    wal_file = f"{db_path}-wal"
    backup_dir = os.path.dirname(db_path) or "/tmp"
    wal_backup_path = os.path.join(
        backup_dir,
        f"{os.path.basename(db_path)}-wal-backup-{int(time.time())}",
    )
    shutil.copy2(wal_file, wal_backup_path)
```

The `db_path` obtained from `PRAGMA database_list` is not validated. If the database file is a symbolic link pointing to an external directory, the WAL file backup destination could be an unexpected location. Additionally, if `backup_dir` is a system directory like `/tmp`, race conditions with other processes creating files with the same name can occur.

## Reason for Change

Without validation, symlinked database paths can cause WAL backups to be written outside the intended directory. In multi-tenant or containerized environments, this can lead to unauthorized writes or file overwrites due to filename collisions.

## Implementation Intent

Validate the database path before using it in filesystem operations. Check for symlinks and ensure the backup destination is within an allowed directory. Verify the backup directory exists and has write permissions.

## Implementation Instructions

1. After obtaining `db_path`, resolve any symlinks using `os.path.realpath()`.
2. Validate that the resolved path is within an allowed base directory (e.g., the project data directory).
3. Before writing the backup, verify the backup directory exists and has write permissions.
4. Use a unique filename based on session_id instead of timestamp to avoid collisions.

## Acceptance Criteria

- [ ] Symlinked database paths are resolved before use
- [ ] Backup destination is within allowed directories
- [ ] Backup directory existence and permissions are verified
- [ ] Unique filenames prevent collisions

## Tests

- Unit test: mock symlinked database path; verify backup is prevented or redirected safely
- Unit test: verify backup directory permission check works correctly
- Integration test: simulate concurrent WAL backups; verify no filename collisions
