## [orchestrator] Message schema validation not applied to conversation history insertion

### Summary

`message_schema.py` に `validate_message()` が存在するが、会話履歴へのメッセージ挿入時に全面的に適用されていない。LLM が会話履歴に不正なキーやフィールドを注入可能。特に `_ephemeral` キーの偽装により、一時的キーの不正使用が可能。

### Problem

`orchestrator.py:389` で `_memory_injected` キーが直接付与されたシステムメッセージが挿入される：

```python
ctx.conv.history.append(
    {
        "role": "system",
        "content": memory_block,
        "_memory_injected": True,
    }
)
```

`_ephemeral` キーも同様に `orchestrator.py:552` でフィルタリングのみ行われる：

```python
ctx.conv.history = [
    m
    for m in ctx.conv.history
    if not m.get("_ephemeral") and not m.get("_memory_injected")
]
```

### Affected Files

- `scripts/agent/orchestrator.py:389` — `_handle_memory_injection()` 内のメッセージ挿入
- `scripts/agent/orchestrator.py:552` — `_clear_previous_turn_ephemeral_messages()` 内のフィルタリング
- `scripts/agent/message_schema.py` — `validate_message()` の定義

### Attack Scenario

1. LLM が会話履歴に不正なキーやフィールドを注入する
2. `_ephemeral` キーの偽装により、一時的キーの不正使用が可能になる
3. 会話履歴の整合性が損なわれ、予期せぬ動作が発生する

### Severity

High — LLM が会話履歴に不正なキーやフィールドを注入可能。特に `_ephemeral` キーの偽装により、一時的キーの不正使用が可能。

### Mitigation

- 会話履歴へのすべてのメッセージ挿入前に `validate_message()` を呼び出す
- 特に `orchestrator.py:389` と `orchestrator.py:552` の両方で検証を適用する
