# Ephemeral message filtering relies on trust

## Priority

Medium

## Target Files

- `scripts/agent/orchestrator.py` — `_clear_previous_turn_ephemeral_messages()`
- `scripts/agent/commands/cmd_skill.py` — ephemeral filtering

## Background

Ephemeral messages (temporary messages that should not persist across turns) are identified and removed based on the presence of `_ephemeral` and `_memory_injected` keys in the message dictionary.

## Problem

In `orchestrator.py:542-553`:

```python
def _clear_previous_turn_ephemeral_messages(self) -> None:
    ctx = self._ctx
    ctx.conv.history = [
        m
        for m in ctx.conv.history
        if not m.get("_ephemeral") and not m.get("_memory_injected")
    ]
```

Similarly in `cmd_skill.py:47-56`:

```python
ctx.conv.history = [
    m for m in ctx.conv.history if not m.get("_skill_ephemeral")
]
```

These filters rely entirely on the presence of specific keys in the message dictionary. If the LLM generates fake system messages containing these keys, the filtering will malfunction. Additionally, messages without these keys are not filtered, meaning the LLM can intentionally omit them to leave persistent messages in the conversation history.

## Reason for Change

Without schema validation, the ephemeral filtering mechanism can be bypassed or manipulated by the LLM. This allows the LLM to inject persistent messages into the conversation history, potentially manipulating future turns' behavior.

## Implementation Intent

Add schema validation for all messages added to the conversation history. Restrict ephemeral message generation to trusted sources only (command handlers). Verify message legitimacy before filtering.

## Implementation Instructions

1. Define a strict schema for valid conversation messages (required fields: role, content).
2. Validate all messages against the schema before adding them to the conversation history.
3. Restrict ephemeral key injection to trusted command handlers only — reject messages with ephemeral keys from untrusted sources.
4. Add a whitelist of allowed keys for each message role.

## Acceptance Criteria

- [ ] All messages validated against strict schema before insertion
- [ ] Ephemeral keys only accepted from trusted command handlers
- [ ] Messages with invalid roles or missing required fields rejected
- [ ] Filtering cannot be bypassed by injecting/removing ephemeral keys

## Tests

- Unit test: attempt to add message with _ephemeral key from non-command-handler source; verify rejection
- Unit test: attempt to add message without required fields; verify rejection
- Integration test: simulate LLM generating message designed to bypass ephemeral filtering; verify prevention
