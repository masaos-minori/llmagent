# Make fetched_at mandatory end to end and remove timestamp compatibility behavior

## Priority

High

## Target files

- `scripts/db/schema_sql.py` (schema default for `documents.fetched_at`)
- Related tests, mocks, and fixtures under `tests/`

## Background

Crawler already records an acquisition timestamp at scrape time, but this value is not
carried through the rest of the ingestion pipeline as a strict, mandatory field. Verified
against current source:

- `scripts/rag/ingestion/crawler.py`: `CrawlPayload.fetched_at` is set via
  `datetime.now().isoformat(timespec="seconds")` (lines 129, 335) — this is a naive local
  time, not the canonical UTC `Z` form the issue requires.
- `scripts/rag/models_data.py`: `ChunkDocument` (line 32) has no `fetched_at` field at all,
  so the timestamp is discarded once chunking starts.
- `scripts/rag/ingestion/chunk_splitter.py`: has zero references to `fetched_at` — it does
  not read the crawler's timestamp or write it into chunk output payloads.
- `scripts/rag/ingestion/pipeline_utils.py` (line 29): `ChunkJsonRaw.fetched_at` is already
  declared as `NotRequired[str | None]`, i.e. optional today.
- `scripts/rag/ingestion/ingester.py`: `_insert_document()` (lines 474-490) has two INSERT
  branches — one that includes `fetched_at` in the column list, and a second (`cursor2`,
  used when `fetched_at is None`) that omits the column entirely, letting the SQLite
  column default apply.
- `scripts/db/schema_sql.py` (line 32): `documents.fetched_at` has
  `DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))` — i.e. database insertion time, not
  source acquisition time.
- `scripts/rag/ingestion/document_manager.py`: `handle_existing_document()` (param
  `fetched_at: str | None`) and `_update_etag()` (param `new_fetched_at: str | None = None`)
  both accept optional timestamps and pass them through unchanged.
- `scripts/rag/ingestion/etag_manager.py`: `ETagManager.update()` (lines 23-48) branches on
  `new_fetched_at is not None`; when `None`, it calls `_update_null_fill()` (lines 95-101),
  which only fills NULL `etag`/`last_modified` columns and never touches `fetched_at`.
  `_is_stale_update()` (lines 50-81) parses both the incoming and stored timestamps inside
  `try/except ValueError` blocks that `return False` (i.e. "treat as non-stale") on parse
  failure — a fail-open behavior that lets malformed timestamps proceed to the update SQL
  in `_update_with_freshness()` (line 91), which itself uses
  `fetched_at = COALESCE(?, fetched_at)`.
- `scripts/db/store_protocols.py` (`DocumentStore.doc_upsert()`, lines 84-93) and
  `scripts/db/store_impl.py` (`SQLiteDocumentStore.doc_upsert()`, lines 84-108) have no
  `fetched_at` parameter; the UPDATE branch of the upsert's `ON CONFLICT` clause sets
  `fetched_at = strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` (store_impl.py line 101) — again,
  database time rather than source time.

All of the issue's factual claims are confirmed against current source. This issue's own
"Dependencies" section names the requirement "Replace permissive RAG payload handling with
strict crawl and chunk contracts," which was already processed into
`requires/20260819-144406_require.md`. That requirement establishes strict, mandatory-field
crawl/chunk contracts; this requirement builds on it by making `fetched_at` specifically one
of those mandatory fields, end to end through storage.

## Problem

`fetched_at` is optional at every layer of the ingestion pipeline (crawler DTO, chunk
metadata, chunk JSON, ingester, document manager, etag manager, document store), and every
layer that finds it missing falls back to a different kind of default or silent tolerance
instead of failing:

- The crawler generates a naive local timestamp, not a canonical UTC `Z` string.
- `ChunkDocument` drops the field, so `ChunkSplitter` output never carries it forward.
- `Ingester._insert_document()` silently omits the `fetched_at` column when the value is
  `None`, letting the schema's `DEFAULT (strftime(...))` (database insertion time) apply.
- `ETagManager.update()` takes a null-fill path (`_update_null_fill()`) whenever
  `new_fetched_at` is `None`, which never updates `fetched_at` and is a distinct
  compatibility branch from the intended freshness comparison.
- `ETagManager._is_stale_update()` treats a malformed (unparseable) timestamp — either the
  incoming value or the stored value — as "not stale," which lets a corrupt or malformed
  timestamp flow through to the `UPDATE ... fetched_at = COALESCE(?, fetched_at)` SQL
  instead of being rejected.
- `SQLiteDocumentStore.doc_upsert()` has no way to accept a caller-supplied `fetched_at` at
  all; both INSERT (schema default) and UPDATE (`ON CONFLICT` `strftime(...)`) branches
  derive the timestamp from database time.

Net effect: the value stored in `documents.fetched_at` can silently become "when this row
was written/updated in SQLite" rather than "when the source document was actually fetched,"
and a metadata refresh with both `etag` and `last_modified` equal to `null` can be silently
dropped without ever updating `fetched_at`, even when the true source timestamp is newer.

## Reason for change

No legacy data exists that depends on `fetched_at` being optional or database-derived, so
there is no compatibility constraint to preserve. Because Crawler already computes the
correct acquisition time, the fix is to (a) make that one value canonical and UTC, (b)
propagate it unchanged through every DTO/model/table in the pipeline, and (c) delete every
fallback/default/null-fill/fail-open branch that exists only because the field used to be
optional. Leaving any of those branches in place after propagation is guaranteed would
reintroduce exactly the ambiguity (source time vs. database time) this change is meant to
eliminate, and a partially-strict rollout (e.g. still allowing `None` in `doc_upsert()`)
would leave open the freshness-comparison bug where updates with only-null HTTP metadata
never refresh `fetched_at`.

## Implementation intent

1. In `crawler.py`, generate `fetched_at` once, in canonical UTC form
   (`YYYY-MM-DDTHH:MM:SSZ`, e.g. via `datetime.now(UTC).strftime("%Y-%m-%dT%H:%M:%SZ")`)
   instead of `datetime.now().isoformat(timespec="seconds")`. For local `file://` sources,
   derive the same UTC form explicitly from the file's modification time rather than reusing
   wall-clock "now."
2. Widen `fetched_at`/`new_fetched_at` from `str | None` to mandatory `str` across every
   signature listed in the issue's Implementation Tasks: `ChunkDocument`, the crawl/chunk
   TypedDicts in `pipeline_utils.py`/`chunk_splitter.py`, `Ingester` document-metadata
   handling, `DocumentManager.handle_existing_document()`, `DocumentManager._update_etag()`,
   `ETagManager.update()`, and `DocumentStore.doc_upsert()` (protocol and
   `SQLiteDocumentStore` implementation).
3. Propagate the single crawler-generated timestamp unchanged from the crawl payload into
   every chunk file produced from that crawl record — do not regenerate or re-derive it at
   chunking time.
4. Remove every fallback/compatibility branch that exists solely to handle a missing
   timestamp:
   - the `Ingester._insert_document()` branch (the `cursor2` path) that omits the
     `fetched_at` column,
   - `ETagManager._update_null_fill()` and the `new_fetched_at is None` dispatch branch in
     `ETagManager.update()`,
   - the SQLite `DEFAULT (strftime(...))` / `ON CONFLICT ... fetched_at =
     strftime(...)` current-time substitutions in `doc_upsert()` and the schema.
5. Change timestamp validation from fail-open to fail-closed: reject timezone-naive
   timestamps, raise on malformed incoming timestamps (do not swallow `ValueError` and
   return `False`), and treat a malformed *stored* timestamp as a database consistency error
   rather than "not stale."
6. Fix the freshness-update logic so that when `etag` and `last_modified` are both `null`
   but the incoming `fetched_at` is newer than the stored value, `fetched_at` is still
   updated (no early return that skips the update purely because HTTP metadata is absent).
   Replace `fetched_at = COALESCE(?, fetched_at)` with a direct `fetched_at = ?` now that the
   value is guaranteed non-null. Explicitly define and test the equal-timestamp case (neither
   "stale" nor triggering a redundant write is acceptable without a documented decision —
   pick one behavior and encode it in a test).
7. Update every caller, `Protocol` implementation, mock, and fixture accordingly so the
   codebase has exactly one non-nullable `fetched_at`/`new_fetched_at` contract from Crawler
   through to the SQLite row.

## Implementation instructions

- `scripts/rag/ingestion/crawler.py`: change both `fetched_at` assignments (currently
  `datetime.now().isoformat(timespec="seconds")`, lines ~129 and ~335) to produce
  `YYYY-MM-DDTHH:MM:SSZ` in UTC. For the local-file crawl path, compute the UTC form from the
  file's modification time explicitly (do not silently reuse "now" for file sources if the
  existing code path already reads mtime elsewhere — check `mtime_iso` usage at line ~134).
- `scripts/rag/models_data.py`: add a mandatory `fetched_at: str` field to `ChunkDocument`
  (no default value, so all constructors must supply it).
- `scripts/rag/ingestion/pipeline_utils.py` / `scripts/rag/ingestion/chunk_splitter.py`:
  change `fetched_at` in `ChunkJsonRaw`, `CrawlFilePayload`, and `ChunkOutputPayload` (and any
  `ChunkMetadata` TypedDict fields) from `NotRequired[str | None]` to a required `str` field,
  and thread the crawler's `fetched_at` value through `ChunkSplitter`'s per-chunk output
  construction so every chunk file for one crawl record carries the identical value.
- `scripts/rag/ingestion/ingester.py`:
  - Change `_get_or_create_document()`, `_insert_document()`, and
    `_commit_url_transaction()` parameter `fetched_at: str | None = None` to `fetched_at: str`
    (no default).
  - Delete the `if fetched_at is not None: ... else: cursor2 = ...` branch in
    `_insert_document()` (lines ~477-490); keep only the INSERT that always includes the
    `fetched_at` column.
- `scripts/rag/ingestion/document_manager.py`: change
  `handle_existing_document(..., fetched_at: str | None, ...)` and
  `_update_etag(..., new_fetched_at: str | None = None)` to require `str` (no default on
  `_update_etag`'s parameter once callers always supply it).
- `scripts/rag/ingestion/etag_manager.py`:
  - Change `update(self, etag, last_modified, new_fetched_at: str)` to require `str`.
  - Delete `_update_null_fill()` entirely and the `else: self._update_null_fill(...)` branch
    in `update()`.
  - In `_is_stale_update()`: reject timezone-naive `new_fetched_at` (raise, do not silently
    assume UTC via `replace(tzinfo=UTC)`); on `ValueError` while parsing the incoming
    timestamp, raise instead of `logger.error(...); return False`; on `ValueError` while
    parsing the *stored* timestamp, raise a distinct error signaling a database consistency
    problem (the stored value should never be malformed since this same code path now
    enforces validity on write).
  - In `_update_with_freshness()`: change the UPDATE SQL's
    `fetched_at = COALESCE(?, fetched_at)` to `fetched_at = ?`.
  - Ensure `update()` still calls `_update_with_freshness()` (or an equivalent single
    freshness-aware path) even when `etag` and `last_modified` are both `null`, as long as
    `new_fetched_at` is newer than the stored value — remove any early return keyed only on
    `etag is None and last_modified is None` that would otherwise skip the timestamp update.
  - Add an explicit, tested decision for the equal-timestamp case (`new_dt == stored_dt`):
    document whether this counts as "stale" (skip) or "fresh" (update) and implement
    consistently with `_is_stale_update()`'s `<` comparison.
- `scripts/db/store_protocols.py`: add `fetched_at: str` to `DocumentStore.doc_upsert()`'s
  signature.
- `scripts/db/store_impl.py`: update `SQLiteDocumentStore.doc_upsert()` to accept
  `fetched_at: str` and use it directly for both the INSERT column list and the
  `ON CONFLICT ... DO UPDATE SET fetched_at = ?` clause; remove the
  `fetched_at = strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` current-time substitution.
- `scripts/db/schema_sql.py`: remove or reconsider the `documents.fetched_at DEFAULT
  (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))` clause (line ~32) — once every INSERT path
  supplies `fetched_at` explicitly, the database default should not be relied upon
  (dropping `DEFAULT` guards against future silent omissions).
- Update all mocks/fixtures/tests that currently construct `ChunkDocument`,
  call `ETagManager.update()`, `DocumentManager._update_etag()`, or
  `SQLiteDocumentStore.doc_upsert()` without a `fetched_at` argument.

## Acceptance criteria

- [ ] Crawler output always contains a canonical UTC `fetched_at` (`YYYY-MM-DDTHH:MM:SSZ`).
- [ ] Every chunk produced from one crawler record contains the identical `fetched_at`.
- [ ] `ChunkDocument`, `Ingester`, `DocumentManager`, `ETagManager`, and `DocumentStore`
      (protocol + `SQLiteDocumentStore`) all require a non-null `fetched_at`/`new_fetched_at`
      — no `str | None` remains on these code paths.
- [ ] `documents.fetched_at` equals the source crawler timestamp after both INSERT and
      UPDATE (no `strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` or schema `DEFAULT` substitution
      remains in the write path).
- [ ] `ETagManager._update_null_fill()` no longer exists in the codebase (`rg` returns zero
      matches).
- [ ] No application path omits or synthesizes `fetched_at` (the `Ingester._insert_document()`
      column-omitting branch is removed).
- [ ] An update with an older incoming `fetched_at` does not overwrite newer stored metadata
      (stale-update prevention preserved).
- [ ] An update with a newer incoming `fetched_at` updates `documents.fetched_at` even when
      `etag` and `last_modified` are both `null`.
- [ ] Malformed or timezone-naive timestamps raise before reaching update SQL (no fail-open
      `return False` on `ValueError` remains in `_is_stale_update()`).
- [ ] `fetched_at = COALESCE(?, fetched_at)` no longer appears in `etag_manager.py`.
- [ ] The equal-timestamp case has a defined, tested behavior.
- [ ] All affected tests pass.

  (expect raise) for both the incoming and the stored value.

  INSERT without it.
- Update/add unit tests for `SQLiteDocumentStore.doc_upsert()` asserting the supplied
  `fetched_at` (not database "now") lands in `documents.fetched_at` for both insert and

  JSON carry the identical `fetched_at` value read from the crawl payload.
