## Background
The embedding backend has moved to a Qwen3 raw-text embedding model, but several code paths still carry over E5-era conventions:
- E5 required `"passage: "` / `"query: "` text prefixes to distinguish document vs. query embeddings; Qwen3 does not use this convention and expects raw text.
- E5-era code also hard-validated a fixed output dimension (384) and treated any mismatch as an error/retry condition.
- `config/ingester.toml` currently sets `embed_url` to a URL that already includes the `/embedding` path suffix, while `build_embed_url()` (`scripts/shared/llm_client.py`) unconditionally appends `/embedding` to whatever base URL it is given.

This is unrelated to the embedding-response dimension-mismatch validation being removed here and must NOT be touched — only the *validation-on-fetch* use of dimension (in `EmbeddingClientConfig.embed_dim` / `_fetch_embedding()` / `DIMENSION_MISMATCH`) is in scope.

## Problem
Multiple embedding call sites format outgoing text with E5-specific prefixes (`passage:`, `query:`) and enforce a hardcoded expected-dimension check with retry-on-mismatch logic. Under the Qwen3 raw-text contract these prefixes corrupt the input text sent to the embedding model, and the dimension-mismatch handling is dead weight now that the output dimension is fixed by a code constant rather than something that needs runtime verification. Separately, `config/ingester.toml`'s `embed_url` already includes `/embedding`, which combined with `build_embed_url()` always appending `/embedding` produces a broken, double-suffixed URL for RAG ingestion.

## Reason for change
The embedding backend now serves Qwen3, which does not use E5's prefix convention; sending `passage:`/`query:` prefixes would alter model input and likely degrade embedding quality/correctness for both RAG ingestion/query and the agent memory subsystem. The dimension-mismatch retry logic adds complexity/latency (sleep-and-retry loops) that no longer serves a purpose once the dimension is fixed by contract, and the ingester's URL misconfiguration is an active bug that will cause every RAG ingestion embedding call to fail once combined with a correctly-implemented `build_embed_url()` call (which is already in place today).

## Implementation intent
Establish one uniform embedding request contract across the codebase: send raw text with no prefix, resolve the endpoint by appending `/embedding` to a base URL via the existing `build_embed_url()` helper only (never store the suffix in config), and drop all dimension-mismatch detection/retry code paths since the dimension is now a fixed code constant. Reduce initial RAG ingestion concurrency to a single worker as a conservative default for the new backend. Update the three affected config files only where their current values violate the "base URL, no `/embedding` suffix" rule.

## Acceptance criteria
- No embedding HTTP request body anywhere in the codebase includes a `"query: "` prefix.
- No embedding HTTP request body anywhere in the codebase includes a `"passage: "` prefix.
- `EmbeddingClientConfig` no longer has a `query_prefix` field.
- `EmbeddingClientConfig` no longer has an `embed_dim` field, and no call site (including `scripts/agent/factory.py::_build_embedding_client`) passes `embed_dim=` to it.
- `RagIngester` no longer has an `_expected_dims` attribute, no longer reads `cfg.get("embedding_dims", ...)`, and `_get_embedding()` no longer raises/retries on an embedding-length mismatch.
- `scripts/agent/memory/embedding_client.py::_fetch_embedding()` no longer performs dimension-mismatch detection.
- `EmbeddingErrorKind.DIMENSION_MISMATCH` is removed from `scripts/agent/memory/types.py`, with no remaining references anywhere in `scripts/` or `tests/`.
- `config/ingester.toml`'s `embed_url` is a base URL with no `/embedding` suffix.
- `config/ingester.toml`'s `embed_workers` is `1`.
- `config/agent.toml` and `config/rag_pipeline_mcp_server.toml` continue to use base URLs for `embed_url` (no regression).
- For every embedding call path (RAG ingestion, RAG query, agent memory), the final URL passed to the HTTP client resolves to exactly one `/embedding` suffix (verified via `build_embed_url()` usage, not a literal suffix baked into config).
- The codebase type-checks and lints cleanly after the change (no leftover unused imports/parameters from the removed fields/logic).
