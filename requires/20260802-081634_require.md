# Resolve undefined "area dependency graph" reference in the Documentation Governance Change Impact Rule

## Priority
Medium

## Target files
- `docs/00_governance_01_documentation-governance.md` (§Change Impact Rule)
- `docs/00_governance_07_needs-confirmation-inventory.md` (new NC entry, if the graph does not exist)

## Background
`docs/00_governance_01_documentation-governance.md` §Change Impact Rule instructs implementers to
"map the change to affected areas using the area dependency graph" as step 2 of a 4-step
procedure for determining which documents are affected by a change. No file path, section
reference, or other locator for this "area dependency graph" is given anywhere in the document,
or anywhere else in the repository.

A repository-wide search (`grep -ril "area dependency graph\|dependency graph\|area-dependency\|dependency_graph\|area_dependency"` across `.md`, `.py`, `.json`, `.yaml`/`.yml` files) confirms:
- No artifact named or resembling an "area dependency graph" exists anywhere in the repo.
- The only other "dependency graph" mentions found are unrelated: `pydeps`-based *module* dependency
  graphing in `skills/require-to-plan/workflow.md` / `SKILL.md`, a circular-import fix in
  `requires/done/20260711_01_require.md`, an out-of-scope mention in
  `requires/done/20260714_15_require.md`, and code-level dependency graphs in
  `plans/done/20260618-065848_plan.md` and `implementations/done/20260712-104531_implementation_procedure.md`.
  None of these define an "area"-level (i.e., Overview/Deployment/RAG/MCP/Agent/EventBus/Shared-DB/Governance)
  dependency graph.
- `docs/00_index.md` and `docs/01_overview.md` contain no dependency map between the eight
  documented areas either.
- The gap was previously identified informally in the root-level review file
  `docs_review_governance.md` (§4 強化候補, §6 Needs confirmation item), but that file is not part
  of the canonical `docs/` governance set, and the gap has **not** been added to
  `docs/00_governance_07_needs-confirmation-inventory.md` — the NC inventory currently runs
  NC-001 through NC-017, none of which cover this topic.

## Problem
The Change Impact Rule directs implementers to consult an artifact ("area dependency graph")
that does not exist and has no defined location. Anyone attempting to follow the rule as written
cannot complete step 2 of the procedure, making the rule unusable as documented. The gap is also
not tracked anywhere in the project's own Needs-Confirmation mechanism, so it is invisible to
anyone who does not happen to read the external review file.

## Reason for change
Governance documents are the highest-priority document class per the Review Rule (any change to
Governance-class documents requires review), so an unusable or misleading procedure in a
Governance document carries outsized risk: implementers may silently skip the impact-mapping step,
undermining the entire Change Impact Rule and any changes proposed under this project's own docs
governance model.

## Implementation intent
Since no "area dependency graph" artifact exists and none is being created as part of this work,
resolve the dangling reference by (a) formally registering the gap as a Needs Confirmation item in
`docs/00_governance_07_needs-confirmation-inventory.md` following that document's existing 15-field
entry format (next sequential ID, i.e. NC-018), and (b) updating the Change Impact Rule text in
`docs/00_governance_01_documentation-governance.md` so it no longer implies the graph exists without
qualification — e.g., by referencing the new NC entry inline or noting that step 2 is currently
unformalized pending that entry's resolution. Do not invent or construct the area dependency graph
itself.

## Implementation instructions
1. In `docs/00_governance_07_needs-confirmation-inventory.md`, add a new entry `NC-018` under
   "Inventory Items", using the existing per-entry field set (ID, Source File, Section, Line
   Number, Question, Evidence, Impact, Required Action, Status, Assigned To, Last Reviewed,
   Priority, Related NC, Resolution Target, Blocking). Populate it based on this requirement:
   - Source File: `00_governance_01_documentation-governance.md`
   - Section: §Change Impact Rule, step 2
   - Question: whether an "area dependency graph" artifact exists or is planned, and if so where
     it is located
   - Evidence: repository-wide search performed for this requirement found no such artifact
   - Status: `open`
2. In `docs/00_governance_01_documentation-governance.md`, update the Change Impact Rule's step 2
   text so it does not present the "area dependency graph" as an existing, locatable resource
   without qualification. Acceptable approaches (pick one, consistent with the document's existing
   style):
   - Add a parenthetical or footnote pointing to the new NC-018 entry (e.g., "the area dependency
     graph (see Needs Confirmation NC-018 — not yet defined/located)"), or
   - Rephrase step 2 to describe the *intent* (map the change to affected areas) without asserting
     a concrete graph artifact exists, while cross-referencing NC-018 for the gap.
   Do not remove the step's intent (mapping changes to affected areas) — only correct the
   unqualified reference to a nonexistent artifact.
3. Do not create the area dependency graph itself, and do not modify any other governance
   document beyond the two listed target files.
