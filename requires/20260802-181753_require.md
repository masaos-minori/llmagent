# Simplify docs/03_rag_02_09 shared-utilities tables; document MIN_TEXT_LENGTH_FOR_DETECTION=100 rationale as Needs Confirmation

## Priority
Medium

## Target files
- `docs/03_rag_02_09_ingestion_pipeline-shared-utilities.md`

## Background
`docs/03_rag_02_09_ingestion_pipeline-shared-utilities.md` documents `scripts/rag/utils.py`. As of this review it still contains, verbatim:
- A "関数 / シグネチャ / 戻り値 / 説明" (function/signature/return-value/description) table for `normalize_unicode`, `floats_to_blob`, `validate_url`, `cosine_sim`, `sanitize_document`, `sanitize_document_full` (lines 43-50).
- A "定数" (constants) table mixing `MIN_TEXT_LENGTH_FOR_DETECTION` with the five `LOG_KEY_*` constants (lines 52-61).
- A prompt-injection-patterns table (lines 63-71) and a structured-log-keys table (lines 73-80) — also mechanical listings.
- A "利用元" (usage source) table mapping scripts to functions they call (lines 83-92).

The originating design review (`docs_review_rag.md` §2 "削除候補", entry for this file, line 70-74) classifies these tables as pure API listings with no design value, derivable directly from the code, and recommends removing them while individually preserving design-relevant constants such as `MIN_TEXT_LENGTH_FOR_DETECTION=100`. The same review (`docs_review_rag.md` §6B "Needs confirmation", line 354-359) separately flags that this threshold's rationale (measured vs. rule-of-thumb) is undocumented and recommends confirming and recording it.

## Problem
1. The doc contains multiple verbatim, mechanically-derivable API-listing tables that add maintenance burden (they drift from code, as seen in commit `6cfb24c10` which had to fix similar drift elsewhere in the RAG docs) without adding design insight.
2. `MIN_TEXT_LENGTH_FOR_DETECTION = 100` (in `scripts/rag/utils.py`, consumed by `detect_lang()` in `scripts/rag/ingestion/crawler_utils.py` and referenced in `scripts/rag/ingestion/crawler.py`) has no documented rationale for why 100 characters was chosen. If a language-misdetection incident occurs, there is no recorded basis for judging whether the threshold should change.

## Reason for change
- Verbatim API tables are mechanical, code-derivable content that should not live in design documentation — this class of content has already caused doc/code drift elsewhere in the RAG docs (see commit `6cfb24c10`, "feat: add RAG docs consistency checker and fix confirmed drift").
- The undocumented threshold rationale is an identified risk: without it, a future misdetection investigation has no way to evaluate whether 100 is well-founded or arbitrary.

## Implementation intent
- Remove the mechanical/verbatim tables from `docs/03_rag_02_09_ingestion_pipeline-shared-utilities.md`: the function/signature/return-value/description table, the constants table containing `LOG_KEY_*`, the prompt-injection-patterns table, the structured-log-keys table, and the usage-source table. Retain a brief prose summary of what the module provides (already present in the surrounding text/import block) so the reader still knows what utilities exist and where to look (source code / Reference API).
- Keep `MIN_TEXT_LENGTH_FOR_DETECTION=100` documented individually as prose (not inside the removed constants table), since it is a design-relevant threshold, not a mechanical listing item.
- Investigation performed for this requirement (git history search across `scripts/rag/utils.py`, `scripts/rag/ingestion/crawler_utils.py`, `scripts/rag/ingestion/crawler.py`, and the design-note docs) found no measurement, benchmark, or incident record backing the value 100. It was introduced in commit `16c27288b` ("refactor: eliminate magic values in scripts/ (PLR2004)") purely as an extraction of a pre-existing literal into a named constant — the commit message and surrounding docstring only restate the assumption "too short for reliable detection" without evidence of measurement. The originating design review (`docs_review_rag.md` line 354-359) independently reached the same "cannot determine" conclusion. Therefore the rationale must be documented as **Needs Confirmation** rather than invented.

## Implementation instructions
1. In `docs/03_rag_02_09_ingestion_pipeline-shared-utilities.md`, delete:
   - The "関数 / シグネチャ / 戻り値 / 説明" table (lines ~43-50 in current content).
   - The "定数" table containing `MIN_TEXT_LENGTH_FOR_DETECTION` and `LOG_KEY_*` (lines ~52-61).
   - The "プロンプトインジェクションパターン" table (lines ~63-71).
   - The "構造化ログキー" table (lines ~73-80).
   - The "利用元" table (lines ~83-92).
2. Add a short prose paragraph in place of the removed constants table that documents `MIN_TEXT_LENGTH_FOR_DETECTION = 100` individually, stating:
   - What it controls (minimum text length required before `detect_lang()` in `scripts/rag/ingestion/crawler_utils.py` attempts CJK-ratio-based language detection; shorter text falls back to the hint language).
   - That its rationale is **Needs Confirmation**: no measurement, benchmark, or design note was found justifying 100 specifically; it originates from a pre-existing literal formalized into a named constant during a magic-value-elimination refactor (commit `16c27288b`), with no accompanying evidence of empirical tuning.
3. Keep any other genuinely design-relevant prose (e.g., the module's role, the `sanitize_document` prompt-injection-defense rationale in the surrounding text) — only the mechanical tables listed above are in scope for removal.

5. Do not modify `scripts/rag/utils.py`, `scripts/rag/ingestion/crawler_utils.py`, `scripts/rag/ingestion/crawler.py`, or the threshold value itself — this requirement is documentation-only.
