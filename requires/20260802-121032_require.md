# Simplify the deploy.sh copy-operation bullet list in docs/02_deployment-part1.md §2.2

## Priority
Low

## Target files
- `docs/02_deployment-part1.md` (§2.2 "Deploying scripts", the "deploy.sh does:" bullet list —
  currently at approximately lines 85-90, immediately after the `bash deploy/deploy.sh` code block)

## Background
`docs/02_deployment-part1.md` §2.2 describes what `deploy/deploy.sh` does when deploying
scripts, config, and schema files to `/opt/llm/`. Immediately under the "deploy.sh does:"
heading it verbatim-transcribes a subset of the script's copy/mkdir operations as a bullet
list:

```
deploy.sh does:
- Copies Python scripts to `/opt/llm/scripts/` (includes `eventbus/` package)
- Copies config files to `/opt/llm/config/` (includes `eventbus.toml`)
- Copies JSON Schema to `/opt/llm/schemas/` (includes `event_envelope.json`)
- Creates `/opt/llm/logs/`, `/opt/llm/rag-src/chunk/`, `/opt/llm/rag-src/registered/`
- Creates `/opt/llm/storage/`, `/opt/llm/offsets/`, `/opt/llm/deadletter/` (Event Bus)
```

This is mechanical content directly derivable from reading `deploy/deploy.sh`, which
already documents its own copy operations via section-header comments (e.g.
`# ── Python スクリプト (パッケージ構造ごと同期) ──`, `# ── 設定ファイル ──`,
`# ── Event Bus スキーマ配置 ──`) and `echo` banners for each step.

## Problem
The bullet list duplicates script detail in the doc, and this duplication has already
gone stale: `deploy.sh` also copies `pyproject.toml`, `uv.lock`, `tests/`, and
`start_agent.sh`, and creates `/opt/llm/memory` and `/opt/llm/db` — none of which appear
in the doc's bullet list. Every time `deploy.sh`'s copy targets change, this list must be
kept in sync by hand or it silently drifts further out of date, while providing no
design-intent value beyond what the script's own comments already convey.

## Reason for change
Removing the duplicated, drift-prone bullet list and replacing it with a one-sentence
statement of intent reduces the doc's maintenance burden and eliminates a second source
of truth that can disagree with the actual script. The script's own comments remain the
single authoritative reference for exact copy-target detail.

## Implementation intent
Compress the "deploy.sh does:" bullet list into a single summary sentence that states the
script's intent (it copies the runtime artifacts needed for production operation —
dependency definitions, scripts, config, and schemas — into `/opt/llm/`, and creates the
required directory structure), and explicitly defer exact copy-target detail to
`deploy/deploy.sh`'s own comments as the source of truth. Do not attempt to make the
bullet list exhaustive/accurate instead — the point is to stop duplicating this detail in
the doc at all.

## Implementation instructions
1. In `docs/02_deployment-part1.md` §2.2, locate the "deploy.sh does:" heading and its
   five bullet points (currently ~lines 85-90, directly below the
   ` ```bash / bash deploy/deploy.sh / ``` ` code block and above the "**Workflow artifact
   responsibilities (deploy.sh):**" subsection).
2. Replace the "deploy.sh does:" heading and its bullet list with a single sentence
   equivalent to: "deploy.sh は本番稼働に必要なランタイム成果物(依存定義・スクリプト・設定・
   スキーマ)を `/opt/llm/` 配下にコピーし、必要なディレクトリ構成を作成する。詳細な対応関係は
   `deploy/deploy.sh` のコメントを正とする。" (or an equivalent English sentence if the
   surrounding section's language convention calls for English — check the existing
   language of §2.2's surrounding prose before choosing).
3. Do not alter the "**Workflow artifact responsibilities (deploy.sh):**" subsection or
   anything below it in §2.2 — this requirement is scoped only to the "deploy.sh does:"
   bullet list.
4. Do not modify `deploy/deploy.sh` itself in this change — its copy logic and comments
   are out of scope; they are only the reference the doc now defers to.

## Acceptance criteria

  the one-sentence summary; no per-target copy detail (source path -> destination path)

- The "**Workflow artifact responsibilities (deploy.sh):**" subsection and the rest of
  §2.2 are unchanged.
- `deploy/deploy.sh` is not modified.
