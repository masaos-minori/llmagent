# Remove verbatim Pydantic model/dataclass field transcription in docs/04_mcp_02_01

## Priority
Low

## Target files
- `docs/04_mcp_02_01_endpoints-and-transport.md`

## Background
`docs/04_mcp_02_01_endpoints-and-transport.md` documents the shared MCP HTTP
protocol (endpoints, transport, correlation keys, health behavior). Two
sections in the current file transcribe code definitions verbatim into prose:

- `## Pydantic モデル（mcp_servers/models.py）` (lines 76-89): a fenced code
  block reproducing `CallToolRequest` and `CallToolResponse` field-by-field.
- `## MCPServer 基底クラス（mcp_servers/server.py）` → `### データクラス` (lines
  134-139): a table transcribing `TruncationResult`'s fields one-for-one.

## Problem
Verified against current source (`scripts/mcp_servers/models.py`,
`scripts/mcp_servers/server.py`):

- The doc's `CallToolRequest`/`CallToolResponse` code block is already stale.
  Actual source uses `Field(..., description=...)` annotations,
  `dict[str, Any] = Field(default_factory=dict, ...)` (not `dict = {}` as
  shown in the doc), a `field_validator` on `name` that rejects blank values,
  and a `validate_args()` method — none of which appear in the doc's
  transcription.
- The `TruncationResult` dataclass table duplicates field names/types that
  are visible by opening `scripts/mcp_servers/server.py` directly.
- This is a documentation-fix case per `rules/coding.md` §"Documentation
  notes": the transcribed content is stale/incomplete relative to source,
  and code-derived detail duplicated in docs is guaranteed to drift again as
  fields change.

## Reason for change
Type definitions are code-derived detail; the source file is the
authoritative definition. Duplicating it in docs costs maintenance (must be
kept in sync on every field change) without adding design information, and
the current transcription is already out of sync with the code it claims to
describe.

## Implementation intent
Replace the verbatim model/dataclass transcriptions with a reference to the
class name and source file path only (no field lists, no code blocks copied
from source). Preserve every piece of design-intent content in the same
sections that is not recoverable by simply reading the class definition:
the correlation-key table, and the `health()` fixed `deps={}` behavior note
(including which servers use `make_health_response()` vs. a custom
implementation).

## Implementation instructions
1. Read `docs/04_mcp_02_01_endpoints-and-transport.md` in full before editing.
2. In the `## Pydantic モデル（mcp_servers/models.py）` section: remove the
   fenced Python code block (lines ~78-86). Replace it with a short prose
   reference stating that `CallToolRequest` and `CallToolResponse` are
   defined in `scripts/mcp_servers/models.py` and are shared across all MCP
   servers (keep the one-line "全 MCP サーバー間で共有される..." sentence or
   equivalent design-relevant statement).
3. In the `### データクラス` sub-section under `## MCPServer 基底クラス`:
   remove the field-listing table row for `TruncationResult`'s fields.
   Replace with a prose reference to `TruncationResult` in
   `scripts/mcp_servers/server.py`, keeping only the purpose statement
   ("メタデータ付き切り詰めメソッドの返り値") without re-listing field
   names/types.
4. Do NOT remove or alter:
   - `### 相関キー` (correlation-key) table.
   - The `health()` method row and its accompanying paragraph describing the

5. Do not modify `scripts/mcp_servers/models.py`, `scripts/mcp_servers/server.py`,
   or any other source file — this is a documentation-only change.
6. Do not modify any other `docs/*.md` file as part of this change.
