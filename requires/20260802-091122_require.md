## Background
`docs/01_overview-files-03-scripts-part2.md` documents the deploy-target directory structure of `scripts/agent/`. The `commands/` subtree portion of that structure is a manually maintained file-by-file enumeration that has drifted from the actual source tree. It was flagged by a documentation audit (`docs_review_overview_architecture.md` §2 削除候補 item 1, §5 例3, §6A) as containing confirmed factual errors, not merely speculative staleness.

## Problem
The current doc text (lines ~27-63) enumerates files under `commands/` and makes claims that are factually wrong against current source:

1. Lists three files that do not exist in `scripts/agent/commands/`: `db_help_display.py`, `db_stats_display.py`, `db_rag_ops.py`. Only stale `.pyc` remnants remain in `scripts/agent/commands/__pycache__/` (`db_help_display.cpython-314.pyc`, `db_stats_display.cpython-314.pyc`, `db_rag_ops.cpython-314.pyc`); the `.py` sources are gone. Git history confirms real removal, not relocation:
   - `db_help_display.py` and `db_stats_display.py` removed in commit `12f8e8c94` ("Normalize config schema: remove deprecated Memory and GitOps security keys").
   - `db_rag_ops.py` removed in commit `846dc93bd` ("feat: remove dead RAG pipeline settings from Agent config and unused /db rag /rag commands").
   - No `/db` command or `_cmd_db` handler exists anywhere in `scripts/agent/commands/` today (verified via grep) — the associated `/db` functionality was fully removed, not moved elsewhere.
2. `registry.py`'s doc comment claims "15 mixins"; the actual current count is **12**.
3. Documents `/tool`, `/rag`, `/export` as existing slash commands. None of these exist in the current single source of truth for commands, `scripts/agent/commands/command_defs_list.py`. `/rag` was explicitly removed in commit `846dc93bd` alongside `db_rag_ops.py`.

Readers or AI agents relying on this file will search for nonexistent files/commands, wasting effort or misdiagnosing issues.

## Reason for change
These are confirmed factual errors verified against current source and git history (see Verified current facts below), not speculative or debatable staleness. The doc actively misleads about both the file layout and the available command surface.

## Implementation intent
Remove the manually-maintained, file-by-file `commands/` enumeration and replace it with a short prose description that states the design intent (responsibility-split via mixin classes for `/help`, `/config`, `/stats`, etc.) plus a pointer telling readers to consult `scripts/agent/commands/` directly for the exact, current file list and command set. Do not replace the removed items with a new, equally detailed enumeration — the goal is to stop hand-maintaining a list that goes stale, not to produce a corrected but still-brittle list.
