# Simplify docs/03_rag_02_02_ingestion_pipeline-crawler-part1.md: drop verbatim method/utility tables, dedupe config-parameter table against 05_1

## Priority
Medium

## Target files
- `docs/03_rag_02_02_ingestion_pipeline-crawler-part1.md` (only file to be modified)
- Reference only (do not modify): `docs/03_rag_05_1-configuration-reference.md`, `scripts/rag/ingestion/crawler.py`, `config/crawler.toml`

## Background
`docs/03_rag_02_02_ingestion_pipeline-crawler-part1.md` documents the `WebCrawler` class
(`scripts/rag/ingestion/crawler.py`). Section 2.1 currently contains two mechanical,
code-derived tables ("公開メソッド" / public methods, and "モジュールレベルのユーティリティ" /
module-level utilities) that are verbatim signature listings with no unique design
value beyond what the source code already shows. Section 2.1.1 contains a 9-item
configuration-parameter table (`crawl_delay`, `max_depth`, `min_chunk`, `fetch_retry`,
`fetch_timeout`, `crawl_concurrency`, `max_pages`, `skip_nofollow`, `skip_external`)
that duplicates entries already present in the canonical configuration reference,
`docs/03_rag_05_1-configuration-reference.md` §1.1 (`config/crawler.toml`, 12 items).

## Problem
1. The public-methods and module-level-utility tables add maintenance burden (must be
   kept in sync with source signatures) without adding design-level insight not already
   visible in the code itself.
2. The 9-item configuration table duplicates `05_1`'s `crawler.toml` table, doubling the
   maintenance surface for any future config change.
3. Neither the current part1 table nor `05_1`'s table distinguishes a parameter's
   in-code fallback default (used via `dict.get(key, fallback)` when the key is absent
   from the TOML file) from its actual operational value as currently set in
   `config/crawler.toml`. For two of the module's most behavior-relevant parameters,
   these values differ, and a reader citing the table's single "デフォルト" value would
   get the wrong number for the running system:
   - `max_pages`: code fallback (`cfg.get("max_pages", 500)`) is **500**; operational
     value in `config/crawler.toml` is **200**.
   - `skip_nofollow`: code fallback (`cfg.get("skip_nofollow", False)`) is **False**;
     operational value in `config/crawler.toml` is **true**.
   - `max_depth`: read via `cfg["max_depth"]` (required key, no code fallback);
     operational value in `config/crawler.toml` is **3**. This one has no
     code/operational split to state — only that no fallback exists — and is already
     noted correctly by the doc's current text.

## Reason for change
This is part of a broader documentation-review effort (source: `docs_review_rag.md`
§2 removal candidates item 1, §3 summarization candidates item 3) targeting
code-derived, duplicative, or ambiguous-value tables across the `docs/03_rag_*` set.
Removing the method/utility tables reduces upkeep cost with no information loss (the
source file remains the authority for signatures). Fixing the config-table
duplication and the missing code-fallback-vs-operational distinction directly
addresses a documented risk of readers citing stale or wrong parameter values for
`max_pages` and `skip_nofollow`.

## Implementation intent
- Remove the "公開メソッド" (public methods) and "モジュールレベルのユーティリティ"
  (module-level utility) tables from §2.1 in their entirety.
- Keep the existing one-line BFS-strategy / concurrency-control design summary
  currently in the "クラス概要" prose (the paragraph describing BFS crawl to
  `max_depth`, condition-GET, local-file handling, and `asyncio.Semaphore`
  concurrency control) — do not remove or shorten this summary.
- Keep the `CrawlPayload` TypedDict table as-is; it is not in scope for this issue.
- Reduce the §2.1.1 configuration-parameter table from 9 rows to exactly 3 rows:
  `max_depth`, `max_pages`, `skip_nofollow` — the parameters directly relevant to
  understanding this module's crawl-scope/BFS-termination responsibility.
- For each of the 3 retained rows, explicitly present both the in-code fallback value
  (or "no fallback — required key" where applicable) and the current operational
  value from `config/crawler.toml`, so the two are never collapsed into one ambiguous
  "デフォルト" column.
- Add an explicit pointer from §2.1.1 to `docs/03_rag_05_1-configuration-reference.md`
  §1.1 for the full `crawler.toml` parameter list (the other 6 removed rows:
  `crawl_delay`, `min_chunk`, `fetch_retry`, `fetch_timeout`, `crawl_concurrency`,
  `skip_external`, plus the parameters `05_1` covers that part1 never listed:
  `rag_src_dir`, `rag_db_path`, `sqlite_timeout`, `sqlite_busy_timeout_ms`,
  `target_urls`).
