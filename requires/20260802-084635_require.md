# Fix confirmed "11 サーバ" server-count error in docs/01_overview-arch-01-process.md and add canonical-source disclaimer

## Priority
High

## Target files
- `docs/01_overview-arch-01-process.md` (primary edit target: process-diagram caption ~line 47, service table ~lines 70-84 and its preceding text)

## Background
`docs/01_overview-arch-01-process.md` documents the agent process architecture, including an ASCII process diagram and a service/port table. The diagram caption at line 47 currently reads:

```
MCP サーバ群 (http)
11 サーバ (:8004〜:8014)
```

Verification against the current `config/agent.toml` shows this "11 サーバ" count is factually wrong and has been wrong for some time (confirmed by an earlier issue and `docs_review_overview_architecture.md`).

## Problem
- `config/agent.toml`'s `[mcp_servers.*]` sections currently define exactly **10** MCP servers: `shell` (8009), `git` (8014), `web_search` (8004), `file_delete` (8008), `file_write` (8007), `file_read` (8005), `github` (8006), `cicd` (8012), `rag_pipeline` (8010), `mdq` (8013). Port `8011` is not assigned to any `[mcp_servers.*]` block (verified via `grep -c '^\[mcp_servers\.'` = 10 and a full port listing).
- The line-47 caption's "11 サーバ (:8004〜:8014)" phrasing implies 11 servers spanning ports 8004 through 8014 inclusive (11 port numbers in that range), but only 10 of those 11 port slots are actually populated — port 8011 is skipped. This is a confirmed count/range error.
- The service table at lines 70-84 is, by contrast, already internally correct: it lists exactly 10 MCP-server rows (ports 8004-8010, 8012-8014, skipping 8011) plus a separately-labeled `eventbus` row (port 8015, explicitly noted as "MCP サーバ群とは別プロセス"). So the error is isolated to the line-47 caption text, which contradicts the file's own table.
- Port `8011`'s status was previously ambiguous from this file alone. Verified via git history: `8011` was assigned to a `sqlite-mcp` server. Commit `bf57d00eb` ("chore: remove mcp.sqlite from test and config after feature deletion") removed the `[mcp_servers.sqlite]` section from `config/agent.toml`, its entry from `tests/test_mcp_tools_validation.py`, and its documentation from `docs/04_mcp_06_configuration_and_operations.md` — i.e., the sqlite-mcp *feature was deleted*, not merely disabled. `rules/env.md` (line 29) currently states "8011, 8016 は未使用" (unused) as the canonical port-registry note, consistent with this. Port 8011 is therefore **fully retired**, not reserved for future use.

## Reason for change
Model names and port numbers are inherently volatile; `config/agent.toml` (and `rules/env.md`'s port-registry note) is the operational source of truth. Hardcoding a specific server count in prose has already drifted from reality once and produced a confirmed, self-contradicting error within the same file. Leaving port 8011's status implicit risks operators wasting troubleshooting effort suspecting a missing/crashed service on that port.

## Implementation intent
- Remove the hardcoded, driftable count/range claim from the line-47 diagram caption and replace it with wording that defers to `config/agent.toml` as the canonical source for the exact count and port mapping (do not invent a new fixed number — describe the servers as configuration-driven).
- Add a short disclaimer note immediately preceding (or as a header note on) the service table at lines 70-84 stating that the table is a representative/example configuration and that `config/agent.toml`'s `[mcp_servers.*]` sections are authoritative for the exact current count and port assignments.
- Explicitly state, near the table or in the port-related implementation note (~lines 86-88), that port 8011 is retired: it was previously assigned to a now-deleted `sqlite-mcp` server (removed in commit `bf57d00eb`) and is not reserved for future reassignment as far as current documentation/config indicates. Do not mark this as "Needs Confirmation" — the git history and `rules/env.md` provide sufficient evidence to state it as fact.
- This change is documentation wording only; do not alter `config/agent.toml`, and do not attempt the separate consolidation of the port table into `docs/01_overview-files-05-config.md` (that is tracked by a related, separate issue/requirement).
