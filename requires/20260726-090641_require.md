# Per-turn tool result limit hint lacks size information for the LLM

## Priority

Medium

## Target Files

- `scripts/agent/tool_runner.py` — `_apply_turn_char_limit()` (lines 231-245) and its caller `_collect_tool_result_msgs` (call site at line 187)
- `scripts/agent/tool_result_formatter.py` — `TURN_LIMIT_HINT` constant (line 13)

## Background

When a tool result's contribution to the running per-turn character budget exceeds the configured limit, `_apply_turn_char_limit()` in `scripts/agent/tool_runner.py` discards the actual tool result text and replaces it with a fixed hint string, `TURN_LIMIT_HINT`, defined in `scripts/agent/tool_result_formatter.py`.

## Problem

`TURN_LIMIT_HINT` is currently a static string with no interpolated values:

```python
TURN_LIMIT_HINT = "[Result omitted: per-turn tool result limit reached.]"
```

Inside `_apply_turn_char_limit()`, the values needed to describe the omitted result's size are already computed and used only for internal logging:

```python
def _apply_turn_char_limit(
    llm_text: str,
    turn_chars: int,
    limit: int,
) -> str:
    """Apply per-turn char limit; return hint if exceeded."""
    if limit > 0 and (turn_chars + len(llm_text)) > limit:
        logger.info(
            "Per-turn tool result limit reached: %s chars > %s; result replaced with hint",
            turn_chars + len(llm_text),
            limit,
        )
        hint: str = TURN_LIMIT_HINT
        return hint
    return llm_text
```

`turn_chars`, `len(llm_text)`, and `limit` are all available at this point (and `llm_text` itself, so line counts are derivable via `llm_text.splitlines()`), but none of this information reaches the returned `hint`. The LLM only sees the generic sentence and has no way to gauge how much content was omitted, whether it was likely truncated mid-structure, or how far over budget the result was. The sole call site, `_collect_tool_result_msgs` (tool_runner.py line 187), has access to the same values and could pass them through if the hint were made dynamic.

## Reason for Change

When the LLM cannot see the actual tool result content, a static "result omitted" message gives it no basis for deciding what to do next — e.g., whether to retry with a narrower query, request a summary, or move on. Surfacing the omitted result's size (character count and/or line count) and the configured limit gives the LLM concrete signal to reason about how much was cut and to choose an appropriate next action (such as asking for a more targeted result or paginating).

## Implementation Intent

Make the turn-limit hint dynamic: include the actual size of the omitted result (characters and/or lines) and the configured limit in the text returned to the LLM, instead of a fixed generic string. Keep the change scoped to the hint-construction path; do not alter the limit-detection logic itself.

## Implementation Instructions

1. Change `TURN_LIMIT_HINT` in `scripts/agent/tool_result_formatter.py` from a fixed string into a format string or a small function that accepts the omitted result's character count (and optionally line count) and the configured limit, and renders a hint that reports these values to the LLM.
2. Update `_apply_turn_char_limit()` in `scripts/agent/tool_runner.py` to compute the values needed for the dynamic hint (e.g., `len(llm_text)`, a line count from `llm_text.splitlines()`, `turn_chars`, `limit`) and pass them into the updated hint constructor instead of returning the static `TURN_LIMIT_HINT` unchanged.
3. Preserve the existing `logger.info(...)` call and its current log message (or update it consistently if the new hint text duplicates the same values), so internal diagnostics remain intact.
4. Keep the hint concise — it should state the omission occurred and give the size signal, without dumping the omitted content itself (that would defeat the purpose of the limit).
5. Check for any other place in the codebase that references `TURN_LIMIT_HINT` as a plain string constant (e.g., in tests) and update those usages to match the new signature/shape.

## Acceptance Criteria

- [ ] When a tool result is replaced due to the per-turn char limit, the hint text returned to the LLM includes the actual size of the omitted result (character count and/or line count) and the configured limit, not just a generic sentence.
- [ ] `_apply_turn_char_limit()` still correctly triggers replacement under the same condition (`turn_chars + len(llm_text) > limit`) as before; only the content of the replacement text changes.
- [ ] Existing internal logging behavior (`logger.info` call) is preserved or consistently updated.
- [ ] No other behavior of `_collect_tool_result_msgs` or the turn budget accounting changes.
