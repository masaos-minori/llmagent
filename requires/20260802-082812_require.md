# Add explicit Evidence Label to Deprecated Document References entries in docs/00_governance_05_deprecated-items.md

## Priority
Low

## Target files
- docs/00_governance_05_deprecated-items.md (section: "Deprecated Document References", currently lines 55-61)

## Background
`docs/00_governance_03_evidence-labels.md` defines seven evidence labels (Explicit in code, Strongly implied by code, Documentation only, Needs confirmation, Deprecated, Verified by test, Operationally observed) used across the design documentation set to indicate confidence/grounding for each statement. `docs/00_governance_05_deprecated-items.md` itself instructs, under "How to Refer to Deprecated Items", to "Always mark deprecated items with the 'Deprecated' evidence label." The "Deprecated Configuration Files" section in the same document already follows this convention: each entry (e.g. `config/rag_pipeline.toml`, `common.toml`) carries an explicit `Evidence:` line citing specific source/doc locations.

## Problem
The "Deprecated Document References" section of `docs/00_governance_05_deprecated-items.md` does not follow this convention. Its two entries:
- `diagnostics.jsonl` — No longer written; session diagnostics stored in memory only
- `Old direct execution fallback explanations` — Removed; WorkflowEngine is now required

carry no `Evidence:` line at all, unlike the "Deprecated Configuration Files" entries in the same document. This was verified by reading the current content of the file (as of this review) — the section still lacks Evidence Label annotations.

## Reason for change
Omitting the label breaks internal consistency with the evidence-labeling system that the rest of the governance document set relies on (and that this same document tells readers to follow), making it harder to gauge confidence in each deprecated-item entry at a glance. Bringing this section in line with the "Deprecated Configuration Files" section's existing style closes that gap.

## Implementation intent
Add an explicit "Evidence: Deprecated(...)" annotation line to each entry in the "Deprecated Document References" section, following the same style already used in "Deprecated Configuration Files" (label + parenthetical detail, optionally naming a successor/replacement or confirming basis). Do not change the "keep for reference, don't delete" policy, do not alter the two entries' descriptive text/meaning, and do not touch the separate "Needs confirmation"-formatted items elsewhere in this file (out of scope, tracked by a different issue/requirement).

## Implementation instructions
1. In `docs/00_governance_05_deprecated-items.md`, under "## Deprecated Document References", add one `Evidence:` line to each of the two existing bullet entries:
   - For `diagnostics.jsonl`, add a line such as: `Evidence: Deprecated(廃止確認済み、後継: 該当なし — セッション診断はメモリのみで保持)` or an equivalent English/Japanese phrasing consistent with the doc's existing language, citing the successor mechanism ("memory only") since there is no successor file.
   - For `Old direct execution fallback explanations`, add a line such as: `Evidence: Deprecated(廃止確認済み、後継: WorkflowEngine 必須化)`, citing WorkflowEngine as the reason/replacement per the existing description.
2. Match the existing bullet sub-item formatting used in "Deprecated Configuration Files" (e.g. an indented sub-bullet under each item, parallel to how "Current Replacement", "Status", "Notes", "Evidence" sub-fields are structured there) so the section reads consistently with the rest of the document. Exact field set (e.g. whether to also add "Current Replacement"/"Status"/"Notes" sub-fields) is left to the implementer's judgment as long as an explicit `Evidence:` label is present and the existing "keep, don't delete" policy and descriptive meaning of each entry are preserved.
3. Do not modify the "Deprecated Concepts" or "Deprecated Commands" sections, and do not modify the "Needs Confirmation" related content elsewhere in the file — those are out of scope for this requirement.

## Acceptance criteria
- Every entry under "Deprecated Document References" in `docs/00_governance_05_deprecated-items.md` carries an explicit Evidence Label line consistent with the labeling scheme defined in `docs/00_governance_03_evidence-labels.md` (using the "Deprecated" label).
- The "keep for reference, don't delete" policy and the existing descriptive text of each entry remain unchanged in meaning.
- No other section of `docs/00_governance_05_deprecated-items.md` is modified as part of this change.

## Tests
Not applicable — this is a documentation-only change. No automated tests are required. Verification is by manual review of the updated document against `docs/00_governance_03_evidence-labels.md`'s labeling scheme.
