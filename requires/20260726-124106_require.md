# Mask secrets in subprocess error logs

## Priority

Medium

## Target Files

- `scripts/agent/http_lifecycle.py:274-279` — stderr log capture and output
- `scripts/agent/startup.py:156-166` — Error log output

## Background

Subprocess stderr is logged up to 500 characters when an MCP server exits early. If the MCP server outputs error messages containing secrets (e.g., authentication tokens), those secrets would be written to log files.

## Problem

```python
logger.error(
    "Lifecycle: %r exited early; stderr (%s chars): %s",
    server_key,
    len(stderr_full),
    stderr_full[:500],
)
```

No secret masking on logged stderr content.

## Reason for Change

Prevent potential secret leakage through subprocess error logs.

## Implementation Intent

Add a secret masking function that redacts common secret patterns before logging.

## Implementation Instructions

1. Create a `_mask_secrets(text: str) -> str` function that uses regex to mask common secret patterns:
   ```python
   import re
   
   SECRET_PATTERNS = [
       r'(?i)(?:api[_-]?key|token|secret|password)\s*[:=]\s*\S+',
       r'Bearer\s+[A-Za-z0-9\-._~+/]+=*',
       r'(?:AKIA|GSK)[A-Z0-9]{16,}',
   ]
   
   def _mask_secrets(text: str) -> str:
       for pattern in SECRET_PATTERNS:
           text = re.sub(pattern, lambda m: m.group(0)[:10] + '***', text)
       return text
   ```
2. Apply `_mask_secrets()` to stderr content before logging
3. Run tests to confirm no regressions
