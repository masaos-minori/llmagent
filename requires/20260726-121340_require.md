## Background

The GitHub MCP server's business logic layer has critically low code coverage (21-47%) despite having an existing test file (`test_github_mcp_service.py`). The existing tests focus on security guard methods (_assert_allowed_repo, _assert_allowed_path, etc.) but do not cover the core service methods that interact with the GitHub API.

## Problem

```
File                          Coverage
service_file.py                21%
service_issues.py              21%
service_pull_requests.py       47%
service_repository.py          47%
server_file.py                 <50%
server_issues.py               <50%
server_pull_requests.py        <50%
server_repository.py           <50%
```

Business logic methods that handle GitHub API responses, error handling, and data transformation are untested. Fail-open scenarios could go undetected.

## Reason for Change

Low coverage means regressions in GitHub API interaction logic would not be caught by CI. Business logic errors (e.g., incorrect response parsing, missing error handling) could silently corrupt data or cause failures.

## Implementation Intent

Extend `tests/test_github_mcp_service.py` with tests for each service module's public methods:

For each `service_*.py`:
1. Success path: valid GitHub API response → correct result
2. GitHub API error path: 4xx/5xx response → proper error handling
3. Authorization failure path: unauthorized → rejection

## Implementation Instructions

1. For each service module, identify the public method(s) that need testing
2. Create test methods following the existing fixture pattern in `test_github_mcp_service.py`:
   ```python
   def _make_service(cfg=None) -> GitHubService:
       raw = cfg or {"allowed_repos": ["org/repo"]}
       return GitHubService(gh=MagicMock(), cfg=GitHubConfig.from_dict(raw))
   ```
3. Mock the GitHub API client (gh parameter) to return controlled responses
4. Test success, 4xx error, and 5xx error paths for each method
5. Run `uv run pytest tests/test_github_mcp_service.py -v --cov=mcp_servers/github --cov-report=term-missing` to verify coverage improvement
