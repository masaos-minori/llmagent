# Remove legacy E5-style query_prefix/embed_dim from EmbeddingClient and verify memory/RAG search integration

## Priority
Medium

## Target files
- `scripts/agent/memory/embedding_client.py` — `EmbeddingClientConfig` (`query_prefix`, `embed_dim` fields), `_fetch_embedding()` (prefix concatenation, dimension-mismatch branch), `EmbeddingClient.fetch()` (passes `query_prefix`/`embed_dim` through)
- `scripts/agent/memory/types.py` — `EmbeddingErrorKind.DIMENSION_MISMATCH`
- `scripts/agent/factory.py` — `_build_embedding_client()` (constructs `EmbeddingClientConfig(embed_dim=ctx.cfg.memory.memory_embed_dim, ...)`)
- `scripts/agent/memory/injection.py` — `MemoryInjectionService.on_user_prompt()` (verify only, no expected code change)
- `scripts/agent/memory/retriever.py` — `HybridRetriever.search()` / `VectorRetriever.knn_search()` (verify only)
- `scripts/agent/memory/services.py` — `MemoryServices.get_activation_mode()` (verify only)
- `scripts/rag/stages/search.py` — `_search_all_queries()` embedding-failure diagnostics (verify only)
- `tests/test_embedding_client.py` — has an explicit test for `DIMENSION_MISMATCH` (lines ~880-899) that must be updated/removed together with the code
- Related but explicitly out of scope for this requirement (see Background): `scripts/rag/llm_client.py::get_embedding()` and `scripts/rag/ingestion/ingester.py::_get_embedding()`, which still implement the old E5 `"query: "` / `"passage: "` prefix and dimension-check scheme

## Background
Issue `issues/20260731_05_issue.md` was written as a follow-up to a prior "Qwen3 embedding cleanup" effort (issues 01-04) and assumes that `query_prefix`, `embed_dim`, the dimension-mismatch diagnostic, and the `"query: "`/`"passage: "` prefixes had already been removed from the memory embedding path, and that this task was purely integration verification.

Verification against current source shows this assumption is **false**: none of that removal has happened yet.

- `scripts/agent/memory/embedding_client.py` still defines `EmbeddingClientConfig.query_prefix: str = "query: "` and `EmbeddingClientConfig.embed_dim: int = 384`, and `_fetch_embedding()` still prepends `query_prefix` to every request body (`json={"content": f"{query_prefix}{text}"}`) and still validates the returned embedding length against `embed_dim`, returning `EmbeddingErrorKind.DIMENSION_MISMATCH` on mismatch.
- `scripts/agent/memory/types.py` still defines `EmbeddingErrorKind.DIMENSION_MISMATCH`, and it is not unused — it is actively returned by `embedding_client.py` and covered by a dedicated test in `tests/test_embedding_client.py`.
- `scripts/agent/factory.py::_build_embedding_client()` still constructs `EmbeddingClientConfig(embed_dim=ctx.cfg.memory.memory_embed_dim, ...)` (no `query_prefix` override is passed explicitly, so the `"query: "` default is used unconditionally).
- On the RAG side, `scripts/rag/llm_client.py::get_embedding()` (used by `scripts/rag/stages/search.py`) and `scripts/rag/ingestion/ingester.py::_get_embedding()` both still hardcode the E5-style `"query: "` / `"passage: "` prefixes and their own dimension checks against `embedding_dims`/`_expected_dims`. These two functions are **not** listed in the issue's "Files to Inspect or Update" and are left out of this requirement's scope, but they are a real blocker to the issue's stated Fix Intent ("Qwen3 raw-text embedding contract works consistently across RAG ingestion / RAG search"). This inconsistency should be flagged to whoever plans the next phase.
- Note: a separate, unrelated `embed_dim` parameter exists in `scripts/agent/memory/store.py`, `write_ops.py`, `import_ops.py`, and `ingestion.py`, used purely to size the float-blob vector serialization for `memories_vec` storage. That usage is not part of the API-response dimension-mismatch validation and must **not** be removed by this requirement — only the validation/prefix logic inside `EmbeddingClientConfig`/`_fetch_embedding` is in scope.
- `scripts/agent/memory/injection.py`, `retriever.py`, and `services.py` already match the issue's description of the current call chain (`on_user_prompt()` → `EmbeddingClient.fetch()` → `HybridRetriever.search()`; `MemoryServices.get_activation_mode()` branches on embedding client status) and need no structural change — only confirmation they keep working once the prefix/dimension logic is removed.
- `scripts/rag/stages/search.py::_search_all_queries()` already records `embed_ok`/`embed_failed` diagnostics without a dimension-mismatch branch, matching the issue's acceptance criteria for the RAG search path.

## Problem
The memory embedding path (`EmbeddingClientConfig` and `_fetch_embedding()`) still implements the legacy E5 contract (mandatory query prefix + strict dimension validation with a dedicated error kind), not the plain Qwen3 raw-text contract the issue assumes is already in place. Because the removal never happened, there is nothing yet to "verify" in the sense the issue describes — the actual next step is to perform the removal first, then confirm the downstream memory injection/retrieval/search paths still function afterward.

## Reason for change
- The issue's stated acceptance criteria ("no memory code passes `query_prefix`", "no memory code passes `embed_dim`", "`EmbeddingErrorKind.DIMENSION_MISMATCH` is removed if unused") cannot be satisfied without first doing the removal.
- Leaving stale E5-specific configuration (`query_prefix`, `embed_dim`, `DIMENSION_MISMATCH`) in the memory embedding client is misleading for anyone reading the code and assumes a Qwen3-only embedding backend that no longer needs a prefix or strict dimension enforcement.
- Confirming the injection/retriever/services/search call chain still works after the removal closes out the actual intent of the original Qwen3 migration for the memory subsystem.

## Implementation intent
1. Remove the `query_prefix` field from `EmbeddingClientConfig` and stop prepending any prefix in `_fetch_embedding()`; send the raw query text as the request body.
2. Remove the `embed_dim` field (and its dimension-mismatch branch) from `EmbeddingClientConfig`/`_fetch_embedding()`/`EmbeddingClient.fetch()`. Keep the response-shape checks that are unrelated to dimension count (missing `embedding` field → `INVALID_RESPONSE`, HTTP/JSON/timeout error kinds).
3. Remove `EmbeddingErrorKind.DIMENSION_MISMATCH` from `scripts/agent/memory/types.py` once nothing references it.
4. Update `scripts/agent/factory.py::_build_embedding_client()` to stop passing `embed_dim=ctx.cfg.memory.memory_embed_dim` into `EmbeddingClientConfig` (leave `ctx.cfg.memory.memory_embed_dim` itself untouched — it is still needed by `MemoryStore`/`write_ops.py` for vector blob sizing, which is a separate concern).
5. After the removal, re-verify (by reading/tracing, and by running the existing test suite) that:
   - `MemoryInjectionService.on_user_prompt()` still receives a usable `EmbeddingResult` from `EmbeddingClient.fetch()`.
   - `HybridRetriever.search()` still degrades correctly to FTS-only when `embedding` is `None` and still merges via RRF when an embedding is present.
   - `MemoryServices.get_activation_mode()` still reports `disabled`/`fts-only`/`degraded`/`hybrid` correctly based on `EmbeddingClientStatus`.
   - `scripts/rag/stages/search.py::_search_all_queries()` still records `embed_ok`/`embed_failed` and degrades gracefully on embedding failure, with no dimension-mismatch-specific branch.
6. Do not touch the storage-side `embed_dim` parameter (`MemoryStore`, `write_ops.py`, `import_ops.py`, `ingestion.py`) — that is unrelated to this requirement.
7. Do not modify `scripts/rag/llm_client.py` or `scripts/rag/ingestion/ingester.py` under this requirement; their continued use of the E5 `"query: "`/`"passage: "` prefix and dimension checks is out of scope here and should be raised separately if a full RAG-side Qwen3 migration is wanted.

## Implementation instructions
- In `scripts/agent/memory/embedding_client.py`:
  - Delete `query_prefix` and `embed_dim` fields from `EmbeddingClientConfig`.
  - Change `_fetch_embedding()`'s signature to drop the `query_prefix` and `embed_dim` parameters; send `json={"content": text}` directly.
  - Remove the `if embed_dim > 0 and len(embedding) != embed_dim:` block and its `DIMENSION_MISMATCH` return.
  - Update the call in `EmbeddingClient.fetch()` to stop passing `self._config.query_prefix` / `self._config.embed_dim`.
- In `scripts/agent/memory/types.py`: remove `EmbeddingErrorKind.DIMENSION_MISMATCH` after confirming no remaining references (re-grep after step above).
- In `scripts/agent/factory.py::_build_embedding_client()`: remove the `embed_dim=ctx.cfg.memory.memory_embed_dim` keyword argument passed to `EmbeddingClientConfig(...)`.
- In `tests/test_embedding_client.py`: remove or rewrite the test(s) asserting `DIMENSION_MISMATCH` behavior (search for `DIMENSION_MISMATCH` in that file) so the suite no longer references the removed enum member/behavior.
- Grep the full repo for `query_prefix`, `embed_dim`, and `DIMENSION_MISMATCH` after the change to confirm no remaining references inside `scripts/agent/memory/` or `scripts/agent/factory.py` (the unrelated storage-side `embed_dim` usages listed in Background must remain).
- Do not change `scripts/rag/llm_client.py`, `scripts/rag/ingestion/ingester.py`, or `scripts/shared/config_validator.py` as part of this requirement.

## Acceptance criteria
- `EmbeddingClientConfig` no longer has `query_prefix` or `embed_dim` fields.
- No code under `scripts/agent/memory/` or `scripts/agent/factory.py` passes `query_prefix` or `embed_dim` to `EmbeddingClientConfig`/`_fetch_embedding`/`EmbeddingClient.fetch`.
- `EmbeddingErrorKind.DIMENSION_MISMATCH` is removed from `scripts/agent/memory/types.py`, with no remaining references anywhere in `scripts/` or `tests/`.
- `EmbeddingClient.fetch()` sends the raw, unprefixed query text to the embed endpoint.
- `MemoryInjectionService.on_user_prompt()` still receives embeddings from `EmbeddingClient.fetch()` and passes them to `HybridRetriever.search()` unchanged in shape.
- `HybridRetriever.search()` still supports hybrid mode (embedding present) and FTS-only fallback (embedding `None` or vector search failure) as before.
- `MemoryServices.get_activation_mode()` still returns `disabled` / `fts-only` / `degraded` / `hybrid` correctly.
- `scripts/rag/stages/search.py` still records embedding failures (HTTP failure, invalid JSON, empty embedding) via `SearchDiagnostics.embed_failed` with no dimension-mismatch-specific diagnostic path.
- The unrelated storage-side `embed_dim` parameter (`MemoryStore`, `write_ops.py`, `import_ops.py`, `ingestion.py`, `ctx.cfg.memory.memory_embed_dim`) is left untouched.
