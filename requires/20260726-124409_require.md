# Add timeout to WAL checkpoint operations

## Priority

Medium

## Target Files

- `scripts/agent/repl.py:256-257` — WAL checkpoint implementation
- `scripts/agent/repl.py:261-285` — Fallback logic

## Background

The WAL checkpoint uses PASSIVE mode first, then falls back to TRUNCATE mode if it fails. However, there's no timeout on the PASSIVE checkpoint operation. If another connection holds an active transaction, the PASSIVE checkpoint may never complete.

## Problem

```python
db.checkpoint("PASSIVE")
logger.info("WAL checkpoint completed (PASSIVE) on shutdown")
```

No timeout on PASSIVE checkpoint. If it hangs indefinitely, shutdown is blocked.

## Reason for Change

Prevent indefinite blocking during shutdown due to WAL checkpoint timeouts.

## Implementation Intent

Add a timeout to WAL checkpoint operations. If the checkpoint doesn't complete within the timeout, force-fallback to the next strategy.

## Implementation Instructions

1. Add a configurable timeout constant (e.g., 5 seconds):
   ```python
   WAL_CHECKPOINT_TIMEOUT_SEC = 5
   ```
2. Wrap the checkpoint call in a timeout context:
   ```python
   try:
       await asyncio.wait_for(db.checkpoint("PASSIVE"), timeout=WAL_CHECKPOINT_TIMEOUT_SEC)
       logger.info("WAL checkpoint completed (PASSIVE) on shutdown")
   except asyncio.TimeoutError:
       logger.warning("WAL PASSIVE checkpoint timed out, falling back to TRUNCATE")
       # Fall through to TRUNCATE logic
   ```
3. Run tests to confirm no regressions

## Acceptance Criteria

- [ ] WAL checkpoint times out after configured duration
- [ ] Fallback to TRUNCATE mode works correctly after timeout
- [ ] No regressions in normal checkpoint behavior
