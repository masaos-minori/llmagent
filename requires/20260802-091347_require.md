## Background
`docs/01_overview-files-03-scripts-part4.md` documents the deployed directory structure of `scripts/mcp_servers/`. The `web_search/` and `github/` subsections list per-file descriptions using generic filenames (`server.py`, `tools.py`, `models.py`). Verification against current source (`ls scripts/mcp_servers/web_search/` and `ls scripts/mcp_servers/github/`) confirms these generic filenames no longer exist — the actual implementation uses service-prefixed filenames, and this is a confirmed rename that was never reflected in the documentation (not speculative staleness).

**`github/` — documented (generic, current doc lines 64, 78, 83):**

Both sections mislead a reader who searches the codebase using the documented generic filenames, since those files do not exist.

## Reason for change
This is a confirmed rename (service-prefixed filenames replaced generic ones) that was never propagated to the documentation. Per `rules/coding.md` "Documentation notes — Current behavior classification," this falls under "Documentation fix required": the doc itself is wrong (stale filenames), so it must be corrected directly rather than annotated or left as a tracked gap.

## Implementation intent
Remove the manually-maintained, file-by-file listing for both the `web_search/` and `github/` subdirectories in `docs/01_overview-files-03-scripts-part4.md`. Replace it with prose that:
- Describes the shared-foundation design pattern already documented at the `mcp_servers/` root level in this file (`models.py`, `dispatch.py`, `tool_validators.py`, `audit.py`, `health_response.py`, `server.py`) that each MCP server subdirectory (including `web_search/` and `github/`) builds on.
- States that each service subdirectory builds its own service-prefixed implementation files on top of that shared foundation (e.g. `web_search_server.py`, `web_search_tools.py`, `web_search_models.py`, `web_search_service.py` for web_search; `github_server.py`, `github_tools.py`, `github_models.py` plus per-domain `server_*.py` / `service_*.py` / `tools_*.py` / `models_*.py` splits for github).
- Points the reader to `scripts/mcp_servers/web_search/` and `scripts/mcp_servers/github/` directly (rather than an enumerated file list) as the authoritative, current source for exact filenames.

Do not attempt to keep the per-file listing in sync with source going forward — the intent is to stop the doc from making per-filename claims that silently rot, per the issue's implementation intent.
