# Define reviewer/owner responsibility for the docs/00_governance_01 Review Rule

## Priority
Medium

## Target files
- `docs/00_governance_01_documentation-governance.md` (Review Rule section, lines 61-68)
- `docs/00_governance_07_needs-confirmation-inventory.md` (new NC entry, if area guides lack owners — see below)

## Background
`docs/00_governance_01_documentation-governance.md` defines cross-cutting rules for maintaining the documentation set, including a "Review Rule" section (lines 61-68) that lists four conditions requiring review before merging:
- Any change to Governance-class documents
- Any change affecting more than three area documents simultaneously
- Any change that removes or renames a documented feature
- Any change that alters cross-area relationships or dependencies

This section states *when* review is required but does not state *who* is responsible for performing or approving that review.

## Problem
Verified against current source: the Review Rule (docs/00_governance_01_documentation-governance.md, lines 61-68) still contains no statement of reviewer/owner responsibility — this part of the issue is confirmed still valid.

Verified against current source: none of the five area document guides (`docs/03_rag_00_document-guide.md`, `docs/04_mcp_00_document-guide.md`, `docs/05_agent_00_document-guide.md`, `docs/06_eventbus_00_document-guide.md`, `docs/90_shared_00_document-guide.md`) currently name a documentation owner anywhere near the top of the file. Each has only a YAML frontmatter block (title, category, tags, related/source) followed by a Japanese introduction — no "owner" or equivalent field exists in any of them.

This means the issue's suggested wording — "レビューは各領域のドキュメントオーナー(領域ガイド冒頭に明記)が実施する。" — cannot be added as a statement of existing fact, because area guides do not currently name an owner at their top. Adding that sentence as-is would introduce a false cross-reference (the parenthetical would claim something that does not exist).

## Reason for change
An operational rule without a defined owner has ambiguous responsibility boundaries — it is unclear who should act when the Review Rule's conditions are triggered. This creates a documentation-governance gap: reviews may not happen, or may happen with unclear authority, because no single role/person is designated as responsible.

## Implementation intent
- Add a sentence to the Review Rule stating who is responsible for performing/approving reviews, without asserting that area guides already name an owner (since they currently do not).
- Register the absence of a per-area documentation owner as a tracked open question in the Needs Confirmation Inventory (`docs/00_governance_07_needs-confirmation-inventory.md`), following that document's existing 15-field entry format (ID, Source File, Section, Line Number, Question, Evidence, Impact, Required Action, Status, Assigned To, Last Reviewed, Priority, Related NC, Resolution Target, Blocking).
- Do not add owner names to individual area guides as part of this requirement — that is explicitly out of scope and is the subject of the Needs Confirmation follow-up instead.

## Implementation instructions
1. In `docs/00_governance_01_documentation-governance.md`, under the "Review Rule" heading (currently lines 61-68), add a sentence identifying the reviewer/owner responsible for the review conditions listed. Phrase it so it does not assert that area guides already name an owner at their top — e.g., state the intended responsible role (each area's designated documentation owner) and note (or cross-reference) that the owner-naming convention in area guides is not yet established, per the Needs Confirmation entry created in step 2. Do not fabricate an owner-naming mechanism that does not exist in the current docs.
2. In `docs/00_governance_07_needs-confirmation-inventory.md`, add a new inventory entry (next sequential `NC-{NNN}` ID after the current last entry) recording that area document guides do not currently name a documentation owner at the top of the file, that this is required for the Review Rule to be enforceable, and what action is needed (decide on and add an owner field/statement to each of the five area guides: 03_rag, 04_mcp, 05_agent, 06_eventbus, 90_shared). Populate all 15 required fields per that document's existing format.
3. Do not modify area guide files (`03_rag_00_document-guide.md`, `04_mcp_00_document-guide.md`, `05_agent_00_document-guide.md`, `06_eventbus_00_document-guide.md`, `90_shared_00_document-guide.md`) themselves in this change — adding actual owner names to them is out of scope per the source issue.

## Acceptance criteria
- The Review Rule section in `docs/00_governance_01_documentation-governance.md` explicitly states who is responsible for performing/approving reviews.
- The Review Rule's added text does not claim area guides already name an owner at their top (since verification showed none currently do).
- A new Needs Confirmation entry exists in `docs/00_governance_07_needs-confirmation-inventory.md` documenting that area guides lack a named documentation owner, following the document's required 15-field entry format.
- No area guide document (`03_rag_00`, `04_mcp_00`, `05_agent_00`, `06_eventbus_00`, `90_shared_00`) is modified by this change.
