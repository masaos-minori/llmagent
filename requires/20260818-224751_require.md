# Fix AttributeError on sqlite3.Row.get() in find_all_pending_approvals causing agent startup failure

## Priority
High

## Target files
- `scripts/agent/workflow/approval_ops.py` (primary fix, line 201)
- `tests/agent/workflow/test_approval_ops.py` (new direct-DB test)
- `tests/agent/test_startup.py` (new non-mocked integration test)

## Background
`StartupOrchestrator._recover_pending_approvals()` in `scripts/agent/startup.py` calls
`find_all_pending_approvals()` during agent startup to restore any workflow approval
gate left pending from a previous session. `find_all_pending_approvals()` is defined
in `scripts/agent/workflow/approval_ops.py`.

`StateStore.__init__()` (`scripts/agent/workflow/state_store.py:31`) always opens its
SQLite connection with `row_factory=True`, which sets `conn.row_factory = sqlite3.Row`.
`StateStore.get_connection()` returns this same `SQLiteHelper` instance, and
`SQLiteHelper.fetchall()` returns whatever `conn.execute(...).fetchall()` yields —
i.e. a list of `sqlite3.Row` objects. Therefore every row reaching
`find_all_pending_approvals()` is guaranteed to be a `sqlite3.Row`.

## Problem
At `scripts/agent/workflow/approval_ops.py:201`:

```python
_approval_from_row(r, status="pending", expires_at=r.get("expires_at")),
```

`r.get("expires_at")` is called directly on a `sqlite3.Row` object. `sqlite3.Row` has
no `.get()` method, so this line unconditionally raises
`AttributeError: 'sqlite3.Row' object has no attribute 'get'` whenever
`find_all_pending_approvals()` returns at least one row (i.e. whenever a pending
approval gate exists in the `approvals`/`tasks` tables).

This was verified directly:
- Read `scripts/agent/workflow/approval_ops.py` lines 183-204: confirmed the exact
  `r.get("expires_at")` call at line 201, inside `find_all_pending_approvals()`.
- Read `scripts/agent/workflow/state_store.py` line 31: confirmed
  `self._db.open(write_mode=True, row_factory=True)`, and `get_connection()` (lines
  37-44) returns `self._db` directly, so the `SQLiteHelper` used by
  `find_all_pending_approvals()` always has `sqlite3.Row` as its row factory.
- Read `scripts/db/helper.py`: confirmed `open(..., row_factory=True)` sets
  `conn.row_factory = sqlite3.Row` (line 190), and `fetchall()` (lines 311-318)
  simply returns `conn.execute(sql, params).fetchall()` with no dict conversion.
- Reproduced the underlying Python behavior directly:
  ```
  $ python3 -c "
  import sqlite3
  con = sqlite3.connect(':memory:'); con.row_factory = sqlite3.Row
  cur = con.cursor()
  cur.execute('CREATE TABLE t (a INTEGER)')
  cur.execute('INSERT INTO t VALUES (1)')
  row = cur.execute('SELECT * FROM t').fetchone()
  row.get('a')
  "
  AttributeError: 'sqlite3.Row' object has no attribute 'get'
  ```
- Confirmed the same file already uses the correct pattern elsewhere:
  `_approval_from_row()` (line 27) accesses `workflow_id` via
  `r["workflow_id"] if "workflow_id" in r.keys() else ""`, proving the codebase is
  aware `sqlite3.Row` lacks `.get()` and has an established safe-access idiom.
- Confirmed via `grep` that no test in `tests/agent/workflow/test_approval_ops.py`
  calls `find_all_pending_approvals()` directly (no matches at all), and every
  reference to `find_all_pending_approvals` in `tests/agent/test_startup.py`
  (lines 247, 279, 319, 349, 390, 426, 452, 472) is a `patch(...)` mock, so the
  bug is never exercised by the current test suite.

## Reason for change
`_recover_pending_approvals()` in `scripts/agent/startup.py` does not catch this
`AttributeError`; it only wraps the call in `try/finally` to close the store
(lines 583-587). The exception propagates up to `StartupOrchestrator.run()`'s
outer `except Exception as setup_err:` (line 109), which triggers
`lifecycle.shutdown_all()` rollback (line 111), terminating any already-started
subprocesses, and then re-raises the original error (line 118). The net effect:
**if any approval gate is left pending from a prior session, the agent cannot
start at all.** This is a critical, user-facing startup failure with a simple,
well-understood root cause, so it should be fixed promptly.

## Implementation intent
Bring line 201 of `scripts/agent/workflow/approval_ops.py` in line with the
codebase's existing safe-access convention for `sqlite3.Row`, using either:
- the `"key" in r.keys()` conditional-access idiom already used at line 27 in the
  same file, or
- converting the row to a `dict` first (as done in
  `scripts/agent/workflow/state_store.py:104` and
  `scripts/agent/workflow/task_ops.py:71`) and calling `.get()` on the dict.

No behavioral change to the returned `ApprovalRecord` values is intended — only the
access mechanism changes so it no longer raises `AttributeError`. Additionally,
close the test gap: add at least one test that exercises
`find_all_pending_approvals()` against a real SQLite `tasks`/`approvals` table
without mocking the function itself, and at least one `_recover_pending_approvals()`
test in `test_startup.py` that goes through the real `find_all_pending_approvals`
implementation instead of mocking it.

## Implementation instructions

   `r.get("expires_at")` with either
   `r["expires_at"] if "expires_at" in r.keys() else None` (matching the pattern
   at line 27), or `dict(r).get("expires_at")`. Prefer the former for consistency
   with `_approval_from_row()` in the same file, unless the row is already being
   converted to a dict elsewhere in the same function for other reasons.
