# Add guard tests for eventbus db migration before refactoring

## Priority

High

## Target Files

- `scripts/eventbus/db.py:61-100` — Migration logic
- `tests/test_eventbus_db_migration.py` — New test file planned

## Background

The eventbus schema initialization and migration logic has no regression detection for old schema transitions. There's no way to verify that migrations work correctly after refactoring.

## Problem

No migration reproduction tests. After refactoring, there's no way to detect if old schema migrations break.

## Reason for Change

Establish behavioral baseline through guard tests before any refactoring of this component.

## Implementation Intent

Create tests that reproduce the migration path from old schemas to the current schema, verifying each step works correctly.

## Implementation Instructions

1. Create `tests/test_eventbus_db_migration.py` with tests for:
   - Old schema migration: Simulate an old schema and verify it migrates correctly to the current version
   - Schema version upgrade: Test incremental upgrades (e.g., v1 → v2 → v3)
   - Error handling: Test that failed migrations produce appropriate error messages
   - Idempotency: Test that running migration multiple times doesn't cause issues
2. Use SQLite in-memory database for testing
3. Run tests to confirm no regressions
4. Proceed with refactoring only after guard tests pass

## Acceptance Criteria

- [ ] Guard tests added for all migration paths
- [ ] All guard tests pass against current codebase
- [ ] No regressions introduced during guard test addition
