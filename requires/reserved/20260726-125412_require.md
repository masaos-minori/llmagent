## Background

Several components have been identified as needing guard tests before refactoring. These components have simple logic but contain implicit dependencies or unverified branches.

## Problem

Without guard tests, refactoring these components risks breaking behavior that isn't currently covered by existing tests.

## Reason for Change

Establish behavioral baselines through guard tests before making structural changes to prevent regressions.

## Implementation Intent

Add characterization tests for each component that capture current behavior, then proceed with refactoring.

## Implementation Instructions

For each component, add a test that verifies the current behavior:

1. **tool_loop_guard.py**: Test boundary values where `ctx.cfg.tool.*` limits are hit
2. **config_validator.py / production_config_validator.py**: Test fallback when `known_tools` is omitted (SHARED-6)
3. **ack_route.py / dlq.py**: Test that DB state doesn't change on `_atomic_write` failure
4. **db/helper.py**: Test rollback on `begin_immediate`/`exclusive` exceptions and `reuse_connection` state management
5. **chunk_splitter.py + chunk_english.py + chunk_japanese.py**: Test actual output of `process_file()` end-to-end

Run tests after adding each guard test to confirm no regressions.

## Acceptance Criteria

- [ ] Guard tests added for all 8 listed components
- [ ] All guard tests pass against current codebase
- [ ] No regressions introduced during guard test addition
