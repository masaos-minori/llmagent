# Add guard tests for eventbus/db.py schema migration

## Priority

High

## Target Files

- `scripts/eventbus/db.py:61-100` — `_migrate` migration logic
- `scripts/eventbus/schema.sql` — target schema definition
- `tests/test_eventbus_db_migration.py` — new file to be created

## Background

The `_migrate` function in `eventbus/db.py` handles schema migration from an older version that had a `retry_count` column to the current schema with `delivery_failure_count` and `dlq_requeue_count` columns. This entire migration code path is untested.

## Problem

```python
def _migrate(conn):
    cursor = conn.execute("PRAGMA table_info(events)")
    columns = {row[1] for row in cursor}
    if "retry_count" in columns:
        conn.execute("ALTER TABLE events ADD COLUMN delivery_failure_count INTEGER DEFAULT 0")
        conn.execute("ALTER TABLE events ADD COLUMN dlq_requeue_count INTEGER DEFAULT 0")
        conn.execute("ALTER TABLE events DROP COLUMN retry_count")
        logger.info("migrated: dropped column retry_count from events")
```

No test verifies:
1. Migration succeeds when `retry_count` column exists
2. New columns are correctly added
3. Existing data is preserved after migration
4. Exception during migration does not corrupt the database

## Reason for Change

This component was classified as High-risk-refactor because migration code is untested. Without guard tests, any change to the migration logic could silently break existing databases.

## Implementation Intent

Create `tests/test_eventbus_db_migration.py` with two test methods:

1. `test_migrate_adds_new_columns`: Create DB with `retry_count` column, run `_migrate()`, verify `delivery_failure_count` and `dlq_requeue_count` exist
2. `test_migrate_preserves_data`: Insert rows before migration, verify they survive migration unchanged

## Implementation Instructions

1. Create `tests/test_eventbus_db_migration.py`
2. For each test:
   - Create a temporary SQLite database with the old schema (including `retry_count` column)
   - Optionally insert test data
   - Call `_migrate(conn)` directly
   - Verify new columns exist and data is intact
3. Run `uv run pytest tests/test_eventbus_db_migration.py -v` to confirm pass
