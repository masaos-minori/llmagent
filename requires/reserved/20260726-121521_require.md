# Add nosec annotations for bandit B608 false positives

## Priority

High

## Target Files

- `scripts/eventbus/db.py:195` — IN clause with placeholder generation
- `scripts/eventbus/subscribe_route.py:47` — same pattern
- `scripts/mcp_servers/mdq/db_grep.py:72` — WHERE clause assembly with params binding
- `scripts/mcp_servers/mdq/health_check.py:35` — STALE_SQL_CONDITION constant
- `scripts/mcp_servers/mdq/mdq_service.py:205` — where_clauses fragment + params
- `scripts/mcp_servers/mdq/mdq_service.py:327` — STALE_SQL_CONDITION constant
- `scripts/mcp_servers/mdq/search.py:145` — _build_search_where() fixed fragment + params
- `scripts/mcp_servers/mdq/search.py:156` — same

## Background

bandit reports 8 B608 (SQL injection via string query construction) issues across two modules. All are false positives: values are always bound via `?` placeholders, never concatenated into SQL strings.

## Problem

```bash
$ uv run bandit -r scripts/ -c pyproject.toml
Issue: [B608:hardcoded_sql_expressions] Possible SQL injection vector through string-based query construction.
```

The db layer already has correct nosec annotations (`scripts/db/maintenance.py:148`, `scripts/db/store_impl.py:258`). The eventbus and mdq layers have identical patterns but lack annotations.

## Reason for Change

Without nosec annotations, CI fails on bandit even though there is no actual vulnerability. This creates noise and reduces signal quality.

## Implementation Intent

Add `# nosec B608 - <justification>` annotations to all 8 locations, matching the format used in the db layer.

## Implementation Instructions

For each location, add a comment after the SQL string expression:

```python
# Before:
cursor.execute(f"SELECT * FROM events WHERE topic IN ({','.join('?' for _ in topics)})", params)

# After:
cursor.execute(f"SELECT * FROM events WHERE topic IN ({','.join('?' for _ in topics)})", params)  # nosec B608 - all values bound via ? placeholders
```

Justifications by category:
- eventbus (2): "all values bound via ? placeholders"
- mdq db_grep (1): "WHERE clause built from fixed column names; values bound via params"
- mdq health_check (1): "STALE_SQL_CONDITION is a fixed string constant"
- mdq mdq_service (2): "where_clauses fragments from fixed constants; values bound via params"
- mdq search (2): "_build_search_where returns fixed fragments; values bound via params"

After adding annotations, verify: `uv run bandit -r scripts/ -c pyproject.toml` exits with medium/high issue count = 0.
