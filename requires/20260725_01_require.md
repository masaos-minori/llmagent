# Tool arguments injection via LLM-generated tool calls

## Priority

High

## Target Files

- `scripts/agent/tool_runner.py` — `orjson.loads(args_str)`, MCP tool execution
- `scripts/shared/tool_executor.py` — `ToolExecutor.execute()`

## Background

When the agent processes a tool call response, it parses the LLM-generated tool arguments using `orjson.loads()` and then executes them against MCP servers or local tools. No validation is performed on the parsed arguments before execution.

## Problem

In `tool_runner.py:132`:

```python
args = orjson.loads(args_str)
```

After parsing, the arguments are passed directly to `ctx.services_required.gateway.execute(ctx, name, args)` or `ctx.services_required.tools.execute(name, args)` without any schema validation. If the LLM generates malicious arguments (e.g., additional unexpected fields like `{"filename": "target.txt", "force_overwrite": true}`), these are sent to the MCP server unchanged.

## Reason for Change

Without argument validation, the LLM can inject arbitrary fields into tool calls, potentially causing unintended side effects. MCP servers execute whatever arguments they receive, so unvalidated arguments pose a security risk.

## Implementation Intent

Add schema-based validation for tool arguments before they reach MCP servers. Reject tool calls with unexpected fields. Allow MCP servers to define their own argument schemas.

## Implementation Instructions

1. After `orjson.loads(args_str)`, validate the parsed arguments against the expected schema for the specific tool.
2. Use the MCP tool definition's inputSchema to determine valid fields and types.
3. Reject tool calls that contain fields not defined in the schema, logging a warning with details.
4. Optionally, allow MCP servers to override validation rules for specific tools.

## Acceptance Criteria

- [ ] Tool arguments validated against MCP tool inputSchema before execution
- [ ] Unexpected fields rejected with warning logged
- [ ] Validation failures do not crash the agent session
- [ ] MCP servers can optionally provide custom validation rules

## Tests

- Unit test: pass arguments with extra fields not in schema; verify rejection
- Unit test: pass valid arguments matching schema; verify acceptance
- Integration test: simulate LLM generating malformed tool arguments; verify graceful handling
