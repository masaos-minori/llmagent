# Remove unused `kwarg` parameter from `LlmHotConfigHandler.apply_one`

## Priority
Low

## Target files
- `scripts/shared/llm_hot_config.py` (`LlmHotConfigHandler.apply_one`, `LlmHotConfigHandler.apply_config`)
- `tests/shared/test_llm_hot_config.py`

## Background
`scripts/shared/llm_hot_config.py` defines `LlmHotConfigHandler`, a static-method helper class
used by `LLMClient` to hot-reload a fixed set of 9 configuration fields (temperature, max_tokens,
max_retries, retry_base_delay, sse_heartbeat_timeout, sse_malformed_retry, sse_reconnect_max,
stream_retry_on_heartbeat_timeout, stream_retry_on_malformed_chunk) without recreating the
instance. `HOT_CONFIG_FIELDS` is a tuple of `(instance_attr_name, kwarg_name)` pairs; `apply_config`
iterates it and calls `apply_one` for each non-`None` value supplied by the caller.

This issue was found during a prior behavior-preserving refactor cycle on this file
(2026-08-13) but was deliberately not fixed there because it changes a public method's
signature and needed explicit sign-off as a separate change.

## Problem
`apply_one` is currently defined as:

```python
@staticmethod
def apply_one(instance: object, field: str, kwarg: str, value: Any) -> None:
    """Set a single config field on an instance."""
    setattr(instance, field, value)
```

The `kwarg` parameter is accepted but never read inside the method body — only `field` and
`value` are used by `setattr`. This is confirmed still true in the current source
(`scripts/shared/llm_hot_config.py:23-25`).

`apply_one` is a public (no leading underscore) `staticmethod`, so this is a signature
simplification, not a private-helper cleanup — it is called from two places, both already
verified via `rg "apply_one"` across the full repository:
- `LlmHotConfigHandler.apply_config` (`scripts/shared/llm_hot_config.py:55`), which passes
  `(instance, attr, kwarg, value)` from its `for attr, kwarg in LlmHotConfigHandler.HOT_CONFIG_FIELDS`
  loop.
- `tests/shared/test_llm_hot_config.py`, in `test_apply_one_sets_field` (line 23) and
  `test_apply_one_sets_non_float_field` (lines 30 and 32-37), each passing the current 4-argument
  form.

No other caller exists anywhere in the repository (docs mentions in
`docs/90_shared_03_04_runtime_and_execution-caching-and-reference-part2.md` and various
`plans/done/` / `implementations/done/` files are historical narrative only, not executable
call sites).

## Reason for change
Carrying an unused parameter on a public method signature is dead surface area: it invites
future callers to assume `kwarg` has an effect, adds noise to every call site, and increases
the chance of a future edit mismatching `field`/`kwarg` order. Since all call sites are
internal to this file and its test module, the signature can be safely simplified now that
the refactor that surfaced the issue is complete and this has been called out for explicit
approval as its own change.

## Implementation intent
Drop the unused `kwarg` parameter from `apply_one`, keeping the method's behavior (a plain
`setattr(instance, field, value)`) unchanged. Update the sole production caller
(`apply_config`'s loop over `HOT_CONFIG_FIELDS`) and all test call sites to the new 3-argument
form. This is a pure signature simplification — no change to what value ends up on `instance`,
no change to `HOT_CONFIG_FIELDS`, no change to `apply_config`'s own public keyword-only
signature.

## Implementation instructions
1. In `scripts/shared/llm_hot_config.py`:
   - Change `apply_one`'s signature from
     `apply_one(instance: object, field: str, kwarg: str, value: Any) -> None`
     to `apply_one(instance: object, field: str, value: Any) -> None`. Leave the body
     (`setattr(instance, field, value)`) unchanged.
   - Update the call in `apply_config`'s loop (currently
     `LlmHotConfigHandler.apply_one(instance, attr, kwarg, value)`) to
     `LlmHotConfigHandler.apply_one(instance, attr, value)`. Note the loop variable `kwarg`
     is still needed there (as the lookup key into `args`), so only the call argument is
     dropped, not the loop variable itself.
2. In `tests/shared/test_llm_hot_config.py`:
   - `test_apply_one_sets_field` (currently
     `LlmHotConfigHandler.apply_one(inst, "_temperature", "temperature", 0.9)`): drop the
     `"temperature"` argument.
   - `test_apply_one_sets_non_float_field` (currently two calls, one with
     `"_max_tokens", "max_tokens", 200` and one multi-line call with
     `"_llm_stream_retry_on_heartbeat_timeout", "stream_retry_on_heartbeat_timeout", False`):
     drop the `kwarg`-name argument from both.
3. Before making the change, re-run `rg "apply_one"` across the repository root to confirm no
   new caller has been introduced since this requirement was written.
4. Re-run mypy on `scripts/shared/llm_hot_config.py` to confirm the reduced-arity call in
   `apply_config` still type-checks.

## Acceptance criteria
- `LlmHotConfigHandler.apply_one` has exactly 3 parameters: `instance`, `field`, `value`.
- `apply_config`'s call to `apply_one` passes exactly 3 arguments and the loop variable
  naming (`attr`, `kwarg`) used to index `args` is otherwise unchanged.
- All call sites in `tests/shared/test_llm_hot_config.py` use the new 3-argument form.
- `apply_config`'s own public keyword-only signature and `HOT_CONFIG_FIELDS` are unchanged.
- `rg "apply_one"` across the repository shows no remaining 4-argument call site.
- No other file outside the two listed target files needs a call-site update (re-verify with
  `rg "apply_one"` before merging).
