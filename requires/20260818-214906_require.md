## Background
The source issue (`issues/20260817_06_issue.md`) reports that several design-doc
sections repeat their full body two or three times, naming as examples "agent
sections covering tool execution and command registry, shared-layer sections, and
the rag section." A duplicated body means a one-sided edit silently creates drift:
readers cannot tell which copy is authoritative, and reviewers cannot see divergence
at a glance.

## Problem
A block-level duplicate scan across all files in `docs/*.md` (paragraphs, tables,
and fenced code blocks of 300+ characters, hashed and compared within each file)
confirms the general problem is real and, in fact, broader than the issue's cited
examples:

- `docs/01_overview-files-03-scripts.md` is the worst offender: it is internally
  organized into sections `3`, `3a`, `3b`, ... `3i`, and each pair (`3`/`3a`,
  `3b`/`3c`, `3d`/`3e`, `3f`/`3g`, `3h`/`3i`) has byte-for-byte identical body text
  (heading, tables, and file-tree code blocks). The `## Related Documents` list in
  every section also repeats the same self-referencing filename 3-4 times in a row.
- At least 19 additional files across the RAG, shared-layer, MCP, and agent doc sets
  (listed above under "Target files") contain internally duplicated tables, prose
  explanations, or code/pseudocode blocks — the same content appears twice
  verbatim in one document.
- However, the two specific examples the issue names under "agent sections
  covering tool execution and command registry" — `docs/05_agent_06_01` through
  `05_agent_06_04` (tool execution and approval) and `docs/05_agent_07_03`
  (command registry) — were checked directly and contain **no** duplicate
  paragraphs, tables, or headings. That part of the issue's claim is stale or
  inaccurate for the current doc set and should not be used to scope the fix.

## Reason for change
The issue's underlying claim (design docs contain duplicated sections that create
edit-drift risk) is verified and, if anything, understates the scope: the actual
worst case (`01_overview-files-03-scripts.md`) is not even one of the issue's named
examples. Meanwhile the two agent-doc examples the issue names are already clean,
so scoping a fix around them (as the issue's own wording suggests) would miss the
real problem entirely. The requirement below re-scopes the work to the files where
duplication was actually found by direct verification, and drops the two
already-clean files from scope.

## Implementation intent
For each target file, identify the duplicated body/section and consolidate it into
a single canonical instance:
- Where a whole section is duplicated (e.g., `3` vs `3a` in
  `01_overview-files-03-scripts.md`), delete the redundant duplicate section
  entirely and keep one canonical copy, renumbering/adjusting headings as needed so
  the document reads as a coherent single pass rather than a doubled structure.
- Where a paragraph, table, or code block is duplicated inside an otherwise
  non-duplicated section, remove the redundant repeated copy and keep the first
  (or most complete/most recently corrected) occurrence.
- Where a `## Related Documents` (or similar) list repeats the same filename
  multiple times in a row, de-duplicate the list to one entry per referenced file.
- Do not delete unique content — only remove exact or near-exact repeats of
  material that already appears elsewhere in the same file. If two "duplicate"
  copies have diverged (one corrected, one stale), keep the corrected version and
  discard the stale one.
- Preserve existing front matter, heading hierarchy, and cross-document links
  (`Related Docs`/`Related Documents` sections linking to other files) except for
  removing the in-list self-duplication described above.

## Implementation instructions
1. For `docs/01_overview-files-03-scripts.md`: merge sections `3`+`3a`,
   `3b`+`3c`, `3d`+`3e`, `3f`+`3g`, `3h`+`3i` into single sections (one section per
   distinct topic: agent/memory package tables, commands mixin note, services/
   shared/workflow tree, mcp_servers web_search/github tree, and the 4-file naming
   convention note). Renumber the surviving sections sequentially. Fix the front
   matter (`related:` list currently repeats the file's own name 4 times) and every
   `## Related Documents` list to list each referenced file once.
2. For each of the other confirmed target files, locate the duplicated
   paragraph/table/code block using a text diff or manual comparison of the
   document against itself, then delete the redundant copy while keeping the file
   internally consistent (headings, surrounding prose, and any lead-in sentences
   that reference the removed copy must still read correctly after removal).
3. Do not touch `docs/05_agent_06_01` through `05_agent_06_04` or
   `docs/05_agent_07_03` — they were verified clean and are out of scope.
4. After edits, re-run a duplicate-block scan (paragraph/table/code-block level,
   split on blank lines, compare hashes within each file) over all edited files to
   confirm no exact-duplicate blocks of 80+ characters remain within any single
   file, excluding legitimate repeated boilerplate that is not a "body duplicate"
   (e.g., a short breadcrumb link like "アーキテクチャ概要 → ..." appearing once per
   section is fine; the same table/paragraph appearing twice is not).
5. Spot-check that no unique information was lost — every fact present before the
   edit that was not an exact duplicate must still be present after the edit.

## Acceptance criteria
- In every file listed in "Target files" (excluding the "Out of scope" list), no
  paragraph, table, or fenced code block of 80+ characters is byte-identical to
  another block within the same file, when the file is split into blank-line
  delimited blocks.
- `docs/01_overview-files-03-scripts.md` has exactly one section per distinct
  topic (no more `3`/`3a` style duplicate pairs), a `related:` front-matter list
  free of self-referencing duplicates, and every `## Related Documents` list has no
  repeated filename entries.
- No content unique to one of the two "duplicate" copies (e.g., a corrected fact
  that only appears in one of the two repeats) is lost during consolidation.
- `docs/05_agent_06_01` through `05_agent_06_04` and `docs/05_agent_07_03` remain
  unmodified (already clean, out of scope).
- This is a documentation-only change: no `scripts/*.py` or other source files are
  modified.

## Tests
- No automated test suite covers `docs/*.md` content directly. Verification is
  manual/scripted:
  - Re-run the blank-line-delimited block-hash duplicate scan (as used to identify
    the target files) over each edited file and confirm zero duplicate blocks
    remain (excluding short shared breadcrumb links under ~80 characters).
  - Manually diff each edited file's before/after content to confirm no unique
    information was dropped, only redundant repeats removed.
  - If the project has an existing doc-lint or doc-consistency script (check
    `tools/` per `AGENTS.md` global rule 6), run it after edits to confirm no
    broken internal links or heading-numbering regressions were introduced.
