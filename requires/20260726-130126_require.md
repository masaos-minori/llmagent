# Add guard tests for config_loader.py before refactoring

## Priority

High

## Target Files

- `scripts/shared/config_loader.py` — ConfigLoader
- `scripts/shared/config_loader.py:92-105` — load_all conflict branch (SHARED-4)
- `scripts/shared/config_loader.py:142-145` — _resolve_path extension omission (SHARED-5)

## Background

The ConfigLoader module is used directly by all layers and has strong side effects due to class variable-based global state. Tests must monkey-patch and reset to avoid contamination.

## Problem

Multiple file merge order, restrict_to unreset pollution prevention, and extension resolution branches are all untested. Any refactoring risks breaking these paths without detection.

## Reason for Change

Establish behavioral baseline through guard tests before any refactoring of this component.

## Implementation Intent

Create comprehensive guard tests covering:
- Multiple file merge order verification
- restrict_to isolation between tests
- Extension resolution branching

## Implementation Instructions

1. Create `tests/shared/test_config_loader.py` with tests for:
   - File merge order: Test that files are merged in the correct order (later files override earlier ones)
   - restrict_to isolation: Test that calling restrict_to() doesn't leak state between tests
   - Extension resolution: Test that missing extensions are resolved correctly
   - Global state cleanup: Test that class variables are properly reset after each test
2. Use pytest fixtures to ensure clean state between tests
3. Run tests to confirm no regressions
4. Proceed with refactoring only after guard tests pass

## Acceptance Criteria

- [ ] Guard tests added for file merge order, restrict_to isolation, and extension resolution
- [ ] All guard tests pass against current codebase
- [ ] No regressions introduced during guard test addition
