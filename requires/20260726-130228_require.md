## Priority

## Target Files

## Background

The http_lifecycle.py module has dense OS/signal/subprocess side effects, is difficult to DI, and contains hidden global state via `signal.signal`. Process lifecycle integration tests are a prerequisite.

## Problem

Signal handler replacement/restoration and try/finally structure is complex. Real process dependency makes reproduction unreliable.

## Reason for Change

Establish behavioral baseline through guard tests before any refactoring of this component.

## Implementation Intent

Create integration tests covering:
- Signal handler registration and restoration
- Subprocess lifecycle management
- Shutdown sequence behavior

## Implementation Instructions

1. Create `tests/test_http_lifecycle_integration.py` with tests for:
   - Signal handling: Test that signal handlers are registered and restored correctly
   - Subprocess lifecycle: Test that subprocesses start, run, and stop correctly
   - Shutdown sequence: Test that shutdown_all works correctly under various conditions
   - Error recovery: Test that failed starts don't prevent subsequent attempts
2. Use subprocess mocking where possible; real processes may be needed for signal tests
3. Run tests to confirm no regressions
4. Proceed with refactoring only after guard tests pass
