# Remove duplicated JSON-output-format example and logging section from docs/03_rag_02_02_ingestion_pipeline-crawler-part2.md

## Priority
Medium

## Target files
- `docs/03_rag_02_02_ingestion_pipeline-crawler-part2.md` (edit: remove duplicated sections, add references)
- `docs/03_rag_04_01_dto-models_data.md` (edit: add the canonical `CrawlPayload` JSON output example, since it is not currently present there)
- `docs/03_rag_05_3-logging.md` (reference target only — verified to already contain the canonical crawler logging content; no changes expected here)

## Background
The source issue (`issues/20260802-080020_rag_crawl_file_responsibility_and_02_02_part2_cleanup.md`, tracing to `docs_review_rag.md` §1 item 4, §2 "削除候補" item 3, §4, §5 例4, §6A) reported two problems in `docs/03_rag_02_02_ingestion_pipeline-crawler-part2.md`:
1. The "鮮度判定" section misattributed the skip/re-ingestion decision to `WebCrawler` instead of `DocumentManager`.
2. The file duplicates a JSON-output-format example and a logging section that the review claimed were already canonical elsewhere (`docs/03_rag_04_01_dto-models_data.md` and `docs/03_rag_05_3-logging.md` respectively).

## Problem
Verification against current source and docs (2026-08-02) found:
- **Item 1 (responsibility misattribution) is already fixed.** The current section is titled "鮮度判定用データの生成(責務境界に注意)" (lines 37-58) and already states that `crawl_file()` only computes mtime/SHA-256 and always emits JSON unconditionally, with no skip decision, and correctly attributes the actual skip/re-ingestion decision to `DocumentManager._is_file_unchanged()`/`_handle_existing_file()` in `scripts/rag/ingestion/document_manager.py`. This matches exactly what commit `6cfb24c10` ("feat: add RAG docs consistency checker and fix confirmed drift") already changed. `scripts/rag/ingestion/document_manager.py` still defines `_handle_existing_file` (line 64) and `_is_file_unchanged` (line 105) with these exact names, confirming the doc text remains accurate. **No further action is needed for this part.**
- **Item 2 (duplication removal) is still unresolved and remains valid, but with a correction to the issue's premise.** The doc still contains:
  - `### 2.4 出力JSON形式` (lines 77-93): a full JSON example (`schema_version`, `artifact_type`, `created_by`, `url`, `title`, `lang`, `fetched_at`, `content`, `code_blocks`, `etag`, `last_modified`) plus a short field-meaning list.
  - `### 2.6 ロギング` (lines 108-116): crawler log file path, format string, and a level/timing/structured-fields table for `crawler.py`.
  - Verification of `docs/03_rag_05_3-logging.md` confirms it already documents the crawler's log file (`/opt/llm/logs/crawl.log` + stderr), log levels (INFO: start/save/skip; WARNING: HTTP errors/retries), and the shared format string (`%(asctime)s %(levelname)s [%(funcName)s] %(message)s`) — this is a genuine duplicate and 05_3 is the correct reference target for the logging section.
  - However, **`docs/03_rag_04_01_dto-models_data.md` does NOT currently contain the `CrawlPayload` JSON example** — it only documents `scripts/rag/models_data.py` dataclasses (`EmbeddingResponse`, `CrawlTarget`, `ChunkDocument`, `ChunkRecord`, `CacheEntry`, `TwoStageFetchResult`), none of which include the concrete JSON literal shown in part2's "2.4 出力JSON形式". The nearest existing description of the `CrawlPayload` TypedDict is in `docs/03_rag_02_02_ingestion_pipeline-crawler-part1.md` (lines 42, 80), but only as a field-name list, not the full example with sample values. Simply deleting the "2.4 出力JSON形式" section and replacing it with a reference to 04_01 (as the original issue instructs verbatim) would delete the only place this concrete example currently exists, losing information rather than de-duplicating it.

## Reason for change
Keeping a duplicated logging section serves no purpose — 05_3-logging.md is unambiguously canonical and up to date, so the crawler-part2 copy is pure duplication and maintenance burden. For the JSON example, the goal (avoid duplicate/divergent canonical sources) is still valid, but it must be implemented as a genuine consolidation (move the content to its canonical home, or confirm the field-list already in crawler-part1.md is sufficient) rather than a blind delete-and-reference that would leave the concrete example undocumented anywhere.

## Implementation intent
- For the logging section: remove the "2.6 ロギング" section content from crawler-part2.md and replace it with a short reference to `docs/03_rag_05_3-logging.md`.
- For the JSON example: consolidate rather than delete-only. Either (a) move the full JSON example (with sample values) from crawler-part2.md into `docs/03_rag_04_01_dto-models_data.md`'s `CrawlTarget`/`CrawlPayload`-related content (or add a new subsection there for `CrawlPayload`), then replace crawler-part2's "2.4 出力JSON形式" with a reference to it; or (b) if a maintainer decides the field-list already in `docs/03_rag_02_02_ingestion_pipeline-crawler-part1.md` (lines 42/80) is judged sufficient as the canonical description, move the full JSON example there instead and reference part1 from part2. Do not simply delete the JSON example without ensuring the concrete literal example is preserved in exactly one place.
- Do not re-touch the freshness-check/responsibility-attribution section (lines 37-58) — it is already correct.
