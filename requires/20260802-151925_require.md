# Fix known filename/import-path errors and audit remaining MCP docs for the same pattern

## Priority
Medium

## Target files
- `docs/04_mcp_04_01_web-search-file-read-github.md` (line 184)
- `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md` (lines 69, 86, 89, 117) — corrected location for the "mdq/server.py" error; see Background
- `docs/04_mcp_05_02_auth-profiles-and-sandboxing.md` (line 72)
- All 45 `docs/04_mcp_*.md` files (for the audit pass)

## Background
An issue-creation-phase review (`docs_review_mcp.md` §1 item 11, §6A) flagged that
several MCP documentation files contain incorrect filenames or import paths, caused by a
naming-drift pattern where per-server modules were renamed from bare names (e.g.
`models.py`, `server.py`) to server-prefixed names (e.g. `github_models.py`,
`mdq_server.py`) without updating all doc references. `docs/04_mcp_07_tool_schema_export_policy.md:41-43`
already self-documents this exact class of staleness and cross-references
`issues/20260719-193357_risks.md` as related tracking.

This requirement's Step 2 re-verification (read-only, against current source)
reconfirmed 2 of the 3 claims exactly as stated, and confirmed the 3rd claim's error is
real but mis-attributed to the wrong doc file in the original issue — the actual broken
reference lives in a different file than the issue named. Details below.

## Problem
Three confirmed factual errors exist in MCP docs, each of which would send a developer
searching for a file or line that does not exist:

1. **`docs/04_mcp_04_01_web-search-file-read-github.md:184`** states the GitHub domain
   exceptions are defined in `scripts/mcp_servers/github/models_config.py` and
   re-exported via `models.py`. No `models.py` exists in
   `scripts/mcp_servers/github/`. The actual re-export file is
   `scripts/mcp_servers/github/github_models.py`.
   - Additional finding (informational, out of scope for this fix): `github_models.py`'s
     own module docstring (lines 2 and 16) still literally reads
     `"""mcp_servers/github/models.py`, i.e., the source file itself has a stale
     self-reference from before its own rename. Not part of this requirement's scope
     (source code, not docs) — flag as a candidate follow-up issue only.

2. **The issue statement's file attribution is wrong for this claim.** The issue says
   `docs/04_mcp_04_04_mdq.md` and `docs/04_mcp_04_05_git.md` reference
   `mdq/server.py:308`. Verification found **zero** occurrences of `mdq/server.py` or
   `server.py:308` in either of those two files. The actual broken reference is in a
   different doc:
   - **`docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md:89`**:
     `` `scripts/mcp_servers/mdq/server.py:308`: `attach_auth_middleware(cast(_FastAPIApp, app), "")` ``
   - The same doc also has bare (line-number-free) mentions of the same non-existent
     path at lines 69, 86, and 117 (e.g. "`scripts/mcp_servers/mdq/server.py` の
     `MdqMCPServer`").
   - `mdq/server.py` does not exist. The actual current file is
     `scripts/mcp_servers/mdq/mdq_server.py` (373 lines total).
   - The `attach_auth_middleware(cast(_FastAPIApp, app), "")` call the doc is pointing to
     is currently at **`scripts/mcp_servers/mdq/mdq_server.py:368`** — matching the
     issue's note that a prior review already found it at 368; it has not shifted
     further since.
   - Two other docs (`docs/04_mcp_03_01_dispatch-and-routing.md:139` and
     `docs/04_mcp_07_tool_schema_export_policy.md:32,54`) also reference bare
     `mdq/server.py` without a line number — these are lower-precision (no line number to
     go stale) but share the same wrong-filename pattern; include them in the audit pass
     as candidates, not as a mandatory direct fix, since the issue's "3 known errors"
     scope was specifically the line-numbered reference.

3. **`docs/04_mcp_05_02_auth-profiles-and-sandboxing.md:72`** lists four config-model
   import paths that `agent/security_audit_config.py` imports:
   `mcp_servers.shell.models`, `mcp_servers.git.models`,
   `mcp_servers.github.models_config`, `mcp_servers.cicd.models`. Three of the four are
   wrong (the fourth, `github.models_config`, is already correct):

   | Doc's current (wrong) path | Actual file on disk | Correct dotted import path |
   |---|---|---|
   | `mcp_servers.shell.models` | `scripts/mcp_servers/shell/shell_models.py` | `mcp_servers.shell.shell_models` |
   | `mcp_servers.git.models` | `scripts/mcp_servers/git/git_models.py` | `mcp_servers.git.git_models` |
   | `mcp_servers.cicd.models` | `scripts/mcp_servers/cicd/cicd_models.py` | `mcp_servers.cicd.cicd_models` |
   | `mcp_servers.github.models_config` | `scripts/mcp_servers/github/models_config.py` | (correct as-is, no change) |

   Correct paths were cross-checked against actual imports in
   `scripts/agent/security_audit_config.py` (lines 48, 66, 98).

It remains unknown whether the same bare-name-vs-prefixed-name drift exists elsewhere
across the full set of 45 `docs/04_mcp_*.md` files beyond the instances found so far.

## Reason for change
These are confirmed factual errors in reference documentation that mislead a developer
into looking for files that do not exist, or into using an import path that would raise
`ImportError`/`ModuleNotFoundError` if copy-pasted. Given the naming-drift pattern is
already known to recur (per `04_mcp_07_tool_schema_export_policy.md`'s own note and the
related `issues/20260719-193357_risks.md` tracking issue), a systematic audit is
warranted to find any remaining instances before they accumulate further.

## Implementation intent
- Directly correct the 3 confirmed-wrong references identified above, in the doc files
  where they actually live (note the corrected location for error #2).
- Separately, perform a mechanical, file-existence-based audit: extract every
  file-path-like string (bare and prefixed module/file names, e.g. `*.py`, dotted
  `mcp_servers.*` import paths) from all 45 `docs/04_mcp_*.md` files, and check each
  against the current repository structure (`scripts/mcp_servers/**`,
  `scripts/agent/**`, etc.) using `find`/`ls`/`grep`, not by re-deriving expected names.
- Do not fix anything found only by the audit in this same change — file audit findings
  as new, separately scoped follow-up issues (per the source issue's explicit
  "Out of Scope" instruction).
