# Confirm Actual .gguf Model Filenames Loaded by External LLM Hosts

## Priority
High (blocks final literal-value correction in plans/20260819-174858_plan.md)

## Target files
- docs/01_overview-files-01-build.md
- docs/02_deployment.md
- docs/03_rag_05_1-configuration-reference.md

## Background
Three different documents currently disagree on the canonical `.gguf` model filenames for the chat LLM and embedding LLM:
- `docs/01_overview-files-01-build.md:31-32`: chat LLM = `Qwen3.6-Instruct-Q4_K_M.gguf`, embedding = `multilingual-E5-small.gguf` (384 dim)
- `docs/02_deployment.md:47-49`: embedding = `multilingual-e5-small-Q8_0.gguf`, and two chat LLMs listed: `gemma-4-e4b-it-Q4_K_M.gguf` and `Qwopus3.6-35B-A3B-v1-MTP-Q4_K_M.gguf`
- `docs/03_rag_05_1-configuration-reference.md:68`: embedding model name given as `all-MiniLM-L6-v2` (384 dim) — a third, architecturally distinct name for the same dimension slot

No deploy script or config file in this repo references a `.gguf` filename (`grep -rn -i "gguf" deploy/ config/*.toml` returns zero matches). The chat LLM (`llm_url = "http://192.168.11.197:8080"`) and embedding LLM (`embed_url = "http://192.168.11.238:8081"`) are served by external `llama-server` processes on two different remote hosts, not started or configured by anything under `deploy/` in this repo. `deploy/setup_services.sh` only health-checks the configured URLs; it does not start or reference the model files.

## Problem
The repository cannot determine the actual `.gguf` filenames loaded by the external llama-server instances from source alone. Three documentation files disagree, and there is no single source of truth in the codebase.

## Reason for change
A canonical, verified model filename table is needed in `docs/02_deployment.md` §1.4 to serve as the single source of truth, with cross-references from the other two documents. This unblocks the structural documentation fix (canonical table location, cross-references, and the new `tools/check_docs_consistency.py` model-reference consistency check) planned in `plans/20260819-174858_plan.md`.

## Implementation intent
Obtain the actual model filenames from the maintainer/operator who has access to the external hosts, then update the documentation to reflect the confirmed values.

## Implementation instructions
1. Ask the maintainer/operator to report, for each host:
   - `192.168.11.197:8080` (chat LLM) — the `llama-server` command line used to start it (or an equivalent `/props` / `/health` endpoint response that names the loaded model file)
   - `192.168.11.238:8081` (embedding LLM) — the same
2. Once confirmed, update `docs/02_deployment.md` §1.4 with the verified filenames
3. Propagate the confirmed values to `docs/01_overview-files-01-build.md` and `docs/03_rag_05_1-configuration-reference.md` per the design in `plans/20260819-174858_plan.md`
4. The structural documentation fix (canonical table location, cross-references, and the new consistency check tool) can proceed independently of this confirmation

## Acceptance criteria
- `docs/02_deployment.md` §1.4 contains the confirmed, canonical `.gguf` filenames for both chat and embedding models
- `docs/01_overview-files-01-build.md` and `docs/03_rag_05_1-configuration-reference.md` are updated to match or link to the canonical table in `docs/02_deployment.md`
- No contradictory model filenames remain in any of the three documents
