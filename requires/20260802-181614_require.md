- **Finding: unconfirmable.** There is no evidence anywhere in the repository history, design
  docs, or plans that `20` was derived from measurement or load testing. It should be

  choice.

## Problem
`docs/03_rag_02_08_ingestion_pipeline-shared.md` describes what `_MAX_FTS_TOKENS=20` does
(truncates FTS5 query tokens to prevent query explosion) but omits any statement of its
rationale or confidence level. A future engineer reading the doc cannot tell whether `20` is a
carefully tuned, load-tested value or an untested guess — which matters if they consider
raising/lowering it for performance or recall reasons.

## Reason for change
Per the source issue, undocumented rationale for a tunable constant blocks future performance
tuning: there is no basis for judging whether `20` is still appropriate, and no signal that the
value has (or has not) been validated. Making the "unconfirmed/rule-of-thumb" status explicit
in the doc gives future maintainers accurate expectations and flags it as a candidate for
follow-up measurement if desired.
