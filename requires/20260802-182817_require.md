# Simplify docs/03_rag_03_07 test-name/assertion listing

## Priority
Low

## Target files
- `docs/03_rag_03_07_query_pipeline-tests.md` (sections 8.1 and 8.2 only)

## Background
`docs/03_rag_03_07_query_pipeline-tests.md` documents the RAG query pipeline's deterministic
regression test suite. Sections 8.1 and 8.2 currently transcribe, verbatim, the name, mode, and
exact assertion text of all 18 tests defined in `tests/test_rag_quality_regression.py` (8 tests
in the 8.1 table, 10 tests in the 8.2 table), plus a "訂正" correction note about a since-removed
test name.

## Problem
Verbatim transcription of test names and assertions in documentation duplicates information that
already lives, and is authoritative, in the test source file itself. As of this review, the 18
test function names in `tests/test_rag_quality_regression.py` still match the doc's listing
exactly (verified: `grep -n "def test_" tests/test_rag_quality_regression.py` returns 18 matches,
all present in the doc's two tables), but this is precisely the kind of listing that silently goes
stale whenever a test is renamed, added, removed, or its assertion changed — every such change
would require a matching doc edit that is easy to forget, doubling maintenance effort for no
lasting benefit.

## Reason for change
Test code is the single source of truth for exact test names and assertion behavior. The
documentation should describe the *behavioral guarantees* the test suite provides at a level
useful for readers who want to understand system correctness properties, and should point to the
test file for exact, always-up-to-date detail — rather than maintaining a second, drift-prone copy
of that detail in Markdown.

## Implementation intent
Replace the two per-test tables in sections 8.1 and 8.2 with a concise "guaranteed properties"
summary: a small set of behavioral-guarantee statements (e.g., deterministic fallback behavior on
embed failure, RRF score ordering/monotonicity, semantic cache hit/miss/invalidation semantics,
diagnostics counters reflecting fusion mode / FTS errors / refiner outcomes) that describe what the
test suite collectively verifies, without naming every individual test function or transcribing
its exact assertion. Keep an explicit pointer directing readers to
`tests/test_rag_quality_regression.py` (and the "how to run" command) for exact test names and
assertions. The existing "訂正" correction note and the "参考" pointer to sibling test files
(`test_rag_pipeline.py`, etc.) in section 8.2 are unrelated informational asides tied to specific
now-removed/out-of-scope test names — evaluate whether they still add value once the verbatim
tables are gone, and drop or fold them into the new summary if they no longer serve a purpose (the
sibling-test-files pointer is separate from and should be preserved regardless, since it is not a
verbatim listing).

## Implementation instructions
1. Read the current content of `tests/test_rag_quality_regression.py` directly (not just this
   requirement or the prior review) to derive the "guaranteed properties" summary, since tests may
   have changed between review and implementation.
2. In `docs/03_rag_03_07_query_pipeline-tests.md`, replace the two Markdown tables under section
   8.1 (`### 8.1 決定論的リグレッションテスト`) and section 8.2 (`### 8.2 追加されたテスト`) with
   prose or bullet-list summaries of guaranteed behavioral properties, grouped sensibly (e.g., by
   fusion/RRF behavior, semantic cache behavior, diagnostics/counters behavior, refiner fallback
   behavior). Do not name individual test functions or transcribe their exact assertions in the
   new summary.
3. Retain (or introduce, if removed) a clear pointer to `tests/test_rag_quality_regression.py` as
   the authoritative source for exact test names and assertions, and retain the "実行:" run command
   (`uv run pytest tests/test_rag_quality_regression.py -v`).
4. Preserve the section 8.2 "参考" pointer to the other test files (`test_rag_pipeline.py`,
   `test_rag_pipeline_stage.py`, `test_rag_pipeline_service.py`, `test_rag_pipeline_mcp_service.py`,
   `test_mcp_rag_pipeline.py`) and the note that this document section is scoped only to
   `test_rag_quality_regression.py`, since that is not a verbatim test listing and remains useful
   orientation.
5. Do not modify any file other than `docs/03_rag_03_07_query_pipeline-tests.md`. Do not modify
   `tests/test_rag_quality_regression.py` or any other test file.
6. Keep the rest of the document (frontmatter, section 8 heading, "Related Documents", "Keywords")
   unchanged unless the edit incidentally requires updating a "Keywords" entry that specifically
   referenced removed content (unlikely; verify before touching).

## Acceptance criteria
- Sections 8.1 and 8.2 of `docs/03_rag_03_07_query_pipeline-tests.md` no longer contain a table (or
  equivalent verbatim listing) enumerating individual test names alongside their exact assertion
  text.
- A "guaranteed properties" summary describing the behavioral guarantees verified by
  `tests/test_rag_quality_regression.py` is present and derived from the current test file
  content.
- A clear pointer to `tests/test_rag_quality_regression.py` (as the source of exact test
  names/assertions) remains in the document, along with the existing run command.
- No other file is modified.

## Tests
Documentation-only change; no test execution is required. If feasible, confirm during review that
the retained run command (`uv run pytest tests/test_rag_quality_regression.py -v`) is still
accurate and that the new summary's claims are consistent with the current test file content.
