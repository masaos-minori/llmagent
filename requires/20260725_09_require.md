# Background task failure threshold does not stop the agent

## Priority

Low-Medium

## Target Files

- `scripts/agent/orchestrator.py` — `_discard_and_log()`, `BG_FAILURE_THRESHOLD`, first-turn background task creation

## Background

When a background task fails, `_discard_and_log()` counts consecutive failures and logs warnings. At a threshold of 5 consecutive failures, only an error log is emitted — the agent continues operating normally.

## Problem

In `orchestrator.py:580-614`:

```python
def _discard_and_log(self, task: asyncio.Task[Any]) -> None:
    exc = task.exception()
    if exc is not None:
        if isinstance(exc, asyncio.CancelledError):
            self._consecutive_bg_failures = 0
        else:
            self._consecutive_bg_failures += 1
            if self._consecutive_bg_failures == 1:
                logger.warning("First background task failure: %s", exc)
                if isinstance(exc, Exception) and self._on_error is not None:
                    try:
                        self._on_error(exc)
                    except Exception as notif_err:
                        logger.error(...)
            elif self._consecutive_bg_failures >= BG_FAILURE_THRESHOLD:
                logger.error(
                    "Consecutive background task failures (%d): %s",
                    self._consecutive_bg_failures,
                    exc,
                )
            else:
                logger.warning(...)
```

`BG_FAILURE_THRESHOLD` is set to 5 (`orchestrator.py:51`). Even after 5 consecutive failures, the agent continues operating. This means important background functionality (e.g., auto-generation of initial messages) stops silently without user awareness. Additionally, when the `_on_error` callback raises an exception, it is only logged via `logger.error()` and never notified to the user.

## Reason for Change

Silent degradation of background functionality reduces system reliability. Users may not realize that critical features have stopped working. The current design only logs failures but takes no action to alert users or mitigate the impact.

## Implementation Intent

Add user notification when background task failures reach the threshold. Provide options to pause agent operation for critical background tasks. Ensure error notifications propagate to the user even if the callback fails.

## Implementation Instructions

1. When `BG_FAILURE_THRESHOLD` is reached, display a warning message to the user indicating which background feature has stopped.
2. Add a configurable option to pause agent operation when critical background tasks fail.
3. Wrap the `_on_error` callback invocation in a try-except that ensures the error is always communicated to the user, even if the callback itself fails.
4. Log the specific background task name alongside the failure count for better diagnostics.

## Acceptance Criteria

- [ ] User receives warning when background task failures reach threshold
- [ ] Critical background task failures can trigger agent pause
- [ ] Error notifications always reach the user regardless of callback behavior
- [ ] Failure logs include specific background task names
