# Fix: dead `ctx.workflow is None` check in `_recover_pending_approvals()`

## Priority
Low

## Target files
- `scripts/agent/startup.py` (`StartupOrchestrator._recover_pending_approvals()`, lines 515-520)
- `scripts/agent/context.py` (`AgentContext.__init__()`, `WorkflowState` definition — reference only)

## Background
`StartupOrchestrator._recover_pending_approvals()` (`scripts/agent/startup.py:515-520`) begins
with:

```python
async def _recover_pending_approvals(self) -> None:
    """Restore workflow approval-pending state from a previous session."""
    ctx = self._ctx
    if ctx.workflow is None:
        return
    store = StateStore()
    ...
```

`AgentContext.__init__()` (`scripts/agent/context.py:271-276`) unconditionally assigns:

```python
def __init__(self) -> None:
    """Create an empty AgentContext with default state objects."""
    self.conv = ConversationState()
    self.turn = TurnState()
    self.stats = RuntimeStats()
    self.workflow = WorkflowState()
    ...
```

`WorkflowState` (`scripts/agent/context.py:205-218`) is a plain dataclass-like state container
with no `Optional` typing; `self.workflow` is typed and populated as `WorkflowState`, never
`WorkflowState | None`.

## Problem
Verified against current source on 2026-08-04:
- `scripts/agent/context.py` contains exactly one assignment to `self.workflow` in the whole
  codebase (`grep -rn "\.workflow\s*=" scripts/agent` → only `context.py:276:
  self.workflow = WorkflowState()`). No method of `AgentContext`, `Orchestrator`, or any command
  handler reassigns `ctx.workflow` to `None` at any point.
- `grep -rn "ctx.workflow" scripts/agent` shows every other reference across
  `scripts/agent/orchestrator.py`, `scripts/agent/tool_audit.py`,
  `scripts/agent/commands/cmd_workflow.py`, and `scripts/agent/commands/cmd_config_stats.py` is a
  direct attribute access (`ctx.workflow.workflow_id`, `ctx.workflow.approval_pending`, etc.) with
  no `None` check anywhere else. `startup.py:518` is the only `is None` check on `ctx.workflow` in
  the codebase.
- Because `ctx.workflow` is always a `WorkflowState` instance from the moment `AgentContext` is
  constructed, `if ctx.workflow is None: return` at `startup.py:518` can never evaluate `True` at
  runtime. It is unreachable/dead code.
- Existing tests in `tests/agent/test_startup.py`
  (`TestStartupOrchestratorRecoverPendingApprovals`) always set
  `ctx.workflow = MagicMock()` (a non-`None` object) before calling
  `_recover_pending_approvals()`, so no existing test exercises or depends on the `None` branch.

The practical effect is limited to a minor amount of wasted work (a `StateStore()` connection and
a `find_all_pending_approvals` query are always executed, since the guard never short-circuits),
but the code's apparent intent — "skip pending-approval recovery when workflow tracking is
inactive/unavailable" — does not match its actual behavior, which risks misleading future readers
and maintainers.

## Reason for change
An unreachable conditional communicates a false invariant to future readers: it suggests
`ctx.workflow` can legitimately be absent and that recovery is meant to be skippable under some
condition, when in fact no such condition currently exists anywhere in the codebase. Left in
place, it either misleads maintainers into thinking there is a skip path to preserve during future
changes, or accumulates as unexplained dead code that erodes trust in the surrounding logic. The
source issue documents this as a `Low`-priority code-clarity issue, not a behavioral bug.

## Implementation intent
Remove the dead `if ctx.workflow is None: return` guard, since no code path in the current
codebase can make `ctx.workflow` `None`, and no design intent for a "workflow tracking disabled"
state currently exists to reattach the check to. This follows option (a) from the source issue.
Do not introduce a new flag or condition (option (b) from the source issue) — the source issue
itself defers that decision to "confirm at implementation time," and the investigation above found
no existing state (e.g., no `Orchestrator._workflow_def is None`-equivalent surfaced on `ctx`, no
config flag) that this check was ever wired to. Inventing a new gating condition would be
speculative behavior change, out of scope for a dead-code cleanup.

## Implementation instructions
1. In `scripts/agent/startup.py`, in `_recover_pending_approvals()` (currently lines 515-520),
   delete the two lines:
   ```python
   if ctx.workflow is None:
       return
   ```
   leaving `ctx = self._ctx` immediately followed by `store = StateStore()`.
2. Do not change any other line in `_recover_pending_approvals()` — the rest of the method's
   control flow (fetching pending approvals, selecting the most recent, updating
   `ctx.workflow.approval_pending` and `ctx.turn.pending_approval_*`, closing the store) is
   unaffected and out of scope.
3. Do not modify `scripts/agent/context.py`, `WorkflowState`, or `AgentContext.__init__()` — they
   are reference-only for this change; the issue's investigation confirmed no change is needed
   there.
4. Do not add a new flag, config option, or alternate condition in place of the removed check
   (see Implementation intent above) — that is out of scope per the source issue.
