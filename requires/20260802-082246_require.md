# Clarify priority-order semantics of the Canonical Source Rule's General Rule

## Priority
High

## Target files

- `docs/00_governance_07_needs-confirmation-inventory.md` (conditional — only if the intended semantics cannot be confirmed; add a new Needs Confirmation entry, e.g. `NC-018`)

## Background
`docs/00_governance_02_canonical-source-rule.md` defines the canonical-source conflict-resolution rules for the documentation set. Its `## General Rule` section presents a 3-item numbered list as the hierarchy for resolving conflicts between documents and between code and documents:

```
1. Code is the ultimate authority for behavioral claims
2. The most recently reviewed document is authoritative among conflicting documents
3. The area's document-guide identifies the canonical source within that area
```

Verified against the current file (as of this review): the list is still presented as plain numbered prose with no accompanying statement clarifying whether the numbering encodes priority order, and the `## Conflict Resolution Rule` and `## Known Issues Registration Rule` sections that follow do not address a direct tie-break between tier 2 ("most recently reviewed document") and tier 3 ("area's document-guide canonical source") when those two sources disagree. `docs/00_governance_07_needs-confirmation-inventory.md` was also checked and contains no existing entry (NC-001 through NC-017, all resolved) covering this ambiguity — it is not yet tracked anywhere.

## Problem
Readers (human or AI) cannot currently determine, from the document text alone:
1. Whether "1, 2, 3" in the General Rule is a strict priority ranking (rule 1 always wins over rule 2, which always wins over rule 3) or merely an enumeration with no implied ordering.
2. What the resolution outcome is when the "most recently reviewed document" (tier 2) and the "area's document-guide canonical source" (tier 3) point to conflicting answers.

This is the core logic used across the project to resolve document/code authority disputes, so the ambiguity risks conflict-resolution work proceeding in the wrong order or reaching the wrong conclusion.

## Reason for change
This ambiguity was flagged in `docs_review_governance.md` §4 (強化候補: General Ruleの優先順位) and §6 (Needs confirmation item: General Ruleの優先順位適用順序), and is confirmed still present in the current document. It is High priority because the Canonical Source Rule is foundational governance infrastructure referenced by conflict-resolution workflows elsewhere in the doc set.

## Implementation intent
Add an explicit statement to the `## General Rule` section of `docs/00_governance_02_canonical-source-rule.md` confirming that the numbered list denotes strict priority order (lower number = higher priority, higher-priority tier wins on conflict), and add an explicit tie-break statement for tier 2 vs. tier 3 conflicts specifically.

If the intended semantics (in particular, the tier-2-vs-tier-3 tie-break) cannot be confirmed from existing project context (e.g., no prior ADR, review note, or document owner input settles it), do not assert an unconfirmed interpretation as fact.
