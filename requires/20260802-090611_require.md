# Close out cross-directory audit of scripts/mcp_servers/ naming-drift documentation

## Priority
Low

## Target files
- `docs/01_overview-files-03-scripts-part4.md` (file/ section, lines ~40-62) — verification only, no edit required
- `scripts/mcp_servers/*/` (all subdirectories, for cross-reference)

## Background
A prior review confirmed a filename-documentation drift (generic `server.py`/`tools.py`/`models.py`
documented vs. actual service-prefixed filenames) in 7 `scripts/mcp_servers/` subdirectories:
`web_search`, `github` (tracked in
`issues/20260802-073738_files_03_scripts_part4_web_search_github_naming_drift.md`) and `shell`,
`rag_pipeline`, `cicd`, `mdq`, `git` (tracked in
`issues/20260802-073738_files_03_scripts_part5_naming_drift_and_db_fts.md`). Neither of those issues
had checked whether the same drift pattern also exists in the remaining, not-yet-reviewed
`scripts/mcp_servers/` subdirectories.

## Problem
It was unverified whether any `scripts/mcp_servers/` subdirectory outside the 7 already tracked
still contains undocumented filename drift, and whether the full subdirectory inventory itself was
even accounted for.

## Reason for change
This requirement formalizes the outcome of performing that audit now, so the tracking trail is
complete and the next phase (require-to-plan / doc-fix issue filing) does not need to repeat the
investigation.

### `file/` — spot-checked, confirmed accurate (no drift)
Actual files in `scripts/mcp_servers/file/` (19 files, verified via `find`, excluding `__pycache__`):
`__init__.py`, `common.py`, `delete_formatter.py`, `delete_models.py`, `delete_server.py`,
`delete_service.py`, `delete_tools.py`, `read_business.py`, `read_models.py`, `read_security.py`,
`read_server.py`, `read_service.py`, `read_static_helpers.py`, `read_tools.py`,
`write_formatter.py`, `write_models.py`, `write_server.py`, `write_service.py`, `write_tools.py`.

`docs/01_overview-files-03-scripts-part4.md` (lines ~40-62, "file/" section) already documents
exactly these 19 filenames with the correct per-operation prefixes (`read_*`, `write_*`,
`delete_*`) — this section does not exhibit the generic-filename drift seen in the web_search/
github sections of the same file. No fix is needed here.

### `browser/` — not a documentation-drift case
`scripts/mcp_servers/browser/` exists on disk but is **untracked by git** (`git ls-files
scripts/mcp_servers/browser/` returns nothing) and contains only stale `__pycache__/*.pyc` remnants
(from both a pre-rename generic-name era — `server.cpython-314.pyc`, `tools.cpython-314.pyc`,
`models.cpython-314.pyc`, `service.cpython-314.pyc` — and a later prefixed-name era —
`browser_server.cpython-314.pyc`, etc.). `git log --oneline --all -- scripts/mcp_servers/browser/`
shows the directory's functionality was merged into `web_search` via commit `3c4fbe066` ("feat: make
RuntimeToolRegistry sole routing authority; merge browser-mcp into web-search-mcp"). There is no
`browser` entry in `docs/01_overview-files-03-scripts-part*.md` and no `[mcp_servers.browser]`
section in `config/agent.toml`, so nothing documents this directory and there is no drift to fix.
It is an orphaned build artifact, not a naming-drift case, and is out of scope here.
