# Update stale "MCP documentation consistency" section in `rules/toolchain.md`

## Priority

Low

## Target files

- `rules/toolchain.md` (lines 111-127, section "MCP documentation consistency")
- `tools/check_mcp_docs_consistency.py` (reference only — source of truth for the corrected
  content; no code change)

## Background

`rules/toolchain.md` lines 111-127 document the `check-mcp-docs` entry point with example
commands and a description of the checks it performs. This section was never updated after
`tools/check_mcp_docs_consistency.py` was deleted in commit `74906389` ("refactor: remove
unsupported MDQ tool/search surface and stale tool-count doc check") and later restored with a
completely different design in commit `5e34c14a6` ("fix: restore MCP docs consistency checker and
fix stale CI/doc references").

This requirement was verified directly against current source before being written:
- `rules/toolchain.md` lines 111-127 currently read exactly as follows:
  ```markdown
  ## MCP documentation consistency

  ```bash
  # Run all checks (startup, failopen, routing, active, toolcount)
  uv run check-mcp-docs

  # Skip specific checks
  uv run check-mcp-docs --skip active --skip toolcount
  ```

  The `check-mcp-docs` entry point is registered in `pyproject.toml`. It verifies:
  - Valid startup modes (persistent/ondemand/subprocess)
  - No fail-open wording for workflow_allowlist
  - Routing authority language consistency
  - Active MCP issue cross-references (MCP-01 through MCP-08)
  - Tool count consistency against canonical frozensets
  ```
- `tools/check_mcp_docs_consistency.py`'s actual `skip_choices` list (around line 241) is
  `["links", "removedfiles", "commanddrift", "portdrift", "tooldrift", "filerefs", "funcrefs"]`.
  Neither `active` nor `toolcount` is a valid `--skip` choice today.
- The module defines exactly two domain-specific check functions:
  - `check_port_drift` (line 110, severity `ERROR`) — compares doc-mentioned ports against
    `config/agent.toml`'s `[mcp_servers.*]` sections.
  - `check_tool_name_drift` (line 183, severity `WARNING`) — compares backtick-quoted tool names
    in docs against live `TOOL_LIST`-style entries in `scripts/mcp_servers/**/*.py`.
  - It also calls the generic checks shared via `tools/_docs_consistency_lib.py`:
    `check_broken_internal_links`, `check_removed_file_references`, `check_command_drift`,
    `check_file_path_references`, `check_function_references`. These same generic checks are
    also imported and used by `tools/check_agent_docs_consistency.py`.
- None of the check set described in `rules/toolchain.md` today (startup modes, fail-open wording,
  routing authority, active-issue cross-references, tool-count consistency) exists in the current
  module.

## Problem

`rules/toolchain.md`'s "MCP documentation consistency" section (lines 111-127) describes a
`check-mcp-docs` tool that no longer exists. A reader who copy-pastes the example command
`uv run check-mcp-docs --skip active --skip toolcount` will hit an argparse `choices` validation
failure, since `active` and `toolcount` are not valid `--skip` values in the current
implementation. The bulleted description of what the tool checks (startup modes, fail-open
wording, routing authority, active-issue cross-references, tool-count consistency) also no longer
matches what the tool actually does (port drift and tool-name drift, plus generic shared docs
checks).

## Reason for change

The stale documentation misleads any maintainer or contributor who consults `rules/toolchain.md`
to learn how to run or configure `check-mcp-docs`. While this does not break CI (the CI workflow
does not read this doc) and is not blocking, it is a source of confusion and wasted debugging time
if left uncorrected. Per `rules/coding.md`'s "Current behavior" classification, this is a
"Documentation fix required" case: the doc itself is wrong (stale example command, wrong check
descriptions) and should be corrected directly to match current code.

## Implementation intent

Update `rules/toolchain.md` lines 111-127 so that the "MCP documentation consistency" section
accurately reflects the current `tools/check_mcp_docs_consistency.py` implementation: correct
`--skip` choices in the example commands, and an accurate description of the two domain-specific
checks plus the shared generic checks. No behavior change to any script or tool — this is a
documentation-only correction.
