# Split the conflated Agent-layer / shell-mcp-server-layer allowlist warning descriptions in docs/04_mcp_*.md (shell-mcp)

## Priority
Medium

## Target files
- `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`
- `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md`
- (Reference pattern only, not itself a required edit target unless convenient: `docs/04_mcp_05_01_access-control-and-allowlists.md` lines 223-226, which already documents the analogous two-layer split for cicd's `workflow_allowlist` and should be used as the template.)

## Background
`shell-mcp` has two independent allowlist settings, `command_allowlist` and `shell_cwd_allowed_dirs`,
sourced from `config/shell_mcp_server.toml`. Two separate code paths emit warnings about these settings
being empty, and they do not check the same things:

1. **Agent layer** — `scripts/agent/repl_health.py::audit_security_defaults()` loads
   `ShellAuditConfig` via `scripts/agent/security_audit_config.py::load_shell_audit_config()`.
   `ShellAuditConfig` (lines 14-19 of `security_audit_config.py`) only carries `sandbox_backend` and
   `command_allowlist` — it has **no field for `shell_cwd_allowed_dirs`**. Consequently
   `audit_security_defaults()` (lines 543-551 of `repl_health.py`) only ever warns about
   `shell.command_allowlist` being empty:
   `"DENY-ALL detected: shell.command_allowlist is empty. shell-mcp will reject ALL shell commands. ..."`
   It never inspects or warns about `shell_cwd_allowed_dirs` at all.

2. **shell-mcp server layer** — `scripts/mcp_servers/shell/shell_service.py::build_service()`
   (lines 332-342) independently checks **both** settings and logs two distinct warnings:
   - `"shell_cwd_allowed_dirs is empty — all cwd values will be rejected"`
   - `"command_allowlist is empty — all commands will be rejected"`

So the two layers are not symmetric: `command_allowlist` emptiness is warned about independently by
*both* layers (with different message text), while `shell_cwd_allowed_dirs` emptiness is warned about
*only* by the shell-mcp server layer — the agent layer is structurally incapable of detecting it.

This is analogous to the already-fixed `cicd-mcp` `workflow_allowlist` case, which `docs/04_mcp_05_01_access-control-and-allowlists.md`
(lines 220-226) documents correctly with an explicit "Agent layer / cicd-mcp server layer" breakdown,
including the exact log message and source file/logger for each layer.

## Problem
The two target docs do not give shell-mcp the same treatment:

- `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`, "起動時の Audit" table (lines 35-46):
  the `command_allowlist` row only documents the agent-layer check ("空の場合（fail-closed）DENY-ALL 警告")
  and has no row at all for `shell_cwd_allowed_dirs`. Unlike the `workflow_allowlist` row in the same
  table, which explicitly states both layers warn and cross-references `04_mcp_05_01`, the
  `command_allowlist` row gives no indication that shell-mcp itself independently emits a second,
  differently-worded warning, and the doc gives no indication that `shell_cwd_allowed_dirs` is checked
  at all (by either layer).

- `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md` (lines 160-216): the "起動時の audit" and
  "ランタイムでの deny-all 状態の確認" sections quote only the agent-layer warning text
  (`"DENY-ALL detected: shell.command_allowlist is empty. shell-mcp will reject ALL shell commands..."`)
  without noting that shell-mcp's own process (`shell_service.py::build_service()`) logs a second,
  independent warning with different wording for the same condition, and a third, independent warning
  for `shell_cwd_allowed_dirs` that the agent-layer audit never produces. A reader who only watches the
  agent REPL log stream will never see any signal — from either layer's documented text — that
  `shell_cwd_allowed_dirs` is empty, because the agent layer does not check it and the doc does not
  say the shell-mcp server layer does.

An operator monitoring only the agent REPL output could reasonably (and incorrectly) believe that an
empty `shell_cwd_allowed_dirs` is silently safe or unmonitored, when in fact shell-mcp's own log stream
carries the signal. Conversely, an operator who sees only the shell-mcp warning
`"command_allowlist is empty — all commands will be rejected"` has no doc pointer back to the
agent-layer's differently-worded `DENY-ALL detected:` message for the same setting.

## Reason for change
Documentation accuracy affects incident-response speed and correctness. Both layers must be documented
individually — which process emits which exact message, for which setting — so operators know precisely
which log stream(s) to check for each of the two independent shell-mcp allowlist settings, and are not
misled into thinking the two layers check the same things.

## Implementation intent
Apply the same two-layer documentation pattern already used for cicd-mcp's `workflow_allowlist` in
`docs/04_mcp_05_01_access-control-and-allowlists.md` (lines 220-226) to shell-mcp's two allowlist
settings, in the two target docs. Do not merge or paraphrase the two layers into one description;
document each layer's exact source file, function/log-call site, and exact message text, and be
explicit that `shell_cwd_allowed_dirs` has no agent-layer equivalent check.
