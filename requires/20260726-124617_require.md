# Add lazy initialization or validation for SessionMessageRepository

## Priority

Medium

## Target Files

- `scripts/agent/session.py:35-37` — AgentSession.__init__ initialization
- `scripts/agent/session.py:128-130` — start() re-initialization
- `scripts/agent/session.py:64-68` — replace_messages() skip condition

## Background

The `SessionMessageRepository` is initialized with `session_id=None` in `__init__`, then re-initialized in `start()` after the session ID is assigned:

```python
def __init__(self, session_id: int | None = None) -> None:
    self.session_id = session_id
    self._message_repo = SessionMessageRepository(self.session_id)
```

This creates an inconsistency: `replace_messages()` skips saving when `session_id is None`, but `save()` and `save_many()` do not check this condition.

## Problem

If `save()` or `save_many()` are called before `start()`, they would use a `SessionMessageRepository` with `None` session ID, potentially causing data corruption or unexpected behavior.

## Reason for Change

Prevent potential data corruption from inconsistent session ID handling across different methods.

## Implementation Intent

Add either lazy initialization (only initialize `_message_repo` when needed) or explicit validation (raise error if session_id is None).

## Implementation Instructions

Option A (lazy initialization):
```python
@property
def _message_repo(self) -> SessionMessageRepository:
    if self.__repo is None and self.session_id is not None:
        self.__repo = SessionMessageRepository(self.session_id)
    elif self.__repo is None:
        raise RuntimeError("Cannot save messages: session has not been started")
    return self.__repo
```

Option B (explicit validation):
```python
def save(self, message: LLMMessage) -> None:
    if self.session_id is None:
        raise RuntimeError("Cannot save messages: session has not been started")
    # existing logic...
```

Choose Option A for cleaner API; Option B for simpler implementation.
