## Background
`issues/20260818_12_issue.md` requested a broad documentation-quality standardization pass across `docs/`. Verification against the current repository confirms several of the described defects are real and still present:
- Inconsistent EventBus terminology casing/spacing across docs: `EVENTBUS` (14), `Event Bus` (70), `EventBus` (9), `event-bus` (20), `eventbus` (567).
- Inconsistent bilingual terminology for the same governance concepts: "Known Issue" (38) vs "known issue" (9) vs "既知の問題" (13) vs "既知の課題" (1); "Needs Confirmation" (29) vs "Needs confirmation" (8) vs "確認が必要" (4) vs "要確認" (5).
- Duplicate bullet lines within a single `## Related Documents` section in at least 7 files (see Target files above).
- A self-referential/incorrect "Part 1" link and duplicated paragraph content within `docs/03_rag_03_02_query_pipeline-rag-pipeline-class.md`.
- Evidence references that cite exact source-code line numbers/ranges, which are inherently unstable as the referenced code evolves (found in `docs/00_governance_05_deprecated-items.md` and `docs/00_governance_07_needs-confirmation-inventory.md`, and likely elsewhere).

Two claims from the original issue could **not** be reproduced during verification and are therefore excluded from this requirement's scope:
- "Empty Keywords sections": a structural scan of all `## Keywords` sections in `docs/*.md` found none that are actually empty (all contain at least one keyword line).
- "Encoding artifacts" / general "typographical errors": no mojibake byte sequences, Unicode replacement characters (`U+FFFD`), or common English typo patterns were found in `docs/*.md`.

If a future pass finds concrete instances of these two items, they can be addressed in a separate, evidence-backed requirement.

## Problem
Documentation terminology and cross-reference structure are inconsistent in ways that are currently verifiable in the repository:
1. The same concepts (EventBus, Known Issue, Needs Confirmation) are spelled/cased/translated inconsistently across files, which harms search, machine-readable categorization, and AI retrieval accuracy.
2. Several `## Related Documents` sections list the same related file twice within one section, which is redundant and misleading about the actual relationship graph.
3. `docs/03_rag_03_02_query_pipeline-rag-pipeline-class.md` links to itself while labeling the link "Part 1" from within content that is already Part 1 — this link is either broken (should point elsewhere) or is vestigial duplicated content that should be removed/consolidated.
4. Some evidence/citation references embed exact source line numbers, which will silently go stale as `scripts/` files change, degrading traceability without any signal that the citation is out of date.

## Reason for change
These are low-severity but compounding defects: they reduce trust in cross-references, make automated/AI-driven document routing (which depends on consistent category and terminology vocabulary) less reliable, and create maintenance drift each time referenced source files are edited. Fixing them now, while the defects are still small in number and precisely located, is cheaper than after further documentation growth.

## Implementation intent
- Introduce one canonical English term and one canonical Japanese term for each of: EventBus, Known Issue, Needs Confirmation (and any other governance/category vocabulary discovered to have the same variant-spelling problem during implementation), and record them in a new terminology glossary document under `docs/`.
- Do not change any runtime identifiers, filenames, class names, config keys, or API names — only prose, headings, and documentation-internal cross-reference text change.
- For duplicate `## Related Documents` entries, remove the redundant bullet, keeping one canonical reference per related file.
- For the `docs/03_rag_03_02_query_pipeline-rag-pipeline-class.md` Part-link defect, determine the correct target of the "Part 1" reference (likely it should point to a different part/file, or the duplicated paragraph in section "2c." should be removed as vestigial) and correct it.
- Where evidence references currently cite raw source line numbers, replace them with stable anchors where practical: fully qualified symbol names (function/class names), configuration keys, or test identifiers. Where no stable symbol exists, keep the line reference but flag it explicitly as approximate (e.g., prefix with "~" as already done in some places) rather than removing the reference entirely.
- This is a documentation-only change. No `scripts/`, `tools/`, or other source code may be modified. Because EventBus terminology is included in scope, explicitly constrain that work to editing prose/headings in `docs/*.md` only — per `AGENTS.md` Global Rule 8, no EventBus implementation, configuration, or behavior changes are in scope, and none are needed since this requirement is documentation-only.
