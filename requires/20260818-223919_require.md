# Make config_loader.load_all() fail fast on missing required config in production

## Priority
Medium

## Target files
- `scripts/shared/config_loader.py`
- `scripts/rag/llm_client.py`
- `scripts/rag/pipeline.py`
- `scripts/agent/config_builders.py`
- `scripts/agent/commands/cmd_config.py`
- `tests/shared/test_config_loader.py`
- `tests/shared/test_config_hot_reload.py`
- `tests/shared/test_shared_boundary_conditions.py`

## Background
`config_loader.py` already centralizes configuration into a single file
(`_BASE_CONFIG_FILES = ("agent.toml",)` and `_REQUIRED_CONFIG_FILES =
frozenset(("agent.toml",))`). This is a leftover from an earlier
multi-file configuration layout (e.g. separate `common.toml`, `llm.toml`,
`rag.toml`, etc.), which has since been consolidated. However,
`ConfigLoader.load_all()` still defaults to `strict=False`: when a file in
`_BASE_CONFIG_FILES` is missing, `_load_single()` raises
`ConfigMissingError`, but `load_all()` catches it and only emits a
`logger.debug(...)` call, silently continuing with whatever was loaded so
far (verified in `scripts/shared/config_loader.py` lines 68-90).

All current production call sites invoke `load_all()` with no arguments,
so `strict=False` is the effective behavior everywhere today:
- `scripts/rag/llm_client.py` lines 68, 81 — `ConfigLoader().load_all()`
- `scripts/rag/pipeline.py` line 75 — `ConfigLoader().load_all()` inside
  `_ModuleConfig.get()`, itself wrapped in a broad
  `except (FileNotFoundError, ValueError)` that turns any load failure
  (including `ConfigMissingError`, a `ValueError` subclass) into a
  `logger.warning(...)` and an empty cached config
- `scripts/agent/config_builders.py` line 60 — `ConfigLoader().load_all()`
  inside `load_config()`
- `scripts/agent/commands/cmd_config.py` line 59 — `ConfigLoader().load_all()`

This means a missing `agent.toml` in production today does not
necessarily stop startup with a clear, actionable error; several paths
proceed silently or with a generic warning, which can result in the
process running with an effectively empty/degraded configuration.

## Problem
`ConfigLoader.load_all()` defaults to a lenient mode (`strict=False`) that
was designed to tolerate missing config files from a legacy multi-file
setup. This lenient default is still what production code paths use
today, so a missing required config file (`agent.toml`) is not
guaranteed to fail startup loudly — it can instead be silently skipped
(`config_loader.py`) or downgraded to a warning with an empty config
(`scripts/rag/pipeline.py`).

## Reason for change
The multi-file legacy layout no longer exists (`_BASE_CONFIG_FILES` is
already a single entry). Continuing to default to a silent-skip mode for
a now-single, now-required file provides no compatibility benefit and
only hides a genuine misconfiguration (missing `agent.toml`) until some
downstream feature fails in a confusing way. Failing fast and loudly at
startup is safer and easier to diagnose.

## Implementation intent
- Flip the default behavior of `ConfigLoader.load_all()` so that missing
  files listed in `_REQUIRED_CONFIG_FILES` raise `ConfigMissingError`
  by default, rather than requiring callers to opt in with
  `strict=True`.
- Any call site that legitimately needs the old lenient behavior (e.g.
  specific test fixtures or an explicit "config not yet present" dev
  flow) must request it explicitly and visibly, rather than relying on
  the implicit default.
- Ensure `scripts/rag/pipeline.py`'s `_ModuleConfig.get()` does not
  quietly swallow `ConfigMissingError` into a generic warning + empty
  config; a missing required config file should surface as a clear
  failure consistent with the other production call sites, not as a
  silently degraded pipeline.
- Remove any comments/docstrings in `config_loader.py` that describe the
  lenient default as accommodating a legacy multi-file config layout,
  since that layout no longer exists.

## Implementation instructions
1. In `scripts/shared/config_loader.py`, change `load_all()`'s default
   parameter to `strict: bool = True` (or equivalent behavior change),
   so missing files in `_REQUIRED_CONFIG_FILES` raise
   `ConfigMissingError` unless a caller explicitly opts out.
2. Update the `load_all()` docstring to describe the new default and to
   drop the framing around tolerating a legacy split-file layout.
3. Audit all production callers (`scripts/rag/llm_client.py`,
   `scripts/rag/pipeline.py`, `scripts/agent/config_builders.py`,
   `scripts/agent/commands/cmd_config.py`) to confirm they rely on the
   new strict-by-default behavior and do not pass `strict=False`
   unless there is a documented, intentional reason.
4. In `scripts/rag/pipeline.py`, adjust `_ModuleConfig.get()` so that a
   `ConfigMissingError` from `load_all()` is not caught by the broad
   `except (FileNotFoundError, ValueError)` and downgraded to a
   warning + empty config; it should propagate (or be handled with the
   same fail-fast intent as other production paths). Non-required,
   recoverable load issues can keep their current warning-and-continue
   behavior if applicable — only the required-file-missing case must
   fail loudly.
5. If any code path intentionally needs lenient/dev-mode behavior
   (e.g. a first-run wizard, a test harness, or a CLI helper that
   should work before `agent.toml` exists), make that call explicit by
   passing `strict=False` at that call site with a comment explaining
   why, rather than relying on a lenient global default.
6. Update `tests/shared/test_config_loader.py`,
   `tests/shared/test_config_hot_reload.py`, and
   `tests/shared/test_shared_boundary_conditions.py` for the new
   default: tests that currently rely on `load_all()` silently
   tolerating a missing file must now either pass `strict=False`
   explicitly or assert that `ConfigMissingError` is raised.

## Acceptance criteria
- `ConfigLoader.load_all()` defaults to strict behavior: a missing file
  listed in `_REQUIRED_CONFIG_FILES` raises `ConfigMissingError` without
  requiring the caller to pass `strict=True`.
- No production call site silently continues (via debug log, warning,
  or empty-config fallback) when a required config file is missing.
- `scripts/rag/pipeline.py`'s `_ModuleConfig.get()` no longer masks a
  missing-required-config failure as a warning with an empty cached
  config.
- Any remaining lenient/non-strict behavior is an explicit,
  intentionally-named opt-out at its call site (e.g. `strict=False`
  with a comment), not an implicit default.
- No code or docstring in `config_loader.py` still frames the lenient
  default as accommodating a legacy multi-file config layout.
- All existing and updated tests pass.

## Tests
- Update/add unit tests in `tests/shared/test_config_loader.py` to
  assert that `load_all()` with no arguments raises `ConfigMissingError`
  when a required config file is absent (replacing any test that
  currently asserts silent skipping as the default).
- Add/adjust a test confirming that a caller can still opt into the old
  lenient behavior by explicitly passing `strict=False`.
- Add or adjust a test around `scripts/rag/pipeline.py`'s
  `_ModuleConfig.get()` verifying that a missing required config file
  now surfaces as a failure rather than an empty cached config with
  only a warning log.
- Run the full existing test suite for `tests/shared/` and
  `tests/rag/` (or project-wide, per `rules/toolchain.md`) to confirm
  no regressions from the default-behavior change.
