# Fix contradictory Status/Evidence in "workflow optional mode" deprecated item

## Priority

Low

## Target Files

- `docs/00_governance_05_deprecated-items.md` — workflow optional mode entry

## Background

`docs/00_governance_05_deprecated-items.md` maintains an inventory of deprecated
configuration files, concepts, and commands, each with a `Status` field
(e.g. `Needs confirmation`) and an `Evidence` field describing the basis for
that status. The "workflow optional mode" entry under `## Deprecated Concepts`
(lines 25-29) currently reads:

```
- **workflow optional mode**
  - Current Replacement: none (replacement unknown)
  - Status: Needs confirmation
  - Notes: WorkflowEngine is now required, not optional
  - Evidence: Confirmed by current implementation
```

## Problem

The `Status: Needs confirmation` field contradicts the `Evidence: Confirmed by
current implementation` field within the same entry. `Needs confirmation` is
meant to signal that verification is still outstanding, but the `Evidence`
field states verification is already complete. This is further corroborated by
ADR-Workflow-Mandatory
(`docs/05_agent_03_03_turn-processing-flow-workflow-engine-part1.md`), which
formally documents that workflow execution is now always mandatory —
supporting that this item is, in substance, already confirmed.

Leaving the contradiction in place causes this already-resolved item to
continue being counted among genuinely unconfirmed `Needs confirmation`
entries, which can obscure prioritization of items that truly still require
investigation (per the review rule in
`docs/00_governance_07_needs-confirmation-inventory.md`, §Maintenance Rule).

## Reason for Change

Keep the deprecated-items inventory internally consistent so that `Status`
and `Evidence` fields for any given entry never contradict each other, and so
the `Needs confirmation` count accurately reflects only genuinely unverified
items.

## Implementation Intent

Update the `Status` field of the "workflow optional mode" entry to a value
consistent with its `Evidence` field (already confirmed), without altering
the `Evidence` or `Notes` content, which remain accurate.

## Implementation Instructions

1. In `docs/00_governance_05_deprecated-items.md`, locate the "workflow
   optional mode" entry (currently lines 25-29 under `## Deprecated
   Concepts`).
2. Change the `Status` field from `Needs confirmation` to a value that
   reflects the fact that this item has already been confirmed (e.g.
   `Confirmed` or another resolved-state value consistent with the document's
   existing Status vocabulary), so it no longer contradicts the `Evidence`
   field.
3. Leave `Current Replacement`, `Notes`, and `Evidence` fields unchanged, as
   their content is accurate.
4. Consider (optional, separate follow-up) whether
   `docs/00_governance_07_needs-confirmation-inventory.md`'s quarterly review
   rule should also cover `Needs confirmation` items listed in
   `docs/00_governance_05_deprecated-items.md`, to catch similar
   inconsistencies going forward.

## Acceptance Criteria

- [ ] The "workflow optional mode" entry's `Status` field no longer
      contradicts its `Evidence` field.
- [ ] No other content in `docs/00_governance_05_deprecated-items.md` is
      altered beyond the `Status` field of this one entry.
