# Add expiration for pending approvals across sessions

## Priority

Medium

## Target Files

- `scripts/agent/startup.py:506-534` — Pending approval recovery
- `scripts/agent/workflow/approval_ops.py:191` — find_all_pending_approvals
- `scripts/agent/tool_approval.py:115-123` — Approval flow implementation

## Background

Pending approvals are restored when a new session starts via `_recover_pending_approvals()`. This means an operation that requires approval can be automatically resumed without re-evaluation.

## Problem

```python
async def _recover_pending_approvals(self) -> None:
    results = find_all_pending_approvals(store.get_connection())
    task_id, approval = results[-1]
    ctx.workflow.approval_pending = True
    ctx.turn.pending_approval_id = approval.approval_id
```

No expiration check on recovered pending approvals. An attacker could start an approval-required operation, interrupt it, and have it automatically resume in the next session without re-authorization.

## Reason for Change

Prevent potential bypass of approval flows through session interruption/resumption.

## Implementation Intent

Add a TTL (Time-To-Live) to pending approvals. Expired approvals should be rejected during recovery rather than restored.

## Implementation Instructions

1. Add an `expires_at` field to `ApprovalRecord` model
2. Update `find_all_pending_approvals()` to filter out expired approvals
3. In `_recover_pending_approvals()`, reject expired approvals with a warning message
4. Run tests to confirm no regressions

## Acceptance Criteria

- [ ] Expired pending approvals are rejected during session startup
- [ ] Non-expired approvals are correctly restored
- [ ] Warning message indicates when an approval has expired
