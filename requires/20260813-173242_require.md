# Title
Narrow redundant except-clause and add constructor-arg validation in RobustSSEParser

## Priority
Low

## Target files
- `scripts/shared/sse_parser.py` (`RobustSSEParser.__init__`, `RobustSSEParser._is_valid_json`)
- `scripts/shared/llm_sse_stream.py` (caller of `RobustSSEParser(...)`, read-only reference for audit)
- `scripts/agent/services/config_reload.py` (`_apply_sse_reload_params`, read-only reference for audit)

## Background
`RobustSSEParser` (in `scripts/shared/sse_parser.py`) is the stateful SSE parser used by the
LLM streaming path. Its constructor accepts `malformed_retry: int` and
`heartbeat_timeout: float`, and its `_is_valid_json` helper validates JSON payloads inside a
`try/except` block. This file was the subject of a recent behavior-preserving refactor
(2026-08-13) that intentionally froze exception-handling behavior and left two small findings
unaddressed, tracked in `issues/20260813-133041_sse_parser_except_clause_and_input_validation.md`.

Verification performed for this requirement (2026-08-13):
- `orjson.JSONDecodeError.__mro__` is
  `(orjson.JSONDecodeError, json.decoder.JSONDecodeError, ValueError, Exception, BaseException, object)`,
  confirming `orjson.JSONDecodeError` is always also a `ValueError`.
- `RobustSSEParser.__init__` (lines 27-36 of `scripts/shared/sse_parser.py`) still performs no
  range checks on `malformed_retry` or `heartbeat_timeout`.
- Upstream, `scripts/agent/config_dataclasses.py`'s `LLMConfig.__post_init__` already calls
  `validate_llm_sse_heartbeat_timeout` / `validate_llm_sse_malformed_retry`
  (`scripts/agent/services/config_validators.py`), which reject negative
  `sse_heartbeat_timeout` / `sse_malformed_retry` — but only at dataclass construction time.
- `scripts/agent/services/config_reload.py::_apply_sse_reload_params` (lines 384-403) applies
  hot-config-reload updates to `ctx.cfg.llm.sse_heartbeat_timeout` and
  `ctx.cfg.llm.sse_malformed_retry` via direct attribute assignment after coercing the raw
  value with `_get_float`/`_get_int` — neither of which performs range validation and neither
  of which re-runs `__post_init__`. This is a real, currently-reachable path by which a
  negative value could reach `RobustSSEParser.__init__` unvalidated (a hot-reloaded config
  with a negative `sse_heartbeat_timeout` or `sse_malformed_retry`), bypassing the dataclass
  validators entirely.
- No current call site (`scripts/shared/llm_sse_stream.py:65`, and all call sites found in
  `tests/agent/test_llm_client.py`, `tests/shared/test_llm_sse_helpers.py`) passes a negative
  value today.

## Problem
1. `RobustSSEParser._is_valid_json`'s `except (orjson.JSONDecodeError, ValueError):` clause
   (line 89) lists a redundant member: `orjson.JSONDecodeError` is already a `ValueError`
   subclass, so catching `ValueError` alone is equivalent and clearer.
2. `RobustSSEParser.__init__` accepts `malformed_retry` and `heartbeat_timeout` without
   rejecting negative values. While the primary production config path
   (`LLMConfig.__post_init__`) validates these at config-construction time, the hot-config-reload
   path (`config_reload.py::_apply_sse_reload_params`) mutates the config attributes directly
   without re-validating, so a negative value can reach the parser constructor unchecked via
   that path today.

## Reason for change
Both are small correctness/robustness gaps identified during a behavior-preserving refactor
review of `scripts/shared/sse_parser.py`, deliberately deferred because that cycle's scope
excluded exception-clause changes and behavior changes. Fixing the except clause improves
clarity with zero behavior change. Adding constructor-time validation closes a real gap (the
hot-reload bypass) rather than a purely theoretical one, and makes `RobustSSEParser` safe to
construct directly (e.g., in tests or future callers) without relying on upstream config
validation as the only guard.

## Implementation intent
1. Narrow the except clause in `_is_valid_json` from
   `except (orjson.JSONDecodeError, ValueError):` to `except ValueError:`. This is behavior-neutral
   given the confirmed subclass relationship.
2. Add constructor-time validation to `RobustSSEParser.__init__`: reject negative
   `malformed_retry` and negative `heartbeat_timeout` by raising `ValueError` with a message
   that includes the offending value and parameter name. Zero must remain valid for both
   (matches existing config validators' `>= 0` boundary and `check_heartbeat`'s existing
   `<= 0` short-circuit for `heartbeat_timeout`).

## Implementation instructions
1. In `scripts/shared/sse_parser.py`, change line 89 from
   `except (orjson.JSONDecodeError, ValueError):` to `except ValueError:`. No other changes to
   `_is_valid_json`.
2. In `scripts/shared/sse_parser.py`, at the top of `RobustSSEParser.__init__` (before the
   existing assignment statements), add validation, e.g.:
   ```python
   if malformed_retry < 0:
       raise ValueError(f"malformed_retry must be >= 0, got {malformed_retry}")
   if heartbeat_timeout < 0:
       raise ValueError(f"heartbeat_timeout must be >= 0, got {heartbeat_timeout}")
   ```
   Match the wording style already used in
   `scripts/agent/services/config_validators.py::validate_llm_sse_heartbeat_timeout` /
   `validate_llm_sse_malformed_retry` for consistency.
3. Do not change `_parse_line`, `feed`, `check_heartbeat`, `_is_keepalive`, `_mark_activity`, or
   `_anext_or_done`. Do not change SSE frame-parsing behavior, heartbeat timing, or the
   malformed-frame budget-exceeded behavior in any way beyond the two items above.
4. Before finalizing, grep all `RobustSSEParser(` construction call sites in `scripts/` and
   `tests/` (already enumerated in Background) to reconfirm none pass a negative value; if a
   new call site appears during implementation that would pass a negative value, treat that as
   a blocking finding, not something to silently work around.
5. Do not modify `scripts/agent/services/config_reload.py` or
   `scripts/agent/config_dataclasses.py` as part of this change — the hot-reload validation gap
   is documented here as motivating evidence only; closing it is out of scope for this
   requirement (the new `RobustSSEParser.__init__` check itself will catch a negative value
   arriving via that path, at construction time in `stream_once`, and raise `ValueError`
   there instead of accepting it silently).

## Acceptance criteria
- `_is_valid_json`'s except clause has exactly one exception type: `ValueError`.
- All existing malformed-JSON tests pass unchanged (no test assertions need updating for item 1).
- `RobustSSEParser(malformed_retry=-1, heartbeat_timeout=0.0)` raises `ValueError` mentioning
  `malformed_retry` and `-1`.
- `RobustSSEParser(malformed_retry=0, heartbeat_timeout=-1.0)` raises `ValueError` mentioning
  `heartbeat_timeout` and `-1.0`.
- `RobustSSEParser(malformed_retry=0, heartbeat_timeout=0.0)` (the boundary) succeeds without
  raising.
- No production call site behavior changes (all current callers pass non-negative values).
