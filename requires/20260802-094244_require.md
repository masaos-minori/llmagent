# Consolidate duplicate/inconsistent `01_overview.md` back-references across Overview/Architecture detail files

## Priority
Medium

## Target files
- `docs/01_overview-arch-01-process.md`
- `docs/01_overview-arch-02-pipelines.md`
- `docs/01_overview-arch-03-features.md`
- `docs/01_overview-files-01-build.md`
- `docs/01_overview-files-02-rag.md`
- `docs/01_overview-files-03-scripts-part1.md`
- `docs/01_overview-files-03-scripts-part2.md`
- `docs/01_overview-files-03-scripts-part3.md`
- `docs/01_overview-files-03-scripts-part4.md`
- `docs/01_overview-files-03-scripts-part5.md`
- `docs/01_overview-files-04-shared-part1.md`
- `docs/01_overview-files-04-shared-part2.md`
- `docs/01_overview-files-05-config.md`
- `docs/01_overview-files-06-misc.md`

(14 detail files total: 3 `01_overview-arch-*.md` + 11 `01_overview-files-*.md`. `docs/01_overview.md` itself is the index file and is explicitly **out of scope** for content/structure changes — see Implementation instructions.)

## Background
`docs/01_overview.md` is the single index for the Overview/Architecture documentation set. Each of the 14 detail files listed above is meant to reference back to this index so readers can always navigate back to the single point of entry. This requirement was raised because the back-reference to `01_overview.md` is implemented inconsistently across the 14 files, and is duplicated (two separate mentions in the same file) in a subset of them.

## Problem
Verified by grepping all `docs/01_overview-*.md` files for `01_overview.md` (2026-08-02):

1. **Frontmatter reference (present in all 14 files, consistent):** Every one of the 14 detail files has a YAML frontmatter `related:` list whose last entry is a plain (non-linked) filename:
   ```yaml
   related:
     - 01_overview-arch-02-pipelines.md   # (varies per file)
     - 01_overview.md
   ```
   Example locations: `docs/01_overview-arch-01-process.md:15`, `docs/01_overview-files-04-shared-part1.md:11`, etc. This part is already consistent across all 14 files and is not duplicated.

2. **Body-level `## Related Documents` section (present in all 14 files, but inconsistent content):** Every one of the 14 files also has a `## Related Documents` section near the end of the file body (before `## Keywords` where present). However:
   - The **3 `01_overview-arch-*.md` files** (`01_overview-arch-01-process.md` line 94, `01_overview-arch-02-pipelines.md` line 97, `01_overview-arch-03-features.md` line 78) list the other two arch files **and additionally** repeat `01_overview.md` as a bare backtick-quoted bullet:
     ```markdown
     ## Related Documents

     - `01_overview-arch-02-pipelines.md`
     - `01_overview-arch-03-features.md`
     - `01_overview.md`
     ```
     This is a **duplicate** mention of `01_overview.md` within the same file (frontmatter + body both reference it).
   - The **11 `01_overview-files-*.md` files** list only sibling `01_overview-files-*.md` filenames in their `## Related Documents` section and **never include `01_overview.md`** in the body. Example (`docs/01_overview-files-06-misc.md`):
     ```markdown
     ## Related Documents

     - `01_overview-files-01-build.md`
     - `01_overview-files-02-rag.md`
     - `01_overview-files-03-scripts-part1.md`
     - `01_overview-files-04-shared-part1.md`
     - `01_overview-files-05-config.md`
     ```

3. **No clickable link exists anywhere.** Confirmed via grep for `01_overview.md)` (Markdown link syntax) across all 14 detail files: zero matches. Every existing mention of `01_overview.md` — in both the frontmatter `related:` list and the body `## Related Documents` bullets — is a plain/backtick-quoted filename, not an actual Markdown hyperlink (e.g. not `[01_overview.md](01_overview.md)`). This is true for `01_overview.md` mentions in all 14 files, unlike the index file itself (`docs/01_overview.md`), whose own table of contents uses real Markdown links, e.g. `[01_overview-arch-01-process.md](01_overview-arch-01-process.md)`.

Net effect: the 3 arch files carry a redundant double-reference to the index within a single file, while the 3 arch files and 11 files-variants are mutually inconsistent in whether the body-level `## Related Documents` section includes the index at all — undermining the intended "single point of navigation back to the index" design.

## Reason for change
Duplicated/inconsistent index references across 14 files create update-drift risk (e.g., if the index file is ever renamed or split, some files would need updating in two places, others in one, and 11 of them silently lack a body-level back-reference at all) and undermine the single-index navigation design intent recorded in `docs/01_overview.md`'s `## 実装意図` section.

## Implementation intent
Standardize on exactly one back-reference mechanism per detail file for "how a reader gets back to the index," applied uniformly across all 14 detail files, and remove the redundant second mention in the 3 arch files. Do not remove index navigation entirely — every detail file must retain a way to reference `01_overview.md`. Prefer making the retained reference an actual clickable Markdown link (since none currently exist) rather than a bare filename, but the primary goal of this requirement is consistency and de-duplication, not necessarily converting to hyperlinks — the next phase (plan) should decide the exact canonical format (e.g., keep the frontmatter `related:` entry as the sole back-reference and drop `01_overview.md` from all body `## Related Documents` sections, versus keeping a body-level link and dropping/keeping the frontmatter entry) and apply it uniformly.

## Implementation instructions
1. Do not modify `docs/01_overview.md` itself (its content, structure, or table of links) — it is out of scope for this change.
2. For all 14 detail files listed under "Target files," decide one canonical convention for referencing `01_overview.md` and apply it identically to every file. Concretely, this means choosing between (a) keep the existing frontmatter `related:` entry as the single source of truth and remove the `01_overview.md` bullet from the body `## Related Documents` section in the 3 arch files (so arch files match the files-* files' current pattern), or (b) keep a single body-level back-reference (as a real Markdown link) in every one of the 14 files and remove the `01_overview.md` entry from the frontmatter `related:` list everywhere. Whichever direction is chosen must be applied to all 14 files with no exceptions.
3. Do not touch the sibling cross-references between detail files (e.g., arch files referencing each other, files-* files referencing each other) — only the `01_overview.md` back-reference lines are in scope.
4. Do not touch any other content, headings, or structure in these 14 files beyond the specific back-reference line(s) being consolidated.
5. After edits, re-run a grep for `01_overview.md` across `docs/01_overview-arch-*.md` and `docs/01_overview-files-*.md` to confirm exactly one occurrence per file (in whichever location was chosen as canonical) and that the format/wording is identical across all 14 files.

## Acceptance criteria
- All 14 detail files (`docs/01_overview-arch-*.md` and `docs/01_overview-files-*.md`) reference `docs/01_overview.md` exactly once each, using the same format and location (frontmatter or body — whichever was selected as canonical).
- No detail file contains `01_overview.md` in both its frontmatter `related:` list and its body `## Related Documents` section simultaneously.
- No detail file is missing a back-reference to `01_overview.md` (every file must still be able to navigate back to the index).
- `docs/01_overview.md` itself is unchanged.
- Sibling cross-references between detail files (arch-to-arch, files-to-files) are unchanged.

## Tests
Documentation-only change; no automated tests required. Manual verification: for each of the 14 detail files, confirm the single retained `01_overview.md` reference is present, correctly formatted per the chosen canonical convention, and (if implemented as a Markdown link) resolves to the correct relative path `01_overview.md`. Re-run the grep commands used to verify this requirement (`grep -n "01_overview.md" docs/01_overview-*.md` and `grep -n "01_overview\.md)" docs/01_overview-arch-*.md docs/01_overview-files-*.md`) to confirm the final state matches the acceptance criteria.
