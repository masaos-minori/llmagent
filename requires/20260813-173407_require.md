# Title
Unify TOOLS/READ/WRITE derivation direction across tool groups in tool_constants.py

## Priority
Low

## Target files
- `scripts/shared/tool_constants.py`
- `tests/shared/test_tool_constants.py` (verification only — existing invariant tests must pass unchanged; no test edits expected)
- `tests/shared/test_tool_registry.py` (verification only — must pass unchanged)

## Background
`scripts/shared/tool_constants.py` holds the canonical frozenset definitions used for MCP tool
classification (consulted by `shared/tool_registry.py`, `shared/tool_executor_helpers.py`,
`agent/tool_policy.py`, and — per the module docstring — MCP routing logic). Verified against
current source (2026-08-13):
- `CICD_TOOLS` is defined directly as a frozenset literal; `CICD_WRITE_TOOLS` is a literal
  subset; `CICD_READ_TOOLS = CICD_TOOLS - CICD_WRITE_TOOLS` (lines 61-71).
- `RAG_TOOLS` is defined directly as a frozenset literal; `RAG_WRITE_TOOLS` is a literal subset;
  `RAG_READ_TOOLS = RAG_TOOLS - RAG_WRITE_TOOLS` (lines 52-74).
- `GIT_READ_TOOLS` and `GIT_WRITE_TOOLS` are both defined directly as frozenset literals;
  `GIT_TOOLS = GIT_READ_TOOLS | GIT_WRITE_TOOLS` (lines 92-112).
- `GITHUB_READ_TOOLS`, `GITHUB_WRITE_TOOLS`, and `GITHUB_DANGEROUS_TOOLS` are all defined
  directly as frozenset literals; `GITHUB_TOOLS = GITHUB_READ_TOOLS | GITHUB_WRITE_TOOLS |
  GITHUB_DANGEROUS_TOOLS` (lines 128-166).

So two derivation directions coexist for structurally equivalent (TOOLS, READ, WRITE) triples:
CICD/RAG derive READ as "TOOLS minus WRITE"; GIT/GITHUB derive TOOLS as "READ union WRITE (union
DANGEROUS)". `tests/shared/test_tool_constants.py` asserts the union/disjointness invariants
hold for each group (e.g. `test_git_tools_is_union_of_read_and_write`,
`test_rag_tools_is_union_of_read_and_write`, `test_github_tools_is_union_of_sub_sets`) but does
not assert a canonical derivation direction — both directions are currently valid per the
invariant tests. This was identified during a behavior-preserving refactor cycle on this file
(2026-08-13) and deliberately deferred rather than fixed inline, because that refactor's
special-case constraint (per `prompts/04_refactor.md`/`workflow.md` — this file is MCP routing
classification data) forbade any change to set membership or classification semantics, and an
inline "fix" to match one direction to the other in the same pass as an unrelated refactor risks
disguising a silent membership change as a consistency cleanup.

## Problem
`scripts/shared/tool_constants.py` derives frozensets in two different directions for what are
conceptually the same three-way relationship (TOOLS / READ / WRITE, optionally + DANGEROUS):
- CICD, RAG: `READ = TOOLS - WRITE` (TOOLS and WRITE are the literals; READ is derived).
- GIT, GITHUB: `TOOLS = READ | WRITE (| DANGEROUS)` (READ, WRITE, and DANGEROUS are the
  literals; TOOLS is derived).

Both directions are individually correct today (confirmed by the passing invariant tests), but
the inconsistency makes the file harder to reason about at a glance and invites a copy-paste
slip in future edits to this file (e.g. copying a GIT-style block as a template for a new group
that should have followed the CICD/RAG pattern, or vice versa).

## Reason for change
This is a pure internal-consistency cleanup with no external contract change (no change to which
tools belong to which classification set, and no change to any consumer of these constants). It
was explicitly deferred from a prior refactor cycle to avoid conflating a consistency fix with
that cycle's stricter "no membership/semantics change" constraint; this requirement gives it a
dedicated, narrowly-scoped cycle with its own membership-preservation verification step.

## Implementation intent
Pick one canonical derivation direction and apply it consistently to every tool group in
`scripts/shared/tool_constants.py` that has a TOOLS/READ/WRITE(/DANGEROUS) relationship
(`CICD_*`, `RAG_*`, `GIT_*`, `GITHUB_*`, and any other group in the file with the same shape,
e.g. `MDQ_TOOLS`/`MDQ_WRITE_TOOLS` if it fits the pattern). Recommended canonical direction:
"derive TOOLS as READ | WRITE (| DANGEROUS)" — this matches the majority-shape groups (GIT,
GITHUB) and keeps the smallest, most-obviously-correct literal sets (READ, WRITE, DANGEROUS) as
the source of truth, with the umbrella TOOLS set as a derived convenience. The alternative
direction ("derive READ as TOOLS - WRITE") is also acceptable if it proves to fit the file's
groups more naturally during implementation — the fixed requirement is consistency across all
groups, not a specific one of the two directions. This must be a **zero membership change**:
every exported frozenset must contain exactly the same string members before and after.

## Implementation instructions
1. Before making any change, write a one-off script (e.g. under a scratch location, not
   committed) that imports every exported frozenset from `scripts/shared/tool_constants.py`
   (`READ_TOOLS`, `WRITE_TOOLS`, `DELETE_TOOLS`, `RAG_TOOLS`, `RAG_READ_TOOLS`,
   `RAG_WRITE_TOOLS`, `CICD_TOOLS`, `CICD_READ_TOOLS`, `CICD_WRITE_TOOLS`, `MDQ_TOOLS`,
   `MDQ_WRITE_TOOLS`, `GIT_READ_TOOLS`, `GIT_WRITE_TOOLS`, `GIT_TOOLS`, `SHELL_TOOLS`,
   `WEB_SEARCH_TOOLS`, `GITHUB_READ_TOOLS`, `GITHUB_WRITE_TOOLS`, `GITHUB_DANGEROUS_TOOLS`,
   `GITHUB_TOOLS`, and the `get_all_mcp_tool_names()` return value) and dumps each as a sorted
   list to a baseline file (e.g. JSON or plain text, one frozenset name to sorted-members
   mapping). This is the byte-for-byte comparison baseline.
2. Identify every group in the file with a TOOLS/READ/WRITE(/DANGEROUS) relationship:
   `CICD_TOOLS`/`CICD_READ_TOOLS`/`CICD_WRITE_TOOLS`, `RAG_TOOLS`/`RAG_READ_TOOLS`/
   `RAG_WRITE_TOOLS`, `GIT_TOOLS`/`GIT_READ_TOOLS`/`GIT_WRITE_TOOLS`,
   `GITHUB_TOOLS`/`GITHUB_READ_TOOLS`/`GITHUB_WRITE_TOOLS`/`GITHUB_DANGEROUS_TOOLS`. Check
   whether `MDQ_TOOLS`/`MDQ_WRITE_TOOLS` fits the same shape (it currently has no
   `MDQ_READ_TOOLS` — decide during implementation whether introducing one is in scope, or
   whether it is a two-set group that doesn't need to change; if left alone, note why in the
   implementation notes/PR description).
3. Re-derive each identified group in the chosen consistent direction. For groups already in
   the target direction, leave them unchanged. For groups that need to switch direction (e.g. if
   choosing "TOOLS = READ | WRITE", then `CICD_TOOLS` and `RAG_TOOLS` change from being the
   literal to being the derived value, and `CICD_READ_TOOLS`/`RAG_READ_TOOLS` change from
   derived to literal) — the literal members that move must be transcribed exactly, with no
   additions, removals, or typos.
4. Re-run the baseline-dump script from step 1 after the change and diff the two outputs. The
   diff must be empty. If it is not empty, stop and do not proceed — treat any non-empty diff as
   a real (out-of-scope) classification change, not something to "fix" by adjusting the new
   code to match old behavior after the fact; instead, revert and redo the derivation for the
   offending group.
5. Do not modify `route_resolver.py`, `tool_executor.py`, `tool_executor_helpers.py`,
   `tool_registry.py`, `agent/tool_policy.py`, or `config/agent.toml` tool_names as part of this
   change — this is confined to `scripts/shared/tool_constants.py`.
6. Discard the one-off baseline-dump script after use; it must not be committed as a new file
   under `scripts/` or `tests/`.

- Every TOOLS/READ/WRITE(/DANGEROUS) group identified in Implementation instructions step 2 uses

- `tests/shared/test_tool_constants.py` passes unchanged (no test file edits).
- `tests/shared/test_tool_registry.py` passes unchanged (no test file edits).
- No file outside `scripts/shared/tool_constants.py` is modified (aside from the temporary,
  non-committed baseline-dump script, which must not appear in the final diff).
