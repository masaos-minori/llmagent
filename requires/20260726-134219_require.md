# Add guard tests for signal handler race condition prevention

## Background

The signal handler _sigterm_handler() directly modifies shared state (shutdown_requested, _input_coro), potentially causing race conditions with the main loop. Additionally, the _repl_loop sets/clears self._turn_active flag but the signal handler doesn't check this flag. If the main loop executes self._turn_active = False while the signal handler is running, a state inconsistency occurs. Furthermore, _close_resources() skips ctx.services when it's None, but the signal handler could execute just before ctx.services becomes None, resulting in incomplete shutdown.

## Problem

Signal handler execution timing differs between Unix (add_signal_handler) and Windows (call_soon_threadsafe), creating potential state inconsistencies.

## Reason for Change

Establish behavioral baseline through guard tests before any refactoring of these components.
