# Correct stale scope wording in MCP-002 (docs/04_mcp_90_inconsistencies_and_known_issues.md)

## Priority
Medium

## Target files
- `docs/04_mcp_90_inconsistencies_and_known_issues.md` (MCP-002 entry only)

## Background
`docs/04_mcp_90_inconsistencies_and_known_issues.md` catalogs known MCP-layer bugs and gaps
using a fixed 17-field template (see `docs/00_governance_04_known-issues-template.md`).
The MCP-002 entry tracks the rollout of `config_dependent` / `enabled` / `disabled_reason`
tool-runtime-availability metadata across the five MCP servers that expose tools
(`git-mcp`, `file-read-mcp`, `file-write-mcp`, `file-delete-mcp`, `web-search-mcp`).

## Problem
Source inspection (re-verified in this cycle) shows:
- `enabled`/`disabled_reason` are fully implemented in `scripts/mcp_servers/git/git_server.py`,
  `scripts/mcp_servers/file/read_server.py`, `scripts/mcp_servers/file/write_server.py`, and
  `scripts/mcp_servers/file/delete_server.py` (all delegate to a shared
  `availability_flags()` / per-tool helper and include `disabled_reason` in their tool
  listing response).
- `config_dependent` is set to `True` on the relevant tools in the git server
  (`scripts/mcp_servers/git/git_tools.py`) and the four file-server tool modules
  (`scripts/mcp_servers/file/read_tools.py`, `write_tools.py`, `delete_tools.py`).
- `scripts/mcp_servers/web_search/web_search_tools.py` sets `config_dependent: True`
  only on the `browser_fetch` tool and has no `enabled`/`disabled_reason` field
  anywhere in the web-search server code (`web_search_server.py`,
  `web_search_tools.py`, etc.) — this is the one remaining gap.

The MCP-002 entry's **Title** and **Current Description** fields already reflect this
narrow, web-search-only scope accurately (they specifically name
`web_search-mcp`/`browser_fetch`). However, the **Impact** and **Recommended Action**
fields still use plural, unscoped language — "他の MCP サーバーの config_dependent
移行と enabled/disabled_reason の実装が必要" (Impact) and "他の MCP サーバーの
config_dependent 移行と enabled/disabled_reason の実装完了後、本エントリを削除"
(Recommended Action) — which implies multiple other servers still need
`config_dependent` migration and `enabled`/`disabled_reason` implementation. That is
no longer true: git-mcp, file-read-mcp, file-write-mcp, and file-delete-mcp already
have both. Only `web-search-mcp` remains, and specifically only
`enabled`/`disabled_reason` (its `config_dependent` adoption for `browser_fetch` is
already done). Additionally, the **First Found** field is still the template's
unfilled placeholder value ("未確認") rather than a real date.

## Reason for change
Leaving the Impact/Recommended Action fields in their current unscoped, plural form
risks a future reader concluding that several servers still need this work, causing
wasted re-investigation or redundant re-implementation effort on servers where the
feature already ships. Keeping the Known Issues document precise about scope is the
purpose of the document.

## Implementation intent
Narrow the **Impact** and **Recommended Action** fields of the MCP-002 entry to name
`web-search-mcp` specifically (mirroring the precision already present in Title and
Current Description), rather than referring generically to "other MCP servers".
Address the **First Found** field per the template note in
`docs/04_mcp_90_inconsistencies_and_known_issues.md`'s migration note ("不足フィールドは
「未確認」で埋める") — if no real discovery date can be determined from history/plans,
leave it as the documented placeholder rather than fabricating a date, but confirm
this via a quick check (e.g. `git log`/related plan files) before deciding. Re-confirm
whether `Status: open` is still the right value now that 4 of 5 servers are done, or
whether it should be reworded to signal the narrowed remaining scope (the entry
should stay `open` since web-search-mcp's implementation is still outstanding — do
not mark it resolved/fixed).

## Implementation instructions
1. Open `docs/04_mcp_90_inconsistencies_and_known_issues.md` and locate the MCP-002
   entry (currently at the section starting `### MCP-002:`).
2. Update the **Impact** field from "他の MCP サーバーの config_dependent 移行と
   enabled/disabled_reason の実装が必要" to explicitly name `web-search-mcp` as the
   sole remaining server, e.g. wording equivalent to: "web-search-mcp のみ
   enabled/disabled_reason が未実装（他4サーバー — git-mcp/file-read-mcp/
   file-write-mcp/file-delete-mcp — は実装済み）".
3. Update the **Recommended Action** field similarly, replacing "他の MCP サーバーの
   config_dependent 移行と enabled/disabled_reason の実装完了後" with wording that
   names `web-search-mcp`'s `enabled`/`disabled_reason` implementation specifically
   as the remaining condition for closing/deleting the entry.
4. Check `git log --follow` on this doc (or its pre-migration source, if
   identifiable) and any related plan files referenced by MCP-002's **Related**
   field (`docs/04_mcp_03_06_tool-runtime-availability-metadata.md`) for a
   discoverable original-discovery date. If found, fill **First Found** with that
   date; if not, leave it as `未確認` (do not fabricate a date).
5. Leave **Status** as `open` (the underlying gap in web-search-mcp is still
   unresolved). Do not change **Severity**, **Area**, **Type**, **Source**,
   **Owner**, **Target**, **Related**, **Summary**, **Current Description**, or
   **Resolution Notes** unless they are found to be inconsistent with the corrected
   Impact/Recommended Action wording during editing.
6. Do not touch any other entry in the file (e.g. MCP-001) and do not modify any
   source code — this is a documentation-only correction.

## Acceptance criteria
- MCP-002's **Impact** and **Recommended Action** fields name `web-search-mcp`
  specifically as the only server with outstanding `enabled`/`disabled_reason` work,
  and no longer use unscoped "他の MCP サーバー" language implying multiple servers
  still need `config_dependent` migration.
- The **First Found** field is either filled with a verified real date or
  deliberately left as the template placeholder after a documented attempt to find
  one — no fabricated date is introduced.
- **Status** remains `open`; no other MCP-002 field is changed except as needed for
  internal consistency with the corrected Impact/Recommended Action text.
- No other entry in `docs/04_mcp_90_inconsistencies_and_known_issues.md` is modified.
- No source code file is modified as part of this change.
