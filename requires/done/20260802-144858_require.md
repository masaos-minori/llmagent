This is operational setup content, not checklist/design content, and it duplicates material that already exists elsewhere in the docs set.

Verification against current source confirmed:
- The install instructions are still present in `06_16` at lines 36-53, unchanged since the issue was filed.
- `docs/04_mcp_05_02_auth-profiles-and-sandboxing.md`, section "サンドボックスバックエンド (shell-mcp)" (lines 92-118), already contains the same sandbox-backend explanation and the identical firejail install line (`sudo apt-get install firejail（Debian/Ubuntu）または apk add firejail（Alpine）。確認: firejail --version`). `04_mcp_05_02` is the canonical MCP security/sandboxing document referenced from the document guide (`docs/04_mcp_00_document-guide.md`).
- No dedicated, standalone operations/setup runbook file exists anywhere in the repo for MCP prerequisites. A "Workflow Deployment Runbook" section exists in `docs/05_agent_10_04_operations-and-observability-validation-and-troubleshooting-part1.md`, but it covers workflow-engine deployment and contains no firejail-related content — it is unrelated to this issue.
- The fail-open/fail-closed checklist items in `06_16` (lines 20-34) — covering `tool_definitions_strict`, `routing_drift_strict`, `serial_tool_calls`, `allowed_tools` non-empty, `tool_safety_tiers` completeness, the `shell_sandbox_backend = "firejail"` requirement as a checklist item (not the install steps), `cicd-mcp` `workflow_allowlist` fail-closed behavior, `security_profile = "production"`, health-check thresholds, the MCP watchdog removal note (2026-07-16), audit log path, API keys via env vars, and `repo_allowlist`/`allowed_repos` fail-closed checks — are code-verified and important; they must remain untouched. The existing pointer to `docs/04_mcp_05_01_access-control-and-allowlists.md` (line 55) for fail-open/closed policy should also remain.

## Problem
Because no dedicated ops runbook exists, and the exact firejail install content already lives in `04_mcp_05_02_auth-profiles-and-sandboxing.md`, the install block in `06_16` is a redundant duplicate rather than unique content that needs relocation to a new file. Leaving it in `06_16` mixes design/checklist intent with operational setup procedure and creates a second place that must be kept in sync if firejail install steps ever change.

## Reason for change
Per the project's documentation conventions, checklist/design documents should not duplicate operational setup procedures that already have a canonical home. Removing the duplicate and pointing to the existing canonical section reduces maintenance burden (one place to update firejail install steps) and keeps `06_16` focused on its pre-production checklist purpose.

Do not create a new operations runbook — one is not needed since the canonical content already exists in `04_mcp_05_02`. Preserve the fail-open/fail-closed checklist items in `06_16` verbatim, including the existing pointer to `04_mcp_05_01_access-control-and-allowlists.md`.
