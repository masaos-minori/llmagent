# Resolve `on_usage` Callback Type Documentation Gap in LlmPayloadHandler Docs

## Priority

Medium

## Target Files

- `docs/90_shared_03_04_runtime_and_execution-caching-and-reference-part2.md:70,72,82` — `on_usage` documented as `object | None`; contains an unresolved `[Needs confirmation]` note about the callback shape
- `docs/00_governance_07_needs-confirmation-inventory.md:259-263` — NC-016 inventory entry tracking this open question
- `scripts/shared/llm_payload.py:38-40,63-64` — actual `on_usage: Callable[[int, int], None] | None = None` signatures for `parse_response` and `parse_non_stream_response`

- `scripts/shared/llm_sse_helpers.py:85,104,114-115` — `parse_usage()` invokes `on_usage(pt, ct)` with two `int` positional arguments

## Background

`docs/90_shared_03_04_runtime_and_execution-caching-and-reference-part2.md` documents
`LlmPayloadHandler` (`shared/llm_payload.py`). Its code-block summary for
`parse_response()` and `parse_non_stream_response()` shows the `on_usage` parameter typed
as `on_usage: object | None = None`, and a `[Needs confirmation]` note at line 82 states
that the real callback shape "cannot be determined from this module alone." This is
tracked as open item NC-016 in `docs/00_governance_07_needs-confirmation-inventory.md`.

## Problem

Verification against the current source shows the documented type is stale and the
open question is in fact answerable from the codebase:

- `scripts/shared/llm_payload.py:40` and `:64` declare
  `on_usage: Callable[[int, int], None] | None = None` — not `object | None` as the doc
  states.
- The same `Callable[[int, int], None] | None` signature is used consistently across
  `scripts/shared/llm_client.py:58`, `scripts/shared/llm_sse_helpers.py:85,104`, and
  `scripts/shared/llm_reconnect.py:52`.
- `scripts/shared/llm_sse_helpers.py:114-115` calls `on_usage(pt, ct)` with two `int`
  arguments (prompt tokens, completion tokens), confirming the shape.
- The one production call site, `scripts/agent/factory.py:258-263`, defines
  `_on_llm_usage(prompt_tokens: int, completion_tokens: int) -> None` and passes it as
  `on_usage=_on_llm_usage` at line 273 — matching `Callable[[int, int], None]` exactly.

So the documentation's own code sample is out of date (it should already say
`Callable[[int, int], None] | None`, matching the pattern used everywhere else in the
same doc for `on_token`), and the `[Needs confirmation]` note is no longer an open
question — it has a concrete, verifiable answer.

## Reason for Change

Leaving a resolvable `[Needs confirmation]` marker and an incorrect type in the
documentation risks readers/implementers relying on the wrong signature (e.g. assuming
`on_usage` accepts an arbitrary `object` and writing an incompatible callback), and
leaves governance tracking (NC-016) open for an item that has already been answered by
inspecting adjacent modules. Closing this out keeps the shared-module reference docs and
the needs-confirmation inventory accurate.

   uniformly `Callable[[int, int], None] | None`, with the two `int` args being
   `(prompt_tokens, completion_tokens)`.
