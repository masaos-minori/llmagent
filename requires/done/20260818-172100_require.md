# Title: [REQ] Standardize Evidence, Uncertainty Tracking, and Area Known Issues
# Priority: Medium
# Target files: docs/**/*.md, routing.md, AGENTS.md
# Background: Currently, evidence labeling, uncertainty markers, and "Known Issues" lists are applied inconsistently across different project areas (Agent, MCP, RAG, etc.), making them difficult to track, validate, or automate.
# Problem: 
# 1. Ambiguous evidence scope makes it unclear if an entire section or just one claim is verified.
# 2. Unregistered uncertainties in area documents lack owners or resolution targets.
# 3. Inconsistent "Known Issues" formats across areas prevent efficient filtering, ownership tracking, and automated validation.
# Reason for change: To create a unified workflow for managing technical debt, verifying documentation, and tracking project uncertainties.
# Implementation intent: Establish a standardized framework for evidence labeling, uncertainty identification, and known issue management.
# Implementation instructions:
# 1. **Standardize Evidence Labeling**: Define the smallest verifiable unit as an "individual claim." Implement a standard evidence block including: label, source module/document, symbol/section, test identifier, verification date, and notes. Prefer stable symbols/test references over line numbers.
# 2. **Uncertainty Management**: Implement a process to scan area documents for uncertainty markers (e.g., "Needs Confirmation", "要確認"). Extract these into a central inventory, linking each finding back to its source statement.
# 3. **Unified Known Issues Framework**: Migrate all area-specific "Known Issues" (Agent, MCP, RAG, EventBus, Shared/DB) to a single, common template. Ensure they include mandatory metadata: status, severity, type, owner, source, target, evidence, impact, and resolution criteria.
# 4. **Issue Classification**: Clearly distinguish confirmed design decisions from active technical defects during migration.
# 5. **EventBus Specifics**: Convert any tabular EventBus issue entries into individual, tracked issue entries.
# Acceptance criteria:
# - Granular evidence labels are defined and used consistently.
# - A standard evidence block format is established and documented.
# - All identified uncertainties are registered in a central inventory with bidirectional links to source documents.
# - All area "Known Issues" follow the new common template with full metadata.
# - Original issue IDs and substantive details are preserved during migration.
# - Automated validation ensures template compliance and metadata completeness.
# Tests:
# - Manual verification of evidence blocks (one code-backed, one test-backed).
# - Comparison of uncertainty extraction reports run at different times.
# - Integrity check of bidirectional links between documentation and the central inventory.
# - Audit of migrated Known Issues for metadata completeness.
