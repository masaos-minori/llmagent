# Migrate `mcp_servers/audit.py` JSON audit-record serialization from stdlib `json` to `orjson`

## Priority
Low

## Target files
- `scripts/mcp_servers/audit.py` (`_audit_log`)
- `tests/agent/test_audit_log_format.py` (existing characterization suite)

## Background
`rules/coding.md` mandates `orjson` (not stdlib `json`) for all JSON serialization repo-wide.
`scripts/mcp_servers/audit.py` violates this by using `json.dumps(record, ensure_ascii=False)` at line 84.
The agent-side audit log (`scripts/agent/tool_audit.py`) already uses `shared.json_utils.dumps`, which wraps `orjson.dumps`.

## Problem
Inconsistent JSON serializer usage across audit-log code paths. The MCP server audit path uses stdlib `json` while the agent-side path uses `orjson` via `shared.json_utils.dumps`.

## Reason for change
Compliance with `rules/coding.md` §Key library choices. Additionally, `orjson` provides better performance for repeated serialization.

## Implementation intent
Before switching serializers, write a byte-level characterization test comparing `orjson.dumps(record, ...).decode()` output against the current `json.dumps(record, ensure_ascii=False)` output across all existing test case record shapes. Only switch once byte-identical (or an intentional, documented difference is signed off per `rules/coding.md` explicit sign-off gates).

## Implementation instructions
1. **Characterization step**: In `tests/agent/test_audit_log_format.py`, add a new test class/method that:
   - For each record shape used by existing MCP audit log tests, compare `orjson.dumps(record, option=orjson.OPT_SORT_KEYS).decode()` against `json.dumps(record, ensure_ascii=False)`.
   - Use `option=orjson.OPT_SORT_KEYS` to match `json`'s default key ordering behavior.
   - Report whether outputs are byte-identical.
2. **If byte-identical**: Replace `json.dumps(record, ensure_ascii=False)` in `scripts/mcp_servers/audit.py:84` with `orjson.dumps(record, option=orjson.OPT_SORT_KEYS).decode()`.
3. **If not byte-identical**: Document the specific difference (e.g., float representation, key ordering) and require explicit sign-off before proceeding.

## Acceptance criteria
- `_audit_log`'s output uses `orjson` for serialization.
- All existing tests in `tests/agent/test_audit_log_format.py` pass unchanged (same assertions, same expected output), or are updated with explicit justification if the output format intentionally changes.
- No other MCP server's audit-log call site behavior changes (this module is shared).

## Tests
- Run `tests/agent/test_audit_log_format.py` before and after the change.
- Byte-level output comparison required per the Implementation Intent above.
- Add the byte-comparison characterization test described in implementation instructions.
