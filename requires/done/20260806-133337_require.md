# Audit whether `BLE`/`PLC0415` noqa suppressions are functionally meaningful, and add automated enforcement of the noqa-justification convention

## Priority
Medium

## Target files
- `pyproject.toml` (`[tool.ruff.lint]` `select` list)
- `tox.ini` (lint environment definition)
- `scripts/agent/startup.py` (five `# noqa: BLE001` / `# noqa: PLC0415` comments)
- Other files using `# noqa: BLE001` or `# noqa: PLC0415`, including but not limited to:
  `tests/mcp_servers/mdq/test_mdq_service.py`, `tests/mcp_servers/mdq/test_mdq_incremental_refresh.py`,
  `tests/mcp_servers/mdq/test_mdq_index_serialization.py`, `tests/mcp_servers/mdq/test_mdq_search_modes.py`,
  `tests/mcp_servers/mdq/test_mdq_get_chunk_behavior.py`, `tests/mcp_servers/cicd/test_mcp_server_health_status.py`,
  `tests/agent/memory/test_memory_store.py`, `tests/agent/test_startup.py`, `tests/agent/test_llm_client.py`
- `rules/coding.md` (§Suppression governance)
- `.pre-commit-config.yaml` (candidate location for new enforcement hook)

## Background
A prior requirement (`requires/done/20260806-103649_require.md`, implemented via
`plans/20260806-105228_plan.md`) added inline em-dash justifications to five previously-unjustified
`# noqa` comments in `scripts/agent/startup.py`, satisfying `rules/coding.md` §Suppression
governance's letter ("every `# noqa`... requires an inline justification"). That work surfaced two
related, unresolved risks, documented in `issues/20260806-105228_risks.md` (RISK-01, RISK-02) and
verified against current source on 2026-08-06:

- `pyproject.toml`'s `[tool.ruff.lint]` `select` list is confirmed to be exactly
  `["E", "W", "F", "I", "UP"]` — it does not include the `BLE` or `PLC` rule families that
  `BLE001`/`PLC0415` belong to.
- `tox.ini`'s `lint` environment runs only `ruff format --check` and `ruff check` — no pylint or
  flake8 is configured anywhere in the toolchain, so ruff is the only tool that could possibly act
  on these codes.
- `scripts/agent/startup.py` still contains the five `# noqa: BLE001` / `# noqa: PLC0415` comments
  (lines 139, 314, 350, 371, 387, 394, 409 per current source), now each with an em-dash
  justification.
- No test or pre-commit hook enforces the em-dash-justification convention: `tests/agent/test_startup_consistency.py`
  contains no reference to `noqa` or justification text, and `.pre-commit-config.yaml` wires up
  `ruff`, `ruff-format`, `mypy`, and several docs/consistency checks, but nothing that inspects
  `# noqa` comment bodies.
- A repo-wide search (`rg -n "noqa" tests/`) shows `BLE001` and `PLC0415` are used across many
  files beyond `startup.py`, most without any inline justification at all.

## Problem
Two related gaps remain open:

1. It is unknown whether ruff, configured with `select = ["E", "W", "F", "I", "UP"]`, ever
   actually flags the lines carrying `# noqa: BLE001` / `# noqa: PLC0415`. If it does not, these
   suppressions — now carrying prose justification — are suppressing nothing, meaning the
   justification effort documents a non-issue while the `select` list vs. noqa-code mismatch goes
   unaddressed, and the same mismatch likely exists in every other file using these two codes.
2. The em-dash-justification convention in `rules/coding.md` §Suppression governance is checked
   only by a developer manually running the three documented `rg` commands. No automated
   mechanism (test, pre-commit hook, or CI step) prevents a future `# noqa` addition — in
   `startup.py` or any other file — from lacking a justification, so the convention can regress
   silently.

## Reason for change
Leaving both gaps open means the codebase's suppression governance is partly cosmetic: the
noqa codes may not correspond to active lint rules, and even where they do, nothing prevents new
unjustified suppressions from being introduced. Resolving both closes the loop opened by the
prior justification-only requirement and prevents recurrence.

## Implementation intent
- Audit whether the `BLE` and/or `PLC` rule families (or the specific `BLE001`/`PLC0415` rules)
  should be added to `pyproject.toml`'s `[tool.ruff.lint]` `select` list, by checking whether ruff
  actually reports these codes today when run with the current config (e.g. via a scratch config
  with the families temporarily enabled, or `ruff check --select` scoped to those codes).
- Based on the audit outcome, decide per-file whether: (a) the `select` list should be expanded to
  include the families so the noqa suppressions become meaningful, or (b) the noqa codes across
  affected files should be corrected to match rules that are actually active under the current
  `select` list. Expanding `select` may surface new findings across many files — treat that as an
  expected, in-scope consequence of this requirement, not a reason to defer further.
- Separately, consider adding automated enforcement of the em-dash-justification convention —
  e.g. wiring the three `rg`-based detection commands already documented in `rules/coding.md`
  §Suppression governance into a pre-commit hook (`.pre-commit-config.yaml`, following the existing
  `local` hook pattern) or a dedicated lightweight check reachable from `tox.ini`/CI — so an
  unjustified suppression fails fast instead of relying on a developer remembering to run `rg`
  before every commit.
- Do not prescribe exact code changes here; the next phase (work plan) should choose the concrete
  mechanism and scope (which rule families to enable, how many files need noqa-code corrections,
  where the enforcement hook lives) based on the audit's findings.

## Implementation instructions
1. Determine ruff's actual behavior for `BLE001` and `PLC0415` under the project's `target-version`
   and current `select` list — confirm whether these codes are silently inactive.
2. Enumerate every `# noqa: BLE001` / `# noqa: PLC0415` occurrence in the repository (not just
   `scripts/agent/startup.py`) and record, for each, whether the underlying rule is active.
3. Decide and document the resolution strategy: expand `select` to include the needed families,
   correct mismatched noqa codes, or a combination — and apply it consistently across all affected
   files.
4. Re-run the suppression-governance `rg` checks from `rules/coding.md` after any noqa-code
   corrections to confirm every remaining suppression still carries a valid inline justification.
5. Design and add an automated enforcement mechanism for the em-dash-justification convention
   (pre-commit hook or CI/tox check) so future unjustified `# noqa`/`# type: ignore`/`# nosec`
   additions are caught without manual review.
6. Update `rules/coding.md` §Suppression governance if the enforcement mechanism changes how
   developers are expected to verify justifications (e.g. replacing "run before every commit" with
   a reference to the new automated check).

## Acceptance criteria
- A documented determination exists of whether `BLE001` and `PLC0415` are active under the
  project's ruff configuration, covering every file currently using these codes.
- The `select` list and/or the noqa codes across the codebase are consistent, such that no
  `# noqa` comment suppresses a rule that ruff would never have flagged in the first place (or
  any intentional exceptions are explicitly documented).
- An automated check (pre-commit hook, tox env, or CI step) exists that fails when a `# noqa`,
  `# type: ignore`, or `# nosec` comment lacks the em-dash inline justification required by
  `rules/coding.md` §Suppression governance.
- `rules/coding.md` accurately reflects the enforcement mechanism in place.

## Tests
- Add or extend a test (or pre-commit hook, whichever is chosen as the enforcement mechanism) that
  fails when a `# noqa` / `# type: ignore` / `# nosec` comment without an em-dash justification is
  present anywhere under `scripts/` (and `tests/`, if in scope).
- If the `select` list changes, run the full `tox -e lint` environment and fix or explicitly
  suppress (with justification) any newly surfaced findings.
- Verify existing tests referencing `scripts/agent/startup.py` (e.g. `tests/agent/test_startup.py`,
  `tests/agent/test_startup_consistency.py`) still pass after any noqa-code corrections.
