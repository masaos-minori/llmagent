# Remove verbatim dataclass field enumeration in docs/01_overview-files-03-scripts-part3.md

## Priority
Medium

## Target files
- `docs/01_overview-files-03-scripts-part3.md` (~lines 52-58, inside the `shared/` directory tree entries for `health_models.py` and `models.py`)

## Background
`docs/01_overview-files-03-scripts-part3.md` documents the deployed directory structure under `scripts/agent/`. In the `shared/` subsection, the entries for `health_models.py` and `models.py` enumerate every field of the dataclasses defined there (`ServiceWarning`, `ToolApprovalEvent`, `ApprovalDecisionEvent`, `ToolExecEvent`, plus method/property names for `HealthCheckResult` and `McpHealthProbeResult`) directly in the document body, as sub-bullets under each file's tree line.

Verified against current source:
- `scripts/agent/shared/health_models.py`: `ServiceWarning` (frozen dataclass) has fields `label: str`, `url: str`, `message: str` — matches the doc's listing exactly.
- `scripts/agent/shared/models.py`: `ToolApprovalEvent`, `ApprovalDecisionEvent`, `ToolExecEvent` (frozen dataclasses) — field lists in the doc match the current source exactly, field-for-field.

The doc is not currently stale relative to source, but the listing is a mechanical transcription of code structure into documentation prose, which is exactly the kind of "code-derived detail" that the project's documentation policy (`docs_review_overview_architecture.md` §1, §2 item 4) flags for removal — it will drift out of sync the next time a field is added, removed, or renamed in these dataclasses, since nothing enforces the doc and code staying in sync.

## Problem
The document body enumerates dataclass fields verbatim (field names and, in one case, types/relationships) instead of describing the responsibility boundary of the module. This duplicates information that is already authoritative in the source code (dataclass definitions and their docstrings, e.g. `McpHealthProbeResult`'s existing docstring in `health_models.py` already documents each field's meaning), creating a second copy that can silently go stale.

## Reason for change
Per the project's documentation classification rules (`rules/coding.md` — "Documentation notes — Current behavior classification" section is analogous guidance for doc-vs-code drift), verbatim code transcription in prose docs is a maintenance liability: it must be manually kept in sync with the dataclass definitions, and there is no automated check tying the doc text to the dataclass fields. The docs review (`docs_review_overview_architecture.md` §1, §2 item 4) has already flagged this specific passage for removal.

## Implementation intent
Replace the verbatim field enumeration (the sub-bullets under `health_models.py` and `models.py` in the `shared/` tree, ~lines 52-58) with a one-sentence responsibility-boundary summary for each file, consistent with the style used for sibling entries in the same tree (e.g. `services/models.py` is described as a single-line comment, not a field-by-field breakdown). Do not invent a new Reference API document for this content — no such document currently exists to receive it. Point readers to the dataclass definitions/docstrings in `scripts/agent/shared/health_models.py` and `scripts/agent/shared/models.py` as the authoritative source for field-level detail.

## Implementation instructions
1. In `docs/01_overview-files-03-scripts-part3.md`, locate the `shared/` subsection of the file tree (currently ~lines 47-58).
2. For the `health_models.py` tree line (~line 51-54): remove the three sub-bullets listing `ServiceWarning`, `HealthCheckResult`, and `McpHealthProbeResult` fields/members. Replace the inline comment on the `health_models.py` line with a short summary, e.g. "ヘルスチェックモデル（`ServiceWarning`/`HealthCheckResult`/`McpHealthProbeResult` を集約）" — do not repeat field names.
