# SessionMessageRepository._VALID_ROLES hardcoded set lacks extensibility

## Priority
Low

## Summary
_VALID_ROLES is a hardcoded frozenset in session_message_repo.py. Adding a new valid role requires modifying this file directly, which could be forgotten during feature development.

## Reason for Change
The validation uses a static frozenset {"user", "assistant", "tool", "system"}. If a new role type is needed in the future, developers must remember to update this constant. A configuration-driven approach would be more maintainable.

## Implementation Intent
Consider making _VALID_ROLES configurable or loading from a central schema definition.

## Target Files or Areas
- scripts/agent/session_message_repo.py
- _VALID_ROLES constant

## Required Changes
- Make _VALID_ROLES configurable or load from a central schema definition
- Ensure backward compatibility with existing role values
- Document the role validation policy clearly

## Acceptance Criteria
- [ ] New roles can be added without modifying session_message_repo.py
- [ ] No regressions in normal operation when registry is available

## Testing Expectations
- Unit test for role validation with various field combinations
- Integration test verifying diagnostic output during startup/shutdown

## Documentation Impact
If DiagnosticsConfig is extended, update documentation to reflect the new state.

## Out of Scope
- Changing the registry initialization order
- Adding retry logic for health checks

## AI Implementation Instruction
Modify only _filter_sensitive_fields() in diagnostic_store.py. Add a new state to McpAvailability enum if needed. Update the fallback logic to use the new state instead of UNKNOWN when registry is None.
