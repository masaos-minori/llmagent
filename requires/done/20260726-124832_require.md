# Prevent double execution of approval checks in workflow mode

## Priority

High

## Target Files

- `scripts/agent/tool_runner.py:472` — _run_approval_gate() call
- `scripts/agent/repository_gateway.py:106` — run_approval_checks() call
- `scripts/agent/tool_approval.py:200-202` — Workflow mode skip condition

## Background

When workflow mode is enabled, the approval check is skipped at `tool_approval.py:201`:

```python
if ctx.workflow.approval_pending:
    logger.debug("run_approval_checks: skipping — workflow approval mode active")
```

However, the gateway's write gate operates independently:

```python
# repository_gateway.py:97-106
from agent.tool_approval import run_approval_checks
approved_calls, denied_ids = await run_approval_checks(...)
```

This means approval checks may be executed twice when both paths are active.

## Problem

Double approval checks cause confusion and potential bypass of workflow intent. The workflow engine expects to handle approvals centrally, but the gateway also performs its own checks.

## Reason for Change

Prevent double approval execution by ensuring only one path handles approvals based on the current mode.

## Implementation Intent

Add a flag or check that prevents the gateway from performing approval checks when workflow mode is active.

## Implementation Instructions

Option A (flag-based): Add a context flag to indicate workflow approval is active:
```python
# In repository_gateway.py:_gate_write():
if ctx.turn.pending_approval_id is not None:
    # Skip gateway-level approval, let workflow handle it
    pass
else:
    approved_calls, denied_ids = await run_approval_checks(...)
```

Option B (centralized): Move all approval logic into the workflow engine and remove it from the gateway.

Choose Option A for minimal change; Option B provides cleaner architecture.

## Acceptance Criteria

- [ ] Only one approval check executes per tool call
- [ ] Workflow mode correctly delegates to workflow engine for approvals
- [ ] No regressions in non-workflow modes
