# Fix collection and logic errors in tests/agent/test_approval_task_persistence.py

## Priority
High

## Target files
- `tests/agent/test_approval_task_persistence.py` (fix target)
- `scripts/agent/context.py` (reference only, not expected to change — `AgentContext`/`TurnState`)
- `scripts/agent/workflow/approval_ops.py` (reference only — `resolve_approval`)
- `scripts/agent/workflow/task_ops.py` (reference only — `update_task_status`)
- `scripts/agent/commands/cmd_workflow.py` (reference only — where `pending_approval_id` clearing
  actually happens, lines 124 and 181)

## Background
The source issue reported that `tests/agent/test_approval_task_persistence.py` fails to collect
because it imports `TurnContext` from `agent.context`, a symbol that does not exist — only
`AgentContext` exists, with a `.turn` attribute holding a `TurnState` instance. This claim was
verified and confirmed true by running:
```
PYTHONPATH=scripts python3 -m pytest tests/agent/test_approval_task_persistence.py -v
```
which fails at collection with:
```
ImportError: cannot import name 'TurnContext' from 'agent.context'
```
`AgentContext()` takes no constructor arguments (confirmed by reading `scripts/agent/context.py`
and by successfully constructing one directly: `AgentContext()` succeeds and
`ctx.turn.pending_approval_id` defaults to `None`). `tests/agent/test_repl.py` already constructs
`AgentContext()` the same way in two places, confirming this is a safe, established pattern. So a
1:1 rename `TurnContext` → `AgentContext` for the import and all five `ctx = TurnContext()`
call sites (lines 73, 85, 93, 107, 122) is mechanically valid and matches the issue's proposed fix.

However, deeper investigation (reading the full test file and its imports' actual targets) found
that the `TurnContext` rename is **not the only problem**, and fixing it alone will not make the
file's tests pass:

1. **A second, independent collection blocker.** The test file also does:
   ```python
   from agent.workflow.approval_ops import (
       resolve_approval,
       update_task_status,
   )
   ```
   `update_task_status` is not defined in `agent.workflow.approval_ops` (confirmed: `grep -n "^def "`
   on that file lists only `request_approval`, `resolve_approval`, `get_latest_approval`,
   `find_pending_approval_by_session`, `count_pending_approvals`, `find_approval_by_id`,
   `find_latest_pending_approval`, `find_all_pending_approvals` — no `update_task_status`, and no
   re-export of it). `update_task_status` actually lives in `agent.workflow.task_ops`. This second
   `ImportError` is currently masked because Python raises on the first failing import
   (`TurnContext`) before ever reaching this line — but it will surface as a new collection error
   the moment the `TurnContext` import is fixed, unless the `update_task_status` import is also
   corrected in the same change.

2. **Three tests assert behavior that is not wired to the code they call**, in
   `TestPendingApprovalIdClearing`:
   ```python
   ctx = TurnContext()
   ctx.turn.pending_approval_id = "test-approval-1"
   db = _make_db(tmp_path)
   resolve_approval(db, "test-approval-1", "approved")
   assert ctx.turn.pending_approval_id is None
   ```
   `resolve_approval(db, approval_id, status, reason=None)` (in `approval_ops.py`) only updates the
   `approvals` table row in SQLite; it never receives `ctx` as an argument and has no way to mutate
   it. Confirmed by reading `resolve_approval`'s full body: it does two `SELECT`/`UPDATE` calls on
   `db` and nothing else. Grepping the codebase for where `ctx.turn.pending_approval_id` is actually
   set to `None` shows it happens only in `scripts/agent/commands/cmd_workflow.py` (lines 124 and
   181, inside the `/approve` and `/reject` command handlers), immediately *after* they call
   `resolve_approval`/`update_task_status` themselves — it is command-handler behavior, not a side
   effect of the workflow-ops functions the test calls directly. As written, calling only
   `resolve_approval(db, ...)` can never clear a `ctx` object that was never passed to it; the
   `test_pending_approval_id_cleared_after_resolution` and `test_pending_approval_id_cleared_on_rejection`
   assertions will fail (value stays `"test-approval-1"`, not `None`) even after both import fixes
   above are applied. (`test_pending_approval_id_not_cleared_before_resolution` happens to pass
   regardless, since it never calls a clearing path.)

3. **One test asserts a task-status check that `resolve_approval` does not perform.**
   `test_halted_task_prevents_resume` (in `TestHaltedTaskStatusRejection`) calls
   `update_task_status(db, "task-1", "halted")` and then expects
   `resolve_approval(db, "test-approval-1", "approved")` to raise `RuntimeError`, on the theory that
   resolving an approval for a halted task should be rejected. Reading `resolve_approval`'s full
   body confirms it only checks the *approval* row's own status (`not found` / `already resolved`)
   and never queries or checks the associated task's status at all. Since the approval row is still
   `"pending"` in this scenario, `resolve_approval` will complete normally and not raise — this
   assertion will fail as written, independent of the two issues above.

None of these three deeper problems were mentioned in the source issue, which described the file as
having a single stale-rename problem. They must be resolved for the acceptance criterion "all tests
in the file pass" to actually be achievable.

## Problem
`tests/agent/test_approval_task_persistence.py` currently fails at collection (blocking all 9 tests
in the file, zero coverage of approval/task persistence behavior), and even after fixing the
reported `TurnContext` → `AgentContext` rename, it would still fail to collect (masked
`update_task_status` import error) and, after that second fix, 3 of the file's 9 tests would still
fail on assertions that do not match how `pending_approval_id` clearing and halted-task rejection
are actually implemented in this codebase.

## Reason for change
A test file with a broken import currently provides zero coverage for approval-task persistence
across resolution/rejection paths. Simply renaming the class per the original issue would only trade
a collection error for a mix of a different collection error and false-negative test failures — it
would not restore working coverage. The underlying behaviors this file is meant to protect
(pending-approval-id clearing on `/approve`/`/reject`, and halted-task handling) are real and
currently implemented in `cmd_workflow.py`/`task_ops.py`/`approval_ops.py`; the tests need to
actually exercise that implementation, not assert an invented contract for `approval_ops.py`
functions that never touched `ctx` or task status in the first place.

## Implementation intent
- Treat this as a from-current-behavior characterization fix, not a pure rename: identify what each
  test is actually trying to verify, then adjust the test body (not the production code) so its
  assertions match how the system truly behaves today.
- For the import-level fixes: rename `TurnContext` to `AgentContext` (constructor takes no
  arguments, matching existing usage in `tests/agent/test_repl.py`), and correct the
  `update_task_status` import to come from `agent.workflow.task_ops` instead of
  `agent.workflow.approval_ops`.
- For `TestPendingApprovalIdClearing`: since `pending_approval_id` clearing is command-handler
  behavior (`cmd_workflow.py` `_cmd_approve`/`_cmd_reject`, not `approval_ops.resolve_approval`),
  either (a) rewrite the two failing tests to directly exercise the actual clearing statement (e.g.
  by calling it in the same pattern the command handlers use, or by testing the command handler
  itself if that is in scope), or (b) if keeping the test at the `approval_ops` level only, change
  the assertions to reflect that `resolve_approval` alone does not clear `ctx.turn.pending_approval_id`
  — whichever keeps the test an accurate characterization of current behavior. Do not modify
  `scripts/agent/commands/cmd_workflow.py`, `scripts/agent/workflow/approval_ops.py`, or
  `scripts/agent/context.py` to make the original assertions pass; the issue's own scope explicitly
  rules out changing production code for this file.
- For `test_halted_task_prevents_resume`: since `resolve_approval` does not check task status,
  either drop/rewrite the assertion to match actual behavior (no exception raised), or reconsider
  whether the test's premise belongs in a different test target — but do not add a task-status
  check into `resolve_approval` itself, since that is a production-code behavior change outside this
  document-only-test-fix issue's scope.
- Preserve existing test intent and structure as much as possible (docstrings, class groupings,
  `_make_db` helper) — only change what is necessary to make imports resolve and assertions match
  real behavior.

   - Change `from agent.context import TurnContext` to `from agent.context import AgentContext`.
   - Change every `ctx = TurnContext()` (5 call sites) to `ctx = AgentContext()`.
   - Change the import block to pull `update_task_status` from `agent.workflow.task_ops` rather
     than `agent.workflow.approval_ops` (keep `resolve_approval` imported from `approval_ops` since
     that import is correct).

   `test_pending_approval_id_cleared_on_rejection` so their bodies exercise that real sequence (or
   explicitly assert the narrower, accurate behavior of `resolve_approval` alone) rather than

3. Update `test_halted_task_prevents_resume` so its assertion matches `resolve_approval`'s actual
   behavior (no task-status check performed) — either by removing the `pytest.raises(RuntimeError)`
