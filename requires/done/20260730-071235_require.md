# Require: Make ingestion failure handling retry-safe and consistency checks reliable

## Priority

High

## Target files

- `scripts/rag/ingester.py`
- `scripts/rag/repository.py`

## Background

RagIngester inserts documents and chunks, generates embeddings, moves processed chunk files to registered/, and performs consistency checks.

The current design has two related risks:

1. Post-ingest consistency checks may run after the DB connection has been closed.
2. Failed embedding chunks may be moved to registered/, making them unavailable for normal retry.

## Problem

If consistency checks run after the DB connection is closed, post-ingest validation may fail or be skipped.

If failed embedding chunks are moved to registered/, they may be lost from the retry path. This can leave documents partially indexed while making the failed chunks difficult to recover.

## Reason for change

The intent is to make ingestion safe under partial failure:

- Consistency checks must run against an open DB connection.
- Failed chunks must remain retryable.
- Operators must be able to identify and recover failed chunks.
- DB consistency reports should not be confused with file-level ingestion failures.

## Implementation intent

### Move check_consistency() inside the active DB context, or open a new read-only DB connection for the consistency check

### Treat a failed consistency check as an explicit error state

### Move only successfully ingested chunk files to registered/

### Keep embedding-failed chunks in chunk/ or move them to retry/

### Optionally move invalid, non-retryable chunks to failed/

### Emit structured logs for failed chunks:

- URL
- chunk_index
- source_file
- failure reason

### Consider writing .error.json metadata for failed chunks

### Ensure embed_failed > 0 is visible in the ingestion summary and operational logs

## Acceptance criteria

- [ ] Consistency checks never run on a closed DB connection.
- [ ] Failed embedding chunks are not moved to registered/.
- [ ] A subsequent ingestion run can retry failed chunks.
- [ ] Partial embedding failure does not silently lose chunk files.
- [ ] The ingestion summary clearly distinguishes:
  - inserted chunks
  - parse or DB failures
  - embedding failures
  - skipped documents
- [ ] Existing successful ingestion behavior remains unchanged.

## Tests

- Add a test with a fake SQLiteHelper that closes on __exit__.
- Add a test that consistency check runs while a DB connection is open.
- Add a test where embedding fails and the chunk remains retryable.
- Add a test with mixed successful and failed chunks.
- Add a test that only successful files move to registered/.
- Add a test confirming embed_failed is reported.
