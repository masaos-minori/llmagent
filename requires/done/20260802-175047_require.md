# Simplify the file-lifecycle table in docs/03_rag_02_01_ingestion_pipeline-overview.md

## Priority
Low

## Target files
- `docs/03_rag_02_01_ingestion_pipeline-overview.md` (only file to edit)

## Background
`docs/03_rag_02_01_ingestion_pipeline-overview.md` contains a "ファイルのライフサイクル"
(file lifecycle) section (currently lines 68-78) with a table that lists, per pipeline
stage, the exact output file path pattern, the producing module, and the content
description:

```
| パス | 作成元 | 内容 |
|---|---|---|
| `{rag_src_dir}/{timestamp}-{slug}.json` | crawler.py | URL, タイトル, 言語, コンテンツ, コードブロック |
| `{rag_src_dir}/chunk/{stem}-{idx:04d}.json` | chunk_splitter.py | チャンク情報, ストラテジ |
| `{rag_src_dir}/registered/{stem}-{idx:04d}.json` | ingester.py | チャンク→登録済み |
```

This overview document is a high-level entry point; the stage-specific detail
documents (`docs/03_rag_02_02_ingestion_pipeline-crawler-part1.md`,
`docs/03_rag_02_03_ingestion_pipeline-chunksplitter-part1.md`,
`docs/03_rag_02_04_ingestion_pipeline-ingester-part1.md`) already document each
stage's module, its I/O, and its output file naming/location in their own
right (e.g. `03_rag_02_02` documents `CrawlPayload`/the crawl output JSON
schema; `03_rag_02_03` documents that `ChunkSplitter` reads `rag-src/*.json`
and writes to `rag-src/chunk/`, including the `{stem}-0000.json` idempotency
sentinel; `03_rag_02_04` documents `RagIngester`'s ingestion behavior).

Verified against current repository state (2026-08-02): the table still
exists in this exact detailed form at `docs/03_rag_02_01_ingestion_pipeline-overview.md`
lines 68-78. Commit 6cfb24c10 (2026-07-30, RAG docs consistency checker) did
not touch this file or this table. The issue has not been resolved by any
other prior change.

## Problem
The overview document duplicates filename-level detail (exact path templates
per stage) that already lives in the three stage-specific detail documents.
Maintaining the same level of detail in two places increases maintenance
cost and creates a risk of silent divergence if one location is updated
(e.g. a path template or module name changes) and the other is not.

## Reason for change
An overview document should summarize the pipeline flow and point readers to
the authoritative detail documents for stage-specific specifics, not
duplicate those specifics. Reducing duplication lowers the chance that the
overview goes stale relative to the detail docs.

## Implementation intent
Rewrite the "ファイルのライフサイクル" section so it conveys only:
1. The 3-stage flow: crawl → split → ingest.
2. The general output-directory structure (i.e. that each stage writes under
   `{rag_src_dir}`, with subdirectories such as `chunk/` and `registered/`),
   without stating the exact per-file naming template (`{timestamp}-{slug}.json`,
   `{stem}-{idx:04d}.json`, etc.) or the full content-description column.

Replace the removed filename-level detail with an explicit reference to the
stage-specific documents (`03_rag_02_02`, `03_rag_02_03`, `03_rag_02_04`),
directing the reader there for exact file-naming and content specifics. The
existing "Related Documents" list at the bottom of the file already links to
these three documents; the implementer should decide whether an additional
inline reference near the shortened table is also warranted for readability,
but must not remove the existing "Related Documents" entries for `02_02`,
`02_03`, `02_04`.
