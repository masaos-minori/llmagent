# Requirement: Fix File Descriptor Leak and Zombie Process on getpgid Failure

## Priority

Critical — file descriptor leak can cause FD exhaustion; zombie process leaves orphaned subprocess

## Target Files

- `scripts/agent/http_lifecycle.py` (lines 290-323)

## Background

In `HttpServerLifecycleManager.start()`, when `os.getpgid()` fails with `OSError`:

```python
try:
    self._http_pgids[server_key] = os.getpgid(proc.pid)
except OSError:
    logger.warning(...)
    await self._terminate_with_timeout(proc, server_key)
    poll_result = proc.poll()
    if poll_result is None:
        logger.warning("... will be orphaned")
    elif poll_result == 0:
        logger.info("... already exited cleanly")
    else:
        logger.info("... terminated with exit code %d", poll_result)
    stderr_fh.close()
    self._stderr_files.pop(server_key, None)
    self._stderr_log_paths.pop(server_key, None)
    self._http_procs.pop(server_key, None)
    self._http_pgids.pop(server_key, None)
    return
```

The current code closes `stderr_fh` directly but does NOT use a try-finally pattern to guarantee closure. If any exception occurs between opening the file and this point, the file handle leaks. Additionally, if `proc.poll()` returns `None` after terminate/kill, the process is left as an orphan without being killed again.

## Problem

Two issues exist in the `getpgid` failure path:

1. **File descriptor leak**: The `stderr_fh.close()` call is not protected by try-finally, so if any code between file open and close raises an exception, the file handle leaks.
2. **Zombie process**: When `proc.poll()` returns `None` after terminate/kill escalation, the process is logged as "will be orphaned" but no further action is taken. The process remains alive indefinitely.

## Reason for Change

Eliminate resource leaks and prevent orphaned processes that consume system resources.

## Implementation Intent

1. Use try-finally to guarantee file handle closure regardless of exceptions
2. Kill the process if it survives terminate/kill escalation

## Implementation Instructions

1. Wrap the entire start-and-getpgid sequence in a try-finally block:
   ```python
   stderr_fh = self._open_stderr_log(server_key)
   try:
       self._stderr_files[server_key] = stderr_fh
       # ... existing code ...
       try:
           self._http_pgids[server_key] = os.getpgid(proc.pid)
       except OSError:
           # ... existing cleanup ...
           raise  # Re-raise to trigger finally block
       # ... rest of method ...
   finally:
       # Guaranteed cleanup
       fh = self._stderr_files.pop(server_key, None)
       if fh is not None:
           try:
               fh.close()
           except OSError:
               pass
       self._stderr_log_paths.pop(server_key, None)
   ```

2. In the `poll_result is None` case, add explicit kill:
   ```python
   if poll_result is None:
       logger.warning("... still alive after terminate/kill; killing")
       pgid = self._http_pgids.get(server_key)
       if pgid is not None:
           try:
               os.killpg(pgid, signal.SIGKILL)
           except (ProcessLookupError, OSError):
               proc.kill()
       else:
           proc.kill()
   ```

## Acceptance Criteria

- [ ] File handle is always closed even if exceptions occur during startup
- [ ] Process that survives terminate/kill is killed with SIGKILL
- [ ] No file descriptor leaks observed under stress testing
- [ ] No zombie processes remain after failed startup attempts
