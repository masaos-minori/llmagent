# Increase error threshold for background tasks

## Priority

Medium

## Target Files

- `scripts/agent/orchestrator.py:51` — BG_FAILURE_THRESHOLD definition
- `scripts/agent/orchestrator.py:600-605` — Error threshold check

## Background

The background failure threshold is set to 5 consecutive failures:

```python
BG_FAILURE_THRESHOLD: int = 5
```

When the background task (session title generation) fails 5 times consecutively, it's logged as a critical error. However, network transient issues could easily cause 5 failures without indicating a real problem.

## Problem

A single network outage could trigger 5+ consecutive failures, causing false positive error reports.

## Reason for Change

Reduce false positives by increasing the threshold or adding exponential backoff to the logging frequency.

## Implementation Intent

Increase the failure threshold to a higher value (e.g., 10) or implement exponential backoff on error logging so that frequent transient failures don't spam logs.

## Implementation Instructions

Option A (increase threshold):
```python
BG_FAILURE_THRESHOLD: int = 10
```

Option B (exponential backoff):
```python
if self._consecutive_bg_failures == 1:
    logger.warning("Background task failed: %s", exc)
elif self._consecutive_bg_failures == BG_FAILURE_THRESHOLD:
    logger.error(
        "Consecutive background task failures (%d): %s",
        self._consecutive_bg_failures,
        exc,
    )
elif self._consecutive_bg_failures > BG_FAILURE_THRESHOLD and \
     self._consecutive_bg_failures % 5 == 0:
    logger.error(
        "Continued background task failures (%d): %s",
        self._consecutive_bg_failures,
        exc,
    )
```

Choose Option A for simplicity; Option B provides more granular control.

- [ ] Real persistent failures still generate appropriate alerts
