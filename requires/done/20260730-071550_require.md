# Require: Fix SearchStage retrieval correctness and diagnostics

## Priority

High

## Target files

- `scripts/rag/stages/search.py`
- `scripts/rag/models_result.py`
- `scripts/rag/pipeline.py`
- `scripts/mcp_servers/rag_pipeline/rag_pipeline_service.py`

## Background

SearchStage currently runs vector search and FTS search as a combined retrieval step.

However, KNN/vector retrieval and FTS/BM25 retrieval are independent hybrid retrieval paths. A failure in one path should not discard successful results from the other path.

SearchDiagnostics currently exposes embedding counters and FTS errors, but it does not cleanly distinguish vector search failures, FTS failures, valid no-hit results, configuration problems, and degraded partial results.

## Problem

The current implementation can lose valid search results.

Example:

- vector_search succeeds
- fts_search raises an exception
- the shared exception handler is triggered
- successful vector results may never be appended
- the final search result becomes worse than necessary

The current diagnostics are also ambiguous.

Examples:

- vector search failures can be reported as fts_errors
- db is None can become an unclassified empty result
- http is None can cause generic embedding failures
- embed_url is empty can produce generic empty results
- ctx.queries can be empty without a clear no_queries reason
- all embeddings can fail and still resemble a valid no-hit result

## Reason for change

This is a correctness and diagnosability issue.

The pipeline should not lose successful KNN results because FTS failed, and it should not lose successful FTS results because KNN failed.

The pipeline must also distinguish valid no-hit results from degraded or failed search execution.

## Implementation intent

### Split vector and FTS exception handling

Refactor SearchStage so these calls are handled independently:

- repo.vector_search()
- repo.fts_search()

Expected behavior:

- Vector succeeds and FTS fails: keep vector results
- FTS succeeds and vector fails: keep FTS results
- Both succeed: keep both result lists
- Both fail: return no results for that query and record diagnostics

### Add vector error diagnostics

Extend SearchDiagnostics with:

- vector_errors: int = 0

Keep:

- fts_errors: int = 0

Rules:

- Increment vector_errors only for vector/KNN failures
- Increment fts_errors only for FTS/BM25 failures

Do not report vector failures as fts_errors.

### Add structured search status fields

Extend SearchDiagnostics with fields such as:

- search_status: str
- empty_result_reason: str | None
- degraded_reason: str | None

Suggested search_status values:

- ok
- no_hits
- partial_degraded
- db_unavailable
- no_queries
- embed_failed_all
- vector_failed_all
- fts_failed_all
- embed_unavailable

### Validate dependencies before search

At the beginning of SearchStage.run(), check:

- db is None
- http is None
- embed_url == ""
- ctx.queries == []

If any of these conditions are true, do not execute search. Set SearchDiagnostics with a clear search_status and empty_result_reason.

Suggested mappings:

- db is None -> search_status=db_unavailable
- http is None -> search_status=embed_unavailable, empty_result_reason=embed_client_missing
- embed_url == "" -> search_status=embed_unavailable, empty_result_reason=embed_url_missing
- ctx.queries == [] -> search_status=no_queries

### Update pipeline diagnostics

Update RagPipeline.get_diagnostics() so search_diagnostics includes:

- embed_ok
- embed_failed
- vector_errors
- fts_errors
- search_status
- empty_result_reason
- degraded_reason
- degraded

The degraded boolean should be true when any degraded or failure counter indicates partial or full search degradation.

### Update logging

Replace ambiguous messages such as:

- FTS/vec errors

Use clear messages such as:

- vector search failed
- fts search failed
- embedding client unavailable
- embedding URL is not configured
- search skipped because no query variants are available

## Acceptance criteria

- [ ] FTS failure does not discard successful vector results.
- [ ] Vector failure does not prevent FTS search from running.
- [ ] vector_errors and fts_errors are tracked separately.
- [ ] fts_errors no longer includes vector search failures.
- [ ] db is None produces db_unavailable diagnostics.
- [ ] http is None produces embed_unavailable diagnostics.
- [ ] empty embed_url produces embed_unavailable diagnostics.
- [ ] ctx.queries == [] produces no_queries diagnostics.
- [ ] all embedding failures are distinguishable from valid no-hit results.
- [ ] get_diagnostics() exposes search status, empty-result reason, and degraded reason.
- [ ] Logs clearly identify vector failures and FTS failures separately.

## Tests Required

Add or update tests for:

- Vector success and FTS failure
- Vector failure and FTS success
- Both vector and FTS success
- Both vector and FTS failure
- Missing DB
- Missing HTTP client
- Missing embed URL
- Empty query list
- All embeddings failed
- Valid no-hit result
