## Background
The `05_agent_*.md` document set mixes design/operational judgment with content that is mechanically derivable from code. A review (`memo-doc-agent-review.md`) identified what to keep vs. remove per chapter.

## Problem
The CLI-and-commands chapter carries full per-command argument tables, handler/mixin names, readline/prompt-string UI implementation detail, and full old-command sub-command mapping tables that add no operational value and duplicate what `command_defs_list.py` already defines authoritatively.

## Reason for change
This chapter should serve as the canonical source for CLI operation and command-usage caveats only. Full argument tables and handler/mixin listings increase staleness risk without adding decision value.

## Implementation intent
Keep this chapter as the canonical source for CLI operation and command-usage caveats. Remove full argument tables and handler/mixin detail. Replace argument tables with a pointer to `command_defs_list.py` (the authoritative source). Retain deprecated-command judgment (status/successor/compatibility) even where sub-command tables are dropped.

## Implementation instructions
1. Read all 11 files in full.
2. Identify sections containing: full per-command argument tables, plain side-effect enumeration, handler names and mixin composition, readline/prompt-string UI implementation detail, full old-command sub-command mapping tables.
3. Remove or compress those sections while preserving: what the CLI provides, the `CommandRegistry`/`CLIView`/REPL responsibility split, `/reload`'s reflected scope and what requires a restart, deprecated-command migration judgment, how `/mcp tools`/`/mcp status` are used operationally, where the command-list source of truth lives, commonly-misunderstood behaviors (`/reload` does not reflect all settings, `/mcp status` shows currently-running server state only, `/diff` depends on current history).
4. For deprecated-command sections: drop the full sub-command table but retain deprecated status, whether a successor exists, and whether compatibility is provided.
5. Replace full argument tables with a pointer to `command_defs_list.py` rather than re-transcribing.
6. Restructure remaining content to follow the template: Purpose / Design Intent / Responsibility Boundary / Key Constraints / Operational Notes / Known Limitations / Related Docs.
7. If a design rationale cannot be recovered from the current text, mark it `Needs Confirmation` rather than guessing.
8. Run `python tools/check_agent_docs_consistency.py` after editing — this includes the slash-command drift check against `command_defs_list.py`, which is the relevant regression risk when command detail is trimmed.

## Acceptance criteria
- All 11 files follow the standard template from `memo-doc-agent-review.md` §「修正後の章構成テンプレート」 where applicable.
- No full command-argument table or handler/mixin listing remains.
- Commonly-misunderstood-behavior notes (`/reload`, `/mcp status`, `/diff`) remain explicit.
- Deprecated-command judgment (status/successor/compatibility) is retained even where sub-command tables are dropped.
