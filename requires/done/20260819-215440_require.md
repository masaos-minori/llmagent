# Title
Add high-risk-tool-common-policy cross-reference to git/github/cicd tool docs

## Priority
Medium

## Target files
- `docs/04_mcp_04_05_git.md`
- `docs/04_mcp_04_01_web-search-file-read-github.md`
- `docs/04_mcp_04_03_rag-pipeline-and-cicd.md`
- `docs/00_security_02_high-risk-tool-common-policy.md` (reference target, not modified)

## Background
`plans/20260819-174040_plan.md` (source requirement: `requires/done/20260818-221156_require.md`,
source issue: `issues/20260818_06_issue.md`) creates two new cross-cutting documents:

- `docs/00_security_01_architecture-and-trust-boundaries.md`
- `docs/00_security_02_high-risk-tool-common-policy.md`

`docs/00_security_02_high-risk-tool-common-policy.md` explicitly states it governs
file-write, file-delete, shell, git, github, cicd, and DB-maintenance-class MCP tools.
The source requirement's `Target files` list names 19 existing docs to receive a
cross-reference back to the new consolidated documents (verified against
`requires/done/20260818-221156_require.md` §Target files), and that list includes
`docs/04_mcp_04_02_file-write-file-delete-shell.md` but omits:

- `docs/04_mcp_04_05_git.md`
- `docs/04_mcp_04_01_web-search-file-read-github.md`
- `docs/04_mcp_04_03_rag-pipeline-and-cicd.md`

`plans/20260819-174040_plan.md` §Cross-reference pattern establishes the exact mechanism
already used for the 19 listed files: a short "See also: `00_security_0X_...md` for the
cross-cutting canonical policy" note, added either as a new bullet under an existing
"Related Documents" section or, where no such section fits, as a one-line note adjacent
to the most relevant existing heading — with no existing sentence deleted or reworded.

Verified: as of this writing, `docs/00_security_02_high-risk-tool-common-policy.md` does
not yet exist (it is created by `plans/20260819-174040_plan.md`, not yet executed); the
three target files above exist unmodified under `docs/`.

## Problem
Without a cross-reference from these three tool-specific docs, an engineer or
implementation AI reading `04_mcp_04_05_git.md`, `04_mcp_04_01_web-search-file-read-github.md`,
or `04_mcp_04_03_rag-pipeline-and-cicd.md` in isolation will not be routed to the new
common policy document, even though that document names git/github/cicd as tools it
governs. This is the same fragmentation problem the source requirement set out to fix,
left unresolved for these three files.

## Reason for change
The source requirement's acceptance criterion "Existing docs ... each reference the new
consolidated document(s) as canonical" is only fully satisfied for the 19 files it
explicitly lists; git/github/cicd tool docs would otherwise remain one hop further from
the new canonical source than file-write/file-delete/shell/mdq, undermining the
consolidation goal for exactly the tool classes the new policy doc names as in scope.

## Implementation intent
Add the same short "See also: `00_security_02_high-risk-tool-common-policy.md`"
cross-reference note to the three files listed above, using the identical mechanism
`plans/20260819-174040_plan.md` already applies to the 19 files: a new bullet under an
existing "Related Documents" section where one exists, otherwise a one-line "See also"
note placed adjacent to the most relevant existing heading. Do not delete or reword any
existing content in these three files. This work depends on
`docs/00_security_02_high-risk-tool-common-policy.md` existing (i.e., it should be
sequenced after `plans/20260819-174040_plan.md` is implemented, or implemented together
with it as an extension of the same file list).

## Implementation instructions
1. Confirm `docs/00_security_02_high-risk-tool-common-policy.md` exists (created by
   `plans/20260819-174040_plan.md`) before adding references to it.
2. In `docs/04_mcp_04_05_git.md`, add a "See also:
   `docs/00_security_02_high-risk-tool-common-policy.md`" cross-reference (git section),
   following the existing 19-file pattern.
3. In `docs/04_mcp_04_01_web-search-file-read-github.md`, add the same cross-reference
   scoped to the github-tool portion of the doc.
4. In `docs/04_mcp_04_03_rag-pipeline-and-cicd.md`, add the same cross-reference scoped
   to the cicd portion of the doc.
5. Do not alter any existing technical content in these three files beyond the added
   reference.
