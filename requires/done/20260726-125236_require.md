# Add command whitelist validation for MCP subprocess execution

## Priority

Critical

## Target Files

- `scripts/agent/http_lifecycle.py:230` — start() method subprocess.Popen() call
- `scripts/shared/mcp_config.py:57-59` — McpServerConfig cmd definition

## Background

The MCP subprocess command is defined as a list in `McpServerConfig`:

```python
cmd: list[str] = field(default_factory=list)
```

While this prevents shell injection via string expansion (since it's passed as a list to Popen), there's no whitelist validation on which commands can be executed. If an attacker modifies the config file, they could redirect the command entirely.

## Problem

No whitelist validation on `cfg.cmd`. An attacker who can modify the config file could change the command to execute arbitrary code.

## Reason for Change

Prevent potential command substitution attacks through config file modification by validating against a whitelist of allowed commands.

## Implementation Intent

Add a whitelist of allowed executable paths/patterns for MCP subprocess commands. Only allow known, expected executables.

## Implementation Instructions

1. Define a whitelist of allowed commands (adjust based on actual deployment needs):
   ```python
   ALLOWED_MCP_COMMANDS = frozenset([
       "uvicorn",
       "fastmcp",
       "/usr/bin/python3",
       "/opt/llm/venv/bin/python",
   ])
   ```
2. Validate the first element of `cfg.cmd` against the whitelist before spawning:
   ```python
   # In http_lifecycle.py:start():
   if cfg.cmd:
       cmd_base = os.path.basename(cfg.cmd[0])
       if cmd_base not in ALLOWED_MCP_COMMANDS:
           logger.error(
               "MCP subprocess rejected: %r not in allowed commands %s",
               cfg.cmd[0],
               ALLOWED_MCP_COMMANDS,
           )
           raise HttpStartupError(
               StartupFailure(server_key=server_key, reason="unauthorized command")
           )
   ```
3. Run tests to confirm no regressions

## Acceptance Criteria

- [ ] Only whitelisted commands can be executed as MCP subprocesses
- [ ] Non-whitelisted commands produce clear error messages
- [ ] No regressions in normal MCP server startup
