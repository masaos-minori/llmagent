# Fix ruff BLE001 in tools/check_all_docstrings.py line 62

## Priority
Medium

## Target files
- `tools/check_all_docstrings.py`

## Background
ruff reports BLE001 on `tools/check_all_docstrings.py:62` where a broad `except Exception`
handler catches all exceptions from `Path.read_text()`. The broad catch is intentional because
`Path.read_text()` can raise OS-level errors (PermissionError, FileNotFoundError, etc.) and
encoding errors (UnicodeDecodeError). The code handles all of them uniformly by appending a
read-error message and returning early.

## Problem
Pre-commit fails with:
```
BLE001 Do not catch blind exception: `Exception`
  --> tools/check_all_docstrings.py:62:12
```

## Reason for change
The broad exception handler masks unexpected errors per ruff's static analysis rules. While the
current behavior is correct (all OS-level errors are handled identically), the pattern violates
the principle of explicit exception handling.

## Implementation intent
Narrow the exception handler to `(OSError, UnicodeDecodeError)` which covers:
- `OSError` and its subclasses (PermissionError, FileNotFoundError, IsADirectoryError, etc.)
- `UnicodeDecodeError` (ValueError subclass — Path.read_text raises this when encoding fails)

This reduces the blast radius while preserving correct behavior for all expected failure modes.
Using `except OSError` alone would leave `UnicodeDecodeError` unhandled.

## Implementation instructions
1. Read `tools/check_all_docstrings.py` around line 62 to confirm the exact context.
2. Replace `except Exception as e:` with `except (OSError, UnicodeDecodeError) as e:` on line 62.
3. Run `uv run ruff check --select=BLE001 tools/check_all_docstrings.py` to verify the error is resolved.
4. Run `uv run pytest` to ensure no behavioral regression.
