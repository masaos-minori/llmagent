# Consolidate redundant Fail-Open/Fail-Closed summary tables between docs/04_mcp_05_03 and docs/04_mcp_05_05

## Priority
Medium

## Target files
- `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`
- `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md`

## Background
`docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md` contains one canonical
"Fail-Open 対 Fail-Closed の要約" table (lines 20-33) covering 10 controls across
file-read/write/delete-mcp, mdq-mcp, github-mcp, git-mcp, cicd-mcp, and shell-mcp.

`docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md` independently contains **three**
separate tables that overlap with this same subject matter:
1. "Fail-open 対 Fail-closed のデフォルト" (lines 156-166) — 4 rows: shell
   `command_allowlist`, git `allowed_repo_paths`, github `allowed_repos`, cicd
   `workflow_allowlist`. Same semantics as rows already present in the 05_03 table.
2. "deny-all を引き起こす設定" (lines 199-205) — 3 rows: shell
   `command_allowlist`, git `allowed_repo_paths`, github `allowed_repos`. This is
   itself a subset/restatement of table 1 within the *same file* (05_05), i.e. it is
   redundant even locally, not just against 05_03.
3. "Fail-Open / Fail-Closed 設定のレビュー" (lines 254-262) — 5 rows:
   `tool_definitions_strict`, `shell_sandbox_backend`, cicd `workflow_allowlist`,
   shell `command_allowlist`, mdq-mcp `allowed_dirs`.

## Problem
Verification shows the issue's premise ("the same table duplicated in 3 places") is
directionally correct but not literally accurate: none of the three 05_05 tables is a
byte-identical copy of the 05_03 table. Instead:
- Rows for shell `command_allowlist`, git `allowed_repo_paths`, github
  `allowed_repos`, and cicd `workflow_allowlist` are restated (with the same
  fail-closed/fail-open classification) in up to three additional places across the
  two files, so any change to that classification must be propagated to 3-4 tables
  instead of one.
- Table 3 in 05_05 also contains genuinely unique content that is **not** present in
  05_03 at all: rows for `tool_definitions_strict` and `shell_sandbox_backend`, and
  an mdq-specific caveat on the `allowed_dirs` (mdq-mcp) row — "ただし起動時 audit の
  対象外" (mdq-mcp's fail-closed allowed_dirs is deliberately excluded from the
  startup `audit_security_defaults()` check, unlike the other fail-closed settings).
  This nuance does not exist anywhere in 05_03's table or narrative.
- Table 2 in 05_05 is fully subsumed by table 1 in the same file (same rows, same
  classification, only the column header differs: "空の場合の挙動" vs "空の場合の
  効果"), so it can simply be dropped without any content loss once table 1 remains
  or is replaced by a reference to 05_03.

Maintaining overlapping tables in up to 4 locations risks silent divergence if the
fail-open/fail-closed classification for any of these settings changes in the future,
and already forces readers to cross-check multiple tables to get the full picture.

## Reason for change
Reduce the update burden and divergence risk identified above, while explicitly
preserving the mdq-specific content that has no home in 05_03 (the `tool_definitions_strict`
/ `shell_sandbox_backend` rows and the mdq-mcp audit-exemption caveat) so no
information is lost in the consolidation.

## Implementation intent
- Keep `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`'s existing
  "Fail-Open 対 Fail-Closed の要約" table as the single canonical baseline table for
  the generic (non-mdq-specific) fail-open/fail-closed classification of
  `command_allowlist`, `allowed_repo_paths`, `allowed_repos`, `workflow_allowlist`,
  etc. It already includes the mdq-mcp `allowed_dirs` row, so no new row needs to be
  added there for this consolidation — but see the acceptance criteria on the
  audit-exemption note below.
- In `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md`:
  - Remove table 2 ("deny-all を引き起こす設定") entirely — it is redundant with
    table 1 in the same file and adds no new information.
  - Replace table 1 ("Fail-open 対 Fail-closed のデフォルト") with a short prose
    reference to `04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md` for the
    shared baseline classification, using wording consistent with the issue's
    suggested text: "Fail-open/fail-closed基本方針は
    `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md` を参照。mdq-mcp
    固有のロックダウン規則(deny-all時の挙動)は本ファイル末尾に別途記載。"
  - Retain table 3 ("Fail-Open / Fail-Closed 設定のレビュー") only for its
    mdq-specific and otherwise-unique content: the `allowed_dirs` (mdq-mcp) row with
    its audit-exemption caveat. Rows that duplicate 05_03 without adding new
    information (cicd `workflow_allowlist`, shell `command_allowlist`) should be
    dropped from this table since they are already covered by the reference to
    05_03. Rows with no mdq-specific angle but that are genuinely absent from 05_03
    (`tool_definitions_strict`, `shell_sandbox_backend`) should either stay in 05_05
    (if judged mdq-lockdown-relevant) or be evaluated for whether they belong in
    05_03 instead — resolve this placement question during implementation, keeping
    the mdq-specific audit-exemption nuance intact wherever it ends up.
  - Preserve all narrative sections in 05_05 that are not table content (e.g. "意図的な
    deny-all ロックダウン", "起動時の audit", the mdq allowed_dirs fail-closed
    narrative in the "mdq-mcp 自身の allowed_dirs 認可" section) — these are out of
    scope for this table-deduplication change.
- Do not alter the actual fail-open/fail-closed classification or policy of any
  setting — this is a documentation restructuring only.

## Acceptance criteria
- `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`'s existing canonical
  table is unchanged in content (unless step 3 above is deliberately invoked) and
  remains the single place documenting the generic fail-open/fail-closed
  classification of `command_allowlist`, `allowed_repo_paths`, `allowed_repos`,
  `workflow_allowlist`, `repo_allowlist`, `path_denylist`, `protected_branches`, and
  `allowed_dirs` (mdq-mcp).
- `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md` no longer contains a table that
  merely restates rows already fully covered by the 05_03 canonical table without
  adding mdq-specific information.
- The "deny-all を引き起こす設定" table in 05_05 is removed (it was redundant with
  another table in the same file).
- The mdq-specific audit-exemption caveat for `allowed_dirs` (mdq-mcp) — i.e. that
  mdq-mcp's fail-closed `allowed_dirs` is not checked by `audit_security_defaults()`
  and therefore produces no startup DENY-ALL warning — is preserved somewhere in the
  documentation set (05_05, or 05_03 if relocated) and is not lost.
- 05_05 contains a clear pointer to 05_03 for the shared/generic baseline
  classification, consistent with the issue's suggested reference text.
- No fail-open/fail-closed policy or classification value is changed anywhere — only
  presentation/location of the documentation changes.
- Neither file's non-table narrative content (audit descriptions, lockdown
  procedures, MDQ/RAG boundary sections, known-issues section, etc.) is altered
  beyond what is necessary to remove now-dangling references to deleted tables.
