# Preserve fetched_at metadata and enforce chunk-size invariants

## Priority
High

## Target files
- `scripts/rag/models_data.py`
- `scripts/rag/ingestion/pipeline_utils.py`
- `scripts/rag/ingestion/chunk_splitter.py`
- `scripts/rag/ingestion/chunk_english.py`
- `scripts/rag/ingestion/chunk_japanese.py`
- `scripts/rag/ingestion/chunk_utils.py`

## Background
The `fetched_at` field exists in the raw crawler JSON input and is intended to be used by the ingester for stale-update guards. However, it is currently dropped during the conversion from crawler JSON to `ChunkDocument` and is not propagated to the final chunk artifacts. Additionally, while `max_chunk` is documented as a maximum size constraint, several code paths allow chunks to exceed this limit (e.g., oversized individual sentences, Markdown snippets, or when including overlaps).

## Problem
1. **Metadata Loss**: The `fetched_at` freshness metadata is lost early in the ingestion pipeline, preventing downstream components (like `ETagManager`) from using it.
2. **Size Invariant Violation**: Chunks can exceed `max_chunk` due to:
    - Oversized single sentences (English/Japanese).
    - Large Markdown sections being delegated to language chunkers without secondary enforcement.
    - Code block items that are individually larger than `max_chunk`.
    - Overlap text causing the combined length of `last_chunk_tail + overlap + next_item` to exceed `max_chunk`.
    - Short tails being merged into previous chunks without checking the new total length.

## Reason for change
To ensure data integrity by preserving freshness metadata and to guarantee that every chunk produced strictly adheres to the configured size constraints.

## Implementation intent
Ensure end-to-end propagation of `fetched_at` and implement "hard" splitting logic across all chunking paths to enforce `max_chunk` limits.

## Implementation instructions
- **Metadata Propagation**:
    - Update `ChunkDocument` in `scripts/rag/models_data.py` to include `fetched_at: str | None = None`.
    - Update `read_json_file` in `scripts/rag/ingestion/pipeline_utils.py` to extract `fetched_at` from the raw JSON.
    - Update `ChunkMetadata` and `_extract_chunk_metadata` in `scripts/rag/ingestion/chunk_splitter.py` to include `fetched_at`.
    - Include `fetched_at` in the final chunk payload in `_build_chunk_payload`.
- **Size Enforcement**:
    - **Hard Splitting**: Implement logic to split an oversized sentence (English or Japanese) if it exceeds `max_chunk`.
    - **Code Blocks**: Ensure `merge_text_items` (or its usage) handles items that are inherently larger than `max_chunk` by splitting them.
    - **Markdown**: Ensure that even after delegating to language chunkers, the resulting segments do not violate `max_chunk`.
    - **Overlap & Tail Merging**: Adjust buffer management in `ChunkEnglishMixin`, `ChunkJapaneseMixin`, and `merge_text_items` so that the addition of overlap or a short tail never pushes the chunk beyond `max_chunk`.
    - **Validation**: Add a final validation step before writing chunk files to assert `0 < len(content) <= max_chunk`.

## Acceptance criteria
- `fetched_at` from source JSON is present in all generated `.json` chunk files.
- Every emitted chunk satisfies `0 < len(content) <= max_chunk`.
- Configuration errors (e.g., `min_chunk > max_chunk`) cause immediate failure at splitter initialization.
- No bypasses exist for oversized elements (sentences, code blocks, markdown headings, or overlaps).

## Tests
- End-to-end test verifying `fetched_at` propagation from crawler output to chunk files.
- Unit tests for `ChunkSplitter` with invalid configurations.
- Property-based or boundary tests ensuring no chunk ever exceeds `max_chunk` regardless of input content size or overlap settings.
- Regression tests for previously identified "oversized" scenarios (long sentences, long code blocks).
