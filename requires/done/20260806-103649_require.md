# Add inline justifications to unjustified `# noqa` suppressions in `_check_services()`

## Priority
Low

## Target files
- `scripts/agent/startup.py` (`StartupOrchestrator._check_services()`, currently lines 348, 369,
  385, 392; and optionally line 313)

## Background
`rules/coding.md` §Suppression governance states: "Every `# noqa`, `# type: ignore`, and `# nosec`
requires an inline justification. Suppressions without explanation are prohibited."

The RAG consistency fix (`requires/20260804-132104_require.md` -> `plans/20260804-144001_plan.md`)
already added a justification to the RAG consistency check's `# noqa: BLE001` (now at line 407:
`# noqa: BLE001 — non-critical maintenance check must not abort startup`). That plan explicitly
excluded the other `except Exception` blocks in the same method from its scope.

## Problem
Verified against current source (`scripts/agent/startup.py`) as of this requirement:
- Lines 348, 369, 385, 392 — `except Exception as exc:  # noqa: BLE001` (readiness,
  mcp_tool_discovery, routing_drift, routing_safety_tiers checks respectively) — carry no inline
  justification.
- Line 313 — `from agent.repl_health import check_workflow_schema  # noqa: PLC0415` — also carries
  no inline justification (a separate rule code, smaller instance of the same gap).
- Line 139's `# noqa: PLC0415` and line 407's `# noqa: BLE001` are the only two suppressions in
  this file that already follow the convention (inline explanation after an em dash).

This violates the "Suppressions without explanation are prohibited" rule and leaves four (or five,
counting line 313) of the seven `# noqa` occurrences in the file inconsistent with the two that
are already compliant.

## Reason for change
Consistent suppression governance makes it clear, for every broad-except or lint suppression in
this file, why it was judged safe/intentional rather than an oversight — the same reasoning
already applied at lines 139 and 407. Leaving the remaining occurrences unjustified is a gap a
future maintainer or auditor would have to re-derive from scratch, and it is drifting further from
the file's own established convention.

## Implementation intent
Add a short inline justification, following the existing em-dash convention at lines 139 and 407,
to each of the four `# noqa: BLE001` suppressions (readiness, mcp_tool_discovery, routing_drift,
routing_safety_tiers checks) and to line 313's `# noqa: PLC0415`. Each justification should state,
specifically for that check, why a broad `Exception` catch (or a deferred/local import) is an
intentional, non-fatal design choice rather than a placeholder — e.g. that an unexpected failure
in one startup check must not abort the whole startup sequence, or why the import is deferred
locally rather than at module level.

## Implementation instructions
- In `scripts/agent/startup.py`, edit the comment text on the `# noqa` suppressions at (current)
  lines 348, 369, 385, 392, and 313 to add an inline justification after an em dash, matching the
  style at lines 139 and 407.
- Do not change exception types caught, control flow, log messages, or any other code on these
  lines — this is a comment-only change.
- Do not modify any other check, suppression, or behavior in `_check_services()` or elsewhere in
  the file.
