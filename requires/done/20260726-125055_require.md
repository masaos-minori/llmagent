# Apply schema validation to all tool calls including read operations

## Priority

High

## Target Files

- `scripts/agent/tool_runner.py:131-136` — execute_one_tool_call() argument parsing
- `scripts/agent/tool_runner.py:140-151` — Schema validation condition
- `scripts/agent/tool_arg_validator.py:34` — validate_tool_arguments definition

## Background

Schema validation is only applied when `ctx.services_required.runtime_tools` is available:

```python
if ctx.services_required.runtime_tools is not None:
    rt_tool = ctx.services_required.runtime_tools.get(name)
    if rt_tool is not None:
        # validation happens here
```

For read tools without a registered RuntimeTool entry, no schema validation occurs at all. This allows invalid parameters to pass through, potentially causing information leakage or error induction.

## Problem

Read tools (e.g., `read_text_file`) may not have schema validation if they're not registered in the RuntimeTool registry. An LLM could generate malicious arguments that bypass validation entirely.

## Reason for Change

Ensure all tool calls are validated against their schemas, regardless of whether they're registered in the RuntimeTool registry.

## Implementation Intent

Apply schema validation to all tool calls by either ensuring all tools are registered in the RuntimeTool registry, or adding fallback validation using TOOL_LIST definitions.

## Implementation Instructions

Option A (ensure all tools are registered):
1. Verify all READ tools are registered in the RuntimeTool registry
2. Ensure each registration includes proper `input_schema` and `allow_extra_fields`

Option B (fallback validation):
1. Add fallback to TOOL_LIST schema when RuntimeTool registry doesn't have the tool:
   ```python
   if ctx.services_required.runtime_tools is None:
       rt_tool = ctx.services_required.gateway.get_tool_by_name(name) if ctx.services_required.gateway else None
   else:
       rt_tool = ctx.services_required.runtime_tools.get(name)
   
   if rt_tool is not None:
       # existing validation logic
   ```
2. Run tests to confirm no regressions

Choose Option A for simplicity; Option B provides more robust coverage.

## Acceptance Criteria

- [ ] All tool calls validated against their schemas
- [ ] Invalid parameters rejected with appropriate error messages
- [ ] No regressions in normal operation
