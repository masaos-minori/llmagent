# Resolve the "Current Replacement" for the deprecated "shared common config" concept

## Priority

Low

## Target Files

- `docs/00_governance_05_deprecated-items.md` — shared common config entry

## Background

- `docs/00_governance_05_deprecated-items.md` lists **shared common config** under
  "Deprecated Concepts" (lines 31-35) with `Current Replacement: none (replacement
  unknown)`, `Status: Needs confirmation`, and the note "Config structure has
  evolved to area-specific files."
- The same document also lists **common.toml** under "Deprecated Configuration
  Files" (lines 14-18) with the near-identical note "May have been consolidated
  into area-specific configs." `issues/20260727_32_issue.md` investigated that
  entry and was already processed into
  `requires/20260727-140816_require.md`, which found:
  - `common.toml` does not exist anywhere in the repository (`ls config/` shows
    no such file).
  - `config/agent.toml` lines 1-3 carry an explicit header comment: "Previously
    split across: common, llm, http, rag, context, tools, memory, otel,
    security, system_prompts, tools_definitions, and `*_mcp_server` transport
    sections."
  - Immediately below, `config/agent.toml` lines 5-18 contain a section
    literally titled `# ── Infrastructure (common) ──`, holding
    infrastructure-wide settings (`rag_db_path`, `session_db_path`,
    `sqlite_vec_so`, `embed_url`, `sqlite_timeout`, etc.) that are shared
    across the whole agent process rather than owned by one specific area.
  - `docs/05_agent_08_01_configuration-loading-agent-config-part1.md:42`
    independently corroborates this: "以前のバージョンでは複数の個別ファイル
    (`common.toml`, `llm.toml`, `http.toml`, `context.toml`, `rag.toml`,
    `tools.toml`, `memory.toml`, `otel.toml`, `security.toml`,
    `system_prompts.toml`, `tools_definitions.toml`、加えてサーバーごとの
    `*_mcp_server.toml`) を読み込んでいた。これらは`agent.toml`に統合され、
    分割されたファイルはもはや存在しない。"
- This issue (`issues/20260727_33_issue.md`) asks whether "shared common
  config" is the same concept as `common.toml` or a distinct one, and notes
  the overlap explicitly. `requires/20260727-140816_require.md` itself
  anticipated this: its Background section states "The evidence found here
  answers that entry's underlying question too, but that entry is out of
  scope for this requirement," and its Implementation Instructions (step 5)
  explicitly deferred the "shared common config" entry to "a future issue
  [that] scopes them in" — this requirement is that future issue.
- Additional investigation for this issue searched for any other candidate
  "shared config" mechanism that the concept might instead refer to (e.g. a
  shared runtime component rather than a file/config-structure history):
  - `scripts/shared/config_loader.py` (`ConfigLoader`) and
    `scripts/shared/config_utils.py` (typed accessor helpers `get_str`, etc.)
    are the current, still-active loading mechanism for `config/agent.toml`
    and the `*_mcp_server.toml` files — they are present-day infrastructure,
    not a deprecated concept, and neither file nor its docstrings reference a
    former "shared common config" architecture.
  - No other file, module, or doc under `scripts/` or `docs/` uses the phrase
    "shared common config" or describes a distinct shared-config mechanism
    other than the `common.toml` → `agent.toml` consolidation already
    documented above.
  - Conclusion: **"shared common config" and `common.toml` refer to the same
    underlying architectural history** — one names the deprecated concept in
    the abstract ("a single common/shared configuration"), the other names
    the deprecated file that embodied it (`common.toml`). Both entries carry
    nearly identical "Notes" wording in the source document, which supports
    this reading. There is no evidence of a second, separate "shared config"
    mechanism (e.g. a former shared config used only across MCP servers,
    later split into per-server `*_mcp_server.toml` files) — the
    `*_mcp_server.toml` split is already covered by the `common.toml`
    consolidation note and is not a distinct deprecated concept in its own
    right.

## Problem

The "shared common config" entry in `docs/00_governance_05_deprecated-items.md`
is marked `Current Replacement: none (replacement unknown)` and "Needs
confirmation," even though the investigation above (and the directly
overlapping `common.toml` investigation in
`requires/20260727-140816_require.md`) already identifies the concrete
replacement: `config/agent.toml`, specifically its "Infrastructure (common)"
section. Leaving this entry unresolved keeps a stale, duplicate open question
in the governance doc alongside the now-resolved `common.toml` entry.

## Reason for Change

The evidence needed to close this entry already exists in source
(`config/agent.toml`'s header comment and "Infrastructure (common)" section)
and has already been validated once for the sibling `common.toml` entry.
Since both entries describe the same underlying history, resolving "shared
common config" with a cross-reference to the `common.toml` entry keeps
`docs/00_governance_05_deprecated-items.md` internally consistent and removes
a redundant "Needs confirmation" item.

## Implementation Intent

Update the "shared common config" entry in
`docs/00_governance_05_deprecated-items.md` (Deprecated Concepts section) so
that:
- `Current Replacement` names `config/agent.toml`, specifically its
  "Infrastructure (common)" section, and states that this is the same
  underlying consolidation as the `common.toml` entry under "Deprecated
  Configuration Files."
- `Status` changes from "Needs confirmation" to "Confirmed" (or the
  document's equivalent resolved-status label), matching whatever label is
  used for the `common.toml` entry once that entry is updated per
  `requires/20260727-140816_require.md`.
- `Evidence` cites the `config/agent.toml` header comment (lines 1-3) and the
  "Infrastructure (common)" section (lines 5-18) as the concrete source-code
  basis, rather than "Requires source code investigation."
- `Notes` is tightened to state that "shared common config" is the same
  concept as the deprecated `common.toml` file (cross-referencing that entry)
  rather than the current wording, which implies an unconfirmed, separate
  evolution "to area-specific files."

This is a documentation-only change; no source code or config files are to be
modified.
