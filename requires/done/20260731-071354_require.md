# Requirement: Fix Signal Handler Race on Windows

## Priority

High

## Target Files

- `scripts/agent/repl.py`
- `scripts/agent/http_lifecycle.py`

## Background

On Windows, Ctrl-C causes a default `KeyboardInterrupt` because signal handlers are not registered. The asyncio event loop is interrupted, leaving MCP subprocesses uncleaned. Additionally, calling `signal.signal()` inside `shutdown_all()` may overwrite signals set by other threads.

## Problem

In `repl.py`:

```python
# repl.py:743-745
try:
    loop.add_signal_handler(sig, _sigterm_handler)
except NotImplementedError:
    pass  # Windows — signal handler NOT installed
```

And:

```python
# repl.py:753
if sys.stdout.isatty():  # Skipped when piped
    # Console control handler registration skipped
```

This means:

1. On Windows, `add_signal_handler()` raises `NotImplementedError` — silently ignored
2. When stdout is piped (e.g., CI), console control handler is not registered
3. Ctrl-C causes raw `KeyboardInterrupt` without cleanup
4. MCP subprocesses remain as zombies after shutdown

Additionally, `http_lifecycle.py:421-437` calls `signal.signal()` from potentially a different thread than the event loop thread, which can cause race conditions.

## Reason for Change

Windows users cannot cleanly shut down the agent. Subprocess resource leaks occur on every shutdown. Pipe connections (common in CI/CD) have no signal handling at all.

## Implementation Intent

Fix Windows signal handling by using `pywin32` console control handlers regardless of stdout/tty status, and ensure `signal.signal()` is only called from the main thread.

## Implementation Instructions

### Step 1: Remove `isatty()` check for console control handler

```python
# Before:
if sys.stdout.isatty():
    # Register console control handler

# After:
# Always register console control handler on Windows
import win32api

def _console_ctrl_handler(ctrl_type):
    """Handle Windows console control events."""
    if ctrl_type == win32api.CTRL_C_EVENT:
        logger.info("Ctrl-C received via console control")
        asyncio.create_task(self._cleanup())
        return True
    return False

win32api.SetConsoleCtrlHandler(_console_ctrl_handler, True)
```

### Step 2: Check stdin instead of stdout

If the intent was to detect interactive terminals, check `stdin`:

```python
if sys.stdin.isatty():
    # Only register for interactive sessions
```

But note: even non-interactive sessions should receive proper shutdown signals (SIGTERM).

### Step 3: Ensure `signal.signal()` is called from main thread

In `http_lifecycle.py`:

```python
import threading

def shutdown_all(self):
    """Shutdown all HTTP servers safely."""
    # Ensure we're on the main thread before modifying signal handlers
    if threading.current_thread() != threading.main_thread():
        # Schedule on main thread
        asyncio.get_event_loop().call_soon_threadsafe(
            self._install_shutdown_signals
        )
        return
    
    self._install_shutdown_signals()

def _install_shutdown_signals(self):
    """Install shutdown signals on the main thread."""
    signal.signal(signal.SIGINT, self._handle_sigint)
    signal.signal(signal.SIGTERM, self._handle_sigterm)
```

1. Windows Ctrl-C triggers proper cleanup
2. Piped connections receive proper shutdown signals
3. No signal handler race conditions between threads
4. Normal Unix signal handling is unaffected — no regression
