# Signal handler race condition with shared state

## Priority

Low-Medium

## Target Files

- `scripts/agent/repl.py` — `_sigterm_handler()`, `_repl_loop()`, `_close_resources()`

## Background

The `_sigterm_handler()` function handles SIGTERM signals by setting shutdown flags and canceling pending input coroutines. It runs within the asyncio event loop context.

## Problem

In `repl.py:542-597`:

```python
def _sigterm_handler() -> None:
    self._ctx.conv.shutdown_requested = True
    if self._shutdown_event is not None:
        self._shutdown_event.set()
    if self._input_coro is not None and not self._input_coro.done():
        try:
            self._input_coro.cancel()
        except RuntimeError:
            pass
```

On Unix systems, `loop.add_signal_handler()` is used, while on Windows, `loop.call_soon_threadsafe()` is used. The difference in execution timing between these two approaches means signal handlers may behave differently across platforms.

Additionally, `_repl_loop` sets and clears `self._turn_active` flag, but the signal handler does not check this flag. If the main loop executes `self._turn_active = False` while the signal handler is running, state inconsistency occurs. Furthermore, `_close_resources()` skips cleanup when `ctx.services` is None, but the signal handler could set shutdown flags just before `ctx.services` becomes None, resulting in incomplete shutdown.

## Reason for Change

While the risk is low in single-threaded asyncio loops (signal handlers run during the same thread), platform differences in signal handling semantics create inconsistent behavior between Unix and Windows. In multi-threaded environments, the race condition becomes more significant.

## Implementation Intent

Make signal handler operations consistent across platforms. Ensure shutdown state is properly synchronized regardless of turn activity status. Guarantee complete resource cleanup even when services become unavailable.

## Implementation Instructions

1. Modify `_sigterm_handler()` to also check and clear `self._turn_active` flag before setting shutdown flags.
2. Document the behavioral differences between Unix (`add_signal_handler`) and Windows (`call_soon_threadsafe`) signal handlers.
3. Add a guard in `_close_resources()` that verifies `self._turn_active` is False before skipping service-dependent cleanup.
4. Use atomic operations where possible for shared state updates.
