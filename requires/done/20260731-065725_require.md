# Requirement: Add Stage Cleanup Before Timeout-Forced Transition

## Priority

High

## Target Files

- `scripts/agent/workflow/workflow_engine.py`
- `scripts/agent/workflow/state_store.py`

## Background

The workflow engine supports forced stage transitions when a stage times out. The `_force_stage_transition()` method immediately calls `_transition_to(next_stage)` without cleaning up the current stage's resources (running tool calls, pending approvals, etc.).

## Problem

When `_force_stage_transition()` is triggered due to a timeout:

1. Current stage's running resources are not cleaned up
2. `_transition_to()` does not guarantee pre-transition cleanup
3. Resulting state inconsistency can cause errors in the next stage
4. Incomplete state may be persisted to the database

Example code path:

```python
if stage_timeout and elapsed > stage_timeout:
    logger.warning(f"Stage timeout exceeded: {stage}")
    await self._transition_to(next_stage)  # No cleanup before transition
```

## Reason for Change

Without proper cleanup, forced transitions leave dangling resources that can corrupt subsequent stages or persist invalid states to the database.

## Implementation Intent

Ensure that before any forced stage transition (timeout-driven), the current stage's resources are properly cleaned up.

## Implementation Instructions

### Step 1: Add `_cleanup_current_stage()` method

In `workflow_engine.py`, add a new method:

```python
async def _cleanup_current_stage(self, stage: WorkflowStage) -> None:
    """Clean up resources associated with the given stage before transition."""
    if stage == WorkflowStage.EXECUTE:
        # Cancel any running tool calls
        await self._cancel_running_tools()
    elif stage == WorkflowStage.APPROVAL:
        # Discard pending approval tasks
        await self._discard_pending_approvals()
    elif stage == WorkflowStage.VERIFY:
        # Clean up verification artifacts
        await self._cleanup_verification_artifacts()
    # Save intermediate state before leaving
    await self._save_intermediate_state(stage)
```

### Step 2: Call cleanup before forced transition

Modify `_force_stage_transition()`:

```python
async def _force_stage_transition(self, current_stage: WorkflowStage, next_stage: WorkflowStage) -> None:
    # Clean up current stage BEFORE transitioning
    await self._cleanup_current_stage(current_stage)
    
    # Then perform the transition
    await self._transition_to(next_stage)
```

### Step 3: Ensure `_transition_to()` also handles cleanup

Review `_transition_to()` to ensure it does NOT duplicate cleanup already performed by `_cleanup_current_stage()`. If it does, remove the duplication.

## Acceptance Criteria

1. When a stage times out and forced transition occurs, all resources of the current stage are cleaned up
2. No resource leaks occur during forced transitions
3. Database state remains consistent after forced transitions
4. Normal (non-timeout) transitions are unaffected — no regression
