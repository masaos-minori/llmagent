# Compress the 8 individual YAML snippets in docs/00_governance_06's "Recommended Additional Fields" into a table

## Priority
Low

## Target files
- `docs/00_governance_06_ai-reading-metadata.md`

## Background
`docs/00_governance_06_ai-reading-metadata.md` documents metadata conventions for AI agents reading the design documentation set. Its "Recommended Additional Fields" section (currently lines 24-83) enumerates 8 new metadata fields (`scope`, `audience`, `status`, `priority`, `version`, `last_updated`, `author`, `completeness`), each with its own one-line YAML code-block example (e.g. `scope: agent`). The same 8 fields, with the same names and values, already appear together in a single combined Front Matter block in the "Usage Examples" section (currently lines 84-104).

## Problem
The 8 individual one-line YAML snippets under "Recommended Additional Fields" are a mechanical, redundant enumeration: each snippet shows exactly one field/value pair that is already demonstrated, in combination with all the others, in the "Usage Examples" section's combined Front Matter block. This duplicates content without adding information and inflates the section with 8 near-identical fenced code blocks.

## Reason for change
Per `rules/coding.md` documentation-notes guidance and the issue's own rationale (tracked from `docs_review_governance.md` §1/§2/§5), this is a case of information that should be compressed rather than repeated: the field names, allowed values, and purpose are the durable content; the per-field YAML snippet is redundant presentational detail once a full combined example exists elsewhere in the same document.

## Implementation intent
Replace the current list-with-8-individual-snippets structure in "Recommended Additional Fields" with a single compact table summarizing all 8 fields (field name / allowed values / purpose), and add a note directing the reader to "Usage Examples" for the full combined worked example. No field name, allowed value, or meaning should be added, removed, or altered — only the presentation format changes.

## Implementation instructions
1. In `docs/00_governance_06_ai-reading-metadata.md`, under the "Recommended Additional Fields" heading:
   - Remove the 8 individual numbered entries' one-line YAML fenced code blocks (the `scope: agent`, `audience: developer`, `status: stable`, `priority: high`, `version: 1.0.0`, `last_updated: "2026-07-22"`, `author: agent-team`, `completeness: complete` snippets).
   - Replace them with a single Markdown table with three columns: フィールド名 (field name) / 許容値 (allowed values) / 目的 (purpose), containing one row per field, covering all 8 fields currently documented: `scope`, `audience`, `status`, `priority`, `version`, `last_updated`, `author`, `completeness`.
   - Preserve every allowed-value list and purpose description exactly as currently documented (e.g. `scope` allowed values remain `overview, deployment, rag, mcp, agent, eventbus, shared-db, governance`; `version` remains semantic versioning; `last_updated` remains ISO 8601 `YYYY-MM-DD`, etc.).
   - Add a short note (e.g. a sentence or "See Usage Examples below for a complete Front Matter block combining all fields.") pointing to the existing "Usage Examples" section for the full combined example.
2. Do not modify the "Usage Examples" section — it remains the sole place containing a full worked combined example.
3. Do not modify the "Markdown記法ルール" or "実装参照で確認できる情報の記載方針" sections of this document (out of scope per the source issue; tracked separately).
4. Do not change any field name, allowed value, or its meaning — this is a reformatting-only change.

## Acceptance criteria
- The "Recommended Additional Fields" section no longer contains the 8 individual one-line YAML fenced code-block snippets.
- The "Recommended Additional Fields" section contains a single 3-column table (field name / allowed values / purpose) covering all 8 fields: `scope`, `audience`, `status`, `priority`, `version`, `last_updated`, `author`, `completeness`, with the same allowed values and purposes as currently documented.
- The section includes a note pointing to "Usage Examples" for the full combined example.
- The "Usage Examples" section is unchanged and remains the only location with a full combined Front Matter example.
- No information (field names, allowed values, meanings) is added or removed — only the presentation format changes.
- No other section of `docs/00_governance_06_ai-reading-metadata.md` is modified.
