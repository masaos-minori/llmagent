# Fix agent-docs-consistency.yml and mcp-docs-consistency.yml to invoke the consolidated check_docs_consistency.py script

## Priority

Medium

## Target files

- `.github/workflows/agent-docs-consistency.yml` (run step invokes `python tools/check_agent_docs_consistency.py`)
- `.github/workflows/mcp-docs-consistency.yml` (run step invokes `python tools/check_mcp_docs_consistency.py`)

## Background

`tools/check_agent_docs_consistency.py` and `tools/check_mcp_docs_consistency.py` were
consolidated into a single unified script, `tools/check_docs_consistency.py`, which is
invoked with a `--domain` flag (`agent`, `mcp`, `rag`, `deployment`, `overview`). The
consolidated script's own module docstring confirms this:

```
"""check_docs_consistency.py — Unified docs consistency checker for all domains.

Consolidated from:
  - tools/check_agent_docs_consistency.py
  - tools/check_mcp_docs_consistency.py
  - tools/check_rag_docs_consistency.py
  - tools/check_deployment_docs_consistency.py
  - tools/check_overview_docs_consistency.py
...
```

Verified directly against the current repository state (2026-08-19):

```
$ ls tools/check_agent_docs_consistency.py tools/check_mcp_docs_consistency.py
ls: cannot access 'tools/check_agent_docs_consistency.py': No such file or directory
ls: cannot access 'tools/check_mcp_docs_consistency.py': No such file or directory
$ ls tools/check_docs_consistency.py
tools/check_docs_consistency.py
```

Both `.github/workflows/agent-docs-consistency.yml` and
`.github/workflows/mcp-docs-consistency.yml` still contain a `run:` step that invokes the
now-deleted per-domain script paths:

```yaml
# agent-docs-consistency.yml
run: |
  set -euo pipefail
  python tools/check_agent_docs_consistency.py
```

```yaml
# mcp-docs-consistency.yml
run: |
  set -euo pipefail
  python tools/check_mcp_docs_consistency.py
```

This same class of breakage (a CI workflow invoking a deleted per-domain script instead of
the consolidated `tools/check_docs_consistency.py --domain <name>` entry point) was already
identified for `overview-docs-consistency.yml`, `deployment-docs-consistency.yml`, and
`rag-docs-consistency.yml`, with the fix specified (not yet implemented as of 2026-08-20 —
`plans/20260819-174858_plan.md`'s Implementation Steps are all unchecked, and the three
workflow files on disk still invoke the deleted per-domain scripts in both their `run:` step
and `paths:` filter) under `plans/20260819-174858_plan.md`, whose scope was explicitly
limited to those three workflows (the ones relevant to the model/embedding reference
consistency check that plan was adding). That plan's follow-up notes flagged
`agent-docs-consistency.yml` and `mcp-docs-consistency.yml` as carrying the identical defect
but explicitly out of scope for that specific plan, to be picked up as an independent fix.

A related but distinct requirement, `requires/done/20260818-220535_require.md`, includes a
one-line implementation instruction to fix `mcp-docs-consistency.yml`'s script invocation as
a minor sub-step of a much larger, unrelated requirement (correcting MCP startup-mode
documentation drift and extending the generated MCP inventory). That requirement does not
mention or touch `agent-docs-consistency.yml` at all, and its primary scope (startup-mode
documentation content, canonical doc creation, generated-inventory extension, a new drift
check) is unrelated to the narrow CI-invocation defect covered here. This requirement is
therefore not a duplicate of that one: it targets both broken workflows as a self-contained,
minimal fix, independent of whether or when the larger startup-mode documentation work is
implemented.

## Problem

`.github/workflows/agent-docs-consistency.yml` and
`.github/workflows/mcp-docs-consistency.yml` each invoke a script path
(`tools/check_agent_docs_consistency.py`, `tools/check_mcp_docs_consistency.py`) that no
longer exists in the repository. Any push or pull request that triggers either workflow's
`paths:` filter causes the run step to fail with a Python "No such file or directory" /
module-not-found error, for reasons entirely unrelated to the actual content of the
`docs/05_agent_*.md` / MCP-related doc files being checked. The workflows currently provide
no real documentation-consistency protection for the agent and MCP doc domains.

## Reason for change

CI should fail only when there is a genuine documentation-consistency problem, not because
the workflow itself references a deleted script path. Until this is fixed, the agent and MCP
docs-consistency checks are silently non-functional (or unconditionally broken), leaving
both doc domains without the automated drift protection that `check_docs_consistency.py`
already provides for the other three domains once their workflows were fixed. This is a
small, low-risk, mechanical fix independent of any content-level documentation work.

## Implementation intent

Update the `run:` step of each of the two workflow files to invoke the consolidated
`tools/check_docs_consistency.py` script with the appropriate `--domain` flag, matching the
pattern already specified (planned, not yet implemented) for `overview-docs-consistency.yml`,
`deployment-docs-consistency.yml`, and `rag-docs-consistency.yml` in
`plans/20260819-174858_plan.md`'s Design/Implementation steps. Do not change any other part
of either workflow file (triggers, `paths:` filters, job/step names, Python setup) unless the
consolidated script requires a different invocation convention than the one already specified
for the other three domains.

## Implementation instructions

1. In `.github/workflows/agent-docs-consistency.yml`, replace the run step:
   ```yaml
   run: |
     set -euo pipefail
     python tools/check_agent_docs_consistency.py
   ```
   with:
   ```yaml
   run: |
     set -euo pipefail
     python tools/check_docs_consistency.py --domain agent
   ```
2. In `.github/workflows/mcp-docs-consistency.yml`, replace the run step:
   ```yaml
   run: |
     set -euo pipefail
     python tools/check_mcp_docs_consistency.py
   ```
   with:
   ```yaml
   run: |
     set -euo pipefail
     python tools/check_docs_consistency.py --domain mcp
   ```
3. Leave the `on:` triggers, `paths:` filters (including the stale
   `tools/check_agent_docs_consistency.py` / `tools/check_mcp_docs_consistency.py` path
   entries under `paths:`, if present — verify against the current file content and update
   only if they still reference the deleted script paths, to keep the trigger consistent with
   the new invocation), job name, and Python setup steps unchanged unless the stale path
   reference is found there too.
4. Confirm `python tools/check_docs_consistency.py --domain agent` and
   `python tools/check_docs_consistency.py --domain mcp` both run locally (from the repo
   root) without a "script not found" error, matching the validation specified (to be
   performed once implemented) for the `overview`/`deployment`/`rag` domains in
   `plans/20260819-174858_plan.md`'s Validation plan.
5. Do not modify `tools/check_docs_consistency.py`, `tools/_docs_consistency_lib.py`, or any
   `docs/*.md` file as part of this fix — this requirement is scoped strictly to the two
   workflow files' invocation command.
