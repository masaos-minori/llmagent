# Replace numeric ingestion sentinels with explicit URL statuses

## Priority
Low

## Target files
- `scripts/rag/ingestion/ingester.py`
- `tests/rag/ingestion/test_rag_ingester.py`

## Background
`IngestUrlResult` uses `n_failed = -1` as a sentinel value to encode unexpected URL-level failures. This approach mixes error signaling with quantitative data, making aggregations unreliable and forcing downstream consumers to implement specialized logic to handle the sentinel.

## Problem
1. **Sentinel usage**: Using `-1` for `n_failed` breaks simple summations (e.g., `sum(r.n_failed for r in results)` would yield incorrect totals).
2. **Ambiguity**: It is unclear whether a result with `n_failed = -1` also implies other states like `skipped`.
3. **Type Safety**: Negative integers are not a type-safe way to represent discrete error states.

## Reason for change
To improve code clarity, maintainable aggregations, and type safety by using an explicit status enumeration instead of magic numbers.

## Implementation intent
Introduce an explicit `IngestionStatus` (or extend `IngestionFailureReason`) to represent the outcome of a URL ingestion attempt and ensure all counts in `IngestUrlResult` are non-negative.

## Implementation instructions
1. Update `IngestionFailureReason` in `scripts/rag/ingestion/ingester.py` to include `UNEXPECTED_FAILURE = "unexpected_failure"`.
2. Modify `IngestUrlResult` dataclass:
   - Ensure `n_failed` and `n_success` are always non-negative.
   - Add a `status` field of type `IngestionFailureReason | None = None`.
   - (Optional but recommended) Deprecate or remove the `skipped` boolean if `IngestionFailureReason.SKIPPED` is used instead.
3. Refactor `RagIngester` implementation:
   - Replace all instances where `n_failed = -1` is assigned with appropriate `status` assignment and `n_failed = 0`.
   - Update `ingest_all()` aggregation logic to use the new status and non-negative counts.
   - Update logging to include the explicit status.
4. Update all tests in `tests/rag/ingestion/test_rag_ingester.py` to reflect the changes in `IngestUrlResult` construction and assertions.

## Acceptance criteria
- No instance of `n_failed = -1` exists in the codebase.
- All `n_failed` and `n_success` values are $\ge 0$.
- `IngestUrlResult` provides clear, typed status information via `failure_reason` or a new `status` field.
- Aggregate reporting correctly reflects successful, failed, and skipped URLs.

## Tests
- Test successful ingestion (status: None/Success, n_success > 0).
- Test skipped URL (status: SKIPPED, n_success: 0, n_failed: 0).
- Test validation failure (status: VALIDATION_FAILED, n_success: 0, n_failed: 0).
- Test embedding failure (status: EMBEDDING_FAILED, n_success: 0, n_failed: 0).
- Test storage failure (status: STORAGE_FAILED, n_success: 0, n_failed: 0).
- Test unexpected exception (status: UNEXPECTED_FAILURE, n_success: 0, n_failed: 0).
- Verify that total counts in `ingest_all()` match expected sums.
