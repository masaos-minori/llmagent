# Resolve unknown replacement for deprecated config/rag_pipeline.toml

## Priority

Low

## Target Files

- `docs/00_governance_05_deprecated-items.md` — config/rag_pipeline.toml entry
- `config/rag_pipeline_mcp_server.toml`

## Background

`docs/00_governance_05_deprecated-items.md` (lines 9-13) lists `config/rag_pipeline.toml`
as a deprecated configuration file with:

```
- **config/rag_pipeline.toml**
  - Current Replacement: none (replacement unknown)
  - Status: Needs confirmation
  - Notes: File may have been replaced during reorganization
  - Evidence: Requires source code investigation
```

Source investigation confirms:
- `config/rag_pipeline.toml` no longer exists in the repository.
- `config/rag_pipeline_mcp_server.toml` is the only RAG-pipeline-related config file
  currently present under `config/`.
- The RAG pipeline MCP server code loads this file directly:
  `scripts/mcp_servers/rag_pipeline/rag_pipeline_models.py` documents
  "Load from rag_pipeline_mcp_server.toml; raises on failure (fail-fast)" and calls
  `ConfigLoader().load("rag_pipeline_mcp_server.toml")`; `scripts/mcp_servers/rag_pipeline/rag_pipeline_server.py`
  registers the same filename as `own_config_file`.
- `implementations/done/20260722-181341_03_rag_stale_config_references.md` records an
  earlier cleanup that removed stale `rag_pipeline.toml` references and states the
  underlying mechanism: each MCP server loads its own `<key>_mcp_server.toml` instead of
  a shared `rag_pipeline.toml`. This confirms `config/rag_pipeline_mcp_server.toml` is the
  de facto replacement, consistent with the `rules/coding.md` convention "MCP server
  addition: create `config/<key>_mcp_server.toml`".
- One stale docstring reference to `config/rag_pipeline.toml` remains in
  `scripts/rag/ingestion/crawler_utils.py:48` (comment only, not a load path) — noted here
  for completeness but out of scope for this documentation-only requirement.
- `docs/00_governance_07_needs-confirmation-inventory.md` has no entry cross-referencing
  this item, so the "Needs confirmation" flag in the deprecated-items doc is currently a
  dangling, untracked item.

## Problem

The deprecated-items doc's `Current Replacement` field for `config/rag_pipeline.toml` says
"none (replacement unknown)" even though the replacement can be determined from current
source code and a prior implementation record. This leaves governance documentation
inaccurate/stale and leaves an unresolved "Needs confirmation" flag with no corresponding
inventory entry, making it easy to overlook during future audits.

## Reason for Change

Per `rules/coding.md` "Documentation notes — Current behavior classification", a doc note
whose underlying discrepancy no longer exists should be resolved rather than left as an
open, ambiguous "Needs confirmation" flag once the answer is verifiable against current
code. Updating the field improves governance-doc accuracy and removes a dangling
unconfirmed item.

## Implementation Intent

Update the `config/rag_pipeline.toml` entry in
`docs/00_governance_05_deprecated-items.md` to record the verified replacement
(`config/rag_pipeline_mcp_server.toml`) and change its status from "Needs confirmation" to
resolved/verified, with a note referencing the supporting evidence (code references and
`implementations/done/20260722-181341_03_rag_stale_config_references.md`). Also determine
whether this item needs an entry added to
`docs/00_governance_07_needs-confirmation-inventory.md`, or whether it should simply be
removed from that inventory's scope since it is being resolved directly.
