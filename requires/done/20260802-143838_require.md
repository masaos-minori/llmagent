## Background
`docs/04_mcp_06_04_major-default-values.md` maintains a "Major Default Values" table (the file's single table, lines 16-28) intended as a quick-reference of important default configuration values across the MCP server stack, each with its default value, production recommendation, and config-file/source location. The table currently has 11 rows and 4 columns: パラメータ (parameter) / デフォルト (default) / Production推奨 (production recommendation) / Configファイル (config file / source).

Verification against current source confirms:
- `half_open_cooldown_sec` is defined in `scripts/shared/mcp_health.py:27` as a keyword parameter of `McpServerHealthRegistry.__init__`, with default value **30.0 seconds**. It is used at `scripts/shared/mcp_health.py:124` (`is_unavailable`) to gate the UNAVAILABLE -> HALF_OPEN transition. It is not overridden in production: `scripts/agent/factory.py:311` instantiates `McpServerHealthRegistry()` with no override arguments, so the 30.0s default applies at runtime.
- The sibling parameter `failure_threshold` (also a constructor argument of the same `McpServerHealthRegistry` class, `scripts/shared/mcp_health.py:26`, default `3`) is already documented in the table as the row "ヘルスレジストリの閾値" (line 22), but `half_open_cooldown_sec` from the same class has no corresponding row.
- The table has no structured column distinguishing "measured" (verified against current code) from "estimated/unmeasured" values. Two rows (line 22 "ヘルスレジストリの閾値" and the supplementary note at line 30) carry an informal, inconsistent `(Explicit in code)` parenthetical appended inside the Configファイル cell — this is not a real column and the other 9 rows carry no such annotation at all, so a reader cannot tell from the table alone which of the 11 rows have actually been re-verified against source.

## Problem
1. The table is incomplete: it omits `half_open_cooldown_sec` (30 seconds), a directly relevant tunable of the same health-registry circuit-breaker mechanism whose sibling parameter (`failure_threshold`) is already listed.
2. The table provides no reliable way for a reader to distinguish values that have been directly verified against current code ("measured") from values that are estimated, stale, or unverified. The existing `(Explicit in code)` annotations are ad hoc, inconsistently applied (2 of 11 rows), and embedded inside an unrelated column rather than being their own column.

## Reason for change
A table titled "Major Default Values" that omits a real default value undermines its purpose as a complete reference. Without an explicit, consistent source/evidence indicator per row, a reader has no way to know which of the 11 values can be trusted without independently re-verifying each one against source — defeating the purpose of having a reference table at all.

## Implementation intent
Keep the existing table's structure, column set, and row order intact except for the two required additions:
- Add one new row for `half_open_cooldown_sec`, placed adjacent to (immediately after, to preserve topical grouping) the existing "ヘルスレジストリの閾値" (`failure_threshold`) row, since both come from the same `McpServerHealthRegistry.__init__` constructor.
- Add one new column (e.g. "根拠" / "Source" / "Evidence" — pick a label consistent with the file's existing Japanese column-header style) that marks, for every existing row plus the new row, whether the value is "measured" (directly re-verified against current code in this pass, with a concrete code reference) or "estimated" (not re-verified in this pass, needs confirmation).

Do not change any other row's value, and do not change any actual default value in source code — this is a documentation-only change.
