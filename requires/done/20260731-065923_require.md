# Requirement: Fix MCP Subprocess Group Leak on Shutdown

## Priority

Critical

## Target Files

- `scripts/agent/http_lifecycle.py`
- `scripts/agent/repl.py`

## Background

When MCP server HTTP subprocesses are terminated during shutdown, if `getpgid()` fails, the process group is not tracked and will not be killed via `os.killpg()`. Only the parent process is terminated, leaving child processes as zombies.

## Problem

In `http_lifecycle.py`, when a subprocess is started with `start_new_session=True`:

```python
# http_lifecycle.py:290
try:
    pgid = os.getpgid(proc.pid)
except OSError:
    # getpgid fails — process group NOT registered
    pass
```

This means:

1. Subprocess is started with `start_new_session=True` (new session leader)
2. `getpgid()` fails to retrieve its process group ID
3. The subprocess is never added to `_http_pgids`
4. During shutdown, `os.killpg()` is never called for this process
5. Parent process receives `terminate()`, but child processes remain as zombies

Additionally, `repl.py:797-799` only calls `proc.terminate()` without killing the process group:

```python
# repl.py:797-799
finally:
    proc.terminate()  # Only kills parent, not children
```

## Reason for Change

Zombie processes consume system resources (PIDs), can cause port conflicts on restart, and violate security policies by running unexpected processes.

## Implementation Intent

Ensure all MCP subprocesses and their descendants are properly terminated during shutdown, even when `getpgid()` fails.

## Implementation Instructions

### Option A: Use psutil to recursively find and kill process tree

```python
import psutil

def _kill_process_tree(pid):
    """Kill a process and all its descendants."""
    try:
        parent = psutil.Process(pid)
        children = parent.children(recursive=True)
        
        # Send SIGTERM to all descendants first
        for child in children:
            try:
                child.send_signal(signal.SIGTERM)
            except psutil.NoSuchProcess:
                pass
        
        # Then send SIGTERM to parent
        parent.send_signal(signal.SIGTERM)
        
        # Wait for termination with timeout
        gone, alive = psutil.wait_procs(children + [parent], timeout=5)
        
        # Force kill any remaining
        for p in alive:
            try:
                p.kill()
            except psutil.NoSuchProcess:
                pass
    except psutil.NoSuchProcess:
        pass
```

Then replace `os.killpg(pgid, signal.SIGTERM)` with `_kill_process_tree(pid)` in shutdown logic.

### Option B: Fallback to agent's own process group

If `getpgid()` fails, use the agent's own process group as a fallback:

```python
try:
    pgid = os.getpgid(proc.pid)
except OSError:
    logger.warning(f"Failed to get pgid for {proc.pid}, using agent process group")
    pgid = os.getpgrp()  # Agent's own process group
```

### Recommendation

Option A is preferred because it handles arbitrary process trees regardless of whether they share the agent's process group. Option B may kill unrelated processes if the agent shares a process group with other services.

## Acceptance Criteria

1. All MCP subprocesses and their descendants are terminated during shutdown
2. No zombie processes remain after shutdown
3. No port conflicts occur on subsequent startup
4. Normal shutdown path (when `getpgid()` succeeds) is unaffected — no regression
