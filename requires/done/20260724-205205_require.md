# Signal handler race condition with asyncio event loop

## Priority

Medium

## Target Files

- `scripts/agent/repl.py` — AgentREPL.run(), _read_input(), _sigterm_handler()

## Background

Signal handlers set `shutdown_event.set()` when SIGTERM or SIGINT is received. The REPL input loop waits on both user input and the shutdown event via `asyncio.wait()`.

## Problem

In `repl.py:353-365`:

```python
done, pending = await asyncio.wait(
    {input_coro, shutdown_coro},
    return_when=asyncio.FIRST_COMPLETED,
)
```

The `shutdown_coro` waits on `shutdown_event.wait()`. When a signal arrives, `_sigterm_handler()` calls `shutdown_event.set()`, which wakes up `shutdown_coro`. However, there is a window between the signal arrival and the completion of `shutdown_coro` where the event loop may process other tasks before returning from `asyncio.wait()`.

Additionally, signal handlers run in the main thread and may interrupt the event loop at any point. If the signal arrives while the event loop is processing another coroutine, the signal handler's effect is delayed until the next event loop tick.

## Reason for Change

Race conditions between signal handling and async I/O can cause:
- Delayed shutdown response (seconds instead of milliseconds)
- Inconsistent state during shutdown (e.g., partial cleanup)
- Missed signals if the handler is already executing

## Implementation Intent

Ensure signal-induced shutdown is detected immediately by the event loop, without relying on the asyncio.Event mechanism that introduces latency through the event loop scheduling cycle.

## Implementation Instructions

1. Use `loop.add_signal_handler()` to register a callback that directly cancels `input_coro` (the pending input task), rather than setting an event.
2. Cancel the pending input future so `asyncio.wait()` returns immediately.
3. Set `shutdown_requested` flag as a side effect of cancellation.
4. Ensure the signal handler does not perform any blocking operations.

Alternative approach:
- Replace `asyncio.wait()` with `asyncio.wait_for(input_coro, timeout=None)` wrapped in a try/except for `CancelledError`, triggered by the signal handler cancelling the input task.

## Acceptance Criteria

- [ ] Shutdown is initiated immediately after signal reception
- [ ] No missed signals during asyncio.wait() execution
- [ ] No race condition between signal handler and event loop
- [ ] Signal handler performs no blocking operations

## Tests

- Unit test: send SIGTERM while asyncio.wait() is blocked; verify immediate return
- Integration test: rapid signal delivery; verify all signals are handled correctly
