# _on_llm_wait_end callback not invoked consistently across LLMTransportError paths

## Priority

Critical

## Target Files

- `scripts/agent/orchestrator.py` — Orchestrator._handle_llm_turn()

## Background

`Orchestrator._handle_llm_turn()` handles two distinct paths for `LLMTransportError`: one where `LLMTurnRunner.run()` returns a result with `result.exception is not None`, and another where `run()` raises the exception directly.

## Problem

In `orchestrator.py:424-425` (result.exception path):

```python
if self._on_llm_wait_end:
    self._on_llm_wait_end()
```

This is inside the `else` branch of `if result.exception is not None:` (line 426). When `result.exception is not None`, neither `_on_llm_wait_end` nor `_on_turn_end` is called.

In `orchestrator.py:440-441` (raise path):

```python
except LLMTransportError as e:
    ...
    if self._on_llm_wait_end:
        self._on_llm_wait_end()
```

The `raise` path correctly calls `_on_llm_wait_end`.

The asymmetry means wait-end callbacks (e.g., UI state restoration) are skipped when `LLMTurnRunner.run()` returns an exception instead of raising it.

## Reason for Change

Missing `_on_llm_wait_end` invocation causes inconsistent UI/state behavior after LLM transport failures, depending on how the error propagates from `LLMTurnRunner.run()`.

## Implementation Intent

Make `_on_llm_wait_end` invocation consistent across both error paths. Add `_on_llm_wait_end` call to the `result.exception is not None` path before returning the result.

## Implementation Instructions

1. In `Orchestrator._handle_llm_turn()`, add `_on_llm_wait_end` call in the `if result.exception is not None:` branch, before calling `_on_error` and returning the result.
2. Ensure the call order matches the raise path: `_on_llm_wait_end` → `_on_error` → return.
3. Verify no double-invocation occurs if `LLMTurnRunner.run()` both sets `result.exception` and raises (which would be a bug in `LLMTurnRunner`).

## Acceptance Criteria

- [ ] `_on_llm_wait_end` is called when `LLMTurnRunner.run()` returns result with exception
- [ ] `_on_llm_wait_end` is called when `LLMTurnRunner.run()` raises LLMTransportError
- [ ] Both paths invoke callbacks in the same order
- [ ] No double-invocation of any callback
