# Requirement: Deduplicate File Handle Cleanup Logic in Health Check Paths

## Priority

Low — cleanup works correctly but duplicated code increases maintenance burden

## Target Files

- `scripts/agent/http_lifecycle.py` (lines 333-336, 366-370)

## Background

The `HttpServerLifecycleManager.start()` method has two paths that clean up file handles when a subprocess exits early or times out:
1. Early exit path (line 333-336): triggered when `proc.poll() is not None` during health polling
2. Timeout path (line 366-370): triggered when health check timeout expires

Both paths perform identical cleanup operations.

## Problem

The cleanup logic is duplicated across two code paths, increasing the risk of future bugs where one path is updated but the other is missed. This violates the DRY principle.

## Reason for Change

Reduce maintenance burden and eliminate the risk of inconsistent cleanup behavior by extracting shared logic into a single method.

## Implementation Intent

Extract the file handle cleanup logic into a dedicated private method `_cleanup_server_resources()` and call it from both paths.

## Implementation Instructions

1. Create a new private method `_cleanup_server_resources(self, server_key: str)` that performs all three cleanup operations:
   - Read stderr tail via `self._read_stderr_tail(server_key)`
   - Pop and close the stderr file handle from `self._stderr_files`
   - Pop the log path from `self._stderr_log_paths`
2. Replace the inline cleanup code in both paths with calls to this method
3. Ensure the method returns the stderr content so callers can log it before cleanup
4. Add unit tests covering both paths verify identical behavior

## Acceptance Criteria

- [ ] No duplicate cleanup code exists between the two paths
- [ ] Both paths produce identical results (same stderr content, same resource state after cleanup)
- [ ] Unit tests cover both paths and verify equivalence
- [ ] No regression in existing behavior

## Tests

- Unit test verifying early-exit path produces same cleanup result as timeout path
- Unit test verifying `_cleanup_server_resources()` properly closes all resources
