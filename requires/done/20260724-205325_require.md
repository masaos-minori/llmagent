# Duplicate ephemeral message filtering across turn lifecycle

## Priority

Low

## Target Files

- `scripts/agent/orchestrator.py` — Orchestrator._clear_previous_turn_ephemeral_messages(), _handle_history_compression()

## Background

Ephemeral and memory-injected messages are filtered out from conversation history at two points: before each turn starts, and after history compression.

## Problem

In `orchestrator.py:526-537`:

```python
def _clear_previous_turn_ephemeral_messages(self) -> None:
    ctx = self._ctx
    ctx.conv.history = [
        m for m in ctx.conv.history
        if not m.get("_ephemeral") and not m.get("_memory_injected")
    ]
```

In `orchestrator.py:396-402`:

```python
ctx.session.replace_messages([
    m for m in ctx.conv.history
    if not m.get("_ephemeral") and not m.get("_memory_injected")
])
```

Both methods apply the exact same filter condition. The first runs at turn start (before LLM call), the second runs after history compression. While functionally correct, this is redundant work.

## Reason for Change

Redundant filtering increases CPU usage on every turn and makes maintenance harder — changes to the filter condition must be applied in both places. A single source of truth for ephemeral message removal would be cleaner.

## Implementation Intent

Consolidate ephemeral message filtering into a single location. Since `_clear_previous_turn_ephemeral_messages()` already runs before every turn and removes ephemeral messages, the filtering in `_handle_history_compression()` can be removed.

## Implementation Instructions

1. Remove the ephemeral/memory-injected filtering from `_handle_history_compression()`.
2. Keep only the `replace_messages()` call without the list comprehension filter.
3. Verify that `_clear_previous_turn_ephemeral_messages()` always runs before any path that modifies `ctx.conv.history`.
4. If `_handle_history_compression()` needs to preserve ephemeral messages during compression (e.g., for context), add an explicit comment explaining why.

## Acceptance Criteria

- [ ] Ephemeral message filtering occurs exactly once per turn
- [ ] Both paths produce identical results
- [ ] No regression in ephemeral message handling correctness
- [ ] Filter logic is centralized in one method
