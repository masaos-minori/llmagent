# Evaluate hoisting shell_server.py's local shutil import in health() to module level

## Priority
Medium

## Target files
- `scripts/mcp_servers/shell/shell_server.py` (health())
- `scripts/mcp_servers/git/git_server.py` (sibling convention for comparison)

## Background
`scripts/mcp_servers/shell/shell_server.py`'s `health()` endpoint does a local `import shutil as _shutil` wrapped in `try/except (ImportError, OSError)`, letting the endpoint degrade gracefully (return a degraded health status) if the import were ever to fail. Sibling file `scripts/mcp_servers/git/git_server.py` imports `shutil` at module (top) level instead.

Found during a `prompts/04_refactor.md` cycle on `shell_server.py` (2026-08-16). Not implemented there because hoisting the import would change the failure mode: currently an (unrealistic) `ImportError` on `shutil` would produce a degraded health response; after hoisting, the same failure would instead crash the whole app at startup. This is a behavior change in an edge case, however unlikely `shutil` failing to import actually is in practice.

## Problem
Inconsistent import patterns between `shell_server.py` (local try/except import) and `git_server.py` (top-level import) in their respective `health()` endpoints.

## Reason for change
Consistency across server modules improves maintainability and reduces cognitive load. However, hoisting the import changes the failure mode from degraded health response to startup crash, which is a behavior change that needs careful consideration.

## Implementation intent
Confirm whether the graceful-degradation behavior for a `shutil` import failure is actually meaningful (i.e., has this ever been observed, or is it purely defensive boilerplate copied from elsewhere?). If it's purely defensive and inconsistent with the sibling `git_server.py`'s top-level-import convention, hoist it for consistency and document the (accepted) change in startup-failure behavior. If the graceful-degradation behavior is intentional, leave it and close this issue as "no action, confirmed intentional."

## Implementation instructions
### Phase 1: Discovery
1. Check whether this same local-vs-top-level-import inconsistency exists in other `*_server.py` health checks before deciding whether to fix it here alone or as a repo-wide convention pass.
2. Determine whether the graceful-degradation behavior for a `shutil` import failure is actually meaningful.

### Phase 2: Code Change (if hoisting)
3. Move `import shutil` to module level, remove the `try/except`.
4. Add a characterization test for `health()` when `shutil.which` returns `None` (the realistic degradation case, distinct from the unrealistic `ImportError` case).

### Phase 3: Validation
5. Run `tests/mcp_servers/shell/test_shell_server_endpoints.py` (new 2026-08-16 characterization tests) plus the new test for `shutil.which() is None` if the import is hoisted.

## Acceptance criteria
- Either: the import is hoisted, the `try/except (ImportError, OSError)` around the import itself is removed, and a characterization test for the realistic `shutil.which() is None` case is added and passes; or
- The current behavior is confirmed intentional and documented, with no code change.

## Tests
`tests/mcp_servers/shell/test_shell_server_endpoints.py` (new 2026-08-16 characterization tests) plus a new test for `shutil.which() is None` if the import is hoisted.
