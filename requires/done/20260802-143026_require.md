# Remove File Index / Related Documents duplication in docs/04_mcp_00_document-guide.md

## Priority
Low

## Target files
- `docs/04_mcp_00_document-guide.md` (only)

## Background
`docs/04_mcp_00_document-guide.md` is the entry-point document for the MCP documentation
set (45 `docs/04_mcp_*.md` files). It contains a "File Index" section (canonical, complete
file listing, ~45 files across grouped rows) and a separate "Related Documents" section
(currently 11 entries). This mirrors a documented cross-cutting pattern in this domain
(`docs_review_mcp.md` §2, item 7, "削除候補: docs/04_mcp_00_document-guide.md / File Index
とRelated Documentsの重複部分") where the same file inventory is maintained in two places,
requiring every file addition/removal to be applied twice to stay accurate.

## Problem
Verified against the current file (as of 2026-08-02):
- "File Index" (lines 83-115) is the complete, canonical listing of all ~45
  `docs/04_mcp_*.md` files.
- "Related Documents" (lines 165-177) lists 11 files. This is not a literal byte-for-byte
  copy of File Index, but it duplicates File Index's role: every entry in Related Documents
  already appears in File Index, and the list is maintained as a second, parallel inventory
  rather than as "links to files actually discussed in this guide's own prose."
- Concrete evidence that the duplication is live and already causing drift risk: when
  `04_mcp_01_tool_ownership_matrix.md` and `04_mcp_02_service_boundaries.md` were added to
  the doc set (commit `7b6b060b6`, "docs: create MCP tool ownership matrix and service
  boundaries"), both files were added to File Index (lines 89-90) AND mechanically appended
  to Related Documents (lines 168-169) — even though neither file is mentioned anywhere in
  the guide's routing table, Canonical Source Rules, or any other prose section. This is
  the exact "must update both lists on every file change" failure mode the original review
  flagged.
- Checked every markdown link of the form `[...](04_mcp*...)` in the file: the only
  full-filename link that appears in body prose outside of File Index and Related Documents
  themselves is `[04_mcp_04_04_mdq.md](04_mcp_04_04_mdq.md)` in the "Navigation to Major
  Known Issues" section (line 69). The routing table ("エージェントクエリルーティングテー
  ブル") and "Canonical Source Rules" section reference sections only by short prefix
  (e.g. `04_mcp_01`, `04_mcp_03`, `04_mcp_06`), not by the specific split-file name that
  Related Documents currently lists (e.g. `04_mcp_01_system_overview.md`,
  `04_mcp_03_01_dispatch-and-routing.md`).

This issue is not resolved and still applies.

## Reason for change
Self-duplication within the entry-point document creates ongoing update-drift risk: every
time a file is added to or removed from the MCP doc set, both File Index and Related
Documents must be updated, and as shown above this has already been missed in a way that
adds files to Related Documents without any prose justification. Fixing this now (while the
list is still small, at 11 entries) is cheaper than after further growth.

## Implementation intent
Keep "File Index" as the single canonical, complete file listing (no change needed there).
Redefine the purpose of "Related Documents" so it only contains files that are actually
referenced or discussed in this guide's own body text (outside of File Index and Related
Documents themselves), rather than serving as a second, independently-maintained inventory
of "major" files.

## Implementation instructions
1. Re-verify, at implementation time, every full-filename markdown link and explicit file
   mention in `docs/04_mcp_00_document-guide.md`'s prose (routing table, Canonical Source
   Rules, Navigation to Major Known Issues, Migration Notes, Known Limitations, 未確認事項),
   outside of the File Index and Related Documents sections themselves.
2. Decide, and document the decision inline (e.g. a one-line note above "Related Documents"
   stating the inclusion rule), whether the routing table's short-prefix references (e.g.
   `04_mcp_01`, `04_mcp_03_06`) count as "referenced in prose" for the purpose of this
   section. Two acceptable resolutions, either is compliant with the issue's intent as long
   as it is applied consistently and documented:
   - Narrow interpretation: only explicit full-filename links count (currently only
     `04_mcp_04_04_mdq.md` qualifies) — Related Documents shrinks to that one entry, or is
     removed entirely if a single-entry section is not useful and folded into "Navigation to
     Major Known Issues" instead.
   - Section-level interpretation: treat the routing table's short-prefix rows as
     referencing the primary/first file of that section's split (matching the existing
     YAML frontmatter `related:` list at the top of the file, which already reflects this
     narrower 9-file set) — Related Documents becomes that primary-file set, and drops
     `04_mcp_01_tool_ownership_matrix.md` and `04_mcp_02_service_boundaries.md` since neither
     is referenced in prose.
3. Under either resolution, `04_mcp_01_tool_ownership_matrix.md` and
   `04_mcp_02_service_boundaries.md` must be removed from Related Documents unless a genuine
   prose reference to them is added first — they were appended without any corresponding
   body-text mention and are the clearest instance of the duplication this issue targets.
4. Do not change the actual set of 45 `docs/04_mcp_*.md` files as part of this change —
   File Index's content and the underlying file set are out of scope.
5. Do not modify File Index's role or content beyond what is needed to keep it the sole
   canonical listing (no content changes expected there).

## Acceptance criteria
- "File Index" in `docs/04_mcp_00_document-guide.md` remains the complete, canonical file
  listing, unchanged in content/role.
- "Related Documents" no longer duplicates the full/major-file inventory already present in
  File Index; it contains only entries traceable to an explicit reference in this guide's
  own prose, per whichever inclusion rule is chosen and documented in step 2 above.
- `04_mcp_01_tool_ownership_matrix.md` and `04_mcp_02_service_boundaries.md` are not present
  in Related Documents unless a genuine prose reference to them exists in the same change.
- No other `docs/04_mcp_*.md` file's content, and no other section of
  `docs/04_mcp_00_document-guide.md`, is altered.

## Tests
Documentation-only change; no automated tests apply. Verify manually (or via a doc-consistency
check/grep) that every entry remaining in "Related Documents" corresponds to an actual
in-prose reference elsewhere in the file, and that "File Index" is unchanged.
