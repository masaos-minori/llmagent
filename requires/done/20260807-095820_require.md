## Background
The `05_agent_*.md` document set mixes design/operational judgment with content that is mechanically derivable from code. A review (`memo-doc-agent-review.md`) identified what to keep vs. remove per chapter.

## Problem
The configuration chapter carries exhaustive field/default-value tables that duplicate `config/agent.toml` and its dataclass definitions, adding drift risk without operational value.

## Reason for change
This chapter should serve as the canonical source for configuration ownership and reload boundaries only. Full field/default-value tables increase staleness risk without adding decision value.

## Implementation intent
Keep this chapter as the canonical source for configuration ownership and reload boundaries. Remove full field/default-value tables and dataclass-structure explanations. Point to `config/agent.toml` / the relevant dataclass for exact values.

## Implementation instructions
1. Read all five files in full.
2. Identify sections containing: full mechanical field lists per config, exhaustive default-value tables, dataclass-structure explanations, plain "this field is this type" statements.
3. Remove or compress those sections while preserving: which files own which settings, the Hot-reloadable / Restart-required / Startup-only judgment criteria, strict-mode settings required in production, the danger of an empty `allowed_tools` list, the operational meaning of `tool_safety_tiers`, the config-drift detection approach, what operators must do after a config change.
4. Where exact default values are needed, point to `config/agent.toml` rather than transcribing a table that will go stale.
5. Restructure remaining content to follow the template: Purpose / Design Intent / Responsibility Boundary / Key Constraints / Operational Notes / Known Limitations / Related Docs.
6. State Hot-reloadable vs. Restart-required vs. Startup-only classification as a judgment criterion, not just a per-field label table.
7. If a design rationale cannot be recovered from the current text, mark it `Needs Confirmation` rather than guessing.
8. Run `python tools/check_agent_docs_consistency.py` after editing to confirm no broken internal links or removed-file references were introduced.

## Acceptance criteria
