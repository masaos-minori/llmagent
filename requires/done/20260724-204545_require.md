# First-turn background task exceptions silently swallowed without user notification

## Priority

Critical

## Target Files

- `scripts/agent/orchestrator.py` — Orchestrator._append_user_message(), _discard_and_log()

## Background

On the first turn, `_on_first_turn` callback is invoked as an asyncio background task. Its completion is tracked by `_discard_and_log`, which logs exceptions but does not surface them to the user.

## Problem

In `orchestrator.py:557-561`:

```python
if ctx.stats.stat_turns == 1 and self._on_first_turn is not None:
    _task = asyncio.create_task(self._on_first_turn(line))
    self._background_tasks.add(_task)
    _task.add_done_callback(self._discard_and_log)
```

`_discard_and_log` (line 564-589) handles exceptions:

```python
def _discard_and_log(self, task: asyncio.Task[Any]) -> None:
    exc = task.exception()
    if exc is not None:
        if isinstance(exc, asyncio.CancelledError):
            self._consecutive_bg_failures = 0
        else:
            self._consecutive_bg_failures += 1
            if self._consecutive_bg_failures == 1:
                logger.warning("First background task failure: %s", exc)
            elif self._consecutive_bg_failures >= BG_FAILURE_THRESHOLD:
                logger.error("Consecutive background task failures (%d): %s", ...)
            else:
                logger.warning("Background task failure #%d: %s", ...)
```

The first failure produces only a log-level WARNING. The user sees no indication that the first-turn setup failed. Subsequent turns may behave unexpectedly because the first-turn initialization did not complete.

## Reason for Change

First-turn setup failures have high impact on session behavior. Silent swallowing of these exceptions makes debugging difficult and can cause subtle bugs that are hard to reproduce.

## Implementation Intent

Surface first-turn background task exceptions to the user immediately, regardless of whether subsequent tasks also fail. Provide a clear error message so the user knows the initial setup did not complete.

## Implementation Instructions

1. In `_discard_and_log`, when `self._consecutive_bg_failures == 1`, also call `self._on_error(exc)` or emit a visible warning to the CLI view.
2. Consider adding a method like `_notify_first_turn_failure()` that writes a fatal/warning message to the user's terminal.
3. Optionally, set `ctx.conv.is_processing = False` or similar flag to indicate the session is in a degraded state.
4. Ensure the notification is idempotent — do not re-notify if the same task fails multiple times.

## Acceptance Criteria

- [ ] First-turn background task exception is notified to the user on first occurrence
- [ ] Exception is logged at appropriate level
- [ ] Session continues to operate (or shows a clear degraded-state indicator)
- [ ] No duplicate notifications for the same failure
