# Harden `delete_models.py` request validation and config immutability

## Priority
Low

## Target files
- `scripts/mcp_servers/file/delete_models.py` (`FileDeleteConfig`, `DeleteFileRequest`, `DeleteDirectoryRequest`)
- `scripts/mcp_servers/file/delete_service.py` (consumer of these models)

## Background
Three related, deferred hardening ideas from `scripts/mcp_servers/file/delete_models.py`'s 2026-08-14 refactor cycle:
1. `DeleteFileRequest`/`DeleteDirectoryRequest`'s `path: str` field has no validation rejecting empty strings or relative paths.
2. `path`/`dry_run` field description text differs slightly between `DeleteFileRequest` and `DeleteDirectoryRequest` ("file" vs. "directory" wording) — could be unified via a shared Mixin.
3. `FileDeleteConfig` is a mutable dataclass with no `frozen=True`, and the Pydantic request models have no `extra="forbid"`, so unexpected fields are silently accepted.

## Problem
Insufficient validation allows invalid inputs to pass through, potentially causing incorrect deletion behavior or security issues.

## Reason for change
Security and correctness: ensure all model fields are validated properly before operations execute. Prevents edge cases where malformed input causes unintended side effects.

## Implementation intent
Review all field validators and constraints in `delete_models.py`. Ensure path normalization, permission checks, and scope validation are comprehensive. Add tests for edge cases.

## Implementation instructions
### Phase 1: Investigate current usage
1. Run `rg "DeleteFileRequest\|DeleteDirectoryRequest" scripts/mcp_servers/` to identify all callers.
2. Confirm no caller sends relative paths or expects permissive behavior.

### Phase 2: Implement sub-changes independently
**Sub-change A: Path validation**
1. If confirmed safe, add `model_validator` to reject empty strings and relative paths.
2. Require absolute paths only.
3. Add characterization tests for the new rejection.

**Sub-change B: Description text unification**
1. Create shared mixin carrying the `repo_path` field.
2. Verify `model_json_schema()` output is byte-identical before and after.
3. Only proceed if schema diff shows zero unintended changes.

**Sub-change C: Config immutability**
1. Add `frozen=True` to `FileDeleteConfig` dataclass.
2. Add `extra="forbid"` to Pydantic request models.
3. Confirm no caller reassigns fields or sends extra fields.
4. Add tests for the new rejection behavior.

### Phase 3: Verify
1. Run full `tests/mcp_servers/file/` regression suite.
2. Run schema-contract tests if description text changes.

## Acceptance criteria
- Each sub-change has its own characterization tests for the newly-rejected cases.
- Existing valid requests/config usage continue to work unchanged.
- Any JSON-schema description change is explicitly reviewed and documented.

## Tests
Full `tests/mcp_servers/file/` regression suite; new tests for each newly-enforced validation rule; schema-contract tests if description text changes.
