# Requirement: Differentiate Memory Ejection Failure by Exception Type

## Priority

Medium

## Target Files

- `scripts/agent/startup.py`

## Background

When `on_session_start()` fails, the memory feature is disabled and the session continues. However, all exceptions are caught with `except Exception`, treating fatal errors (DB connection failures) the same as transient errors (embedding API failures).

## Problem

In `startup.py`:

```python
try:
    ctx.services_required.memory.on_session_start()
except Exception as exc:
    ctx.conv.memory_disabled = True
    logger.warning(...)
```

This means:

1. DB connection error → treated the same as embedding API timeout
2. Fatal errors that should block startup are silently ignored
3. Transient errors that could be retried are permanently disabled
4. User cannot distinguish between recoverable and unrecoverable failures

## Reason for Change

Different failure modes require different responses. A DB connection error should likely fail fast; an embedding API timeout could be retried or logged as a warning only.

## Implementation Intent

Categorize memory ejection failures by exception type and apply appropriate fallback strategies.

## Implementation Instructions

### Step 1: Define exception categories

Add constants or enums to categorize failures:

```python
class MemoryEjectionFailureType(Enum):
    FATAL = "fatal"        # DB connection, disk I/O
    TRANSIENT = "transient" # Embedding API timeout, rate limit
    CONFIG = "config"      # Missing config, invalid settings
```

### Step 2: Add classification method

```python
def _classify_memory_failure(self, exc: Exception) -> MemoryEjectionFailureType:
    if isinstance(exc, (sqlite3.Error, OSError)):
        return MemoryEjectionFailureType.FATAL
    elif isinstance(exc, (TimeoutError, requests.Timeout)):
        return MemoryEjectionFailureType.TRANSIENT
    else:
        return MemoryEjectionFailureType.CONFIG
```

### Step 3: Apply differentiated handling

```python
try:
    ctx.services_required.memory.on_session_start()
except Exception as exc:
    failure_type = self._classify_memory_failure(exc)
    
    if failure_type == MemoryEjectionFailureType.FATAL:
        raise RuntimeError(f"Fatal memory initialization error: {exc}") from exc
    
    elif failure_type == MemoryEjectionFailureType.TRANSIENT:
        logger.warning(f"Transient memory error, will retry later: {exc}")
        ctx.conv.memory_retry_pending = True
    
    else:  # CONFIG
        ctx.conv.memory_disabled = True
        logger.error(f"Memory configuration error: {exc}")
```

## Acceptance Criteria

1. Fatal errors (DB connection failures) cause startup to fail
2. Transient errors (API timeouts) set a retry flag instead of disabling memory
3. Config errors disable memory with an error log
4. Normal operation is unaffected — no regression
