# Requirement: Implement Log Rotation for MCP Server Stderr Logs

## Priority

High — unbounded log growth can exhaust disk space and cause system-wide failures

## Target Files

- `scripts/agent/http_lifecycle.py` (lines 81-89)

## Background

The `_open_stderr_log()` method opens stderr logs in append mode without any size limits:

```python
def _open_stderr_log(self, server_key: str) -> IO[bytes]:
    safe_key = re.sub(r"[^A-Za-z0-9_-]", "_", server_key)
    log_dir = Path("/opt/llm/logs/mcp_servers")
    log_dir.mkdir(parents=True, exist_ok=True)
    log_path = log_dir / f"{safe_key}.stderr.log"
    fh = log_path.open("ab")
```

Files are opened once per server startup and never rotated or truncated. A misbehaving MCP server will fill disk over time.

## Problem

Unbounded log growth can cause:
1. Disk space exhaustion on the host system
2. Cascading failures across all services on that system
3. Inability to write new logs even for healthy processes

## Reason for Change

Prevent disk exhaustion by implementing log rotation with configurable size limits.

## Implementation Intent

Add log rotation support to prevent unbounded growth while maintaining backward compatibility with existing log paths.

## Implementation Instructions

**Option A — Built-in rotation:**
- Add configuration parameters `max_stderr_log_size_mb` (default: 100 MB) and `max_stderr_log_files` (default: 3)
- Track current log file size before opening
- If file exceeds `max_stderr_log_size_mb`, rotate: rename to `.stderr.log.1`, then open new file
- Keep up to `max_stderr_log_files` rotated copies
- Delete oldest when exceeding limit

**Option B — External logrotate integration:**
- Document recommended logrotate configuration for operators
- No code changes needed but requires external tooling

**Option C — Hybrid approach:**
- Implement built-in rotation as primary mechanism
- Also document logrotate configuration as alternative

Option A is recommended because it provides immediate protection without requiring external tooling.

## Acceptance Criteria

- [ ] Stderr log files do not grow beyond configured maximum size
- [ ] Rotated log files are preserved up to the configured count
- [ ] Oldest rotated files are deleted when limit is exceeded
- [ ] Current log file is always writable after rotation
- [ ] No data loss during rotation (atomic rename)

## Tests

- Unit test verifying log rotation triggers when file exceeds max size
- Integration test verifying rotated files are preserved and oldest are deleted
- Stress test verifying no disk exhaustion under sustained logging
