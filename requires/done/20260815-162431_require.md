# Add protocol validation for CLIView Writer/Reader test doubles

## Priority
Low

## Target files
- scripts/agent/cli_view.py
- Test doubles for CLIView

## Background
During adversarial review of the agent startup process, we traced the full CLI presentation flow through cli_view.py. The Writer and Reader Protocols allow test doubles and alternative I/O backends without touching callers. However, there's no evidence of comprehensive testing for edge cases where test doubles might not implement all required methods correctly.

## Problem
The current `Writer` and `Reader` Protocols use `@runtime_checkable`, which allows structural subtyping but doesn't enforce completeness at runtime. This creates several issues:

1. **Incomplete test doubles**: A test double could omit some methods and still pass type checking, leading to `AttributeError` at runtime when those methods are called
2. **No validation feedback**: Developers creating test doubles get no indication until execution time that their implementation is incomplete
3. **Debugging difficulty**: Runtime `AttributeError` exceptions are harder to diagnose than compile-time type errors
4. **Protocol drift risk**: Adding new methods to the Protocol requires manual updates to all existing test doubles

For example, if a developer adds a new method like `write_debug()` to the `Writer` Protocol, any existing test double that doesn't implement it will silently fail at runtime rather than being caught by type checkers.

## Reason for change
Adding protocol validation would catch incomplete implementations early, improve developer experience, and reduce runtime errors caused by missing methods in test doubles.

## Implementation intent
Add a runtime validation mechanism that checks whether a test double implements all required methods of the Protocol. Options include:
- Using `inspect.getmembers()` to verify all Protocol methods exist on the instance
- Using `typing.get_protocol_members()` to extract required members from the Protocol
- Using a decorator that validates protocol compliance at instantiation time

## Implementation instructions
1. Add a helper function `_validate_protocol_compliance(obj, protocol)` that uses `inspect.getmembers()` or `typing.get_protocol_members()` to check if all Protocol methods are implemented
2. Call this validator in the `__init__` method of any class that accepts a Writer/Reader as a dependency
3. Raise a descriptive error if the object doesn't implement all required methods
4. Document the protocol requirements clearly in docstrings

## Acceptance criteria
- [ ] Incomplete test doubles raise clear errors at instantiation time
- [ ] No regressions in normal operation when registry is available

## Tests
- Unit test for protocol validation with various incomplete implementations including edge cases
- Integration test verifying diagnostic output during startup/shutdown

## Documentation Impact
If DiagnosticsConfig is extended, update documentation to reflect the new state.

## Out of Scope

- Adding retry logic for health checks
