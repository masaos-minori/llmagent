# Message schema validation not applied to conversation history insertion

## Priority

High

## Target Files

- `scripts/agent/orchestrator.py` — `_handle_memory_injection()` (history append, lines 385-391) and `_clear_previous_turn_ephemeral_messages()` (ephemeral filter, lines 549-553)
- `scripts/agent/message_schema.py` — `validate_message()` (defined at line 42)

## Background

`scripts/agent/message_schema.py` defines `validate_message(msg: dict) -> ValidationResult`, whose own module docstring states its purpose is to "prevent LLM from manipulating ephemeral message filtering by injecting/removing keys." It enforces a `role`/`content` shape, a per-role `ROLE_KEY_WHITELIST`, and restricts ephemeral keys (`_ephemeral`, `_memory_injected`, `_skill_ephemeral`) to trusted `source` values via `TRUSTED_SOURCES`.

Verification against current HEAD (after commit `7c7bbe47d`, "feat: consolidate signal handling, ephemeral filtering, and workflow diagnostics") confirms:

- `_handle_memory_injection()` in `orchestrator.py` (function starts at line 373) appends directly to `ctx.conv.history` at lines 385-391:
  ```python
  ctx.conv.history.append(
      {
          "role": "system",
          "content": memory_block,
          "_memory_injected": True,
      }
  )
  ```
- `_clear_previous_turn_ephemeral_messages()` (function starts at line 542) filters history at lines 549-553:
  ```python
  ctx.conv.history = [
      m
      for m in ctx.conv.history
      if not m.get("_ephemeral") and not m.get("_memory_injected")
  ]
  ```
- A repo-wide search (`grep -rn "validate_message(" scripts/agent/`) finds only the function's own definition at `message_schema.py:42`. It is not called from `orchestrator.py`, `tool_runner.py`, `llm_turn_runner.py`, `mode_classification.py`, `cmd_skill.py`, `startup.py`, `session_restore.py`, `undo_service.py`, `conversation_service.py`, or anywhere else in `scripts/agent/`.
- Commit `7c7bbe47d` did not touch `message_schema.py` at all (that file has had only its original addition commit, `299964b14`). Its "ephemeral filtering" change only removed a duplicate filter inside `_handle_history_compression()` in `orchestrator.py` — it is unrelated to closing this validation gap.

The issue's line numbers, function names, and code quotes are all accurate as of current HEAD; the described gap is confirmed still present and unaffected by the recent consolidation commit.

## Problem

`validate_message()` exists specifically to guard against forged/ephemeral-key injection in conversation history messages, but it is dead code: it is never invoked at any point in the history-append path, including the two locations most directly relevant to ephemeral-key trust (`_handle_memory_injection()`'s history append, and every other `ctx.conv.history.append(`/`ctx.conv.history =` site across the agent module — e.g. `tool_runner.py:193`, `llm_turn_runner.py:95,202`, `cmd_skill.py:47,50`, `mode_classification.py:38`, `orchestrator.py:571`). Because nothing enforces `ROLE_KEY_WHITELIST` or `TRUSTED_SOURCES` at insertion time, any code path that builds a history message dict — including ones that incorporate LLM-influenced content — can attach an untrusted `_ephemeral`, `_memory_injected`, or other reserved key. `_clear_previous_turn_ephemeral_messages()` trusts these keys at face value when deciding what to strip, so a forged `_ephemeral: True` (or a forged `_memory_injected: True`) on an attacker-influenced message could cause it to be silently dropped from history at end of turn, or conversely a legitimate ephemeral flag could be manipulated to persist a message that should have been removed.

## Reason for Change

The existence of an unused validation function whose docstring describes exactly the threat model in question is a latent security gap: the protection was designed and implemented but never wired in, so the conversation history remains exposed to the key-injection/ephemeral-forgery attack it was meant to prevent. Closing this gap is low-risk (the validator already exists and is unit-testable in isolation) and directly addresses a High-severity integrity issue in the agent's conversation state management.

## Implementation Intent

Wire `validate_message()` into the conversation-history append/mutation path in `orchestrator.py` so that every message added to `ctx.conv.history` is validated before insertion, and so that trust decisions about ephemeral keys (made in `_clear_previous_turn_ephemeral_messages()` and any other filter relying on `_ephemeral`/`_memory_injected`) are based on validated, schema-conformant messages rather than raw dicts. Prefer a single centralized append helper over scattering `validate_message()` calls across every call site, to reduce the chance of new call sites bypassing validation in the future.

## Implementation Instructions

1. Add or identify a single history-append entry point (e.g. a small helper/method such as `ctx.conv.append_message(msg)` or a local `_append_history(ctx, msg)` in `orchestrator.py`) that all in-repo call sites route through, and have it call `validate_message()` before appending.
2. In `_handle_memory_injection()` (`orchestrator.py`, history append around lines 385-391), route the system-message-with-`_memory_injected` append through this validated path, passing an appropriate trusted `source` so `TRUSTED_SOURCES` allows the `_memory_injected` key.
3. Audit the other internal history-construction sites identified during verification (`orchestrator.py:571`, `tool_runner.py:193`, `llm_turn_runner.py:95` and `:202`, `cmd_skill.py:47` and `:50`, `mode_classification.py:38`, and any others found under `scripts/agent/`) and route them through the same validated append path, or explicitly document/justify any site that legitimately needs to bypass validation.
4. Define clear behavior for validation failure: log a warning/error with enough detail to debug (message role, offending key(s)), and drop the offending key(s) or reject the message rather than silently trusting it — do not crash the turn.
5. In `_clear_previous_turn_ephemeral_messages()` (around lines 549-553), ensure the ephemeral-key trust check aligns with `message_schema.py`'s `TRUSTED_SOURCES` semantics — i.e. only messages whose `_ephemeral`/`_memory_injected` keys were set through a validated, trusted path are treated as ephemeral; do not change this function to call `validate_message()` on every filter pass if validation is already guaranteed at append time (avoid redundant validation, consistent with the recent consolidation work in commit `7c7bbe47d`).
6. Keep `message_schema.py`'s public API and existing `ROLE_KEY_WHITELIST`/`TRUSTED_SOURCES` definitions unchanged in this pass; this task is about wiring in the existing validator, not changing its rules, unless implementation reveals the schema itself needs a new trusted source value for legitimate internal callers.

## Acceptance Criteria

- [ ] Every message appended to `ctx.conv.history` in `scripts/agent/orchestrator.py` passes through `validate_message()` (directly or via a shared append helper) before being stored.
- [ ] A message dict containing a forged `_ephemeral` or `_memory_injected` key from an untrusted source is rejected or stripped of that key rather than accepted as-is.
- [ ] `_handle_memory_injection()`'s system-message append is validated and continues to result in the memory block being present in history with `_memory_injected: True` for the legitimate/trusted case.
- [ ] `_clear_previous_turn_ephemeral_messages()` continues to correctly strip ephemeral/memory-injected messages inserted through the legitimate, validated path, with no regression versus current behavior.
- [ ] No duplicate/redundant `validate_message()` calls are introduced that conflict with the ephemeral-filter deduplication done in commit `7c7bbe47d`.
- [ ] Validation failures are logged and do not crash the agent turn.

## Tests

- Unit test: call the shared append path (or `_handle_memory_injection()`) with a well-formed system message and confirm it is validated and appended with `_memory_injected: True` intact.
- Unit test: attempt to append a message with a forged/untrusted `_ephemeral` or `_memory_injected` key (simulating LLM-influenced content) and confirm `validate_message()` rejects it or the key is stripped before it reaches `ctx.conv.history`.
- Unit test: for each audited call site (`tool_runner.py`, `llm_turn_runner.py`, `cmd_skill.py`, `mode_classification.py`), confirm messages constructed there are validated before being added to history.
- Regression test: run `_clear_previous_turn_ephemeral_messages()` against a history containing legitimately-inserted ephemeral/memory-injected messages plus normal messages, and confirm only the intended messages are stripped, with behavior unchanged from before this fix for the non-attack case.
