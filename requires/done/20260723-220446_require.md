## Title

Replace locals().get('task') with explicit variable initialization in finally block

## Priority

Critical

## Target files

- scripts/agent/orchestrator.py

## Background

The `_handle_workflow_engine()` method updates task status in its finally block after the workflow engine runs. It uses `locals().get("task")` to retrieve the task object for status update.

## Problem

`orchestrator.py:239` uses `locals().get("task")` to access the `task` variable in the finally block. While this currently works in CPython (because CPython's implementation includes local variables in `locals()` even in async functions), the Python documentation explicitly warns that `locals()` results are unreliable in async functions. Additionally, if `_init_workflow_task()` raises an exception before assigning `task`, the variable will be undefined.

## Reason for change

1. **Reliability**: Using `locals()` to access local variables violates Python best practices and may break under different implementations or future changes.
2. **Clarity**: Explicit variable initialization makes the intent clear — we want to handle the case where `task` might not exist.
3. **Maintainability**: Future developers reading the code won't need to wonder why `locals()` is being used.

## Implementation intent

Initialize `task = None` before the try block and reference it directly in the finally block.

## Implementation instructions

Change the code from:

```python
# Before (line ~228):
engine = WorkflowEngine(...)
task = self._init_workflow_task(ctx, session_id)

# After (add line before engine creation):
task = None  # Initialize before try block for finally block access

# Before (line ~239):
_task = locals().get("task")

# After:
_task = task
```

No other changes needed — the rest of the logic (`if _task is not None and _task.task_id`) already handles the None case correctly.

## Acceptance criteria

1. Task status update still works when `task` is defined.
2. Task status update is safely skipped when `task` is None (i.e., `_init_workflow_task()` raised an exception).
3. No mypy errors introduced by the change.
4. All existing tests pass without modification.

## Tests

1. Test: Task status updated after successful workflow execution
   - Verify task status is set to "completed" after engine.run() succeeds

2. Test: Task status updated after failed workflow execution

3. Test: No crash when _init_workflow_task() fails
   - Simulate _init_workflow_task() raising an exception
   - Verify no AttributeError or KeyError occurs during finally block execution
