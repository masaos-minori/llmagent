# Add explicit trigger-condition and logging statement to the conflict-resolution section of docs/03_rag_00_document-guide.md

## Priority
Medium

## Target files
- `docs/03_rag_00_document-guide.md`

## Background
`docs/03_rag_00_document-guide.md`'s "正典ソースのルール" section contains a
"コンフリクト解決" (conflict resolution) paragraph (currently line 67) that is the sole
documented process for handling contradictions found between RAG documentation files. It
currently reads:

> 2つのドキュメントで事実が一致せず、すぐに解決できない場合は、
> `03_rag_90_inconsistencies_and_known_issues.md` にDOC-Nラベルを付けたエントリとして
> 記録し、その後、責任を持つドキュメント側で根本原因を修正すること。ローカルチェックは
> `python tools/check_docs_consistency.py [対象ファイル...]` を使用。

This paragraph does state a general condition ("two documents disagree and cannot be
resolved immediately") and a two-step action (log to `03_rag_90` with a `DOC-N` label,
then fix the "responsible" document), but it does not say *when in the workflow* (review
vs. implementation work) the check applies, does not tie the correction explicitly back
to the Canonical Source Rule table directly above it, and does not require recording the
detection date alongside the entry.

## Problem
Verified directly against current source (2026-08-02): the conflict-resolution paragraph
at `docs/03_rag_00_document-guide.md` line 67 still lacks:
1. An explicit statement that the trigger point is contradiction detection *during review
   or implementation work* (not just "whenever two documents happen to disagree").
2. An explicit link from "the responsible document" back to the canonical-source file as
   determined by the Canonical Source Rule table in the same section (lines 58-65),
   rather than the vaguer "責任を持つドキュメント側" (the document side that is
   responsible).
3. A requirement to record the detection date (not just content) in the
   `03_rag_90_inconsistencies_and_known_issues.md` entry.

A `grep` for `レビューや実装変更で矛盾` and `検出日` across `docs/` confirms neither
phrase exists anywhere yet, so this gap is confirmed still present and unresolved.

## Reason for change
This section is the operational foundation for correcting the numerous confirmed
contradictions found across the RAG documentation domain (tracked separately in
`03_rag_90_inconsistencies_and_known_issues.md`). Without an explicit trigger condition
(when, and against which file the correction applies), the correction process itself
risks being applied inconsistently by different reviewers/implementers, and entries in
`03_rag_90` may omit the detection date needed to track how long an inconsistency went
unresolved.

## Implementation intent
Add one to two sentences to the existing "コンフリクト解決" paragraph (do not restructure
the section) that:
- States the trigger condition explicitly: a contradiction detected during review or
  implementation work.
- Directs the correction to the canonical-source file as defined by the Canonical Source
  Rule table immediately above (lines 58-65 of the same file), rather than the vaguer
  "responsible document" phrasing.
- Requires logging both the detection date and the content of the contradiction in
  `docs/03_rag_90_inconsistencies_and_known_issues.md`.

Keep the existing DOC-N labeling convention and the `check_docs_consistency.py` reference
intact; this is an additive clarification, not a rewrite of the paragraph's existing
content.

## Implementation instructions
1. Open `docs/03_rag_00_document-guide.md` and locate the "コンフリクト解決" paragraph
   (currently line 67, inside the "正典ソースのルール" section).
2. Add a sentence (in Japanese, consistent with the surrounding document's language)
   stating: when a contradiction is detected during review or implementation work, the

   場合、Canonical Source Ruleで定めた正本側のファイルを修正し、
   `docs/03_rag_90_inconsistencies_and_known_issues.md`に検出日・内容を追記する。" —
   use this as a starting point but adapt phrasing/placement so it reads naturally

3. Keep the addition concise (one to two sentences) and do not restructure or remove any
   existing content in the "コンフリクト解決" paragraph or the surrounding
