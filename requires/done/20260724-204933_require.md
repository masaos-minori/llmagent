# Memory disabled warning timing depends on user input

## Priority

High

## Target Files

- `scripts/agent/startup.py` — StartupOrchestrator._setup_prompt() (sets memory_disabled)
- `scripts/agent/repl.py` — AgentREPL._repl_loop() (shows warning)
- `scripts/agent/context.py` — ConversationState.memory_disabled

## Background

When memory injection fails during startup, `ctx.conv.memory_disabled` is set to `True`. The warning message is displayed in `_repl_loop` only when the user enters a line.

## Problem

In `startup.py:556`:

```python
ctx.conv.memory_disabled = True
```

In `repl.py:309-313`:

```python
if ctx.conv.memory_disabled and not ctx.conv.memory_warning_shown:
    ctx.conv.memory_warning_shown = True
    self._view.write_warning(
        f"{OutputTag.NON_FATAL} Memory is disabled for this session."
    )
```

The warning is shown only inside `_repl_loop`, which means it is triggered by user input. If the user closes the REPL immediately (e.g., via SIGTERM or /exit), the warning is never displayed.

## Reason for Change

Users should be informed about degraded capabilities (memory disabled) as early as possible, regardless of whether they interact with the REPL. Silent degradation makes debugging difficult.

## Implementation Intent

Show the memory disabled warning immediately after startup completes (whether successful or partially successful), rather than waiting for the first user input.

## Implementation Instructions

1. In `AgentREPL.run()`, after `StartupOrchestrator.run()` succeeds, check `self._ctx.conv.memory_disabled` and emit the warning before entering `_run_repl_loop()`.
2. Alternatively, add the warning check in `_run_repl_loop()` before the main loop starts, so it fires once regardless of user input.
3. Ensure idempotency: do not show the warning twice if both the startup path and the repl loop path are checked.

## Acceptance Criteria

- [ ] User sees the memory disabled warning immediately after startup
- [ ] Warning is shown even if the user does not enter any input
- [ ] Warning is not duplicated across startup and REPL phases
- [ ] `memory_warning_shown` flag still prevents duplicate warnings within the same session

## Tests

- Unit test: mock memory injection failure; verify warning is emitted before first user input
- Integration test: start REPL, send SIGTERM immediately; verify warning was displayed
