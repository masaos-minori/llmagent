# Decide Config-Value Type-Strictness Consistency Across *_Models.py Config Loaders

## Priority
Medium

## Target files
- `scripts/mcp_servers/git/git_models.py` (`GitConfig.from_dict`, current strict behavior)
- `scripts/mcp_servers/file/write_models.py` (`FileWriteConfig.from_dict`)
- `scripts/mcp_servers/file/read_models.py`, `delete_models.py` (confirm current strictness level)
- `scripts/mcp_servers/web_search/web_search_models.py` (confirm current strictness level)
- `rules/coding.md` or `rules/env.md` (document the decided strictness policy)

## Background
`scripts/mcp_servers/file/write_models.py`'s `FileWriteConfig.from_dict` coerces raw TOML values via bare `int(...)`/`list(...)` calls with no `isinstance` pre-check (e.g. a TOML float like `1048576.0` for `max_write_bytes` currently coerces successfully via `int()`). This is looser than `scripts/mcp_servers/git/git_models.py`'s `GitConfig.from_dict`, which was refactored (2026-08-14) to use an explicit `_get_typed(d, key, expected_type, type_label)` helper that raises `ValueError` on a type mismatch.

Found during a `prompts/04_refactor.md` cycle on `write_models.py` (2026-08-15). Not implemented there because adding an `isinstance` guard to `write_models.py` would change what values are accepted and what exception/message is raised for malformed config — a real behavior change on the config-loading boundary, not a pure refactor.

## Problem
Inconsistent type-coercion strictness across `*_models.py` config loaders: `git_models.py` uses strict validation with explicit type checking, while `write_models.py`/`read_models.py`/`delete_models.py`/`web_search_models.py` use loose coercion via bare `int()`/`float()`/`list()` calls.

## Reason for change
A cross-cutting consistency question: should `write_models.py`/`read_models.py`/`delete_models.py`/`web_search_models.py`'s config loaders match `git_models.py`'s stricter validation, or should `git_models.py`'s validation be relaxed to match the others' looser coercion? That decision should be made once, not per file.

## Implementation intent
Decide the target strictness level for config-value coercion across all `*_models.py` config loaders in `scripts/mcp_servers/`. Once decided, apply consistently: either backport `git_models.py`'s `_get_typed`-style validation to the looser loaders, or relax `git_models.py` to match them.

## Implementation instructions
### Phase 1: Policy Decision
1. Audit every `*_models.py` config loader's current type-coercion strictness (via `rg` for `int(`/`float(`/`list(` calls inside `from_dict` methods).
2. Decide and document the target strictness policy for the codebase.
3. Get explicit sign-off per `rules/coding.md`'s explicit sign-off gates before proceeding.

### Phase 2: Consistent Application
4. Apply the decision consistently across all affected loaders, one file at a time.
5. Add characterization tests for both accepted and newly-rejected value shapes per file.
6. Verify that every existing `config/*.toml` file still loads successfully.

## Acceptance criteria
- All `*_models.py` config loaders apply the same, documented strictness policy.
- Each affected file has characterization tests covering both the valid-value and malformed-value paths.
- No existing valid TOML config file in `config/` fails to load after the change (verify by loading each real config file, not just synthetic test values).

## Tests
Full `tests/mcp_servers/` regression suite; new characterization tests per affected loader; manual verification that every existing `config/*.toml` file still loads successfully.
