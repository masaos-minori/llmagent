# Determine whether `BLE`/`PLC0415` rule families are intentionally excluded from ruff `select`, and align `# noqa: BLE001` / `# noqa: PLC0415` suppressions across the codebase with the rules actually enforced

## Priority
Medium

## Target files
- `pyproject.toml` (`[tool.ruff.lint]` section, `select`/`ignore` lists)
- `tox.ini` (`lint` environment)
- All files under `scripts/` and `tests/` that contain `# noqa: BLE001` or `# noqa: PLC0415` (confirmed widespread — see Background; not limited to `scripts/agent/startup.py`)

## Background
`pyproject.toml`'s `[tool.ruff.lint]` section currently configures:

```toml
select = ["E", "W", "F", "I", "UP"]
ignore = ["E501"]
```

This selects only pycodestyle (`E`, `W`), pyflakes (`F`), isort (`I`), and pyupgrade (`UP`) rule
families. It does not select `BLE` (flake8-blind-except, source of `BLE001`) or `PLC` (pylint
convention codes, source of `PLC0415`). `RUF100` (ruff's own unused-`noqa` detector) is also not
selected, so ruff cannot flag these `# noqa` comments as unused even if they suppress nothing.

`tox.ini`'s `lint` environment runs only `ruff format --check` and `ruff check` — no pylint or
flake8 tool is configured anywhere in the repository.

Despite this, `# noqa: BLE001` and `# noqa: PLC0415` comments are used extensively as
suppression-with-justification annotations throughout the codebase (confirmed via project-wide
grep during Step 2 verification of this requirement, 2026-08-06):
- `BLE001`: e.g. `scripts/agent/startup.py` (5 occurrences), `scripts/mcp_launcher.py`,
  `scripts/agent/repl_health.py`, `scripts/agent/services/mcp_status.py`,
  `scripts/agent/workflow/workflow_engine.py` (3 occurrences), `scripts/agent/commands/session_title.py`,
  `scripts/shared/tool_executor.py`, `scripts/mcp_servers/web_search/web_search_service.py`,
  `scripts/mcp_servers/web_search/search_provider.py`, `scripts/mcp_servers/rag_pipeline/rag_pipeline_server.py`,
  and multiple `tests/*.py` files (e.g. `tests/agent/test_startup.py`, `tests/agent/memory/test_memory_store.py`).
- `PLC0415`: dozens of occurrences across `scripts/agent/*.py`, `scripts/agent/commands/*.py`,
  `scripts/mcp_servers/*/*.py`, `scripts/shared/*.py`, `scripts/eventbus/*.py`, `scripts/rag/*.py`,
  and `tests/mcp_servers/mdq/*.py`, `tests/mcp_servers/cicd/test_mcp_server_health_status.py`,
  `tests/agent/test_llm_client.py`.

This is materially wider than a single file: essentially every lazy-import (`PLC0415`) and
broad-except (`BLE001`) pattern in the codebase currently carries a `noqa` comment citing a rule
code that ruff — as currently configured — never raises in the first place, making these
suppressions potentially inert (decorative) rather than functional.

This requirement was filed as issue `issues/20260806-105228_unknowns.md` (UNK-01), discovered
during the require-to-plan workflow for `requires/20260806-103649_require.md` (a narrow,
comment-text-only change to `scripts/agent/startup.py` that was explicitly out of scope for this
broader question). It is filed as its own requirement per that plan's Step 5 handling of
non-blocking unknowns, because resolving it could surface real new lint findings across many files
— a materially larger change than the comment-only edit that originally surfaced it. It may also
be relevant background to `requires/20260806-133337_require.md` (from the related "risks" issue
investigated in the same cycle), since both stem from the same investigation of
`scripts/agent/startup.py`'s `# noqa` comments.

## Problem
It is currently unknown (a) whether the omission of `BLE` and `PLC` from `[tool.ruff.lint] select`
is an intentional project decision or an oversight, and (b) whether the `# noqa: BLE001` /
`# noqa: PLC0415` comments scattered across the codebase are functional suppressions of rules ruff
would otherwise raise, or inert comments that look like suppressions but suppress nothing under
the current configuration. Suppression comments (per `rules/coding.md` §Suppression governance)
are expected to cite a rule that is actually enforced; if these codes are not enforced, the
comments are misleading maintainer-facing documentation even though they are functionally
harmless.

## Reason for change
Suppression governance in `rules/coding.md` requires every `# noqa` to carry an inline
justification, implicitly on the assumption that the cited rule is one the linter would otherwise
raise. If `BLE001`/`PLC0415` are not enforced, either the project should correct the `noqa`
annotations to reflect reality (citing an enforced code, or removing the comment if no enforced
rule applies to that line), or the project should enable the missing rule families so the
suppressions become functional and any newly-surfaced findings can be triaged and fixed or
properly suppressed. Leaving the ambiguity unresolved risks future maintainers trusting a
suppression comment that does not do what it claims.

## Implementation intent
- First, establish intent: check git history / prior configuration (e.g. via `git log -p` on
  `pyproject.toml`'s `[tool.ruff.lint]` section, and any related documentation in `docs/` or
  `rules/coding.md`) for evidence of whether `BLE` and `PLC` were ever selected or discussed, to
  determine whether their absence from `select` is intentional or accidental.
- Based on that determination, choose one of two paths (do not attempt both in the same change):
  - (a) **Exclusion is intentional**: Correct the `# noqa: BLE001` / `# noqa: PLC0415` comments
    across the codebase so they either cite a rule code that is actually enforced under the
    current `select` list, or are removed where no enforced rule ever flags that line. Preserve
    the existing inline justification text where the underlying reasoning (e.g. "lazy import
    avoids circular import", "broad catch prevents one failure aborting startup") remains valid
    documentation, even if the rule code itself changes or the comment format changes.
  - (b) **Exclusion is accidental**: Add the missing rule families (`"BLE"` and the relevant `PLC`
    codes, e.g. `"PLC0415"` or the broader `PLC` family per project preference) to
    `[tool.ruff.lint] select` in `pyproject.toml`, then run `ruff check` project-wide to enumerate
    what newly surfaces. Triage each new finding individually: fix the underlying pattern where
    reasonable, or add a properly justified suppression per `rules/coding.md` §Suppression
    governance where the pattern is intentional (e.g. legitimate lazy imports, legitimate broad
    excepts at failure-isolation boundaries).
  - Also decide, as part of this same review, whether to add `"RUF100"` to `select` so ruff itself
    can detect genuinely unused `noqa` directives going forward, regardless of which path is taken.
- This requirement is scoped as its own follow-up, separate from any narrower comment-text-only
  change, because either path — but especially (b) — could surface real new lint findings across
  many files in `scripts/` and `tests/`, which is a materially larger change than a single-file
  comment edit.

## Implementation instructions
1. Investigate whether `BLE`/`PLC` exclusion from `[tool.ruff.lint] select` in `pyproject.toml` is
   intentional (check `git log` on `pyproject.toml`, `tox.ini`, and any relevant `docs/*.md` or
   `rules/coding.md` history/discussion for context).
2. Record the determination (intentional vs. accidental) in the resulting plan/implementation
   document, along with the evidence used to reach it.
3. If intentional: enumerate every `# noqa: BLE001` and `# noqa: PLC0415` occurrence project-wide
   (`scripts/` and `tests/`) and correct or remove each one so `noqa` comments only cite rule codes
   that are actually enforced by the current `[tool.ruff.lint] select` list.
4. If accidental: add the missing rule families to `[tool.ruff.lint] select`, run
   `uv run ruff check scripts/` (and `tests/` if in scope for lint) to capture the full list of
   newly surfaced findings, and triage each: fix, or suppress with a rule-accurate,
   properly-justified `# noqa` comment per `rules/coding.md` §Suppression governance.
5. Either way, decide on and apply a consistent treatment for `RUF100` (add to `select` or
   explicitly note why not) so unused `noqa` directives are structurally preventable going
   forward.
6. Do not mix paths (a) and (b) within the same change — pick one based on the intent
   determination in step 1-2.

## Acceptance criteria
- A documented determination exists (in the plan or implementation record) of whether `BLE`/`PLC`
  exclusion from `pyproject.toml`'s `[tool.ruff.lint] select` was intentional or accidental, with
  supporting evidence.
- Every `# noqa: BLE001` and `# noqa: PLC0415` comment in `scripts/` and `tests/` cites a rule code
  that is actually enforced under the resulting `[tool.ruff.lint] select` configuration (whether
  that resolution came from correcting the comments or from expanding `select`).
- `uv run ruff check scripts/` (and any other configured lint scope) passes cleanly with the final
  configuration.
- A decision on `RUF100` (selected or explicitly deferred with rationale) is recorded.
- No unrelated formatting or behavioral changes are introduced as a side effect.

## Tests
- Run `uv run ruff check scripts/` (and `tests/` if included in lint scope) after the change and
  confirm no unexpected findings remain unaddressed.
- Run `uv run ruff format --check scripts/` to confirm no formatting regressions were introduced.
- If path (b) is chosen (expanding `select`), run the full existing test suite (`uv run pytest`)
  after any code changes made in response to newly-surfaced findings, to confirm no behavioral
  regressions were introduced while fixing lint findings (e.g. narrowing a broad `except Exception`
  must not change error-handling behavior in ways that break existing tests).
- No new tests are required solely for the `pyproject.toml`/`tox.ini` configuration change itself.
