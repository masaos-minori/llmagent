# Resolve self-contradiction in docs/00_governance_02_canonical-source-rule.md between the "no hard-coded canonical sources" declaration and the per-area canonical entry point table

## Priority
High

## Target files
- `docs/00_governance_02_canonical-source-rule.md` (primary)
- `docs/00_governance_07_needs-confirmation-inventory.md` (only if the ambiguity cannot be resolved from context and must be registered as a Needs Confirmation entry)

## Background
`docs/00_governance_02_canonical-source-rule.md` defines how conflicts between documents, and between code and documents, are resolved. Its "Canonical Documents by Area" section (lines 21-23) states:

> "Each area defines its own canonical sources through its document-guide. This document does not hard-code specific canonical documents because they may change over time. Refer to each area's document-guide for the current canonical sources."

Further down in the same document, a section titled "## 領域別の正典入口" ("Per-area canonical entry points", lines 74-89) contains a fixed Markdown table hard-coding a canonical source-code entry point per area, e.g.:

| 領域 | 正典 |
|---|---|
| エージェント | `scripts/agent/` |
| MCP サーバー | `mcp_servers/` |
| DB | `db/` |
| ... | ... |

This was verified against the current file content (read in full on 2026-08-02): both sections still exist as described. Note one detail correction versus the source issue: the table is not literally "immediately" adjacent to the declaration — three other sections (Conflict Resolution Rule, Code vs Document Conflict Rule, Known Issues Registration Rule, Resolution Workflow, Related Governance Documents) sit between them — but the substantive contradiction is unchanged: the document asserts it does not hard-code canonical sources, then hard-codes exactly that, per area, later in the same file.

No existing Needs Confirmation entry (checked `docs/00_governance_07_needs-confirmation-inventory.md`, entries NC-001 through NC-017) tracks this discrepancy, so it has not yet been resolved or registered.

## Problem
The document contradicts itself on a governance-critical point: whether canonical sources are hard-coded in this file or delegated entirely to per-area document-guides. A reader (human or AI) cannot tell from the document alone which table to update when an area's directory structure changes, nor whether the "領域別の正典入口" table is authoritative or merely illustrative/stale.

Two plausible readings exist and must be distinguished:
1. **Distinct concepts, currently under-explained**: "canonical *document*" (which document-guide governs an area's documentation) and "canonical *code entry point*" (which source directory is authoritative for an area's code) may be intentionally different things that happen to both be called "canonical" — in which case the document needs an explicit sentence distinguishing them.
2. **Genuine inconsistency**: the declaration and the table both describe the same concept and simply disagree — in which case they must be reconciled (either remove/soften the "does not hard-code" declaration, or remove/relocate the table, or scope the declaration to exclude the table).

## Reason for change
An internally contradictory governance document undermines trust in the entire governance document set and creates ambiguity about maintenance responsibility (which artifact to update when project structure changes). This was raised as a "Needs confirmation" item in `docs_review_governance.md` §6 and has not yet been addressed in the current document.

## Implementation intent
Do not unilaterally guess which of the two readings above is correct. Instead:
- Re-read the full document in context (both the "Canonical Documents by Area" section and the "領域別の正典入口" table, plus the intervening sections) to determine whether the document's author intended these as distinct concepts.
- Check `docs_review_governance.md` and any related governance docs (e.g. `00_governance_01_documentation-governance.md`) for supporting evidence of intent.
- Resolve based on that evidence rather than by removing content that may still be needed (the per-area table's actual content should be preserved unless resolving the contradiction requires removing or relocating it).

## Implementation instructions
1. Determine intent:
   - If evidence supports that "canonical document per area" and "canonical code entry point per area" are intentionally distinct concepts, add an explicit clarifying sentence near the "Canonical Documents by Area" section and/or immediately before the "領域別の正典入口" table, stating the distinction in plain terms (e.g., that the "does not hard-code" declaration applies to canonical *documents*, while the "領域別の正典入口" table hard-codes canonical *source code* entry points, and these are governed independently).
   - If no such distinction was intended, reconcile the two by doing one of:
     a. Narrowing the "does not hard-code specific canonical documents" sentence so it explicitly excludes source-code entry points (i.e., scope it to documents only), or
     b. Moving/rephrasing the table so it is clearly presented as illustrative/example content rather than an authoritative hard-coded canonical list, with a pointer to the true source of truth (e.g., each area's document-guide), or
     c. Some other reconciliation that removes the direct contradiction while preserving the table's practical value as a lookup aid.
2. If intent cannot be determined from available context (the document itself and related governance docs), do not pick an interpretation unilaterally. 3. Preserve the actual per-area table content (the list of areas and their directories) unless the chosen resolution specifically requires removing or relocating it.
4. This is documentation-only work; do not modify source code or any file outside the two files listed in Target files.
