## Background
Two sibling issues currently pending in `issues/` — `files_04_shared_part1_file_listing_and_3db_rationale` and
`files_04_shared_part2_restructure_stale_tree_and_missing_files` — describe adding new design-rationale content
to `docs/01_overview-files-04-shared-part1.md` (3-DB separation rationale) and
`docs/01_overview-files-04-shared-part2.md` (tool-cache/health-gate rationale). As of this writing, neither
document contains that rationale content yet: a direct check of both files
(`grep -n -iE "分離理由|設計判断|rationale|why.*separat|health.?gate|キャッシュ.*理由" docs/01_overview-files-04-shared-part1.md
docs/01_overview-files-04-shared-part2.md`) returned no matches, and both sibling issue files are still present
under `issues/` (not yet moved to `issues/done/`), confirming the dependency has not landed.

This requirement captures the follow-up audit described in
`issues/20260802-073738_files_04_shared_arch_docs_duplication_audit.md` (source: `docs_review_overview_architecture.md`
§6B), but records explicitly that it is **not yet actionable** — it must wait until the sibling rationale content is
actually written into the docs, not merely proposed in issue text.

## Problem
It is currently unconfirmed whether the 3-DB separation rationale and the tool-cache/health-gate rationale — once
added to `01_overview-files-04-shared-part1.md` / `part2.md` — will duplicate content already present in the
`01_overview-arch-01-process.md` through `01_overview-arch-03-features.md` architecture documents. If the same
rationale ends up documented in both places, it recreates the same duplication problem this documentation review
effort is trying to eliminate elsewhere (e.g. the previously identified port-number and
Related-Governance-Documents duplication patterns).

## Reason for change
Without this cross-check, the two sibling rationale-writing issues could each independently introduce content that
overlaps with existing architecture documentation, silently reintroducing duplication into a doc set that is
actively being de-duplicated. Performing the check once the dependency content exists is cheaper than discovering
and fixing the duplication later.

## Implementation intent
After (and only after) the 3-DB separation rationale and the tool-cache/health-gate rationale have been actually
written into `01_overview-files-04-shared-part1.md` and `part2.md` respectively, read/grep
`01_overview-arch-01-process.md` through `01_overview-arch-03-features.md` for equivalent existing content covering
the same design rationale. If overlapping content is found, designate a single canonical location for it (most
likely the `arch-*` documents, consistent with how other architecture rationale is centralized) and replace the
duplicate in the other location with a cross-reference link, following the same consolidation pattern already used
for the port-number and Related-Governance-Documents duplication fixes.

## Acceptance criteria
