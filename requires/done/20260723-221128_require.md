## Title

Add post-startup MCP subprocess health verification

## Priority

Medium

## Target files

- scripts/agent/startup.py
- scripts/agent/factory.py

## Background

When an HTTP MCP subprocess starts successfully, `start_http_subprocess()` performs a health-poll during startup. However, after startup completes, there is no ongoing health verification. If the server becomes unhealthy between startup and the first tool call, the error message displayed to the user is vague ("unreachable during discovery").

## Problem

The current flow is:
1. `_start_servers()` calls `start_http_subprocess()` which polls `/health` until ready.
2. After startup, no further health checks are performed.
3. When a tool is called, `ensure_ready()` attempts to connect.
4. If the connection fails, the error message is generic.

This means a server could start healthy but fail shortly after (due to memory issues, port conflicts, etc.), and the user wouldn't know until they encounter a vague error during tool use.

## Reason for change

Adding a post-startup health verification step provides immediate feedback about server health rather than waiting for the first tool call to discover the problem. This improves observability and reduces debugging time.

## Implementation intent

After all MCP subprocesses have been started, perform a final health check against each running subprocess before declaring startup complete.

## Implementation instructions

Add a new method `_verify_mcp_health()` to `StartupOrchestrator` that:

1. Iterates over all HTTP MCP subprocesses in `ctx.services_required.lifecycle._http_procs`.
2. For each subprocess, sends a GET request to `{cfg.url}/health`.
3. If any server fails the health check, log an error and optionally raise a warning or error depending on the security profile.

Call this method after `_start_servers()` completes:

```python
# In StartupOrchestrator.run():
await self._start_servers()
await self._verify_mcp_health()  # NEW
await self._check_services()
```

Alternatively, integrate the verification into `_start_servers()` by adding a second pass after the loop:

```python
async def _start_servers(self) -> None:
    ...
    # Start all subprocesses
    for key, cfg in ctx.cfg.mcp.mcp_servers.items():
        ...
    
    # Verify all started servers
    await self._verify_started_servers(ctx)
```

## Acceptance criteria

1. After startup, all HTTP MCP subprocesses pass a health check.
2. If a server fails the health check, a clear error message is displayed indicating which server failed and why.
3. Existing behavior for healthy servers is unchanged.
4. No mypy errors introduced by the change.
5. All existing tests pass without modification.

## Tests

1. Test: All servers healthy after startup
   - Simulate successful startup with all servers passing health check
   - Verify no warnings or errors logged

2. Test: One server unhealthy after startup
   - Simulate one server failing health check
   - Verify clear error message including server name and failure reason

3. Test: Production mode blocks startup on unhealthy server
   - Set security_profile to PRODUCTION
   - Simulate one server failing health check
   - Verify startup is blocked
