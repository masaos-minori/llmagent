## Background
The `05_agent_*.md` document set mixes design/operational judgment with content that is mechanically derivable from code. A review (`memo-doc-agent-review.md`) identified what to keep vs. remove per chapter.

## Problem
The operations-and-observability chapter functions as the operational runbook (startup validation, MCP health, routing drift, where to look during an incident) but also carries full command-output transcripts and exhaustive metric-name tables that add maintenance burden without runbook value.

## Reason for change
This chapter should serve as the canonical source for startup/monitoring/incident-response judgment only. Full command-output transcripts and metric-name inventories increase staleness risk without adding decision value. However, this chapter is directly used during Deploy tasks per `routing.md`, so runbook usability must not regress.

## Implementation intent
Keep this chapter as the canonical source for startup/monitoring/incident-response judgment. Remove full command-output examples and metric-name inventories. Do not remove any FATAL/WARNING condition or "what to check during an incident" content — only trim command-output examples and metric-name tables.

## Implementation instructions
1. Read all seven files in full.
2. Identify sections containing: full command-output transcripts, log-field enumerations, exhaustive metric-name tables, plain monitoring-item listings.
3. Remove or compress those sections while preserving: the purpose of startup validation, the meaning of OK/WARNING/FATAL/SKIPPED, conditions that should fail startup, operational judgment for MCP health / routing drift / tool-definition validation, the audit-log vs. `session_diagnostics` usage split, where to look during an incident, runbook-necessary procedures.
4. Do NOT remove any FATAL/WARNING condition or "what to check during an incident" content.
5. Restructure remaining content to follow the template: Purpose / Design Intent / Responsibility Boundary / Key Constraints / Operational Notes / Known Limitations / Related Docs.
6. Ensure `routing.md`'s reference to `docs/05_agent_10_01_operations-and-observability-startup-and-health.md` (used for Deploy tasks) still resolves to usable runbook content after editing.
7. Manually verify the runbook remains actionable — an operator following it during an incident should still be able to determine next steps.
8. If a design rationale cannot be recovered from the current text, mark it `Needs Confirmation` rather than guessing.
9. Run `python tools/check_agent_docs_consistency.py` after editing.
