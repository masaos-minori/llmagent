# Duplicate StateStore instances during workflow execution

## Priority

High

## Target Files

- `scripts/agent/orchestrator.py` — Orchestrator._handle_workflow_engine(), _init_workflow_task()

## Background

During a workflow turn, `_handle_workflow_engine()` opens a `StateStore()` instance and passes it to `WorkflowEngine`. Separately, `_init_workflow_task()` opens another `StateStore()` instance to call `create_task()`.

## Problem

In `orchestrator.py:183`:

```python
store = StateStore()
engine = WorkflowEngine(self._workflow_def, store, tracer=self._tracer)
...
await engine.run(task, plan_fn, execute_fn, verify_fn)
```

In `orchestrator.py:261` inside `_init_workflow_task()`:

```python
store = StateStore()
try:
    task = create_task(store._db, ...)
finally:
    store.close()
```

Two independent `StateStore()` instances are created, each with its own SQLite connection. This causes:
- Duplicate connections to the same database
- Potential visibility issues if one instance commits before the other flushes
- Connection leak risk if one instance fails to close

## Reason for Change

Duplicate database connections waste resources and can cause transaction isolation anomalies where changes made through one connection are not visible through another within the same logical operation.

## Implementation Intent

Ensure only one `StateStore` instance is used per workflow execution. Pass the store from `_handle_workflow_engine()` down to `_init_workflow_task()` instead of creating a new one.

## Implementation Instructions

1. Modify `_init_workflow_task()` to accept an optional `store` parameter.
2. In `_handle_workflow_engine()`, pass the existing `store` instance to `_init_workflow_task()`.
3. Ensure the store is closed exactly once at the end of `_handle_workflow_engine()` (currently done at line 249).
4. Review other callers of `_init_workflow_task()` to ensure they also pass the store or handle the default case correctly.

## Acceptance Criteria

- [ ] Only one StateStore instance is opened per workflow execution
- [ ] The same database connection is reused across _handle_workflow_engine() and _init_workflow_task()
- [ ] No connection leaks occur
- [ ] All callers of _init_workflow_task() work correctly

## Tests

- Unit test: mock StateStore instantiation count; verify only one instance is created per workflow execution
- Integration test: verify data written by create_task() is visible to WorkflowEngine using the same store
