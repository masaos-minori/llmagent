# `tools/check_no_compat.py`'s `--help` text for `files` omits `tools/` from the stated default scan scope

## Priority
Low

## Target files
- `tools/check_no_compat.py` (the `help=` string on the `files` argparse argument)

## Background
`tools/check_no_compat.py`'s `main()` accepts an optional list of positional `files` arguments.
When none are given, it falls back to scanning a fixed set of directories via
`dirs_to_scan = [ROOT_DIR / "scripts", ROOT_DIR / "docs", ROOT_DIR / "tests", ROOT_DIR /
"tools"]` (confirmed at `tools/check_no_compat.py` lines ~202-207, unchanged by the recent
positional-directory-argument fix in `plans/20260809-170033_plan.md`).

## Problem
The `files` argument's `help=` text reads `"Files to check (default: scripts/, docs/,
tests/)"` (`tools/check_no_compat.py` line ~186) — it omits `tools/`, even though the actual
no-args scan includes it. Confirmed still present and unchanged in current source.

## Reason for change
Inaccurate `--help` output is misleading to anyone manually invoking the tool, and could cause
someone to believe `tools/` (including `check_no_compat.py` itself) is not covered by a default
scan when it in fact is.

## Implementation intent
Update only the `help=` string for the `files` positional argument so it accurately reflects
all four directories scanned by the no-args path, or phrase it so it does not enumerate a
subset that omits one (e.g. reference the `dirs_to_scan` list generically instead of hardcoding
directory names a second time, if that avoids future drift). Do not change any scanning logic,
arguments, defaults, `ROOT_DIR`, `COMPAT_PATTERNS`, `DEFAULT_ALLOWLIST`, or the
positional-directory-argument handling.

## Implementation instructions
1. Read `tools/check_no_compat.py`'s argparse setup for the `files` argument (currently line
   ~183-187).
2. Update the `help=` string to list all four directories actually scanned by the no-args path
   (`scripts/`, `docs/`, `tests/`, `tools/`), or rephrase it to avoid enumerating a subset.
3. Do not modify `dirs_to_scan`, `ROOT_DIR`, `COMPAT_PATTERNS`, `DEFAULT_ALLOWLIST`, or the
   `args.files`-branch directory-expansion logic added in the prior fix.
4. Run `uv run python -m tools.check_no_compat --help` and visually confirm the `files`
   argument's help text now accurately reflects the four scanned directories.
5. If any existing test asserts on the exact help text, update it; otherwise no new test is
   required (this is a text-only, no-behavior-change fix).

## Acceptance criteria
- `uv run python -m tools.check_no_compat --help` output for the `files` argument accurately
  reflects the directories scanned by the no-args `dirs_to_scan` path (`scripts/`, `docs/`,
  `tests/`, `tools/`).
- No scanning behavior, arguments, or defaults are changed.

## Tests
- No behavior change; a visual/manual check of `--help` output is sufficient.
- If an existing test asserts on the exact help text, update it to match; run `uv run pytest
  tests/tools/test_check_no_compat.py -v` to confirm no regression.
