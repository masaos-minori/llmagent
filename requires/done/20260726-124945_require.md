# Apply message schema validation on all conversation history insertions

## Priority

High

## Target Files

- `scripts/agent/orchestrator.py:389` — Memory injection message insertion
- `scripts/agent/orchestrator.py:552` — Ephemeral message filtering
- `scripts/agent/message_schema.py:42` — validate_message() definition

## Background

The `validate_message()` function exists in `message_schema.py` but is not applied when inserting messages into the conversation history:

```python
ctx.conv.history.append(
    {
        "role": "system",
        "content": memory_block,
        "_memory_injected": True,
    }
)
```

This allows the LLM to inject invalid keys or fields into the conversation history, potentially bypassing ephemeral key controls.

## Problem

No validation on messages being inserted into conversation history. The LLM could inject arbitrary keys that bypass ephemeral key restrictions.

## Reason for Change

Prevent potential manipulation of conversation history through unvalidated message insertion.

## Implementation Intent

Apply `validate_message()` to all message insertions into `ctx.conv.history`, rejecting or sanitizing invalid messages.

## Implementation Instructions

1. Wrap each message insertion with validation:
   ```python
   from agent.message_schema import validate_message
   
   msg = {
       "role": "system",
       "content": memory_block,
       "_memory_injected": True,
   }
   result = validate_message(msg)
   if not result.success:
       logger.warning("Rejected invalid message: %s", result.reason)
       return  # Skip this message
   ctx.conv.history.append(msg)
   ```
2. Apply to all locations where messages are appended to `ctx.conv.history`:
   - `orchestrator.py:389` — memory injection
   - `orchestrator.py:552` — ephemeral filtering (ensure filtered messages aren't re-inserted)
   - Any other locations found by search
3. Run tests to confirm no regressions

## Acceptance Criteria

- [ ] All message insertions validated before appending to history
- [ ] Invalid messages rejected with appropriate logging
- [ ] No regressions in normal operation
