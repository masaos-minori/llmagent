## Background
The `05_agent_*.md` document set mixes design/operational judgment with content that is mechanically derivable from code. A review (`memo-doc-agent-review.md`) identified what to keep vs. remove per chapter.

## Problem
The data-layer chapter carries table lists, column enumerations, and SQL/DDL that duplicate `schema_sql.py` verbatim and will drift on any schema change.

## Reason for change
This chapter should serve as the canonical source for DB responsibility boundaries only. Table/column lists and raw SQL/DDL increase staleness risk without adding decision value.

## Implementation intent
Keep this chapter as the canonical source for DB responsibility boundaries. Remove table/column lists, CRUD function lists, and raw SQL/DDL. Point to `schema_sql.py` for exact schema.

## Implementation instructions
1. Read all three files in full.
2. Identify sections containing: table lists, column lists, CRUD function lists, raw SQL/DDL, content that is directly visible in `schema_sql.py`.
3. Remove or compress those sections while preserving: the responsibility boundary between `session.sqlite`/`workflow.sqlite`/`rag.sqlite`/`eventbus.sqlite`, which DB is the source of truth for what, which DBs the Agent may/may not touch directly, operational judgment for DB recreation/migration/recovery, `session_diagnostics`'s role, why workflow state lives in `workflow.sqlite`.
4. Where exact schema details are needed, point to `schema_sql.py` rather than transcribing tables/columns.
5. Check `05_agent_04_state-and-persistence` for overlapping content and replace duplication with a cross-reference per the canonical-source rule.
6. Restructure remaining content to follow the template: Purpose / Design Intent / Responsibility Boundary / Key Constraints / Operational Notes / Known Limitations / Related Docs.
7. State DB-boundary rules (which DB may be touched directly by the Agent) explicitly as a constraint.
8. If a design rationale cannot be recovered from the current text, mark it `Needs Confirmation` rather than guessing.
9. Run `python tools/check_agent_docs_consistency.py` after editing (schema-drift check vs. `schema_sql.py`).
