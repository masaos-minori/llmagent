# Requirement: Complete Rollback Tracking for All MCP Server Types

## Priority

Medium — incomplete rollback can leave zombie processes after startup failures

## Target Files

- `scripts/agent/startup.py` (lines 75-85)
- `scripts/agent/lifecycle_protocol.py`

## Background

The `StartupOrchestrator.run()` method has a try-except block that rolls back on startup failure:

```python
except Exception as setup_err:
    if _servers_started:
        try:
            await self._ctx.services_required.lifecycle.shutdown_all()
```

Currently, only HTTP subprocess MCP servers are tracked via `self._spawned_subprocesses`. The lifecycle manager's `shutdown_all()` only terminates HTTP subprocess servers.

## Problem

If `_start_servers()` succeeds but subsequent steps (`_verify_mcp_health()`, `_check_services()`) fail, the rollback only shuts down HTTP subprocess servers. Any stdio-mode MCP servers started elsewhere during this window would be orphaned.

## Reason for Change

Ensure complete cleanup of all MCP server types (HTTP and stdio) during startup rollback to prevent resource leaks.

## Implementation Intent

Track all started MCP servers regardless of transport type, and ensure rollback cleans up all tracked servers.

## Implementation Instructions

1. Add a new tracking list `self._all_started_servers: list[tuple[str, McpServerConfig]] = []` to `StartupOrchestrator.__init__()`
2. Populate this list whenever any MCP server is started (both HTTP subprocess and stdio modes)
3. Modify the rollback handler to iterate over `self._all_started_servers` and shut down each one using the appropriate lifecycle method
4. For HTTP subprocess servers, use `lifecycle.shutdown_all()` as currently done
5. For stdio servers, call their individual shutdown methods
6. Clear the tracking list after successful completion or rollback

## Acceptance Criteria

- [ ] Both HTTP and stdio MCP servers are tracked during startup
- [ ] Rollback shuts down all tracked servers on any startup failure
- [ ] No zombie processes remain after failed startup
- [ ] Successful startup clears all tracking data

## Tests

- Integration test verifying stdio MCP servers are cleaned up during startup rollback
- Integration test verifying HTTP subprocess servers are cleaned up during startup rollback
- Unit test verifying tracking list is cleared after successful startup
