# Signal handler fallback not integrated with asyncio event loop on Windows

## Priority

Low

## Target Files

- `scripts/agent/repl.py` — AgentREPL.run()

## Background

On Unix-like systems, `loop.add_signal_handler()` registers signal handlers through asyncio's event loop. On Windows, this method raises `NotImplementedError`, so a fallback using `_signal.signal()` is used instead.

## Problem

In `repl.py:500-504`:

```python
for sig in (signal.SIGTERM, signal.SIGINT):
    try:
        loop.add_signal_handler(sig, _sigterm_handler)
    except NotImplementedError:
        _signal.signal(sig, lambda *_: _sigterm_handler())
```

The `_signal.signal()` approach sets a process-wide signal handler that runs independently of asyncio's event loop. This causes:
- Signal handling may interrupt async operations mid-execution
- The handler cannot safely interact with asyncio primitives (e.g., setting an Event)
- Signal timing becomes unpredictable relative to the event loop cycle

## Reason for Change

Non-integrated signal handling on Windows can cause inconsistent shutdown behavior and potential deadlocks if the handler attempts to interact with async resources.

## Implementation Intent

Provide a Windows-compatible mechanism for signal-driven shutdown that integrates with asyncio's event loop, or document the limitation and provide a workaround.

## Implementation Instructions

1. Use `asyncio.get_event_loop_policy().get_event_loop()` to check if the current event loop supports signal handling.
2. On Windows, use `msvcrt.set_signal_handler()` if available, or register a Windows console control handler via `win32api.SetConsoleCtrlHandler()`.
3. Alternatively, implement a polling-based shutdown detection: periodically check for a shutdown flag file or IPC signal that the external process writes when it wants to terminate the agent.
4. Document the Windows limitation clearly in the code comments.

## Acceptance Criteria

- [ ] SIGTERM/SIGINT is correctly received on Windows
- [ ] Signal handler integrates with asyncio event loop (no mid-operation interruption)
- [ ] Windows-specific signal handling works stably across repeated signals
