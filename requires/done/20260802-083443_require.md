# Fix stale "eleven required fields" reference and remove duplicate Japanese Priority section in docs/00_governance_07

## Priority
Medium

## Target files
- `docs/00_governance_07_needs-confirmation-inventory.md`

## Background
`docs/00_governance_07_needs-confirmation-inventory.md` defines the schema for "Needs
confirmation" (NC-XXX) inventory entries. The "Inventory Entry Fields" section (line 16)
enumerates 15 fields and its header currently reads "the following fifteen fields" — this
count is already correct as of the current document state (a related issue,
`governance_07_field_definition_mismatch_with_03`, appears to have already corrected this
header from an earlier "eleven fields" wording). However, the "Extraction Process" section
(line 54) still reads "Populate all eleven required fields based on the context," which now
contradicts the fifteen-field enumeration above it. Separately, the document contains a
"### プライオリティ値（日本語）" subsection (lines 42-46) that duplicates, in Japanese, the
same High/Medium/Low priority-level explanation already given in English inline in the
Priority field description (line 29).

## Problem
Verification against the current document (2026-08-02) confirms two live inconsistencies:

1. **Stale field count in Extraction Process section**: Line 54 says "Populate all eleven
   required fields," which no longer matches the 15 fields enumerated in "Inventory Entry
   Fields" (lines 16-32). This is an internal inconsistency within the same document — a
   reader following the Extraction Process steps would populate only 11 fields and be
   uncertain about the remaining 4.
2. **Duplicate Priority explanation**: The Priority field's High/Medium/Low definitions are
   given twice — once in English at line 29 (inline in the field list) and again in
   Japanese in the standalone "### プライオリティ値（日本語）" section (lines 42-46). This is
   redundant and increases the risk of the two copies drifting out of sync in future edits.

Verification of actual field usage across all 17 existing NC-XXX entries (NC-001 through
NC-017) in this document shows:
- The first 11 fields (ID, Source File, Section, Line Number, Question, Evidence, Impact,
  Required Action, Status, Assigned To, Last Reviewed) are filled in on every single entry
  (17/17).
- Of the last 4 fields (Priority, Related NC, Resolution Target, Blocking):
  - **Priority**, **Resolution Target**, and **Blocking** are filled in only on NC-003,
    NC-008, NC-010, and NC-014 (4/17 entries).
  - **Related NC** is filled in on only NC-014 (1/17 entries).

This confirms the "eleven required fields" wording is not simply stale text to delete — it
accurately describes actual practice: 11 fields are consistently populated ("required" in
effect) and 4 fields (Priority, Related NC, Resolution Target, Blocking) are populated only
occasionally ("optional" in effect). The fix should make this required/optional split
explicit rather than just changing "eleven" to "fifteen," which would erase real information
about actual usage.

## Reason for change
Leaving the Extraction Process section's field count out of sync with the Inventory Entry
Fields enumeration creates ambiguity for anyone (human or AI) using this document to add new
NC entries — it's unclear whether all 15 fields must be populated or only some. The
duplicate Japanese Priority section adds no new information beyond the existing English
description and is a maintenance liability (edits to one copy can silently leave the other
stale, as already happened with the field count itself).

## Implementation intent
- Update the "Inventory Entry Fields" list (lines 16-32) to mark each of the 15 fields as
  required or optional, based on the observed usage above (fields 1-11 required; fields
  12-15 — Priority, Related NC, Resolution Target, Blocking — optional).
- Update the "Extraction Process" section (line 54) so its field-count language matches the
  Inventory Entry Fields section exactly (e.g., referencing "required fields" using the same
  required/optional split, rather than restating a bare number that can drift again).
- Remove the standalone "### プライオリティ値（日本語）" section (lines 42-46) and fold its
  Japanese labels into the single canonical Priority field description (line 29), e.g.:
  "**Priority** — Classification of urgency: High（高: 次のリリース前に解決必須）, Medium
  （中: スプリント内で解決すべき）, Low（低: やりたいが必須ではない）."
- Do not change the field set itself or reconcile it with `docs/00_governance_03` — that is
  explicitly out of scope and tracked by the separate
  `governance_07_field_definition_mismatch_with_03` issue/requirement.
- Do not rewrite the content of existing NC-001 through NC-017 entries; only the schema
  description sections (Inventory Entry Fields, Extraction Process, Priority Values) are in
  scope.

## Implementation instructions
1. In `docs/00_governance_07_needs-confirmation-inventory.md`, edit the "Inventory Entry
   Fields" list (lines 16-32) to annotate each of the 15 items as required or optional:
   - Required: ID, Source File, Section, Line Number, Question, Evidence, Impact, Required
     Action, Status, Assigned To, Last Reviewed (11 fields).
   - Optional: Priority, Related NC, Resolution Target, Blocking (4 fields).
2. Edit the "Extraction Process" step 3 (currently "Populate all eleven required fields
   based on the context") so the count/terminology matches the annotated list from step 1 —
   e.g., "Populate all required fields (11) based on the context; populate optional fields
   (Priority, Related NC, Resolution Target, Blocking) when applicable."
3. Remove the "### プライオリティ値（日本語）" section (lines 42-46) entirely.
4. Merge its content into the Priority field bullet in the Inventory Entry Fields list
   (line 29) so the High/Medium/Low levels are described once, with both English and
   Japanese labels in the same bullet.
5. Re-read the full document after editing to confirm no other reference to "eleven" or to
   the removed Japanese section remains, and that the field count stated anywhere in the
   document is internally consistent.
