## Background
This requirement follows up on `issues/20260817_05_issue.md`, which proposed applying four
mechanical documentation-hygiene rules in one sweep because they touch overlapping files and
share the same review: (1) no maintained counts, (2) no source line-number references, (3) no
restated concrete `config/*.toml` values, (4) no stale Resolved/Deprecated notes. A read-only
verification pass against the current repository (2026-08-18) confirmed all four problem
classes are still present with concrete evidence (see Problem section).

## Problem
Four classes of documentation content predictably drift from the source of truth (code or
config) and have already drifted in at least one confirmed case:

1. **Maintained counts.** `scripts/agent/config_dataclasses.py` module docstring (line 16)
   states `AgentConfig` "composes 9 domain-specific sub-configs," the `AgentConfig` class
   docstring itself (line 421) says "8," and `docs/05_agent_01_system-overview.md` (line 52)
   says "7 sub-configs." The actual code composes 9 sub-config fields
   (`llm, rag, tool, memory, mcp, approval, obs, diagnostics, messages`). Three sources of
   truth, three different numbers. Separately, github-mcp tool-category docstrings
   (`github_tools.py`) and the `mdq_server.py` module docstring and
   `docs/04_mcp_03_01_dispatch-and-routing.md`'s `READ_TOOLS` count currently match their
   actual list sizes, but they are the same drift-prone pattern that already broke for the
   sub-config count and will silently go stale on the next code change.

2. **Source line-number references in design docs.** `docs/00_governance_05_deprecated-items.md`
   and `docs/00_governance_07_needs-confirmation-inventory.md` contain multiple raw
   `file.py:NN-NN` / "line NN" / "~line N" references (e.g. `jsonl_store.py:72-111`,
   `config/agent.toml lines 5-18`, `ingestion.py:178-184`). These rot on every edit to the
   referenced file. `docs/03_rag_05_5-constraints-reference.md` already documents (in
   Japanese, line 28) that this exact problem was previously fixed by switching to
   section-name references — the fix was not applied to the governance docs listed above.

3. **Concrete `config/*.toml` values restated in docs.** Many docs restate literal defaults
   from `config/agent.toml` / `config/ingester.toml` instead of naming the owning config
   field only: `max_tool_turns=5`, `context_char_limit=8000`, `http_timeout=30.0`,
   `llm_max_retries=3`, `tool_cache_ttl=300`, `sqlite_busy_timeout_ms=30000` (restated 3x in
   one file), `embedding_dims=384` (restated across at least 4 files, twice within
   `docs/03_rag_02_04_ingestion_pipeline-ingester.md` alone), and
   `COMPRESS_TEMPERATURE=0.3` / `COMPRESS_MAX_TOKENS=300` (restated twice in
   `docs/05_agent_05_llm-and-streaming.md`). Each restatement is a second source of truth
   that can diverge from the actual config default.

4. **Stale "Known Limitations" note.** `docs/05_agent_07_03_cli-and-commands-command-registry.md`
   (lines 53-55) states that `AgentREPL.SLASH_COMMANDS` (tab completion) and
   `command_defs_list._COMMANDS` (dispatch) "are maintained separately and currently
   mismatched," specifically that `/memory`, `/audit`, `/plan`, `/skill`, `/mdq` are missing
   from `SLASH_COMMANDS`. Current source (`scripts/agent/repl.py`) shows `AgentREPL.SLASH_COMMANDS`
   is a `cached_property` that returns `completion_command_names()`, which unions
   `builtin_command_names()` (derived from `_COMMANDS`, the single source of truth) with
   `_REPL_RESERVED_COMMANDS` (`{"/exit"}`). There is no longer a separately maintained,
   hand-written `SLASH_COMMANDS` set, so the described mismatch cannot occur. The note
   describes a condition that no longer exists in the code.

## Reason for change
The sub-config count has already drifted into three mutually inconsistent numbers across two
docstrings and one design doc, demonstrating the maintenance-burden risk is not theoretical.
Line-number references and restated config values are silent single-purpose landmines that
break the next time someone edits the referenced file or changes a config default, and one doc
already shows repo awareness that line-number references were meant to be eliminated in favor
of section-name references — this sweep completes that intent elsewhere. The stale
"Known Limitations" note actively misinforms a reader about current CLI tab-completion
behavior and should be removed rather than left to mislead.

## Implementation intent
Apply four mechanical, low-risk documentation edits, scoped to `docs/*.md` and Python
docstrings only (no behavior change):

1. Replace every maintained count in a docstring or design doc with either (a) a plain name
   enumeration with no leading number (e.g. "sub-configs: llm, rag, tool, memory, mcp,
   approval, obs, diagnostics, messages" with no "N" prefix), or (b) a reference to the
   authoritative symbol that defines the count (e.g. "see `AgentConfig`'s field list") so the
   count is never independently maintained in prose.
2. Replace every source line-number reference in `docs/*.md` with a class / function / method
   name reference (e.g. replace `jsonl_store.py:72-111` with "see
   `JsonlMemoryStore.append`" or the equivalent enclosing symbol), following the same
   section-name-reference pattern already applied in
   `docs/03_rag_05_5-constraints-reference.md`.
3. Replace every restated literal `config/*.toml` value in `docs/*.md` with a reference to the
   owning config dataclass field (e.g. replace "default 300 sec" with "see
   `ToolConfig.tool_cache_ttl`"), removing the literal number/string from the doc.
4. Delete the stale "Known Limitations" note in
   `docs/05_agent_07_03_cli-and-commands-command-registry.md` (lines 53-55) describing the
   `SLASH_COMMANDS`/`_COMMANDS` mismatch, since it no longer reflects current behavior.
   Do not remove other "no longer ..." notes that explain current behavior (e.g. notes about
   single-engine scheduling or the absence of a static tool-definitions fallback) — those are
   in scope to *preserve*, not to delete.

## Implementation instructions
1. Fix the sub-config count disagreement first as the concrete, demonstrated case:
   - `scripts/agent/config_dataclasses.py` line 16 (module docstring) and line 421
     (`AgentConfig` class docstring): make both state the sub-config list without a leading
     number, or make both cite the same authoritative number consistently — prefer removing
     the number entirely per the "keep name enumerations without a number" rule.
   - `docs/05_agent_01_system-overview.md` line 52: same fix — drop the numeric count, keep
     the referenced concept only (e.g. "sub-configs, hot-reload" or name the dataclass).
2. Search `docs/*.md` and Python docstrings under `scripts/` for other hard-coded counts
   ("N tools", "N sub-configs", "N modules" and similar patterns) beyond the ones already
   identified (github-mcp `github_tools.py` category docstrings, `mdq_server.py` module
   docstring, `docs/04_mcp_03_01_dispatch-and-routing.md` `READ_TOOLS` reference) and apply
   the same no-number rule everywhere found.
3. Search `docs/*.md` for source line-number references using a pattern such as
   `grep -rn "\.py:[0-9]\|line [0-9]\|lines [0-9]" docs/`, starting from the confirmed hits in
   `docs/00_governance_05_deprecated-items.md` and
   `docs/00_governance_07_needs-confirmation-inventory.md`, and replace each with the
   enclosing class/function/method name.
4. Search `docs/*.md` for literal `config/*.toml` values using the confirmed field names
   (`max_tool_turns`, `context_char_limit`, `http_timeout`, `llm_max_retries`,
   `tool_cache_ttl`, `sqlite_busy_timeout_ms`, `embedding_dims`, `COMPRESS_TEMPERATURE`,
   `COMPRESS_MAX_TOKENS`) as a starting list, plus a broader scan for other numeric/string
   literals that match current `config/agent.toml` / `config/ingester.toml` values, and
   replace each restated value with a reference to the owning dataclass field.
5. Delete the "Known Limitations" entry in
   `docs/05_agent_07_03_cli-and-commands-command-registry.md` (lines 53-55) about the
   `SLASH_COMMANDS`/`_COMMANDS` mismatch.
6. While removing stale notes, do a light pass over the other "解消済み/解決済み/Resolved/
   Deprecated" hits noted during verification (`docs/00_governance_05_deprecated-items.md`,
   `docs/05_agent_07_07_cli-and-commands-migration-notes.md`,
   `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md`) to confirm each is either (a) a
   legitimate current-behavior-explaining note to keep, or (b) truly stale and removable —
   verify against current code before deleting anything beyond the one item confirmed here.
7. Do not touch source code behavior — this is a documentation- and docstring-only change.
   (Docstring edits are text-only; do not alter any function/class signatures or logic.)

## Acceptance criteria
- No design doc (`docs/*.md`) or Python docstring under `scripts/` states a maintained count
  of tools, sub-configs, or modules; name enumerations remain but without a leading number.
- No design doc references a specific source line number; all such references are replaced
  with class/function/method name references.
- No design doc restates a concrete `config/*.toml` value; each such reference instead names
  the owning config dataclass/field.
- The stale `SLASH_COMMANDS`/`_COMMANDS` "Known Limitations" note in
  `docs/05_agent_07_03_cli-and-commands-command-registry.md` is removed.
- Other legitimate "no longer ..." / current-behavior-explaining notes (e.g. single-engine
  scheduling, no static tool-definitions fallback, the MDQ-02 hybrid-search note) remain
  intact and are not deleted.
- The `AgentConfig` module docstring, class docstring, and
  `docs/05_agent_01_system-overview.md` no longer contain three mutually inconsistent
  sub-config counts.
