# Fix stale MCP port numbers, single-server file-mcp description, and duplicate content in 04_mcp_01_tool_ownership_matrix.md and 04_mcp_02_service_boundaries.md

## Priority
High

## Target files
- `docs/04_mcp_02_service_boundaries.md` (primary — still contains 7 stale port numbers and a single-server `file-mcp` description)
- `docs/04_mcp_01_tool_ownership_matrix.md` (secondary — port numbers and file-mcp split are already correct; only the duplicate Mermaid diagram remains to be addressed)

## Background
An earlier issue reported that both `docs/04_mcp_01_tool_ownership_matrix.md` and
`docs/04_mcp_02_service_boundaries.md` had port numbers that did not match
`config/agent.toml`, that `file-mcp` was documented as one server when it is
actually split into `file-read-mcp` / `file-write-mcp` / `file-delete-mcp`, that
`01_tool_ownership_matrix.md` carried a redundant Mermaid diagram duplicating its
own table, and that `02_service_boundaries.md`'s per-server "Allowed/Forbidden
operation types" duplicated the Ownership Matrix.

Re-verification against the current repository state (2026-08-02) shows this
issue is **partially resolved**: `01_tool_ownership_matrix.md` has already been
corrected for ports and the file-mcp split (it now carries an accurate
auto-generated "Server Port & Tool Reference" table sourced from
`config/agent.toml` and a note explaining the 3-way file-mcp split). However,
`02_service_boundaries.md` was not updated and still has the original problems.
The Mermaid-diagram duplication in `01_tool_ownership_matrix.md` was also not
addressed. This requirement covers only the remaining, still-real work.

## Problem
1. **`docs/04_mcp_02_service_boundaries.md` port numbers are wrong for 7 of 8
   servers** (git-mcp is correct). Confirmed against `config/agent.toml`
   `[mcp_servers.*]` sections:

   | Server (doc heading) | Doc's port | Actual port (`config/agent.toml`) |
   |---|---|---|
   | file-mcp (doc says one server) | 8004 | N/A — split into 3 servers (see below) |
   | rag-pipeline-mcp | 8005 | 8010 |
   | cicd-mcp | 8006 | 8012 |
   | mdq-mcp | 8007 | 8013 |
   | git-mcp | 8014 | 8014 (correct) |
   | shell-mcp | 8008 | 8009 |
   | web-search-mcp | 8009 | 8004 |
   | github-mcp | 8012 | 8006 |

   Actual per-server ports, from `config/agent.toml`:
   - `web_search` → 8004
   - `file_read` → 8005
   - `github` → 8006
   - `file_write` → 8007
   - `file_delete` → 8008
   - `shell` → 8009
   - `rag_pipeline` → 8010
   - `cicd` → 8012
   - `mdq` → 8013
   - `git` → 8014

2. **`docs/04_mcp_02_service_boundaries.md` documents `file-mcp` as a single
   server** ("file-mcp (port 8004)" with combined read/write/delete
   responsibilities). In reality it is 3 independent servers:
   `file-read-mcp` (8005), `file-write-mcp` (8007), `file-delete-mcp` (8008), as
   already correctly documented in `01_tool_ownership_matrix.md`.

3. **`docs/04_mcp_02_service_boundaries.md`'s "Allowed operation
   types"/"Forbidden operation types"** sub-sections under each per-server
   heading substantially duplicate information already captured in
   `04_mcp_01_tool_ownership_matrix.md`'s Tool-to-MCP Server Mapping table
   (which tool belongs to which server, and its risk tier/approval
   requirement). This is a duplicate-maintenance burden with two sources of
   truth that can (and did) drift apart.

4. **`docs/04_mcp_01_tool_ownership_matrix.md` still contains a Mermaid
   diagram** (the `graph LR` block under "## Mermaid Diagram", lines ~44-63)
   that duplicates the same tool→server mapping already present in the
   Markdown table above it and in the auto-generated reference table below
   it. It is a third representation of the same information, hand-maintained
   and therefore driftable, though it does currently list the correct/split
   file-mcp servers.

   Note: points (a) wrong ports and (b) file-mcp single-server description,
   as originally reported for `01_tool_ownership_matrix.md`, no longer apply
   to that file — it already has correct ports and the correct 3-way file-mcp
   split (see its "Note" callout above the Mermaid diagram and its
   auto-generated "Server Port & Tool Reference" table at the bottom, which
   matches `config/agent.toml` exactly). Do not re-introduce port numbers or
   file-mcp-as-single-server language there while fixing the Mermaid diagram.

## Reason for change
Stale port numbers in `02_service_boundaries.md` are a confirmed factual error,
verified directly against `config/agent.toml`: an operator or agent trusting
this document would attempt to connect to the wrong port for 7 of 8 servers.
The single-server `file-mcp` description is also stale relative to the actual
3-way least-privilege split. The duplicated Allowed/Forbidden tables and the
duplicated Mermaid diagram are redundant maintenance burdens that already
caused drift once (this is why `02_service_boundaries.md` and
`01_tool_ownership_matrix.md` disagree with each other today) and will
continue to invite drift if left as-is.

## Implementation intent
- Stop hardcoding port numbers in `02_service_boundaries.md`'s prose; align it
  with the pattern already used in `01_tool_ownership_matrix.md` — either
  remove fixed port values in favor of a note pointing to
  `config/agent.toml`'s `[mcp_servers.*]` section as the authoritative source,
  or correct the values and add the same auto-generated reference-table
  pattern already present in `01_tool_ownership_matrix.md` (sourced via
  `tools/gen_mcp_reference.py`) so future drift is machine-detectable.
- Update `02_service_boundaries.md`'s per-server headings and responsibilities
  to describe `file-read-mcp` / `file-write-mcp` / `file-delete-mcp` as three
  separate servers instead of one `file-mcp`, mirroring the split and the
  explanatory note already present in `01_tool_ownership_matrix.md`.
- Replace `02_service_boundaries.md`'s "Allowed operation types" / "Forbidden
  operation types" sub-sections with a reference link to
  `04_mcp_01_tool_ownership_matrix.md`, retaining only the unique
  design-intent content ("Responsibilities" / "Explicit Non-responsibilities"
  prose and the "Ownership rationale" / "Key Boundary Rules" sections, which
  are not duplicated elsewhere).
- Remove the Mermaid diagram from `01_tool_ownership_matrix.md`, or — if a
  visual representation is judged worth keeping — mark it clearly as
  generated/do-not-hand-edit and wire it into the same generation path as the
  "Server Port & Tool Reference" auto-generated table, so it cannot silently
  drift from the table again.
- Do not modify `config/agent.toml` or any source code; this is a
  documentation-only change confined to the two named files.
