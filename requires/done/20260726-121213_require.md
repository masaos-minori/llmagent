# Add dedicated unit tests for shared/config_utils.py

## Priority

Medium

## Target Files

- `scripts/shared/config_utils.py:18-25` — `get_str` type validation (no dedicated test)
- `tests/shared/test_config_utils.py` — new file

## Background

**Needs confirmation resolved (verified 2026-08-23):** this requirement originally targeted
three shared modules (`json_utils.py`, `config_utils.py`, `llm_hot_config.py`), all claimed
to have "no dedicated test files." That is no longer true for two of the three:
`tests/shared/test_json_utils.py` already exists and covers `extract_llm_content`'s 4
branches plus every other public function in the module; `tests/shared/test_llm_hot_config.py`
already exists and covers `apply_one`/`apply_config` for all 9 hot-config fields, including
partial updates, false/zero-value application, and the no-op-when-all-None case. Only
`scripts/shared/config_utils.py` remains untested — this requirement is narrowed to that file.

## Problem

| File | Lines | Issue |
|---|---|---|
| `shared/config_utils.py` | 48 | `get_str` type validation for non-string values untested; `get_typed` (the module's other public function) is also untested but out of scope — see Scope below |

## Reason for Change

`get_str` is used across config loaders (per `rules/coding.md` Type-coercion policy context)
but has no dedicated test protection. A regression in its type-validation branch would go
undetected.

## Implementation Intent

Create `tests/shared/test_config_utils.py` covering `get_str()`'s full branch set: string
value, non-string value (raises `ValueError`), missing key (returns default), key present
but `None` (returns default), and the default `default=""` behavior.

## Implementation Instructions

### test_config_utils.py
- Test `get_str()` returns the value when it is already a `str`
- Test `get_str()` raises `ValueError` (with the key name in the message) for a non-string
  value (e.g. `int`, `list`, `dict`)
- Test `get_str()` returns `default` when the key is missing
- Test `get_str()` returns `default` when the key is present but `None`
- Test `get_str()` returns `""` when no `default` argument is given and the key is missing

## Acceptance Criteria

- [ ] `tests/shared/test_config_utils.py` created with tests covering all `get_str()`
      branches listed above
- [ ] `uv run pytest tests/shared/ -v` passes with no regressions
- [ ] `get_str` reaches full branch coverage (all 4 branches: non-None+str,
      non-None+non-str, None-with-default, missing-key-with-default)
