# Reduce template-memo-style detail in docs/90_shared_90_inconsistencies_and_known_issues.md

## Priority
Medium

## Target files
`docs/90_shared_90_inconsistencies_and_known_issues.md`

## Background
This chapter is the canonical source for known issues (per `memo-doc-shared-review.md` §「章間の正本ルール」: 既知問題・未解決事項 = `90_shared_90_inconsistencies_and_known_issues`). Per the memo, this chapter must be kept as the authoritative reference for known-issues decisions.

Note: `memo-doc-shared-review.md` exists and its guidance for this chapter remains valid based on independent verification against the source codebase.

## Problem
The Known Issues chapter contains exhaustive metadata-field template details that contradict the memo's instruction to focus on operational meaning rather than mechanical descriptions. Specifically:

- The full 17-field issue template
- Unverified metadata fields (Owner / First Found / Target / Related)
- Migration notes
- Detailed implementation file/test names
- Mechanical documentation-gap classification

All these items are explicitly listed under 「削る内容」 (items to remove) in the memo.

## Reason for change
The document violates the design-doc reduction policy established in `memo-doc-shared-review.md`. Detail should be redirected to the source files rather than deleted, ensuring no loss of information for readers who need it.

## Implementation intent
Restructure each entry to explain what the issue means, why it matters, operational cautions, and fix-decision criteria — not a metadata template. Explicitly retain SHARED-001 (`recover_corruption` propagating an exception instead of a `RecoveryResult` on real page corruption) and its unresolved status.

## Implementation instructions
1. Read `memo-doc-shared-review.md` §「90_shared_90_inconsistencies_and_known_issues」 and `rules/coding.md`'s "Current behavior" classification table.
2. Keep: the meaning of each known issue, why it is a problem, operational cautions, fix-decision criteria, SHARED-001's impact, that `recover_corruption` can propagate an exception on real page corruption, that this remains unresolved.
3. Replace the full 17-field issue template, unverified metadata fields (Owner / First Found / Target / Related), migration notes, detailed implementation file/test names, and mechanical documentation-gap classification with cross-references to the appropriate source files.
4. Point to `scripts/db/recovery.py` for exact implementation detail rather than transcribing it.
5. Before removing any entry, verify against current code per `rules/coding.md` §「Documentation notes — "Current behavior" classification」 whether the discrepancy still applies; do not delete a note without this verification.
6. Coordinate with `docs/90_shared_05_04_db_api_and_operations-recovery-and-reference.md`'s cleanup issue so SHARED-001 is not duplicated across both chapters — that chapter should cross-reference here instead of re-explaining.
7. When in doubt whether a detail is operationally-critical, keep it. Mark unclear rationale as `Needs Confirmation`.
8. Manually check internal Markdown links after editing.
