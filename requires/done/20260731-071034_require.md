# Requirement: Improve Visibility of MCP Server Initialization Failures

## Priority

Medium

## Target Files

- `scripts/agent/factory.py`
- `scripts/agent/startup.py`

## Background

When `_initialize_mcp_servers()` uses `return_exceptions=True`, failures of individual MCP servers are silently swallowed. The agent starts without knowing which servers failed, leading to confusing tool call errors later.

## Problem

In `factory.py`:

```python
async def _initialize_mcp_servers(self):
    tasks = [self._init_single_server(server) for server in servers]
    results = await asyncio.gather(*tasks, return_exceptions=True)
    
    # Exceptions are returned but may not be logged or reported
```

This means:

1. Server A initializes successfully
2. Server B fails (e.g., connection refused)
3. Server C initializes successfully
4. Agent starts — unaware that Server B failed
5. Tool calls targeting Server B fail with cryptic errors
6. Debugging is difficult because no failure was reported at startup

## Reason for Change

Silent failures make debugging impossible. Users need to know which servers failed during startup so they can take corrective action.

## Implementation Intent

Ensure all MCP server initialization failures are explicitly logged and reported, even when some servers succeed.

## Implementation Instructions

### Step 1: Replace `return_exceptions=True` with explicit error handling

```python
async def _initialize_mcp_servers(self):
    """Initialize all MCP servers, reporting failures."""
    failed_servers = []
    
    for server in servers:
        try:
            result = await self._init_single_server(server)
            logger.info(f"MCP server initialized: {server.name}")
        except Exception as e:
            logger.error(f"MCP server initialization failed: {server.name} — {e}")
            failed_servers.append({
                "name": server.name,
                "error": str(e),
            })
    
    if failed_servers:
        logger.error(
            f"{len(failed_servers)} MCP server(s) failed to initialize: "
            + ", ".join(s["name"] for s in failed_servers)
        )
        raise RuntimeError(
            f"Failed to initialize {len(failed_servers)} MCP server(s)"
        )
```

### Alternative: Partial success mode

If partial success is acceptable (some servers can work while others fail):

```python
if failed_servers:
    logger.warning(
        f"Partial MCP server initialization: {len(failed_servers)} failed, "
        f"{len(servers) - len(failed_servers)} succeeded"
    )
    # Do NOT raise — allow agent to start with available servers
else:
    logger.info("All MCP servers initialized successfully")
```

### Recommendation

The first approach (raise on any failure) is safer — it prevents silent degradation. The second approach (partial success) requires careful design of fallback behavior for missing tools.

## Acceptance Criteria

1. All MCP server initialization failures are logged at startup
2. Failed server names and error messages are included in logs
3. Startup either succeeds fully or fails entirely (no silent partial success)
4. Normal successful initialization is unaffected — no regression
