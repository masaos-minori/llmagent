# Fix internal contradiction in the LLM model-retrieval table in docs/02_deployment-part1.md §1.4

## Priority
Medium

## Target files
- `docs/02_deployment-part1.md` (§1.4 "LLM モデルの取得", the model-retrieval table, currently at approximately lines 77-81)

## Background
`docs/02_deployment-part1.md` §1.4 documents how to retrieve LLM/embedding model files into
`/opt/llm/models/` via `huggingface-cli download`, and includes a table mapping a
model label (purpose/version) to the expected filename. This table is meant to let an
implementer download the correct file and cross-check it against the model path
configured for the corresponding service.

## Problem
The table's third row is internally contradictory:

```
| モデル | ファイル名 |
|---|---|
| multilingual-e5-small (埋め込み) | multilingual-e5-small-Q8_0.gguf |
| gemma-4-e4b-it (LLM) | gemma-4-e4b-it-Q4_K_M.gguf |
| Qwen2.5-Coder-7B (LLM) | Qwen3.6-Instruct-Q4_K_M.gguf |
```

The label "Qwen2.5-Coder-7B (LLM)" names a different model family, version, and
variant (Coder) than the filename "Qwen3.6-Instruct-Q4_K_M.gguf" (Instruct). Verified
still present in the current repository content at the time this requirement was
written — this is not a stale/already-fixed issue.

Two other current docs consistently reference the filename-side value for the same
service (agent-llm, port 8080, chat/code-generation), which is useful context but not
proof, since these are also just documentation and could themselves be wrong or stale:
- `docs/01_overview-arch-01-process.md` line 72: `agent-llm` (port 8080) uses
  "Qwen3.6-Instruct-Q4_K_M" for chat/code-gen (also MQE / re-ranking).
- `docs/01_overview-files-01-build.md` line 30: lists
  `Qwen3.6-Instruct-Q4_K_M.gguf # チャット/コード生成用 LLM (MQE・再ランク兼用, :8080)`.

The actual deployed model file cannot be confirmed from this environment:
`/opt/llm/models/` does not exist on this machine (this is a dev checkout, not the
production host where models are deployed), and `config/agent.toml` in this repo does
not contain a literal model filename or model-path key for the port-8080 `agent-llm`
service — only `llm_url = "http://192.168.11.197:8080"`, i.e. the model file itself is
selected on a separate host outside this repo's visibility.

## Reason for change
An implementer following this table as-is could download or expect the wrong model
file (mismatched family/version/variant), which can degrade generation/embedding
quality or cause a startup-time model-mismatch error for the `agent-llm` service. This
is a confirmed internal document inconsistency, independent of whether the actual
deployed environment matches either side.

## Implementation intent
Resolve the contradiction by determining which side (the model label or the filename)
reflects the actually-deployed/intended model for the `agent-llm` service, then correct
the table so the label and filename are consistent for every row. Do not pick a side
based on inference alone — the cross-references in `01_overview-arch-01-process.md` and
`01_overview-files-01-build.md` are supporting context, not confirmation, since they are
documentation and not the deployed artifact itself.

Additionally, per the related summarization intent noted in the source issue,
compress the surrounding §1.4 text so the main body carries only the
placement-and-key-matching principle (model files live under `/opt/llm/models/`, and
the filename must match the corresponding model-path key/config used by the service
that loads it), with the corrected table kept as a compact reference for exact
filenames.
