# Fix nonexistent check_routing_drift_vs_live() reference, deduplicate the "add new tool" procedure, and add missing side-effect-tool constants in docs/04_mcp_03_02 and docs/04_mcc_03_05

## Priority
High

## Target files
- `docs/04_mcp_03_02_tool-registry.md`
- `docs/04_mcp_03_05_lifecycle-and-new-server.md`

## Background
`docs/04_mcp_03_02_tool-registry.md` and `docs/04_mcp_03_05_lifecycle-and-new-server.md` both document
the MCP tool routing/registry system and the procedure for adding a new tool or server. Both files
were found (via `docs_review_mcp.md`) to reference a function name that does not exist in source, and
both contain substantially overlapping "add a new tool" procedures. Additionally, `03_02`'s
side-effect-tool listing in source code (`_SIDE_EFFECT_TOOLS`) does not match what is documented.

## Problem
Verified directly against current source (2026-08-02):

1. **Nonexistent function name.** Both files reference `check_routing_drift_vs_live()`, which does not
   exist anywhere in `scripts/shared/` or elsewhere in source. The real function is
   `validate_routing_against_live()`, defined in `scripts/shared/tool_routing_validation.py` (line 38):
   ```python
   def validate_routing_against_live(
       registry: "ToolRegistry | None" = None,
       live_tool_lists: dict[str, list[str]] | None = None,
   ) -> dict[str, list[str]]:
       """Validate that live /v1/tools responses match the registry.

       Returns {server_key: [mismatch_messages]} for servers with mismatches.
       Empty dict means no drift detected.
       """
   ```
   Occurrences of the wrong name found:
   - `docs/04_mcp_03_02_tool-registry.md` line 54 (7-step table, row 4's "推奨" note)
   - `docs/04_mcp_03_02_tool-registry.md` line 59 ("推奨手順" paragraph)
   - `docs/04_mcp_03_05_lifecycle-and-new-server.md` line 53 ("要点" list, item 2)
   Note: `docs/04_mcp_03_02_tool-registry.md` line 31 (the drift-validation function table) **already**
   correctly names `validate_routing_against_live()` — only the prose references below that table are
   wrong. Do not touch the already-correct line 31 entry except to keep it consistent.

2. **Duplicated "add new tool" procedure.** The same underlying 7-step procedure for registering a new
   tool appears redundantly in both files:
   - `docs/04_mcp_03_02_tool-registry.md` lines 47-59: a full 7-step table ("新しいツールの追加") plus a
     "推奨手順" summary paragraph.
   - `docs/04_mcp_03_05_lifecycle-and-new-server.md` lines 44-63: a 5-point "要点" summary list, followed
     later (lines 78-98) by an 8-step checklist table ("新規サーバー/ツール登録チェックリスト") and a
     separate 8-step "手動での作業手順" numbered list — both covering essentially the same ground as
     `03_02`'s 7-step table, with an internal anchor link `#adding-a-new-tool` in `03_05` line 48 that
     appears to reference `03_05`'s own heading, not `03_02`.
   This is effectively duplicated/triplicated content that must be kept in sync manually today (a
   maintenance burden), and the intra-document self-link in `03_05` is confusing given the phrase
   "上記の [Adding a new tool]" suggests cross-referencing content that is meant to live in `03_02`.

3. **Missing side-effect-tool constants in `03_02`.** `docs/04_mcp_03_02_tool-registry.md` lines
   113-116 document:
   ```python
   _SIDE_EFFECT_TOOLS = (
       WRITE_TOOLS | DELETE_TOOLS | frozenset({"shell_run"})
       | GIT_WRITE_TOOLS | GITHUB_WRITE_TOOLS | GITHUB_DANGEROUS_TOOLS
   )
   ```
   The actual definition in `scripts/shared/tool_executor_helpers.py` (lines 35-45) is:
   ```python
   _SIDE_EFFECT_TOOLS: frozenset[str] = (
       WRITE_TOOLS
       | DELETE_TOOLS
       | frozenset({"shell_run"})
       | GIT_WRITE_TOOLS
       | GITHUB_WRITE_TOOLS
       | GITHUB_DANGEROUS_TOOLS
       | CICD_WRITE_TOOLS
       | RAG_WRITE_TOOLS
       | MDQ_WRITE_TOOLS
   )
   ```
   `CICD_WRITE_TOOLS`, `RAG_WRITE_TOOLS`, and `MDQ_WRITE_TOOLS` are confirmed to exist in
   `scripts/shared/tool_constants.py`:
   - `CICD_WRITE_TOOLS: frozenset[str] = frozenset({"trigger_workflow"})` (line 70)
   - `RAG_WRITE_TOOLS: frozenset[str] = frozenset({"rag_delete_document"})` (line 73)
   - `MDQ_WRITE_TOOLS: frozenset[str] = frozenset({"index_paths", "refresh_index"})` (line 89)
   These are real, active members of `_SIDE_EFFECT_TOOLS` at runtime and their omission from the doc is
   an unintentional gap (no evidence anywhere in source or docs of a deliberate exclusion) — a reader of
   `03_02` alone would underestimate which tools trigger serialization of a batch in
   `execute_all_tool_calls()`.

## Reason for change
- The nonexistent function name is a confirmed factual error present in both files; a developer
  searching for or trying to invoke `check_routing_drift_vs_live()` will fail to find it and may
  conclude the documented drift-detection mechanism doesn't exist or is misconfigured.
- The duplicated procedure across `03_02` and `03_05` (in three different renderings: `03_02`'s 7-step
  table, `03_05`'s 5-point summary, and `03_05`'s separate 8-step checklist/manual-steps) doubles (or
  triples) the maintenance cost of keeping "how to add a tool" accurate, and has already partially
  drifted (line 31 of `03_02` was fixed but the prose below it was not), demonstrating the real risk of
  multi-copy content going stale.
- The missing constants leave `03_02`'s documented side-effect-tool set incomplete relative to actual
  runtime behavior, which could cause a reviewer relying on the doc to underestimate which tools force
  serial execution — a correctness/safety-review gap.

## Implementation intent
- Correct the function name in both files' prose so all references to the drift-detection function say
  `validate_routing_against_live()` (matching the already-correct table entry in `03_02` line 31 and the
  real source function in `scripts/shared/tool_routing_validation.py`).
- Designate `docs/04_mcp_03_05_lifecycle-and-new-server.md` as the canonical home for the full "add a
  new tool / new server" procedure (it already contains the more complete checklist table and manual
  steps). Reduce `docs/04_mcp_03_02_tool-registry.md`'s "新しいツールの追加" section to a short summary
  (a few lines) that links to the full procedure in `03_05`, removing the duplicated 7-step table body

  "推奨手順" clarification about `tool_names` not being a routing input, if not already present in
  `03_05`).
  - Do not remove content that is unique to `03_05` (e.g. its 8-step "手動での作業手順" for a brand-new
    server, distinct from adding a tool to an existing server) — only consolidate the overlapping "add a
    new tool" steps.
- Add `CICD_WRITE_TOOLS`, `RAG_WRITE_TOOLS`, `MDQ_WRITE_TOOLS` to the `_SIDE_EFFECT_TOOLS` code excerpt
  and to the accompanying prose note in `docs/04_mcp_03_02_tool-registry.md` (lines 110-123), matching
  the verified real definition in `scripts/shared/tool_executor_helpers.py`.
