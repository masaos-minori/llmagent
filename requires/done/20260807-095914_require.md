# tools/check_no_compat.py's ROOT_DIR resolves one directory too high, causing the no-compat-stubs check to silently scan nothing

## Priority
Medium

## Target files
- `tools/check_no_compat.py` — the `ROOT_DIR` computation, the stale module docstring header, and `DEFAULT_ALLOWLIST` (if newly-surfaced findings need individual allowlisting, and to fix the path reference described below)
- `tests/tools/test_check_no_compat.py` — the actual current location of the test file (confirmed by source inspection; `DEFAULT_ALLOWLIST` inside `check_no_compat.py` still references the stale path `tests/test_check_no_compat.py`, which does not exist)

## Background
`tools/check_no_compat.py` exists specifically to catch backward-compatibility leftovers
(stale import paths, re-export stubs, `_cfg` cache references, etc.) before they land, per
its own docstring and `COMPAT_PATTERNS`. It is wired into `.pre-commit-config.yaml` as the
`no-compat-stubs` hook, invoked with `pass_filenames: false` — i.e. it always runs via its
default, directory-based scan (`ROOT_DIR / "scripts"`, `"docs"`, `"tests"`, `"tools"`), never
via per-file arguments.

## Problem
`ROOT_DIR` is computed as `Path(__file__).resolve().parent.parent.parent` (three `.parent`
calls). Since the file lives at `tools/check_no_compat.py` — one directory below the
repository root — the correct depth is two `.parent` calls, matching the sibling module
`tools/check_suppression_justification.py` (`Path(__file__).resolve().parent.parent`).

The extra `.parent` makes `ROOT_DIR` resolve to the parent of the repository root
(confirmed by direct execution: resolves to `/home/masaos` instead of
`/home/masaos/llmagent`). As a result, every `dirs_to_scan` entry in `main()` fails its
`d.exists()` guard, the scanned-files list stays empty, and the tool always reports
`All checks passed` with exit code `0` — confirmed by running
`uv run python -m tools.check_no_compat` (default scan, no file args, matching exactly how
the pre-commit hook invokes it): output was `All checks passed`, exit code `0`, with zero
files actually scanned.

The module docstring's first line still reads `"""scripts/checks/check_no_compat.py`, a
stale header from before the file was moved to its current location — the likely origin of
the extra `.parent` level (the file used to live one directory deeper, where three
`.parent` calls would have been correct).

Additionally, verification found a related, previously unconfirmed discrepancy:
`DEFAULT_ALLOWLIST` inside `check_no_compat.py` references a test path as
`tests/test_check_no_compat.py`, but the file actually lives at
`tests/tools/test_check_no_compat.py`. The existing test file only exercises individual
`check_*` functions (e.g. `check_compat_patterns`) against synthetic content — it does not
test `main()`'s real default-scan / `ROOT_DIR` path at all, so it would not have caught this
regression.

## Reason for change
A silently-broken compatibility check is worse than no check: it has been giving false
confidence that compatibility-leftover patterns are caught in every commit and in
`pre-commit run --all-files`, when in fact this hook has been a no-op (unconditionally
passing, having scanned zero files) since some prior move of the file to its current path.
This was discovered incidentally while implementing an unrelated requirement and was
explicitly deferred as a separate concern to avoid unrelated scope creep in that change.

## Implementation intent
Fix the path depth so `ROOT_DIR` resolves to the actual repository root, matching the
pattern already used correctly in `tools/check_suppression_justification.py`. Correct the
stale docstring header to reflect the file's real current path. After fixing the depth,
re-run the tool against the current repository and address (fix, or explicitly and
individually allowlist per existing convention) whatever compatibility-leftover findings
newly surface — do not bulk-allowlist without reviewing each finding individually. Also
correct the `DEFAULT_ALLOWLIST` entry that references the wrong test file path, and add a
regression test that exercises `main()`'s real default-scan / `ROOT_DIR` path, since the
existing test suite only covers individual `check_*` functions with synthetic content.

## Implementation instructions
1. In `tools/check_no_compat.py`, change
   `ROOT_DIR = Path(__file__).resolve().parent.parent.parent` to
   `ROOT_DIR = Path(__file__).resolve().parent.parent`.
2. Update the module docstring's first line from `"""scripts/checks/check_no_compat.py` to
   `"""tools/check_no_compat.py`.
3. Run `uv run python -m tools.check_no_compat` (default scan, no file args) after the fix
   and confirm it scans a non-empty file list.
4. Triage every newly-surfaced compatibility-leftover finding individually: fix genuine
   leftovers, or add them to `DEFAULT_ALLOWLIST` one at a time with a clear inline reason
   if confirmed intentional/historical exceptions. Do not bulk-suppress.
5. Fix the `DEFAULT_ALLOWLIST` entry that currently references `tests/test_check_no_compat.py`
   so it points at the file's real location, `tests/tools/test_check_no_compat.py`.
6. In `tests/tools/test_check_no_compat.py`, add a regression test asserting that `ROOT_DIR`
   resolves to a directory that actually contains `scripts/`, `docs/`, `tests/`, and
   `tools/` (or otherwise exercises `main()`'s real default-scan path), so a future file
   move cannot silently reintroduce this bug.
7. Run the standard validation sequence from `rules/toolchain.md` (format, lint, type,
   arch, security, test, coverage) against the changed files.
8. Run `uv run pre-commit run no-compat-stubs --all-files` and
   `uv run pre-commit run --all-files` to confirm the hook is both functional and passing
   against the current, correctly-triaged repository state.

## Acceptance criteria

  reports a real result (either `All checks passed` after genuine triage, or a nonzero exit
  with concrete findings) — not a silent, zero-file `All checks passed`.
- `uv run pre-commit run no-compat-stubs --all-files` passes against the current,

- The module docstring's path header matches the file's actual location
  (`tools/check_no_compat.py`).
- `DEFAULT_ALLOWLIST`'s reference to the test file path matches the file's real location
  (`tests/tools/test_check_no_compat.py`).
- Any newly-surfaced compatibility-leftover findings are either fixed or individually
  allowlisted with a documented reason — not bulk-suppressed.
