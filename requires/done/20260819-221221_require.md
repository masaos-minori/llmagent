# Keep Event Bus _REMOVED_CONFIG_KEYS Startup-Failure Guard Permanently

## Priority
Medium (decision documentation only — no implementation required)

## Target files
- scripts/eventbus/config.py (reference only — no changes permitted per AGENTS.md Global Rule 8)

## Background
`requires/done/20260818-224506_require.md` asked whether the `_REMOVED_CONFIG_KEYS = ("poll_interval_ms", "offset_checkpoint_interval")` hard-fail guard in `scripts/eventbus/config.py::load_config` (lines 69-83) should remain permanently or be retired now that the deprecation window has likely passed.

The guard runs once at process startup (`scripts/eventbus/config.py:72`) and raises a precise, actionable error message if deprecated keys are present in the config file.

## Problem
A decision was needed on whether to keep or retire the startup-failure guard for removed Event Bus configuration keys.

## Reason for change
Document the decision and rationale for future reference. This is a decision record only — implementation is prohibited per AGENTS.md Global Rule 8 ("eventbus に関連する実装は絶対にしないこと").

## Decision
Keep the guard permanently, unchanged.

## Implementation intent
No implementation — this is a decision record. The guard remains as-is in `scripts/eventbus/config.py`.

## Implementation instructions
None — this requirement documents a decision only. No code changes are permitted per AGENTS.md Global Rule 8. Debugging and investigation of eventbus code remain permitted; implementation does not.

## Rationale (for traceability)
- `load_config` runs once at process startup, so the cost of a hard failure is a refused startup with a precise, actionable error message ("delete them from {path}") — not an ongoing runtime cost
- A "warn and continue" relaxation would risk an operator running with a silently-ignored stale config, which is strictly worse than a loud, self-explaining startup failure
- There is no evidence available that the deprecation window has definitively closed for every deployed config (this requires checking the live production `/opt/llm/config/eventbus.toml`, which is outside the scope and tooling of a requirement-to-plan document pass). Retiring the guard without that confirmation would be premature

## What would change this decision
If a maintainer with access to the production eventbus config confirms no deployed config has referenced `poll_interval_ms`/`offset_checkpoint_interval` for a defined, closed deprecation window, and that closure is worth formalizing in code, this decision may be revisited. Any resulting code change still requires a Global Rule 8 exception before implementation.
