# Requirement: Improve Token Usage Tracking Accuracy in Tool Loop Guard

## Priority

High

## Target Files

- `scripts/agent/tool_loop_guard.py`
- `scripts/agent/orchestrator.py`

## Background

When multiple tool calls occur within a single turn, `current_tokens` accumulates across calls. However, `response_tokens` may be inaccurately estimated, especially for streaming responses where token counts are not known until the full response is received.

## Problem

In `tool_loop_guard.py`:

```python
class ToolLoopGuard:
    def __init__(self, max_tokens: int):
        self.max_tokens = max_tokens
        self.current_tokens = 0
    
    async def check_and_record(self, tool_call_id: str, response_tokens: int):
        self.current_tokens += response_tokens
        if self.current_tokens > self.max_tokens:
            raise ToolLoopError("Token limit exceeded")
```

This means:

1. For streaming responses, `response_tokens` is an estimate — not the actual count
2. Underestimation allows token limit to be silently exceeded
3. Overestimation causes false positives (premature termination)
4. No warning when approaching the limit — only fails after exceeding

## Reason for Change

Accurate token tracking is critical for cost control and preventing runaway LLM usage. The guard must use actual token counts, not estimates.

## Implementation Intent

Improve token usage tracking accuracy by using real-time token counting during streaming and adding early warnings before reaching the limit.

## Implementation Instructions

### Step 1: Add real-time token tracking for streaming

In `orchestrator.py`, track tokens as they arrive during streaming:

```python
async def stream_response(self):
    try:
        async for chunk in response:
            # Track tokens per chunk
            if hasattr(chunk, 'usage'):
                self._guard.record_streaming_tokens(chunk.usage.completion_tokens)
            yield chunk
    finally:
        # Finalize streaming token count
        final_count = self._guard.finalize_streaming_tokens()
        await self._guard.check_and_record(final_call_id, final_count)
```

### Step 2: Add streaming token methods to ToolLoopGuard

```python
class ToolLoopGuard:
    def __init__(self, max_tokens: int):
        self.max_tokens = max_tokens
        self.current_tokens = 0
        self._streaming_tokens = defaultdict(int)
    
    def record_streaming_tokens(self, tokens: int):
        """Record tokens during streaming."""
        self._streaming_tokens[self.current_tool_call_id] += tokens
    
    def finalize_streaming_tokens(self) -> int:
        """Get accumulated streaming tokens and reset."""
        total = sum(self._streaming_tokens.values())
        self._streaming_tokens.clear()
        return total
    
    async def check_and_record(self, tool_call_id: str, response_tokens: int):
        self.current_tokens += response_tokens
        
        # Early warning at 80% threshold
        if self.current_tokens > self.max_tokens * 0.8:
            remaining = self.max_tokens - self.current_tokens
            logger.warning(f"Token limit approaching: {remaining} tokens remaining")
        
        if self.current_tokens > self.max_tokens:
            raise ToolLoopError("Token limit exceeded")
```

## Acceptance Criteria

1. Streaming token counts are accurate (not estimated)
2. Warning is logged when approaching token limit (80% threshold)
3. Token limit is enforced correctly for both streaming and non-streaming responses
4. Normal operation is unaffected — no regression
