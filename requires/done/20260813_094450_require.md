# Strengthen canonical RAG schema and remove obsolete dimension configuration

## Priority
High

## Target files
- `scripts/db/schema_sql.py`
- `scripts/db/create_schema.py`
- `scripts/shared/config_validator.py`
- Configuration documentation, examples, MCP config, and fixtures
- Schema and config-validation tests

## Background
Essential chunk invariants (uniqueness, index range, type constraints, content presence) are currently enforced only by application code rather than at the database level. Additionally, legacy configuration parameters related to embedding dimensions remain in `RagConfigValidator` despite dimensions being fixed in code, creating potential confusion and technical debt.

## Problem
1. Lack of database-level constraints on the `chunks` table allows malformed data (duplicates, negative indices, invalid types, empty content) to be inserted if application logic fails.
2. Obsolete `embedding_dim` versus `vec_dim` comparison remnants exist in `RagConfigValidator`, which is unnecessary since dimensions are now hardcoded.

## Reason for change
To improve data integrity through durable database-level invariants and to clean up technical debt by removing obsolete configuration paths.

## Implementation intent
Add SQL constraints to the RAG schema definition and remove all references to configurable embedding dimensions from the validation logic and configuration schemas.

## Implementation instructions
1. Update `_RAG_SCHEMA_TEMPLATE` in `scripts/db/schema_sql.py` to include:
   - `UNIQUE (doc_id, chunk_index)` constraint on `chunks`.
   - `CHECK (chunk_index >= 0)` constraint on `chunks`.
   - `CHECK (chunk_type IN ('text', 'code'))` constraint on `chunks`.
   - `CHECK (length(content) > 0)` constraint on `chunks`.
2. Remove `embedding_dim` versus `vec_dim` comparison from `scripts/shared/config_validator.py`.
3. Clean up all configuration references, examples, MCP configurations, and test fixtures to remove `embedding_dims`, `embedding_dim`, and `vec_dim`.
4. Ensure that no runtime dimension-validation feature is introduced into `RagConfig`, `SearchConfig`, or `IngesterConfig`.
5. Recreate databases to apply the new schema changes.

## Acceptance criteria
- Database rejects duplicate document indices.
- Database rejects negative chunk indices.
- Database rejects unsupported `chunk_type` values.
- Database rejects empty `content`.
- No runtime configuration accepts or compares embedding dimensions.
- New RAG and session schemas correctly use 1024 dimensions from the code constant.

## Tests
- Valid and invalid schema inserts (testing constraints).
- Configuration validation without dimension keys.
- Fixtures containing removed keys.
- Schema recreation at 1024 dimensions.
