# Rewrite `test_parent_dict_merge_one_level_deep` to exercise `ConfigLoader.load_all()` instead of duplicating its merge algorithm

## Priority
Low

## Target files
- `tests/shared/test_shared_boundary_conditions.py` (`TestDictMergeConflictResolution::test_parent_dict_merge_one_level_deep`, currently lines 83-108)
- `scripts/shared/config_loader.py` (`ConfigLoader.load_all()`, lines 68-94 — reference only, must not change)

## Background
A prior fix cycle (`requires/done/20260804-131256_require.md`, implemented via
`plans/20260804-135935_plan.md`) rewrote the sibling test
`test_different_subsections_in_load_all_merged` in the same test class to call the real
`ConfigLoader.load_all()` (via `monkeypatch.setattr("shared.config_loader._BASE_CONFIG_FILES", (...))`)
instead of hand-copying its merge algorithm. That fix and an earlier related one
(`requires/done/20260804-100530_require.md`) both left `test_parent_dict_merge_one_level_deep`
untouched — it was not listed as a target file in either requirement, and the later
requirement's document explicitly scoped only `test_different_subsections_in_load_all_merged`,
listing other tests in the class as "unaffected."

## Problem
`test_parent_dict_merge_one_level_deep` (verified still present, current lines 83-108) has the
same anti-pattern the sibling test used to have: its docstring claims to verify
"Parent dicts are merged one level deep in load_all", but the test body calls
`loader.load("extra_mcp.toml")` and `loader.load("extra_mcp2.toml")` separately, then manually
re-implements `load_all()`'s one-level-deep dict-merge loop inline (comment: "Manually merge
like load_all does") and asserts against that hand-rolled `merged` dict — never against
`ConfigLoader.load_all()`'s actual return value. This was confirmed by reading the current file
content, which matches the issue's description exactly (only the line numbers shifted slightly,
83-108 vs. the issue's 91-116, due to unrelated changes elsewhere in the file).

## Reason for change
Because the test never calls `load_all()`, it would not catch a regression in
`ConfigLoader.load_all()`'s real one-level-deep dict-merge logic (`config_loader.py` lines 82-93).
The fix pattern is already established and in use in the same file
(`test_different_subsections_in_load_all_merged`) and in
`tests/shared/test_config_loader.py::TestMergeOrder::test_nested_dict_merge`, so applying it here
requires no new technique — only replicating a known-good pattern to close a coverage gap two
prior fix cycles missed.

## Implementation intent
Replace the hand-rolled merge loop in `test_parent_dict_merge_one_level_deep` with a call to
`ConfigLoader.load_all()`, using `monkeypatch.setattr("shared.config_loader._BASE_CONFIG_FILES", (...))`
to point `load_all()` at the test's `extra_mcp.toml` / `extra_mcp2.toml` fixture files (the same
approach already used by `test_different_subsections_in_load_all_merged`). Assertions must read
from `load_all()`'s real return value rather than from a manually constructed dict. Do not modify
`scripts/shared/config_loader.py` — this is a test-only change.

## Implementation instructions
1. In `tests/shared/test_shared_boundary_conditions.py`, add a `monkeypatch: pytest.MonkeyPatch`
   parameter to `test_parent_dict_merge_one_level_deep` (mirroring
   `test_different_subsections_in_load_all_merged`'s signature).
2. Keep the two fixture files (`extra_mcp.toml` with `[mcp_servers.github]\nurl = "..."`,
   `extra_mcp2.toml` with `[mcp_servers.github]\ntimeout = 30`) as-is — they already set up the
   one-level-deep merge scenario (same `github` subsection key, different fields).
3. Add `monkeypatch.setattr("shared.config_loader._BASE_CONFIG_FILES", ("extra_mcp.toml", "extra_mcp2.toml"))`.
4. Replace the manual `loader.load(...)` calls and the two merge `for` loops with a single
   `result = loader.load_all()` call.
5. Update assertions to read from `result` (e.g. `assert "github" in result.get("mcp_servers", {})`,
   `assert "url" not in result["mcp_servers"]["github"]`,
   `assert result["mcp_servers"]["github"]["timeout"] == 30`), preserving the same semantic checks
   the original test made (later file's `timeout` key present, earlier file's `url` key absent from
   the merged `github` subsection — i.e. `load()`'s shallow-update behavior propagated through
   `load_all()`'s one-level-deep merge).
6. Leave the docstring's intent statement accurate to what is now actually being tested (it already
   matches: "Parent dicts are merged one level deep in load_all").
7. Do not modify `scripts/shared/config_loader.py` or any other test in
   `TestDictMergeConflictResolution`.

## Acceptance criteria
- `test_parent_dict_merge_one_level_deep` calls `ConfigLoader.load_all()` directly (via a
  monkeypatched `_BASE_CONFIG_FILES`) rather than hand-copying its merge algorithm.
- The test's assertions read from `load_all()`'s real return value, not from a manually
  constructed `merged` dict.
- No production code (`scripts/shared/config_loader.py`) is modified.
- Other tests in `TestDictMergeConflictResolution` remain unmodified and continue to pass.
