# Require: Extend ROLE_KEY_WHITELIST to cover LLMMessage optional fields

## Priority

Low

## Target files

- `scripts/agent/message_schema.py` (ROLE_KEY_WHITELIST)
- `scripts/shared/types.py` (LLMMessage TypedDict)

## Background

While planning the `validate_message()` wiring work (`plans/20260726-093008_plan.md`, source requirement `requires/done/20260726-085634_require.md`), a schema/type mismatch was discovered between `ROLE_KEY_WHITELIST` in `message_schema.py` and the `LLMMessage` TypedDict in `types.py`.

## Problem

`LLMMessage` declares `name`, `importance`, and `pinned` as valid optional fields. These fields are used by `scripts/agent/history_selection_policy.py`'s `classify_importance()` to prioritize messages during history compression. However, none of these three fields appear in any `ROLE_KEY_WHITELIST` entry (`system`, `user`, `assistant`, `tool`).

## Reason for change

If a future change starts setting `pinned` or `importance` directly on a `ctx.conv.history` message, the newly-wired `validate_message()` would treat those as "Unexpected keys" and either reject the message or strip the field — silently degrading `history_selection_policy`'s compression-priority behavior.

## Implementation intent

Ensure `ROLE_KEY_WHITELIST` entries include all valid optional fields declared in the `LLMMessage` TypedDict, preventing silent field stripping during validation.

## Implementation instructions

Two possible approaches:

1. **Extend `ROLE_KEY_WHITELIST`**: Add `name`, `importance`, and `pinned` to each role's whitelist entry where appropriate, based on role semantics.
2. **Reconcile `LLMMessage` TypedDict**: Remove the unused optional fields (`name`, `importance`, `pinned`) from the TypedDict if they are never intended for conversation-history messages.

In the interim, before the chosen approach is implemented, the append-path implementation should log a `warning` (not fail silently) whenever `validate_message()` causes a key to be stripped.

## Acceptance criteria

- [ ] All fields declared in `LLMMessage` TypedDict that can appear on conversation-history messages are included in the relevant `ROLE_KEY_WHITELIST` entries
- [ ] No existing tests are broken by the change
- [ ] If warning logging is added in the interim, warnings are emitted when keys are stripped due to whitelist mismatch

## Tests

- Verify `validate_message()` accepts messages with `name`, `importance`, and `pinned` fields without stripping them
- Verify `classify_importance()` correctly reads `importance` and `pinned` from conversation-history messages after the fix
