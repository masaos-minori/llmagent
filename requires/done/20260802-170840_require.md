# Fix confirmed tool-count errors in docs/04_mcp_01_system_overview.md Server Catalog

## Priority
High

## Target files
- docs/04_mcp_01_system_overview.md (Server Catalog table, around lines 71 and 79)

## Background
`docs/04_mcp_01_system_overview.md` contains a "Server Catalog" table that records, among other
attributes, the number of tools each MCP server exposes. This table is a reference used for
design changes and audits of the MCP server fleet. A prior review (`docs_review_mcp.md` §1 item
2, §5 example 2, §6A) flagged that two entries in this table have incorrect tool counts.

## Problem
The Server Catalog table currently states:
- `web-search-mcp` (port 8004): 1 tool
- `mdq-mcp` (port 8013): 9 tools

Independent re-verification against current source code (2026-08-02) confirms both counts are
wrong:
- `web-search-mcp` actually exposes **2** tools: `search_web` and `browser_fetch`, defined in
  `TOOL_LIST` in `scripts/mcp_servers/web_search/web_search_tools.py` (lines 15 and 40). The
  `browser_fetch` tool was added at some point and this table was never updated to reflect it.
- `mdq-mcp` actually exposes **7** tools: `search_docs`, `get_chunk`, `outline`, `index_paths`,
  `refresh_index`, `stats`, `grep_docs`, defined in `TOOL_LIST` in
  `scripts/mcp_servers/mdq/mdq_tools.py` (lines 25, 81, 103, 127, 146, 169, 175). This matches the
  docstring in `scripts/mcp_servers/mdq/mdq_server.py` ("Exposes 7 tools for indexing, searching,
  and inspecting Markdown documents."), which is itself already correct — only the Server Catalog
  table in the overview doc is wrong.

Additionally, there is no record in the document of when/why `web-search-mcp`'s tool count
changed from 1 to 2 (i.e., no note of the `browser_fetch` integration event), which suggests the
table has no reliable update process.

## Reason for change
This is a confirmed factual error (re-verified independently against current source, not merely
carried over from the original review), not speculation. Anyone relying on this table for a
design change or audit will encounter a mismatch between documented and actual tool counts and
lose trust in the document's accuracy. The missing update-history note means the same drift is
likely to recur.

## Implementation intent
Correct both tool-count cells in the Server Catalog table to match current source, and add a
note (either an adjacent column or an inline annotation) recording that `web-search-mcp`'s count
changed from 1 to 2 due to the `browser_fetch` integration. Do not introduce a full
update-history mechanism for the entire document — scope this to the two corrected cells and
their accompanying note only.

## Implementation instructions
1. Open `docs/04_mcp_01_system_overview.md` and locate the Server Catalog table (currently around
   line 71 for `web-search-mcp` and line 79 for `mdq-mcp`).
2. Change the `web-search-mcp` row's tool-count value from `1` to `2`.
3. Change the `mdq-mcp` row's tool-count value from `9` to `7`.
4. Add a note recording the `web-search-mcp` count change from 1 to 2 due to the `browser_fetch`
   integration. This can be a short parenthetical/footnote next to the `web-search-mcp` count
   cell, or a one-line note immediately below the table — whichever fits the document's existing
   conventions with minimal structural disruption.
5. Before finalizing, re-verify both counts directly against current source (count entries in
   `TOOL_LIST` in `scripts/mcp_servers/mdq/mdq_tools.py` and
   `scripts/mcp_servers/web_search/web_search_tools.py`, or equivalent tool-registration
   structures if they have changed), since additional time may have passed since this requirement
   was written and counts could have changed again.
6. Do not add a general update-history mechanism for the whole document; keep the change scoped
   to the two corrected values and the one accompanying note.

## Acceptance criteria

- No other unrelated content in `docs/04_mcp_01_system_overview.md` is changed.
