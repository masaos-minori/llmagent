## Background
The source issue (`issues/done/20260802-080020_rag_05_8_cleanup_and_delete_order_fix.md`)
originally raised two problems in `docs/03_rag_05_8-rag-mcp-internal-operations-direct-db-access.md`:

1. The `delete_document()` deletion-order description incorrectly claimed a 3-stage
   deletion (`chunks_vec → chunks → documents`) when the actual implementation
   (both `document_manager.py` copies, in `scripts/mcp_servers/rag_pipeline/` and
   `scripts/rag/ingestion/`) is 2-stage (`chunks_vec → documents`, with `documents`
   deletion cascading to `chunks` via `ON DELETE CASCADE`).
2. The doc transcribes `crawler.py`/`chunk_splitter.py`/`ingester.py` `--help` output
   and a `list_documents()` signature verbatim, which is mechanical, auto-generatable
   content that adds maintenance burden.

Verification against the current repository (as of 2026-08-02) shows that problem (1)
was already fixed by commit `6cfb24c10` ("feat: add RAG docs consistency checker and
fix confirmed drift"). The doc's current "削除順序 (重要)" section correctly describes
the 2-stage `chunks_vec → documents` order with CASCADE removing `chunks`, and it
already cites `docs/03_rag_91_design_notes-part1.md` DESIGN-3, which matches. **No
further action is needed for the deletion-order claim.**

Problem (2) is still present and unresolved: the doc still contains a `## crawler`,
`## chunk_splitter`, and `## ingester` section, each with a verbatim `--help` output
block, and a `list_documents()` signature listing under `## list_documents()`.

## Problem
`docs/03_rag_05_8-rag-mcp-internal-operations-direct-db-access.md` still transcribes:
- The `list_documents()` Python signature (`def list_documents(lang: str | None = None, limit: int = 20) -> list[DocumentItem]`).
- The full `--help` output of `crawler.py`, `chunk_splitter.py`, and `ingester.py`,
  wrapped in an (incompletely-applied) auto-generation guard region ending in
  `<!-- END AUTO-GENERATED -->` but missing the matching
  `<!-- AUTO-GENERATED: gen_rag_reference.py cli-help -->` start marker that
  `tools/gen_rag_reference.py` looks for. Because the start marker is absent, running
  `tools/gen_rag_reference.py` (without `--dry-run`) would not update the block in
  place — it would append a second, duplicate block instead. The generator's current
  output format (`### crawler`, etc.) also does not match the doc's current heading
  level (`## crawler`, etc.), a further sign the transcribed content and the generator
  have drifted apart.

This mechanical content duplicates information that lives in the CLI scripts
themselves and in `tools/gen_rag_reference.py`, and it is not reliably kept in sync.

## Reason for change
Verbatim CLI `--help` output and method signatures are auto-generatable and provide
no design-level value in a document meant to describe responsibility boundaries
(RAG MCP internal operations vs. Agent-layer direct DB access). Keeping them here:
- Adds maintenance burden (must be manually or mechanically re-synced whenever the
  CLI argparse definitions or `list_documents()` signature change).
- Is currently out of sync with the generator tool that is supposed to maintain it
  (missing start guard marker, mismatched heading levels), so the "AUTO-GENERATED"
  framing is misleading to a reader.
- Distracts from the file's main value: the responsibility-boundary declaration and
  the (now-correct) `delete_document()` deletion-order/CASCADE explanation.

## Implementation intent
Remove the transcribed `--help` output blocks (crawler/chunk_splitter/ingester
sections) and the `list_documents()` signature listing from
`docs/03_rag_05_8-rag-mcp-internal-operations-direct-db-access.md`, replacing them
with a short pointer to the implementation tree (i.e., point the reader to
`scripts/rag/ingestion/crawler.py --help`, `chunk_splitter.py --help`,
`ingester.py --help`, and the `list_documents()` definition in
`scripts/mcp_servers/rag_pipeline/document_manager.py` /
`scripts/rag/ingestion/document_manager.py`) for current, authoritative usage and
signatures. Do not change the deletion-order description (already correct) or the
opening responsibility-boundary declaration (already the most valuable, unrelated
content in the file — keep unchanged).

Because the CLI-help block is tied to `tools/gen_rag_reference.py`, this change
should also resolve (or explicitly decide against) the mismatch between the
generator's guard markers/heading format and the doc's current content: either
(a) remove the CLI-help auto-generation feature from `gen_rag_reference.py` entirely
since the transcribed section is being deleted, or (b) if the tool is still used
elsewhere/should be kept for future use, leave it untouched but ensure the doc no
longer references or depends on it. Prefer (a) unless another document is found to
depend on `gen_rag_reference.py`'s CLI-help generation — check for such dependents
before deciding.
