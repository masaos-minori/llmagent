## Background

`docs/00_governance_07_needs-confirmation-inventory.md` tracks open "Needs confirmation" questions across the documentation set. NC-011 (lines 190-199) records an open question about whether the docstring reference to `common.toml::embedding_dims` in `03_rag_02_04_ingestion_pipeline-ingester-part2.md` is intentional legacy text, with `Status: open` and `Required Action: Confirm with original author that docstring is outdated`.

The source document has since been updated. `docs/03_rag_02_04_ingestion_pipeline-ingester-part2.md` §4.4 (around line 49) now reads:

> - `embedding_dims`: `config/ingester.toml` で指定（デフォルト384）
> - docstringの `common.toml::embedding_dims` は古い記述（`common.toml` は存在しない）

This text is declarative, contains no `Needs confirmation` label, and directly answers the question NC-011 was tracking: the `common.toml` reference is confirmed outdated because `common.toml` does not exist and the actual config source is `config/ingester.toml`.

## Problem

The inventory entry (NC-011, `Status: open`) no longer reflects the current state of the source document it tracks. The underlying question has already been answered in the source text, but the inventory still presents it as an open, unassigned action item requiring author confirmation. This is a stale-inventory defect: a reader consulting the inventory for outstanding documentation questions would be misled into believing this item still needs work, when the resolution is already committed to the docs.

## Reason for Change

An inventory of open documentation questions is only useful if it accurately reflects reality. A stale `open` entry for an already-resolved question:

- Wastes reviewer/author time re-investigating a question that has already been answered.
- Undermines trust in the inventory as a governance artifact — if one entry is known-stale, readers must independently re-verify all entries.
- Was itself flagged as the motivating example for a broader governance concern (per the source issue): the inventory as a whole may need a periodic reconciliation process against its source documents, since at least one stale entry (NC-011) was found during this investigation.

1. Update the NC-011 entry's `Status` field in `docs/00_governance_07_needs-confirmation-inventory.md` from `open` to a resolved state (e.g. `resolved`), reflecting that the source document already contains the confirmed, declarative answer.
2. Add a brief note/reference in the NC-011 entry pointing to the resolving text in `docs/03_rag_02_04_ingestion_pipeline-ingester-part2.md` (§4.4, ~line 49), so the resolution is traceable.
