# SessionTitleService.extract_llm_content behavior undocumented

## Priority
Low

## Summary
When LLM returns a valid response but with unexpected format, extract_llm_content returns None and SessionTitleGenerationError is raised. This is correct behavior but not documented anywhere.

## Reason for Change
The error handling catches specific exceptions and wraps them in SessionTitleGenerationError. However, the case where extract_llm_content returns None (valid response, wrong format) is not explicitly documented. Users might not understand why title generation fails.

## Implementation Intent
Consider documenting the expected LLM response format and adding a more specific error message when extract_llm_content returns None.

## Target Files or Areas
- scripts/agent/services/session_title.py
- extract_llm_content function

## Required Changes
- Document the expected LLM response format
- Add a more specific error message when extract_llm_content returns None
- Ensure error messages are user-friendly and actionable

## Acceptance Criteria

- [ ] No regressions in normal operation when registry is available

## Documentation Impact
If DiagnosticsConfig is extended, update documentation to reflect the new state.

## Out of Scope

## AI Implementation Instruction
Modify only _filter_sensitive_fields() in diagnostic_store.py. Add a new state to McpAvailability enum if needed. Update the fallback logic to use the new state instead of UNKNOWN when registry is None.
