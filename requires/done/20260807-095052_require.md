## Background
The `05_agent_*.md` document set mixes design/operational judgment with content that is mechanically derivable from code. A review (`memo-doc-agent-review.md`) identified what to keep vs. remove per chapter.

## Problem
The runtime-architecture chapter mixes genuine architectural boundary decisions with implementation detail that changes on every refactor (private class names, mixin counts, MRO, per-method tables), causing frequent doc/code drift.

## Reason for change
This chapter should serve as the canonical source for runtime responsibility boundaries only. Fine-grained implementation detail increases staleness risk without adding decision value.

## Implementation intent
Keep this chapter as the canonical source for runtime responsibility boundaries. Remove private-class/mixin/MRO detail and method-level responsibility tables. Preserve shared/agent dependency-direction rules verbatim (architectural boundary rule enforced elsewhere, e.g. `lint-imports`).
