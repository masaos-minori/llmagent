# Requirement: Add Concurrency Control to TurnState

## Priority

Medium

## Target Files

- `scripts/agent/context.py`

## Background

When multiple turns concurrently read or write `TurnState`, simultaneous access to the `tool_calls` list can cause race conditions leading to data corruption.

## Problem

In `context.py`:

```python
class TurnState:
    def __init__(self):
        self.turn_count = 0
        self.tool_calls = []
    
    def add_tool_call(self, call_id: str):
        self.tool_calls.append(call_id)  # Non-atomic operation
```

This means:

1. Two coroutines simultaneously call `add_tool_call()` on the same `TurnState`
2. Both read the current length of `tool_calls`
3. Both append their item at the same index
4. One item is silently lost (data loss)

Note: In CPython, the GIL makes simple `list.append()` atomic at the bytecode level. However, this is an implementation detail — it should not be relied upon. The real risk is when `turn_count` or other non-atomic operations are involved.

## Reason for Change

Relying on CPython's GIL for thread safety is fragile and incorrect by design. Explicit locking ensures correctness across all Python implementations and future-proof against changes.

## Implementation Intent

Add explicit concurrency control using `asyncio.Lock` to protect shared state in `TurnState`.

## Implementation Instructions

### Step 1: Add lock to TurnState

```python
import asyncio
from typing import List

class TurnState:
    def __init__(self):
        self.turn_count = 0
        self.tool_calls: List[str] = []
        self._lock = asyncio.Lock()
    
    async def add_tool_call(self, call_id: str):
        """Thread-safe addition of a tool call."""
        async with self._lock:
            self.tool_calls.append(call_id)
            self.turn_count += 1
    
    async def get_tool_calls(self) -> List[str]:
        """Return a copy of tool calls."""
        async with self._lock:
            return list(self.tool_calls)
    
    async def get_turn_count(self) -> int:
        """Return the current turn count."""
        async with self._lock:
            return self.turn_count
```

### Step 2: Ensure all callers use async methods

Review all code that accesses `TurnState` fields directly and update them to use the new async methods.

## Acceptance Criteria

1. All `TurnState` field access goes through locked methods
2. No data loss occurs under concurrent access
3. Normal single-turn operation is unaffected — no regression
