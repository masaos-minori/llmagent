# Clarify duplicate search orchestration and semantic-cache mismatch behavior

## Priority
Low

## Target files
- `scripts/rag/pipeline.py`
- `scripts/rag/stages/search.py`
- `scripts/rag/cache.py`
- `tests/rag/ingestion/test_rag_ingester.py` (and other related search tests)

## Background
Currently, both `RagPipeline.search_queries()` and `SearchStage.run()` perform similar tasks: concurrent embedding fetching followed by sequential database searches (vector and FTS). This redundancy risks divergent error handling and diagnostic reporting. Additionally, `SemanticCache.lookup` raises a `ValueError` when an embedding dimension mismatch occurs, which could crash the pipeline instead of being handled gracefully as a cache miss.

## Problem
1. **Redundant Orchestration**: Multiple code paths exist for searching, leading to potential inconsistencies in how errors are caught and how diagnostics are reported.
2. **Brittle Cache Handling**: `SemanticCache` uses hard exceptions for dimension mismatches, forcing the caller to manage these critical runtime issues rather than treating them as simple cache misses.

## Reason for change
To consolidate search orchestration into a single canonical path and establish a robust, graceful degradation policy for semantic cache dimension mismatches.

## Implementation intent
Consolidate search logic into `SearchStage` where possible and modify `SemanticCache` to handle dimension mismatches by returning a miss (None) instead of raising an exception.

## Implementation instructions
1. **Orchestration Consolidation**:
   - Review usage of `RagPipeline.search_queries()`. If it is purely internal or redundant with `SearchStage`, refactor callers to use `SearchStage`.
   - Ensure `SearchStage` provides standardized `SearchDiagnostics`.
2. **Cache Robustness**:
   - Modify `SemanticCache.lookup` in `scripts/rag/cache.py` to catch dimension mismatches and return `None` instead of raising `ValueError`.
   - Log the dimension mismatch event as a warning.
   - Consider invalidating the incompatible cache entry upon detection.
3. **Documentation**:
   - Update design docs to reflect the new behavior for cache dimension mismatches (graceful degradation vs failure).

## Acceptance criteria
- A clear, documented canonical path for search orchestration exists.
- `SemanticCache.lookup` returns `None` (cache miss) when encountering a dimension mismatch.
- Dimension mismatches in the cache are logged as warnings.
- Search diagnostics remain accurate and consistent across all search execution paths.

## Tests
- Test `SemanticCache.lookup` with mismatched dimensions (verify it returns `None` and logs a warning).
- Test search orchestration through both `RagPipeline.search_queries()` and `SearchStage` to ensure identical diagnostics and error handling.
- Verify that valid cache hits still work correctly.
