## Problem
`tests/tools/test_check_mcp_docs_consistency.py` fails at collection in its entirety, so the
`check-mcp-docs` CI entry point's actual current logic (`check_port_drift`, `check_tool_name_drift`,
the shared generic checks it wires up, and `main()`'s `--skip` handling) has zero automated test
coverage. The file's own content is not a reliable guide for a fix: it is a full test suite written
against a check catalog that was deleted and replaced, not a small set of renamed symbols — there is
no 1:1 mapping from any of the twelve missing imports to a current function.

## Reason for change
Zero test coverage on the sole automated guard against MCP documentation drift (port-config
mismatches vs. `config/agent.toml`, and tool-name mismatches vs. live `TOOL_LIST` definitions) means
regressions in `check_port_drift`/`check_tool_name_drift`/`main()` would go undetected until CI
(or, worse, a human) notices stale docs in production. The check logic itself was deliberately
redesigned to read live sources of truth instead of a hand-maintained catalog specifically to avoid
becoming stale — but the test suite meant to protect that redesign has itself been silently stale
since commit `74906389`.

## Implementation intent
Treat this as a full test rewrite against the current module's actual public surface, not an import
rename. Do not attempt to preserve the old test file's class names, structure, or fixture shapes
where they do not map to current functions — `TestCheckStartupModes` and similar classes test
behavior that no longer exists and must be dropped, not patched.

Write fresh, synthetic-fixture-based tests (matching the file's own stated convention — see its
docstring: "synthetic doc content, not references to real doc files") covering:
- `check_port_drift`: doc/config pairs that agree (no issue), pairs that disagree (ERROR issue with
  correct file/line/message), a server name with no digit-string near it (no issue), a 4-digit
  number outside the `80xx` range or on a `is_historical_line()`-flagged line (skipped), and a
  missing/unparsable `config/agent.toml` (function returns `[]`, i.e. `_extract_authoritative_ports`
  returning `None` short-circuits the check).
- `check_tool_name_drift`: a "ツール:"/"Tools:" line whose backtick-quoted names are all present in a
  synthetic live-tool-name set (no issue), a line with a name absent from that set (WARNING issue),
  a backtick name with no underscore (skipped as "too generic"), and an empty live-tool-name set
  (function returns `[]`).
- `main()`'s `--skip` flag handling: for at least a couple of the seven current `--skip` choices
  (`links, removedfiles, commanddrift, portdrift, tooldrift, filerefs, funcrefs`), confirm that
  passing `--skip <name>` prevents the corresponding check from contributing issues to the exit
  code/output, using a temporary `docs_dir` fixture (via `tmp_path`) rather than the real `docs/`
  tree, so the test is not coupled to the current (drifting) state of `docs/`.

Since `check_port_drift` and `check_tool_name_drift` both take a `repo_root: Path` and read
`config/agent.toml` / `scripts/mcp_servers/**/*.py` from it via helper functions
(`_extract_authoritative_ports`, `_extract_live_tool_names`), prefer testing those two check
functions with a synthetic `repo_root` (a `tmp_path`-based fixture with a minimal
`config/agent.toml` and/or `scripts/mcp_servers/` tree) so tests do not depend on the real repo's
current config/tool state drifting out from under them. Reading the helper functions' full bodies
(`tools/check_mcp_docs_consistency.py` lines 74-107 for ports, lines 166-181 for tool names) before
writing fixtures is necessary to match their exact expected shapes (e.g. the port-name convention
`"<key>-mcp"` with underscores replaced by hyphens; the `'{ "name": "..." }'`-style regex for tool
names).
