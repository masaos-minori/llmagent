# Remove dead `except PermissionError` handlers around `rglob()` in `read_business.py`

## Priority
Medium

## Target files
- `scripts/mcp_servers/file/read_business.py` (`search_files`, `_collect_grep_matches`)
- `tests/mcp_servers/file/test_read_service.py` (verification only)

## Background
`scripts/mcp_servers/file/read_business.py` has two `except PermissionError` blocks wrapping `base.rglob("*")` traversals — one in `search_files` (line 222) and one in `_collect_grep_matches` (line 256). Under Python 3.14, `pathlib.Path.rglob()`'s internal `scandir()` calls are wrapped in their own `try: ... except OSError: pass` (confirmed by reading CPython's `Lib/glob.py`). This means these two `except PermissionError` blocks are provably unreachable on this runtime.

The project's `pyproject.toml` declares `requires-python = ">=3.13"` and `target-version = "py313"`. Verified that Python 3.13's `glob.py` also wraps `scandir()` errors in `except OSError: pass` (same pattern confirmed via source inspection at https://github.com/python/cpython/blob/v3.13.0/Lib/glob.py). Empirical test on the current runtime (3.14) confirms rglob() swallows PermissionError when encountering a chmod-000 subdirectory.

## Problem
Two `except PermissionError` handlers around `rglob()` calls are dead code under all supported Python versions (3.13+). They add unnecessary complexity and mislead developers about the actual exception behavior of rglob().

## Reason for change
Dead code removal reduces cognitive load and prevents confusion about rglob() exception semantics. The handlers were likely added defensively before the rglob() swallowing behavior was understood, or based on assumptions from earlier Python versions where rglob() may have propagated PermissionError.

## Implementation intent
Remove both `except PermissionError` handlers around `rglob()` calls since they are unreachable under all supported Python versions (3.13+). Document the reason inline referencing this issue. Verify existing tests still pass.

## Implementation instructions
1. **Confirm**: Read the two handler contexts in `read_business.py`:
   - `search_files` (line ~222): `except PermissionError as e:` followed by `logger.debug(...)`
   - `_collect_grep_matches` (line ~256): `except PermissionError as e:` followed by `logger.warning(...)`
2. **Remove** both handlers:
   - Delete the `except PermissionError` block in `search_files` (lines 222-223).
   - Delete the `except PermissionError` block in `_collect_grep_matches` (lines 256-259).
3. **Document** the decision with an inline comment near each removal site explaining why the handler was removed (referencing this issue and the Python 3.13+ rglob() swallowing behavior).
4. **Verify**: Run `tests/mcp_servers/file/test_read_service.py` to confirm no regression. Specifically verify the two characterization tests mentioned in the original issue (`test_search_files_permission_error_during_traversal_is_swallowed`, `test_grep_files_permission_error_during_traversal_is_swallowed`) still pass — they should since they assert observable behavior, not coverage of the specific `except` block.

## Acceptance criteria
