# Add guard tests for approval task ID persistence across turns

## Background

After executing /approve command, the approved task ID is set in ctx.turn.pending_approval_task_id. This value persists until the next turn and gets overwritten when another approval is accepted, but no validation occurs. Additionally, even if the retrieved task has a "halted" status, processing continues.

## Problem

Multiple approvals can cause the approved task ID to be silently overwritten, leaving original approval-related tasks in an unknown state.

## Reason for Change

Establish behavioral baseline through guard tests before any refactoring of these components.

## Implementation Intent

Create comprehensive guard tests covering:
- Task ID overwrite detection verification
- Pending approval ID clearing after resolution verification
- Halted task status rejection verification
- Multiple sequential approval handling verification
