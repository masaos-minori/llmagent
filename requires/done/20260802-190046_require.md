## Reason for change
Line-number references in documentation are inherently fragile: every reference in the original
issue that pointed at a specific line had already drifted by the time of review, and re-verification
today shows further drift on 2 of those (repository.py, llm_client.py) plus 13 more previously
unaudited instances across the `docs/03_rag_*.md` set. `docs/03_rag_05_5-constraints-reference.md`
already adopted and documented a robust alternative (name/key-based references) specifically because
of this exact failure mode. Extending that pattern domain-wide removes an entire class of future doc
rot without requiring re-verification whenever source line numbers shift.

## Implementation intent
For each of the 15 locations listed under Problem, replace the raw `<file>:<line>` or
`<file>:<line>-<line>` citation with a name-based reference — the enclosing function, method,
class, property, or constant name (e.g. "`RagRepository.fetch_full_document()` 関数",
"`RagPipeline.invalidate_cache()` メソッドのdocstring", "`SemanticCache` クラス定義") — matching the
prose and citation style already used in `docs/03_rag_05_5-constraints-reference.md` (e.g.
`config/chunk_splitter.toml:chunk_overlap`, `scripts/rag/utils.py:floats_to_blob`,
`crawler.py`の`cfg.get("max_pages", 500)`). Do not change the technical claims themselves — only
the anchor mechanism — unless converting the anchor surfaces an actual factual error, in which case
correct the fact too and note it the way `03_rag_05_5` does ("訂正" / "旧版では...現行では...").

Do not touch `docs/03_rag_01_system_overview-part2.md` or `docs/03_rag_05_1-configuration-reference.md`
— these are already fixed and out of scope.

## Implementation instructions
1. Re-confirm each of the 15 locations above still exists at roughly the cited spot (source may
   have moved further between requirement-writing and implementation); if a reference has moved,
   use the current location as the anchor point, not the numbers quoted in this document.
2. For each location, replace the numeric line/range citation with a name-based citation:
   - Function/method def → "`<name>()` 関数" / "`<name>()` メソッド"
   - Class def → "`<ClassName>` クラス"
   - Import statement → the module path only (drop the line number), e.g. "`rag.cache` からの
     `SemanticCache` のimport"
   - Docstring/comment reference → name the enclosing function/method rather than its line number
   - Config key → `file.toml:key_name` style (already used in `03_rag_05_5`), not a line number

   classification or the surrounding claim.
