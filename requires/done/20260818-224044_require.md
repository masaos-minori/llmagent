# Remove test-compatibility re-export shim for TransportError in tool_executor.py

## Priority
Low

## Target files
- scripts/shared/tool_executor.py
- tests/shared/test_tool_executor.py

## Background
`scripts/shared/tool_executor.py` imports `TransportError` from its true definition
location, `shared/http_transport`, and re-exports it solely so that
`tests/shared/test_tool_executor.py` can import `TransportError` from
`shared.tool_executor` instead of from its real module. The re-export is marked with
an explicit suppression comment:
`# noqa: F401 -- re-exported: tests/shared/test_tool_executor.py imports TransportError from this module`.

Verified in current code (2026-08-18):
- `scripts/shared/tool_executor.py` lines 26-29 import `HttpTransport` and
  `TransportError` from `shared.http_transport` with the `# noqa: F401` re-export
  comment still present.
- `tests/shared/test_tool_executor.py` lines 27-30 import `ToolExecutor` and
  `TransportError` from `shared.tool_executor` (not from `shared.http_transport`),
  and uses `TransportError` at lines 307, 330, 352, 379, and 608.

## Problem
The test suite depends on an implementation module (`tool_executor.py`) re-exporting
a symbol (`TransportError`) that is not actually used by `tool_executor.py` itself,
purely to satisfy a test import. This creates a latent trap: a future contributor
who sees `TransportError` imported-but-unused in `tool_executor.py` may remove it
(since the `noqa: F401` easily gets missed or stripped during cleanup), silently
breaking `tests/shared/test_tool_executor.py` at collection time.

## Reason for change
The re-export exists only for test convenience and does not reflect any real usage
of `TransportError` within `tool_executor.py`'s own logic. Aligning the test's
import with the symbol's actual defining module (`shared.http_transport`) removes
this fragile indirection and the associated suppression comment, reducing future
maintenance confusion with no behavior change.

## Implementation intent
Change the test to import `TransportError` directly from its defining module,
`shared.http_transport`, alongside (or instead of) its existing import of
`ToolExecutor` from `shared.tool_executor`. Then remove the now-unnecessary
re-export of `TransportError` (and its `# noqa: F401` comment) from
`tool_executor.py`, keeping only imports that `tool_executor.py` itself actually
uses (e.g., `HttpTransport`, if still needed there).

## Implementation instructions
1. In `tests/shared/test_tool_executor.py`, update the import block so that
   `TransportError` is imported from `shared.http_transport` rather than from
   `shared.tool_executor`. Keep `ToolExecutor` imported from `shared.tool_executor`.
2. In `scripts/shared/tool_executor.py`, remove `TransportError` from the
   `from shared.http_transport import (...)` block and delete the
   `# noqa: F401 -- re-exported: tests/shared/test_tool_executor.py imports
   TransportError from this module` comment. Verify whether `HttpTransport` is
   still used directly by `tool_executor.py`; if so, keep that import (without the
   re-export comment), otherwise adjust accordingly.
3. Confirm no other module relies on importing `TransportError` from
   `shared.tool_executor` (grep the codebase for
   `from shared.tool_executor import` and `tool_executor.TransportError`).

## Acceptance criteria
- `tests/shared/test_tool_executor.py` imports `TransportError` from
  `shared.http_transport`.
- `scripts/shared/tool_executor.py` no longer re-exports `TransportError` and no
  longer contains the associated `# noqa: F401` compatibility comment.
- No other production or test code depends on obtaining `TransportError` via
  `shared.tool_executor`.
- Existing test suite (including `tests/shared/test_tool_executor.py`) passes
  unchanged in behavior.
