# Correct Japanese, English, and Markdown chunk generation

## Priority
High

## Target files
- `scripts/rag/ingestion/chunk_japanese.py`
- `scripts/rag/ingestion/chunk_english.py`
- `scripts/rag/ingestion/chunk_splitter.py`
- `scripts/rag/ingestion/chunk_utils.py`

## Background
Japanese chunk generation mutates `self._result` while returning a separate local `result`, which can raise an error or lose output. English chunk generation removes stopwords before assigning the text to canonical `content`, so the original text is lost. Markdown handling selects heading mode before language handling and sends oversized Japanese sections to the English chunker.

## Problem
Improper state management and incorrect logic in chunk splitting leads to corrupted chunk content (lost original text, wrong linguistic processing, and potential runtime errors).

## Reason for change
To ensure that chunked segments accurately represent the source text and follow correct linguistic rules without side effects or data loss.

## Implementation intent
Fix the chunk generation logic in both Japanese and English mixins and the splitter to preserve original text, manage buffers correctly, and respect language-specific chunking requirements even when using Markdown headings.

## Implementation instructions
- In `ChunkJapaneseMixin._merge_ja_sentence_pairs`, stop mutating class-level `self._result` and instead return the accumulated results locally. Ensure `_emit_and_start_new` updates the local result list.
- In `ChunkEnglishMixin._chunk_english`, avoid removing stopwords from the text that is assigned to the canonical `content` field. Only use normalized versions for FTS if required.
- In `ChunkSplitter._chunk_markdown_by_heading`, when a Markdown section exceeds `md_snippet_max_chars`, delegate to the appropriate language-specific chunker (`_chunk_japanese` or `_chunk_english`) based on the document's language, rather than always calling `_chunk_english`.

## Acceptance criteria
- Japanese chunk generation returns correct segments without `AttributeError` and preserves original text.
- Consecutive document processing does not leak state between documents.
- Each Japanese original/normalized pair represents the same sentence set, including overlap.
- English `content` preserves the original selected text.
- Large Japanese Markdown sections are processed by the Japanese chunker.

## Tests
- Single and multiple Japanese chunks.
- Short Japanese tail.
- Overlap on and off.
- Consecutive documents.
- English negation and punctuation preservation.
- Small and large Japanese Markdown sections.
- English Markdown.
- Markdown with code blocks.
