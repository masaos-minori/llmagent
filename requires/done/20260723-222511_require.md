## Title

Ensure WAL checkpoint uses existing DB connection during shutdown

## Priority

Low

## Target files

- scripts/agent/repl.py
- scripts/agent/session.py

## Background

When shutting down, the agent performs a WAL checkpoint before closing database connections. However, it opens a new connection instead of using the existing one. If the existing session DB connection has been closed earlier, the WAL file may be in an inconsistent state.

## Problem

`repl.py:260-266`: The code opens a new connection via `SQLiteHelper("session").open(write_mode=True)` to perform the WAL checkpoint. This works fine if the existing connection is still open, but if the session connection was already closed (e.g., due to an error), the WAL file may be incomplete or corrupted.

## Reason for change

Using the existing session connection for the WAL checkpoint ensures data consistency. If the session connection is already closed, the checkpoint should be skipped rather than attempting to use a potentially stale WAL file.

## Implementation intent

Move the WAL checkpoint operation to occur before any potential session connection closure, or check whether the session connection is still available before performing the checkpoint.

## Implementation instructions

Option A — Check if session connection exists before checkpointing:

```python
# In repl.py ~line 259:
try:
    # Try to get the session connection from the context
    if self._ctx.session is not None and hasattr(self._ctx.session, 'db'):
        db = self._ctx.session.db
        db.checkpoint("TRUNCATE")
    else:
        # Session connection unavailable; skip checkpoint
        logger.debug("Skipping WAL checkpoint: session connection not available")
except sqlite3.Error as e:
    errors.append(("wal_checkpoint", f"{type(e).__name__}: {e}"))
    logger.warning("WAL checkpoint failed on shutdown: %s", e)
```

Option B — Move WAL checkpoint to session close method:

```python
# In session.py, AgentSession class:
def close(self):
    """Close the session and perform WAL checkpoint."""
    self.db.checkpoint("TRUNCATE")
    self.db.close()
```

Then remove the WAL checkpoint logic from `repl.py:260-266`.

Option C — Keep current approach but add verification:

```python
# In repl.py ~line 260:
try:
    with SQLiteHelper("session").open(write_mode=True) as db:
        # Verify WAL mode before checkpointing
        wal_mode = db.execute("PRAGMA journal_mode").fetchone()[0]
        if wal_mode != "wal":
            logger.warning("WAL checkpoint skipped: journal mode is %r", wal_mode)
        else:
            db.checkpoint("TRUNCATE")
            logger.info("WAL checkpoint completed on shutdown")
except sqlite3.Error as e:
    errors.append(("wal_checkpoint", f"{type(e).__name__}: {e}"))
    logger.warning("WAL checkpoint failed on shutdown: %s", e)
```

Option C is preferred because it's minimal and adds defensive checks without changing the architecture.
