# Introduce a typed schema (TypedDict) for MCP `TOOL_LIST` definitions across `scripts/mcp_servers/**/*_tools.py`

## Priority
Low

## Target files
- `scripts/mcp_servers/models.py` (new TypedDict definitions)
- `scripts/mcp_servers/git/git_tools.py`
- `scripts/mcp_servers/file/{read,write,delete}_tools.py`
- `scripts/mcp_servers/web_search/web_search_tools.py`
- Unknown: `scripts/mcp_servers/{mdq,github,cicd,rag_pipeline,shell}/*_tools.py`

## Background
Every `scripts/mcp_servers/**/*_tools.py` module types its `TOOL_LIST`/tool-property dicts as bare `dict[str, Any]`, which the Type Safety Rules discourage ("do not use `Any` ... unless needed"). This was raised independently in at least 3 separate refactor cycles (`git_tools.py`, `read_tools.py`, `write_tools.py`) as a cross-cutting, not single-file, improvement.

## Problem
`dict[str, Any]` provides no static guarantee about a tool schema's shape (required fields, value types), so a typo in a `TOOL_LIST` entry (e.g. misspelled key, wrong value type for `is_write`) would not be caught by `mypy`/`pyright`. A shared `TypedDict` definition would let every `*_tools.py` module benefit from static shape-checking, and would need to be decided once and applied uniformly rather than ad hoc per file.

## Reason for change
Static safety: eliminate `Any` usage in tool schema definitions so typos in tool names, descriptions, or field values are caught at type-check time. Cross-cutting nature means it should be decided once and applied uniformly.

## Implementation intent
Define `McpToolProperty`, `McpInputSchema`, and `McpTool` `TypedDict`s (exact shape to be derived from actual usage across all `*_tools.py` files, not guessed) in a shared location (e.g. `scripts/mcp_servers/models.py` or a new `scripts/mcp_servers/tool_schema_types.py`). Since `TypedDict` is erased at runtime, this should be a pure static-typing change with zero behavior impact — but because ~13+ modules share the same `TOOL_LIST` pattern (per `git_tools.py`'s Proposals note), the full `mypy`/`pyright` surface and the schema-contract test suite must be re-verified across every affected module, not just one.

## Implementation instructions
### Phase 1: Enumerate and derive
1. Run `rg -l "TOOL_LIST" scripts/mcp_servers/` to identify all modules with `TOOL_LIST` entries.
2. Read every `TOOL_LIST` entry across all `*_tools.py` modules to derive the actual field set (do not guess).
3. Document the derived field set in a comment above the TypedDict definitions.

### Phase 2: Define TypedDicts
1. Define `McpToolProperty`, `McpInputSchema`, and `McpTool` `TypedDict`s in one location (e.g. `scripts/mcp_servers/models.py` or a new `scripts/mcp_servers/tool_schema_types.py`).
2. Use `Required`/`NotRequired` annotations where appropriate based on which fields are present in all vs. some `TOOL_LIST` entries.

### Phase 3: Apply and verify
1. Update each `*_tools.py` module's `TOOL_LIST` annotation to use the new types.
2. Re-run `mypy`/`pyright` across the full `scripts/mcp_servers/` tree.
3. Verify `tests/mcp_servers/test_tool_schema_contract.py` and `tests/mcp_servers/test_mcp_tool_schema_exports.py` pass unchanged.
4. Perform before/after `TOOL_LIST` value-equality check per touched module.

## Acceptance criteria

- No `TOOL_LIST` value or JSON-schema shape changes (verify via before/after value-equality check per module).
