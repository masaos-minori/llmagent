# Add workflow definition file integrity validation

## Priority

Low

## Target Files

- `scripts/agent/orchestrator.py:135-140` — WorkflowLoader exception handling
- `scripts/agent/orchestrator.py:115-120` — _WORKFLOWS_DIR definition
- `scripts/agent/workflow/workflow_loader.py` — WorkflowLoader.load()

## Background

The orchestrator catches `(WorkflowLoadError, Exception)` when loading workflow definitions. While the WorkflowLoader only reads JSON files and does not execute arbitrary Python code, catching `Exception` is overly broad and could mask unexpected errors during startup.

## Problem

```python
try:
    self._workflow_def: WorkflowDef | None = WorkflowLoader().load()
except (WorkflowLoadError, Exception) as exc:
    raise RuntimeError(...)
```

Catching `Exception` means KeyboardInterrupt, SystemExit, and other critical exceptions would be caught and re-raised as RuntimeError, losing their original semantics.

## Reason for Change

Even though the attack scenario (malicious workflow file executing code) is not valid — WorkflowLoader only parses JSON and validates against a schema — catching `Exception` is still a bad practice that could hide bugs.

## Implementation Intent

Narrow the exception handler to only catch expected exceptions:

```python
try:
    self._workflow_def: WorkflowDef | None = WorkflowLoader().load()
except WorkflowLoadError as exc:
    raise RuntimeError(...)
except FileNotFoundError:
    raise RuntimeError(...)
```

Optionally add a whitelist of allowed workflow filenames to prevent loading arbitrary files.

## Implementation Instructions

1. Replace `except (WorkflowLoadError, Exception)` with specific exception types
2. Consider adding filename validation (whitelist or pattern matching)
3. Run tests to confirm no regressions

## Acceptance Criteria

- [ ] Only expected exceptions are caught
- [ ] KeyboardInterrupt/SystemExit propagate correctly
- [ ] No regressions in workflow loading behavior
