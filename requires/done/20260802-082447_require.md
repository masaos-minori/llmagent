# Replace docs/00_governance_04 Area Values list with a reference to docs/00_governance_01 In Scope

## Priority
Low

## Target files
- `docs/00_governance_04_known-issues-template.md` (Area Values section, currently lines 68-77)
- `docs/00_governance_01_documentation-governance.md` (In scope section, currently lines 16-27) — read-only reference for verification, not to be edited

## Background
`docs/00_governance_04_known-issues-template.md` defines a "Known Issue Entry Template" used across all areas of the design documentation set. Its "Area Values" section enumerates the 8 areas an issue's "Area" field may reference. Separately, `docs/00_governance_01_documentation-governance.md` defines the "In scope" section of the overall governance rules, which enumerates the same 8 areas that the governance rules apply to.

Verification against current repo content confirms both lists are present and identical, item-for-item, in the same order:
- Overview
- Deployment
- RAG
- MCP
- Agent
- EventBus
- Shared/DB
- Governance

## Problem
The 8-area list is maintained in two separate governance documents (00_governance_01 and 00_governance_04). This is a verbatim duplication of canonical information. If the set of areas changes in the future (an area added, renamed, or removed), both locations must be updated in lockstep, and there is no mechanism enforcing that — creating a risk of drift between the two lists.

## Reason for change
Duplicated canonical lists violate single-source-of-truth practice within the documentation governance set itself. Establishing `00_governance_01`'s "In scope" list as the single canonical source reduces future maintenance burden and eliminates the drift risk identified above.

## Implementation intent
Make `docs/00_governance_01_documentation-governance.md`'s "In scope" list the single canonical enumeration of the 8 areas. Replace `docs/00_governance_04_known-issues-template.md`'s independent "Area Values" enumeration with a short reference sentence pointing to `00_governance_01`'s "In scope" section, rather than re-listing the items. Do not change the actual set of areas, their names, or their order. Do not modify `00_governance_01` itself.

## Implementation instructions
1. In `docs/00_governance_04_known-issues-template.md`, locate the "## Area Values" section (the bulleted list of 8 areas).
2. Before editing, re-verify the two lists are still identical item-by-item at the time of implementation (in case either document was edited since this requirement was generated). If they differ in even one item, stop and report the discrepancy instead of silently reconciling — do not guess which list is correct.
3. Replace the bulleted enumeration under "## Area Values" with a single reference sentence indicating that the area values are defined by `00_governance_01`'s "In scope" list of 8 areas (e.g., a sentence such as "対象領域は `docs/00_governance_01_documentation-governance.md` のIn scopeで定義される8領域と同一。" or an equivalent English sentence, consistent with the surrounding document's language/style — check the document's existing language convention before choosing wording).
4. Keep the "## Area Values" heading itself in place so existing cross-references to that section still resolve.
5. Do not alter `docs/00_governance_01_documentation-governance.md` in any way.
6. Do not alter any other section of `docs/00_governance_04_known-issues-template.md` (e.g., Status Values, Type Values, Severity Values, Owner Values, Lifecycle, Migration Notes, Related Governance Documents).
7. Do not touch any other governance file beyond these two.

## Acceptance criteria
- `docs/00_governance_04_known-issues-template.md` no longer independently enumerates the 8 areas as a bulleted list.
- A single reference sentence in the "## Area Values" section points readers to `docs/00_governance_01_documentation-governance.md`'s "In scope" list as the canonical source.
- `docs/00_governance_01_documentation-governance.md`'s "In scope" list is unchanged (still the same 8 items, same order).
- No other section of either document is modified.
- No other governance file is modified.

## Tests
Not applicable — this is a documentation-only change. No automated tests are required. Verification is manual: confirm the reference sentence resolves correctly and that both documents remain internally consistent (e.g., cross-reference links in each document's "Related Governance Documents" section still function).
