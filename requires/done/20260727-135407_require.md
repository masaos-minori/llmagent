# Fix gen_rag_reference.py OPS_DOC target to match post-split docs structure

## Priority

Medium

## Target Files

- `tools/gen_rag_reference.py:22` — `OPS_DOC` constant points to `docs/03_rag_05_configuration_and_operations.md`, a file that no longer exists after the docs split

- `docs/03_rag_05_7-rag-index-consistency-checks.md:94-96` — same root-cause `AUTO-GENERATED` guard mismatch (tracked separately as NC-014 / `issues/20260727_25_issue.md`)

## Background

`docs/03_rag_05_configuration_and_operations.md` was previously a single document covering RAG configuration and operations. It has since been split into eight files: `03_rag_05_1-configuration-reference.md` through `03_rag_05_8-rag-mcp-internal-operations-direct-db-access.md`. `tools/gen_rag_reference.py` was never updated to reflect this split: its `OPS_DOC` constant (line 22) still points at the old, now-nonexistent file path.

Verified against current source (2026-07-27):
- `tools/gen_rag_reference.py:22` still reads `OPS_DOC = Path("docs/03_rag_05_configuration_and_operations.md")`.
- `docs/03_rag_05_configuration_and_operations.md` does not exist; `ls docs/ | grep 03_rag_05` shows only the eight split files (`03_rag_05_1` .. `03_rag_05_8`).
- `docs/03_rag_05_8-rag-mcp-internal-operations-direct-db-access.md:86` contains an explicit `Needs confirmation` note (NC-010 in `docs/00_governance_07_needs-confirmation-inventory.md`) stating the tool's output target does not follow the split and that the section is now maintained by hand.
- The same file's lines 84-115 hold `<!-- AUTO-GENERATED: gen_rag_reference.py config -->` / `<!-- END AUTO-GENERATED -->` guard markers wrapping CLI usage text for `crawler` and `chunk_splitter`, which is exactly the kind of content `generate_cli_help()` in the tool produces — but the tool would write it to a file that does not exist, so running the tool as-is would raise `FileNotFoundError` on `OPS_DOC.read_text()` rather than update anything.
- `docs/03_rag_05_7-rag-index-consistency-checks.md:94-96` has the identical guard-marker mismatch, tracked as NC-014 in a separate issue (`issues/20260727_25_issue.md`) with the same root cause; the issue explicitly recommends resolving NC-010 and NC-014 together.

The issue is confirmed as still reproducing in current source; this is not a stale/already-fixed report.

## Problem

`tools/gen_rag_reference.py` cannot regenerate any documentation content because its single `OPS_DOC` output target no longer exists post-split. The AUTO-GENERATED guard blocks now present in `docs/03_rag_05_8-...md` (and `docs/03_rag_05_7-...md`, per NC-014) are stale copies maintained by hand, with no automated tooling keeping them in sync with `config/crawler.toml`, `config/chunk_splitter.toml`, `config/ingester.toml`, and the `--help` output of `scripts/rag/ingestion/{crawler,chunk_splitter,ingester}.py`. There is an open policy question (NC-010) that has not been decided: should the tool be updated to target the split files, or should manual maintenance be formally adopted as the documented policy instead?

## Reason for Change

Leaving this undecided means the AUTO-GENERATED guard markers in the docs are misleading (they imply automated freshness that does not exist) and the tool itself is effectively dead code with respect to its write path. Resolving the open question — one way or the other — removes a source of documentation drift and clarifies whether contributors should ever run `gen_rag_reference.py` expecting it to update `docs/03_rag_05_*` files.

## Implementation Intent

This is a documentation/tooling-policy decision, not a behavior change to ship blindly. The intent is to:
1. Decide whether `gen_rag_reference.py` should be updated to write to the current split files (and if so, which content maps to which file), or whether manual upkeep should be the documented, permanent policy.
2. If automation is chosen, update `OPS_DOC` (or replace the single-path model with a mapping) so `generate_config_table()` output and `generate_cli_help()` output land in the correct split files, and keep the existing `GUARD_START`/`GUARD_END` marker mechanism so re-running the tool only replaces the guarded block.
3. Resolve this together with NC-014 (`docs/03_rag_05_7-rag-index-consistency-checks.md`), since both stem from the same stale `OPS_DOC` constant / docs-split root cause. A future work-plan/implementation cycle should treat NC-010 and NC-014 as one coordinated change, not two independent patches, to avoid inconsistent per-file decisions.
4. Whichever policy is chosen, the `Needs confirmation` notes in `docs/03_rag_05_8-rag-mcp-internal-operations-direct-db-access.md:86` and `docs/03_rag_05_7-rag-index-consistency-checks.md:94-96` must eventually be replaced with a factual statement of the adopted policy (in a later, documentation-editing workflow phase — not in this requirement-writing phase).
