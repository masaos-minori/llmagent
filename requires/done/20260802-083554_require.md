# Rewrite docs/00_governance_08 as a completion record instead of a stale in-progress migration plan

## Priority
Medium

## Target files
- `docs/00_governance_08_known-issues-migration-plan.md` (primary and only file to modify)

## Background
`docs/00_governance_08_known-issues-migration-plan.md` was written to plan a migration of five areas' Known Issues documents (RAG, MCP, Agent, EventBus, Shared/DB) to a common 17-field template. Verification against `git log` confirms commit `7b04065ce` ("docs: migrate all Known Issues documents to common template", 2026-07-23 18:58:49 +0900) performed this migration for all five areas in a single combined commit, and each of the five target files now contains a migration note with `- 移行日: 2026-07-23`. `docs/00_index.md` (lines 51-55) already lists all five Known Issues files. Despite this, the plan document has no `Status` field and is still written entirely in forward-looking, hypothetical-future language (e.g. Scope's "Excluded: Actually modifying any existing Known Issues documents during this planning phase", "Suggested Migration Order", "Acceptance Criteria for Future Migration", "Non-Goals").

## Problem
The document contradicts the current state of the repository: it presents a migration as not-yet-done when it was completed on 2026-07-23. This risks misleading readers into believing the described 5-area migration is still pending. It also duplicates a file listing (`## Target Files`) and a governance-document listing (`## Related Governance Documents`) that already exist canonically elsewhere (`docs/00_index.md`), and retains pre-migration format details and a proposed execution order that no longer have operational value in their current framing.

## Reason for change
A plan document describing already-completed work is stale and misleading. Keeping it in its current forward-looking framing conflicts with the documentation governance principle that documents should accurately reflect current state. The reusable parts of the document (Migration Policy, Priority Criteria) have ongoing value for future similar migrations, but only if reframed as general/reusable guidance rather than area-specific planning artifacts.

## Implementation intent
Convert the document from a forward-looking plan into a completion record for the 2026-07-23 migration, while preserving and generalizing the parts of it that remain useful as reusable guidance for future documentation migrations of a similar kind. Do not lose historical/substantive content — reframe tense and framing (planned → completed / reusable), rather than deleting content that still carries information value, except where the issue explicitly calls for deletion or replacement with a cross-reference.
