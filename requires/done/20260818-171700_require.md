# Title: [REQ] Complete EventBus Functional, Persistence, and Security Contract
# Priority: High
# Target files: scripts/eventbus/**/*.py, docs/eventbus/*.md, OpenAPI spec
# Background: The EventBus lacks a comprehensive and consistent contract covering delivery semantics, ordering, persistence, and security, leading to risks in workflow execution and reliability.
# Problem: 
# 1. Undefined delivery guarantees (ordering, duplicates, loss).
# 2. Ambiguous offset management (monotonicity, concurrency, `since_seq`).
# 3. Unclear ACK/NACK behaviors and error handling.
# 4. Undefined persistence authority and partial-failure behavior (DB vs JSONL).
# 5. Missing production-grade security model (authentication/authorization).
# Reason for change: To provide a reliable foundation for event-driven architecture, ensuring predictable behavior for clients and developers.
# Implementation intent: Formally define and implement the full EventBus lifecycle contract.
# Implementation instructions:
# 1. Define and implement delivery semantics (e.g., at-least-once), including ordering, retry, and duplication rules.
# 2. Formalize offset management, ensuring monotonicity and defining behavior for concurrent/out-of-order updates.
# 3. Specify the full state machine for ACK/NACK operations and their HTTP/response implications.
# 4. Establish the authoritative event store and define precise success/failure criteria for dual-persistence (DB + JSONL).
# 5. Implement a robust production security model (e.g., Bearer tokens, mTLS) and reflect it in the API specification.
# 6. Register any intentional implementation limitations as Known Issues.
# Acceptance criteria:
# - All delivery, offset, ACK/NACK, persistence, and security aspects are explicitly defined and implemented.
# - The system behaves exactly as specified under both normal and failure conditions (including partial persistence failures).
# - Production security constraints are enforced.
# - Automated tests validate the entire contract.
# Tests:
# - Comprehensive integration tests covering all defined edge cases (duplicates, reorders, failures, etc.).
# - Security penetration testing against the chosen model.
