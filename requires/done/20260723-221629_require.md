## Title

Persist memory injection failure state across sessions

## Priority

Medium

## Target files

- scripts/agent/startup.py
- scripts/agent/context.py

## Background

When memory injection fails during startup, the agent continues without memory functionality. However, the warning displayed to the user is only shown once at startup, and subsequent turns do not indicate that memory is unavailable.

## Problem

`startup.py:504-511`: When memory injection fails, a warning is logged and displayed. However, this warning is only shown once. If the user later tries to use memory-dependent features (e.g., asking about previous conversations), they won't understand why memory isn't working because the original warning has scrolled out of view.

## Reason for change

Users need persistent visibility into the fact that memory is disabled for their session. This prevents confusion when memory-dependent features don't work as expected.

## Implementation intent

Set a flag on the conversation state when memory injection fails, and check this flag before each turn to display a persistent warning if memory is disabled.

## Implementation instructions

Add a flag to `ConversationState`:

```python
# In context.py, ConversationState class:
class ConversationState:
    def __init__(self):
        ...
        self.memory_disabled: bool = False  # NEW
```

Set the flag in `StartupOrchestrator._setup_prompt()`:

```python
# In startup.py ~line 504:
except Exception as exc:
    logger.warning(...)
    self._view.write_warning(...)
    ctx.conv.memory_disabled = True  # NEW
```

Check the flag in the REPL loop and display a persistent warning:

```python
# In repl.py, _repl_loop():
if ctx.conv.memory_disabled:
    self._view.write_warning(
        f"{OutputTag.NON_FATAL} Memory is disabled for this session."
    )
```

Alternatively, display the warning only on the first tool call after memory injection failure rather than every turn:

```python
# In factory.py, ensure_ready() or tool execution path:
if ctx.conv.memory_disabled and not ctx.conv.memory_warning_shown:
    ctx.conv.memory_warning_shown = True
    self._view.write_warning(...)
```

The second approach (warn-on-first-use) is preferred to avoid spamming the user with warnings on every turn.

## Acceptance criteria

1. When memory injection fails, a flag is set indicating memory is disabled.
2. A warning is displayed to the user indicating memory is disabled for the session.
3. The warning is displayed only once per session (not on every turn).
4. Existing behavior for successful memory injection is unchanged.
5. No mypy errors introduced by the change.
6. All existing tests pass without modification.

3. Test: No warning when memory injection succeeds

   - Verify no warning is displayed
