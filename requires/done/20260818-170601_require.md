# Title: [REQ] Ensure monotonic consumer offset updates in EventBus
# Priority: High
# Target files: scripts/eventbus/offsets.py
# Background: In the current implementation of `write_offset()`, the sequence number is written to disk without comparison against the existing offset. A late or out-of-order acknowledgment carrying a smaller sequence rewinds the committed offset, causing duplicate consumption after a reconnect.
# Problem: `write_offset()` in `scripts/eventbus/offsets.py` performs unconditional overwriting of the offset file.
# Reason for change: To prevent unintended re-delivery of already processed messages caused by backward jumps in the committed offset.
# Implementation intent: Guarantee that a consumer's committed offset is non-decreasing.
# Implementation instructions:
# 1. Modify `write_offset` in `scripts/eventbus/offsets.py` to read the current offset using `read_offset` before writing.
# 2. Only update the offset if the new `seq` is strictly greater than the current one.
# 3. Add a regression test in `tests/eventbus/test_eventbus_offsets.py` that attempts to write a lower sequence number and asserts that the offset remains unchanged.
# Acceptance criteria:
# - `write_offset()` never lowers a consumer's stored offset.
# - Out-of-order acknowledgments do not trigger a backward jump in the offset.
# Tests:
# - Unit test for `write_offset` ensuring monotonicity.
