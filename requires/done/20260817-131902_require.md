# Reconcile `pyproject.toml` coverage `omit` list with current MCP server filenames

## Priority
Medium

## Target files
- `pyproject.toml` (`[tool.coverage.run] omit`)
- `rules/toolchain.md` or `skills/python-refactoring/workflow.md` (if they document the omit rationale)

## Background
`pyproject.toml`'s `[tool.coverage.run] omit` list contains stale glob entries referencing pre-rename `*_server.py` paths (`scripts/mcp_servers/{github,shell,web_search,rag_pipeline}/server.py`). These were renamed to `*_server.py` (e.g., `github_server.py`, `shell_server.py`) in commit `7ffa728ac` to resolve a `mcp` PyPI package-name collision. Only `scripts/mcp_servers/file/*_server.py` still matches its intended targets. As a result, these 4 files are silently included in coverage measurement, contradicting the comment above the list ("FastAPI server entry points ... not unit-testable").

## Problem
Stale omit entries cause inconsistent coverage instrumentation: 4 MCP server files are measured when the original intent was to omit them. This invalidates any prior assumption that these files are coverage-exempt.

## Reason for change
The omit list must reflect reality. Two valid directions:
1. **Re-omit**: Update the 4 stale glob entries to current filenames (`shell_server.py`, `github_server.py`, `web_search_server.py`, `rag_pipeline_server.py`) to restore the original "not unit-testable, omit them" intent.
2. **Keep measured**: Remove the stale entries entirely, documenting that these particular server files are unit-testable via `TestClient` (endpoint-level tests already exist for all 4).

## Implementation intent
Before deciding, run `uv run coverage run -m pytest tests/mcp_servers/` + `uv run coverage report` to check whether the existing coverage percentage for these 4 files is already reasonable. Given that TestClient tests exist for all 4 servers (shell, web_search, github, rag_pipeline), Direction 2 (keep measured) appears viable. If coverage is low (< 70%), consider Direction 1 instead.

## Implementation instructions
1. Run `uv run coverage run -m pytest tests/mcp_servers/` + `uv run coverage report` to assess current coverage for the 4 affected files.
2. Decide direction based on findings:
   - If coverage is reasonable (≥ 70%): choose Direction 2 — remove the 4 stale entries from `pyproject.toml`'s omit list.
   - If coverage is low (< 70%): choose Direction 1 — update the 4 entries to match current filenames.
3. Update the inline comment above the omit list if Direction 2 is chosen (it would no longer be accurate for these 4 files).
4. Verify no stale paths remain: `for p in <omit-list-entries>; do ls $p 2>/dev/null || echo "STALE: $p"; done`.

## Acceptance criteria
- `pyproject.toml`'s omit list contains no path that fails to match any file on disk.
- Repo-wide `coverage report` reflects the intended, chosen behavior for these 4 files.
- Inline comment above the omit list accurately describes the rationale for the chosen direction.

## Tests
Run `uv run coverage run -m pytest tests/` + `uv run coverage report` before/after; no test behavior changes, only coverage instrumentation scope.
