# Title: [REQ] Standardize Document Templates, Minimal Behavioral Contracts, and Diagrams
# Priority: Low
# Target files: docs/**/*.md, routing.md, AGENTS.md
# Background: Current document structures vary widely. Many specifications lack essential design information (e.g., responsibilities, side effects, failure behavior, concurrency, security boundaries), effectively acting as mere file indexes. Additionally, complex ASCII diagrams are fragile and difficult to maintain.
# Problem: 
# 1. Lack of consistent document structure makes it hard to validate and create new documentation.
# 2. Insufficient "behavioral contracts" in specifications lead to incomplete design understanding.
# 3. Fragile ASCII diagrams are prone to corruption and are difficult to read/maintain.
# Reason for change: To improve documentation consistency, ensure critical design information is captured, and provide robust, readable architectural visualizations.
# Implementation intent: Establish reusable templates, define minimum requirements for specification content, and migrate complex diagrams to more robust formats.
# Implementation instructions:
# 1. **Document Templating**: Create standard templates for all document classes: Governance, Guide, Specification, Reference, Operations, Note, and Known Issues. Templates must include required front matter, mandatory/optional sections, and conventions for evidence and related documents.
# 2. **Minimum Behavioral Contracts**: For public or critical components, supplement "refer to source code" statements with explicit definitions of: Responsibility, Input/Output contracts, Side effects, Failure behavior, Idempotency, Concurrency constraints, and Security boundaries.
# 3. **Diagram Modernization**: Convert complex ASCII diagrams into Mermaid diagrams or other approved, maintained image assets. Focus on key flows: process architecture, RAG ingestion/query flows, workflow approvals, and EventBus recovery. Ensure accessibility by providing text alternatives.
# Acceptance criteria:
# - Reusable templates exist and are used for all new documentation.
# - All document classes have defined required/optional sections and metadata.
# - Critical components include documented minimal behavioral contracts (responsibility, side effects, etc.).
# - Key architectural diagrams are migrated to Mermaid or approved image formats and render correctly.
# - Accessible text alternatives are provided for all visual diagrams.
# - Documentation guidance explicitly points to these templates.
# Tests:
# - Verification that sample documents adhere to the new templates.
# - Audit of existing specifications to ensure they meet the minimum behavioral contract requirements.
# - Visual verification of diagram rendering in GitHub/markdown viewers.
