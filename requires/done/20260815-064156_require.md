## Background
ruff reports BLE001 on `tools/fix_d205.py:128` where a bare `except Exception:` handler
catches all exceptions from `Path.read_text()`. The broad catch is intentional because
`Path.read_text()` can raise OS-level errors (PermissionError, FileNotFoundError, etc.) and
encoding errors (UnicodeDecodeError). The code handles all of them uniformly by skipping the
file and continuing to the next one.

## Problem
Pre-commit fails with:
```
BLE001 Do not catch blind exception: `Exception`
   --> tools/fix_d205.py:128:16
```

## Reason for change
The bare exception handler masks unexpected errors per ruff's static analysis rules. While the
current behavior is correct (all OS-level and encoding errors result in skipping the file), the
pattern violates the principle of explicit exception handling.

## Implementation intent
Narrow the exception handler to `(OSError, UnicodeDecodeError)` which covers:
- `OSError` and its subclasses (PermissionError, FileNotFoundError, IsADirectoryError, etc.)
- `UnicodeDecodeError` (ValueError subclass — Path.read_text raises this when encoding fails)

This reduces the blast radius while preserving correct behavior for all expected failure modes.
Using `except OSError` alone would leave `UnicodeDecodeError` unhandled.

## Implementation instructions
1. Read `tools/fix_d205.py` around line 128 to confirm the exact context.
2. Replace `except Exception:` with `except (OSError, UnicodeDecodeError):` on line 128.
3. Run `uv run ruff check --select=BLE001 tools/fix_d205.py` to verify the error is resolved.
4. Run `uv run pytest` to ensure no behavioral regression.
