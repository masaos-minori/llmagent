# Unexpected keys silently discarded during HistoryMessage conversion

## Priority

Low

## Target Files

- `scripts/agent/repl.py` — AgentREPL._persist_session_memories()
- `scripts/agent/memory/models.py` — HistoryMessage

## Background

`_persist_session_memories()` converts conversation history dicts to `HistoryMessage` dataclass instances before calling `on_session_stop()`.

## Problem

In `repl.py:120-123`:

```python
history = [
    HistoryMessage(role=m["role"], content=m.get("content") or "")
    for m in ctx.conv.history
]
```

This explicitly passes only `role` and `content` to the `HistoryMessage` constructor. If any message dict contains additional keys (e.g., `_ephemeral`, `_memory_injected`, or future fields), they are silently discarded without validation or warning.

While Python's dataclass constructor does not raise TypeError for extra keyword arguments, this silent discarding means:
- Future schema changes to message dicts will go unnoticed
- Debugging becomes harder when unexpected keys are silently dropped
- No audit trail of what was discarded

## Reason for Change

Silent data loss during conversion makes debugging difficult and risks missing important diagnostic information about message structure changes.

## Implementation Intent

Add validation to detect and report unexpected keys during the dict-to-dataclass conversion. Either warn on unexpected keys or raise an error to make the failure visible.

## Implementation Instructions

1. After extracting `role` and `content`, check for unexpected keys:
   ```python
   expected_keys = {"role", "content"}
   extra_keys = set(m.keys()) - expected_keys
   if extra_keys:
       logger.warning("Unexpected keys in history message: %s", extra_keys)
   ```
2. Optionally, pass the extra keys as metadata to `HistoryMessage` if the dataclass supports it.
3. Consider adding a similar check in the reverse direction (HistoryMessage → dict).

## Acceptance Criteria

- [ ] Unexpected keys trigger a warning or error during conversion
- [ ] No silent data loss during dict-to-dataclass transformation
- [ ] Validation occurs before the conversion completes

## Tests

- Unit test: create a message dict with extra keys; verify warning is emitted
- Integration test: run session stop with messages containing unexpected keys; verify no silent discard
