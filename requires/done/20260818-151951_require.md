# Fix `replay_ceil` possibly-unbound pyright finding in subscribe_route.py

## Priority
Medium

## Target files
- scripts/eventbus/subscribe_route.py

## Background
A lint/typecheck sweep (`uv run pyright scripts/`) found one outstanding error while `mypy`
and `ruff check` were both clean: `"replay_ceil" is possibly unbound
(reportPossiblyUnboundVariable)` in `scripts/eventbus/subscribe_route.py`'s SSE generator, at
the `logger.info(...)` call inside the `except asyncio.CancelledError` handler. Because this
file lives under `scripts/eventbus/`, AGENTS.md Global Rule 8 forbids implementing any fix
without explicit maintainer sign-off — debug/investigation is permitted, implementation is not.
This requirement records the verified finding so a future, explicitly-approved implementation
cycle can act on it without re-investigating.

## Problem
In the `_sse_gen()` generator (function starting around line 40s, replay/live-delivery logic
around lines 55-88):
- `replay_ceil = start_seq` is assigned only after `rows = await run_with_db_lock(_fetch_replay)`
  completes successfully (current line 61-62).
- If `asyncio.CancelledError` is raised before that line executes, `replay_ceil` does not yet
  exist as a local variable.
- The `except asyncio.CancelledError` handler (current line 82) already guards this at runtime
  with `replay_ceil if locals().get("replay_ceil") is not None else start_seq`, which correctly
  falls back to `start_seq` because `locals()` is evaluated dynamically.
- `pyright` cannot follow the `locals().get(...)` guard and still flags the direct `replay_ceil`
  reference in the ternary's true-branch as possibly unbound (`reportPossiblyUnboundVariable`).
- Re-verified against current source on 2026-08-18: `uv run pyright
  scripts/eventbus/subscribe_route.py` still reports exactly this one error; `mypy` and `ruff`
  remain clean on the same file.
- No functional/runtime risk currently exists — the logged value is correct in every case. This
  is purely a static-analysis gap between `pyright`'s flow analysis and the `locals()`-based
  runtime guard.

## Reason for change
`rules/toolchain.md` treats `pyright` as a required cross-validation type checker alongside
`mypy`, and the completion checklist expects a clean run across `scripts/`. Leaving a known,
unaddressed `pyright` error creates a CI-consistency gap and makes it harder to notice genuinely
new pyright regressions in future changes, since this one is always present in the baseline.

## Implementation intent
Initialize `replay_ceil = start_seq` before the code path that can raise `CancelledError` (i.e.
before or immediately after the `await run_with_db_lock(_fetch_replay)` call), so the name is
always bound on every control-flow path. Once always bound, simplify the except-handler log call
to reference `replay_ceil` directly and remove the `locals().get(...)` workaround. This is a
minimal, behavior-preserving change: the initialized value is already `start_seq`, matching the
value the current fallback produces in the unbound case. Do not alter replay/live-delivery
semantics, SSE payload format, or subscribe/unsubscribe lifecycle.

## Implementation instructions
1. In `scripts/eventbus/subscribe_route.py`, move/add `replay_ceil = start_seq` so it executes
   unconditionally before the `try` block's `await run_with_db_lock(_fetch_replay)` call (or
   at the earliest point after `start_seq` is known), ensuring `replay_ceil` is always bound
   before the `except asyncio.CancelledError` handler can reference it.
2. Simplify the `logger.info(...)` call in the `except asyncio.CancelledError` handler to
   reference `replay_ceil` directly, removing the `locals().get("replay_ceil") is not None else
   start_seq` guard.
3. Run `uv run pyright scripts/eventbus/subscribe_route.py` and confirm 0 errors.
4. Run `uv run mypy scripts/` and `uv run ruff check scripts/` and confirm no regressions.
5. Locate and run the eventbus subscribe/SSE test module (`rg -l subscribe_route tests/`) to
   confirm the logged `seq` value is unchanged for both the "replay happened" and "cancelled
   before any replay row" cases.
6. This is eventbus-related implementation and requires explicit maintainer sign-off per
   AGENTS.md Global Rule 8 and `rules/coding.md` §Explicit sign-off gates (e.g. a comment on
   this requirement or the corresponding plan entry) before Steps 1-2 are carried out.
