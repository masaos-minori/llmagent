# Add cross-reference from §2.2 Workflow artifact fail-closed design to the failure-mode table in part2

## Priority
Low

## Target files
- `docs/02_deployment-part1.md` (§2.2 "Deploying scripts", specifically the "Workflow artifact responsibilities (deploy.sh)" subsection, lines ~92-100)

## Background
`docs/02_deployment-part1.md` §2.2's "Workflow artifact responsibilities (deploy.sh)" subsection documents the fail-closed design of the workflow deployment artifact: `deploy.sh` checks that `config/workflows/default.json` exists (aborting before any copy if missing), validates the workflow definition via `python -m agent.workflow.validate`, copies it to `/opt/llm/config/workflows/`, and verifies a SHA256 checksum match between source and deployed copies, aborting on mismatch. This was re-verified against the current `deploy/deploy.sh` and is accurate:
- Line 17-19: existence check, `[FATAL] Missing required workflow definition...` + "does not support workflow-disabled mode"
- Line 24-26: validation via `python -m agent.workflow.validate`, `[FATAL] Workflow definition failed validation...`
- Line 103-110: copy, then checksum comparison, `[FATAL] Deployed workflow definition checksum does not match source...`

`docs/02_deployment-part2.md` §3.3 "失敗モード" (lines 52-61) contains a table mapping each of these `[FATAL]` symptom strings (e.g. `[FATAL] Missing required workflow definition`, `[FATAL] Invalid workflow definition`, `[FATAL] Checksum does not match source`) to the failing script and the remediation action, plus a further pointer to a detailed runbook.

## Problem
§2.2 in part1 fully and accurately describes the fail-closed behavior but contains no pointer to where a reader can find the specific exit/log strings and remediation steps for these failure conditions (the table in part2 §3.3). A reader hitting one of these failures while reading part1 has no in-document lead to the failure-mode table and must search separately.

## Reason for change
Readers troubleshooting a workflow deployment failure while reading §2.2 should be able to navigate directly to the failure-mode table instead of having to search across documents. This is a low-cost, low-risk documentation improvement that improves navigability without altering any existing accurate content.

Do not rewrite, restructure, or otherwise alter the existing content of this subsection — it has already been verified as accurate and complete.
