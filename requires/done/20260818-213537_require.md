# DiagnosticStore: configurable sensitive_fields, decrypt-on-fetch, and accurate docstring

## Priority
Medium

## Background
`DiagnosticsConfig` already declares a `sensitive_fields: frozenset[str]` field (default
`{"artifacts", "rag_stage_outcomes"}`) intended to let operators extend the set of payload
keys redacted by `DiagnosticStore._filter_sensitive_fields()`. `DiagnosticStore.save()` also
supports an `encrypt=True` path that Fernet-encrypts row content when an `encryption_key` is
configured.

## Reason for change
The data-hygiene and observability-correctness risk originally described here (silent
no-op redaction config, unreadable encrypted rows) is already closed in the source code by
commit `fa824caa27f`. What remains is: (a) a documentation gap — operators reading
`docs/05_agent_08_04_configuration-mcp-approval-obs.md` still have no way to learn that
`sensitive_fields` is configurable — and (b) two automated-test gaps that leave the
already-fixed behavior unverified by the test suite (a future refactor could silently
regress either path without a failing test to catch it).

## Implementation intent
- No source changes are required to `_build_diagnostics_config()`,
  `DiagnosticStore._load_diagnostics_config()`, `DiagnosticStore.fetch()`, or the
  `_filter_sensitive_fields()` docstring — all four are already correct in the current
  source (re-verified 2026-08-19; see Problem section above). The original Option A/B
  decision is moot: Option A (decrypt-on-fetch) is what's already implemented.
- Add `sensitive_fields` to the DiagnosticsConfig section of
  `docs/05_agent_08_04_configuration-mcp-approval-obs.md`, describing its purpose (additive
  redaction field list) without embedding the concrete default value in the doc.
- Add the two missing unit tests identified during verification (see Tests section below)
  so the already-fixed behavior is actually covered by the test suite.

## Implementation instructions
1. Update `docs/05_agent_08_04_configuration-mcp-approval-obs.md`'s 診断設定 (DiagnosticsConfig)
   section to document `sensitive_fields` alongside `encryption_key` and `retention_days`,

2. Add a unit test in `tests/agent/test_config_builders.py`'s `TestBuildDiagnosticsConfig`

   `DiagnosticStore._load_diagnostics_config()` in `tests/agent/test_diagnostic_store.py`.
3. Add a unit test in `tests/agent/test_diagnostic_store.py` (or
   `tests/agent/test_diagnostic_store_security.py`) covering the encrypted round trip through
   the actual public API: call `store.save(session_id, kind, content, encrypt=True)` with a
   configured `encryption_key`, then call `store.fetch(session_id)` and assert the returned
   `content` equals the original plaintext — not a manual `Fernet(...).decrypt(...)` call
   inside the test, since that would not exercise the decrypt branch inside `fetch()` itself.
