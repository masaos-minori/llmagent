# Reconcile Needs-Confirmation required-field definitions between docs/00_governance_03 and docs/00_governance_07

## Priority
High

## Target files
- `docs/00_governance_03_evidence-labels.md` (section "Needs Confirmation Required Fields")
- `docs/00_governance_07_needs-confirmation-inventory.md` (sections "Inventory Entry Fields" and "Extraction Process")

## Background
`docs/00_governance_03_evidence-labels.md` defines the "Needs confirmation" evidence label and states that any use of it "must have required fields" — it enumerates exactly six: Question, Evidence, Impact, Required Action, Target Document, Review Timing.

`docs/00_governance_07_needs-confirmation-inventory.md` is the operational inventory where NC-XXX entries are actually recorded. Its "Inventory Entry Fields" section states entries "must contain the following fifteen fields" and lists: ID, Source File, Section, Line Number, Question, Evidence, Impact, Required Action, Status, Assigned To, Last Reviewed, Priority, Related NC, Resolution Target, Blocking.

## Problem
Verified against current file content (both docs read in full):

1. **03 vs 07 field-set mismatch (the core issue).** Of 03's six required fields, only four (Question, Evidence, Impact, Required Action) appear in 07 under the same name. The remaining two — "Target Document" ("Where should the result be recorded?") and "Review Timing" ("When should this be reviewed?") — have no field in 07 that is clearly the same thing:
   - "Source File" in 07 records where the *statement being questioned* lives, not "where should the result be recorded" — these are different pieces of information.
   - "Last Reviewed" in 07 is a backward-looking date (when it was last reviewed), while 03's "Review Timing" is forward-looking (when it *should* be reviewed next) — these are semantically opposite, not equivalent.
   - 07 additionally defines nine fields with no counterpart in 03 at all (ID, Section, Line Number, Status, Assigned To, Priority, Related NC, Resolution Target, Blocking).
   - There is no explicit mapping/cross-reference between the two documents' field lists anywhere in either file.

2. **Additional internal inconsistency found in 07 itself while verifying (same field-count problem, one level deeper).** 07's "Inventory Entry Fields" section says entries "must contain the following fifteen fields" and lists 15, but its own "Extraction Process" section step 3 says to "Populate all eleven required fields based on the context" — an internal contradiction about how many fields are actually required. This is in the same document under review and directly relevant to establishing 07 as a stable canonical source, so it is reported here as supporting evidence; fixing it is folded into the same reconciliation work (see Implementation instructions).

3. Existing NC-001 through NC-017 entries in 07 are inconsistent with each other in practice: some include all of Priority/Resolution Target/Blocking/Related NC (e.g., NC-003, NC-008, NC-010, NC-014), most omit them, confirming the field template is not being applied uniformly today.

## Reason for change
Without one clear source of truth for what fields a "Needs confirmation" entry must have, future entries will keep being recorded inconsistently (as the existing NC-001..017 entries already demonstrate), undermining 07's stated purpose of being a centralized, trackable inventory. The mismatch has not been resolved by any change since the issue was filed — both documents were re-read and the discrepancy is confirmed present in current content.

## Implementation intent
Pick one document as the canonical source of the Needs-Confirmation field definition and make the other reference/defer to it rather than maintaining a second, independent list. Per the source issue's suggestion, 07 (the operational inventory in active use, with 17 real entries) is the natural candidate for canonical status, since rewriting 17 existing entries to match a 6-field model would lose operationally useful tracking fields (Status, Assigned To, Priority, etc.) that 07 already depends on. 03 should then be updated to either (a) reference 07's field list directly instead of restating a divergent one, or (b) keep its 6 fields as a conceptual minimum but explicitly note which 07 fields satisfy each one, with an explicit mapping for the two fields that don't cleanly correspond (Target Document, Review Timing). Do not invent new fields or remove tracking fields from 07 that are already populated in existing NC entries.

If, when doing this work, it is not clear from context which document should be authoritative, do not decide unilaterally — register the ambiguity as a new Needs Confirmation entry in 07 itself (following 07's own field template) instead of guessing, per the issue's explicit instruction.

## Implementation instructions
1. In `docs/00_governance_07_needs-confirmation-inventory.md`, resolve the internal "fifteen fields" vs "eleven required fields" contradiction first (Inventory Entry Fields section vs Extraction Process step 3) — determine the actual intended count/list and make both sections agree.
2. Decide the canonical document for Needs-Confirmation field definitions (07 recommended per above, unless context clearly indicates otherwise).
3. In the non-canonical document, replace or annotate the field list so it no longer independently diverges:
   - If 03 stays non-canonical: keep its 6-field conceptual list if desired, but add an explicit mapping table/note showing which 07 field(s) satisfy each of 03's six fields, including how "Target Document" and "Review Timing" map (or do not map, if intentionally different) to 07's "Source File" and "Last Reviewed"/"Resolution Target"/etc.
   - If 07 stays non-canonical (unlikely per the recommendation, but possible depending on the decision): update 07's field list to match 03's six named fields directly, and separately document the extra operational fields (Status, Assigned To, Priority, Related NC, Resolution Target, Blocking, ID, Section, Line Number) as inventory-specific additions layered on top of the canonical set.
4. Add a short cross-reference note in each document pointing at the other's field-definition section, so a reader landing on either doc can find the authoritative list.
5. Do not rewrite the content of existing NC-001 through NC-017 entries beyond aligning field names/labels if the canonical decision requires a rename; do not change the Evidence Label spectrum in 03 (the seven labels themselves are out of scope).
6. If the canonical-document decision cannot be made confidently from available context, stop and add a new Needs Confirmation entry to 07 (using 07's own — now reconciled — field template) describing the undecided question, rather than picking one arbitrarily.
