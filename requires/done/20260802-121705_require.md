# Add sqlite-vec path cross-reference note to docs and fix build_sqlite_vec.sh's incorrect "common.toml" reference

## Priority
Medium

## Target files
- `docs/02_deployment-part1.md` (§2.1 "Building sqlite-vec (first time only)")
- `deploy/build_sqlite_vec.sh` (comment at line 41 and echo message at line 48)

## Background
`docs/02_deployment-part1.md` §2.1 states (line 75): "Install path: `/opt/llm/sqlite-vec/vec0.so` (must match `sqlite_vec_so` in `agent.toml`)". This is confirmed correct against the actual config file `config/agent.toml`, which defines the `sqlite_vec_so` key. There is no `config/common.toml` file in the repository.

## Problem
`deploy/build_sqlite_vec.sh` references a nonexistent `common.toml` file in two places instead of the correct `agent.toml`:
- Line 41 (comment): `# common.toml: sqlite_vec_so = "/opt/llm/sqlite-vec/vec0.so"`
- Line 48 (echo message shown to the operator running the script): `echo "  → config/common.toml の sqlite_vec_so と一致しています"`

Both instances are incorrect and inconsistent with the documentation's own (correct) description in `docs/02_deployment-part1.md` §2.1. Additionally, the documentation currently has no note cross-referencing this discrepancy, so a reader has no warning that the script's wording is wrong.

## Reason for change
This is a confirmed inconsistency between the documentation (correct) and the script's comment/output text (incorrect). Left unaddressed, a future reader or operator following the script's own printed output could be misled into searching for a nonexistent `config/common.toml`, wasting time. The fix is low-risk (text-only, no behavioral change) and improves maintainability and operator trust in the deploy tooling's messages.

## Implementation intent
1. In `docs/02_deployment-part1.md` §2.1, add a clarifying note next to the existing install-path sentence stating that the placement path must match `config/agent.toml`'s `sqlite_vec_so` key (this is the correct, authoritative file), and that `deploy/build_sqlite_vec.sh` contains an outdated/incorrect reference to a nonexistent `common.toml` (call out that this has been fixed, once the script is corrected in the same change).
2. In `deploy/build_sqlite_vec.sh`, replace both incorrect occurrences of `common.toml` with `agent.toml`:
   - The comment on line 41.
   - The echo string on line 48 (operator-facing output).
   Do not change any other behavior, logic, or formatting of the script.

## Implementation instructions
- Edit `deploy/build_sqlite_vec.sh`:
  - Line 41: change `# common.toml: sqlite_vec_so = "/opt/llm/sqlite-vec/vec0.so"` to reference `agent.toml` instead of `common.toml`.
  - Line 48: change `echo "  → config/common.toml の sqlite_vec_so と一致しています"` to reference `config/agent.toml` instead of `config/common.toml`.
  - Make no other edits to this file (comment/output text only; no functional/behavioral change).
- Edit `docs/02_deployment-part1.md` §2.1: add a sentence after (or appended to) the existing install-path line (currently line 75) clarifying that the placement path must match `config/agent.toml`'s `sqlite_vec_so` key (agent.toml is authoritative), and noting that `deploy/build_sqlite_vec.sh` previously referenced a nonexistent `common.toml` in its comment/output, which has been corrected. Match the existing documentation's language/tone and, where the surrounding doc uses Japanese, keep the added note in Japanese (e.g., along the lines of: "vec0.so の配置パスは `config/agent.toml` の `sqlite_vec_so` と一致させること(agent.tomlが正)。なお `deploy/build_sqlite_vec.sh` のコメント/出力メッセージは古い記述(`common.toml`)を参照していたが、修正済みである。").
- Do not introduce or reference `config/common.toml` anywhere; it does not exist.

- No functional or behavioral change to `deploy/build_sqlite_vec.sh` beyond the text of the comment and echo string.
