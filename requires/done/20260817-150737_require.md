# Evaluate hoisting `shell_server.py`'s local `shutil` import in `health()` to module level

## Priority
Low

## Target files
- `scripts/mcp_servers/shell/shell_server.py` (`health()`)
- `scripts/mcp_servers/git/git_server.py` (sibling convention for comparison)

## Background
`scripts/mcp_servers/shell/shell_server.py`'s `health()` endpoint does a local `import shutil as _shutil` wrapped in `try/except (ImportError, OSError)`, letting the endpoint degrade gracefully (return a degraded health status) if the import were ever to fail. Sibling file `scripts/mcp_servers/git/git_server.py` imports `shutil` at module (top) level instead.

## Problem
Inconsistent import conventions between sibling modules. The graceful-degradation behavior for a `shutil` import failure is questionable — it's an unrealistic edge case that would only occur if the stdlib itself failed to load, which should never happen in practice.

## Reason for change
Consistency: align with the sibling `git_server.py`'s top-level-import convention. Also removes unnecessary defensive boilerplate that adds complexity without meaningful benefit.

## Implementation intent
Confirm whether the graceful-degradation behavior for a `shutil` import failure is actually meaningful (i.e., has this ever been observed, or is it purely defensive boilerplate copied from elsewhere?). If it's purely defensive and inconsistent with the sibling `git_server.py`'s top-level-import convention, hoist it for consistency and document the (accepted) change in startup-failure behavior. If the graceful-degradation behavior is intentional, leave it and close this issue as "no action, confirmed intentional."

## Implementation instructions
### Phase 1: Investigate
1. Check whether any other `*_server.py` health-check import pattern is inconsistent in the same way (local vs. top-level `shutil`/similar stdlib import), to decide if this should be a repo-wide convention fix or a one-off.
2. Confirm that no caller relies on the degraded health response when `shutil` fails to import (this is purely theoretical — `shutil` is a stdlib module that cannot fail to import under normal circumstances).

### Phase 2: Decide and implement
**Option A: Hoist the import (recommended)**
1. Move `import shutil` to module level (remove the `try/except`).
2. Add a characterization test for `health()` when `shutil.which` returns `None` (the realistic degradation case, distinct from the unrealistic `ImportError` case).
3. Document the accepted change in startup-failure behavior.

**Option B: Leave as-is (if graceful degradation is intentional)**
1. Close this issue as "no action, confirmed intentional."
2. Document why the graceful-degradation behavior is needed despite being theoretically impossible.

## Acceptance criteria
Either:
- The import is hoisted, the `try/except (ImportError, OSError)` around the import itself is removed, and a characterization test for the realistic `shutil.which() is None` case is added and passes; or
- The current behavior is confirmed intentional and documented, with no code change.

## Tests
`tests/mcp_servers/shell/test_shell_server_endpoints.py` (new 2026-08-16 characterization tests) plus a new test for `shutil.which() is None` if the import is hoisted.
