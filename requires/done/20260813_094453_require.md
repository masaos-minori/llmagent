# Align ETag freshness handling with transaction ownership

## Priority
Medium

## Target files
- `scripts/rag/ingestion/etag_manager.py`
- `scripts/rag/ingestion/document_manager.py`
- `scripts/rag/ingestion/ingester.py`
- ETag tests

## Background
Currently, `ETagManager` manages document freshness by performing lexical string comparisons on timestamp strings and, crucially, executing `commit()` operations within its internal helper methods. This violates the principle of transaction ownership, as it prevents callers (like the ingestion pipeline) from managing atomicity across multiple database operations.

## Problem
1. Lexical comparison of timestamps is unreliable and depends on perfectly consistent ISO-8601 formatting.
2. Internal calls to `commit()` break the transaction boundaries established by higher-level services, making rollbacks impossible for multi-step operations.
3. Inability to handle invalid timestamp formats gracefully during freshness checks.

## Reason for change
To ensure robust transaction management and reliable freshness ordering by moving commit responsibility to the service layer and using proper datetime parsing.

## Implementation intent
Refactor `ETagManager` to remove internal `commit()` calls and use timezone-aware UTC datetimes for all freshness comparisons.

## Implementation instructions
1. Update `ETagManager` to accept a `db` instance but do NOT call `commit()` or `rollback()` itself.
2. Refactor `_is_stale_update` to parse both the incoming `new_fetched_at` and the stored `fetched_at` into timezone-aware UTC `datetime` objects before comparing them.
3. Define explicit behavior for handling invalid or malformed timestamp strings (e.g., logging an error and treating them as non-stale or rejecting the update).
4. Ensure that `ETagManager` can participate in an existing transaction managed by the caller (e.g., `DocumentManager` or `Ingester`).
5. Remove any direct commits from `_update_with_freshness` and `_update_null_fill`.

## Acceptance criteria
- Document metadata updates are part of the caller's transaction and can be rolled back.
- Freshness is correctly determined using proper datetime comparison rather than lexical string comparison.
- Invalid timestamps follow the documented reject or fallback policy.
- Older input cannot overwrite newer metadata.

## Tests
- Test with older, equal, and newer timestamps.
- Test with timezone-offset equivalence.
- Test with missing or invalid timestamps.
- Test rollback after an `ETagManager` update operation.
