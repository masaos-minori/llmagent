# Title: [REQ] Canonicalize MCP Runtime Lifecycle and Automate Service Inventory
# Priority: High
# Target files: docs/**/*.md, scripts/mcp_servers/*.py, config files
# Background: Inconsistent documentation regarding MCP server lifecycle (e.g., agent-managed vs. external) and manual maintenance of service inventories leads to information drift and operational risks.
# Problem: 
# 1. Ambiguous definitions for startup modes (`none`, `persistent`, `subprocess`).
# 2. Manually maintained service inventories diverge from actual configurations.
# 3. Conflicting descriptions of process ownership, health checks, and tool discovery across different documentation areas.
# Reason for change: To ensure consistent, accurate, and automated documentation of the MCP ecosystem.
# Implementation intent: Standardize lifecycle definitions and automate the generation of the active service inventory.
# Implementation instructions:
# 1. Formally define the three startup modes (`none`, `persistent`, `subprocess`) including their properties (ownership, health checks, tool discovery, routing, etc.).
# 2. Reconcile all existing documentation to use these standardized definitions.
# 3. Implement an automation mechanism to generate the active MCP service inventory from the current configuration.
# 4. Integrate stale-output detection into the CI pipeline to detect outdated generated documentation.
# 5. Replace all manual service value tables with the generated output.
# Acceptance criteria:
# - A single canonical definition for all MCP startup modes exists.
# - All relevant documentation uses the standardized lifecycle terminology.
# - The MCP service inventory is automatically generated and reflects the current configuration.
# - CI detects and flags stale generated documentation.
# Tests:
# - Verification that generated inventory matches active configuration.
# - Test that changing a configuration value triggers a CI warning for stale documentation.
