# Add design rationale to the identity-vs-truthiness note in docs/03_rag_03_01_query_pipeline-overview.md

## Priority
Low

## Target files
- `docs/03_rag_03_01_query_pipeline-overview.md` (specifically the "identity vs truthiness" note, currently at line 62)

## Background
`docs/03_rag_03_01_query_pipeline-overview.md` documents the fallback chain of `RagPipeline.augment()` (`scripts/rag/pipeline.py`). One note, labeled "identity vs truthiness (Explicit in code)", explains that the HTTP and refiner stages use `is not None` identity checks rather than truthiness checks, so that an empty string `""` returned by HTTP mode is treated as a valid result while only an explicit `None` triggers fallback. This description was verified against the current source: `scripts/rag/pipeline.py` performs `is not None` checks (e.g. at the HTTP result handling and `refined.text is not None`), confirming the doc's factual accuracy.

## Problem
The note correctly states *what* the code does (identity check, not truthiness check) but does not explain *why* this distinction matters. Without the rationale, a future editor unfamiliar with the design intent could "simplify" the check to a truthiness check (e.g. `if result:` instead of `if result is not None:`), silently breaking the ability to distinguish "searched but got zero/empty results" from "not yet searched / no result available."

## Reason for change
This is flagged as one of the most easily-misunderstood behaviors for implementers. Documenting the underlying reasoning (distinguishing "searched but got zero results" from "not yet searched") reduces the risk that a correct-but-unexplained rule gets accidentally regressed by someone who doesn't understand its purpose.

## Implementation intent
Add a single sentence of design rationale immediately following (or appended to) the existing "identity vs truthiness" note, explaining that treating `""` as a valid (empty) result and reserving `None` for "not yet executed" allows the fallback chain to distinguish a zero-result search from a stage that hasn't run yet. Do not rewrite or restructure the existing note — only append the rationale.

## Implementation instructions

   `「」は有効な(空の)結果として扱われ、Noneは未実行を表す。これにより「検索したが0件だった」と「まだ検索していない」を区別できる。`
