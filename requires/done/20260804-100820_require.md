# Remove stale `embed_dim` keyword argument from `test_memory_status.py`'s `EmbeddingClientConfig` construction sites

## Priority
High

## Target files
- `tests/agent/commands/test_memory_status.py` (`config` fixture at line ~24-31 and the inline
  construction inside `test_auto_reset_when_elapsed` at line ~72-78 — to be modified)
- `scripts/agent/memory/embedding_client.py` (`EmbeddingClientConfig`, `EmbeddingClientStatus` —
  reference only, confirmed not expected to change)
- `docs/05_agent_12_05_memory-module-ref-extraction-and-facade.md` (line 67 — stale doc reference,
  flagged for a separate fix, not part of this requirement's scope)

## Background
`scripts/agent/memory/embedding_client.py`'s `EmbeddingClientConfig` dataclass currently has
exactly six fields: `embed_url`, `timeout`, `max_retries`, `circuit_open_after`,
`circuit_reset_sec`, `local_only`. It has no `embed_dim` field and no `query_prefix` field.
`tests/agent/commands/test_memory_status.py` passes `embed_dim=0` to `EmbeddingClientConfig(...)`
in its shared `config` fixture (used by 10 of the file's test methods across four test classes)
and again in the standalone `cfg` built inside `test_auto_reset_when_elapsed`.

## Problem
Running `PYTHONPATH=scripts pytest tests/agent/commands/test_memory_status.py -v` was verified
during requirement authoring and reproduces exactly as described in the source issue:
`1 failed, 5 passed, 11 errors`. Every error/failure is
`TypeError: EmbeddingClientConfig.__init__() got an unexpected keyword argument 'embed_dim'. Did
you mean 'embed_url'?`, raised either at fixture setup (11 tests depending on the `config`
fixture) or directly inside `test_auto_reset_when_elapsed` (1 failure, since that test builds its
own `EmbeddingClientConfig` inline rather than via the fixture). This leaves `cmd_memory`'s
status-table rendering and circuit-breaker display logic (`TestGetStatus`,
`TestHybridRetrieverAttributes`, `TestCmdMemoryStatus`, `TestBuildStatusTableModeLabels`)
effectively untested.

## Reason for change
A grep of the full repository (`tests/`, `scripts/`, `docs/`, `agent/`) for `embed_dim` confirms:
- `EmbeddingClientConfig`/`EmbeddingClientStatus` in `scripts/agent/memory/embedding_client.py` do
  not define or use `embed_dim` anywhere in their bodies.
- Embedding dimensionality is tracked as a wholly separate concept elsewhere in the codebase:
  `MemoryStore.__init__(embed_dim=...)` (`scripts/agent/memory/store.py`), threaded through
  `agent/memory/ingestion.py`, `write_ops.py`, and `import_ops.py`, ultimately sourced from
  `AgentConfig.memory.memory_embed_dim` (`agent/config_dataclasses.py`, default `384`) via
  `agent/factory.py: MemoryStore(embed_dim=get_embedding_dims())`. This is a distinct code path
  from `EmbeddingClientConfig`, which configures the HTTP embedding client connection
  (URL/timeout/retry/circuit-breaker), not vector dimensionality.
- No assertion in `test_memory_status.py` reads `embed_dim` off the resulting config or status
  object — the keyword only appears at the two construction call sites. Removing it does not
  invalidate any existing assertion in the file.
- A stray, already-stale doc reference was found at
  `docs/05_agent_12_05_memory-module-ref-extraction-and-facade.md:67`, which lists
  `EmbeddingClientConfig`'s fields as including both `query_prefix="query: "` and `embed_dim=384` —
  neither field exists on the current dataclass. This is a pre-existing documentation/code
  mismatch, separate from the test bug; it is noted here per the issue's own "Documentation
  Impact" guidance but is out of scope for this requirement's fix (a distinct doc-correction task
  should be filed if the mismatch is to be addressed).

This is conclusively a stale test-authoring bug (case: field removed from production dataclass,
test not updated), not a production regression — `embed_dim` should not be re-added to
`EmbeddingClientConfig`.

## Implementation intent
Remove the stale `embed_dim=0` keyword argument from both `EmbeddingClientConfig(...)`
construction call sites in `tests/agent/commands/test_memory_status.py`, without altering any
other fixture behavior, test intent, or assertion in the file. Do not introduce any new concept of
embedding dimensionality into this test file — the tests in scope (`get_status()`,
`HybridRetriever` attributes, `_memory_status()` rendering, `build_status_table` mode labels) do
not depend on it.
