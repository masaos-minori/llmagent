## Background

`docs/05_agent_12_02_memory-gate-data-model-search-part1.md` documents two constants defined in
`scripts/agent/memory/enums.py`: `DEDUP_THRESHOLDS` (per-source-type duplicate-similarity
thresholds) and `RETENTION_DAYS` (per-source-type retention windows for the JSONL archive). The
doc's author confirmed `DEDUP_THRESHOLDS` is read by a "重複判定閾値取得関数" in `ingestion.py`,
but explicitly flagged `RETENTION_DAYS`'s usage as "Needs confirmation" (tracked as NC-015 in
`docs/00_governance_07_needs-confirmation-inventory.md`), noting the author could not find any
retention-deletion logic referencing it within their assigned module scope
(`store.py`/`retriever.py`/`services.py`/`ingestion.py`) and speculated it might be used in an
unread module such as `rebuild_ops.py`.

## Problem

Investigation of the current source (this cycle) resolves the open question with a concrete,
verifiable answer:

- `DEDUP_THRESHOLDS` is actively used: `MemoryIngestion._get_dedup_threshold()`
  (`scripts/agent/memory/ingestion.py:178-183`) reads it keyed by `entry.source_type`, and is
  called from `_has_near_duplicate()` (`ingestion.py:189-196`), which gates the skip-duplicate
  decision during memory ingestion. This is a live, exercised production path.
- `RETENTION_DAYS` is referenced in exactly one place: `JsonlMemoryStore.read_active()`
  (`scripts/agent/memory/jsonl_store.py:91-111`, the lookup is at line 98). A repo-wide search
  (`grep -rn "read_active" .` across `scripts/`, `tests/`, and all other directories) finds **zero
  callers** of `read_active()` anywhere in the codebase — not in production code, not in tests.
  `RETENTION_DAYS` is therefore defined and technically "referenced," but the retention-based
  expiry filter it drives is currently dead/unreachable code: no code path actually applies
  per-source-type retention expiry to the JSONL archive today.
- This confirms and extends the doc's own suspicion (it could not find retention-deletion logic
  in its assigned modules) — the reference does exist, but in a module outside that doc's scope
  (`jsonl_store.py`), and that reference is itself unused.
- A related, already-created requirement (`requires/20260727-134808_require.md`, addressing a
  different doc's NC-007 item) independently flagged `read_active()` as having no production
  caller and recommended a follow-up decision (wire it in vs. remove it) as a separate,
  out-of-scope item. This requirement should cross-reference that finding rather than duplicate
  the follow-up recommendation.

## Reason for Change

Leaving NC-015 open indefinitely in the governance inventory is misleading once a concrete answer
exists: it implies the usage is genuinely unknown, when in fact the code has been read and the
answer is "referenced only by dead code." Documenting this precisely also surfaces an accurate
picture to future readers: retention-based expiry of the JSONL archive is currently inert, which
is useful context for anyone reasoning about data lifecycle or planning to rely on `RETENTION_DAYS`.

## Implementation Intent

This is a documentation-only correction, not a behavior change. No source file should be modified
as part of resolving NC-015 itself. The dead-code status of `read_active()` is already tracked as
a follow-up elsewhere (`requires/20260727-134808_require.md` / NC-007); this item should reference
that tracking rather than re-open or duplicate a decision about wiring in or removing
`read_active()`.
