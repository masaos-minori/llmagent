# TypedValidators treat None value and missing key identically

## Priority
Medium

## Summary
All _get_* helpers return None both when the key is missing AND when the value is explicitly None. This masks bugs where a required field is accidentally set to None.

## Reason for Change
Example: cfg = {"max_retries": None}. _get_int(cfg, "max_retries") returns None, same as if the key was missing. Callers expecting a non-None value get None silently, potentially causing downstream errors.

## Implementation Intent
Consider distinguishing between missing keys and explicit None values. For required fields, raise ConfigReloadValidationError when the value is None.

## Target Files or Areas
- scripts/agent/services/typed_validators.py
- All _get_* helper functions

## Required Changes
- Add optional parameter to distinguish missing vs None
- Raise ConfigReloadValidationError for required fields with None values
- Ensure backward compatibility with existing callers that expect None for missing keys

## Acceptance Criteria
- [ ] Required fields with None values raise ConfigReloadValidationError
- [ ] Optional fields still return None for both missing and None values
- [ ] No regressions in normal operation when registry is available

## Testing Expectations
- Unit test for role validation with various field combinations
- Integration test verifying diagnostic output during startup/shutdown

## Documentation Impact
If DiagnosticsConfig is extended, update documentation to reflect the new state.

## Out of Scope
- Changing the registry initialization order
- Adding retry logic for health checks

## AI Implementation Instruction
Modify only _filter_sensitive_fields() in diagnostic_store.py. Add a new state to McpAvailability enum if needed. Update the fallback logic to use the new state instead of UNKNOWN when registry is None.
