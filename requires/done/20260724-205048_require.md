# Session schema missing detection relies on fragile text matching

## Priority

High

## Target Files

- `scripts/agent/repl.py` — AgentREPL._run_repl_loop()
- `scripts/agent/session.py` — Session.start()

## Background

When the session database tables do not exist, SQLite raises an error. The current code detects this by checking for the string `"no such table"` in the exception message.

## Problem

In `repl.py:446-448`:

```python
if "no such table" in msg.lower():
    self._view.write_fatal(
        "Session schema missing. Run: bash deploy/init_db.sh to initialize the database."
    )
```

A similar pattern exists in `session.py:102`:

```python
if "no such table" in str(e):
```

Text-based matching is fragile because:
- SQLite error messages may be localized in non-English environments
- SQLite version upgrades may change error message formatting
- The substring match can produce false positives if unrelated error messages contain the phrase

## Reason for Change

Reliable error detection should use structured error information (error codes, exception types) rather than text parsing. This ensures correctness regardless of locale or SQLite version.

## Implementation Intent

Replace text-based matching with SQLite error code inspection. Use `sqlite3.OperationalError` and check the specific error code (e.g., SQLITE_ERROR = 1) combined with a more robust table existence check.

## Implementation Instructions

1. In `_run_repl_loop()`, catch `sqlite3.OperationalError` specifically instead of relying on the generic `RuntimeError` handler.
2. Check the SQLite error code using `e.args[0]` (which contains the SQLite error code number). Error code 1 corresponds to `SQLITE_ERROR`.
3. Alternatively, perform an explicit table existence check before starting the session:
   ```python
   cursor.execute("SELECT name FROM sqlite_master WHERE type='table' AND name=?", ("sessions",))
   if cursor.fetchone() is None:
       # Schema missing
   ```
4. Apply the same fix to `session.py:102`.

## Acceptance Criteria

- [ ] Localized SQLite error messages are correctly detected
- [ ] SQLite version changes do not break detection logic
- [ ] Error detection uses structured error codes, not text parsing
- [ ] False positive detections are eliminated

## Tests

- Integration test: run with non-English locale; verify detection still works
