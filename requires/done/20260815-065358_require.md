# Fix git-exc-import-guard pre-commit hook intermittent failure

## Priority
Medium

## Status
Resolved

## Target files
- `.pre-commit-config.yaml` (hook definition)
- `scripts/shared/git_helper.py` (has `import git.exc` on line 40)
- `scripts/mcp_servers/git/git_service.py` (has `import git.exc` on line 20)

## Background
The `git-exc-import-guard` pre-commit hook fails via pre-commit but passes when run manually
from the same repository root. Both files that reference `git.exc.*` currently include
`import git.exc`:
- `scripts/shared/git_helper.py:40` — local `import git.exc` inside function scope
- `scripts/mcp_servers/git/git_service.py:20` — top-level `import git.exc`

## Problem
Pre-commit fails with:
```
git.exc import guard.....................................................Failed
- hook id: git-exc-import-guard
- exit code: 1
```

Manual verification commands (both pass):
```bash
rg -l "git\.exc\." scripts/
for f in $(rg -l "git\.exc\." scripts/); do
    grep -n "import git\.exc" "$f" || echo "NO MATCH: $f"
done
# Output:
# scripts/mcp_servers/git/git_service.py:20:import git.exc
# scripts/shared/git_helper.py:40:        import git.exc
```

Pre-commit execution (fails):
```bash
uv run pre-commit run git-exc-import-guard --all-files
# Returns exit code 1 with no additional output
```

## Reason for change
The hook's logic has a subtle bug: when `grep -q "import git.exc"` succeeds (finds the import),
`! grep -q` returns exit code 1, and since `&& echo` doesn't execute, the exit code of that line
is 1. The while loop's final exit code becomes 1 even though all files are correct.

## Root cause analysis
The original hook entry was:
```bash
bash -c 'rg -l "git\\.exc\\." scripts/ | while read f; do ! grep -q "import git\\.exc" "$f" && echo "$f"; done'
```

When iterating over files that ALL have `import git.exc`:
1. `grep -q "import git\\.exc" "$f"` → succeeds (exit 0)
2. `! grep -q "import git\\.exc" "$f"` → fails (exit 1) because negation of success is failure
3. Since left side of `&&` failed, right side (`echo "$f"`) doesn't execute
4. Exit code of the entire line = 1 (the exit code of the failed left side)
5. The while loop ends with exit code 1 because the LAST iteration had a failed condition

This explains why the hook always fails regardless of whether imports are present or not.

## Fix applied
Capture the output and check if it's empty:
```bash
bash -c 'missing=$(rg -l "git\\.exc\\." scripts/ | while read f; do ! grep -q "import git\\.exc" "$f" && echo "$f"; done); [ -z "$missing" ] && exit 0 || echo "$missing" && exit 1'
```

Changes:
- `missing=$(...)` captures the output of the while loop into a variable
- `[ -z "$missing" ] && exit 0` — if nothing was printed (no missing imports), exit 0
- `|| echo "$missing" && exit 1` — if something was printed, display filenames and exit 1

## Verification
- `uv run pre-commit run git-exc-import-guard --all-files` now passes (exit 0)
- Hook still correctly detects missing `import git.exc` when present (exit 1)
