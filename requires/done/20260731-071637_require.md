# Requirement: Enforce Encryption for Diagnostic Data Containing Secrets

## Priority

Medium

## Target Files

- `scripts/agent/repl.py`
- `scripts/agent/diagnostic_store.py`

## Background

Session diagnostics include `artifacts` (URI array) and `rag_stage_outcomes`, which may contain sensitive information (file paths, search results). These fields are passed to `DiagnosticStore.save()` without encryption when `encryption_key` is empty.

## Problem

In `repl.py`:

```python
# repl.py:206-235
diagnostic = {
    "artifacts": artifacts,  # May contain sensitive URIs
    "rag_stage_outcomes": rag_stage_outcomes,  # May contain search results
}

if artifacts or rag_stage_outcomes:
    logger.warning("Diagnostics contains secret fields")

# Warning logged but data saved unencrypted
await self.diagnostics.save(diagnostic)
```

This means:

1. When `encryption_key` is empty, sensitive data is stored in plaintext
2. A warning is logged but the data is still saved unencrypted
3. No enforcement mechanism prevents saving sensitive data without encryption
4. Security policy violation if encryption is required by compliance requirements

## Reason for Change

Sensitive diagnostic data must be encrypted before persistence. A warning alone is insufficient — the system should enforce encryption or refuse to save.

## Implementation Intent

Ensure that diagnostic data containing sensitive fields is always encrypted before being saved. If encryption is not available, refuse to save the data.

## Implementation Instructions

### Step 1: Enforce encryption in `_save_session_diagnostic()`

```python
async def _save_session_diagnostic(self):
    """Save session diagnostics with mandatory encryption."""
    has_sensitive_data = bool(artifacts or rag_stage_outcomes)
    
    if has_sensitive_data:
        # Check if encryption key is available
        if not self.diagnostics.encryption_key:
            logger.error(
                "Cannot save diagnostics with sensitive data — no encryption key available"
            )
            return  # Refuse to save
        
        # Force encryption
        await self.diagnostics.save(diagnostics, encrypt=True)
    
    else:
        # No sensitive data — save normally
        await self.diagnostics.save(diagnostics)
```

### Step 2: Add explicit `encrypt` parameter to `DiagnosticStore.save()`

If `DiagnosticStore.save()` doesn't already support an `encrypt` parameter:

```python
class DiagnosticStore:
    async def save(self, data: dict, encrypt: bool = False):
        """Save diagnostic data, optionally encrypting it."""
        if encrypt and not self.encryption_key:
            raise RuntimeError("Cannot encrypt without encryption key")
        
        if encrypt:
            encrypted_data = self._encrypt(data)
            await self._persist(encrypted_data)
        else:
            await self._persist(data)
```

### Step 3: Remove the warning-only approach

Replace the existing warning with the enforcement logic above. The warning was a workaround; the proper solution is to prevent unencrypted saves.

## Acceptance Criteria

1. Diagnostics with sensitive data cannot be saved without encryption
2. An error is raised/logged when encryption key is unavailable
3. Normal diagnostics (without sensitive data) can still be saved unencrypted
4. Existing diagnostic save operation is unaffected — no regression
