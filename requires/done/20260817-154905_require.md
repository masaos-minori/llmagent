# Consolidate Output-Truncation and Dry-Run Message Templates in Git Format Output

## Priority
Medium

## Target files
- `scripts/mcp_servers/git/format_output.py`
- Unknown: other MCP server formatter modules with similar truncation logic
- `tests/mcp_servers/git/test_format_output.py`

## Background
`scripts/mcp_servers/git/format_output.py` has two related duplication patterns not addressed during its 2026-08-14 refactor cycle:
1. `format_show`'s byte-limit truncation logic (`GIT_SHOW_OUTPUT_MAX_CHARS`) is not shared with any other MCP server's output-truncation logic, despite the same concern existing elsewhere in `scripts/mcp_servers/`.
2. `format_add`, `format_commit`, `format_checkout`, `format_pull`, and `format_push` each repeat an `if req.dry_run: return "[DRY RUN] ..."` branch with a distinct message template per function.

Both patterns were identified as genuine duplication during the refactor cycle but deferred because truncation and dry-run message wording are both visible-output-sensitive — any consolidation risks silently altering the exact truncation boundary or wording that callers/tests may depend on verbatim.

## Problem
Two duplication patterns exist in `format_output.py`:
1. Truncation logic is duplicated across MCP servers without a shared utility.
2. Five dry-run message templates are repeated with different wording per function.

## Reason for change
Consolidation would reduce maintenance burden and ensure consistent behavior, but must be done carefully to avoid silent output changes.

## Implementation intent
Treat as two independent sub-tasks: truncation consolidation and dry-run message consolidation. Each can be implemented and reviewed separately.

For truncation: enumerate every MCP server module with similar byte/char-limit truncation logic, add snapshot/characterization tests pinning the exact truncated output at `len == max`, `len == max+1`, `len == max-1` boundaries for each, then extract a shared utility.

For dry-run messages: get explicit confirmation on whether the 5 current wordings should be unified before extracting a shared template.

## Implementation instructions
### Truncation consolidation
1. Enumerate all truncation-limit constants across `scripts/mcp_servers/` using `rg` for byte/char-limit constants across `scripts/mcp_servers/**/format*.py` and `**/*formatter.py`.
2. Add boundary characterization tests (at/over/under the limit) for each truncation site found.
3. Extract a shared truncation utility.
4. Verify byte-for-byte identical truncated output at all tested boundaries for every consolidated call site.

### Dry-run message consolidation
1. Get explicit maintainer sign-off on whether the 5 current dry-run wordings should be unified.
2. If confirmed, extract a shared `_dry_run_or(...)` helper.
3. Update all 32 existing `test_format_output.py` characterization tests to match the (deliberately changed) wording.
4. Call out the wording changes in the PR description.

## Acceptance criteria
- If a shared truncation utility is introduced: byte-for-byte identical truncated output at all tested boundaries, for every consolidated call site.
- If dry-run templates are unified: explicit maintainer sign-off recorded, and all 32 existing `test_format_output.py` characterization tests updated to match the (deliberately changed) wording, with the change called out in the PR description.

## Tests
Full `tests/mcp_servers/git/test_format_output.py` suite plus any other affected formatter test files; new boundary tests for truncation.
