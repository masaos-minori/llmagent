# Rewrite `test_different_subsections_in_load_all_merged` to call the real `ConfigLoader.load_all()`

## Priority
Medium

## Target files
- `tests/shared/test_shared_boundary_conditions.py` (`TestDictMergeConflictResolution::test_different_subsections_in_load_all_merged`, lines 37-62 — to be modified)
- `scripts/shared/config_loader.py` (`ConfigLoader.load_all()`, lines 68-94 — reference only, not expected to change)

## Background
`scripts/shared/config_loader.py:28` defines a module-level constant:
```python
_BASE_CONFIG_FILES: tuple[str, ...] = ("agent.toml",)
```
`ConfigLoader.load_all()` (lines 68-94) always iterates over this constant and has no parameter to
pass alternate filenames. Its docstring states: "Dict-valued keys are merged one level deep so that
multiple MCP server config files can each contribute a `[mcp_servers.<key>]` section without
overwriting entries from previously loaded files."

A sibling fix (tracked under `requires/done/20260804-100530_require.md` and
`plans/20260804-105925_plan.md`) already established the technique for exercising `load_all()`'s
real merge logic in tests without touching production files: monkeypatching the module-level
constant via `monkeypatch.setattr("shared.config_loader._BASE_CONFIG_FILES", (...))`. This pattern
is now in use in `tests/shared/test_config_loader.py::TestMergeOrder::test_nested_dict_merge`
(lines 58-72, confirmed present in the current file), and is consistent with an existing precedent
of monkeypatching module-level state in `tests/eventbus_helpers.py` (e.g. `monkeypatch.setattr(eb_app, "load_config", ...)`).

## Problem
`tests/shared/test_shared_boundary_conditions.py::TestDictMergeConflictResolution::
test_different_subsections_in_load_all_merged` (confirmed still present at lines 37-62) does not
use this technique and does not call `load_all()` at all. Instead it calls `loader.load()` twice
and hand-copies `load_all()`'s one-level-deep dict-merge algorithm inline into the test body:
```python
# load_all merges dict-valued keys one level deep
# We need to manually combine since load_all only loads _BASE_CONFIG_FILES
result_a = loader.load("extra_mcp.toml")
result_b = loader.load("extra_mcp2.toml")
merged: dict[str, Any] = {}
for key, val in result_a.items():
    if isinstance(val, dict) and isinstance(merged.get(key), dict):
        merged[key] = {**merged[key], **val}
    else:
        merged[key] = val
for key, val in result_b.items():
    ...
```
The test's own docstring — "Different subsections under the same parent are merged by
`load_all()`" — is misleading: the test asserts against a separately hand-rolled copy of the merge
algorithm, not against `load_all()`'s actual output. Confirmed against the current source: this
test still uses the pre-fix workaround comment ("We need to manually combine since load_all only
loads `_BASE_CONFIG_FILES`") that predates the sibling fix's monkeypatch technique.

`test_same_subsection_later_file_wins` and `test_deep_nested_same_subsection_replaced` in the same
class both intentionally call `loader.load()` directly (not `load_all()`) to test `load()`'s flat
shallow-merge behavior, and are correctly named/documented for that; they are unaffected by this
issue.

## Reason for change
If `ConfigLoader.load_all()`'s real merge logic (`config_loader.py:82-93`, specifically the
`isinstance(val, dict) and isinstance(merged.get(key), dict)` condition and the
`{**merged[key], **val}` merge expression) ever regresses in a future refactor, this test would not
catch it: it asserts against a copy of the algorithm maintained separately in the test file, which
will not necessarily drift in sync with the real implementation. This is a coverage-duplication
risk, not a currently-uncovered production code path — `load_all()`'s real merge logic is already
exercised by the sibling-fixed `test_nested_dict_merge`. There is no evidence (comment or commit
message) that the hand-rolled copy in this test was a deliberate, accepted design choice rather
than an oversight predating the now-established monkeypatch technique.

## Implementation intent
Rewrite `test_different_subsections_in_load_all_merged` to use the same
`monkeypatch.setattr("shared.config_loader._BASE_CONFIG_FILES", (...))` pattern that the sibling
fix introduced for `test_nested_dict_merge`, so the test calls the real `ConfigLoader.load_all()`
instead of hand-copying its merge algorithm. Do not change `load()` or `load_all()` production
logic — this is a test-only change. Do not modify `test_same_subsection_later_file_wins` or
`test_deep_nested_same_subsection_replaced`, which are unaffected.

## Implementation instructions
- In `tests/shared/test_shared_boundary_conditions.py`, add a `monkeypatch: pytest.MonkeyPatch`
  parameter to `test_different_subsections_in_load_all_merged`.
- Replace the two `loader.load(...)` calls and the manual merge loop with:
  ```python
  monkeypatch.setattr(
      "shared.config_loader._BASE_CONFIG_FILES",
      ("extra_mcp.toml", "extra_mcp2.toml"),
  )
  loader = ConfigLoader(config_dir=tmp_path)
  result = loader.load_all()
  ```
- Update the assertions to read from `result` (the real `load_all()` output) instead of the
  hand-rolled `merged` dict: `assert "server_a" in result.get("mcp_servers", {})` and
  `assert "server_b" in result.get("mcp_servers", {})`.
- Remove the now-unused manual merge loop and its misleading inline comments
  ("We need to manually combine since load_all only loads `_BASE_CONFIG_FILES`").
- If the `Any` import in this file becomes unused after removing the manual merge loop's
  type annotation (`merged: dict[str, Any] = {}`), remove the now-unused import — check other
  usages of `Any` in the file first (`_load_single`-style helpers or other tests) before removing
  the import outright, since it is a module-level import shared across the file.
- Keep the test's existing docstring ("Different subsections under the same parent are merged by
  `load_all()`.") since it will now be accurate.
- Do not modify `scripts/shared/config_loader.py`.
- Do not modify `tests/shared/test_config_loader.py` (already fixed by the sibling plan).
