# Validate complete chunk groups before embedding or database mutation

## Priority
High

## Target files
- `scripts/rag/ingestion/ingester.py`
- `scripts/rag/ingestion/pipeline_utils.py`

## Background
The ingester currently derives document metadata from the first chunk, allows invalid `chunk_index` values to fall back to zero, and does not verify that all files in a URL group belong to the same generated document version. This permits mixed metadata, duplicate indices, missing indices, and incomplete groups to reach embedding or storage.

## Problem
Inconsistent or malformed chunk groups can lead to corrupted RAG index (mixed metadata, duplicate/missing indices, etc.) because validation happens too late or is insufficient.

## Reason for change
To ensure data integrity in the RAG ingestion pipeline by enforcing strict contract validation for chunk groups before any expensive or permanent operations (embedding, DB write) occur.

## Implementation intent
Implement a strict, deterministic validation boundary for chunk groups within the ingestion process. Ensure all chunks in a group share identical metadata and have valid, contiguous indices starting from zero.

## Implementation instructions
- In `RagIngester.ingest_url_group`, after sorting chunk files, validate that all chunks in the group have matching `title`, `lang`, `etag`, `last_modified`, `fetched_at`, `chunking_strategy`, and other critical metadata.
- Enforce that `chunk_index` values are non-boolean integers, start at 0, and are strictly contiguous up to `chunk_count - 1`.
- Reject the entire group if any chunk fails validation or if there is a mismatch between manifest (if present) and actual chunk count.
- Return detailed validation errors specifying the offending file and field.

## Acceptance criteria
- Invalid/inconsistent groups are rejected before calling embedding API or modifying the database.
- Valid groups have unique, contiguous indices starting at 0 and consistent metadata.
- Error messages clearly identify the offending file and field.
- Manifest/file-count mismatches are caught and rejected early.

## Tests
- Missing and incorrect artifact metadata.
- Mixed source files under one URL.
- Duplicate and missing indices.
- Boolean and string indices.
- Invalid chunk type.
- Empty content.
- Manifest count mismatch.
