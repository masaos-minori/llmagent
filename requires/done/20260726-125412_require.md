## Problem

Three genuine gaps remain (all guard tests missing before any refactor of these paths):

1. `scripts/eventbus/dlq.py::_atomic_write()` failure path — no test proves the DB row
   is left unchanged when the on-disk write raises.
2. `scripts/db/helper.py`'s `reuse_connection` parameter — no test proves it actually
   skips reconnect when already connected, or skips close in `__exit__`.
3. `scripts/rag/ingestion/chunk_splitter.py::process_file()` — no end-to-end test on
   real input text verifies actual chunk output (count, boundaries, content).

## Reason for Change

Establish behavioral baselines through guard tests before making structural changes to
prevent regressions, for the 3 paths confirmed to still lack coverage.

## Implementation Intent

Add characterization tests for the 3 confirmed gaps only; do not duplicate the coverage
already confirmed present for `tool_loop_guard.py` and `production_config_validator.py`.

## Implementation Instructions

1. **`dlq.py`**: Add a test that monkeypatches or otherwise forces `_atomic_write()` to
   raise, calls the DLQ-write function that wraps it, and asserts the event's DB row is
   unchanged (still live, not marked dead-lettered) after the exception.
2. **`db/helper.py`**: Add tests for `reuse_connection=True`:
   - Opening with `reuse_connection=True` when already connected does not reconnect
     (e.g., assert the underlying `sqlite3.Connection` object identity is unchanged, or
     that no new connection call occurs).
   - Exiting a context manager opened with `reuse_connection=True` does not close the
     connection (subsequent use of the same helper instance still works).
3. **`chunk_splitter.py`**: Add an end-to-end test calling `process_file()` on a small
   real file (mixing English and Japanese content, if `process_file()` dispatches by
   language) and assert on actual output: chunk count, that chunk boundaries land where
   expected, and that no content is dropped or duplicated across chunks.

Run tests after adding each guard test to confirm no regressions.
