# Restrict environment variable overrides for subprocesses

## Priority

Medium

## Target Files

- `scripts/agent/http_lifecycle.py:224-226` — Environment variable merge
- `scripts/agent/http_lifecycle.py:230-236` — Subprocess launch with environment variables

## Background

The subprocess environment is created by merging system environment variables with config-provided ones:

```python
if cfg.env:
    env = {**os.environ, **cfg.env}
```

This allows `cfg.env` to override critical environment variables like `PATH`, `PYTHONPATH`, etc. If an attacker modifies the config file, they could redirect library loading or command execution.

## Problem

No restriction on which environment variables can be overridden. Critical variables like `PATH`, `PYTHONPATH`, `LD_LIBRARY_PATH` should not be overridable via config.

## Reason for Change

Prevent potential subversion of MCP server behavior through environment variable manipulation.

## Implementation Intent

Add a whitelist of allowed environment variable overrides. Only allow non-critical variables to be modified.

## Implementation Instructions

1. Define a set of protected environment variable names:
   ```python
   PROTECTED_ENV_VARS = {"PATH", "PYTHONPATH", "LD_LIBRARY_PATH", "HOME", "USER"}
   ```
2. Filter out protected variables before merging:
   ```python
   if cfg.env:
       safe_env = {k: v for k, v in cfg.env.items() if k not in PROTECTED_ENV_VARS}
       env = {**os.environ, **safe_env}
   ```
3. Log a warning when a protected variable is attempted to be overridden
4. Run tests to confirm no regressions

## Acceptance Criteria

- [ ] Protected environment variables cannot be overridden via config
- [ ] Warning logged when protection triggers
- [ ] No regressions in subprocess startup
