# Remove dead RuntimeToolRegistry.is_side_effect()/classify_operation_type() duplication

## Priority
High

## Target files
- `scripts/shared/runtime_tool_registry.py`
- `tests/shared/test_runtime_tool_registry.py`

## Background
`scripts/shared/runtime_tool_registry.py`'s module docstring documents `is_side_effect()` as an
"intentionally duplicate," temporary side-effect classifier that sources its answer from the
registered `RuntimeTool.is_write` field, explicitly pending "a future unification decision"
against the other side-effect classifier, `shared.tool_executor_helpers.is_side_effect()`
(frozenset-based, actively used by `ToolExecutor.execute()` at
`scripts/shared/tool_executor.py:234` as the TTL-cache-bypass check, imported at line 37). The
registry class also defines `classify_operation_type()`, a coarse read/write derivation from the
same `is_write` field, with a docstring noting it cannot distinguish
`DELETE`/`EXECUTE`/`API_WRITE` — "a documented gap."

## Problem
A full-repository grep for method-call usages confirms both `RuntimeToolRegistry.is_side_effect()`
and `RuntimeToolRegistry.classify_operation_type()` have **zero production callers**:

- `grep -rn "\.is_side_effect(" scripts/ tests/` shows the only call-site is
  `tests/shared/test_runtime_tool_registry.py:132-133` (`reg.is_side_effect(...)`), which tests the
  method directly and is not itself a caller from other production code.
- `grep -rn "\.classify_operation_type(" scripts/ tests/` shows the only call-site is
  `tests/shared/test_runtime_tool_registry.py:140-141` (`reg.classify_operation_type(...)`), same
  situation.
- The unrelated, actively-used `classify_operation_type()` **free function** in
  `scripts/agent/tool_policy.py:54` (consumed by `scripts/agent/repository_gateway.py:84`,
  `scripts/agent/tool_audit.py:52,183`, and multiple `tests/agent/test_tool_policy*.py` /
  `test_tool_approval_risk.py` tests) is a **different symbol** with a different signature — it
  returns `agent.tool_enums.OperationType`, not the registry method's
  `Literal["read", "write"]` — and must not be confused with, or touched as part of, this cleanup.
- `RuntimeToolRegistry.apply_policy()`, `tool_spec_for_call()`, and `ToolSpec.requires_serial` (the
  scheduler's actual serial/parallel decision path, per both files' docstrings) are unrelated to
  this dead code and must not be modified.

Both methods are therefore dead code: defined, exercised only by tests that assert on their own
implementation, and never consulted by any runtime code path. Leaving them in place keeps the
"two answers to the same question" duplication alive with no offsetting benefit, and continues to
invite a future caller to pick the wrong (registry) classifier by mistake, since the module
docstring itself flags this drift risk.

## Reason for change
The docstring explicitly frames this duplication as temporary, pending a unification decision.
The grep evidence needed to make that decision (are there live callers of the registry version?)
is now available and is negative — no production caller exists. Resolving the duplication now
(by deletion, since there is nothing to migrate) removes dead API surface from a shared,
security-relevant registry class and eliminates the drift risk the docstring warns about, without
waiting for a hypothetical future caller that has not materialized.

## Implementation intent
Delete `RuntimeToolRegistry.is_side_effect()` and `RuntimeToolRegistry.classify_operation_type()`
outright rather than migrating them, since no production caller exists to redirect.
`shared.tool_executor_helpers.is_side_effect()` remains the sole side-effect classifier used by
`ToolExecutor.execute()`'s TTL-cache-bypass check; nothing about that call path changes. Update the
module docstring to remove the now-resolved "temporary, parallel duplication pending a future
unification decision" note, and drop the corresponding direct-unit tests. Do not touch
`ToolSpec.requires_serial` / `is_write`-driven scheduler logic (`agent/tool_scheduler.py`) or the
unrelated `agent.tool_policy.classify_operation_type()` free function.
