# Narrow `register_validator`'s Callable parameter type from `dict[str, Any]` to `dict[str, object]`

## Priority
Low

## Target files
- `scripts/mcp_servers/tool_validators.py`
- Unknown: confirm no other module currently defines a validator via `@register_validator` outside this file

## Background
`scripts/mcp_servers/tool_validators.py`'s `_VALIDATORS`, `register_validator`, and every registered validator function type their `args` parameter as `dict[str, Any]`, but the module's own docstring usage example types it as `dict[str, object]` — the docstring and the actual `Callable` signature disagree.

## Problem
Type inconsistency between the docstring example (`dict[str, object]`) and the actual type annotation (`dict[str, Any]`). This creates confusion for future validator authors about what type they should expect for the `args` parameter.

## Reason for change
Consistency: make the code match the existing docstring rather than the other way around. Since all 4 existing registered validators already use `isinstance` narrowing internally before accessing typed values, this change is likely a mypy/pyright-only adjustment with no behavior change.

## Implementation intent
Narrow `Any` to `object` in `register_validator`'s `Callable[[dict[str, Any]], None]` type and in `_VALIDATORS`'s value type. Since all 4 existing registered validators already use `isinstance` narrowing internally before accessing typed values, this change is likely a mypy/pyright-only adjustment with no behavior change — but confirm this for each validator before finalizing.

## Implementation instructions
### Phase 1: Verify safety
1. Run `rg "@register_validator" scripts/` to confirm no external module defines a validator via `@register_validator` outside this file.
2. Confirm that all 4 existing validators (`_validate_git_commit`, `_validate_git_push`, `_validate_trigger_workflow`, `_validate_shell_run`) use `isinstance` narrowing internally before accessing typed values.

### Phase 2: Apply the change
1. Change `register_validator`'s `Callable[[dict[str, Any]], None]` annotation to `Callable[[dict[str, object]], None]`.
2. Update `_VALIDATORS`'s value-type annotation to match.

### Phase 3: Verify
1. Re-run `mypy`/`pyright` on the 4 existing validators to confirm they still type-check cleanly with `object` (they already use `isinstance` narrowing throughout, so this is expected to be a no-op fix).
2. If any validator fails to type-check under `object`, add the minimal `isinstance` narrowing needed rather than reverting to `Any`.
