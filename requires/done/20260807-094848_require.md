# Reduce implementation-derived detail in docs/05_agent_00_document-guide.md

## Priority
Medium

## Target files
`docs/05_agent_00_document-guide.md`

## Background
The `05_agent_*.md` document set mixes design/operational judgment with content that is mechanically derivable from code (exhaustive file indexes, keyword lists). This makes the doc set stale-prone and harder to use as a decision reference. A review (`memo-doc-agent-review.md`) identified what to keep vs. remove per chapter.

## Problem
`docs/05_agent_00_document-guide.md` contains mechanical file/link inventories that duplicate what code search already shows. It does not follow the design-doc reduction policy, making it verbose and maintenance-heavy.

## Reason for change
The document set needs to stay focused on decision-making reference material. Mechanical inventories add noise without adding value and increase the risk of staleness when code changes outpace doc updates.

## Implementation intent
Restructure `docs/05_agent_00_document-guide.md` to serve as the doc-guide entry point only: overall purpose of the doc set, chapter structure, "which question maps to which chapter," the Canonical Source Rule, and how Known Issues / Deprecated Items / Needs Confirmation are handled. Remove all mechanical file indexes, keyword lists, and implementation-diff-memo-style notes.

## Implementation instructions
1. Read `docs/05_agent_00_document-guide.md` in full.
2. Identify sections that contain mechanical file indexes, keyword enumerations, or link lists duplicatable by code search.
3. Remove or compress those sections while preserving: overall purpose, chapter structure, question-to-chapter navigation, Canonical Source Rule, handling of Known Issues / Deprecated Items / Needs Confirmation.
4. Verify any removed information is not the sole source of a fact needed elsewhere before deletion.
5. Restructure remaining content to follow the template: Purpose / Design Intent / Responsibility Boundary / Key Constraints / Operational Notes / Known Limitations / Related Docs.
6. If a design rationale cannot be recovered from the current text, mark it `Needs Confirmation` rather than guessing.
7. Run `python tools/check_agent_docs_consistency.py` after editing to confirm no broken internal links or removed-file references were introduced.

## Acceptance criteria
- The chapter follows the template in `memo-doc-agent-review.md` §「修正後の章構成テンプレート」 where applicable to this chapter's role as a guide.
- No mechanical file/keyword listing remains that duplicates content already covered by `tools/check_agent_docs_consistency.py` or code search.
- Any judgment that could not be reconstructed from the current doc is recorded as `Needs Confirmation` rather than invented.

## Tests
Not required for behavior (documentation-only). Run `python tools/check_agent_docs_consistency.py` after editing to confirm no broken internal links or removed-file references were introduced.
