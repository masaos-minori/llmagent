## Background

The `purge_old_sessions` function uses `if len(rows) > cfg.max_sessions:` to decide whether to delete excess sessions. When `len(rows) == cfg.max_sessions`, no deletion should occur, but this exact boundary condition is not tested.

## Problem

```python
def purge_old_sessions(db, cfg):
    rows = db.fetchall("SELECT * FROM sessions ORDER BY last_accessed ASC")
    if len(rows) > cfg.max_sessions:  # boundary: len(rows) == cfg.max_sessions
        to_delete = [row[0] for row in rows[cfg.max_sessions :]]
        ...
```

Current tests use values far from the boundary (e.g., 2 sessions vs max_sessions=10). An off-by-one error would not be caught by these tests.

## Reason for Change

Boundary conditions are the most common source of bugs. Without testing the exact boundary, an off-by-one regression could go undetected.

## Implementation Intent

Add three boundary value test cases to `TestPurgeOldSessions`:

1. `max_sessions - 1` sessions → 0 deletions (below boundary)
2. `max_sessions` sessions → 0 deletions (exact boundary)
3. `max_sessions + 1` sessions → 1 deletion (above boundary)

## Implementation Instructions

1. Add test method `test_boundary_at_max_sessions` to `TestPurgeOldSessions` class in `tests/test_db_maintenance.py`
2. Create three test methods covering the three boundary scenarios above
3. Each test should verify the exact number of deleted sessions matches expected behavior
4. Run `uv run pytest tests/test_db_maintenance.py::TestPurgeOldSessions -v` to confirm all pass
