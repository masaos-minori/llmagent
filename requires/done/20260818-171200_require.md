# Title: [REQ] Refactor Configuration Dataclasses for Consistency and Correctness
# Priority: Low
# Target files: scripts/agent/config_dataclasses.py, shared/config_loader.py, shared/config_validators.py, and relevant factories.
# Background: There are multiple inconsistencies in the configuration system: dead fields, duplicate definitions across different config types, missing validations, and inconsistent defaults between related components.
# Problem: 
# 1. `AgentConfig.agent_memory_max_startup_snippets` is a dead field.
# 2. `security_lockdown_enabled` is defined redundantly in `MCPConfig` and `AgentConfig`.
# 3. `ToolConfig.progress_stagnation_window` lacks validation.
# 4. `MemoryConfig` validation is inconsistently split between build paths and dataclass `__post_init__`.
# 5. `InjectionPolicy.min_importance` and `MemoryConfig.memory_min_importance` have differing defaults.
# 6. LLM compression parameters are hardcoded instead of being part of `LLMConfig`.
# Reason for change: To make the configuration surface honest, uniform, and predictable.
# Implementation intent: Clean up the configuration hierarchy and ensure robust validation.
# Implementation instructions:
# 1. Remove `AgentConfig.agent_memory_max_startup_snippets`.
# 2. Resolve the redundancy of `security_lockdown_enabled` by choosing one authoritative field and updating all readers.
# 3. Add `>= 0` validation for `ToolConfig.progress_stagnation_window`.
# 4. Consolidate `MemoryConfig` validation logic into `MemoryConfig.__post_init__`.
# 5. Align `InjectionPolicy.min_importance` default with `MemoryConfig.memory_min_importance`.
# 6. Either move compression LLM parameters to `LLMConfig` or explicitly document them as fixed.
# 7. Update all corresponding docstrings and configuration loaders.
# Acceptance criteria:
# - No dead fields remain in configuration dataclasses.
# - One authoritative source for security lockdown settings.
# - All configured windows are validated upon instantiation.
# - Defaults are aligned across related configuration objects.
# - Compression parameters are either configurable or properly documented.
# Tests:
# - Unit tests for all configuration dataclasses ensuring correct validation and defaults.
# - Integration tests verifying configuration loading from `agent.toml`.
