## Background
The source issue (`issues/20260802-075026_mcp_audit_logging_contradiction_and_code_example_removal.md`)
reported a cross-file contradiction: `docs/04_mcp_02_03_audit-logging-and-errors.md` allegedly stated that
cicd-mcp and git-mcp use only `logging.getLogger` (no shared audit log), while
`docs/04_mcp_06_07_reading-audit-logs.md`'s table and actual source confirm both servers DO call the shared
`_audit_log()` function. The issue also asked to remove a "near-verbatim `dispatch_tool` code transcription"
from `02_03`, and to resolve rag-pipeline-mcp's audit-log status.

Verification against current source and current doc content (as of 2026-08-02) found:

1. **The specific cross-file contradiction no longer exists.** `docs/04_mcp_02_03_audit-logging-and-errors.md`
   currently contains no claim at all about cicd-mcp/git-mcp's audit-logging capability (grep confirms zero
   occurrences of "git-mcp" in that file; the only "cicd" mention is an unrelated `server_key` example value
   at line 33). This part of the issue appears already resolved by a prior commit
   (`1199aadcb docs: reconcile MCP audit logging and security policy documentation with actual implementation`).
2. **The `dispatch_tool` block in `02_03` (lines 83-90) is not a near-verbatim code transcription.** It is a
   6-line usage example (import + one call + return-value comment), not a copy of the actual ~30-line
   `dispatch_tool` implementation in `scripts/mcp_servers/dispatch.py` (lines 43-73, which includes name
   validation, dispatch-table lookup, and exception handling). No removal is warranted on accuracy grounds.
3. **rag-pipeline-mcp's audit-log status is already correct and consistent** in `06_07`: it is listed as not
   implementing audit logging in all three places it appears (the audit-log-layer table, the per-server
   audit-log-file table, and the "servers that write no audit log" list). This matches source — grep of
   `scripts/mcp_servers/rag_pipeline/` finds no `_audit_log` call, only plain `logging.getLogger`/`logger.info`
   usage. No change needed.
4. **However, the underlying factual defect has not been eliminated — it has relocated.** It now exists as a
   self-contradiction *within* `docs/04_mcp_06_07_reading-audit-logs.md` itself:
   - Lines 50-52 (a blockquote note) state: "cicd-mcp、git-mcp、mdq-mcp は共有audit logのみを使用する。
     cicd-mcp/git-mcp は `logging.getLogger(__name__)` のみを使用し、mdq-mcp は `_audit_log()` 経由で共有
     audit log...にJSON-linesで記録する。" — this asserts cicd-mcp/git-mcp use **only**
     `logging.getLogger(__name__)`, i.e. no shared audit log call.
   - This directly contradicts the same document's later, source-verified tables: the "サーバ別Auditログ
     レイヤー" table (lines ~69-82, showing cicd-mcp/git-mcp with `mcp_tool_exec` in "Layer2: 共有MCP") and the
     "サーバ別audit logファイル" table (lines ~84-97, showing cicd-mcp/git-mcp writing to
     `/opt/llm/logs/audit.log`（共有）in `JSON-lines（_audit_log() 経由）` format).
   - Confirmed against actual source: `scripts/mcp_servers/cicd/cicd_server.py` calls `_audit_log()` (import at
     line 31, call at line 100); `scripts/mcp_servers/git/git_server.py` calls `_audit_log()` (import at line
     32, call at line 128). Both servers DO write to the shared audit log via `_audit_log()`, in addition to
     using `logging.getLogger` for their own application-level logging.

## Problem
`docs/04_mcp_06_07_reading-audit-logs.md` contradicts itself: the note at lines 50-52 says cicd-mcp/git-mcp use
only `logging.getLogger(__name__)` and do not write to the shared audit log, while the tables later in the
same document (and actual source) confirm both servers do call `_audit_log()` and write to the shared
`/opt/llm/logs/audit.log`. A reader relying on the note in isolation (e.g., for a compliance/audit-coverage
review) would incorrectly conclude cicd-mcp and git-mcp are not audited via the shared log, undercounting
audit coverage — the same risk the original issue described, just now confined to a single file rather than
spanning two.

## Reason for change
This is a confirmed, still-present factual inaccuracy in currently-shipped documentation. The correct fact
(cicd-mcp and git-mcp both call the shared `_audit_log()`) is already established elsewhere in the same
document and matches source, so the fix is a targeted correction, not new research.

claiming they use only `logging.getLogger(__name__)`. Do not alter the correct table entries. Do not modify
