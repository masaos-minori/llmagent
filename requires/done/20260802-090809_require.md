# Add repository_gateway.py to the scripts-part1 responsibility table and extend the "変更時の注意点" pattern to services/ and workflow/

## Priority
Medium

## Target files
- `docs/01_overview-files-03-scripts-part1.md` (responsibility table for `scripts/agent/`, and its existing "変更時の注意点" section)
- `docs/01_overview-files-03-scripts-part3.md` (covers `scripts/agent/services/` and `scripts/agent/workflow/`; currently has no "変更時の注意点" section)

## Background
`docs/01_overview-files-03-scripts-part1.md` documents the `scripts/agent/` package with a responsibility table (§3, lines ~26-50) and a "変更時の注意点" (cautions when changing) section (lines 67-71) that calls out coupled-but-separately-located files that must be changed together, e.g.:
- `store.py` and `sql_constants.py` (session persistence schema)
- `tool_approval.py` and `repository_gateway.py` (tool approval flow)
- `retriever.py` and `scoring.py` (memory search algorithm)

This cautions section is a high-value pattern: it prevents implementers from editing one half of a coupled pair and missing the other. However:
1. `repository_gateway.py` (`scripts/agent/repository_gateway.py`) is referenced in the cautions section (line 70) but is absent from the responsibility table above it (lines 26-50), so a reader scanning only the table would not know this file exists.
2. `docs/01_overview-files-03-scripts-part3.md`, which documents `scripts/agent/services/` and `scripts/agent/workflow/` as a file tree (not a table), has no equivalent cautions section, even though at least one genuine coupled-change risk exists there.

## Problem
- The part1 responsibility table is incomplete: `repository_gateway.py` exists in source (`scripts/agent/repository_gateway.py`, verified present), implements the single write/delete/API-write enforcement boundary described in its own module docstring, and is already cited by name in the same document's cautions section — yet it has no row in the table itself. This undermines the table's claim to be a complete map of the package.
- The "変更時の注意点" pattern is confined to part1 even though at least the `workflow/` subdirectory (covered in part3) has a verifiable coupled-change pitfall that the same pattern would capture.

## Reason for change
The responsibility table is meant to be the first-stop reference for "what does this file do and where does it live." Omitting a file that is (a) live in source and (b) already important enough to be named in the cautions section is an internal inconsistency in the same document. Separately, the cautions pattern's value (verified above) is not diluted by extending it only where a real risk exists — doing so elsewhere increases the same protection this document already provides for `scripts/agent/`.

## Implementation intent
1. Add one row to the responsibility table in `docs/01_overview-files-03-scripts-part1.md` for `repository_gateway.py`, describing it as the single enforcement boundary for repository write/delete/API-write tool calls (policy preflight → execution → audit), consistent with its module docstring and class docstring in `scripts/agent/repository_gateway.py`. Do not remove or alter the existing cautions-section line that already mentions it.
2. Add a "変更時の注意点" section to `docs/01_overview-files-03-scripts-part3.md` (or the most relevant part file covering `workflow/`) documenting the verified coupling between `scripts/agent/workflow/idempotency_ops.py` and `scripts/agent/workflow/attempt_ops.py`: `idempotency_ops.begin_stage_if_new()` independently performs the same `INSERT INTO attempts (...)` that `attempt_ops.start_attempt()` performs, so a schema or logic change to attempt creation/the `attempts` table must be applied in both files or the two attempt-creation paths will diverge.
3. Do not add a cautions section for `scripts/agent/services/` unless a similarly concrete, source-verified coupling is identified; a plausible candidate (config schema changes touching `config_dataclasses.py`, `services/config_validators.py`, `services/typed_validators.py`, and `config_builders.py` together, per the comment at `scripts/agent/orchestrator.py:67-73`) exists but was not required to be added — evaluate and add only if the next phase confirms it meets the same "genuine, identifiable coupling" bar, per the issue's explicit instruction not to let this section become boilerplate.
