# DiagnosticStore bypasses StateStore layer for workflow queries

## Priority

Medium

## Target Files

- `scripts/agent/repl.py` — AgentREPL._persist_session_diagnostics()
- `scripts/agent/workflow/state_store.py` — StateStore

## Background

`_persist_session_diagnostics()` collects workflow statistics (task count, workflow count, approval events, retry count, artifacts) by querying `workflow.sqlite` directly using `SQLiteHelper("workflow")`.

## Problem

In `repl.py:158-194`:

```python
with SQLiteHelper("workflow").open(row_factory=True) as wdb:
    sid = str(session_id)
    rows = wdb.fetchall(
        "SELECT COUNT(*) as cnt FROM tasks WHERE session_id=?",
        (sid,),
    )
    task_count = int(rows[0]["cnt"]) if rows else 0
    ...
```

This opens a new database connection and executes raw SQL queries, bypassing the `StateStore` abstraction layer entirely. If `StateStore` holds uncommitted writes, the diagnostic summary will be inconsistent with the actual state.

Additionally, this approach duplicates query logic that should be encapsulated within StateStore.

## Reason for Change

Bypassing the StateStore layer breaks the abstraction boundary, risks data inconsistency, and makes it harder to maintain query correctness across the codebase.

## Implementation Intent

Route all workflow table queries through StateStore's public API. Add diagnostic-specific query methods to StateStore if they do not already exist.

## Implementation Instructions

1. Identify which StateStore methods are used by `_persist_session_diagnostics()`:
   - `get_task_by_session()` — for task count
   - `get_workflow_count()` — may need to be added
   - `get_approval_events()` — may need to be added
   - `get_retry_count()` — may need to be added
   - `get_artifacts()` — may need to be added
2. Either add missing methods to StateStore or refactor `_persist_session_diagnostics()` to use existing StateStore methods.
3. Remove the direct `SQLiteHelper("workflow")` connection from `_persist_session_diagnostics()`.
4. Ensure the StateStore instance passed to the diagnostics method reflects any pending writes.

## Acceptance Criteria

- [ ] DiagnosticStore uses StateStore API for all workflow queries
- [ ] Uncommitted StateStore writes are included in the diagnostic summary
- [ ] No direct SQLiteHelper connections to workflow tables outside StateStore
- [ ] Query logic is centralized in StateStore

## Tests

- Unit test: mock StateStore with pending writes; verify diagnostic summary includes them
- Integration test: verify diagnostic summary consistency between StateStore reads and direct SQL reads
