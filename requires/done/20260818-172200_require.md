# Title: [REQ] Clarify Workflow Execution and Define High-Risk Operation Approval Policy
# Priority: Medium
# Target files: docs/**/*.md, scripts/workflow/*.py, config files, ADRs
# Background: There is ambiguity regarding whether mandatory workflow execution implies mandatory human approval. Additionally, the production approval policy for high-risk operations is not sufficiently defined.
# Problem: 
# 1. Potential confusion between workflow execution (mandatory) and human approval (policy-driven).
# 2. Lack of explicit approval rules for high-impact operations (e.g., file modification, shell execution, git/github changes).
# 3. Undefined behaviors for approval lifecycle (rejection, expiration, cancellation, resumption).
# Reason for change: To prevent accidental bypasses or incorrect disabling of workflows and to ensure robust security through explicit approval policies.
# Implementation intent: Distinguish between mandatory execution/deployment and policy-based human approval, and formalize the latter for high-risk tasks.
# Implementation instructions:
# 1. **Clarify Terminology**: Explicitly separate "Mandatory WorkflowEngine Execution," "Mandatory Workflow-Definition Deployment," and "Policy-Controlled Human Approval" in all relevant documentation (Overview, Deployment, Agent, workflow, ADRs).
# 2. **Define Production Approval Rules**: Formally specify approval requirements for high-risk operations, including:
#    - File writes and deletions.
#    - Shell command execution.
#    - Git commits and pushes.
#    - GitHub changes.
#    - CI/CD execution.
#    - Database maintenance.
# 3. **Map Approval to Risk Tiers**: Associate specific approval requirements with predefined operational risk tiers.
# 4. **Specify Lifecycle Behaviors**: Define the expected system behavior for approval: rejection, expiration, cancellation, and resumption of pending approvals.
# 5. **Document Local Exceptions**: Specify permitted deviations for local development environments.
# 6. **Enforce via Config/Schema**: Ensure workflow definitions and configurations can effectively implement the documented approval policies.
# Acceptance criteria:
# - Clear distinction between mandatory execution and policy-based approval in all documentation.
# - Comprehensive production approval rules for all specified high-risk operation categories.
# - Defined mapping of approval requirements to risk tiers.
# - Documented behaviors for approval lifecycle events (rejection, expiration, etc.).
# - Documented local-development exceptions.
# - Workflow definitions/configs support enforcement of the documented policy.
# - Automated tests verify that required approvals are enforced for high-risk tasks.
# Tests:
# - Verification that startup fails if no workflow definition is present.
# - Testing various operation types (low vs. high risk) to confirm correct approval prompting/enforcement.
# - Simulation of approval lifecycle scenarios (rejection, expiration, cancellation, resumption).
# - Verification of local vs. production profile differences.
