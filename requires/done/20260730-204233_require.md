# Requirement: Clean Up Health Check Timestamps When Servers Are Removed

## Priority

Low — bounded memory leak proportional to number of configured servers; negligible impact in practice

## Target Files

- `scripts/agent/http_lifecycle.py` (line 173)

## Background

The `HttpServerLifecycleManager` tracks last health check timestamps in `_last_health_check` dictionary. These entries are cleared in `shutdown_all()` and `restart()`, but not when a server key is dynamically removed from the configuration (hot-reload scenario).

## Problem

When an MCP server is removed from `ctx.cfg.mcp.mcp_servers` via hot-reload, the corresponding entry in `_last_health_check` remains indefinitely. This creates a small memory leak proportional to the number of historically configured servers.

## Reason for Change

Ensure cleanup consistency — all tracked resources should be cleaned up when a server is removed, regardless of whether removal happens via shutdown, restart, or hot-reload.

## Implementation Intent

Add cleanup of `_last_health_check` entries when a server key is removed from the configuration.

## Implementation Instructions

1. Identify where server keys are removed from `ctx.cfg.mcp.mcp_servers` during hot-reload
2. Add cleanup logic that removes the corresponding entry from `_last_health_check`
3. Alternatively, add a method `_cleanup_server_resources(self, server_key)` that clears all tracking data for a given server key, and call it whenever a server is removed
4. Ensure this cleanup is called consistently across all removal paths

## Acceptance Criteria

- [ ] Removing a server from configuration also removes its `_last_health_check` entry
- [ ] Cleanup occurs regardless of removal path (shutdown, restart, hot-reload)
- [ ] No regression in existing behavior for active servers

## Tests

- Unit test verifying `_last_health_check` entry is removed when server key is deleted from config
