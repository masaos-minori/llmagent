# Deduplicate the implemented-feature summary table in docs/01_overview-arch-03-features.md against docs/01_overview-files-03-scripts-part*.md

## Priority
Medium

## Target files
- `docs/01_overview-arch-03-features.md` (section "2.5 実装済み機能サマリ", the table currently at lines 28-42)

## Background
`docs/01_overview-arch-03-features.md` §2.5 ("実装済み機能サマリ") contains a 13-row table mapping each implemented feature to specific implementation filenames (e.g. `agent/tool_runner.py`, `shared/tool_executor.py`, `agent/mdq_rag_classifier.py`). The same filenames are already documented, with fuller per-file responsibility detail, in the `docs/01_overview-files-03-scripts-part*.md` series (5 parts), which is the file-structure reference for `scripts/`. For example, `docs/01_overview-files-03-scripts-part1.md` already lists `tool_runner.py`, `tool_loop_guard.py`, `diagnostic_store.py`, and `mdq_rag_classifier.py` under the `scripts/agent/` directory breakdown.

Verification performed against current source (2026-08-02): the table still exists in its original filename-listing form at `docs/01_overview-arch-03-features.md` lines 28-42, and every filename in it was confirmed to still exist on disk under `scripts/` (e.g. `scripts/agent/tool_runner.py`, `scripts/shared/tool_executor.py`, `scripts/agent/memory/`, `scripts/agent/workflow/`, `scripts/db/`, `scripts/rag/pipeline.py`). The corresponding entries were confirmed present in `docs/01_overview-files-03-scripts-part1.md` (e.g. line 35: `tool_runner.py`, `tool_scheduler.py`, `tool_policy.py`, `tool_approval.py`; line 36: `tool_loop_guard.py`; line 43: `diagnostic_store.py`; line 44: `mdq_rag_classifier.py`, `mode_classification.py`). This issue is confirmed still applicable, not resolved by any other recent change.

## Problem
The feature-to-filename mapping is maintained in two places: the summary table in `01_overview-arch-03-features.md` and the file-structure tables in `01_overview-files-03-scripts-part*.md`. Per the project's Canonical Source Rule, file-level correspondence should have exactly one authoritative home. Today, any filename rename, split, or move requires updating both documents, and if only one is updated, the two documents will silently diverge (the summary table showing stale filenames while the file-structure doc has moved on).

## Reason for change
Reducing duplication lowers the ongoing maintenance burden for future file-level changes to any of the 13 listed features and removes the risk of the two documents drifting out of sync unnoticed.

## Implementation intent
Make `docs/01_overview-files-03-scripts-part*.md` the sole canonical source for file-level (filename-granularity) correspondence. Rewrite the §2.5 table in `docs/01_overview-arch-03-features.md` so each row maps feature name to directory name only (no individual filenames), and add a pointer from each row (or from the table as a whole, if all rows resolve to one part file) to the relevant `01_overview-files-03-scripts-part*.md` file for filename-level detail. Do not edit the `files-03-scripts-part*.md` files themselves — they are the target, not the source, of this change and are tracked separately.
