# Requirement: Validate MCP Server URLs Before Use

## Priority

Medium — invalid URLs produce opaque DNS resolution errors instead of clear validation errors

## Target Files

- `scripts/agent/http_lifecycle.py` (lines 180, 326)
- `scripts/agent/startup.py` (line 187)
- `shared/mcp_config.py` (where McpServerConfig is validated)

## Background

The URL is constructed without validation:

```python
url = cfg.url.rstrip("/") + "/health"
```

When `cfg.url` is empty or malformed:
- `"http://"` → `"http:///health"`
- Empty string → `"/health"`

Both result in DNS resolution errors that are confusing to debug.

## Problem

Invalid URLs cause opaque DNS resolution errors rather than clear configuration validation errors. This makes debugging difficult and delays identification of the root cause.

## Reason for Change

Provide clear error messages at startup time so configuration mistakes are immediately visible rather than surfacing as cryptic network errors later.

## Implementation Intent

Add URL format validation during configuration loading and fail fast with a clear error message if the URL is invalid.

## Implementation Instructions

1. Add URL validation in `McpServerConfig._validate_cross_fields()` (or equivalent validation method):
   ```python
   from urllib.parse import urlparse
   
   parsed = urlparse(cfg.url)
   if not parsed.scheme or not parsed.hostname:
       raise ValueError(f"MCP server '{key}': invalid URL '{cfg.url}' — scheme and hostname are required")
   ```

2. Ensure the validation runs before any HTTP client is created for this server

3. Include the server key in the error message for easy identification

## Acceptance Criteria

- [ ] Invalid URLs (empty, missing scheme, missing hostname) produce clear validation errors at startup
- [ ] Error message includes the server key for easy identification
- [ ] Valid URLs pass validation unchanged
- [ ] No regression in existing behavior for valid configurations

## Tests
