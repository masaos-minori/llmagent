# `tools/check_no_compat.py`'s `main()` crashes with `IsADirectoryError` when given a directory as a positional file argument

## Priority
Low

## Target files
- `tools/check_no_compat.py` (`main()`'s positional-file-argument handling, around line 215-221)
- `tests/tools/test_check_no_compat.py` (new test coverage)

## Background
`tools/check_no_compat.py` scans for backward-compatibility stubs/shims. Its `main()` supports
two invocation modes: no positional arguments (used by the `no-compat-stubs` pre-commit hook,
configured with `pass_filenames: false`), which builds a file list via `Path.glob("**/*.py")` /
`glob("**/*.md")` over a fixed `dirs_to_scan` list; and one or more positional file arguments
(`args.files`, `nargs="*"`), used for manual/targeted invocation.

## Problem
When `args.files` is non-empty, `main()` converts each entry directly to a `Path` (line 215) and
later calls `filepath.read_text(encoding="utf-8")` on it (line 221) with no `is_dir()` /
`is_file()` guard — only an `exists()` check (line 219), which is also true for directories.
Passing a directory (e.g. `scripts/`, `tools/`) as a positional argument therefore raises an
unhandled `IsADirectoryError` and exits with code 1, instead of either scanning the directory's
files or reporting a clear usage error.

Confirmed by direct execution against current source:
- `uv run python -m tools.check_no_compat tools/` → exit code 1, `IsADirectoryError: [Errno 21]
  Is a directory: 'tools'`, raised at `tools/check_no_compat.py:221`.
- `uv run python -m tools.check_no_compat scripts/` → same failure shape for `'scripts'`.

The no-args/pre-commit code path (lines 201-213) is a genuinely separate branch that only ever
yields real files via glob, so the `no-compat-stubs` pre-commit hook is unaffected by this bug.
`tests/tools/test_check_no_compat.py` (18 existing tests) has no test that passes a directory as
a positional argument or invokes `main()`/the module via `sys.argv`/subprocess with directory
args, so this scenario is currently uncovered.

## Reason for change
The tool's `--help`/usage does not document that positional arguments must be files, not
directories, and there is no guard against directory input. A user manually invoking the tool
with a directory — a natural thing to try, since the tool's default mode scans whole directories
— gets a raw traceback instead of a clear error or correct behavior.

## Implementation intent
Decide and implement one of two behaviors for a directory passed as a positional argument, and
document the choice:
1. Directory expansion: treat a directory argument like the default `dirs_to_scan` behavior —
   expand it to its contained `*.py`/`*.md` files via glob — so manual invocation with a
   directory works the same way the no-args pre-commit path does.
2. Explicit usage error: detect a directory argument up front and exit with a clear,
   non-traceback error message (e.g. via `argparse` type validation or an early check in
   `main()`), rather than letting `read_text()` raise.

Either choice must not alter the existing no-args/pre-commit behavior, and must not widen scope
into `ROOT_DIR`, `COMPAT_PATTERNS`, or `DEFAULT_ALLOWLIST` (addressed separately in
`plans/20260807-100914_plan.md`).

## Implementation instructions
1. Read `tools/check_no_compat.py`'s `main()` in full, focusing on the `args.files` branch
   (currently lines ~215-221).
2. Choose one of the two behaviors described in Implementation intent (directory expansion or
   explicit error) and implement it only in the positional-file-argument branch.
3. If choosing directory expansion: for each positional argument that is a directory, expand it
   using the same glob pattern (`**/*.py`, `**/*.md`) as the no-args path, and merge/deduplicate
   with any plain file arguments given alongside it.
4. If choosing explicit error: check `Path(f).is_dir()` for each positional argument before
   reading it, and if true, print a clear usage message (e.g. naming the offending path and
   stating that only files are accepted, or how to scan a directory) and exit with a non-zero
   status without an unhandled traceback.
5. Do not modify `ROOT_DIR`, `COMPAT_PATTERNS`, `DEFAULT_ALLOWLIST`, or the no-args
   `dirs_to_scan` glob logic.
6. Add a test to `tests/tools/test_check_no_compat.py` covering a directory passed as a
   positional argument, asserting the chosen behavior (either: files under the directory are
   scanned, or: a clean non-traceback error/exit code is produced — not an unhandled
   `IsADirectoryError`).
7. Run `uv run pytest tests/tools/test_check_no_compat.py -v`.

## Acceptance criteria
- `uv run python -m tools.check_no_compat <directory>` no longer raises an unhandled
  `IsADirectoryError`.
- The chosen behavior (directory expansion or explicit error) is implemented consistently and
  documented (e.g. in the tool's `--help` text or a comment on the `args.files` branch).
- A test exists in `tests/tools/test_check_no_compat.py` covering a directory passed as a
  positional argument, and it passes.
- The no-args/pre-commit invocation path (`dirs_to_scan` glob logic) is unchanged in behavior.
