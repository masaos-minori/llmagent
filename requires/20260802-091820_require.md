# Fix service-name-prefix naming drift and resolve the nonexistent db_fts.py reference in docs/01_overview-files-03-scripts-part5.md

## Priority
High

## Target files
- `docs/01_overview-files-03-scripts-part5.md` (the directory-tree block at approximately lines 27-82)

## Background
`docs/01_overview-files-03-scripts-part5.md` documents the file layout of five MCP server
subdirectories under `scripts/mcp_servers/`: `shell/`, `rag_pipeline/`, `cicd/`, `mdq/`, and
`git/`. The tree is a manually maintained enumeration of filenames with Japanese one-line
descriptions. Manually maintained trees drift from actual source structure over time as files
are renamed, added, or removed without a corresponding doc update.

## Problem
Verification against current source (`ls scripts/mcp_servers/{shell,rag_pipeline,cicd,mdq,git}/`)
confirms two confirmed defects in the doc:

1. **Generic-filename drift.** The doc lists the core quartet of each server as generic
   `server.py` / `service.py` / `tools.py` / `models.py`, but every one of the five
   subdirectories actually prefixes these four files with the service name. Actual current
   contents (verified 2026-08-02):
   - `scripts/mcp_servers/shell/`: `__init__.py`, `service_static_helpers.py`, `shell_models.py`,
     `shell_server.py`, `shell_service.py`, `shell_tools.py`, `subprocess_runner.py`
   - `scripts/mcp_servers/rag_pipeline/`: `__init__.py`, `document_manager.py`,
     `rag_pipeline_models.py`, `rag_pipeline_server.py`, `rag_pipeline_service.py`,
     `rag_pipeline_tools.py`
   - `scripts/mcp_servers/cicd/`: `__init__.py`, `cicd_models.py`, `cicd_server.py`,
     `cicd_service.py`, `cicd_tools.py`, `exception_handlers.py`, `service_business.py`,
     `service_defs.py`, `service_github_actions.py`, `service_github_actions_composite.py`,
     `service_github_actions_job.py`, `service_guards.py`, `service_init.py`
   - `scripts/mcp_servers/mdq/`: `__init__.py`, `__main__.py`, `audit_target.py`, `auth.py`,
     `db_grep.py`, `db_schema.py`, `health_check.py`, `index_delete.py`, `indexer.py`,
     `mdq_models.py`, `mdq_server.py`, `mdq_service.py`, `mdq_tools.py`, `parser.py`, `search.py`
   - `scripts/mcp_servers/git/`: `__init__.py`, `format_output.py`, `git_models.py`,
     `git_security.py`, `git_server.py`, `git_service.py`, `git_tools.py`

   The pattern is consistent: the core `server`/`service`/`tools`/`models` quartet is always
   service-name-prefixed (e.g. `shell_server.py`, `cicd_models.py`); auxiliary/helper modules
   (e.g. `subprocess_runner.py`, `document_manager.py`, `format_output.py`,
   `service_github_actions.py`) generally keep an unprefixed or partially-prefixed name. The
   documented tree does not reflect this.

2. **Nonexistent `db_fts.py` reference.** The doc lists `db_fts.py` under `mdq/` as "MDQ FTS
   データベース". This file was deliberately deleted in commit `74906389b` ("refactor: remove
   unsupported MDQ tool/search surface and stale tool-count doc check", 2026-07-16). Investigation
   findings (conclusive, not inconclusive):
   - The implementation record `implementations/done/20260716-131149_db_fts.py.md` confirms the
     file was fully deleted (whole-file deletion, 55 lines removed), not merged or renamed. Its
     two functions, `fts_consistency_check` and `fts_rebuild`, had no remaining callers once the
     companion `service.py` edit (in the same commit) removed the corresponding
     `MdqService.fts_consistency_check()` / `fts_rebuild()` methods.
   - `git show --stat 74906389b` confirms this same commit also trimmed `db_schema.py` (-37
     lines) and `search.py` (-60 lines) — but neither file gained the FTS functionality;
     the functionality was removed outright as part of eliminating an unsupported/undispatchable
     admin tool surface, not merged into a sibling module.
   - Only remnants of `db_fts.py` in the current tree are stale build artifacts: a `.pyc` file
     under `scripts/mcp/mdq/__pycache__/db_fts.cpython-314.pyc` (note: this is the old
     `scripts/mcp/` path, pre-dating the `scripts/mcp` → `scripts/mcp_servers` rename in commit
     `7ffa728ac`) and stale `.mypy_cache` entries. Neither reflects current source.
   - Conclusion: **`db_fts.py`'s FTS functionality was removed entirely, with no successor file.**
     `db_grep.py` and `db_schema.py` remain but do not carry the removed FTS logic — they are
     unrelated, pre-existing siblings that happen to share the `db_` prefix.

## Reason for change
The naming pattern mismatch spans all 5 documented subdirectories, making it a confirmed,
high-impact readability/trust problem for anyone using this doc as a map of the MCP server
source tree. The `db_fts.py` entry actively misleads: a reader following the doc would look for
a file that does not exist and has no successor, with no indication that FTS admin tooling was
intentionally removed as unsupported.

## Implementation intent
Replace the manually maintained, drift-prone directory-tree enumeration with a description of
the naming *convention* (service-name-prefixed core quartet, i.e. `<service>_server.py` /
`<service>_service.py` / `<service>_tools.py` / `<service>_models.py`) plus a pointer to the
actual source directories (`scripts/mcp_servers/{shell,rag_pipeline,cicd,mdq,git}/`) for the
authoritative, current file list — rather than re-enumerating filenames that will drift again.
For the `mdq/` subdirectory specifically, replace the `db_fts.py` line with a note that FTS
admin tooling (`fts_consistency_check`/`fts_rebuild`) was removed in commit `74906389b` as an
unsupported/undispatchable tool surface, with no successor file; `db_grep.py` and `db_schema.py`
remain but serve their original, unrelated purposes.

## Implementation instructions
1. In `docs/01_overview-files-03-scripts-part5.md`, remove the literal directory-tree code block
   (~lines 27-82) that enumerates every file per subdirectory with generic `server.py`/
   `service.py`/`tools.py`/`models.py` names.
2. Replace it with prose (not a maintained file-by-file tree) that:
   - States the naming convention: each server's core quartet is prefixed with the service name
     (`shell_server.py`, `shell_service.py`, `shell_tools.py`, `shell_models.py`;
     `rag_pipeline_server.py`, etc.; `cicd_server.py`, etc.; `mdq_server.py`, etc.;
     `git_server.py`, etc.), while helper/auxiliary modules in each directory may keep
     unprefixed names.
   - Points readers to `scripts/mcp_servers/{shell,rag_pipeline,cicd,mdq,git}/` as the
     authoritative source for the current, complete file list, rather than re-listing every
     filename in the doc.
   - Retains the per-server one-line role description and port number currently given in the
     subdirectory comments (`:8009` shell, `:8010` rag_pipeline, `:8012` cicd, `:8013` mdq,
     `:8014` git) since that information is not redundant with a directory listing.
3. Remove the `db_fts.py` line entirely and replace it with a short note (in the mdq section)
   stating that FTS admin tooling was removed in commit `74906389b` (unsupported/undispatchable
   tool surface eliminated), with no successor file — `db_grep.py` and `db_schema.py` are
   unrelated, pre-existing modules, not successors.
4. Do not add or move MCP server port-to-name mapping information into this file — a separate
   issue tracks consolidating that into `docs/01_overview-files-05-config.md`; this requirement
   is scoped to fixing the tree/db_fts.py drift only.
5. Do not touch any other `docs/01_overview-files-03-scripts-part*.md` file — this requirement is
   scoped to `part5.md` only.
