# Resolve the "Current Replacement" for the deprecated common.toml entry

## Priority

Low

## Target Files

- `docs/00_governance_05_deprecated-items.md` — common.toml entry
- `config/agent.toml` — current file that absorbed common.toml's role

## Background

- `docs/00_governance_05_deprecated-items.md` lists `common.toml` under
  "Deprecated Configuration Files" with `Current Replacement: none (replacement
  unknown)`, `Status: Needs confirmation`, and a note that it "May have been
  consolidated into area-specific configs."
- `issues/20260727_29_issue.md` (already processed) established that
  `common.toml` does not exist as a file anywhere in the repository — this was
  confirmed via a docstring correction in
  `docs/03_rag_02_04_ingestion_pipeline-ingester-part2.md:49`. That prior work
  confirmed non-existence but did not identify what replaced it.
- Source investigation for this issue confirms both facts directly:
  - `ls config/` shows no `common.toml` file; the directory contains only
    `agent.toml` and area-specific `*_mcp_server.toml` / pipeline config files
    (`chunk_splitter.toml`, `crawler.toml`, `eventbus.toml`, `ingester.toml`,
    plus the various `*_mcp_server.toml` files).
  - `config/agent.toml` lines 1-3 contain an explicit header comment:
    ```
    # agent.toml — agent process configuration
    # Previously split across: common, llm, http, rag, context, tools, memory, otel,
    # security, system_prompts, tools_definitions, and *_mcp_server transport sections.
    ```
  - Immediately below that header, `config/agent.toml` has a section literally
    titled `# ── Infrastructure (common) ──` (lines 5-18) containing
    `rag_db_path`, `session_db_path`, `sqlite_vec_so`, `embed_url`,
    `sqlite_timeout`, `sqlite_busy_timeout_ms`, `sqlite_wal_checkpoint_mode`,
    `sqlite_retention_max_sessions`, `sqlite_retention_max_age_days`,
    `sqlite_archive_dir`, `embedding_dims`, and `eventbus_db_path` — settings
    that are infrastructure-wide rather than specific to any single MCP
    server or pipeline area.
- `docs/00_governance_05_deprecated-items.md` also lists a second, related
  entry under "Deprecated Concepts" — **shared common config** — with the same
  `Current Replacement: none (replacement unknown)` status and the note
  "Config structure has evolved to area-specific files." The evidence found
  here answers that entry's underlying question too, but that entry is out of
  scope for this requirement (target file list above is scoped to the
  `common.toml` entry per the source issue); a future pass may want to update
  it using the same evidence.

## Problem

The deprecated-items doc explicitly flags the replacement for `common.toml`
as unknown and "Needs confirmation," even though the current codebase
contains direct, unambiguous evidence (a header comment plus a section
literally labeled "Infrastructure (common)") identifying `config/agent.toml`
as the consolidation target. Leaving the field unresolved forces readers to
re-derive this same conclusion from source every time the question comes up.

## Reason for Change

The "Needs confirmation" status is stale: the evidence needed to resolve it
already exists in `config/agent.toml`'s own header comment. Updating the
`Current Replacement` field closes out a tracked open question with no
remaining ambiguity, and keeps `docs/00_governance_05_deprecated-items.md`
accurate for future readers.

## Implementation Intent

Update the `common.toml` entry in
`docs/00_governance_05_deprecated-items.md` so that:
- `Current Replacement` names `config/agent.toml`, specifically its
  "Infrastructure (common)" section (and, more broadly, the fact that
  `agent.toml`'s header comment documents the full set of areas — common,
  llm, http, rag, context, tools, memory, otel, security, system_prompts,
  tools_definitions, and `*_mcp_server` transport sections — that former
  standalone config files (including `common.toml`) were split across).
- `Status` changes from "Needs confirmation" to "Confirmed" (or the
  document's equivalent resolved-status label).
- `Evidence` cites the `config/agent.toml` header comment (lines 1-3) and the
  "Infrastructure (common)" section (lines 5-18) as the concrete source-code
  basis, rather than "Requires source code investigation."

This is a documentation-only change; no source code or config files are to
be modified.
