# Document actual tooling usage of AI-reading-metadata fields in 00_governance_06

## Priority
Medium

## Target files
- `docs/00_governance_06_ai-reading-metadata.md`

## Background
`docs/00_governance_06_ai-reading-metadata.md` documents five "Existing Metadata Fields"
(`title`, `category`, `tags`, `related`, `keywords`) and eight "Recommended Additional
Fields" (`scope`, `audience`, `status`, `priority`, `version`, `last_updated`, `author`,
`completeness`) intended to help AI agents select relevant documents. However, the
document's own Non-Goals section explicitly states that "how AI agents parse or use
these metadata fields" is out of scope for the document, leaving readers unable to tell
whether any of these fields have real operational effect.

A repository-wide code search (`scripts/`, `tools/`) was performed as part of this
requirement's preparation and found:
- Only two scripts touch YAML frontmatter in `docs/*.md` at all:
  `tools/validate_docs_structure.py` and `tools/add_missing_frontmatter.py`. Both check
  only for the presence/validity of `title`, `category`, `tags`, and `related` — i.e.
  structural completeness checks, not document-selection logic.
- `scripts/mcp_servers/mdq/parser.py` additionally parses YAML frontmatter and extracts
  the `tags` field specifically as document-level tags (returned alongside parsed
  Markdown sections) — this is a real, working consumer of `tags`, though it is a
  generic Markdown/tag extraction utility, not an AI document-selection mechanism per se.
- None of the eight "Recommended Additional Fields" (`scope`, `audience`, `status`,
  `priority`, `version`, `last_updated`, `author`, `completeness`) appear anywhere in
  `scripts/` or `tools/` as a parsed/consumed frontmatter key. No script reads, filters,
  or ranks documents using any of these eight fields.
- The `keywords` field (from the "Existing" list) is not read from frontmatter by any
  script either; only a `## Keywords` **section** (body heading, not a frontmatter key)
  is required by `tools/validate_docs_structure.py`'s `check_tail_sections`.

## Problem
The document presents eight "Recommended Additional Fields" as if adopting them provides
value for AI agent document selection, but no tooling in the repository currently reads
or acts on any of them. Documentation authors following this guide may spend effort
maintaining metadata (e.g., keeping `priority`, `status`, `last_updated` accurate) that
has zero operational effect today, without being told so.

## Reason for change
Per `rules/coding.md` §"Documentation notes — Current behavior classification", a gap
between what a doc implies (these fields aid AI selection) and what the code actually
does (nothing consumes most of them) must be classified and resolved rather than left as
an unlabeled ambiguity. This is a documentation-fix case: the doc's own Non-Goals section
already disclaims defining usage, but it stops short of stating the current factual
reality, which is knowable and was verified by this requirement's investigation.

## Implementation intent
Add a short, factual statement to the "Recommended Additional Fields" section (and
optionally a brief note in "Existing Metadata Fields") of
`docs/00_governance_06_ai-reading-metadata.md` reporting the current tooling-usage
reality, based strictly on the code-search findings above. Do not add new tooling and do
not change the Non-Goals section's scope — only add a factual "current usage" statement
using existing repo conventions (plain prose; no unlabeled "Current behavior" framing,
per `rules/coding.md`).

     `priority`, `version`, `last_updated`, `author`, `completeness`) are currently
