# Risk Follow-up Issue Template (Canonical)

Use this exact Markdown structure for `issues/{timestamp}_risks.md` (or its
zero-padded-sequence variant) generated by `skills/issue-to-plan/workflow.md` Step 6,
when a Plan's Risk lacks a complete mitigation and needs separate follow-up beyond the
Plan's inline Risks section. This is a GitHub Issue Markdown document — one issue per
section when more than one Risk is filed together — not a `templates/issue.md`-shaped
Issue.

```markdown
# Risk follow-up: <one-line summary>

## Priority
High / Medium / Low

## Context
Background — what Plan/Requirement surfaced this Risk and why it was not fully
mitigated inline.

## Risk
Concrete description of what could go wrong and its consequence if left unaddressed.

## Suggested resolution
Concrete follow-up action(s) to mitigate or resolve the Risk.

## Traceability
- Workflow phase: issue-to-plan
- Source issue: `{path}`
- Source plan: `{path}`
- Generated at: {timestamp from date +%Y%m%d-%H%M%S}
```

## Field notes

- `Priority` reflects the Risk's follow-up urgency, not necessarily the source Plan's
  overall Priority.
- The `Traceability` fields here are a deliberately narrower subset of
  `templates/traceability.md`'s full field list (no `Source requirement`, `Source
  implementation procedure`, or `Related target files`) — this document traces back to
  exactly one Issue and one Plan, never to a target file set.
- Do not restate the Plan's full Risk description text in `Risk` — summarize the
  specific consequence that still needs a follow-up decision.
