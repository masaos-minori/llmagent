## Background
`docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md` section "3.1.4 Markdown Heading Chunking Behavior" (lines 113-118) already states that oversized sections "are further split using sentence-based chunking" and that Japanese content routed this way skips Sudachi normalization (line 118). Section "3.2 Splitting Strategies" (lines 134) adds that heading-chunked output always has `normalized_content = null` regardless of `lang`. `scripts/rag/ingestion/chunk_splitter.py`'s `_chunk_markdown_by_heading()` (lines 158-174) implements the exact mechanism: split the whole text at heading boundaries first (one pass), then for each resulting section — if it fits within `md_snippet_max_chars`, keep it as one chunk (discarding it if below `min_chunk`, per line 168-169's noise-discard check); if it exceeds `md_snippet_max_chars`, re-split that section specifically via `_chunk_english()` and append those sub-chunks instead. What is not yet connected explicitly: the fallback is per-section (not whole-document), sequential (heading split always runs first; sentence splitting is a second pass applied only to oversized individual sections), and sub-`min_chunk` sections are silently discarded rather than being an "edge case" left unmentioned.

## Problem
A developer reading section 3.1.4 knows oversized sections "are further split using sentence-based chunking" but not the mechanics: whether this happens per-section or restarts the whole document, whether `chunking_strategy` changes for the sentence-split portion, or what happens to sections that end up too small.

## Reason for change
Per the Issue's Impact: developers modifying chunking logic may not understand the interaction between strategies, and operators can't predict chunk sizes for large sections. Documenting the exact mechanism, grounded in the actual implementation, reduces this risk without inventing behavior beyond what the code does.

## Implementation intent
Add a subsection immediately after "3.1.4 Markdown Heading Chunking Behavior" (after line 118, before "### 3.2 Splitting Strategies" at line 119), stating: (1) the fallback triggers per-section — each heading-delimited section is checked against `md_snippet_max_chars` individually, not the document as a whole; (2) the two strategies combine sequentially, not in parallel — heading-boundary splitting always runs first across the entire text, and sentence-based splitting (`_chunk_english()`) is applied only as a second pass to whichever individual sections exceed the size limit; (3) chunk metadata: `chunking_strategy` remains `"heading"` for the overall Markdown source regardless of which sections fell back to sentence splitting (per line 134's "Heading chunking (`chunking_strategy="heading"`)... regardless of `lang`"); `normalized_content` stays `null` for both non-fallback and fallback sections; sections below `min_chunk` after either path are silently discarded as noise (per the existing noise-discard convention documented elsewhere in this same file, e.g. `config/chunk_splitter.toml`'s `min_chunk` description); (4) the known edge case already stated in section 3.1.4 (Japanese content loses Sudachi normalization when routed through heading chunking, including its sentence-split fallback portion).
