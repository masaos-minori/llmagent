## Background
`### Context Loader Pattern Validation` (lines 236-269) defines two concrete
checks — "Minimal loading, measured" and "Circular reference check" — each with
its own procedure. `#### Step 4: Validate the reorganization` (lines 373-389)
correctly says "Apply Validation and Context Loader Pattern Validation above",
but then adds "Additionally confirm the Context Loader Pattern still holds"
followed by five bullets (378-385) that mostly restate `### Validation`'s
ownership-boundary bullet (lines 229-232) rather than the two concrete
measurements actually defined in `Context Loader Pattern Validation`.

The source Issue for this Plan is filed under the label "Consolidate Context
Loader Validation," naming `Context Loader Pattern Validation` as the
counterpart being duplicated. Direct re-inspection (current session) confirms
the restatement in `Step 4` overlaps more with `### Validation`'s bullet (and,
transitively, with `### Deduplication Rules`' acceptance criteria — see the
H-002 plan) than with `Context Loader Pattern Validation`'s own two concrete
checks, which `Step 4` never actually restates — it only references them by
name.

## Problem
`Step 4`'s five-bullet "Additionally confirm..." list re-derives, in expanded
form, constraints already fully stated in `### Validation` (compressed) and in
`### Deduplication Rules`' acceptance criteria (see the H-002 plan). By the time
`Step 4` is reached, the same ownership-boundary check exists in three places,
and `Step 4` never references the two concrete measurements that `Context Loader
Pattern Validation` actually defines.

## Reason for change
- Maintenance risk: `Step 4`'s five bullets must be kept in sync with
  `Validation`'s bullet and `Deduplication Rules`' acceptance criteria by hand.
- Clarity risk: `Step 4` says "Apply Context Loader Pattern Validation above"
  and then lists bullets not actually drawn from that section, so a reader can
  mistake the five bullets for a summary of `Context Loader Pattern Validation`
  when they are not.
- Context cost: fixed per-invocation overhead from restating the same
  ownership-boundary check for a third time.

## Implementation intent
Keep `### Context Loader Pattern Validation` (236-269) as the authoritative
definition of its two concrete checks, unchanged. In `Step 4`, keep the existing
correct reference sentence and remove the five-bullet restatement, since it
duplicates `### Validation`'s ownership-boundary bullet rather than adding
instruction beyond what "Apply Validation... above" already covers. If any
bullet is found, during implementation, to state something genuinely absent from
both `Validation` and `Context Loader Pattern Validation`, keep that specific
bullet (or relocate it to its true home section) rather than deleting
information that exists nowhere else.

## Requirements

  it.
