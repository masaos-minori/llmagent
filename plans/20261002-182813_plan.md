## Background
Translating the ADRs to English (`langadr001`) replaced the full-width parentheses that
had been hiding some Known Issue IDs from `tools/check_known_deviation_sync.py`. The
checker matches an ID only when it is followed by whitespace, an em dash, or end of line
(`_ID_LOOKAHEAD_RE`); in the Japanese text IDs were followed by full-width punctuation
(for example `CI-003（`), so they were never checked. After translation the IDs are now
followed by ASCII `, `, so the checker scans them and finds no matching canonical entry.
The translation follows the user-approved decision to translate faithfully rather than to
format IDs to evade detection (implementation cycle for
`implementations/done/20261001-115707_03_docs_10_adr_ADR-003-runtime-tool-registry-routing-authority.md.md`).

The checker's canonical set (`tools/check_known_deviation_sync.py::discover_canonical_docs`)
is every `docs/*/_90_inconsistencies_and_known_issues.md` file plus the consolidated
`docs/00_governance/governance_03_issue-and-uncertainty-management.md`. No `*_90...`
files exist in this repository (post-reorg), so `governance_03` is the only real canonical
source. An ID is "dangling" when it lacks a `### <ID>` / `#### <ID>` heading in
`governance_03` (or a `*_90...` file). None of the four listed IDs currently has such a
heading.
