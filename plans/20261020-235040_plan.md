## Goal
Remove the twelve component classes and the `AgentREPL` facade that `scripts/agent/__init__.py` re-exports "for backward compatibility", so the package no longer exposes an alternate public import path for its submodules — but only after the owner confirms nothing outside the repository imports those twelve names from `agent`. Add a regression test that locks the removal so the re-exports and their import side effect cannot return unnoticed.

Medium

  - The sibling backward-compatibility items `requeue_event()`, `read_json_file()`, and the export `md` alias.

## Background
- Source: an investigation of the design documents dated 2026-10-20 listing backward-compatibility features. Every claim below was re-checked against current code on 2026-10-20.
- `scripts/agent/__init__.py` is 34 lines: twelve `from agent.<module> import <Name>` statements (lines 8-19) and a single `__all__` listing the twelve names (lines 21-34). Its docstring states it "Exports all component classes and the AgentREPL facade for backward compatibility". (Confirmed by code)
- No in-repository consumer imports any of the twelve names from the top-level `agent` package. Tests import directly from the canonical submodules (`from agent.resource_shutdown_coordinator import ResourceShutdownCoordinator`, `from agent.repl_input_loop import ReplInputLoop`, ...). A search of `scripts/`, `tests/`, and `docs/` finds no `from agent import <Name>` or `agent.<Name>` usage of the twelve names. (Confirmed by code: absence verified by search)
- No Agent document cites the facade as a public import path. (Confirmed by code: absence verified by search of `docs/`)
- The issue depends on `compat009`, which removes the Glossary citation of this docstring; removing the docstring here while `compat009` still cites it would leave a dangling reference.

## Problem
The package exposes two import paths for each component: the canonical submodule and the re-exported name on `agent`. The re-export path has no in-repository user, adds import side effects at package load, and is a public API surface whose external consumers cannot be seen from the repository. Keeping it past its useful life is dead surface area; removing it without confirming there is no external user risks breaking an operator script, plugin, or tool that imports `agent.AgentREPL` etc.

## Reason for Change
Dead public surface: twelve re-exports with zero in-repository users that still run import side effects on every `import agent`. Removing them narrows the package's public API to the canonical module paths. The risk is external consumers, which is exactly why the removal is gated on owner confirmation rather than on the in-repository reachability check alone.

## Implementation Intent
- Treat this as a guarded deletion. The in-repository evidence shows zero callers, but the removal is authorized only by the owner's confirmation of no external users. Until that is recorded, do not start the removal.
- Change only `scripts/agent/__init__.py` and the locking test. Do not add forwarding, aliases, or deprecation scaffolding.
- If any test, tool, or module fails because it relied on a removed name or the import side effect, fix that caller to import from the canonical module; do not restore the re-export.
- Preserve the runtime contract: the REPL, startup, and shutdown paths must work unchanged, including `python -m agent`.
