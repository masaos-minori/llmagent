## Goal
- Make all 43 currently-failing tests in `tests/agent/commands/test_agent_cmd_session.py`
  pass by converting them to `async def` and awaiting `cmd._cmd_session(...)`, so the
  test suite actually exercises `_cmd_session`'s coroutine body instead of discarding it
  unawaited.

## Priority
Medium

## Scope

  `async def test_...` (with the file's existing `@pytest.mark.asyncio` convention) and

- **Out-of-Scope**: Any change to `scripts/agent/commands/cmd_session.py`,

## Background
Commit `c9d564322` ("feat: implement per-server MCP health timeout, typed validators,
and session/message repo improvements") converted `_SessionMixin._cmd_session()`
(`scripts/agent/commands/cmd_session.py`) from `def` to `async def`. The same commit set
`is_async=True` on the `/session` `CommandDef` entry in
`scripts/agent/commands/command_defs_list.py`, so `registry.py`'s dispatcher
(`_invoke_handler`) already awaits `_cmd_session` correctly in production.
`tests/agent/commands/test_agent_cmd_session.py` was never updated after this
conversion.

## Problem
43 of the 52 test methods in `tests/agent/commands/test_agent_cmd_session.py` call
`cmd._cmd_session(...)` synchronously from a plain `def test_...` method. This creates a
coroutine object that is never awaited, so its body never executes, and every
assertion checking captured output or mock call counts fails identically regardless of
which `/session` subcommand the test targets.

## Reason for change
The 43 failing tests leave the entire `/session` command family without working test
coverage, even though the production command itself is confirmed correct. This blocks
confident verification of any future change to session command behavior.

## Implementation intent
Convert each of the 43 failing test methods to `async def`, add the file's existing
`@pytest.mark.asyncio` marker convention, and add `await` at each
`cmd._cmd_session(...)` call site. This is a mechanical, repeated pattern — no
assertion, fixture, or mock setup needs to change beyond the async conversion itself.

## Assumptions
- The two currently-passing synchronous tests in `TestCmdSessionRecover`
  (`test_recover_with_backup_path`, `test_recover_error_raises`) are intentionally left
  unconverted: they are not part of the 43 confirmed-failing tests, and the Issue's Out

  substitutes an `AsyncMock` (Python 3.8+ behavior) rather than a plain `MagicMock`, so
  awaiting the mocked call inside `_session_load_safe` will not raise after the test
  conversion — confirmed by reading `_load_session`'s `async def` signature; this
  assumption is re-verified empirically by Implementation step Phase 2's per-class
  `pytest` run.

## Design
Path A classification (see Routing below) applies: the change touches exactly one file,
introduces no public/runtime-facing interface change, and no database schema change.

Direct verification (Step 3) confirmed the full causal chain end to end:
`_cmd_session` is `async def` in `cmd_session.py`; the `/session` `CommandDef` in
`command_defs_list.py` already sets `is_async=True`; `registry.py`'s `_invoke_handler`
already awaits the handler whenever `cmd.is_async` is true — so production dispatch is
unaffected and already correct. Running
`uv run pytest tests/agent/commands/test_agent_cmd_session.py -q` reproduced exactly
"43 failed, 9 passed", matching the Issue's claim precisely. The 9 passing tests split
into 7 pre-existing `async def` tests (in `TestGenerateSessionTitle*`, already using
`@pytest.mark.asyncio`, unaffected by this bug since they do not call `_cmd_session`)
and 2 synchronous `TestCmdSessionRecover` tests that pass only because they wrap the
call in a broad `try/except Exception: pass` (see Assumptions) — both are out of scope
per the Issue.

The conversion is mechanical: within `_cmd_session`, the only internally-awaited call is
`_session_load_safe` → `_load_session` (used by the `load` subcommand only); all other
subcommand branches call synchronous helper methods directly. `_load_session` is itself
`async def`, and `unittest.mock.patch.object` auto-substitutes an `AsyncMock` for a
patched async function, so awaiting the mocked call after conversion will not raise.
No fixture or mock-type change is required beyond adding `async`/`await` and the marker.

## Risks
- **Risk**: A mechanical async conversion applied across 43 methods by hand risks an
  indentation, decorator-placement, or missed `await` copy-paste error in one or more
  methods → **Mitigation**: convert and verify one test class at a time (Implementation
  step Phase 2), running that class's tests immediately after each conversion rather
  than converting all 43 methods before running anything.
- **Risk**: `tests/agent/commands/` has 17 pre-existing, unrelated test failures
  (`test_cmd_config_char.py`, `test_cmd_skill.py`, `test_agent_rag.py`) recorded in this
  Plan's baseline run → **Mitigation**: T-2/Phase 3's directory-level regression check
  compares against the recorded `60 failed, 348 passed` baseline, not against zero
  failures, so these pre-existing failures are not mistaken for a regression introduced
  by this change.
- **Risk**: `pyproject.toml` sets `asyncio_mode = "auto"`, under which
  `@pytest.mark.asyncio` is redundant; a future `pytest-asyncio` upgrade could change
  strict/auto mode interaction → **Mitigation**: match the file's own existing,
  already-passing convention (explicit marker on all 7 current `async def` tests) rather
  than introducing a second convention; Phase 3's full-file test run will surface any
  marker-related warning immediately.
