## Reason for change
A negative-only instruction tells an AI agent what not to do but leaves the correct
action to be inferred, risking incorrect improvisation or unnecessary hesitation. Every
prohibition in these files guides autonomous agent behavior, so each should resolve to
a concrete next action, not only a boundary.

## Implementation intent
For each confirmed bullet, add the positive-form alternative in the same sentence or
the immediately following sentence, matching the phrasing style of existing good
examples already in the repository (`rules/ai-execution.md` Context Reading; `skills/
python-design/SKILL.md`; `skills/python-code-review/SKILL.md`). Do not restructure,
reorder, or reword the existing prohibition — this is an additive, minimal-diff change
per file.

## Design
This is a Path B classification (9 claimed target files > 3, before Step 2's
correction reduced the actual modification scope to 8 — Path B classification is
retained since it was determined at Step 3 before the correction, and 8 still exceeds
the Path A threshold of ≤3).

`rules/ai-execution.md` and `rules/workflow-lifecycle.md` are each referenced by over
100 other repository files (Dependency graphing, Step 3), so edits to these two files
must be strictly additive (a short clause appended to an existing bullet) — no
restructuring, reordering, or heading changes, consistent with the Issue's own
Constraint. All 8 files show high recent churn as a set (32 commits in the last 30
days) and a single dominant author (bus factor risk if that author is unavailable, but
not a blocker for this additive, low-risk change). No architecture, dependency-graph,
or operational-dependency tooling from `workflow-path-b.md` (`grimp`, `pyan3`,
`lint-imports`, `lsof`, `pip-audit`) applies — all 8 target files are Markdown
documentation, not Python source under `scripts/`, so the Path B toolchain's
Architecture analysis and Operational dependency inspection commands have no valid
target; `rg`-based cross-reference counting (Dependency graphing) and `git log`-based
churn (Historical analysis) were used instead, as the closest applicable analog for a
documentation-only Plan.

Each edit follows the same micro-pattern: keep the existing "Do not X" / "MUST NOT X" /
"Never X" clause verbatim, and append " — instead, {alternative}" or a new trailing
sentence stating the alternative, mirroring whichever of the three cited good examples
best fits that bullet's grammar (inline em-dash clause vs. separate sentence).
