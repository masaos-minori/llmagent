## Background
The Issue's cited claim
(`docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md:50,125`: "`CrawlFilePayload`
and `ChunkOutputPayload` are declared as types in `chunk_splitter.py`, but they
are not used as type annotations in the actual implementation within the same
file") is quoted accurately from the document, but the underlying facts do not
hold.

**Re-verified 2026-09-13** (this cycle): neither `CrawlFilePayload` nor
`ChunkOutputPayload` exists anywhere in the repository (confirmed via `rg
"CrawlFilePayload|ChunkOutputPayload" scripts/` — no match). The actual
`TypedDict` classes with similar purposes are `CrawlJsonPayload` and
`ChunkJsonPayload`, both defined in `scripts/rag/ingestion/pipeline_utils.py`
(lines 23-34, 36-49) — **not** `chunk_splitter.py`. Their usage status also
differs from the Issue's claim:
- `CrawlJsonPayload` **is** used as a type annotation — confirmed at
  `scripts/rag/ingestion/crawl_persister.py:71,119`
  (`payload: CrawlJsonPayload = {...}`), imported explicitly at line 20/36. The
  Issue's premise that this class is unused does not hold.
- `ChunkJsonPayload` is genuinely **not** used as a type annotation anywhere —
  `chunk_splitter.py`'s `_build_chunk_payload()` (lines 274-292), which
  constructs an equivalent chunk-output dict, is annotated to return
  `dict[str, object]` (line 281), not `ChunkJsonPayload`. Confirmed technical
  reason: `_build_chunk_payload()`'s return statement uses `**metadata` to
  unpack a separate `ChunkMetadata` TypedDict into the result dict (line 287,
  `**metadata`) alongside additional literal keys — combining `TypedDict`
  unpacking with additional keys in a dict literal is not something current
  static type checkers can verify against a strict `TypedDict` return
  annotation, making `dict[str, object]` the practically necessary return type
  here.

This document's duplicate-section structure (already tracked by a sibling Plan,
`plans/20260913-202903_plan.md`) means this same incorrect Typed dict
table/Evidence note appears twice — once in `## 3.` (lines 42-50) and once in
`## 3a.` (lines 117-125), byte-for-byte identical.

## Problem
The documentation misidentifies both TypedDict classes by name and file, and
makes an incorrect blanket claim that both are unused — when one
(`CrawlJsonPayload`) is actively used and the other (`ChunkJsonPayload`) is not,
for a specific, confirmable technical reason the Issue's evidence note does not
mention.

## Reason for change
Correct the class names and defining file, and replace the blanket "not used"
claim with the accurate per-class status and the confirmed technical reason
`ChunkJsonPayload` specifically cannot be used as a strict return-type
annotation given its construction via `**metadata` unpacking.

## Implementation intent
In both duplicate "Typed dict" sections (lines 42-50, 117-125): (1) rename
`CrawlFilePayload`→`CrawlJsonPayload` and `ChunkOutputPayload`→`ChunkJsonPayload`
throughout the table and Evidence note; (2) correct the defining file from
`chunk_splitter.py` to `pipeline_utils.py`; (3) replace the blanket "not used as
type annotations" claim with the accurate distinction: `CrawlJsonPayload` is used
as a type annotation in `crawl_persister.py`; `ChunkJsonPayload` is not, because
`_build_chunk_payload()`'s return value combines `**metadata` unpacking with
additional literal keys, which is incompatible with a strict `TypedDict` return
annotation under current type-checker support.
