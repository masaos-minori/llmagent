## Goal

Eliminate race conditions between signal handlers and the main REPL loop by adding proper synchronization for shared state updates and ensuring complete resource cleanup regardless of service availability.

## Scope

**In-Scope:**
- Modify `_sigterm_handler()` to check and clear `self._turn_active` flag before setting shutdown flags
- Add guard in `_close_resources()` that verifies `self._turn_active` is False before skipping service-dependent cleanup
- Document behavioral differences between Unix (`add_signal_handler`) and Windows (`call_soon_threadsafe`) signal handlers
- Ensure shutdown state consistency across all code paths

**Out-of-Scope:**
- Adding new signal types beyond SIGTERM/SIGINT
- Changing subprocess termination behavior
- Modifying WAL checkpoint logic
- Cross-platform signal handler implementation changes

## Assumptions

1. Signal handlers run in the same thread as the asyncio event loop (both Unix and Windows paths)
2. Setting `shutdown_requested = True` from within the event loop is safe (no additional locking needed)
3. The `_turn_active` flag should be checked atomically — if True, the signal handler should wait for the turn to complete before proceeding with shutdown
4. Resource cleanup must always occur, even if services are already None
