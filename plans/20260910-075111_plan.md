# Consolidate DLQ promotion paths and remove obsolete code

## Goal

Keep one authoritative implementation for each DLQ use case. Inline promotion and recovery sweep may remain separate entry points, but they must share the same state-transition and persistence logic. Unsupported duplicate code should be removed.

## Priority
Medium

## Scope
- **In-Scope**: Confirming that `promote_to_dlq()` has no supported runtime caller; removing `promote_to_dlq()` if so; extracting shared promotion logic used by the inline (`promote_single`) and sweep (`sweep_orphans`) paths where appropriate; aligning `sweep_orphans()`'s safer `dlq_at IS NULL` re-run guard into whatever shared helper is extracted; preserving atomic file creation (`_atomic_write()`) and conditional database update behavior; updating the three test files currently calling `promote_to_dlq()` directly; updating current-specification documentation.
- **Out-of-Scope**: DLQ requeue real-redelivery redesign (EB-H03). Changing the DLQ file format or `_atomic_write()`'s mechanism itself.

## Background

Confirmed by direct read of `scripts/eventbus/dlq.py`: `promote_to_dlq()` (lines 47-77) and `sweep_orphans()` (lines 80-111) are near-duplicates — both select `WHERE delivery_failure_count >= ? AND dlq_at IS NULL` and both call `_atomic_write()` then update `dlq_at`; the only functional difference is that `sweep_orphans()`'s `UPDATE` includes an extra `AND dlq_at IS NULL` guard (line 104) making it safely re-runnable, while `promote_to_dlq()`'s `UPDATE` (line 66) has no such guard. `promote_single()` (lines 114-147) is the third, distinct inline-promotion path actually wired into `ack_route.py`'s `nack()` (line 92, via a local `from eventbus.dlq import promote_single` import).

## Problem

Runtime code uses `promote_single()` for inline promotion and `sweep_orphans()` as a safety sweep, while `promote_to_dlq()` duplicates batch-promotion behavior with no runtime caller. Retaining three overlapping implementations increases the chance that a future fix to the promotion/write logic is applied to one path but not the others — `promote_to_dlq()`'s already-weaker `UPDATE` guard (missing the `dlq_at IS NULL` re-run safety that `sweep_orphans()` has) is itself an example of this drift.

## Reason for change

Keep one authoritative implementation for each DLQ use case. Inline promotion and recovery sweep may remain separate entry points, but they must share the same state-transition and persistence logic. Unsupported duplicate code should be removed.

## Implementation intent

Confirm (already done for this issue, but re-verify at implementation time) that `promote_to_dlq()` has no supported runtime caller, and remove it if so — updating or removing the tests that currently exercise it directly (`test_eventbus_dlq.py`, `test_eventbus_dlq_promotion.py`, `test_eventbus_requeue_edge_cases.py`) rather than leaving them referencing a deleted function. Extract the shared row-select/atomic-write/DB-update logic common to `sweep_orphans()` and `promote_single()` into one internal helper both call, so a future fix to that shared logic cannot land in one path without the other.

## Design

### Task-size classification: Path B

### Architecture analysis

The EventBus currently has three independent DLQ promotion paths:
1. **Inline promotion**: `promote_single()` — called from `ack_route.py`'s `nack()` when retry threshold is exceeded.
2. **Safety sweep**: `sweep_orphans()` — called from `app.py`'s `_dlq_loop` periodically.
3. **Batch promotion**: `promote_to_dlq()` — unused in runtime code, only referenced in tests.

The critical issue is that there is no shared logic between these paths — a future fix to the promotion/write logic could land in one path without the other, creating inconsistency.

### Dependency graphing

```
FastAPI routing ──► nack() ──► _nack_and_promote() ──► promote_single(db, dir, event_id)
   │                    │              │                        │
   │                    │              │                        ├──► SELECT ... FROM events WHERE event_id = ? AND dlq_at IS NULL
   │                    │              │                        ├──► _atomic_write(deadletter_dir, event_id, record)
   │                    │              │                        └──► UPDATE events SET dlq_at = ? WHERE event_id = ? AND dlq_at IS NULL
   │                    │              │
   └──► get_db()        │
   └──► get_config()    │

Periodic ──► _dlq_loop() ──► sweep_orphans(db, dir, max_retry)
   │                    │              │
   │                    │              ├──► SELECT ... FROM events WHERE delivery_failure_count >= ? AND dlq_at IS NULL
   │                    │              ├──► _atomic_write(deadletter_dir, event_id, record)
   │                    │              └──► UPDATE events SET dlq_at = ? WHERE event_id = ? AND dlq_at IS NULL
   │                    │
   └──► get_db()        │
   └──► get_config()    │
```

After refactoring, the flow becomes:
```
FastAPI routing ──► nack() ──► _nack_and_promote() ──► _promote_to_dlq(db, dir, event_id)
   │                    │              │                        │
   │                    │              │                        ├──► SELECT ... FROM events WHERE event_id = ? AND dlq_at IS NULL
   │                    │              │                        ├──► _atomic_write(deadletter_dir, event_id, record)
   │                    │              │                        └──► UPDATE events SET dlq_at = ? WHERE event_id = ? AND dlq_at IS NULL
   │                    │              │
   └──► get_db()        │
   └──► get_config()    │

Periodic ──► _dlq_loop() ──► _promote_batch(db, dir, max_retry)
   │                    │              │
   │                    │              ├──► SELECT ... FROM events WHERE delivery_failure_count >= ? AND dlq_at IS NULL
   │                    │              ├──► _atomic_write(deadletter_dir, event_id, record)
   │                    │              └──► UPDATE events SET dlq_at = ? WHERE event_id = ? AND dlq_at IS NULL
   │                    │
   └──► get_db()        │
   └──► get_config()    │
```

Key dependencies:
- `dlq.py` must extract shared promotion logic into internal helpers.
- `ack_route.py` must call the new shared helper instead of `promote_single()`.
- `app.py` must call the new shared helper instead of `sweep_orphans()`.
- The shared helper must preserve the `dlq_at IS NULL` re-run safety guard.

### Historical analysis

- The `promote_to_dlq()` function was likely created early for batch promotion but never wired into runtime code.
- The `sweep_orphans()` function was added later as a safety-net sweep, with the safer `dlq_at IS NULL` guard.
- The `promote_single()` function was added for inline promotion on nack threshold.
- No prior attempt to consolidate these paths exists — this is the first effort.

### Operational dependency inspection

- Removing `promote_to_dlq()` means that any external tooling or scripts that depend on it will break — this is a breaking change for such users.
- Extracting shared logic means that future fixes to the promotion/write logic will automatically apply to both inline and sweep paths — this is a positive change for consistency.
- The `dlq_at IS NULL` re-run safety guard should be applied uniformly across all promotion paths — this prevents double-promotion of the same event.

### Design decisions

1. **Remove `promote_to_dlq()` (REQ-001)**: Remove the function entirely since it has no runtime caller. Update the three test files that reference it directly to retarget their assertions to the surviving function(s).

2. **Extract shared promotion logic (REQ-002)**: Create an internal helper `_promote_event(db, deadletter_dir, event_id, now)` that encapsulates:
   - Row selection (`SELECT ... FROM events WHERE event_id = ? AND dlq_at IS NULL`)
   - Atomic file writing (`_atomic_write(deadletter_dir, event_id, record)`)
   - Conditional DB update (`UPDATE events SET dlq_at = ? WHERE event_id = ? AND dlq_at IS NULL`)

3. **Align `dlq_at IS NULL` guard (REQ-003)**: Apply the `dlq_at IS NULL` re-run safety guard uniformly across all promotion paths — both inline and sweep.

4. **Preserve atomic write behavior (REQ-004)**: Preserve `_atomic_write()` behavior exactly — temp file + rename for atomicity.

5. **Update tests (REQ-005)**: Update the three test files to stop referencing `promote_to_dlq()` directly, retargeting assertions to the surviving function(s).

6. **Documentation update (REQ-006)**: If any documentation describes `promote_to_dlq()` as a supported entry point, correct it to reflect the consolidated inline/sweep model.
