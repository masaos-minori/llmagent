## Background
- Commit `1c13637ea` ("per-consumer NACK idempotency + 4-tuple ack contract") made `ack_event_for_consumer()` return `(found, newly_acked, seq, dlq)` so the ACK route could answer HTTP 409 for an event already in the DLQ. This implemented REQ-005 of the approved plan `plans/done/20261008-160952_plan.md` ("return 409 for DLQ events", "DLQ event ACK rejected (test)") and was recorded in the Execution Status of `implementations/done/20261009-071937_02_scripts_eventbus_ack_route.py.md` ("ACK path returns 409 via `ERR_EVENT_IN_DLQ` when `dlq=True`").
- Later commits `7e5e3d750` and `b5663a371` rewrote the delivery repository. The function now returns three values, the DLQ case returns `(True, False, None)`, and the ACK route no longer checks the DLQ. Six tests still unpack four values.
- `docs/24_eventbus/eventbus_12_ack_nack_endpoints.md` documents the ACK result as a 3-value contract; its 409 section appears only under NACK, so no document specifies the ACK-on-DLQ behavior.
- The pending procedure `implementations/20261011-080000_01_delivery_repo_fix_test_failures.md` (source plan `plans/20261008-160952_plan.md`) rewrites the same 4-value unpack sites to 3 values and treats the 3-value contract as intentional, citing removal of an `already_acked` flag. It does not mention the lost DLQ 409.

## Problem
- Six tests fail with `ValueError: not enough values to unpack (expected 4, got 3)`: four in `tests/eventbus/test_eventbus_offsets.py` and two in `tests/eventbus/test_eventbus_restart_resume.py`.
- The issue assumed the DLQ case is distinguishable from "already acked" by `seq is None`. It is not: the already-acked path also returns `(True, False, None)` because `seq` is assigned only inside the `newly_acked` branch. The route therefore cannot derive the DLQ case from the return value.
- `_do_ack` in the ACK route has no DLQ check. A DLQ-event ACK reaches the already-acked branch and returns HTTP 200 `{acked: true, already_acked: true, seq}`, contradicting the approved REQ-005 intent. No test covers this.
- The ACK UPSERT in `ack_event_for_consumer()` is `acked = COALESCE(consumer_delivery.acked, excluded.acked)`, but `consumer_delivery.acked` is `INTEGER NOT NULL DEFAULT 0`, so a pre-existing pending row (`acked = 0`) is never updated to `1`. A duplicate ACK is then reported as newly acked, and a later NACK from the same consumer is not rejected. Verified in a scratch worktree: replacing `COALESCE` with `MAX(consumer_delivery.acked, excluded.acked)` makes five more eventbus tests pass (`test_ack_event_with_consumer_id`, `test_ack_event_already_acked`, `test_ack_repeated_returns_200_already_acked`, `test_nack_http_409_on_per_consumer_acked`, `test_concurrent_ack_same_event`). The pending procedure `implementations/20261011-080000_01_delivery_repo_fix_test_failures.md` instead plans to remove the `already_acked` assertions from those tests, which would hide this defect.
- The docstring of `ack_event_for_consumer()`, the endpoint documentation, and `TestConsumerOffsetsTable::test_offset_does_not_regress_on_older_seq` (`assert seq3 is not None` after a duplicate ACK) all state that an already-acked event returns `(True, False, seq)`, but the code returns `seq = None` there because `seq` is assigned only inside the `newly_acked` branch. Fixing only the unpack arity would leave that test failing, so the code, not the tests, must change. The docstring also omits the DLQ case.
- `test_resume_from_sqlite_offset` in `tests/eventbus/test_eventbus_restart_resume.py` (currently skipped) also contains two 4-value unpack sites and is updated with the six failing tests for consistency.

## Reason for change
- The eventbus suite is red on `master` (16 failures, 6 in scope), which hides further regressions.
- The ACK contract is a boundary between the delivery repository, the ACK route, and the tests; the unresolved mismatch has already silently lost the approved DLQ 409 behavior.

## Implementation intent

- Change the tests first in one commit and the implementation in a separate commit, as the issue requires. The new DLQ-ACK route test is part of the implementation commit because it fails until the route is changed.

## Design
- **Decision (REQ-001)**: keep the 3-value return `(found, newly_acked, seq)` and handle the DLQ case in the route. Rationale: (1) the approved intent of REQ-005 in `plans/done/20261008-160952_plan.md` is the 409 behavior, not the 4-value shape; (2) the three-value form is used by the route, the other tests (`test_eventbus_ack_nack.py`, `test_eventbus_crash_ack.py`, `test_eventbus_subscribe.py`), the reference API table, and the endpoint documentation, so restoring four values would touch more files; (3) the NACK path already reads `events.dlq_at` in the route to choose 409, so the ACK path follows the same pattern.
- **`seq` for already-acked (found during procedure generation)**: the docstring, the endpoint documentation, and `test_offset_does_not_regress_on_older_seq` all expect `(True, False, seq)` for a duplicate ACK, but the code leaves `seq` as `None`. The repository function is changed to look up `seq` regardless of `newly_acked`; only the offset UPSERT stays inside the `newly_acked` branch, so the offset still never moves backward and INV-16 atomicity is untouched. The DLQ case keeps returning `(True, False, None)`.
- **Why the return value alone is not relied on for DLQ**: in the current code both the DLQ case and the already-acked case return `(True, False, None)`, so the issue's `seq is None` statement is incorrect today. After the `seq` fix above they differ, but the route still reads `events.dlq_at` explicitly, matching the NACK path.
- **UPSERT fix (REQ-007)**: replace `COALESCE(consumer_delivery.acked, excluded.acked)` with `MAX(consumer_delivery.acked, excluded.acked)` in the ACK UPSERT. `acked` is a NOT NULL boolean, so `MAX` keeps an existing `1` and turns a pending `0` into `1`; no schema change. The decision of newly-acked versus duplicate still reads the existing row before the write.
- **Route change**: in `_do_ack`, after the `found` check and for a non-new ACK, read `seq` and `dlq_at` for the event in one locked query; raise HTTP 409 with `ERR_EVENT_IN_DLQ` when `dlq_at` is set, otherwise keep the current already-acked response. The repository function is unchanged apart from its docstring, so the single-transaction UPSERT and offset advancement (INV-16) is untouched.
- **Commit split**: the six tests (REQ-002) go in one commit; the docstring, route, new test, and documentation (REQ-003 to REQ-006) go in a separate commit.
- **Path classification**: Path B. The Plan has six target files (more than three) and changes the runtime-facing HTTP behavior of the ACK endpoint. Path B analysis results: `lint-imports` could not run (`Could not find package 'agent'` in this environment); `radon` and `vulture` are not installed and were skipped; `bandit -q -r scripts/eventbus` completed with no new findings recorded for the targets; the dependency graph shows `scripts/eventbus/db.py` as the only importer of `delivery_repo.py` plus lazy imports in `ack_route.py` and `subscribe_route.py`.
