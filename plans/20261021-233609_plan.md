## Background
`startup.py` defines:
```python
def _classify_memory_failure(self, exc: Exception) -> str:
    return self._prompt_setup._classify_memory_failure(exc)
```
This is `StartupOrchestrator._classify_memory_failure` (`startup.py:139-140`), a pure delegation to `self._prompt_setup._classify_memory_failure`. The authoritative classifier is `PromptSetup._classify_memory_failure` (`startup_prompt_setup.py:36`), called from `PromptSetup.setup_prompt()` (`startup_prompt_setup.py:82`). A repo-wide search for `_classify_memory_failure` returns only: the definition+body in `startup.py`, the live definition+call in `startup_prompt_setup.py`, and a docstring reference in `startup_validation.py:34`. No caller invokes `StartupOrchestrator._classify_memory_failure`.

## Problem
Dead code that forwards to another method invites confusion about which classifier is authoritative and accumulates maintenance burden. If the delegation target signature changes, this method silently breaks without any test covering it.

## Reason for Change
Removing it eliminates an unused forwarding shim and removes a symbol that implies a second classification path exists. The real classifier remains reachable through `PromptSetup`.
