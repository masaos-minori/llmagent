## Goal
- Correct the tool-routing documentation so that no current specification describes
  a `ToolRouteResolver.server_configs` backward-compatibility argument that no
  longer exists in code, and so that `RuntimeToolRegistry` (routing authority),
  static `ToolRegistry` (drift-validation input), and `ToolExecutor.server_configs`
  (active MCP execution configuration) are consistently and correctly distinguished
  everywhere they are documented.

## Priority
High

## Scope
- **In-Scope**: the files listed in Implementation Target Files below; removing the
  stale `ToolRouteResolver(server_configs)` backward-compatibility claim; clarifying
  `ToolExecutor.server_configs` vs. the removed resolver argument; a Known Issue
  entry recording the correction.
- **Out-of-Scope**: modifying `ToolRouteResolver`, `RuntimeToolRegistry`,
  `ToolExecutor`, or `ADR-003`'s Decision/Rationale/Invariants sections; re-editing
  `docs/04_mcp_03_01_dispatch-and-routing.md`'s constructor example already
  corrected by DOC-001; removing static `ToolRegistry`; changing routing or
  tool-discovery behavior.

## Background
`issues/done/20260828-130451_doc001_tool_route_resolver_stale_spec.md` (DOC-001)
already corrected the stale `ToolRouteResolver(server_configs)` constructor example
in `docs/04_mcp_03_01_dispatch-and-routing.md`. This Plan covers the remaining files
DOC-001 did not scope, plus one occurrence DOC-001 missed within a file it did spot
check.

## Problem
`docs/05_agent_13_reference-api.md` line 114 states: "The constructor accepts
`server_configs` for backward compatibility but does not read them." This is
factually incorrect — `scripts/shared/route_resolver.py`'s `ToolRouteResolver.__init__()`
accepts only `warn_on_missing`, `strict_mode`, and `runtime_registry`; it has never
had a `server_configs` parameter in the current code (repository evidence: full read
of the constructor signature). The same file's line 117 already contains a correction
note stating the opposite (that `ToolRegistry` was "downgraded to seed data for
drift detection"), so the file contradicts itself between line 114 and line 117.
`docs/04_mcp_03_01_dispatch-and-routing.md` documents `ToolRouteResolver`/
`RuntimeToolRegistry`/static-`ToolRegistry` responsibilities accurately (already
corrected by DOC-001) but does not mention `ToolExecutor.server_configs` at all, so
it does not yet draw the distinction this Issue's Required Changes calls for.

## Reason for Change
`ADR-003`'s fail-closed security rationale for unregistered tools depends on this
responsibility split being documented accurately and consistently across every file
that references it — a stale `server_configs` claim risks a developer or AI agent
expecting an argument that does not exist, or misclassifying active components
(`ToolExecutor.server_configs`, static `ToolRegistry`'s drift-validation role) as
obsolete.

## Implementation intent
Remove the incorrect `server_configs` backward-compatibility claim from
`docs/05_agent_13_reference-api.md`'s `ToolRouteResolver` "Configuration" line,
replacing it with the constructor's actual parameters, and reconcile it with the
file's own existing correction note at line 117 rather than leaving both statements
present. Add an explicit `ToolExecutor.server_configs`-vs.-resolver-argument
distinction to `docs/04_mcp_03_01_dispatch-and-routing.md`, which already documents
the `ToolRouteResolver`/`RuntimeToolRegistry`/static-`ToolRegistry` split accurately
via DOC-001 and treats `ADR-003` as authoritative background. Add a Known Issue
entry to `docs/04_mcp_90_inconsistencies_and_known_issues.md` recording the
`docs/05_agent_13_reference-api.md` self-contradiction found during this Plan's
investigation, since no existing entry on this topic was found.
