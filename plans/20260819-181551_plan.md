## Goal

classes (Governance, Guide, Specification, Reference, Operations, Note), add
minimum behavioral contract blocks next to the 11 bare "see source code for
details" (`詳細はソースコードを参照してください`) occurrences across 3 RAG
doc files, and convert the 10 identified ASCII box-drawing diagrams to
Mermaid with a retained plain-text description — all documentation-only,
with no source code or EventBus implementation changes.

## Design

1. **Template document** (`docs/00_governance_11_document-templates.md`):
   follow the Front-Matter + section pattern of
   `00_governance_04_known-issues-template.md` (title/category/tags/related
   front matter, then one H2 per topic, then a "Related Governance
   Documents" footer). For each of the 6 classes (Governance, Guide,
   Specification, Reference, Operations, Note), define:
   - Required Front Matter fields (at minimum `title`, `category`, `tags`,
     `related`; add class-specific fields only if the class has a real
     structural need, e.g. Operations may want a `severity`/`runbook`
     field — keep additions minimal and justified).
   - Required sections list (e.g. Specification classes require Purpose,
     Scope, and per-component detail sections, matching the existing style
     observed in `03_rag_02_03_...` and `03_rag_03_02_...`).
   - Optional sections list.
   - One line stating how `00_governance_03_evidence-labels.md`'s evidence
     labels (e.g. "Explicit in code", "Strongly implied by code", "Needs
     Confirmation") apply to that class's required/optional sections.
2. **Governance cross-links**: in `00_governance_01_documentation-governance.md`,
   add `[Document Templates](00_governance_11_document-templates.md)` to
   "Related Governance Documents" (alphabetical/logical position matching
   the existing list order), and edit the Non-Goals bullet "Document
   formatting conventions within Specification documents" to either remove
   it or replace it with "Document formatting conventions beyond what
   `00_governance_11_document-templates.md` defines" so the exclusion is
   narrowed rather than left stale.
3. **Behavioral contracts**: for each of the 11 occurrences, replace or
   supplement the bare deferral sentence with a fenced/quoted block using
   only the fields relevant to that section, e.g.:
   - A constants list (module-level constants in chunksplitter/shared-utils)
     needs Responsibility + (if applicable) the existing "Needs Confirmation"
     evidence note — no Concurrency/Security fields.
   - A public-method/public-attribute list (RagPipeline class, ChunkSplitter
     public methods) needs Responsibility, Input contract, Output contract,
     Side effects, Failure behavior; Idempotency only where relevant (e.g.
     ChunkSplitter's sentinel-file idempotency is already documented in
     §3.1's "冪等性あり" prose — cross-reference it rather than duplicate).
   - Do not restate full signatures; keep pointing to source (per requirement
     §Implementation intent, bullet 2: "Do not restate the full API surface").
4. **Diagram conversion**: for each ASCII box-drawing diagram, write an
   equivalent ```mermaid flowchart TD``` (or `graph LR` where the original
   flow reads left-to-right) block with the same nodes/edges/labels, and keep
   a short existing or newly-added plain-text sentence describing the flow
   immediately before/after — do not remove any surrounding explanatory prose
   that is not itself the ASCII diagram.
5. Apply the classification rubric from `rules/coding.md` §"Current
   behavior" classification if any accidental discrepancy between docs and
   code is noticed while touching these files (expected to be rare, since
   this requirement is diagram/template/contract-only) — file as an issue
   rather than silently patch.

## Risks

- **Risk**: The requirement's suggested path for the new governance doc was
  already stale (`00_governance_09` taken) — a naive implementer following
  the requirement literally would create a filename collision or overwrite
  `docs/00_governance_09_terminology-glossary.md`.
  **Mitigation**: Already corrected in this plan and in the requirement
  document itself (Step A of this workflow cycle) to use
  `docs/00_governance_11_document-templates.md`. No open action needed.
- **Risk**: `docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md`'s
  duplicated content blocks (UNK-01) could cause an implementer to only fix
  the first occurrence of each deferral phrase and miss the duplicates,
  failing the acceptance criterion silently.
  **Mitigation**: Implementation step 2 explicitly calls out re-running
  `grep -c` after editing to confirm all 4 occurrences in that file are
  addressed. Also file a non-blocking issue recommending deduplication as a
  separate future requirement (documentation-quality debt, not blocking this
  requirement).
- **Risk**: Mermaid diagrams that are visually wrong (nodes/edges
  misrepresenting the original ASCII diagram) could be merged if the manual
  GitHub-preview check is skipped or done carelessly.
  **Mitigation**: Implementation step 4 makes the render check mandatory
  before closeout, matching the requirement's own acceptance criterion
  ("confirmed to render correctly on GitHub").
- **Risk**: Editing `docs/00_governance_01_documentation-governance.md`'s
  Non-Goals section touches a Governance-class document, which per that same
  document's own "Review Rule" ("Any change to Governance-class documents...
  requires review before merging") requires review before merging.
  **Mitigation**: Flag this explicitly in the implementation procedure/PR
  description so a reviewer is requested; likelihood low, impact low (single
  bullet-point edit), no further action needed at planning time.

No unmitigated risks remain; no `issues/{timestamp}_risks.md` is required.
