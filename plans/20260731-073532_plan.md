# Work Plan: Enforce Deny-All Policy When Security Audit Config Is Missing in Local Mode

## Status: DEFERRED

This plan has been deferred after code review. See "Deferred Decision" section below.

## Goal

Ensure that when security audit configuration files are missing in LOCAL mode, a default deny-all policy is applied for shell commands rather than silently skipping all checks.

## Scope

- Modify `scripts/agent/security_audit_config.py` to return a deny-all config instead of `None` in LOCAL mode
- Optionally add defensive fallback in `scripts/agent/repl_health.py`
- Add tests for the new behavior

## Assumptions

1. The `mode` variable can be determined from the application context (LOCAL vs PRODUCTION)
2. An empty `command_allowlist` set correctly implements deny-all semantics in the shell MCP server
3. Users expect deny-all behavior when config is missing, rather than silent failure

## Design

### Primary Approach: Fix at the source (Option A) — DEPRECATED

In `security_audit_config.py`, modify `load_shell_audit_config()` to return a deny-all config instead of `None` when the config file is missing in LOCAL mode:

```python
def load_shell_audit_config(mode: str = "LOCAL") -> ShellAuditConfig | None:
    """Load shell config for audit. Returns deny-all config if not installed."""
    try:
        from mcp_servers.shell.shell_models import ShellConfig
    except ImportError:
        # Config not installed — apply deny-all in LOCAL mode
        if mode == "LOCAL":
            logger.warning("Security audit config not found, applying deny-all policy")
            return ShellAuditConfig(sandbox_backend="none", command_allowlist=[])
        return None
    
    try:
        cfg = ShellConfig.load()
        return ShellAuditConfig(
            sandbox_backend=cfg.shell_sandbox_backend,
            command_allowlist=list(cfg.command_allowlist),
        )
    except Exception as exc:
        raise RuntimeError(
            f"Security audit: failed to load shell config: {exc}"
        ) from exc
```

**Key changes:**
1. Add `mode` parameter to control LOCAL vs PRODUCTION behavior
2. Return `ShellAuditConfig(sandbox_backend="none", command_allowlist=[])` instead of `None` when config is missing in LOCAL mode
3. Keep PRODUCTION mode behavior unchanged (raise RuntimeError)

### Secondary Approach: Defensive fallback in repl_health.py (Option B) — DEPRECATED

Add a fallback in `repl_health.py` to handle the case where `shell_cfg` is `None`:

```python
if shell_cfg is None:
    if production_mode:
        # Already handled by the RuntimeError above
        pass
    else:
        logger.error("Security audit config unavailable in LOCAL mode — enforcing deny-all")
        # Apply deny-all: treat as empty allowlist
        effective_allowlist = []
        # Continue with deny-all logic...
else:

```

**Recommendation:** Option A was preferred because it fixes the root cause. However, both options have been deprecated due to design concerns. See "Deferred Decision" below.

## Deferred Decision

After code review, this plan has been deferred. The current design is intentional:

- Current behavior: "configあり→チェック実施」「configなし→チェックスキップ」
- This is an intentional design choice (flexibility for local development)
- Forcing deny-all would break existing workflows

### Alternative approach (no code changes):

1. Add documentation comments to `repl_health.py:489-497`
2. Clarify "configなしの場合、チェックはスキップされる"
3. If deny-all becomes the default in the future, add an explicit configuration flag

### Step 5: Add tests

- Test that LOCAL mode applies deny-all when config is missing
- Test that PRODUCTION mode still blocks startup when config is broken

## Validation Plan

1. Unit tests: Verify deny-all behavior in LOCAL mode when config is missing
2. Integration tests: Verify that shell commands are rejected when allowlist is empty
3. Manual testing: Start agent in LOCAL mode without shell config and verify deny-all behavior

## Risks

| Risk | Mitigation |
|------|------------|
| Breaking change for LOCAL mode users who rely on missing config not blocking commands | Document as breaking change; provide migration guide |
| Empty allowlist may not trigger deny-all in shell MCP server | Verify shell MCP server behavior with empty allowlist before implementation |
| Mode detection may not work correctly in all contexts | Pass mode explicitly as parameter rather than relying on global state |
| Sandbox backend "none" may conflict with other security checks | Ensure sandbox backend validation is consistent across modes |
