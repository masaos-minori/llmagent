# Remove dead RagPipeline.search_queries()/rerank_candidates() and correct related documentation

## Goal
Remove the dead `RagPipeline.search_queries()` and `RagPipeline.rerank_candidates()`
methods (and their now-unused imports) from `scripts/rag/pipeline.py`, and correct
`docs/03_rag_03_04_query_pipeline-search-stages.md` to remove the stale claim that
`rerank_candidates()` passes the RRF flag to `FusionStage` (it does not — that
claim contradicts the same document's own dead-code note).

## Background
The Issue's cited claim (`docs/03_rag_03_04_query_pipeline-search-stages.md:59`:
"While `RagPipeline.search_queries()` and `RagPipeline.rerank_candidates()` are
defined in `pipeline.py`, neither has any callers (dead code)") is confirmed
accurate. Both methods are defined (`pipeline.py:180-219`) but a repository-wide
search (`rg "search_queries\(|rerank_candidates\(" scripts/ tests/`) found no call
site anywhere outside their own definitions — the one match in
`tests/mcp_servers/mdq/test_mdq_schema_migration.py` is a test function name
(`test_fts_search_queries_chunks_fts`), an unrelated coincidental substring match,
not a call.

**Re-verified 2026-09-13** (this cycle): found an additional documentation defect
the Issue did not identify — the same document's section 5.3
(`docs/03_rag_03_04_query_pipeline-search-stages.md:75`) states
"`RagPipeline.rerank_candidates()` passes the RRF configuration flag to
`FusionStage`." This is also false: `rerank_candidates()`'s actual body
(`pipeline.py:197-219`) only performs Cross-Encoder rerank + dedup and has no
reference to `FusionStage` or any RRF flag anywhere in its implementation. This
claim directly contradicts the same document's own section 5.2 dead-code Note four
paragraphs earlier — an internal inconsistency, not just a stale claim.

Confirmed the deletion's safety: `self.stat_search_embed_failed`/
`self.stat_search_fts_errors` (updated inside `search_queries()`, lines 193-194) are
also updated via the actually-used code path
(`RagPipelineStageLifecycle`→`pipeline.py:241-242`, aggregating
`lifecycle.stat_search_embed_failed`/`stat_fts_errors`), so removing
`search_queries()`'s own redundant update does not affect these counters'
production behavior. The `_search_all_queries` import (line 53) and
`deduplicate_chunks` import (line 47) are used exclusively inside
`search_queries()`/`rerank_candidates()` respectively (confirmed via `grep -n`), so
both become unused imports once the methods are removed.

## Problem
1. `search_queries()` and `rerank_candidates()` are dead code — confirmed no caller
   exists — increasing maintenance burden and risking future confusion if someone
   modifies them expecting an effect
2. The same documentation file that correctly notes this dead-code status also
   contains a contradictory, false claim two sub-sections later, describing
   behavior for `rerank_candidates()` (passing an RRF flag to `FusionStage`) that
   does not exist in its implementation

## Reason for change
Remove the confirmed-dead methods and their now-unused imports to reduce
maintenance burden and eliminate the risk of a future edit having no effect;
correct the documentation's internal contradiction so both sections agree on the
methods' (non-)role.

## Implementation intent
1. Delete `RagPipeline.search_queries()` (`pipeline.py:180-195`) and
   `RagPipeline.rerank_candidates()` (`pipeline.py:197-219`) in their entirety
2. Remove the `from rag.stages.search import _search_all_queries` import
   (line 53) and the `deduplicate_chunks` import from
   `from rag.repository import deduplicate_chunks` (line 47) if no other reference
   to either remains after step 1
3. Update section 5.2's Note to state the methods have been removed (rather than
   "are dead code"), and delete section 5.3's false `rerank_candidates()`/
   `FusionStage` claim
