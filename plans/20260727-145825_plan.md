## Goal

Fix `DocumentManager._update_etag` so it threads the real `existing_doc_id` through to `ETagManager` instead of a hardcoded `0`, so the ETag/Last-Modified refresh SQL on the "skip and refresh ETag" path actually updates the correct `documents` row.

**In-Scope:**
- `scripts/rag/ingestion/document_manager.py:94-101` — add a `doc_id: int` parameter to `_update_etag` and pass it into `ETagManager(self._db, doc_id)` instead of the literal `0`
- `scripts/rag/ingestion/document_manager.py:61` — update the call in `handle_existing_document` to pass `existing_doc_id` through to `_update_etag`
- A new/extended unit test asserting the correct `doc_id` row (not `doc_id=0`) is updated on the skip path (e.g. in `tests/test_ingester_etag_guard.py` or a new `DocumentManager`-focused test)

## Assumptions

1. `ETagManager(self._db, 0)` at `document_manager.py:101` is an unintentional bug, not a deliberate design choice — confirmed by the requirement's background and by there being no test or comment justifying `doc_id=0`.
2. `existing_doc_id` is always a valid, already-inserted `documents.doc_id` (an autoincrement PK ≥ 1) at the point `handle_existing_document` is called, since `ingester.py:365-373` only calls it after `SELECT doc_id FROM documents WHERE url = ?` returned a row.
3. No caller outside `scripts/` (e.g. no other package or test harness) constructs `ETagManager` directly with a relied-upon `doc_id=0`.
4. Changing `_update_etag`'s signature is safe because it is a private (`_`-prefixed) method with exactly one call site (`document_manager.py:61`), both in the same file/class.

## Risks

- **Risk**: The new `doc_id` parameter's position in `_update_etag`'s signature could be added inconsistently with `ETagManager.__init__`'s `(db, doc_id)` ordering, causing a silent argument-order bug (e.g. swapping `doc_id` and `etag`) → **Mitigation**: Add the parameter as the explicit first positional argument (`doc_id: int`) mirroring `ETagManager.__init__(self, db, doc_id)`, and cover it with a test that uses a distinctive non-zero `doc_id` (e.g. `doc_id=7`) so any accidental argument swap fails the test loudly with a type error or wrong-row assertion.
- **Risk**: Existing tests that mock `handle_existing_document` (in `test_ingestion_freshness.py`, `test_rag_ingester.py`) could mask a regression in the real (non-mocked) code path, since mocks bypass `_update_etag` entirely → **Mitigation**: The new/extended test in `tests/test_ingester_etag_guard.py` (or a new `DocumentManager`-focused test) exercises the real, non-mocked `handle_existing_document` → `_update_etag` → `ETagManager` chain end-to-end against an in-memory/temp SQLite DB, per the requirement's "Tests" section.
- **Risk**: Downstream code or reports that have silently come to depend on the skip path being a no-op (because `doc_id=0` always failed the `WHERE` match) could see new UPDATE side effects once the fix lands → **Mitigation**: No such dependency was found — `check_rag_consistency` and other consumers of `documents.etag`/`last_modified`/`fetched_at` read state, they do not assert on it staying stale; this is confirmed only by static grep of `etag`/`last_modified`/`fetched_at` consumers, not by an exhaustive dynamic trace, so treat as a low-likelihood residual risk to watch for in the Phase 3 full-suite run rather than a blocking unknown.
