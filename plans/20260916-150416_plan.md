## Problem
`docs/00_governance_03_issue-and-uncertainty-management.md` defines exactly three Status values (`open`, `investigating`, `deferred`) and a disposal rule: a resolved entry is removed, not retained with a closed-out status. A full-document scan (`grep -n "^\- \*\*Status\*\*:"`) found three entries violating this — EVENTBUS-001 and CI-003 both use the undefined value `Mitigated`, and EVENTBUS-002 uses the undefined value `resolved` plus three fields (`Resolved Date`, `Resolution`, `Impact Resolved`) outside the 16-field template.

## Reason for change
The document's own Acceptance-Criteria-equivalent rule ("No entry in Part 1 carries a Status value absent from the Status Values list") is document-wide, not scoped to specific IDs. Leaving any one of the three violations unfixed would leave that rule false and the vocabulary only partially enforced — the same rationale the source issue gives for batching EVENTBUS-002 and CI-003 together applies identically to EVENTBUS-001.

## Implementation intent
Apply the same Option A treatment (prose placeholder, evidence carried into the placeholder text) uniformly to all three non-conforming entries, using the wording pattern already established by the nine existing placeholders (RAG-003, RAG-004, DESIGN-1, SHARED-001, EVENTBUS-008, CI-001, CI-004, CI-005, CI-006): a short paragraph stating the entry was resolved, citing the resolution date, citing the concrete evidence, and stating "Its absence from the active list is the correct, policy-compliant state — do not create a `#### {ID}` heading."
