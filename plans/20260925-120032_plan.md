## Goal
- Adjust the RAG service delegation logic so that JSON parse errors are treated as empty results rather than triggering an in‑process fallback.

## Priority
Medium

## Scope
- **In‑Scope**: Modify `scripts/rag/pipeline_service.py::call_rag_service()` to remove fallback on parse error.
- **Out‑of‑Scope**: No changes to ADR‑010 or other system behaviour beyond this.

## Background
ADR‑010 Decision #9 / INV‑07 specify that JSON parse errors in `call_rag_service()` must be logged and treated as empty results, without invoking a fallback. The mismatch this Plan targeted — a `_set_fallback_reason()` call in the `except ValueError` handler that triggered an in-process fallback — was resolved by plan `20260925-104405` (commit `4ee51b8d`). The current `except ValueError` handler logs the parse error and returns `("", None, 0.0)` without calling `_set_fallback_reason()`.

## Problem
This mismatch leads to double processing, hidden bugs, and unnecessary latency.

## Reason for change
Align code with governance policy (ADR‑010) and eliminate unintended side effects.

## Implementation intent
No change required. The intended modification (drop the `_set_fallback_reason()` call from the `except ValueError` block while keeping the log statement and returning `("", None, 0.0)`) has already been applied by commit `4ee51b8d`.

## Requirements
- `REQ-001`: Update `scripts/rag/pipeline_service.py` to stop invoking fallback on parse error.
- `REQ-002`: Ensure tests expecting fallback on parse error are updated accordingly.
