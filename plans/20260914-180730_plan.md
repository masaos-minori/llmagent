## Design

### Decide Whether the EventBus-Specific Loader Is the Accepted Architecture (REQ-001, REQ-002)
Current state:
- ADR-002 Decision #9 says: "共通Config Loaderの利用は許可するが、プロセスごとに許可ファイルを限定し、許可外ファイルの読込をRuntime Errorとする。"
- ADR-002 line 87: EventBus row says "*N/A* (does not use ConfigLoader)"
- ADR-002 lines 363-375: CI-001 note marks it as "Resolved (2026-08-25)" with a local-invariant exception
- Governance doc CI-001 (lines 269-286): Still lists CI-001 as "open" with High severity

**Decision**: The local-invariant approach documented in ADR-002 is sufficient. Rationale:
1. The `.importlinter` `eventbus-is-isolated` contract explicitly forbids importing ConfigLoader from shared/mcp_servers
2. ADR-002 already accepted this as a documented architectural exception
3. The local-invariant (load_config()'s docstring + regression test in test_eventbus_config.py) provides equivalent enforcement
4. CI-001 should be closed with a reference to ADR-002's local-invariant exception

Update ADR-002:
```markdown
### CI-001: EventBus does NOT use ConfigLoader at all

- **Known Issue**: CI-001
- **Type**: Design Deviation
- **Summary**: EventBus uses tomllib directly for config loading, bypassing ConfigLoader.restrict_to() permission checks
- **Conflicting Source**: docs/adr/ADR-002-config-isolation.md:Decision #9, scripts/eventbus/config.py (load_config()), scripts/eventbus/app.py
- **Expected Design**: All processes MUST load config through ConfigLoader.restrict_to() to enforce process-level config ownership boundaries
- **Observed Implementation**: EventBus config.py loads its own config via tomllib without calling restrict_to(), allowing it to access configs outside its declared scope
- **Impact**: Config isolation invariant violated for EventBus; could read/write configs belonging to other processes
- **Recommended Action**: EventBus cannot import ConfigLoader (.importlinter eventbus-is-isolated contract). Resolved via a local invariant instead: load_config()'s docstring states callers must pass get_config_path()'s return value, and a regression test in tests/eventbus/test_eventbus_config.py locks both call sites in app.py to that invariant. Agent-side, ConfigLoader.restrict_to("agent.toml") was added to AgentContext.__init__ (scripts/agent/context.py).
- **Owner**: TBD
- **Status**: Resolved (2026-08-25)
- **Resolution Target**: Before ADR-002 moves from Proposed to Accepted status
```

Update Governance doc CI-001:
```markdown
#### CI-001

CI-001 ("EventBus process reads configuration directly instead of using ConfigLoader") was resolved and removed from this active inventory 2026-08-25. Confirmed by direct code inspection: `scripts/eventbus/config.py::load_config()` uses `tomllib.load()` directly rather than `ConfigLoader.restrict_to()`. However, if we need to add a new entry to track remaining authorization/audit gaps:
```
```markdown
#### EVENTBUS-009

- **ID**: EVENTBUS-009
- **Title**: Consumer identity validation fail-open when no consumer_id allowlist configured
- **Status**: open
- **Severity**: Medium
- **Area**: EventBus
- **Type**: design-gap
- **Source**: `scripts/eventbus/auth.py::require_consumer_identity()`
- **Owner**: Unassigned
- **First Found**: 2026-09-14
- **Target**: `06_eventbus_02_operations.md`, `06_eventbus_06_reference-api.md`
- **Related**: EVENTBUS-008
- **Summary**: When a token has no configured `consumer_id` allowlist entry, consumer-identity validation is skipped entirely (fail-open), allowing any caller to act as any consumer_id.
- **Current Description**: A token with no `_TOKEN_CONSUMER_MAP` entry passes `require_consumer_identity()` without checking the caller's requested `consumer_id`.
- **Observed Implementation**: `auth.py:195-196`: `allowed_consumers = _TOKEN_CONSUMER_MAP.get(token, set())`; if `allowed_consumers` is empty, the check on line 196 (`if consumer_id and allowed_consumers and consumer_id not in allowed_consumers:`) short-circuits because `allowed_consumers` evaluates to falsy.
- **Impact**: Any caller holding a token without a consumer_id allowlist can impersonate any consumer_id, violating INV-02 of ADR-013.
- **Recommended Action**: Add an explicit "no allowlist configured" rejection path in `require_consumer_identity()` when `allowed_consumers` is empty but `consumer_id` is provided. Tracked as `issues/20260914-102317_eventbus03_consumer-topic-authorization-ack-nack.md`.
```
