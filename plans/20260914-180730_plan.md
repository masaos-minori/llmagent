However, if we need to add a new entry to track remaining authorization/audit gaps:
```markdown
#### EVENTBUS-009

- **ID**: EVENTBUS-009
- **Title**: Consumer identity validation fail-open when no consumer_id allowlist configured
- **Status**: open
- **Severity**: Medium
- **Area**: EventBus
- **Type**: design-gap
- **Source**: `scripts/eventbus/auth.py::require_consumer_identity()`
- **Owner**: Unassigned
- **First Found**: 2026-09-14
- **Target**: `06_eventbus_02_operations.md`, `06_eventbus_06_reference-api.md`
- **Related**: EVENTBUS-008
- **Summary**: When a token has no configured `consumer_id` allowlist entry, consumer-identity validation is skipped entirely (fail-open), allowing any caller to act as any consumer_id.
- **Current Description**: A token with no `_TOKEN_CONSUMER_MAP` entry passes `require_consumer_identity()` without checking the caller's requested `consumer_id`.
- **Observed Implementation**: `auth.py:195-196`: `allowed_consumers = _TOKEN_CONSUMER_MAP.get(token, set())`; if `allowed_consumers` is empty, the check on line 196 (`if consumer_id and allowed_consumers and consumer_id not in allowed_consumers:`) short-circuits because `allowed_consumers` evaluates to falsy.
- **Impact**: Any caller holding a token without a consumer_id allowlist can impersonate any consumer_id, violating INV-02 of ADR-013.
- **Recommended Action**: Add an explicit "no allowlist configured" rejection path in `require_consumer_identity()` when `allowed_consumers` is empty but `consumer_id` is provided. Tracked as `issues/20260914-102317_eventbus03_consumer-topic-authorization-ack-nack.md`.
```
