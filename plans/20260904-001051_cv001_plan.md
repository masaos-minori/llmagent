# Plan: Add timeout to CLIView.run_in_executor input() call

## Goal
- Prevent indefinite blocking of multiline input when the default ThreadPoolExecutor is saturated during shutdown

## Priority
Medium

## Scope
- **In-Scope**: Add timeout protection to the run_in_executor call in read_multiline; handle TimeoutError gracefully
- **Out-of-Scope**: Rewriting the CLI presentation layer; adding new configuration options; executor lifecycle management beyond what's necessary for timeout

## Background
CLIView.read_multiline calls loop.run_in_executor(None, lambda: input("... ")). With executor=None, this uses Python's default ThreadPoolExecutor. If the executor is busy or full, input() will block indefinitely waiting for a thread slot. There's no timeout on this operation.

## Problem
During shutdown, if the executor is saturated, the multiline continuation hangs forever. Users cannot interrupt the REPL during this state.

## Reason for change
Operational reliability: users should always be able to interrupt the REPL, even during shutdown when resources may be constrained.

## Implementation intent
Pass a dedicated ThreadPoolExecutor with bounded queue size and implement a timeout wrapper around run_in_executor. Use asyncio.wait_for() to enforce a configurable timeout on the executor submission. Handle TimeoutError by raising KeyboardInterrupt or logging a warning.

## Requirements
- `REQ-CV001-1`: Multiline input times out after configurable period instead of hanging
- `REQ-CV001-2`: Timeout is handled gracefully (KeyboardInterrupt or logged warning)
- `REQ-CV001-3`: No regression in normal multiline input behavior

## Design
1. Create a bounded ThreadPoolExecutor with max_workers=1 and a small queue size (e.g., 5)
2. Wrap the run_in_executor call with asyncio.wait_for(timeout=X)
3. On TimeoutError, raise KeyboardInterrupt to allow user interruption
4. Document the timeout behavior in the method docstring
