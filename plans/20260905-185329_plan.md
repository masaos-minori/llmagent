## Goal
- Inventory the repository's active canonical-source declarations, classify each by decision target and claim type, and migrate the unambiguous, uncontested mappings into the Canonical Source Registry — reporting every ambiguous, missing, or conflicting mapping explicitly instead of guessing.

## Priority
Medium

## Scope
- **In-Scope**: a full Migration Inventory (all 10 required columns) built from a repository-wide search for the required keywords plus the named locations (Area Canonical Maps, area document guides, ADR index, Specification/Reference/Operations docs, templates); classifying every found declaration as migrated / needs-confirmation / conflict / not-applicable; actually migrating the two declarations found to be unambiguous and uncontested (EventBus's "trust the code" runtime-behavior rule, and the EventBus persistence-schema authority statement) into `config/documentation_canonical_sources.toml`, and updating `docs/06_eventbus_00_document-guide.md`'s Canonical Source Rule section to link to those two registry entries instead of restating them independently; flagging every stale/non-existent file path found in `docs/00_governance_01_documentation-policy.md`'s Area Canonical Maps as `Needs Confirmation` (not deleting or guessing a replacement).
- **Out-of-Scope**: fixing any application implementation deviation the inventory surfaces (`docs/00_governance_03_issue-and-uncertainty-management.md` is where a resulting Known Issue would be filed, not this Plan); closing any Known Issue merely because a canonical source was identified; adding a historical/superseded document to the active registry; migrating RAG/MCP/Agent/Shared area guides whose "Canonical Source Rules" content was found to be a documentation topic-to-file index (not a decision-target/claim-type canonical-source declaration) rather than a code-vs-doc authority question — recorded as `Not applicable` in the Inventory, not migrated; resolving every Area Canonical Maps row this Plan finds `Needs Confirmation` (recorded, not guessed).
- **Constraint**: keep body-content changes limited to canonical-source declarations and required cross-references — do not perform unrelated rewrites of area guides or other documents touched during migration (source Issue's Constraints section, citing `AGENTS.md` Global Rule 5).

## Background
Existing canonical ownership is distributed across governance policy (`docs/00_governance_01_documentation-policy.md`'s Area Canonical Maps), area guides' own Canonical Source Rule(s) sections, the ADR index, and informal phrases (`authoritative`, `primary`, `source of truth`) scattered elsewhere — none of it maps cleanly to a decision-target-and-claim-type pair the way `M-01-04`'s registry requires.

## Problem
The migration must not mechanically convert every Primary document into a canonical source; each declaration must be assigned to a specific decision target and claim type, or explicitly flagged as unresolved rather than guessed.

## Reason for change
`M-01-04`'s registry and `M-01-05`'s validator have no value until the repository's actual canonical-source declarations are inventoried and migrated into them — until then, the old hand-maintained area tables remain the de facto system of record.

## Implementation intent
Perform the repository-wide search this Issue specifies, build the full Migration Inventory as this Plan's primary deliverable, and migrate only the subset the inventory shows to be unambiguous and uncontested — deferring everything else to the Inventory's own `Needs Confirmation`/`Not applicable` rows rather than resolving it by guesswork.
