## Goal
- Remove remaining production-vs-local/dev behavioral difference language from three Specification documents that contradict ADR-004's Production-only model.

## Priority
Medium

## Scope
- **In-Scope**: Update `docs/05_agent_10_01_operations-and-observability-startup-and-health.md`, `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`, and `docs/90_shared_03_01_runtime_and_execution-config-and-logging.md` to remove production-vs-local/dev behavioral distinction language.
- **Out-of-Scope**: Any other Specification document; code changes; ADR-004 modification.

## Background
ADR-004 defines "Production" as the only supported operating mode, removing Local/Dev-mode distinctions. However, three Specification documents still describe production-vs-local/dev behavioral differences that contradict this decision. Direct code inspection confirmed these behavioral differences exist in the source code (e.g., `security_profile == "production"` checks in `production_config_validator.py`, `production_mode` parameter branching in `startup.py` and `repl_health.py`).

## Problem
Three Specification documents describe production-vs-local/dev behavioral differences that contradict ADR-004's Production-only model:
- `docs/05_agent_10_01_operations-and-observability-startup-and-health.md`: Line 46 describes different FATAL/WARNING behavior based on production/local mode for unreachable health probes.
- `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`: Lines 87-88 describe Missing Tiers and Unknown Keys having different severity (fatal error in production, warning in local/development).
- `docs/90_shared_03_01_runtime_and_execution-config-and-logging.md`: Line 45 describes ProductionConfigValidator treating violations as errors only when `security_profile == "production"`.

## Reason for change
These documents are relied upon by downstream consumers (including ADR-012 evaluation) as authoritative descriptions of operational behavior. Contradictory claims cause confusion about which behavior is correct and which environments are supported.

## Implementation intent
Remove production-vs-local/dev behavioral distinction language from the three affected Specification documents. Where the distinction is factual (e.g., code still branches on `security_profile == "production"`), add a note explaining the discrepancy rather than silently removing it.

## Requirements
- `REQ-001`: All three Specification documents must accurately reflect ADR-004's Production-only model
- `REQ-002`: Production-vs-local/dev behavioral distinction language must be removed or flagged as stale
- `REQ-003`: Any factual discrepancies between documentation and source code must be explicitly noted
