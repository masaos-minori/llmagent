# Work Plan: Preserve Messages on History Compression Failure

## Goal

Ensure that original messages are preserved when history compression fails (either by returning None or raising an exception).

## Scope

- Modify `scripts/agent/history.py` to handle compression failures gracefully
- Ensure callers properly handle compression failure cases

## Assumptions

1. The current `HistoryCompressionError` exception is caught by callers but doesn't preserve messages
2. Adding fallback logic won't break existing error handling
3. The `_call_compress_llm()` method can return None on failure

## Unknowns

1. **How do callers currently handle `HistoryCompressionError`?** Need to verify that preserving messages doesn't leave callers in an inconsistent state.
2. **What is the impact of skipping compression entirely?** May cause memory issues if compression is critical for managing context window.
3. **Is there a difference between "empty summary" and "compression failed"?** Need to understand the distinction.

## Affected Areas

- `scripts/agent/history.py` — Core logic change
- Callers of `compress_history()` — May need updates
- `tests/test_history.py` — New test coverage

## Design

### Approach: Add defensive checks in compress() method

After reviewing the code, the current implementation already handles some failure cases:

1. `_call_compress_llm()` returns None on empty summary → handled by checking `if not summary_text:`
2. `_call_compress_llm()` raises `HistoryCompressionError` → caller needs to handle this

**Decision:** Add explicit check for None return and ensure callers don't lose messages.

### Implementation Steps

#### Step 1: Verify current behavior in compress()

Check if the current `compress()` method already preserves messages on failure. If yes, no changes needed.

#### Step 2: Add explicit None check

If `_call_compress_llm()` can return None and it's not handled, add:

```python
async def compress(self, history: list[dict]) -> tuple[list[dict], CompressResult]:
    try:
        summary_text = await self._call_compress_llm(history_text)
        
        if summary_text is None:
            logger.warning("History compression returned None, keeping original messages")
            return history, CompressResult(
                compressed_count=0,
                summary_added=False,
                error="compression returned None",
            )
        
        # ... rest of compression logic
    except HistoryCompressionError as e:
        logger.error(f"History compression failed: {e}")
        return history, CompressResult(
            compressed_count=0,
            summary_added=False,
            error=str(e),
        )
```

#### Step 3: Update callers to handle compression failure

Verify that all callers of `compress()` handle the case where compression didn't occur.

#### Step 4: Add tests

- Test that None return preserves messages
- Test that exception preserves messages

## Validation Plan

1. Unit tests: Verify each failure mode preserves messages
2. Integration tests: Verify normal operation works correctly
3. Manual testing: Simulate each error type and verify correct response
4. Regression testing: Verify no breaking changes

## Risks

| Risk | Mitigation |
|------|------------|
| Skipping compression may cause memory issues | Document risk; monitor context window usage |
| Existing callers may not handle compression failure | Thorough review of all callers before deployment |
| Error handling may differ across environments | Test in both LOCAL and PRODUCTION modes |
