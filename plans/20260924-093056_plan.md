## Goal
Update the `paths:` trigger filters in 5 GitHub Actions workflows under
`.github/workflows/` so each keeps triggering correctly once its corresponding
`docs/*.md` files move into their planned area subfolder, replacing today's
flat, prefix-only glob with one scoped to the new subfolder location.

## Priority
High

## Scope
- **In-Scope**: the `paths:` list under both the `push` and `pull_request`
  trigger sections of `agent-docs-consistency.yml`,
  `overview-docs-consistency.yml`, `deployment-docs-consistency.yml`,
  `rag-docs-consistency.yml`, and `rag-docs-quality.yml`.
- **Out-of-Scope**: any other `paths:` entry, job step, or trigger condition in
  these 5 files; `governance-docs-consistency.yml`, `mcp-docs-consistency.yml`,
  `backward-compat-check.yml` (already recursive, confirmed unaffected);
  physically moving any file under `docs/`; removing or shortening any
  filename prefix; fixing `rag-docs-quality.yml`'s pre-existing broken
  `tools/check_doc_quality.py` script reference (see Risks).

## Background
A separate investigation (2026-09-23) evaluated reorganizing `docs/` into 11
area-based subfolders (`00_governance/`, `01_overview/`, `10_adr/`, `21_rag/`,
`22_mcp/`, `23_agent/`, `24_eventbus/`, `40_shared/`, `41_db/`,
`90_deployment/`, `91_security/`) while keeping every existing filename
unchanged — confirmed via `plans/done/20260923-142045_plan.md` (docsreorg01),
which lists this exact 11-subfolder set. That investigation produced 16 issues
(`docsreorg01`-`docsreorg16`); this Plan covers `docsreorg03`, one of two
prerequisite CI/tooling issues (alongside `docsreorg02`, already implemented —
`plans/done/20260923-152824_plan.md`) that the 11 per-area physical-move
issues depend on.

## Problem
5 of the 8 `docs/`-related workflows under `.github/workflows/` use a `paths:`
filter that matches files only directly under `docs/` (not a recursive
`docs/**/*.md` pattern), scoped by filename prefix — confirmed via Read of
each file:
- `agent-docs-consistency.yml` (lines 6-7, 11-12): `"docs/05_agent_*.md"`,
  `"docs/90_shared_04_*.md"`
- `overview-docs-consistency.yml` (lines 6, 11): `"docs/01_overview*.md"`
- `deployment-docs-consistency.yml` (lines 6, 13): `"docs/02_deployment*.md"`
- `rag-docs-consistency.yml` (lines 6, 11): `"docs/03_rag_*.md"`
- `rag-docs-quality.yml` (lines 6, 11): `"docs/03_rag_*.md"`

Once the corresponding files move into `docs/23_agent/`, `docs/41_db/` (for
the `90_shared_04_*` DB-architecture files), `docs/01_overview/`,
`docs/90_deployment/`, and `docs/21_rag/` respectively, none of these path
patterns match anymore. GitHub Actions raises no error in this case — the
workflow simply stops triggering on future edits to those files, a
silent-failure mode.

The other 3 docs-related workflows (`governance-docs-consistency.yml`,
`mcp-docs-consistency.yml`, `backward-compat-check.yml`) already use
`"docs/**/*.md"` for their `paths:` trigger and are confirmed unaffected by
the move — verified via Read of each file's `on.push.paths`/
`on.pull_request.paths`.

**Adversarial-verification finding (2026-09-24), not present in the source
Issue**: `governance-docs-consistency.yml`'s trigger `paths:` is correctly
recursive, but its job step (line 69) separately invokes
`python tools/check_docs_structure.py docs/*.md docs/adr/*.md --schema
schemas/doc_front_matter.json` with an explicit, non-recursive **shell-glob
argument** — a different mechanism from the trigger filter, and already
recorded as an out-of-scope Risk in `plans/done/20260923-142045_plan.md`
(docsreorg01) with the mitigation "file a follow-up issue ... or address it
as part of `docsreorg16`'s final validation sweep." This Plan's own Issue
explicitly excludes "any other ... job step" in the 5 files it covers, and
this gap is in a 6th, out-of-scope file — carried forward here as a Risk
(below), not fixed by this Plan.

**Second adversarial-verification finding**: `rag-docs-quality.yml`'s job step
(line 35) invokes `python tools/check_doc_quality.py docs/03_rag_*.md` — but
`tools/check_doc_quality.py` does not exist in the current repository (only a
stale `tools/__pycache__/check_doc_quality.cpython-313.pyc`). Confirmed via
`git log --oneline --all -- tools/check_doc_quality.py`: it was renamed to
`tools/check_docs_quality.py` in commit `2bf74b1bc` ("refactor: unify tools/
script names to verb+object convention"), and this workflow's `run:` step was
never updated to match. This is a pre-existing, already-documented drift —
also recorded in `plans/done/20260831-222003_plan.md` and
`plans/done/20260903-125706_plan.md` — unrelated to the `docs/` folder
reorganization and out of scope for this Plan (see Risks; the Issue's Out of
Scope also excludes "job step" changes to this file). Because the workflow
already fails outright on every run for this unrelated reason, the "silent
stop-triggering" failure mode this Plan protects against does not currently
apply to `rag-docs-quality.yml` in practice — but the trigger `paths:` fix is
still correct and required for when the script reference is eventually fixed.

## Reason for change
These 5 workflows are the CI enforcement for docs-consistency checks in their
respective domains. A workflow that silently stops triggering removes a
safety net without any visible signal, which is worse than an outright
failure — and this Plan's fix must land in coordination with each
corresponding physical file move (see Risks) to avoid introducing a new,
equally silent gap.

## Implementation intent
For each of the 5 workflows, change every `paths:` entry that currently
matches the flat `docs/` location to instead match the confirmed new
subfolder location, applying the identical change to both the `push` and
`pull_request` trigger sections (each file currently duplicates the same
`paths:` list verbatim across both). Keep the existing filename-prefix
specificity — do not relax to a bare `docs/<subfolder>/**` recursive pattern,
since each subfolder is not guaranteed to hold only that domain's files after
every reorg issue lands (e.g. `docs/41_db/` will hold only the `90_shared_04_*`
prefix group, not all of `docs/90_shared_*`).

## Design
Each edit is a literal string replacement of one or two `paths:` list entries,
applied identically to both the `push` and `pull_request` sections of the
same file — no other line in any of the 5 files changes. The existing
filename-prefix specificity is preserved by prefixing the new subfolder
segment onto the current glob, rather than widening to a bare
`"docs/<subfolder>/**"` recursive pattern: this matters concretely for
`agent-docs-consistency.yml`'s second entry, since `docs/41_db/` will (per
`docsreorg10`) hold only the `90_shared_04_*` prefix group, not every file
that currently lives under the `90_shared_*` prefix family — a bare
`"docs/41_db/**"` would over-trigger this workflow on unrelated DB-doc
changes once other `90_shared_*` files eventually land elsewhere. Since no
Python source, test, or `tools/` file is touched, `radon`/`vulture`/`bandit`/
`diff-cover`'s validation-quality baseline (Step 5 of `workflow.md`) does not
apply — confirmed by this Plan's own Implementation Target Files table
containing only `.yml` files, and by `rg` above showing no other file
references these 5 workflows outside sibling planning documents.
