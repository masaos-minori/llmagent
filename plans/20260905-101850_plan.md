## Background
`skills/DESIGN.md` Shared Vocabulary already establishes four related
principles applied when *generating* new documentation: "Avoid
implementation-reference duplication", "No source-code line numbers", "No
concrete configuration values", and "No implementation counts" (confirmed:
`skills/DESIGN.md` lines 155-189). None of these names the specific
categories this policy targets precisely — a raw ASCII file tree is not a
"line number" or an "implementation count" under the current wording — so a
tool or writer cannot reliably tell "does this violate policy?" from the
current text alone.

## Problem
Repository-wide search confirms concrete, current examples of the
remove-categories this policy must name precisely (all re-verified against
current source):
- **Full file trees with per-file descriptions**: `docs/01_overview-files-02-rag.md`
  lines 28-33 contain a literal ASCII tree (`├─`, `│`, `└─`) with a one-line
  description per entry (confirmed by direct read); `docs/01_overview-files-01-build.md`
  and `docs/01_overview-files-06-misc.md` also confirmed to exist as the
  Issue's cited examples of this file-tree pattern.
- **Class/function/method index tables**: `docs/03_rag_02_08_ingestion_pipeline-shared.md`
  lines 58-60 contain a "Public Functions" table
  (`| Function | Signature | Description |`, confirmed by direct read);
  `docs/03_rag_02_05_ingestion_pipeline-document-manager.md`,
  `docs/03_rag_02_07_ingestion_pipeline-utils.md`,
  `docs/04_mcp_02_01_endpoints-and-transport.md`, and
  `docs/04_mcp_03_02_tool-registry.md` confirmed to exist as the Issue's
  cited examples of this pattern.
- **Literal port numbers**: `docs/04_mcp_04_02_file-write-file-delete-shell.md`
  lines 13, 47, 81 contain the section headings "## file-write-mcp (Port 8007)",
  "## file-delete-mcp (Port 8008)", "## shell-mcp (Port 8009)" (confirmed by
  direct grep).
- **Implementation-location mappings**: `docs/01_overview-files-02-rag.md`
  line 30 states inline which `.py` performs an action
  (`# Files ingested into DB (moved by ingester.py)`, confirmed by direct
  read).
- `docs/03_rag_05_5-constraints-reference.md` line 33 already records this
  failure mode once at the line-number-citation level specifically: a
  previous version cited `config/agent.toml:43` and specific hop/page-count
  values that had already drifted from the actual `config/crawler.toml`
  values, requiring the correction "Line number references are deprecated;
  use section-based references instead" (confirmed by direct grep) — this is
  the same failure mode the new policy generalizes to file trees, per-file
  descriptions, and location mappings.

## Reason for Change
Implementation-detail listings go stale the moment the underlying code
changes, and duplicate what `grep`/code/git already answer authoritatively.
File trees, per-file descriptions, and location mappings are the same
failure mode as the already-corrected line-number citation, at larger scale,
and they crowd out the design-intent content that is genuinely hard to
recover from code alone (why components are separated, what dependency
direction is allowed, what design boundaries need joint review).

## Implementation intent
Extend `skills/DESIGN.md` Shared Vocabulary with two new named subsections
(placed adjacent to the existing four related principles, after "No
implementation counts" and before "Out-of-scope paths") rather than creating
a disconnected parallel rule set. Each category gets a one-sentence
definition plus a short example drawn from the Problem section's evidence.
Cross-reference `rules/env.md` Architecture for the canonical
dependency-direction/layer content instead of restating it — that document
is already `AGENTS.md` Environment's designated source for "schema, config
reference, service ports."

## Design
This Plan is documentation/policy-text-only; there is no code architecture
change. Path A/B classification (see `skills/issue-to-plan/SKILL.md`
Routing): **Path A** — affects exactly 1 file (`skills/DESIGN.md`), no
public/runtime-facing interface change, no database schema change. Direct
verification (Step 3) confirmed the Issue's cited evidence (existing four
principles, the five concrete remove-category examples, and the prior
line-number-deprecation precedent) all still hold against current source, so
no correction to the Issue's factual claims was needed. The core design
decision is to extend the existing principle group with two clearly-marked,
symmetric five-item lists rather than introducing a new, disconnected
policy section, keeping the "avoid implementation detail / retain design
intent" framing consistent across all of Shared Vocabulary's related rules.
