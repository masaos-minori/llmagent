# Plan: Remove stale "local mode" language from operations document

## Goal
- Replace dual-mode phrasing ("production or local mode") in the Operations document with unified single-policy language consistent with ADR-004's environment-agnostic failure handling policy.

## Priority
Low

## Scope
- **In-Scope**: Updating `docs/05_agent_10_04_operations-and-observability-validation-and-troubleshooting.md` to remove references implying separate production/local modes.
- **Out-of-Scope**: Modifying source code, modifying other documents, adding tests, updating ADR-004 itself.

## Background
ADR-004 defines a single common failure handling policy across ALL environments (Local, Development, Production, etc.). Environment names must NOT change startup validation, authentication, authorization, Allowlist enforcement, approval control, Tool ownership requirements, Routing requirements, resource scope validation, DB integrity requirements, or Workflow requirements. The Operations document's phrase "regardless of whether it is production or local mode" contradicts this unified approach by implying two modes exist.

## Problem
The Operations document contains the phrase "production or local mode" describing startup failure classification, which creates a false impression that two execution modes exist despite ADR-004 now defining a Production-only model with no Local mode distinction.

## Reason for change
Language in the Operations document contradicts ADR-004's unified policy, potentially confusing operators about supported execution modes.

## Implementation intent
Replace the dual-mode phrasing with language that reflects the single-policy approach defined by ADR-004, without changing the FATAL classification outcome (which remains correct under the unified policy).

## Requirements
- `REQ-001`: The Operations document MUST NOT contain phrasing that implies separate production and local execution modes.
- `REQ-002`: The FATAL classification for `mcp_tool_discovery` failure MUST be preserved, as tool discovery failure makes all session tool calls impossible regardless of environment.
