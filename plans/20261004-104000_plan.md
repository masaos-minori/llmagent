# Plan: ResourceShutdownCoordinator cancels only tracked background tasks

## Goal
- Ensure `ResourceShutdownCoordinator.close_resources()` cancels only tasks tracked via `TurnState.background_tasks`, preserving critical operations like history-write tasks.

## Priority
High

## Scope
- **In-Scope**: Modify `close_resources()` to use `turn.background_tasks` instead of `asyncio.all_tasks()`; clear the set after cancellation
- **Out-of-Scope**: Changes to WAL checkpoint logic (already correctly placed before cancellation); changes to the shutdown sequence ordering

## Background
`ResourceShutdownCoordinator.close_resources()` in `scripts/agent/resource_shutdown_coordinator.py` coordinates resource shutdown during REPL exit. It cancels pending tasks after WAL checkpoint completes.

## Problem
The method uses `asyncio.all_tasks(loop)` to get all pending tasks and cancels them all indiscriminately. This includes tasks that may be critical for data integrity, such as history-write tasks that are mid-operation. History write operations may be cancelled mid-flight, losing data. Any task spawned during the turn loop could be affected. The LIFO ordering claim ("last-created-first-cancelled") provides no guarantee of correctness — it's arbitrary based on task creation order.

## Reason for change
Data loss during shutdown is a reliability concern. Cancling critical operations silently loses user data. The existing `TurnState.background_tasks` set already tracks background tasks for clean shutdown but is unused by the shutdown coordinator.

## Implementation intent
Track which tasks are safe to cancel vs. which must complete (e.g., via a `turn.background_tasks` set as documented in `TurnState`). Only cancel tasks from `turn.background_tasks`. Await completion of non-cancellable tasks (like WAL checkpoint, which is already done before this point).

## Requirements
- `REQ-001`: Only tracked background tasks are cancelled
- `REQ-002`: Critical operations (WAL checkpoint, history flush) are not cancelled
- `REQ-003`: Test verifies no data loss during shutdown with active history writes
- `REQ-004`: Test verifies cancellation of background-only tasks

## Design
### Current Behavior (Verified Against Source)
1. `resource_shutdown_coordinator.py` line 113-114: `pending_tasks = [t for t in asyncio.all_tasks(loop) if t is not asyncio.current_task()]` — gets ALL pending tasks
2. Line 121-122: Cancel all in reverse order (LIFO)
3. Line 124: Gather results with `return_exceptions=True`
4. `context.py` line 184: `TurnState.background_tasks` exists but is unused by shutdown coordinator
5. `orchestrator.py` line 110: `_background_tasks: set[asyncio.Task[object]] = set()` — tracks background tasks during turns

### Proposed Change
```python
# 2. Cancel only tracked background tasks
pending_tasks = list(self._ctx.turn.background_tasks)
self._ctx.turn.background_tasks.clear()
if pending_tasks:
    logger.info(
        "Cancelling %d pending background tasks during shutdown", len(pending_tasks)
    )
    # Cancel in reverse order (LIFO) for deterministic shutdown
    for t in reversed(pending_tasks):
        t.cancel()

    results = await asyncio.gather(*pending_tasks, return_exceptions=True)
    for res in results:
        if isinstance(res, Exception):
            errors.append(("task_cancellation", f"{type(res).__name__}: {res}"))
```

Key changes:
1. Replace `asyncio.all_tasks(loop)` with `list(self._ctx.turn.background_tasks)`
2. Clear the set after copying to prevent double-cancellation
3. Keep LIFO ordering within the tracked set
