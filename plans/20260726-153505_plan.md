## Goal

Add schema-based validation for LLM-generated tool call arguments before execution, rejecting calls with unexpected fields not defined in the MCP tool's inputSchema.

## Scope

**In-Scope:**
- Validate tool arguments against MCP tool inputSchema after `orjson.loads()` in `execute_one_tool_call()`
- Reject tool calls containing fields not declared in the schema (extra field rejection)
- Log warnings for rejected tool calls with details
- Graceful handling of validation failures without crashing the agent session
- Allow MCP servers to optionally provide custom validation rules per tool

**Out-of-Scope:**
- Modifying existing MCP server implementations
- Adding new MCP servers
- Changing DAG scheduling logic
- Modifying tool result formatting or history

## Assumptions

1. MCP servers expose `inputSchema` in their tool definitions (standard MCP protocol behavior)
2. `jsonschema` library is available in the project dependencies
3. Validation failures should be treated as errors returned to the LLM, not as fatal crashes
4. Each MCP server can declare whether its tools accept extra fields beyond the schema
