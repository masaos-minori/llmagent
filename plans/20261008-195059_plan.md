## Problem
- The issue's main premise is obsolete: ADR-001's Implementation Notes already read "Startup preflight checks ... abort startup on failure" and "`Orchestrator` constructs the `WorkflowEngine` ...", and there is no AGENT-003 anywhere in `docs/` or `scripts/` (Confirmed by repository evidence — `rg 'AGENT-003' docs scripts` finds nothing). The proposed paragraph "Orchestrator.__init__() does not satisfy Decision item 4 today ... tracked as AGENT-003" would now be false.
- The code now raises `RuntimeError` when `WorkflowLoader().load()` raises `WorkflowLoadError` or `FileNotFoundError`, so a load failure cannot produce a fallback mode (Confirmed by repository evidence — `scripts/agent/orchestrator.py` lines 127-133; the module docstring says "there is no fallback mode (ADR-001 Decision 4, ADR-004 INV-03)"; `tests/agent/test_orchestrator.py::TestWorkflowLoadFailureIsFatal`).
- Decision item 4 still reads only "There is no direct execution path that bypasses the workflow." It does not name the fallback path that was the actual violation, so the ADR does not state the property that wfstartup01 now enforces (Explicit in ADR-001).
- The Implementation Notes describe only the startup preflight as enforcement, not the Orchestrator-level abort that now backs INV-01 and INV-05 (Explicit in ADR-001).

## Reason for change
- The ADR should state, and point to the enforcement of, the property whose violation was fixed, so a regression can be recognized as a Decision violation.
