## Problem
- INV-12 says "When ACK persistence fails, an error response is returned and the Event is not redelivered" (Explicit in ADR-006 line 237) and Decision item 11 repeats it as "no redelivery (Fail-Closed)". This contradicts INV-07 (At-Least-Once: duplicates are tolerated, losses are not).
- The verification for INV-12 already reads "A failure to persist an ACK is not treated as success" (Explicit in ADR-006 line 297), and the cited test shows that the failure raises and nothing is committed (Confirmed by repository evidence — `tests/eventbus/test_eventbus_crash_ack.py::TestCrashBeforeAck::test_offset_write_failure_after_delivery_state`). That matches the revised interpretation, not "no redelivery".
- INV-10 reads "Concurrent use of the same Consumer ID is prohibited" but is enforced only on `GET /subscribe` (Explicit in ADR-006 line 378 and `docs/24_eventbus/eventbus_05_dlq_offsets_and_delivery_semantics.md` line 37); the invariant text implies wider coverage.
- Known Deviations lists EVENTBUS-008, 011, 012, 013 but not EVENTBUS-014, which exists in the ledger (Explicit in `docs/00_governance/governance_03_issue-and-uncertainty-management.md`).
- The Review Triggers still contain "Consumer ID exclusivity must also be enforced on ACK and NACK (EVENTBUS-013)", which is now a Known Issue, not a trigger.

## Reason for change
- A reader trusting INV-12 would conclude a failed ACK loses the event; the revised text keeps the At-Least-Once guarantee and the Known Deviations stay consistent with the ledger.
