# Plan: Limit HALF_OPEN trial calls to one

## Goal

Allow only a single trial call while a server's circuit breaker is HALF_OPEN, and make other calls wait or be rejected until the result is known.

## Priority

Low

## Scope

- **In-Scope**:
  - `scripts/shared/tool_transport_invoker.py`: add per-server in-flight trial flag in `_check_health()`
  - `scripts/shared/mcp_health.py`: add per-server in-flight trial tracking in `McpServerHealthRegistry`
  - `docs/22_mcp/mcp_03_01_dispatch-and-routing.md`: update circuit-breaker description if it states trial behavior
- **Out-of-Scope**:
  - Breaker thresholds and timing
  - Other circuit breaker states (HEALTHY, DEGRADED, UNAVAILABLE)

## Background

Source: local investigation notes (memo1.md, ISSUE-13), from an earlier review finding.

## Problem

- When the circuit breaker is HALF_OPEN, `_check_health()` lets all calls through, so any number of trial calls can flow concurrently (Explicit in code — `scripts/shared/tool_transport_invoker.py` logs "allowing trial dispatch" for every call in that state).

## Reason for Change

- HALF_OPEN exists to test recovery with one call; sending many at once concentrates load on a recovering server and can cause another failure.

## Implementation Intent

- Restrict HALF_OPEN to one in-flight trial.

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| Server in HALF_OPEN + no in-flight trial | Allow this call as the trial |
| Server in HALF_OPEN + in-flight trial active | Reject with "unavailable" error |
| Trial succeeds | Transition to HEALTHY, release trial flag |
| Trial fails | Transition to UNAVAILABLE, release trial flag |
| Trial cancelled | Release trial flag |

### Decision details

1. **Add per-server in-flight trial flag to `McpServerHealthRegistry`**: Add a set `_half_open_trials: set[str]` to track which servers currently have an in-flight trial call. Add methods `_acquire_trial(server_key)` and `_release_trial(server_key)` to manage the flag.
2. **Modify `_check_health()` to use the trial flag**: In `tool_transport_invoker.py`, when state is HALF_OPEN, try to acquire the trial flag. If acquired, allow the call. If not acquired, return an "unavailable" error result.
3. **Ensure trial flag release on all exit paths**: Use `try/finally` blocks in the invocation path to ensure the trial flag is released on success, failure, and cancellation.
4. **Update documentation**: Update `mcp_03_01_dispatch-and-routing.md` if it states that multiple trial calls are allowed.

## Assumptions

- The trial flag should be an async-safe mechanism (e.g., using `asyncio.Lock` or a set with atomic operations).
- The "unavailable" error message for rejected calls should clearly indicate the reason (e.g., "trial in progress").
- The existing `is_unavailable()` transition logic (UNAVAILABLE → HALF_OPEN) remains unchanged.
