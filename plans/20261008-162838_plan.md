# Plan: Provide reproducible startup for LLM services

## Goal

Add repository-managed service definitions and documented startup steps for the embedding LLM and agent LLM services, like the other services.

## Priority

Medium

## Scope

- **In-Scope**:
  - `deploy/setup_services.sh`: add actual LLM service startup logic (subprocess management)
  - `deploy/`: add systemd service definitions or equivalent for embed-llm and agent-llm
  - `docs/90_deployment/deployment_01_deployment.md`: update deployment procedure with LLM service startup steps
  - `deploy/deploy.sh`: fix header comment about Agent starting LLM
- **Out-of-Scope**:
  - LLM model download procedures
  - LLM configuration file creation
  - Health check endpoint changes

## Background

Source: local investigation notes (memo1.md, ISSUE-12), from DEPLOY-001.

## Problem

- No script, service definition, or configuration for starting embed-llm and agent-llm exists in the repository (per investigation notes).
- The header comment of `setup_services.sh` wrongly says the Agent starts the LLM.

## Reason for Change

- Operators cannot learn from the documentation how to start the LLM services, so recovery and rebuild are not reproducible.
- The embedding model dimension must match the RAG schema, but that prerequisite is not recorded in any procedure.

## Implementation Intent

- LLM services are started reproducibly from definitions inside the repository, like the other services.

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| LLM service not running + startup requested | Start via subprocess with health check |
| LLM service already running + startup requested | Skip (idempotent) |
| Model not loaded yet + health check fails | Wait with retry loop |
| Health check succeeds | Report success |

### Decision details

1. **Add LLM service startup logic to `setup_services.sh`**: Replace the placeholder `echo "起動: ${svc}"` loops with actual subprocess management using `PYTHONPATH=/opt/llm/scripts uv run python -m <module>` commands, similar to how Event Bus is started on line 87-90.
2. **Add health check retry loop for LLM services**: After starting LLM services, implement a retry loop that polls `/health` endpoints until they respond or timeout.
3. **Add systemd service definitions**: Create `embed-llm.service` and `agent-llm.service` files in `deploy/` with proper environment variables, working directory, and restart policies.
4. **Update deployment documentation**: Add LLM service startup steps to `deployment_01_deployment.md`, including model dimension prerequisites.
5. **Fix `deploy.sh` header comment**: Correct the misleading statement about Agent starting LLM.
