## Background
Three MCP servers use a fail-closed security model: when their allowlist is empty they deny all operations. The relevant fields are:
- git-mcp `allowed_repo_paths` (fail-closed; paths resolved via `Path.resolve()` before comparison).
- github-mcp `allowed_repos` (fail-closed; `owner/repo` format).
- cicd-mcp `repo_allowlist` (fail-closed) and `workflow_allowlist` (fail-closed; `owner/repo/.github/workflows/<file>` format).

Each server emits a startup warning when its allowlist is empty, and `scripts/agent/services/security_audit.py::audit_security_defaults()` additionally emits a `DENY-ALL detected: ...` warning at AgentREPL startup. The current configuration has empty allowlists for all three servers.

The canonical, editable copies of these configs live in the repository `config/` directory. `deploy/deploy.sh` copies every `config/*.toml` (including all three) into `/opt/llm/config/` at deploy time; the `/opt/llm/config/` copies are deployment artifacts, not edit targets.

## Problem
AgentREPL startup produces three DENY-ALL warnings and two cicd-mcp service-level warnings:

```
DENY-ALL detected: git.allowed_repo_paths is empty. git-mcp will reject ALL repository operations.
DENY-ALL detected: github.allowed_repos is empty. github-mcp will reject ALL repo access requests.
DENY-ALL detected: cicd.workflow_allowlist is empty. cicd-mcp will reject ALL workflow trigger requests.
cicd-mcp: repo_allowlist is empty — all repository operations will be denied
cicd-mcp: workflow_allowlist is empty — all workflow triggers will be denied
```

Empty allowlists cause complete denial of service for git/GitHub/workflow operations.

## Reason for change
Empty allowlists block all repository and workflow operations, removing the agent's ability to perform git, GitHub, and CI/CD tasks. Populating the allowlists restores these capabilities while preserving the fail-closed model (only explicitly listed repos/workflows are allowed).

## Implementation intent
Add explicit entries to each of the three empty allowlists in the repository `config/` copies, preserving every other setting in each file. Then redeploy the three files with `deploy.sh`. The exact entries (repository paths, repository names, workflow file paths) must be approved by a maintainer before being written — the specific values are the one unresolved element of this change.

## Design
The change is data-only: populate three empty TOML arrays in three repository config files. Each file keeps its existing structure and every other key. The fail-closed model is preserved — populating an allowlist grants access only to explicitly listed entries; it does not convert the servers to fail-open.

Entry formats (per `mcp_05_01_access-control-and-allowlists.md`):
- `allowed_repo_paths`: absolute filesystem paths; resolved via `Path.resolve()` before comparison, so symlinks/traversals cannot escape the list.
- `allowed_repos`: `owner/repo` strings.
- `repo_allowlist`: `owner/repo` strings.
- `workflow_allowlist`: `owner/repo/.github/workflows/<file>` strings.

Because the exact entries are an unresolved maintainer decision (UNK-01..03), the frozen rows specify "populate with maintainer-approved entries" rather than hardcoding values. The implementation phase resolves the values with the maintainer and writes them in; no concrete values are baked into this Plan.
