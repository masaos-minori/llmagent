## Background
`docs/10_adr/ADR-004-environment-failure-handling-policy.md` Decision 25-27 prohibit Fallback unless an Accepted ADR defines trigger, destination, eligibility, restrictions, result semantics, and observability. ADR-010 (`docs/10_adr/ADR-010-rag-fallback.md`) is the sole Accepted ADR that defines a Fallback. The INV-15/INV-16 audit recorded in the ADR-004 Manual Review classified every fallback-named path in `scripts/`; most are defensive patterns (default-value substitution, best-effort cleanup), but two were not classifiable and are tracked in this Issue. INV-03 states that a missing or invalid Workflow definition aborts startup.

## Problem
Two production paths substitute a degraded mode when a component fails, and no Accepted ADR explicitly defines either:
1. `scripts/agent/orchestrator.py`: on `WorkflowLoadError`/`FileNotFoundError` from `WorkflowLoader().load()`, the REPL continues in "fallback mode" with a sentinel workflow definition (`stages=[]`, `require_approval=False`).
2. `scripts/agent/memory/retriever.py` (`HybridRetriever.search()`): when the embedding is absent, the KNN call raises `sqlite3.OperationalError`, or returns no hits, retrieval degrades to FTS-only and increments `fts_fallback_count`.

Without a recorded decision these can be read either as sanctioned or as unreviewed fallbacks, which is exactly the ambiguity INV-15 exists to prevent.

## Reason for change
The ADR-004 Manual Review currently lists both paths as open (lines 452-456). Leaving them open preserves the ambiguity INV-15 targets; resolving them requires an owner judgment that the AI must not self-authorize.

## Implementation intent
Get an owner decision per path and record it. Do not invent a rationale. The plan structures implementation as gated branches that activate only after the recorded decision exists. Runtime behavior is untouched until an owner decides otherwise.

## Design
Evidence-based assessment of each path against ADR-004. This is the material presented to
the owner to inform the decision; it does not itself resolve the decision.

**Path 1 — `orchestrator.py` Workflow-loader fallback.** On `WorkflowLoadError` or
`FileNotFoundError`, the constructor installs `_FALLBACK_WORKFLOW_DEF`
(`stages=[]`, `require_approval=False`) and sets `_fallback_mode=True`; `handle_turn()`
then emits an error warning but still calls `_execute_turn()`. The sentinel deliberately
disables workflow-stage execution and approval. ADR-004 INV-03 mandates abort when the
Workflow definition is missing/invalid; Decision 17 forbids disabling a mandatory
component or Fallbacking unless an Accepted ADR permits it; Decision 65 forbids turning a
failure into "continuing execution after disabling a component." This path exhibits all six
elements of a Fallback (trigger = loader failure, destination = sentinel degraded workflow,
eligibility, restrictions, result semantics = degraded REPL, observability = log + warning)
yet is defined by no Accepted ADR. It therefore reads as a strong candidate for an
ADR-004-scope fallback that contradicts INV-03 — subject to the owner's ruling on whether
the Workflow engine is a mandatory component and whether the path is reachable (UNK-02).

**Path 2 — `retriever.py` vector-to-FTS degradation.** `HybridRetriever.search()` returns
FTS-only when the embedding is `None`, the KNN call raises `sqlite3.OperationalError`, or
the KNN returns no hits, incrementing `fts_fallback_count`. Both modes read the same
`memories` table, so this is a within-database query-mode switch, not a Destination
substitution to another system. That argues against ADR-004 scope; however the code
self-describes as "falling back" (log reason, counter name), producing genuine ambiguity.
Whether a within-database mode switch counts as a "Destination" under Decision 26 is the
definitional crux for the owner.

**Option space (per path).** (a) Classify as accepted current behavior and document the
rationale. (b) Define it in an Accepted ADR (or amend an existing one) with the six
elements of Decision 26. (c) Change the behavior. Runtime changes are out of scope until
an owner decides. Whichever ruling is taken should be recorded so future classifications
have a precedent (addressing INV-15's intent).
