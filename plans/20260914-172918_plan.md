# Plan: Harden SSE lifecycle, heartbeat, idle timeout, and broker health

## Goal

Unify heartbeat, idle-timeout, disconnect handling, and broker-availability reporting under one configuration and failure policy so subscriptions stay observable/releasable and health reporting degrades in a controlled way.

## Priority
Medium

## Scope
- **In-Scope**: SSE lifecycle/heartbeat/idle-timeout and broker-health reporting — adding `sse_idle_timeout` configuration, enforcing controlled degradation in health endpoint, unifying heartbeat/idle interaction semantics
- **Out-of-Scope**: Unrelated route handler rewrites, broker internals beyond health metrics exposure

## Background
Heartbeat, idle-timeout, disconnect handling, and broker-availability reporting for SSE subscriptions are coupled runtime-lifecycle concerns currently handled inconsistently; this issue unifies them under one configuration and failure policy so subscriptions stay observable/releasable and health reporting degrades in a controlled way.

## Problem
When the broker is unavailable, the health endpoint risks raising an internal exception rather than returning a controlled degraded response, and there is no `sse_idle_timeout` configuration key (only `sse_heartbeat_interval` currently exists per the source review), so idle-subscription behavior and its interaction with heartbeats is undefined.

## Reason for change
Heartbeat, idle timeout, disconnect handling, and broker availability are coupled runtime-lifecycle concerns and should use one configuration and failure policy.

## Implementation intent
Keep subscriptions observable and releasable during idle or degraded operation, and return controlled health results rather than propagating internal exceptions.

## Requirements
- `REQ-001`: Report `broker_unavailable` as a degraded reason when the broker is unavailable.
- `REQ-002`: Read the backlog threshold from EventBus configuration or guard broker access.
- `REQ-003`: Return a controlled HTTP 503 response instead of raising an internal exception.
- `REQ-004`: Evaluate the heartbeat deadline in the timeout branch of the live-delivery loop.
- `REQ-005`: Emit heartbeat comments independently of event arrival.
- `REQ-006`: Define how heartbeat activity interacts with the idle timeout.
- `REQ-007`: Add `sse_idle_timeout` to the dataclass, known keys, type validation, and configuration loader.
- `REQ-008`: Define its default and valid range.
- `REQ-009`: Validate its relationship with `sse_heartbeat_interval`.
- `REQ-010`: Update configuration documentation and examples.

## Design

### Broker Availability Reporting in Health Endpoint (REQ-001, REQ-002, REQ-003)
When the broker is unavailable (None), the health endpoint must return a controlled HTTP 503 response rather than raising an internal exception. Current code already guards broker property access with `if broker is not None:` at line 53, but the issue mentions broker initialization failure specifically.

The fix involves:
1. Adding `broker_unavailable` to `degraded_reasons` when broker is None
2. Ensuring the status_code is set to 503 when broker is unavailable
3. Guarding the backlog threshold check (line 65) which accesses `broker.backlog_health_threshold` outside the `if broker is not None:` block

```python
# Current (problematic):
if max_queue_depth >= broker.backlog_health_threshold:  # Line 65 — broker could be None
    degraded_reasons.append("broker_queue_backlog_high")

# Fix: Move inside the guard or add explicit None check
if broker is not None:
    if max_queue_depth >= broker.backlog_health_threshold:
        degraded_reasons.append("broker_queue_backlog_high")
else:
    degraded_reasons.append("broker_unavailable")
```

### SSE Lifecycle Unification (REQ-004, REQ-005, REQ-006)
Current state:
- `sse_heartbeat_interval` exists in config (default 30s) — used for periodic heartbeat comments
- `sse_idle_timeout` does NOT exist in config — falls back to `DEFAULT_SSE_IDLE_TIMEOUT = 60` module-level constant
- Heartbeat is emitted only during active delivery (when events arrive) — line 204-207
- Idle timeout checks `last_event_time` — line 185

**Decision**: Add `sse_idle_timeout` to the config dataclass with proper validation. Define the interaction between heartbeat activity and idle timeout:

**Heartbeat-idle interaction semantics**:
- **Heartbeat resets idle timeout**: If a heartbeat comment is emitted within the idle window, the connection is considered active and the idle timer resets. This prevents premature disconnection of clients that are connected but receiving no events.
- **Idle timeout applies independently of heartbeat**: The idle timeout is evaluated in the timeout branch of the live-delivery loop (REQ-004). When no events arrive AND no heartbeat was recently emitted, the connection is eligible for idle timeout.

```python
# In the live-delivery loop (subscribe_route.py:169-207):
while True:
    get_task = asyncio.ensure_future(sub.queue.get())
    disc_task = asyncio.ensure_future(sub.disconnect.wait())
    done, pending = await asyncio.wait(
        {get_task, disc_task},
        timeout=1.0,
        return_when=asyncio.FIRST_COMPLETED,
    )
    for p in pending:
        p.cancel()
    if disc_task in done:
        break
    if not done:
        if await request.is_disconnected():
            break
        # REQ-004: Evaluate heartbeat deadline in timeout branch
        now = time.time()
        elapsed_since_heartbeat = now - last_heartbeat_time
        elapsed_since_event = now - last_event_time
        
        # REQ-005: Emit heartbeat if deadline reached (independent of event arrival)
        if elapsed_since_heartbeat >= heartbeat_interval:
            yield ": heartbeat\n\n"
            last_heartbeat_time = now
        
        # REQ-006: Heartbeat activity resets idle timeout
        # Use the later of last_event_time and last_heartbeat_time as the effective last activity time
        last_activity_time = max(last_event_time, last_heartbeat_time)
        if elapsed_since_event > idle_timeout:
            logger.info(
                "subscribe idle timeout exceeded consumer=%s timeout=%.1f",
                consumer_id,
                idle_timeout,
            )
            break
        continue
    # ... event handling (unchanged)
```

### Configuration Addition (REQ-007, REQ-008, REQ-009)
Add `sse_idle_timeout` to the EventBusConfig dataclass:

```python
class EventBusConfig:
    # ... existing fields ...
    sse_heartbeat_interval: float = 30.0
    
    # NEW:
    sse_idle_timeout: float = 60.0  # Default matches current implicit DEFAULT_SSE_IDLE_TIMEOUT
```

**Default and valid range decisions**:
- Default: 60 seconds (matches current `DEFAULT_SSE_IDLE_TIMEOUT` constant)
- Valid range: [1.0, inf] — minimum 1 second to prevent rapid reconnect storms; no upper bound (infinity allowed for persistent subscriptions)
- Type: `float` — consistent with `sse_heartbeat_interval` type

**Cross-field validation**:
- `sse_idle_timeout` must be greater than `sse_heartbeat_interval` — a heartbeat interval longer than the idle timeout would cause heartbeats to never fire before the connection times out
- Validation error message: `"sse_idle_timeout ({idle}) must be greater than sse_heartbeat_interval ({heartbeat})"`

```python
# In config loader validation:
def _validate_sse_lifecycle(cfg: EventBusConfig) -> None:
    """Validate SSE lifecycle configuration cross-fields."""
    if cfg.sse_idle_timeout < 1.0:
        raise ValueError(f"sse_idle_timeout must be >= 1.0, got {cfg.sse_idle_timeout}")
    if cfg.sse_idle_timeout <= cfg.sse_heartbeat_interval:
        raise ValueError(
            f"sse_idle_timeout ({cfg.sse_idle_timeout}) must be greater than "
            f"sse_heartbeat_interval ({cfg.sse_heartbeat_interval})"
        )
```
