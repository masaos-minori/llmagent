## Background
`skills/DESIGN.md`'s "No concrete configuration values" section
(`skills/DESIGN.md:188-196`, confirmed unchanged 2026-09-20) states: "Do not
copy concrete values from `config/*.toml`... into design documents...
Describe the policy and its consequences instead... and point to the owning
configuration file for the current operational value." Direct reading
(2026-09-20) confirms all 3 target locations still contain exactly this
violation, unchanged since the source Issue was filed:
- `docs/03_rag_02_02_ingestion_pipeline-crawler.md:46-52` — table header
  `| Parameter | Code Fallback Value | Production Value (config/crawler.toml) |`.
  A pointer to `docs/03_rag_05_1-configuration-reference.md` already exists
  immediately below the table (line 54: "For a full list of parameters,
  see...") — this Plan's edit removes the duplicate table, not the existing
  pointer.
- `docs/03_rag_01_system_overview.md:205-215` — "## Constraints" table;
  rows 213-214 ("Crawl Depth", "Max Pages Per Site") explicitly restate
  "Operational value is 3... Differs from code fallback" / "Operational
  value is 200... Code fallback is 500"; rows 210-211 ("Chunk Size", "Chunk
  Overlap") restate `40`/`500`/`50` without an explicit comparison, but
  still duplicate `config/chunk_splitter.toml`'s `min_chunk`/`max_chunk`/
  `chunk_overlap` values.
- `docs/03_rag_05_5-constraints-reference.md:19-24` — rows "Chunk size
  range"/"Chunk overlap" (same `min_chunk`/`max_chunk`/`chunk_overlap`
  values a second time) and "Crawl depth"/"Max crawl pages" (same
  `max_depth`/`max_pages` comparison a third time, counting
  `system_overview.md`'s copy as the second).

`docs/03_rag_05_5-constraints-reference.md`'s own "Evidence" section (line
34, confirmed unchanged) documents a past staleness incident: earlier
versions stated `config/agent.toml:43`/"max 6 hops"/"max 500 pages", since
proven wrong (current values are `max_depth=3`/`max_pages=200`) — direct,
already-realized evidence of the drift risk this Plan addresses.

Two of the underlying "why this value" questions are already correctly
tracked in `docs/00_governance_03_issue-and-uncertainty-management.md`:
**NC-034** (`min_chunk`/`max_chunk`/`chunk_overlap`, confirmed unchanged) and
**NC-035** (`max_depth`/`max_pages`, confirmed unchanged). This Plan does not
create new NC entries — it points the 3 target files at these two instead of
letting them restate the values as fixed, self-contained facts.
`docs/03_rag_01_system_overview.md:217`'s own "Note" already states "No
empirical basis or trade-off analysis for these six constraint values is
recorded..." — the document's own author already flags this uncertainty for
all 6 rows in that table, 4 of which are this Plan's target.

## Problem
Restating the same configuration value in more than one design document (a)
goes stale the moment the operational config or code default changes, since
nothing enforces agreement across the copies, and (b) has already gone
stale once in this exact corpus.

## Reason for change
Proven documentation drift risk (an already-realized staleness incident,
not a hypothetical one) and duplication across 3 files of values that have
exactly one canonical owner (`docs/03_rag_05_1-configuration-reference.md`)
and, for the "why this value" question specifically, exactly one
already-tracked home (NC-034/NC-035).

## Implementation intent
For each of the 3 target files, replace the confirmed table/rows with (a) a
description of what the value controls and the boundary it exists to
enforce (e.g. crawl range bounded to prevent unbounded growth in processing
time, storage, and external-site load; chunk-size range bounded to keep
retrieval-unit granularity within a useful range), (b) a pointer to
`docs/03_rag_05_1-configuration-reference.md` for the current operational
value, and (c) a pointer to NC-035 (`max_depth`/`max_pages` rows) or NC-034
(`min_chunk`/`max_chunk`/`chunk_overlap` rows) for the "why this specific
value" rationale gap. `docs/03_rag_02_02_ingestion_pipeline-crawler.md`
already has a pointer to the configuration reference immediately below its
table — reuse it rather than duplicating a second pointer. Preserve every
other row/section in the 3 files unchanged, including
`system_overview.md`'s "Note" paragraph and every row not named in Scope.
