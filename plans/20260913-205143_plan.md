## Background
The Issue's three claims were independently re-verified against
`docs/03_rag_01_system_overview.md`'s current content and the codebase:

1. **Query Pipeline** (lines 94-101): the section already states the 5-stage flow
   (MQE → Search → Fusion → Rerank → Augmentation) with an entrypoint and caller —
   the Issue's claim that it "doesn't explain the overall flow" overstates the gap;
   what is missing is a one-line description of *what each stage does*, not the flow
   itself
2. **Semantic Cache** (lines 103-105): the section describes `use_semantic_cache`,
   `semantic_cache_threshold` (cosine-similarity gating), and
   `semantic_cache_max_size` (FIFO eviction) as if the feature is active. **This
   feature was deliberately removed** — confirmed via `git log`:
   `282b08f38 req-005: remove SemanticCache from RAG pipeline and MCP server`,
   followed by `09093016d feat(rag): remove semantic cache configuration fields and
   references`, whose commit message states these three exact config keys were
   removed and replaced by `RagConfigValidator._check_removed_semantic_cache_keys()`
   (`scripts/shared/config_validator.py:55-73`), which now returns a migration error
   if any of `use_semantic_cache`/`semantic_cache_threshold`/`semantic_cache_max_size`
   is present in a config source. Confirmed via `rg
   "use_semantic_cache|semantic_cache_threshold|semantic_cache_max_size|SemanticCache"
   scripts/` that no active implementation of this feature exists anywhere in
   `scripts/rag/` or `scripts/mcp_servers/rag_pipeline/` — the only remaining
   references are the removal-rejection validator and an unrelated
   `stat_semantic_cache_hits` agent-side statistics counter
   (`scripts/agent/context.py:219`) that is a leftover metric field, not the cache
   feature itself. The Issue's Recommended Action ("Document TTL, invalidation
   triggers, and consistency guarantees") is inapplicable to a removed feature —
   this Plan corrects the section instead
3. **MCP Server Responsibility Division** (lines 134-136): confirmed accurate as
   described — the section is a single sentence referring entirely to
   `docs/03_rag_03_01_query_pipeline-overview.md` with no inline summary. Reading the
   three components' own module docstrings establishes a clear, concise division:
   `rag_pipeline_server.py` (HTTP/MCP protocol layer — endpoint routing, tool
   listing, health check, debug endpoint), `rag_pipeline_service.py`
   (`RagPipelineMCPService` — service layer wrapping `RagPipeline` for MCP use), and
   `scripts/rag/pipeline.py` (`RagPipeline` — the core pipeline logic itself,
   MQE→Search→RRF→Rerank→Augment)

## Problem
1. The "Query Pipeline" section names the 5 stages but does not say what each one
   does, requiring a reader to open the detailed per-stage documents even for a
   one-line summary
2. The "Semantic Cache" section actively misinforms readers that a removed feature
   is active, including specific (now-nonexistent) configuration parameters and
   behavior
3. The "MCP Server Responsibility Division" section provides no inline information,
   requiring a reader to leave the overview document even to learn the high-level
   division of responsibility

## Reason for change
Bring the overview document's three sections in line with the current codebase:
add the missing one-line stage summaries, replace the stale semantic-cache
description with an accurate "removed" note, and add a concrete MCP responsibility
summary — all while preserving existing cross-references to the detailed documents
for readers who need more depth.

## Design
This task is classified as **Path A** (small task): affects 1 file, no public
interface changes, no database schema changes, no source code changes at all
(documentation-only).

This cycle's re-verification found the Issue's three claims required three
different responses: the Query Pipeline claim was somewhat overstated (the flow
already exists, only per-stage descriptions were missing); the MCP Server
Responsibility Division claim was accurate as stated; and the Semantic Cache claim
required the opposite action from what the Issue's Recommended Action proposed
(the feature does not exist to document further — it must be marked removed).

Key design decisions:
1. Use a textual one-line-per-stage summary for Query Pipeline rather than a
   diagram — this document's existing style (tables, short prose) does not use
   diagrams elsewhere, and a diagram would be a larger, disproportionate addition
   for what the Issue's own evidence shows is a small gap (missing one-line
   descriptions, not a missing flow)
2. Replace, rather than delete, the Semantic Cache section — a reader who
   encounters `use_semantic_cache` in an old config or a stale reference elsewhere
   benefits from an explicit "this was removed" note with the removal commit cited,
   rather than the section disappearing silently
3. Add the MCP responsibility summary as a supplement to, not a replacement for,
   the existing cross-reference — `docs/03_rag_03_01_query_pipeline-overview.md`
   remains the authoritative detailed source; this overview should summarize, not
   duplicate, that document
