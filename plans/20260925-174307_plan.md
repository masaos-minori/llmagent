## Background
The ADR Index file resides at `docs/10_adr/adr-index.md`. Two governance documents under `docs/00_governance/` link to it with paths that do not resolve: from `docs/00_governance/`, `../adr-index.md` resolves to `docs/adr-index.md`, which does not exist. A prior partial fix (`e556f99d`) changed both links to `../adr-index.md`, which is still broken. The correct relative path from `docs/00_governance/` to `docs/10_adr/adr-index.md` is `../10_adr/adr-index.md`.

## Problem
Two markdown hyperlinks in `docs/00_governance/` point to a non-existent `docs/adr-index.md`:
- `docs/00_governance/00_index.md` line 27: `[ADR Index](../adr-index.md)`
- `docs/00_governance/00_governance_01_documentation-policy.md` line 545: `[ADR Index](../adr-index.md)`

`check_docs_structure.py` reports `broken link -> '../adr-index.md'` for both files. This breaks human navigation and fails the link-reachability portion of the ADR invariant checks.

## Reason for change
Broken links violate the documentation structure validation rules (check #8 in `docs/00_governance/00_governance_04_documentation-checks.md`) and cross-area link rules (`docs/00_governance/00_governance_02_documentation-metadata.md`, line 130: "For cross-area references, use full filenames with path"). The end state required by the source issue is `[ADR Index](../10_adr/adr-index.md)` in both files.

## Implementation intent
Replace the broken link target string `../adr-index.md` with `../10_adr/adr-index.md` in each of the two hyperlinks, preserving every other character on those lines. No structural, front-matter, or content changes beyond the link target.

## Requirements
