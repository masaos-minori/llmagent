## Goal
Remove the self-recursive `subprocess.run(["uv", "run", "pytest", "tests/agent/test_tool_approval_preflight.py", "-v"])` call in `tests/agent/test_tool_approval_preflight.py::TestRunApprovalChecks::test_regression_existing_agent_tests_pass`, which re-invokes pytest on the same file it is itself collected from — recursively spawning nested subprocesses of the same file (each containing this same test) — causing unbounded/very-long-running execution and likely contributing to a host memory-pressure event observed during this session's full-suite investigation.

## Background
This test was confirmed, via direct source inspection during this session's full-suite failure investigation, to call `subprocess.run(["uv", "run", "pytest", "tests/agent/test_tool_approval_preflight.py", "-v"])` — i.e. it re-runs the entire file it is itself a member of. Since that re-run's own collection includes this same test, each subprocess spawns another nested subprocess recursively. Two attempts to run this single test in isolation (90-second and 400-second timeouts) both failed to complete. This is very likely the root cause (or a major contributing factor) of an unrelated background full-suite pytest run being killed by the harness for host memory pressure earlier in the same investigation session.

## Problem
`test_regression_existing_agent_tests_pass`'s `subprocess.run(...)` call recurses indefinitely (in practice, until process/memory limits are hit), because the subprocess it spawns re-collects and re-executes this same test, which spawns another subprocess, and so on. This makes the test effectively un-runnable (never completes within any reasonable timeout) and poses an environment-stability risk when the file or full suite is run.

## Reason for change
A test that cannot complete and can exhaust host memory/CPU when triggered is both a correctness defect (it never actually verifies anything — it does not complete) and an operational risk to the CI/dev environment. It must be fixed before it causes further instability.

## Implementation intent
Remove the test entirely. Its evident intent — "confirm this file's other tests still pass as a regression check" — is structurally circular when implemented via subprocess re-invocation of the same file (the regression test is itself one of the tests being re-checked), and the file's own other tests already provide direct, non-recursive coverage of the same behaviors when the file (or full suite) is run normally. Do not replace it with a deselect-based variant (e.g. `-k 'not test_regression_existing_agent_tests_pass'`) or a differently-scoped subprocess call, since either still adds a redundant, fragile subprocess-based self-check with no coverage benefit over simply running the file's tests directly (which any invocation of this file, or the full suite, already does).
