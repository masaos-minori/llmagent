## Design
This is a documentation cleanup with no behavioral effect. Two design decisions drive the exact wording:

- **Pointer by title/filename, not by concept.** The replacement references `governance_03_issue-and-uncertainty-management.md` by name, never by the phrase "Needs Confirmation". The inventory checker's marker regex is `needs confirmation` (case-insensitive) and treats any occurrence in a non-exempt doc as an untracked marker. Naming the doc by its title ("Issue and Uncertainty Management") / filename conveys the pointer while avoiding a self-created warning.
- **Removal, not correction-with-equivalent-statement, for the false claims.** The two Known Limitations bullets assert a flag mechanism that does not exist anywhere in `docs/23_agent/`. There is no true statement to substitute, so deletion is the correct action. Reintroducing an analogous claim would merely move the false statement elsewhere.
- **Scope discipline.** Only the six identified markers are touched. The pre-existing repeated Key Constraints / Known Limitations blocks in `agent_13_reference-api.md` are left intact; deduplicating them is unrelated work excluded per the project's no-unrelated-refactoring policy.
