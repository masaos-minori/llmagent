## Problem

- `validation.md` lines 44-47 state the order "Run `mypy`. Cross-check with
  `pyright`. Run `ruff`. Run characterization tests." `workflow.md` line 236 (Step 6:
  Transformation) states "Run `ruff format` and `ruff check --fix` after each
  transformation" and line 273 (Step 8: Incremental Migration) states "Run tests,
  `ruff`, and `mypy` once per logical group" — confirmed at the exact line numbers the
  Issue cites. One nuance found during verification, not present in the Issue's own
  framing: lines 236 and 273 belong to two different Steps (6 and 8, not both "Step
  6"), and Step 7 (Validation) itself is simply "Follow `validation.md` Required
  Validation and Conditional Validation in full" with no order of its own beyond what
  `validation.md` states. This does not change the substance of the finding — an
  agent reading `validation.md` in isolation, without cross-referencing `workflow.md`
  Step 6's already-completed post-transform `ruff` pass, would still read `validation.md`'s
  stated order as "mypy first, ruff last," which is the reverse of the ruff-then-
  typecheck sequencing the rest of the file's workflow actually depends on.
- `report-template.md`'s Completion Gate (lines 90-108) lists 9 pass conditions with a
  closing sentence at line 108: "If any item is not satisfied, do not report the task
  as complete." This is confirmed present — a partial exit condition already exists,
  contrary to the Issue's framing of "no exit/Blocked condition" as a complete
  absence. However, line 108 does not route to this file's own `Blocked` status
  vocabulary (used elsewhere at lines 27, 71, 84, and 101) — it says only "do not
  report...complete," not "report `Blocked`." The Issue's underlying concern (no
  explicit connection to the `Blocked` vocabulary) is confirmed; its literal framing
  ("no exit/Blocked condition" at all) is corrected here to "an exit condition exists
  but does not use this file's own `Blocked` vocabulary."

## Reason for change
`validation.md`'s stated order, read on its own (e.g. by an agent that consults it
without also having `workflow.md` Step 6 loaded), would lead to running mypy/pyright
before the post-transform `ruff format`/`--fix` pass — producing mypy findings against
not-yet-reformatted code, which is wasted or misleading work. The Completion Gate's
exit condition, while present, does not connect to this file's own `Blocked` status
vocabulary used consistently elsewhere in the same template, leaving ambiguous whether
an unsatisfied item should be reported the same way as other `Blocked` conditions in
this file.

## Implementation intent
Correct `validation.md`'s stated order to match `workflow.md`'s actual ruff-first
sequence; update the Completion Gate's existing line 108 exit condition to explicitly
route to `Blocked` status, using this file's own existing vocabulary, rather than
leaving it as a bare "do not report complete" statement disconnected from that
vocabulary.
