## Goal
- Enable the shell MCP server sandbox by switching `shell_sandbox_backend` from `"none"` to `"firejail"` so that AgentREPL can start (the `"none"` value is a fatal startup blocker) and shell commands run inside sandbox isolation. Requires installing the `firejail` binary on the deployment host before the config change takes effect.

## Background
The shell MCP server supports two sandbox backends (`scripts/shared/protocols/shell.py`):
- `"firejail"` — sandboxed execution via firejail (requires the firejail binary in PATH).
- `"none"` — unsandboxed execution.

`scripts/agent/services/security_audit.py:89-91` raises `RuntimeError("shell_sandbox_backend=none is not permitted regardless of environment")` when the configured backend is `"none"`. This audit runs unconditionally during startup (`scripts/agent/startup_validation.py:44`), and a raised `RuntimeError` is recorded as a FATAL pipeline error (`startup_validation.py:48-53`), so AgentREPL cannot start with `"none"`.

`scripts/mcp_servers/shell/shell_service_static_helpers.py:34-37` (`init_sandbox`) additionally raises `RuntimeError` when `shell_sandbox_backend="firejail"` is configured but the `firejail` binary is missing from PATH. Therefore the binary must be installed BEFORE the config is switched to `"firejail"`, otherwise the agent still cannot start.

The repo config comment already states the requirement (`config/shell_mcp_server.toml` lines 27-30): production sets `"firejail"` (requires `apt-get install firejail`); the binary-missing case raises at startup.

## Problem
Startup fails with:
```
RuntimeError: shell_sandbox_backend=none is not permitted regardless of environment
```
This is a fatal error — AgentREPL cannot start while `shell_sandbox_backend` is `"none"`.

## Reason for change
Unsandboxed shell execution allows arbitrary command execution without resource limits or isolation. This is also a hard startup blocker — AgentREPL cannot start with `sandbox_backend="none"`.

## Implementation intent
Install `firejail` on the deployment host, then set `shell_sandbox_backend = "firejail"` in `config/shell_mcp_server.toml`, then redeploy via `deploy.sh`, then verify startup and sandboxed execution.

## Requirements
- `REQ-001`: `firejail` is installed on the deployment host and `command -v firejail` succeeds.
- `REQ-002`: `config/shell_mcp_server.toml` line 31 reads `shell_sandbox_backend = "firejail"`.
- `REQ-003`: The deployed `/opt/llm/config/shell_mcp_server.toml` matches the repo (via `deploy.sh`).
- `REQ-004`: AgentREPL starts without the sandbox fatal error; existing shell tool calls work within the sandbox.
- `REQ-005`: Deployment documentation names `firejail` as a required dependency.
