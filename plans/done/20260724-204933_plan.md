## Goal

Show the memory disabled warning immediately after startup completes, rather than waiting for the first user input.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _run_repl_loop()), `scripts/agent/startup.py` (StartupOrchestrator._setup_prompt())
**Out**: Changes to memory injection logic, other startup warnings

## Assumptions

1. `ctx.conv.memory_disabled` is set during startup by `_setup_prompt()` when memory injection fails
2. `memory_warning_shown` flag prevents duplicate warnings within the same session
3. CLIView.write_warning writes to the terminal regardless of whether REPL loop has started

## Implementation Steps

1. In `AgentREPL.run()`, after `StartupOrchestrator.run()` succeeds (line 508), add a check for `self._ctx.conv.memory_disabled and not self._ctx.conv.memory_warning_shown`.
2. If both conditions are true, emit the warning using `self._view.write_warning(f"{OutputTag.NON_FATAL} Memory is disabled for this session.")` and set `self._ctx.conv.memory_warning_shown = True`.
3. Remove or keep the existing check in `_repl_loop` (lines 309-313) as a safety net — the idempotency guard (`memory_warning_shown`) ensures no duplicate warnings.
4. Verify the warning is displayed even if the user closes the REPL immediately via SIGTERM or /exit.
