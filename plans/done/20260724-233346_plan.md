## Goal

Ensure signal-induced shutdown is detected immediately by the event loop without relying on the asyncio.Event mechanism that introduces latency through the event loop scheduling cycle.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _read_input(), _sigterm_handler())
**Out**: Changes to signal handling outside the REPL, other async event patterns

## Assumptions

1. Signal handlers must remain synchronous — cannot use async operations inside them
2. Canceling a Future from a signal handler is safe — it just sets a flag on the Future object
3. Windows doesn't support `loop.add_signal_handler()` — already handled with fallback

## Unknowns

| Unknown | Evidence missing | Resolution | Blocking |
|---|---|---|---|
| Whether cancelling input_coro from a signal handler is safe on all platforms | Need to verify asyncio.Future.cancel() is thread-safe from signal context | Analyze asyncio source code behavior | no |

Analysis: `Future.cancel()` is safe to call from any context including signal handlers. It sets an internal flag and schedules a callback on the next event loop iteration. No blocking or threading issues.

## Design

Replace the asyncio.Event-based shutdown detection with direct `input_coro.cancel()` from the signal handler. When the signal arrives, cancel the pending input future so `asyncio.wait()` returns immediately. Set `shutdown_requested` flag as a side effect. Remove the `_shutdown_watcher` coroutine entirely since it's no longer needed.

```python
        self._shutdown_event = asyncio.Event()

        def _sigterm_handler() -> None:
            """Handle SIGTERM by setting shutdown flag on context and event."""
            self._ctx.conv.shutdown_requested = True
            if self._shutdown_event is not None:

```

Change to:

```python
        loop = asyncio.get_running_loop()
        self._shutdown_event = asyncio.Event()
        self._pending_input_task: asyncio.Task[str] | None = None

        def _sigterm_handler() -> None:
            """Handle SIGTERM by canceling pending input and setting shutdown flag."""
            self._ctx.conv.shutdown_requested = True
            if self._pending_input_task is not None:
                self._pending_input_task.cancel()
            if self._shutdown_event is not None:
                self._shutdown_event.set()
            logger.info("SIGTERM received; graceful shutdown initiated")

        import signal as _signal

        for sig in (signal.SIGTERM, signal.SIGINT):
            try:
                loop.add_signal_handler(sig, _sigterm_handler)
            except NotImplementedError:
                _signal.signal(sig, lambda *_: _sigterm_handler())
```

Key points:
- Added `self._pending_input_task` instance variable to track the input coroutine
- Signal handler cancels the pending input task instead of just setting the event
- Event still set for consistency with existing shutdown path logic
- Input task reference stored before being passed to `asyncio.wait()`
