# Plan: Detect orphaned Needs Confirmation markers in governance docs

## Goal

Make `tools/check_needs_confirmation_inventory.py` distinguish between definitional/discussion uses of the "Needs Confirmation" label and actual unresolved-item markers inside governance documents, so that orphaned markers in governance docs are detected without flooding false positives from definition text.

## Priority

Medium

## Scope

- **In-Scope**: Modify `_GOVERNANCE_META_DOCS` handling in `check_untracked_inline_markers()` to detect unresolved-item markers while exempting definitional mentions; add regression tests; record exit-status decision for untracked-marker warnings.
- **Out-of-Scope**: Registering or resolving existing untracked markers in `docs/23_agent/` and `docs/21_rag/`; resolving Policy Area Canonical Maps markers (canon001); changing Inventory entry format; editing `docs/00_governance/governance_01_documentation-policy.md` content.

## Background

The Needs Confirmation Inventory in `docs/00_governance/governance_03_issue-and-uncertainty-management.md` is the single central place for unresolved items; a marker left only in an individual document is not allowed. The checker excludes `_GOVERNANCE_META_DOCS` (all five `governance_0[0-4]_*.md` files) in `check_untracked_inline_markers()`, because those documents define and cross-reference the label itself. This exclusion prevents false positives from definitional text but also hides genuine unresolved-item markers.

## Problem

The checker reports nothing for governance documents when looking for untracked inline Needs Confirmation markers. Because of this, any orphaned markers in governance docs go undetected, violating the inventory's role as the single central place for unresolved items.

## Reason for change

The work in canon001 requires proving that no orphaned Needs Confirmation marker remains in the Policy; the current checker cannot provide that evidence, so verification would rely on manual grep only.

## Implementation intent

Keep governance docs exempt for definitional/discussion uses of the label, but detect marker uses that denote an unresolved item (for example a Needs Confirmation status value in a table cell, or a parenthesized status annotation). Prefer a narrow, explicit rule (pattern or section-scoped) over removing the exemption entirely, to avoid flooding false positives from the label's definition text. Keep the output format and existing severities unless the confirmed intent requires change.

## Requirements

- `REQ-001`: Define which marker forms inside governance docs count as unresolved-item markers (e.g., Needs Confirmation status value in a table cell, parenthesized status annotation).
- `REQ-002`: Report those markers when they have no matching Inventory entry.
- `REQ-003`: Add regression tests: a governance doc fixture with a definitional mention (not reported) and a status-cell marker (reported).
- `REQ-004`: Record the decision on whether untracked-marker warnings should cause a non-zero exit.

## Design

### Approach

Extend `_GOVERNANCE_META_DOCS` handling in `check_untracked_inline_markers()` to allow detection of unresolved-item markers while still exempting definitional/discussion uses. The key insight is that the exemption should apply to definitional text (mentions of the label itself) but not to actual unresolved-item markers (status values in table cells, parenthesized annotations).

### Decision Target Matching Logic

Before processing each error in `_wrap_validation_errors`, add:

```python
if entry.decision_target and entry.decision_target not in err:
    continue
```

This ensures each finding is only emitted for the entry that actually caused the error — no cross-product duplication.

### Marker Classification Rule

After inspecting all five governance docs, classify each "Needs Confirmation" occurrence as either:

1. **Definitional**: Text that defines, discusses, or references the label itself (e.g., "A Needs Confirmation marker indicates...", "See the Needs Confirmation Inventory"). These are exempt.
2. **Unresolved-item marker**: Text that denotes an actual unresolved item (e.g., a table cell containing "Needs Confirmation" as a status value, or a parenthesized annotation like "(Needs Confirmation)"). These are reported.

The classification will be encoded as a regex pattern or section-scoped exclusion list, depending on what the inspection reveals.

### Exit Status Decision

Document the decision on whether untracked-marker warnings should cause a non-zero exit. Based on the issue's observation that "the checker exits 0 even when such warnings exist," and the issue's statement that "Whether warnings should fail verification is Needs confirmation," the decision should be recorded in the plan's Unknowns table and implemented accordingly.
