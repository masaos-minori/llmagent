# Plan: Move cleanup_server_key after confirmed termination

## Goal
Only remove tracking entries after confirmed process termination, preventing orphaned processes when shutdown fails.

## Priority
High

## Scope
- **In-Scope**: Modify `ShutdownCoordinator.shutdown_all()` to conditionally call `cleanup_server_key()` only after successful termination; add regression tests
- **Out-of-Scope**: Changes to `ProcessTerminator.terminate_with_timeout()` itself; changes to `cleanup_server_key()` implementation

## Background
`ShutdownCoordinator.shutdown_all()` in `scripts/agent/http_lifecycle_shutdown_coordinator.py` coordinates graceful shutdown of HTTP subprocess MCP servers. It delegates termination to `ProcessTerminator.terminate_with_timeout()` and then calls `cleanup_server_key()` to remove tracking entries.

## Problem
When `terminate_with_timeout()` fails (caught by the except block), `cleanup_server_key()` is still called unconditionally. This removes tracking data while the process may still be running, creating orphaned processes.

## Reason for change
Process continues running without tracking — zombie process. Subsequent attempts to shut down the same server will not find it. Resource leak (file descriptors, ports, memory).

## Implementation intent
Move the `cleanup_server_key()` call inside the try block so it only executes after successful termination. On failure, keep the tracking entry intact so subsequent cleanup attempts can target the process.

## Requirements
- `REQ-001`: Tracking data is removed only after confirmed process termination
- `REQ-002`: Failed termination leaves tracking entry intact for retry
- `REQ-003`: Test verifies no zombie process after shutdown failure scenario
- `REQ-004`: Test verifies tracking entry persists on termination failure
