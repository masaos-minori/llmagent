## Goal

Ensure all resources acquired during the startup phase are released regardless of whether startup succeeds or fails.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _close_resources()), `scripts/agent/startup.py` (StartupOrchestrator._start_servers())
**Out**: MCP subprocess management logic, HTTP client lifecycle outside startup path

## Assumptions

1. `_close_resources()` is only called from `AgentREPL.run()` finally block
2. `self._ctx.services` can be None when `build_agent_context()` never completed
3. MCP subprocess cleanup requires tracking spawned processes from `_start_servers()`

## Implementation Steps

1. In `AgentREPL.run()`, wrap the startup call in a try/finally that calls `_close_resources()` unconditionally. Move the except handler inside the try so it re-raises after cleanup.
2. Refactor `_close_resources()` to handle `self._ctx.services is None` — skip lifecycle shutdown and HTTP close if services were never initialized.
3. In `StartupOrchestrator._start_servers()`, collect any successfully spawned MCP subprocesses into a list returned alongside the success/failure result.
4. Pass the subprocess list back through `StartupOrchestrator.run()` to `AgentREPL.run()`.
5. In the finally block of `AgentREPL.run()`, terminate any subprocesses collected during partial-start before calling `_close_resources()`.
6. Verify no new exceptions introduced by the cleanup logic.
