## Problem

`skills/deploy/workflow.md` lines 100-148: Phase 3's sub-steps each already have an

and, where applicable, a failure/stop condition (Step 3c line 114 "If a service does
not return OK within 30 seconds of restart: proceed to Step 3d"; Step 3d line 129
"Stop and report to the user when..."). Phase 4 (lines 135-148) states a Gate
("service is running; no new errors in logs") and the verification commands (`curl`/

"Completed when" line nor a failure-routing line — confirmed absent by direct reading
of the full Phase 4 section. This matches the Issue's claim exactly.

## Reason for change
Deployment verification is the last safety check before a change is considered live in
production; per `AGENTS.md`'s emphasis on deployment as a high-blast-radius operation,
this Phase having no stated pass/fail condition is a higher-severity gap than the same
omission would be in a lower-stakes skill — an agent could run the checks, see an
ambiguous or partially-bad result, and have no stated next step.

## Implementation intent
Add a "Completed when" line stating the concrete pass condition (health check returns
OK for every restarted service, log tail shows no new error since the restart
timestamp, and — if the agent was restarted — `/mcp` shows every server healthy), and
an "If any check fails" line routing back to Phase 3d's existing failure-recovery
procedure for the affected service, rather than duplicating it.

## Requirements
- `REQ-001`: Phase 4 — add "**Completed when**: every restarted service's `/health`
  endpoint returns OK, the log tail shows no new error timestamped after the restart,
  and (if the agent was restarted) `/mcp` shows every MCP server healthy."
- `REQ-002`: Phase 4 — add "**If any check fails**: return to Phase 3d's
  failure-recovery procedure for the affected service rather than repeating ad hoc
