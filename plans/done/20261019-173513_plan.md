## Goal
- Rename the 14 ADR files `docs/10_adr/adr_02_NNN_*.md` to `adr_02_<GG>_<NNN>_<group>-<topic>.md` so that ADRs of one theme are adjacent in a directory listing, keeping every ADR ID and all ADR content unchanged, and update every reference, name-shape pattern, test, rule, and size ceiling that depends on the old shape, in a single commit.

## Priority
Medium

## Background
- Request from `memo1.md` (2026-10-19): review the relationships among the ADR files and propose grouped names; the owner chose the group-number-first scheme (option B) and asked for the issue (`issues/20261019-170548_adrname001_group-adr-file-names-by-theme.md`).
- ADR relationships from the bodies: ADR-002 and ADR-004 are each referenced by 10 ADRs; ADR-014 references 001, 002, 003, 004 and ADR-003 references 001, 002, 004; ADR-012 references 007; ADR-013 references 006; ADR-009 and ADR-010 reference 005; ADR-008 references 002, 004, 005, 006, 013; ADR-015 references none. ADR-011 is intentionally unassigned (stated in `adr_01_index.md`).

## Problem
- Related ADRs are not adjacent by name, and the current names carry no theme element (six slugs already begin with a theme word).
- Source inspection (2026-10-19) shows what the rename breaks if done naively:
  - `ADR_ID_RE = ^adr_02_(\d+)_` reads the group number as the ADR ID for the new names (`adr_02_01_002_...` gives `01`), so `check_unique_adr_ids` reports false duplicates.
  - `_ADR_FILE_RE = ^adr_02_\d{3}_.*\.md$` stops matching, and `check_section_headings` and `check_template_residue` then `continue` past every ADR, so the checks would pass vacuously.
  - `check_workitem_traceability` resolves `ADR-NNN` through the glob `docs/10_adr/adr_02_{id}_*.md`, which would match nothing.
  - `SIZE_EXCEPTIONS` is keyed by old file names; three ADRs would exceed their ceilings (ADR-003 26602 against 26592, ADR-004 32305 against 32280, ADR-007 24596 against the 24576 default), because the longer names appear in ADR bodies and front matter.
- `tools/rename_doc.py` (dry-run on ADR-002, 2026-10-19) rewrites front matter `related:` entries and bare or sibling-style links, but reports `../10_adr/<file>` links as unresolved and never rewrites prose or backticked mentions (for example the Reading Order table in `adr_00_document-guide.md`). It cannot be the only mechanism for 183 references.
- `tools/check_adr_preservation.py` compares each changed file with `git show <base>:<path>` using the new path, so it cannot compare a renamed file (expected from `changed_docs` and the `git show` call).
- Reference counts (2026-10-19, excluding the done-archives): 183 references in 51 files under `docs/`, 3 in 2 files under `scripts/`, 2 in 1 file under `skills/`, 43 in 7 files under `tests/`, and 29 in 10 files under `tools/`. No match was found in `.github/`, `.pre-commit-config.yaml`, `templates/`, `prompts/`, `rules/`, or `config/`. Docs churn is high (375 commits under `docs/` in 30 days), so conflicts with concurrent documentation work are likely.

## Reason for Change
- Maintainability and navigability: theme grouping by name lets people and agents find related ADRs by listing the directory.
- The patterns that would silently stop working (vacuous heading checks, wrong ADR IDs) make this a change that must be done together with its tool and test updates, not as a plain rename.

Glob and placeholder forms (`adr_02_{NNN}_*.md`, `adr_02_NNN_*.md`, `adr_02_{next-number}_{slug}.md`, and the `adr_02_007_*.md`-style globs in the Resolution Matrix) are edited by hand.
- Prove the change is names-only: for each renamed ADR, take `git show HEAD:<old path>`, replace the 14 old names with the new ones, and require equality with the new file content (a throwaway script outside the repository); this replaces `check_adr_preservation.py`, which cannot follow renames.
- Do the whole change in one commit on a clean, up-to-date tree; run every checker before committing.
- Guard against silent skipping: tests assert that every real `adr_02_*` file matches `_ADR_FILE_RE` and that `ADR_ID_RE` yields 14 unique IDs.
