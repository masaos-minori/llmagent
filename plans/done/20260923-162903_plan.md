## Background

ADR-014 (Agent Control Plane Responsibility Boundaries) defines INV-024: "LlmTurnExecutor instance construction is centralized in the component that drives the LLM/tool-call loop; no other component holds an unused or duplicate instance." The invariant was recorded as "Violated" because `Orchestrator.__init__` constructed an unused `self._llm_runner`, duplicating the instance `LlmTurnExecutor` constructs and actually uses.

Direct verification against current source confirms:
- `grep -rn '_llm_runner' scripts/agent/` returns zero matches (attribute no longer exists)
- `Orchestrator.__init__` constructs `self._llm_executor = LlmTurnExecutor(...)` at line 139
- `self._llm_executor` is actively used: passed to `WorkflowEngineAdapter` (line 168), called directly via `await self._llm_executor.handle_llm_turn(...)` (line 275)
- Tests extensively reference `orch._llm_executor` (27 occurrences across 2 test files)
- No duplicate instance exists — only one `LlmTurnExecutor` instance is constructed per `Orchestrator` lifetime

## Problem

The INV-024 violation record in adr-index.md and ADR-014 documents a problem that has already been resolved. Keeping the "Violated" status misleads readers into thinking there is an unresolved architectural issue.
