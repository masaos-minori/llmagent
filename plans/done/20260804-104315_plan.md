## Design

No architectural change. This is a characterization-test repair: align the test file's imports and
assertions with the verified current behavior of `AgentContext`, `resolve_approval`, and
`update_task_status`, without touching production code.

- **Import layer:** `TurnContext` → `AgentContext` (`agent.context`); `update_task_status` moves from
  `agent.workflow.approval_ops` (wrong, never defined there) to `agent.workflow.task_ops` (correct,
  matches the pattern in every other test file in this directory).
- **`TestPendingApprovalIdClearing`:** narrow the two "cleared" tests' assertions to `resolve_approval`'s
  real, DB-only contract (per UNK-01/option b). `test_pending_approval_id_not_cleared_before_resolution`
  is unaffected — it never calls a clearing path and needs no changes beyond the `ctx` construction fix.
- **`TestHaltedTaskStatusRejection`:** narrow `test_halted_task_prevents_resume`'s assertion to the real
  outcome (no exception) per UNK-03; `test_halted_task_returns_error` and
  `test_running_task_allows_resume` need only the mechanical import fix.
- **`TestTaskIdOverwriteDetection` and `TestMultipleSequentialApprovals`:** need only the mechanical
  `ctx = AgentContext()` fix (2 call sites in the former); the latter class doesn't instantiate `ctx`
  at all and needs no test-body change.
- Preserve existing docstrings/class groupings/`_make_db` helper, per the requirement's own
  instruction, changing only what's necessary for imports to resolve and assertions to match verified
  behavior.

## Risks

- **R1 — Removing the `RuntimeError` expectation from `test_halted_task_prevents_resume` erases the
  only regression guard for "should a halted task's approval be resolvable."** If halted-task rejection
  is actually desired product behavior (just unimplemented), downgrading this test to a passing
  characterization means no test will ever flag its continued absence.
  Likelihood: Medium. Mitigation: **filed as a separate risk issue** (see below) asking a maintainer to
  decide whether `resolve_approval` should reject halted-task approvals — tracked independently of this
  test-fix, since adding that check is a production-code change out of scope here.
- **R2 — Partial/inconsistent mechanical edit** (e.g. missing one of the 5 `TurnContext` sites, or
  editing the wrong import line) leaves a subtly broken import. Likelihood: Low.
  Mitigation: run the target file's test after the import-only step (Implementation step 1) before
  touching assertions, and `rg -n "TurnContext" tests/agent/test_approval_task_persistence.py` to
  confirm zero remaining hits.
- **R3 — Misreading the sibling collection regression check.** `tests/agent/ --collect-only` has 11
  pre-existing, unrelated errors (missing `respx`/`jsonschema` dev deps in this environment); comparing
  raw pass/fail instead of the specific error identity could wrongly read the fix as ineffective or
  wrongly attribute unrelated failures to this change. Likelihood: Medium (already nearly happened while
  building this plan). Mitigation: Validation plan above states the expected count explicitly (12 → 11)
  and names the unrelated errors, so this is already mitigated in-plan; no issue filed.
