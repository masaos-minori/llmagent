# Plan: Atomic URL-Level Transaction for RAG Ingestion

## 1. Goal

Treat one URL and its complete chunk set as the smallest commit unit, ensuring that a failed forced re-ingestion leaves the previous document, chunks, FTS rows, and vectors unchanged.

## 2. Scope

- `scripts/rag/ingestion/ingester.py`: Introduce `PreparedChunk` frozen dataclass DTO

## 3. Assumptions

1. `SQLiteHelper.begin_immediate()` correctly serializes concurrent writers via BEGIN IMMEDIATE — verified by inspecting helper.py:243-246
2. `floats_to_blob()` from `rag.utils` produces deterministic float32 BLOB output — no change needed
3. `chunks_fts` trigger fires automatically on INSERT INTO chunks — verified by existing consistency checks in rag_consistency.py
4. `chunks_vec_ad` trigger fires on DELETE FROM chunks — verified by delete_document_chain() in document_manager.py:17-33
5. HTTP client (`self._client`) lifecycle is unaffected by transaction refactoring — no change needed
6. Thread pool executor shutdown is unaffected — workers no longer hold DB connections, simplifying cleanup

## 8. Risks & Mitigations

- **Risk**: BEGIN IMMEDIATE may block indefinitely under heavy concurrent write load → **Mitigation**: Monitor SQLite busy_timeout (currently 30000ms); add logging around transaction acquisition; consider adding a timeout wrapper if production incidents occur
- **Risk**: Sequential chunk preparation (vs current parallel) may slow down large URL groups → **Mitigation**: Keep HTTP embedding calls parallel where useful (instruction 3); only serialize DB access; measure throughput impact before/after
- **Risk**: Transaction scope too wide — if any single chunk fails, the entire URL group rolls back → **Mitigation**: This is intentional per requirement; individual chunk failures should not corrupt the corpus; implement granular failure tracking via IngestionFailureReason
- **Risk**: Existing tests mock `_embed_and_store()` which opens its own connection — new design eliminates this pattern → **Mitigation**: Rewrite affected tests to use shared connection via DocumentManager; update mocks accordingly
- **Risk**: Cache invalidation timing change could cause stale search results briefly → **Mitigation**: Cache invalidation still happens after first successful commit; latency increase is bounded by time to process first URL group
