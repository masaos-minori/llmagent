## Goal
- Move the 5 governance-area documentation files from the flat `docs/` root into a new
  `docs/00_governance/` subfolder using `git mv` only (no rename, no content change
  beyond what a prior, already-landed Requirement covers), and update the one test file
  whose assertions hardcode the pre-move bare filenames as dict keys, so the governance
  area's docs are grouped exactly as the broader `docs/` reorganization plan intends.

## Priority
Medium

## Background
A separate investigation (2026-09-23) evaluated reorganizing `docs/` into area-based
subfolders while keeping every existing filename unchanged, producing 16 issues
(`docsreorg01`-`docsreorg16`). This Plan covers `docsreorg05`, the physical move for the
`00_governance` area — the first and lowest-risk per-area move, since these 5 files are
policy/meta docs rather than deeply cross-referenced technical reference docs.
Two prerequisite issues have already landed: `docsreorg01` (folder-independent
cross-reference resolution — `plans/done/20260923-142045_plan.md`) added a
repository-wide basename index to `tools/check_docs_structure.py` so bare-filename
references resolve regardless of directory; `docsreorg02` (subfolder-aware domain
checkers — `plans/done/20260923-152824_plan.md`) updated 9 tools' path constants,
including 2 of the 3 tools that read these 5 files by a hardcoded path
(`tools/check_dependency_graph_cycles.py`'s `GRAPH_DOC_PATH`,
`tools/check_needs_confirmation_inventory.py`'s `INVENTORY_DOC_NAME`, and
`tools/check_known_deviation_sync.py`'s `_GOVERNANCE_KNOWN_ISSUES_PATH`), to already
expect `docs/00_governance/` as the post-move location. `docsreorg04` (canonical routing
reference updates) has also landed
(`issues/done/20260923-140832_docsreorg04_update-canonical-docs-routing-references-for-folder-reorganization.md`).

## Problem
`docs/00_governance_01_documentation-policy.md`,
`docs/00_governance_02_documentation-metadata.md`,
`docs/00_governance_03_issue-and-uncertainty-management.md`,
`docs/00_governance_04_documentation-checks.md`, and `docs/00_index.md` currently sit
directly under `docs/` alongside all other areas' files, with no folder grouping —
confirmed via `ls docs/00_governance_*.md docs/00_index.md`, all 5 present at the flat
path today.

## Reason for change
Grouping governance/meta docs into their own folder is the first physical-move step of
the broader `docs/` reorganization, validating the move process (tooling readiness +
reference fixups + baseline updates) on the smallest, lowest-risk batch before larger
areas (`docsreorg06`-`docsreorg16`) are moved. Additionally,
`issues/done/20260924-115855_risks.md` (a Risk follow-up filed from this same Plan's
prior revision) identified that `tools/check_issue_inventory_conformance.py`'s default
`doc_path` would break CI immediately once this move landed; absorbing that fix into
this Plan avoids a CI regression window between the move landing and a separately
scheduled follow-up fix.

## Implementation intent
Use `git mv` for each of the 5 files, one command per file (`git log --follow`
continuity is preserved by `git mv` regardless of whether commands are batched, but
one-per-file keeps each step independently revertable per Incrementalism). Then update
only the `EXPECTED_WITHIN_FILE_PAIRS` keys in
`tests/tools/test_check_docs_quality.py` that reference the 2 (not all 5 — see REQ-002
below) governance files with existing within-file content-similarity entries, adding
the `00_governance/` prefix, mirroring the existing `eventbus/*.md` subfolder key
format already present in that same frozenset. No other file requires modification for
this Plan's originally in-scope work, per the dependency-graphing evidence in Design
below.

Per the resolution proposed in `issues/done/20260924-115855_risks.md`: give
`tools/check_issue_inventory_conformance.py` a module-level `REPO_ROOT`/`DOCS_DIR`/
`GOVERNANCE_DOC_PATH` constant, mirroring the pattern `docsreorg02` already applied to
`tools/check_dependency_graph_cycles.py`'s `GRAPH_DOC_PATH`,
`tools/check_needs_confirmation_inventory.py`'s `INVENTORY_DOC_PATH`, and
`tools/check_known_deviation_sync.py`'s `_GOVERNANCE_KNOWN_ISSUES_PATH`, and switch
`main()`'s default `doc_path` to that constant. Add a real-repo-path regression test to
`tests/tools/test_check_issue_inventory_conformance.py` mirroring
`tests/tools/test_check_dependency_graph_cycles.py::TestRealGraphIntegration`'s pattern,
so the fix is verified against the actual post-move repository tree, not only a
hermetic fixture.

  folder-independent basename index only when it contains no `/`; a target containing

  breaks when either endpoint of the reference changes its directory depth. All other
  cross-references to the 5 moved files are bare filenames (no `/`) and remain correctly

  `tools/` or `docs/` (reused from `docsreorg02`'s own Reference Files finding — not
  re-verified this session, per Tool Usage's unchanged-input reuse rule); no import
  boundary applies to a documentation-only move.
- **Dependency graphing**: a repository-wide `rg` search for each of the 5 bare
  filenames, scoped to active (non-archive) directories, found:
  1. Three tools already hardcode a `docs/00_governance/`-qualified path for 3 of the 5
     files (`check_dependency_graph_cycles.py`, `check_needs_confirmation_inventory.py`,
     `check_known_deviation_sync.py`) — landed by `docsreorg02`, ready for this move,
     no further change needed.

     keys (not 13, as the Issue states — see the corrected count in REQ-002) across 2 of
     the 5 files as `EXPECTED_WITHIN_FILE_PAIRS` frozenset members — these need the
     `00_governance/` prefix, matching the existing `eventbus/*.md` key format already
     present in the same frozenset.

     prose/front-matter reference, already resolved independent of directory by
     `docsreorg01`'s basename index in `tools/check_docs_structure.py` — no rewrite
