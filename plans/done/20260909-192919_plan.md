# Plan: Remove stale TestStartupOrchestratorRecoverPendingApprovals and port coverage

## Goal
Remove the broken `TestStartupOrchestratorRecoverPendingApprovals` class from `tests/agent/test_startup.py` after porting its 9 scenario coverages to `tests/agent/test_startup_approval_recovery.py`, eliminating dead test debt without loss of coverage.

## Priority
Medium

## Scope
- **In-Scope**: Port 9 approval-recovery scenarios from `tests/agent/test_startup.py` to `tests/agent/test_startup_approval_recovery.py`; delete `TestStartupOrchestratorRecoverPendingApprovals` from `tests/agent/test_startup.py`; verify both test files pass.
- **Out-of-Scope**: Changes to `scripts/agent/startup.py` or `scripts/agent/startup_approval_recovery.py`; fixing the ~36 unrelated pre-existing failures in `tests/agent/test_startup.py`; any other test file modifications.

## Background
Commit `729ff8beb` ("refactor: extract ApprovalRecovery and delegate `_recover_pending_approvals`") moved pending-approval recovery logic out of `StartupOrchestrator` in `scripts/agent/startup.py` into a new `ApprovalRecovery.recover()` in `scripts/agent/startup_approval_recovery.py`. That commit added `tests/agent/test_startup_approval_recovery.py` to cover the new location but never touched `tests/agent/test_startup.py`, leaving `TestStartupOrchestratorRecoverPendingApprovals` behind as orphaned, now-broken duplicate coverage.

## Problem
`ApprovalRecovery.recover()` does local imports inside its method body — `from agent.workflow.approval_ops import find_all_pending_approvals` and `from agent.workflow.state_store import StateStore` — so neither symbol was ever an attribute of `agent.startup` to begin with. `TestStartupOrchestratorRecoverPendingApprovals` patches `agent.startup.find_all_pending_approvals` / `agent.startup.StateStore`, which fail immediately at `mock.patch(...)` setup. Confirmed by reading `tests/agent/test_startup.py` lines 259-262, 291-294, etc. where `patch("agent.startup.find_all_pending_approvals", ...)` is used.

**Correction to Issue claim**: The Issue stated "its scenarios are already exercised against the correct current module in `tests/agent/test_startup_approval_recovery.py`." This is incorrect — `test_startup_approval_recovery.py` contains NO tests for `_recover_pending_approvals`. It only covers `_start_servers` and `_verify_mcp_health`. All 9 scenarios must be ported.

## Reason for change
The class contributes 9 guaranteed failures to every `tests/agent/test_startup.py` run and to the full suite, and its assertions duplicate coverage that already exists and passes in `tests/agent/test_startup_approval_recovery.py`. Removing it eliminates dead, misleading test debt without any loss of coverage.

## Implementation intent
Diff each scenario from `TestStartupOrchestratorRecoverPendingApprovals` against `test_startup_approval_recovery.py`. Since none exist there, port all 9 scenarios to `test_startup_approval_recovery.py` with appropriate patch targets (`agent.workflow.approval_ops.find_all_pending_approvals` and `agent.workflow.state_store.StateStore`). Then delete the class from `tests/agent/test_startup.py`.
