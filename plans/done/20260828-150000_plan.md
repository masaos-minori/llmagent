# Plan: Make fetched_at mandatory end-to-end through RAG ingestion pipeline

## Goal
Make `fetched_at` a mandatory, non-null `str` across every layer of the RAG ingestion pipeline (crawler DTO, chunk metadata, chunk JSON, ingester, document manager, etag manager, document store) and delete the null-fill compatibility branch `_update_null_fill()`. Change timestamp validation from fail-open to fail-closed.

## Priority
High

## Scope
- **In-Scope**:
  - Crawler: generate canonical UTC `fetched_at` (`YYYY-MM-DDTHH:MM:SSZ`)
  - ChunkDocument: add mandatory `fetched_at` field
  - ChunkJsonRaw/CrawlFilePayload/ChunkOutputPayload/ChunkMetadata: add required `fetched_at`
  - Ingester: remove `fetched_at` omission branch, require `str` parameter
  - DocumentManager: require `str` for `fetched_at`/`new_fetched_at` parameters
  - ETagManager: delete `_update_null_fill()`, require `str`, fail-closed validation
  - DocumentStore protocol + SQLiteDocumentStore: add `fetched_at: str` parameter
  - Schema: remove `DEFAULT (strftime(...))` clause from `documents.fetched_at`
  - All callers, mocks, fixtures updated accordingly
- **Out-of-Scope**:
  - Changing envelope-level `MCP_TOOL_SCHEMA_VERSION` constant
  - Removing unused constructor arguments from ToolRouteResolver/ToolExecutor
  - Server-side MCP response builder changes

## Background
Crawler already records an acquisition timestamp at scrape time, but this value is not carried through the rest of the ingestion pipeline as a strict, mandatory field. Verified against current source:

- `scripts/rag/ingestion/crawler.py`: `CrawlPayload.fetched_at` is set via `datetime.now().isoformat(timespec="seconds")` — naive local time, not canonical UTC `Z` form.
- `scripts/rag/models_data.py`: `ChunkDocument` has no `fetched_at` field at all, so the timestamp is discarded once chunking starts.
- `scripts/rag/ingestion/chunk_splitter.py`: has zero references to `fetched_at`.
- `scripts/rag/ingestion/pipeline_utils.py` (line 29): `ChunkJsonRaw.fetched_at` is declared as `NotRequired[str | None]`, i.e. optional today.
- `scripts/rag/ingestion/ingester.py`: `_insert_document()` has two INSERT branches — one including `fetched_at`, and a second (`cursor2`, used when `fetched_at is None`) that omits the column entirely.
- `scripts/db/schema_sql.py` (line 32): `documents.fetched_at` has `DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))` — database insertion time, not source acquisition time.
- `scripts/rag/ingestion/document_manager.py`: `handle_existing_document()` and `_update_etag()` both accept optional timestamps.
- `scripts/rag/ingestion/etag_manager.py`: `ETagManager.update()` branches on `new_fetched_at is not None`; when `None`, it calls `_update_null_fill()` which never touches `fetched_at`. `_is_stale_update()` treats malformed timestamps as "not stale" (fail-open).
- `scripts/db/store_protocols.py` and `scripts/db/store_impl.py`: no `fetched_at` parameter; UPDATE branch uses `ON CONFLICT ... fetched_at = strftime(...)`.

All factual claims confirmed against current source.

## Problem
`fetched_at` is optional at every layer of the ingestion pipeline, and every layer that finds it missing falls back to a different kind of default or silent tolerance instead of failing:

- The crawler generates a naive local timestamp, not a canonical UTC `Z` string.
- `ChunkDocument` drops the field, so `ChunkSplitter` output never carries it forward.
- `Ingester._insert_document()` silently omits the `fetched_at` column when the value is `None`, letting the schema's `DEFAULT (strftime(...))` apply.
- `ETagManager.update()` takes a null-fill path whenever `new_fetched_at` is `None`, which never updates `fetched_at`.
- `ETagManager._is_stale_update()` treats a malformed timestamp as "not stale," letting corrupt values flow through to update SQL.
- `SQLiteDocumentStore.doc_upsert()` has no way to accept a caller-supplied `fetched_at` at all; both INSERT and UPDATE branches derive the timestamp from database time.

Net effect: the value stored in `documents.fetched_at` can silently become "when this row was written in SQLite" rather than "when the source document was actually fetched."

## Reason for change
No legacy data exists that depends on `fetched_at` being optional or database-derived, so there is no compatibility constraint to preserve. Because Crawler already computes the correct acquisition time, the fix is to make that one value canonical and UTC, propagate it unchanged through every DTO/model/table in the pipeline, and delete every fallback/default/null-fill/fail-open branch that exists only because the field used to be optional.

## Implementation intent
1. In `crawler.py`, generate `fetched_at` once, in canonical UTC form (`YYYY-MM-DDTHH:MM:SSZ`) instead of `datetime.now().isoformat(timespec="seconds")`. For local `file://` sources, derive the same UTC form explicitly from the file's modification time.
2. Widen `fetched_at`/`new_fetched_at` from `str | None` to mandatory `str` across every signature listed in the issue's Implementation Tasks.
3. Propagate the single crawler-generated timestamp unchanged from the crawl payload into every chunk file produced from that crawl record.
4. Remove every fallback/compatibility branch that exists solely to handle a missing timestamp.
5. Change timestamp validation from fail-open to fail-closed: reject timezone-naive timestamps, raise on malformed incoming timestamps, treat a malformed stored timestamp as a database consistency error.
6. Fix the freshness-update logic so that when `etag` and `last_modified` are both `null` but the incoming `fetched_at` is newer than the stored value, `fetched_at` is still updated. Replace `COALESCE(?, fetched_at)` with direct assignment.
7. Update every caller, Protocol implementation, mock, and fixture accordingly.

## Design
This is a Path B task affecting > 3 files, changing public/runtime interfaces, and modifying DB schema. Full architecture analysis applies:

**Architecture**: The RAG ingestion pipeline flows as: Crawler → ChunkSplitter → Ingester → ETagManager → SQLiteDocumentStore. Each layer currently has its own tolerance for missing `fetched_at`. The design is to establish a single source of truth: the crawler generates `fetched_at` once in canonical UTC form, and every downstream layer requires it as a mandatory `str` parameter.

**Dependency graph**: 
```
Crawler (generates) → ChunkSplitter (propagates) → Ingester (inserts)
                                                          ↓
                                                    ETagManager (updates freshness)
                                                          ↓
                                                  SQLiteDocumentStore (persists)
```

**Key design decisions**:
1. `fetched_at` is generated once at crawl time, never regenerated downstream.
2. All layers use the same canonical UTC string format (`YYYY-MM-DDTHH:MM:SSZ`).
3. Fail-closed validation replaces fail-open: reject malformed timestamps instead of treating them as "not stale."
4. Equal-timestamp case needs explicit decision (UNK-01): recommend "skip" (equal means not fresh) since `<` comparison already defines staleness.

## Risks
- **Risk**: Removing `DEFAULT (strftime(...))` from schema could break any direct SQL inserts that omit `fetched_at`. **Mitigation**: Verify no such inserts exist; if they do, add the column to those INSERT statements.
- **Risk**: Changing `_is_stale_update()` from fail-open to fail-closed could cause legitimate updates to be rejected if there are existing malformed timestamps in the database. **Mitigation**: This is intentional — the issue states "no legacy data depends on fetched_at being optional or database-derived," so any malformed values should be surfaced as errors during migration.
- **Risk**: Equal-timestamp edge case behavior is undefined (UNK-01). **Mitigation**: Recommend "skip" (equal means not fresh) based on the existing `<` comparison semantics, and document this decision explicitly.
