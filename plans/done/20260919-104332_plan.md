## Goal
Add the 5 missing per-role authentication token fields (`publisher_token`,
`consumer_token`, `operator_token`, `monitoring_token`, `admin_token`) and their
startup-validation behavior to
`docs/06_eventbus_05_configuration-and-operations.md`'s Configuration Fields list,
so an operator configuring EventBus from that document alone knows these fields
exist and that at least one per-role (or the legacy shared) token must be set.

## Priority
High

## Scope
- **In-Scope**: adding the 5 field entries and a short startup-validation note to
  the Configuration Fields list, cross-referencing `ADR-013`.
- **Out-of-Scope**: any change to `scripts/eventbus/config.py`, `ADR-013`, or any
  other section of `docs/06_eventbus_05_configuration-and-operations.md`.

## Background
`EventBusConfig` (`scripts/eventbus/config.py`) defines `publisher_token`,
`consumer_token`, `operator_token`, `monitoring_token`, `admin_token`
(lines 98-102), and `_validate_token_combinations()` (lines 47-60) enforces that at
least one of `auth_token` or a per-role token is configured (raises `ValueError` at
line 60 otherwise). `ADR-013-eventbus-authentication-authorization.md` documents
the four-role model these fields implement. A related prior issue
(`issues/done/20260914-102535_eventbus09_config-validation-role-token-policy.md`)
mapped its "document valid token combinations" requirement only to
`tests/eventbus/test_eventbus_config.py`, not to this operational reference
document, so the gap remained open.

## Problem
`docs/06_eventbus_05_configuration-and-operations.md`'s Configuration Fields list
(confirmed: 16 entries, lines 55-70) does not mention any of the 5 per-role token
fields or the startup-validation rule — an operator configuring EventBus purely
from this document would not know they exist or that one must be set.

## Reason for change
This is a live documentation/code mismatch on a security-relevant configuration
surface (authentication/authorization tokens) — the kind most likely to cause an
operational misconfiguration.

## Implementation intent
Add the 5 fields to the Configuration Fields list, in the same style as the
existing 16 entries (`` - `field_name` — one-line description (default/behavior
note if applicable) ``), placed near the existing `auth_token` entry, plus a short
note on the startup-time "at least one per-role token configured" requirement,
cross-referencing `ADR-013` rather than restating its content. Do not document a
token value for any of these fields — only purpose and validation behavior.

## Requirements
- `REQ-001`: Add `publisher_token`, `consumer_token`, `operator_token`,
  `monitoring_token`, `admin_token` to the Configuration Fields list, each with a
  one-line description of the role it grants, matching the existing entry style.
- `REQ-002`: Add a short note that startup fails unless at least one of
  `auth_token` or a per-role token is configured, cross-referencing `ADR-013`.
