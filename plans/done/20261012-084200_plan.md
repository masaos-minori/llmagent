## Goal
- Record, in the `NackResult` docstring and the NACK endpoint reference, that the events-level `delivery_failure_count` and `cycle_failure_count` of `NackResult` are legacy values and also carry the not-found and invalid-state sentinels, and that the HTTP response field `delivery_failure_count` carries the per-consumer failure count.

Low

- **Out-of-Scope**:

## Background
- `plans/done/20261011-220109_plan.md` corrected the `nack_event` docstring and left UNK-01 open: whether anything depends on the events-level counters returned by `NackResult`.
- Repository evidence (`Explicit in code`): the only non-test caller is the NACK route; it reads `delivery_failure_count` for the `-1` and `-2` sentinels and as a fallback value; nothing outside tests reads `cycle_failure_count`; tests compare whole `NackResult` values.
- The route requires `consumer_id`, so a successful NACK always carries the per-consumer count, and the HTTP field `delivery_failure_count` carries that count. The endpoint reference still calls it a "lifetime failure count".
- The `NackResult` docstring documents `-1` for `delivery_failure_count` and `-2` for `cycle_failure_count` but not that `delivery_failure_count` is also `-2` for an invalid state; the idempotent repeat-NACK path returns the stored value in `delivery_failure_count` together with `-2` in `cycle_failure_count`.

## Problem
- The result type and the HTTP response give the same name different meanings, and the docstring and endpoint reference do not say so, which has already caused one stale-docstring defect.

## Reason for change
- Maintainability and documentation accuracy; low urgency because behavior is correct and tested.

## Implementation intent
- Apply the issue's default outcome: keep the fields as documented legacy values and make the documents agree. Do not change executable behavior, the response shape, or the schema without an owner decision.

## Requirements
- `REQ-001`: The `NackResult` docstring states, per field, the sentinel values (`-1` not found, `-2` invalid state), that otherwise the events-level stored legacy value is returned, and the idempotent repeat-NACK case; no executable line changes.
- `REQ-002`: The NACK endpoint reference describes the response `delivery_failure_count` as the per-consumer failure count after this NACK, consistent with the NACK state table.
- `REQ-003`: The decision and the open questions (owner decision on separation; external consumers) are recorded in this Plan's Assumptions and Unknowns.
