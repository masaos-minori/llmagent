## Problem
- ADR-008 covers four databases, but mdq.sqlite is an active fifth store owned by mdq-mcp (Confirmed by repository evidence — `docs/41_db/db_08_active_databases.md` "mdq.sqlite" section: owner, `db_path` in `config/mdq_mcp_server.toml`, schema authority `scripts/mcp_servers/mdq/db_schema.py`). The ADR's own Review Trigger "A fifth persistence domain is added" therefore already applies.
- The matrix row "Required service stop scope" names "RAG process" and the row "Service restart condition" names "RAG process restart after restore" (Explicit in ADR-008); no such process exists — the callers of the RAG pipeline are the rag-pipeline MCP server (`scripts/mcp_servers/rag_pipeline/rag_pipeline_service.py`), the Agent and the ingester.
- The "Rollback condition" row gives "atomic replacement enables rollback if restore fails" for workflow.sqlite and eventbus.sqlite, although the same matrix marks automatic restore as prohibited for them (Explicit in ADR-008 matrix rows "Automatic restore allowed or prohibited" and "Physical integrity verification").
- The Constraint "No migration mechanism exists; a Schema change requires recreating the whole DB" contradicts `docs/41_db/db_03_architecture_and_schema-migration-and-scaling.md` sections 8a and 8b (workflow and eventbus migrations) (Explicit in memo2.md; to be re-read in that document before writing).
- Known Deviations lists EVENTBUS-008 (EventBus authentication model), which is unrelated to database separation (Explicit in ADR-008 line 216).
- mdq.sqlite is not touched by `recover_corruption()` or `rotate_all_dbs()` (Confirmed by repository evidence — `scripts/db/recovery.py` and `scripts/db/rotation.py` contain no reference to mdq) and is filled by `index_paths` from Markdown files (Confirmed by repository evidence — `scripts/mcp_servers/mdq/indexer.py`). That it is "rebuilt from allowed_dirs" and holds no system-of-record data needs one more check against the mdq design documents before it is written (see UNK-01).
