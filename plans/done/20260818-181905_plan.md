## 1. Goal
- Guarantee that `write_offset()` never lowers a consumer's committed offset, preventing duplicate message delivery caused by out-of-order acknowledgments.

## 2. Scope
- **In-Scope**:
  - Modify `write_offset()` in `scripts/eventbus/offsets.py` to enforce non-decreasing offset semantics
  - Add regression unit test in `tests/eventbus/test_eventbus_offsets.py`
- **Out-of-Scope**:
  - Changes to the SSE subscribe loop or replay logic
  - Changes to the `/publish` or `/ack` HTTP endpoints
  - Migration of existing offset files

## 3. Assumptions
- `read_offset()` always returns a valid integer (0 on missing/invalid file) — verified by existing callers
- The offset file is single-writer per consumer_id — confirmed by the app-level singleton broker pattern
- Existing integration tests (`test_ack_writes_offset`, `test_reconnect_resume_via_consumer_id`) will continue to pass since they only exercise forward-progress scenarios

## 8. Risks & Mitigations
- **Risk**: Out-of-order acks silently dropped without operator visibility → **Mitigation**: Add `logger.warning()` on skipped writes so operators can detect anomalies in logs
- **Risk**: Race between `read_offset()` and `write_offset()` under concurrent access → **Mitigation**: Document that consumers must be single-threaded per consumer_id; add a note in the docstring. If multi-process becomes necessary later, switch to atomic compare-and-swap via file locking.
