## Background
`prompts/05_skills.md`'s `### Architectural Principles` section restates the
repository's layer dependency-direction diagram in full (the "dependency
direction" bullet, currently at lines 34-50). `skills/DESIGN.md`'s `### Import
layer contract` section (lines 110-115) explicitly states: "The canonical layer
diagram lives in `rules/env.md` Architecture (includes the current `eventbus`
isolation rule and `agent`'s actual scope) — do not restate or re-derive the
diagram here." `prompts/05_skills.md` restates the diagram anyway, and the
restated version has already drifted from the canonical source: it omits the
`eventbus` layer entirely, and omits the "installer use only" qualifier on
`agent`'s dependency on `mcp_servers` — both of which `rules/env.md`
Architecture (lines 39-51, current) documents.

This issue was discovered as a byproduct of a separate, now-closed
investigation (`issues/done/20260831-091832_skills05m001_consolidate_shared_rule_references.md`)
into internal duplication among `prompts/05_skills.md`'s own sections; that
investigation found no confirmed duplicate in its own scope, but surfaced this
distinct, out-of-scope finding involving `rules/env.md`.

## Problem
`prompts/05_skills.md`, `### Architectural Principles`, "dependency direction"
bullet currently states (re-verified by direct read immediately before writing
this Plan, unchanged since the Issue was filed):

    Apply this direction: `agent -> rag/mcp -> db -> shared`. The arrow means
    "may depend on or reference".
    - `agent` may reference `rag`, `mcp`, `db`, and `shared`.
    - `rag` and `mcp` may reference `db` and `shared`.
    - `db` may reference `shared`.
    - `shared` must not reference higher layers.
    - A lower layer must not reference a higher layer.
    - `rag` and `mcp` are sibling layers.
    - `rag` and `mcp` must not reference each other unless an approved rule
      explicitly allows it.

`rules/env.md`, `## Architecture`, currently states (re-verified by direct read
immediately before writing this Plan, unchanged since the Issue was filed):

    shared  -> external only (leaf layer, no dependency on other layers)
    db      -> shared
    rag     -> db, shared
    mcp_servers -> db, shared
    agent   -> rag, db, shared, mcp_servers (installer use only)
    eventbus -> fully independent of every other layer (not even a dependency
                on shared)

The restated version in `prompts/05_skills.md` is missing the `eventbus` layer
entirely and the "installer use only" qualifier on `agent -> mcp_servers`,
directly contradicting `skills/DESIGN.md`'s instruction not to restate the
diagram elsewhere (a restatement that then drifts is exactly the failure mode
that instruction exists to prevent).

## Reason for change
- Direct violation of `skills/DESIGN.md`'s explicit "do not restate or
  re-derive the diagram here" instruction.
- Documentation drift risk: the restated copy has already drifted (missing
  `eventbus`'s isolation rule and the `agent`/`mcp_servers` "installer only"
  qualifier); anyone reading only `prompts/05_skills.md` gets an incomplete
  picture of the actual dependency contract.
- Maintenance risk: two independent copies of the same architectural contract
  must be kept in sync by hand; this issue's own discovery shows that
  synchronization has already failed once.

## Implementation intent
Replace the "dependency direction" bullet's inline diagram with a short
statement of the general rule plus a reference to `rules/env.md` Architecture
as the canonical source, consistent with `skills/DESIGN.md`'s own `### Import
layer contract` section (which already does this correctly). Keep the general
principle ("a lower layer must not reference a higher layer") since it is the
operative constraint this workflow needs to apply; remove the specific layer
names, arrows, and sibling-layer detail, since those belong solely to
`rules/env.md`.
