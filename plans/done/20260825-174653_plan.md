# Plan: Fix manage_frontmatter.py add-missing destructive-by-default CLI

## Goal
Make `manage_frontmatter.py add-missing` safe by default: no-flag invocation must report-only (no writes), require explicit opt-in (`--fix`) to perform actual writes, and fix the `main()` → `cmd_add_missing()` argument hand-off so `--dry-run` actually reaches the subcommand parser.

## Priority
High

## Scope
- **In-Scope**: `tools/manage_frontmatter.py` (`cmd_add_missing`, `main`)
- **Out-of-Scope**: Changes to `cmd_dedupe_lists` behavior, changes to Front-Matter content-generation logic (`build_frontmatter`, `extract_category_from_filename`, etc.), any other `tools/*.py` script.

## Background
`tools/manage_frontmatter.py add-missing` writes to `docs/*.md` by default with no flag required, and its `--dry-run` option is unreachable because of an argument-passing bug in `main()`. There is currently no safe way to preview what this subcommand would do before it mutates files.

## Problem
The `add-missing` subcommand has two bugs that make it destructive-by-default:
1. `main()` re-encodes parsed flags back into CLI-style strings via `f"--{k}"` where `k` comes from `vars(args)` using underscores (e.g., `dry_run`). It then calls `cmd_add_missing(["--dry_run"])`, but `cmd_add_missing`'s own `argparse.ArgumentParser` only recognizes the hyphenated form `--dry-run`. Reproduced directly: `uv run python tools/manage_frontmatter.py add-missing --dry-run` exits with code 2 and `error: unrecognized arguments: --dry_run`.
2. The `--fix` flag is declared (`tools/manage_frontmatter.py:163`, `:324`) but never read anywhere in the function body. The write path (`md_file.write_text(...)`) executes whenever `args.dry_run` is falsy — which is the default state when no flag is passed at all, not only when `--fix` is passed.

Net effect: there is no working preview mode, and the unsafe write path is the one that actually runs when a user invokes the subcommand with no flags (the most natural first invocation). This is a destructive-by-default CLI for a script that runs against the entire `docs/` tree.

## Reason for change
Operationally observed: running `uv run python tools/manage_frontmatter.py add-missing` with no flags on this repository wrote Front Matter into 49 files under `docs/` immediately, with no confirmation prompt and no prior dry-run step performed. Explicit in code: `tools/manage_frontmatter.py:178-207` `cmd_add_missing` — the write path executes whenever `args.dry_run` is falsy; `tools/manage_frontmatter.py:333-336` — `main()` re-encodes `add-missing`'s own parsed flags back into CLI-style strings via `f"--{k}"` where `k` comes from `vars(args)` (e.g., `dry_run`, using an underscore, because that's argparse's `dest` naming).

## Implementation intent
Flip the default to non-destructive: `add-missing` should not write to any file unless the caller explicitly opts in (keep `--fix` as the write-enabling flag, and make its absence mean dry-run/report-only). Fix the `main()` → `cmd_add_missing()` argument hand-off so `--dry-run` (or whatever the chosen opt-in flag is) actually reaches the subcommand parser without a name-mangling bug. Prefer removing the round-trip re-encoding entirely (have `cmd_add_missing` accept the already-parsed `Namespace`) rather than patching the string conversion. Keep the rest of the subcommand's file-discovery and Front-Matter-generation logic unchanged — this is a safety/argument-wiring fix, not a rewrite of `add-missing`'s content logic.

## Design
### Current behavior analysis
- Line 198-206: When `args.dry_run` is falsy (default), the code writes to files via `md_file.write_text(new_content, encoding="utf-8")`. When truthy, it prints a preview instead.
- Line 333-336: `main()` passes `[f"--{k}" for k, v in vars(args).items() if v and k not in ("subcommand",)]` to `cmd_add_missing`. The key `dry_run` (underscore) becomes `--dry_run`, but `cmd_add_missing`'s parser only recognizes `--dry-run` (hyphenated).
- Line 163: `--fix` is declared but never checked in the function body.

### Design decision: remove round-trip re-encoding
Rather than patching the string conversion, have `cmd_add_missing` accept the already-parsed `Namespace` object directly. This eliminates the underscore/hyphen mismatch entirely.

### Design decision: flip default to non-destructive
Change `cmd_add_missing` so that:
1. No-flag invocation = dry-run/report-only (no writes)
2. `--fix` = explicit opt-in to write
3. `--dry-run` = still works as documented (preview only)

This means the condition on line 198 flips: `if args.fix:` triggers writes instead of `if not args.dry_run:`.

### Design decision: keep `--dry-run` flag
Retain the `--dry-run` flag for backward compatibility with users who may have scripts referencing it. Both `--dry-run` and no-flag now behave identically (report-only). Only `--fix` enables writes.
