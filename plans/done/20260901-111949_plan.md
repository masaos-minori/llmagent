# Plan: Fix recover_corruption() UNKNOWN condition handling violation of ADR-008 INV-17

## Goal
- Ensure `recover_corruption()` treats `DbCondition.UNKNOWN` identically to `LOCK_CONTENTION`/`PERMISSION_FAILURE`/`INVALID_FORMAT`: return early without attempting automatic restoration, preserving the target database and requiring operator intervention.

## Priority
High

## Scope
- **In-Scope**: Modify `scripts/db/recovery.py` to add `DbCondition.UNKNOWN` to the early-return branch; add unit tests for UNKNOWN condition handling.
- **Out-of-Scope**: Changes to backup infrastructure, ADR-008 text updates, integration test modifications outside `test_db_maintenance.py`.

## Background
ADR-008 INV-17 requires Unknown/unclassifiable integrity-check failures preserve the target database and require operator intervention rather than triggering automatic restoration. The current code treats UNKNOWN identically to CORRUPTION, violating this invariant.

## Problem
`recover_corruption()`'s branch `if condition in (LOCK_CONTENTION, PERMISSION_FAILURE, INVALID_FORMAT)` at line 204-208 does NOT include `UNKNOWN`, so execution falls through to the "CORRUPTION or UNKNOWN" comment at line 216 and attempts `_restore_from_backup()` for both conditions.

## Reason for change
The bug causes automatic restoration for unclassifiable integrity failures, which violates ADR-008 INV-17 and risks data loss when the corruption type cannot be determined.

## Requirements
- `REQ-001`: When `condition == DbCondition.UNKNOWN`, `recover_corruption()` MUST return early with `action="error"` and detail indicating manual intervention required, WITHOUT attempting `_restore_from_backup()`.
- `REQ-002`: Existing behavior for CORRUPTION, LOCK_CONTENTION, PERMISSION_FAILURE, INVALID_FORMAT MUST remain unchanged.
- `REQ-003`: All existing tests MUST continue to pass after the fix.
- `REQ-004`: A new unit test MUST verify UNKNOWN condition returns `RecoveryResult(success=False, action="error")` without calling `_restore_from_backup()`.

## Design
Add `DbCondition.UNKNOWN` to the existing early-return branch at line 204-208:

```python
if condition in (
    DbCondition.LOCK_CONTENTION,
    DbCondition.PERMISSION_FAILURE,
    DbCondition.INVALID_FORMAT,
    DbCondition.UNKNOWN,  # NEW: INV-17 compliance
):
```

This ensures UNKNOWN triggers the same early return as other non-corruption conditions, preventing automatic restoration while preserving CORRUPTION's restore behavior.
