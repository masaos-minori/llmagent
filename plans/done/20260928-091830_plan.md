## Problem
`scripts/shared/route_resolver.py::resolve()` only looks up in `_runtime_registry`, never falling back to `ToolRegistry` — confirmed correct via code inspection — but no automated test covers this routing-authority invariant.

## Reason for change
Without test coverage, a future change to `resolve()` could silently reintroduce a fallback to `ToolRegistry`, violating ADR-003, with no automated signal.

## Implementation intent
Add a focused unit test asserting `resolve()` never falls back to `ToolRegistry` when `RuntimeToolRegistry` is available, following existing test conventions for MCP routing tests. No production code change is expected.

## Requirements
- `REQ-001`: `resolve()` must raise `ValueError` when a tool is not found in `RuntimeToolRegistry`, without falling back to `ToolRegistry`
- `REQ-002`: `resolve()` must not consult `ToolRegistry` under any circumstances (strict_mode or non-strict_mode)
- `REQ-003`: When `RuntimeToolRegistry` is None, `resolve()` must raise `ValueError` without attempting fallback to `ToolRegistry`

## Design
The existing `TestRoutingSourceIsolation` class in `tests/shared/test_route_resolver.py` (lines 181-194) covers:
- Proving config tool_names cannot affect routing (via `test_config_tool_names_do_not_affect_routing`)
- Proving ToolRouteResolver doesn't fall back to tool_constants frozensets (via `test_constants_not_used_directly_by_resolver`)

However, these tests prove certain fallback mechanisms don't work, they don't explicitly assert that `resolve()` doesn't fall back to `ToolRegistry` specifically. The gap analysis focuses on:
1. **Explicit negative assertion**: Test that even when `ToolRegistry` has registrations for a tool, `resolve()` raises `ValueError` instead of returning a server key from `ToolRegistry`
2. **Cross-mode verification**: Verify both strict_mode and non-strict_mode paths reject `ToolRegistry` fallback
3. **None registry edge case**: Verify that when `RuntimeToolRegistry` is None, `resolve()` still raises `ValueError` without attempting `ToolRegistry` lookup
