## Design
The current `assert_valid_transition()` raises `ValueError("Invalid lifecycle transition: {from_state!r} -> {to_state!r}")`. The fix appends valid target information by looking up `valid_targets = _VALID_TRANSITIONS.get(from_state, frozenset())` and joining their `.name` attributes. For the UNKNOWN state, this will list all five enum members since UNKNOWN allows any transition.

```python
def assert_valid_transition(
    from_state: LifecycleState, to_state: LifecycleState
) -> None:
    """Raise ValueError when the transition from_state -> to_state is not legal."""
    if to_state not in _VALID_TRANSITIONS.get(from_state, frozenset()):
        valid_targets = _VALID_TRANSITIONS.get(from_state, frozenset())
        raise ValueError(
            f"Invalid lifecycle transition: {from_state!r} -> {to_state!r}. "
            f"Valid targets from {from_state!r}: {', '.join(t.name for t in valid_targets)}"
        )
```

Example outputs:
- From FAILED to RUNNING: `"Invalid lifecycle transition: <LifecycleState.FAILED: 'failed'> -> <LifecycleState.RUNNING: 'running'>. Valid targets from <LifecycleState.FAILED: 'failed'>: STARTING, STOPPED"`
- From UNKNOWN to anything: `"Invalid lifecycle transition: ... Valid targets from <LifecycleState.UNKNOWN: 'unknown'>: STARTING, RUNNING, STOPPED, FAILED, UNKNOWN"`

## Risks
1. **Breaking change**: Existing code that parses the error message string will fail with the new format. Mitigation: search for string parsing of this error before implementing.
2. **UNKNOWN state verbosity**: Listing all 5 enum names for UNKNOWN might be noisy. Acceptable trade-off since UNKNOWN→any is theoretically impossible to trigger an error anyway.
3. **Empty valid_targets**: If `from_state` is not in `_VALID_TRANSITIONS`, the default frozenset() yields empty string after join. Should display something like "(none)" instead.
