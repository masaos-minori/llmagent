# Plan: Document HttpTransport timeout_sec behavior for zero/negative values

## Goal
Document the behavior of `HttpTransport.__init__()` when `timeout_sec` is zero or negative, ensuring developers understand that such values result in httpx's default timeout being applied.

## Priority
Low

## Scope
- **In-Scope**: Updating the docstring of `HttpTransport.__init__()` to document the behavior when `timeout_sec <= 0`; ensuring consistency between documentation and implementation.
- **Out-of-Scope**: Changing the retry logic itself; modifying other transport layers; changing error handling behavior.

## Background
`scripts/shared/http_transport.py` line 31-47:
```python
def __init__(
    self,
    http: httpx.AsyncClient,
    base_url: str,
    server_key: str,
    cfg: McpServerConfig | None = None,
    timeout_sec: float = 60.0,
) -> None:
    """Initialize with HTTP client, server URL, key, and optional auth config."""
    self._http = http
    self._base_url = base_url
    self._server_key = server_key
    self._auth_token: str = cfg.auth_token if cfg is not None else ""
    if self._auth_token:
        register_secret(self._auth_token)
    self._timeout = timeout_sec
    self._session_id: str = ""
```

And line 117:
```python
timeout = httpx.Timeout(self._timeout) if self._timeout > 0 else None
```

When `timeout_sec <= 0`, the timeout is set to `None`, which means httpx's default timeout (10 seconds) is used instead. This behavior is not documented in the docstring.

## Problem
Developers who set `timeout_sec` to 0 or a negative number may expect the timeout to be disabled, but instead httpx's default timeout is applied. This can lead to confusion during debugging and incident investigation.

## Reason for change
Documentation clarity improvement. Ensuring consistent documentation prevents misinterpretation during code reviews and refactoring.

## Implementation intent
Update the docstring of `HttpTransport.__init__()` to document the behavior when `timeout_sec <= 0`.

## Requirements

- REQ-002: Documentation remains consistent with implementation
- REQ-003: Existing tests pass after the change

Two possible approaches:

   ```python
   def __init__(
       self,
       http: httpx.AsyncClient,
       base_url: str,
       server_key: str,
       cfg: McpServerConfig | None = None,
       timeout_sec: float = 60.0,
   ) -> None:
       """Initialize with HTTP client, server URL, key, and optional auth config.

       Args:
           http: AsyncHTTPClient instance for making requests.
           base_url: Base URL of the MCP server.
           server_key: Server key for identifying this connection.
           cfg: Optional MCP server configuration.
           timeout_sec: Timeout in seconds. If <= 0, httpx's default timeout (10s) is used.
       """
   ```
2. **Keep current documentation**: Keep the current documentation as-is, since the parameter-level docstring already correctly explains the `strict_mode` behavior.

Approach 1 is preferred as it provides better visibility for developers who only read the class-level docstring.
