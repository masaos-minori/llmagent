# Work Plan: Distinguish Missing Key from Explicit None in TypedValidators

## Goal

Modify `_get_*` helpers in `scripts/agent/services/typed_validators.py` to distinguish between missing keys and explicit None values. For required fields, raise `ConfigReloadValidationError` when the value is None; for optional fields, preserve the current behavior of returning None.

## Scope

- Modify all `_get_*` helper functions (`_get_int`, `_get_float`, `_get_bool`, `_get_str`, `_get_list`, `_get_dict`) in `scripts/agent/services/typed_validators.py`
- Add `required: bool = False` parameter to each `_get_*` function
- When `required=True` and value is None, raise `ConfigReloadValidationError`
- When `required=False` and value is None, return None (preserving backward compatibility)
- Update callers in `config_reload.py` and `config_builders.py` that need the distinction
- Add unit tests for the new behavior

## Assumptions

1. `ConfigReloadValidationError` exists and is importable from `agent.services.exceptions`
2. Existing callers that do NOT pass `required=True` will continue working without changes (backward compatible)
3. The `_apply_*` functions and `_get_*_or_default` wrappers do NOT need `required=True` because they already handle None via their own logic (`is not None` checks, `or default` patterns)
4. Fields that should reject None values are those where the caller expects a concrete value (not a default), typically in config reload paths where the field must be present and valid

## Unknowns

2. Does the existing test suite cover any of these validators directly?

## Design

### API change

Add `required: bool = False` parameter to each `_get_*` function:

```python
def _get_int(d: dict[str, object], key: str, required: bool = False) -> int | None:
    v = d.get(key)
    if v is None:
        if required:
            raise ConfigReloadValidationError(f"config key {key!r} is required but is None")
        return None
    ...
```

### Backward compatibility strategy

- Default `required=False` preserves existing behavior for all current callers
- Callers that need strict validation pass `required=True`
- `_apply_*` functions keep their current `is not None` guard — no change needed
- `_get_*_or_default` wrappers keep their `or default` semantics — no change needed

### Caller classification

Based on the grep results:
- **Optional fields** (keep `required=False`): All `_apply_*` calls, all `_get_*_or_default` calls, and conditional assignments like `if (v := _get_int(...)) is not None`
- **Required fields** (need `required=True`): Fields where the caller expects a concrete value and would fail if None slips through — typically in config reload paths where the field is mandatory

## Implementation steps

1. Read `scripts/agent/services/typed_validators.py` and confirm all `_get_*` signatures
2. Add `required: bool = False` parameter to each `_get_*` function
3. In each `_get_*`, after `if v is None:`, add `if required: raise ConfigReloadValidationError(...)` before `return None`
4. Search for all callers of `_get_*` in the codebase to classify them as optional or required
5. Update callers that need strict validation to pass `required=True`
6. Write unit tests for the new behavior
7. Run existing tests to verify no regressions

## Validation plan

- Unit test: `_get_int({"key": None}, "key", required=True)` raises `ConfigReloadValidationError`
- Unit test: `_get_int({"key": None}, "key", required=False)` returns None
- Unit test: `_get_int({}, "key", required=True)` raises `ConfigReloadValidationError`
- Unit test: `_get_int({}, "key", required=False)` returns None
- Unit test: `_get_int({"key": 5}, "key", required=True)` returns 5
- Verify existing callers still work by running the full test suite
- Manual verification: config reload path with None value for a required field raises error

## Risks

1. **Backward compatibility**: If any existing caller relies on the implicit assumption that None values are treated as missing, adding `required=True` could introduce regressions. Mitigation: start with `required=False` everywhere and gradually tighten.
2. **Missing callers**: If there are callers beyond `config_reload.py` and `config_builders.py` that were missed during the grep search, they may silently break. Mitigation: thorough grep coverage.
3. **Over-eager raising**: Adding `required=True` too broadly could cause false positives where None is a legitimate value. Mitigation: only mark fields as required where the domain model requires it.
