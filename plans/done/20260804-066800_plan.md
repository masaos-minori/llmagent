## Design
The goal is to fill a critical operational knowledge gap: what is the "blast radius" of a single failing MCP server during its initial startup?

1. **Clarify Exception Propagation Path**:
   - Explain that if an MCP server fails to start (i.e., `/health` polling fails after retries), a `RuntimeError` is raised.
   - State that there is a single retry attempt (`HEALTH_CHECK_RETRY_DELAY_SEC` = 1.0s) before the security profile logic determines the outcome.

2. **Distinguish by Security Profile**:
   - **`security_profile=production`**: A failure causes the `RuntimeError` to propagate up through the startup orchestration, ultimately causing the **entire Agent process to terminate** (a crash).
   - **`security_profile=local`**: A failure is caught and handled gracefully. The specific MCP server is marked as unavailable/disabled, but the **rest of the Agent process and all other MCP servers continue to run normally**.

3. **Provide Source References**:
   - Include references to `scripts/agent/startup.py` (for the orchestration and decision logic), `scripts/agent/http_lifecycle.py` (where the error originates), and `shared/mcp_config.py::SecurityProfile` (defining the profiles).

4. **Maintain Tone and Style**:
   - Write as plain prose within the existing section.
   - Avoid using "Current behavior" labels, as this is an accepted, intentional part of the system's fail-safe design.
   - Match the Japanese language register used in the existing document.
