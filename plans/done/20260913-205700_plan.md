# Clarify no-cache guarantee's relationship to the removed semantic cache

## Goal

## Background
The Issue's cited claim
(`docs/03_rag_03_06_query_pipeline-helpers-and-cache.md:31`: "Every query executes
the full retrieval pipeline ... No query-result cache exists.") is confirmed
accurate — this statement is itself correct and verified by an existing test
(`tests/rag/test_rag_pipeline_no_cache_freshness.py`, confirmed to exist).

**Re-verified 2026-09-13** (this cycle, cross-referencing a sibling issue processed
this same cycle,
`issues/done/20260913-183011_missing_rag_system_overview_content.md`): the
"contradiction" the Issue identifies is not actually a contradiction between two
currently-true statements — it is that `docs/03_rag_01_system_overview.md`'s
"Semantic Cache" section (lines 103-105) still describes a semantic cache as an
active feature (`use_semantic_cache`, `semantic_cache_threshold`,
`semantic_cache_max_size`), when this feature was deliberately removed
(`282b08f38 req-005: remove SemanticCache from RAG pipeline and MCP server`,
followed by `09093016d feat(rag): remove semantic cache configuration fields and
references`). A sibling Plan generated this same cycle
(`plans/20260913-205143_plan.md`) already corrects that stale section to state the
feature was removed.

Once that sibling Plan's correction lands, this file's "no query-result cache
exists" claim and `03_rag_01_system_overview.md`'s corrected "semantic cache was
removed" note will both describe the same true, consistent state (no caching layer
of any kind exists) — but a reader arriving at this file before or independently of
that other document would still benefit from an explicit forward-pointer here,
rather than needing to already know the other document was corrected.

## Problem

caching layer exists, absent an explicit note in this file connecting the two.

## Reason for change
Add a one-sentence clarifying note in this file's own "Retrieval Freshness" section
stating that the semantic cache mechanism once documented elsewhere was removed,
so a reader does not need to reconcile the two documents' history on their own.

## Implementation intent

section documents has applied since that removal.
