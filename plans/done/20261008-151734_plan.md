## Problem
Verified against the current repository:
- ADR-004 INV-09 is "Confirmed", but AGENT-004 (a non-required subprocess MCP server aborts startup) is open, so the row must be "Partial".
- ADR-007 INV-09 (loopback bind and Bearer verification on every server) has no matrix row; MCP-005 is open (rag-pipeline-mcp attaches no authentication), so a "Partial" row is needed.
- ADR-012 INV-01 to INV-04 are one "Confirmed" row, but MCP-004 (no generic technical force-push block beyond the allow-list and the absent force parameter) is open and concerns INV-02, so INV-02 must be separated as "Partial".
- ADR-013 INV-07 (a token granting every role is never distributed to publisher or consumer processes) has no row; EVENTBUS-015 is open, so a "Partial" Manual Review row is needed.
- ADR-001 INV-01 is "Confirmed" citing only the preflight test; the Orchestrator construction path is now also fatal and has its own tests, so the row should cite both (the fallback deviation no longer exists).
- ADR-002's matrix statement says isolation is enforced "between environments"; the ADR is about processes.
- The Pipeline Mapping Summary disagrees with the matrix: it lists rows whose status is "Not verified" (ADR-006 INV-02, ADR-010 INV-04) under CI as if enforced, lists an "Operations" stage for rows that the matrix times as CI, and puts a "Not verified" invariant (ADR-014 INV-02) under Manual Review.
- The circular-reference list has three pairs; the actual ADR Related sections contain six bidirectional pairs (ADR-001/004, ADR-001/014, ADR-002/004 are missing), verified by parsing every ADR's Related section.
- The index does not explain the missing ADR-011. History shows ADR-011 existed and was merged into ADR-008; the repository has no stated rule that IDs are never reused (the Issue's proposed sentence "IDs are never reassigned" is unsupported; see UNK-01).

## Reason for change
Security decisions rely on the verification status; a "Confirmed" next to an open Known Issue is false assurance.
