## Assumptions

- The production `/opt/llm/config/eventbus.toml` deprecation-window status is not
  re-verified here; the requirement already documents this as an open item that would
  require separate maintainer confirmation, out of scope for a document-only pass.
- "Keep the guard permanently" means no expiry/removal is scheduled; this is a standing
  decision, not a time-boxed one.
- **Critical finding, added during implementation-procedure review**: the plan's Phase 1
  claim that `tests/eventbus/test_eventbus_config.py`'s regression tests "already pass"
  is false as currently written. The file imports `from scripts.eventbus.config import
  EventBusConfig, load_config` — but `scripts/` has no `__init__.py` and is not
  importable as a dotted package from the repo root, so running
  `uv run pytest tests/eventbus/test_eventbus_config.py -v` (with or without
  `PYTHONPATH=scripts`) fails at collection with `ModuleNotFoundError: No module named
  'scripts'`, before any test in the file executes. The correct, working import
  pattern — used by every other file in `tests/eventbus/` (e.g.
  `tests/eventbus/test_eventbus_dlq.py`'s `from eventbus.config import EventBusConfig`)
  — is `from eventbus.config import ...` under `PYTHONPATH=scripts`; verified directly
  with `PYTHONPATH=scripts python3 -c "from eventbus.config import EventBusConfig,
  load_config"`, which succeeds. `tests/eventbus/test_eventbus_startup.py` has the
  identical `from scripts.eventbus.config import (...)` defect (confirmed via `grep -n
  "from scripts\." tests/eventbus/*.py` — exactly these two files match). Both appear
  to have been left behind by commit `073825b3a` ("refactor: mirror tests/ directory
  structure onto scripts/ package layout"), which evidently updated most but not all
  `tests/eventbus/*.py` import lines. This plan cannot honestly claim "regression tests
  already cover and pass" without first fixing this import in both files — see
  Implementation steps and Risks.

## Risks

- **Risk**: A future contributor mistakes this decision record as inviting removal of the
  guard once the deprecation window "feels" closed → **Mitigation**: The requirement
  explicitly states the guard is kept permanently and unchanged, with a documented
  "what would change this decision" clause requiring maintainer confirmation of the live
  production config before any further code change.
- **Risk, found during implementation-procedure review**: this plan almost closed a
  requirement's "regression tests already pass" acceptance criterion without anyone
  having actually run those tests successfully — the Phase 1 verification step was
  marked complete based on reading the test *source* (confirming the right test names
  exist) without executing them, and the file has been non-functional since commit
  `073825b3a` left its import unconverted. → **Mitigation**: Phase 2 (added by this
  review) fixes the import and Phase 3 now requires an actual passing run before the
  requirement is closed out — "the test names exist" and "the tests pass" are no longer
  conflated.
- **Risk**: Regression tests for the guard could be deleted or weakened in an unrelated
  future refactor without anyone noticing the guard has lost coverage → **Mitigation**:
  This plan records the exact test names
  (`tests/eventbus/test_eventbus_config.py::test_load_config_rejects_stray_poll_interval_ms`,
  `::test_load_config_rejects_stray_offset_checkpoint_interval`,
  `::test_load_config_rejects_both_stray_keys`) as the durable regression baseline for this
  decision, so any future diff removing them against this file is discoverable by grep.
