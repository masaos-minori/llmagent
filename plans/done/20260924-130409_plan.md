  `docs/01_overview/` subfolder using `git mv` only (no rename, no content change
  beyond what a prior, already-landed Requirement covers), and fix every relative-path
  (containing `/`) reference broken by that move, so the overview area's docs are
  grouped exactly as the broader `docs/` reorganization plan intends.

references, which break when either endpoint of the reference changes its directory

planning, rather than discovering it during Phase 3 verification as `docsreorg05` did.

## Implementation intent
Use `git mv` for each of the 10 files, one command per file (`git log --follow`
continuity is preserved by `git mv` regardless of whether commands are batched, but
one-per-file keeps each step independently revertable per Incrementalism). This Git
environment does not auto-create an intermediate destination directory for `git mv`
(confirmed empirically during `docsreorg05`'s execution) — create `docs/01_overview/`
with `mkdir -p` before the first move.

Then fix the 3 relative-path references identified by the dependency-graphing analysis
below (Design): `docs/01_overview-arch-01-process.md`'s and
`docs/01_overview-arch-02-pipelines.md`'s own outbound links to `docs/adr/*.md` (their
new nesting depth under `docs/01_overview/` changes what `../adr/...` needs to resolve
correctly), and `docs/00_governance/00_index.md`'s 2 links to `01_overview/01_overview.md`
(that file itself moved into `docs/00_governance/` during `docsreorg05`, so its own
relative depth to the newly-created `docs/01_overview/` sibling also needs a leading
`../`).

## Design
**Path classification: Path B** (the Issue's Target Files span 10 files, satisfying
`SKILL.md` Routing's "Affects > 3 files" Path B criterion — the same classification
`docsreorg05` used). Path B's four analyses were performed:

- **Architecture analysis**: `.importlinter`'s `root_packages` contract does not cover
  `docs/` (reused from `docsreorg02`'s own Reference Files finding — not re-verified
  this session, per Tool Usage's unchanged-input reuse rule); no import boundary
  applies to a documentation-only move.
- **Dependency graphing**: applying the exact lesson from `docsreorg05`'s mid-execution
  `REQ-005` discovery, this Plan searched proactively (before Freeze, not after) for
  relative-path (containing `/`) references in both directions:
  1. Inbound: repository-wide search for Markdown links (`](...)` pattern) and front
     matter `related`/`source` fields containing `/` and naming any of the 10 files.
     Found exactly 2 matches, both in `docs/00_governance/00_index.md` (the "Overview"
     category entry and "System Overview" reading-order entry, both targeting
     `01_overview/01_overview.md`) — that file itself moved into `docs/00_governance/`
     during `docsreorg05`, so its relative depth to the new `docs/01_overview/` sibling
     needs a leading `../`, which it currently lacks. A third apparent match
     (`docs/02_deployment.md`'s citation of `` `docs/01_overview-files-01-build.md` ``)
     is a backtick-quoted prose mention, not a Markdown link — `check_docs_structure.py`'s
     `check_links()` only parses `[text](target)` syntax, so this prose form is never
     checked as a link and needs no fix (same class of non-issue confirmed during
     `docsreorg05`'s equivalent search).
  2. Outbound: read each of the 10 files' own Markdown links for a `/`-containing
     target. Found exactly 3 occurrences across 2 files:
     `docs/01_overview-arch-01-process.md` (1, to `docs/adr/ADR-002-config-isolation.md`)
     and `docs/01_overview-arch-02-pipelines.md` (2, to
     `docs/adr/ADR-001-workflow-engine-mandatory.md` and

     (`adr/ADR-*.md` resolves correctly from the flat `docs/` root today) but will
     break once these 2 files move one directory level deeper into

  3. Front matter `related` fields across all 10 files use only bare filenames citing
     sibling files within this same move batch — all 10 files move together, so these
     remain valid same-directory references with no fix needed.
  4. `tools/check_docs_consistency.py`'s `_CONF_D_DOC_PATH` constant already hardcodes
     `docs/01_overview/01_overview-files-06-misc.md` (landed by `docsreorg02`), ready
     for this move.
