## Background
`docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md` section "3.1.3 Markdown Source Detection Behavior" (lines 109-111) already states the behavior the Issue quotes: `.md`/`.markdown`/`.mdx` URLs always use heading chunking regardless of `md_index_enable`; other files use heuristic detection only if `md_index_enable=true`. `scripts/rag/ingestion/chunk_splitter.py`'s `_is_markdown_source()` method (lines 138-148) implements exactly this behavior with a docstring restating it, but neither the code nor the docs explain *why* file extension unconditionally overrides the heuristic/config-driven path for other files. Separately, the same document's section "3.1.4 Markdown Heading Chunking Behavior" (lines 113-117) already states, as an "Explicit in code" note, that Markdown heading chunking skips Sudachi normalization even for Japanese content — an already-documented behavior that answers the Issue's "known edge cases" request, just not yet framed as one.

## Problem
Two distinct gaps exist under one Issue: (1) a documentable fact — whether/how to override the `.md`/`.markdown`/`.mdx` unconditional behavior for non-URL sources — that Step 3 code inspection can answer directly (no override exists); and (2) an undocumented design rationale — why file extension determines chunking strategy at all — that no source in the repository answers, matching this batch's prior finding for Issue 183016 (`RAG-006`) and 183003 (`NC-033`): the correct action is to track the open question, not fabricate an answer.

## Reason for change
Per the Issue's Impact: operators cannot understand why files are chunked differently, and new developers may not realize `md_index_enable` does not apply to `.md`-extension URLs. Documenting the answerable override question directly, and tracking the unanswerable rationale question as a Needs Confirmation item, addresses both without inventing a design justification that does not exist in the repository.

## Implementation intent
Add a new subsection to `docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md` immediately after "3.1.4 Markdown Heading Chunking Behavior" (after line 117, before "### 3.2 Splitting Strategies" at line 119), stating: (a) there is no override — `.md`/`.markdown`/`.mdx` URLs unconditionally use heading chunking regardless of `md_index_enable` (per `_is_markdown_source()`, `chunk_splitter.py` lines 146-148, which checks the URL extension before even reading `self._md_index_enable`); (b) the known edge case already stated in section 3.1.4 (Japanese content in Markdown skips Sudachi normalization), explicitly labeled as the answer to "known edge cases where this behavior causes problems."
