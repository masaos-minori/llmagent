## Goal

Make LLM turn-end callback invocation consistent across all LLMTransportError propagation paths.

## Scope

**In**: `scripts/agent/orchestrator.py` (Orchestrator._handle_llm_turn())
**Out**: Changes to LLMTurnRunner behavior, other callback invocations

## Assumptions

1. Only `_handle_llm_turn` calls `_llm_runner.run()`
2. Callback ordering must be identical across all paths: `_on_llm_wait_end` → `_on_error` → `_on_turn_end`
3. No double-invocation risk — each callback is guarded by its own conditional check

Analysis: Current code at line 424-425 calls `_on_llm_wait_end()` BEFORE the `if result.exception is not None:` check. It IS called in the exception-return path. However, the callback ORDERING differs between paths:
- Exception-return path: `_on_llm_wait_end` → `handle_llm_transport_error` → `_on_error`
- Raise path: `handle_llm_transport_error` → `_on_llm_wait_end` → `_on_error`
- Success path: `_on_llm_wait_end` → `_on_turn_end`

Additionally, `_on_turn_end` is missing from the exception-return path (it's only in the else branch at line 434-435).

## Design

Move `_on_llm_wait_end` call to after exception handling in the exception-return path, matching the raise path ordering. Add `_on_turn_end` call to the exception-return path for consistency with the success path.

#### Step A: Modify _handle_llm_turn() — reorder callbacks in exception-return path

Current code (lines 424-436):

```python
                if self._on_llm_wait_end:
```

Change to:

```python
                if result.exception is not None:
                    # run() caught LLMTransportError internally; propagate callbacks
                    handle_llm_transport_error(
                        result.exception, ctx, self._diagnostic_store
                    )
                    if self._on_llm_wait_end:
                        self._on_llm_wait_end()
                    if self._on_error:
                        self._on_error(result.exception)

                    if self._on_llm_wait_end:

                    if self._on_turn_end:
                        self._on_turn_end()
                return result
```

Key points:
- Moved `_on_llm_wait_end` into both branches — ensures consistent ordering
- Added `_on_turn_end` to the exception-return path — matches success path behavior
- Ordering now matches raise path: `handle_exception` → `_on_llm_wait_end` → `_on_error` / `_on_turn_end`
