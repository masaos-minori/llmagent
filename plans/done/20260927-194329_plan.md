# Refactor repository_state.py to separate pipeline orchestration from the RepositoryState snapshot value object

## Goal
Move the write-protection pipeline's orchestration logic out of the `RepositoryState` frozen snapshot and into `WriteProtectionPipeline`, and remove the dead backward-compat delegation methods, so `repository_state.py` splits cleanly into a pure snapshot value object and a single orchestrator class — behavior-preserving.

## Priority
Medium

## Scope
- **In-Scope**:
  - Move `RepositoryState.verify_authorization`, `verify_preconditions`, `verify_postcondition`, `audit`, `structured_result` into `WriteProtectionPipeline` (methods or pipeline-owned helpers).
  - Rewrite `WriteProtectionPipeline.run()` to call the relocated stage methods locally instead of reaching into `self._state`.
  - Collapse the `verify_preconditions` → `check_dirty_worktree` / `check_detached_head` two-layer delegation by checking `is_dirty` / `is_detached_head` directly.
  - Relocate `audit()` and update `PipelineResult.reject()` / `PipelineResult.ok_result()` factory call sites.
  - Remove the backward-compat delegation methods (`check_dirty_worktree`, `check_detached_head`, `validate_protected`, `validate_ref`) and their dedicated tests, after re-confirming zero non-test callers.
  - Group module-level helpers by concern (ref-validation family vs. remote-URL family) with unchanged signatures.
  - Update the module docstring and the `WriteProtectionPipeline` docstring.
- **Out-of-Scope**:
  - Changing write-protection policy, adding/removing pipeline stages, or branch/remote configuration.
  - Changing `snapshot()` semantics, the frozen dataclass field set, or the Pydantic opaque-type schema.
  - Altering the process-local per-path lock registry (`_repo_locks`, `_registry_guard`, `_get_repo_lock`) or REQ-005 / REQ-006 serialization semantics.
  - Renaming public symbols (`RepositoryState`, `WriteProtectionPipeline`, `PipelineResult`, `PipelineStage`).
  - Fixing unrelated findings in sibling modules.

## Background
The module is a frozen `RepositoryState` dataclass plus a multi-stage `WriteProtectionPipeline` orchestrator that unifies scattered `git.Repo` queries into a single snapshot per request, backing the process-local per-path write-serialization locks (REQ-005 / REQ-006). Over time, pipeline stage logic was added as methods on `RepositoryState` alongside the snapshot data. Current consumers: `git_service.py` builds the snapshot and runs the pipeline; `git_security.py` holds a repo-state reference; `git_models.py` exposes it through a Pydantic mixin; `format_output.py` reads the snapshot and remote-URL helpers; `git_server.py` serializes state. Tests live in `tests/mcp_servers/git/test_repository_state.py`.

## Problem
`RepositoryState` mixes two responsibilities in one frozen dataclass:

1. Immutable snapshot data (path, is_dirty, head_type, active_branch, ...) — its declared purpose.
2. Pipeline orchestration behavior (`verify_authorization`, `verify_preconditions`, `verify_postcondition`, `audit`, `structured_result`) — orchestration concerns that belong to the write-protection pipeline, not the snapshot.

Consequences:

- The orchestrator `WriteProtectionPipeline.run()` reaches back into `self._state.verify_*()` instead of owning the stage logic, so the pipeline's control flow is split across two classes.
- The backward-compat delegation methods (`check_dirty_worktree`, `check_detached_head`, `validate_protected`, `validate_ref`) duplicate logic already available as properties/fields (`is_dirty`, `is_detached_head`, `protected_branch`, `ref_valid`) and return the same `(bool, str)` shape. Static grep across `scripts/` and `tests/` shows they are invoked only by `tests/mcp_servers/git/test_repository_state.py`, never by production code under `scripts/`.
- Module-level helpers are not grouped by concern: the ref-validation family (`_normalize_branch_name`, `_is_safe_ref`, `_validate_ref`, `_is_protected_branch`) sits near the remote-URL family (`_resolve_remote_url`, `_redact_remote_url`).

## Reason for change
Maintainability and testability. A reader must understand two concerns before trusting the snapshot, and the pipeline's control flow is divided between the snapshot and the orchestrator. The dead delegation surface adds a second place whose behavior must mirror the properties it duplicates. This is Medium priority: it affects maintainability and type-safety, not behavior, because the refactor preserves behavior.

## Implementation intent
High level only.

- Make `RepositoryState` a pure frozen snapshot holding only captured data plus the transient `_repo` handle. Move the pipeline stage methods out of the snapshot and into `WriteProtectionPipeline` as methods or small private helpers owned by the pipeline, so the pipeline owns all stage logic in one class.
- Preserve exact rejection messages, stage names, and stage indices — these form the security contract.
- Remove the backward-compat delegation methods and their dedicated tests after re-confirming zero non-test callers; keep the underlying properties/fields and the module-level `_validate_ref` intact.
- Group the module-level helpers by concern (ref-validation vs. remote-URL) without changing signatures.
- Do not change `snapshot()`, the Pydantic core schema, the frozen-dataclass field set, or the lock registry semantics.

## Design
Path A (small task): affects ≤ 3 files, no public/runtime interface change, no DB schema change. Analysis limited to direct verification of the target file and its immediate dependencies plus the validation-quality baseline (`radon cc` on the target module: `verify_postcondition` C=11 is the complexity hot spot; moving orchestration out reduces `RepositoryState` complexity).

- `RepositoryState` becomes a pure frozen value object: captured-data fields plus the transient `_repo` handle only, no behavior methods.
- `WriteProtectionPipeline` owns all stage logic. Move `verify_authorization`, `verify_preconditions`, `verify_postcondition`, `audit`, `structured_result` into the pipeline as methods or small private helpers owned by the pipeline. Rewrite `run()` to call them locally (`self.verify_authorization()` etc.) instead of `self._state.verify_*()`.
- When moving `verify_preconditions`, inline the dirty-worktree and detached-HEAD checks against `self._state.is_dirty` / `self._state.is_detached_head`, collapsing the two-layer delegation through `check_dirty_worktree` / `check_detached_head`.
- `audit()` return dict must stay identical; relocate it and update both `PipelineResult.reject()` and `PipelineResult.ok_result()` factory call sites together.
- `structured_result` has zero production callers (defined once, called only by a test). Preserve its behavior on move per REQ-001; decide whether to delete it as dead code in a follow-up, not in this issue.
- Placement choice for `audit()` / `structured_result`: recommend moving into `WriteProtectionPipeline` as methods to keep orchestration cohesive; standalone module functions are acceptable if they need no instance state. Non-blocking design decision.
- Remove the four delegation methods and their dedicated tests (UNK-01 gate applies first). Keep the underlying properties/fields and the module-level `_validate_ref`.
- Regroup helpers by concern without changing signatures: ref-validation family (`_normalize_branch_name`, `_is_safe_ref`, `_validate_ref`, `_is_protected_branch`) and remote-URL family (`_resolve_remote_url`, `_redact_remote_url`).
- Do not change: frozen dataclass fields, `snapshot()` inputs/outputs, `__get_pydantic_core_schema__` opaque schema, `_repo_locks` / `_registry_guard` / `_get_repo_lock`, REQ-005 / REQ-006 semantics, `__all__`.
