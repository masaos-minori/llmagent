# Plan: Normalize EventBus configuration validation and role-token policy

## Goal

Make every accepted configuration meaningful, fail closed on invalid security settings, and use one error contract — separate from (but coordinated with) `CI-001`'s broader ConfigLoader-migration question.

## Priority
Medium

## Scope
- **In-Scope**: Configuration validation structure (field vs cross-field separation), administrator role definition/removal, supported token combinations, authentication-failure response contract
- **Out-of-Scope**: CI-001 ConfigLoader migration, unrelated route handler changes

## Background
Cross-field validation currently runs inside the per-key type-validation loop rather than as a separate pass, making validation error handling harder to reason about and test in isolation. Whether an administrator role exists (and which endpoints it may access) is not clearly defined, and `admin_token` may be present without a corresponding role. Required tokens are validated against what appears to be an arbitrary subset of enabled capabilities rather than a rule tied to which capabilities are actually enabled, and authentication-failure handling is not centralized to one documented HTTP 401 response format.

## Problem
Cross-field validation currently runs inside the per-key type-validation loop rather than as a separate pass, making validation error handling harder to reason about and test in isolation. Whether an administrator role exists (and which endpoints it may access) is not clearly defined, and `admin_token` may be present without a corresponding role. Required tokens are validated against what appears to be an arbitrary subset of enabled capabilities rather than a rule tied to which capabilities are actually enabled, and authentication-failure handling is not centralized to one documented HTTP 401 response format.

## Reason for change
Cross-field validation, administrator-token semantics, supported token combinations, and unauthorized responses are one configuration and authentication contract.

## Implementation intent
Make every accepted configuration meaningful, fail closed on invalid security settings, and use one error contract — separate from (but coordinated with) `CI-001`'s broader ConfigLoader-migration question.

## Requirements
- `REQ-001`: Move cross-field validation outside the per-key type-validation loop.
- `REQ-002`: Separate field validation from cross-field policy validation.
- `REQ-003`: Add focused tests for each validation error.
- `REQ-004`: Define whether an administrator role exists and which endpoints it may access.
- `REQ-005`: Remove `admin_token` if no administrator role is required.
- `REQ-006`: Validate required tokens based on enabled capabilities rather than an arbitrary subset.
- `REQ-007`: Document valid token combinations.
- `REQ-008`: Centralize authentication failure handling.
- `REQ-009`: Return one documented HTTP 401 response format.
- `REQ-010`: Add the appropriate authentication challenge header if required by the API contract.
- `REQ-011`: Ensure one audit record per failure.

### Separate Cross-Field Validation from Field Validation (REQ-001, REQ-002)
Current state in `load_config()`:
```python
# Line 184-192: Per-key type validation
for key, expected_type in _CONFIG_KEY_TYPES.items():
    if key in data:
        value = data[key]
        if not isinstance(value, expected_type):
            raise ValueError(...)

# Line 194-196: Auth token validation
if not data["auth_token"]:
    raise ValueError("eventbus config 'auth_token' must not be empty.")

# Lines 198-206: Cross-field validation (mixed with per-key validation!)
if not any([
    data.get("consumer_token"),
    data.get("operator_token"),
    data.get("admin_token"),
]):
    raise ValueError("At least one per-role token must be configured")
```

And in `__post_init__()`:
```python
# Lines 73-80: Cross-field validation
if self.slow_consumer_threshold >= self.subscriber_queue_maxsize:
    raise ValueError(...)
if self.backlog_health_threshold > self.subscriber_queue_maxsize:
    raise ValueError(...)
```

**Decision**: Separate validation into three distinct phases:

1. **Phase 1: Key presence validation** (in `load_config()`)
   - Reject unknown keys
   - Validate required keys exist

2. **Phase 2: Per-key type/value validation** (in `load_config()`)
   - Type checking for each key
   - Single-value constraints (port range, max_retry >= 1, etc.)

3. **Phase 3: Cross-field policy validation** (new function, called after Phase 2)
   - Token combination rules
   - Threshold relationships
   - Deployment mode validation

```python
def _validate_cross_field(cfg: EventBusConfig) -> None:
    """Validate cross-field relationships after per-key validation passes."""
```

### Administrator Role Definition (REQ-004, REQ-005)
Current state:
- `admin_token` field exists in EventBusConfig (line 54)
- No `Role.ADMIN` in the Role enum (line 21-25)
- `_populate_token_maps()` gives admin_token superuser privileges (lines 85-88)
- No `/admin` route in `_ROUTE_ROLE_MAP` (lines 29-39)

**Decision**: Add ADMIN role and corresponding routes. Rationale:
1. The infrastructure (`admin_token` field, superuser mapping in `_populate_token_maps()`) suggests an admin role was intended

### Supported Token Combinations (REQ-006, REQ-007)
Current state: The rule "at least one per-role token must be configured" is enforced in `load_config()` (lines 198-206), which means:
- Publisher-only deployment is NOT allowed (no consumer/operator/admin token)
- Monitoring-only deployment is NOT allowed (same reason)

**Decision**: Allow publisher-only and monitoring-only deployments. These are valid operational modes where:
- Publisher-only: Only `/publish` endpoint is used
- Monitoring-only: Only `/health` endpoint is used

The validation should check which endpoints are actually accessed rather than enforcing a blanket requirement:
```python
def _validate_token_combinations(cfg: EventBusConfig) -> None:
    """Validate that required tokens are present based on enabled capabilities."""
    # If any per-role capability is used, that token must be configured
    # But we don't require ALL per-role tokens — just the ones needed
    
    # At minimum, either auth_token OR at least one per-role token must be configured
    has_any_token = bool(cfg.auth_token) or any([
        cfg.publisher_token,
        cfg.consumer_token,
        cfg.operator_token,
        cfg.monitoring_token,
        cfg.admin_token,
    ])
    
    if not has_any_token:
        raise ValueError("At least one authentication token must be configured")
```

### Centralize Authentication Failure Handling (REQ-008, REQ-009, REQ-010)
Current state: Authentication failures use inconsistent response formats:
- Middleware level: `JSONResponse({"error": "Unauthorized"}, status_code=401)` (line 279)
- `verify_bearer_token()`: `HTTPException(status_code=401, detail="Unauthorized")` (line 109)
- `require_role()`: `HTTPException(status_code=401, detail="Unauthorized")` (line 141)
- Server misconfiguration: `HTTPException(status_code=500, detail="Server misconfiguration: auth_token not configured")` (line 118)

**Decision**: Centralize to one documented HTTP 401 response format:
```json
{
    "error": "Unauthorized",
    "detail": "<specific reason>",
    "www-authenticate": "Bearer realm=\"eventbus\""
}
```

Add a helper function:
```python
def unauthorized_response(detail: str = "Unauthorized") -> JSONResponse:
    """Return a standardized HTTP 401 Unauthorized response."""
    return JSONResponse(
        content={"error": "Unauthorized", "detail": detail},
        status_code=401,
        headers={"WWW-Authenticate": 'Bearer realm="eventbus"'},
    )
```

Update `attach_auth_middleware()` to use it:
```python
async def _auth_middleware(request: Request, call_next):
    req_id = str(__import__("uuid").uuid4())
    request.state.request_id = req_id
    if not _is_authorized(request):
        return unauthorized_response("Invalid or missing Bearer token")
    response = await call_next(request)
    response.headers["X-Request-Id"] = req_id
    return response
```

Update `verify_bearer_token()`:
```python
async def verify_bearer_token(...):

        return unauthorized_response("Missing Authorization header")
    # ... rest of function
```
