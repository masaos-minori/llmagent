# Reduce cross-class private coupling in factory.py lifecycle classes

## Goal
Remove the private cross-class coupling between `_ServerLifecycleRouter` and
`_SubprocessLifecycleManager` in `scripts/agent/factory.py` so the router coordinates
through the manager's public `LifecycleManagerProtocol` surface instead of reaching into
its private `_http_mgr` attribute, without changing any external behavior.

## Priority
Medium

## Scope
- **In-Scope**:
  - Replace `_ServerLifecycleRouter` accesses to `_SubprocessLifecycleManager._http_mgr`
    (12 sites: factory.py lines 268, 275, 278, 287, 293, 314, 318, 337, 352, 360, 367,
    382) with calls to the manager's public `LifecycleManagerProtocol` methods where a
    matching public method exists.
  - Where no public equivalent exists, add a thin documented public wrapper to
    `_SubprocessLifecycleManager` mirroring its existing delegation pattern, or leave the
    access with a one-line note.
  - Update the router class docstring only if it describes the private-delegation
    mechanism.
- **Out-of-Scope**:
  - Changing `HttpServerLifecycleManager` or the `LifecycleManagerProtocol` definition.
  - Collapsing the two lifecycle classes into a single class.
  - Refactoring builder functions or `build_agent_context` sequential wiring.
  - Any behavioral, state-machine, cooldown, or policy change.

## Background
`scripts/agent/factory.py` assembles `AgentContext` services; service injection into
`ctx.services` is separated from `AgentREPL` to enable testing. Two lifecycle classes
implement `LifecycleManagerProtocol`:

- `_ServerLifecycleRouter` — coordinator (state tracking, cooldown, shutdown guard).
- `_SubprocessLifecycleManager` — subprocess operations (start/restart/shutdown).

Both are wired into `ToolExecutor` and used exclusively through the protocol by external
callers (`scripts/shared/tool_executor.py`,
`scripts/shared/tool_transport_invoker.py`).

## Problem
`_ServerLifecycleRouter` accesses `_SubprocessLifecycleManager._http_mgr` (a private
instance attribute) at 12 call sites — lines 268, 275, 278, 287, 293, 314, 318, 337,
352, 360, 367, 382 — to perform operations that `_SubprocessLifecycleManager` already
exposes through its public `LifecycleManagerProtocol` methods (`ensure_ready`,
`shutdown_all`, `restart`, `get_process_snapshot`, `cleanup_server_resources`, ...). This
couples the coordinator to the manager's private internals across a class boundary.

## Reason for change
Maintainability and testability risk. The private access forces both classes to evolve
together: a rename or move of `_http_mgr` in the manager would break the router silently.
It also makes the router hard to unit-test in isolation, since tests must stand up the
real manager plus its `_http_mgr`. Because every external interaction already goes through
the protocol, routing the router through the manager's public surface reduces coupling
without changing any external behavior.

## Implementation intent
Move the router's dependency on the manager from its private `_http_mgr` to its public
protocol surface. Where the router performs a passthrough the manager already implements
publicly, delegate to that method. Where the router wraps an operation with shutdown-guard
or cooldown logic, keep the wrapper but drive its leaf operations through the manager's
public protocol methods rather than `_http_mgr`. Where no public equivalent exists, add a
thin documented public wrapper to `_SubprocessLifecycleManager` mirroring its existing
delegation pattern (e.g. `get_process_snapshot`), keeping such wrappers off the protocol.
Preserve the `LifecycleManagerProtocol` contract and all observable behavior (state
transitions, cooldown timing, process snapshots) exactly.

## Requirements
- `REQ-001`: Remove every `_ServerLifecycleRouter` access to
  `_SubprocessLifecycleManager._http_mgr` that has a matching public manager method,
  replacing it with a call to that public method.
- `REQ-002`: Preserve the `LifecycleManagerProtocol` contract exactly — no method added to
  or removed from the protocol definition.
- `REQ-003`: Do not change which class owns `_http_mgr` nor alter `HttpServerLifecycleManager`.
- `REQ-004`: Preserve observable behavior — state-machine transitions (`assert_valid_transition`),
  cooldown window (`_COOLDOWN_SECONDS`), shutdown guard, and process-snapshot contents.
- `REQ-005`: Where no public-method equivalent exists, add a thin documented public
  wrapper to `_SubprocessLifecycleManager` mirroring its existing delegation pattern, or
  leave the access with a one-line note; do not invent new behavior.

## Design
- Scope: single-file internal refactor of `scripts/agent/factory.py`.
- Two classes implement `LifecycleManagerProtocol`: `_ServerLifecycleRouter` (coordinator)
  and `_SubprocessLifecycleManager` (subprocess ops). The router currently reaches the
  manager's private `_http_mgr` (an `HttpServerLifecycleManager`) at 12 sites.
- Approach: move the router's dependency from the private attribute to the manager's public
  protocol surface. For passthroughs where the manager already exposes the operation
  publicly, delegate directly. For guarded wrappers (`ensure_ready`, `restart`,
  `start_http_subprocess`), keep the shutdown-guard/cooldown/transition logic in the router
  but drive leaf ops through the manager's public methods; where no public equivalent
  exists, add a thin documented wrapper on the manager mirroring its existing delegation
  pattern (e.g. `get_process_snapshot` at L149).
- Invariants: preserve `LifecycleManagerProtocol` contract (no protocol change), preserve
  `_http_mgr` ownership in `HttpServerLifecycleManager`, preserve observable behavior
  (state transitions, cooldown, shutdown guard, snapshots).

  pre/post snapshot contents.

  → **Mitigation**: explicitly keep new wrappers off `LifecycleManagerProtocol` (UNK-03);
  verify the protocol diff is empty.
- **Risk**: Removing `_http_mgr` access breaks tests that reach into `_http_mgr` mocks.
  → **Mitigation**: existing tests route through the manager's real methods onto the same
  mock; verify assertions still hold; update test assertions only if behavior legitimately
  changes (it must not).
