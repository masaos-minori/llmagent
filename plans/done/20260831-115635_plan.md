# Plan: Remove dead `GitSecurityGuards` class and correct stale documentation citations

## Goal
Eliminate the dead `GitSecurityGuards` class from `scripts/mcp_servers/git/git_security.py` and update all stale documentation that incorrectly attributes protected-branch enforcement to this unused class.

## Priority
Medium

## Scope
- **In-Scope**: Dead code removal of GitSecurityGuards; documentation correction across 3 doc files and 1 source file comment
- **Out-of-Scope**: Any change to the actual protected-branch enforcement behavior; changes to `docs/00_security_02_high-risk-tool-common-policy.md` (already corrected in prior fix); `_check_dirty_worktree()`/`_check_detached_head()` dead-code removal (already completed)

## Background
`GitSecurityGuards` (`scripts/mcp_servers/git/git_security.py`) is a fully-defined class whose docstring claims "Mixed into GitService via inheritance so tests can still call svc._check_repo_path() and svc._check_write()" — a claim the current code does not fulfill. Direct source inspection confirms:
- `GitService` declares no base class (`class GitService:` at line 83)
- Zero imports/instantiations of `GitSecurityGuards` anywhere in `scripts/`, `tests/`, or `docs/`
- The actual protected-branch enforcement is `GitService._check_protected_branch()` / `GitService._validate_protected()`, defined directly on `GitService`

Four documentation locations attribute behavior to this dead class, one explicitly labeled `(Explicit in code)` — a confidence label that is currently incorrect.

## Problem
Five files contain stale references to `GitSecurityGuards`:
- `scripts/mcp_servers/git/git_security.py:12` — the dead class definition itself
- `scripts/mcp_servers/git/git_service.py:8` — module-docstring comment describing an architecture the code no longer has
- `docs/04_mcp_04_05_git.md:93,107,111,130` — four citations claiming `GitSecurityGuards` is a mixin on `GitService` enforcing checks
- `docs/04_mcp_90_inconsistencies_and_known_issues.md:84` — cites `GitSecurityGuards._check_protected_branch()` as the enforcement method
- `docs/adr/ADR-012-git-mcp-server-side-write-enforcement.md:205,240` — lists `GitSecurityGuards` as a key symbol and misattributes its location to `git_service.py`

## Reason for change
- Four documentation locations attribute behavior to a class that is not actually used, one explicitly labeled `(Explicit in code)` — a confidence label that is currently incorrect
- `GitSecurityGuards` itself is dead code: a fully-defined, docstring-documented class with zero callers, which readers would reasonably assume is live given `git_service.py`'s own header comment describing it as mixed in
- Risk of confusing a future contributor into modifying `GitSecurityGuards` expecting it to take effect, when it does not

## Implementation intent
Two independent tracks, executed sequentially:
1. **Dead code removal** (code track): Delete the `GitSecurityGuards` class and its file if nothing else remains, update `git_service.py`'s stale docstring comment
2. **Documentation correction** (doc track): Update all five stale citations to name `GitService._check_protected_branch()` / `GitService._validate_protected()` instead of `GitSecurityGuards`; correct ADR-012's "Key symbols" and "defined in" file-path claims
