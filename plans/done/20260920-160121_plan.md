## Goal
Remove the mechanically-derivable content `tools/check_docs_content_policy.py` flags in
five MCP design documents (two error-handling tables, a full JSON payload example, a
duplicate default-value sentence, and a field/type/default table), replacing each with

findings for these five files while preserving all non-code-derivable design intent
already present around them.

## Reason for change
Each finding duplicates a claim whose canonical source is code (`HealthRegistry`'s
retry/failure logic, `error_type` values, `McpServerConfig` fields, each server's own
`/v1/tools` handler) or an already-present table in the same document
(`04_mcp_04_05_git.md`'s case duplicates its own Configuration Fields table). Per
`docs/00_governance_01_documentation-policy.md` Claim Type Taxonomy, these are
`runtime-behavior`/`configuration-schema` claims whose canonical source is
`scripts/`/`shared/mcp_config.py`, not the design document.

Step 3's inspection (`uv run python tools/check_docs_structure.py`, run against all five
target files) additionally found four pre-existing structural findings unrelated to the
content-policy findings above — a malformed front-matter `related` entry in
`04_mcp_02_03_audit-logging-and-errors.md` (the related-file field carries a long
description appended after the filename, not a bare filename) and missing `##
Related Documents`/`## Keywords` sections in `04_mcp_03_06_tool-runtime-availability-metadata.md`

fixing them is unrelated cleanup this Plan's Requirements do not cover, and the source
Issue's Acceptance Criteria ("`check_docs_structure.py` passes for the five files") is
corrected below to account for this pre-existing, non-zero baseline rather than treating
it as a new regression this Plan must fix.
