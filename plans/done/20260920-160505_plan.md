## Goal
Remove the mechanically-derivable content `tools/check_docs_content_policy.py` flags
across five EventBus documents (two literal port numbers, a seven-line config-file
inventory list, and five full JSON payload examples), replacing each with a
placeholder or a pointer to its canonical source, so the tool reports zero findings for
these five files while preserving all non-code-derivable design intent already present
around them.

## Background
`docscope1`/`docscope2` (see `issues/done/`) established the Docs content policy and
the `check_docs_content_policy.py` detection tool. A prior EventBus cleanup issue
(`issues/done/20260905-153715_dcp006_eventbus_docs_content_policy_cleanup.md`) already
removed one literal port number from `06_eventbus_05_configuration-and-operations.md`,
but subsequent feature commits (e.g. `d743e6639` centralizing operational thresholds
into `EventBusConfig`) reintroduced new findings in the same and adjacent files.
`GV-021`'s own entry in `docs/00_governance_04_documentation-checks.md` already notes
this domain has had unresolved literal-port-number findings since 2026-09-05.

## Reason for change
The port numbers and config-field list duplicate `EventBusConfig`
(`scripts/eventbus/config.py:75`) — per
`docs/00_governance_01_documentation-policy.md` Claim Type Taxonomy,
`production-effective-value`/`configuration-schema` claims whose canonical source is the
config file/dataclass, not runbook prose. The JSON payload examples duplicate the
actual response schema each route handler produces (`api-contract` claim type,
confirmed against the three handler files in Problem) — a field added or removed from
the response would require multiple separate doc edits to stay in sync, the exact
drift mode this policy targets.

## Implementation intent
For the runbook commands, keep the command shape but replace the literal port with a
placeholder or a pointer to the configured `port` value (per `skills/DESIGN.md` "No
concrete configuration values"). For the Configuration Fields list, replace the
per-field bullets with a pointer to `EventBusConfig`, retaining the per-role-token
bullets and cross-field constraint prose immediately below it (already compliant, not
flagged, confirmed still present at Step 3). For each JSON example, keep only the
fields carrying non-obvious health/degradation semantics already explained in
surrounding prose, and point to the corresponding route handler for the exact schema.
