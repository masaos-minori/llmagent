## Goal
- Let a procedure declare that its target file is to be created, with `` `path` (new) `` in the "### Target file" section, so that `tools/stale_detector.py` no longer reports `source_missing` for it, while an unmarked absent target, a declared-new target whose directory is missing, and a declared-new target that already exists are all still reported.

## Priority
Medium

## Scope
- **In-Scope**:
  - Recognize `(new)` after the target path in the "### Target file" section.
  - For a declared-new target: skip the existence check, require that the containing directory exists, report a mismatch if the file already exists, check symbols, imports, and "Before:" blocks against an empty target, and skip line-number citations that resolve to the target.
  - Keep `source_missing` for an unmarked absent target, and keep every check for an existing target unchanged.
  - Tests for each acceptance case, the template notes, `code-implementation` Step 3 text, and the `TOOL_DESCRIPTIONS.md` entry.
- **Out-of-Scope**:
  - Changing `tools/generate_workitem.py` to write the marker automatically (decided: not in this plan; see `UNK-02`).
  - Non-Python names reported as missing symbols (sibling issue `stale003`).
  - Plan Freeze validation, `rules/workflow-lifecycle.md`, and making the detector read the Plan.
  - The abort-on-any-mismatch policy, the rule against correcting a procedure and continuing, archived procedures under `implementations/done/`, and the `.claude/worktrees/` copy of the tool.

## Background
- `skills/code-implementation/workflow.md` Step 3 runs `tools/stale_detector.py` and aborts the cycle on any mismatch.
- `rules/workflow-lifecycle.md` (Implementation Target Files Validation) accepts a Plan row for a file not yet created when its Reason for Modification states "New file" and the containing directory exists. The detector has no counterpart for this.
- `plans/done/20261012-132739_plan.md` (stale001, implemented and pushed) introduced the `(new)` marker for backticked symbols and imports. It did not cover the target file.
- Issue `issues/20261012-172916_stale002_allow-new-target-files-in-stale-detector.md` records the gap and leaves two decisions open; both were decided by the user when this Plan was made (see `UNK-01`, `UNK-02`).

## Problem
Verified against current source and by running the detector (`Confirmed by repository evidence`):
- **Absent target aborts (reproduced)**: a procedure whose "### Target file" is `` `tools/brand_new_tool.py` (new) `` followed by a symbol marked `(new)` is reported `Stale: 1 mismatch(es) detected.` with `source_missing: Source file does not exist: tools/brand_new_tool.py`, exit code 1. The marker has no effect on the target.
- **Cause (explicit in code)**: `StaleResult.from_procedure` (`tools/stale_detector.py:337`) takes the path from `_TARGET_FILE_SECTION_RE` (line 79), which captures only the backticked path and ignores what follows it, then returns `source_missing` at line 385 as soon as the file is absent, before any other check runs.
- **Marker already accepted elsewhere (reproduced)**: `` `tools/stale_detector.py` (new) `` on an existing file is reported clean today, so the `(new)` text after a target is silently ignored; the new "already exists" rule is therefore a behavior change for that input, and it is limited to procedures that write the marker (38 of the 5043 archived procedures write `(new)` on the Target-file line; they were archived after implementation and are not re-run by the workflow).
- **Downstream tools tolerate the marker (reproduced)**: `tools/check_workitem_traceability.py` `_clean_field_value` returns `tools/x.py` for both `` `tools/x.py` (new) `` and `` `tools/x.py` ``, so the target-file-mismatch comparison is not disturbed.
- **Line citations need care**: `_check_line_refs` (line 415) validates a "Line N" citation against the target's length unless `_find_scoped_path` resolves it to another file; against an empty new target every unscoped citation would be reported out of bounds, so unscoped citations must be skipped for a declared-new target.
- **Frequency (measured by the Issue)**: 161 of 2581 plans in `plans/done/` have a "New file" row (about 6%). How often the abort happened is unknown, because the archive only shows post-implementation state.

## Reason for change
- The gate exists to catch a procedure whose premises changed under it. A file that is supposed to be created is not such a premise, so for about 6% of plans the abort is a false positive by construction, and the usual workaround (rewording the target) is not available because the target is the point of the procedure.
- The fix reuses the repository's existing `` `path` (new) `` convention, so no new syntax is introduced.

## Implementation intent
- Narrow and additive: behavior changes only for a procedure that writes `(new)` after its target path. A procedure without the marker behaves exactly as today.
- Detect the marker with the stale001 helper (`_is_marked_new`) applied right after the target-section match, so one definition of "marked new" serves symbols, imports, and targets.
- For a declared-new target, decide the target's state before any content check: directory missing → mismatch `new_target_dir_missing`; file already present → mismatch `new_target_exists` (decided by the user: report it); otherwise continue with an empty source text.
- Pass an empty source and a flag that makes `_check_line_refs` skip citations that do not resolve to another file. Cross-file citations and repository-wide symbol presence keep working.
- Keep the detector regex-based and dependency-free; report all findings in one pass.

## Requirements
- `REQ-001`: A procedure whose "### Target file" is a backticked path followed by `(new)`, naming an absent file in an existing directory, is reported clean when its other references are valid.
- `REQ-002`: The same procedure without `(new)` is still reported `source_missing`. A declared-new target whose containing directory does not exist is reported as a mismatch, and a declared-new target whose file already exists is reported as a mismatch.
- `REQ-003`: For a declared-new target, symbols that exist elsewhere in the repository are not reported, names that exist nowhere and are not marked `(new)` are still reported `symbol_missing`, a "Before:" block is reported (a new file has no prior content), and line citations that resolve to the target are skipped while citations scoped to another file are still verified.

- `REQ-005`: The convention is documented where procedures are authored and consumed: the procedure template notes, `code-implementation` Step 3 text, and the `stale_detector.py` entry of `TOOL_DESCRIPTIONS.md`.
- `REQ-006`: Detector verdicts on a sample of archived procedures are identical before and after the change, and the traceability checker still passes for a procedure that writes the marker.

## Design
- Path B (5 target files). Architecture analysis: `tools/stale_detector.py` imports only the standard library; `lint-imports` covers `scripts/`, which this plan does not touch. Dependency graph: the detector is referenced by `tests/tools/test_stale_detector.py`, `tools/TOOL_DESCRIPTIONS.md`, and the `code-implementation` workflow text; no hook or CI job runs it. `tools/check_workitem_traceability.py` reads the same "### Target file" line and tolerates the marker (reproduced). Historical analysis: moderate recent churn on the detector, its test, and the workflow; the template is quiet. Operational dependencies: none.
- Target parsing: `from_procedure` keeps `_TARGET_FILE_SECTION_RE` and evaluates `_is_marked_new(text, target_match.end())` for the section match, so the path value stays marker-free (the traceability comparison and `result.target_file` are unchanged). The fallback path (no "### Target file" section) is never declared new.
- Flow for a declared-new target, in order: (1) parent directory missing → `new_target_dir_missing`, return; (2) file exists → `new_target_exists`, return (checking further against a file the procedure says it creates would only add noise); (3) otherwise run the symbol, import, and "Before:" checks with an empty source text and the line check in skip-unscoped mode. Unmarked targets follow the existing flow with no change.
- Line citations: `_check_line_refs` gains a keyword flag. When set, a citation for which `_find_scoped_path` returns no path is skipped; a scoped citation is validated as today. This keeps the existing-target behavior byte-identical when the flag is off.
- Complexity: `from_procedure` is small today; the new branch is extracted into a helper so the function does not grow past its current grade (`radon` baseline recorded in Validation plan).
- Mismatch types are new strings (`new_target_dir_missing`, `new_target_exists`); `StaleResult` takes arbitrary type strings, so no schema change is needed.

## Risks
- **Risk**: `(new)` is used to bypass the existence gate for a file that should exist → **Mitigation**: a declared-new target that already exists is reported `new_target_exists`, and a missing directory is reported, so the marker cannot hide a changed premise; symbols and "Before:" blocks are still checked.
- **Risk**: A procedure that already carries `(new)` on an existing target (38 archived ones) now aborts if re-run → **Mitigation**: archived procedures are not re-run by the workflow; the behavior is recorded in Problem and in the tool description.
- **Risk**: Skipping unscoped line citations lets a stale citation through for a declared-new target → **Mitigation**: a new file has no lines to be stale against; scoped citations to other files are still verified, and a test covers both.
- **Risk**: Authors forget the marker and the cycle still aborts with `source_missing` → **Mitigation**: no regression (behavior unchanged for them); the template note and the workflow text state the convention, and generated procedures pick it up through the template. A generator change is deliberately left out (`UNK-02`).
- **Risk**: A change to `from_procedure` alters verdicts for existing targets → **Mitigation**: the new branch runs only when the marker is present; the line-check flag defaults off; the 73 existing tests and the before/after verdict comparison guard it.
