## Background
The generic checks of the docs consistency checker, now registered for the `db` domain, report `docs/41_db/db_05_api_and_operations-protocol-and-backend.md:22` for referencing `_insert_chunk()`, which is not defined under `scripts/`. The document says the `chunk_insert` field set "intentionally matches `RagIngester._insert_chunk()` in `scripts/rag/ingestion/ingester.py`". The docstring of `DocumentStore.chunk_insert` in `scripts/db/store_protocols.py:130-131` carries the same note and cites `rag/ingester.py`, which does not exist.

## Problem
The documented consistency anchor between the protocol's field set and ingestion points to a removed method and, in the docstring, a nonexistent module path. Current source: the chunk INSERT now lives in `TransactionManager._insert_chunks_batch()` in `scripts/rag/ingestion/transaction_commit.py:86-115`; `scripts/rag/ingestion/ingester.py` exists but does not define `_insert_chunk`.

Adversarial verification result (Issue's open question answered): the field sets still match. `SQLiteDocumentStore.chunk_insert` (`scripts/db/store_impl.py:156-160`) and the ingestion INSERT (`scripts/rag/ingestion/transaction_commit.py:97-99`) both write exactly the six `chunks` columns `doc_id`, `chunk_index`, `content`, `normalized_content`, `chunk_type`, `source_file` (the `index` parameter maps to `chunk_index`; only column order differs). Two non-field differences exist and must not be described as part of the field-set match: ingestion stores `normalized_content or None` (an empty string becomes NULL) while `chunk_insert` passes `normalized` through unchanged, and ingestion also inserts the `chunks_vec` embedding row in the same loop while `chunk_insert` inserts only the `chunks` row. No `scripts/` module outside `scripts/db/store_*.py` calls `chunk_insert`; only `tests/db/test_db_store_impl.py` does.

## Reason for Change
The note tells callers to verify consistency with the ingester; a dangling reference makes that instruction impossible to follow and leaves a claim in the design document that cites a removed symbol.

## Implementation Intent
Restate the relationship at responsibility level without naming a private method: the `chunk_insert` field set matches the chunk INSERT performed by RAG ingestion's transaction commit step, and callers must keep the two in sync when adding or modifying chunk fields. Use the same wording (adapted to docstring style) in both places. Because the match is verified, no Known Issue or Needs Confirmation entry is added.
