# Plan: Split conflated Agent-layer / shell-mcp-server-layer allowlist warning descriptions (shell-mcp)

## Goal

Update two documentation files so that shell-mcp's two independent allowlist settings
(`command_allowlist`, `shell_cwd_allowed_dirs`) are each documented with the correct
layer attribution — which process (agent-layer `audit_security_defaults()` vs. shell-mcp
server-layer `build_service()`) emits which exact warning message — following the
two-layer documentation pattern already established for cicd-mcp's `workflow_allowlist`
in `docs/04_mcp_05_01_access-control-and-allowlists.md` (lines 220-226). This closes the
gap where an operator watching only the agent-layer log stream would see no signal at all
for an empty `shell_cwd_allowed_dirs`, and would not know that `command_allowlist`
emptiness is independently logged (with different wording) by both layers.

## Design

This is a pure documentation edit; no architecture/import-layering concerns apply (no
Python module boundaries are crossed). The design work is confirming the claims are
accurate, verbatim-quotable from source, and matching the established two-layer
documentation convention.

Verified source facts (read directly, all `(Explicit in code)`):

1. **Agent layer** — `scripts/agent/repl_health.py::audit_security_defaults()`, lines
   543-551:
   ```python
   if not shell_cfg.command_allowlist and not lockdown:
       fail_closed_empty.append("shell.command_allowlist")
       msg = (
           "DENY-ALL detected: shell.command_allowlist is empty. "
           "shell-mcp will reject ALL shell commands. "
           "Verify this is intentional or add allowed commands to shell_mcp_server.toml."
       )
       logger.warning(msg)
       warnings.append(msg)
   ```
   This reads `shell_cfg` (a `ShellAuditConfig`), which per
   `scripts/agent/security_audit_config.py` lines 14-18 is a frozen dataclass with exactly
   two fields: `sandbox_backend: str` and `command_allowlist: list[str]` — no field exists
   for `shell_cwd_allowed_dirs`, so the agent layer is structurally incapable of checking it
   (confirmed, matches requirement's claim exactly).

2. **shell-mcp server layer** — `scripts/mcp_servers/shell/shell_service.py::build_service()`,
   lines 332-341:
   ```python
   def build_service(policy: ShellPolicy) -> ShellService:
       """Construct a ShellService from a ShellPolicy object."""
       if not policy.cwd_allowed_dirs:
           logger.warning(
               "shell_cwd_allowed_dirs is empty — all cwd values will be rejected",
           )
       if not policy.allowed_commands:
           logger.warning(
               "command_allowlist is empty — all commands will be rejected",
           )
       return ShellService(policy)
   ```
   Confirms both independent warnings, exact message text, in the same function,
   unconditionally (no lockdown gate at this layer) — matches requirement's claim exactly.

3. **Existing cicd-mcp two-layer pattern to mirror** —
   `docs/04_mcp_05_01_access-control-and-allowlists.md` lines 220-226 documents:
   > これらの警告は、エージェント層と cicd-mcp サーバ層における独立した別レイヤーの仕組みに
   > よって発生します。
   followed by two bullet points, one per layer, each naming the exact source file/function,
   the logger, and the exact message string. The new shell-mcp doc edits will follow this
   same bullet structure and phrasing convention.

4. **Current doc gaps confirmed** —
   `docs/04_mcp_05_03_fail-open-fail-closed-and-risk-tiers.md`'s audit table (read in full,
   lines ~35-42) has a `command_allowlist` row reading only "空の場合（fail-closed）DENY-ALL
   警告" with no per-layer breakdown and no `shell_cwd_allowed_dirs` row at all — confirmed.
   `docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md` (read lines 150-220) quotes only the
   agent-layer `DENY-ALL detected: shell.command_allowlist is empty...` message text in its
   "起動時の audit" and "ランタイムでの deny-all 状態の確認" sections, with no mention of the
   shell-mcp server-layer warnings — confirmed.

No layering/import-boundary considerations apply since no code changes. The only
"boundary" concern is documentation-internal: keep the per-layer breakdown in
`04_mcp_05_03`'s table (the canonical fail-open/fail-closed reference doc) and have
`04_mcp_05_05` cross-reference it rather than duplicating the full explanation, consistent
with how `04_mcp_05_05` already cross-references `04_mcp_05_03` for the general
fail-open/fail-closed policy ("Fail-open/fail-closed基本方針は
