# Plan: Fix Qwen3 embedding dimension contract as a 1024-dimensional code constant

## Metadata

- **Generated at:** 20260802-102150
- **Source requirement:** requires/20260802-070234_require.md
- **Task type:** Refactoring (config values → code constant)
- **Priority:** High

## Architecture Analysis

### Current architecture

Two independent paths supply embedding dimensions:

1. **DB layer path:** `config/agent.toml` → `build_db_config()` → `DbConfig.embedding_dims` → `get_embedding_dims()` → schema creation & ingester
2. **Agent memory path:** `config/agent.toml` → `config_builders.py` → `MemoryConfig.memory_embed_dim` → `factory.py` → `MemoryStore`/`EmbeddingClientConfig`

Both paths default to 384, creating drift risk between them.

### Target architecture

Single constant `QWEN3_EMBEDDING_DIMS = 1024` defined in the DB layer. All consumers reference it via `get_embedding_dims()`. The agent memory path is eliminated — `factory.py` calls `get_embedding_dims()` directly instead of reading from `MemoryConfig`.

## Dependency Graph

```
QWEN3_EMBEDDING_DIMS (constant)
  → get_embedding_dims() [store_protocols.py]
    → create_schema.py (schema creation)
    → schema_sql.py (DDL generation)
    → factory.py (MemoryStore/EmbeddingClientConfig)

DbConfig.embedding_dims [DELETE]
  → build_db_config() [DELETE]
  → _check_embedding_dimensions() [DELETE]
  → store_protocols.py:get_embedding_dims() [REPLACE]

MemoryConfig.memory_embed_dim [DELETE]
  → config_builders.py [DELETE]
  → factory.py [REPLACE with get_embedding_dims()]
```
