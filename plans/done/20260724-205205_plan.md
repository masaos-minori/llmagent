## Goal

Ensure signal-induced shutdown is detected immediately by the event loop without relying on the asyncio.Event mechanism that introduces latency through the event loop scheduling cycle.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run(), _sigterm_handler())
**Out**: Changes to asyncio internals, signal handling in other modules

## Assumptions

1. `loop.add_signal_handler()` is available on Unix-like systems and raises NotImplementedError on Windows
2. Cancelling `input_coro` causes `asyncio.wait()` to return immediately via FIRST_COMPLETED
3. Signal handlers must not perform blocking operations

## Implementation Steps

1. In `_sigterm_handler()`, replace `self._shutdown_event.set()` with `self._input_coro.cancel()` if `self._input_coro` is not None.
2. Store `input_coro` as `self._input_coro` in `_repl_loop` so it's accessible from the signal handler.
3. Set `self._ctx.conv.shutdown_requested = True` as a side effect of cancellation (already done).
4. Update the asyncio.wait() logic in `_repl_loop` to handle the case where `input_coro` was cancelled due to a signal — check `done` set for CancelledError.
5. Keep the existing finally block that cancels pending coroutines; ensure it doesn't double-cancel.
