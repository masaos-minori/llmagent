# Plan: Fix consecutive_bg_failures property to support arbitrary task names

## Goal
Make `BgTaskMonitor.consecutive_bg_failures` property operate on an arbitrary task name instead of always defaulting to the `"unknown_bg_task"` sentinel string.

## Priority
Low

## Scope
- **In-Scope**: Modify `BgTaskMonitor.consecutive_bg_failures` property to accept a task name parameter or replace with method-based access
- **Out-of-Scope**: Adding new failure tracking features, changing the BG_FAILURE_THRESHOLD constant

## Background
The `consecutive_bg_failures` property getter/setter pair (`bg_task_monitor.py:65-72`) hardcodes `"unknown_bg_task"` as the task name, making them useless for monitoring specific tasks. The class already has `get_consecutive_failures(task_name)` and `reset_consecutive_failures(task_name)` methods that properly accept task names, but the property wrapper bypasses them by always passing the sentinel.

## Problem
No mechanism exists to set the task name for this property. Any code that accesses `monitor.consecutive_bg_failures` will always read/write the counter for the sentinel task name, not the caller's intended task.

## Reason for change
This property appears designed to provide convenient access to the default task's failure count, but without a way to specify which task, it cannot serve that purpose reliably.

## Implementation intent
Replace the property with method-based access using `get_consecutive_failures(task_name)` and `reset_consecutive_failures(task_name)`. If backward compatibility requires keeping the property, add a `task_name` parameter to the setter.

## Requirements
- `REQ-001`: `BgTaskMonitor.consecutive_bg_failures` getter must return the failure count for a specified task name, not the hardcoded sentinel
- `REQ-002`: `BgTaskMonitor.consecutive_bg_failures` setter must reset the failure count for a specified task name, not the hardcoded sentinel
- `REQ-003`: Existing callers using `monitor.consecutive_bg_failures` without arguments must continue to work (or receive a deprecation warning)
- `REQ-004`: Code can monitor failure counts for any named task via the property or its replacement methods

## Design
The simplest fix is to remove the property and have callers use the existing `get_consecutive_failures(task_name)` / `reset_consecutive_failures(task_name)` methods directly. However, since the Issue mentions preserving backward compatibility, the alternative approach is to modify the property to accept a `task_name` parameter:

```python
@property
def consecutive_bg_failures(self) -> int:
    """Return the current consecutive failure count for a task."""
    # Backward-compatible: if no task_name provided, default to None
    # Caller must pass task_name explicitly going forward
    raise AttributeError(
        "consecutive_bg_failures now requires a task_name argument. "
        "Use get_consecutive_failures(task_name) or reset_consecutive_failures(task_name)."
    )

@consecutive_bg_failures.setter
def consecutive_bg_failures(self, value: int) -> None:
    """Reset consecutive failure counter for a task."""
    raise AttributeError(
        "consecutive_bg_failures now requires a task_name argument. "
        "Use reset_consecutive_failures(task_name, value)."
    )
```

However, raising `AttributeError` would break any existing callers silently. A better approach: keep the property but make it require a `task_name` keyword argument, with a deprecation warning if called without one:

```python
@property
def consecutive_bg_failures(self) -> int:
    """Return the current consecutive failure count for a task.
    
    Deprecated: Use get_consecutive_failures(task_name) instead.
    """
    import warnings
    warnings.warn(
        "consecutive_bg_failures now requires a task_name argument. "
        "Use get_consecutive_failures(task_name) instead.",
        DeprecationWarning,
        stacklevel=2,
    )
    return self.get_consecutive_failures("unknown_bg_task")

@consecutive_bg_failures.setter
def consecutive_bg_failures(self, value: int) -> None:
    """Reset consecutive failure counter for a task.
    
    Deprecated: Use reset_consecutive_failures(task_name, value) instead.
    """
    import warnings
    warnings.warn(
        "consecutive_bg_failures now requires a task_name argument. "
        "Use reset_consecutive_failures(task_name, value) instead.",
        DeprecationWarning,
        stacklevel=2,
    )
    self.reset_consecutive_failures("unknown_bg_task")
```

But this still doesn't solve the core problem: the property cannot accept a task name. The cleanest solution is to **remove the property entirely** and update the class docstring to note the removal. Since grep confirms zero callers of the property in the current codebase, backward compatibility concern is minimal.
