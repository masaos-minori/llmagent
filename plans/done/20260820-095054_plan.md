# Plan: Make `fetched_at` mandatory end-to-end and remove timestamp compatibility behavior

## Goal

Make the crawler-generated acquisition timestamp (`fetched_at`) a single,
canonical, non-nullable UTC value that is propagated unchanged through every
DTO, TypedDict, and SQL statement in the RAG ingestion pipeline (crawler ->
chunk splitter -> ingester -> document manager -> etag manager -> document
store), and delete every fallback/default/null-fill/fail-open branch that
exists only because the field used to be optional.

## Scope

**In-Scope**
- `scripts/rag/ingestion/crawler.py`: generate `fetched_at` as canonical UTC
  (`YYYY-MM-DDTHH:MM:SSZ`) in both payload-construction sites (`crawl_file()`
  line 129, `_save_crawl_file()` line 335); derive the local-file case from
  `stat.st_mtime` in UTC instead of wall-clock `datetime.now()`.
- `scripts/rag/models_data.py`: add a mandatory `fetched_at: str` field to
  `ChunkDocument` (no default).
- `scripts/rag/ingestion/pipeline_utils.py`: change `ChunkJsonRaw.fetched_at`
  from `NotRequired[str | None]` to a required `str`; make `read_json_file()`
  read and propagate it (raise on missing/invalid, not default).
- `scripts/rag/ingestion/chunk_splitter.py`: add a required `fetched_at: str`
  field to `CrawlFilePayload`, `ChunkOutputPayload`, and `ChunkMetadata`
  (currently absent from all three); thread `ChunkDocument.fetched_at`
  through `_extract_chunk_metadata()` so every chunk file for one crawl
  record carries the identical value.
- `scripts/rag/ingestion/ingester.py`: widen `fetched_at` from `str | None`
  to mandatory `str` in `_get_or_create_document()`, `_insert_document()`,
  `_commit_url_transaction()`; delete the `cursor2` fallback branch in
  `_insert_document()` that omits the `fetched_at` column.
- `scripts/rag/ingestion/document_manager.py`: widen `fetched_at`/
  `new_fetched_at` from `str | None` to mandatory `str` in
  `handle_existing_document()` and `_update_etag()`.
- `scripts/rag/ingestion/etag_manager.py`: widen `new_fetched_at` to
  mandatory `str` in `update()`; delete `_update_null_fill()` and its
  dispatch branch; change `_is_stale_update()` to fail-closed (raise on
  timezone-naive or malformed input, distinct error for a malformed stored
  value); change `_update_with_freshness()`'s SQL from
  `fetched_at = COALESCE(?, fetched_at)` to `fetched_at = ?`; remove the
  early return in `update()` that skips the update solely because
  `etag is None and last_modified is None`; define and test the
  equal-timestamp (`new_dt == stored_dt`) behavior.
- `scripts/db/store_protocols.py` / `scripts/db/store_impl.py`: add
  mandatory `fetched_at: str` to `DocumentStore.doc_upsert()` and
  `SQLiteDocumentStore.doc_upsert()`; use it directly in both the INSERT and
  the `ON CONFLICT ... DO UPDATE SET fetched_at = ?` clause, removing the
  `strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` current-time substitution.
- `scripts/db/schema_sql.py`: remove the `documents.fetched_at DEFAULT
  (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))` clause (keep `NOT NULL`).
- Update all mocks/fixtures/tests listed in Affected areas that construct
  `ChunkDocument`, call `ETagManager.update()`/`DocumentManager._update_etag()`/
  `SQLiteDocumentStore.doc_upsert()`, or assert on the removed
  compatibility branches.

  `plans/20260820-094150_plan.md` (the strict crawl/chunk contract plan)

## Assumptions

- `datetime.now(UTC).strftime("%Y-%m-%dT%H:%M:%SZ")` is an acceptable
  canonical form (falsifiable: `crawler.py` currently imports only
  `from datetime import datetime` — no `UTC` — confirmed by reading the
  import block; the import must be widened to
  `from datetime import UTC, datetime`, mirroring the pattern already used
  in `etag_manager.py`).
- Inserting `fetched_at: str` into `ChunkDocument` immediately after
  `content: str` (before `code_blocks`) satisfies Python dataclass field
  ordering (falsifiable: confirmed by reading `models_data.py:32-46` —
  `ChunkDocument` is `@dataclass(frozen=True)` with `code_blocks` as the
  first field carrying a default (`field(default_factory=list)`); any new
  non-default field must precede it or the class definition raises
  `TypeError: non-default argument follows default argument` at import
  time).
- `SQLiteDocumentStore.doc_upsert()` has zero production callers today
  (falsifiable: confirmed via `rg -n "doc_upsert\(" scripts/ tests/` —
  matches only the `Protocol`/implementation definitions in
  `store_protocols.py`/`store_impl.py` and 12 direct calls in
  `tests/db/test_db_store_impl.py`; the live ingestion path writes documents
  through `Ingester._insert_document()`'s raw SQL instead). Widening its
  signature is still required by the requirement's acceptance criteria and
  is safe because the only callers are the tests in this plan's own
  Affected areas list.
- `CrawlPayload` (in `crawler.py`) already declares `fetched_at: str` as a
  non-`NotRequired` field (confirmed by reading `crawler.py:44-57`), so no
  TypedDict widening is needed there — only the *generation* logic (UTC vs.
  naive local time) changes.
- No on-disk `rag-src/*.json` / `rag-src/chunk/*.json` file from a prior
  crawl needs to remain readable after this change (per the requirement's
  "Reason for change" — no legacy-data compatibility constraint is claimed).

## Design

Single-source, propagate-unchanged, fail-closed:

1. **Generation (crawler.py)**: both `CrawlPayload` construction sites
   compute `fetched_at` once. For live HTTP crawls (`_save_crawl_file()`,
   line 335) use `datetime.now(UTC).strftime("%Y-%m-%dT%H:%M:%SZ")`. For
   local `file://` sources (`crawl_file()`, line 129), replace
   `datetime.now().isoformat(timespec="seconds")` with a UTC-derived form of
   `stat.st_mtime` (the same `stat` object already used for `mtime_iso` at
   line 118), e.g. `datetime.fromtimestamp(stat.st_mtime, UTC).strftime(...)`
   — this makes `fetched_at` and `last_modified` consistent (both mtime-
   derived) for file sources, whereas today `fetched_at` uses wall-clock
   `now()` while `last_modified` uses mtime, a latent inconsistency the
   requirement's item 1 calls out explicitly.
2. **Propagation, unchanged, through every layer**: `ChunkDocument.fetched_at`
   (new mandatory field) is populated in `pipeline_utils.py::read_json_file()`
   directly from the crawl/chunk JSON's `fetched_at` key (raise
   `ChunkFormatError` if the key is missing or not a non-empty string — no
   silent default). `ChunkSplitter._extract_chunk_metadata()` copies
   `data.fetched_at` into `ChunkMetadata`, which `_build_chunk_payload()`
   already spreads (`**metadata`) into every per-chunk output file, so all
   chunks from one crawl record carry the identical value without
   re-derivation.
3. **Ingester and store**: `Ingester` reads `first_data["fetched_at"]`
   (mandatory key, no `.get()` default) and passes it unchanged through
   `_get_or_create_document()` -> `DocumentManager.handle_existing_document()`
   -> `_update_etag()` -> `ETagManager.update()`, and through
   `_commit_url_transaction()` -> `_insert_document()`'s single INSERT
   (the `cursor2` fallback branch is deleted outright, not made
   conditional).
4. **Fail-closed freshness comparison (etag_manager.py)**: `_is_stale_update()`
   raises (does not `return False`) when either the incoming or the stored
   timestamp is malformed, and raises when the incoming timestamp is
   timezone-naive (no silent `replace(tzinfo=UTC)`). A malformed *stored*
   value raises a distinct error (see UNK-02) since the write path now
   guarantees validity, making a malformed stored value a genuine data
   integrity signal rather than a normal input to tolerate.
   `_update_with_freshness()`'s SQL becomes `fetched_at = ?` (no `COALESCE`,
   since the value is now guaranteed non-null). `update()` drops its early
   `if etag is None and last_modified is None: return` (this is the actual
   code location of the "silently dropped" bug described in the
   requirement's Problem section, at lines 34-35) so that a newer
   `fetched_at` alone still triggers `_update_with_freshness()` even when
   both HTTP metadata fields are null. `_update_null_fill()` and its
   dispatch branch are deleted entirely — with `new_fetched_at` mandatory,
   that branch (`new_fetched_at is None`) becomes permanently unreachable,
   so deleting it is a correctness cleanup, not a behavior change to any
   reachable path.
5. **Store layer**: `SQLiteDocumentStore.doc_upsert()` accepts `fetched_at: str`
   and uses it literally in both the INSERT column list and the
   `ON CONFLICT ... DO UPDATE SET fetched_at = ?` clause, replacing the
   `strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` current-time substitution.
   `schema_sql.py` drops the `documents.fetched_at` column's `DEFAULT`
   clause (keeping `NOT NULL`) so a future caller that forgets to supply
   `fetched_at` fails fast at the SQL layer instead of silently getting
   "now."

Layering: all changed files are within `rag` (`crawler.py`,
`pipeline_utils.py`, `models_data.py`, `chunk_splitter.py`,
`ingester.py`, `document_manager.py`, `etag_manager.py`) and `db`
(`store_protocols.py`, `store_impl.py`, `schema_sql.py`). Per
`.importlinter`, `rag` already imports `db` (unchanged direction); no new
cross-package import is introduced, so no `import-linter` contract is at
risk.
