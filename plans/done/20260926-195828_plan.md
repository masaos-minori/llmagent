# Governance Verification Matrix — GV-011 / GV-012 / GV-016 / GV-018 / GV-019 ステータスと Follow-up の矛盾

## Goal

Resolve the status inconsistency between the Governance Verification Matrix and the Follow-up Work Needed section for GV-011, GV-012, GV-016, GV-018, and GV-019 in `governance_04_documentation-checks.md`: the Matrix marks all five as `Missing` but the Follow-up list contains specific implementation tasks for each.

## Priority
Medium

## Scope
- **In-Scope**: Evaluating whether each rule's implementation task should be registered as a Known Issue or if the Matrix Status should be updated; updating either the Matrix Status or the Follow-up Work Needed section to reflect the true state
- **Out-of-Scope**: Modifying the tools' functionality; changing any other rule's status

## Background
- GV-011: "Duplicate canonical document specification" — Matrix shows `Missing`, Follow-up shows `Implement cross-document canonical source conflict detection`
- GV-012: "Multiple Primary Canonical Sources within the same area" — Matrix shows `Missing`, Follow-up shows `Implement cross-document canonical source conflict detection`
- GV-016: "No unimplemented auto-checks documented as implemented" — Matrix shows `Missing`, Follow-up shows `Audit auto-check implementations against documentation claims`
- GV-018: "Glossary limited to project-specific terms" — Matrix shows `Missing`, Follow-up shows `Add glossary term classification validation`
- GV-019: "No unnecessary Metadata or Status fields added" — Matrix shows `Missing`, Follow-up shows `Add metadata field usage policy enforcement`

All five rules are Manual review with Missing status, but the Follow-up Work Needed section lists specific implementation tasks. According to the governance process, Missing status should trigger "Register Known Issue" rather than listing implementation tasks.

## Problem
The Missing status rules have specific implementation tasks listed in the Follow-up Work Needed section, but they have not been formally registered as Known Issues. This creates ambiguity about whether implementers should treat these as Known Issues or as implementation tasks.

## Reason for change
Resolving the status/Follow-up contradiction ensures implementers can accurately determine whether each rule requires implementation work or is already tracked as a Known Issue.

## Implementation intent
Evaluate each rule and reconcile the status/Follow-up mismatch by one of the following approaches:
1. Register the implementation tasks as Known Issues in `governance_03_issue-and-uncertainty-management.md`
2. Update the Matrix Status to reflect the current state (if partially implemented)
3. Remove the entries from the Follow-up Work Needed section (if not needed)

## Requirements
- REQ-001: Evaluate whether each rule's implementation task should be registered as a Known Issue
- REQ-002: If registration is appropriate, register the Known Issue in `governance_03_issue-and-uncertainty-management.md`
- REQ-003: If the Matrix Status should be updated, update it consistently across both sections
- REQ-004: Do not alter the tools' functionality
