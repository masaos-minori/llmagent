## Goal
- Make the `nack_event` docstring in `scripts/eventbus/delivery_repo.py` describe the per-consumer failure model, so the auto-generated reference API row for `nack_event` no longer claims that events-level counters are incremented.

## Priority
Low

## Scope
- **In-Scope**:
  - Rewrite the `nack_event` docstring summary and description (docstring text only).
  - Check the `NackResult` docstring for the same drift and fix only stale wording.
  - Regenerate the auto-generated block of the reference API document.
- **Out-of-Scope**:
  - Any change to executable statements, SQL, return values, NACK, DLQ promotion, or ACK behavior.
  - Removing or repurposing the legacy `delivery_failure_count` and `cycle_failure_count` columns or `NackResult` fields.
  - Other docstring drift in `scripts/eventbus/` not related to `nack_event`.

## Background
- The auto-generated block of the reference API document takes each description from the first docstring line of the function.
- While regenerating that block for `plans/done/20261011-204704_plan.md`, the `nack_event` row was found to read "Increment delivery_failure_count and cycle_failure_count for an event."; it could not be fixed on the documentation side because the block is generated.
- An inline comment in `nack_event` already states that the events-level counters are kept for backward compatibility and are no longer written under the per-consumer model.

## Problem
- The docstring says NACK increments the events-level counters, while the function body only upserts the per-consumer failure count and attempt marker, and reads the events-level counters back for the return value.
- The generated reference row repeats the stale summary, so a reader is told NACK mutates event-level counters, which contradicts the per-consumer model used for DLQ promotion.

## Reason for change
- Documentation/code mismatch caused by a stale docstring, surfaced in a generated reference. Non-critical: behavior is correct.

## Implementation intent
- Describe NACK as recording a per-consumer failure and attempt marker when a consumer is given, leaving the events-level counters unmodified, and returning the stored counters. Keep the statements about DLQ'd events, already-acked consumers, and per-attempt idempotency. Regenerate the block with the generator, not by hand.

## Requirements
- `REQ-001`: The `nack_event` docstring (summary line and description) no longer states that events-level counters are incremented and describes the per-consumer behavior; executable statements are unchanged.
- `REQ-002`: The `NackResult` docstring and field comments are checked for the same drift; only stale wording is corrected.
- `REQ-003`: The reference API generated block is regenerated so the `nack_event` row matches the new summary, and a second generation produces no further diff.
