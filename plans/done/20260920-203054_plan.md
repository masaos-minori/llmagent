## Goal
Complete the refactoring of HttpServerLifecycleManager to fully delegate responsibilities to concern-specific modules, resolving remaining private attribute access violations and constant inconsistencies.

## Priority
Medium

## Scope
- **In-Scope**: Remove remaining private attribute access from ShutdownCoordinator, resolve constant inconsistencies (_TERMINATE_POLL_INTERVAL_SEC vs _DEFAULT_TERMINATE_POLL_INTERVAL_SEC), update module docstrings to reflect final delegation design
- **Out-of-Scope**: Adding new features, changing public APIs, modifying subprocess launch semantics, adding new error types, performance optimization beyond what refactoring naturally achieves

## Background
HttpServerLifecycleManager was previously extracted from lifecycle.py and partially refactored into six concern-specific modules (CommandValidator, StderrLogManager, ProcessTerminator, HealthChecker, ShutdownCoordinator). Commit d98dda9a addressed most concerns: removed pure delegation wrapper methods, resolved circular imports in HealthChecker, added public cleanup methods to avoid private attribute access. However, some gaps remain: ShutdownCoordinator still accesses `manager._http_procs` directly, and there are inconsistent constant defaults across modules.

## Problem
Despite partial refactoring, HttpServerLifecycleManager still has incomplete delegation:
- ShutdownCoordinator accesses `manager._http_procs` directly (line 88 of http_lifecycle_shutdown_coordinator.py), violating responsibility boundaries
- Inconsistent constant defaults: `_TERMINATE_POLL_INTERVAL_SEC` (0.05 in http_lifecycle.py) vs `_DEFAULT_TERMINATE_POLL_INTERVAL_SEC` (0.1 in ProcessTerminator) serve different purposes but create configuration drift risk
- Module docstrings don't reflect the final delegation design

## Reason for change
Incomplete refactoring reduces maintainability and testability. Each concern-specific module should own its domain completely. Private attribute access couples ShutdownCoordinator to HttpServerLifecycleManager's internal state layout. Constant inconsistencies create configuration drift risk when developers assume they align.

## Implementation intent
1. Add a public method to expose process iteration capability to ShutdownCoordinator
2. Resolve constant inconsistency by consolidating terminate poll interval to one source
3. Update module docstrings to reflect final delegation design
4. Verify all existing tests pass after changes

## Requirements
- `REQ-001`: Replace `manager._http_procs` direct access in ShutdownCoordinator with a public method call
- `REQ-002`: Consolidate terminate poll interval constants to eliminate inconsistency between http_lifecycle.py and ProcessTerminator
- `REQ-003`: Update module docstrings to reflect final delegation design

## Design
The refactoring follows the existing delegation pattern established in commit d98dda9a. HttpServerLifecycleManager exposes public methods for operations that other modules need to perform, rather than allowing direct access to internal state. The terminate poll interval constant should be consolidated to a single source to prevent future configuration drift.
