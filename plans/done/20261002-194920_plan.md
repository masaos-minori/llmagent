## Goal

## Design
- Each ADR is processed independently per AI Implementation Instruction in the issue.
- For each ADR, identify and remove:
  1. Duplicate tables (e.g., ADR-002 has two identical "Per-Process Required Files and Keys" tables)
  2. Keywords section with `<placeholder>` value
  3. Status values list (Proposed/Accepted/Rejected/Deprecated/Superseded) — already defined in governance doc
  4. "If not applicable, write 'Not applicable'" boilerplate under Failure Policy, Data Ownership, Verification sections
  5. "Do not record line numbers; reference by File Path and Symbol name." boilerplate under Implementation Notes
  6. "Do not unconditionally align the ADR text with the current implementation; manage discrepancies as Known Issues." boilerplate under Known Deviations
  7. "Do not use 'the current code is implemented this way' as the sole reason for adoption." boilerplate under Rationale
  8. Verbose alternative descriptions where the alternative is not rejected but merely listed for comparison (e.g., ADR-004 Alternative D)
- After each ADR edit, verify size is ≤ 24576 bytes.
- If an ADR remains over the limit after boilerplate/duplication removal, identify further reductions (e.g., trimming verbose rationale text, shortening alternative descriptions).
