## Problem
`scripts/eventbus/offsets.py::write_offset()` enforces `seq > current` (monotonically increasing offsets) per ADR-006 — confirmed correct via code inspection — but no automated test covers this invariant.

## Reason for change
Without test coverage, a future change to `write_offset()` could silently allow a non-monotonic (out-of-order or duplicate) offset write, violating ADR-006, with no automated signal.

## Implementation intent
Add a focused unit test asserting `write_offset()` rejects or otherwise prevents a non-increasing offset write, following existing conventions in `tests/eventbus/`. No production code change is expected.

## Requirements
- `REQ-001`: `write_offset()` must prevent a non-increasing offset write when `seq <= current`
- `REQ-002`: `write_offset()` must log a warning when `seq <= current` and skip the write silently
- `REQ-003`: `write_offset()` must enforce monotonicity for both file-based and SQLite-based offset storage

## Design
The existing `TestFileOffsetMonotonicity` class in `tests/eventbus/test_eventbus_offsets.py` (lines 294-339) covers:
- Verifying `write_offset()` does not lower a consumer's committed offset (via `test_write_offset_prevents_backward_jump`)
- Verifying forward progress works correctly (via `test_write_offset_allows_forward_progress`)
- Verifying equal seq writes are skipped (via `test_write_offset_skips_equal_seq`)
- Verifying first write always succeeds (via `test_first_write_always_succeeds`)

However, these tests verify the invariant holds but don't explicitly assert that `write_offset()` rejects non-increasing writes. The gap analysis focuses on:
1. **Explicit rejection assertion**: Test that even when `seq < current`, the write is rejected (silently skipped with warning logged)
2. **Equal seq handling**: Verify that `seq == current` is also rejected (not just `seq < current`)
3. **Cross-storage verification**: Verify monotonicity holds for both file-based and SQLite-based offset storage
