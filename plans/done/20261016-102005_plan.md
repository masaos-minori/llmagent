## Goal
- Make `ProcessTerminator` terminate admin-started HTTP subprocess MCP servers by signaling the true process group, resolving the real pgid via `os.getpgid(proc.pid)` instead of assuming `proc.pid` is itself a group id.

## Priority
Medium

## Scope
- **In-Scope**:
  - Resolve the authoritative process-group id in `terminate_with_timeout` and `wait_exited` via `os.getpgid(proc.pid)`, guarding a missing pid (returns `None` so the caller keeps its `proc.terminate()` fallback).
  - Add a private module-level `_resolve_pgid` helper in the terminator.
  - Add a regression test with a fake proc whose `pid` differs from its pgid.
  - Keep the already-exited early return in `terminate_with_timeout` working when the pgid cannot be resolved (`REQ-008`).
  - Update the four existing `TestProcessGroupShutdown` tests in `tests/agent/test_lifecycle.py` that patch only `os.killpg` with a fake pid, so they resolve the group through `os.getpgid` explicitly (`REQ-009`).
  - Document the group-leader (`start_new_session=True`) requirement at the pgid-resolution site in the terminator.
- **Out-of-Scope**:
  - Any edit to `scripts/agent/http_lifecycle.py` (launch site) or `scripts/agent/http_lifecycle_shutdown_coordinator.py` (coordinator loop / `_get_pgid`).
  - Changing the SIGTERM→SIGKILL escalation order, any timeout value, or the no-pgid `proc.terminate()` fallback behavior.
  - Passing the stored `self._http_pgids[server_key]` from the manager into the terminator (would change the manager↔terminator runtime interface).
  - Any compatibility shim.

## Background
HTTP subprocess MCP servers are started with `start_new_session=True` (`scripts/agent/http_lifecycle.py::_create_and_validate_proc`), which makes each child a session/group leader, so `proc.pid == os.getpgid(proc.pid)` in practice. The manager records the real pgid in `self._http_pgids[server_key]` immediately after launch. Termination flows through `ProcessTerminator.terminate_with_timeout` (`scripts/agent/http_lifecycle_process_terminator.py`), which recomputes the pgid from `proc.pid` rather than reading the stored value.

## Problem
Verified against the code on 2026-10-16:
- `terminate_with_timeout` line 84: `pgid = getattr(proc, "pid", None)` followed by `os.killpg(pgid, signal.SIGTERM/KILL)`. `os.killpg` requires a process-group id, not a pid.
- The invariant `proc.pid == pgid` holds only for group leaders. `http_lifecycle.py` lines 302-311 build `popen_kwargs` with `"start_new_session": True` then apply `if cfg.fields: popen_kwargs.update(cfg.fields)`, so an admin config can set `fields: {start_new_session: false}`. If set, the child is not a group leader and `os.killpg(proc.pid)` targets an unrelated process group, potentially signaling unrelated processes.
- The authoritative pgid in `self._http_pgids` (computed correctly at line 323) is ignored by the terminator.
- `wait_exited` carries the identical latent bug at line 58.
- Inconsistency: `http_lifecycle_shutdown_coordinator.py::_get_pgid` correctly falls back to `os.getpgid(proc.pid)`, showing the correct approach exists but is not used by the terminator.
- Adversarial verification on 2026-10-16 (step 3a of the next phase) found two consequences the original analysis missed: (1) `tests/agent/test_http_lifecycle_warning.py::test_terminate_warning_when_killpg_fails` passes `Mock(spec=subprocess.Popen)`, whose `pid` is not an int, and relies on the current `not isinstance(pgid, int)` fallback warning; `os.getpgid()` on such a value raises `TypeError`, which `_resolve_pgid` must not let escape. (2) For an exited and reaped process `os.getpgid(proc.pid)` raises `ProcessLookupError`, so the new resolution would skip the current early return (`poll()` is not `None`, info log, return `True`) and instead warn `children may remain` and call `proc.terminate()`.
- Plan gap found while executing the first implementation procedure on 2026-10-16: four tests in `tests/agent/test_lifecycle.py::TestProcessGroupShutdown` (`test_terminate_uses_killpg_sigterm` pid 42, `test_terminate_fallback_on_process_lookup_error` pid 42, `test_terminate_sigkill_on_second_timeout` pid 55, `test_terminate_never_uses_thread_even_when_process_never_exits` pid 77) patch only `os.killpg` and assume the fake pid is the group id. With the fix, the real `os.getpgid(fake pid)` is called; it raises `ProcessLookupError` (or resolves an unrelated real process if the pid exists), so two of them failed in the executed attempt (the change was reverted) and the others depend on the host's process table. These tests are in scope of the fix but were missing from `Implementation Target Files`.
- Impact is currently latent: no production config sets `fields.start_new_session=false` (grep of `config/` found no `start_new_session`/`fields` popen overrides), so the default `start_new_session=True` everywhere and `proc.pid == pgid` in practice.

## Reason for change
The termination path silently assumes an invariant (`proc.pid == pgid`) that is not enforced or documented at the point of use, and that config can break. Correctness of process-group termination should not depend on an undocumented assumption.

## Implementation intent
Add a private module-level `_resolve_pgid(proc) -> int | None` that returns the true group via `os.getpgid(proc.pid)`, returning `None` when the pid is missing, is not an `int`, or `os.getpgid` raises `OSError` (preserving the existing `proc.terminate()` fallback). In `terminate_with_timeout`, when `_resolve_pgid` returns `None`, first check `proc.poll()`: a non-`None` result keeps the current `already exited` info log and `return True`; otherwise take the existing fallback branch. Replace the `getattr(proc, "pid", None)` derivation in both `terminate_with_timeout` (line 84) and `wait_exited` (line 58) with `_resolve_pgid(proc)`, keeping every fallback branch, warning, and the SIGTERM→SIGKILL escalation untouched. Document the group-leader requirement at the resolution site. Add a regression test with a fake proc whose `pid` differs from its pgid. Do not touch the coordinator or the launch site.

- `REQ-006`: Add a unit test asserting `terminate_with_timeout` sends `os.killpg` to the resolved group id when the fake proc's `pid` differs from its pgid, that `wait_exited` uses the resolved group, and that the no-pgid fallback still calls `proc.terminate()`.

## Design
- **Path A classification**: affects ≤ 3 files (2 modification targets), no public/runtime interface change (only a private module-level helper is added; `terminate_with_timeout`/`wait_exited` signatures are unchanged), no DB schema. Skips architecture analysis, dependency graphing, historical analysis, and operational dependency inspection per `skills/issue-to-plan/SKILL.md` Path A.
- **Fix approach**: add module-level `_resolve_pgid(proc) -> int | None` returning `os.getpgid(proc.pid)`, guarding a missing pid and `OSError` (both return `None`, preserving the current fallback). Rationale for resolving via `os.getpgid(proc.pid)` directly instead of a `proc.pgid` attribute shortcut: `Popen` instances do not carry a `.pgid` attribute in practice, and a shortcut would return an unset `MagicMock` child in the existing `MagicMock`-based tests (which set `proc.pid` but never `proc.pgid`), breaking them. `os.getpgid(proc.pid)` yields the true group even for non-group-leader processes, which is exactly the defect being fixed.
- **No circular import**: the terminator currently imports only stdlib; the coordinator imports the terminator, so importing `_get_pgid` from the coordinator would be circular. The local helper avoids this and honors "do not alter the shutdown coordinator loop."
- **Scope**: two files; documentation as a code-level docstring/comment (`A2`).

## Risks
- **Risk**: Changing the pgid derivation could surface an unexpected exception type from `os.getpgid`. → **Mitigation**: `_resolve_pgid` catches only `OSError` (matching `_get_pgid`) and guards a missing pid; any unresolved case returns `None` and falls back to `proc.terminate()`, preserving current safety.
- **Risk**: The value passed to `os.killpg` changes, potentially surfacing a pre-existing wrong-group situation in tests that assumed `proc.pid`. → **Mitigation**: existing tests mock `os.getpgid.return_value` to the same value as `proc.pid`, so behavior is identical for the group-leader case (verified during analysis).
- **Risk**: Documenting in the terminator rather than the launch site may miss readers of `http_lifecycle.py`. → **Mitigation**: the terminator is where group signals are actually sent, so the semantic lives at the point of use; launch-site documentation is flagged as an optional follow-up (`A2`).
- **Risk**: Tests that run with a real `os` and a non-integer or non-existent `pid` (e.g. `tests/agent/test_http_lifecycle_warning.py`) would raise `TypeError` or take a different branch once `os.getpgid` is called. → **Mitigation**: `_resolve_pgid` checks `isinstance(pid, int)` before calling `os.getpgid` and returns `None` for it; the `REQ-008` early return covers exited processes; run `tests/agent/test_http_lifecycle*.py`, `tests/agent/test_lifecycle.py`, and `tests/integration/test_mcp_transport_crash.py` after the change. **Update**: the executed attempt showed that `tests/agent/test_lifecycle.py` is affected too; it is now a target (`REQ-009`).
- **Risk**: Adding a module-level helper could be flagged by `vulture` as dead code if unreferenced. → **Mitigation**: `_resolve_pgid` is referenced by both `terminate_with_timeout` and `wait_exited`; confirmed used. Baseline `vulture` reported 0 findings.
