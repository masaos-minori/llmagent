## Goal
- Remove the opt-in loopback `/health` admission from the shared Bearer-auth middleware and from web-search, so that every route of every MCP server, including `/health`, requires the server's token again, without breaking the agent's startup health poll.

## Priority
Medium

## Scope
- **In-Scope**:
  - Delete the `exempt_health_on_loopback` parameter and its logic from `attach_auth_middleware`, delete `_is_loopback_client` and the now-unused `ipaddress` import, and restore the docstring.
  - Remove the opt-in keyword from the web-search call.
  - Replace the tests whose subject was the admission with tests that `/health` requires the token (including from loopback), keep the coverage of the agent poll against a token-guarded server, and change the real-application test's health expectation.
  - Remove the two documentation sentences that describe the admission.
- **Out-of-Scope**:
  - The token model (settled in mcp005), the other servers' authentication, the server runner's loopback bind check, the agent's health poll and `auth_headers`.
  - Any new unauthenticated health or readiness endpoint.
  - Deploying (a separate step with the deploy skill, and an explicit precondition of this plan's implementation; see `UNK-01`).

## Background
- Plan mcp004 (`plans/done/20261012-175600_plan.md`) added the admission while web-search validated a separate browser token; plan mcp005 (`plans/done/20261012-183348_plan.md`) moved web-search to the shared `auth_token`, the credential the agent's poll sends. Both recorded the redundancy as `UNK-02`.
- Issue `issues/20261012-185047_mcp006_remove-the-loopback-health-admission-from-the-shared-auth-middleware.md` tracks the removal. Its Dependencies state that the removal must follow the deployment of mcp005 and a live check of the web-search startup poll and a tool call.
- Both mcp004 and mcp005 are committed but not deployed to `/opt/llm/`, and no live agent run has confirmed mcp005.

## Problem
Re-verified against current source (`Confirmed by repository evidence`):
- **Redundant and unauthenticated (reproduced)**: with `MCP_WEB_SEARCH_AUTH_TOKEN` set, the real web-search app answers `/health` from a loopback client without a token with 200 and a body with `status`, `ready`, `liveness`, `dependencies`, and `details` (`provider`, `browser_provider`, `metrics`, `browser_metrics`, `service`); with the shared token it also answers 200. The unauthenticated answer comes only from the admission.
- **One caller (explicit in code)**: only `web_search_server.py` passes the keyword; git, rag-pipeline, cicd, and mdq do not.
- **The poll no longer needs it (explicit in code and by test)**: `_health_poll_until_ready` sends `cfg.auth_headers()` (the server's `auth_token`), which is the token web-search now validates; the existing test where the server token equals the main token already shows the poll succeeding through ordinary validation.
- **No other consumer needs an unauthenticated health request (explicit in code)**: `port_is_responding` in `scripts/mcp_launcher.py` treats any response below 500 (a 401 included) as "responding", and the deploy scripts probe only the eventbus and LLM health endpoints, not the MCP servers'.
- **Test and doc footprint (measured)**: `tests/mcp_servers/web_search/test_web_search_health.py` holds the loopback test class (9 test methods, one parametrized), the opt-in AST class, and the real-application expectation `health_from_loopback`; `tests/agent/test_http_lifecycle_health_check.py` holds a helper with the switch parameter and three tests, of which two depend on the switch; two documents mention the admission (one sentence each).
- Consequence: dead security-relevant code in the shared middleware, and an inconsistency (one server exposes health details to any local process without credentials).

## Reason for change
- The admission was a workaround for a credential mismatch that no longer exists; keeping it widens one server's unauthenticated surface for no benefit and adds a path every future middleware change must keep correct.
- Removing it restores one rule for every MCP server.

## Implementation intent
- Remove completely, not disable: no parameter, helper, or opt-in stays. The middleware returns to its behavior from before mcp004.
- Keep what is still valuable as coverage: the agent poll against a token-guarded server (success with the matching token, failure with a different one), the shared-token wiring check, and the real-application test with `/health` now requiring the token.
- Gate the implementation on a live confirmation of mcp005 so the removal cannot bring the startup `401` back on a host with the old configuration.

## Requirements
- `REQ-001`: A request to `/health` without a token, or with a wrong token, is rejected with 401 by the shared middleware, including from a loopback client; the correct token is accepted.
- `REQ-002`: `exempt_health_on_loopback`, `_is_loopback_client`, the `ipaddress` import, and the web-search opt-in no longer exist, and no test or document refers to them.
- `REQ-003`: The agent's startup poll and liveness check still succeed against web-search with the shared token; the poll against a server expecting a different token still fails.
- `REQ-004`: The two documents no longer say the health endpoint is admitted without a token; no other documentation changes.
- `REQ-005`: Implementation starts only after mcp005 is deployed and confirmed against a live agent (web-search startup poll and one tool call succeed).

## Design
- Path B (6 target files; a shared interface parameter is removed). Architecture analysis: the change is a revert inside the shared middleware and its one caller; `lint-imports` covers `scripts/` and runs in validation; the middleware module keeps its other imports. Dependency graph: `attach_auth_middleware` has five callers, four of which never passed the keyword, so only web-search changes behavior (health now authenticated); the agent's poll already sends the matching token. Historical analysis: the keyword and helper are recent (mcp004, one commit), so the revert is small and local. Operational dependencies: the agent supplies the same token on both sides; the launcher's port probe accepts a 401.
- Removal, not disablement: delete the parameter, the closure's exemption expression, the helper, the import, and the docstring paragraph; the closure returns to a single authorization check.
- Test rewrite: the admission class becomes a "health requires the token" class driven by parametrized client addresses (the framework test client accepts an explicit client pair); the helper `_guarded_app` loses its switch parameter; the opt-in AST class becomes a wiring class asserting that no server passes keywords to the middleware, and keeping the shared-token check; the real-application script's `/health` call is made both without and with the token. In the agent poll tests the helper loses the switch, the switch-on test is deleted, the switch-off failing test is replaced by a different-token failing test, and the matching-token test stays.
- Validation quality baseline (`scripts/mcp_servers/server.py`): `radon` finds no function above grade B; bandit and the other checks pass at the current commit.
