## Background
ADR-001 INV-03 は実行成功と検証成功の独立した区別を要求している。`WorkflowEngine.run()`（`scripts/agent/workflow/workflow_engine.py:130-158`）の実装は、verify 失敗時に `except Exception` 節で task status を `failed` に更新するため、execute 成功後の verify 失敗が `completed` と誤って記録されることはないコード構造になっている。

## Problem
`tests/agent/workflow/test_workflow_engine.py` 内の既存テストを確認した結果:
- `test_non_retryable_verify_stage_does_not_retry_on_failure`（line 447-465）は verify 失敗時に `pytest.raises` で例外送出とリトライ回数のみを確認しており、`task.status` の値は一切検証していない。
- `.status ==` を含む全アサーションを grep した結果（line 109, 144, 161, 325, 389, 394）、`"failed"` を期待するアサーションは1件も存在しない。
- 一方、issue の Recommended Action (2)「実行失敗→修正後再実行で成功→completed」は `test_retry_succeeds_on_second_attempt`（line 126-144）で既に `found.status == "completed"` として検証済みであることを確認した。issue はこの既存テストの存在を把握していなかった可能性がある。

## Reason for change
INV-03 の「実行成功≠検証成功」という区別のうち、「実行成功・検証失敗→failed」の側だけが未検証のまま残っている。将来 `WorkflowEngine.run()` の例外処理順序が変更された際、この区別が回帰しても検出できない。

## Implementation intent
既存の `test_non_retryable_verify_stage_does_not_retry_on_failure` を拡張するか、新規テストケースを追加し、execute が正常終了した後に verify が例外を送出した場合、`get_task_by_idempotency_key()` で取得した task の `status` が `"failed"` であることを明示的に assert する。

## Design
