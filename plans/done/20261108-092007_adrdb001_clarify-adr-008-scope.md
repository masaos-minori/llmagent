## Problem
A broad Out of Scope line contradicts the recreate policy the same document states. "Canonical store" mixes the authoritative database file with canonical source tables and derived indexes. "none" in the matrix can be read as "recovery is prohibited" rather than "no automated recovery source". The approval basis of the amendments cannot be traced from the Approval Record.

## Reason for Change
Readers and implementers need to know which migration decisions the ADR governs, and which records approve its current text. It is Medium because it is a documentation inconsistency with no behavior change and no time pressure.

## Implementation Intent
Clarify the existing architecture only. State that the current-only schema policy (startup accepts only the current canonical schema; a refused file is archived and recreated) is in scope, and that migration mechanism design and schema-version mappings are out of scope because no migration mechanism exists. Separate automatic recovery capabilities from manual procedures in the matrix wording without changing its meaning. Describe `rag.sqlite` as the authoritative database file holding canonical `documents` and `chunks` and the derived FTS5 and Vector Index. Map each amendment to the approval evidence that actually exists, and state plainly where none exists. Condense historical text so the file meets its size ceiling.

3. Matrix cells keep their meaning; only "none" is qualified as "no automated ...", and the manual rows stay as they are.
4. The size ceiling is met by condensing the superseded dbmig001 Amendment text and duplicated phrases, not by editing the checker.
