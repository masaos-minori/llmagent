# Plan: HttpServerLifecycleManager reuses passed-in HTTP client for health checks

## Goal
- Eliminate redundant HTTP client creation by removing the inner `httpx.AsyncClient` in `_health_poll_until_ready()` and using the passed-in client from the caller.

## Priority
Low

## Scope
- **In-Scope**: Remove inner `httpx.AsyncClient` creation in `_health_poll_until_ready()`; update docstring to reflect that the client is managed externally
- **Out-of-Scope**: Changes to the health-check polling interval or timeout; changes to the HTTP client configuration

## Background
`HttpServerLifecycleManager._health_poll_until_ready()` in `scripts/agent/http_lifecycle.py` polls the `/health` endpoint of a newly started subprocess MCP server until it becomes healthy.

## Problem
A new `httpx.AsyncClient` is created inside the health-poll loop for each health-poll session. While this is correct for connection management (the client is closed when the context exits), it means connection pooling is lost across health-poll sessions. For servers that need multiple health checks during startup, this creates unnecessary TCP connection overhead. Additionally, the method receives a `client` parameter but ignores it, creating its own client — resulting in two clients per health-poll session.

## Reason for change
Redundant HTTP client creation wastes resources and adds latency. Two clients per health-poll session is clearly a bug — the inner one shadows the outer one.

## Implementation intent
Remove the inner `httpx.AsyncClient` creation and use the passed-in client. Update the docstring to clarify that the client is managed externally. Consider adding a shared client pool in a future iteration if connection reuse across health-poll sessions becomes important.

## Requirements
- `REQ-001`: Only one HTTP client is created per health-poll session
- `REQ-002`: Test verifies no connection leaks on failure paths
- `REQ-003`: Test verifies health check works correctly with reused client
- `REQ-004`: Docstring updated to reflect external client management

## Design
### Current Behavior (Verified Against Source)
1. `http_lifecycle.py` line 466-468: Caller creates `httpx.AsyncClient`
2. Line 469-471: Caller passes client to `_health_poll_until_ready()`
3. Line 393-395: Method creates its OWN `httpx.AsyncClient`, shadowing the passed-in client
4. Result: Two clients per health-poll session — wasteful and incorrect

### Proposed Change
```python
async def _health_poll_until_ready(
    self,
    server_key: str,
    cfg: McpServerConfig,
    proc: subprocess.Popen[bytes],
    client: httpx.AsyncClient,  # Client is managed externally by the caller
    deadline: float,
    shutdown_event: asyncio.Event | None,
) -> None:
    """Poll /health endpoint until the server becomes healthy or timeout expires.

    Polls the health endpoint in a loop, checking for early exit and shutdown
    events between polls. Raises HttpStartupError on early exit, shutdown,
    or timeout.

    Args:
        server_key: Server identifier key.
        cfg: Server configuration.
        proc: Subprocess instance to monitor.
        client: Async HTTP client for health check requests. Managed externally
            by the caller — do NOT close this client within this method.
        deadline: Monotonic time at which to abort polling.
        shutdown_event: Optional event to race against poll sleep.

    Raises:
        HttpStartupError: On early exit, shutdown, or timeout.
    """
    health_url = cfg.url.rstrip("/") + "/health"
    hc_timeout = self._health_checker.compute_health_check_timeout(
        cfg.startup_timeout_sec, MCPSERVER_HEALTH_TIMEOUT
    )
    while time.monotonic() < deadline:
        if proc.poll() is not None:
            stderr_full = self._cleanup_server_resources(server_key)
            logger.error(...)
            raise HttpStartupError(...)
        try:
            response = await client.get(health_url)
            ...
        except Exception as e:
            ...
```

Key changes:
1. Remove `async with httpx.AsyncClient(...) as client:` wrapper
2. Use the passed-in `client` directly
3. Update docstring to clarify that the client is managed externally
