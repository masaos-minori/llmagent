## Goal
- Make `uv run mypy --no-namespace-packages scripts/` give the same clean result on a cold and a warm mypy cache, by removing the cache-dependent `# type: ignore[attr-defined]` comments in the OTel tracer module and fixing the cause in the mypy configuration.

## Priority
Low

## Scope
- **In-Scope**:
  - Add a per-package mypy override for `opentelemetry.*` (`follow_imports = "skip"`) in `pyproject.toml`, so the dynamic re-exports of the OpenTelemetry SDK type as `Any` on every run.
  - Remove the six `# type: ignore[attr-defined]` comments (and their justification text) from `scripts/shared/otel_tracer.py`; fix the module comments that describe them.
  - Verify the result on a cold cache, a warm cache, and `--no-incremental`, and run the tracer tests and the suppression checker.
- **Out-of-Scope**:
  - Other type errors outside this module, OpenTelemetry dependency changes, tracing behavior.
  - `.github/workflows/ci.yml` and `.pre-commit-config.yaml` (they already pass; see Problem).

## Background
Source: `issues/20261008-115808_otelmypy01_remove-unused-type-ignore-comments-in-the-otel-tracer-module.md`, filed after a type-check run reported errors in a file that a different change had not touched. The issue assumed the ignores were unused because the stubs are present or an optional package is absent (unknown). Investigation shows a different cause.

## Problem
- A cold-cache run of `uv run mypy --no-namespace-packages scripts/` passes, and the next (warm-cache) run reports three `unused-ignore` errors at `scripts/shared/otel_tracer.py` lines 82, 150 and 167 (Confirmed by repository evidence — reproduced in this session with mypy 2.1.0: cold run "Success", warm run "Found 3 errors"; the count the issue gives as five differs between runs for the same reason).
- With all six ignores removed, a cold run reports eight `attr-defined` errors, while a warm run reports three different ones (lines 76, 79 and 147) (Confirmed by repository evidence — same experiment). The set of `attr-defined` errors for the OpenTelemetry imports therefore depends on cache state, so no ignore comment can be correct for both runs.
- The pre-commit hook passes because it uses `--no-incremental`, and CI starts from a fresh checkout without a cache; only repeated local runs show the failure (Confirmed by repository evidence — `.pre-commit-config.yaml` mypy hook and `.github/workflows/ci.yml`; `rules/toolchain.md` states the hook adds `--no-incremental`).
- `opentelemetry-api` and `opentelemetry-sdk` 1.37.0 are installed in this environment, so the packages are present (Confirmed by repository evidence — `uv pip list`); the cause is mypy's handling of the SDK's dynamic re-exports (Derived from confirmed evidence, to be re-checked in UNK-01).
- The repository already uses a per-module override for a comparable case (`agent.signal_handler` with `disable_error_code = ["attr-defined"]`) (Explicit in `pyproject.toml`).

## Reason for change
- A clean type check is part of the completion checklist (`rules/toolchain.md`), and a result that flips between runs hides new type errors and wastes time.

## Implementation intent
- Fix the cause, not the symptom: treat `opentelemetry.*` as untyped for mypy so no per-line suppression is needed and the result is the same on every run. Prefer `follow_imports = "skip"` for that package over `disable_error_code = ["attr-defined"]` on the whole module, because the latter would also hide real attribute errors in the tracer's own code.

## Design
Why a mypy override and not per-line ignores: the per-line ignores are right on a cold run and wrong on a warm run (and vice versa for the three names that report only on a warm run), so any fixed set of ignores fails one of the two. Typing the package as `Any` through `follow_imports = "skip"` removes the dependence on how mypy loads the SDK's dynamic re-exports.

Why not a module-wide `disable_error_code`: it would also silence real `attr-defined` errors in the tracer's own code; the package-level override is narrower. The existing `agent.signal_handler` override is the fallback if UNK-01 shows the narrow override is insufficient.

No runtime behavior changes: the imports stay inside `try/except ImportError` in the lazy-import helpers.
