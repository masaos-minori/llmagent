## Goal
- Stop the test suite from reading or writing production state under `/opt/llm`: redirect the configuration and log locations to a temporary root for every test run, add a guard that fails any test that opens a production database or log file, fix the tests that currently write test data into the production session database, and keep production behavior unchanged when the new log override is not set.

## Priority
High

## Scope
- **In-Scope**:
  - `tests/conftest.py`: at import time, build a temporary root with a copy of `config/` whose writable-state paths point into the temporary root, and set `LLMAGENT_CONFIG_DIR`, the Event Bus path variables, and a new log-directory variable; remove the root at session end.
  - `scripts/shared/logger.py`: a log-directory override that applies only when its environment variable is set.
  - A guard (autouse fixture plus a collection-time check) and an opt-out marker, both defined in `tests/conftest.py`, and the new fixture's entry in the conftest integrity manifest in `tools/check_conftest_integrity.py`.
  - A new test module for the isolation, extra tests in `tests/shared/test_logger.py`, and patching the four unpatched tests in `tests/agent/memory/test_memory_layer.py`.
- **Out-of-Scope**:
  - Deleting the existing test rows from the production session database (`memories`, `memories_fts`, 65 `messages` rows) and trimming production logs (separate, approved operation).
  - Changing production logging, configuration, or the binaries' behavior with the override unset; rebuilding binaries.
  - The unreachable LLM servers and unrelated pre-existing test failures.
  - Rewriting the 36 `Logger(__name__, "/opt/llm/logs/...")` call sites.
  - Running the full suite before the isolation exists.

## Background
- Found on 2026-10-19 during a startup-error investigation. This host is both the development checkout and the production install, so the repository `config/agent.toml` (with `/opt/llm/...` paths) is what tests resolve by default.
- The owner permitted production reads for the investigation; all database inspection used a copy.

## Problem
- Production session database (from a copy of `/opt/llm/db/session.sqlite`): all 1172 `memories` rows are test artifacts in three repeated contents (586, 293, 293 rows), four rows per test run since 2026-07-10; the newest four rows match the file's modification time `12:40:27 JST` and a full test run. `messages` holds 65 user rows with content `content` whose writer is not yet identified.
- Cause, confirmed on 2026-10-19 by running `tests/agent/memory` with a throwaway plugin that redirected `db.helper.build_db_config` to a temporary database (the production file was unchanged): four tests in `tests/agent/memory/test_memory_layer.py` each write one `memories` row because they reach the real `write_ops.upsert` through `MemoryIngestionService` without patching `agent.memory.ingestion.write_upsert`: `test_no_entry_when_embed_fails`, `test_increment_on_embed_failure_in_persist_entry_with_dedup`, `test_increment_on_embed_failure_in_persist_entry`, and `test_summary_log_contains_count`. `test_on_session_stop_delegates` was initially suspected as a fifth, but it drives a `MemoryServices` facade whose ingestion is a `MagicMock` and never reaches the real writer, so it needs no change (corrected during procedure generation, 2026-10-19).
- `build_db_config()` resolves `session_db_path` from `config/agent.toml` (`/opt/llm/db/session.sqlite`) through `ConfigLoader`; `resolve_config_dir` honors `LLMAGENT_CONFIG_DIR`, but nothing sets it for tests.
- Logs: about 36 modules under `scripts/` call `Logger(__name__, "/opt/llm/logs/<name>.log")` at import time and `shared/logger.py` opens a `FileHandler` on that literal path with no test-mode branch, so `agent.log`, `ingest.log`, `chunk.log`, `crawl.log`, `search.log`, `mdq-mcp.log`, the file MCP logs, and `web-search-mcp.log` receive test output (in `agent.log`, test bursts account for 3189 of 4067 lines).
- Other callers of `build_db_config()` (`db/recovery.py`, `db/rotation.py`, `db/maintenance.py`) and the Event Bus (`get_config_path()` uses `EVENTBUS_CONFIG_PATH`, defaulting to `/opt/llm/config/eventbus.toml`, not `LLMAGENT_CONFIG_DIR`) also resolve production paths.
- No isolation exists today: the autouse fixtures in `tests/conftest.py` reset the tool registry, web-search metrics, and `ConfigLoader` state only.

## Reason for Change
- Data integrity and operations: every test run silently modifies the production session database and fills production logs, buries real startup errors, may feed test memories into real sessions (unconfirmed), and made a full test run unsafe during an incident.
- The fix is cheap now and the isolation is the prerequisite for cleaning the production data safely.

## Implementation Intent
- Use one mechanism for configuration: `tests/conftest.py` sets `LLMAGENT_CONFIG_DIR` (and the Event Bus path variables) at module import, before any `scripts/` module is imported, pointing to a temporary copy of `config/` in which only writable-state paths are rewritten.
- Rewrite only writable state: the prefixes `/opt/llm/db`, `/opt/llm/storage`, `/opt/llm/offsets`, `/opt/llm/deadletter`, `/opt/llm/rag-src`, `/opt/llm/logs`, and `/opt/llm/memory`. Leave read-only resources untouched (`/opt/llm/bin`, `/opt/llm/sqlite-vec` for `sqlite_vec_so`, `/opt/llm/docs`, `/opt/llm/venv`), because tests load the real extension and validate command paths.
- Use one mechanism for logs: a new `LLMAGENT_LOG_DIR` variable read by `shared/logger.py`; when set, a requested path under `/opt/llm/logs/` is rewritten into that directory (parents created); when unset, behavior is identical to today. `tests/conftest.py` sets it at import time because `Logger` instances are created during collection.
- Add a guard for what the redirect cannot guarantee: an autouse fixture wraps `sqlite3.connect` and `logging.FileHandler.__init__` and raises when a path resolves under `/opt/llm/` (unless the test carries the opt-out marker), and a collection-finish check fails if any logger handler already points under `/opt/llm/`.
- Patch the four unpatched tests so their correctness does not depend on the global redirect, and register the new fixture in the conftest integrity manifest.
- Validate without touching production: targeted tests only until the isolation is in place, then one full-suite run bracketed by before/after snapshots of `/opt/llm/db/*.sqlite` and `/opt/llm/logs/*`.

## Design
- Path B (more than 3 files; changes a shared runtime module; affects every test). Analyses: architecture (`lint-imports`: 6 contracts kept, 0 broken; the change adds no import across layers), dependency graphing (`shared.logger` consumers: 39 files under `scripts/`; `build_db_config` callers: `db/helper.py`, `db/recovery.py`, `db/rotation.py`, `db/maintenance.py`, and two lazy command modules; `/opt/llm` prefixes in `config/*.toml`: `bin`, `db`, `storage`, `sqlite-vec`, `rag-src`, `logs`, `docs`, `venv`, `offsets`, `memory`, `deadletter`), historical (churn above; single author), operational (production state was read through copies; the plan prescribes no production write).
- Why `LLMAGENT_CONFIG_DIR`: it already exists in `resolve_config_dir`, so a single conftest-level setting redirects every default `ConfigLoader()` load without touching call sites. It must be set at import time: `Logger` instances and several MCP server modules read configuration while `scripts/` modules are imported during collection (`tests/conftest.py` already sets authentication variables at import for the same reason).
- Why a log-directory variable in `shared/logger.py` rather than editing 36 call sites: one small, inert-when-unset change in the single place that opens the file.
- Why a guard in addition: the redirect is configuration-driven, so literal paths and unanticipated callers would still reach production; failing loudly on `sqlite3.connect` and `FileHandler` under `/opt/llm/` turns silent pollution into a visible test failure. The opt-out marker lets a test that must use a real path say so explicitly instead of weakening the guard.
- Temporary root: created with `tempfile.mkdtemp` at import, removed by an `atexit` handler and `pytest_sessionfinish`; directories for rewritten paths are created so `DbConfig` validation (parent directory must exist) passes.
- Failure behavior: the guard raises `AssertionError` naming the path and the test; no silent fallback.

## Risks
- **Risk**: Setting `LLMAGENT_CONFIG_DIR` globally breaks tests that read real values from `config/*.toml` through `ConfigLoader`. → **Mitigation**: Rewrite only writable-state prefixes; run the affected files first (UNK-03); fix with a local patch or the opt-out marker and list each.
- **Risk**: The guard produces false failures for tests that legitimately use a `/opt/llm` string without opening the file. → **Mitigation**: The guard checks only the resolved path passed to `sqlite3.connect` and `FileHandler`; the opt-out marker handles the rest.
- **Risk**: The import-time temporary root leaks or is not removed when a run is interrupted. → **Mitigation**: `atexit` plus `pytest_sessionfinish`; the root is under the system temporary directory and holds only copies.
- **Risk**: Rewriting `/opt/llm/sqlite-vec` would break tests that load the real extension. → **Mitigation**: The rewrite uses an allowlist of writable-state prefixes; `sqlite_vec_so` is asserted unchanged by AC-001.
- **Risk**: The log override changes production behavior by accident. → **Mitigation**: It activates only when `LLMAGENT_LOG_DIR` is set, a test covers the unset case, and the variable is set only by the test configuration.
- **Risk**: The acceptance full-suite run still pollutes production if the isolation is incomplete. → **Mitigation**: Run the targeted suites first, take the before snapshot, and stop and report if any difference appears; cleaning production remains a separate approved action.
