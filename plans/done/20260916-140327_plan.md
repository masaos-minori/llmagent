## Goal
- Complete `HttpServerLifecycleManager`'s already-declared six-module delegation architecture in `scripts/agent/http_lifecycle.py`: consolidate the two non-equivalent shutdown implementations into one, resolve a dataclass name collision, delegate health-check logic, split a two-concern cleanup method, and remove confirmed-dead code — all while preserving the documented public API (`start()`, `restart()`, `verify_running()`, `verify_running_async()`, `list_processes()`, `get_process_info()`, `get_process_snapshot()`, `shutdown_all()`).

## Priority
Medium

## Scope
- **In-Scope**:
  - Porting `HttpServerLifecycleManager.shutdown_all()`'s resource-cleanup steps into `ShutdownCoordinator.shutdown_all()` and fixing its dead `terminator`-parameter override, before switching `HttpServerLifecycleManager.shutdown_all()` to delegate.
  - Moving `_absorb_sigint_during_shutdown`'s use to `ShutdownCoordinator` only.
  - Renaming `http_lifecycle_process_snapshot.ProcessInfoSnapshot` to `RawProcessSnapshot` to resolve its name collision with `agent.services.models.ProcessInfoSnapshot`.
  - Delegating `verify_running_async()` to `HealthChecker.verify_running_async()`, passing `url=cfg.url.rstrip("/") + "/health"` explicitly and using `HealthChecker`'s recheck-interval constant instead of a second hardcoded `10.0` literal.
  - Splitting `_cleanup_server_resources()` into two single-concern methods.
  - Deleting `ProcessTerminator.terminate()` (confirmed zero callers).
  - Adding an optional, keyword-only `fields` parameter to `ProcessSnapshotProvider.from_proc_pid()`/`get_info()`.
  - Adding unit tests for each of the above.
- **Out-of-Scope**:
  - Adding new lifecycle operations (e.g. zero-downtime restart).
  - Changing `StartupFailure`/`HttpStartupError` DTO shape or `McpServerConfig` schema.
  - Making the health-recheck interval configurable via `McpServerConfig`.
  - Deciding whether `ProcessSnapshotProvider` should gain a real caller or be deleted as dead code (filed as a follow-up decision, not a mechanical refactor step — see Unknowns UNK-02).
  - Removing `# noqa`/`# nosec` suppressions (Problem #7's 3 sites at lines 23, 25, 291) unless clearly unjustified after the refactor.

## Background
`http_lifecycle.py` was extracted from `lifecycle.py` and partially decomposed into six concern-specific sub-modules (`CommandValidator`, `StderrLogManager`, `ProcessTerminator`, `HealthChecker`, `ProcessSnapshotProvider`, `ShutdownCoordinator`) — confirmed by the module docstring (lines 1-16). `HttpServerLifecycleManager` still retains parallel, non-delegated implementations for shutdown, health-check, and snapshot construction.

## Problem
Confirmed by direct comparison of `scripts/agent/http_lifecycle.py` (532 lines) against its six sub-modules:
1. `HttpServerLifecycleManager.shutdown_all()` (L483-532) and `ShutdownCoordinator.shutdown_all()` (`http_lifecycle_shutdown_coordinator.py` L50-95) are not behaviorally equivalent: only the manager's version clears `_http_pgids`, closes/clears `_stderr_files`, and clears `_stderr_log_paths`/`_last_health_check`. `ShutdownCoordinator.shutdown_all()` additionally has a confirmed dead-parameter bug: `terminator = terminator or manager._process_terminator` (L76) is unconditionally overwritten two lines later by `terminator = manager._process_terminator` (L85). `ShutdownCoordinator.shutdown_all()` itself has zero callers anywhere in `scripts/`/`tests/` today (confirmed by `rg` — only the constructor call at `http_lifecycle.py:90` exists; the method is never invoked), so this bug is currently latent, not live.
2. `_build_snapshot()` (L188) constructs `agent.services.models.ProcessInfoSnapshot` (7 fields, confirmed by reading its `dataclass(...)` call). `http_lifecycle_process_snapshot.ProcessInfoSnapshot` (L20-45) is a same-named but incompatible dataclass with 23 `/proc`-derived fields. `http_lifecycle.py` imports only the first by name (L35) — no import-time shadowing occurs today, but the two same-named dataclasses in sibling modules are a real collision risk for any future import combining both. `ProcessSnapshotProvider`'s `get_info()`/`get_snapshot()`/`list_processes()` (L486-543) have no external callers — confirmed: the only two `.get_info(` hits are internal self-calls within the same file (L521, L541), and `self._snapshot_provider` (constructed at `http_lifecycle.py:89`) is never read again.
3. `verify_running_async()` (L157-176) performs HTTP polling inline via `httpx.AsyncClient`, duplicating `HealthChecker.verify_running_async()` (`http_lifecycle_health_checker.py` L37-69).
4. `_cleanup_server_resources()` (L178-186) mixes stderr-tail reading with health-check-timestamp/tracking-data clearing.
5. `ProcessTerminator.terminate()` (`http_lifecycle_process_terminator.py` L36-92) has zero callers anywhere in `scripts/`/`tests/` (confirmed by `rg` — all `.terminate(` matches are either `subprocess.Popen.terminate()` or the unrelated `terminate_method()` local variable inside `terminate_with_timeout()`); only `terminate_with_timeout()` (L125-217) is ever invoked.
6. `ProcessSnapshotProvider` reads all 23 `/proc`-derived fields per snapshot regardless of caller need, compounded by finding #2 (no live caller exists to need any of them today).
7. Three suppression comments exist at `http_lifecycle.py` lines 23 (`# noqa: F401`), 25 (`# nosec B404`), 291 (`# nosec B603` / `# noqa: S603`) — confirmed by direct read.
8. `ProcessSnapshotProvider.list_processes()` (`http_lifecycle_process_snapshot.py` L527-543) reimplements `HttpServerLifecycleManager.list_processes()` (`http_lifecycle.py` L218-224)'s role but has no callers either — compounds finding #2/#6 rather than being an actively-used duplication.

## Reason for change
- **Corrected during this Plan's adversarial verification**: the Issue's "Reason for Change" claims `HttpServerLifecycleManager.start()` has cyclomatic complexity ">15" — `radon cc scripts/agent/http_lifecycle.py -s` measures `start()` at grade A, complexity 4. This claim does not hold against current source (it reads as a copy-paste artifact from the sibling `config_reload.py` refactor Issue — the cited "validator try/catch blocks, outcome classification" phrasing describes that file's `apply_config_dict()`, not anything in `http_lifecycle.py`). The file's actual highest-complexity method is `shutdown_all()` at grade C, complexity 12 — still a legitimate, if smaller, complexity concern motivating the shutdown consolidation (Requirement REQ-001/REQ-003).
- Two independent, non-equivalent shutdown implementations (Problem #1) are a live maintenance risk once `ShutdownCoordinator.shutdown_all()` gains a real caller.
- The declared six-module architecture (docstring L8-16) is incomplete: 3 of 6 modules (`ShutdownCoordinator`, `HealthChecker`, `ProcessSnapshotProvider`) are constructed but not actually delegated to for their primary purpose.
- No unit tests exist today for `http_lifecycle_shutdown_coordinator.py` or `http_lifecycle_health_checker.py` (confirmed: no `tests/agent/test_http_lifecycle_shutdown_coordinator.py` or `test_http_lifecycle_health_checker.py` exists; `tests/agent/test_resource_shutdown_coordinator.py` tests an unrelated class, `agent.resource_shutdown_coordinator.ResourceShutdownCoordinator`).
- `ProcessTerminator.terminate()`'s dead status (Problem #5) is confirmed dead code, not a design smell requiring reconciliation with `terminate_with_timeout()`.

## Implementation intent
Port `ShutdownCoordinator.shutdown_all()` to full behavioral equivalence with today's `HttpServerLifecycleManager.shutdown_all()` (including its dead-parameter fix) before switching the manager to delegate — verified against the existing `tests/agent/test_http_lifecycle_integration.py` suite, which asserts on `manager`'s internal state (`_http_pgids`, `_stderr_files`, `_stderr_log_paths`, `_last_health_check`) after `shutdown_all()` runs. Resolve the `ProcessInfoSnapshot` name collision by renaming only the un-consumed dataclass (`http_lifecycle_process_snapshot.ProcessInfoSnapshot` → `RawProcessSnapshot`); do not attempt to unify `_build_snapshot()` with `ProcessSnapshotProvider.get_info()` since their return types are genuinely incompatible. Delegate `verify_running_async()`'s HTTP request to `HealthChecker` while keeping the rate-limiting wrapper (and its state, `self._last_health_check`) in `HttpServerLifecycleManager`, since that state is per-manager, not something a stateless `HealthChecker` static method should own.

## Design
`HttpServerLifecycleManager` keeps its six injected sub-module instances (`__init__`, L72-95) and becomes progressively thinner: `shutdown_all()` becomes a one-line delegation to `self._shutdown_coordinator.shutdown_all(self)` once `ShutdownCoordinator` is proven behavior-equivalent; `verify_running_async()` keeps its own rate-limit gate (`self._last_health_check`) but delegates the actual HTTP call. The `ProcessInfoSnapshot` rename is the only change touching `http_lifecycle_process_snapshot.py`'s public surface besides the additive `fields` parameter — `_build_snapshot()` and `agent.services.models.ProcessInfoSnapshot` are explicitly left alone since their 7-field shape is a different, real, actively-used contract (`get_process_info()`, `get_process_snapshot()`, `list_processes()` all return it). `ProcessTerminator.terminate()`'s deletion has no design implication for `terminate_with_timeout()` since the two never shared a live call graph.
