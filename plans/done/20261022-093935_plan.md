# Plan

## Goal
Remove both EventBus schema migration paths (the bootstrap list applied by `create_eventbus_schema()` and the startup `_migrate()` in `scripts/eventbus/schema.py`) so that `scripts/eventbus/schema.sql` remains the only schema definition and an `eventbus.sqlite` older than the supported baseline is recreated, not migrated.

## Priority
Medium

## Scope
- **In-Scope**:
  - Delete `_EVENTBUS_MIGRATIONS` and `apply_eventbus_migrations()` from `scripts/db/schema_sql.py` and simplify `create_eventbus_schema()` to run the DDL only.
  - Delete `_migrate()` from `scripts/eventbus/schema.py`, simplify `_init_schema()`, and remove the imports that become unused.
  - Make `tools/check_db_separation.py` read only the base DDL for `eventbus.sqlite`.
  - Remove or rewrite the tests that exercise the migrations or compare the two paths, keeping base-DDL, fresh-database, and pragma tests.
  - Update the docs and the Canonical Source Registry entry that describe the EventBus migration, and drop the open decision about two paths.
- **Out-of-Scope**:
  - The workflow migrations, the MDQ legacy rebuild, and the legacy offset import (separate issues).
  - Changing `schema.sql`, adding an EventBus schema-version marker, or changing how a fresh database is created.
  - A fail-fast column check for an out-of-baseline EventBus database (UNK-01).

## Background
The database design document (Supported Upgrade Baseline) states that the minimum supported source schema of `eventbus.sqlite` is the current release schema defined by `scripts/eventbus/schema.sql`; the single host `/opt/llm` recreated its `eventbus.sqlite` from the current DDL on 2026-10-21. Verified against current source: two paths exist. `apply_eventbus_migrations()` runs `_EVENTBUS_MIGRATIONS` before the DDL in `create_eventbus_schema()`. `_migrate()` runs inside `_init_schema()` when the `events` table already exists and otherwise `_init_schema()` runs `schema.sql`. `open_db()` in `scripts/eventbus/db_conn.py` is the only caller of `_init_schema()`. Every statement in `schema.sql` uses `IF NOT EXISTS`.

## Problem
Both paths alter a database in place on bootstrap and on every service start, and keep a conversion for `consumer_delivery.acked_at` and a drop of `events.retry_count` for databases no supported installation holds. Their equivalence needs its own test and the design document lists "are two paths intentional" as an open decision. Adversarial verification of the Issue found further coupling the Issue does not list:
- The Canonical Source Registry (`config/documentation_canonical_sources.toml`) registers the decision target `eventbus.persistence-schema.incremental-migration`, and `docs/41_db/db_02_architecture_and_schema-schema-reference.md` cites it; both describe the mechanism being removed.
- `_migrate()` is not purely legacy conversion: it also adds missing indexes and tables to an existing database (covered by `test_existing_database_without_consumer_delivery_index_is_migrated`). Removing it means an existing database is not repaired; this is the behavior the baseline permits, but it must be a recorded decision (UNK-01).
- `tests/eventbus/test_eventbus_db_migration.py` also holds the only pragma test (`TestApplyEventbusPragmas`), which must survive.
- The Issue's acceptance pattern `_migrate\b` also matches the workflow-test helper `_migrate(db_file)` in `tests/db/test_create_schema.py` and a reference in the `schema-repair` definition of ADR-008; both belong to the workflow removal plan (`plans/20261022-093726_plan.md`) and ADR-008 is shared by both plans.

## Reason for Change
Migration code on the startup path of the EventBus service can alter a database in place; keeping it for databases that do not exist is risk and test cost without benefit. Deleting both paths together also removes the duplication and the related open decision, and keeps `schema.sql` the single DDL source required by the four-database separation ADR.

## Implementation Intent
Delete both paths together so they cannot diverge. `_init_schema()` keeps creating the schema from `schema.sql` when the `events` table is absent and does nothing when it exists (decided here, as the Issue directs, and recorded in the docs as current behavior); a supported database already has the current schema. `create_eventbus_schema()` runs only the DDL under the existing DDL error label. The registry entry for the removed decision target is deleted with the docs that cite it. Documentation states only intent and constraints (a database older than the baseline is recreated) and leaves no history of the removal.

## Design
- Path B (more than three files; EventBus startup schema path).
- Evidence: `open_db()` is the only caller of `_init_schema()`; `schema.sql` is fully idempotent; `_migrate()` additionally repairs missing indexes/tables, which the no-repair decision (UNK-01) deliberately drops; `_COL_*` constants stay in `scripts/eventbus/_constants.py` because other modules use them, only the imports in `schema.py` go.
- `create_eventbus_schema()` keeps one DDL execution with its error label; the "migrations before DDL" ordering rationale disappears with the migrations.
- The pragma test is preserved in place to avoid renaming an existing file; its module docstring is corrected.
- Shared files with the workflow removal plan (`scripts/db/schema_sql.py`, `scripts/db/create_schema.py`, `tools/check_db_separation.py`, `tests/db/test_create_schema.py`, `db_03`, `db_02`, ADR-008) are edited sequentially.
