## 1. Goal
- Establish a consistent type-coercion strictness policy across all `*_models.py` config loaders in `scripts/mcp_servers/`.
- Adopt the stricter approach (explicit `isinstance` checks via `_get_typed` helper) as the codebase standard.
- Backport `_get_typed`-style validation to the currently-loose loaders (`write_models.py`, `read_models.py`, `web_search_models.py`).

## 2. Scope
### In-Scope
- Audit all `*_models.py` config loaders' current type-coercion behavior
- Decide and document the target strictness policy
- Apply `_get_typed`-style validation to `write_models.py`, `read_models.py`, `web_search_models.py`
- Add characterization tests for accepted and newly-rejected value shapes per file
- Verify every existing `config/*.toml` file still loads successfully

### Out-of-Scope
- Changes to Pydantic request/response models (only config-loading boundary)
- Changes to `shared/config_loader.py` or `shared/config_utils.py` (unless needed for the shared helper)
- Changes to MCP server business logic

## 3. Assumptions
- The stricter approach (explicit `isinstance` checks) is preferable because it catches malformed config early with clear error messages rather than silently accepting wrong types.
- Existing valid TOML configs will continue to pass after the change (no legitimate use of float values where int is expected, etc.).
- The `_get_typed` helper in `git_models.py` can be extracted to a shared utility or duplicated per-file depending on whether other MCP servers already reference it.
