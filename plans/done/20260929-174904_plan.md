## Background
The Issue (`int002`) was filed from a 2026-09-28 full-suite validation re-check that found this test failing with "DID NOT RAISE" and a captured "No chunk files to process" log line.

This Plan's own Step 3 verification found the test currently reports a **false pass** when run as part of the full file or after `test_ingester_processes_chunk_files`: that sibling test (lines 54-89) writes a chunk file to `/tmp/crawl-test-chunks/chunk/dummy-001.json` and never removes it, and since `test_ingester_handles_embedding_failure` (lines 92-113) uses the exact same hardcoded `rag_src_dir` (`/tmp/crawl-test-chunks`), a leftover file from an earlier run or an earlier test in the same session lets this test's `ingest_all()` call skip the "no chunk files" guard by accident — not because the test itself sets up the precondition. Confirmed by direct reproduction: removing the leftover file (`rm /tmp/crawl-test-chunks/chunk/dummy-001.json`) and re-running `test_ingester_handles_embedding_failure` in isolation reproduces the Issue's exact failure (`Failed: DID NOT RAISE <class 'Exception'>`, with the "No chunk files to process" log line) — confirming the Issue's diagnosis is accurate and the bug is real, not stale, despite the test appearing to pass when run in combination with its polluting sibling.

`RagIngester.ingest_all()` (`scripts/rag/ingestion/ingester.py:141-153`) confirmed to glob `self._chunk_dir` (`rag_src_dir/chunk`, line 104) for `*.json` files and return `None` immediately if none are found (lines 151-153), before ever constructing `SQLiteHelper` or calling `_process_url_groups` (line 166) — so mocking `SQLiteHelper` (as the test currently does) has no bearing on whether this guard is passed; only the presence of an actual `*.json` file under `_chunk_dir` does.

## Problem
`test_ingester_handles_embedding_failure`'s own `mock_cfg` points `rag_src_dir` at `/tmp/crawl-test-chunks`, but the test itself never creates a chunk file there — unlike the established sibling pattern in `test_ingester_processes_chunk_files` (same file, lines 64-70), which explicitly creates `/tmp/crawl-test-chunks/chunk/dummy-001.json` before calling `ingest_all()`. Without its own chunk file, `test_ingester_handles_embedding_failure`'s pass/fail outcome depends on whether a leftover file from a previously-run sibling test happens to still exist in the same shared, non-isolated `/tmp` path — a test-order-dependent false pass, not a genuine assertion of the embedding-failure-propagation behavior its docstring claims to verify.

## Reason for change
As written, this test provides no real regression protection for `ingest_all()`'s embedding-failure propagation path: it silently depends on filesystem state left behind by an unrelated sibling test rather than establishing its own precondition. A genuine regression in that path would not reliably be caught (the test's pass/fail would depend on execution order/history, not on the code under test).

## Implementation intent
Add the same chunk-file-creation step `test_ingester_processes_chunk_files` already uses (create `/tmp/crawl-test-chunks/chunk/dummy-001.json` with a minimal valid JSON payload) to the start of `test_ingester_handles_embedding_failure`, before the existing `_process_url_groups`/`SQLiteHelper` mocking and `pytest.raises` block, so the test establishes its own precondition instead of relying on incidental leftover state. No change to `ingest_all()`'s short-circuit logic itself, and no change to the existing mocks or assertion.
