also extends an existing tool's public dispatch surface). Architecture analysis: `lint-imports`/
import-graph tooling is `N/A: tools/generate_reference_table.py is a standalone script
under tools/, not scripts/, and out of `.importlinter`'s layer-contract scope` — its
only structural change is adding dictionary entries with the same shape as three

dependency surface is the `DOMAIN_*` dictionaries themselves (see Affected areas) and
`scripts/agent/memory/`'s public symbols (the generation input) — both directly
inspected in Step 3. Operational dependency inspection is `N/A: no running service or
process lock is affected by extending a documentation-generation CLI tool`. Historical
analysis (churn) is recorded above; the target tool has low churn (2 commits) and a
single author, presenting no unusual review risk.

The central design decision this Plan makes is resolving `UNK-01` (see Problem): the
Agent-domain precedent (`agent_13` + `agent_14`) shows that when Reference-class
migration meets a domain whose reference material is genuinely spread across multiple
files, or where an existing hand-curated document already fully occupies the "intent"
role, the correct move is a **new, additive** generated companion file — never editing
the existing hand-curated document to insert generated content, and never treating an
already-template-compliant intent document as raw Reference-class material to replace.
This Plan applies that same logic to Memory: all 6 existing chapter files stay
untouched; one new companion file is added.
