# Plan: Fix agent-docs-consistency.yml and mcp-docs-consistency.yml to invoke the consolidated check_docs_consistency.py script

## Goal

Update the `run:` step (and, where stale, the `paths:` trigger) of
`.github/workflows/agent-docs-consistency.yml` and
`.github/workflows/mcp-docs-consistency.yml` so each invokes
`python tools/check_docs_consistency.py --domain <agent|mcp>` instead of the deleted
per-domain scripts `tools/check_agent_docs_consistency.py` /
`tools/check_mcp_docs_consistency.py`, restoring real CI drift protection for the agent and
MCP doc domains.

## Design

1. **Run-step fix (both files).** Replace the single `python tools/check_<domain>_docs_consistency.py` line inside each workflow's `run: |` block with `python tools/check_docs_consistency.py --domain <domain>`, keeping the surrounding `set -euo pipefail` line and step name (`Run Agent docs consistency checks` / `Run MCP docs consistency checks`) unchanged — this is a pure invocation-target swap, matching the same one-line substitution style used in the referenced (not-yet-implemented) design for the overview/deployment/rag workflows in `plans/20260819-174858_plan.md`.
2. **Stale `paths:` fix (both files, both `push` and `pull_request` blocks).** Replace the literal string `tools/check_agent_docs_consistency.py` with `tools/check_docs_consistency.py` in `agent-docs-consistency.yml`, and `tools/check_mcp_docs_consistency.py` with `tools/check_docs_consistency.py` in `mcp-docs-consistency.yml`. This keeps the trigger consistent with the new invocation target (a change to the now-shared `check_docs_consistency.py` script should still re-trigger both workflows), per requirement instruction 3's explicit condition ("verify against the current file content and update only if they still reference the deleted script paths") — confirmed both files meet that condition.
3. **No other line changes.** `on:` trigger types (`push`/`pull_request`), the other `paths:` entries (`docs/05_agent_*.md`, `docs/90_shared_04_*.md` for agent; `docs/**/*.md` for mcp), `concurrency:` block, job name, `runs-on:`, `actions/checkout@v4`, and `actions/setup-python@v5` with `python-version: "3.13"` are left byte-for-byte identical.
4. **Do not touch `pyproject.toml`.** The stale `check-mcp-docs`/`check-agent-docs` console-script entries are a related but out-of-scope defect (not one of the requirement's two target files); flagged as a follow-up risk instead of fixed here, mirroring how `plans/20260819-174858_plan.md` flagged these two workflows as out-of-scope follow-ups for its own narrower scope.
