## Goal
- Move the 9 general-shared (non-DB) documentation files from the flat `docs/` root
  into a new `docs/40_shared/` subfolder using `git mv` only (no rename, no content
  change beyond what a prior, already-landed Requirement covers), and fix every
  relative-path (containing `/`) reference — including a test-fixture hardcoded path
  discovered during verification of the source Issue's own explicit dependency
  concern — broken by that move, so the general-shared area's docs are grouped
  exactly as the broader `docs/` reorganization plan intends.

## Background
Same `docs/` reorganization effort as `docsreorg05`-`08`
(`plans/done/20260924-115855_plan.md`, `plans/done/20260924-130409_plan.md`,
`plans/done/20260924-133825_plan.md`, `plans/done/20260924-143444_plan.md`); this Plan
covers `docsreorg09`, the physical move for the `40_shared` area — the general-purpose
subset (document-guide, overview, types/protocols, runtime/execution) of the current
`shared_*` files. The DB-architecture and DB-API subsets (`shared_04_*`,
`shared_05_*`) move separately into `docs/41_db/` per `docsreorg10` — confirmed via
Read of that issue file, not this Plan's concern. Prerequisite issues `docsreorg01`
(folder-independent cross-reference resolution) and `docsreorg02` (subfolder-aware
domain checkers) have already landed.

`docsreorg05`-`08` (this same session) each discovered that `docsreorg01`'s
basename-index resolution in `tools/check_docs_structure.py` covers only bare-filename
references, not existing relative-path (containing `/`) references, which break when
either endpoint of the reference changes its directory depth; `docsreorg07`
additionally discovered that an anchor-suffixed link (`.md#section`) requires an
anchor-tolerant search pattern. This Plan applies both lessons from the start.

The source Issue explicitly asks this Plan to verify a specific dependency:
"`docsreorg02`'s `_docs_consistency_lib.py`/`check_docs_consistency.py` fix must
already point the 'shared' domain's `discover_md_files` call at the correct new
subfolder before this move... verify that dependency does not implicitly also expect
the general-shared files to remain in the old flat location." Investigation (Design)
found `tools/check_docs_consistency.py` has no "shared" domain at all (only `agent`,
`mcp`, `rag`, `deployment`, `overview` — confirmed via Read of `DOMAIN_PREFIXES`), and
the only `shared_*`-related code (`check_schema_drift()`) never references the 9
general-shared files this Plan moves — it references only `shared_04_*`, with its
own pre-existing, unrelated destination-path bug (see Out-of-Scope). The Issue's
specific concern is therefore answered: no impact on this Plan's own move. That same
investigation separately surfaced the `_KNOWN_DEFECT_PATH` gap in
`tests/tools/test_check_docs_quality.py`, which is in this Plan's scope (REQ-002).
