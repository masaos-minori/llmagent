## Goal
Fix 2 unrelated test-fixture gaps in `tests/agent/test_tool_runner.py`: (1) the shared `_make_ctx()` helper never initializes `ctx.turn.pending_approval_id`, so it defaults to a truthy `MagicMock` child attribute, causing `RepositoryGateway._gate_write()` to always deny writes as "approval pending" regardless of the interactive-approval outcome; (2) a DAG-scope-grouping test's `github_push_files` call supplies empty args, tripping an unrelated `check_allowed_repo` preflight check that requires `owner`/`repo` args.

## Priority
Medium

  - Add valid `owner`/`repo` args (e.g. `{"owner": "org", "repo": "repo"}`, matching `cfg`'s `approval_github_allowed_repos=["org/repo"]`) to `test_two_scope_groups_all_execute`'s `github_pc` tool call.
- **Out-of-Scope**: `scripts/agent/repository_gateway.py::_gate_write`'s pending-approval-deny check and `scripts/agent/tool_policy.py::check_allowed_repo` — both confirmed correct and intentional.

## Background
`RepositoryGateway._gate_write()` (`scripts/agent/repository_gateway.py:89-104`) denies any write operation when `ctx.turn.pending_approval_id is not None`, with its own docstring clarifying "This method does not prompt" — the interactive prompt happens earlier, in `agent.tool_approval.run_approval_checks()`. `tests/agent/test_tool_runner.py::_make_ctx()` builds `ctx = MagicMock()` and sets several fields explicitly (`ctx.turn.current_turn_id`, `ctx.stats.*`, etc.) but never sets `ctx.turn.pending_approval_id` — so accessing it for the first time auto-vivifies a new child `MagicMock` (truthy, not `None`), making `_gate_write`'s pending-approval check always deny, independent of whether the interactive approval prompt (mocked via `_prompt_user_approval`) returned `True`. Separately, `check_allowed_repo()` (`scripts/agent/tool_policy.py:305-320`) requires `args["owner"]`/`args["repo"]` for any `_GITHUB_MUTATION_TOOLS` call (including `github_push_files`) and denies with `PolicyViolationError` if either is missing — `test_two_scope_groups_all_execute`'s `github_pc` call uses empty `args={}`, tripping this check even though the test's actual focus is DAG resource-scope-group execution ordering, not repo-allowlist enforcement.

## Problem
- `test_run_approval_checks_invoked_exactly_once_through_gateway`: `executor.execute.assert_awaited_once_with("write_file", {})` fails (`Awaited 0 times`) — confirmed via captured log `gateway.write_denied tool='write_file' reason=pending_approval id=<MagicMock name='mock.turn.pending_approval_id' ...>`, i.e. `ctx.turn.pending_approval_id` was a truthy Mock, not `None`, at gate-check time.
- `test_two_scope_groups_all_execute`: `PolicyViolationError: github_push_files: repo not in approval_github_allowed_repos` — confirmed via traceback that `check_allowed_repo` received `args={}` (no `owner`/`repo`) against `cfg.approval.approval_github_allowed_repos=["org/repo"]`.

## Reason for change
Both are confirmed test-fixture gaps, not production defects: `_gate_write`'s pending-approval semantics and `check_allowed_repo`'s owner/repo requirement are both already correct and intentional. Fixing them restores 2 tests' actual coverage (an end-to-end single-approval-prompt regression test, and a DAG scope-group execution-ordering test).

## Implementation intent
For the first: set `ctx.turn.pending_approval_id = None` explicitly in `_make_ctx()`, after checking whether any other test in the file relies on the current (accidental) truthy-Mock default — if so, scope the fix to only the affected test(s) instead of the shared helper. For the second: add valid `owner`/`repo` args to the `github_pc` fixture call in `test_two_scope_groups_all_execute`, matching the test's own `cfg = _cfg(approval_github_allowed_repos=["org/repo"])`.
