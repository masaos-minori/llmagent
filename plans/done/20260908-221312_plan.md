# Plan: Unknown-top-level-key validation breaks legacy flat-key test configs across 2 test files

## Goal
Fix the regression introduced by commit `9a7cdb40e` ("REQ-004: Add `_check_unknown_production_keys()` method to ProductionConfigValidator") that rejects any top-level config key not present in its derived allowed-keys set. Confirmed via revalidation to still cause 35 failures across 2 test files (`tests/agent/test_tool_policy_comprehensive.py`, `tests/agent/test_agent_negative_paths.py` — the other 3 originally-suspected files no longer reproduce this cause, see Background's Revalidation note). Direction 1 (remove the 12 obsolete legacy flat keys from these test helpers) is the confirmed correct fix — see Implementation intent.

## Priority
High

## Scope
- **In-Scope**: Remove the 12 obsolete legacy flat config keys from the 2 confirmed-affected test helpers (`tests/agent/test_tool_policy_comprehensive.py`, `tests/agent/test_agent_negative_paths.py`); re-run the full suite and confirm no failure remains attributable to the "Unknown config keys" check specifically
- **Out-of-Scope**: Any other validation rule already present in `ProductionConfigValidator` before commit `9a7cdb40e`; any change to REQ-004's own new tests (`TestProductionConfigValidatorUnknownTopLevelKeys`) beyond what's needed to keep them passing; any unrelated refactor of `config_builders.py` or the affected test files; `tests/agent/test_tool_policy_comprehensive.py`'s separate, pre-existing gap (its `_cfg()` helper also omits `tool_definitions_strict`, `routing_drift_strict`, and a non-empty `allowed_tools` — see Unknowns UNK-03) — a distinct root cause, not part of this Plan; `tests/integration/test_rag_llm_integration.py`, `tests/agent/services/test_runtime_tool_routing_integration.py`, and `tests/agent/test_repl.py` — confirmed via revalidation to contain none of the 12 legacy flat keys and to fail for unrelated reasons; removed from `Implementation Target Files` (see Background's Revalidation note)

## Background
`_get_valid_production_keys()` derives its allowed-keys set via `dataclasses.fields()` introspection over the current nested sub-config dataclasses (`LLMConfig`, `RAGConfig`, `ToolConfig`, `MemoryConfig`, `MCPConfig`, `ApprovalConfig`, `ObservabilityConfig`, `DiagnosticsConfig`, `MessageRoleConfig`) plus a short explicit list of `AgentConfig`-level and `build_agent_config()`-direct keys. Several existing test helpers still call `build_agent_config()` with old flat top-level keys (e.g. `tool_cache_ttl`, `top_k_search`, `top_k_rerank`, `rag_top_k`, `use_mqe`, `use_search`, `use_rrf`, `use_rerank`, `rag_min_score`, `max_chunks_per_doc`, `use_two_stage_fetch`, `two_stage_max_docs`) that are not in the new derived set, and the new validation now rejects them with `SystemExit(1)`.

**Revalidation note (2026-09-09)**: re-running `uv run pytest` against each of the 5 originally-listed files found that only `tests/agent/test_tool_policy_comprehensive.py` (29 failed) and `tests/agent/test_agent_negative_paths.py` (6 failed) still reproduce this regression's exact `SystemExit(1)` / `Unknown config keys` traceback. The other 3 files (`tests/integration/test_rag_llm_integration.py`, `tests/agent/services/test_runtime_tool_routing_integration.py`, `tests/agent/test_repl.py`) contain zero occurrences of any of the 12 legacy flat keys (confirmed via `rg` against the exact key list) and their current failures are unrelated, independent defects (see the corresponding acceptance-criteria/scope updates below) — removed from `Implementation Target Files` accordingly.

None of the 12 legacy flat keys has a current nested equivalent (resolves UNK-01): `use_two_stage_fetch`/`two_stage_max_docs` were removed from `AgentConfig`'s schema entirely on 2026-07-13, per `config/agent.toml`'s own maintainer note confirming neither key appears anywhere in `scripts/` any longer; the remaining RAG keys (`top_k_search`, `top_k_rerank`, `rag_top_k`, `use_mqe`, `use_search`, `use_rrf`, `use_rerank`, `rag_min_score`, `max_chunks_per_doc`) now belong exclusively to the separate RAG pipeline MCP server's own configuration (`scripts/rag/*`, `scripts/mcp_servers/rag_pipeline/*`, `config/rag_pipeline_mcp_server.toml`), not `AgentConfig`; `tool_cache_ttl` has zero consumers anywhere in `scripts/` (the `ToolCache` class it would map to is never instantiated). The correct fix is therefore to remove these obsolete keys from the affected test fixtures, not to rename them to a nested form.

## Problem
`_cfg()` in `tests/agent/test_tool_policy_comprehensive.py` (and equivalent helpers in the other affected files) constructs a config dict with these legacy flat keys and passes it to `build_agent_config()`. `build_agent_config()` calls `ProductionConfigValidator.validate()`, which now calls `_check_unknown_production_keys()` and exits the process with `SystemExit(1)` and a "Production config validation failed: ... Unknown config keys: ..." error, instead of constructing the config.

Reproduction (both confirmed by direct execution, not by the raw test-suite `278 failed` line alone — see Evidence):
```
uv run pytest tests/agent/test_tool_policy_comprehensive.py -q
# → 29 failed, 9 passed in 1.35s
uv run pytest tests/agent/test_agent_negative_paths.py -q
# → 6 failed, 8 passed in 0.55s
```

These 35 failures span exactly:
- `tests/agent/test_tool_policy_comprehensive.py`
- `tests/agent/test_agent_negative_paths.py`

The originally-suspected `tests/integration/test_rag_llm_integration.py`,
`tests/agent/services/test_runtime_tool_routing_integration.py`, and
`tests/agent/test_repl.py` do not reproduce this cause on revalidation — see
Background's Revalidation note.

## Reason for change
This is a real, reproducible regression against `origin/master` — not a flaky or environment-specific failure (confirmed by a single-test run completing in under 1 second with the identical `SystemExit(1)` traceback). Left unfixed, it makes the entire test suite an unreliable signal for every unrelated change (a genuinely broken change and this pre-existing regression are currently indistinguishable in a full `pytest` run), and blocks anyone relying on `uv run pytest tests/` passing cleanly before merging further work.

## Implementation intent
Direction 1 (update the test helpers) is confirmed correct (see Unknowns UNK-01): `build_agent_config()` passes its config dict directly into `ProductionConfigValidator().validate()` with no flat-to-nested key normalization, and none of the 12 legacy flat keys has a current nested equivalent — they correspond to settings already removed from `AgentConfig`'s schema entirely (RAG two-stage-fetch, removed 2026-07-13), migrated to a separate RAG pipeline MCP server's own configuration (the remaining RAG keys), or simply unconsumed (`tool_cache_ttl`). Extending `_get_valid_production_keys()`/`_check_unknown_production_keys()` (the alternative direction) would not be correct: these keys are not read by any current `AgentConfig`-building code path, so accepting them would silently mask dead configuration rather than fix a genuine input-shape mismatch. The fix is to remove these 12 obsolete keys from `test_tool_policy_comprehensive.py`'s and `test_agent_negative_paths.py`'s `_cfg()`/`defaults` dicts.

## Requirements
- `REQ-001`: Determine `build_agent_config()`'s current intended input shape for the keys listed in Problem (flat vs. nested) — **RESOLVED**: nested-only, no flat-key acceptance; see Unknowns UNK-01
- `REQ-002`: Remove the 12 obsolete legacy flat keys (Direction 1, confirmed correct) from both confirmed-affected test helpers' config dicts, consistently
- `REQ-003`: Re-run the full suite and confirm the failure count drops to zero for this cause
