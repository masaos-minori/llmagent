## Reason for change
Items 1 and 2 as currently written create the same synchronization risk this
session's whole review targets: item 2 duplicates INV-05/INV-09 with no
mechanism keeping the two copies aligned; item 1 documents a real data-integrity
constraint with no Invariant to violate/flag if a future refactor breaks it. Item
3's relationship to `EVENTBUS-007` needs to be made explicit (enhance, don't
duplicate) so the ADR does not end up with two overlapping descriptions of the
same legacy-migration mechanism.

## Implementation intent
Delete item 2 outright except for a short SQL-mechanism pointer (per Constraint).
Add item 1 as a new Invariant (ADR-006 local INV-16) with a Verification entry
citing the existing test that already exercises this atomicity
(`tests/eventbus/test_eventbus_crash_ack.py::test_offset_write_failure_after_delivery_state`
— confirmed during this Plan's evidence-gathering; per the source issue's own
Testing Expectations, no new test is needed since coverage already exists), then
condense the Notes prose into a short pointer citing the new Invariant ID. Enhance
`EVENTBUS-007`'s existing description with the `migrate_legacy_offsets()`
mechanism detail from item 3, then replace item 3's Notes prose with a pointer to
`EVENTBUS-007`. Add the new Invariant to `docs/adr-index.md`'s Invariant
Verification Matrix, following the ADR-014 INV-023/024/025 precedent format.
