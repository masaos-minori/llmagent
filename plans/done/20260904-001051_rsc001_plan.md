# Plan: Add deterministic ordering to ResourceShutdownCoordinator.close_resources task cancellation

## Goal
- Replace non-deterministic asyncio.all_tasks() iteration with ordered cancellation strategy to ensure consistent shutdown behavior

## Priority
Medium

## Scope
- **In-Scope**: Implement deterministic cancellation ordering; ensure WAL checkpoint completes before history write is cancelled; document the cancellation ordering rationale
- **Out-of-Scope**: Adding new locking primitives; changing the overall shutdown architecture

## Background
ResourceShutdownCoordinator coordinates cleanup during REPL shutdown. It collects pending tasks and cancels them before gathering results.

## Problem
Non-deterministic task cancellation order means shutdown behavior differs between runs when multiple async operations are active concurrently.

## Reason for change
Operational risk: during shutdown, inconsistent state from arbitrary cancellation order can cause data loss (e.g., WAL checkpoint interrupted mid-operation while history write proceeds).

## Implementation intent
Implement a deterministic cancellation strategy. Options include: topological sort of task dependencies, priority-based ordering (WAL before history), or sequential cancellation with explicit dependency awareness. Focus on ensuring critical operations complete before dependent ones are cancelled.

## Requirements
- `REQ-RSC001-1`: Shutdown behavior is deterministic across multiple runs with same concurrent operations
- `REQ-RSC001-2`: WAL checkpoint completes before history write is cancelled
- `REQ-RSC001-3`: No data loss during forced shutdown scenarios

## Design
1. Identify task types by coroutine name (asyncio.Task.get_name()) or custom attribute
2. Separate pending tasks into priority tiers:
   - Tier 1 (high priority): WAL checkpoint tasks (must complete before tier 2)
   - Tier 2 (medium priority): History write tasks
   - Tier 3 (low priority): All other tasks
3. Cancel tiers sequentially: cancel tier 3 first, then tier 2, then tier 1
4. Preserve existing gather semantics (return_exceptions=True)
5. Document the ordering rationale in the class docstring
