# Plan

## Goal
Record the `md` input form of `/session export` as a permanent short alias in the registry usage, the help text, and the command document, and extend removed-command coverage to the one deleted command (`/db`) and the other removed commands that are locked only at registry level.

## Priority
Low

## Scope
- **In-Scope**:
  - Show `md` in the `/session export` usage (registry argument spec, help line, error usage, docstring) and in the command document.
  - Add a regression test that `md` selects the Markdown export.
  - Add dispatch, completion, and help rejection tests for the commands that `tests/agent/commands/test_removed_commands.py` currently checks at registry level only.
- **Out-of-Scope**:
  - Export content, supported formats, a deprecation warning (the alias is permanent), general CLI redesign.
  - Tests for `/diff`, `/system`, `/audit`, `/workflow` (already complete, see Background).

## Background
Adversarial verification against the repository found the issue's premises partly outdated:
- `tests/agent/commands/test_agent_cmd_context.py` (section "removed command rejection") already covers `/diff`, `/system`, `/audit`, and `/workflow` with five parametrized tests: absent from `_COMMANDS`, dispatch returns False like an unknown command, no state change, absent from completion names, absent from `/help`. Running `uv run pytest tests/agent/commands/test_removed_commands.py -q` passes 9 tests, so no new tests are needed for those four.
- `tests/agent/commands/test_removed_commands.py` checks only registry membership, for `/db` (four identical tests), the note, skill, mdq, approve, and reject commands. `/db` and those commands have no dispatch, completion, or help check.
- `scripts/agent/commands/cmd_session.py` `_session_export` accepts `markdown` and `md` (both select the internal `md`) and `json`. The registry argument spec (`ArgSpec("markdown|json", default="markdown")` in `scripts/agent/commands/command_defs_list.py`), the help line, the validation-error usage, and the docstring list only `markdown|json`. The command document states in prose that `md` is accepted as an alias, but its usage form does not show it. No test calls the export with `md`.
- The command contract check (`GV-023`, `check_docs_consistency.py --domain agent`) compares registry usages with documented forms in both directions, so the registry spec and the document must change together.
- Owner decision (recorded): `md` is a permanent short form, to be documented.

## Problem
The permanent alias is not visible in the usage that the registry renders and the document shows, and nothing tests it; the removed `/db` command and five others are not shown to be rejected by dispatch, completion, and help.

## Reason for Change
The command contract stays unambiguous and a removed command cannot silently return through a path the registry-only assertion does not reach.

## Implementation Intent
Change the argument spec token to `markdown|md|json` (default unchanged) and the three text copies; update the document usage form in the same change so the contract check passes. Parametrize the removed-command tests over the names, reusing the dispatch, completion, and help patterns already used for the four covered names.

## Requirements
- `REQ-001`: The `/session export` usage in the registry spec, help line, validation-error text, and docstring lists `markdown|md|json`.
- `REQ-002`: The command document's usage form and prose state `md` as a permanent short form of `markdown`, and `check_docs_consistency.py --domain agent` passes.
- `REQ-003`: A test shows `/session export md` selects the Markdown format.
- `REQ-004`: Each of `/db`, the note, skill, mdq, approve, and reject commands is tested absent from the registry, rejected by dispatch like an unknown command, and absent from completion names and `/help` output.
