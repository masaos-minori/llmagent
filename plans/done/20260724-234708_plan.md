## Goal

Make Windows signal handler integration-safe by scheduling the signal callback through the asyncio event loop instead of calling it directly from the OS signal handler thread.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL.run())
**Out**: Changes to signal handling, other async resource access patterns

## Assumptions

1. Only `_sigterm_handler()` needs to be made integration-safe — it's the only handler registered in the fallback path
2. `loop.call_soon_threadsafe()` is available on all supported Python versions (3.7+)
3. No other code paths need similar treatment in this scope

## Unknowns

| Unknown | Evidence missing | Resolution | Blocking |
|---|---|---|---|
| Whether _sigterm_handler accesses any asyncio primitives beyond Event.set() | Need to review _sigterm_handler body | Already reviewed — only sets Event and logs | no |

Analysis: `_sigterm_handler()` only does three things: sets `self._ctx.conv.shutdown_requested`, calls `self._shutdown_event.set()`, and logs. Both `Event.set()` and logging are thread-safe. The real issue is that calling `_sigterm_handler()` directly from the OS signal handler thread means the handler runs asynchronously relative to the event loop cycle. Using `call_soon_threadsafe()` ensures the handler executes on the event loop's next iteration, preventing any potential race with async operations.

## Design

Replace the direct `_signal.signal(sig, lambda *_: _sigterm_handler())` call with one that schedules the handler via `loop.call_soon_threadsafe(_sigterm_handler)`. This ensures the handler runs on the event loop's next iteration rather than interrupting async operations mid-execution.

### Procedure

#### Step A: Modify signal handler registration in run()

Current code (lines 498-504):

```python
import signal as _signal

for sig in (signal.SIGTERM, signal.SIGINT):
    try:
        loop.add_signal_handler(sig, _sigterm_handler)
    except NotImplementedError:
        _signal.signal(sig, lambda *_: _sigterm_handler())
```

Change to:

```python
import signal as _signal

for sig in (signal.SIGTERM, signal.SIGINT):
    try:
        loop.add_signal_handler(sig, _sigterm_handler)
    except NotImplementedError:
        # On Windows, register a process-wide handler that schedules the
        # callback on the event loop via call_soon_threadsafe(). This prevents
        # the handler from interrupting async operations mid-execution.
        _signal.signal(sig, lambda *_: loop.call_soon_threadsafe(_sigterm_handler))
```

Key points:
- Changed the lambda to use `loop.call_soon_threadsafe(_sigterm_handler)` instead of calling `_sigterm_handler()` directly
- Added comment explaining why this approach is used on Windows
- Same behavior as before — shutdown is still triggered on SIGTERM/SIGINT
- Thread-safe because `call_soon_threadsafe()` is designed for cross-thread event loop interaction
