## Background
`tests/eventbus/test_eventbus_auth.py::_make_test_app` builds its own standalone `local_app` FastAPI instance with hand-written route wrappers (to test auth middleware/dependencies in isolation from the real `scripts/eventbus/app.py`). Its `/dlq` (`dlq_list`) and `/replay` (`replay`) wrappers call `eb_app.dlq_list_route(...)`/`eb_app.replay_route(...)` with an extra `_principal=_principal` keyword — but the real `dlq_list()`/`replay()` functions (`scripts/eventbus/dlq_route.py`, `scripts/eventbus/replay_route.py`) accept no such parameter (confirmed: the real `scripts/eventbus/app.py` wrapper for these routes never passes it either). Separately, 3 tests call `require_consumer_identity` directly with a bare `unittest.mock.MagicMock()` standing in for `request`, expecting an `HTTPException` from the topic/consumer-identity rejection path; but that path first calls `log_auth_failure(..., request_id=request.state.request_id, route=request.url.path, ...)`, which passes those (Mock-typed, since `request` is a bare `MagicMock`) values into `scripts/eventbus/audit.py`'s `orjson.dumps(record, ...)` — `orjson` raises `TypeError: Type is not JSON serializable: MagicMock` before the intended `HTTPException` is ever raised.

## Problem
Confirmed via a direct `TestClient(raise_server_exceptions=True)` reproduction and live `--tb=long` runs:
- `TestDlqListAuth::test_dlq_list_with_valid_operator_token`, `TestReplayAuth::test_replay_with_valid_operator_token`: `TypeError: dlq_list() got an unexpected keyword argument '_principal'` (and the equivalent for `replay()`), surfaced as an HTTP 500 through `TestClient(raise_server_exceptions=False)`.
- `TestRequireConsumerIdentityTopicSemantics::test_non_empty_topic_restriction_is_enforced_and_returned`, `TestAuditRecordValidation::test_topic_authorization_rejection_produces_structured_audit_record`, `TestAuditRecordValidation::test_consumer_identity_rejection_produces_structured_audit_record`: `orjson.dumps` raises `TypeError: Type is not JSON serializable: MagicMock` (`scripts/eventbus/audit.py`, inside `log_auth_failure`) before the test's expected `HTTPException` is raised, because these tests pass a bare `MagicMock()` as `request`.

## Reason for change
Both clusters are confirmed test-only issues, not production regressions: the first is stale duplicated test-infrastructure code (a hand-copied route wrapper drifted from the real function's signature); the second is a test-fixture inadequacy (a bare `MagicMock()` doesn't provide the real string attributes the audit-logging path legitimately expects from any genuine `Request`). Fixing both restores 5 tests' coverage of DLQ-list/replay operator authorization and consumer-identity/topic rejection audit-record structure.

## Implementation intent
For cluster 1: remove the extra `_principal=_principal` argument from both wrapper calls, matching the real `app.py` wrapper's call pattern exactly. For cluster 2: replace the bare `MagicMock()` `request` argument in the 3 affected tests with a lightweight stand-in that provides real string values for `.state.request_id` and `.url.path` (e.g. `MagicMock()` with those two attributes explicitly set to string literals, or a minimal fake object/`SimpleNamespace`-based stand-in) — do not change `log_auth_failure`/`audit.py`'s serialization behavior, since it correctly assumes string inputs for any genuine request.

- `REQ-002`: Fix the 3 `require_consumer_identity`-unit-testing tests' `request` stand-in to provide real string `.state.request_id`/`.url.path` values.
