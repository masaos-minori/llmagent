## Design

### 1. Terminology glossary already exists — use it, don't recreate it

`docs/00_governance_09_terminology-glossary.md` already defines canonical
English forms for EventBus, Known Issue, and Needs Confirmation (and ~90
other terms), is already cross-linked from 13 other docs, and matches the
requirement's Implementation instruction 1 almost verbatim. This plan
therefore treats acceptance criterion 1 ("A terminology glossary document
exists...") as already met and does not create a new file. If implementation
discovers a governance term with variant spellings that is *not* yet in the
glossary table, add a row to the existing table (do not create a second
glossary file).

Key nuance from the glossary's Notes column: EventBus is CamelCase in
English prose but "Event Bus" (with space) in Japanese prose. The sweep
logic must branch on language context per occurrence, not apply one
global substitution.

Sweep procedure per file: `rg -n` each variant, inspect each hit's context
(prose/heading vs. code fence/path/identifier vs. Japanese vs. English
sentence), and normalize only the prose/heading hits to the glossary's
preferred form for that language.

### 3. Related Documents duplicate bullets

Confirmed via a Python script that parses each `## Related Documents`
section into its bullet multiset and flags any bullet appearing more than
once within the same section:

- 7 files named in the requirement each have exactly one bullet duplicated
  once (2 occurrences) within their single `## Related Documents` section.
- `docs/01_overview-files-03-scripts.md` is a more severe instance of the
  *same* defect: it has 10 separate `## Related Documents` sections (the
  file interleaves 10 near-duplicate content blocks), and in every one of
  the 10 sections the bullet `` - `01_overview-files-03-scripts.md` `` (a
  self-reference) appears 4 times alongside one distinct bullet
  (`` - [01_overview.md](01_overview.md) ``). Fix: in each of the 10
  sections, keep exactly one self-reference bullet + the one
  `01_overview.md` bullet, removing 3 duplicate lines per section (30
  lines total).

### 4. Part 1 self-link / 2b-2c duplication

`docs/03_rag_03_02_query_pipeline-rag-pipeline-class.md`'s own frontmatter
title is `"RAG Query Pipeline - RagPipeline Class Detail (Part 1)"`. Lines
137 and 246 each read `> [Part 1](03_rag_03_02_query_pipeline-rag-pipeline-class.md)
参照。` — a link from Part 1 to itself, labeled "see Part 1", which is either
vestigial or a leftover from a copy-paste. Investigation found no sibling
"Part 2" file for this document class exists anywhere under `docs/03_rag_03_*`,
and section `## 2c.` (lines 238 through the point where the file continues
into HTTP-mode content, mirroring lines 129-207 in `## 2b.`) is a verbatim
duplicate of `## 2b.`, including an embedded stray repeat of the file's own
H1 heading/intro links and a "### Related Documents"/"### Keywords" block
mid-file (lines 211-234) between 2b and 2c. This is consistent with an
accidental double-paste of the same content block, not a real "Part 2"
cross-reference.

Fix: delete the duplicated `## 2c.` section (and the stray
Related-Documents/Keywords/H1-repeat block at lines 211-234 that sits
between 2b and 2c, since that content belongs only once, in the file's
real end-of-file `## Related Documents`/`## Keywords` sections if present)
and remove the two "[Part 1](self)" links inside the retained `## 2b.`
section, replacing them with a plain-prose cross-reference to
`03_rag_03_03_query_pipeline-context-and-diagnostics.md` §4.2 (the doc
already cross-references that file/section two paragraphs later for a
related contract, at line 206) or, if no correct target can be identified
with confidence, simply drop the dangling link text and keep the caveat
prose standalone. Implementer must diff the file before/after to confirm
no unique content is lost — read the full file end-to-end first, since the
duplication pattern may extend further than the two lines identified.

### 5. Unstable line-number citations

Beyond the two governance files named in the requirement, a repo-wide
`grep -rl '\.py:[0-9]+' docs/*.md` found one additional instance:
`docs/04_mcp_05_05_mdq-enforcement-and-lockdown.md:89` cites
`mdq_server.py:368`. Same fix pattern applies to all three files: where a
stable symbol/function/config-key name exists at that location, cite the
symbol instead of (or alongside) the line number; where no stable anchor
exists, keep the line reference but prefix with `~` to flag it as
approximate (pattern already used elsewhere in these files, e.g.
"Line Number: ~176").

## Risks

- **Risk**: Bulk-replacing "eventbus" case-insensitively would corrupt code
  identifiers, file paths, and module names that legitimately use lowercase
  `eventbus` (283 of 320 hits). *Likelihood*: high if done via blind
  find-replace. → **Mitigation**: per-occurrence manual/scripted
  classification (prose vs. code/path) before editing; never run a bulk
  `sed -i` across `docs/*.md` for this term.
- **Risk**: Deleting the duplicated `## 2c.` section in
  `03_rag_03_02_query_pipeline-rag-pipeline-class.md` could accidentally
  remove content that is *not* actually a duplicate if the two sections
  diverge in some paragraph not yet inspected. *Likelihood*: low (spot
  checks of both sections found them byte-for-byte identical in the
  inspected ranges) but not exhaustively diffed end-to-end. → **Mitigation**:
  implementer must run a full-file diff (e.g. extract 2b and 2c as separate
  text blocks and `diff` them) before deleting, not rely on this plan's
  spot check.
- **Risk**: `docs/01_overview-files-03-scripts.md` has a much larger
  structural duplication problem (whole content blocks, not just bullets,
  repeated ~10x) than this plan addresses. Fixing only the
  `## Related Documents` bullets leaves the file's underlying corruption
  in place, which may resurface as a "duplicate content" complaint later.
  *Likelihood*: medium. → **Mitigation**: stay within this requirement's
  explicit scope (bullet-level dedup only) to avoid an unreviewed "broad
  formatting-only rewrite"; file a separate follow-up issue recommending a
  full-file review of `docs/01_overview-files-03-scripts.md`'s repeated
  content blocks as its own require-to-plan cycle. Tracked as
  `issues/20260819-181233_risks.md`.
- **Risk**: Replacing a line-number citation with a symbol name could go
  stale just as easily if the symbol is later renamed, giving a false sense
  of permanence. *Likelihood*: low (symbol renames are rarer than line
  churn, and are typically ripped through the whole repo via `rg` including
  docs, per existing project convention) → **Mitigation**: none needed
  beyond what the requirement already specifies (this is the requirement's
  own accepted tradeoff, not a new risk introduced by this plan).
- **Risk**: The glossary's language-conditional rule (CamelCase in English,
  spaced form in Japanese, for EventBus) is easy to apply inconsistently
  across ~320 occurrences by different reviewers/passes. *Likelihood*:
  medium. → **Mitigation**: Validation plan's re-scan step catches any
  leftover non-canonical form; treat the scan as the actual gate, not
  reviewer diligence alone.
