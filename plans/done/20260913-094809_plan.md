## Problem
Three related defects, all stemming from the same incomplete per-role-token rollout
(introduced in commit `96d02ac52`):

1. In `scripts/eventbus/config.py`'s `load_config()`, the `auth_token`-non-empty check
   and the per-role-token-required check are indented one level too deep — inside the
   `for key, expected_type in _CONFIG_KEY_TYPES.items():` type-validation loop instead
   of after it. The validation *outcome* is unchanged (the same checks still run, just
   redundantly per iteration), but this is a clear structural mistake.
2. `EventBusConfig.__post_init__` only requires `auth_token` to be non-empty; it has
   no equivalent check that at least one per-role token
   (`consumer_token`/`operator_token`/`admin_token`) is set. That requirement exists
   only in `load_config()`'s TOML-parsing path, so directly constructing
   `EventBusConfig(...)` (as most test fixtures do) never sees it.
3. `tests/eventbus/test_eventbus_auth.py`'s `_make_test_app()` helper defaults `token`
   to `None` (not a `str`, which `EventBusConfig.auth_token` expects), has no
   `publisher_token` parameter at all despite a caller's comment saying "using
   per-role tokens only", and several call sites pass `token=None` explicitly.
   `tests/eventbus/test_eventbus_config.py::test_load_config_succeeds_without_stray_keys`
   and `tests/eventbus/test_eventbus_subscribe.py`'s fixtures likewise construct
   configs with no per-role token set.

## Reason for change
Confirmed by repository evidence: running `tests/eventbus/test_eventbus_auth.py` and
`tests/eventbus/test_eventbus_subscribe.py` produces `ValueError: auth_token is
required but not configured` or `ValueError: At least one per-role token must be
configured` at test *setup* (13 errors in `test_eventbus_auth.py`, 2 in
`test_eventbus_subscribe.py`, 2 in `test_eventbus_config.py`) — the entire
per-role-token authorization path currently has no passing test coverage.

## Implementation intent
Fix the `config.py` indentation so the two checks run exactly once, after the
type-validation loop. Decide explicitly whether `EventBusConfig.__post_init__` should
also enforce the per-role-token rule (recorded as Unknown UNK-01 below — a design
decision, not a discovered fact) and apply that decision consistently. Then update
every affected test fixture to supply values satisfying the current requirements, and
add the missing `publisher_token` parameter to `_make_test_app()` so its "per-role
tokens only" test cases actually exercise that path.

  and current `scripts/eventbus/auth.py`).
- `REQ-006` (added during `code-implementation`, per a second additional-scope

  `require_consumer_identity`'s consumer_id-allowlist check

  `_populate_token_maps()`'s own comment, "Empty means any consumer_id"), not as

  This surfaced concretely via `tests/eventbus/test_eventbus_subscribe.py`'s
  `consumer_token` (present in `_TOKEN_ROLE_MAP` after REQ-005, but never given an

  rejected with 403 instead of reaching the endpoint logic
  `test_subscribe_duplicate_consumer_id_returns_409` (REQ-004's own target test)
  needs to observe.

## Design
`load_config()`'s validation block is de-indented one level so the `auth_token`
and per-role-token checks run once, immediately after the `_CONFIG_KEY_TYPES` loop,
preserving their current logic and error messages exactly. **UNK-01 is resolved to
No** (see Unknowns): `EventBusConfig.__post_init__` keeps only its pre-existing
`auth_token`-non-empty check and does **not** gain a new per-role-token-required
check — that requirement remains exclusive to `load_config()`'s TOML-parsing path,
exactly as it was before this Plan. This was reached empirically, not
prescriptively: `Yes` was tried first and reverted after it broke 114+22 tests
across the repository that this Plan's `Implementation Target Files` never
accounted for.
