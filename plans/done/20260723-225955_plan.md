## Goal

Improve error messages for tool calls during MCP subprocess cooldown so users understand why a tool call failed.

## Scope

**In-Scope**:
- Raise `ServerCooldownError` from `ensure_ready()` when server is in cooldown
- Define `ServerCooldownError` custom exception class
- Catch `ServerCooldownError` in callers to display meaningful message

**Out-of-Scope**:
- Modifying cooldown logic itself
- Changing `_COOLDOWN_SECONDS` duration
- Adding new configuration options

## Assumptions

1. Raising an exception (rather than returning a sentinel value) makes the failure explicit at the call site.
2. `ServerCooldownError(RuntimeError)` will be caught by existing `except (OSError, RuntimeError)` handlers.
3. Both callers (`tool_transport_invoker.py` and `tool_executor.py`) need to handle the new exception type.
