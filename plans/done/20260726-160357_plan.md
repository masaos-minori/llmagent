## Goal

Protect sensitive data in diagnostic store by filtering/redacting sensitive fields before persistence and adding optional encryption for stored diagnostics.

## Scope

**In-Scope:**
- Define and apply filter to remove or redact sensitive fields (artifact URIs, RAG outcomes) before saving
- Add optional encryption layer using configurable key for diagnostic data storage
- Implement retention policy to automatically delete old diagnostic records (default: 30 days)
- Log warnings when sensitive data would be persisted but is filtered out

**Out-of-Scope:**
- Modifying existing diagnostic save methods to add new kinds of diagnostics
- Adding encryption for conversation history or other non-diagnostic data
- Changing the database schema beyond what's needed for retention

## Assumptions

1. Encryption should be opt-in via configuration rather than always-on to avoid breaking existing deployments
2. Retention policy can run lazily during diagnostic operations rather than requiring a separate cron job
3. Redacted fields should retain metadata (e.g., count of items) without exposing actual values
