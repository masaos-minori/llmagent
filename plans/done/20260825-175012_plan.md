# Plan: Fix rename_modules.py hardcoded path and silent-failure behavior

## Goal
Make `rename_modules.py` work correctly across environments by deriving the repository root from the script's own location instead of a hardcoded absolute path, and fail loudly (non-zero exit + clear error message) when required paths do not exist.

## Priority
High

## Scope
- **In-Scope**: `tools/rename_modules.py` (module-level `BASE`, `main()`)
- **Out-of-Scope**: Any actual module rename operation against `scripts/mcp_servers/`, rewriting the import/docstring/patch-target update logic beyond fixing the described base-path and dead-code issues, any other `tools/*.py` script.

## Background
`tools/rename_modules.py` resolves its repository root from a hardcoded absolute path (`/home/sugimoto/llmagent`) that does not exist in the current environment (`/home/masaos/llmagent`). Because the failure is swallowed, the script reports success while processing zero files.

## Problem
The script has two related bugs:
1. **Hardcoded path**: `tools/rename_modules.py:8` — `BASE = pathlib.Path("/home/sugimoto/llmagent")` is a hardcoded, user-specific absolute path rather than one derived from the script's own location or the current working directory.
2. **Silent failure**: `main()` loop — each target directory is checked with `if not d.exists(): continue`, so a missing `BASE` means every directory lookup silently continues past, and the script finishes with a "Done. Updated 0/0 files." style success message rather than an error.

Impact: a user who runs this script to rename an `mcp_servers/<server>/` module gets no indication that nothing happened. The script looks like it succeeded (exit 0, "Done" message) while performing zero renames, imports updates, or patch-target updates. This is a silent-failure trap for exactly the kind of multi-file mechanical rename this script exists to make safe.

## Reason for change
Explicit in code: `tools/rename_modules.py:8` — `BASE = pathlib.Path("/home/sugimoto/llmagent")` is a hardcoded, user-specific absolute path; `/home/sugimoto/llmagent` does not exist on this machine; the actual repository root is `/home/masaos/llmagent`. Explicit in code: `main()` loop — each target directory is checked with `if not d.exists(): continue`, so a missing `BASE` means every directory lookup silently continues past, and the script finishes with a "Done. Updated 0/0 files." style success message rather than an error.

## Implementation intent
Derive the repository root from the script's own location (e.g., `Path(__file__).resolve().parent.parent`) instead of a hardcoded, environment-specific absolute path, consistent with how other scripts in `tools/` compute `ROOT_DIR`/`REPO_ROOT` (see `tools/check_no_compat.py`, `tools/gen_reference_table.py`). Where the resolved `BASE` (or any directory the script depends on) does not exist, fail loudly — non-zero exit and a clear error message — instead of silently skipping and reporting success.

## Requirements

- `REQ-003`: A successful rename run's "Updated N/M files" count reflects actual files scanned, not a silently-empty set.

## Design
### Current behavior analysis
- Line 8: `BASE = pathlib.Path("/home/sugimoto/llmagent")` — hardcoded absolute path.
- Lines 421-428: `main()` builds `dirs_to_process` using `BASE / "scripts"`, etc.
- Line 434: `if not d.exists(): continue` — silently skips missing directories.
- Line 469: Prints "Done. Updated 0/0 files." even when all directories were skipped.

### Design decision: derive BASE from script location
Replace `BASE = pathlib.Path("/home/sugimoto/llmagent")` with:
```python
BASE = pathlib.Path(__file__).resolve().parent.parent
```
This matches the pattern used by `tools/manage_frontmatter.py` (line 25: `ROOT_DIR = Path(__file__).resolve().parent.parent`), `tools/check_no_compat.py`, and `tools/gen_reference_table.py`.

### Design decision: fail-loud for missing BASE only
Add an existence check on `BASE` at the start of `main()` that exits non-zero with a clear error if the path is missing. Do NOT add similar checks for individual subdirectories (`scripts/`, `tests/`, `mutants/`, etc.) — these are optional and may not exist in all environments. The existing `continue`-based skip remains for those.

### Design decision: keep process_file() for now
The issue mentions dead-code duplication between `process_file()` and `main()`. Leave this out of scope unless trivially fixable alongside the base-path change. Investigate during implementation.
