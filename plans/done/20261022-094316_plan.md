# Plan

## Goal
Remove the EventBus startup step that imports legacy file-based consumer offsets into `consumer_offsets` (the `offset_migrator` module, its re-export, and its startup call), leaving offset storage, advancement, and resume behavior unchanged and `consumer_offsets` as the only resume source.

## Priority
Medium

## Scope
- **In-Scope**:
  - Delete `scripts/eventbus/offset_migrator.py` and remove its import, re-export, `__all__` entry, and the startup call in the lifespan.
  - Remove the tests of the import, keeping every test of ACK-advanced offsets, resume behavior, and the file-based helpers.
  - Update the EventBus and database documents: remove the import description, the import's open decisions, and the generated reference row; reduce the "Legacy Offset Files" operations section to the statement that offset files are not used by the service; keep the file-based helper question as an open decision.
- **Out-of-Scope**:
  - Removing the `offsets_dir` key, `write_offset()`, `read_offset()`, `scripts/eventbus/offsets.py`, or their tests (separate decision).
  - Deleting any offset file from any host.
  - Editing `docs/10_adr/adr_02_04_006_eventbus-sqlite-persistence-and-sse-delivery.md` (needs the owner's decision first; see UNK-01).
  - The schema migrations of `eventbus.sqlite`, `workflow.sqlite`, and `mdq.sqlite` (separate plans).

## Background
The EventBus operations document states that the import may be removed when no supported deployment keeps files in `offsets_dir`. The owner decided on 2026-10-21 that the only supported deployment is the single host `/opt/llm`; a read-only inspection that day found `/opt/llm/offsets` empty and `consumer_offsets` empty. Verified against current source: `migrate_legacy_offsets()` is called once in the `lifespan` of `scripts/eventbus/app.py` inside a `try` that only logs a failure; it is re-exported by `scripts/eventbus/db.py`; its only runtime dependency on the file-based store is the private helper `_sanitize_consumer_id` in `scripts/eventbus/offsets.py`. Live ACK and subscribe paths use the `consumer_offsets` table.

## Problem
The import has no completion marker, runs on every start for files that do not exist, raises on a consumer-ID collision (skipping the rest of the import), and does not commit its inserts. A startup `try`/log path can hide a failure. Adversarial verification of the Issue found further facts it does not state:
- In `tests/eventbus/test_eventbus_offsets.py`, the class `TestLegacyOffsetMigrationDirect` is followed, after its last migration test, by a stray docstring and three `write_offset` collision tests (`test_collision_rejected_for_equal_seq`, `..._lower_seq`, `..._higher_seq`). Those tests belong to the retained file-based helpers (REQ-001 identity validation), so deleting the class wholesale would remove them.
- After the import is removed, `scripts/eventbus/offsets.py` has no production caller, and `docs/24_eventbus/eventbus_08_reference_api.md` says it is "used only by the one-time startup migration", which becomes false. The "File-based helpers" bullet inside the open-decisions section of `eventbus_05` records that undecided removal and is not moot with the import, although that section states "each item is moot if the import is removed".
- `eventbus_08_reference_api.md` holds a row for the removed function inside a generated block, so the block must be regenerated and `generate_reference_table.py --check` re-run.
- Anchors are involved: `eventbus_07` links to the open-decisions heading in `eventbus_05`, and `db_03` links to the `legacy-offset-files` heading in `eventbus_07`; removing or renaming a heading breaks a link.
- `docs/10_adr/adr_02_04_006_eventbus-sqlite-persistence-and-sse-delivery.md` names `migrate_legacy_offsets()` and `offset_migrator.py` in its Implementation Notes, file list, and offset-file entry; it is outside the Issue's target list and may not be edited without a recorded owner decision.

## Reason for Change
Consumer offsets decide where each consumer resumes; a data-integrity path that runs on every start without an explicit commit is a liability once nothing needs it. Removing it ends the open decisions about collisions, the completion marker, and commit behavior in one step.

## Implementation Intent
Delete the import and everything that only serves it, leaving offset storage, monotonic advancement, and resume computation untouched, along with the `offsets_dir` key and the file-based helpers. Documentation states only current behavior: the service does not read offset files, and `consumer_offsets` is the only resume source. The helper-removal question stays recorded as one open decision because this Plan neither decides nor prepares it. The ADR is left as is until the owner decides (UNK-01).

## Design
- Path B (more than three files; EventBus startup path in `scripts/`).
- Evidence: the module has exactly one runtime caller (`lifespan`) and one re-export; `_sanitize_consumer_id` remains in `offsets.py` for the retained helpers; no other module imports `offset_migrator`; `config.py` still requires `offsets_dir`, so the key and `config/eventbus.toml` stay.

- Anchor stability: the `Legacy Offset Files` heading stays in `eventbus_07`; links to the removed open-decisions heading and to the removed `db_03` subsection are removed together with their targets.
