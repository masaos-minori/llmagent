# Plan: Enforce approval policy in configuration validation

## Goal

Require `require_approval: true` in configuration validation for any workflow that can reach tools needing approval (shell execution, deletion, push, etc.), so a misconfiguration is detected at startup.

## Priority

Medium

## Scope

- **In-Scope**:
  - `config/workflows/default.json`: change `require_approval` to `true`
  - `scripts/agent/workflow/workflow_loader.py`: enforce `require_approval: true` at load/startup
  - `docs/23_agent/agent_03_03_turn-processing-flow-workflow-engine.md`: replace the "no code enforces it" policy note with the enforcement mechanism; resolve the Known Limitations entry
  - `docs/00_governance/governance_03_issue-and-uncertainty-management.md`: remove AGENT-001 from the Known Issues ledger once resolved
- **Out-of-Scope**:

  - Changes to approval behavior itself
  - Adding a `require_approval` rule to `ProductionConfigValidator` (see Plan correction notes below)

## Background

Source: local investigation notes (memo1.md, ISSUE-10), from AGENT-001. Documentation calls the approval policy mandatory; no code enforces it.

## Problem

- The default `default.json` sets `require_approval` to `false` (confirmed: `config/workflows/default.json` line 25).
- `WorkflowLoader` parses `require_approval` as an optional boolean that defaults to `false` when absent (`scripts/agent/workflow/workflow_loader.py` line 136), so a missing or wrong value is never caught.
- Documentation says the approval policy is mandatory, but nothing in code enforces it.

## Reason for change

- A policy described as mandatory but not enforced is only nominal.
- Tool-level approval gates alone cannot confirm a whole stage's result after execution.

## Implementation intent

- Detect, at startup, a workflow definition that does not set `require_approval: true`, and reject it at load time.

## Requirements

- `REQ-001`: At load, a workflow definition must carry `require_approval: true`; otherwise raise `WorkflowLoadError`. (Source: Problem, Reason for Change)
- `REQ-002`: The bundled `default.json` sets `require_approval: true`. (Source: Required Changes)

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| Workflow + `require_approval: true` | Accept |
| Workflow + `require_approval: false` | Reject at load |
| Workflow + `require_approval` absent | Reject at load (cannot silently default to false) |

### Design details

1. In `workflow_loader._validate()`, after the existing structural checks, require
   `data.get("require_approval") is True`. If not, raise
   `WorkflowLoadError("require_approval must be true for this workflow")`.
2. `default.json` sets `require_approval: true`.
3. Because workflows do not enumerate tools (`workflow/models.py` `WorkflowDef` has no
   tool field) and the standard execute stage reaches every configured tool, the check is
   workflow-level rather than tool-intersection-based. This is a deliberate narrowing from
   the plan's original tool-intersection matrix, which is not achievable given the current
   workflow schema.
