## Background
Same `docs/` reorganization effort as `docsreorg05`
(`plans/done/20260924-115855_plan.md`) and `docsreorg06`
(`plans/done/20260924-130409_plan.md`); this Plan covers `docsreorg07`, the physical
move for the `90_deployment` area — a single-file batch. Prerequisite issues
`docsreorg01` (folder-independent cross-reference resolution) and `docsreorg02`
(subfolder-aware domain checkers) have already landed; `tools/check_docs_consistency.py`'s
`DOMAIN_PREFIXES["deployment"]` (`"02_deployment"`) combined with the already-recursive
`discover_md_files()` continues to find the moved file by prefix match, no code change
needed. `docsreorg03`'s `.github/workflows/deployment-docs-consistency.yml` path filter
already points at the post-move location (`docs/90_deployment/02_deployment*.md`) —
confirmed via Read, already landed. `docsreorg04` (canonical routing reference updates)
has landed repository-wide.

Both `docsreorg05` and `docsreorg06` (this same session, immediately prior) discovered
that `docsreorg01`'s basename-index resolution in `tools/check_docs_structure.py`
covers only bare-filename references, not existing relative-path (containing `/`)
references, which break when either endpoint of the reference changes its directory
depth. This Plan applies that same dependency-graphing check proactively during
planning.

## Problem
`docs/02_deployment.md` currently sits directly under `docs/` alongside all other
areas' files, with no folder grouping — confirmed via `ls docs/02_deployment.md`
(13165 bytes), present at the flat path today; `docs/90_deployment/` does not yet
exist.

## Reason for change
Grouping the deployment doc into its own folder is the next physical-move step of the
broader `docs/` reorganization, for consistency with every other area even though this
one has only a single file today.

## Implementation intent
Use `git mv` for the one file. This Git environment does not auto-create an
intermediate destination directory for `git mv` (confirmed empirically during
`docsreorg05`'s execution) — create `docs/90_deployment/` with `mkdir -p` first.

Then fix the 4 relative-path references identified by the dependency-graphing analysis
below (Design): `docs/02_deployment.md`'s own outbound link to
`docs/adr/ADR-001-workflow-engine-mandatory.md` (its new nesting depth under
`docs/90_deployment/` changes what `../adr/...` needs to resolve correctly),
`docs/adr/ADR-001-workflow-engine-mandatory.md`'s and
`docs/adr/ADR-004-environment-failure-handling-policy.md`'s own inbound links to
`docs/02_deployment.md` (each needs an added `90_deployment/` path segment), and

file itself moved into `docs/00_governance/` during `docsreorg05`, so its relative
depth to the newly-created `docs/90_deployment/` sibling also needs a leading `../`,
the same pattern already fixed for its `01_overview/01_overview.md` links during
`docsreorg06`).
