## Goal
- Remove the `/mdq` slash command and its `_MdqMixin` handler so that MDQ is reachable only through the normal LLM tool-selection and MCP execution path, while keeping the MDQ server, tools, classifier, and `mdq_rag_mode` unchanged; guard against the command coming back.

## Priority
Low

## Scope
- **In-Scope**: delete `cmd_mdq.py` and its `CommandDef` / mixin wiring; delete `test_cmd_mdq.py` and edit the six other tests that reference the removed code; add a `/mdq` unregistered regression test; update `agent_02`, `agent_07_01`, `agent_07_03`, `agent_07_10`; fix the docs-consistency checker's false positive on `<log_dir>/mdq-mcp.log` that the removal would expose; register `/mdq` in `COMPAT_PATTERNS` with a test case.
- **Out-of-Scope**: `/approve` and `/reject` removals; MDQ server, classifier, and configuration; any new MDQ-path statement in docs (it already exists in `mcp_05_04` and `agent_03_01`); the `--check-removed-names` GV-017 check and its two pre-existing findings; a `/skill` entry in `COMPAT_PATTERNS`; archived files under `*/done/`; `memo2.md`.

## Background
`/mdq` (status, index, refresh, search, outline, get, grep) is implemented by `_MdqMixin` in `scripts/agent/commands/cmd_mdq.py` and calls MDQ MCP tools through the tool executor after `check_preflight()`. It follows the `/skill` removal (commit 6ef4f8fbd), which needed an out-of-scope test fix; this Plan therefore lists every referencing test up front. The source Issue was verified adversarially before this Plan; its claims are re-checked below. This Plan was then verified adversarially a second time (static review plus a trial removal in an isolated worktree with the full test suite); the corrections are folded in below.

## Problem
- A second REPL path reaches `mdq-mcp` besides the normal LLM and MCP path, with its own preflight and output handling (`scripts/agent/commands/cmd_mdq.py:58-76`).
- `/mdq search --mode grep` is advertised (`cmd_mdq.py:176`) and forwarded to `search_docs`, which rejects `grep` (`tests/mcp_servers/mdq/test_mdq_search_modes.py::test_grep_mode_rejected`); the command also uses only the first token as the query (`cmd_mdq.py:189`).
- `docs/23_agent/agent_02_runtime-architecture.md:64,80` lists the command as a `check_preflight` call site and a gateway-bypass example.

## Reason for change
Consolidating MDQ access into one path removes a command, a mixin, a partly broken option, and one gateway-bypass call site. Doing it now, before the `/approve` and `/reject` removals, keeps each registry and count-test change separate and reviewable.

## Implementation intent
Delete only the command, its handler mixin, registration, tests, and documentation entries. Add no new documentation sentence, because `mcp_05_04` (lines 76-81, 108) and `agent_03_01` (line 108) already state MCP-only access and hint-only classification. Guard reintroduction with an unregistered-command test and a `COMPAT_PATTERNS` entry (default-on, code and docs, CI) rather than the opt-in markdown-only GV-017 table. Apply Steps 1-8 as one commit unit and add the `COMPAT_PATTERNS` entry last (Step 8), so the guard never fires on a half-removed tree. Fix the docs-consistency checker's regex (Step 7) instead of rewording valid docs, because the false positive is a checker defect that the removal merely exposes.
