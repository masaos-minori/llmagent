# Plan: Fix Front Matter Inconsistencies Across docs/

## Goal
Repair the remaining Front Matter violations in `docs/` — a missing Front Matter
block on one file, and stale ADR short-name cross-references on six files — to
ensure consistent metadata structure and valid field references across all
Markdown documents.

## Priority
Medium

## Scope
- **In-Scope**: Add the missing Front Matter block (`area`, `tags`, `related`) to
  `docs/databases/active_databases.md`; fix invalid `related` cross-references in six
  documents that cite ADR files by short name (`ADR-001`) instead of their actual
  filename (`ADR-001-workflow-engine-mandatory.md`), including one non-ADR reference
  that has a description string appended after a bare filename.
- **Out-of-Scope**: Renaming documents to match old reference names; adding new Front
  Matter fields beyond what the schema requires; restructuring document content;
  fixing broken internal links (covered by separate issue DOC-001); external HTTP
  link repair; the file-size-limit warnings `check_docs_structure.py` reports for
  several ADR files (a separate, pre-existing concern unrelated to Front Matter
  correctness); H1 heading counts, missing `## Keywords`/`## Related Documents`
  sections, and the other 21 originally-targeted files — all independently confirmed
  already resolved (see Problem and Revalidation below).

## Background
The `docs/` directory uses YAML Front Matter with required fields (`title`, `area`,
`tags`, `related`) defined in `schemas/doc_front_matter.json`. This Plan was
originally generated from `issues/done/20260922-064743_doc002_fix-front-matter-inconsistencies-in-docs.md`
against 28 target files. Before this revision, `check_docs_structure.py --schema
schemas/doc_front_matter.json` was re-run against all 28 originally-listed files.

## Problem

already fully compliant — confirmed via direct `check_docs_structure.py` (plain and
`--schema`) re-run producing zero findings for each. `git log` confirms this happened
via commit `7e4c2dbc3` ("docs: fix front matter inconsistencies across documentation
files", 2026-09-22 18:12), an out-of-band fix applied after this Plan was first

## Reason for change
Inconsistent Front Matter breaks automated documentation tooling (schema validation,
link checking, navigation generation). The 7 remaining violations are the only ones
still causing `check_docs_structure.py --schema schemas/doc_front_matter.json` to
report findings.

## Implementation intent
1. Add a standard Front Matter block to `docs/databases/active_databases.md`
   (`area: shared`, per the existing convention for other `shared_04_*` DB-related
   documents; `tags: [databases, sqlite, shared]`; `related: []`, since it references
   config/code files, not other docs).
2. In the 6 files with stale ADR short-name references, replace each `ADR-XXX` entry
   with its actual filename, and remove the appended description text from
   `04_mcp_02_03_audit-logging-and-errors.md`'s malformed entry (keeping the filename
   itself, which is correct).

## Design
All 7 fixes are localized Front Matter edits with no content/structure change:
1. `active_databases.md`: insert a `---`-delimited YAML block before the existing
   `# Active Databases` H1, with `title: "Active Databases"`, `area: shared`,
   `tags: [databases, sqlite, shared]`, `related: []`.
2. The 6 stale-ADR-reference files: replace each short-name list entry (`ADR-001`,
   etc.) with its full actual filename, preserving list structure and any sibling
   fields (`supersedes`, `superseded_by`) unchanged.
3. `04_mcp_02_03_audit-logging-and-errors.md`: truncate the last `related` list entry
   at the filename boundary (remove everything from ` — ` onward), leaving
   `00_security_01_architecture-and-trust-boundaries.md` as a bare filename matching
   every other entry's format.

No production code, schema, or tooling change — this Plan is Front-Matter-data-only.
