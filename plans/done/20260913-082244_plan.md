# Plan: Refactor http_lifecycle.py to reduce complexity and improve type safety

## Goal
Reduce cyclomatic complexity in `scripts/agent/http_lifecycle.py`, consolidate duplicate resource cleanup and process termination logic into shared helpers, and replace the implicit dict-to-dataclass mapping in `_build_snapshot_dict()` with an explicit `ProcessInfoSnapshot` return path.

## Priority
Medium

## Scope
- **In-Scope**: Refactoring `scripts/agent/http_lifecycle.py` only; extracting helper functions/methods for duplicate logic; replacing dict snapshot with typed dataclass where appropriate.
- **Out-of-Scope**: Modifying `scripts/agent/services/models.py` (`ProcessInfoSnapshot`), adding new features or capabilities, changing public API contracts, refactoring the six delegated concern modules, modifying test files beyond ensuring they still pass.

## Background
`http_lifecycle.py` is the HTTP subprocess MCP server lifecycle manager. It was previously extracted from `lifecycle.py` and refactored to delegate to six concern-specific modules (CommandValidator, StderrLogManager, ProcessTerminator, HealthChecker, ProcessSnapshotProvider, ShutdownCoordinator). However, the class itself still contains significant complexity:
- `_health_poll_until_ready()` has deeply nested try/except blocks and multiple early-exit paths
- `_terminate_with_timeout()` duplicates pgid-based termination logic in two places
- Resource cleanup logic is scattered across `_cleanup_server_resources()`, `_terminate_with_timeout()`, and `_create_and_validate_proc()`
- `shutdown_all()` uses fragile SIGINT signal handlers that could leave orphaned processes if interrupted during handler setup

## Problem
The class violates the Single Responsibility Principle despite having injected components — it still orchestrates too much lifecycle logic internally. Additionally, the implicit dict-to-dataclass mapping between `_build_snapshot_dict()` and `ProcessInfoSnapshot` makes type mismatches hard to detect.

## Reason for change
- Reduces maintenance burden by consolidating duplicate cleanup logic
- Improves testability by extracting complex control flow into smaller units
- Prevents potential resource leaks from fragile SIGINT handling
- Makes type contracts explicit rather than implicit through dict mappings

## Implementation intent
Focus on responsibility boundaries: each method should do one thing well. Extract complex control flow into helper functions or small classes. Replace the dict snapshot with an explicit `ProcessInfoSnapshot` return path. Do not change public behavior or API contracts.

## Design
### Approach
1. **Extract shared termination helper (REQ-001)**: Create `_do_pgid_terminated(pgid, proc, force=False)` that encapsulates the pgid-based termination logic currently duplicated in `_terminate_with_timeout()`. This method handles the try/catch around `os.killpg()` and falls back to `proc.terminate()`/`proc.kill()`.

2. **Consolidate cleanup paths (REQ-002)**: Ensure `_cleanup_server_resources()` is the single entry point for all resource cleanup. Currently, `_health_poll_until_ready()` calls it directly in two places (early-exit and shutdown paths). Move the stderr log closing and tracking removal into this method consistently.

3. **Replace dict snapshot with typed dataclass (REQ-003)**: Rename `_build_snapshot_dict()` to `_build_snapshot()` and have it return `ProcessInfoSnapshot | None` directly. Update `get_process_snapshot()` to convert the dataclass to a dict if callers need dict format, or update both callers to accept `ProcessInfoSnapshot`.

4. **Simplify health poll loop (REQ-004)**: Extract the early-exit-on-process-death path into `_handle_early_exit(server_key, proc)` and the shutdown-event path into `_handle_shutdown_request(server_key)`. Each returns a boolean indicating whether the caller should raise `HttpStartupError`.

5. **Improve SIGINT handling (REQ-005)**: The current approach already restores the handler in a `finally` block. Add a guard to ensure the handler is always restored even if an unexpected exception occurs between setting and restoring.

### Type safety improvement
The key insight is that `_build_snapshot_dict()` returning `dict | None` creates an implicit contract: the dict keys must match `ProcessInfoSnapshot` field names exactly. By returning `ProcessInfoSnapshot | None` directly, we make this contract explicit and let mypy verify it.
