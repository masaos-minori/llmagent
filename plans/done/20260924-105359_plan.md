## Goal
Update every specific `docs/*.md` filename reference in `docs/00_index.md`,
`rules/env.md`, and `routing.md` — the three canonical "where do I find the
doc for X" routing references — to include its planned reorg subfolder path,
so these references keep pointing at the correct location once the
corresponding per-area physical-move issues land.

## Priority
High

## Scope

  `routing.md`; any physical file move; renaming or shortening any filename.

## Reason for change
If these three files are not updated in step with the physical move, the
single most consulted "where do I find the doc for X" reference in the whole
documentation set becomes stale immediately, defeating the reorganization's
purpose and actively misdirecting anyone (human or AI agent) who trusts it.

## Implementation intent
For every specific filename reference identified in Problem, prepend the
correct new subfolder path per the confirmed folder-classification mapping
(see Design), leaving the filename itself unchanged. Do not attempt to fix
the pre-existing `-part1`/`-part2` broken references in `rules/env.md`, or
the pre-existing broken `tools/01_overview.md` reference in
`docs/00_index.md`, as part of this issue — both are independent,
already-existing defects unrelated to the folder move.
