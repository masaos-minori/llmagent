# Plan

## Goal
Fix `ReadinessReporter.report_readiness()` (`scripts/agent/startup_reporter.py`) so a validation source that produced only `WARNING` outcomes (and no `FATAL`) is reported as `WARNING` instead of `FAIL`, and use a single consistent status word across all three summary lines.

## Priority
Low

## Scope
- **In-Scope**:
  - Change the per-source status word in `report_readiness()` from the binary `{'OK' if counts['OK'] else 'FAIL'}` / `{'OK' if counts['OK'] else 'WARN'}` expression to a value derived from the full count breakdown.
  - Derive the word by precedence: `FATAL` if any `FATAL`, else `WARNING` if any `WARNING`, else `SKIPPED` if all outcomes are `SKIPPED`, else `OK`.
  - Apply the same word to all three sources (`readiness`, `mcp_tool_discovery`, `rag_consistency`) so the vocabulary is uniform.
  - Add a regression test asserting a warning-only source reports `WARNING` (not `FAIL`).
- **Out-of-Scope**:
  - Any change to `StartupValidationPipeline.check_services()` or how outcomes are produced.
  - Changing the counts shown in parentheses (`fatal` / `warnings` / `skipped`).
  - Renaming `report_readiness()` or changing its return type (still `None`).
  - Governance documentation updates.

## Background
`report_readiness()` builds three summary lines, one per source, using `_count_by_status()`:
```python
f"  Service readiness: {'OK' if mcp_counts['OK'] else 'FAIL'} ({mcp_counts['FATAL']} fatal, {mcp_counts['WARNING']} warnings, {mcp_counts['SKIPPED']} skipped)"
```
`_count_by_status()` (`startup_reporter.py:27-47`) returns an ordered dict `{OK, FATAL, WARNING, SKIPPED}` counting each outcome's `o.status.name` for the given source. In `StartupValidationPipeline.check_services()` (`scripts/agent/startup_validation.py`), `pipeline.add_ok("readiness")` is called only when `result.has_issues` is False, so a readiness probe that emits warnings produces a `WARNING` outcome and zero `OK` outcomes.

## Problem
The status word is computed as `'OK' if counts['OK'] else 'FAIL'` (and `'OK' if counts['OK'] else 'WARN'` for the RAG line). A source with zero `OK` outcomes — including one that emitted only `WARNING` outcomes and no `FATAL` — is therefore labeled `FAIL`. This overstates the problem: a line reading `FAIL (0 fatal, N warnings, ...)` is self-contradictory. The RAG line uses yet another word (`WARN`), so the three lines already disagree on vocabulary.

## Reason for Change
The readiness summary is operator-facing diagnostics. Mislabeling a warning-only source as `FAIL` misleads operators into treating a non-fatal condition as a hard failure, and the inconsistent word set (`FAIL` vs `WARN`) makes the summary harder to parse.

## Implementation Intent
Introduce a small helper `_status_word(counts)` returning the highest-precedence present status (`FATAL` > `WARNING` > `SKIPPED` > `OK`), and substitute it for the inline ternaries on all three lines. Keep the parenthetical counts unchanged.

## Design
The current code computes the status word inline as `{'OK' if counts['OK'] else 'FAIL'}` (lines 82, 85) and `{'OK' if counts['OK'] else 'WARN'}` (line 88). Both collapse any zero-`OK` source to a failure-ish word, ignoring the `WARNING`/`SKIPPED` counts that `_count_by_status()` already provides.

Introduce a helper:
```python
def _status_word(counts: OrderedDict[str, int]) -> str:
    """Return the highest-precedence present status: FATAL > WARNING > SKIPPED > OK."""
    if counts["FATAL"] > 0:
        return "FATAL"
    if counts["WARNING"] > 0:
        return "WARNING"
    if counts["SKIPPED"] > 0 and counts["OK"] == 0:
        return "SKIPPED"
    return "OK"
```
The `counts["OK"] == 0` guard in the `SKIPPED` branch ensures a source that mixes `SKIPPED` and `OK` outcomes reports `OK` (not `SKIPPED`), matching the issue's "else SKIPPED if all are SKIPPED, else OK" precedence. Substitute `_status_word(mcp_counts)`, `_status_word(tool_disc_counts)`, and `_status_word(rag_counts)` for the inline ternaries on lines 82, 85, 88. The parenthetical counts are left untouched.
