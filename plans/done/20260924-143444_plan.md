## Background
Same `docs/` reorganization effort as `docsreorg05`
(`plans/done/20260924-115855_plan.md`), `docsreorg06`
(`plans/done/20260924-130409_plan.md`), and `docsreorg07`
(`plans/done/20260924-133825_plan.md`); this Plan covers `docsreorg08`, the physical
move for the `91_security` area — a 2-file batch. Prerequisite issues `docsreorg01`
(folder-independent cross-reference resolution) and `docsreorg02` (subfolder-aware
domain checkers) have already landed. Unlike `docsreorg05`-`07`, no
`security-docs-consistency.yml` CI workflow exists — confirmed via `ls .github/workflows/
| grep -i security` (empty) — and `tools/check_docs_consistency.py`'s `DOMAIN_PREFIXES`

`overview` — confirmed via Read), so no domain-consistency check or CI path filter

`docsreorg05`, `docsreorg06`, and `docsreorg07` (this same session) each discovered
that `docsreorg01`'s basename-index resolution in `tools/check_docs_structure.py`
covers only bare-filename references, not existing relative-path (containing `/`)
references, which break when either endpoint of the reference changes its directory
depth. `docsreorg07` additionally discovered that a naive inbound-search regex can miss
an anchor-suffixed link (`.md#section`) — this Plan's own search used an
anchor-tolerant pattern from the start to avoid repeating that specific miss.
