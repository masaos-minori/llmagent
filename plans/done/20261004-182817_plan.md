# Plan: Add required service validation to AppServices constructor

## Goal
Enforce the invariant that all required services are non-None at construction time, preventing silent creation of invalid objects.

## Priority
Medium

## Scope
- **In-Scope**: Add None-check validation in `AppServices.__init__()`; update docstring to clarify optional vs required services; add regression tests
- **Out-of-Scope**: Changes to the service initialization order in factory.py; changes to the type annotations

## Background
`AppServices` in `scripts/agent/context.py` represents fully-initialized service references built by `factory.py`. Its docstring states: "All required services are non-None."

## Problem
The constructor accepts `None` for all parameters including required ones (`http`, `llm`, `tools`, `lifecycle`, `hist_mgr`, `audit_logger`). There is no runtime validation that required services are present.

## Reason for change
A caller passing `None` for a required service creates an invalid object. Errors manifest later at access time, far from the root cause. Type hints suggest required services but enforcement is absent.

## Implementation intent
Add a loop in `AppServices.__init__()` that checks each required service parameter against None and raises RuntimeError if any is missing. Update the docstring to clarify which services are optional.

## Requirements
- `REQ-001`: Constructor raises RuntimeError when any required service is None
- `REQ-002`: Test verifies error message includes the service name
- `REQ-003`: Existing callers reviewed for compatibility
- `REQ-004`: Docstring updated to clarify which services are optional vs required
