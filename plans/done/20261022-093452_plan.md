# Plan

## Goal
Add anchor validation to the shared docs link check so that a `[text](file.md#anchor)` or same-page `[text](#anchor)` link whose anchor does not match a heading in the target document is reported at Warning level, without changing the existing file-existence check or gating the existing corpus.

## Priority
Low

## Scope
- **In-Scope**:
  - Extend `check_broken_internal_links` in `tools/_docs_consistency_lib.py` to resolve the `#anchor` part against the target document's headings (cross-document and same-page links), emitting Warning findings.
  - Define the heading slug rule in code and document it.
  - Update the existing anchor-only test whose contract changes and add unit tests (valid anchor, stale anchor, same-page anchor, duplicate heading).
  - Document the check in `tools/TOOL_DESCRIPTIONS.md` and `governance_04`.
  - Run on live `docs/` and triage the finding(s).
- **Out-of-Scope**:
  - Fixing the stale anchors found on live docs (triage as a follow-up issue; docs content is not edited in this change).
  - EventBus and Shared/DB domain coverage (separate issue).
  - Changing the `related:` basename rule in `check_docs_structure.py`.
  - A blocking gate on the existing corpus.

## Background
`check_broken_internal_links` in `tools/_docs_consistency_lib.py` splits a link target into file and anchor parts through `_split_link_target`, discards the anchor, resolves only the file part, and skips pure `#anchor` links. `tools/check_docs_structure.py` matches body links with a regex that drops the anchor and verifies only that the target `.md` file exists; its `related:` entries are plain basenames. Neither tool checks that an anchor exists in the target.

## Problem
A link such as `[text](other.md#some-heading)` still passes after the heading is renamed or removed. Reading the source confirmed the gap, and a read-only prototype confirmed it on live data: of 79 anchor links in `docs/`, one points to a heading that does not exist (`mcp_03_01_dispatch-and-routing.md` links to `mcp_06_07_mcp-failure-diagnosis.md#llm-called-a-tool-but-execution-failed-with-unknown-tool`, while the live heading reads "LLM sees a tool but execution fails with \"Unknown tool\"").

## Reason for Change
The docs cleanup removes and renames sections, and "no dangling link or anchor" is an acceptance condition of that work that no tool verifies. The live finding shows the breakage already exists.

## Implementation Intent
Keep the change inside the existing shared link check (the owning tool is decided here: the shared library, because it already parses links for every domain and `check_docs_structure.py` strips the anchor in its regex). Compute a per-document set of heading slugs from the docs tree lazily, resolve each anchor against the right document, and emit a Warning for an unresolved anchor. The existing file-existence ERROR path is untouched. Same-page anchors are covered. Because the new findings are Warning severity and `report_and_exit` fails only on ERROR, existing runs keep exit 0.

## Requirements
- `REQ-001`: `check_broken_internal_links` reports a Warning for a link whose file part exists but whose `#anchor` matches no heading slug in that file, and does not report a link to an existing anchor.
- `REQ-002`: Same-page `#anchor` links are resolved against the headings of the containing document.
- `REQ-003`: The slug rule (GitHub-style: lowercase, punctuation stripped except hyphens, spaces to hyphens, markup removed, duplicate headings suffixed `-1`, `-2`, headings inside fenced code ignored) is implemented once and documented.
- `REQ-004`: The existing ERROR behavior for a missing target file is unchanged, and all existing consistency and structure checks still pass.
- `REQ-005`: Update `test_anchor_only_link_skipped` and `test_link_with_anchor_to_existing_file_no_issue` to the new contract (the second one links to an anchor in a file that has no such heading) and add unit tests for valid anchor, stale anchor, same-page anchor, and duplicate heading.
- `REQ-006`: Document the check (Warning, report-only, slug rule, same-page coverage) in `tools/TOOL_DESCRIPTIONS.md` and `governance_04`.
- `REQ-007`: Run on live `docs/` and triage the findings (fix or follow-up issue), starting with the one confirmed stale anchor.

## Design
- Path B (more than three files; behavior change in a library shared by nine other tools).
- Owning-tool decision: the shared library. `check_docs_structure.py` strips the anchor in its link regex and indexes documents by basename, and the library function already splits the anchor and runs for every domain.
- Contract change: `check_broken_internal_links` currently treats a pure `#anchor` link as skipped; this Plan changes that to a resolved Warning, so the existing test is replaced rather than preserved.
- Headings are collected per target file from the docs tree (the function already enumerates `docs_dir.rglob("*.md")`) with fenced code stripped; slugs are computed once per file and cached for the run.
- Severity: Warning for anchors, ERROR kept for missing files. `--skip links` skips both because they share one function; a separate skip option is not added to avoid touching `check_docs_consistency.py`.
