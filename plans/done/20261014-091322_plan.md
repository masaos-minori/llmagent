- **Out-of-Scope**: deleting `skills/` or `skills/DESIGN.md`; changing `_ephemeral` / `_memory_injected` semantics or the turn-start clearing order; adding entries to `_REMOVED_NAME_PATTERNS` in `tools/check_compat_shims.py`; editing archived files under `issues/done/`, `plans/done/`, `requires/done/`, `implementations/done/`; `memo2.md`.

## Background
`/skill <name>` appends `skills/<name>/SKILL.md` as a system message tagged `_ephemeral` and `_skill_ephemeral`. No ADR defines it. The source Issue was adversarially verified before this Plan; its findings are re-checked in this cycle (Repository Evidence below). Upstream rebase (88972412f) did not change any target file's relevant lines.

## Problem
- The documented behavior ("passes the content to the next LLM turn") does not occur: `_process_turn` calls `clear_previous_turn_ephemeral_messages()` first (`scripts/agent/workflow_engine_adapter.py:379`), and `_skill_ephemeral` is in `_EPHEMERAL_KEYS` (`scripts/agent/conversation_state_manager.py:30-32`), so the skill message is removed before `handle_llm_turn`. Reproduced by script in the Issue cycle: history is non-empty after `/skill`, empty after the turn-start clear.
- AGENT-009 and `agent_07_10` state the opposite (message not cleared); both are stale.
- `/skill` arguments are appended to a system-role message without injection filtering (`scripts/agent/commands/cmd_skill.py:38-40`).
- The feature requires a dedicated marker and trusted source (`scripts/agent/message_schema.py:21`, `scripts/shared/types.py:31`).

## Reason for change
The command cannot work without redesigning turn-boundary clearing, and its purpose is covered by asking in the user message (the model reads the file through file-read tools), a `/system` preset, or MDQ indexing of `skills/`. Deleting it removes a silently non-functional command, one untrusted-input path, one marker, one trusted source, and a stale ledger entry.

## Implementation intent
Delete only the feature and its dedicated plumbing. Keep `skills/`, `_ephemeral`, `_memory_injected`, and the clearing order unchanged. No backward-compat alias: typing `/skill` falls through to the existing unknown-command warning. Edit mixed test files in place; the unregistered-command test is the real regression guard because `_REMOVED_NAME_PATTERNS` scans `*.md` only and is opt-in.
