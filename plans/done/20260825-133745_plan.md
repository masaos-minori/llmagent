## Background
ADR-008「SQLite 4DB Separation」は rag.sqlite/session.sqlite/workflow.sqlite/eventbus.sqlite の4つを独立した永続化ドメインとして定義している。`scripts/db/rotation.py` の `rotate_all_dbs()` は rag/session/workflow の3DBのみをアーカイブし、eventbus.sqlite 用の rotate 関数がリポジトリ全体に存在しない。

## Problem
- `scripts/db/rotation.py` の全文を確認した結果、`rotate_session_db()`（line 51-54）、`rotate_workflow_db()`（line 56-59）に対応する `rotate_eventbus_db()` は存在せず、`rotate_all_dbs()`（line 61-67）も rag/session/workflow の3つのみを呼び出し・返却している。
- `DbConfig`（`scripts/db/config.py`）には既に `eventbus_db_path: str = "/opt/llm/db/eventbus.sqlite"` フィールドが存在し、他の3DBパスと同様に `build_db_config()` から取得可能であることを確認済み。
- `rotate_all_dbs()` の呼び出し元をリポジトリ全体で grep した結果、本番コードからの実呼び出しは存在せず（`scripts/db/maintenance.py` のモジュール docstring 内のコメント記載のみ）、実際に3タプルを分解して使用しているのは `tests/db/test_db_maintenance.py:976`（`test_rotate_all_dbs_archives_all_three`）のみであることを確認済み。戻り値タプルの拡張による影響範囲は限定的。

## Reason for change
ADR-008 の設計意図どおり、eventbus.sqlite が標準の DB メンテナンス手順（rotate_all_dbs 経由のアーカイブ）から漏れている状態を解消する。障害復旧手順が `rotate_all_dbs()` に依存している場合、現状では eventbus データが未アーカイブのまま残る。

## Implementation intent
`rotate_session_db()`/`rotate_workflow_db()` と同一パターンで `rotate_eventbus_db()` を追加し、`rotate_all_dbs()` の戻り値を `tuple[Path, Path, Path, Path]`（rag, session, workflow, eventbus の順）に拡張する。

## Requirements
- `REQ-001`: `scripts/db/rotation.py` に `rotate_eventbus_db(archive_dir: str | Path | None = None) -> Path` を追加する。実装は `rotate_workflow_db()` と同一パターン（`build_db_config()` → `db_cfg.eventbus_db_path` → `_archive_db_file()`）。
- `REQ-002`: `rotate_all_dbs()` の戻り値を `tuple[Path, Path, Path, Path]` に拡張し、`rotate_eventbus_db()` の呼び出しを追加する。docstring も4DB構成に更新する。
- `REQ-003`: `scripts/db/__init__.py` に `rotate_eventbus_db` のインポート・`__all__` 登録を追加する。
- `REQ-004`: `scripts/db/maintenance.py` のモジュール docstring 内の `rotate_all_dbs()` 説明コメントを4DB構成に更新する。
- `REQ-005`: `tests/db/test_db_maintenance.py` の `test_rotate_all_dbs_archives_all_three`（line 963-984）を4タプル前提に更新し、`test_rotate_all_dbs_missing_workflow_raises`（line 996-1009）と対になる eventbus 版のテスト、および `rotate_eventbus_db()` 単体の正常系テストを追加する。

## Design
`rotate_eventbus_db()` は `rotate_workflow_db()` と完全に同一の構造（`build_db_config()` → 該当パス取得 → `_archive_db_file()` 呼び出し）を踏襲する。`rotate_all_dbs()` の戻り値順序は既存の `(rag, session, workflow)` の後ろに `eventbus` を追加し `(rag, session, workflow, eventbus)` とする（既存順序を変更しないことで、万一の呼び出し元への影響を最小化）。
