## Background
ADR-012（Status: Proposed）Decision #6 は、git コマンドが非ゼロ終了で失敗する基本保証（既に `_wrap_git_op()` の `except _GIT_ERRORS` で担保済み）とは別に、「実際に意図した状態に到達したか」という低レベルの後条件確認を求めている。この差異は ADR-012 自身の Known Deviations に `GIT-002` として既に登録済みである。

## Problem
- `scripts/mcp_servers/git/format_output.py` の `format_checkout()`（line 118-133）、`format_pull()`（line 136-147）、`format_push()`（line 150-156）を確認した結果、いずれも GitPython 呼び出し後、戻り値の有無のみで成功メッセージを組み立てており、以下の後条件検証が存在しない：
  - `format_checkout()`: `repo.git.checkout("--", req.branch)` 実行後、実際に `repo.active_branch.name == req.branch` かつ `not repo.head.is_detached` であることの確認なし
  - `format_pull()`: `repo.git.pull(*pull_args)` 実行後、`repo.index.unmerged_blobs()` によるコンフリクト残存確認なし（`git pull` がコンフリクトで非ゼロ終了する通常ケースは `_wrap_git_op` で捕捉されるが、マージが完了した体裁で終了コード0を返しつつ未解決コンフリクトマーカーが残るような境界事例は捕捉されない）
  - `format_push()`: `repo.git.push(req.remote, "--", branch)` 実行後、push 結果の追加検証なし（生CLI呼び出しのため非ゼロ終了時は既に例外化されるが、ADR-012 Decision #6 は「終了コード確認と同一の保証ではない」ことを明示的に要求している）
- `GitServiceError`（`scripts/mcp_servers/git/git_models.py:66`）は既に `format_output.py` にインポート・使用済み（`format_commit()` の "nothing staged to commit" チェック、line 113）であり、本 Plan の後条件検証失敗時にも同じ例外クラスを再利用できることを確認した。

## Reason for change
ADR-012 Decision #6 が要求する後条件検証が未実装のまま Known Deviations `GIT-002` として残っている。Git write 操作の結果が意図通りであることを、終了コード確認とは独立した層で保証する。

## Implementation intent
`format_checkout()`/`format_pull()`/`format_push()` の各関数末尾（成功メッセージ生成前）に後条件検証を追加し、検証失敗時は `GitServiceError` を送出する。

## Requirements
- `REQ-001`: `format_checkout()` に、`checkout`/`create_head`+`checkout()` 実行後、`repo.active_branch.name == req.branch` かつ `not repo.head.is_detached` であることを検証するコードを追加する。不一致の場合 `GitServiceError` を送出する。
- `REQ-002`: `format_pull()` に、`repo.git.pull()` 実行後、`repo.index.unmerged_blobs()` が空であることを検証するコードを追加する。未解決コンフリクトが残る場合 `GitServiceError` を送出する。
- `REQ-003`: `format_push()` に、push 実行後の結果文字列に既知の拒否マーカー（例: `"[rejected]"`, `"non-fast-forward"`）が含まれていないことを確認するコードを追加する。含まれる場合 `GitServiceError` を送出する。
- `REQ-004`: `tests/mcp_servers/git/test_format_output.py` に、各後条件検証が正常系（検証成功）と異常系（検証失敗 → `GitServiceError`）の両方でテストされるケースを追加する。

## Acceptance criteria
- AC-01（REQ-001対応）: checkout 後にブランチ不一致（またはDetached HEAD）が検出された場合に `GitServiceError` が送出されることをテストで確認できる。
- AC-02（REQ-002対応）: pull 後に未解決コンフリクト（`unmerged_blobs()` が非空）が残る場合に `GitServiceError` が送出されることをテストで確認できる。
- AC-03（REQ-003対応）: push 結果文字列に拒否マーカーが含まれる場合に `GitServiceError` が送出されることをテストで確認できる。
- AC-04: 正常系（checkout/pull/push が意図通り完了するケース）で従来通りの成功メッセージが返ることを確認できる（回帰防止）。

## Assumptions
- `git pull`/`git checkout`/`git push` が非ゼロ終了した場合の基本的な失敗検知は `scripts/mcp_servers/git/git_service.py:_wrap_git_op()` の `except _GIT_ERRORS` で既に担保されている。本 Plan が追加するのは、終了コード0でも意図した状態に到達していない境界事例を検出する追加の防御層であり、現時点で確認された具体的な悪用可能な脆弱性への対処ではなく、ADR-012 Decision #6 が要求する後条件確認の実装である。
- `format_push()` の拒否マーカー検出は、`repo.git.push()`（生CLI呼び出し）の標準出力・標準エラー文字列に基づく簡易検出であり、100%網羅的ではない。より厳密な検証（porcelain API `repo.remote().push()` の `PushInfo.flags` 確認）への置き換えは Out-of-Scope とした（Scope 参照）。

## Design
各後条件検証は「GitPython呼び出し → 検証 → 成功メッセージ生成」の順に既存関数内へ挿入する。検証失敗時は既存の `GitServiceError`（`format_commit()` の前例と同じ例外クラス）を送出し、`git_service.py:_wrap_git_op()` の `except _GIT_ERRORS` で捕捉されるかを確認する（`GitServiceError` が `_GIT_ERRORS` に含まれるか実装時に確認する）。
