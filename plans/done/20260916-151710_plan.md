## Goal
- Add a new, dedicated `tools/check_*.py` script that mechanically validates `docs/00_governance_03_issue-and-uncertainty-management.md` Part 1/Part 2 vocabulary, template conformance, and intra-document referential integrity; register it in the Governance Verification Matrix (reconciled with the already-reserved `GV-008` slot, not a duplicate); wire it into CI; and fix the one confirmed dangling reference found during this Plan's own verification.

## Background
This Plan is derived from `issues/20260915-200449_gov03_add-conformance-and-referential-integrity-checks-for-the-issue-inventory.md`, itself derived from a consolidated governance-documentation audit (`memo3.md`, repository root — not used as evidence in this Plan per standing instruction to exclude that file).

## Problem
`docs/00_governance_04_documentation-checks.md` defines a substantial battery of automated documentation checks, but none of them validates `docs/00_governance_03_issue-and-uncertainty-management.md` Part 1 field values or cross-entry references. A manual review pass found six classes of defects mechanical checking would have caught, and a specifically-relevant automated check (`check_docs_quality.py::check_resolved_in_active`) already exists but does not work against this document (see Assumptions).

## Reason for change
The document that adjudicates correctness for every other document in the repository is itself unchecked; this Plan makes its own rules executable so conformance is enforced at merge time.

## Implementation intent
Implement a single new parser-based script (per the source issue's own constraint: "one parser for both vocabulary and reference validation"), modeled on the closest existing analogue — `tools/check_known_deviation_sync.py` (the same ID-resolves-to-a-heading problem, one document hop removed: ADR→governance-doc rather than intra-governance-doc) and `tools/check_needs_confirmation_inventory.py` (Part 2 parsing pattern) — reusing `tools/_docs_consistency_lib.py`'s shared `DocFile`/`Issue`/`report_and_exit` helpers. Register it against the Governance Verification Matrix's existing `GV-008` slot rather than creating a second, overlapping Rule ID, since `GV-008` already reserves tracking for "Known Issue required fields" against this same document.

## Risks
- **Risk**: `check_docs_quality.py::check_resolved_in_active` already exists, appears purpose-built for exactly this document's "resolved item retained as active" defect class, but silently does nothing against it (heading mismatch: `## Active Issues` vs. this document's actual `### Active Items`). - **Risk**: `docs/00_governance_03` has 29 prior modifying commits in its history — a high-churn document. A checker whose parser assumes today's exact heading/field conventions could go stale quickly. → **Mitigation**: REQ-001 explicitly requires parsing the document (per the source issue's own Constraint) rather than hardcoding the entry list, and reuses `tools/_docs_consistency_lib.py`'s existing, already-battle-tested parsing primitives rather than inventing new ones.
- **Risk**: Updating `GV-008` in place (REQ-004) rather than adding a new Rule ID is a judgment call a reviewer could see differently. → **Mitigation**: Justified directly by `GV-011`/`GV-012`'s own existing anti-duplication principle for canonical sources, applied here by analogy to rule-tracking slots; the Governance Verification Matrix's own doc-consistency checker (`tools/check_docs_consistency.py --domain overview` or equivalent) would otherwise need to reconcile two overlapping rows for the same document later.
