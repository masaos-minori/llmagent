## Goal
- Make the ToolLoopGuard-triggered final-answer fallback stream to the turn's real LLM URL instead of the uninitialized empty `self.llm_url`, so a guard-blocked turn degrades to a final answer instead of surfacing an `LLMTransportError`.

## Priority
Medium

  - Thread the turn's real `llm_url` into the guard-triggered final-answer path in `scripts/agent/llm_turn_runner.py`.
  - Add/adjust a unit test in `tests/agent/test_llm_turn_runner.py` that verifies the final-answer path streams to a non-empty URL and fails if the URL is reverted to `""`.
- **Out-of-Scope**:

  - Updating `docs/*.md` or `deploy.sh`.

## Background
`LLMTurnRunner` (`scripts/agent/llm_turn_runner.py`) streams one LLM response per turn in two places:
- `_stream_llm(llm_url, turn)` — used by the main tool-call loop in `run()`. It takes `llm_url` as a parameter and passes it to `ctx.services_required.llm.stream(...)`.
- `_stream_llm_final_answer()` — used only by `_finalize_after_guard()`, the graceful-degradation path when `ToolLoopGuard.check_all()` returns a block message (dedup / cycle / retry / stagnation / empty-result / error-limit). It calls `ctx.services_required.llm.stream(self.llm_url, ...)`.

`self.llm_url` is set to `""` in `LLMTurnRunner.__init__` and is never reassigned to a real value anywhere in `scripts/`. The real URL is available as the `llm_url` parameter to `run()` and as `ctx.conv.llm_url` (set at startup in `scripts/agent/startup_component_init.py`).

## Problem
The guard-triggered final-answer path reads the stale, empty `self.llm_url` instead of the turn's real URL. Streaming to an empty URL fails with `LLMTransportError` (via `LlmReconnectHandler.stream` -> `LlmSseStreamHandler.stream_once(http, "", ...)`), so instead of producing a best-effort final answer the turn surfaces a transport error to the operator.

## Reason for change
The guard fallback exists precisely so a turn can degrade gracefully to a final answer when the LLM keeps requesting the same/failed tool calls. With the empty URL, that degradation path is broken: every guard block currently ends in a surfaced transport error rather than a final answer. This is a correctness defect on a live runtime path. It is not caught by existing tests because `tests/agent/test_llm_turn_runner.py` asserts `stream.assert_awaited_once_with(runner.llm_url, ...)` — which passes even when `runner.llm_url` is `""`.

## Implementation intent
Ensure the final-answer fallback uses the same LLM URL as the normal turn. Implement exactly one of these minimal approaches (no second code path):
- Assign `self.llm_url = llm_url` at the start of `run()` so the instance attribute reflects the current turn, OR
- Pass the turn's `llm_url` into `_stream_llm_final_answer` (and thus into the final stream call), OR
- Read the configured URL directly via `ctx.conv.llm_url` in `_stream_llm_final_answer`.

The recommended approach is the first (assign in `run()`); see Design. Keep the change confined to `scripts/agent/llm_turn_runner.py`.
