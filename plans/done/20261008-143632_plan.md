## Goal
- Make a workflow definition load failure a fatal startup error instead of a silent fallback mode, remove the fallback path and the unused backward-compatibility wrappers from the Orchestrator, fix its misleading docstrings, and update the tests and documentation that record the fallback as a Known Issue.

## Priority
Medium

## Scope
- **In-Scope**: the Orchestrator constructor and turn entry point (fallback removal, error raised with the file path and cause); the module and class docstrings; removal of the delegating compatibility wrappers after their test callers are rewritten; new failure tests; removal of Known Issue AGENT-003 and the ADR records that cite it.
- **Out-of-Scope**: workflow engine internals; approval policy enforcement in configuration validation (a separate issue; the default workflow file sets `require_approval` to false); changing other startup validation; the startup preflight beyond what the tests need.

## Background
ADR-001 makes the Workflow Engine mandatory and forbids a fallback path (Decision 4); ADR-004 requires fail-fast for a missing or invalid workflow (INV-03). AGENT-003 records that the Orchestrator catches load errors and continues with a stage-less sentinel definition. The Issue rated this High on the assumption that fallback mode lets tools run without approval.

## Problem
- Verified in code: the constructor catches the loader error and the missing-file error, logs a warning, sets a fallback flag, and uses a sentinel definition with no stages and the approval gate off; `handle_turn` reports an error and still executes the turn.
- Verified: the startup preflight only checks that the default workflow file exists, so a malformed file passes the preflight and reaches the fallback.
- The Issue's top-priority question is answered: fallback mode does not remove approval that normal operation provides. The shipped default definition also sets the workflow-level approval gate to false, and per-tool approval is a separate mechanism that stays active in both modes. What fallback does lose is the configured stage timeouts and retry policy (the engine falls back to a fixed default timeout when a stage is undefined) and operator visibility. The violation of ADR-001 Decision 4 and ADR-004 INV-03 stands, so the change is still required, but the "approval bypass" rationale does not hold; the priority is therefore set to Medium here (the Issue and the ledger give High and Medium respectively; see UNK-01).
- Documentation (the agent overview, runtime architecture, turn-flow overview, and API reference) already states that a load failure raises a runtime error and stops startup, which is the intended behavior and not what the code does.
- The module docstring names a coordinator module that does not exist in the package (a stale name), duplicates the component list, and says the facade preserves the old private surface "for backward compatibility"; about a dozen delegating wrappers remain, called only from two test modules (about 60 call sites) and from no production code.

## Reason for change
A silently degraded Agent contradicts two ADRs and hides misconfiguration from operators; the stale docstrings and compatibility wrappers contradict the repository's no-compatibility-layer policy.

## Implementation intent
- Remove the fallback rather than gating it: the constructor raises a runtime error naming the workflow file and the cause; `handle_turn` loses its fallback branch; the sentinel and flag disappear.
- Rewrite each test that calls a wrapper to call the owning component (or the public entry point), then delete the wrappers; keep tests' intent and assertions.
- Add tests: construction fails with a runtime error for a missing and a malformed definition (no engine is built, no turn runs).
- Update records: remove AGENT-003 from the ledger and from ADR-001 and ADR-004 Known Deviations, and correct the ADR-004 supporting text that lists the Orchestrator sentinel fallback as an unresolved path.

## Requirements
- `REQ-001`: A load failure of the workflow definition (missing or malformed) raises a runtime error from the Orchestrator constructor whose message contains the definition file path and the underlying cause; no fallback definition, flag, or fallback branch remains in code.
- `REQ-002`: The module and class docstrings name only components that exist, list them once, and no longer describe backward-compatible wrappers.
- `REQ-003`: The delegating compatibility wrappers are removed after their test callers are rewritten to call the owning components directly; no production caller exists.

- `REQ-006`: All existing tests pass; lint, format, type, security, and doc checks introduce no new findings.
