# Plan: Remove dead outer AsyncClient and unused client param in HTTP MCP startup poll

## Goal
Eliminate the unused `httpx.AsyncClient` opened in `HttpServerLifecycleManager.start()` (which is shadowed and never used inside `_health_poll_until_ready()`) and drop the now-unused `client` parameter from `_health_poll_until_ready()`, with no change to health-poll timing, timeouts, or failure semantics.

## Priority
Low

## Scope
- **In-Scope**:
  - Remove the outer `async with httpx.AsyncClient(...)` wrapper in `start()`.
  - Drop the unused `client: httpx.AsyncClient` parameter from `_health_poll_until_ready()` and its docstring.
- **Out-of-Scope**:
  - Any change to health-check logic, timeout computation, or the `HealthChecker` module.
  - Refactoring other lifecycle methods.
  - Adding/removing env-var handling.

## Background
`HttpServerLifecycleManager.start()` (scripts/agent/http_lifecycle.py) launches an HTTP MCP subprocess and polls `/health` until ready. It delegates polling to `_health_poll_until_ready()`. In `start()`, when `cfg.startup_timeout_sec > 0`, an outer `async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=MCPSERVER_HEALTH_TIMEOUT))` is opened and its `client` is passed to `_health_poll_until_ready()`. That method ignores the argument and immediately opens its own client via `async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=hc_timeout)) as client:`, where `hc_timeout = self._health_checker.compute_health_check_timeout(...)`.

## Problem
The `client` argument passed from `start()` is never referenced inside `_health_poll_until_ready()`; the method re-binds `client` to its own `async with` context. Consequences:
- Every successful HTTP-MCP startup opens one extra `AsyncClient` that performs no request, then closes it — wasted connection-setup work on the hot startup path.
- The `client` parameter is misleading: readers assume the caller's client drives the polls.
- `MCPSERVER_HEALTH_TIMEOUT` backs the dead outer client, while the real client uses `compute_health_check_timeout(...)` — so the outer block's timeout is meaningless.

## Reason for change
Dead resource setup on the startup path and a misleading signature invite confusion and future bugs (e.g., someone "fixing" the timeout on the wrong client). Removing it makes the actual client authoritative and removes wasted connection setup.

## Implementation intent
Delete the outer `async with httpx.AsyncClient(...)` block in `start()` and stop passing a client to `_health_poll_until_ready()`. Drop the `client` parameter (and its docstring `Args:` entry) from `_health_poll_until_ready()`. Keep the single authoritative client inside `_health_poll_until_ready()` unchanged, and preserve the `cfg.startup_timeout_sec > 0` guard and the skip log. No behavior change to polling, timeouts, or error handling.

## Requirements
- `REQ-001`: Remove the outer `async with httpx.AsyncClient(...)` wrapper in `start()` and call `_health_poll_until_ready()` without a client argument.
- `REQ-002`: Drop the unused `client: httpx.AsyncClient` parameter (and its docstring `Args:` entry) from `_health_poll_until_ready()`.
- `REQ-003`: Preserve all behavior — the health-poll loop, deadline handling, `shutdown_event` interrupt racing, `compute_health_check_timeout` timeout computation, failure semantics, and the `cfg.startup_timeout_sec > 0` guard. Do not change observable behavior.
