# Plan: Remove duplicate document-management code and regenerate RAG runtime data

## Goal

Delete the dead, duplicate `_handle_existing_file()` method from
`scripts/rag/ingestion/document_manager.py` (leaving `handle_existing_document()` as the
single authoritative file-URL SHA-256 skip/replace decision path), close a real gap in its
regression coverage, and define the gated, one-time operational procedure to delete and
regenerate RAG runtime data (`rag-src/*`, `rag.sqlite`) once the three prerequisite strict-
contract requirements have been implemented and deployed.

## Scope

**In-Scope:**
- Delete `_handle_existing_file()` (lines 104-132) from
  `scripts/rag/ingestion/document_manager.py`.
- Add a regression test to `tests/rag/ingestion/test_ingestion_freshness.py` that exercises
  the "changed SHA-256 -> replace" outcome through the real `DocumentManager.
  handle_existing_document()` (not a mock) — this specific outcome is not currently covered
  against the real object (see Unknowns UNK-03).

  `tests/rag/ingestion/test_rag_ingestion_pipeline.py:68`, which names the about-to-be-deleted
  `_handle_existing_file` even though the fixture it documents actually exercises
  `handle_existing_document()`'s SQL access pattern.
- Define the gated Phase 4 operational runbook (stop processes, delete runtime data, recreate
  schema, re-run Crawler -> ChunkSplitter -> Ingester, verify consistency and `fetched_at`)
  for execution only after the three dependency requirements are implemented and deployed.

**Out-of-Scope:**
- Any change to `handle_existing_document()` or `_is_file_unchanged()` — both remain exactly
  as implemented today.
- Implementing the three dependency requirements themselves (`requires/done/20260819-144406_

  require.md`) — each is tracked by its own plan
  (`plans/20260820-094150_plan.md`, `plans/20260820-095054_plan.md`,

- Actually executing the Phase 4 regeneration against `/opt/llm/` during this planning cycle —
  it is a future, explicitly gated implementation action.
- `docs/*.md` updates — this document-only phase does not touch documentation; the "record
  the exact commands" instruction is satisfied by the runbook step names in this plan, not by
  editing any `docs/*.md` file.

## Design

No architectural change. `handle_existing_document()` (lines 48-102) already contains the
complete, correct file-URL SHA-256 skip/replace decision (verified by direct read: same
`_is_file_unchanged(...)` call, same two log messages, at lines 75-89) and is the method every
current caller (`ingester.py`) actually invokes. `_handle_existing_file()` is a byte-for-byte
behavioral duplicate with zero callers; removing it is a pure deletion with no ripple into
`_is_file_unchanged()` (line 145, unchanged) or its five existing direct unit tests
(`TestIsFileUnchanged`, lines 18-46 of `test_ingestion_freshness.py`).

The Phase 4 regeneration is operational, not architectural: it re-runs the existing
Crawler -> ChunkSplitter -> Ingester pipeline and the existing schema-creation code
(`scripts/db/create_schema.py` via `deploy/init_db.sh`) against the current, unmodified
source set. No new schema, module, or interface is introduced.

## Risks

- **Risk**: Executing Phase 4 before the three dependency requirements are actually
  implemented and deployed would delete production RAG data and regenerate it under the old
  permissive contracts, defeating the purpose. → **Mitigation**: explicit precondition check
  against deployed source (not just plan-document existence) is the first Phase 4 step; Phase
  4 is documented as gated in this plan.
- **Risk**: `rag.sqlite` deletion at `/opt/llm/db/rag.sqlite` is irreversible once executed,
  with no backup step named in the source requirement. → **Mitigation**: added a timestamped
  backup-copy step before deletion in Phase 4.
- **Risk**: Full-corpus Crawler re-run makes live HTTP requests to every target URL and may
  hit rate limits, take a long time, or incur embedding cost during Ingester's run. →
  **Mitigation**: run Phase 4 during a maintenance window; rely on the existing
  `crawl_delay`/`fetch_retry` config in `config/crawler.toml` rather than introducing new
  throttling logic.
- **Risk**: The stale `_handle_existing_file` reference in
  `tests/rag/ingestion/test_rag_ingestion_pipeline.py:68` is comment-only and low severity, but
  if left unfixed will misdescribe the code after deletion. → **Mitigation**: included as an
  explicit Phase 2 step in this plan.
- **Risk**: Low bus factor (single primary author) on `document_manager.py` means limited
  independent review bandwidth. → **Mitigation**: none beyond standard code review; noted for
  awareness, not blocking given the change is a pure, well-tested deletion.
