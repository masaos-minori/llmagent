**Test infrastructure constraint (evidence: `tests/eventbus/test_eventbus_replay_subscribe.py:84-88` docstring)**: `test_subscribe_yields_matching_event` documents that `httpx.ASGITransport` blocks on `response_complete` for infinite SSE generators, so this codebase's existing convention is to test `/subscribe`'s internals directly (e.g. `_row_to_dict`, the DB query) rather than driving the endpoint end-to-end through `TestClient`. **Prior fix attempt (evidence: `git log`/`git show`, verified 2026-08-18)**: `implementations/done/20260727-025628_subscribe_route.py.md` already proposed a fix for this same pyright finding, and commit `98f99309f` (2026-07-28) implemented part of it — changing `_sse_gen()`'s return type from `Any` to `AsyncGenerator[str]` and refining the runtime guard from `"replay_ceil" in dir()` to `locals().get("replay_ceil") is not None`. - **Risk**: Moving the initialization could mask a future real "used before assigned" bug if the function is refactored later (Likelihood: low) → **Mitigation**: keep the initialization directly adjacent to `start_seq`'s definition with a short comment explaining why it must be unconditional (mirrors the fallback value the removed `locals()` guard used to provide).
- **Risk**: New test could be flaky if it relies on timing to trigger cancellation before replay completes, or could silently no-op if driven through `TestClient`'s HTTP layer (which blocks on infinite SSE generators per the `httpx.ASGITransport` constraint in Section 5) (Likelihood: medium) → **Mitigation**: drive the `_sse_gen()` async generator directly via `subscribe()`'s returned `StreamingResponse.body_iterator` and `athrow(asyncio.CancelledError())` (deterministic, no timing dependency, no HTTP transport involved), matching the existing direct-internals testing convention already used in `test_subscribe_yields_matching_event`.
