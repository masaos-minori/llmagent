## Goal
- Make ADR-013 describe EventBus authentication and authorization as it is actually wired, record the two real gaps (shared tokens granting every role; `/health` and `/publish` registered without any role dependency), and register the second gap as a new Known Issue so the ADR can cite it.

## Priority
High

## Scope
- **In-Scope**: ADR-013 sections (Assumptions, Context, Decision 1, Rationale 4, Consequences, Invariants, Failure Policy, Verification, Known Deviations, Implementation References, approval record); registration of one new Known Issue in the ledger; the size ceiling for the ledger in the structure checker.
- **Out-of-Scope**: fixing authentication in code; removing the `auth_token` requirement; editing other EventBus documents or the security architecture document (reported only); changing roles or routes.

## Background
memo2.md proposed the ADR-013 corrections (review findings H09, M24). The Issue claims `/health` requires the Monitoring role per the EventBus health reference; the Issue was verified adversarially against the real application wiring.

## Problem
- Decision 1 says a middleware checks the Authorization header; the middleware only assigns a request ID, and roles are resolved by endpoint dependencies.
- The Positive Consequences claim per-role tokens make the five-role model enforceable, while the mandatory shared token and the admin token grant every role.
- Failure Policy says `/health` stays open for monitoring, contradicting the EventBus health reference (Monitoring role required).
- New finding: in the production application, `/health` and `/publish` are registered without any role dependency (route introspection shows no dependency on either; the handlers call no authentication helper), so INV-01 ("all routes reject unauthenticated requests") does not hold for them. The existing authentication tests build their own fixture app with its own dependencies, so they do not prove the production wiring.
- Assumptions carries a historical reference to a source issue.

## Reason for change
ADR-013 is the reference for EventBus security decisions; it asserts guarantees (all routes authenticated, five-role enforcement, middleware-based checks) that the code does not provide. A Decision change also triggers the governance_01 approval requirement.

## Implementation intent
- Document current behavior and keep the intended policy visible: state the intended Monitoring/Publisher requirements, and record the gap as a Known Deviation instead of silently aligning the ADR to the buggy behavior.
- Register the new defect with the ledger's Entry Template and cite it from the ADR.
- Keep the ledger ceiling policy: raise the structure checker's ceiling for the ledger to its new accepted size, as done earlier in this series.

## Requirements
