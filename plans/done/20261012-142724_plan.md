## Goal
- Restore the concrete types at the boundaries of the memory-service builder helpers in `scripts/agent/factory.py`, so that passing `None` or a wrong object to a builder is rejected by `mypy` instead of surfacing later as an `AttributeError`, with no runtime behavior change.

## Priority
Low

## Scope
- **In-Scope**:
  - Replace the `object` annotations on the builder parameters with the concrete memory types (`EmbeddingClient`, `HybridRetriever`, `MemoryStore`, `JsonlMemoryStore`).
  - Remove the one `= None` default that exists (`embed_client` of the retriever builder).
  - Give the two builders that return `object` their concrete return types, and type their class parameters accordingly, because `mypy` requires it (see Problem).
  - Name the concrete types through the existing `TYPE_CHECKING` block so no import runs at module load.
- **Out-of-Scope**:
  - Changing `_build_memory_services` call sites, call order, or how `MemoryServices` is assembled.
  - Any non-memory builder in `factory.py`.
  - The lazy imports inside `_build_memory_services`, and the bare `type` parameters of the policy and dedup classes.
  - New runtime tests: the change is type-only and is verified by `mypy`.

## Background
- `_build_memory_services` constructs `MemoryServices` through five helpers that take previously built instances. Four of them annotate those instances as `object`; two return `object`.
- Issue `issues/20261012-124821_start002_memory-service-builders-in-factory.py-erase-concrete-types-with-object-annotations-and-none-defaults.md` asks to restore the concrete types and drop unused `None` defaults.

## Problem
Verified against current source (`Confirmed by repository evidence`):
- **Erased parameter types (confirmed)**: `_build_retriever` (`embed_client: object = None`), `_build_injection_service` (`embed_client: object`, `retriever: object`) and `_build_ingestion_service` (`store`, `jsonl`, `retriever`, `embed_client`, all `object`) are in `scripts/agent/factory.py` lines 576 to 637. The downstream constructors declare concrete types: the injection service takes `retriever: HybridRetriever` and `embed_client: EmbeddingClient`; the ingestion service takes `store: MemoryStore`, `jsonl: JsonlMemoryStore`, `retriever: HybridRetriever`, `embed_client: EmbeddingClient`.
- **Correction to the Issue (`None` defaults)**: the Issue says "some of them" have a `= None` default. Only one does, `embed_client` of `_build_retriever`. The other defaults in these helpers are `branch: str = ""`. The retriever builder has exactly one caller (`_build_memory_services`, line 527), which always passes a real client, and no test calls it. The underlying `HybridRetriever` itself accepts `EmbeddingClient | None`; that contract is not changed here.
- **Correction to the Issue (scope is wider)**: `_build_embedding_client` and `_build_jsonl_store` return `object`, and take bare `type` class parameters. The Issue's Required Changes only annotate parameters. Experiment on a scratch copy of `scripts/`:
  - typing the parameters concretely and the two returns concretely, with `type[EmbeddingClient]` and `type[JsonlMemoryStore]` for the class parameters, gives `mypy` clean (425 files) and `ruff` clean;
  - typing the returns but keeping the bare `type` class parameters gives two `no-any-return` errors (`warn_return_any = true` in `pyproject.toml`), at the two builders;
  - leaving the returns as `object` would make `_build_memory_services` pass an `object` where the typed parameters expect `EmbeddingClient` and `JsonlMemoryStore`, which `mypy` rejects.
  So the returns and the two class parameters must be typed for `mypy` to stay clean, which the Issue's own constraint requires.
- **The check works (confirmed by run)**: with the typed signatures, changing the caller to pass `embed_client=None` to the retriever builder is reported by `mypy` as `arg-type` ("expected EmbeddingClient").
- **Lazy imports can stay**: `factory.py` already has `from __future__ import annotations` and a `TYPE_CHECKING` block (one name today), so the concrete types can be named there without an import at load time; `_build_memory_services` keeps its own deferred imports. No code in `scripts/` evaluates these annotations at runtime.

## Reason for change
- Builder boundaries are the cheapest place to reject a wrong argument; `object` accepts anything, including `None`, and says nothing to the reader.
- The change is type-only and verified by the type checker the project already runs in pre-commit and CI.

## Implementation intent
- Add the four memory types to the existing `TYPE_CHECKING` block and use them in the signatures of the five builders; do not add runtime imports.
- Make the retriever builder's `embed_client` a required keyword-only `EmbeddingClient` (no default), since its only caller always supplies one.
- Give `_build_embedding_client` the return type `EmbeddingClient` with `client_cls: type[EmbeddingClient]`, and `_build_jsonl_store` the return type `JsonlMemoryStore` with `jsonl_cls: type[JsonlMemoryStore]`.
- Leave every call site, every function body, and the generic `type[T]` parameters unchanged.

## Requirements
- `REQ-001`: The parameters of `_build_injection_service`, `_build_ingestion_service` and `_build_retriever` that are annotated `object` are annotated with their concrete memory type.
- `REQ-002`: The `= None` default of the retriever builder's `embed_client` is removed (parameter stays keyword-only and required); no `X | None` is introduced.
- `REQ-003`: `_build_embedding_client` and `_build_jsonl_store` return their concrete type and take `type[EmbeddingClient]` and `type[JsonlMemoryStore]` as their class parameter, so `mypy` stays clean under `warn_return_any`.
- `REQ-004`: No behavior change: function bodies, call sites and call order are untouched; the concrete types are named only under `TYPE_CHECKING`.
- `REQ-005`: `mypy`, `ruff`, `bandit`, `lint-imports`, the existing factory and memory tests, and the full suite pass with no new findings.
