## Reason for change
Each `CREATE TABLE` statement in the design document duplicates the actual schema
created by `scripts/eventbus/schema.py` (with the base DDL sourced from
`scripts/eventbus/schema.sql`) — a `database-schema` claim whose canonical source, per
the Claim Type Taxonomy, is the schema-creation code/file itself, not this design
document. A column added, renamed, or removed in the migration code would leave this
document silently wrong — this is not hypothetical: the source Issue's own citation of
`db.py` (rather than the actual `schema.py`) is itself an instance of exactly this kind
of drift, discovered during this Plan's own verification.

## Implementation intent
Remove the three DDL code blocks, but retain the design-intent content around them —
the "Each table serves a distinct purpose" bullets already describe
`events`/`consumer_delivery`/`consumer_offsets` responsibilities without needing the
column-level DDL, and the surrounding paragraph's explanation of *why*
`eventbus.sqlite` uses incremental, additive migration (unlike `rag.sqlite`/
`session.sqlite`, which have none) is design intent, not code-derivable. Point to the
verified-correct canonical source — `scripts/eventbus/schema.py` (`_init_schema()`/
`_migrate()`) and `scripts/eventbus/schema.sql` (base DDL) — not the stale `db.py`
reference the source Issue carried forward.
