## Goal
Remove the `/diff`, `/system`, `/audit`, and `/workflow` slash commands from the Agent CLI with no alias, shim, forwarding path, or hidden flag, make each removed name fail like any unknown command, and extend `GV-017` so reintroduction of any removed command name in a current specification is detected.

## Priority
Medium

## Scope
- **In-Scope**:
  - Remove the `/diff`, `/system`, `/audit` `CommandDef` entries (and any alias or alternate spelling) from `scripts/agent/commands/command_defs_list.py`.
  - Delete the handlers and helpers they own (`_cmd_diff`, `_collect_diff_touched_paths`, `_group_paths_by_repo`, `_print_repo_diffs`, `_DIFF_TOUCHED_TOOL_NAMES`, `_cmd_system`) from `scripts/agent/commands/cmd_context.py`, and remove imports that become unused.
  - Delete `scripts/agent/commands/cmd_audit.py` and remove the `_AuditMixin` import, composition, and docstring mention from `scripts/agent/commands/registry.py`.
  - Remove `switch_system_prompt` from `scripts/agent/services/conversation_service.py` (its only production caller is the removed `/system` handler) and delete its dedicated test class, keeping `clear_conversation`, system-prompt configuration, and startup selection unchanged.
  - Add `GV-017` removed-name patterns for `/diff`, `/system`, `/audit`, and `/workflow` to `tools/check_compat_shims.py`, matching command usage rather than ordinary words, with the historical-context exemption.
  - Add rejection tests for all four names and update/remove the tests that exercise the removed commands.
  - Update the command index, per-command chapters, the runtime-architecture enforcement table, and the `GV-017` description; regenerate guarded reference blocks; keep only approved historical mentions.
- **Out-of-Scope**:
  - The Workflow Engine and its persistence, audit logging, audit persistence/redaction, system-prompt configuration used outside the removed command, and file-change tracking used by a supported feature.
  - Introducing replacement commands (needs a separate issue).
  - Changes to the `/memory` command contract (tracked under `plans/done/20261016-143248_plan.md`).

## Background
Source directive: `memo3.md` (2026-10-16), a breaking command-surface reduction. Verified against the repository on 2026-10-16:
- `/diff`: `CommandDef` in `scripts/agent/commands/command_defs_list.py` (async, no arguments); handler `_ContextMixin._cmd_diff()` in `scripts/agent/commands/cmd_context.py` with helpers `_collect_diff_touched_paths`, `_group_paths_by_repo`, `_print_repo_diffs`, and the constant `_DIFF_TOUCHED_TOOL_NAMES`; it derives touched files from tool calls in the conversation history and calls the `git_diff` tool.
- `/system`: `CommandDef` (prefix, argument `name`); handler `_ContextMixin._cmd_system()` in `cmd_context.py`, which calls `switch_system_prompt()` in `scripts/agent/services/conversation_service.py` (its only production caller).
- `/audit`: the whole module `scripts/agent/commands/cmd_audit.py` (`_AuditMixin._cmd_audit()`) reads the audit log file named by `cfg.obs.audit_log_file`; `registry.py` documents the mixin in its module docstring and composes it.
- `/workflow`: no `CommandDef`, no handler, and no occurrence as a command in `scripts/`, `tests/`, `docs/`, or `tools/` (only paths such as `scripts/agent/workflow/` match a plain search).
- `GV-017` is implemented by `_REMOVED_NAME_PATTERNS` in `tools/check_compat_shims.py` (11 patterns, none for a command name; status `Partial`, severity `Warning` in `docs/00_governance/governance_04_documentation-checks.md`).
- No command-completion code exists in `scripts/agent` (the matches for "completion" are LLM completions).

## Problem
The three commands are part of the supported CLI contract that must be implemented, documented, tested, and covered by `GV-023`, although they are no longer wanted: they expose repository-diff, prompt-selection, and audit information through the REPL, overlapping other interfaces. There is also no guard that keeps removed command names out of current specifications.

## Reason for change
Reduce the CLI to commands with a clear, current responsibility and an actively maintained contract, and make the removal permanent by checking for reintroduction.

## Implementation intent
Delete the three registry entries, the handlers and helpers used only by them, and the mixin module for `/audit`; keep every shared service that a supported path still uses. Make the removed names fail like any unknown command, with a test per name that also shows no state is changed. Add the command names (including `/workflow`) to the removed-name patterns of `GV-017` so that only command-like uses match, not ordinary words. Update current documentation and tests to the reduced command set.

## Design
- **Delete over gate.** The three commands are removed from the registry (`command_defs_list.py`) rather than gated behind a flag or shim, so there is no runtime path to reach them. Dispatch is driven by `_COMMANDS` imported into `registry.py`, so removing the `CommandDef` entries is sufficient to stop routing; the handler methods are deleted in the same change so the registry integrity check (every `_COMMANDS` entry references a handler) never fails.
- **`/audit` as whole-module deletion.** `_AuditMixin` lives in `cmd_audit.py` and is composed into `registry.py`. Deleting the module and removing its import/composition/docstring mention is a single coherent deletion; audit generation, persistence, and redaction (`audit_event_emitter.py`, `factory.py`) are untouched.
- **`switch_system_prompt` removal is conditional on evidence.** The function's only production caller is the `/system` handler being removed; `startup_prompt_setup.py` does not call it. Removal proceeds only after a fresh `rg switch_system_prompt` confirms no other caller (see `UNK-01`). Its dedicated test class is deleted with it; `clear_conversation` and system-prompt configuration are preserved.
- **Fail-closed rejection, not silent ignore.** Removed names must behave exactly like any unknown command through the existing REPL rejection path (`repl.py`); no separate rejection mechanism is introduced. A per-name test asserts the unknown-command result, no state mutation, and absence from `/help`.
- **GV-017 pattern design.** New `_REMOVED_NAME_PATTERNS` entries match command-like usage (`/diff`, `/system`, `/audit`, `/workflow` as slash-command invocations), not ordinary words (`workflow`, `audit`, `system`, `diff`). The historical-context exemption (release note / migration history) is preserved so legitimate documentation is not flagged.
- **`/workflow` without a CommandDef.** `/workflow` has no current `CommandDef`, handler, or registration. It is guarded by a GV-017 pattern plus a rejection test to prevent future accidental registration, consistent with the source directive naming it.
- **Documentation is regenerated where guarded.** Guarded reference blocks are regenerated with `tools/generate_reference_table.py`; unguarded docs are edited by hand. Historical mentions are confined to an approved release-note or migration-history context (see `UNK-02`).
