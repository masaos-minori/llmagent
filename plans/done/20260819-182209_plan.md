# Plan: Remove dead RuntimeToolRegistry.is_side_effect()/classify_operation_type() duplication

## Goal

Delete the dead `RuntimeToolRegistry.is_side_effect()` and
`RuntimeToolRegistry.classify_operation_type()` methods from
`scripts/shared/runtime_tool_registry.py` (both have zero production callers),
remove their direct-unit tests, and update the stale module/doc text that
frames this as a "temporary, pending unification" duplication — without
touching the unrelated, actively-used `shared.tool_executor_helpers.is_side_effect()`
or the unrelated `agent.tool_policy.classify_operation_type()` free function.

## Scope

**In scope:**
- `scripts/shared/runtime_tool_registry.py`: remove `is_side_effect()` (line 168-173)
  and `classify_operation_type()` (line 175-181); remove the now-unused `Literal`
  import; update the module docstring (lines 11-19, 26-30).
- `tests/shared/test_runtime_tool_registry.py`: remove
  `test_is_side_effect_reflects_is_write` (127-133) and
  `test_classify_operation_type_read_vs_write` (135-141).
- `docs/90_shared_02_02_types_and_protocols-tool-and-execution-dto.md`: fix the
  two now-stale Japanese notes (lines 82, 159) that describe
  `RuntimeToolRegistry.is_side_effect()` as an "intentionally duplicated,
  temporary" implementation — this framing becomes factually wrong once the
  method is deleted (per `rules/coding.md` "Documentation notes" classification:
  this is a "Documentation fix required" case).

**Out of scope:**
- `shared.tool_executor_helpers.is_side_effect()` and its caller
  `ToolExecutor.execute()` (`scripts/shared/tool_executor.py:234`) — unchanged.
- `agent.tool_policy.classify_operation_type()` free function and its callers
  (`repository_gateway.py`, `tool_audit.py`) — unchanged, different symbol,
  different return type (`OperationType` enum vs. `Literal["read","write"]`).
- `RuntimeToolRegistry.apply_policy()`, `tool_spec_for_call()`,
  `_build_tool_spec()`, `ToolSpec.requires_serial` / scheduler logic
  (`agent/tool_scheduler.py`) — unrelated, must not be touched.
- `tests/mcp_servers/cicd/test_tool_server_layer_consistency.py:376` — this
  line only *mentions* `shared.tool_executor_helpers.is_side_effect()` (the
  surviving symbol) in a comment/string, not the deleted registry method; no
  change needed there.

## Design

Pure deletion, no migration:

1. In `runtime_tool_registry.py`, remove the two method bodies. Since
   `Literal` has no other use in the file after `classify_operation_type()`
   is removed, drop `Literal` from the `from typing import Any, Literal` line
   (keep `Any`, since it's used elsewhere e.g. `dict[str, Any]`).
2. Rewrite the module docstring:
   - Remove the `classify_operation_type()` bullet (lines 12-19) from the
     "Import-layer design decisions" list. Leave the `apply_policy()` bullet
     (lines 20-24) untouched — it documents a still-live design decision.
   - Remove the trailing paragraph about `is_side_effect()`'s "temporary,
     parallel duplication" (lines 26-30) entirely, since the duplication no
     longer exists.
3. In the test file, delete the two now-orphaned test methods verbatim,
   leaving surrounding tests (`apply_policy`, `tool_spec_for_call`, etc.)
   untouched.
4. In the docs file, remove (or rewrite to past-tense/historical framing only
   if the surrounding paragraph structure requires it — prefer straight
   removal since the note's only purpose was describing the now-gone
   duplication) the two identical stale sentences at lines 82 and 159.

No behavior changes to any runtime code path; this is a dead-code removal
with a documentation-consistency follow-up.

## Risks

- **Risk**: Missing the `Literal` import cleanup leaves an unused import.
  **Mitigation**: `ruff check` (step in Implementation step 5) catches unused
  imports (`F401`); explicitly verified in Design step 1 that `Literal` has
  no other use in the file before removal.
- **Risk**: Deleting the docstring's `classify_operation_type()` bullet
  accidentally removes the still-relevant `apply_policy()` bullet next to it.
  **Mitigation**: Design step 2 explicitly calls out leaving the
  `apply_policy()` bullet untouched; diff review (`git diff`) before staging
  per `rules/toolchain.md` step 9 catches over-deletion.
- **Risk**: A future contributor reintroduces the same duplication pattern
  without reading the (now-removed) docstring warning.
  **Mitigation**: none added beyond the deletion itself — the requirement's
  own rationale is that removing the confusing "two answers" surface is the
  fix, not preserving a warning comment for code that no longer exists.
  Accepted as a low-likelihood, low-impact residual risk; no issue filed.
- **Risk**: `docs/90_shared_02_02_types_and_protocols-tool-and-execution-dto.md`
  update is out of the require-to-plan phase's own write permissions (this
  phase must not modify `docs/*.md`), so it is deferred to the implementation
  phase. **Mitigation**: explicitly listed in Scope/Implementation steps above
  so the implementation phase does not miss it; low likelihood of being
  skipped since it is now written into the plan.

No risk in this plan is blocking or unmitigated enough to warrant a separate
`issues/` file.
