## Goal
Fix the misplaced resource cleanup in `AgentREPL.run()` so that `ResourceShutdownCoordinator.close_resources()` runs only after the REPL input loop ends (or on the startup-failure path via `StartupOrchestrator`'s own rollback), never ahead of the input loop on a successful startup.

## Priority
High

## Scope
- **In-Scope**:
  - Move `close_resources()` out of the `finally` wrapping `startup.run()` in `scripts/agent/repl.py`.
  - Call `close_resources()` exactly once after `await self._input_loop.run(...)` returns.
  - Preserve the startup-failure path: the `except` writes the fatal message and re-raises; cleanup relies on `StartupOrchestrator.run()`'s own `shutdown_all()` rollback.
  - Add spy-based tests proving `close_resources()` runs only after the input loop on success and not on failure.
- **Out-of-Scope**:
  - Rebuilding the HTTP client or MCP servers lazily as a workaround (issue Out-of-Scope).
  - Any change to `resource_shutdown_coordinator.py`, `startup.py`, `shared/llm_client.py`, or the input loop.
  - Preserving a WAL checkpoint specifically on the startup-failure path (no session/WAL state exists at startup failure; see Unknown UNK-01 and its resolution).

## Background
`repl.py` extracts startup orchestration into `StartupOrchestrator` and resource cleanup into `ResourceShutdownCoordinator`. The original implementation (commit `26dc21eff6`) placed `close_resources()` in a `finally` attached to the `try` around `startup.run()`. The intent was cleanup-on-startup-failure, but a `finally` also executes on the success path.

## Problem
On a successful startup the sequence is: `startup.run()` → `finally: await self._shutdown.close_resources()` (which closes the shared `httpx.AsyncClient` via `svc.http.aclose()` and stops all MCP subprocesses via `lifecycle.shutdown_all()`) → memory warning → `await self._input_loop.run(...)`. The shared HTTP client is therefore closed before the REPL input loop starts.

## Reason for change
The shared `httpx.AsyncClient` (held by `LLMClient._http`) is required for the session's LLM calls. Closing it before the input loop breaks the session. Cleanup must happen when the session ends, not before it begins.

## Implementation intent
Restructure `run()`'s control flow: remove the `finally` that wraps `startup.run()`, keep the `except` block that writes the fatal message and re-raises, and add a single `await self._shutdown.close_resources()` call after the input loop returns. Startup-failure cleanup stays in `StartupOrchestrator.run()`'s existing exception rollback.

## Requirements
- `REQ-001`: On a successful startup, `close_resources()` MUST NOT run before `await self._input_loop.run(...)` returns.
- `REQ-002`: After `await self._input_loop.run(...)` returns normally, `close_resources()` MUST be awaited exactly once.
- `REQ-003`: On the startup-failure path, `run()` MUST still write the fatal message and re-raise, and MUST NOT call `close_resources()` (rely on `StartupOrchestrator.run()`'s own `shutdown_all()` rollback).
- `REQ-004`: Tests MUST assert the ordering (`REQ-001`/`REQ-002`) and the failure-path behavior (`REQ-003`) using spies, and existing `test_repl.py` / `test_startup_rollback.py` behavior MUST be preserved.

## Design
Path A (affects ≤ 3 files, no public/runtime interface change, no DB schema change). The fix is a pure control-flow restructure within `AgentREPL.run()`. The `finally` wrapping `startup.run()` is replaced by: (a) keep the `except` block that writes the fatal message and re-raises, (b) a single `await self._shutdown.close_resources()` call after the input loop. Startup-failure cleanup stays in `StartupOrchestrator.run()`'s own rollback (`startup.py:80-88`). This matches the existing test contract in `TestAgentREPLRunSubprocessTermination`: subprocess termination is delegated to `lifecycle.shutdown_all()` via `StartupOrchestrator`, never done directly by `repl.py`.

Moving `close_resources()` after the loop does not break the existing success-path test: under the test's `MagicMock` ctx, `write_history()` is a mock, the WAL checkpoint/backup are wrapped in try/except (no propagation), and `list(ctx.turn.background_tasks)` returns `[]` (a bare `MagicMock.__iter__` yields an empty iterator), so `close_resources()` completes without raising.

## Risks
- **Risk**: An exception raised mid-input-loop would skip `close_resources()` after the move. → **Mitigation**: This matches current behavior (`close_resources` was never in a `finally` around the loop) and the issue's stated contract ("cover normal user exit"); turn-level errors are handled by the input-loop/turn error handling, not by this cleanup.
- **Risk**: Moving `close_resources()` after the loop makes the success-path test reach it. → **Mitigation**: Verified safe under the test's `MagicMock` ctx (see Design). If it unexpectedly raises, instrument `repl._shutdown.close_resources = AsyncMock()` — a pattern already used in `test_repl.py` (line 1167).
- **Risk**: Removing the `finally` could be misread as removing startup-failure cleanup. → **Mitigation**: `startup.py:80-88` retains `lifecycle.shutdown_all()` in `StartupOrchestrator.run()`'s rollback; the failure-path test (`T-002`) asserts `shutdown_all` is awaited.
