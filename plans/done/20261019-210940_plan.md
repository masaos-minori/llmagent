## Goal
- Make `restore_session` compute the `/undo` compression boundary (`ctx.conv.undo_floor`) correctly and safely: compute it before mutating any session state so a failure never leaves the session half-restored with `undo_floor == 0`, and anchor the boundary index to the post-sanitization rebuilt history so a dropped snapshot row cannot misalign `/undo`.

## Priority
Medium

## Scope
- **In-Scope**:
  - Reorder `restore_session` so the boundary is computed and assigned to `ctx.conv.undo_floor` before `ctx.session.session_id` is reassigned and before `reset_session_stats` runs.
  - On a raised boundary computation, surface the error without leaving the session half-restored with `undo_floor == 0`.
  - Anchor the boundary index to the rebuilt (post-sanitization) history instead of the pre-sanitization fetched rows.
  - Add unit tests for the failure path and the dropped-snapshot-row path in `tests/agent/test_session_restore.py`.
- **Out-of-Scope**:
  - Changing the compression/persistence path that writes `sessions.undo_floor_message_id`.
  - Changing `undo_last_turn` deletion logic.
  - Changing how `replace_history` sanitizes/restores rows (validation policy is out of scope).

## Background
On `/session load`, `restore_session` rebuilds the in-memory conversation history from the persisted DB rows and re-derives the `/undo` boundary. After a history compression, the compressed snapshot must NOT be undoable; only turns appended after the snapshot are. The boundary is persisted as `sessions.undo_floor_message_id` and converted back to an in-memory history index on restore via `_boundary_to_index`, using `count_messages_up_to` for the snapshot count. `replace_history` clears `ctx.conv.history` and appends each restored row validated as untrusted (`_UNTRUSTED_RESTORE_SOURCE`), so any row whose role/content is stripped by `_sanitize_message()` is dropped from the rebuilt history.

## Problem
Two independent defects break the `/undo` semantics on the restore path:

1. Failure path: `restore_session` switches `ctx.session.session_id` and calls `reset_session_stats` BEFORE computing the boundary. If `count_messages_up_to` raises (DB error), the exception propagates but the session is already switched and `undo_floor` is left at the `ConversationState` default of 0. An `undo_floor` of 0 means every turn is undoable, so the previously non-undoable compressed snapshot becomes undoable after a transient DB error.
2. Index drift: `_boundary_to_index` indexes the rebuilt history using the pre-sanitization `messages` list. `replace_history` validates every restored row as untrusted and drops any row whose role/content is stripped. If a snapshot row is dropped, the computed index no longer matches the actual rebuilt-history length, silently misaligning `/undo`.

Reproduced the failure path directly: after `count_messages_up_to` raised, `ctx.session.session_id` had already changed and `ctx.conv.undo_floor` was 0.

## Reason for Change
The `/undo` boundary is a data-integrity guarantee: users rely on it to undo only their own recent turns, never the compressed snapshot. A silent `undo_floor=0` after a recoverable DB error lets `/undo` delete the compressed snapshot, which cannot be rebuilt. The current tests mock `count_messages_up_to` and never exercise the raise path or a dropped snapshot row, so neither defect is covered.

## Implementation Intent
Compute the `/undo` boundary BEFORE mutating any session state (before switching `session_id` and before `reset_session_stats`). If the boundary computation fails, surface the error without leaving the session half-restored with `undo_floor=0`. For the index-drift case, derive the boundary index from the actual post-sanitization rebuilt history (`ctx.conv.history`) rather than the pre-sanitization `messages` list, so the floor always matches the live history. Keep the existing `_boundary_to_index` system-prompt adjustment; only anchor it to the messages that actually made it into memory. The fix lives entirely in `session_restore.py`; `context.py`'s sanitization/drop behavior is understood but not modified (validation policy is out of scope).

- `REQ-002`: Anchor the boundary index to the rebuilt (post-sanitization) history (`ctx.conv.history`) rather than the pre-sanitization fetched `messages`, so a dropped snapshot row cannot shift `undo_floor` past the true boundary.

## Design
- **Failure-path contract = propagate-before-mutate (resolves UNK-01).** Move the `undo_floor` boundary block in `restore_session()` to run *before* `ctx.session.session_id` is reassigned and before `reset_session_stats(ctx)`. Because `count_messages_up_to(session_id, undo_floor_id)` depends only on data available right after `fetch_messages()`, computing the boundary first means a raised `sqlite3.Error` propagates with zero session-state mutated — the session is left exactly as it was (session_id unchanged, stats not reset). This is strictly simpler than capturing/restoring the prior `session_id` for a rollback, and it satisfies the Issue's "propagate before any state mutation" acceptance criterion directly. No rollback bookkeeping is introduced.
- **Anchor the boundary index to the rebuilt history (resolves UNK-02).** `_boundary_to_index(n_snapshot, messages, ...)` keeps its signature; the caller passes `ctx.conv.history` (the post-sanitization list populated by `replace_history()`) instead of the pre-sanitization `messages`. When `replace_history()` drops a snapshot row, `ctx.conv.history` reflects the actual in-memory length, so the computed index can no longer exceed the live history. No new helper or signature change is required.
- **Minimal surface.** The change is confined to `session_restore.py`: reorder the two statements and swap the argument to `_boundary_to_index`. `context.py`'s sanitization/drop policy and the persisted `undo_floor_message_id` semantics are read-only references (out of scope).
- **Preserve existing exceptions.** `SessionNotFoundError` / `SessionNoMessagesError` still raise from their existing guards before the reordered block; the reorder does not alter their conditions.
