# Plan: Make the REPL shutdown and signal tests assert production wiring instead of mock state

## Goal
- Make the REPL shutdown/signal test surface fail when `AgentREPL`'s construction wiring is wrong, so a defect of the `repl001` kind cannot stay invisible behind green tests. Concretely: add one guard test that runs the real `AgentREPL.__init__`/`run()` and asserts the identity of the shutdown event across the objects that hold it; delete the eight tests that assert only state their own body assigned to a `MagicMock`; delete the four permanently-skipped tests that can never run on this repository's CI matrix; replace the never-failing assertions in the graceful-shutdown test with assertions that can fail; and register the rule in the two places `routing.md` sends test work.

## Priority
Medium

## Scope
- **In-Scope**: a constructor-level wiring guard in `tests/agent/test_repl.py` that builds the real `AgentREPL()` with only `agent.repl.AgentContext`, `agent.repl.CLIView` and `agent.repl.DiagnosticStore` replaced at the use-site module, and asserts one `asyncio.Event` object is held by `AgentREPL`, `ReplInputLoop`, `SignalHandler`, and (after `run()`) `StartupOrchestrator`/`McpServerStarter`; honest docstrings on the two fixtures that repair wiring (`tests/agent/test_repl.py:28-88`, `:618-637`); removal of the never-failing assertions at `tests/agent/test_repl.py:359-361`, `:364-367`; real signal coverage in `tests/agent/test_signal_handler.py` (`SignalHandler.register()` on the real running loop, both `SIGTERM` and `SIGINT` installed, a real `os.kill(os.getpid(), signal.SIGTERM)` observed on a real `AgentContext`, and the `shutdown_event=None` case HEAD's `__init__` produces); deletion of `tests/agent/test_signal_handler_race.py` and of the permanently-skipped Windows-success test at `tests/agent/test_signal_handler.py:51-78`; the test-policy rule in `skills/python-test-and-fix/SKILL.md` and `skills/python-test-and-fix/workflow.md`.
- **Out-of-Scope**: every production-code change — `scripts/agent/repl.py`, `scripts/agent/signal_handler.py`, `scripts/agent/repl_input_loop.py` are read-only here (`repl001`, `plans/20261022-030840_plan.md` owns the wiring this Plan asserts; `repl002`, `plans/20261022-040200_plan.md` owns the reads); the value of `_GRACEFUL_TIMEOUT_S` (`repl_input_loop.py:55`) or any other timeout; a process-spawning end-to-end REPL harness (`repl002`'s `tests/agent/test_stdin_reader.py` owns that shape); the condition-gated skips at `tests/agent/test_context.py:41`, `tests/agent/memory/test_memory_vec_session.py:25`, `tests/agent/memory/test_memory_retriever.py:610`; the Windows runtime itself.

## Background
`tests/agent` is green at HEAD while `repl001`'s defect exists. Measured at `dc26b0015`: `uv run pytest tests/agent -q --collect-only` collects 3487 tests; `uv run pytest tests/agent tests/test_cli_view.py -q` reports 3536 passed, 7 skipped in 121.00 s. The issue's `3467 passed / 7 skipped` is not reproducible at this HEAD; the qualitative claim is confirmed.

The reason the suite stays green is a fixture that repairs the wiring it then tests. `_make_bare_repl()` (`tests/agent/test_repl.py:28-88`) builds the object with `AgentREPL.__new__(AgentREPL)` (`:30`), assigns `repl._shutdown_event = asyncio.Event()` (`:60`), constructs `repl._input_loop = ReplInputLoop(ctx, view, repl._shutdown_event)` (`:78`) and hand-binds `_cmds`/`_orchestrator` (`:79-80`). `_make_repl_for_shutdown()` (`:618-637`) does the same with its own fresh event (`:632-636`). Production does none of that: `repl.py:82` sets `self._shutdown_event: asyncio.Event | None = None`, `:85` passes that `None` to `ReplInputLoop`, `:92` passes it to `SignalHandler`; `run()` creates the event at `:113`, rebinds only `SignalHandler` via `set_shutdown_event()` (`:114` → `signal_handler.py:136-138`) and hands it to `StartupOrchestrator` (`:120-122` → `startup.py:53`, `:61`, forwarded to `McpServerStarter` at `:62`). `ReplInputLoop.bind()` (`repl_input_loop.py:72-75`) binds only `_cmds` and `_orchestrator`. So in a real session `ReplInputLoop._shutdown_event` is `None` for the whole session.

That is not a cosmetic difference: `_repl_loop` chooses its shutdown strategy on that attribute. With a real event it takes the race at `repl_input_loop.py:255-284`, which cancels a hung dispatch (`:279`) and exits. With `None` it falls to `:285-305` and awaits the dispatch with `timeout=self._GRACEFUL_TIMEOUT_S` (10.0, `:55`) only if `ctx.conv.shutdown_requested` is set, logs `_log_graceful_shutdown_timeout()` and breaks. Every existing shutdown test runs on the first path; the path a real session takes is the second, and no test asserts it.

## Problem
Three concrete failures of the current test surface, each verified at HEAD:

1. Wiring is never constructed by a test. `grep -rn "AgentREPL(" tests/` returns no match. The only two constructions in the suite are `AgentREPL.__new__` + manual attribute assignment (`test_repl.py:30`, `:620`). A guard in the shape of the existing `TestRunBindsStartupResultsToInputLoop` (`:712-730`, which is green and does assert `repl._input_loop._cmds is cmds`) exists for `_cmds`/`_orchestrator` and for no other attribute.
2. Assertions that cannot fail. `test_repl.py:367` is `assert dispatch_hang.is_set() or True  # may or may not have been cancelled`. In the same test, `except TimeoutError: pass  # Should not happen` (`:359-361`) swallows the only guard the test has, and `:364-365` asserts `elapsed = time.time() - start; elapsed < 2.0` — wall-clock arithmetic this repository's test skill already forbids for timing fixes (`skills/python-test-and-fix/SKILL.md:21`).
3. Tests that simulate production instead of calling it. `tests/agent/test_signal_handler_race.py` (140 lines, 8 tests) asserts on `MagicMock(spec=AgentREPL)` state the test body itself set (`:17`, `:25`, `:34`, `:39-45`), calls `handler._on_first_turn`, an attribute that exists on `Orchestrator` (`orchestrator.py:83`), `ConversationStateManager` (`conversation_state_manager.py:68`) and `AuditEventEmitter` (`audit_event_emitter.py:64`) but not on `AgentREPL`, and uses `repl.ctx` (`:75-92`) where production spells `_ctx` (`repl.py:78`). Two of its classes are permanently skipped (`:48` class, 2 tests; `:106`, 1 test), and the skipped `signal.signal` class would not touch `loop.add_signal_handler` (`signal_handler.py:51-63`) even if enabled. `tests/agent/test_signal_handler.py` (78 lines, 2 tests) covers only the `NotImplementedError` fallback (`:36-49`) plus a permanently-skipped test (`:51-78`). Across the whole suite the permanently-`skipif(True)` sites are exactly these three (4 tests), and no job in `.github/workflows/` runs on anything but `ubuntu-latest`, so those skips can never become passes.

The counter-evidence the issue omitted is equally part of the problem, because a new test that ignores it duplicates existing coverage: `TestSigtermHandlerShutdownCoordination` (`test_repl.py:1249-1312`) already drives the real `AgentREPL.run()`, captures the closure the real `SignalHandler.register()` handed to the loop (only the `add_signal_handler` call is patched, `:1268-1277`) and asserts `repl._ctx.conv.shutdown_requested is True` and `repl._shutdown_event.is_set()` (`:1297-1298`). The gap is not the handler body; it is (a) a signal actually delivered to the process and both signal numbers actually installed, and (b) the objects `__init__` produced.

## Reason for Change
`repl001` is about to change exactly this wiring (`plans/20261022-030840_plan.md` makes `AgentREPL.__init__` the sole owner of one event). If no test constructs `AgentREPL.__init__`, that change is verified only by tests that already hand-wired the same thing by hand. This Plan is the regression guard for `repl001`, and it must land after it for that reason.

## Implementation Intent
Add one small, deterministic guard that calls the production constructor, and remove test code whose outcome does not depend on production code. Keep the existing doubles where they are load-bearing (view, orchestrator, command registry, diagnostic store) and remove them where they replace the wiring under test. Move real signal coverage into the mirror-named test file (`skills/python-test-and-fix/workflow.md:53-54`), and make the deletion of the non-mirror file a scope decision rather than a rewrite.

## Design
- **The guard is the plan's core, and it must be a construction test, not an attribute test.** It calls `AgentREPL()` (the real body) with only the three heavy names substituted, then asserts `isinstance(event, asyncio.Event)` before any identity comparison. Requiring the object to exist is what makes the guard fail at HEAD (`repl.py:82`, `:85`) and pass after `repl001`; a pure `a is b` assertion would pass today on two `None`s and would be the exact failure mode this Plan exists to remove.
- **A second guard for the `run()` handoff, in the same class.** It follows the already-proven shape of `TestSigtermHandlerShutdownCoordination._run_and_capture_handler` (`test_repl.py:1262-1286`): real `run()`, `StartupOrchestrator` and `SQLiteHelper` substituted, `close_resources` stubbed (`:1280` precedent), `add_signal_handler` captured instead of installed. The new part is inspecting what the constructed objects hold rather than what a handler does.
- **Fixture repair is allowed but must be declared and paired.** `_make_bare_repl` and `_make_repl_for_shutdown` stay: their doubles stand in for config, terminal, LLM and MCP services, which no unit test should construct. What changes is that each docstring names the bypassed constructor, the attribute it supplies, and the guard that covers the real one. `TestRunBindsStartupResultsToInputLoop` (`:712-730`) stays as the pattern the new guard joins.
- **Assertions must be able to fail.** In `test_signal_mid_turn_exits_within_graceful_timeout` the three never-failing structures are replaced by: the `wait_for` bound deciding the outcome (a `TimeoutError` now fails the test instead of being swallowed), an awaited-once post-loop persist hook, and a `CancelledError` captured inside the test's own dispatch stub. This keeps the test's subject (a mid-turn signal exits the loop) and removes the wall-clock arithmetic.
- **Signal coverage moves to the mirror-named file and uses the real transport.** `test_signal_handler.py` gains the real-loop registration case, the delivered-signal case and the `None`-event case; the non-mirror `test_signal_handler_race.py` is deleted rather than rewritten, because after removing self-asserting bodies nothing left in it calls production code. Teardown restores the process's signal dispositions, so a test that touches the real loop does not leak into the remaining 3400+ tests.
- **Rule registration is part of the change, not a note.** The pattern is only durable where `routing.md` sends future test work, so it goes into the skill's enforced rules and its test-structure section.
