# Fix ROOT_DIR depth in tools/check_no_compat.py and restore the no-compat-stubs check

## Goal
`tools/check_no_compat.py`'s default scan (used by the `no-compat-stubs` pre-commit hook)
actually scans the repository's `scripts/`, `docs/`, `tests/`, and `tools/` trees instead of
silently scanning zero files, and `DEFAULT_ALLOWLIST` references only paths that currently
exist.

## Scope

**In-Scope**
- Fix `ROOT_DIR = Path(__file__).resolve().parent.parent.parent` to
  `Path(__file__).resolve().parent.parent` in `tools/check_no_compat.py` (line 21).
- Fix the stale path references in the module docstring: the header line (`"""scripts/checks/check_no_compat.py`)
  and the `Usage: python -m scripts.checks.check_no_compat` line — both must reflect the
  file's real location/module path (`tools/check_no_compat.py` / `python -m tools.check_no_compat`).
- Audit all 29 entries in `DEFAULT_ALLOWLIST` for path existence; fix every entry found to
  reference a moved/renamed file (at least the 10 confirmed stale entries below), including
  the entry for this file's own test (`tests/test_check_no_compat.py` -> `tests/tools/test_check_no_compat.py`).
- Remove the duplicate `test_rag_get_cfg.py` allowlist entry (currently listed twice, lines
  ~94 and ~122) once its path is corrected — a single corrected entry is enough.
- Re-run `uv run python -m tools.check_no_compat` (default scan) after the ROOT_DIR and
  allowlist fixes, and triage the real remaining findings (after allowlist-path corrections
  remove the false positives) one at a time: fix genuine compatibility leftovers, or add a
  new individually-justified allowlist entry.
- Add a regression test in `tests/tools/test_check_no_compat.py` that exercises `main()`'s
  real default-scan path (i.e. asserts `ROOT_DIR` resolves to a directory that actually
  contains `scripts/`, `docs/`, `tests/`, and `tools/`), so a future file move cannot
  silently reintroduce this bug.
- Run the full validation sequence (`rules/toolchain.md`) and confirm
  `uv run pre-commit run no-compat-stubs --all-files` passes.

**Out-of-Scope**
- Any change to `COMPAT_PATTERNS` or the detection regexes themselves.
- Fixing `main()`'s crash when a directory (e.g. `scripts/`) is passed as a positional file
  argument (`Path(f).read_text()` raises `IsADirectoryError`) — this is a pre-existing,
  separate bug in the file-argument code path, not the default-scan path this requirement
  targets. Filed as a follow-up issue (see Risks).
- Bulk-allowlisting all 90 newly-surfaced matches without individual review.
- Changes to `tools/check_suppression_justification.py` or any other unrelated `tools/`
  module.

## Assumptions
1. `tools/check_suppression_justification.py`'s `ROOT_DIR = Path(__file__).resolve().parent.parent`
   is the correct depth pattern for a module living directly under `tools/`, and copying it
   verbatim is correct for `check_no_compat.py` (same directory depth). Falsifiable via
   `(ROOT_DIR / "scripts").exists()` after the fix.
2. The 10 stale `DEFAULT_ALLOWLIST` paths identified during investigation are the complete
   set of stale entries; the remaining ~19 entries reference paths that still exist.
   Falsifiable by checking every entry's existence in Implementation Step 2.
3. After allowlist-path corrections, the number of genuinely new compatibility-leftover
   findings (real positives, not allowlist-path false positives) is small enough to triage
   individually within this task's scope. Falsifiable once the corrected scan is re-run in
   Implementation Step 3 — if the real-finding count is large/ambiguous, this plan escalates
   per Unknown UNK-01 below rather than silently bulk-allowlisting.
4. No other module imports or depends on `check_no_compat.ROOT_DIR` or `DEFAULT_ALLOWLIST`
   as a public symbol (this is a standalone pre-commit-hook script, not a library import
   target) — so changing these values has no blast radius beyond this file and its test.

## Risks

- **Risk**: The 90-match/19-file measurement taken pre-fix mixes real compatibility
  leftovers with allowlist-path false positives; if Phase 2's allowlist corrections are
  incomplete, Phase 3 will over-count real findings and risk being bulk-allowlisted under
  time pressure (likelihood: medium) → **Mitigation**: Phase 2 requires checking existence
  of all 29 entries individually (not just the 10 already identified) before Phase 3 triage
  begins; Phase 3 explicitly forbids bulk allowlisting and requires escalation if the count
  is large/ambiguous.
- **Risk**: `main()` crashes with `IsADirectoryError` when a directory is passed as a
  positional argument, a pre-existing bug independent of this fix (likelihood: low impact
  on this task, since the default no-args scan path — the only path the pre-commit hook
  uses — does not hit this code) → **Mitigation**: out of scope for this plan; file a
  separate follow-up issue (`issues/{timestamp}_main_dir_arg_crash.md`) documenting the
  `Path(f).read_text()` crash on directory arguments, so it is tracked without expanding
  this task's scope.
- **Risk**: Some of the 10 identified stale allowlist paths might correspond to files that
  were deleted outright (not moved), meaning the correct fix is entry removal, not a path
  rewrite — misclassifying this would leave a phantom allowlist entry (likelihood: low) →
  **Mitigation**: UNK-02 resolution step (`git log --diff-filter=D`) before rewriting each
  entry in Phase 2.
- **Risk**: `rules/toolchain.md`'s lint/type/coverage commands are scoped to `scripts/` by
  convention (e.g. `mypy` config `files = ["scripts/"]`); running them against `tools/`
  directly may require explicit path arguments not covered by the documented defaults
  (likelihood: low, mostly a documentation-following nuance, not a code risk) →
  **Mitigation**: explicitly pass `tools/` and `tests/tools/` paths to each tool invocation
  in Phase 4 rather than relying on the `scripts/`-scoped defaults.
