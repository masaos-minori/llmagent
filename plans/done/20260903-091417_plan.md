environment name (Decision Group 1). Several narrower steps are already complete:
`required_in_local`/`required_in_production` were unified into `required`

## Reason for Change
Retaining a two-profile model that must be kept in permanent outcome-parity is
harder to guarantee than a single unconditional policy, and the profile is not
latent — it is the currently configured value in `config/agent.toml`, so closing
this gap directly reduces live risk, not only hypothetical drift risk.

## Implementation intent
Make Production-grade behavior the sole, unconditional behavior: delete the
`SecurityProfile` enum's `LOCAL` member and, since the architecture-owner sign-off
confirmed full removal (not two-profile-with-parity retention — resolves `UNK-01`),
remove the `SecurityProfile` enum/field entirely wherever it serves no purpose
other than distinguishing the now-eliminated profile (implementer verifies during
`plan-to-implementation-procedure` whether any call site still needs a type marker
for other reasons; default to full removal per the sign-off's direction);
remove the `"local"` default/fallback in `config_dataclasses.py`/`config_builders.py`;
remove `is_production`-conditional downgrading in `ProductionConfigValidator`, making
every strict-mode/tool-safety/approval-risk/allowlist violation an unconditional
error; remove the `production_mode`/`SecurityProfile.PRODUCTION` conditionals in
`startup.py` and `mcp_tool_discovery.py`, making the FATAL paths and `is_fatal`
severity unconditional; remove `security_profile`'s runtime-reload path in
`config_reload.py`; remove or hardcode `security_audit.py`'s derived value; remove
`config/agent.toml`'s `security_profile` key and reject it as an unknown/invalid
key if still present (per Constraints, no silent compatibility alias).
