# Plan: HttpTransport fails loud instead of silently disabling auth when built without config

## Goal
Make `HttpTransport.__init__` treat a missing configuration (`cfg=None`) as an explicit, loud error instead of a silent authentication-off switch, so a mis-constructed HTTP MCP transport cannot quietly send unauthenticated calls to an endpoint that requires a bearer token.

## Priority
Medium

## Scope
- **In-Scope**:
  - Modify `scripts/shared/http_transport.py` (`HttpTransport.__init__`) so that constructing a transport without a usable credential fails loud (raises) rather than defaulting to an empty token / disabled auth.
  - Audit every `HttpTransport(...)` construction site and update the test constructions that currently omit `cfg` to carry explicit configuration.
  - Add unit tests asserting the fail-loud contract and preserving the authenticated path.
- **Out-of-Scope**:
  - Changing `call()`, retry/backoff, response parsing, or session-id injection.
  - Altering how `ToolTransportInvoker` builds transports (it already passes `cfg`).
  - Adding new env/loader variables or touching any other module's auth policy.

## Background
`HttpTransport` (scripts/shared/http_transport.py) POSTs to `/v1/call_tool`. Auth is applied in `call()` (adds an `Authorization: Bearer <token>` header only when `self._auth_token` is truthy). The token is derived in `__init__`:

```python
self._auth_token: str = cfg.auth_token if cfg is not None else ""
if self._auth_token:
    register_secret(self._auth_token)
```

The signature is `__init__(self, http, base_url, server_key, cfg=None, timeout_sec=60.0)`. When constructed with `cfg=None`, `_auth_token` becomes `""`, so `call()` omits the Authorization header entirely — silently.

A caller audit shows the construction landscape:
- Production: exactly **one** constructor — `ToolTransportInvoker` (scripts/shared/tool_transport_invoker.py) — which always passes a real `cfg` (so production transports always carry their token).
- Tests: ~20 constructions across `tests/shared/test_tool_executor.py` (~18) and `tests/shared/test_tool_executor_routing.py` (~6) that omit `cfg` to exercise non-auth behaviors (retries, errors, redaction, x-request-id). One of them, `test_no_cfg_sends_empty_headers`, explicitly encodes the silent-off behavior ("Backward-compat: HttpTransport without cfg arg sends no auth header").

`scripts/shared/mcp_config.py` enforces a non-empty `auth_token` for all non-disabled servers at config-build time, so in practice no legitimate unauthenticated transport exists in production.

## Problem
`cfg=None` is a silent auth-off switch. If any code path constructs `HttpTransport(http, url, key, cfg=None, ...)`, the resulting transport sends requests with no `Authorization` header regardless of what the server requires. Combined with the fact that real servers require a bearer token, a mis-constructed transport leaks unauthenticated access to an authenticated endpoint. There is no exception and no log — the failure mode is invisible.

## Reason for change
Silently disabling authentication based on a missing config object is a classic fail-open pattern. Authentication decisions must never be implicit; a missing config should surface loudly so it cannot quietly bypass auth. Because production never constructs a transport without `cfg`, making this condition loud carries zero production risk while removing the footgun.

## Implementation intent
In `HttpTransport.__init__`, after resolving whether a usable credential exists, raise when the transport is built without one (`cfg is None` and no token), instead of assigning `""`. Preserve the happy path where `cfg` is provided (including the existing `cfg` with an empty-token branch, which is an explicit config choice, not a missing-config case). Then audit call sites: the single production caller is unchanged; the ~20 test constructions that omit `cfg` are updated to carry explicit configuration, and the test that encodes the silent-off behavior is rewritten to assert the fail-loud contract.

## Requirements
- `REQ-001`: In `HttpTransport.__init__`, construct the transport without a usable credential (`cfg is None` and no provided token) must fail loud by raising; do NOT silently set an empty token or disable auth. Preserve the `cfg`-provided path byte-for-byte (including registering a non-empty token via `register_secret`).
- `REQ-002`: Audit every `HttpTransport(...)` construction site; update the test constructions that currently omit `cfg` to carry explicit configuration (making prior implicit intent explicit); remove or rewrite `test_no_cfg_sends_empty_headers` so it asserts the fail-loud contract instead of the silent-off behavior. The production `ToolTransportInvoker` call site is unchanged.
- `REQ-003`: Do not change `call()`, retry/backoff, response parsing, session-id injection, or the authenticated path. Existing cfg-provided transports behave identically.
- `REQ-004`: Resolve UNK-01 by defaulting to fail-loud (raise-by-default). An explicit opt-out flag for deliberately unauthenticated transports is OPTIONAL and only introduced later if a producer genuinely requires one (that change escalates this Plan to Path B); it is out of scope here.

## Design
Path A (small task), recommended classification: affects ≤ 3 files, no public/runtime interface change (the `__init__` signature is unchanged — only its internal guard changes), no database schema change. Per Path A, architecture/dependency/historical analysis is normally skipped; it is performed here anyway because the change touches a security-critical leaf module and the issue flags an unresolved design decision (UNK-01).

Architecture: `shared` is the import-layer leaf (`shared → external only`). The change stays within `http_transport.py` and introduces no new imports, so there is no layer-boundary impact. `HttpTransport.call()` (complexity C(13)) is untouched; only `__init__` (complexity M(3)) gains a conditional raise.

Dependency graph (caller audit): 23 total `HttpTransport(...)` constructions — 1 production (`tool_transport_invoker`, always passes `cfg`) and ~22 in tests. Only the test constructions omit `cfg`; they are fixtures for non-auth behaviors and are updated to carry explicit config.

Historical: 15 commits touch `http_transport.py`, all by a single author (high bus factor). This raises the cost of a mistake on this security-critical module, so the validation plan requires a full-suite regression in addition to targeted fail-loud coverage.

Design decision (UNK-01 resolution): default to **fail-loud (raise)**. The alternative — an explicit opt-out flag — widens the public interface and would escalate this Plan to Path B; it is documented as a deferred follow-up rather than implemented, since no production consumer needs an unauthenticated transport. Either way the frozen target files are identical; only the internal mechanism differs.
