## Goal
Fix a variable-swap bug in `scripts/mcp_servers/mdq/mdq_server.py::_mdq_error_handler`: it unpacks `extract_request_context(request)`'s `(session_id, request_id, idempotency_key)` tuple as `request_id, session_id, _`, silently swapping the two values in every MDQ error-path audit log record.

## Priority
High

## Scope
- **In-Scope**: Fix the tuple-unpacking order in `_mdq_error_handler` (`scripts/mcp_servers/mdq/mdq_server.py`) to match `extract_request_context`'s documented and actual return order.
- **Out-of-Scope**: `scripts/mcp_servers/server.py::extract_request_context` itself — confirmed correct (its docstring, return statement, and implementation all consistently order `(session_id, request_id, idempotency_key)`). Any other MCP server's own error-handler call site — not investigated as part of this Plan; if the same swap pattern exists elsewhere, that would be a separate finding.

## Background
`scripts/mcp_servers/server.py::extract_request_context(request)` returns `(session_id, request_id, idempotency_key)`, reading `session_id` from the `x-session-id` header and `request_id` from `request.state.request_id` (populated by `attach_auth_middleware`) falling back to the `x-request-id` header. `scripts/mcp_servers/mdq/mdq_server.py::_mdq_error_handler` calls this function but unpacks the result as `request_id, session_id, _ = extract_request_context(request)` — swapping the first two positions relative to the function's actual, documented return order — before passing both into `_audit_log(session_id=session_id, request_id=request_id, ...)`.

## Problem
`test_session_id_from_header_and_request_id_from_middleware_state` confirms: `mock_audit.call_args.kwargs["session_id"]` is a middleware-generated UUID (`e3ed0dba-...`) instead of the `x-session-id` header's value (`"sess-456"`) — because the swapped unpacking assigns `extract_request_context`'s actual `session_id` return value (the header value) to the local `request_id` variable, and its actual `request_id` return value (the middleware UUID) to the local `session_id` variable.

## Reason for change
Every MDQ error response's audit log record currently has its `session_id`/`request_id` fields swapped — a correctness bug in security/operational audit logging (session-based tracing and per-request correlation across the MDQ service's error paths are both affected, since all of `mdq_server.py`'s `@app.exception_handler(...)` functions funnel through this one shared `_mdq_error_handler`).

## Implementation intent
Swap the two variable names in the unpacking statement to `session_id, request_id, _ = extract_request_context(request)`, matching `extract_request_context`'s actual return order. No other change needed — `_audit_log`'s call already uses the correct keyword names (`session_id=session_id, request_id=request_id`); only the preceding unpacking assigns them from the wrong tuple positions.

## Requirements
- `REQ-001`: Fix `_mdq_error_handler`'s `extract_request_context(...)` unpacking order.
