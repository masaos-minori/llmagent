# Plan: Deprecate and remove unused Orchestrator._llm_runner and _guard fields

## Goal
Add deprecation warnings to `Orchestrator._llm_runner` and `Orchestrator._guard` fields, migrate test callers to use `LlmTurnExecutor` directly, then remove the dead code in a subsequent phase.

## Priority
Medium

## Scope
- **In-Scope**: Phase 1 — add deprecation warnings and migrate test callers; Phase 2 — remove the fields entirely after all callers are migrated
- **Out-of-Scope**: Refactoring `LlmTurnExecutor` to share guard state across turns, adding new guard functionality

## Background
During refactoring, `LLMTurnRunner` was extracted into `LlmTurnExecutor`, and the main execution path was updated to use `self._llm_executor.handle_llm_turn()` (orchestrator.py:283). However, the original `self._llm_runner` field and its associated `self._guard` (`ToolLoopGuard`) were not removed.

Evidence verified against source:
- `orchestrator.py:111`: `self._guard = ToolLoopGuard(ctx)` — created but never called within Orchestrator class
- `orchestrator.py:115-119`: `self._llm_runner = LLMTurnRunner(ctx, self._guard, ...)` — created but never called within Orchestrator class
- `orchestrator.py:283`: `await self._llm_executor.handle_llm_turn(...)` — actual execution path uses executor, not `_llm_runner`

**Correction to Issue claim**: The Issue states "_llm_runner is never called," but verification found multiple test files that access `orch._llm_runner.run()` and `orch._guard.check_all()` directly. These are external callers, not internal Orchestrator usage.

## Problem
1. **Dead code**: `Orchestrator._llm_runner` and `Orchestrator._guard` are never invoked within the Orchestrator class itself, wasting memory and creating maintenance burden.
2. **Confusion about authority**: Having two `ToolLoopGuard` instances operating on the same `ctx` makes it unclear which guard is authoritative for dedup/cycle/retry checks.
3. **Inconsistent guard state**: If someone later tries to use `self._llm_runner`, they would get different guard behavior than the active path because the two `ToolLoopGuard` instances have separate `_empty_result_counts` dicts.

## Reason for change
Dead code violates the principle of least surprise and increases maintenance cost. Removing these fields clarifies that `LlmTurnExecutor` is the sole owner of tool-loop guard logic for the current execution path.

## Implementation intent
Phase 1: Add deprecation warnings to both fields and migrate test callers to use `LlmTurnExecutor` directly. Phase 2: Remove the fields entirely after all callers are migrated. No behavioral change expected since neither was ever called within the Orchestrator class itself.

## Design
### Phase 1: Deprecation

Replace direct field assignments with property-based accessors that emit warnings:

```python
# In __init__:
self._llm_runner = LLMTurnRunner(ctx, self._guard, tracer=tracer)
self._guard = ToolLoopGuard(ctx)
```

Becomes:

```python
# In __init__:
self._llm_runner = LLMTurnRunner(ctx, self._guard, tracer=tracer)
self._guard = ToolLoopGuard(ctx)

@property
def _llm_runner(self):
    import warnings
    warnings.warn(
        "Orchestrator._llm_runner is deprecated. Use Orchestrator._llm_executor.handle_llm_turn() instead.",
        DeprecationWarning,
        stacklevel=2,
    )
    return self.__dict__.get("_llm_runner")

@_llm_runner.setter
def _llm_runner(self, value):
    import warnings
    warnings.warn(
        "Orchestrator._llm_runner is deprecated. Use Orchestrator._llm_executor.handle_llm_turn() instead.",
        DeprecationWarning,
        stacklevel=2,
    )
    self.__dict__["_llm_runner"] = value

@property
def _guard(self):
    import warnings
    warnings.warn(
        "Orchestrator._guard is deprecated. Create ToolLoopGuard directly if needed.",
        DeprecationWarning,
        stacklevel=2,
    )
    return self.__dict__.get("_guard")

@_guard.setter
def _guard(self, value):
    import warnings
    warnings.warn(
        "Orchestrator._guard is deprecated. Create ToolLoopGuard directly if needed.",
        DeprecationWarning,
        stacklevel=2,
    )
    self.__dict__["_guard"] = value
```

### Phase 2: Migration and Removal

Migrate all test callers:
- `orch._llm_runner.run(...)` → `orch._llm_executor.handle_llm_turn(...)` (adjusting parameter names as needed)
- `orch._guard.check_all(...)`, `orch._guard.check_error_limit(...)`, etc. → create new `ToolLoopGuard(ctx)` instances in each test

After all callers are migrated, remove the fields entirely:
- Delete `self._guard = ToolLoopGuard(ctx)` from `__init__`
- Delete `self._llm_runner = LLMTurnRunner(...)` from `__init__`
- Remove the property accessors
- Remove unused imports (`from agent.tool_loop_guard import ToolLoopGuard`, `from agent.llm_turn_runner import LLMTurnRunner`)
