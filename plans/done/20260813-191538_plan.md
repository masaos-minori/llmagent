# Plan: Type the `server_tool_lists` tool-descriptor shape in `route_resolver.build_discovery_map`

## Goal
Close a documented type-safety gap (`skills/DESIGN.md` — avoid raw `dict[str, Any]` for core
domain data) by giving `build_discovery_map`'s `server_tool_lists` parameter a `TypedDict`-based
type instead of `dict[str, list[dict[str, Any]]]`, with zero runtime behavior change. This is a
static-typing-only change: `build_discovery_map`'s logic, its `isinstance`/truthiness guard on
`name`, and its return shape must remain byte-for-byte identical, and `ToolRouteResolver`'s
routing/resolution logic must not change at all.

## Assumptions
- The `TypedDict` is defined locally in `scripts/shared/route_resolver.py` (not added to
  `scripts/shared/types.py`) because none of the three consuming test files need to import it —
  mypy performs structural checks on dict literals passed directly at a call boundary against the
  parameter's declared `TypedDict` type, so plain `{"name": ..., ...}` literals in the test files
  continue to type-check without any new imports. Placing it in `route_resolver.py` (the sole
  definition + consumption site) keeps the diff smallest, consistent with the coding convention
  to prefer minimal, accurate diffs.
- `total=False` (rather than per-field `NotRequired`) is used for the whole `TypedDict`, since
  every field it has (`name`, `server_key`) is optional-per-literal across the three test files'
  fixtures (some omit `server_key` entirely; `name` is always present as a key but its value is
  sometimes deliberately malformed in one test).
- Python 3.13 (`pyproject.toml` `target-version`) supports `TypedDict`/`total=False` natively via
  `typing` — no `typing_extensions` dependency needed.

## Design
`build_discovery_map` (defined at `scripts/shared/route_resolver.py:27-56`) is a pure, standalone
function — not a method of `ToolRouteResolver` — that reduces a live-discovery payload
(`{server_key: [tool_descriptor, ...]}`) into a routing map and a duplicate-ownership report. It
sits below `ToolRouteResolver` in the same module and has no import-boundary implications: it
imports nothing new, and its only production-adjacent neighbor (`ToolRouteResolver.__init__`'s
`discovery_map: dict[str, str] | None` parameter) consumes `build_discovery_map`'s *first return
value*, not its input, so the parameter retype has no ripple into `ToolRouteResolver`.

The new type:
```python
class ToolDescriptor(TypedDict, total=False):
    """One tool-descriptor entry from a server's /v1/tools discovery payload."""

    name: str
    server_key: str  # present in some fixtures; ignored by build_discovery_map (outer dict key is authoritative)
```
placed directly above `build_discovery_map`, replacing the `Any` import with this locally-scoped
type. `server_tool_lists: dict[str, list[dict[str, Any]]]` becomes
`server_tool_lists: dict[str, list[ToolDescriptor]]`. The function body (`tool.get("name")`, the
`isinstance(name, str) or not name` guard, the warning log, and the returned `route_map`/
`duplicates`) is untouched — `total=False` means `tool.get("name")` still type-checks (the key may
be absent), preserving the existing defensive-read pattern exactly.

This is a leaf-level typing change: no other module reaches into `build_discovery_map`'s
parameter type, so there is no cross-file propagation beyond the three test files that construct
literals for it directly at the call boundary.
