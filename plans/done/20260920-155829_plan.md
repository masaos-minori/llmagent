## Reason for change
Each finding duplicates a claim whose canonical source is code or an operational config
file (per `docs/00_governance_01_documentation-policy.md` Claim Type Taxonomy:
`configuration-schema` → the dataclass definition, `production-effective-value` →
`config/*.toml`). A table cell stating both the code default and the current
operational value (e.g. `03_rag_05_1` line 93) must be hand-kept in sync and will go
stale independently — the exact drift mode this policy targets.

## Implementation intent
For each flagged table/cell, replace the mechanically-derivable listing with a concise
pointer to the owning dataclass or config file, and retain only information that is not
code-derivable: cross-field constraints, stage/mode-applicability distinctions,
default-value rationale, and failure-mode/severity intent. Step 3's inspection found
that `SearchDiagnostics` is defined twice under the same name in two different modules
(`scripts/rag/diagnostics.py` — a 4-field diagnostics-extraction dataclass — and
`scripts/rag/models_result.py` — a 9-field dataclass with additional Remote-mode
fields); `03_rag_04_02_dto-models_result.md` documents the `models_result.py` version
specifically (its Local/Remote field split matches `models_result.py`'s fields exactly,
not `diagnostics.py`'s). Any pointer this Plan's implementation adds MUST cite
`scripts/rag/models_result.py::SearchDiagnostics` by full module path, not the bare
class name, to avoid ambiguity with the unrelated same-named class.
