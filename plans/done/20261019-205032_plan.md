## Goal
- Give the three Memory change-event writers (`write_ops.delete`, `pin_ops.pin`/`unpin`, and `memory_data_ops.memory_prune`) a single shared accessor that resolves the JSONL archive path from the top-level `memory_jsonl_dir` config key, so `/memory delete`, `/memory pin`, `/memory unpin`, and `/memory prune` append their change events instead of raising `KeyError` after the SQLite change has been committed.

## Scope

  - Add one shared path resolver in the `agent` layer that returns the JSONL archive directory from the flat `memory_jsonl_dir` key using the builder's default.

## Background
`agent.toml` declares `memory_jsonl_dir` as a top-level key, and `config_builders._build_memory_config` reads it as a top-level key with a builder default to populate `MemoryConfig.memory_jsonl_dir`. `ConfigLoader().load("agent.toml")` returns that raw flat dict verbatim (it does not nest keys under a `memory` table); the nested `memory` mapping only exists on the built `ctx.cfg.memory` dataclass. The three change-event writers were written to read `cfg["memory"]["memory_jsonl_dir"]` from the raw loaded dict, which has no `memory` key.

## Problem
On the main path (no injected connection), each writer commits its SQLite change and then appends a change event to `memories.jsonl`. The append step reads the archive path via `Path(cfg["memory"]["memory_jsonl_dir"]) / "memories.jsonl"`. Against the real flat config this raises `KeyError('memory')` because `cfg` has no `memory` key. Because the writers are SQLite-first, the SQLite change already stands when the `KeyError` escapes, so the command crashes after having mutated the database and after having printed nothing. The failure is invisible to the suite: `test_memory_data_ops.py::TestEmitPruneEvent` mocks `ConfigLoader.load()` to return the wrong nested shape `{"memory": {"memory_jsonl_dir": ...}}`, and `test_memory_store.py` replaces `_emit_delete_event`/`_emit_event` with mocks, so neither path exercises the real config read.

## Reason for Change
Every `/memory delete`, `/memory pin`, `/memory unpin`, and `/memory prune` that matches a real id currently fails at the archive-append step with an uncaught `KeyError`. The SQLite change stands but the command never completes, and no audit/JSONL record is written. This is a normal-use runtime failure, not an edge case.

## Implementation Intent
Introduce one shared resolver in the `agent` layer that loads the flat config and returns the `memory_jsonl_dir` value using the same accessor/default policy as `config_builders._build_memory_config`. Replace the three nested reads with a call to that resolver, preserving the SQLite-first ordering and the re-raise of real append failures. Correct the one test that mocks the wrong shape, then add tests that run the real loader against the isolated temporary root.

## Design
The defect is a config-shape mismatch: `ConfigLoader().load("agent.toml")` returns the raw flat TOML dict where `memory_jsonl_dir` is a top-level key, but the three writers index it as `cfg["memory"]["memory_jsonl_dir"]`, which has no `memory` key and raises `KeyError`. The fix centralizes the correct access in one resolver so the flat-key read cannot drift again.

Placement: the resolver lives in the `agent.memory` package and imports `ConfigLoader` from `shared`. This is inside the enforced `agent → shared` boundary (lint-imports 6/6 KEPT). `agent.commands.memory_data_ops` importing from `agent.memory` is a within-layer edge, which importlinter does not forbid. The resolver reproduces `config_builders._build_memory_config`'s accessor policy (flat key + builder default) so the archive path matches `ctx.cfg.memory.memory_jsonl_dir` used everywhere else.

Behavioral invariants preserved by construction: the resolver returns only a path string; the callers still append after the SQLite commit and re-raise real append failures (M-07). No JSONL format or archive name changes.
