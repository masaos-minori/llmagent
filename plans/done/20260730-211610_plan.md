# Work Plan: Clean Up Health Check Timestamps When Servers Are Removed

## Goal

Ensure `_last_health_check` entries are cleaned up when an MCP server key is removed from configuration, preventing bounded memory leak.

## Scope

**In-Scope:**
- Identify where server keys are removed from `ctx.cfg.mcp.mcp_servers` during hot-reload
- Add cleanup of corresponding `_last_health_check` entry alongside existing cleanup operations

**Out-of-Scope:**
- Adding hot-reload support (this is about cleaning up after removal that already happens)
- Cleaning up other dictionaries that may also leak (`_stderr_files`, `_stderr_log_paths`)
- Modifying shutdown/restart paths (those already clean up correctly)

## Assumptions

1. Hot-reload removes server keys from `ctx.cfg.mcp.mcp_servers` dict
2. The same cleanup method used for `_stderr_files` and `_stderr_log_paths` should also clear `_last_health_check`
3. A dedicated cleanup method would be cleaner than scattered cleanup calls

## Implementation Steps

1. **Phase 1: Preparation**
   - [ ] Search codebase for hot-reload implementation to identify where server keys are removed

2. **Phase 2: Core Logic Implementation**
   - [ ] Add `_cleanup_server_resources(self, server_key: str) -> str` method that:
     - Reads stderr tail via `self._read_stderr_tail(server_key)`
     - Pops and closes the stderr file handle from `self._stderr_files`
     - Pops the log path from `self._stderr_log_paths`
     - Pops the health check timestamp from `self._last_health_check`
     - Returns the stderr content string
   - [ ] Call this method wherever server keys are removed from `ctx.cfg.mcp.mcp_servers` during hot-reload
   - [ ] Also consider replacing inline cleanup in `start()` with calls to this method (addresses DRY issue simultaneously)

3. **Phase 3: Deployment & Verification**
   - [ ] Run `ruff check scripts/agent/http_lifecycle.py` to verify lint passes
   - [ ] Run `pytest tests/test_lifecycle*.py -v` to verify existing tests pass
   - [ ] Verify no new mypy errors introduced
