## Background
`docs/03_rag_01_system_overview.md`'s "Constraints" table (lines 163-173) lists 7 constraints — this table's structure and content have changed since the Issue was filed: it no longer contains the "Constraint | Reason" format or the "Embedding server must be available..." row the Issue's Evidence quotes (that item now lives in the "Prerequisites" section, already resolved for a related Issue earlier in this batch). The current 7 rows (Language Detection, Chunk Size, Chunk Overlap, Embedding Dimension, Crawl Depth, Max Pages Per Site, Database) are the actual current scope. For each, Step 3 code/ADR inspection found:
- **Embedding Dimension**: `scripts/db/store_protocols.py`'s `validate_embedding_blob()` (lines 38-47) raises `TypeError`/`ValueError` on any size mismatch — strictly enforced programmatically; the value (1024) is documented in-code as the Qwen3 model's dimension count (line 13, 25).
- **Database (SQLite single node)**: `docs/adr/ADR-008-sqlite-4db-separation.md`'s Assumptions ("対象環境：単一Host、複数プロセス") and Rationale (Operability/Performance/Data Integrity/Correctness, lines 91-101) already document both why and the architectural nature of this constraint.
- **Language Detection**: `scripts/rag/ingestion/crawler_utils.py`'s `detect_lang()` (lines 130-141) enforces the CJK-ratio-≥-0.10 rule programmatically and returns `None` (triggering a documented hint-language fallback) for text under 100 characters — but the `0.10` threshold itself has no rationale comment.
- **Chunk Size (40/500)** and **Chunk Overlap (50)**: `chunk_splitter.py` enforces both via `merge_text_items()`/inline length checks (confirmed at lines 168-169, 185-186); `docs/03_rag_05_1-configuration-reference.md` line 39 already documents that sub-40-char chunks are discarded as noise — but the specific values 40/500/50 have no documented rationale.
- **Crawl Depth (3)** and **Max Pages Per Site (200)**: `crawler.py` reads `max_depth`/`max_pages` from config (lines 61, 66) and stops BFS traversal at the limit (already documented behavior, per `docs/03_rag_05_1-configuration-reference.md` lines 31, 35) — but the specific operational values 3/200 have no documented rationale.

## Problem
The Issue's four questions per constraint split into two kinds: (1) violation behavior and enforcement mechanism, both answerable directly from existing code/ADR evidence for all 7 constraints; (2) the deeper "why this specific value" rationale, which does not exist anywhere in the repository for 5 of the 7 constraints (the other 2 — Embedding Dimension and Database — already have a documented rationale).

## Reason for change
Per the Issue's Impact: operators don't understand constraint violation consequences, and new developers may not realize prerequisites must be met. Documenting the answerable half directly, and tracking the unanswerable half as Needs Confirmation (rather than inventing a rationale), addresses this without misrepresenting undecided design values as settled.

Separately, add 3 new Needs Confirmation entries to `docs/00_governance_03_issue-and-uncertainty-management.md` Part 2 grouping the 5 unrationale'd values by their config-file proximity: (a) CJK ratio threshold (`crawler_utils.py`); (b) chunk size/overlap values (`chunk_splitter.py`/`config/chunk_splitter.toml`); (c) crawl depth/max-pages operational values (`config/crawler.toml`).
