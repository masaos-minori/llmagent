## Background
The Issue was filed because the ADR-008 amendment plan deferred the rename: the ADR title already reads "Separation and Lifecycle Policy for Six SQLite Stores" and its body, the ADR index entry, and the document guide describe six stores, but the file name still says `4db`. Repository evidence checked on 2026-11-24:
- The old name appears in 18 files outside `issues/`, `plans/`, and `implementations/` (13 documents and 5 tool files) and in five open issues; the exact lines are in the target table. No match exists in `tests/`, `config/`, `.github/`, `deploy/`, or `docs/00_index.md`.
- Two tool files hold the slug only inside the file names of archived implementation procedures (`tools/check_archived_status_baseline.txt`, `tools/check_status_value_baseline.txt`); those procedures are history, so the baselines do not change. The short form `adr_02_05_008` (without the slug) appears in a comment of `tools/check_docs_structure.py` and in one sentence of `docs/23_agent/agent_10_01_operations-and-observability-startup-and-health.md`; it still names the ADR and needs no change.
- The ADR id is read from the three-digit number by `ADR_FILE_RE` (`adr_02_<group>_<NNN>_<slug>.md`) in `tools/_adr_authority_core.py`, so a new slug does not change the id, the authority graph, or the guarded index sections.
- `tools/check_docs_structure.py` keys its per-file size ceilings by base name (`"adr_02_05_008_db-sqlite-4db-separation.md": 46907`); the ADR is exactly at that ceiling, so the key must follow the rename. `docs/10_adr/adr_02_01_004_platform-environment-failure-handling-policy.md` is 36260 bytes against a ceiling of 36267, and the new file name is 6 bytes longer than the old one, so the front matter edit in that file leaves one byte of headroom. Three other documents sit exactly at their ceilings and gain 6 bytes per reference: `docs/00_governance/governance_03_issue-and-uncertainty-management.md` (5 references, 36807 to 36837 against 36807), `docs/10_adr/adr_01_index.md` (2 references, 41389 to 41401 against 41389), and `docs/10_adr/adr_02_04_006_eventbus-sqlite-persistence-and-sse-delivery.md` (1 reference, 39575 to 39581 against 39575); their ceilings are re-recorded in `tools/check_docs_structure.py` (measured in Step 3a).
- All ADR checks, the eight docs consistency domains, the drift checks, and the docs structure check pass on the current tree.

## Problem
The file name says four-database separation while the ADR, its index entry, and the Known Issues describe six stores, so the name misleads a reader and a file search for the title. The cost of fixing it is the number of active references.

## Reason for Change
The ADR amendment is complete, so the name is the last inconsistent label. It is not urgent (no operator takes a wrong action because of it), and the longer it waits the more documents cite the old name, so it is best done as one dedicated change.

Keep archived work items and the baseline files that hold archived procedure names unchanged, because they are history. Use `git mv` so the file history follows. - Procedure ordering: the rename procedure is first (`seq` 01) and marks the new path `(new)`; later procedures cite the new path and resolve it from that sibling.
- Consumer scan and predictable fallout check: this is a file rename and a constant key change, so `tools/scan_change_consumers.py` is not applicable; pinned counts: no test asserts the ADR file name (`rg` over `tests/` finds none); tool inventory and module size: `not affected`; generated blocks: the guarded index sections are id-based and stay unchanged (`generate_adr_authority.py --check` is a validation step); size ceilings: the ADR-008 key follows the rename, and ADR-004 is measured.

- Operational check: no process or database is touched (not run). Persisted schema check (`rules/persisted-schema-change.md`): not applicable, no DDL or migration changes.
