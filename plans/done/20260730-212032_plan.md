# Work Plan: Fix SIGINT Handler Race Condition During Shutdown

## Goal

Fix both race conditions in signal handler management during shutdown_all(): prevent restoring a handler that was never replaced, and avoid invalid `signal.signal(signal.SIGINT, None)` call.

## Scope

**In-Scope:**
- Track whether the new handler was successfully installed before attempting restoration
- Only restore the original handler if replacement succeeded

**Out-of-Scope:**
- Modifying the `_absorb_sigint_during_shutdown` handler itself
- Adding additional signal handlers
- Changing the subprocess termination logic

## Assumptions

1. When `signal.signal()` raises ValueError, the original handler remains unchanged
2. When `signal.getsignal()` returns None, it means the default handler is active and cannot be restored
3. The existing try-except around `signal.getsignal()` already handles non-main-thread cases
