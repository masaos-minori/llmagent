# Document the Markdown-heading-to-sentence-chunking fallback mechanism

## Goal
Expand `docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md`'s "Markdown
Heading Chunking Behavior" subsection to explain when the fallback from
heading-based chunking to sentence-based chunking triggers, how the two
strategies combine (sequential, per-section), what happens to chunk metadata
during fallback (no distinction — all chunks share the same `chunk_type`), and
one confirmed edge case (undersized sections being silently dropped).

## Background
The Issue's cited claim
(`docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md:190`: "Text is split by
Markdown headings (# through ######). Sections exceeding `md_snippet_max_chars`
characters are further split using sentence-based chunking.") is confirmed
accurate against `_chunk_markdown_by_heading()`
(`scripts/rag/ingestion/chunk_splitter.py:158-175`).

**Re-verified 2026-09-13** (this cycle): read the full implementation to answer
each of the Issue's 4 requested points:
1. **Fallback trigger**: line 169, `if len(section) <= self._md_snippet_max_chars:`
   — a section is chunked as-is only if it fits within
   `md_snippet_max_chars` (default 600, confirmed at
   `chunk_splitter.py:77`); otherwise (line 172-174) it falls back to
   `self._chunk_english(section)` (sentence-boundary splitting)
2. **How the strategies combine**: sequential, per-section — the text is first
   split into heading-delimited sections (line 161-163, `re.split` on heading
   boundaries), then *each section independently* either passes through as one
   chunk or is further split by `_chunk_english()`; the two strategies are not
   applied in parallel or merged, each section takes exactly one path
3. **Chunk metadata during fallback**: no distinction is made — the caller
   (`chunk_splitter.py:221`: `return [("text", c, "") for c in
   self._chunk_markdown_by_heading(content)]`) tags every chunk this method
   returns with the same literal `"text"` chunk-type marker, regardless of
   whether that specific chunk came from a whole heading section or from a
   `_chunk_english()`-split fragment of an oversized one — there is no
   metadata field distinguishing "heading chunk" from "fallback-split chunk"
4. **Confirmed edge case**: line 169-171 — a section that fits within
   `md_snippet_max_chars` but is *smaller* than `self._min_chunk` is silently
   dropped (`if len(section) >= self._min_chunk: chunks.append(section)` — the
   `append` only happens inside this inner check; a too-small section produces
   no chunk at all, not an error or warning)

## Problem
A developer investigating why a document's chunk count or chunk sizes don't
match expectations from the heading structure alone has no documented
explanation of the fallback trigger, the metadata implications (fallback chunks
are indistinguishable from whole-section chunks), or the silent-drop edge case
for undersized sections.

## Reason for change
Document the confirmed fallback trigger, combination model, metadata behavior,
and edge case so a developer can reason about chunk output from the documented
behavior alone, without needing to read `_chunk_markdown_by_heading()`'s source.

## Implementation intent
Expand the existing "### 3.1.4 Markdown Heading Chunking Behavior" subsection
(after its current one-paragraph description) with: (1) the exact trigger
condition (`len(section) > md_snippet_max_chars`, default 600); (2) the
sequential, per-section combination model — each section takes exactly one path,
never both; (3) that fallback-split chunks carry no distinguishing metadata from
whole-section chunks (all tagged `"text"`); (4) the confirmed edge case that
sections shorter than `min_chunk` are silently dropped, producing no chunk.
