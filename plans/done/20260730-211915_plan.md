# Work Plan: Fix File Descriptor Leak and Zombie Process on getpgid Failure

## Goal

Eliminate file descriptor leak and prevent zombie processes when `getpgid()` fails during HTTP subprocess MCP server startup.

## Scope

**In-Scope:**
- Use try-finally to guarantee file handle closure regardless of exceptions during startup
- Kill the process if it survives terminate/kill escalation in the getpgid failure path

**Out-of-Scope:**
- Fixing file handle leaks in other error paths (separate concern)
- Adding retry logic to the getpgid operation
- Handling the case where pgid is lost due to OSError (the process group is already lost)

## Assumptions

1. When `getpgid()` fails, the process group information is unrecoverable — we must fall back to per-process termination
2. A process that survives terminate+kill is truly stuck and needs SIGKILL on the process directly
3. The file handle should always be closed even if an exception occurs between opening and cleanup

     stderr_fh = self._open_stderr_log(server_key)

     try:
         self._http_pgids[server_key] = os.getpgid(proc.pid)

         logger.warning("Lifecycle: getpgid() failed for %r pid=%d; cleaning up", ...)
         await self._terminate_with_timeout(proc, server_key)
         poll_result = proc.poll()
         if poll_result is None:
             logger.warning("Lifecycle: subprocess %r (pid=%d) still alive after terminate/kill; killing", ...)
             try:
                 proc.kill()
             except (ProcessLookupError, OSError):
                 pass
         elif poll_result != 0:
             logger.info("Lifecycle: subprocess %r (pid=%d) terminated with exit code %d", ...)
         raise  # Re-raise to trigger finally block
     finally:
         fh = self._stderr_files.pop(server_key, None)
         if fh is not None:
             try:
                 fh.close()
             except OSError:
                 pass
         self._stderr_log_paths.pop(server_key, None)
         self._http_procs.pop(server_key, None)
         self._http_pgids.pop(server_key, None)

## Risks & Mitigations

- **Risk:** Re-raising in the getpgid path changes control flow — callers may not expect the exception → **Mitigation:** Current code doesn't catch the OSError from getpgid; the exception propagates naturally
- **Risk:** `proc.kill()` may fail silently if process already exited → **Mitigation:** Wrap in try-except for ProcessLookupError/OSError
- **Risk:** Finally block may run after process is already cleaned up → **Mitigation:** Use `.pop(key, None)` pattern which is safe for missing keys
