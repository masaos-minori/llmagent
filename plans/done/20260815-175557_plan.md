# Work Plan: Add protocol validation for CLIView Writer/Reader test doubles

## Goal
Add runtime validation that checks whether test doubles implementing the `Writer` and `Reader` Protocols implement all required methods, catching incomplete implementations at instantiation time rather than at runtime.

## Scope
- Add `_validate_protocol_compliance(obj, protocol)` helper function in `scripts/agent/cli_view.py`
- Call validator in `CLIView.__init__` or wherever Writer/Reader dependencies are accepted
- Add unit tests for protocol validation with various incomplete implementations including edge cases
- Add integration test verifying diagnostic output during startup/shutdown

## Assumptions
1. `typing.get_protocol_members()` is available in Python 3.13 (it was added in 3.13)
2. `inspect.getmembers()` can reliably extract method names from Protocol classes
3. The validation should only apply to non-Protocol types (i.e., skip if obj already satisfies the Protocol via `isinstance`)
4. Writer/Reader Protocols are standalone definitions not currently consumed by CLIView or other classes
5. Raising `NotImplementedError` or `TypeError` with a descriptive message is appropriate for validation failures

## Design
The current `Writer` and `Reader` Protocols use `@runtime_checkable` (line 24, line 75). This allows structural subtyping but does not enforce completeness at runtime. A test double could omit some methods and still pass type checking, leading to `AttributeError` at runtime.

Two approaches are considered:
1. **Decorator approach**: Decorate classes that claim to implement the Protocol, validating at decoration time.
2. **Constructor injection approach**: Validate when Writer/Reader is passed as a dependency to CLIView or similar consumers.

Approach 2 is preferred because it catches violations at the point of use without requiring changes to every test double class definition. The validation function extracts required members from the Protocol using `typing.get_protocol_members()` and verifies each one exists on the instance using `hasattr`.

```python
from typing import get_protocol_members

def _validate_protocol_compliance(obj: object, protocol: type) -> None:
    """Raise TypeError if obj doesn't implement all members of protocol."""
    missing = []
    for name in get_protocol_members(protocol):
        if not hasattr(obj, name):
            missing.append(name)
    if missing:
        raise TypeError(f"{obj!r} is missing Protocol members: {missing}")
```

For Python versions before 3.13, fall back to `inspect.getmembers()` filtering by callable attributes defined directly on the Protocol class.

## Risks
1. **Existing test doubles may fail**: Some test doubles might already be incomplete; validation would surface these as errors
2. **Python version compatibility**: `typing.get_protocol_members()` is only available in Python 3.13+; need fallback for older versions
3. **Performance overhead**: Validation adds a small cost at instantiation time; acceptable given low frequency
4. **False positives**: If a test double uses `__getattr__` to dynamically provide methods, `hasattr` might return True even though the method isn't truly implemented
