## Goal

Route all workflow table queries through StateStore's public API instead of bypassing it with direct SQLiteHelper connections.

## Scope

**In**: `scripts/agent/repl.py` (AgentREPL._persist_session_diagnostics()), `scripts/agent/workflow/state_store.py` (StateStore)
**Out**: Changes to workflow table schema, other workflow query patterns outside diagnostics

## Assumptions

1. StateStore holds uncommitted writes that should be visible to diagnostic queries
2. Adding methods to StateStore does not violate architecture boundaries (agent → db layer)
3. The diagnostic queries are: task count, workflow count, approval events, retry count, artifacts

## Unknowns

| Unknown | Evidence missing | Resolution | Blocking |
|---|---|---|---|
| Exact columns available in workflow tables for each query type | Need to inspect workflow.sqlite schema | Read deploy/schema.sql or similar migration files | no |

## Implementation Steps

1. In `StateStore`, add a method `get_task_count(session_id: str) -> int` that returns `COUNT(*)` for the given session_id. This replaces the raw SQL at repl.py line 23-27.
2. In `StateStore`, add a method `get_workflow_count(session_id: str) -> int` that counts distinct workflow_ids for the session. May need to be added as a new method.
3. In `StateStore`, add a method `get_approval_events(task_id: str) -> list[dict]` that fetches approval records for a task. May need to be added as a new method.
4. In `StateStore`, add a method `get_retry_count(task_id: str) -> int` that counts retry attempts. May need to be added as a new method.
5. In `StateStore`, add a method `get_artifacts(task_id: str) -> list[dict]` that fetches artifact records. May need to be added as a new method.
6. In `repl.py`, replace the direct `SQLiteHelper("workflow").open(row_factory=True)` block with calls to the StateStore instance passed from the caller.
7. Ensure the StateStore instance reflects any pending writes before querying.
