## Goal
- Make the `issue-to-plan` workflow instruct the AI to generate the Plan's `Affected areas` and `Risks` sections in Step 5 and verify both in Step 8a, so that every generated Plan conforms to `templates/plan.md` for those sections.

## Priority
High

## Scope
- **In-Scope**:
  - Append an `Affected areas` generation instruction to `skills/issue-to-plan/workflow.md` Step 5 (Generate the Plan), with the Path A / Path B distinction.
  - Append a `Risks` generation instruction to Step 5, and state that Step 5 writes the Plan's inline `Risks` section and Step 6 refines that same section.
  - Append `Affected areas` and `Risks` checks to Step 8a's verification list.
  - Verify that `skills/issue-to-plan/SKILL.md` Output format stays consistent with the added instructions.
- **Out-of-Scope**:
  - Adding or changing sections of `templates/plan.md`.
  - Changing the Path A / Path B classification criteria.
  - Modifying `templates/execution-status.md` or `templates/requirement-traceability.md`.
  - Fixing already generated non-conformant plans (separate issue).
  - Restructuring or rewriting existing workflow text, or renumbering steps.

## Background
Investigation of the plans generated on 2026-10-08 found plans without `Affected areas` and `Risks` sections. The cause traced to the workflow: Step 5 has no generation instruction for either section, and Step 8a's completeness list names risks and mitigations only loosely and does not name `Affected areas` at all.

## Problem
- `Affected areas`: no step tells the AI to generate it; Step 8a does not verify it. Step 4 maps Target files to it only by reference, and the Path B historical and dependency tools (`git churn`, `git-fame`, `pydeps`) are never tied to filling the table.
- `Risks`: Step 4 maps Constraints and repository evidence to it, but Step 5 has no explicit instruction, and Step 6 does not say whether it writes the Plan's inline section or only a separate file.

## Reason for change
Plans that omit required sections cannot be consumed reliably by `plan-to-implementation-procedure` and `code-implementation`. The gap is a workflow defect: the AI follows the instructions it is given.

## Implementation intent
Append instructions only. Add the two generation instructions to Step 5, the two checks to Step 8a, and one clarifying sentence on the Step 5 / Step 6 relationship for Risks. Keep existing text, step numbering, and the Path A / B split unchanged. Reuse the column definitions and value vocabulary already defined by `templates/plan.md` and `skills/DESIGN.md` Change-impact table by reference instead of copying them.

## Requirements
- `REQ-001`: Step 5 instructs the AI to generate the `Affected areas` table with one row per `Implementation Target Files` row and all six columns (File, Change, Blast Radius, Churn (30d), Bus Factor, deploy.sh Impact); Path B fills Churn and Bus Factor from the historical analysis results where the tools are available and marks `N/A` otherwise; Path A gives a qualitative Blast Radius only and marks Churn and Bus Factor `N/A`.
- `REQ-002`: Step 5 instructs the AI to generate the `Risks` section by extracting a risk from each Constraint and each repository evidence finding and pairing it with a mitigation, and states that Step 5 writes the inline `Risks` section which Step 6 refines (not a separate file).
- `REQ-003`: Step 8a's verification list includes `Affected areas`: every row's File is a subset of the `Implementation Target Files` rows, and all six columns are populated or marked `N/A`.
- `REQ-004`: Step 8a's verification list includes a structural `Risks` check: every Risk entry has a corresponding Mitigation.
- `REQ-005`: `skills/issue-to-plan/SKILL.md` Output format and Phase overview remain consistent with REQ-001 to REQ-004; a change there is made only if an inconsistency is found.
- `REQ-006`: The change appends text only: existing workflow text and step numbering are preserved, `templates/plan.md` is unchanged, all added text is English, and `check_workitem_structure.py` still passes against an existing plan.
