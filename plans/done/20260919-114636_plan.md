## Goal
Reduce complexity of `ConfigReloadService.apply_config_dict()` by extracting five distinct responsibilities into smaller private methods without changing public behavior.

## Priority
Medium

## Scope
- **In-Scope**: Extracting private methods from `apply_config_dict()`, updating docstrings, fixing pre-existing test failures
- **Out-of-Scope**: Changes to `config_field_registry.py`, `config_validators.py`, `config_section_reload.py`, `config_service_sync.py`, `config_outcome_classification.py`; adding new features or changing public APIs

## Background
`ConfigReloadService` was previously part of `_ConfigMixin` in `scripts/agent/commands/cmd_config.py`. The migration extracted config handling into dedicated modules (`config_section_reload.py`, `config_outcome_classification.py`, `config_service_sync.py`). However, `apply_config_dict()` itself remains monolithic with multiple concerns mixed together.

## Problem
`apply_config_dict()` (~44 lines) performs five distinct operations: section-based reload, direct field updates, MCP server change classification + lifecycle cleanup, service sync, and outcome classification. This violates the Single Responsibility Principle and makes the method hard to follow, test, and modify. Additionally, 14 existing tests fail due to CONFIG_FIELD_REGISTRY import issues.

## Reason for change
Maintainability risk: the method's size and mixed concerns make it difficult to add new configuration sections or modify existing ones without risking unintended side effects.

## Implementation intent
Extract each of the five responsibilities into separate private methods on `ConfigReloadService`. Each extracted method returns a partial `ConfigReloadOutcome` that gets merged into the final result, preserving the current return contract while improving internal organization.

## Requirements
- `REQ-001`: Extract section-based reload logic into `_apply_sections()` private method
- `REQ-002`: Extract direct field updates into `_apply_direct_fields()` private method
- `REQ-003`: Extract MCP server change classification + lifecycle cleanup into `_handle_mcp_changes()` private method
- `REQ-004`: Extract service sync + outcome classification into `_sync_and_classify()` private method
- `REQ-005`: Update `apply_config_dict()` docstring to reference new internal structure
- `REQ-006`: Fix pre-existing test failures related to CONFIG_FIELD_REGISTRY imports

## Design
The refactoring follows the Extract Method pattern (Fowler). Each extracted private method receives the minimal parameters needed to perform its single responsibility. The `apply_config_dict()` method becomes a thin orchestrator that calls these methods sequentially and merges their results.

Key design decisions:
- Each extracted method returns a partial `ConfigReloadOutcome` rather than mutating the outcome passed in — avoids shared mutable state and makes each method independently testable
- The `ConfigReloadOutcome` dataclass is reused as the merge mechanism — no new types introduced
