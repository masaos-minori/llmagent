# Plan: Eliminate cross-module duplication in HttpServerLifecycleManager

## Goal
Consolidate duplicated lifecycle logic across `scripts/agent/http_lifecycle*.py` modules so that `HttpServerLifecycleManager` delegates exclusively to its six concern-specific components, removing inline implementations that duplicate those modules' responsibilities.

## Priority
Medium

## Scope
- **In-Scope**: Remove inline implementations from `HttpServerLifecycleManager`, delegate to concern-specific modules, unify liveness semantics, fix circular import, reduce `ProcessInfoSnapshot` fields
- **Out-of-Scope**: Adding new lifecycle operations (e.g., graceful restart with zero-downtime), changing the MCP server command allowlist, modifying stderr log rotation thresholds, adding process monitoring metrics or alerting, refactoring `McpServerConfig` or `StartupFailure` structures, adding support for non-process-based MCP servers (WebSocket, stdio)

## Background
`HttpServerLifecycleManager` was refactored to delegate to six concern-specific modules (CommandValidator, StderrLogManager, ProcessTerminator, HealthChecker, ProcessSnapshotProvider, ShutdownCoordinator). However, the main class retains its own inline implementations of termination, shutdown, and snapshot logic that duplicate the work of those delegated modules. Additionally, `ProcessInfoSnapshot` carries 22 fields most of which are unused in practice.

## Problem
Six concrete issues identified through cross-file analysis:

1. **`_terminate_with_timeout()` duplicates `ProcessTerminator.terminate_with_timeout()`** — Both implement SIGTERM → SIGKILL escalation with polling. The main class uses `os.killpg()` + `asyncio.sleep()` while ProcessTerminator does the same. Note: `_terminate_with_timeout()` has subtle behavioral differences — it checks `proc.poll()` before terminating (early-exit), includes a warning about children remaining when pgid wasn't used, and falls back to `proc.terminate()` when `os.killpg()` fails. These differences must be reconciled during migration.

2. **`shutdown_all()` duplicates `ShutdownCoordinator.shutdown_all()`** — Both iterate over `_http_procs`, send SIGTERM/SIGKILL, poll for exit, and clean up resources. The main class's version handles SIGINT absorption; the coordinator's version does not.

3. **`_build_snapshot_dict()` vs `ProcessSnapshotProvider.get_snapshot()`** — Partially overlapping but serving different purposes: `_build_snapshot_dict()` returns a simple dict with 7 fields (`server_key`, `managed`, `pid`, `pgid`, `running`, `last_exit_code`, `stderr_log`); `get_snapshot()` returns a JSON-serializable dict via `asdict(ProcessInfoSnapshot)` including ALL 22 fields. This is NOT a pure duplication — they serve different consumers.

4. **`list_processes()` duplicates `ProcessSnapshotProvider.list_processes()`** — Both iterate over `_http_procs` and produce snapshots. The main class produces `ProcessInfoSnapshot`; the provider does the same via `/proc`.

5. **`verify_running()` and `verify_running_async()` have inconsistent semantics** — One checks `proc.poll()` (process existence), the other makes an HTTP request. Callers cannot know which liveness model applies. Evidence: `factory.py:150-159` calls both methods sequentially in the same context.

6. **`HealthChecker.compute_health_check_timeout()` has a circular import** — Imports `MCPSERVER_HEALTH_TIMEOUT` from `agent.http_lifecycle` at runtime inside the method body.

## Reason for change
The dual implementation pattern increases maintenance burden: changes to termination/shutdown logic must be applied in two places. The circular import in `HealthChecker` is fragile and will break under certain import orders. `ProcessInfoSnapshot`'s 22-field structure is unmaintainable and unused beyond a handful of fields.

## Implementation intent
Establish a single delegation path per concern:

1. **Terminate**: Remove `HttpServerLifecycleManager._terminate_with_timeout()` and `_wait_exited()`. Have callers use `self._process_terminator.terminate_with_timeout()` and `self._process_terminator.wait_exited()` instead. Merge the SIGINT absorption logic from `shutdown_all()` into `ShutdownCoordinator.shutdown_all()` so shutdown cleanup lives in one place.

2. **Shutdown**: Remove `HttpServerLifecycleManager.shutdown_all()`'s inline SIGTERM/SIGKILL loop. Delegate entirely to `ShutdownCoordinator.shutdown_all()`. Move the SIGINT guard logic into the coordinator.

3. **Snapshot**: Remove `HttpServerLifecycleManager._build_snapshot_dict()` and `list_processes()`. Delegate to `ProcessSnapshotProvider.get_snapshot()` and `ProcessSnapshotProvider.list_processes()`.

4. **Liveness**: Unify `verify_running()` and `verify_running_async()` into a single method that always performs an HTTP health check. Remove the `proc.poll()` shortcut from `verify_running()`.

5. **Circular import**: Pass `MCPSERVER_HEALTH_TIMEOUT` as a parameter to `HealthChecker.compute_health_check_timeout()` or extract it to a shared constants module.

6. **ProcessInfoSnapshot**: Reduce to the 7 fields currently used by `_build_snapshot_dict()` (`server_key`, `managed`, `pid`, `pgid`, `running`, `last_exit_code`, `stderr_log`). Deprecate unused fields.

## Design
### Architecture decision: Single delegation per concern
The plan establishes a single delegation path per concern. `HttpServerLifecycleManager` becomes a thin composition facade — it owns state (`_http_procs`, `_http_pgids`, etc.) but delegates all lifecycle operations to its six components.

### Termination: Merge behavioral differences during migration
`_terminate_with_timeout()` has subtle differences from `ProcessTerminator.terminate_with_timeout()`:
- Early-exit when `proc.poll()` returns non-None
- Warning about children remaining when pgid wasn't used
- Fallback to `proc.terminate()` when `os.killpg()` fails

These differences must be reconciled: either add them to `ProcessTerminator` or remove them from the main class. Recommendation: add missing behaviors to `ProcessTerminator` first, then replace callers.

### Shutdown: Move SIGINT absorption into coordinator
`HttpServerLifecycleManager.shutdown_all()` handles SIGINT absorption via `_absorb_sigint_during_shutdown`. This logic belongs in `ShutdownCoordinator.shutdown_all()` since it is specific to the shutdown operation.

### Snapshot: Preserve both APIs temporarily
`_build_snapshot_dict()` returns a 7-field dict; `ProcessSnapshotProvider.get_snapshot()` returns a 22-field dict. These serve different consumers. After removing `_build_snapshot_dict()`, `get_process_snapshot()` should delegate to `ProcessSnapshotProvider.get_snapshot()` and return the full 22-field dict. Consumers expecting the 7-field dict will need to adapt.

### Liveness: Unify to HTTP health check
`verify_running()` checks `proc.poll()` (process existence); `verify_running_async()` makes an HTTP request. Unifying to HTTP-only means callers lose the ability to distinguish between "process dead" and "HTTP unhealthy." However, the current inconsistency is a bug — callers cannot know which liveness model applies.

### Circular import fix
Pass `MCPSERVER_HEALTH_TIMEOUT` as a parameter to `HealthChecker.compute_health_check_timeout()` instead of importing it at runtime inside the method body. This eliminates the circular dependency.

### ProcessInfoSnapshot reduction
Reduce the dataclass from 22 fields to 7 fields: `server_key`, `managed`, `pid`, `pgid`, `running`, `last_exit_code`, `stderr_log`. The other 15 fields are populated but never accessed by any known consumer. If backward compatibility is needed, consider keeping the old fields as deprecated properties.
