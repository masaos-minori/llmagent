## Goal
- ADR-004 Decision #8 が定める `failure_policy`（`fail-fast` / `disable-tool` / `degraded`）を、`required_in_production`/`required_in_local` が `true` の MCP サーバーに対しても選択可能にする。既存の `required=False` 時の Tool 除外・起動継続の仕組み（`RuntimeToolRegistry.unavailable_servers`）を活用し、真に不足している「required だが fail-fast ではない」という組合せを段階的に実装する。

Medium

  - `scripts/agent/startup.py`: 起動継続時のログ出力に、どの `failure_policy` が適用されたかを含める（既存の `unavailable_servers` 表示行の拡張）

## Background
ADR-004（Status: Proposed）Decision #8 は、MCP サーバーごとに `required_in_production`/`required_in_local` と `failure_policy`（`fail-fast`/`disable-tool`/`degraded`）を設定可能にすることを「検討する」としている。`failure_policy` フィールドは `scripts/shared/mcp_config.py:98,300` に既に定義・パースされているが、消費箇所が存在しない。

## Problem
- `scripts/agent/services/mcp_tool_discovery.py:discover_all()`（line 117-168）を確認した結果、サーバー到達不可時の判定は `is_required`（`required_in_production`/`required_in_local`）のみに基づく二値分岐（`FATAL` or `WARNING`）であり、`cfg.failure_policy` は一度も参照されない（`failure_policy`/`FailurePolicy` のリポジトリ全体 grep で定義・パース箇所以外にヒットなし）。
- ただし、`required=False` の場合に既に「`WARNING` + `unreachable.append(key)` → `unavailable_servers` へ登録 → 該当サーバーの Tool を `RuntimeToolRegistry` から除外しつつ起動継続」という仕組み（`scripts/agent/startup.py:557-567` で読み出し）が実装済みであり、これは ADR-004 の `disable-tool` が意図する動作と実質的に同じである。
- 真に不足しているのは「サーバーが `required=True`（可用性上は必須）だが、到達不可時に `fail-fast` ではなく `disable-tool`/`degraded` として扱いたい」という組合せを表現する手段のみである。issue が主張する「MCPサーバーは二値の required/not-required 以外の柔軟性を持てない」という Impact は、`required=False` 側では既に解消されており、`required=True` 側にのみ残存する。

## Reason for change
ADR-004 Decision #8 の実装を、既存の `unavailable_servers` 機構を再利用する形で段階的に進める。この段階では `required=True` サーバーに `disable-tool`/`degraded` を選択可能にすることに限定し、大規模な新機構の追加を避ける。

## Implementation intent
`discover_all()` のサーバー到達不可時の判定において、`is_required and cfg.failure_policy == FailurePolicy.FAIL_FAST`（デフォルト）の場合のみ `FATAL` とし、`is_required and cfg.failure_policy in (DISABLE_TOOL, DEGRADED)` の場合は `WARNING` を発行しつつ `unreachable.append(key)` に含める（`required=False` の既存経路と合流させる）。`startup.py` のログ出力で、適用された `failure_policy` の値を明示する。

## Requirements
- `REQ-001`: `scripts/agent/services/mcp_tool_discovery.py:discover_all()` の到達不可判定を、`is_required` 単独ではなく `is_required and cfg.failure_policy == FailurePolicy.FAIL_FAST` の場合のみ `FATAL` とするロジックに変更する。`failure_policy` が `disable-tool`/`degraded` の場合は `required` の値に関わらず `WARNING` + Tool 除外（`unreachable` へ追加）とする。
- `REQ-002`: `scripts/agent/startup.py` の `unavailable_servers` 表示ログに、各サーバーの `failure_policy` 値（`disable-tool`/`degraded`/デフォルト到達不可）を含める。
- `REQ-003`: 以下の回帰テストを追加する:
  - `required_in_production=True` + `failure_policy=fail-fast`（デフォルト）+ 到達不可 → `FATAL`（既存挙動の回帰確認）
  - `required_in_production=True` + `failure_policy=disable-tool` + 到達不可 → `WARNING` + 該当サーバーが `unavailable_servers` に含まれる
  - `required_in_production=True` + `failure_policy=degraded` + 到達不可 → `WARNING` + 該当サーバーが `unavailable_servers` に含まれる

## Acceptance criteria
- AC-01（REQ-001対応）: `required=True` かつ `failure_policy=disable-tool`/`degraded` のサーバーが到達不可でも起動が `FATAL` にならず継続することをテストで確認できる。
- AC-02（REQ-001対応）: `required=True` かつ `failure_policy=fail-fast`（デフォルト）のサーバーが到達不可の場合、従来どおり `FATAL` になることをテストで確認できる（回帰防止）。
- AC-03（REQ-002対応）: 起動ログに適用された `failure_policy` が表示されることを目視またはログアサーションで確認できる。

## Assumptions
- `disable-tool` と `degraded` は、本 Plan の実装範囲では「WARNING + Tool除外 + 起動継続」という同一の実行結果を持ち、ログメッセージの文言のみで区別する。ADR-004 Decision #8 自体が「次の設定モデルを検討する」という提案段階の記述であり、両ポリシーの実行結果上の厳密な違い（例: degraded は Tool を除外せず利用可能なまま警告のみ、等）を定義していないため、この簡略化は次回 ADR レビューサイクルで ADR-004 が Accepted に進む際に再検討する。
- `FailurePolicy` のデフォルト値 `fail-fast`（`scripts/shared/mcp_config.py:98`）により、既存の `config/*_mcp_server.toml` 等の設定ファイルを変更しなくても現行の全 required-server-unreachable-FATAL 挙動は維持される（後方互換）。

## Design
- `discover_all()` 内の `is_unreachable` 分岐で、`new_status` の決定式を `FATAL if (is_required and cfg.failure_policy == FailurePolicy.FAIL_FAST) else WARNING` に変更する。`cfg.failure_policy` のデフォルトが `FAIL_FAST` であるため、既存の全設定ファイルは変更なしで現行動作を維持する。
- `unreachable.append(key)` は現状 `is_unreachable` の全ケースで実行されており（`required` に関わらず）、この既存動作をそのまま活かす。変更が必要なのは `new_status` の決定式のみ。
- `startup.py` のログ行 `f"  Excluded tools (unavailable): {...}"`（line 567 付近）に、各サーバーの `failure_policy` 値を付記する形へ拡張する。具体的な文言は実装時に確定する。

## Risks
- **Risk**: `required=True` サーバーを `disable-tool`/`degraded` に設定した運用者が、本来必須のはずのサーバー欠落に気づかず本番運用してしまう → **Mitigation**: REQ-002 のログ出力拡張により、起動時に必ず `failure_policy` の適用結果が可視化される。ADR-004 Decision #5「Degraded状態、無効化されたTool、起動継続理由をCLI、Diagnostics、ログから確認できるようにする」に対応。
