# Plan: Fix orphaned MCP subprocess when `_start_servers()` fails mid-loop

## Goal
`StartupOrchestrator.run()` reliably invokes `lifecycle.shutdown_all()` to terminate any
already-started MCP subprocess whenever startup fails after at least one subprocess start was
attempted — including when `_start_servers()` itself raises partway through its loop (e.g. the
2nd of 2+ configured servers fails a `SecurityProfile.PRODUCTION` retry) — so no subprocess
outlives a failed startup attempt.

## Assumptions
1. `ctx.services_required.lifecycle` is fully constructed and non-None by the time
   `_start_servers()` is invoked in `run()`, because `_initialize()` (called at `run()` line 69,
   before the try block) calls `build_agent_context()`, which unconditionally constructs
   `lifecycle: LifecycleManagerProtocol = _ServerLifecycleRouter(...)` (factory.py:314-318) and
   assigns it as a required (non-Optional) field of `AppServices` (context.py:234) before
   `ctx.services` is ever set. Falsifiable by: reading factory.py `build_agent_context()` and
   `AppServices.__init__` signature — confirmed in Step 3.
2. `HttpServerLifecycleManager.shutdown_all()` and `_ServerLifecycleRouter.shutdown_all()` are
   both idempotent and safe to call with zero tracked subprocesses. Falsifiable by: reading
   `http_lifecycle.py:495-545` (pops from `_http_procs` dict, checks `poll()` before terminating)
   and existing tests `test_repeated_shutdown_all_is_idempotent` (test_agent_factory.py:363),
   `test_shutdown_all_twice_is_safe` and `test_shutdown_all_noop_when_no_procs`
   (test_http_lifecycle_integration.py) — confirmed in Step 3.
3. `_initialize()` failing (before the try block starts) is unaffected by this fix, since the
   exception propagates out of `run()` before the try/except is ever entered — confirmed by
   reading `run()`'s control flow directly.
4. No other code path reads the local variable `_servers_started` in `run()` — it is
   function-local, not an instance attribute. Falsifiable by `rg "_servers_started"
   scripts/ tests/` — confirmed in Step 3 (only defined/used inside `run()`).

## Design

1. **`StartupOrchestrator.__init__()`** — add `self._spawned_subprocesses: list[subprocess.Popen] = []`
   so the attribute exists immediately after construction, not only after `run()` begins. This
   keeps `_start_servers()` callable in isolation (as existing unit tests do) without an
   `AttributeError`, and makes the attribute available for incremental updates.

2. **`StartupOrchestrator.run()`** — remove the `_servers_started` gating flag entirely (requirement's
   option (b)): call `self._ctx.services_required.lifecycle.shutdown_all()` unconditionally inside
   `except Exception as setup_err:`, since Assumption 1 establishes `lifecycle` is always
   constructed by the time the try block is reached. This is a straight `if` removal — no new
   branch is added — keeping `run()`'s CC at or below its current grade-B (6) rating.

   ```python
   async def run(self) -> tuple[CommandRegistry, Orchestrator, list[subprocess.Popen]]:
       self._initialize()
       try:
           self._spawned_subprocesses = await self._start_servers()
           await self._verify_mcp_health()
           await self._check_services()
           await self._recover_pending_approvals()
           await self._setup_prompt()
       except Exception as setup_err:
           try:
               await self._ctx.services_required.lifecycle.shutdown_all()
           except Exception as shutdown_err:
               logger.error(
                   "CRITICAL: Startup rollback FAILED — subprocesses may be orphaned: %s",
                   shutdown_err,
               )
           raise setup_err
       ...
   ```

3. **`StartupOrchestrator._start_servers()`** — replace the local `spawned: list[subprocess.Popen]`
   accumulator with direct appends to `self._spawned_subprocesses` at both the first-attempt and
   retry success points (lines ~167-168 and ~186-188 in current code), and change the final
   `return spawned` to `return self._spawned_subprocesses`. This is a mechanical rename of the
   append target — no new conditional logic — so it does not increase `_start_servers`'s CC beyond
   its current grade-C (14) rating. Effect: even when the function raises mid-loop (e.g. the
   `SecurityProfile.PRODUCTION` retry-failure `raise RuntimeError(...)` at line 195), every
   subprocess successfully started before the raise is already recorded on
   `self._spawned_subprocesses`, independent of whether the function returns normally.

4. **`AgentREPL.run()`** — no code change required (per UNK-03's resolution); re-verified only.
   The existing `hasattr(startup, "_spawned_subprocesses")` fallback and `all_procs` merge logic
   (lines 836-841) continue to work: `all_procs` may now contain duplicates of processes already
   terminated by `run()`'s (now-unconditional) `shutdown_all()` call, but `proc.poll() is None`
   already guards `repl.py`'s loop against acting on processes that exited from `terminate()`
   moments earlier via `shutdown_all()` in the same event loop tick — and `Popen.terminate()` on an
   already-signaled-but-not-yet-reaped process is a safe, idempotent re-send of `SIGTERM`. No
   change made; documented here as the reason `repl.py` needs no edit.

## Risks

- **Risk**: Renaming/inverting `test_no_rollback_on_start_servers_failure` could be mistaken for
  an unrelated test regression by a future reviewer unaware this is the intended fix.
  **Likelihood**: low. **Mitigation**: the test rename and the requirement's Traceability/
  Acceptance-criteria are cross-referenced in this plan's Implementation step 4; commit message
  for that change should explicitly state it inverts previously-buggy expected behavior.

- **Risk**: `lifecycle.shutdown_all()` being called twice in a single failure path — once
  unconditionally inside `StartupOrchestrator.run()`'s except block, once potentially via
  `repl.py`'s fallback `proc.terminate()` loop acting on the same already-shutdown `Popen` objects.
  **Likelihood**: low (this dual-path already existed before this fix, just less frequently
  triggered). **Mitigation**: confirmed via `http_lifecycle.py:524-545`
  (`shutdown_all()` pops from `_http_procs` and checks `proc.poll() is not None` before
  terminating — a second call/duplicate `terminate()` on an already-signaled process is a
  no-op/safe re-send) and existing tests `test_shutdown_all_twice_is_safe`,
  `test_repeated_shutdown_all_is_idempotent`, `test_shutdown_all_noop_when_no_procs`. No
  additional code change needed; risk fully mitigated by pre-existing idempotency guarantees.

- **Risk**: Moving `self._spawned_subprocesses` initialization to `__init__()` and having
  `_start_servers()` mutate it directly could silently break the 3 existing
  `TestStartupOrchestratorStartServers` tests that call `_start_servers()` in isolation (they
  don't currently assert on `self._spawned_subprocesses`, but do rely on `_start_servers()`
  completing without `AttributeError`). **Likelihood**: low, if step 1 (init in `__init__`) is
  done before step 2. **Mitigation**: Implementation step 1 explicitly orders the `__init__` fix
  before the `_start_servers()` mutation fix, and step 2's completion criterion re-runs that exact
  test class.

- **Risk**: `_start_servers()` is already at CC 14 (grade C, per `radon`); any implementation that
  adds new conditional branches while fixing this (e.g. a naive attempt to special-case retry vs.
  first-attempt bookkeeping) could push it to CC ≥ 15, which the skill flags as needing additional
  test coverage before further changes. **Likelihood**: low, given Design §3 specifies a pure
  rename (local list → instance attribute) with no new branches. **Mitigation**: Validation plan's
  radon re-check step explicitly gates on CC not increasing.

- **Risk**: Because `scripts/agent/startup.py`, `repl.py`, and `factory.py` are all single-author,
  high-churn files (bus factor 1, 40+ commits/30d on startup.py alone), there is limited
  independent review bandwidth for subtle async-lifecycle regressions. **Likelihood**: medium
  (structural — not specific to this change). **Mitigation**: the Validation plan's full pytest +
  diff-cover + pre-commit gate is mandatory before merge; no additional issue filed since this is
  an existing, project-wide condition rather than a risk newly introduced by this fix.

All identified risks were mitigated through analysis and design decisions in this plan; none
required filing an `issues/*_risks.md` file.
