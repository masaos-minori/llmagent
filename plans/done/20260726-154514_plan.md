## Goal

Add schema validation for all messages added to conversation history to prevent LLM-generated messages from manipulating ephemeral filtering mechanisms.

## Scope

**In-Scope:**
- Define strict schema for valid conversation messages (required fields: role, content)
- Validate all messages against the schema before adding them to conversation history
- Restrict ephemeral key injection (`_ephemeral`, `_skill_ephemeral`, `_memory_injected`) to trusted sources only
- Add whitelist of allowed keys per message role

**Out-of-Scope:**
- Modifying existing trusted message insertion points (they remain trusted by default)
- Adding new ephemeral key types beyond the three already in use
- Changing message persistence behavior in session storage

## Assumptions

1. Trusted sources include: command handlers, orchestrator methods, LLM runner (for assistant responses), tool runner (for tool results)
2. The LLM can only inject messages through its response (line 95 of llm_turn_runner.py)
3. Allowed keys per role: `role` + `content` always; additional keys only when explicitly set by trusted code
4. Validation should fail-fast — reject invalid messages rather than silently stripping keys

## Risks

- **Risk**: Sanitization (stripping invalid keys) vs. rejection (dropping entire message) — choosing sanitization to preserve legitimate data but may allow subtle manipulation → Mitigation: Log warnings for sanitized messages; consider stricter rejection policy in future
- **Risk**: LLM responses from different providers have different key sets → Mitigation: Normalize LLM responses at the transport layer before validation; keep allowed-key lists provider-agnostic
- **Risk**: Trusted source classification becomes stale as new code is added → Mitigation: Require explicit `source_trusted=False` for any new message insertion point; review during PR process
