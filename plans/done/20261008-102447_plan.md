## Problem
- Rationale 2 and 3, the Alternative A disadvantages, the Positive/Negative Consequences, Decision 10 and INV-10 present TLS and placement on separate hosts as benefits or priorities, although TLS is not implemented and exposure beyond localhost is unsupported.
- INV-09 and Decision 9 say every server requires and verifies a token, but mdq-mcp attaches the middleware with an empty token (by design, relying on its fail-closed allowed_dirs authorization) and rag-pipeline-mcp attaches no middleware at all.
- Retry Policy lists only HTTP statuses, but non-timeout transport request errors are retried too.
- Implementation Notes say `run_http()` enforces a Bearer-token middleware; it enforces loopback binding only, and each server module attaches the middleware.
- Known Deviations says "No confirmed deviations".

## Reason for change
The ADR is the reference for security decisions; stating a guarantee that does not hold (every server verifies tokens, TLS available) misleads reviewers. A Decision change also triggers the governance_01 approval requirement.

- Record MCP-005 as a Known Deviation in the established `**Known Issue**` format.
- Do not decide approval wording: ask the user at implementation time.
