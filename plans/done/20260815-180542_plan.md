# Work Plan: Document extract_llm_content behavior for unexpected LLM response formats

## Goal

Document the behavior of `SessionTitleService.extract_llm_content` when LLM returns a valid response with unexpected content format, ensuring users understand why title generation fails in such cases.

## Scope

- Add docstring documentation to `extract_llm_content` in `scripts/shared/json_utils.py` clarifying empty string handling
- Update error message on line 55 of `scripts/agent/services/session_title.py` to distinguish between empty content and malformed response
- No changes to control flow or exception handling logic

## Assumptions

1. `extract_llm_content` never returns `None` — it either returns a stripped string or raises `ValueError`. The require document's claim about "returns None" appears to conflate empty string with None.
2. The existing error handling in `session_title.py` (lines 54-55) correctly distinguishes empty content from other failures
3. Users benefit from knowing whether failure was due to empty content vs malformed response

## Unknowns

1. `extract_llm_content` has 4 callers: `session_title.py` (1), `history.py` (1), `rag/llm_client.py` (2). Only `history.py` explicitly checks for empty string (`if not raw_content`). Others do not validate.
2. Does the OpenAI API specification guarantee `content` will always be a string when present, or could it legitimately be null?
3. Should the distinction between empty content and malformed response be surfaced to end users, or is the current unified error sufficient?

## Affected areas

- scripts/shared/json_utils.py — `extract_llm_content` docstring
- scripts/agent/services/session_title.py — error message on line 55
- Any tests covering `extract_llm_content` behavior

## Design

The current code path for empty content:
```
LLM returns {"choices": [{"message": {"content": ""}}]}
→ extract_llm_content returns "" (stripped empty string)
→ session_title.py line 54: `if not title:` evaluates True
→ raises SessionTitleGenerationError("LLM returned empty title")
```

This is correct behavior but the docstring of `extract_llm_content` only documents ValueError cases, not the empty string case. Additionally, the error message "LLM returned empty title" doesn't help users distinguish between:
- LLM returned empty content (should retry with better prompt)
- LLM returned malformed response (should check API status)

## Implementation steps

1. Read `scripts/shared/json_utils.py` — verify `extract_llm_content` docstring coverage (already read: confirms ValueError docs exist but omit empty string case)
2. Search for other callers of `extract_llm_content` to assess change scope
3. Update `extract_llm_content` docstring to clarify: empty string content is valid input and the function returns stripped empty string (not None)
4. Update error message on `session_title.py` line 55 from `"LLM returned empty title"` to something more specific like `"LLM returned empty content — try adjusting your prompt"`
5. Verify no test expectations depend on exact error message text
6. Run lint/typecheck

## Validation plan

- Unit test verifying `extract_llm_content("")` returns `""` (not None, not ValueError)
- Integration test verifying session title generation fails with appropriate error when LLM returns empty content
- Manual review confirming error message improvement is actionable

## Risks

1. Changing error message text could break tests that assert exact error message strings
2. If `content` can be `null` in some API versions, `isinstance(content, str)` check on line 130 would raise ValueError — need to confirm API contract
3. Over-documenting may create maintenance burden if API behavior changes
