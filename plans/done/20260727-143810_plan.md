## Goal

Anchor `_repl_loop()`'s `_GRACEFUL_TIMEOUT` bound to shutdown-signal-arrival time (not
turn-dispatch time), so a turn already in flight when SIGTERM/SIGINT arrives is force-cut
off no later than `_GRACEFUL_TIMEOUT` seconds after the signal, instead of being left to
run indefinitely under `timeout=None`.

## Scope

**In-Scope:**
- `scripts/agent/repl.py` `_repl_loop()` (currently lines 462-502): replace the single
  `asyncio.wait_for(self._dispatch_line(line, ctx), timeout=... )` call with a
  task-based race against `self._shutdown_event`, so the grace-period timer starts when
  the shutdown event fires rather than when `wait_for` was originally called.
- `scripts/agent/repl.py` `_sigterm_handler()` comment (currently lines 676-680): correct
  the inaccurate claim that `_repl_loop()` "already checks shutdown_requested after each
  turn and applies the `_GRACEFUL_TIMEOUT` wait" — this is only true for turns that start
  after the signal, not the one already in flight.
- Hoist the hardcoded local `_GRACEFUL_TIMEOUT: float = 10.0` (currently declared inline
  inside `_repl_loop()`, line 470) to a class-level attribute so tests can override it
  with a short value, matching the existing convention of `_WAL_CHECKPOINT_TIMEOUT_S`
  and `_WAL_BACKUP_TIMEOUT_S` (`scripts/agent/repl.py` lines 87-88).
- New/updated unit tests in `tests/test_repl.py` covering: signal mid-turn, signal
  before turn start (regression guard), and normal completion with no signal.

**Out-of-Scope:**
- Any change to `_read_input()`'s existing input/shutdown race (lines 504-553) beyond
  reading it as a pattern reference — it already behaves correctly.
- Any change to `_sigterm_handler`'s `_input_coro` cancellation logic (lines 681-689) —
  unaffected by this fix, only the adjacent comment is corrected.
- Any change to orchestrator-level (`scripts/agent/orchestrator.py`) turn-cancellation

  into the same `_sigterm_handler` closure being modified.

  feature; only referenced here as a naming-convention precedent).

## Assumptions

1. `self._shutdown_event` is always a live `asyncio.Event()` by the time `_repl_loop()`
   runs in production, because `run()` (`scripts/agent/repl.py` line 663) sets it before
   `_run_repl_loop()` → `_repl_loop()` is ever awaited (line 642). It is `None` only in
   test doubles that bypass `run()`/`__init__` (`tests/test_repl.py` `_make_bare_repl()`,
   line 56 sets `repl._shutdown_event = None`).
2. The fix must therefore keep a `None`-safe fallback branch (behave exactly as today:
   `timeout=_GRACEFUL_TIMEOUT if ctx.conv.shutdown_requested else None`) so existing
   `TestReplLoop` tests that construct a bare `AgentREPL` with `_shutdown_event = None`
   keep passing unchanged.
3. `asyncio.wait_for()`'s existing auto-cancel-on-timeout semantics (it cancels the
   awaited task/coroutine when the timeout fires) is acceptable to keep for the
   second-stage bounded wait — this matches current behavior exactly (today's
   `wait_for(self._dispatch_line(...), timeout=_GRACEFUL_TIMEOUT)` already cancels
   `_dispatch_line` on timeout), so no new cancellation-safety risk is introduced.
4. The class attribute name for the hoisted timeout should follow the file's existing
   `_TIMEOUT_S` suffix convention (e.g. `_GRACEFUL_TIMEOUT_S`) rather than keeping the
   bare `_GRACEFUL_TIMEOUT` name, for consistency with `_WAL_CHECKPOINT_TIMEOUT_S` /
   `_WAL_BACKUP_TIMEOUT_S`. This is a naming choice, not a behavior change.

## Risks

- **Risk**: Silently dropping `_dispatch_line`'s exception when `dispatch_task` completes
  first inside the `asyncio.wait()` race (since `asyncio.wait()`, unlike `wait_for`, does
  not re-raise automatically) → **Mitigation**: explicitly call `dispatch_task.result()`
  (or `await dispatch_task`) whenever it is in `done`, so any exception it raised
  propagates exactly as it does today via the direct `await asyncio.wait_for(...)` call.
- **Risk**: Breaking the existing `_shutdown_event is None` test double path used
  throughout `TestReplLoop` (`_make_bare_repl()`, `tests/test_repl.py` line 56) →
  **Mitigation**: keep an explicit fallback branch that behaves exactly like today
  (`timeout=self._GRACEFUL_TIMEOUT_S if ctx.conv.shutdown_requested else None`) when
  `self._shutdown_event is None`; run the full existing `TestReplLoop` suite unmodified
  as a regression gate before considering the change complete.
- **Risk**: Leaking the shutdown-watcher task when `dispatch_task` wins the race (task
  never cancelled, accumulates as an unresolved `asyncio.Task` per turn over a long
  session) → **Mitigation**: mirror `_read_input()`'s existing `for t in pending: t.cancel()`
  cleanup block (lines 533-534) for the new race in `_repl_loop()`.
- **Risk**: `scripts/agent/repl.py` is a high-churn file (72 modifying commits); a
  concurrent change landing on the same lines could conflict or reintroduce the bug →
  **Mitigation**: keep the diff minimal and localized to `_repl_loop()`, the
  `_sigterm_handler` comment, and the new class attribute; do not refactor adjacent code
  in the same change.
- **Risk**: Cancelling `dispatch_task` on timeout expiry could interrupt a tool call or
  DB write mid-flight (e.g. `ctx.session.save` inside `_dispatch_line` → `orchestrator.handle_turn`),
  leaving partial state → **Mitigation**: this is not a new risk — today's code already
  cancels the exact same coroutine on timeout via `wait_for`'s built-in cancel-on-timeout
  behavior when `shutdown_requested` was already `True` at call time; this plan only
  extends the *same* existing cancellation semantics to also cover the mid-flight-signal
  case, so no new partial-state failure mode is introduced beyond what graceful shutdown
  already accepts today.
