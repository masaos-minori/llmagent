## Background
ADR-002「プロセス単位の設定所有権と Config Isolation」は、各プロセスが自身の設定ファイルのみを読み込むことを Decision #1〜#9 で定めている。EventBus はこの ADR の対象プロセス（Scope 記載）でありながら、実装は `ConfigLoader` を一切使わず `tomllib` を直接呼んでいる。この差異は ADR-002 自身の Known Deviations に CI-001 として既に登録済みである。

## Problem
- `scripts/eventbus/config.py:load_config()` (line 72-90) が `tomllib.load()` を直接呼んでおり、`ConfigLoader.restrict_to()` の許可ファイルチェックを経由しない。
- `scripts/agent/startup.py` は `ConfigLoader.restrict_to()` を一度も呼んでいない（grep で確認、ゼロ件）。Agent プロセスは実行中ずっと `_allowed_files=None`（無制限）のままであり、ADR-002 Decision #1 の「Agent は agent.toml のみを読み込む」という不変条件がコードレベルで強制されていない。
- **[REVISED 2026-08-25]** Agent プロセスの実際の設定読み込み（`ConfigLoader().load_all()`）は `scripts/agent/config_builders.py:60`（`build_agent_config()`）で発生し、これは `AgentContext.__init__`（`scripts/agent/context.py:304`）から呼ばれ、`AgentREPL.__init__`（`scripts/agent/repl.py:100`）の実行時点、つまり `StartupOrchestrator`（`scripts/agent/startup.py`）が動く前に完了している。したがって `restrict_to()` を `startup.py` に追加しても、最初の（唯一の）`load_all()` 呼び出しには適用されない — 挿入位置を `scripts/agent/context.py` の `AgentContext.__init__` に修正する。
- issue および ADR-002 Known Deviations の CI-001 エントリは、いずれも問題箇所を `scripts/eventbus/broker.py` と誤って記載している。`broker.py` を grep したが `tomllib` / `ConfigLoader` / `restrict_to` / 設定読み込み関連コードは一切存在しない（ゼロ件）。実際の設定読み込みは `scripts/eventbus/config.py` の `load_config()` であり、これを呼び出しているのは `scripts/eventbus/app.py` (line 58, 198) である。

## Reason for change
ADR-002 Known Deviations は CI-001 の解決を「ADR-002 が Proposed から Accepted に移行する前」を Resolution Target としているが、ADR-002 の Status は既に `Accepted` になっている（Completion Checklist 側は「現行実装との差異が Known Issue へ登録されている」等が未チェックのまま）。Known Deviations に登録されたまま放置されている状態を解消する必要がある。

## Implementation intent
- EventBus には `shared.config_loader.ConfigLoader` を import させず（`.importlinter` の `eventbus-is-isolated` 契約を維持）、`scripts/eventbus/config.py` 内に、許可された1パス（`get_config_path()` が返すパス）以外を読み込ませないことを保証する軽量なローカルガードを追加する。EventBus は元々 `load_config(path: Path | None = None)` という単一パス固定の設計であり、`ConfigLoader.load(*names)` のような可変長ファイル名受け入れ API を持たない点を活かし、ADR-002 の INV-01/INV-02 と同等の保証を、契約に抵触しない形で明文化・テストで固定する。
- Agent プロセスには、`ConfigLoader().load_all()` が実際に呼ばれる最初の地点である `AgentContext.__init__`（`scripts/agent/context.py`、`build_agent_config()` 呼び出しより前）に `ConfigLoader.restrict_to("agent.toml")` を追加する。
- ADR-002 の Known Deviations は、修正後の実装に合わせて file attribution を訂正し、Recommended Action を「ローカル実装によるガード追加」に更新する（Decision 本文は変更しないため新規 ADR 不要、Known Deviations の記述更新のみ）。

## Design
- EventBus 側: `.importlinter` の `eventbus-is-isolated` 契約（`shared` を含む全モジュールの import 禁止）を維持するため、`shared.config_loader.ConfigLoader` は使わない。`scripts/eventbus/config.py` の `load_config()` は既に `get_config_path()` が返す単一パス（環境変数 `EVENTBUS_CONFIG_PATH` かデフォルト固定パスのいずれか）しか受け付けない設計になっており、`ConfigLoader.load(*names)` のような複数ファイル名を受け入れる API を持たない。この既存設計の不変条件（単一パス固定）を、テストによって明示的に固定することで、ADR-002 の INV-01/INV-02 と実質的に同等の保証を、契約に抵触しない形で担保する。
- Agent 側: `scripts/agent/context.py` の `AgentContext.__init__` 冒頭、`build_agent_config()` 呼び出し（304行目）より前に `ConfigLoader.restrict_to("agent.toml")` を追加する。`scripts/agent/startup.py` は対象外とする — `AgentREPL.__init__`(`repl.py:100`) → `AgentContext.__init__`(`context.py:304`) → `build_agent_config()`(`config_builders.py:60`) の順で、Agent の設定読み込みは `StartupOrchestrator` 実行前に完了済みであることを確認済み。
- ADR-002 Known Deviations は Decision 本文ではないため、新規 ADR 作成は不要。記述訂正のみで足りる（ADR-002 の Change History にも一行追記する）。
