# Plan: Reconcile Model/Embedding References, Needs-Confirmation Archive, and Known-Issues Metadata Duplication

## Goal
Eliminate conflicting `.gguf`/embedding-model/`embedding_dims` references across the Overview, Deployment, and RAG-configuration docs (or clearly flag the parts that cannot be reconciled without operator input), add an automated doc-consistency check that catches future model-reference drift, split the Needs-Confirmation inventory into active/archive sections while fixing NC-005's duplicate `Last Reviewed` field, and correct the stale `docs/00_governance_08_known-issues-migration-plan.md` so it no longer misrepresents an already-executed migration as an unexecuted plan.

## Design

1. **Canonical model table.** `docs/02_deployment.md` §1.4 keeps its existing table but is annotated as canonical (e.g. an inline "Canonical source — see `docs/00_governance_02_canonical-source-rule.md`" note, consistent with the project's existing canonical-source convention). `docs/01_overview-files-01-build.md`'s file-structure block and `docs/03_rag_05_1-configuration-reference.md`'s `embedding_dims` row are rewritten to state the same filenames/model name as `docs/02` (once UNK-01 is answered) or, if the answer is still pending at implementation time, to state "see `docs/02_deployment.md` §1.4 for the current canonical filename" instead of restating a value that could drift again.
2. **Consistency-check design.** Add a role-tagged extraction: for each of the three files, scan lines for `\S+\.gguf` and for `embedding_dims` key-value mentions; classify each `.gguf` hit as `embedding` if the line/nearby context contains "embed"/"埋込"/"埋め込み", else `chat_llm`. Group all hits per role across the three files; if a role has more than one distinct filename (case-sensitive exact match) or more than one distinct `embedding_dims` value, emit one `Issue` (ERROR severity) per conflicting file/line pair, mirroring the existing `check_schema_drift`/`check_port_drift` pattern (best-effort, returns `[]` if none of the three target files exist rather than hard-failing).
3. **CI wiring.** Add a new skip option (e.g. `"modelrefs"`) to `ALL_SKIP_OPTIONS`, call the new function inside the `overview`, `deployment`, and `rag` branches of `main()`'s domain dispatch (same pattern as `check_conf_d_listing`/`check_db_count_claim`/`check_crawler_config_drift`), and update the three CI workflow YAMLs to invoke `python tools/check_docs_consistency.py --domain <domain>` instead of the deleted per-domain scripts — otherwise the new check would be dead code from CI's perspective.
4. **NC inventory restructuring.** Add a new `## Archived (Resolved) Items` section after the existing `## Inventory Items` section (keeping the same document rather than a separate file, per the requirement's "whichever keeps the existing doc's structure simplest" guidance — a single doc avoids a new cross-reference to maintain). Cut all 17 `### NC-00N` blocks from "Inventory Items" and paste them verbatim under the archive heading, in existing ID order. Leave "Inventory Items" with one explicit sentence: "No active (open/investigating/deferred) items as of {date} — all 17 originally tracked items have been resolved; see Archived (Resolved) Items below." Fix NC-005 by deleting the stale `**Last Reviewed**: 2026-07-22` line, keeping only `2026-07-29` (the more recent/more specific date, matching the requirement's explicit instruction).
5. **Governance_08 correction.** Add a short "Migration Status" note near the top of `docs/00_governance_08_known-issues-migration-plan.md` stating: executed 2026-07-23 (commit `7b04065ce`); Agent area's entries were subsequently resolved and removed (commit `646152e61`, 2026-07-26) and the document restructured (commit `96c0d6231`, 2026-08-07) leaving zero entries; RAG/MCP/EventBus/Shared retain migrated IDs/Status fields but have partially drifted from strict template conformance (tracked as follow-up, not fixed here). Leave the rest of the document (Current Format Summary, Migration Policy) as historical record rather than deleting it, since it still documents the pre-migration baseline accurately.

## Risks
- **Risk**: The literal `.gguf` filename correction (UNK-01) never gets answered, leaving the canonical table with a placeholder/cross-reference instead of a concrete filename (Likelihood: medium) → **Mitigation**: ship the structural fix (single canonical table + consistency check) regardless; the consistency check itself will keep the three docs from silently re-diverging even if the exact filename stays provisionally marked "unconfirmed."
- **Risk**: `.github/workflows/agent-docs-consistency.yml` and `mcp-docs-consistency.yml` have the identical "calls a deleted script" defect found for overview/deployment/rag, but are out of this requirement's target-file list, so they will remain broken after this change (Likelihood: high — confirmed via `ls tools/check_agent_docs_consistency.py` → not found) → **Mitigation**: file a follow-up issue explicitly calling out these two workflows so they don't get missed; do not fix them in this pass to avoid scope creep beyond the stated target files.
- **Risk**: Moving 17 NC entries to a new archive section could accidentally drop or truncate content during the edit (Likelihood: low, but high impact if it happens) → **Mitigation**: perform the move as a structural cut-paste (not a rewrite) and diff line counts before/after to confirm no net content loss beyond the added section heading/note.
- **Risk**: The new model-reference check's role classification heuristic (embedding vs. chat_llm by nearby "embed" keyword) could misclassify a line and produce false positives/negatives on future doc edits (Likelihood: medium) → **Mitigation**: scope the check to the three specific files by exact path rather than a broad glob, and document the heuristic's limitation inline as a code comment, matching the "best-effort check; verify manually" wording used by `check_schema_drift`/`check_obsolete_diagnostics_references`.
