## Goal

Make the distinction between Workflow approval and Tool approval explicit through configuration and documentation, eliminating ambiguity about which approval mechanism `/approve` and `/reject` apply to.

## Scope

**In-Scope:**
- Add explicit `"require_approval": false` to `config/workflows/default.json`
- Update docstrings/comments in `workflow_engine.py` to clarify Workflow vs Tool approval
- Update command handler documentation in `cmd_workflow.py` to clarify `/approve` and `/reject` apply to Workflow approval only
- Update agent workflow documentation to explain both approval mechanisms

**Out-of-Scope:**
- Changes to Workflow approval logic itself
- Changes to Tool approval logic itself
- Changes to the interaction between the two approval mechanisms beyond documentation

## Assumptions

1. The intended default for `require_approval` is `false` (no workflow-level approval gate), matching the current implicit behavior.
2. Tool approval denial already appears as a tool message in conversation history — this behavior is correct and does not need code changes.
3. Documentation updates should follow the existing doc structure; new docs should reference existing ones rather than duplicating content.
