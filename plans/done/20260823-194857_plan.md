## Assumptions

- `dlq.py::promote_single()` (not `promote_batch`, though both share the same
  write-then-update pattern) is the right target for the guard test: it is the
  inline/single-event path exercising the same `_atomic_write()` → `UPDATE ... SET
  dlq_at` sequence, and is simpler to set up than the batch path.
- `SQLiteHelper._connect()` can be monkeypatched or its call count tracked to verify
  `reuse_connection=True` skips it on a second `open()` call — confirmed by reading
  `scripts/db/helper.py:166-195` in full.
- `chunk_splitter.py::process_file()` dispatches internally to
  `ChunkEnglishMixin`/`ChunkJapaneseMixin` methods (both mixed into the same class per
  `scripts/rag/ingestion/chunk_splitter.py`'s class definition (`ChunkSplitter
  (ChunkEnglishMixin, ChunkJapaneseMixin)`)) — **corrected during this workflow's
  adversarial verification** (was: "a single `process_file()` test with mixed
  English/Japanese input content exercises all three files"): `process_file()` takes a
  single JSON file matching the `CrawlFilePayload` schema (`url`, `title`, `lang`,
  `content`, `code_blocks`, `etag`, `last_modified`), and `lang` is one value for the
  *entire* document (`_build_text_triples` dispatches on `data.lang == "ja"` for the
  whole call) — a single document cannot mix English and Japanese chunking paths in
  one `process_file()` call. Two separate input JSON files (one `lang: "en"`, one
  `lang: "ja"`) are required to exercise both mixin paths.

## Design

1. **`dlq.py`** (`tests/eventbus/test_eventbus_dlq.py`):
   - `test_atomic_write_failure_leaves_db_row_unchanged` — insert a live event row,
     monkeypatch `eventbus.dlq._atomic_write` to raise `OSError`, call
     `promote_single(db, deadletter_dir, event_id)` inside `pytest.raises(OSError)`,
     then query the row and assert `dlq_at IS NULL` (unchanged).
2. **`db/helper.py`** (`tests/db/test_sqlite_helper.py`):
   - `test_reuse_connection_skips_reconnect` — call `.open(reuse_connection=True)`
     twice on the same `SQLiteHelper` instance; assert `helper.conn` is the *same
     object* (`is`) after the second call, and that `_connect()` was not called a
     second time (patch/spy on `self._connect`).
   - `test_reuse_connection_skips_close_on_exit` — use `with
     helper.open(reuse_connection=True): ...`; after the `with` block exits, assert
     `helper.conn is not None` and a subsequent query on `helper.conn` still succeeds
     (connection was not closed).
3. **`chunk_splitter.py`** (`tests/rag/ingestion/test_chunk_splitter.py`) — **Design
   corrected during this workflow's adversarial verification** to match
   `process_file()`'s actual contract (verified this cycle:
   `def process_file(self, src_path: Path, force: bool = False) -> int`, an instance
   method reading a JSON file matching `CrawlFilePayload` and writing
   `ChunkOutputPayload`-shaped JSON files to `{rag_src_dir}/chunk/`; the existing
   `test_chunk_splitter_processes_json` test in
   `tests/rag/ingestion/test_rag_ingestion_pipeline.py` already demonstrates the
   construction pattern: `ChunkSplitter(config={"rag_src_dir": str(tmp_path),
   "min_chunk": 10, "max_chunk": 1000, "en_stopwords": [], "ja_stop_pos": []})`):
   - `test_process_file_end_to_end_english` — write one temp JSON file matching
     `CrawlFilePayload` with `lang: "en"` and multi-paragraph `content`; call
     `chunker.process_file(path, force=True)`; assert the returned `int` chunk count is
     `>= 1`; read back the written `{chunk_dir}/{path.stem}-NNNN.json` output file(s)
     (`ChunkOutputPayload` schema) and assert `source_file`/`lang`/`chunk_index`/
     `content` are populated correctly, and that concatenating all written chunks'
     `content` reproduces the original `content` with no loss or duplication.
   - `test_process_file_end_to_end_japanese` — same shape, with a second file
     (`lang: "ja"`, Japanese `content`), to exercise the `ChunkJapaneseMixin` path
     that the English-language test above cannot reach.

## Risks

- **Risk (materialized and resolved during this workflow's adversarial verification)**:
  `process_file()`'s actual signature/return type did not match the Design section's
  original assumptions — it is an instance method returning only an `int` chunk count,
  and its `CrawlFilePayload` JSON input carries one `lang` value per document (English
  and Japanese cannot be mixed in a single call). → **Resolution**: Design (item 3
  above) and Implementation steps were corrected in place to two per-language tests
  reading the actual written `ChunkOutputPayload` output files for metadata assertions,
  following the existing construction pattern already demonstrated by
  `test_chunk_splitter_processes_json` in `tests/rag/ingestion/test_rag_ingestion_pipeline.py`.
- **Risk**: Monkeypatching `_atomic_write` inside `eventbus.dlq` could miss if the
  function is imported by reference elsewhere. → **Mitigation**: patch
  `eventbus.dlq._atomic_write` (the module-local name `promote_single()` actually calls),
  not a re-exported alias.
