## Goal
Fix `tools/check_no_compat.py`'s `main()` so that passing a directory as a positional file
argument no longer raises an unhandled `IsADirectoryError`, by expanding directory arguments
into their contained `*.py`/`*.md` files (consistent with the tool's existing no-args scan
behavior), and add test coverage for it.

## Scope
**In-Scope**:
- `tools/check_no_compat.py`: the `args.files` branch of `main()` (currently lines ~215-221).
  Expand any positional argument that is a directory into its contained `*.py`/`*.md` files
  (recursive glob, same pattern as the no-args `dirs_to_scan` path), merge with any plain file
  arguments given alongside it, and deduplicate — mirroring the existing `sorted(set(...))`
  pattern used by the no-args path.
- `tests/tools/test_check_no_compat.py`: add a test covering a directory passed as a positional
  argument.

**Out-of-Scope**:
- `ROOT_DIR`, `COMPAT_PATTERNS`, `DEFAULT_ALLOWLIST` (addressed separately in
  `plans/20260807-100914_plan.md`).
- The no-args `dirs_to_scan` glob logic itself (must remain behaviorally unchanged).
- The pre-existing `--help` text drift (says "default: scripts/, docs/, tests/" but the actual
  no-args scan also includes `tools/`) — unrelated to this bug, filed separately (see Risks).

## Assumptions
1. Directory expansion (not an explicit usage error) is the correct fix: the positional-args
   branch is used for ad-hoc/manual invocation only — confirmed via blast-radius check, the
   `no-compat-stubs` pre-commit hook always runs with `pass_filenames: false` and never reaches
   this branch — so making a directory argument behave like a smaller, targeted version of the
   no-args scan is more useful than a hard failure, and matches the pattern the issue's Required
   Changes section listed first.
2. `check_all`/`check_compat_patterns` take a single already-read file's content + its `Path`,
   not a list, so the fix is confined to how `files: list[Path]` is built before that loop —
   confirmed by reading their signatures (`tools/check_no_compat.py` lines ~149-170).
3. No existing test invokes `main()` directly; a new one will be the first, so it must either
   patch `sys.argv` + call `main()`, or exercise the file-collection logic as an extracted
   helper — whichever keeps the diff smallest (decided in Implementation Steps).

## Implementation Steps
1. **Phase 1: Core Logic Implementation**
   - [ ] In `tools/check_no_compat.py`, in the `args.files` branch of `main()`, replace the
     unconditional `files = [Path(f) for f in args.files]` with logic that, for each argument:
     if it is a directory, expand it via `.glob("**/*.py")` + `.glob("**/*.md")` (the exact
     pattern used by the no-args `dirs_to_scan` path); if it is a file, keep it as-is.
   - [ ] Merge the expanded/kept paths and deduplicate with `sorted(set(...))`, matching the
     no-args path's existing convention.
   - [ ] Do not modify the no-args `dirs_to_scan` branch, `ROOT_DIR`, `COMPAT_PATTERNS`, or
     `DEFAULT_ALLOWLIST`.
   - [ ] If extracting a helper function improves testability without widening the diff

## Risks
- **Risk**: Directory expansion could silently scan far more files than the user intended if a
  very large or unexpected directory is passed → **Mitigation**: This exactly mirrors the
  tool's own existing, already-trusted no-args behavior (same glob patterns); the tool is a
  manual/ad-hoc CLI utility, not something invoked automatically with untrusted input, and the
  blast-radius check confirmed the pre-commit hook path is unaffected.
- **Risk**: Mixed file+directory positional arguments could produce confusing or duplicate
  results if not deduplicated correctly → **Mitigation**: Implementation Step 1 explicitly
  requires reusing the `sorted(set(...))` dedupe pattern already used by the no-args path.
- **Risk**: No established convention exists for testing `main()` directly in this test file,
  risking an inconsistent test style → **Mitigation**: Implementation Step 1 explicitly allows
  either extracting a small testable helper or falling back to `sys.argv` patching, whichever
  keeps the diff smaller; Phase 2 requires matching the file's existing fixture/helper style.
- **Risk (unmitigated, out of scope for this plan)**: `tools/check_no_compat.py`'s `--help` text
  says "default: scripts/, docs/, tests/" but the actual no-args scan also includes `tools/` —
  a pre-existing, unrelated documentation-drift bug discovered incidentally while reading the
  argparse setup. Filed separately as `issues/20260809-170451_risks.md` rather than fixed here,
  per this requirement's explicit instruction to fix only the positional-file-argument handling.
