# Plan: Remove redundant _RETRYABLE_STATUS check in HttpTransport HTTPStatusError handler

## Goal
Remove the redundant `_RETRYABLE_STATUS` check in the `except httpx.HTTPStatusError` block of `HttpTransport.call()`, improving code maintainability and preventing future confusion during refactoring.

## Priority
Medium

## Scope
- **In-Scope**: Removing the redundant `_RETRYABLE_STATUS` check in `HttpTransport.call()`; adding a comment explaining why the check is removed (or keeping it with a clarifying comment).
- **Out-of-Scope**: Changing the retry logic itself; modifying other transport layers; changing error handling behavior.

## Background
`scripts/shared/http_transport.py` line 128-161:
```python
if resp.status_code in self._RETRYABLE_STATUS:
    last_retryable_status = resp.status_code
    # ... retry logic ...
    continue
resp.raise_for_status()
# ...
except httpx.HTTPStatusError as e:
    # ...
    if e.response.status_code in self._RETRYABLE_STATUS:
        last_retryable_status = e.response.status_code
```

When `resp.status_code` is in `_RETRYABLE_STATUS`, the `continue` statement skips `resp.raise_for_status()`. Therefore, when `raise_for_status()` raises `HTTPStatusError`, the status code cannot be in `_RETRYABLE_STATUS`.

Currently, the `except httpx.HTTPStatusError` block checks `_RETRYABLE_STATUS` again, which is unnecessary because:
1. The same check was already performed before `raise_for_status()`
2. Any `HTTPStatusError` caught here must have a non-retryable status code

## Problem
The redundant check creates confusion during future refactoring. Developers may assume the check serves a purpose and hesitate to remove it, even though it's logically unreachable.

## Reason for change
Code maintainability improvement. Eliminating dead code paths reduces cognitive load and prevents misinterpretation during future changes.

## Implementation intent
Either:
1. Remove the `_RETRYABLE_STATUS` check entirely and add a comment explaining why it's safe to do so
2. Keep the check but add a comment stating "This check is theoretically unreachable but kept for safety"

Approach 1 is preferred as it eliminates dead code.
