## Goal
- Remove the TTL-based internal cache from `ToolExecutor` to simplify its implementation and prevent configuration inconsistencies during reloads.

## Priority
High

## Scope
- **In-Scope**:
    - Removal of `_cache`, `_execute_with_cache`, and `stat_cache_hits` from `scripts/shared/tool_executor.py`.
    - Removal of `apply_config(..., cache_ttl=...)` parameter and implementation in `scripts/shared/tool_executor.py`.
    - Removal of `tool_cache_ttl` and `tool_cache_max_size` from `ToolConfig` in `scripts/agent/config_dataclasses.py`.
    - Update `ConfigReloadService` in `scripts/agent/services/config_reload.py` to stop applying `cache_ttl`.
    - Cleanup of unused imports (e.g., `CacheEntry`, `OrderedDict`) in affected files.
- **Out-of-Scope**:
    - Adding new caching mechanisms.
    - Modifying tool execution logic beyond removing the cache layer.

## Background
The current `ToolExecutor` implements an internal Time-To-Live (TTL) cache using an `OrderedDict`. While this improves performance for repeated calls, it introduces significant complexity to the agent's lifecycle management.

## Problem
The presence of an internal cache makes the system state dependent on how long the process has been running and what specific tools have been called. This leads to potential inconsistencies when configurations are reloaded via `ConfigReloadService`, as the executor may still be operating under old cache settings or holding stale data that doesn't align with the updated configuration.

## Reason for change
Simplification of the `ToolExecutor` architecture and elimination of configuration drift between the `AgentConfig` and the active runtime state. This refactor unblocks several planned improvements related to tool routing and lifecycle management.

## Implementation intent
Strip all caching-related attributes (`_cache`, `stat_cache_hits`, etc.) and methods (`_execute_with_cache`) from `ToolExecutor`. Correspondingly, remove the `cache_ttl` parameter from `ToolConfig` and ensure that the configuration reload service no longer attempts to apply this non-existent setting.
