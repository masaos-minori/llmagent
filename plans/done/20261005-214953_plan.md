# Plan: RAG crawler resolves `lang="auto"` for local files

## Goal
Make `WebCrawler.crawl_file()` / `CrawlPersister.save()` resolve `lang="auto"` for local files using the existing CJK-ratio language detection, so local-file ingestion with `auto` produces a crawl JSON instead of being silently rejected.

## Priority
Medium

## Scope
- **In-Scope**:
  - Resolve `auto` inside `CrawlPersister.save()` before the supported-language check, reusing the existing `detect_lang()` logic (no new CJK implementation).
  - Add unit tests for the local-file `auto` path (Japanese, English, short/inconclusive, unsupported value) and for a `file://` target with `auto` routed through `WebCrawler.crawl()`.
  - Update the `crawl_file` behavior doc to state that `auto` is now resolved for local files.
  - Remove/correct the misleading identity expression and comment in `save()`.
- **Out-of-Scope**:
  - Changing the CJK threshold (`_CJK_RATIO_THRESHOLD`) or minimum text length (`MIN_TEXT_LENGTH_FOR_DETECTION`).
  - Adding languages beyond `en`/`ja`.
  - Changing the web-page resolution path or `CrawlPersister.save_http()` (HTTP already routes through `LanguageResolver` before `save_http()`).
  - Fixing the pre-existing cosmetic staleness of the `crawler.py` module docstring (`{en,ja}`) — see Unknowns.

## Background
The issue originates from a documented-and-CLI-advertised behavior (`auto` resolves by CJK ratio) that is not implemented for local files. Current state, confirmed by repository evidence (Evidence label: Confirmed by repository evidence):
- `CrawlPersister.save()` (`scripts/rag/ingestion/crawl_persister.py`) contains `resolved_lang: str = lang if lang != "auto" else lang` (an identity expression) followed by `if resolved_lang not in frozenset({"en", "ja"})`, so `auto` logs a warning and returns `0` without writing anything.
- `WebCrawler.crawl()` routes `file://` targets to `crawl_file(path, lang)` with the raw hint, so a `file://` target with `auto` reaches the broken path.
- `parse_targets_file()` / `parse_target_urls()` validate `lang` against `_VALID_HINT_LANGS = {en, ja, auto}`, so a `file://` target with `auto` passes validation and reaches `save()`.
- Real resolution exists for web pages: `LanguageResolver.resolve_lang(text, hint_lang)` reuses `crawler_utils.detect_lang()` (CJK ratio, `en` fallback for short/inconclusive text). `detect_lang()` returns `None` for text shorter than `MIN_TEXT_LENGTH_FOR_DETECTION` (100).
- `docs/21_rag/rag_02_02_ingestion_pipeline-crawler.md` correctly states `auto` is rejected and cross-references this issue; the argparse `--lang` help already states `auto` detects by CJK ratio. The two therefore contradict each other.
- Only one caller exists: `WebCrawler.crawl_file()` → `CrawlPersister.save()`. No existing test passes `auto` to a local-file `crawl_file()`, so no existing test currently fails.

## Problem
`crawl_file(path, "auto")` and a `file://` target with `auto` are silently skipped (warning only, return `0`, no JSON written). Only `--lang auto` combined with `--url` of http(s) pages gets auto-detection. The CLI help advertises `auto` for local files while the doc correctly describes rejection — a contradiction between advertised and actual behavior.

## Reason for change
Documented and CLI-advertised behavior is not implemented for local files; ingestion of local files with `auto` silently produces nothing. The CLI help and documentation contradict each other on whether `auto` is accepted for local files.

## Implementation intent
Resolve `auto` inside `CrawlPersister.save()` before the supported-language check, reusing `crawler_utils.detect_lang()` (same CJK threshold and `en` fallback as web pages) instead of duplicating logic. This fixes the only entry point and any future caller. Do not alter the web-page resolution path or `save_http()`.

## Requirements

- `REQ-002`: The misleading identity expression/comment in `save()` is removed or corrected to describe the implemented behavior.

- `REQ-004`: The `crawl_file` behavior doc states that `auto` is now resolved for local files; the CLI `--lang` help already describes this and needs no change.
- `REQ-005`: Supported output languages remain limited to `en`/`ja`; the web-page resolution path is unchanged.

## Design
- **Option A (encoded)**: resolve `auto` inside `CrawlPersister.save()` before the `{"en", "ja"}` check, reusing `crawler_utils.detect_lang()`:
  ```python
  if lang == "auto":
      resolved_lang = detect_lang(content) or "en"
  else:
      resolved_lang = lang
  ```
  `content` is already read above this point, so no ordering change is needed. `detect_lang()` returns `None` below `MIN_TEXT_LENGTH_FOR_DETECTION`, so `detect_lang(content) or "en"` yields `en` for short text — identical to `LanguageResolver.resolve_lang(content, "auto")` for `hint_lang == "auto"`. Import `detect_lang` alongside the existing `url_to_slug` local import from `crawler_utils`.
- **Rationale for A**: there is exactly one caller (`WebCrawler.crawl_file()`), so resolving in `save()` covers the only entry point and any future caller, and avoids duplicating the CJK logic.
- **Option B (alternative, not encoded)**: because there is a single caller, resolving in `WebCrawler.crawl_file()` before delegating to `save()` is equally valid and keeps `CrawlPersister` free of language-detection concerns. The implementer may choose A or B; both satisfy REQ-001.
- **`save_http()` left unchanged**: the HTTP orchestrator resolves the language via `LanguageResolver` before calling `save_http()`, so `auto` never reaches it in practice. Changing it is out of scope and could mask the real resolution location.
- **Complexity**: `CrawlPersister.save()` is currently radon `B(7)`; adding one branch raises cyclomatic complexity slightly. If the grade degrades below the acceptable threshold, factor the resolution into a small private helper rather than inlining it.
- **Layering note**: resolving inside `save()` slightly expands `CrawlPersister` responsibility; mitigated by recording option B as an alternative and keeping the branch a one-liner reusing an existing pure function.
