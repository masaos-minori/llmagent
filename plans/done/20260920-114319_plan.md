## Goal
Extend `tools/check_docs_content_policy.py` with a new report-only check that
detects a design document restating a "code default/fallback vs.
operational/production value" comparison — a config-value duplication
pattern proven present in RAG design docs but undetected by the tool's
current 15 categories.

## Priority
Medium

## Scope
- **In-Scope**:
  - Add one new `check_*` function to `tools/check_docs_content_policy.py`
    detecting the code-fallback-vs-operational-value comparison pattern, in
    two shapes: a table with dedicated "Code Fallback"/"Production Value"
    (or equivalent) header columns, and a cell/prose line stating both a
    code-default/fallback phrase and an operational/production-value phrase
    together.
  - Add unit tests (positive and negative cases) to

## Background
`skills/DESIGN.md`'s "No concrete configuration values" section
(`skills/DESIGN.md:188-196`, confirmed unchanged 2026-09-20) already
prohibits copying concrete config values into design documents.
`tools/check_docs_content_policy.py` already implements 15 report-only
checks (confirmed via `grep -c "all_issues += check_"` = 15, 2026-09-20),
wired into `main()`. Running the tool against the full `docs/` tree today
(2026-09-20) produces 36 total warnings and zero findings for the
code-fallback-vs-operational-value pattern, confirmed present in:
- `docs/03_rag_02_02_ingestion_pipeline-crawler.md`'s "2.1.1 Configuration
  Parameters" table (header `| Parameter | Code Fallback Value | Production
  Value (config/crawler.toml) |`, confirmed unchanged at lines 46-52).
- `docs/03_rag_01_system_overview.md`'s "## Constraints" section (confirmed
  at line 205; the source Issue's original "Operational Constraints"
  heading name does not exist in this file — already corrected during the
  Issue's own adversarial verification, carried forward here), rows "Crawl
  Depth"/"Max Pages Per Site" (lines 213-214).
- `docs/03_rag_05_5-constraints-reference.md`'s "Crawl depth"/"Max crawl
  pages" rows (confirmed at lines 23-24).

`docs/03_rag_05_5-constraints-reference.md`'s own "Evidence" section (line
34, confirmed unchanged) documents a past staleness incident where earlier
versions of the file stated `config/agent.toml:43`/"max 6 hops"/"max 500
pages", since proven wrong — direct evidence of the drift risk this check
guards against.

## Problem
None of the 15 existing check functions match either target shape:
`check_field_type_table` requires a `Field`/`Key` header column paired with
`Type`/`Default` (crawler.md's header uses `Parameter`; system_overview.md's
and constraints-reference.md's tables use `Constraint`, neither matches);
`check_default_value_restatement` only matches `` `x` defaults to `y` ``
prose and explicitly skips any line starting with `|`. No existing check
inspects a table row's cell content for a code-default-vs-operational-value
comparison phrase.

## Reason for change
The same documentation-drift category the tool's existing 15 checks already
guard against, evidenced by an already-realized staleness incident in this
exact corpus (not a hypothetical risk).

## Implementation intent
Add one new check function, `check_code_fallback_value_comparison`,
following the exact structural pattern `check_error_handling_table` already
uses (two independent detection paths merged into one function, each
appending the same `Issue` message): a header-shaped path (a table row
whose header contains both a `Code Fallback`/`Fallback Value`-style column
and a `Production Value`/`Operational Value`-style column) and a
phrase-shaped path (any line — table row or prose — containing both a
`code default`/`code fallback` phrase and an `operational`/`production`
phrase). Both paths respect the existing `_is_guard_start`/`_is_guard_end`
auto-generated-block exemption, matching all 15 existing checks.

Do not add a filename-based exemption for
`docs/03_rag_05_1-configuration-reference.md` (see Design) — its own "1.4"
section will also be flagged by the phrase-shaped path, and this Plan
treats that as an accepted, documented outcome rather than a defect to
prevent, consistent with how `docs/03_rag_05_4-error-handling-reference.md`
is still flagged by `check_error_handling_table` today with no code-level
exemption.

## Design
This is a small, single-module Plan (3 target files) — Path A per
`skills/issue-to-plan/SKILL.md` Routing (≤3 files, no public/runtime
interface change, no DB schema change). Direct-verification inspection only

- **Validation quality baseline**: see Tests section above (radon/vulture/
  bandit/pytest all clean or unremarkable before this change).
- **Detection design**: two-path structure inside one function
  (`check_code_fallback_value_comparison`), mirroring
  `check_error_handling_table`'s existing precedent of combining a
  heading-proximity path and a header-shape path in one function. Header
  path: a table row whose header contains both a `Code Fallback`/`Fallback
  Value`-style column and a `Production Value`/`Operational Value`-style
  column (catches `crawler.md`'s "2.1.1" table). Phrase path: any line
  containing both a `code default`/`code fallback` phrase and an
  `operational`/`production` phrase (catches `system_overview.md`'s and
  `constraints-reference.md`'s rows). Both regexes were hand-tested this
  cycle against 8 real lines from the 4 files in Reference Files (see
  Implementation Target Files' Repository Evidence column) via a standalone
  Python snippet, confirming: crawler.md's header matches both paths;
  crawler.md's data rows match neither; system_overview.md's/
  constraints-reference.md's Crawl-Depth/Max-Pages rows match the phrase
  path only; system_overview.md's/constraints-reference.md's Chunk-Size/
  Chunk-Overlap rows match neither path (correctly out of scope);
  config-reference.md's "1.4" `top_k_search` row matches the phrase path
  (the accepted false positive, see below).
- **Corrected understanding: config-reference.md exemption** (Step 2/3
  finding, overrides the source Issue): the source Issue's Acceptance
  Criteria stated the new check "produces no new finding attributable to
  the new check" against `docs/03_rag_05_1-configuration-reference.md`, and
  its Unresolved Questions flagged this as needing verification "not by
  assumption." Empirical regex testing this cycle (see above) confirms the
  phrase path WOULD flag that file's "1.4" section (its
  `top_k_search`/`top_k_rerank`/`rag_min_score`/`refiner_max_chars_per_chunk`
  rows all state "code default; operational config uses X"). No existing
  check in this tool implements a filename-based exemption — all 15

  which `check_error_handling_table` already flags today with no exemption

  follows the same precedent: `check_code_fallback_value_comparison` will
  flag `docs/03_rag_05_1-configuration-reference.md`, and that is accepted
