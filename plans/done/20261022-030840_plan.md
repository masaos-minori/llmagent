# Plan: Deliver one shutdown event to every REPL consumer so Ctrl-C and SIGTERM take effect

## Goal
- Make `AgentREPL` own a single `asyncio.Event` and hand that same object to every shutdown consumer before any of them is built, so that the already-written shutdown-race code in `ReplInputLoop` becomes reachable: a signal while the prompt is waiting ends the REPL without further keyboard input, and a signal during a turn cancels that turn's dispatch with a bounded unwind.

## Priority
High

## Scope
- **In-Scope**: shutdown-event ownership and construction order in `scripts/agent/repl.py`; the bounded cancellation unwind on the shutdown branch of the mid-turn race in `scripts/agent/repl_input_loop.py`; removal of the now-unreachable rebinding hook in `scripts/agent/signal_handler.py`; regression tests that drive the real `AgentREPL` construction rather than hand-wired fixtures; correction of the two documents that state the current (wrong) signal contract.
- **Out-of-Scope**: making the interpreter exit while a worker thread is still blocked in `input()` (`repl002` — the executor/timeout owner decision); changing the value of `_GRACEFUL_TIMEOUT_S` or consolidating its duplicate definition; distinguishing SIGINT from SIGTERM behavior; MCP subprocess orphan policy and termination timeouts (`shutdown003`); restructuring the REPL test fixtures so every test uses the real wiring (`repl003`); signal behavior during startup (`StartupInterrupted`), which already consumes this event.

## Background
`ReplInputLoop` was extracted from `repl.py` together with its shutdown-race machinery: the `_shutdown_watcher` race in `_read_input` (`repl_input_loop.py:136-188`), the dispatch-vs-shutdown race in `_repl_loop` (`:255-284`), the `_InputAborted` sentinel (`:146`, `:186`) and the bounded `asyncio.wait_for` (`:288-297`). All of it is written to be driven by one `asyncio.Event`.

Only two consumers receive that event. `SignalHandler` is rebound after `run()` creates it (`repl.py:113-114`, `signal_handler.py:136-138`) and `StartupOrchestrator` is constructed with it (`repl.py:120-122`, `startup.py:53-62`). `ReplInputLoop` is constructed in `AgentREPL.__init__` (`repl.py:85`) with `self._shutdown_event`, which is `None` at that point (`repl.py:82`), and has no rebinding hook: `bind()` (`repl_input_loop.py:71-74`) attaches only `_cmds` and `_orchestrator`.

`tests/agent/test_repl.py:712-730` (`TestRunBindsStartupResultsToInputLoop`) exists specifically to guard the `_cmds`/`_orchestrator` rebinding. No equivalent guard exists for the shutdown event, and the shutdown tests build their own correctly-wired object (see `Problem`), which is why the suite is green.

## Problem
Verified against HEAD `b17ca6a26`. All four claims of the source issue are confirmed; the mechanism is stated as it is at HEAD.

- `ReplInputLoop._shutdown_event` is assigned in exactly one place, `repl_input_loop.py:65` (`grep -n "_shutdown_event" scripts/agent/` shows no other assignment), so the `None` passed at `repl.py:85` is never replaced. `_signal` is rebound at `repl.py:114`; the input loop is not.
- Dead code, live branch identified: `repl_input_loop.py:139` (`if shutdown_event is not None:`) is always false, so the prompt is read by the `else` branch at `:189-194` — `await loop.run_in_executor(None, lambda: input("> "))`, default executor, no timeout, no shutdown watcher, no `_abort_input()` path. `_input_coro` is therefore never assigned on the live path (`:120`, `:149` are in the dead branch). The mid-turn race at `:255-284` is likewise unreachable; `:285-305` is the live path, and its `timeout=self._GRACEFUL_TIMEOUT_S` (`:288-297`) is computed from `ctx.conv.shutdown_requested` at the moment the await starts — which `_should_exit` (`:201-208`, called at `:243`) has just excluded. A signal arriving during a turn therefore yields `timeout=None`, and only the post-turn check at `:316` ends the loop.
- Measured directly (project venv, probe with `loop.add_signal_handler(SIGINT, ev.set)` awaiting `run_in_executor(None, input)`, stdin held open by `tail -f /dev/null`): after SIGINT was delivered (`event set = True`) the read was still blocked; `asyncio.run()` returned; the process did not exit within 25 s because the default-executor worker `asyncio_0` was still inside `input()`. Cancelling the `Future` did not unblock the worker thread. A second probe with an executor whose threads are daemon returned immediately after the event fired and the process exited with code 0. Both facts are used below: the first is `repl002`'s problem, the second is why this Plan does not attempt it.
- No existing mitigation covers the primary prompt: `_INPUT_TIMEOUT_S = 30` (`cli_view.py:24`) guards only the multi-line continuation read (`read_multiline`, `cli_view.py:285-291`), and that executor is itself non-daemon (`cli_view.py:286-288`), released only by `shutdown(wait=False)` in `__del__` (`:115-118`).
- The reason the suite is green: both REPL fixtures bypass `AgentREPL.__init__` and hand-wire a real event — `tests/agent/test_repl.py:78` and `:632-636` (`_make_repl_for_shutdown`) construct `ReplInputLoop(ctx, view, shutdown_event)` directly, and no test constructs `AgentREPL()` (`grep -rn "AgentREPL()" tests/` returns nothing). `TestReadInputShutdownRace` (`:640-706`) therefore tests machinery the production object never enables.
- Operator-facing text is wrong: `deploy/start_agent.sh:195` prints "Ctrl+C で停止"; `docs/23_agent/agent_07_05_cli-and-commands-repl-io.md:39` states Ctrl-C during input wait terminates the REPL like EOF, `:43` states a running turn is awaited for a bounded grace period, `:52` states Ctrl-C while waiting terminates the REPL. `docs/23_agent/agent_02_runtime-architecture.md:163` states the loop terminates after the next turn completion with a bounded grace period. Only the post-turn completion half is true; the bounded grace never applies to a signal that arrives during a turn.

## Reason for Change
Ctrl-C is the primary exit interaction for this REPL and the operator instruction promises it. Today a signal at the prompt is ignored until the user submits a line, a running turn is unbounded, and an operator who gives up and force-kills the process skips WAL checkpoint, session persistence and MCP termination (`repl.py:161-162`, `repl_input_loop.py:111-115`; MCP subprocess servers are started with `start_new_session: True`, `http_lifecycle_subprocess_launcher.py:99`, so they are not signalled with the REPL). The fix is one wiring line of consequence, not new behavior: everything it enables is already written.

## Implementation Intent
Give `AgentREPL.__init__` sole ownership of the shutdown event and construct every consumer after it, so no consumer can ever hold `None` and no rebinding hook is needed. Then make the second half of the contract explicit where it is currently implicit: the shutdown branch of the mid-turn race already cancels the dispatch task, so bound the wait for that cancellation with the module's existing graceful bound and route a timeout through the existing warning helper. Keep signal delivery, signal handling and the None-fallback read path exactly as they are.

## Assumptions
- `AgentREPL` is instantiated once per process (`main()` at `repl.py:170-172`), and `run()` is not designed to be re-entered after shutdown; the event's lifetime is therefore the instance's lifetime. No test calls `run()` twice on one instance (`tests/agent/test_repl.py` constructs a fixture per test).
- Cancelling a `run_in_executor` `Future` cannot interrupt a worker that has already started `input()` — measured, not assumed — so this Plan never claims that the pending read stops; it only guarantees the loop stops waiting for it.
- `loop.add_signal_handler()` is available in production (Linux, `deploy/start_agent.sh`); the Windows fallback path is left untouched.
- The existing race branch's intent is as written in its own comment (`repl_input_loop.py:271-273`: "exit rather than looping back to `_read_input`"), so making it live is a restoration, not a new policy.

## Design
Path B: one architectural defect (an object graph built before one of its shared objects exists) plus the behavioral consequence it hides, in three production modules, with an observable behavior change (a signal now takes effect at the prompt and during a turn) and an existing test suite that encodes the pre-fix shape. Classification evidence: the issue's own target list spans `repl.py`, `repl_input_loop.py`, `signal_handler.py`, a docs chapter and `deploy/start_agent.sh`; verification narrows the code change to the event's construction order and one bound, because everything else needed already exists in `repl_input_loop.py`.

Design decisions:
- One owner, constructed first. `AgentREPL.__init__` creates the event before any consumer. Rejected alternative: add `ReplInputLoop.set_shutdown_event()` and call it beside `SignalHandler`'s at `repl.py:113-114`. That fixes this symptom but keeps two initialization states for one object and makes correctness depend on every future consumer remembering to rebind — which is exactly how this defect arose. The rebinding hook is therefore deleted rather than duplicated (`REQ-005`).
- Keep `asyncio.Event | None` in both signatures and keep the `None`-fallback read branch. Tightening the type to `asyncio.Event` would delete a defensive path that `tests/agent/test_repl.py:674-680` deliberately covers and that `startup.py:53` and `http_lifecycle.py:290` also accept as optional. The guarantee this Plan adds is narrower and testable: no production call site passes `None` (`AC-1`).
- Bound the unwind instead of inventing a second mechanism. The reachable branch at `repl_input_loop.py:271-284` already cancels `dispatch_task` and `await`s it without a limit; `asyncio.wait_for(dispatch_task, self._GRACEFUL_TIMEOUT_S)` plus `_log_graceful_shutdown_timeout()` reuses the module's existing bound and warning path, which is what `REQ-003` and the issue's Acceptance Criteria ask for. In Python 3.12+ `wait_for` raises `TimeoutError` when the bound expires regardless of whether the awaited task unwinds, so the bound is deterministic; the cost is that a cancelled-but-unwinding task can outlive the loop, which `UNK-03` records rather than hides.
- Do not change the constant or merge the two definitions (`REQ-004`). Silently altering a shutdown timeout while also changing which code paths reach it would make the behavioral change unattributable, and the duplicate's ownership is undecided (`UNK-02`).
- Do not touch the input-read executor, its threads, or `_INPUT_TIMEOUT_S`. Making the loop stop waiting for the read is this Plan's half; making the blocked worker stop holding the interpreter is `repl002`'s half, measured as a separate defect (the second probe: a daemon-thread executor exits cleanly, the default executor does not). Splitting them keeps each change attributable and each test single-purpose. `repl001`'s AC-3 asserts the loop returns; `repl002` owns process exit.
- Keep one signal handler for SIGINT and SIGTERM (`signal_handler.py:54-63` unchanged). Distinguishing them is a policy decision the codebase does not currently make (`UNK-01`), and adding it here would couple an unrelated policy to a wiring fix.
- Cross-plan overlaps, recorded deliberately: `scripts/agent/repl_input_loop.py` is also a planned target of `repl002` (the input-read executor/timeout), and `tests/agent/test_repl.py` is also a planned target of `repl003` (real-wiring test harness). The regions are disjoint — `repl.py`'s constructor and the race's `await` here, `_read_input`'s executor there, fixture construction there — and the implementation order is fixed as `repl001` → `repl002` → `repl003`. `scripts/agent/repl.py` is a Frozen target of no other active Plan (`plans/20261022-020701_plan.md` names it only as must-not-change, and `plans/20261022-024105_plan.md` rewrites its docstring only, in a region `REQ-001` does not touch); the docs rows are not targeted by any other active Plan.

## Risks
- **Risk**: Making the mid-turn race live changes the outcome of a signal during a turn from "the turn finishes, then the loop exits" to "the turn's dispatch is cancelled", which can truncate a partially completed turn. → **Mitigation**: `REQ-003` and AC-4 test both a cancellation-responsive and a non-cooperative stub, `UNK-01` records the policy question rather than deciding it silently, and the docs state the implemented behavior only. The alternative (never cancel) is the pre-fix behavior the issue's Acceptance Criteria reject.
- **Risk**: A task cancelled at the bound may still be unwinding when `close_resources()` runs, so a turn could touch resources that are being closed. → **Mitigation**: the task is already cancelled before the bounded wait, so it raises `CancelledError` at its next await point; the boundary and the open question are recorded in `UNK-03`/WI-02 instead of being papered over, and `tests/agent/test_resource_shutdown_coordinator.py` must pass unchanged.
- **Risk**: `_repl_loop` is already the module's most complex function (radon D (29)) and `repl_input_loop.py` is the nearest file to the size gate (13224 B of 16384 B). → **Mitigation**: the change stays inside the existing branch and reuses the existing helper; radon and `check_module_size.py` are run in the validation plan, and any extraction must lower the score, not hide it in a new function.
- **Risk**: Constructing the event in `__init__` extends its lifetime to the instance's lifetime. → **Mitigation**: `AC-1` asserts the same object before and after `run()`; the single-instance lifecycle of `AgentREPL` is stated as an assumption, and `main()` (`repl.py:170-172`) is the only production instantiation.
- **Risk**: The change looks complete but the process can still hang at exit because a worker thread is blocked in `input()`, which could be mistaken for a fix that did not work. → **Mitigation**: the split is stated in `Scope` and `Design`, AC-3 asserts only loop return, and `repl002`'s plan owns the executor decision with its own measured evidence.
- **Risk**: The two docs rows and `tests/agent/test_repl.py` are shared with `repl002`/`repl003`'s future Plans. → **Mitigation**: regions are disjoint and the order is fixed (`repl001` → `repl002` → `repl003`); `check_plan_target_overlaps.py` is run so an unintended overlap is visible.
- **Risk**: Docs could claim a SIGINT/SIGTERM distinction the code does not implement. → **Mitigation**: AC-7 forbids it explicitly and UNK-01 gates any such wording on the owner's answer.
