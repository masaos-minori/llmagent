# Plan: Document the module-level `logger`-declared-ahead-of-use convention in rules/coding.md

## Goal

Add an explicit, unambiguous statement to `rules/coding.md` codifying that a module-level
`logger = logging.getLogger(__name__)` declared before its first call site is accepted,
intentional boilerplate — not dead code — so future refactor cycles and automated dead-code
passes stop re-litigating this per file. This is a documentation-only change; no `scripts/*.py`
file content changes.

## Scope

### In-Scope
- Add one new short subsection (a `##`-level heading with a bullet list, matching the file's
  existing style) to `rules/coding.md` stating the convention in English.
- The note must cover: (a) the pattern is accepted intentional boilerplate anticipating
  near-future use, (b) dead-code tools (vulture, manual review, refactor passes) should not flag
  or remove an unused module-level `logger` on this basis alone, (c) the exemption is scoped
  narrowly to the `logger = logging.getLogger(__name__)` pattern only — it does not exempt other
  unused module-level names (imports, constants, functions) from normal dead-code review.

### Out-of-Scope
- Any change to `scripts/shared/token_estimation.py`, `scripts/shared/llm_client.py`,
  `scripts/shared/llm_sse_stream.py`, `scripts/shared/mcp_config.py`,
  `scripts/shared/tool_registry.py`, or any other `scripts/*.py` file.
- Any change to `docs/*.md` files.
- Any change to lint configuration (`pyproject.toml` vulture/ruff settings) — not needed since
  vulture already does not flag this pattern (verified below).

## Design

`rules/coding.md` is the repo's single source of truth for shared coding conventions (per its own
header) and is organized as a flat sequence of `##`-level sections (`Mandatory conventions`, `Tool
configuration`, `Suppression governance`, `Constraint checks`, `Bandit priority findings`, `Key
library choices`, `mypy note`, `Documentation notes`, `Prohibited behavior`). It is a pure
Markdown convention document — no Python module imports it, no `import-linter` contract references
it, and it has no runtime/layering role, so there is no architecture or import-boundary
consideration for this change.

The new section will be inserted as `## Logging convention`, placed after `## Key library choices`
(line 84) and before `## mypy note` (line 89), matching the file's existing terse
heading-plus-bullet-list style (see `## mypy note` at lines 89-91 for an example of a short,
single-topic subsection). Content will state, in the file's existing tone:

- A module-level `logger = logging.getLogger(__name__)` may be declared ahead of the module
  having any call site for it — this is accepted, intentional boilerplate anticipating near-future
  use, not dead code.
- Dead-code tooling (`vulture`, manual review, refactor passes) must not flag or remove an unused
  module-level `logger` declaration on this basis alone.
- The exemption is scoped narrowly to this exact `logger = logging.getLogger(__name__)` pattern —
  it does not extend to other unused module-level names (imports, constants, functions), which
  remain subject to normal dead-code review.

No other file requires a corresponding change: the five `scripts/shared/*.py` reference files stay
exactly as-is (confirmed above), and no `docs/*.md` file is touched per the requirement's explicit
instruction that this is a coding-convention change, not user-facing behavior documentation.

## Risks

- **Risk**: The new section's wording is too broad and inadvertently reads as exempting *all*
  unused module-level names in `scripts/shared/`, not just `logger` declarations, weakening
  dead-code review elsewhere. → **Mitigation**: Explicitly scope the note to the exact
  `logger = logging.getLogger(__name__)` pattern (third bullet in Design), as the requirement's
  acceptance criteria mandates; have the Phase 2 re-read step specifically check this scoping
  sentence is present and unambiguous before committing. Likelihood: low.
- **Risk**: Placing the new section between "Key library choices" and "mypy note" could be
  reviewed as an awkward fit if a future contributor expects logging conventions grouped with
  "Documentation notes" instead. → **Mitigation**: This is a low-cost, easily-revertable choice —
  moving a `##` section within a flat Markdown file is a trivial follow-up edit if a reviewer
  requests it; no downstream reference (docs/skills) hardcodes a line number into
  `rules/coding.md`, so relocating the section later carries no additional blast radius.
  Likelihood: low.
- **Risk**: A future contributor unaware of this new convention still manually deletes one of the
  five unused logger declarations during an unrelated refactor, before having read the updated
  `rules/coding.md`. → **Mitigation**: This is exactly the scenario the requirement is designed to
  prevent going forward; residual risk is inherent to any documentation-based (non-enforced)
  convention and is accepted per the requirement's own reasoning (a single logger line is
  zero-risk/zero-maintenance even if it recurs). No tooling enforcement is in scope for this
  requirement. Likelihood: low.
