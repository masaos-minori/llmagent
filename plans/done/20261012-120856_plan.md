## Background
- `tools/check_mock_patch_targets.py` is a report-only heuristic that flags `patch("origin.Symbol")` when a module the test file imports binds `Symbol` from `origin` at module level. It reports 23 findings at 11 call sites in 6 test files.
- Issue `issues/20261012-120426_mock001_fix-ineffective-mock-patch-targets-in-tests.md` asked to triage every site. Step 2 verification against current source showed that most flagged sites are not ineffective (see Problem).
- The checker's candidate-module set is every known source module the test file imports at any scope, so it names importers that are not on the code path the test exercises.

## Problem
Verified per call site against current source (`Confirmed by repository evidence`):
- **1 confirmed ineffective patch**: `tests/mcp_servers/git/test_git_security_compliance.py:696` patches `mcp_servers.audit._audit_log`, but `scripts/mcp_servers/git/git_server.py:32` binds it with `from mcp_servers.audit import _audit_log`. A probe run of the same request recorded `called=False` for the origin patch and `called=True` for `mcp_servers.git.git_server._audit_log`. The test's assertions sit inside `if mock_audit.called:`, so with the current patch they never run. The same file already patches the correct target at line 2388.
- **1 dead ineffective fixture**: `tests/agent/commands/test_memory_consistency.py:167` (`mem_store`) patches only `db.helper.SQLiteHelper`, which `agent.memory.store` does not see, and no test in `tests/` uses the fixture.
- **2 redundant origin patches**: `tests/agent/memory/test_memory_store.py:147` already patches `agent.memory.write_ops`, `agent.memory.store`, and `agent.memory.count_ops` explicitly; `tests/agent/commands/test_memory_consistency.py:175` replaces the bound references in `import_ops` and `write_ops` by hand. The origin patch adds nothing at either place.
- **7 effective patches reported by the heuristic** (the Issue's claim that they are ineffective does not hold):
  - `tests/agent/commands/test_agent_cmd_memory.py:348,369,404`: `memory_prune` in `scripts/agent/commands/memory_data_ops.py` imports `SQLiteHelper` inside the function, so patching `db.helper.SQLiteHelper` works.
  - `tests/agent/test_llm_turn_runner.py:147`: `_finalize_after_guard` in `scripts/agent/llm_turn_runner.py` imports `validate_message` inside the function.
  - `tests/agent/test_startup_approval_recovery.py:649,690,817`: `recover()` in `scripts/agent/startup_approval_recovery.py` imports `Logger` inside the function. The Issue's statement that `agent.startup` creates the logger at import time is true but is not the code path under test.

## Reason for change
- The git audit compliance test claims to check that the raw requested path is not leaked into the audit record, but currently checks nothing.
- The checker cannot reach zero findings, and so cannot later be gated, while it reports patches that are correct. Without a way to record why a patch is correct, the next triage repeats this analysis.

## Implementation intent
- Fix only what is wrong: one retarget, one fixture removal, two redundant-patch removals.
- For patches that are correct because of a function-local import, do not rewrite them. Teach the checker an explicit per-line suppression that requires a reason, so the justification lives next to the patch.
- Keep the checker report-only and its candidate heuristic unchanged; the marker is the only behavior change.
- The suppression marker is `# mock-patch-ok: <reason>` on the physical line of the `patch(` call. A marker with an empty reason does not suppress.
