## 1. Goal
Fix the `git-exc-import-guard` pre-commit hook's intermittent failure caused by a bash exit code logic bug where the while loop always returns exit code 1 regardless of whether `import git.exc` statements exist.

## 2. Scope
**In-Scope**:
- Modify `.pre-commit-config.yaml`: fix the `git-exc-import-guard` hook entry's bash command
- Change from: `bash -c 'rg -l "git\\.exc\\." scripts/ | while read f; do ! grep -q "import git\\.exc" "$f" && echo "$f"; done'`
- Change to: `bash -c 'missing=$(rg -l "git\\.exc\\." scripts/ | while read f; do ! grep -q "import git\\.exc" "$f" && echo "$f"; done); [ -z "$missing" ] && exit 0 || echo "$missing" && exit 1'`
- Verify `uv run pre-commit run git-exc-import-guard --all-files` passes
- Verify hook still detects missing imports when present

## 6. Implementation Steps
1. **Phase 1: Core Logic Fix**
   - [ ] Replace the `git-exc-import-guard` hook entry in `.pre-commit-config.yaml` (line 50):
     ```yaml
     # Before:
     entry: bash -c 'rg -l "git\\.exc\\." scripts/ | while read f; do ! grep -q "import git\\.exc" "$f" && echo "$f"; done'
     
     # After:
     entry: bash -c 'missing=$(rg -l "git\\.exc\\." scripts/ | while read f; do ! grep -q "import git\\.exc" "$f" && echo "$f"; done); [ -z "$missing" ] && exit 0 || echo "$missing" && exit 1'
     ```
   - Root cause explanation: When iterating over files that ALL have `import git.exc`, each iteration's `! grep -q` returns exit code 1 (because negation of success = failure). Since `&& echo` doesn't execute on failure, the exit code of that line becomes 1. The while loop ends with exit code 1 because the LAST iteration had a failed condition.

2. **Phase 2: Verification**
