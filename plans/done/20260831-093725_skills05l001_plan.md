## Background
The source Issue for this Plan named `### Context Efficiency`, `### Tasks`, and
`### Repository Tool Usage` as containing restated rather than referenced
context-management and tool-usage guidance, but flagged this as
**lower-confidence** than the H-001/H-002/H-003 findings, since only one
concrete overlap (`Step 5`'s report-item list vs. `Context Efficiency`'s
final-report bullet) had been tentatively identified, and it asked for an
item-by-item equivalence check during implementation before editing anything.

That item-by-item check has now been performed (current session, direct
re-read): `Step 5`'s six report items (lines 394-400) and `Context Efficiency`'s
final-report bullet (lines 319-322, itself six items) match on five of six
points almost verbatim (modified files; relocated content/canonical
destinations; deferred items and reason; the two Context Loader Pattern
Validation measurements; the Step 4/validation result). The sixth `Step 5` item
— "any new file created, per the New File Creation Policy" — has no counterpart
in `Context Efficiency`'s list and is therefore genuinely unique. `###
Repository Tool Usage` was also re-checked against `Context Efficiency` and
found non-duplicative: it delegates to `rules/ai-execution.md`'s "Repository
Tool Usage" section for a different topic (tool-usage scope for this workflow's
detection/validation needs) than `Context Efficiency`'s topic (context-reading
and progress-reporting economy).

## Problem
`Step 5`'s report-item list restates, almost item-for-item, content already
stated once in `Context Efficiency`'s final-report bullet. Any future addition
to one list (e.g. a new required report field) can be made without updating the
other, and the two lists already differ enough in wording that a reader cannot
tell at a glance that they describe the same five items.

## Reason for change
- Maintenance risk: two near-identical lists of required final-report content
  must be kept in sync by hand.
- Context cost: `prompts/05_skills.md` is loaded in full by its own Step 0;
  restating five of six items again in `Step 5` is pure per-invocation overhead.
- Clarity: reducing `Step 5` to a reference plus its one unique item makes that
  uniqueness visible, instead of burying it inside a six-item list that is
  otherwise a full restatement.

## Implementation intent
Rewrite `Step 5`'s report-item list to a single reference to `Context
Efficiency`'s final-report bullet (using the `See <file path>, section
"<heading or Rule ID>".` format from `### Canonical References`), followed by
the one item not covered there ("any new file created, per the New File
Creation Policy"). Leave `Context Efficiency` and `Repository Tool Usage`
unchanged — `Context Efficiency` because it is the canonical target, and
`Repository Tool Usage` because it was confirmed non-duplicative rather than
merely assumed so.
