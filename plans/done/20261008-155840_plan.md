# Plan: Fix EventBus authorization model for consumer tokens

## Goal

Make the EventBus authorization model fail closed: every consumer token must map to an explicit set of allowed consumer IDs, an empty allow-list always means "deny all", and all-role tokens are operator-only.

## Priority

Medium

## Scope

- **In-Scope**:
  - `scripts/eventbus/auth.py`: reject `consumer_token` without `consumer_authorization` at startup config validation, unify allow-list semantics
  - `scripts/eventbus/ack_route.py`: unify allow-list checks to `is not None` plus membership in both ACK and NACK, remove debug WARNING log
  - `scripts/eventbus/app.py`: confirm `_principal` passing to ACK/NACK handlers
  - `config/eventbus.toml`: update documentation comments for operator-only tokens
  - `docs/10_adr/ADR-006-eventbus-sqlite-persistence-and-sse-delivery.md`: revise INV-10
  - `docs/10_adr/ADR-013-eventbus-authentication-authorization.md`: document operator-only constraint for `auth_token`/`admin_token`
  - `docs/24_eventbus/eventbus_02_api-reference-index.md`: update auth model documentation
  - `docs/00_governance/governance_03_issue-and-uncertainty-management.md`: update Known Issues (EVENTBUS-008, EVENTBUS-013, EVENTBUS-015)
- **Out-of-Scope**:
  - ACK/NACK state management (separate issue)
  - DLQ model
  - Health endpoint changes of unrelated servers
  - Circuit-breaker behavior

## Background

Source: local investigation notes (memo1.md, ISSUE-07), consolidating EVENTBUS-008, EVENTBUS-013 and three earlier findings. ADR-013 INV-02 requires fail-closed; ADR-006 INV-10 concerns concurrent use of one Consumer ID.

## Problem

- Without `consumer_authorization`, a CONSUMER token has `allowed_consumer_ids=None` (no restriction) and can act as any consumer ID (EVENTBUS-008).
- `auth_token` is mandatory (`get_auth_token()`) and grants all roles with no consumer-ID restriction, so an all-powerful token always exists; `admin_token` also grants all roles, contradicting eventbus_02's "role tokens only for their own role".
- The meaning of an empty allow-list is inverted between code paths: `ack_route.py` uses truthiness (empty = unrestricted) while `require_consumer_identity()` uses `is not None` (empty = deny all).
- ACK/NACK cannot prevent several principals from using the same Consumer ID (EVENTBUS-013, ADR-006 INV-10).
- `_do_ack()` keeps a debug log at WARNING that prints principal information.

## Reason for Change

- "No allow-list means allow all" is fail-open and violates ADR-013 INV-02.
- A mandatory all-role token defeats least privilege regardless of role-token granularity.
- One concept with opposite meanings per location yields configurations that do not match intent and cannot be security-reviewed.
- ACK can arrive after a subscription disconnects, so binding INV-10 to an open subscription would reject legitimate ACKs; what must be prevented is a different principal using the same consumer ID, which token-to-consumer-ID binding achieves.
- The debug log leaks authentication information at WARNING.

## Implementation Intent

- Token to allowed consumer-ID set must always be explicit and fail closed.
- All-role tokens are for operators only and are not distributed to consumers (stated as a design rule).
- An empty allow-list consistently means deny all.

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| `consumer_token` configured without `consumer_authorization` | Reject at startup config validation |
| Empty allow-list (`frozenset()`) | Deny all consumer IDs (consistent with `is not None` semantics) |
| `auth_token` or `admin_token` present | Document as operator-only; do not weaken auth |
| `_principal` missing in ACK/NACK handler | Pass `_principal` through app.py wrapper |

### Option B for `/health` auth (from ADR-007 precedent)

Agent sends Bearer token on `/health` requests when `cfg.auth_token` is set, consistent with ADR-007 "authenticate all endpoints".

### Decision details

1. **Reject `consumer_token` without `consumer_authorization`**: In `_populate_token_maps()`, if `consumer_token` is set but `consumer_authorization` is not, raise ValueError at startup. This enforces the fail-closed principle.
2. **Unify allow-list semantics**: Replace the truthiness check in `ack_route.py` with `is not None` plus membership check, matching `require_consumer_identity()` semantics.
3. **Pass `_principal` to NACK handler**: In `app.py`, forward `_principal` to `nack_route()` so the authorization check in `_do_ack()` is enforced.
4. **Remove debug WARNING log**: Change `logger.warning("DEBUG _do_ack: ...")` to `logger.debug(...)`.
5. **Document operator-only constraint**: Update ADR-013 and eventbus_02 to explicitly state that `auth_token` and `admin_token` are operator-only credentials.
6. **Revise ADR-006 INV-10**: Update to "a consumer ID may be used only by the principal bound to it by token", with scope stated.

- **Source**: Issue "Problem" section, "Reason for Change" section

## Assumptions

- Option B (authenticate all endpoints) is the preferred `/health` authentication policy, consistent with ADR-007.
- The `consumer_authorization` config field is available on `EventBusConfig` (confirmed in `config.py` line 104).
- `McpServerConfig.required` defaults to `True` (line 104 of mcp_config.py), so only explicitly set `required=false` servers are affected.
- The existing `is_disabled` property on `McpServerConfig` (line 110) is sufficient for disabling a server — no new property needed.
