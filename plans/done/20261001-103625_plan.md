# Plan: Remove Redundant Subprocess Termination in repl.py Startup-Failure Exception Handler

## Goal
Remove the `hasattr`-based process collection and redundant subprocess termination from `AgentREPL.run()` in `scripts/agent/repl.py`, relying solely on `StartupOrchestrator.run()`'s internal `lifecycle.shutdown_all()` for subprocess cleanup on startup failure.

## Priority
Low

## Scope
- **In-Scope**: Removing the `hasattr`-based process collection and termination loop from `repl.py`; verifying no orphaned processes remain on startup failure paths.
- **Out-of-Scope**: Changing how subprocesses are spawned or health-checked; refactoring the normal REPL shutdown path (`ResourceShutdownCoordinator`).

## Background
`StartupOrchestrator.run()` spawns HTTP-subprocess MCP servers, tracks them in `self._spawned_subprocesses`, and on any setup exception calls `await self._ctx.services_required.lifecycle.shutdown_all()` before re-raising. `repl.py`'s `run()` wraps `startup.run()` and, in its `except`, also terminates the returned processes.

## Problem
The `except` block builds its process list via `all_procs = _spawned_subprocesses` then conditionally appends `list(startup._spawned_subprocesses)` using `hasattr`. This depends on attribute introspection and on the local `_spawned_subprocesses` remaining empty when `startup.run()` raises mid-unpacking. It works today, but the `hasattr` introspection is fragile (future `StartupOrchestrator` changes to how it exposes spawned processes would break it) and the termination it performs is redundant with `startup.run()`'s own `shutdown_all()`, which fully terminates each subprocess before this handler runs (repl.py guards with `if proc.poll() is None:`, so the already-dead processes are skipped). Consolidating to a single authoritative shutdown path removes the introspection fragility rather than fixing a live double-terminate bug.

## Reason for change
Resource-cleanup code on the failure path should be obvious and singular. Introspection-based collection invites future breakage if `StartupOrchestrator` changes how it exposes spawned processes.

## Implementation intent
Establish one authoritative shutdown path for startup-spawned subprocesses. Either (a) rely solely on `StartupOrchestrator.run()`'s internal `shutdown_all()` and remove the termination loop from `repl.py`, or (b) have `startup.run()` propagate the process list reliably and terminate there once. Confirm with whoever owns the lifecycle contract which is correct; do not leave two partial terminations.

## Requirements
- `REQ-001`: Remove the `hasattr`-based process collection and termination loop from `repl.py`'s startup-failure exception handler.
- `REQ-002`: Ensure each spawned subprocess is terminated exactly once on startup failure (no leak, no double-terminate error).
- `REQ-003`: Preserve the success-path return contract `(cmds, orchestrator, spawned_subprocesses)`.
- `REQ-004`: Run lint/type checks (ruff, mypy) on modified files.

Verification confirmed that:
1. `startup.run()` calls `shutdown_all()` on its own exception path (line 81 of `startup.py`)
2. `repl.py` has NO `shutdown_all()` call — it relies on `hasattr` introspection to collect processes
3. Both paths perform termination on the failure path; repl.py's loop is redundant with `shutdown_all()` and guarded by `if proc.poll() is None:`, so no live double-terminate occurs today.

**Recommended approach**: Option (a) — rely solely on `StartupOrchestrator.run()`'s internal `shutdown_all()` and remove the termination loop from `repl.py`.

Rationale:
- `shutdown_all()` already handles subprocess termination (confirmed by `test_http_lifecycle_shutdown_coordinator.py`)
- The return value of `startup.run()` is never used on the failure path anyway
- Removing the redundant termination consolidates cleanup into one authoritative path (no live double-terminate occurs today; repl.py guards with `if proc.poll() is None:`)
- The `hasattr` check is unnecessary since `startup` is always the same object created just above

The fix removes lines 127-134 of `repl.py` and replaces them with a simple fatal message + re-raise:
```python
except Exception as e:
    self._view.write_fatal(f"Startup failed: {e}")
    raise
```

  obtained from `Lifecycle.start_http_subprocess()` returning

  `manager.iter_processes()` over `_http_procs`. Same object set. Every spawned
  subprocess is covered; removing repl.py's loop leaks nothing.
- **TEST GAP CLOSED (row added).** `tests/agent/test_repl.py::
  TestAgentREPLRunSubprocessTermination::test_run_terminates_subprocesses_on_failure`
