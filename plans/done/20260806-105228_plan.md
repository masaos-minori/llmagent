## 8. Risks & Mitigations
- **Risk**: A reviewer could judge one of the added justifications too generic/boilerplate, failing
  the spirit (if not the letter) of "Suppressions without explanation are prohibited."
  → **Mitigation**: Write each justification specific to *that* check's own failure semantics (as
  itemized in Step 6, Phase 2) rather than reusing one generic sentence across all five lines,
  matching how line 407's justification is specific to the RAG maintenance check.
- **Risk**: `BLE001`/`PLC0415` may not correspond to any rule ruff actually selects in this project
  (`pyproject.toml` selects only `E, W, F, I, UP` — see UNK-01), so these suppressions could already
  be functionally inert; adding justification text does not address that deeper inconsistency.
  → **Mitigation**: Out of scope for this narrow, comment-only requirement — filed as a separate
  non-blocking issue (see `issues/20260806-105228_risks.md`) for a future audit of whether the
  ruff `select` list should include `BLE`/`PLC0415`'s rule family, or whether these noqa comments
  should instead target codes the project's active linter actually raises.
- **Risk**: No automated test currently enforces the "every noqa has an em-dash justification"
  convention, so a future edit could silently reintroduce an unjustified suppression.
  → **Mitigation**: Out of scope to add such a test under this comment-only requirement; noted as
  a non-blocking follow-up risk in the filed issue rather than expanding this task's scope.
