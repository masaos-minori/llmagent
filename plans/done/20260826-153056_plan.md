## Reason for change
Tests, linting, and type checking protect behavior but do not fully verify module
ownership, dependency direction, lifecycle ownership, or structural migration
(quoted from the issue's `## Reason`). Today, `prompts/04_refactor.md`'s Step 4
(Behavior lock) and Step 7 (Validation) protect *behavior* — coverage, mutation
testing, public API stability, exception behavior, side effects — but record nothing
about the *structural* properties an architectural (Path C) change actually moves:
which module owns what, which direction dependencies point, where components are
registered or configured, and what a rollback would need to undo. Without a captured
"before" state, Step 7 cannot compare structure before and after a Path C
transformation, so a migration could complete with passing tests while silently
inverting a dependency direction, orphaning a registration entry, or leaving a
partially-migrated `deploy.sh`/config reference behind.
