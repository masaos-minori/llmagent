## 1. Goal

Make signal handler operations consistent across platforms and ensure shutdown state remains synchronized regardless of turn activity status. Prevent race conditions between signal handlers and main loop that could cause inconsistent shutdown behavior.

## 2. Scope

### In-Scope
- Modify `_sigterm_handler()` to check and clear `self._turn_active` flag before setting shutdown flags
- Document behavioral differences between Unix (`add_signal_handler`) and Windows (`call_soon_threadsafe`) signal handlers
- Add guard in `_close_resources()` that verifies `self._turn_active` is False before skipping service-dependent cleanup
- Use atomic operations where possible for shared state updates

### Out-of-Scope
- Changes to signal handling mechanism itself
- Database schema changes
- Changes to WAL checkpoint logic
- Changes to HTTP client lifecycle

## 3. Assumptions

- Signal handlers should always set shutdown flags regardless of turn activity status
- The `_turn_active` flag should be checked before setting shutdown flags to prevent double-shutdown scenarios
- Resource cleanup should complete even when services become unavailable during shutdown
- Atomic operations can be achieved using asyncio.Event instead of boolean flags for some shared state

## 8. Risks & Mitigations

- **Risk**: Deferred shutdown may delay shutdown by one turn, causing user-visible delay. → **Mitigation**: Keep deferred shutdown as opt-in only; document expected behavior for users.
- **Risk**: asyncio.Event usage may introduce complexity without solving actual problems (race conditions are unlikely in single-threaded asyncio). → **Mitigation**: Start with boolean flag fixes first; upgrade to asyncio.Event only if needed.
- **Risk**: Cross-platform testing limitations may miss platform-specific issues. → **Mitigation**: Document known differences; provide configuration option to adjust behavior per platform.
