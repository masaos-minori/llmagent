## Goal
- Bring the `/memory` slash command and the JSONL archive in session.sqlite in line with specification v1.0 (approved 2026-10-14): implement the subcommands `status`, `list`, `delete`, `pin`/`unpin`, `prune`, `reindex`, `rebuild`; record JSONL change events (`delete`, `pin`, `unpin`, and each pruned memory) that `rebuild` replays; enforce a pin limit; and make `rebuild` safe (dry run, `--allow-loss`, pre-run backup). After the change the code matches the behavior the approved docs already describe; `agent_11_04` (generated from code) is regenerated.

## Priority
Medium

## Scope
- **In-Scope**:
  - Add append-only JSONL change events for `delete`, `pin`, `unpin`, and each memory removed by `prune`, written after the SQLite write (SQLite-first ordering), with the M-07 warning when the append fails.
  - Replace the replay-less `import_from_jsonl()` with ordered replay that computes final state before touching SQLite.
  - Rework the `/memory` subcommand dispatch to the spec set and remove the subcommands the spec does not list.
  - Make `delete` remove `memory_links` rows for that memory in one transaction; make `prune` exclude pinned memories and be all-or-nothing (`STRICT`).
  - Add `memory_max_pinned` (default 10, at least 1, hot-reloadable) with validators, field registry, and `config/agent.toml`.
  - Implement `reindex [--fts|--vec]`, the `list` filters, the `rebuild` dry-run table 5.8-1, `--allow-loss`, and the pre-run backup of `memories`.
  - Emit the specified messages and audit records; resolve the Unresolved Questions against the code.
  - Update help text and registry consistency tests; add unit/integration tests; run the full validation suite with sandbox config.
  - Regenerate `agent_11_04`; verify the slash-command docs agree with the final subcommand set.
- **Out-of-Scope**:
  - Manual writing or editing of memories; automatic pruning by retention (MEM-09-2).
  - Changes to extraction, injection, and retrieval.
  - Recovery of deletes and pins made before change events existed.
  - Production deployment.

## Reason for change
Today a rebuild resurrects deleted memories and drops pins, and deletion paths lack confirmation and pin protection. The approved spec makes recovery faithful and destructive operations safe.

## Implementation intent
- Add change events to the JSONL archive: `{"event", "memory_id", "at"}` lines appended after the SQLite change; memory lines stay unchanged and are told apart by the absent `event` field.
- Teach JSONL reading and `import_from_jsonl()` the replay rules (6.3 of the spec): add/overwrite on memory line, remove on `delete` (re-added by a later memory line), `pinned` update on `pin`/`unpin` when the entry exists, skip and count unparsable lines.
- Rework the subcommands per the spec and remove those the spec does not list, after the open question below is answered. `delete` also removes `memory_links` rows for that memory in one transaction.
- Add `memory_max_pinned` (default 10, at least 1, hot-reloadable) with the config validators, field registry, and `config/agent.toml`.
- Implement `reindex [--fts|--vec]`, the `list` filters, `rebuild` dry-run table 5.8-1, `--allow-loss`, and the pre-run backup of `memories`.
- Emit the specified messages and audit records.

## Requirements
- `REQ-001`: JSONL records change events for `delete`, `pin`, `unpin`, and each memory removed by `prune`, appended after the SQLite write (SQLite-first ordering); existing memory lines are never rewritten; a failed append keeps the SQLite change and prints the M-07 warning. (`jsonl_store.py`, `write_ops.py`, `pin_ops.py`)
- `REQ-002`: `import_from_jsonl()` replays the archive in order to compute final state before touching SQLite: add/overwrite on a memory line, remove on `delete` (re-added by a later memory line), update `pinned` on `pin`/`unpin` when the entry exists, and skip-and-count unparsable lines. (`import_ops.py`, `jsonl_store.py`)
- `REQ-003`: `/memory` dispatches exactly `status`, `list`, `delete`, `pin`, `unpin`, `prune`, `reindex`, `rebuild`; subcommands other than `status` are removed; `/memory` without arguments runs `status`; with the memory layer disabled only `status` runs and others print M-02 without changing data. (`cmd_memory.py`)
- `REQ-004`: `delete` removes the memory's rows from all four memory tables (`memories`, `memories_fts`, `memories_vec`, `memory_links`) in one transaction and appends a `delete` event. (`write_ops.py`, `store_impl.py`)
- `REQ-005`: `prune` excludes pinned memories, is all-or-nothing (`MaintenanceMode.STRICT`), asks a `y/N` confirmation (a `N` changes nothing), honors `--days`, and appends a `delete` event for each memory it removes. (`store_impl.py`, `maintenance.py`, `memory_data_ops.py`)
- `REQ-006`: `memory_max_pinned` exists (default 10, at least 1, hot-reloadable) with a validator, a field-registry entry, and a `config/agent.toml` value; pinning at the limit is refused and prints M-05. (`config_dataclasses.py`, `config_builders.py`, `services/config_validators.py`, `services/config_field_registry.py`, `config/agent.toml`, `memory_data_ops.py`)
- `REQ-007`: `rebuild` is a dry run unless `--confirm` is passed and shows table 5.8-1; it backs up `memories` as JSONL before a confirmed run and aborts if the backup fails; a confirmed rebuild that would lose SQLite-only memories refuses unless `--allow-loss`; after a confirmed rebuild deleted memories stay deleted and pins are reproduced. (`memory_rebuild_ops.py`, `import_ops.py`)
- `REQ-008`: `reindex [--fts|--vec]` rebuilds only the requested index; `memories` and the JSONL archive are unchanged. (`memory_rebuild_ops.py`, `cmd_memory.py`)
- `REQ-009`: `list` emits short IDs; `delete`, `pin`, `unpin` accept a full `memory_id` or a short ID of at least 8 characters; an ambiguous ID prints M-04 and changes nothing, and an unknown ID prints M-03 and changes nothing. (`memory_data_ops.py`, `cmd_memory.py`)
- `REQ-010`: `command_defs_list.py` help lists the spec subcommand set and the registry consistency tests pass. (`command_defs_list.py`, tests)
- `REQ-011`: every data-changing operation (`delete`, `pin`, `unpin`, `prune`, `reindex`, `rebuild`) is written to the audit log. (`cmd_memory.py`, `memory_data_ops.py`, `memory_rebuild_ops.py`)
- `REQ-012`: unit tests per subcommand and per replay rule, an integration round-trip test (delete, pin, rebuild) over a temporary JSONL and SQLite, config-validation and hot-reload tests for `memory_max_pinned`, and the full validation suite (`ruff`, `mypy --no-namespace-packages scripts/`, `lint-imports`, `bandit`, `pytest` with sandbox config, `diff-cover`); regenerate `agent_11_04` and verify the slash-command docs agree. (`tests/`, `docs/23_agent/agent_11_04_memory-module-reference-generated.md`)

## Design
- **SQLite-first, append-only JSONL**: every data-changing op writes SQLite first, then appends a change event line `{"event": "delete"|"pin"|"unpin", "memory_id": ..., "at": <iso>}`. Existing memory lines are never rewritten. If the append fails, the SQLite change stands and the M-07 warning is emitted. Events are told apart from memory lines by the presence of the `event` field.
- **Ordered replay**: `import_from_jsonl()` reads the archive top-to-bottom and computes the final in-memory state (add/overwrite on memory line, remove on `delete`, `pinned` update on `pin`/`unpin` when the entry exists), skipping and counting unparsable lines, and only then applies that state to SQLite in one transaction. This makes `delete`/`pin`/`unpin` faithful after a rebuild.
- **One-transaction delete**: `write_ops.delete()` and `store_impl.delete_memories_before()` remove rows from `memories`, `memories_fts`, `memories_vec`, and `memory_links` in a single transaction so no orphaned `memory_links` remain.
- **Safe destructive ops**: `prune` excludes pinned memories, runs in `MaintenanceMode.STRICT` (all-or-nothing), and asks a `y/N` confirmation; `delete` asks `y/N` before removing.
- **Pin limit**: `MemoryConfig.memory_max_pinned` (default 10, ≥1) validated at load and hot-reloaded via `CONFIG_FIELD_REGISTRY`; the pin handler refuses at the limit with M-05.
- **Safe rebuild**: dry run unless `--confirm`; dry run reports table 5.8-1 (entries to import, pins after rebuild, SQLite-only entries, differing entries, entries needing a new embedding); a confirmed run backs up `memories` as JSONL first and aborts on failure; SQLite-only memories block `--confirm` unless `--allow-loss`.
- **reindex**: `reindex [--fts|--vec]` rebuilds only the requested index; `memories` and the JSONL archive are untouched.
- **Short IDs**: `list` emits short IDs; `delete`/`pin`/`unpin` accept a full `memory_id` or a ≥8-character prefix; ambiguous prefixes print M-04, unknown IDs print M-03, both change nothing.
- **Audit logging**: all data-changing ops write an audit record.
- **No compatibility shims**: removed subcommands are removed outright; `tools/check_compat_shims.py` patterns applied where the repository convention requires.
