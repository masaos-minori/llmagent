## Goal
- Remove the rule that the most recently reviewed or modified document is authoritative, and add a normative statement that recency never determines canonical authority (only staleness detection/investigation).

## Background
`docs/00_governance_04_documentation-checks.md` Manual Check 9 ("Canonical Source Verification") currently states, as its second numbered rule, that the most recently reviewed document is authoritative among conflicting documents.

## Problem
This recency rule can let a newer Reference, Note, or Guide override an Accepted ADR or canonical Specification solely because it was reviewed later — timestamp carries no ownership information, and this directly contradicts the target-based, claim-type resolution model `M-01-01`/`M-01-02` establish.

## Reason for change
A recency-based authority rule directly contradicts the target-based resolution model: a stale-but-canonical Specification would lose authority to a newer non-canonical Note purely because of its timestamp.

## Implementation intent
Add one normative sentence to `docs/00_governance_01_documentation-policy.md` stating recency never determines canonical authority, and remove the one identified recency-based authority statement in `docs/00_governance_04_documentation-checks.md`, replacing it with a reference to that sentence — not a second copy of it.

## Requirements
- `REQ-001`: Remove `docs/00_governance_04_documentation-checks.md` Manual Check 9 line 2 ("The most recently reviewed document is authoritative among conflicting documents") — the only recency-based authority statement found repository-wide.
- `REQ-002`: Add the required normative sentence (recency does not determine canonical authority; permitted only as staleness/investigation evidence) once, to `docs/00_governance_01_documentation-policy.md`.
- `REQ-003`: Document the four permitted uses of recency (staleness detection for non-canonical content, investigation prioritization, periodic-review scheduling, same-file revision identification) alongside the new normative sentence.
- `REQ-004`: Document the six prohibited uses of recency (overriding an Accepted ADR, a canonical Specification, an official API contract/schema, deployed configuration, an Operations runbook; promoting a Note/Reference to canonical status) alongside the new normative sentence.
- `REQ-005`: Replace the removed Manual Check 9 line 2 with a one-line reference to the new normative sentence in `docs/00_governance_01_documentation-policy.md`, so the rule exists in exactly one canonical location.
