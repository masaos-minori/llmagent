## Problem
Adversarial verification (Step 2) confirmed all 8 claimed locations match current
source, each using a qualifier with no accompanying measurable threshold or example:
- `skills/issue-to-plan/SKILL.md` line 106 ("small, reviewable increments") and
  `skills/issue-creator/SKILL.md` line 70 ("small, reviewable issues") — no numeric
  threshold; `issue-to-plan`'s own Path A/B classification (≤3 files) exists elsewhere
  in the same skill family.
- `skills/python-implementation/SKILL.md` line 37 ("smallest change") and
  `skills/python-implementation/workflow.md` line 163 ("log errors with sufficient
  context before re-raising") — neither has a stated criterion. The workflow.md
  location sits immediately after a worked example (lines 158-161: naming the function
  and invalid value in the raised error) that already operationalizes what "context"
  means for this specific rule — the qualifier is a summary of that adjacent example,
  not an independently undefined term.
- `rules/ai-execution.md` lines 132-133 ("genuinely uncertain," "granularity needed") —
  neither has an operational definition.
- `prompts/08_document-sync.md` line 212 ("Use concise, professional Markdown. Do not
  bloat the documents.") — no length or structural guideline for "bloat".
- `skills/python-code-review/SKILL.md` line 68 ("Respect project conventions and
  explain trade-offs") — "conventions" is not linked to `rules/coding.md`, where the
  actual conventions live.
- `skills/python-refactoring/SKILL.md` lines 104 and 115 ("Keep every change small,"
  "Reduce nesting, branching, and long functions") — "long" has no threshold, unlike
  this project's other numeric standards (e.g. `rules/toolchain.md`'s `radon cc ... -n
  C` complexity-grade check).

## Reason for change
A qualifier with no operational definition forces an AI agent to guess at compliance,
producing inconsistent behavior across sessions and making review harder — a human
reviewer also cannot check "was this small enough?" without a stated bar.

## Implementation intent
For each location, either state a concrete numeric/structural threshold (reusing an
existing one from elsewhere in this project's rules where a suitable one already
exists, e.g. `issue-to-plan`'s Path A ≤3-file rule, or `rules/toolchain.md`'s `radon cc
-n C` grade) or name the specific existing document/rule that already defines the term
precisely (e.g. link "conventions" to `rules/coding.md`), rather than inventing a new
threshold from scratch where an existing one can be reused.

plan/SKILL.md` Routing section) for "small, reviewable," and `rules/toolchain.md`'s

`workflow.md` location is resolved by cross-referencing its own immediately-preceding
