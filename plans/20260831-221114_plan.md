## Background
Per the governance-policy change that consolidated the governance documentation set from 11 area-specific documents into the current 4-document set, the Needs Confirmation Inventory was folded into Part 2 of `docs/00_governance_03_issue-and-uncertainty-management.md`. The tool's hardcoded reference to the old standalone file (`00_governance_07_needs-confirmation-inventory.md`) makes it non-functional.

## Problem
`tools/check_needs_confirmation_inventory.py` hardcodes `INVENTORY_DOC_NAME = "00_governance_07_needs-confirmation-inventory.md"` which does not exist. Running the tool fails immediately with `ERROR: 00_governance_07_needs-confirmation-inventory.md not found under docs/.`, so the Needs Confirmation inventory consistency check documented in `routing.md` and `docs/00_governance_04_documentation-checks.md` is not actually running.

## Reason for change
An automated consistency check that always fails before it can check anything provides no actual verification value and gives a false sense that NC-marker consistency is being enforced. Any documentation change involving Needs Confirmation markers currently gets no automated cross-check at all.

## Implementation intent
Update the tool to read the Needs Confirmation inventory from its current location (`docs/00_governance_03_issue-and-uncertainty-management.md`, "Part 2: Needs Confirmation Inventory" section). Since that file also contains Part 1 (Known Issues) and other sections, the tool's parsing logic must scope itself to the Part 2 section boundaries. Keep the tool's existing check semantics unchanged — only the source-location resolution needs to change.

## Design
The tool's architecture consists of four key components that need updates:

1. **Source path resolution** (`INVENTORY_DOC_NAME`): Change from `"00_governance_07_needs-confirmation-inventory.md"` to `"00_governance_03_issue-and-uncertainty-management.md"`.

2. **Entry parsing** (`_parse_inventory_entries()`): The current regex `_NC_ENTRY_RE = re.compile(r"^### (NC-\d+)\s*$")` matches 3-level headings. The new structure uses 4-level headings (`#### NC-XXX`). Update to `_NC_ENTRY_RE = re.compile(r"^#### (NC-\d+)\s*$")`.

3. **Section scoping**: Before parsing NC entries, skip lines until reaching `## Part 2: Needs Confirmation Inventory`. After Part 2 ends (next `##` heading or end of file), stop parsing. This prevents Part 1 Known Issue entries from being misinterpreted as NC entries.

4. **Status handling** (`check_stale_resolved_markers()`): The function checks `entry.status != "resolved"` but the new inventory uses `fixed` as the resolved status synonym. Update to `entry.status not in ("resolved", "fixed")`.

5. **Meta-doc exclusion** (`_GOVERNANCE_META_DOCS`): Replace the old filename `INVENTORY_DOC_NAME` with the new filename `"00_governance_03_issue-and-uncertainty-management.md"`.
