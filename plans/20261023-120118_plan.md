## Goal
- Make the rag-pipeline-mcp lifespan build its pipeline from the same configuration object that produced its security posture, leave no open resources when startup fails, and run `stop()` exactly once on shutdown.

## Priority
Low

## Scope
- **In-Scope**: An optional configuration parameter on `RagPipelineMCPService.start()` that the lifespan passes; cleanup of a partially started service; an idempotent `stop()`; a `try`/`finally` around the lifespan `yield`; tests for those behaviors.
- **Out-of-Scope**: The RAG pipeline logic, embedding and refiner settings; authentication, posture gate and logging changes (other issues); documentation (no documented behavior changes).

## Background
`rag_pipeline_server.py` loads `_cfg` and builds `_security_posture` at import time. Its `_lifespan` calls `RagPipelineMCPService.start()`, which calls `RagPipelineConfig.load()` again, creates an `httpx.AsyncClient`, then builds `RagPipeline` and `DocumentManager`. `stop()` closes only the HTTP client. The service is initialized only in the lifespan, and requests are served after it completes.

## Problem
A probe with `RagPipeline` replaced by a function that raises showed the lifespan raising the error, one extra `RagPipelineConfig.load()` inside `start()`, and the `httpx.AsyncClient` left open. The posture and tool availability therefore describe the import-time read while the pipeline uses a later read, `stop()` is not guaranteed to run because the lifespan has no `try`/`finally`, and a second `start()` would overwrite a still-open client. A failed lifespan ends the process, so the leak is short-lived; the lifecycle contract is still not enforced.

## Reason for Change
Startup behavior must be deterministic with clean failure paths, and the posture the Agent reads must describe the configuration that is actually running.

## Implementation Intent
Let the lifespan hand the already loaded configuration to `start()` while keeping `start()` callable with no argument (existing tests rely on it loading its own configuration). Make `start()` all-or-nothing by closing the client on any failure, and make `stop()` safe to call repeatedly and on a partially built service.

## Requirements
- `REQ-001`: `RagPipelineMCPService.start()` accepts an optional `RagPipelineConfig`; when given it is used and no second `RagPipelineConfig.load()` happens; when omitted it loads its own, as today. The lifespan passes the module's `_cfg`.
- `REQ-002`: If any step of `start()` fails after the HTTP client is created, the client is closed and the stored client reference is cleared before the error propagates.
- `REQ-003`: `stop()` is safe to call more than once and on a service whose `start()` failed or never ran, tolerates missing attributes, and clears the references it closes.
- `REQ-004`: The lifespan wraps the `yield` in `try`/`finally` so `stop()` runs once on shutdown.
- `REQ-005`: Tests prove REQ-001 to REQ-004 and the existing service and lifespan tests still pass.

## Design
Path A (three files, no public interface change: `start()` gains an optional parameter that defaults to the current behavior, no schema change). Direct verification: `rag_pipeline_service.py` imports `DocumentManager`, the models, `mcp_servers.server.ToolArgs`, `shared.llm_client` and `httpx`; it is imported by `rag_pipeline_server.py`, `rag_pipeline_models.py` and tests, so the change stays inside the package. `start(cfg: RagPipelineConfig | None = None)` uses `cfg if cfg is not None else RagPipelineConfig.load()`; the client is created, then the remaining construction runs inside `try`/`except BaseException` that closes the client, clears the reference and re-raises. `stop()` reads `_http` defensively, closes it once, and sets the references to `None`. `_lifespan` passes `_cfg` and uses `try: yield finally: await svc.stop()`. Validation baseline (recorded): `radon cc` reports every method of the service at rank A; `bandit` reports no finding for the two source files; `ruff` and `mypy` pass for the package.
