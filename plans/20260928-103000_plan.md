# Plan: Reduce cross-class private coupling in factory.py lifecycle classes

- **Issue**: `issues/20260927-205833_fac001_reduce-cross-class-private-coupling-in-factory.py-lifecycle-classes.md`
- **Priority**: Medium
- **Classification**: Path A (single file, no public/runtime interface change, no DB schema change)
- **Author**: (agent)
- **Created**: 2026-09-28
- **Status**: Draft awaiting approval

---

## Goal

Reduce the number of places where `_ServerLifecycleRouter` reaches into
`_SubprocessLifecycleManager._http_mgr` (the `HttpServerLifecycleManager`) by
delegating through `_SubprocessLifecycleManager`'s existing public methods,
where doing so is behaviour-preserving. Leave the remaining accesses with an
in-code note explaining why they cannot be delegated without a behaviour change
or a new public API.

## Non-goal

- Do not collapse the two lifecycle classes.
- Do not add or remove any public API method (on either class or the protocol).
- Do not change lifecycle-state transitions, cooldown windows, or the shutdown
  guard.
- Do not touch anything outside `scripts/agent/factory.py`.

---

## Scope

**In scope**

- `scripts/agent/factory.py` only.
- Route delegatable `_http_mgr` accesses through `_SubprocessLifecycleManager`
  public methods.
- Add one-line in-code notes at the accesses that cannot be delegated.

**Out of scope**

- Any change to `agent/http_lifecycle.py`, `agent/lifecycle_protocol.py`,
  `agent/services/models.py`, or callers.
- New public methods on `_SubprocessLifecycleManager` or `LifecycleManagerProtocol`.

---

## Requirements

### Constraints (hard)

1. **Behaviour-preserving.** No change to lifecycle-state machine, cooldown
   (`_COOLDOWN_SECONDS`), shutdown-guard (`_shutting_down`), or error handling.
2. **No public API added or removed.** Only reuse existing public methods.
3. **Both classes remain distinct.** No merging of `_ServerLifecycleRouter` and
   `_SubprocessLifecycleManager`.
4. **Minimal diff.** Only the targeted call sites change; surrounding logic is
   untouched.

### Behavioural lock (evidence)

The following existing tests pin the behaviour that must survive:

- `test_subprocess_http_dead_attempts_restart` (`test_lifecycle.py:156`) replaces
  `mgr._subprocess_mgr._http_mgr` with an `AsyncMock` and asserts
  `.start` is awaited during `ensure_ready`. => `ensure_ready` must keep calling
  `_http_mgr.start(...)` directly; it cannot delegate to
  `_SubprocessLifecycleManager.ensure_ready()` (that path drops the router's
  state-machine wrapper and would not invoke `.start` on the injected mock).
- `TestShutdownAll.*` (`test_lifecycle.py:560`) assert `shutdown_all()` terminates
  running procs, skips dead ones, and tolerates terminate/stop errors.
- `TestStartHttpSubprocess.*` (`test_lifecycle.py:169`) assert the returned Popen
  equals `_http_procs[key]` after start.
- `TestHttpManagerRestart.test_restart_pgid_still_present_during_terminate`
  (`test_lifecycle.py:526`) pins `HttpServerLifecycleManager.restart()` pgid
  handling — unaffected by the router refactor.

## Detailed changes

`_ServerLifecycleRouter` currently accesses the target at 12 sites. Mapping:

| # | Line | Access | Action | Reason |
| --- | --- | --- | --- | --- |
| 1 | 268 | `verify_running` (ensure_ready) | Keep w/ note | No public equivalent; part of router's custom control flow. |
| 2 | 275 | `start` (ensure_ready) | Keep w/ note | Delegating to manager `ensure_ready` drops the state-machine wrapper and breaks `test_subprocess_http_dead_attempts_restart`. |
| 3 | 278 | `verify_running_async` (ensure_ready) | Keep w/ note | No public equivalent; part of router's custom control flow. |
| 4 | 287 | `restart` (ensure_ready) | Keep w/ note | Part of router's custom ensure_ready flow (state machine + inline cfg). |
| 5 | 293 | `shutdown_all` | **Delegate** → `self._subprocess_mgr.shutdown_all()` | Exact public equivalent; behaviour identical. |
| 6 | 314 | `start` (start_http_subprocess) | **Delegate** → `self._subprocess_mgr.start_http_subprocess(...)` | Exact public equivalent incl. `shutdown_event`; returns same Popen. |
| 7 | 318 | `_http_procs.get` (return) | Keep w/ note | Manager's `start_http_subprocess` return value is discarded inside `_run_lifecycle_transition`; re-fetch is simplest safe option. |
| 8 | 337 | `restart` (router.restart) | **Delegate** → `self._subprocess_mgr.restart(server_key)` | Same dict lookup; cooldown/shutdown guards already checked before the transition. |
| 9 | 352 | `get_process_snapshot` | **Delegate** → `self._subprocess_mgr.get_process_snapshot(...)` | Exact public equivalent. |
| 10 | 360 | `get_process_info` | Keep w/ note | Router-only extra; not in `LifecycleManagerProtocol`. |
| 11 | 367 | `list_processes` | Keep w/ note | Router-only extra; not in `LifecycleManagerProtocol`. |
| 12 | 382 | `_cleanup_server_resources` | **Delegate** → `self._subprocess_mgr.cleanup_server_resources(...)` | Exact public equivalent. |

Net result: **5 delegations, 7 documented keeps** (down from 12 direct
`_http_mgr` accesses on the router to 7).

### Edit 5 — `shutdown_all` (line 293)

```python
        await self._subprocess_mgr._http_mgr.shutdown_all()
```
→
```python
        await self._subprocess_mgr.shutdown_all()
```

### Edit 6 — `start_http_subprocess` op (lines 314-316)

```python
            lambda: self._subprocess_mgr._http_mgr.start(
                server_key, cfg, shutdown_event=shutdown_event
            ),
```
→
```python
            lambda: self._subprocess_mgr.start_http_subprocess(
                server_key, cfg, shutdown_event=shutdown_event
            ),
```

(`return self._subprocess_mgr._http_mgr._http_procs.get(server_key)` at line 318
is left unchanged.)

### Edit 8 — `restart` op (line 337)

```python
            lambda: self._subprocess_mgr._http_mgr.restart(server_key, cfg)
```
→
```python
            lambda: self._subprocess_mgr.restart(server_key)
```

Note: `_SubprocessLifecycleManager.restart(server_key)` looks up `cfg` from its
own `_server_configs` reference. This is the same dict object passed to the
router in `_build_tool_executor`, so the lookup resolves identically. The
"not a subprocess-mode server" warning is emitted once by `router.restart`
before reaching this point, so no duplicate warning occurs.
