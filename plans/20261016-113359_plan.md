## Goal
- Make `SessionMessageRepository.fetch_messages()` work against a real `SQLiteHelper` for an existing session by removing its out-of-range column read and running the messages query while the connection is open, and lock the second defect with a test that does not mask it.

## Priority
High

## Scope
- **In-Scope**: delete the unused `session_rows[0][1]` read; move the messages query inside the `with SQLiteHelper(...)` block; add a regression test that uses a helper which really closes its connection on exit.
- **Out-of-Scope**: the pinned-memory change and mem001; redesign of the `/undo` compression floor; other `SessionMessageRepository` methods unless found defective in the same pattern; changing the `fetch_messages()` signature or return contract; the `sessions` schema; production deployment.

## Background
Found on 2026-10-16 while running the full suite for the pinned-memory change: 57 tests fail with the same `IndexError` with and without that change. The `IndexError` comes from commit `646d97916`, whose diff for `scripts/agent/session_message_repo.py` is one added line. Adversarial verification of the source issue (`issues/20261016-110710_sess001_fix-fetch_messages-indexerror-on-undo-floor-column.md`) showed that deleting that line makes all 113 tests in the four affected modules pass, and that a second defect, dating from `c9d564322` (2026-08-17), is hidden by the tests' fake helper: the messages query runs after the `with` block has closed the connection.

## Problem
- `fetch_messages()` selects one column (`undo_floor_message_id`) from `sessions`, reads index 0 into `undo_floor`, then reads `session_rows[0][1]` (line 215) into `undo_floor_message_id`, which is never used. Index 1 does not exist, so every call for an existing session raises `IndexError`; 57 tests fail (29 in `tests/agent/test_session_message_repo.py`, 18 in `tests/agent/test_agent_session.py`, 6 in `tests/agent/test_history_compression_consistency.py`, 4 in `tests/agent/test_regression_undo_artifact.py`).
- `SQLiteHelper.__exit__` closes the connection and resets it to `None`; `fetch_messages()` runs `rows = db.fetchall(...)` for messages after the `with` block, so with the real helper `fetchall()` raises `RuntimeError: DB not open — call open() first` (shown with a script on a temporary DB, not by running `fetch_messages()` against a real session DB).
- The tests patch `SQLiteHelper` with `_FakeSQLiteHelper` (`tests/agent/test_session_message_repo.py`), whose `__exit__` and `close()` do nothing, so they cannot detect the second defect.
- `restore_session()` in `scripts/agent/services/session_restore.py` calls `fetch_messages()` without handling these exceptions; the user-facing effect through `cmd_session.py` was not run.

## Reason for change
Restoring an existing session is expected to fail at runtime, which is a correctness failure in a core path. 57 red tests also hide other regressions, and the fake-helper tests would keep passing while the real path stays broken.

## Implementation intent
- Remove the leftover duplicate read so the undo floor has one source (`undo_floor`).
- Keep both queries inside one `with` block so the connection is open for the messages query; do not touch the parsing loop, the return contract, or any other method.
- Add one test with a helper whose `__exit__` closes the connection and whose `fetchall()` fails when closed, so the second defect cannot pass unnoticed again; keep the existing fake for all other tests.

## Requirements
- `REQ-001`: `fetch_messages()` no longer raises `IndexError` for an existing session (remove the unused out-of-range read).
- `REQ-002`: `fetch_messages()` runs its messages query while the DB connection is open, returning `(messages, True, undo_floor)` for an existing session with a real `SQLiteHelper`.
- `REQ-003`: A regression test using a closing helper fails before REQ-002 is applied and passes after.

## Design
Path A (2 files, no interface or schema change). In `fetch_messages()`, keep the session-rows query and the messages query inside one `with SQLiteHelper("session").open(row_factory=True) as db:` block, drop the unused `undo_floor_message_id` assignment, and keep the early returns (`([], False, 0)`, `([], True, 0)`) and the parsing loop and final `return (messages, True, undo_floor)` as they are.
