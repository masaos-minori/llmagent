# Area Canonical Maps — Status 値の不統一

## Goal

Resolve the Status value inconsistency in the Area Canonical Maps table of `governance_01_documentation-policy.md`: Governance Primary entries show `Active` while Overview/Deployment/RAG/MCP/Agent/EventBus/Shared/DB Primary entries show `(Needs Confirmation — path does not exist in repository)`.

## Priority
Low

## Scope
- **In-Scope**: Investigating and resolving the Status value difference between Governance Primary and other areas' Primary entries in the Area Canonical Maps table
- **Out-of-Scope**: Changing the Area Canonical Maps structure; modifying any governance rules beyond the Status values

## Background
The Area Canonical Maps table defines the relationship between documents and authority for each area. Most areas' Primary entries show `(Needs Confirmation — path does not exist in repository)` because those paths do not exist in the repository. However, Governance Primary entries show `Active`. The reason for this Status difference is not explained.

Note: Overview Primary also shows `Active` (for `docs/00_index.md`), which is correct since that file exists. The issue is specifically about why Governance Primary entries are `Active` while Deployment/RAG/MCP/Agent/EventBus/Shared/DB Primary entries are `(Needs Confirmation — path does not exist in repository)`.

## Problem
Without explanation for the Status difference, implementers may be confused about whether the difference is intentional or an inconsistency. Additionally, it is unclear why other areas' Primary entries are marked as Needs Confirmation.

## Reason for change
The Status difference needs clarification: either explain why it is intentional, or reconcile the Status values.

## Implementation intent
Investigate and resolve the Status inconsistency by one of the following approaches:
1. If the Status difference is intentional, document the reason within the Area Canonical Maps section
2. If the Status difference is an inconsistency, update the Status values to be consistent
3. Clarify the reason for Needs Confirmation status where applicable

## Requirements
- REQ-001: Determine whether the Status difference between Governance Primary and other areas' Primary entries is intentional or an inconsistency
- REQ-002: If intentional, add an explanation in the Area Canonical Maps section
- REQ-003: If inconsistent, update the Status values to be consistent across all areas
- REQ-004: Do not alter the Area Canonical Maps structure
- REQ-005: Keep changes isolated to `governance_01_documentation-policy.md`
