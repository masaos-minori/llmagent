## Goal
- Make `tests/docs/test_github_config_consistency.py::TestGitHubConfigConsistency::test_github_tools_in_tools_definitions` agree with the deliberate configuration in which the GitHub MCP server is disabled (`startup_mode = "none"`) and has no `[[tool_definitions]]` entries, while still requiring all 21 definitions whenever the server is enabled, so the suite and CI are green without hiding a real inconsistency.

## Priority
Medium

## Scope
- **In-Scope**:
  - Rewrite the one failing test so its expectation follows the server's `startup_mode`: all 21 registry tools must be defined when the server is enabled, and none may be defined when it is disabled.
  - Move the decision into a small pure helper that returns the problems found, and add parametrized tests of that helper for the enabled and disabled cases, so the enabled rule stays verified while the real config is disabled.
  - Read `config/agent.toml` with `tomllib` in the changed test instead of scanning lines.
- **Out-of-Scope**:
  - Changing `config/agent.toml`, restoring the 573 deleted lines, re-enabling the GitHub server, or provisioning `GITHUB_TOKEN`.
  - The other tests in the file (they compare the registry and `TOOL_LIST` with `[mcp_servers.github].tool_names`, which was kept, and pass).
  - Documentation (no document describes a GitHub re-enable procedure, and none states that GitHub tool definitions must be present in `agent.toml`).
  - The flaky mdq test (filed separately as testfix002).

## Background
- Found on 2026-10-19 as the single remaining failure of the full suite (9432 passed, 1 failed); it fails on the unchanged tree and keeps CI red (`uv run pytest -v` in `.github/workflows/ci.yml`).
- Commit `4e2442a75` (2026-10-18, "fix: disable the github MCP server until GITHUB_TOKEN is provisioned") changed `config/agent.toml` by 2 insertions and 573 deletions: `[mcp_servers.github]` now has `startup_mode = "none"` and `required = false`, and every GitHub `[[tool_definitions]]` block was removed; `tool_names` (21 names) remains.
- `docs/22_mcp/mcp_03_04_tool-call-tracing-and-lifecycle.md` describes `startup_mode="none"` as a disabled server: no subprocess spawn, no health check, and calls rejected immediately.

## Problem
- The test asserts that each of the 21 GitHub tools registered in `shared.tool_registry` appears on a line of `config/agent.toml` that contains both `"github_` and `name`. After the commit above no `[[tool_definitions]]` entry for a GitHub tool exists, so all 21 are reported missing.
- Confirmed by source inspection (2026-10-19) with `tomllib`: `[mcp_servers.github]` has `startup_mode = "none"` and `required = false`; `tool_definitions` holds 42 entries of which none is a GitHub tool; every other MCP server uses `startup_mode = "subprocess"`.
- The rule "all 21 definitions exist" is only true while the server is enabled; the configuration change was deliberate, so the test is stale, not the configuration.

## Reason for Change
- A permanently failing test hides new failures and blocks a green CI run.
- Keeping a consistency check for both states preserves its value: re-enabling the server without restoring the definitions, or removing definitions while it is enabled, will fail it.

## Implementation Intent
- Add a pure helper `_github_definition_problems(cfg, registry_tools)` (new) that takes the parsed configuration and the registry's GitHub tool names and returns a list of problems: enabled server with missing definitions, or disabled server with any GitHub definition present.
- The failing test loads the real `config/agent.toml` with `tomllib`, asks the registry for the GitHub tools, and asserts the helper returns no problems.
- Add parametrized tests that feed the helper small synthetic configurations (enabled with all definitions, enabled with some missing, disabled with none, disabled with some present), so the enabled rule is verified without editing the real configuration.
- Keep the existing assertion that the registry holds 21 GitHub tools.

## Requirements

- `REQ-002`: The decision is made by a pure helper, and parametrized tests cover the enabled and disabled cases with synthetic configurations.
- `REQ-003`: The other tests in the file keep their behavior and still pass.
