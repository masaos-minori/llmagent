## Background
Commit `35a1e1969` ("refactor: extract orchestrator into dedicated component modules")
renamed the attribute assigned in `Orchestrator.__init__` (`scripts/agent/orchestrator.py`)
from `self._llm_turn_executor` to `self._llm_executor`, and updated the one internal call
site accordingly. Confirmed by repository evidence: `scripts/agent/orchestrator.py` lines
155, 186, and 286 all use `_llm_executor`; no `_llm_turn_executor` reference remains in
`scripts/`. `LlmTurnExecutor.__init__` (`scripts/agent/llm_turn_executor.py:35-41`) already
accepts `diagnostic_store` as a constructor parameter, confirming the issue's claim that a
post-construction reassignment onto the executor is redundant.

## Problem
`rg -n "_llm_turn_executor" tests/ scripts/` confirms exactly 7 remaining references, all in
tests, none in production code:
- `tests/agent/test_orchestrator.py`: lines 126, 765, 800, 831 — all of the form
  `orch._llm_turn_executor._diagnostic_store = orch._diagnostic_store`. Line 126 is inside
  the shared `_make_orchestrator()` helper, which is called 71 times across the file's 17
  test classes — this single line is why one stale attribute name cascades into 78 failures.
- `tests/integration/test_orchestrator_integration.py`: lines 109, 408, 430 — same pattern.

Confirmed by direct test execution: `uv run pytest tests/agent/test_orchestrator.py -q`
currently reports 78 failed, 9 passed; `uv run pytest
tests/integration/test_orchestrator_integration.py -q` currently reports 33 failed, 6
passed. All 78 failures in the first file, and 32 of the 33 failures in the second file,
raise `AttributeError: 'Orchestrator' object has no attribute '_llm_turn_executor'`. The
integration file's remaining 1 failure
(`test_handle_turn_history_compression_persists_when_needed`) constructs `Orchestrator`
directly (not through the shared helper) and is unaffected by this rename — confirmed as a
distinct, separately-tracked defect (`orch003`).

## Reason for change
78 failing tests in `tests/agent/test_orchestrator.py`, plus 32 in
`test_orchestrator_integration.py`, block confident verification of `Orchestrator`
behavior — a core Agent component — and mask any genuine regression a future change might
introduce in this area, since the current failure list already looks total.

## Implementation intent
Apply the rename mechanically at each of the 7 confirmed occurrences. For the
`orch._llm_turn_executor._diagnostic_store = orch._diagnostic_store` line specifically (all
7 occurrences follow this exact pattern), delete the line entirely rather than renaming its
left-hand side — `LlmTurnExecutor`'s constructor already receives `diagnostic_store`
directly (`scripts/agent/llm_turn_executor.py:39`), so the reassignment has no effect beyond
restating what the constructor already set. No production file is touched.
