## Goal
Restore RAG embedding functionality by resolving the unreachable embed-llm connection error during startup.

## Priority
Low

## Scope
- **In-Scope**: Updating the `embed_url` configuration to point to a reachable embedding service, or enabling local embedding mode
- **Out-of-Scope**: Adding new embedding services; modifying the embedding client implementation; changing the RAG pipeline architecture

## Background
The agent connects to an external embedding service at the URL configured in `agent.toml`. The current URL is `http://192.168.11.238:8081` (no path component). The health check derives the probe URL by stripping the path from `embed_url` and appending `/health`, resulting in `http://192.168.11.238:8081/health`. The actual embedding endpoint path is `/embedding` (per `shared/llm_client.py:EMBEDDING_PATH`).

## Problem
Startup output includes:
```
[non-fatal] embed-llm unreachable at http://192.168.11.238:8081/health: All connection attempts failed
```

Note: The health check probes `http://192.168.11.238:8081/health` (derived by stripping the path from `embed_url` and appending `/health`). The actual embedding endpoint path is `/embedding` (per `shared/llm_client.py:EMBEDDING_PATH`). Whether the service has a `/health` endpoint is unknown.

## Reason for change
Without a reachable embedding endpoint, RAG features (semantic search, memory retrieval) are disabled. This affects the agent's ability to use context from previous sessions. Two approaches are possible:
1. Update `embed_url` to point to a reachable external embedding service
2. Enable local embedding (if available) — see `scripts/agent/memory/embedding_client.py:116-120` for `local_only` logic

## Implementation intent
Update the `embed_url` configuration to point to a reachable embedding service, or enable local embedding mode via the `memory_local_only` flag. The preferred approach depends on whether a local embedding service is available.

- `REQ-001`: The embed-llm health check must succeed during startup (no "embed-llm unreachable" warning).
- `REQ-002`: RAG embedding functionality must work (semantic search and memory retrieval operate correctly).
- `REQ-003`: Other RAG configuration settings must remain unchanged.

## Design
**Preferred approach: Option A — Update `embed_url` to a reachable external embedding service.**

Rationale: Updating the `embed_url` configuration is the minimal change that directly resolves the reported problem. It preserves the existing architecture and does not require changes to the embedding client implementation.

**Option B (enable local embedding)** is viable if a local embedding service is available. The `local_only` flag in `EmbeddingClientConfig` (line 39 of `embedding_client.py`) rejects non-local embed URLs when set to `True`, so enabling local embedding would require both setting `memory_local_only = True` in the config and ensuring a local embedding service is running.

### Implementation details
- In `config/agent.toml`, update the `embed_url` value to point to a reachable embedding service:
  ```toml
  embed_url = "http://<reachable-host>:<port>"
  ```
- Alternatively, if a local embedding service is available:
  ```toml
  embed_url = "http://localhost:<port>"
  memory_local_only = true
  ```
