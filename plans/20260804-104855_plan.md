## Design

No architectural change. This is a mechanical characterization-test repair: point the test file at
the actual `ConfigReloadService.apply_config_dict()` API instead of the non-existent
`apply_config_changes()` free function, and give the mock context the minimum shape
`apply_config_dict()` needs to run without raising.

- **API surface used:** `ConfigReloadService(ctx).apply_config_dict(new_cfg)` — constructed fresh
  per call (matching the constructor contract `__init__(self, ctx: AgentContext) -> None` at
  `config_reload.py:95-97`, which just stores `self._ctx = ctx`; no state to share across the 4
  tests, so no fixture/class-scoped instance is needed — each test can do
  `ConfigReloadService(ctx).apply_config_dict(new_cfg)` inline, mirroring how `new_cfg` is already
  built fresh per test).
- **Mock context shape:** `_make_ctx()` keeps building the real `AgentConfig(**merged)` exactly as
  today (Assumption 1's default dict and `**overrides` merge logic are unchanged — only the final
  `ctx = type(...)` line changes), then wraps it in a `MagicMock()` with `ctx.cfg` explicitly set to
  that real object and `ctx.services_required.llm = None`, `.hist_mgr = None`, `.tools = None`,
  `.runtime_tools = None` explicitly set (per Assumption 3). This is the minimum needed for
  `_sync_services()`'s four `is not None` checks to short-circuit to "skip" for every attribute,
  matching the "characterize the fallback-only path" intent of the test file — these tests are not
  meant to exercise live service syncing, only the `security_profile` reload's own
  invalid/empty/numeric/valid-value fallback branch (`config_reload.py:456-462`).
- **Call-site + marker changes:** mechanical only — swap `await apply_config_changes(ctx, new_cfg)`
  for `ConfigReloadService(ctx).apply_config_dict(new_cfg)`, drop `@pytest.mark.asyncio`, drop
  `async` from each `def`. The security-profile assertions themselves (reading
  `ctx.cfg.mcp.security_profile`) are untouched, since `_reload_approval_settings()` mutates
  `ctx.cfg.mcp.security_profile` in place on the same real `AgentConfig` object the test already
  holds a reference to via `original_value = ctx.cfg.mcp.security_profile`.

## Risks

- **R1 — Stubbing only 4 of the `services_required` attributes (`llm`, `hist_mgr`, `tools`,
  `runtime_tools`) leaves `MagicMock()`'s auto-generated attributes for anything else
  (`ctx.services_required.lifecycle`, `ctx.services_required.memory`, etc.) as truthy `MagicMock`
  objects rather than `None` or realistic stand-ins.** For these 4 specific tests this is safe
  (Assumption 2: `.lifecycle` is never reached because `needs_restart` is empty for
  `new_cfg = {"security_profile": ...}`), but the risk is latent: if a future test reuses this same
  `_make_ctx()` helper with a `new_cfg` that *does* include `mcp_servers` changes, the auto-generated
  `MagicMock` for `.lifecycle` would be treated as non-`None` and
  `getattr(lifecycle, "_cleanup_server_resources")(server_key)` would be called against a `MagicMock`
  — silently "succeeding" without exercising real cleanup logic, potentially masking a bug.
  Likelihood: Low (no such test exists today; only realized if this helper is extended later).
  Mitigation: Implementation step 1 stubs exactly the 4 attributes needed for the current test
  matrix — see Implementation step 1's checkpoint. No production-code or current-test change is
  needed. Because this only matters for *hypothetical future* test additions and doesn't affect the
  behavior or correctness of the 4 tests in scope, this is documented here as an in-plan mitigation
  guideline (do not extend `_make_ctx()`'s mcp-server-changing test cases without also stubbing
  `.lifecycle`) rather than filed as a separate issue.
- **R2 — Partial/inconsistent mechanical edit** (e.g. missing one of the 4 `apply_config_changes`
  call sites, or leaving one `@pytest.mark.asyncio` in place while removing `async def`, which would
  raise a `pytest-asyncio` collection warning/error for a non-async test). Likelihood: Low.
  Mitigation: run `grep -n "apply_config_changes\|pytest.mark.asyncio\|async def" tests/agent/services/test_config_reload_security_profile.py`
  after step 2 and confirm zero remaining hits for the first two patterns and zero `async def`
  remaining in this file.
- **R3 — `MagicMock()`'s auto-vivified attribute access could mask a real `AttributeError`** that
  would otherwise reveal a mismatch between the test's assumed `ConfigReloadService` internals and
  its actual internals (e.g., if a future refactor renames `_sync_services` reads from
  `ctx.services_required.llm` to something else, the test would still "pass" silently instead of
  failing loudly, because `MagicMock` invents any attribute on access). Likelihood: Low for this
  specific fix (attributes are explicitly stubbed to `None`, and `None` behaves identically whether
  the underlying object is a real context or a mock). Mitigation: none needed beyond what
  Implementation step 1 already does — the explicit `= None` assignments make the four checked
  attributes behave identically to a real context missing those services, so this risk does not
  materialize for the current test matrix; not filed as a separate issue.
