## Goal
- Make the four EventBus subscribe-transition tests that time out finish quickly and deterministically, by giving their client a short SSE idle timeout, so the EventBus suite can run without deselecting that module.

## Priority
Medium

## Scope
- **In-Scope**: an optional idle-timeout argument on the shared EventBus test client helper (default behavior unchanged) and its use in the transition test module's client fixture.
- **Out-of-Scope**: production subscribe code; changing the default idle timeout for other test modules (see UNK-02); the replay logic; the heartbeat settings of production.

## Background
The EventBus suite had to be run with the transition module deselected because four of its tests time out. The Issue suspected an SSE stream that never ends, a missing idle-timeout setting, or a stale scenario.

## Problem
- The cause is confirmed by experiment: the tests read `/subscribe` responses until the server ends the stream, and the server ends an idle stream only after `sse_idle_timeout`, which defaults to 60 seconds; the module's client fixture never shortens it, so each blocking read waits a full minute and exceeds the 40 to 60 second test timeouts.
- Probe: with the idle timeout set to 1 second on the configuration object the shared helper builds (done from an out-of-repository pytest plugin, without changing the repository), all nine tests of the module pass in about 15 seconds, including the four that fail today. No production defect is involved, and the earlier replay fix is not the cause.
- The configuration validates that the idle timeout is at least one second and greater than the heartbeat interval, so the timeout cannot be shortened through the constructor with the default heartbeat; other test modules shorten it by assigning the attribute after construction.

## Reason for change
A suite that always contains known failing tests cannot gate changes, and the 60-second waits make the EventBus suite slow.

## Implementation intent
- Add an optional argument to the shared helper that, when given, sets the idle timeout on the configuration object after construction (the pattern other modules already use); leave behavior unchanged when it is omitted.
- Use a short value in the transition module's client fixture. Do not change assertions or add sleeps.

## Requirements
- `REQ-001`: The shared EventBus test client helper accepts an optional idle-timeout argument and applies it to the configuration used by the app; calling it without the argument behaves exactly as before.
- `REQ-002`: The transition module's client fixture passes a short idle timeout (1 second), so its tests no longer wait for the 60-second default.
- `REQ-003`: All tests of the transition module pass, each of the four formerly timing-out tests finishes in well under 10 seconds, and the whole EventBus suite and the full suite pass with no deselection of the module.
