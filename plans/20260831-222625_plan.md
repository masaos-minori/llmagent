## Background
Discovered incidentally while running `uv run python tools/check_docs_consistency.py --domain overview` to validate an unrelated governance-policy documentation change. This finding is unrelated to that change.

## Problem
`tools/check_docs_consistency.py --domain overview` reports: `reference to removed/nonexistent doc file '01_overview-arch.md'` and `reference to removed/nonexistent doc file '01_overview-files.md'`, both at `01_overview.md`. `docs/00_index.md`'s own Document References by Task table describes the actual structure as `01_overview.md` indexing `01_overview-arch-*.md` and `01_overview-files-*.md` (i.e., multiple suffixed files per prefix), so the two references in `01_overview.md` are pointing at a singular filename that was likely split into multiple files at some point without updating this reference.

## Reason for change
A standing, automatically-detected broken link in the system-overview document — the first document new readers are directed to per `docs/00_index.md`'s Recommended Reading Order — degrades navigation and leaves the documentation consistency checker permanently reporting an error that will mask genuinely new link breakages introduced by future changes.

## Implementation intent
Update the two references in `01_overview.md` to either link to the actual current index entry point for each split (if one exists) or to the correct set of suffixed files, matching whatever pattern `docs/00_index.md` and the actual files under `docs/` currently use.

## Requirements
- `REQ-001`: No broken links remain in `docs/01_overview.md` for the `-arch-*` or `-files-*` prefixes
- `REQ-002`: All corrected links resolve to files that actually exist under `docs/`
- `REQ-003`: The link pattern matches how equivalent links are handled elsewhere in the document
