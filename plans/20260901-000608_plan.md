## Background
ADR-004 was revised to adopt a single common failure-handling policy across all environments. The revision removed environment-specific distinctions (Decision #1, #3) and introduced Decision #12 for undefined component criticality. However, some invariant entries in `adr-index.md` still contain pre-revision terminology ("Fail-Fast/Fail-Closed", "required/non-required branch") and may have inaccurate verification statuses.

## Problem
Several invariant entries in `adr-index.md` reference pre-revision ADR-004 concepts that no longer apply:
- INV-011 uses "Fail-Fast at startup / Fail-Closed at execution" and "required/non-required branch" — these terms conflict with the unified policy approach adopted in the revision.
- INV-019 and INV-020 are marked "Not verified" — their statuses need confirmation against current code.
- INV-021 references "undefined component criticality" — should reference Decision #12 instead.
- INV-022 is marked "Confirmed" — needs re-verification.

Additionally, the ADR List entry for ADR-004 has already been updated (title changed to "環境における障害処理方針", status changed to "Accepted"), so those parts of the original issue are no longer valid.

## Reason for change
The ADR-004 revision introduced new decision points (especially Decision #12) and eliminated environment-based branching logic. Invariant descriptions must accurately reflect the current ADR text and code reality.

## Implementation intent
For each affected invariant entry:
1. Read the current ADR-004 text to identify the correct terminology and decision numbers.
2. Read relevant code (`mcp_tool_discovery.py`, `production_config_validator.py`) to verify the invariant's current enforcement mechanism.
3. Update the invariant description and/or verification status to match current reality.
4. Ensure invariant descriptions use the revised ADR's terminology (e.g., "component criticality classification" instead of "required/non-required branch").
