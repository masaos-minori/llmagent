## Goal
- Restore the import-layer contract "shared must not import from agent, mcp_servers, rag, or db" by moving the production configuration validator, which depends on the agent's configuration schema and tool-risk policy, from the shared package into the agent package, with no change in validation behavior.

## Priority
Medium

## Scope
- **In-Scope**: moving the validator module and its unit tests to the agent package and test tree; updating every importer, patch target, docstring, and documentation line that names the old path; keeping validation results identical.
- **Out-of-Scope**: changing any validation rule; changing the agent's tool policy or configuration dataclasses; other layer contracts; the pre-existing type-check findings in the tracer module.

## Background
`PYTHONPATH=scripts uv run lint-imports` reports one broken contract: the shared validator imports the agent's tool policy (for the tier-to-risk mapping and the risk enum) and the agent's configuration dataclasses (to learn which top-level configuration keys are valid). The user chose to relocate the module rather than inject those dependencies.

## Problem
- Verified: the shared validator imports the agent package in exactly two functions; the import-linter output names exactly these two imports and no other violation.
- The validator is not used outside the agent: its only production importers are two agent modules; the other mentions are tests and documentation, so relocation matches how it is used.
- Moving it avoids duplicating the risk enum or the configuration key list in the shared package.

## Reason for change
A permanently broken architecture contract hides new layering violations; the module's own logic is agent-specific (agent configuration keys, agent tool risk policy).

## Implementation intent
- Move the module with `git mv` (history kept) and the unit tests with it, change only import paths and path references, and leave behavior and function bodies untouched.
- Do not leave a re-export at the old path (no backward-compatibility layer).

## Requirements
- `REQ-001`: The validator module lives under the agent package; the shared package no longer contains it or imports from the agent; `lint-imports` reports every contract kept.
- `REQ-002`: Both production importers use the new path.
- `REQ-003`: The validator's unit tests live under the agent test tree and all tests that import or patch the validator use the new path; test results are unchanged.
- `REQ-004`: Docstrings and documentation that name the old path name the new path; the shared documentation no longer describes the validator as a shared module.
- `REQ-005`: Lint, type, security, documentation checks, and the full suite introduce no new findings.
