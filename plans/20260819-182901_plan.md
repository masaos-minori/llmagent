# Plan: Make `ConfigLoader.load_all()` fail fast on missing required config by default

## Goal
Flip `ConfigLoader.load_all()`'s default from lenient (`strict=False`, silent-skip) to
strict (missing files listed in `_REQUIRED_CONFIG_FILES` raise `ConfigMissingError`
by default), and update every production call site — including one not named in the
source requirement — so a missing `agent.toml` fails loudly instead of degrading
silently to a warning or an empty config.

## Scope

**In-Scope:**
- `scripts/shared/config_loader.py`: change `load_all()`'s default parameter to
  `strict: bool = True`; update its docstring to drop the "tolerates legacy
  multi-file layout" framing (verified: no such framing currently exists in the
  file's comments/docstrings — see Assumptions).
- `scripts/rag/pipeline.py`: `_ModuleConfig.get()` (lines 65-79) must not let its
  `except (FileNotFoundError, ValueError)` swallow `ConfigMissingError` into a
  warning + empty `_cache`. `ConfigMissingError` must propagate.
- `scripts/rag/llm_client.py`: `_get_cached_llm_url()` (lines 63-73) and
  `_get_cached_embed_url()` (lines 76-86) have the **same** silent-swallow pattern
  (`except (FileNotFoundError, ValueError): ... = ""`) around their own
  `ConfigLoader().load_all()` calls. This file is listed in the requirement's
  Target files and call-site audit, but the Implementation instructions only name
  `pipeline.py`'s swallow explicitly. The requirement's own Acceptance criteria
  ("No production call site silently continues ... via debug log, warning, or
  empty-config fallback") is broader than the Implementation instructions text and
  covers these two functions. Fixing them is in scope for this plan.
- `scripts/agent/config_builders.py` `load_config()` (line 60) and
  `scripts/agent/commands/cmd_config.py` `_cmd_reload()` (line 59): confirm they
  already propagate (they do — no swallow of `ConfigMissingError`/`ValueError`
  around `ConfigMissingError` specifically; `config_builders.py` re-raises as
  `ConfigLoadError`, which is acceptable fail-fast behavior). No behavior change
  required beyond relying on the new strict-by-default value.
- `tests/shared/test_config_loader.py`, `tests/shared/test_config_hot_reload.py`,
  `tests/shared/test_shared_boundary_conditions.py`: update/add tests for the new
  default (see Affected areas for exact test-by-test impact).

**Out-of-Scope:**
- No change to `_BASE_CONFIG_FILES` / `_REQUIRED_CONFIG_FILES` contents (still a
  single-entry `("agent.toml",)`).
- No change to `scripts/agent/services/config_reload.py` (`ConfigReloadService`) —
  it operates on an already-loaded dict, not on `ConfigLoader` directly.
- No change to `scripts/eventbus/app.py`'s `load_config()` — this is a different,
  unrelated `load_config` (eventbus has its own config loader, confirmed by path
  `scripts/eventbus/app.py` vs `scripts/agent/config_builders.py`); per
  `AGENTS.md` Global Rule 8, eventbus implementation changes are prohibited in
  this workflow regardless.
- No first-run/dev-mode wizard exists in the current codebase to carve out an
  explicit `strict=False` opt-out for (see Unknowns UNK-01).
- No documentation updates (`docs/*.md`) — out of scope for this workflow phase
  per `prompts/01_require-to-plan.md`.

## Assumptions
- A1: `config_loader.py` currently has no comment/docstring text describing the
  lenient default as accommodating a legacy multi-file layout — verified by
  `grep -n "legacy\|multi-file\|split" scripts/shared/config_loader.py` (no
  matches). The requirement's instruction to "remove" such text is a no-op; the
  docstring update needed is simply to describe the new strict-by-default
  semantics, not to delete legacy framing that isn't present. Falsifiable: re-run
  the grep after any intermediate edit to confirm no such text was introduced.
- A2: `ConfigMissingError` is a subclass of `ValueError` (confirmed in
  `scripts/shared/config_errors.py`), so any bare `except (..., ValueError)` around
  a `load_all()` call will catch it unless specifically excluded. This is why
  `llm_client.py`'s two cache functions need the same fix as `pipeline.py`.
- A3: All 5 production call sites invoke `ConfigLoader().load_all()` with no
  arguments today (confirmed via `grep -rn "\.load_all(" scripts/`), so all 5 are
  affected by the default flip; no call site currently passes `strict=` explicitly.
- A4: `agent.toml` is expected to exist at process startup in all real deployments
  (confirmed indirectly: `config_builders.load_config()` is the main startup path
  feeding `build_agent_config()`, and no code path constructs a running agent
  without it). Therefore flipping the default to strict is safe for production
  startup and does not require a new lenient opt-in path for a "first run" flow,
  because no such flow exists in this codebase today.

## Design
1. `scripts/shared/config_loader.py`:
   - Change `def load_all(self, strict: bool = False)` → `def load_all(self, strict: bool = True)`.
   - Rewrite the docstring's `Args: strict:` line to read (example):
     `strict: If False, missing files are skipped with a debug log instead of
     raising. Defaults to True: a missing file listed in _REQUIRED_CONFIG_FILES
     raises ConfigMissingError.`
   - No change to the `try/except ConfigMissingError` branch logic inside the loop
     itself — the branch `if strict and name in _REQUIRED_CONFIG_FILES: raise` is
     already correct; only the parameter default changes.
2. `scripts/rag/pipeline.py` `_ModuleConfig.get()`:
   - Split the except clause so `ConfigMissingError` (a required-file-missing
     condition) is not caught by the broad `except (FileNotFoundError, ValueError)`.
     Concretely: catch `ConfigMissingError` first (re-raise it, or simply let it
     propagate by not catching it at all — remove it from the tuple), and keep
     `except (FileNotFoundError, ValueError)` for genuinely recoverable cases
     (e.g. malformed non-required files) if any remain reachable. Since
     `_BASE_CONFIG_FILES` is single-entry and that entry is required, in practice
     the simplest correct fix is: catch `ConfigMissingError` explicitly and
     re-raise (or omit `_cache = {}` fallback for it), while leaving
     `FileNotFoundError`/other `ValueError` subtypes (e.g. `ConfigParseError`,
     `ConfigReadError`) to decide case-by-case whether fail-fast also applies to
     them (the requirement only mandates fail-fast for the missing-required-file
     case, so parse/read errors may keep warn-and-continue if desired — confirm
     with `ConfigParseError`/`ConfigReadError` still being caught).
3. `scripts/rag/llm_client.py`:
   - Apply the identical split to `_get_cached_llm_url()` and
     `_get_cached_embed_url()`: `ConfigMissingError` must propagate instead of
     being caught by `except (FileNotFoundError, ValueError)` and silently cached
     as `""`.
4. No call site in scope needs an explicit `strict=False` opt-out (per Assumption
   A4 / Unknown UNK-01) — all 5 production callers should keep calling
   `load_all()` with no arguments and inherit the new strict default.
5. Update the 3 test files per Affected areas.

## Risks
- **Risk**: Flipping the default to strict could crash a running agent process at
  startup in any environment where `config/agent.toml` is not yet provisioned
  (e.g. a fresh container before first-boot config generation).
  → **Mitigation**: Assumption A4 found no such bootstrap flow in the current
  codebase; re-verify with `rg -rn "ConfigLoader\(\)" scripts/ deploy/` immediately
  before merge (per UNK-01) to catch any newly added call site. Likelihood: low.
- **Risk**: Narrowing `pipeline.py`'s and `llm_client.py`'s except clauses to stop
  catching `ConfigMissingError` could inadvertently also stop catching
  `ConfigParseError`/`ConfigReadError` if the edit is done carelessly (e.g. by
  removing `ValueError` entirely instead of excluding only
  `ConfigMissingError`), silently changing behavior for malformed (not missing)
  config files.
  → **Mitigation**: Implementation step explicitly re-adds/keeps
  `except (FileNotFoundError, ValueError)` for the remaining recoverable cases
  and only special-cases `ConfigMissingError`; covered by the Phase 3 regression
  tests asserting both behaviors (missing → raise, malformed → existing warn
  path) separately. Likelihood: medium if unreviewed; low with the added test.
- **Risk**: `_cmd_reload()`'s runtime `/reload` command may now surface a raw
  `ConfigMissingError` traceback to an interactive user instead of a clean error
  message if `agent.toml` is deleted mid-session (UNK-02).
  → **Mitigation**: Verify the command dispatcher's exception handling during
  implementation; if it does not already render a clean error, this is a
  pre-existing gap in error presentation, not introduced by this change (today's
  lenient default would instead silently reload an empty config, which is worse).
  Likelihood: low; acceptable given fail-fast is the stated goal.
- **Risk**: Existing callers or third-party scripts (outside `scripts/`) may call
  `ConfigLoader().load_all()` and rely on the lenient default without this plan's
  visibility (e.g. ad-hoc tools under `tools/`).
  → **Mitigation**: `rg -rn "\.load_all(" ` was run repo-wide during planning and
  found only the 5 documented `scripts/` call sites plus the 3 test files;
  re-run the same search as a pre-commit sanity check. Likelihood: low.
