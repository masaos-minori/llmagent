## Background

The File Lifecycle section in `docs/03_rag_02_01_ingestion_pipeline-overview.md` provides a verification command using `orjson.loads()` that requires manual file path substitution and binary mode reading. Operators attempting to verify JSON artifacts will struggle with the command due to unclear binary mode requirements and lack of output format guidance.

## Problem

The current verification command `python -c "import orjson; print(orjson.loads(open('FILE', 'rb').read()))"` has several usability issues:
- Requires manual file path substitution (no placeholder example)
- The binary mode (`'rb'`) requirement is non-obvious — standard Python `json.load()` would use text mode
- No explanation of why `orjson` is used instead of the standard `json` module
- No guidance on what to look for when verifying the output

## Reason for change

Operators need clear, actionable guidance to verify JSON artifacts during debugging and operational tasks. Without it, they may attempt incorrect commands or misinterpret results.

## Implementation intent

Enhance the existing verification command block with: a concrete working example, an explanation of the binary mode requirement, the rationale for `orjson`, and an expected output format description. Consider adding a helper script as an optional enhancement.

## Design

This is a Path A task (small scope: single documentation file, no interface changes). The design follows these principles:

1. Enhance the existing inline command rather than replacing it — keep the compact form for quick reference while adding a separate expanded example block.
2. Use the actual JSON key structures from `pipeline_utils.py` as the basis for the expected output format description.
3. Keep the explanation concise — approximately 5-10 sentences total — since this is a practical operational guide, not a deep dive into `orjson`.
4. Defer helper script creation (REQ-005) unless inline improvements prove insufficient.

Evidence grounding:
- `pipeline_utils.py:106`: `raw = path.read_bytes()` — confirms binary mode is necessary because `orjson.loads()` accepts `bytes` input directly
- `pipeline_utils.py:110`: `data = orjson.loads(raw)` — confirms the function signature expects bytes
- Crawl JSON keys: `url`, `content`, `title`, `lang`, `code_blocks`, `etag`, `last_modified`, `fetched_at`
- Chunk JSON keys: `url`, `content`, `title`, `lang`, `code_blocks`, `etag`, `last_modified`, `normalized_content`, `chunk_index`, `source_file`, `chunk_type`, `chunking_strategy`, `fetched_at`
- `orjson` rationale: faster serialization/deserialization, deterministic output ordering, strict JSON compliance — all confirmed by its usage pattern across the RAG module
