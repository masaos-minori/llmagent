# Plan: HttpServerLifecycleManager preserves tracking on getpgid failure with terminated process

## Goal
- Ensure `HttpServerLifecycleManager._create_and_validate_proc()` preserves tracking entries when `getpgid()` fails AND process termination also fails, allowing operators to manually intervene.

## Priority
High

## Scope
- **In-Scope**: Modify `_create_and_validate_proc()` to conditionally remove tracking entries only after confirmed process exit following `getpgid()` failure; preserve `finally` block for resource cleanup
- **Out-of-Scope**: Changes to `ProcessTerminator.terminate_with_timeout()` behavior; changes to subprocess creation parameters; removal of `finally` block

## Background
`HttpServerLifecycleManager._create_and_validate_proc()` in `scripts/agent/http_lifecycle.py` creates a subprocess, validates its command, and records its process-group ID via `os.getpgid()`.

## Problem
When `getpgid()` fails after the subprocess has been created, the code attempts cleanup but the process itself may still be running. The tracking entries are removed, but the process continues without being tracked. If `terminate_with_timeout()` fails (e.g., permission denied), the process runs untracked. The subprocess consumes resources indefinitely. Subsequent health checks will fail silently because the key is no longer tracked.

## Reason for change
Orphaned processes during startup are a reliability concern. Without tracking data, there is no way to clean up the process later. Monitoring systems cannot detect or alert on orphaned processes.

## Implementation intent
After `getpgid()` failure, attempt termination first. Only remove tracking entries AFTER confirming the process has exited. Log the process PID so operators can manually clean up if needed. Preserve the `finally` block for resource cleanup while conditionally removing tracking entries based on termination outcome.

## Requirements
- `REQ-001`: Tracking entries are removed only after confirmed process exit
- `REQ-002`: Failed termination leaves process PID logged for manual intervention
- `REQ-003`: Test verifies no orphaned process after getpgid failure scenario
- `REQ-004`: Test verifies tracking entry persists when termination fails

## Design
### Current Behavior (Verified Against Source)
1. `http_lifecycle.py` line 320-321: Try to record pgid via `os.getpgid(proc.pid)`
2. Line 322-327: On `OSError`, log warning and attempt termination
3. Line 328-339: Call `terminate_with_timeout()` and check poll result
4. Line 340-346: `finally` block always cleans up resources — even if termination failed
5. Line 347: Re-raise the original `OSError`

### Proposed Change (Revised after adversarial validation)

The original proposal removed the `finally` block entirely. However, the `finally` block ensures resource cleanup (stderr_fh close, `_http_procs`/`_http_pgids` removal) regardless of how the `except OSError` handler exits. Removing it means:
- If `terminate_with_timeout()` raises an unexpected exception (not OSError/TimeoutError), resources leak
- The current code handles this correctly by always cleaning up in `finally`

The correct fix preserves the `finally` block while also preserving tracking entries when termination fails:

```python
try:
    self._http_pgids[server_key] = os.getpgid(proc.pid)
except OSError as e:
    logger.warning(
        "Lifecycle: getpgid() failed for %r pid=%d; attempting cleanup",
        server_key, proc.pid,
    )
    # Attempt termination first
    try:
        await self._process_terminator.terminate_with_timeout(
            proc, server_key, timeout=TERMINATE_TIMEOUT_SEC
        )
        # Termination succeeded — safe to clean up
        stderr_fh.close()
        self._stderr_files.pop(server_key, None)
        self._stderr_log_manager.forget(server_key)
        self._http_procs.pop(server_key, None)
        self._http_pgids.pop(server_key, None)
    except Exception as term_err:
        logger.error(
            "Lifecycle: failed to terminate orphaned process %r pid=%d: %s",
            server_key, proc.pid, term_err,
        )
        # Do NOT remove tracking — process may still be running
        # Tracking entries preserved by finally block below
    finally:
        # Always cleanup resources if getpgid fails, even if termination fails
        stderr_fh.close()
        self._stderr_files.pop(server_key, None)
        self._stderr_log_manager.forget(server_key)
        # Only remove tracking if termination succeeded
        if 'term_err' not in locals():
            self._http_procs.pop(server_key, None)
            self._http_pgids.pop(server_key, None)
    raise e
```

Key changes:
1. Keep the `finally` block for resource cleanup (stderr_fh, _stderr_files, _stderr_log_manager)
2. Add `except Exception` clause around `terminate_with_timeout()` to catch failures
3. Move tracking entry removal (`_http_procs`, `_http_pgids`) into the success path only
4. Log PID for manual intervention if termination fails
