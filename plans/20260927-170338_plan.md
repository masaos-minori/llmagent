## Goal
- Reconcile every `docs/*.md` document's front-matter `related:` list against its body
  `## Related Documents` heading so the two converge, per the owner's ruling on NC-031
  that front-matter `related:` is authoritative.

## Priority
Low

## Scope
- **In-Scope**: For each of the 42 `docs/*.md` files confirmed to have a divergent
  front-matter `related:` list vs. body `## Related Documents` heading (see Problem),
  reconcile the body heading's link list to exactly match the front-matter list (same
  target set, by relative path).
- **Out-of-Scope**: The 75 `docs/*.md` files that already match, or that have only one
  of the two fields (front-matter `related:` only, or body heading only — 91 and 20
  files respectively, confirmed via the same corpus scan). Changing the
  authoritative-field ruling itself (already decided per NC-031 and reconfirmed by the
  owner during this Plan's own scope-check — see Design). Any code change (this Plan is
  documentation-only).

## Background
NC-031 (`docs/00_governance/governance_03_issue-and-uncertainty-management.md`) tracked
whether the front-matter `related` field and the body `## Related Documents` heading
were expected to match. During
`implementations/done/20260927-124641_01_docs_00_governance_governance_02_documentation-metadata.md.md`'s
execution, the owner ruled: this is drift, not intentional duality — front-matter
`related:` is authoritative, and body `## Related Documents` headings should be
reconciled to match it going forward. This Plan is the reconciliation work filed as a
follow-up from that cycle.

## Problem
A full-corpus scan (Python script reading every `docs/*.md` file, comparing
front-matter `related:` entries against body `## Related Documents` markdown-link
targets, both normalized to basenames) found:
- 117 files have both a front-matter `related:` list and a body `## Related Documents`
  heading.
- Of those, **42 diverge** (the two lists are not the same set) and **9 already match**
  (66 files' body heading had no parseable markdown-link entries and were excluded from
  automated comparison — out of scope per this Plan's In-Scope definition, which
  requires both fields to be present and comparable).
- Two sub-patterns were observed among the 42: (a) the majority are simple
  partial-overlap drift — one list is missing entries the other has (e.g.
  `governance_01_documentation-policy.md`: front matter lists `00_index.md`,
  `overview_00_document-guide.md`; body lists `governance_02/03/04` and
  `adr-index.md` — no overlap at all). (b) 15 ADR documents plus
  `mcp_03_01_dispatch-and-routing.md`/`mcp_03_02_tool-registry.md` show front matter
  referencing sibling design documents (other ADRs, or sibling docs in the same
  numbered series) while the body references implementation/operational documents —
  e.g. `ADR-005-rag-source-derived-index-relationships.md`: front matter = `[ADR-002]`,
  body = 9 RAG/DB implementation docs. This pattern could plausibly be an intentional
  split by purpose rather than drift.
- This Plan's own scope-check (via AskUserQuestion, 2026-09-27) presented both
  sub-patterns to the owner and confirmed: the front-matter-authoritative ruling
  applies uniformly to all 42 files, including sub-pattern (b) — see Design for the
  accepted consequence.

## Reason for change
`docs/00_governance/governance_02_documentation-metadata.md`'s `related` field
description now states that front-matter `related:` is authoritative over the body
heading when they diverge, and points to this Plan's originating issue as the
follow-up. Leaving the 42 confirmed-divergent documents unreconciled means the stated
policy does not yet match actual document content.

## Implementation intent
For each of the 42 target files, replace the body `## Related Documents` heading's link
list so it contains exactly the same target set as the file's own front-matter
`related:` list (same relative paths). Link text (the visible title in each new/changed
body entry) is derived from each target file's own `<title>`/H1 heading at
implementation time — this Plan does not pre-resolve titles, since that is
per-target-file lookup work suited to the implementation phase, not scope-definition
work. Process files grouped by directory (governance, ADR, RAG, MCP, agent) for
review-sized batches, then run the two docs checkers across all 42 as a final pass.

## Requirements
- `REQ-001`: For each of the 42 confirmed-divergent `docs/*.md` files, reconcile the
  body `## Related Documents` heading's link list to exactly match the front-matter
  `related:` list.
