## Goal
- Unify `docs/03_rag_*.md` documentation of the `fetched_at`/ETag freshness contract
  with the already-implemented mandatory-`fetched_at`, no-Null-Fill-Mode code
  (`ETagManager`, `DocumentManager`), fill the confirmed gaps (missing `fetched_at`
  from the DTO's Required-fields list; missing invalid-timestamp error
  classification), and document currently-unspecified edge-case behavior (equal
  timestamps, both ETag/Last-Modified absent) from code evidence.

## Priority
High

## Scope
- **In-Scope**: the `docs/03_rag_*.md` files listed in Implementation Target Files
  below; documenting `fetched_at` as required; documenting `ETagManager`'s exact
  freshness-comparison and error behavior; adding the missing invalid-timestamp
  error classification to the error-handling reference; a new/updated Known Issue
  entry.
- **Out-of-Scope**: removing `_update_null_fill()` from source code (already done);
  implementing fail-closed timestamp handling; repairing existing database values;
  defining timestamp rules outside the RAG ingestion domain; changing the SHA-256
  local-file freshness description, which is already accurate.

## Background
`issues/done/20260828_01_remove-fetched-at-null-fill-and-mandatory-contract.md`
already implemented the code-side change (`_update_null_fill()` removal,
`fetched_at` made mandatory on `ChunkDocument` and on `ETagManager.update()`/
`DocumentManager.handle_existing_document()`). Its Documentation Impact was limited
to docstrings and did not update the `docs/03_rag_*.md` Specification set, which this
Plan covers.

## Problem
`docs/03_rag_04_01_dto-models_data.md`'s `ChunkDocument` "Key Fields for Design"
section lists `` `url`, `title`, `lang`, `content`: Required fields `` and does not
include `fetched_at` in that Required list, even though
`scripts/rag/models_data.py`'s `ChunkDocument` dataclass declares `fetched_at: str`
with no default (repository evidence: confirmed missing via direct read of the
document's "Key Fields for Design" section). `docs/03_rag_05_4-error-handling-reference.md`'s
`RagIngester` error table has no entry for invalid/unparseable `fetched_at` values,
even though `ETagManager._is_stale_update()` raises `ValueError` for both an invalid
incoming timestamp and an invalid stored timestamp (repository evidence:
`scripts/rag/ingestion/etag_manager.py:56-76`). No current document states the
equal-timestamp outcome (update proceeds; `new_dt < stored_dt` is `False`) or the
both-`etag`-and-`last_modified`-absent outcome (`update()` returns early without a
DB write).

## Reason for Change
Removing the legacy Null Fill Mode path from documentation must not silently weaken
the current freshness guard's documented guarantee. An explicit, single
freshness-update contract is needed so readers cannot conflate the removed legacy
behavior with current protection, and so the currently-undocumented edge cases
(invalid timestamps, equal timestamps, both-metadata-absent) have a documented,
code-verified outcome.

## Implementation intent
Add `fetched_at` to `docs/03_rag_04_01_dto-models_data.md`'s Required-fields list.
Extend `docs/03_rag_02_06_ingestion_pipeline-supporting-components.md`'s
`ETagManager` description (already correct on the freshness-guard and
both-absent-early-return behavior) with the invalid-incoming-timestamp,
invalid-stored-timestamp, and equal-timestamp outcomes, all sourced from
`_is_stale_update()`. Add an invalid-`fetched_at` row to
`docs/03_rag_05_4-error-handling-reference.md`'s `RagIngester` table, citing the two
distinct `ValueError` messages (`Invalid incoming timestamp` /
`Invalid stored timestamp`) as the current distinguishing mechanism — code does not
raise two distinct exception classes. Cross-link
`docs/03_rag_02_04_ingestion_pipeline-ingester.md`'s and
`docs/03_rag_02_05_ingestion_pipeline-document-manager.md`'s existing
freshness-guard descriptions (already accurate: no fallback path, `fetched_at`
required) to the extended `ETagManager` description rather than duplicating it. Add
a Known Issue entry to `docs/03_rag_90_inconsistencies_and_known_issues.md`
documenting that Null Fill Mode has been fully removed from code and this
documentation set, since no existing entry on this topic was found.
