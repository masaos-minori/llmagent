# Plan: Remove Redundant Subprocess Termination in repl.py Startup-Failure Exception Handler

## Goal
Remove the `hasattr`-based process collection and redundant subprocess termination from `AgentREPL.run()` in `scripts/agent/repl.py`, relying solely on `StartupOrchestrator.run()`'s internal `lifecycle.shutdown_all()` for subprocess cleanup on startup failure.

## Priority
Low

## Scope
- **In-Scope**: Removing the `hasattr`-based process collection and termination loop from `repl.py`; verifying no orphaned processes remain on startup failure paths.
- **Out-of-Scope**: Changing how subprocesses are spawned or health-checked; refactoring the normal REPL shutdown path (`ResourceShutdownCoordinator`).

## Background
`StartupOrchestrator.run()` spawns HTTP-subprocess MCP servers, tracks them in `self._spawned_subprocesses`, and on any setup exception calls `await self._ctx.services_required.lifecycle.shutdown_all()` before re-raising. `repl.py`'s `run()` wraps `startup.run()` and, in its `except`, also terminates the returned processes.

## Problem
The `except` block builds its process list via `all_procs = _spawned_subprocesses` then conditionally appends `list(startup._spawned_subprocesses)` using `hasattr`. This depends on attribute introspection and on the local `_spawned_subprocesses` remaining empty when `startup.run()` raises mid-unpacking, and it double-terminates processes that `shutdown_all()` already tore down. It works today but is fragile and redundant.

## Reason for change
Resource-cleanup code on the failure path should be obvious and singular. Introspection-based collection invites future breakage if `StartupOrchestrator` changes how it exposes spawned processes.

## Implementation intent
Establish one authoritative shutdown path for startup-spawned subprocesses. Either (a) rely solely on `StartupOrchestrator.run()`'s internal `shutdown_all()` and remove the termination loop from `repl.py`, or (b) have `startup.run()` propagate the process list reliably and terminate there once. Confirm with whoever owns the lifecycle contract which is correct; do not leave two partial terminations.

## Requirements
- `REQ-001`: Remove the `hasattr`-based process collection and termination loop from `repl.py`'s startup-failure exception handler.
- `REQ-002`: Ensure each spawned subprocess is terminated exactly once on startup failure (no leak, no double-terminate error).
- `REQ-003`: Preserve the success-path return contract `(cmds, orchestrator, spawned_subprocesses)`.
- `REQ-004`: Run lint/type checks (ruff, mypy) on modified files.

Verification confirmed that:
1. `startup.run()` calls `shutdown_all()` on its own exception path (line 81 of `startup.py`)
2. `repl.py` has NO `shutdown_all()` call — it relies on `hasattr` introspection to collect processes
3. Both paths attempt to terminate the same processes → double termination risk

**Recommended approach**: Option (a) — rely solely on `StartupOrchestrator.run()`'s internal `shutdown_all()` and remove the termination loop from `repl.py`.

Rationale:
- `shutdown_all()` already handles subprocess termination (confirmed by `test_http_lifecycle_shutdown_coordinator.py`)
- The return value of `startup.run()` is never used on the failure path anyway
- Removing the duplicate termination eliminates the double-terminate bug
- The `hasattr` check is unnecessary since `startup` is always the same object created just above

The fix removes lines 127-134 of `repl.py` and replaces them with a simple fatal message + re-raise:
```python
except Exception as e:
    self._view.write_fatal(f"Startup failed: {e}")
    raise
```

## Adversarial Verification
Verified against source + tests on 2026-10-01. Findings recorded here to inform
the owner/freeze decision; this section makes no implementation decision.

- **RG EVIDENCE ACCURATE.** `rg hasattr repl.py` = 1 match (line 129);
  `rg shutdown_all repl.py` = 0 matches; `rg shutdown_all startup.py` = 1 match
  (line 81). All three Repository-Evidence claims in the target-files table are
  correct.
- **UNK-01 RESOLVES NON-BLOCKING (option (a) will NOT leak).** Full call chain
  traced: `startup.run()` stores procs in `self._spawned_subprocesses`, each
  obtained from `Lifecycle.start_http_subprocess()` returning
  `self._http_mgr._http_procs.get(server_key)` (factory.py:147) and appended to
  the list (`startup_mcp_starter.py:160`). `shutdown_all()` routes
  router(307) -> `_subprocess_mgr.shutdown_all`(116) -> `http_mgr.shutdown_all`(495)
  -> `ShutdownCoordinator.shutdown_all(manager)`, which iterates
  `manager.iter_processes()` over `_http_procs`. Same object set. Every spawned
  subprocess is covered; removing repl.py's loop leaks nothing.
- **CRITICAL TEST GAP (must fix before freeze).**
  `tests/agent/test_repl.py::TestAgentREPLRunSubprocessTermination::
  test_run_terminates_subprocesses_on_failure` (line 1221) asserts
  `fake_proc.terminate.assert_called_once()` -- it verifies repl.py's OWN
  termination loop, not `shutdown_all()`. Deleting the loop makes this assertion
  fail. The plan OMITS test_repl.py from Reference Files, adds NO
  Implementation-Target row for it (rules require a row when a test needs
  modification), and its Validation plan runs only
  `pytest tests/agent/test_startup_rollback.py` -- which IS unaffected (it tests
  `StartupOrchestrator.run()`). The two suites are conflated: test_startup_rollback.py
  passes unchanged, but the repl.py failure-path test breaks. The sibling
  `test_run_does_not_terminate_subprocesses_on_success` (line 1199) still passes
  (terminate is never called on success either way). Implementer must update or
  delete the failing test AND add a row for `tests/agent/test_repl.py`.
- **MOTIVATION OVERSTATED.** The plan frames this as eliminating a "double-terminate
  bug." In practice repl.py guards with `if proc.poll() is None:` (repl.py:132);
  `shutdown_all()` fully terminates each proc (SIGTERM then SIGKILL fallback via
  `terminate_with_timeout`), so by the time repl.py runs the procs are already
  dead and the guard skips them. There is effectively no double-terminate on the
  normal path. The real benefit is removing `hasattr` introspection fragility /
  consolidating the terminator, not fixing a live bug. Priority=Low is still
  appropriate; the Problem wording should be corrected.
- **REQ-003 holds.** Removing only the except-block termination leaves
  `return (cmds, orchestrator, spawned_subprocesses)` (startup.py:93) intact; the
  success-path return contract is preserved.
- **Safety-net reduction (minor risk).** Consolidation replaces two independent
  terminators (`shutdown_all` + repl.py backstop) with one. Tracing shows
  `shutdown_all()` catches OSError/TimeoutError per-proc and continues
  (http_lifecycle_shutdown_coordinator.py:109), so it will not raise mid-loop and
  the backstop is largely redundant -- but failure-path cleanup now depends
  entirely on `shutdown_all()`'s correctness. Acceptable given UNK-01 resolved;
  worth keeping in mind.

  recommends option (a) pending owner confirmation -- consistent. No decision made
