# Plan: Add ctypes-based signal handler fallback on Windows without pywin32

## Goal
Register a minimal signal handler on Windows using ctypes when pywin32 is unavailable, preventing silent loss of graceful shutdown capability.

## Priority
Medium

## Scope
- **In-Scope**: Add ctypes-based ConsoleCtrlHandler registration as fallback when pywin32 is unavailable; add regression tests
- **Out-of-Scope**: Adding cross-platform signal handling abstraction; changes to POSIX signal handler behavior

## Background
`SignalHandler.register()` in `scripts/agent/signal_handler.py` registers SIGTERM/SIGINT handlers using `loop.add_signal_handler()` on POSIX systems. On non-POSIX platforms, it falls back to Windows console control handlers.

## Problem
When `loop.add_signal_handler()` raises `NotImplementedError`, the fallback path requires pywin32. If pywin32 is not installed, the warning is logged but NO signal handler is registered. This means the agent receives no graceful shutdown notification on Windows without pywin32.

## Reason for change
On Windows without pywin32: Ctrl+C/Ctrl+Break produces no graceful shutdown. Process terminates abruptly, losing in-memory state. No warning is visible to the user about missing signal handling.

## Implementation intent
Add a ctypes-based fallback for registering `SetConsoleCtrlHandler` when pywin32 is unavailable. This provides the same functionality without the pywin32 dependency.

- `REQ-002`: Error message clearly indicates the limitation
- `REQ-003`: Test verifies handler registration on Windows without pywin32
