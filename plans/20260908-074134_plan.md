# Plan: Deterministic exception-to-state mapping for structured integrity classification

## Goal
Replace fragile substring matching in `_classify_error()` with structured error code detection where available, and add the missing `INVALID_FORMAT` classification path for non-SQLite files misidentified as databases.

## Priority
Medium

## Scope
- **In-Scope**: Modifying `_classify_error()` internals in `scripts/db/recovery.py`; adding unit tests for `_classify_error()` in `tests/db/test_db_recovery.py`
- **Out-of-Scope**: Changing `recover_corruption()` control flow or action names; changing `_run_integrity_check()` return shape; implementing backup-candidate domain-identity validation; changing WAL/SHM handling; adding `IntegrityCheckResult` dataclass

## Background
`scripts/db/recovery.py` defines `DbCondition` (StrEnum: HEALTHY, CORRUPTION, LOCK_CONTENTION, PERMISSION_FAILURE, INVALID_FORMAT, UNKNOWN) and routes recovery decisions through it. `_run_integrity_check()` and `recover_corruption()` dispatch on `DbCondition` via `tuple[DbCondition, str | None]` return shape. H-07-01 (completed) established the normative recovery terminology that this issue builds on.

## Problem
- `_classify_error()` maps every `sqlite3.DatabaseError` or `ValueError` to `CORRUPTION` — there is no code path that returns `INVALID_FORMAT`, even though the enum defines it. A non-SQLite file (e.g., a text file with a `.sqlite` extension) raises `sqlite3.DatabaseError: file is not a database`, which is currently indistinguishable from genuine page-level corruption.
- Lock-contention and permission-failure detection depend on `"database is locked" in msg.lower()` / `"permission denied" in msg.lower()` substring matching against `str(e)`, not on SQLite error codes or `OSError.errno`. A differently worded SQLite build message could produce text that does not match these substrings, silently misclassifying a lock/permission condition as `UNKNOWN` or `CORRUPTION`.
- `tests/db/test_db_recovery.py` covers `LOCK_CONTENTION`/`PERMISSION_FAILURE`/`UNKNOWN` only by mocking `_run_integrity_check`'s return value directly — there is no test that exercises `_classify_error()` itself against a real or constructed exception.

## Reason for change
Substring matching against exception messages is fragile across SQLite versions/locales and conflates "file is not a valid SQLite database" with "page-level corruption of an otherwise valid SQLite file". The backup-validation and atomic-replacement logic tracked separately in this batch needs this distinction to reject a wrong-format backup candidate without treating it identically to physical corruption.

## Implementation intent
Keep `DbCondition` as the contract (no new states). Change `_classify_error()`'s internals to prefer structured error codes over message substrings where available, and add a deterministic path that returns `DbCondition.INVALID_FORMAT` for the "not a database" condition, distinct from `CORRUPTION`. Preserve the existing public signatures (`_run_integrity_check` return shape, `recover_corruption` action names) unless a caller genuinely needs the new distinction surfaced.

## Requirements
- `REQ-001`: `_classify_error()` must return `DbCondition.INVALID_FORMAT` when the exception indicates a non-SQLite file was opened as a database (signal: `"file is not a database"` in the exception message).
- `REQ-002`: `_classify_error()` must use structured error codes (`sqlite3.OperationalError.errno` for lock/permission conditions) where available, falling back to substring matching only as a documented fallback.
- `REQ-003`: Direct unit tests for `_classify_error()` covering all six `DbCondition` states must exist, separate from `_run_integrity_check` mocked-return tests.

## Design
### Error code strategy
Since `sqlite3.Error.sqlite_errorcode` and `sqlite3.Error.sqlite_errorname` are **not available** on Python 3.14 (confirmed), the design uses `sqlite3.OperationalError.errno` for lock/permission conditions where available. This attribute provides the POSIX errno value (e.g., EACCES for permission failures), which is stable across SQLite versions and locales.

For INVALID_FORMAT detection, there is no structured error code available — the signal comes exclusively from the exception message containing `"file is not a database"`. This is a reliable signal because it is produced by SQLite's own C library when opening a non-database file, and it is not subject to localization or version differences.

### Classification priority order
1. Check `isinstance(e, sqlite3.OperationalError)` first — if true, inspect `errno` for lock/permission conditions before falling back to substring matching.
2. For `sqlite3.OperationalError` with no matched errno, fall back to substring matching for `"database is locked"` / `"busy"` (lock) and `"permission denied"` / `"readonly"` (permission).
3. For `sqlite3.DatabaseError` or `ValueError`, check for `"file is not a database"` → `INVALID_FORMAT`; otherwise → `CORRUPTION`.
4. All other exceptions → `UNKNOWN`.

### Test strategy
Add `_classify_error()`-direct tests using constructed exceptions rather than mocking `_run_integrity_check`. Each test creates the appropriate exception type and asserts the returned `DbCondition` value.
