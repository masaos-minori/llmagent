## Background
`docs/adr/ADR-004-environment-failure-handling-policy.md` defines INV-08 (required-component
unavailability aborts startup), INV-09 (non-required-component availability failure permits
continuation with partial availability), and INV-14 (undefined criticality must not permit
continuation) — listed as INV-019/INV-020/INV-021 in `docs/adr-index.md`'s cross-ADR Invariant
Verification Matrix. The source Issue was filed during the 2026-08-31 ADR-004 rewrite, reporting
that none of these had a dedicated automated test, based on a `grep` search of the test suite for
`is_required`, `required_in_local`, `required_in_production`.

## Problem
(Evidence: Explicit in issue, then refuted for two of three invariants by adversarial verification
against current source — see Requirements below for the per-invariant breakdown.)

The Issue's Problem statement claims: "`grep`-ing the test suite for `is_required`,
`required_in_local`, `required_in_production` found no test in `tests/agent/` that exercises the
classification branch in `scripts/agent/services/mcp_tool_discovery.py::discover_all()`."

Re-running that exact `grep` against current `tests/agent/` finds
`tests/agent/services/test_mcp_tool_discovery.py` for `required_in_local` (0 hits for `is_required`
and `required_in_production`, since those are not literal identifiers used in the test file — the
test file constructs `McpServerConfig(required_in_local=...)` directly). Reading that file's
`TestDiscoverAllUnreachableServers` class shows four tests directly exercising the classification
branch:
- `test_unreachable_required_server_with_fail_fast_returns_fatal` (`required_in_local=True`,
  `FailurePolicy.FAIL_FAST` → asserts a FATAL finding)
- `test_unreachable_non_required_server_with_fail_fast_returns_warning`
  (`required_in_local=False`, `FailurePolicy.FAIL_FAST` → asserts no FATAL, a WARNING finding)
- `test_unreachable_required_server_with_degraded_returns_warning`
  (`required_in_local=True`, `FailurePolicy.DEGRADED` → asserts no FATAL, a WARNING finding)
- `test_unreachable_non_required_server_with_degraded_returns_warning`
  (`required_in_local=False`, `FailurePolicy.DEGRADED` → asserts no FATAL, a WARNING finding)

Running `uv run pytest tests/agent/services/test_mcp_tool_discovery.py -k
TestDiscoverAllUnreachableServers` confirms all 12 tests in this class currently pass (Verified by
test, this Plan's Step 3 verification, 2026-09-01).

Git history shows these four tests were added in commit `346cb8bd` (2026-08-26), five days before
the Issue was filed (2026-08-31) and before the "2026-08-31 ADR-004 rewrite" the Issue references.
`docs/adr/ADR-004-environment-failure-handling-policy.md`'s own Verification section (INV-08/INV-09
entries, Manual Review bullet list, and Known Deviations "report only" bullet) and
`docs/adr-index.md`'s INV-019/INV-020 rows still state "no dedicated automated test exists" as of
the current repository state — this is the actual problem this Plan addresses: the ADR-004 rewrite
and the Issue were both written without discovering tests that already existed at the time.

INV-14/INV-021 (undefined criticality) is unaffected by this finding: `scripts/shared/mcp_config.py`
confirms `McpServerConfig.required_in_production`/`required_in_local` remain plain booleans
defaulting to `True`, with no distinct "undefined" state — so the Issue's claim that INV-14/INV-021
has "no implementation to test against" remains accurate (Confirmed by repository evidence).

## Reason for change
Documentation that claims verification gaps which do not actually exist misdirects future
engineering effort (e.g., a future contributor re-implementing tests that already exist) and
undermines the Verification section's purpose as an authoritative, evidence-grounded record per
each document's own instruction to cite real evidence. The Issue's own Constraint — "Do not claim
these tests exist or pass in any ADR or index document until they are actually written and run" —
is satisfied here in the corrective direction: the tests already exist and were confirmed passing
during this Plan's creation, so the documents must now be corrected to say so.
