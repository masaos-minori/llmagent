## Background
`repl.py` is a composition facade: it builds `AgentContext`, `CLIView` and `DiagnosticStore`, constructs the REPL
concern classes, hands the command registry and orchestrator to `ReplInputLoop` after startup, and closes
resources in one `finally` (`repl.py:76-92`, `:110-162`). Its module docstring is quoted as the source of that
layer split by `docs/01_overview/overview_01_02-arch-pipelines.md:60` ("The responsibilities of each layer are
declared in the docstrings of `agent/repl.py`") and
`docs/23_agent/agent_07_04_cli-and-commands-purpose.md:32`. `tool_hash_key` is the identity function for failed
tool calls: `tool_runner.py:237` (`out_failed_keys`) and `tool_loop_guard.py:25`.

## Problem
Verified against HEAD (`b17ca6a26`), all four stale claims confirmed:
- `repl.py:15` claims `ToolExecutor — MCP routing, error handling, TTL cache`. `scripts/shared/tool_executor.py`
  contains no cache, TTL, or idempotency code (`grep -in 'cache|ttl|idempot'` matches nothing); its own docstring
  (`:2-10`) and `docs/23_agent/agent_02_runtime-architecture.md:115-120` describe routing, dispatch,
  name-to-server resolution and per-server health. The only such cache is server-side
  (`scripts/mcp_servers/dispatch.py:68`, `:93`, `:101-106`, `:113-119`, `:122-129`, key at `:173`), documented in
  `docs/22_mcp/mcp_03_01_dispatch-and-routing.md:57-69`.
- `repl.py:19` names `agent/config.py`; the file does not exist. The dataclass lives in
  `scripts/agent/config_dataclasses.py`, the builder in `agent/config_builders.py`, which is what
  `docs/23_agent/agent_12_reference-api.md:192-195` already states.
- `repl.py:21` names `agent.py`; the file does not exist. The entry point is `main()` in this module (`:170-172`),
  compiled into `/opt/llm/bin/agent` by `deploy/build_binaries.sh:124` (`"agent.repl:agent:"`) whose generated
  launcher does `from agent.repl import main` (`build_binaries.sh:239-241`). Running `python scripts/agent/repl.py`
  from the repository root fails on the first package import (`ModuleNotFoundError: No module named
  'shared.config_loader'` raised from `scripts/agent/context.py:30`).
- `tool_executor_helpers.py:41` states cache keys are built by `f'{name}:{json_dumps(args)}'`. No such key is
  constructed anywhere in `scripts/shared/`; that concatenation exists only as the string `tool_hash_key` hashes
  (`:42-45`), and the real cache above is keyed by the caller's idempotency key.
- `_turn_active`, `_input_coro`, `_prompt`, `_n_tools` have no reader in production; the live counterparts are
  `ReplInputLoop._turn_active` (`repl_input_loop.py:66`, `:251`, `:314`), `ReplInputLoop._input_coro` (`:67`,
  `:120`, `:149`) and the literal prompts `input("> ")` (`repl_input_loop.py:144`, `:191`) / `input("... ")`
  (`cli_view.py:289`).
- Guard constraint found during verification: `agent/repl.py` is grandfathered in
  `tools/check_docstrings_baseline.txt:52` with issue kind `empty description`, because its architecture list uses
  one spaced em-dash per line while `tools/check_docstrings.py` parses exactly one `scripts/<relpath> — `
  separator. Measured: removing that baseline line without changing the docstring, or making the docstring conform
  without removing the line, both make `tools/check_docstrings.py` exit 1.

## Reason for Change
Three of the pointers a new contributor follows (config dataclass, entry point, tool cache) lead to files that do
not exist, and one describes a cache that exists only on the MCP server side under a different key scheme. The
unused attributes make it ambiguous which object owns live REPL state; `ReplInputLoop` owns it.

## Implementation Intent
Rewrite the false sentences in place, keep the docstring's structure and the layer-split wording the docs quote,
name the two composed objects that are missing, correct the `tool_hash_key` description to what the function
actually does, and delete the four dead declarations without touching any wiring.

## Design
- Keep the docstring's three-part shape (path header, delegation paragraph, `Architecture (dependency injection
  via AgentContext)` list). The two docs that treat the docstring as authoritative depend on that shape, and the
  list style is what keeps the grandfathered `check_docstrings` entry accurate (REQ-007).
- Fix by substitution, not by restructuring: `:15` becomes the routing/dispatch/health description from
  `agent_02_runtime-architecture.md:115-120`; `:19` becomes `agent/config_dataclasses.py` per
  `agent_12_reference-api.md:192-195`; `:21` becomes "this module is the process entry point; `main()` is what
  `deploy/build_binaries.sh` compiles into `/opt/llm/bin/agent`". No sentence is added about a tool cache — the
  server-side idempotency cache belongs to `docs/22_mcp/`, which already documents it.
- Add the two missing composed objects to the delegation paragraph (`DiagnosticStore`, `StartupOrchestrator`)
  rather than expanding the DI list: the DI list describes state the context carries, the delegation paragraph
  describes what the facade constructs, and those two are constructed (`:80`, `:120`).
- Ownership rule applied to the dead attributes: the live owner already exists in every case
  (`ReplInputLoop` for turn/input state, `CLIView`/`ReplInputLoop` for prompt strings), so the fix is deletion,
  not re-parenting (issue Required Changes: "Delete unused state rather than documenting it").
- `_n_tools` is deleted rather than wired to the banner: `StartupBanner.print_startup_banner()` already derives
  tool counts from the orchestrator at `repl.py:158`, so a facade-level counter would be a second source of the
  same number.
- `tool_hash_key`'s docstring keeps the existing "NOT for cache keys" contrast (it is accurate and load-bearing
  for readers who confuse it with the server cache) and drops the invented key format; if it points at the real
  cache it must name the idempotency key as the key.
- Sequencing: this plan is written now but implemented last among the `repl.py`-touching plans
  (`repl001`, `repl003`, `shutdown002`, `shutdown003`), per the source issue's Dependencies. Its acceptance
  checks are written as greps against the file at implementation time so the checks remain valid after those
  plans land.
