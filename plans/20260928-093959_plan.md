## Problem
`_format_chunks()` uses `c.content`, not `c.normalized_content`, when formatting chunks for LLM presentation — confirmed correct via code inspection — but no automated test covers this prohibition.

## Reason for change
Without test coverage, a future change to `_format_chunks()` could silently reintroduce `normalized_content` (the FTS5-only, LLM-unsafe field) into LLM-facing output, violating ADR-009, with no automated signal.

## Implementation intent
Add a focused unit test asserting `_format_chunks()`'s output never contains `normalized_content`'s value when it differs from `content`, following existing conventions in the RAG test suite. No production code change is expected.

## Requirements
- `REQ-001`: `_format_chunks()` must prevent `normalized_content` from appearing in LLM output when it differs from `content`
- `REQ-002`: `_format_chunks()` must use `c.content` (not `c.normalized_content`) when formatting chunks for LLM presentation
- `REQ-003`: The monotonicity invariant applies regardless of whether the source type has a `normalized_content` attribute

## Design
The existing `TestFormatChunksDesign2` class in `tests/rag/test_rag_pipeline.py` (lines 130-161) covers:
- Verifying `content` text appears in output (via `test_content_appears_in_output`)
- Verifying a string that happens to look like normalized content doesn't appear (via `test_normalized_content_does_not_appear`)
- Verifying when normalized != content, normalized doesn't appear (via `test_normalized_differs_from_content_not_in_output`)

However, these tests use `RankedHit` which does NOT have a `normalized_content` attribute. So they can't actually construct a chunk with differing `content` and `normalized_content` values — they only verify that a string that happens to look like normalized content isn't present.

The gap analysis focuses on:
1. **Explicit normalized_content rejection**: Test that even when a chunk has both `content` and `normalized_content` attributes set differently, only `content` appears in the output
2. **Mock-based verification**: Since `RankedHit` lacks `normalized_content`, the test will need to construct a mock object with both fields set differently
