## Problem
`ChunkJapaneseMixin._emit_and_start_new()` (`scripts/rag/ingestion/chunk_japanese.py`
lines 107-119) duplicates the overlap-buffer-start logic that
`chunk_utils.start_next_buf()` already implements and that `ChunkEnglishMixin`
(`chunk_english.py` line 65) already reuses:

```python
def _emit_and_start_new(self, orig: str, norm: str) -> None:
    """Emit buffer as chunk and start new buffer with overlap."""
    self._result.append((self._orig_buf, self._norm_buf))
    if self._chunk_overlap:
        self._orig_buf = (
            self._orig_buf[-self._chunk_overlap :] + " " + orig
        ).strip()
        self._norm_buf = (
            self._norm_buf[-self._chunk_overlap :] + " " + norm
        ).strip()
    else:
        self._orig_buf = orig
        self._norm_buf = norm
```

This duplicated logic risks silently diverging from `start_next_buf()` if either is
edited independently in the future (the exact risk the Issue names for L-6).

Separately, Step 2 verification found the Issue's L-1 claim is now stale: `rg -n
"RegisteredDocument" --type py` and `rg -n "MqeConfig|FusionConfig" --type py` return no
matches under `scripts/` or `tests/` (only a tracked `mutants/` mutation-testing
snapshot tree still contains the old `RegisteredDocument` definition — that tree is a

## Reason for change
Reduce the risk of the Japanese and shared chunking logic silently diverging, and
retire duplicated code the codebase already intended to consolidate.

## Implementation intent
Replace the two duplicated overlap-slicing branches in `_emit_and_start_new()` with two
calls to the already-shared `start_next_buf()` helper (one per parallel buffer:
`_orig_buf`, `_norm_buf`), matching the pattern `ChunkEnglishMixin` already uses.
Preserve behavior exactly: `start_next_buf(prev, next_item, sep, chunk_overlap)`
returns `next_item` unchanged when `chunk_overlap` is falsy, and otherwise prepends
`prev`'s trailing `chunk_overlap` characters (dropping the separator entirely when that
trailing slice is empty) — behaviorally equivalent to the current inline code's
`(prev[-chunk_overlap:] + sep + next_item).strip()`, since `.strip()` removes the
leading separator in the empty-slice case. No change to `chunk_utils.py`'s public
functions, `chunk_english.py`, or `chunk_splitter.py` is required.

## Design
`ChunkJapaneseMixin` is mixed into `ChunkSplitter` alongside `ChunkEnglishMixin`
(`scripts/rag/ingestion/chunk_splitter.py` line 62). `ChunkEnglishMixin` already
imports and calls `start_next_buf(buf, para, "\n", self._chunk_overlap)`
(`chunk_english.py` lines 14, 65) for its single-buffer paragraph accumulation.
`ChunkJapaneseMixin` accumulates two parallel buffers (`_orig_buf` for the original
text, `_norm_buf` for the Sudachi-normalized text) because
`_merge_ja_sentence_pairs()` operates on `(original, normalized)` sentence pairs
rather than a flat list of strings — this is why it cannot directly reuse
`merge_text_items()` (which assumes a single `list[str]`), but it can reuse
`start_next_buf()` twice (once per buffer) since that helper is already generic over
separator and overlap length and does not assume single-buffer state.

The fix is confined to `_emit_and_start_new()`:

```python
def _emit_and_start_new(self, orig: str, norm: str) -> None:
    """Emit buffer as chunk and start new buffer with overlap."""
    self._result.append((self._orig_buf, self._norm_buf))
    self._orig_buf = start_next_buf(self._orig_buf, orig, " ", self._chunk_overlap)
    self._norm_buf = start_next_buf(self._norm_buf, norm, " ", self._chunk_overlap)
```

requiring one new import: `from rag.ingestion.chunk_utils import start_next_buf`.
`_reset_buffer()` and `_append_to_buffer()` are unaffected — they contain no overlap
logic and have no equivalent in `chunk_utils.py`.
