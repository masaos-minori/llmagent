## Goal

Correct three documentation files that falsely claim `build_agent_config()` enforces a
`_FORBIDDEN_KEYS`-based `ConfigLoadError` rejection of the `workflow_mode` (and
`workflow_require_approval`) config keys. Git history confirms this mechanism was real
but was deliberately removed on 2026-07-19 (commit `9711ca96`) because "Pydantic
dataclasses silently ignore unknown fields, making explicit key rejection checks
redundant." The removal commit updated two related docs but missed three others, which
is the direct cause of this documentation drift. This plan implements **Path 1
(documentation-only fix)**: align the three stale docs with current, intended behavior
(`workflow_mode` is not read by any config builder and is silently ignored if present),
consistent with the sibling doc `docs/05_agent_08_01_configuration-loading-agent-config-part1.md`,
which was already corrected in the same removal commit and contains no `_FORBIDDEN_KEYS`
mention today.

  claim; state that `workflow_mode` is not a recognized config key and is silently ignored

  rationale is intact.

  smaller-scale version of the same drift this plan is meant to fix. → **Mitigation**: Phase 1
  requires re-reading part1.md in full immediately before editing part2.md, and Phase 3 requires
  an explicit side-by-side re-read of both files' `workflow_mode` sections as a validation step.

  runtime config-file validation," and treat this as optional/skippable if it cannot be phrased

  mention.
- **Risk**: This plan does not re-verify whether other docs outside the three named targets also
  reference `_FORBIDDEN_KEYS` (only `scripts/`/`tests/` were grepped in the requirement's own
  investigation, not the full `docs/` tree, until Phase 1 of this plan). If additional stale docs
  exist, the fix would be incomplete. → **Mitigation**: Phase 1's `grep -rn "_FORBIDDEN_KEYS" docs/`
  step is mandatory before editing and its result must be reconciled against the three named
  files; if it surfaces extra hits, they must be added to scope before Phase 3 sign-off. This is
