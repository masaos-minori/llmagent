## Background
`docs/04_mcp_90_inconsistencies_and_known_issues.md`'s `GIT-001` (Dirty-Worktree/Detached-HEAD guards) and `GIT-002` (postcondition verification) are both marked `Status: open`, but direct code inspection confirms both are already implemented in `scripts/mcp_servers/git/git_service.py` and `format_output.py`. The implementation and archival of the corresponding issues (`issues/done/20260823_git_dirty_worktree_detached_head_issue.md` and `issues/done/20260823_git_postcondition_verification_issue.md`, dated 2026-08-23) did not include updating these tracking documents, causing them to fall out of sync. `ADR-012`'s Known Deviations section also lists `GIT-001` and `GIT-002` as open gaps and likely needs the same correction.

## Problem
Confirmed by reading current source code:

- **GIT-001 stale**: `git_checkout` and `git_pull` both call `self._check_dirty_worktree(repo)` and `self._check_detached_head(repo)` before proceeding (unless `dry_run` is set), returning the guard's error if either check fails. Current code: `scripts/mcp_servers/git/git_service.py::git_checkout()` (lines 246-253) and `git_pull()` (lines 278-285). `_check_dirty_worktree()` (`git_security.py:64-71`) returns `(False, "[DENIED] worktree has uncommitted changes")` when dirty; `_check_detached_head()` (line 73-80) returns `(False, "[DENIED] repository is in a detached HEAD state")` when detached and `allow_detached_head` is False. The issue's Observed Implementation claim ("calls `git reset --hard` unconditionally" / "calls `git pull` without checking for uncommitted changes") predates this change.
- **GIT-002 stale**: `format_checkout()` (lines 135-141) verifies the resulting branch/detached-HEAD state and raises `GitServiceError` on mismatch; `format_pull()` (lines 156-159) checks for unresolved merge conflicts and raises on detection; `format_push()` (lines 169-173) scans for push-rejection markers and raises if found. The issue's Observed Implementation claim ("returns success ... without verifying the branch actually changed" / "returns success ... without verifying the remote refs updated") predates this change.
- **ADR-012 Known Deviations stale**: Lines 181-182 still list both `GIT-001` and `GIT-002` as unqualified open gaps despite the implementations above.
- **Security policy doc stale**: `docs/00_security_02_high-risk-tool-common-policy.md` line 187 states "Dirty-Worktree/Detached-HEAD/postcondition verification gaps remain open (tracked as Known Issues `GIT-001`/`GIT-002`)" — this statement is now incorrect.
- **Tests exist and pass**: `test_git_checkout_dirty_worktree_denied`, `test_git_pull_dirty_worktree_denied`, `test_git_checkout_detached_head_denied`, `test_git_pull_detached_head_denied` (in `test_git_security_compliance.py`, GIT-001) and `test_checkout_postcondition_failure_wrong_branch`, `test_checkout_postcondition_failure_detached_head`, `test_pull_postcondition_failure_unresolved_conflicts`, `test_push_postcondition_failure_rejection_marker_in_output` (in `test_format_output.py`, GIT-002). These were confirmed at issue-drafting time; re-confirm at implementation time since the repo has other sessions actively modifying it concurrently.

## Reason for change
Known Issues that are actually already resolved but still marked `open` mislead anyone (human or AI) using this document to scope future Git MCP work — as happened while drafting `NC-019` in this same session, where the stale status caused an issue to be drafted against work that was already done. Correcting this prevents duplicate effort and keeps the Known Issues doc usable as a source of truth for what is actually still open (per this doc's own purpose).
