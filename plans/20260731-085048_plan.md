# Work Plan: Fix MCP Subprocess Group Leak on Shutdown

## Status: DEFERRED

This plan has been deferred after code review. See "Deferred Decision" section below.

## Goal

Ensure all MCP subprocesses and their descendants are properly terminated during shutdown, even when `getpgid()` fails.

## Scope

- Modify `scripts/agent/http_lifecycle.py` to handle `getpgid()` failure cases
- Optionally modify `scripts/agent/repl.py` to use process group termination
- Add tests for shutdown behavior

## Assumptions

1. `psutil` can be added as a dependency for reliable process tree termination
2. The `_http_pgids` dictionary is the primary mechanism for tracking process groups
3. `start_new_session=True` creates new session leaders that won't be in the agent's process group

## Design

### Recommended Approach: Use psutil for reliable process tree termination — DEPRECATED

Since `start_new_session=True` creates new session leaders that won't be in the agent's process group, both Option A (psutil) and Option B (fallback to agent's process group) have limitations:

- **Option A (psutil):** Works regardless of process group membership, but requires adding a new dependency
- **Option B (fallback):** Won't work because the subprocess is not in the agent's process group

**Decision:** Option A was necessary. However, this approach has been deprecated due to dependency concerns. See "Deferred Decision" below.

### Implementation Steps

#### Step 1: Verify psutil availability

Check if psutil is already installed:
```bash
python -c "import psutil"
```

If not available, add it to dependencies.

#### Step 2: Add `_kill_process_tree()` function

In `http_lifecycle.py`, add:

```python
def _kill_process_tree(pid):
    """Kill a process and all its descendants."""
    import psutil
    
    try:
        parent = psutil.Process(pid)
        children = parent.children(recursive=True)
        
        # Send SIGTERM to all descendants first
        for child in children:
            try:
                child.send_signal(signal.SIGTERM)
            except psutil.NoSuchProcess:
                pass
        
        # Then send SIGTERM to parent
        parent.send_signal(signal.SIGTERM)
        
        # Wait for termination with timeout
        gone, alive = psutil.wait_procs(children + [parent], timeout=5)
        
        # Force kill any remaining
        for p in alive:
            try:
                p.kill()
            except psutil.NoSuchProcess:
                pass
    except psutil.NoSuchProcess:
        pass
```

#### Step 3: Replace `os.killpg()` with `_kill_process_tree()` in shutdown

Replace the current shutdown logic:

```python
# Before (problematic):
pgid = self._http_pgids.get(server_key)
if pgid:
    os.killpg(pgid, signal.SIGTERM)

# After (robust):
proc = self._procs.get(server_key)
if proc is not None:
    _kill_process_tree(proc.pid)
```

Also update the error handling path where `getpgid()` fails:

```python
try:
    self._http_pgids[server_key] = os.getpgid(proc.pid)
except OSError:
    logger.warning(
        "Lifecycle: getpgid() failed for %r pid=%d; using process tree kill",
        server_key,
        proc.pid,
    )
    # Don't call _terminate_with_timeout here — it will be handled by shutdown
```

#### Step 4: Update repl.py shutdown logic

Verify if `repl.py` also starts subprocesses with `start_new_session=True`. If so, apply similar fix.

#### Step 5: Add tests

- Test shutdown with `getpgid()` failure scenario
- Test that process tree is fully terminated
- Test normal shutdown path (no regression)

## Deferred Decision

After code review, this plan has been deferred. The current design is acceptable:

- Current implementation: `_http_pgids` が空の場合でも `proc.terminate()` が実行される
- This means the parent process is always terminated, even without process group ID
- Child processes may remain, but this is an acceptable trade-off for avoiding a new dependency

### Alternative approach (no psutil required):

1. **Current code maintenance** — Keep existing `_http_pgids` logic
2. **Add warning log** — When `proc.terminate()` succeeds but children may remain, add a warning log
3. **Document limitation** — Clarify that "when `start_new_session=True` is used, child processes may not be cleaned up via process group termination"

## Validation Plan

1. Unit tests: Verify process tree termination when `getpgid()` fails
2. Integration tests: Verify no zombie processes after shutdown
3. Manual testing: Start MCP servers, shut down, verify no leftover processes
4. Regression testing: Verify normal shutdown path works correctly

## Risks

| Risk | Mitigation |
|------|------------|
| psutil not available in production environment | Check dependencies before implementation; consider alternative approaches |
| Killing process tree may affect unrelated processes | Document risk; ensure MCP subprocesses don't share process groups |
| SIGTERM/SIGKILL timing issues | Use proper wait/probe mechanism; document expected behavior |
| Changes to shutdown order may cause other issues | Thorough testing of shutdown sequence |
