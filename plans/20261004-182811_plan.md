# Plan: Replace universal task cancellation with tracked-task-only cancellation

## Goal
Only cancel tracked background tasks during shutdown instead of all pending tasks, preventing data loss from mid-flight critical operations.

## Priority
High

## Scope
- **In-Scope**: Modify `ResourceShutdownCoordinator.close_resources()` to use `turn.background_tasks` instead of `asyncio.all_tasks()`; add regression tests
- **Out-of-Scope**: Changes to WAL checkpoint logic (already correctly placed before cancellation); changes to the shutdown sequence ordering

## Background
`ResourceShutdownCoordinator.close_resources()` in `scripts/agent/resource_shutdown_coordinator.py` coordinates resource shutdown during REPL exit. It cancels pending tasks after WAL checkpoint completes.

## Problem
The method uses `asyncio.all_tasks(loop)` to get all pending tasks and cancels them all indiscriminately. This includes tasks that may be critical for data integrity, such as history-write tasks that are mid-operation.

## Reason for change
History write operations may be cancelled mid-flight, losing data. Any task spawned during the turn loop could be affected. The LIFO ordering claim provides no guarantee of correctness.

## Implementation intent
Replace the `asyncio.all_tasks()` iteration with the `turn.background_tasks` set tracked by the Orchestrator. Clear the set before cancelling to prevent double-cancellation.

## Requirements
- `REQ-001`: Only tracked background tasks are cancelled
- `REQ-002`: Critical operations (WAL checkpoint, history flush) are not cancelled
- `REQ-003`: Test verifies no data loss during shutdown with active history writes
- `REQ-004`: Test verifies cancellation of background-only tasks
