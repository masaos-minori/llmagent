## Goal

## Background

The RAG ingestion pipeline declares TypedDicts (`CrawlJsonPayload`, `ChunkJsonPayload`, `ChunkJsonRaw`) in `scripts/rag/ingestion/pipeline_utils.py` as strict interface specifications for crawl and chunk JSON payloads. However, `scripts/rag/ingestion/chunk_splitter.py` does not use these TypedDicts as type annotations — instead it processes data via `ChunkDocument` (from `models_data.py`) or `dict[str, object]`. This creates a gap between documented contract and actual behavior.

## Problem

TypedDicts declared in `pipeline_utils.py` serve as interface specifications but aren't enforced at runtime in `chunk_splitter.py`. This means:
- Type checking tools won't catch violations of the TypedDict contract in chunk_splitter.py
- Future developers may assume the TypedDicts are enforced when they're not
- The interface specification becomes stale without enforcement

Additionally, the existing documentation references TypedDict names (`CrawlFilePayload`, `ChunkOutputPayload`) that differ from the actual TypedDict names in the codebase (`CrawlJsonPayload`, `ChunkJsonPayload`).

## Reason for change

The TypedDict declarations represent intentional design decisions about data contracts. Without enforcement or clear documentation of their purpose, they become misleading rather than helpful.

## Implementation intent

Evaluate which approach best serves the project's needs: enforce the TypedDicts in chunk_splitter.py (option 1), remove them if they're no longer needed (option 2), or document them as interface specifications only (option 3). The decision should be based on whether TypedDict enforcement would improve type safety without introducing unnecessary coupling.

## Requirements

- `REQ-001`: Determine which of the three approaches (enforce TypedDict, remove declarations, or document as interface spec) is appropriate

- `REQ-003`: If removing declarations: delete the TypedDict declarations from pipeline_utils.py and update all references
- `REQ-004`: If documenting as interface spec: add clear documentation explaining the TypedDicts' role as interface specifications, not runtime-enforced types
- `REQ-005`: Update `docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md` to correct the TypedDict name discrepancy and reflect the chosen resolution
- `REQ-006`: Ensure any type annotation additions pass mypy validation

## Design

This is a Path A task (small scope: ≤ 3 files, no public interface changes, no DB schema changes). However, the decision point (which of three approaches to take) introduces some complexity. The design follows these principles:

1. **Decision-first approach**: Before implementing any option, determine which is most appropriate based on:
   - Whether TypedDict enforcement would provide meaningful type safety benefits
   - Whether the cost of adding type annotations outweighs the benefit
   - Whether the TypedDicts serve a valid purpose as interface specifications even without enforcement

2. **Evidence-based comparison**: Compare the TypedDict schemas against `ChunkDocument` to assess redundancy (UNK-02). If `ChunkDocument` already provides equivalent type safety, TypedDict enforcement may be unnecessary.

3. **Minimal coupling**: If enforcing TypedDicts, ensure the dependency direction is correct — `chunk_splitter.py` should depend on `pipeline_utils.py`'s TypedDicts, not vice versa.

4. **Documentation accuracy**: Always correct the TypedDict name discrepancy regardless of the chosen approach.

Evidence grounding:
- `pipeline_utils.py:23-51`: `CrawlJsonPayload` (8 required keys) and `ChunkJsonPayload` (13 required keys) — strict TypedDicts with no optional fields
- `pipeline_utils.py:236-256`: `ChunkJsonRaw` — relaxed TypedDict with `NotRequired` fields for flexibility
- `chunk_splitter.py:25-29`: imports `read_crawl_json` from pipeline_utils but doesn't use TypedDicts directly
- `chunk_splitter.py:30`: uses `ChunkDocument` from models_data for internal processing
- `models_data.py`: `ChunkDocument` dataclass likely provides equivalent type safety to `ChunkJsonPayload`
