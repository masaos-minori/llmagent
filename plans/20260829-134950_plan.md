# MCP-003: Git Write Protection Pipeline — RepositoryState-Based Unification

**Issue:** MCP-003
**Priority:** High

## Goal

Eliminate redundant ad hoc `git.Repo` queries across write-protection guards by introducing a single shared `RepositoryState` dataclass and a 9-stage pipeline that unifies dirty-worktree checks, detached-HEAD detection, command-specific preconditions, postcondition verification, and audit logging.

## Scope

- **Add:** New `scripts/mcp_servers/git/repository_state.py` module with `RepositoryState` dataclass and pipeline orchestration
- **Modify:** `git_service.py`, `git_security.py`, `format_output.py`, `git_models.py`, `git_server.py`, `dispatch.py`, `audit.py`
- **Add:** Tests under `tests/mcp_servers/git/test_repository_state.py`
- **Update:** ADR-012 to reflect new pipeline architecture

## Background

The current write-protection implementation scatters `git.Repo` queries across multiple modules:

| File | Scattered Checks |
|------|------------------|
| `git_service.py` | `_check_dirty_worktree()`, `_check_detached_head()`, `_is_safe_ref()`, `_validate_ref()`, `_validate_protected()` |
| `git_security.py` | `_check_repo_path()`, `_check_protected_branch()` |
| `format_output.py` | `repo.is_dirty()`, `repo.active_branch.name`, `repo.untracked_files` in `format_checkout/pull/push` |
| `git_server.py` | `call_tool()` endpoint handler |

Each guard independently instantiates `git.Repo(path)` and runs its own queries, leading to duplicate work, inconsistent state snapshots, and no shared repository-state model reused across guards, verification, audit, and tests.

## Problem

1. **Duplicate instantiation:** Each guard calls `git.Repo(path)` separately — same filesystem traversal, same object creation overhead
2. **Inconsistent snapshots:** Guards may observe different repo states if the repo is modified between calls
3. **No shared model:** No single dataclass captures the full set of properties needed by all stages (dirty flag, HEAD type, branch name, untracked files, etc.)
4. **Scattered logic:** Command-specific preconditions live in different files without a unified ordering guarantee
5. **Audit gaps:** Postcondition verification results are not consistently logged alongside preconditions

## Reason for Change

This is a maintainability and consistency investment. It reduces code duplication, ensures consistent state observation, and provides a clear extension point for future guards. It does NOT supersede NC-019/NC-020 decisions — scope overlaps explicitly gated on their own outcomes.

## Implementation Intent

Introduce a 9-stage pipeline built on a shared `RepositoryState` dataclass:

```
Stage 1: Schema validation (tool input validation)
Stage 2: Repository resolution (git.Repo instantiation + cache)
Stage 3: Common authorization (path existence, permissions)
Stage 4: State snapshot (single git.Repo query → RepositoryState)
Stage 5: Command-specific precondition (dirty check, branch check, etc.)
Stage 6: Execution (the actual git operation)
Stage 7: Postcondition verification (verify expected state change)
Stage 8: Audit (log pre/post conditions)
Stage 9: Structured result (DispatchResult with state metadata)
```

## Design

### `RepositoryState` Dataclass

```python
@dataclass(frozen=True)
class RepositoryState:
    path: str
    is_dirty: bool
    head_type: Literal["detached", "branch"]
    active_branch: str | None
    untracked_file_count: int
    protected_branch: bool
    ref_valid: bool
    _repo: git.Repo | None = field(default=None, repr=False, compare=False)

    @classmethod
    def snapshot(cls, repo_path: str) -> "RepositoryState":
        """Capture full state from a single git.Repo query."""
        repo = git.Repo(repo_path)
        return cls(
            path=repo_path,
            is_dirty=repo.is_dirty(indexed_working_tree=True),
            head_type="detached" if repo.head.is_detached else "branch",
            active_branch=repo.active_branch.name if not repo.head.is_detached else None,
            untracked_file_count=len(repo.untracked_files),
            protected_branch=_is_protected_branch(repo),
            ref_valid=_is_safe_ref(repo),
            _repo=repo,
        )
```

### Pipeline Orchestrator

```python
class WriteProtectionPipeline:
    def __init__(self, state: RepositoryState):
        self.state = state

    def run(self, command: str, operation: Callable[[], GitOperationResult]) -> DispatchResult:
        # Stage 1: Schema validation (already done by caller)
        # Stage 2: Repository resolution (already done — state captured)
        # Stage 3: Common authorization
        self._verify_authorization()

        # Stage 4: State snapshot (already done — passed as constructor arg)
        # Stage 5: Command-specific precondition
        self._verify_preconditions(command)

        # Stage 6: Execution
        result = operation()

        # Stage 7: Postcondition verification
        self._verify_postcondition(result)

        # Stage 8: Audit
        self._audit(result)

        # Stage 9: Structured result
        return self._structured_result(result)
```

### Key Design Decisions

1. **Frozen dataclass**: `RepositoryState` is immutable after snapshot — prevents accidental mutation between stages
2. **Single source of truth**: One `git.Repo` query per request — eliminates duplicate instantiation
3. **Early exit**: Pipeline rejects at Stage 5 if preconditions fail — execution never runs
4. **Backward compatibility**: Existing guard methods delegate to `RepositoryState` properties rather than being replaced wholesale
