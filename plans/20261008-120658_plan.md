## Goal
- Make `/subscribe` replay every event it must deliver on reconnect, for all three resume sources and for backlogs larger than one replay batch, without duplicates inside one connection and without changing the public `since_seq` meaning; align tests and documentation to one predicate.

## Priority
High

## Scope
- **In-Scope**: the replay predicate and the replay batching/handoff logic in the subscribe route; end-to-end tests for each resume source and for multi-batch backlogs; correcting the stale test expectation and the two placeholder tests; the misleading code comment; the two EventBus documents that describe the predicate.
- **Out-of-Scope**: ACK/NACK/offset write paths, DLQ, the consumer-offset schema, the replay route, the resume-position helper's return semantics (unless analysis shows it is the better single point of change), authentication, and the timing-out transition tests (a separate issue that this fix may resolve).

## Background
The issue was filed from a documentation review (items H07/M21) because `start_seq` appears to hold an inclusive resume position while the replay query is exclusive. Delivery is specified as At-Least-Once (duplicates allowed, loss not allowed).

## Problem
Confirmed by an end-to-end probe against the production application (run outside the repository):
- With the default batch size, `Last-Event-ID: 1` over events 1 to 8 replays 3..8, so event 2 is skipped (the `Last-Event-ID + 1` start is treated as exclusive). `since_seq=2` replays 3..8 correctly.
- With a small batch size (3), the replay loop is also wrong independently of the resume source: `since_seq=0` over events 1 to 8 emits 1, 2, 3, 3, 4 and then stops (a duplicate and events 5 to 8 lost); `since_seq=2` emits 3, 4, 5, 4, 5; `Last-Event-ID: 1` emits 3, 4, 5, 4, 5. The loop sets its ceiling from the first emitted seq and advances `start_seq` from that ceiling instead of from the last emitted seq, so it repeats and then truncates a backlog larger than about two batches.
- The existing test for the `Last-Event-ID` fallback asserts the skip (first replayed seq is 3 for `Last-Event-ID: 1`); the two offset-resume tests are placeholders; the code comment describes the resume position as a maximum, which does not match the helper (lowest unacked seq, else stored offset + 1).
- The offset-based resume sources were verified by code reading only; the Plan requires an end-to-end test first.

## Reason for change
Events can be silently lost on reconnect, which contradicts At-Least-Once, and a backlog larger than a couple of batches is truncated even without any resume position. A test currently locks in one defect, so a code-only fix would fail CI.

## Implementation intent
- Write the failing end-to-end tests first (each resume source; backlog larger than a batch; first-event identity; no duplicates; handoff to live).
- Choose one meaning for the route's lower bound and apply it consistently: keep an exclusive lower bound for `since_seq`, convert inclusive resume positions (resume helper, `Last-Event-ID + 1`) to exclusive at assignment, and advance the batch cursor from the last emitted seq; make the live-phase duplicate filter use the last replayed seq.
- Keep the 412 behavior, precedence (`since_seq`, then resume position, then `Last-Event-ID`), and the replay route unchanged.

## Requirements
- `REQ-001`: Reconnect with in-order ACKs up to N replays event N+1 first; reconnect after an out-of-order ACK replays the lowest unacked event first (included); `Last-Event-ID: L` replays event L+1 first; `since_seq=N` still replays `seq > N`.
- `REQ-002`: A backlog larger than the replay batch is replayed completely and in order, with no duplicate within one connection, and the live phase does not re-emit replayed events.
- `REQ-003`: Add end-to-end tests through the subscribe endpoint for REQ-001 and REQ-002 (including a small batch size), correct the stale `Last-Event-ID` expectation, and replace the two placeholder tests with real tests.
- `REQ-004`: Correct the misleading comment in the subscribe route.
- `REQ-005`: The two EventBus documents describe one consistent predicate and one resume rule, including the batch advance.
- `REQ-006`: Existing EventBus tests that pass today still pass; lint, type, security, and doc checks introduce no new findings.

## Design
Path B (five files). Architecture: the subscribe route sits inside the isolated `eventbus` package and only uses its own database helpers and the in-process broker; no new imports are needed. Dependency graph: the route is imported by the application module and exercised by about five EventBus test modules. History: the route and its tests are high-churn and single-author. Operational: no live process inspection is needed in this document-only phase; the fix requires an EventBus restart when deployed, and in-flight SSE clients reconnect. The chosen design keeps the replay predicate exclusive and converts inclusive resume positions at assignment, so the `since_seq` contract and the helper stay unchanged; the batch cursor advances from the last emitted seq and the live-phase filter uses the last replayed seq. The Python validation baseline (radon, vulture, bandit) applies to the subscribe route at implementation time. The pre-existing import-contract and tracer type-check findings are unrelated.
