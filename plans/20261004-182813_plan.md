# Plan: Remove tracking entries only after confirmed process exit

## Goal
Only remove tracking entries after confirming the process has exited, preventing orphaned processes when getpgid failure leads to failed termination.

## Priority
High

## Scope
- **In-Scope**: Modify `_create_and_validate_proc()` to conditionally remove tracking entries based on termination success; add regression tests
- **Out-of-Scope**: Changes to ProcessTerminator.terminate_with_timeout() behavior; changes to subprocess creation parameters

## Background
`HttpServerLifecycleManager._create_and_validate_proc()` in `scripts/agent/http_lifecycle.py` creates a subprocess, validates its command, and records its process-group ID via `os.getpgid()`.

## Problem
When `getpgid()` fails after the subprocess has been created, the code attempts cleanup but the process itself may still be running. The tracking entries are removed, but the process continues without being tracked.

## Reason for change
If `terminate_with_timeout()` fails (e.g., permission denied), the process runs untracked. The subprocess consumes resources indefinitely. Subsequent health checks will fail silently because the key is no longer tracked.

## Implementation intent
Move the tracking entry removal from the finally block into a conditional path that only executes after confirming the process has actually exited. On termination failure, keep the tracking entries and log the PID for manual intervention.

## Requirements
- `REQ-001`: Tracking entries are removed only after confirmed process exit
- `REQ-002`: Failed termination leaves process PID logged for manual intervention
- `REQ-003`: Test verifies no orphaned process after getpgid failure scenario
- `REQ-004`: Test verifies tracking entry persists when termination fails
