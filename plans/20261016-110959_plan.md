## Goal
- Restrict the environment inherited by HTTP-subprocess MCP servers to an explicit allowlist and stop logging raw env values, so parent-process secrets are not leaked into the subprocess or persisted in plaintext in the agent log.

## Priority
Medium

## Scope
- **In-Scope**:
  - Rewrite `CommandValidator.filter_env` to a default-deny model: inherit only an explicit allowlist of safe parent variables plus the server's configured `env`; drop all other inherited parent variables.
  - Redact logging: when blocking a protected-var override, log only the key name, never the value.
  - Preserve blocking of `LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH` (denylist) and protected-var overrides as an additional filter layer.
  - Preserve `filter_env(None)` returning `None`.
  - Add a module-level `_DEFAULT_ALLOWED_ENV_VARS` allowlist (provisional set, finalized from production config).
  - Update the validator docstring and the affected unit tests; add allowlist/redaction/`None` tests.
- **Out-of-Scope**:
  - Changes to command validation, subprocess launch, health polling, or process termination.
  - Changes to the `_ENV_KEY_DENYLIST` contents (kept unchanged; applied as a filter layer).
  - Per-server configurable allowlist (decided: fixed global set — see Unknowns UNK-02).

## Background
`CommandValidator.filter_env` (`scripts/agent/http_lifecycle_command_validator.py` lines 134-152) is called from `_create_and_validate_proc` (`scripts/agent/http_lifecycle.py` line 275) to prepare the environment for `subprocess.Popen`. It starts from `result = dict(os.environ)`, deletes keys matching `_ENV_KEY_DENYLIST` (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH`), then merges the server's configured `env`, logging a warning for each blocked protected-var override.

## Problem
Verified against the code on 2026-10-16:
- Line 143: `result = dict(os.environ)` copies every variable in the parent environment (e.g. cloud credentials, API tokens, `AWS_*`, `GITHUB_TOKEN`) into the child. Only `LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH` (denylist) plus the server `env` survive; there is no positive allowlist of what the subprocess may receive.
- Lines 148-150: `logger.warning("Blocked protected env var override: %s=%s", key, value)` writes the full secret value of the blocked override to the log. If an admin places a secret in a protected var (or an attacker injects one), it is persisted in plaintext in the agent log.
- Impact: MCP subprocesses are semi-trusted admin-configured processes; passing the parent's full environment and logging protected-var values widens the secret-exposure surface beyond the intended denylist.

## Reason for change
The default-allow approach (inherit everything except a short denylist) leaks broadly and logs secrets. A default-deny allowlist plus no-secret-in-logs is materially safer.

## Implementation intent
Replace the copy-`os.environ`-then-strip model with an explicit allowlist of safe variables (e.g. `PATH`, `TEMP`, `TMP`, `SYSTEMROOT`, locale vars) plus the server's configured `env`; remove anything not on the allowlist. Never log raw env values — log only the key name when blocking an override. Keep the existing denylist and protected-var semantics as an additional filter layer. Gate the change behind production-config verification of the minimal required variable set (see Unknowns).

## Design
- **Default-deny inheritance.** `filter_env` builds `result` from an explicit allowlist: for each key in `_DEFAULT_ALLOWED_ENV_VARS`, copy it from `os.environ` if present. This replaces `result = dict(os.environ)` (line 143). Parent variables not on the allowlist are never copied.
- **Server-env merge with filters.** Merge the server's `env`: skip keys matching `_ENV_KEY_DENYLIST` (blocks `LD_PRELOAD`/`LD_LIBRARY_PATH`/`PYTHONPATH` even when set by config); skip protected-var overrides, logging only the key name; otherwise set the key. This keeps the denylist and protected-var semantics as an additional layer over the allowlist.
- **Redacted logging.** Replace `logger.warning("Blocked protected env var override: %s=%s", key, value)` with `logger.warning("Blocked protected env var override: %s", key)` — the value is never formatted into the log.
- **`None` passthrough.** Keep the early `return None` for `env is None` (line 140-141).
- **Allowlist contents.** `_DEFAULT_ALLOWED_ENV_VARS` is a module-level constant (like `_DEFAULT_ALLOWED_COMMANDS`), initialized conservatively and finalized from production config (`UNK-01`).
- **Import-linter.** No new imports are introduced; the existing `from shared.mcp_config import _ENV_KEY_DENYLIST` stays. The 6 existing contracts remain KEPT. No new module/package.

## Risks
- **Risk**: A too-restrictive `_DEFAULT_ALLOWED_ENV_VARS` breaks server startup for servers that rely on inheriting a non-allowlisted parent variable. → **Mitigation**: determine the minimal required variable set from production configs/running servers before finalizing (`UNK-01`); add a regression test asserting the required vars (`PATH`, etc.) are passed (`AC-003`); verify against running configs post-deploy.
- **Risk**: Logging the key name could still reveal a secret's purpose/category. → **Mitigation**: log only the bare key name with no value or context; the previous plaintext-value persistence is removed, which is the primary exposure.
- **Risk**: Merging all server-configured `env` re-introduces exposure if the config file is writable by an untrusted party. → **Mitigation**: config files are admin-controlled (existing threat model); restricting server `env` is out of scope for this issue.
- **Risk**: The three existing `TestCommandValidatorFilterEnv` tests encode the old default-ALLOW contract and will fail under default-deny. → **Mitigation**: explicitly update/remove those three tests as Phase 3 Step 1 (`AC-001`..`AC-003`).
