## Background
NC-041 is registered as an active Needs Confirmation item in `docs/00_governance/governance_03_issue-and-uncertainty-management.md`. The classification table in `docs/23_agent/agent_08_04_configuration-mcp-approval-obs.md` records `github` as `required` ("Not assessed as satisfying Decision Group 3 item 10; status quo default"). `config/agent.toml` currently sets `required = false` and `startup_mode = "none"` for `[mcp_servers.github]`, introduced by commit `4e2442a75` ("disable the github MCP server until GITHUB_TOKEN is provisioned"). ADR-004 Decision #13 requires the `required` field to match the classification table and states that configuration alone cannot weaken a mandatory component without an approved architecture or specification change.

## Problem
The classification table and the deployed configuration disagree for `github`: the table classifies it `required` while `config/agent.toml` sets `required = false`. It is unknown whether the disabled-state handling was assessed against ADR-004 Decision Group 3 item 10, and no owner decision accompanies the configuration change.

## Reason for Change
An unresolved disagreement between an Accepted ADR contract and effective configuration is a canonical source conflict that startup validation may treat inconsistently. The active NC item has no assigned owner.

## Implementation Intent
Obtain an owner decision first; do not infer it. Then apply exactly one of two outcomes:

- **Reclassify**: update the `github` row of the classification table with a Decision Group 3 item 10 assessment (criteria met or not, observability of the disabled state, Fail-Closed rejection of calls), keeping `config/agent.toml` as is.
- **Restore**: set `required = true` in `config/agent.toml` with an appropriate `startup_mode` once `GITHUB_TOKEN` is provisioned, leaving the classification table unchanged.

Either outcome leaves ADR-004 Decision text unchanged.
