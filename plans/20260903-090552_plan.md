## Problem
Investigation during this Plan's Step 2/3 (see Repository Evidence in
Implementation Target Files below) found: (1) the three dependency Plans already
each specify adding a Known Issue entry to their own area's inconsistencies-and-
known-issues document (`ragcontract` → `docs/03_rag_90_...`, `ragfreshness` →
same file, `toolroutedoc` → `docs/04_mcp_90_...`) — none of these three planned
entries currently exist yet, so no duplication exists today, but the entries are
each destined for a canonical location already, one per topic; (2) no current
document was found that misclassifies static `ToolRegistry` as an obsolete routing
layer — `docs/90_shared_90_inconsistencies_and_known_issues.md`'s `CI-010` and
`docs/adr/ADR-003-runtime-tool-registry-routing-authority.md` both already state
`ToolRegistry` is not a routing fallback; (3) `docs/00_governance_03_issue-and-uncertainty-management.md`'s
"Needs Confirmation Inventory" Active Items list only `NC-020` and `NC-021`, neither
related to RAG artifact-versioning; (4) `scripts/rag/ingestion/pipeline_utils.py`'s
`ChunkJsonRaw` TypedDict already comments `artifact_type`/`schema_version`/
`created_by` as `"ingestion-pipeline metadata only; not persisted to DB"`, and
`ragcontract`'s Plan already treats making them mandatory as explicitly
Out-of-Scope — so the "artifact-versioning" contract question this Issue raises may
already be sufficiently resolved by that comment, pending confirmation once
`ragcontract` lands (see `UNK-01`).
