## Background
A recent docs/ folder reorganization (docsreorg01/02, per `plans/20260925-072438_plan.md`) renamed governance (and other domain) doc files to drop a duplicated `00_`/domain-number prefix — e.g. `docs/00_governance/00_governance_01_documentation-policy.md` → `docs/00_governance/governance_01_documentation-policy.md`. An earlier, separate docs reorg (docsreorg05, `plans/done/20260924-115855_plan.md`, REQ-003) had added a `GOVERNANCE_DOC_PATH` module constant to `tools/check_issue_inventory_conformance.py` — mirroring the same pattern already used in `tools/check_dependency_graph_cycles.py`'s `GRAPH_DOC_PATH` — specifically so the tool's default path would keep resolving after a docs move. Neither constant's filename value was updated for the later docsreorg01/02 rename. Separately, `tests/tools/test_check_docs_quality.py`'s `EXPECTED_WITHIN_FILE_PAIRS` is a documented, intentionally-refreshed golden snapshot (see its own header comment: "this drift is expected... a set-based snapshot tolerates the count changing") that was likewise not regenerated after docsreorg01/02.

## Problem
- `tests/tools/test_check_dependency_graph_cycles.py::TestRealGraphIntegration::test_real_repo_graph_has_no_cycle` fails: `GRAPH_DOC_PATH` (`docs/00_governance/00_governance_01_documentation-policy.md`) does not exist; the real file is `docs/00_governance/governance_01_documentation-policy.md`.
- `tests/tools/test_check_issue_inventory_conformance.py::TestGovernanceDocPathIntegration::test_governance_doc_path_resolves_on_disk` fails identically for `GOVERNANCE_DOC_PATH` (`docs/00_governance/00_governance_03_issue-and-uncertainty-management.md` vs. the real `docs/00_governance/governance_03_issue-and-uncertainty-management.md`).
- `tests/tools/test_check_docs_quality.py::TestRegressionFullDocsTree::test_cross_file_duplication_detected_on_full_docs_tree` fails: `EXPECTED_WITHIN_FILE_PAIRS` still keys entries to old flat/duplicated-prefix filenames (e.g. `00_governance/00_governance_01_documentation-policy.md`, `24_eventbus/06_eventbus_04_dlq_offsets_and_delivery_semantics.md`, `41_db/active_databases.md`) that no longer match the current `docs/` tree's actual paths (e.g. `24_eventbus/eventbus_06_dlq_offsets_and_delivery_semantics.md`, `41_db/db_08_active_databases.md`).
- Beyond the test failures, `.github/workflows/governance-docs-consistency.yml` invokes both `tools/check_dependency_graph_cycles.py` and `tools/check_issue_inventory_conformance.py` with no path argument (lines 52, 57), relying on each tool's default-path resolution — so the same stale constants also break the CI job itself against the current tree, not only the pytest tests.

## Reason for change
Two of the three checkers are meant to validate real invariants (no dependency cycles in the documented Software Runtime Dependency Graph; the governance issue-inventory document is well-formed) against the live repository tree — with a stale default path, they either error out or silently fail to run against real content, both in CI and locally. The third (docs-quality duplication snapshot) is a documented, expected-to-drift regression baseline whose own header comment specifies exactly when and how to refresh it; this is that refresh.

## Implementation intent
For the two tool constants, change only the literal filename string each constant holds — do not alter either tool's path-construction logic (`DOCS_DIR / "00_governance" / *_DOC_NAME`), which is already correct and shared with sibling tools per `plans/done/20260924-115855_plan.md`'s own note that this pattern mirrors `check_dependency_graph_cycles.py`. For the test snapshot, regenerate `EXPECTED_WITHIN_FILE_PAIRS` mechanically by running the tool against the current tree and capturing its actual within-file duplication-pair output, per the test file's own documented procedure — do not hand-edit individual keys or guess at new paths.
