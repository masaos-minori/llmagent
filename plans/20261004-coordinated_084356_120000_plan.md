# Plan: Coordinated — Eliminate redundant HTTP client in HTTP MCP startup poll

**Coordinates:** Plans 084356 (Remove dead outer AsyncClient) + 120000 (Reuse passed-in HTTP client for health checks)

## Goal
Eliminate redundant HTTP client creation by removing the inner `httpx.AsyncClient` in `_health_poll_until_ready()` and using the passed-in client from the caller, with no change to health-poll timing, timeouts, or failure semantics.

## Priority
Low

## Scope
- **In-Scope**:
  - Remove the inner `async with httpx.AsyncClient(...)` wrapper in `_health_poll_until_ready()`.
  - Use the passed-in `client` parameter directly (no shadowing).
  - Update docstring to reflect external client management.
- **Out-of-Scope**:
  - Any change to health-check logic, timeout computation, or the `HealthChecker` module.
  - Refactoring other lifecycle methods.
  - Adding/removing env-var handling.

## Background
`HttpServerLifecycleManager.start()` (scripts/agent/http_lifecycle.py) launches an HTTP MCP subprocess and polls `/health` until ready. It delegates polling to `_health_poll_until_ready()`. In `start()`, when `cfg.startup_timeout_sec > 0`, an outer `async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=MCPSERVER_HEALTH_TIMEOUT))` is opened and its `client` is passed to `_health_poll_until_ready()`. That method ignores the argument and immediately opens its own client via `async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=hc_timeout)) as client:`.

Two independent plans were generated addressing this issue:
- **Plan 084356**: Proposed removing the outer client entirely and dropping the `client` parameter from `_health_poll_until_ready()`.
- **Plan 120000**: Proposed keeping the outer client but removing the inner one and using the passed-in client.

The coordinated approach keeps the outer client (preserving caller lifecycle) and removes only the inner one (eliminating redundancy).

## Problem
Every successful HTTP-MCP startup opens two `AsyncClient` instances — one in `start()` and one in `_health_poll_until_ready()` — where the inner one shadows the outer one. Consequences:
- Wasted connection-setup work on the hot startup path (one extra client performs no request, then closes).
- Misleading signature: readers assume the caller's client drives the polls.
- `MCPSERVER_HEALTH_TIMEOUT` backs the dead outer client, while the real client uses `compute_health_check_timeout(...)`.

## Reason for change
Redundant HTTP client creation wastes resources and adds latency. Two clients per health-poll session is clearly a bug — the inner one shadows the outer one. Removing it makes the actual client authoritative and removes wasted connection setup.

## Implementation intent
Remove the inner `async with httpx.AsyncClient(...)` block in `_health_poll_until_ready()` and use the passed-in `client` parameter directly. Update the docstring to clarify that the client is managed externally. Keep the single authoritative client inside `_health_poll_until_ready()` unchanged, and preserve the `cfg.startup_timeout_sec > 0` guard and the skip log. No behavior change to polling, timeouts, or error handling.

## Requirements
- `REQ-001`: Only one HTTP client is created per health-poll session (the outer one from `start()`).
- `REQ-002`: Test verifies no connection leaks on failure paths.
- `REQ-003`: Test verifies health check works correctly with reused client.
- `REQ-004`: Docstring updated to reflect external client management.
- `REQ-005`: Preserve all behavior — the health-poll loop, deadline handling, `shutdown_event` interrupt racing, `compute_health_check_timeout` timeout computation, failure semantics, and the `cfg.startup_timeout_sec > 0` guard. Do not change observable behavior.

### Coordination rationale
Plan 084356 proposed removing the outer client entirely and dropping the `client` parameter. Plan 120000 proposed keeping the outer client but removing the inner one. The coordinated approach adopts Plan 120000's core insight (keep outer, remove inner) because:
1. Preserving the outer client avoids changing the caller's lifecycle responsibility.
2. Removing only the inner client eliminates the redundancy without requiring changes to the caller.
3. The `client` parameter is already passed — we just need to stop shadowing it.

### Current Behavior (Verified Against Source)
1. `http_lifecycle.py` line ~466-468: Caller creates `httpx.AsyncClient`
2. Line ~469-471: Caller passes client to `_health_poll_until_ready()`
3. Line ~393-395: Method creates its OWN `httpx.AsyncClient`, shadowing the passed-in client
4. Result: Two clients per health-poll session — wasteful and incorrect

### Proposed Change
```python
async def _health_poll_until_ready(
    self,
    server_key: str,
    cfg: McpServerConfig,
    proc: subprocess.Popen[bytes],
    client: httpx.AsyncClient,  # Client is managed externally by the caller
    deadline: float,
    shutdown_event: asyncio.Event | None,
) -> None:
    """Poll /health endpoint until the server becomes healthy or timeout expires.

    Polls the health endpoint in a loop, checking for early exit and shutdown
    events between polls. Raises HttpStartupError on early exit, shutdown,
    or timeout.

    Args:
        server_key: Server identifier key.
        cfg: Server configuration.
        proc: Subprocess instance to monitor.
        client: Async HTTP client for health check requests. Managed externally
            by the caller — do NOT close this client within this method.
        deadline: Monotonic time at which to abort polling.
        shutdown_event: Optional event to race against poll sleep.

    Raises:
        HttpStartupError: On early exit, shutdown, or timeout.
    """
    health_url = cfg.url.rstrip("/") + "/health"
    hc_timeout = self._health_checker.compute_health_check_timeout(
        cfg.startup_timeout_sec, MCPSERVER_HEALTH_TIMEOUT
    )
    while time.monotonic() < deadline:
        if proc.poll() is not None:
            stderr_full = self._cleanup_server_resources(server_key)
            logger.error(...)
            raise HttpStartupError(...)
        try:
            response = await client.get(health_url)
            ...
        except Exception as e:
            ...
```

Key changes:
1. Remove `async with httpx.AsyncClient(...) as client:` wrapper
2. Use the passed-in `client` directly
