## Background
`governance_04_documentation-checks.md` maps GV-017 ("Removed-name reintroduction in current
specifications") to `check_compat_shims.py --check-removed-names`, gate `Chk`, scope `Auto`,
trigger `PR`, status `Warning | Partial`, with the follow-up: "Slash-command removed-name
patterns implemented (`/diff`, `/system`, `/audit`, `/workflow`); promote to default-on once the
corpus is compliant". The retired-identifier patterns and historical-context markers live in
`tools/check_compat_shims.py` (`_REMOVED_NAME_PATTERNS`, `_HISTORICAL_CONTEXT_MARKERS`).

## Problem
While `--check-removed-names` is opt-in, reintroduction of a retired removed-name pattern (e.g.
using a retired slash-command or identifier name in a current specification) goes undetected
unless someone explicitly passes the flag. This lets removed names reappear silently in the
corpus.

## Reason for change
Once the corpus is verified compliant, promoting the check to default-on enforces GV-017
continuously at the PR/CI gate. The tool's "report-only until compliant" design means promoting
it does not risk failing CI while any residual non-compliance exists.

## Implementation intent
First run `check_compat_shims.py --check-removed-names` across the corpus to confirm zero
reintroductions. Then wire the check into the CI backward-compatibility job so it runs by
default, preserving the report-only-until-compliant guard (it must not hard-fail CI while
residual non-compliance may exist). Use `_REMOVED_NAME_PATTERNS` / `_HISTORICAL_CONTEXT_MARKERS`
as the detection basis. Keep the detector read-only.

## Design
Promotion is a CI-config change only; the detector stays read-only.

1. **Re-confirm compliance (UNK-01, REQ-001).** Run
   `python tools/check_compat_shims.py --check-removed-names` across the corpus and confirm zero
   findings before touching any config.
2. **Promote in CI (REQ-002, REQ-003).** In `.github/workflows/backward-compat-check.yml`, add
   `--check-removed-names` to the existing bare invocation:
   `python tools/check_compat_shims.py --check-removed-names`. The job's `paths:` triggers
   already cover `docs/**/*.md`, so reintroductions in docs are caught on the next PR.
3. **Preserve the guard (UNK-01, REQ-003).** Because the corpus is compliant, the report-only
   guard's purpose (avoid failing CI during the non-compliant transition) is satisfied; promote
   without modifying the detector's exit logic. If residual non-compliance is found, revert the
   promotion instead of changing the detector.
4. **Update the matrix (REQ-005).** Set GV-017 status `Partial` → `Existing`, clear the
   Follow-up note.

No change to `_REMOVED_NAME_PATTERNS`, `_HISTORICAL_CONTEXT_MARKERS`, or the tool's exit logic.
