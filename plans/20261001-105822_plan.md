Normative meaning, identifiers, structure, and current checker results must stay the same, so that the canonical architecture decisions comply with the `skills/DESIGN.md` Output language rule ("All files under `docs/` are English, with no exception").

## Background
- `skills/DESIGN.md` Output language requires every file under `docs/` to be English, with no exception. (Explicit in issue; Confirmed by repository evidence: `skills/DESIGN.md` Output language section)
- `uv run python tools/check_docs_japanese.py` lists all 15 target files. Lines that contain Japanese characters total 2395 across the 14 ADRs, 14 in `adr-index.md`, and 63 ADR headings. (Confirmed by repository evidence: command output, 2026-10-01)
- Japanese ADR titles have been copied into link descriptions in area guides. Issue `langdoc001` depends on this Plan for the English titles.
- Every commit touching `docs/10_adr/` has a single author. (Confirmed by repository evidence: `git log --format=%an -- docs/10_adr`)

## Problem
- Normative architecture decisions use a language that the project rule forbids under `docs/`. AI agents and English-only tools get inconsistent text: governance and area docs are English, but the ADRs they defer to are mostly Japanese.
- Five ADRs are larger than the `check_docs_structure.py` per-file limit: ADR-002, ADR-003, ADR-004, ADR-006, and ADR-008. (Confirmed by repository evidence: `uv run python tools/check_docs_structure.py "docs/10_adr/*.md"`)
- Issue claims that needed correction:
  - The issue's warning that ADR checkers "may parse section headers or markers" was checked. `check_adr_structure.py`, `check_adr_reference.py`, and `check_adr_invariant_matrix.py` match English headings only. However, `tests/tools/test_check_docs_quality.py` hard-codes ADR section names in its `EXPECTED_WITHIN_FILE_PAIRS` snapshot, and several of those names contain Japanese, for example `'3. 第3の採用理由 — Operability'`. Translating those headings changes that snapshot, so that test file has been added as a target. (Derived from confirmed evidence)
  - `tools/check_compat_shims.py` `_HISTORICAL_CONTEXT_MARKERS` includes Japanese marker words such as 解消, 解決, and 削除済み. These exempt historical notes from findings. A translated note that loses its historical marker could become a new finding. (Confirmed by repository evidence)

## Reason for change
- ADRs are the canonical source for architecture decisions. Their language must follow the project rule so every consumer reads them reliably.
- `langdoc001` cannot translate area-guide ADR link descriptions until the English ADR titles exist.

## Implementation intent
- Translate one ADR per implementation step. Each step can then be reviewed for semantic fidelity against its original and reverted on its own.
- Translate prose only. Keep the following byte-identical:
  - invariant IDs, Known Issue IDs, status values, dates, links, and backtick-quoted identifiers and paths;
  - the English section headings that checkers parse (`## Known Deviations`, `## Implementation Notes`, `### Implementation References`, `## ADR Invariant Verification Matrix`);
  - the `**Known Issue**` and `**Resolved**` bullet labels.
- When translating a historical, resolved, or removed note, use an English marker word that `check_compat_shims.py` recognizes (`resolved`, `removed`, `historical`, `legacy`) wherever the meaning supports it. This keeps the note exempt.
- Do not resolve ambiguity while translating. Record any inconsistency found through the governance process (`docs/00_governance/governance_03_issue-and-uncertainty-management.md`) as a follow-up issue, without editing it in place.
- Translate `adr-index.md` after all ADRs, so its titles copy the final H1 titles.

## Design
- Path B (more than 3 target files). The four Path B analyses were adapted to a documentation-only change:
  - **Architecture analysis**: N/A. No module under `scripts/` changes. `scripts/` cites ADRs only by ID (for example ADR-014 in `scripts/agent/orchestrator.py`), and IDs do not change.
  - **Dependency graphing**: These consumers of ADR content were identified:
    - ADR checkers, which parse English headings only;
    - `check_known_deviation_sync.py`, which uses labels as its status signal;
    - `check_compat_shims.py`, whose historical markers include Japanese;
    - the `test_check_docs_quality.py` snapshot, which contains Japanese section names;
    - area-guide link descriptions and quotes (`langdoc001`).
    No anchor link into an ADR heading exists (`grep` for `ADR-0NN...md#` returned 0), so translating headings breaks no links.
  - **Historical analysis**: Each ADR changed 4 to 7 times since 2026-09-01; every change has the same single author.
  - **Operational dependency inspection**: N/A. `deploy/deploy.sh` does not copy `docs/` (only a comment mentions a doc), and no runtime process reads ADRs.
- Validation quality baseline for the only code-adjacent target (`tests/tools/test_check_docs_quality.py`):
  - `radon cc -n C`: no blocks graded C or worse.
  - `vulture --min-confidence 80`: no findings.
  - `bandit`: 30 Low (B101 asserts, B404/B603 subprocess), all pre-existing test patterns.
  - diff-cover: N/A, because no `scripts/` lines change; the `rules/toolchain.md` 90% threshold applies only to changed `scripts/` lines.
- Checker baseline (2026-10-01), which REQ-003 is compared against:
  - ADR structure/reference/matrix: "No issues found".
  - known_deviation_sync: exit 1, 2 errors and 10 warnings.
  - compat_shims: exit 1, with 0 `docs/10_adr/` findings.
  - `check_docs_structure.py "docs/10_adr/*.md"`: 17 findings (5 size, 11 broken links, 1 missing Keywords).
  - `test_check_docs_quality.py`: already failing before this work because of stale `23_agent/05_agent_*` snapshot rows.
- Translation rules:
  - Keep heading hierarchy and order.
  - Keep tables row for row.
  - Translate Japanese text inside headings while keeping any English part, for example `### 3. 第3の採用理由 — Operability` becomes `### 3. Third Reason for Adoption — Operability`.
  - Follow governance_02 terminology.
