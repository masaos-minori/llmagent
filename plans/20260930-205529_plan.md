## Goal
Remove the dead method `McpToolDiscoveryService._fetch_server_tools()` (and the helper `_validate_and_normalize_entry()` that only it called) from `scripts/agent/services/mcp_tool_discovery.py`, eliminating a second, diverging MCP `/v1/tools` fetch-and-validate implementation while leaving the live discovery path byte-for-byte unchanged.

## Priority
Medium

## Scope
- **In-Scope**: Delete `_fetch_server_tools()` from `McpToolDiscoveryService`. Delete `_validate_and_normalize_entry()` when confirmed unused after the first deletion. Remove any import newly left unused by the deletions. Re-confirm no external caller exists immediately before deleting.
- **Out-of-Scope**: Any change to `discover_all()`, `McpToolsHttpClient.fetch_tools()`, or any other method. Unifying the two validation implementations into one (a separate improvement). Re-wiring `_fetch_server_tools()` as the live path. Modifying test files beyond running existing tests.

## Background
`McpToolDiscoveryService` (`scripts/agent/services/mcp_tool_discovery.py`) discovers live MCP tools at startup via `discover_all()`, which builds the `RuntimeToolRegistry` through the sibling `McpToolsHttpClient.fetch_tools()` plus `ToolEntryValidator.validate_entry()`. A separate async method `_fetch_server_tools()` implements an equivalent-but-not-identical fetch-and-validate flow using `self._validate_and_normalize_entry()`. The module documents a unified severity scheme and duplicate-tool handling for the live pass; the dead method predates or duplicates that design and never received a caller.

## Problem
Two parallel implementations of nearly identical MCP `/v1/tools` fetch-and-validate logic coexist. One is dead (`_fetch_server_tools()` has no caller anywhere in the repository). Future maintainers may assume both are live, copy logic between them, or be confused about which path governs production behavior. The two paths also differ subtly in how `cfg.required` escalates per-entry findings, so the dead path is not a byte-for-byte duplicate -- it is latent divergence that can mask which validation path is authoritative.

## Reason for change
Dead code silently accumulates and drifts. This method has had no caller since it was introduced, and its existence risks masking which validation path is authoritative. Removing it restores a single source of truth for `/v1/tools` validation.

## Implementation intent
Confirm via a fresh caller search that nothing (including tests, dynamic dispatch, or subclass overrides) invokes either method, then delete `_fetch_server_tools()` followed by `_validate_and_normalize_entry()` (dead once the former is gone). Fix any import ruff flags as newly unused. Leave `discover_all()` and every live-path method untouched. Verify behavior is unchanged by re-running the existing discovery and startup test suites.

## Requirements
