## Background
Session titles are persisted via `AgentSession.set_title`, which currently truncates the stored string to 50 characters (`title[:50]`) with no ellipsis. LLM title generation (`SessionTitleService.generate`) delegates the final truncation to `set_title`. When generation fails, `SessionTitleGen.generate` falls back to a truncated version of the first user input using `SESSION_TITLE_MAX_CHARS` (32) / `SESSION_TITLE_TRUNCATE_AT` (29). The `/session list` command (`_session_list`) also truncates any stored title longer than `SESSION_TITLE_MAX_CHARS` (32) for display, appending `"..."`.

## Problem
The stored hard cap (50) and the display/fallback cap (32) disagree. An LLM-generated title of 33-50 characters is stored as-is (up to 50 chars) because `set_title` slices at 50, yet the `/session list` view truncates it at 29 characters plus `"..."` and the fallback path would have capped it at 32. The stored value can therefore exceed the 32-character convention that the rest of the title subsystem assumes, and the rename success echo (`{title[:50]!r}`) reports up to 50 chars while only 32 are actually stored.

## Reason for Change
Two different maximums for the same field are a latent inconsistency: a title can be stored longer than the UI convention expects, the list view silently truncates it again, and the rename echo advertises a length that was never stored. The caps should resolve to one value so storage, fallback, and display agree. The existing fallback test (`test_agent_cmd_session.py`) already asserts the fallback title passed to `set_title` is `<= 32`, so 32 is the established convention; the `50` in `set_title` is the sole outlier.

## Implementation Intent
Introduce a single authoritative title-length maximum owned by `AgentSession` (the storage owner of the `title` field) and reference it from both `set_title` and the `SessionTitleGen`/display code. The value is 32, matching the established `SESSION_TITLE_MAX_CHARS` convention used by the fallback generator, the list display, and the fallback test. Because `AgentSession` cannot import from `commands/` without an import cycle (see Design), the constant is defined in `session.py` and re-exported from `commands/session_title.py`, which already imports `agent.context` and therefore sits above the session layer. The storage slice keeps its current no-ellipsis semantics (`title[:N]`); only the bound changes from 50 to 32. Display still uses `SESSION_TITLE_TRUNCATE_AT` (`N - 3`) plus `"..."`, unchanged.

## Design
- **Canonical location = `agent.session`, re-exported from `commands/session_title.py` (resolves UNK-02).** `AgentSession.set_title` is the storage owner of the `title` field, so it owns the storage cap. `session.py` cannot import from `commands/session_title.py`: `commands/session_title.py` imports `agent.context` at runtime and `context.py` imports `agent.session` at runtime, so importing the other direction would form a cycle (`session.py` → `commands/session_title.py` → `agent.context` → `session.py`). Defining the constant in `session.py` avoids the cycle, and `commands/session_title.py` can safely import `agent.session` because none of `agent.session`'s dependencies reach `agent.context` or any `commands/` module (and it already transitively reaches `agent.session` via its `agent.context` import). `commands/session_title.py` therefore replaces its local definition with a re-export, preserving the `SESSION_TITLE_MAX_CHARS` / `SESSION_TITLE_TRUNCATE_AT` names that `cmd_session.py::_session_list` imports.
- **Value = 32 (resolves UNK-01).** `SESSION_TITLE_MAX_CHARS=32` is used by the fallback generator, the `/session list` display, and is asserted by the existing fallback test (`<= 32`); the `50` in `set_title` is the sole outlier. Storage and display/unify on 32.
- **Preserve truncation semantics.** Storage keeps the current no-ellipsis slice (`title[:N]`); only the bound changes from 50 to 32. Display keeps `SESSION_TITLE_TRUNCATE_AT = N - 3` plus `"..."`, so a stored title at the cap (32) displays as-is (`32 > 32` is False) and is never double-truncated. The two conventions share one maximum but keep their distinct formatting.
- **Minimal surface.** The change is confined to the storage slice in `session.py`, a re-export in `commands/session_title.py`, the rename echo in `cmd_session.py`, and the existing `test_truncates_to_50_chars` assertion. No signature, interface, or schema change; `set_title`'s `sqlite3.Error` propagation and `session_id is None` no-op guard are untouched.
