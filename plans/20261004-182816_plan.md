# Plan: Prevent ApprovalRecovery from overwriting active approvals

## Goal
Only overwrite `pending_approval_task_id` during recovery when the current value is stale (from a previous session), preventing silent overwrites of active approvals.

## Priority
High

## Scope
- **In-Scope**: Modify `ApprovalRecovery.recover()` to compare recovered task ID against current value before overwriting; add regression tests
- **Out-of-Scope**: Changes to the approval recovery query logic; changes to the StateStore API

## Background
`ApprovalRecovery.recover()` in `scripts/agent/startup_approval_recovery.py` restores workflow approval-pending state from a previous session during startup. It sets `ctx.turn.pending_approval_task_id` to the most recent pending approval's task ID.

## Problem
The method overwrites `pending_approval_task_id` without checking whether the Orchestrator has already set it for a different approval. The warning log is emitted but the overwrite proceeds regardless.

## Reason for change
If the Orchestrator has already set `pending_approval_task_id` for a different approval, the recovery silently overwrites it. The user sees the wrong approval wired up for immediate action. Inconsistent state between what the user expects and what the system acts on.

## Implementation intent
Add a comparison between the recovered task ID and the current value. If they differ and the current value appears to be active (not stale), keep the current value instead of overwriting.

## Requirements
- `REQ-001`: Recovery does not overwrite an active approval without justification
- `REQ-002`: Test verifies recovery respects existing approval state
- `REQ-003`: Test verifies recovery correctly overwrites stale state
- `REQ-004`: Warning message includes both old and new values
