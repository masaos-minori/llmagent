## Background
The first line of `scripts/eventbus/db.py` describes the facade as re-exporting "connection, event, delivery, DLQ, offset migration" layers. The offset migration layer was removed, so the docstring names a layer that no longer exists. `scripts/eventbus/README.md` describes the schema layer as "Schema definition, migration logic" although the schema-migration paths were removed (commit `31f8c3be9`) and `scripts/eventbus/schema.py` now describes itself as "schema definition and creation". The README's "Stub Module Pattern" section already documents `db.py` as the single entry point and needs no change.

## Problem
A docstring and a README line name a removed layer and a removed responsibility, so a reader looks for code that is not there. Adversarial verification found that `README.md` is not a `docs/` document, so the documentation checkers (`check_docs_structure.py` reports a missing `## Keywords` section for it) do not apply; the applicable automated check is the docstring checker.

## Reason for Change
Accurate navigation text avoids sending developers to deleted modules; the change is small and independent of other work.

## Implementation Intent
Edit the two statements to match the current layers and the wording already used by `schema.py`; add no note about what was removed.

## Requirements
- `REQ-001`: The first-line docstring of `scripts/eventbus/db.py` lists the connection, event, delivery, and DLQ layers only.
- `REQ-002`: The README schema-layer line reads "Schema definition and creation".
