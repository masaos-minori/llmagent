## Background
`McpToolDiscoveryService.discover_all()` (`scripts/agent/services/mcp_tool_discovery.py:305`) skips any server config where `cfg.is_disabled` is `True` before attempting discovery. `McpServerConfig`'s class default is `startup_mode = StartupMode.NONE` (confirmed in `shared001`'s investigation, `scripts/shared/mcp_config.py:82`), and `is_disabled` returns `True` exactly when `startup_mode == StartupMode.NONE`. This test's `McpServerConfig(TransportType.HTTP, "http://127.0.0.1:9100", auth_token="test-token")` never sets `startup_mode`, so the constructed server config is (silently) disabled, and `discover_all()` skips it — confirmed by the captured log line "No tool definitions in config and no servers reachable; skipping validation".

## Problem
`AssertionError: assert 'visible_tool' in set()` — `result.registry.llm_tool_definitions()` returns no tools at all, because the one configured server was skipped by discovery entirely (not because the visibility-filtering logic incorrectly excluded both the visible and hidden tool).
