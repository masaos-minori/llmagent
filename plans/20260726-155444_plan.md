## Goal

Fix the WAL file backup path traversal vulnerability by validating database paths and ensuring backups are written only to safe locations.

## Scope

**In-Scope:**
- Resolve symlinks in `db_path` using `os.path.realpath()`
- Validate resolved path is within allowed base directory
- Verify backup directory exists and has write permissions before writing
- Use session ID-based naming instead of timestamp to prevent filename collisions

**Out-of-Scope:**
- Modifying WAL checkpoint behavior
- Adding new configuration options for allowed directories
- Changing backup strategy (always attempt backup regardless of journal mode)

## Assumptions

1. The allowed base directory is the project data directory (configured in `agent.toml`)
2. Session ID is available and unique enough to prevent collisions
3. The WAL file must exist before attempting backup (may not exist if journal mode is not WAL)

## Risks

- **Risk**: Rejecting symlinked database paths breaks existing deployments → Mitigation: Allow symlinks but validate the resolved path; log warning for symlink usage
- **Risk**: Permission check may fail due to race condition (directory deleted between check and write) → Mitigation: Catch OSError on write and handle gracefully
- **Risk**: Session ID may not be set at shutdown time → Mitigation: Fall back to UUID or timestamp if session ID unavailable
