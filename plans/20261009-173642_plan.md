# Plan: Validate workflow definition content in the startup preflight

## Goal
- Make the startup preflight (`check_workflow_definition`) reject a malformed workflow definition file (invalid JSON, wrong shape, missing required keys or required stages) with a `RuntimeError` naming the file and cause, instead of passing it through to fail later in the Orchestrator constructor.

## Priority
Low

## Scope
- **In-Scope**: extend `check_workflow_definition` to load the definition through the existing loader and re-raise `WorkflowLoadError` as `RuntimeError`; add content-validation tests to `tests/agent/test_repl_health.py`; fix the existing `test_present_file_passes` fixture that writes an invalid `{}`.
- **Out-of-Scope**: changing the loader's validation rules (`_validate`); changing the Orchestrator constructor; other startup validations; the schema preflight (`check_workflow_schema`); any public interface change.

## Background
ADR-001 makes the Workflow Engine mandatory and forbids a fallback path (Decision 4); ADR-004 requires fail-fast for a missing or invalid workflow (INV-03). The wfstartup01 plan (`plans/done/20261008-143632_plan.md`) made a workflow load failure a fatal startup error in the Orchestrator constructor. The preflight (`check_workflow_definition`) runs earlier but currently checks only file existence, so a malformed definition slips past it and fails only when the Orchestrator is constructed.

## Problem
- The preflight function checks `default.json` existence only; invalid JSON, a wrong shape, or missing required stages pass it.
- The failure is still fatal (the Orchestrator constructor fails), but it is reported from a different place and message than the other preflight failures, and some preflight-time cleanup/reporting that runs only for preflight failures does not run.

## Reason for change
Consistent, early failure reporting: a malformed definition is caught by the preflight with its usual message rather than surfacing later from the Orchestrator constructor. The change also reinforces fail-fast reporting for a missing or invalid workflow (ADR-004 INV-03; ADR-001 INV-05), surfacing it at preflight rather than only at Orchestrator construction (the *missing* case alone is ADR-001 INV-01).

## Implementation intent
Reuse the existing loader's validation rather than duplicating its rules. After the existing existence check, call `WorkflowLoader(workflows_dir=target_dir).load("default")` inside a `try` that catches `WorkflowLoadError` and the scalar-coercion errors (`ValueError`, `TypeError`, `AttributeError`) and re-raises them as a `RuntimeError` naming the file and cause. Keep the existing missing-file message unchanged. The loader is side-effect free (pure read + in-memory construct), so calling it from the preflight is safe.

## Requirements
- `REQ-001`: When `default.json` contains invalid JSON, `check_workflow_definition` MUST raise a `RuntimeError` naming the file and cause.
- `REQ-002`: When `default.json` has the wrong shape or is missing a required key or required stage, `check_workflow_definition` MUST raise a `RuntimeError` naming the file and cause.
- `REQ-003`: A valid `default.json` (matching the shipped definition shape) MUST pass `check_workflow_definition` without raising.
- `REQ-004`: The existing missing-file `RuntimeError` message (naming the file and remediation hint) MUST be unchanged.

## Design
- `check_workflow_definition` keeps its signature and lazy-import pattern. After the existing existence check, it imports `WorkflowLoader`, `WorkflowLoadError`, and the scalar-coercion exceptions (`ValueError`, `TypeError`, `AttributeError`) lazily and calls `WorkflowLoader(workflows_dir=target_dir).load("default")`. Any `WorkflowLoadError` or scalar-coercion error (`ValueError`/`TypeError`/`AttributeError` from coercing a malformed definition's numeric fields/stages) is caught and re-raised as `RuntimeError(f"Workflow definition invalid: {workflow_file}: {exc}") from exc`. This makes the preflight emit a consistent `RuntimeError` for every malformed input, not only the cases the loader raises `WorkflowLoadError` for; the loader and Orchestrator are left unchanged.
- The loader's validation rules are reused, not duplicated (per the issue's constraint).
- The missing-file branch and its message are unchanged.
- `test_present_file_passes` is updated because `"{}"` is now invalid; it writes a complete valid definition instead.

## Adversarial Verification Results

Verified against current source on 2026-10-10. All core claims hold; two ADR
citation errors were found and corrected (see "Discrepancies").

### Confirmed
- `check_workflow_definition` (`scripts/agent/services/workflow_schema.py:22-33`)
  checks `.exists()` only; invalid JSON, wrong shape, and missing required stages
  pass it unchanged.
- Content validation lives in the loader: `workflow_loader.py:_validate()` raises
  `WorkflowLoadError` for missing required keys, wrong types, empty/duplicate
  stages, missing required stages (`plan`/`execute`/`verify`), and bad
  `retry_policy`; `load()` raises `WorkflowLoadError` on parse error and
  non-object JSON. Re-raising as `RuntimeError` names file+cause (REQ-001, REQ-002).
- Exception coverage is broadened beyond `WorkflowLoadError` to include the
  scalar-coercion errors (`ValueError`/`TypeError`/`AttributeError`) so every
  malformed input yields the preflight `RuntimeError` (owner-resolved; see
  "Resolved decision").
- Shipped `config/workflows/default.json` passes `_validate()` (`name`, `version`,
  three required stages, `retry_policy.max_attempts`/`backoff_sec`,
  `require_approval=true`), so REQ-003 holds today.
- `"{}"` fails `_validate()` (missing `name`/`version`/`stages`/`retry_policy`), so
  `test_present_file_passes` (`tests/agent/test_repl_health.py:899`) MUST be
  updated; this is a necessary consequence of the change, not a regression.
- Real-function tests belong in `TestCheckWorkflowDefinition`
  (`tests/agent/test_repl_health.py:887`); `tests/agent/test_startup_workflow_preflight.py`
  patches `agent.startup_component_init.check_workflow_definition` and exercises
  only the wrapper `_check_workflow_definition`, never the real function's content
  path.
- Call site `startup_component_init.py:_check_workflow_definition` (lines 88-91)
  calls `check_workflow_definition()`; last line of defense `orchestrator.py:129`
  catches `(WorkflowLoadError, FileNotFoundError)` and re-raises `RuntimeError` at
  line 130. Failure remains fatal.
- Loader is side-effect free (pure read + in-memory construct); callable from the
  preflight.

### Discrepancies (corrected)
- Requirement Traceability cited **ADR-001 INV-03** for REQ-003. ADR-001 INV-03 is
  "Execution success and verification success are distinguished and verified
  independently" — unrelated to workflow loading. Corrected to **ADR-004 INV-03**
  ("Missing/invalid Workflow -> abort"), the invariant this change reinforces.
- "Reason for change" cited **ADR-001 INV-01** with wording "a missing or invalid
  workflow", but INV-01 covers only the *missing* case; the *invalid* case is
  ADR-001 INV-05 / ADR-004 INV-03. Corrected the citation and wording.

### Open decision (owner)
- Citation preference for REQ-003: resolved to ADR-004 INV-03 (matches the
  "missing or invalid" phrasing). ADR-001 INV-05 ("If the workflow definition file
  fails validation, startup is aborted") is equally valid if the owner prefers to
  stay within ADR-001. No code impact.

### Source-issue path note
- Traceability references the source issue as `issues/...`; the file now lives at
  `issues/done/...` after issue-to-plan. This matches the established repo
  convention (e.g. the wfstartup01 done plan references `issues/...`). Left
  unchanged; flag if the convention should switch to the post-move path.

### Resolved decision (owner): exception coverage for malformed scalar fields
- Finding: `WorkflowLoader.load()` raises `WorkflowLoadError` for missing file, JSON
  parse error, non-object JSON, and `_validate()` failures, but certain malformed
  inputs raise other exceptions the planned `except WorkflowLoadError` does NOT catch
  (verified against current loader): `ValueError` (numeric field holding a non-numeric
  string, e.g. `"timeout_sec": "abc"` -> `int()` at `workflow_loader.py:90`/`:123`) and
  `AttributeError` (stage entry that is not a dict, e.g. `"stages": ["plan"]` ->
  `.get` at `workflow_loader.py:68`). These would leak as a raw exception from the
  preflight, not the `RuntimeError` the Goal and `REQ-002` require ("wrong shape ...
  MUST raise a RuntimeError").
- Resolution (owner, 2026-10-10): adopt option (a) — broaden the preflight `except`
  to `(WorkflowLoadError, ValueError, TypeError, AttributeError)` and re-raise as
  `RuntimeError`. Reflected in Implementation intent, Design, and Implementation step 2.
  Loader and Orchestrator remain unchanged.
