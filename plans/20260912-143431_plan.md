## Goal
- Remove stale references to nonexistent `_execute_with_cache()` and `_store_and_evict()` methods from `scripts/shared/tool_cache.py`'s module docstring, which incorrectly describes `ToolExecutor` as having an internal OrderedDict-based cache mechanism that was removed.

## Priority
High

## Scope
- **In-Scope**: Updating `scripts/shared/tool_cache.py`'s module docstring to accurately reflect current state of `ToolExecutor`
- **Out-of-Scope**: Any changes to `config/agent.toml`, `test_runtime_tool_routing_integration.py`, or reinstating caching in `ToolExecutor`

## Background
Discovered while investigating `test_runtime_tool_routing_integration.py`'s failure during a freeze-validation re-entry for `plans/done/20260908-221312_plan.md` (cfgval001). `scripts/shared/tool_cache.py` defines a standalone `ToolResultCache` class whose own docstring explicitly states it is "NOT currently used by `ToolExecutor`" and that `ToolExecutor` instead "maintains its own internal ... cache" via `_execute_with_cache()` / `_store_and_evict()` — but a repository-wide `rg` for both method names finds no occurrences anywhere in `scripts/`. `git log -S"_execute_with_cache" -- scripts/shared/tool_executor.py` shows historical commits that added and later removed cache-related code from this file, but the exact removal commit was not pinpointed.

## Problem
The module docstring in `scripts/shared/tool_cache.py` describes a `ToolExecutor`-internal cache mechanism (`_execute_with_cache()`/`_store_and_evict()`) that does not exist anywhere in the current codebase. This creates confusion about the relationship between `ToolResultCache` and `ToolExecutor`.

## Reason for change
The stale documentation misleads developers about the existence of a caching mechanism in `ToolExecutor`. Since the original issue's other claims (about `config/agent.toml` and the failing test) have been resolved by subsequent changes, only this docstring correction remains actionable.

## Implementation intent
Update the module docstring to remove references to the nonexistent `_execute_with_cache()` and `_store_and_evict()` methods, clarifying that `ToolExecutor` has no internal cache mechanism and that `ToolResultCache` exists solely as a standalone utility.

## Requirements
- `REQ-001`: Module docstring in `scripts/shared/tool_cache.py` must accurately describe `ToolExecutor`'s current capabilities without referencing nonexistent methods
- `REQ-002`: No behavioral changes to `ToolResultCache` or any other component
