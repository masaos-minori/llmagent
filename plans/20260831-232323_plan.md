# Plan: Update adr-index.md to reflect ADR-004 revision

## Goal
Update `docs/adr-index.md` to eliminate stale references to ADR-004's pre-revision state, including outdated invariant descriptions that reference removed Local-mode concepts.

## Priority
Medium

## Scope
- **In-Scope**: Updating ADR List entry for ADR-004, rewriting Invariant Verification Matrix rows INV-010 through INV-022 that reference ADR-004, deciding whether to consolidate overlapping invariant rows.
- **Out-of-Scope**: Modifying ADR-004 itself, changing the Invariant Verification Matrix structure for other ADRs' rows, resolving circular dependency notes (CDR-1/CDR-2/CDR-3).

## Background
ADR-004 was revised from "Environment Profile別障害方針 — Fail-Fast/Fail-Open" (Proposed) to "環境における障害処理方針" (Accepted, Production-only model). The revision eliminated Local mode and unified the failure-handling model. `docs/adr-index.md` was explicitly out of scope during that revision, with a note to report required follow-ups — this issue is that follow-up.

## Problem
Several entries in `docs/adr-index.md` describe ADR-004 using pre-revision terminology:
- INV-011 still references "Fail-Fast at startup / Fail-Closed at execution" and "required/non-required branch" — inconsistent with the revised unified terminology.
- INV-019, INV-020, INV-021, INV-022 contain descriptions that need re-verification against current code.
- INV-021 references an "undefined" classification state that doesn't exist in current code.
- The four invariant rows may overlap after the revision reduced the number of distinct invariants worth tracking.

## Reason for change
An ADR index that shows stale invariant descriptions misleads anyone using `docs/adr-index.md` as the canonical list to understand what the current architecture requires.

## Implementation intent
Verify each invariant row's description against the current ADR-004 document and source code, rewrite descriptions to match the revised Production-only model, decide whether to consolidate overlapping rows, and update the verification status column for each affected row.

## Requirements
- `REQ-001`: ADR List entry for ADR-004 must show the current title "環境における障害処理方針" and status "Accepted" (currently correct — no change needed).
- `REQ-002`: INV-010 description must accurately reflect the revised ADR-004's single common failure-handling policy without Local-mode language.
- `REQ-003`: INV-011 description must be rewritten to use the revised ADR-004's unified terminology (no "Fail-Fast at startup / Fail-Closed at execution" distinction; no "required/non-required branch" reference).
- `REQ-004`: INV-019 description must accurately reflect the current production-only model for required-component unavailability.
- `REQ-005`: INV-020 description must accurately reflect the current production-only model for non-required component failure handling.
- `REQ-006`: INV-021 description must reference Decision #12's actual requirement about undefined classification, not a nonexistent "undefined component criticality" concept.
- `REQ-007`: INV-022 description must accurately reflect the current Fallback prohibition rule.
- `REQ-008`: Each affected invariant row's Verification Status column must be re-verified against current source code.
- `REQ-009`: If consolidation reduces the number of distinct invariant rows, record the decision made.
