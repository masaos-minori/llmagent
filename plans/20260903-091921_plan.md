## Goal
- Restrict Event Bus and MCP server HTTP binding to loopback-only, close the
  confirmed private-LAN/wildcard detection gap in the existing bind-address guard,
  and remove the `allow_public_bind` escape hatch — for the services confirmed to
  run same-host. **Architecture-owner decision obtained 2026-09-03** (`UNK-01`
  resolved): `embed_url`/`llm_url` are legitimate remote/cross-host endpoints,
  explicitly out of `loopbackonly`'s scope — no same-host migration is required
  for them.

## Background
Event Bus has no complete production authentication/authorization model, so
loopback binding is its effective security boundary (source Issue Background).
The same boundary should extend to MCP servers and other same-host HTTP services.

## Problem
`scripts/eventbus/config.py`'s `_is_public_host()` (repository evidence, full read)
detects only wildcard addresses (`0.0.0.0`, `::`, unspecified) — it does **not**
detect private-LAN (RFC 1918), other public, or non-loopback-but-valid addresses.
`EventBusConfig.host` could be set to a private-LAN address (e.g. `192.168.1.5`)
and `_is_public_host()` would return `False` (a valid, non-unspecified IP),
allowing the bind without `allow_public_bind` ever being consulted — the exact gap
the source Issue's Problem section warns about ("Binding to a private LAN address
is also outside the requirement"). `scripts/mcp_servers/server.py`'s `MCPServer`
base class has **no bind-address validation at all**: `http_host: str = "127.0.0.1"`
is a class-level default with no runtime check preventing a subclass or future
config path from overriding it to a non-loopback value (repository evidence:
`rg` found no `_is_public_host`/`is_public`/validation call in this file). Contrary
to the source Issue's premise that LLM and embedding services are same-host,
`config/agent.toml:10,23` and `config/rag_pipeline_mcp_server.toml:7-10` currently
set `embed_url = "http://192.168.11.238:8081"` and
`llm_url = "http://192.168.11.197:8080"` — both private-LAN addresses on different
hosts than the Agent process, not loopback (repository evidence, confirmed by
direct read of both config files). All 9 MCP server TOML `url` entries in
`config/agent.toml` already use `127.0.0.1` (repository evidence: `grep` found 0
non-loopback MCP server URLs), and no `--host` CLI argument or `HOST`-style
environment-variable override exists anywhere in `scripts/` (repository evidence:
`rg` found no match).

## Reason for Change
The target architecture disallows external HTTP access to Agent-internal services;
the current wildcard-only check leaves a real, exploitable gap for private-LAN
bindings, and the base MCP server class enforces nothing at all — both must be
closed regardless of how the `embed_url`/`llm_url` question resolves.

## Implementation intent
Extend `_is_public_host()` (or a shared helper both Event Bus and MCP servers can
call) to reject any address that is not `127.0.0.1` (and, only if intentionally
retained, `::1`) — private-LAN, other public, and unresolvable-hostname addresses
all fail, not only wildcard. Remove `EventBusConfig.allow_public_bind` entirely so
the check cannot be bypassed. Add the same validation to
`scripts/mcp_servers/server.py`'s `MCPServer.__init__`/startup path, even though no
current override path was found, per the source Issue's Constraint against relying
solely on "the default configuration is safe today." Add post-start socket
verification (confirm the actual bound socket via `socket.getsockname()` or
equivalent) for both Event Bus and MCP servers.

## Design
Path A/B classification (see `skills/issue-to-plan/SKILL.md` Routing): **Path B** —
this Plan changes a base class consumed by every MCP server (runtime-facing
interface change) and Event Bus's configuration validation. Architecture analysis
confirmed `_is_public_host()` is Event-Bus-local (no shared helper with
`scripts/mcp_servers/`) — this Plan's design introduces the same validation logic
to both without necessarily extracting a shared module, since `rules/coding.md`
scope discipline favors the smallest change that closes both gaps; a shared helper
extraction is left to the implementer's judgment during
`plan-to-implementation-procedure`; if it is not extracted, both call sites must
independently apply the identical address-class rules — do not diverge them.
Dependency graphing confirmed the MCP server base class's blast radius: every MCP
server subclass inherits `http_host` and would be affected by `REQ-003`'s
validation addition, but only `mdq_server.py` explicitly overrides it (with the
same safe value). Historical analysis found low, evenly distributed churn (3
authors on each in-scope file, low bus-factor risk); `scripts/eventbus/app.py` has
0 commits in the last 30 days. Operational dependency inspection: this Plan does
not change any listening port or running service's port number, only validates the
bind address more strictly — a currently-running Event Bus or MCP server instance
already bound to `127.0.0.1` is unaffected; a hypothetical instance bound to a
private-LAN address would fail to restart until corrected, which is the intended
effect of `REQ-001`/`REQ-003`.

  server `url` entries in `config/agent.toml` already resolve to `127.0.0.1`

  same safe value — no subclass is expected to fail the new check.
