# Plan: NC-019 Git MCP Protected-Branch Bypass via Empty Branch Argument

## Goal
- Prevent git-mcp handlers (`git_push`, `git_pull`) from bypassing protected-branch checks when the `branch` argument is empty.

## Priority
High

## Scope
- **In-Scope**: Fix `_validate_protected` to reject empty branch strings; add regression tests for `git_push` and `git_pull` with empty `branch` argument.
- **Out-of-Scope**: Changes to `git_checkout` (not affected); changes to other MCP servers; configuration schema changes.

## Background
Git MCP server has a protected-branch enforcement mechanism: `_check_protected_branch` denies operations on branches listed in `protected_branches` config. However, `_validate_protected` returns `(True, "")` when `branch` is empty string, skipping the protected-branch check entirely. Since `GitPushRequest.branch` and `GitPullRequest.branch` allow empty string as a valid value (default), an attacker can omit the `branch` argument to push/pull against the current branch without triggering the protection.

## Problem
When `branch=""`:
1. `git_push` line 301 calls `_validate_protected("")` → returns `(True, "")`
2. `git_pull` line 271 calls `_validate_protected("")` → returns `(True, "")`
3. Handler proceeds with operation on the current branch (which may be protected)
4. In `format_push` line 165: `branch = req.branch or repo.active_branch.name` uses current branch

## Reason for change
The current behavior violates the intended security boundary: protected-branch enforcement should apply regardless of whether the caller explicitly specifies a branch name. An empty branch argument effectively means "use whatever branch HEAD points to," which may be a protected branch.

## Implementation intent
Modify `_validate_protected` in `git_service.py` to return `(False, "[DENIED] branch must not be empty")` when the branch argument is falsy (empty string). This ensures protected-branch checks cannot be bypassed by omitting the branch parameter.

## Requirements
- `REQ-001`: `_validate_protected` must reject empty branch strings before proceeding with any git operation.
- `REQ-002`: `git_push` with empty `branch` argument must return a denial message containing `[DENIED]` and indicating branch is required.
- `REQ-003`: `git_pull` with empty `branch` argument must return a denial message containing `[DENIED]` and indicating branch is required.
- `REQ-004`: Existing protected-branch enforcement behavior must remain unchanged for non-empty branch names.

## Design
Minimal fix: modify `_validate_protected` to reject empty branch strings. The method currently returns `(True, "")` for falsy values, which skips the protected-branch check. Changing it to reject empty strings is a single-line change that closes the security gap without affecting other functionality.

```python
def _validate_protected(self, branch: str) -> tuple[bool, str]:
    """Check if a branch is protected."""
    if not branch:
        return False, "[DENIED] branch must not be empty"  # Changed from True, ""
    return self._check_protected_branch(branch)
```
