## Background
`docs/00_governance_01_documentation-policy.md` currently contains two competing authority models at once: a universal ranking of source types ("Canonical Source Precedence": Code > Tests > ADRs > Specifications > Configuration > Documentation) and a "Decision Target Canonical Source Matrix" that assigns different canonical sources per decision target. The universal ranking is also echoed outside this file: `docs/00_governance_04_documentation-checks.md` Manual Check 9 states "Code is the ultimate authority for behavioral claims", and `docs/06_eventbus_00_document-guide.md`'s own "Canonical Source Rule" states unconditionally that code should always be trusted over documentation.

## Problem
The universal ranking incorrectly suggests code always overrides tests, ADRs, Specifications, configuration, and documentation. This directly conflicts with the rule (already present in the Decision Target Canonical Source Matrix, and formalized by `M-01-01`'s taxonomy) that code is canonical for current runtime behavior but not for adopted design.

## Reason for change
Two competing, unreconciled authority models coexisting in the same governance document (and echoed in at least two other documents) risk a reviewer applying the wrong one and reaching a contradictory conclusion about which artifact is authoritative for a given conflict.

## Implementation intent
Replace `docs/00_governance_01_documentation-policy.md`'s "Canonical Source Precedence" universal-ranking table with a normative statement that the ranking is no longer authoritative, followed by the six-step resolution sequence and the six required conflict outcomes. Preserve the "Decision Target Canonical Source Matrix" subsection's actual per-target content (it becomes the primary reference the new resolution sequence points to), removing only its framing as a secondary/alternative model alongside the now-invalidated ranking. Update the two other identified restatements of the universal-ranking model (`docs/00_governance_04_documentation-checks.md` Manual Check 9's line 1, `docs/06_eventbus_00_document-guide.md`'s Canonical Source Rule) to reference the new resolution sequence instead of asserting unconditional code authority.

## Design
`docs/00_governance_01_documentation-policy.md`'s "## Canonical Source Precedence" heading is retained (so existing cross-references to the heading name do not break), but its body is replaced: the Rank 1-6 table is removed and replaced with (a) one sentence stating the ranking is no longer normative, superseded by the resolution sequence below (satisfies `REQ-001`), (b) the six-step resolution sequence as a numbered list (`REQ-002`), (c) a short note that a canonical source for one claim type does not extend to other claim types in the same document (`REQ-003`), (d) a short note on preserving intended-vs-observed state distinctly (`REQ-004`), (e) a short prohibition statement on auto-converting implementation deviations into approved specs (`REQ-005`), (f) the six required conflict-outcome rules as a table (`REQ-006`, `REQ-007`). The existing "### Decision Target Canonical Source Matrix" subsection is kept as-is (its per-target rows are the concrete registry the new Step 4 of the resolution sequence consults), with only its introductory sentence adjusted to describe itself as the sole per-target reference rather than an alternative to the now-removed ranking.

`docs/00_governance_04_documentation-checks.md` Manual Check 9's numbered list item 1 ("Code is the ultimate authority for behavioral claims") is replaced with a line pointing to the new resolution sequence (e.g. "Canonical authority is resolved per claim type and decision target — see `00_governance_01_documentation-policy.md`'s resolution sequence"). Items 2 (recency rule) and 3 (area document-guide) are left untouched (`M-01-03`'s scope covers item 2; item 3 is unrelated to the universal-ranking defect).

`docs/06_eventbus_00_document-guide.md`'s "## Canonical Source Rule" section's "trust the code" sentence is replaced with a reference to the new resolution sequence, preserving the existing guidance that `scripts/eventbus/` is canonical specifically for current runtime behavior (consistent with the taxonomy's `runtime-behavior` claim type), without extending that canonical status to other claim types (architecture decisions, requirements) as the current unconditional wording does.
