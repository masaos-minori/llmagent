## Background
`docs/03_rag_01_system_overview.md`'s "System Architecture" section (lines 44-56) already states, for both the Ingestion Pipeline and Query Pipeline component groups, each component's "Owned State", the "Reason for Process Separation" (failure isolation, independent scaling, deployment independence), and "Design Boundaries Requiring Joint Review" — but does not connect these bullets explicitly to answer why each specific ownership assignment holds. Separately, `docs/adr/ADR-005-rag-source-derived-index-relationships.md`'s "Rationale" section (lines 93-107) already documents, in an Accepted ADR, why SQLite's `documents`/`chunks` tables are authoritative and `chunks_fts`/`chunks_vec` are derived indexes (Data Integrity, Operability, Portability) — the same reasoning that grounds "SQLite (rag.db) owns the vector store layer" in the system overview.

## Problem
The Issue's Evidence quotes "Owned State: RagPipeline owns the query execution lifecycle; SQLite (rag.db) owns the vector store layer" and observes that the ownership model isn't explained inline. Verification confirms the *reasoning* that would explain this ownership already exists (Process Separation reasons in the same document; ADR-005's Rationale for the SQLite case) but is not connected to the ownership statements themselves, leaving a reader to independently infer the link.

## Reason for change
Per the Issue's Impact: developers modifying components may not understand ownership boundaries, and cross-component refactoring may violate implicit contracts. Connecting the already-accepted reasoning explicitly to each ownership statement reduces this risk without requiring new design decisions.
