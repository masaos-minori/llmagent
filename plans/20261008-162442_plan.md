# Plan: Unify cicd-mcp workflow_allowlist to file-name form

## Goal

Make the `workflow_allowlist` value format match what requests carry (a workflow file name such as `ci.yml`) so valid calls are no longer rejected, and reject path separators before matching.

## Priority

Medium

## Scope

- **In-Scope**:
  - `config/cicd_mcp_server.toml`: change `workflow_allowlist` value from full-path to file-name form
  - `scripts/mcp_servers/cicd/cicd_service_guards.py`: add path separator rejection before matching
  - `docs/22_mcp/mcp_05_01_access-control-and-allowlists.md`: update examples
  - `docs/00_governance/governance_03_issue-and-uncertainty-management.md`: remove MCP-003 from Known Issues ledger
- **Out-of-Scope**:
  - Other cicd guards
  - Repository allow-list

## Background

Source: local investigation notes (memo1.md, ISSUE-11), from MCP-003.

## Problem

- The configured value is a full-path form (Explicit in code — `config/cicd_mcp_server.toml` sets a path-style value), while its own comment and the requests use file names (e.g. `ci.yml`); matching therefore fails and valid calls are rejected.

## Reason for Change

- The feature is unusable. It fails on the safe side, but users who loosen the allow-list as a workaround make it dangerous.

## Implementation Intent

- Align the config, comments, and docs with the file-name form that the tool schema and tests assume.

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| Workflow value contains path separator (`/`) | Reject with CicdAuthorizationError before matching |
| Workflow value matches file name in allowlist | Allow |
| Workflow value does not match file name in allowlist | Reject |
| Empty allowlist | Deny all (fail-closed) |

### Decision details

1. **Change `workflow_allowlist` value to file-name form**: In `config/cicd_mcp_server.toml`, change `"masaos-minori/llmagent/.github/workflows/ci.yml"` to `"ci.yml"`. Update the comment example to match.
2. **Add path separator rejection**: In `cicd_service_guards.py::_assert_allowed_workflow()`, check if the workflow value contains a path separator (`/`) before matching against the allowlist. If it does, raise CicdAuthorizationError immediately.
3. **Update documentation**: Update `mcp_05_01_access-control-and-allowlists.md` examples to show file-name form; remove MCP-003 from the Known Issues ledger.
