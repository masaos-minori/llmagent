## Goal

Make the RAG pipeline resilient to LLM-side failures by adding explicit fallback paths: MQE failure falls back to original query; rerank failure falls back to RRF-ranked results.

## Scope

**In-Scope:**
- Add MQE failure fallback: when expand_queries() raises, set ctx.queries = [ctx.query]
- Add rerank failure fallback: when cross_encoder_rerank() raises, use ctx.merged directly
- Update stage status reporting to distinguish disabled vs failed-with-fallback
- Ensure AugmentStage always receives usable reranked hits when search and fusion succeed
- Add comprehensive tests for both fallback scenarios

**Out-of-Scope:**
- Changes to SQLite schema
- Changes to embedding service
- Changes to RRF fusion logic
- Changes to augment formatting

## Assumptions

1. MQE fallback uses the original query unchanged — no attempt to retry or modify the query.
2. Rerank fallback applies deduplicate_chunks() + rag_top_k slicing to ctx.merged (same as _rerank_fallback()).
3. Fallback reasons are recorded as distinct strings: "mqe_exception" and "rerank_exception".
4. Both fallbacks should be logged at INFO level for observability.
5. The fallback behavior should apply only on LLM exceptions, not on configuration errors.

## Risks

- **Risk**: MQE fallback with original query may produce significantly worse retrieval quality than expanded queries. → **Mitigation**: Log clearly; operators can monitor fallback frequency via diagnostics.
- **Risk**: Rerank fallback bypasses relevance scoring entirely — results are in RRF order, not reranked order. → **Mitigation**: Log clearly; this is better than producing no results at all.
- **Risk**: If AugmentStage cannot handle empty ctx.reranked even after rerank fallback, the pipeline may silently fail. → **Mitigation**: Verify AugmentStage handles empty reranked list; if needed, add additional fallback to raw chunks.
- **Risk**: Existing tests may expect "failure" status for LLM exceptions — changing to "fallback" breaks assertions. → **Mitigation**: Update existing test assertions to match new behavior.
