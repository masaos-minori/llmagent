## Goal
Add an end-to-end test that exercises the real `/reload` trigger path (`ConfigReloadService.apply_config_dict()` → `_sync_services()`) against a real, non-mocked `RuntimeToolRegistry` instance, confirming both that `apply_policy()`'s effect is observable and that no MCP tool-discovery HTTP call occurs during reload — closing the verification gap tracked as `CI-003`.

## Priority
Medium

## Scope
- **In-Scope**: One new end-to-end test in `tests/agent/services/test_config_reload.py` that calls `ConfigReloadService.apply_config_dict()` (the actual `/reload`-invoked entry point, confirmed as the sole caller of `_sync_services()` outside tests) with a real `RuntimeToolRegistry` instance; update `CI-003`'s governance entry once the test passes.
- **Out-of-Scope**: Changing `apply_policy()`'s or the reload trigger's actual behavior (unless the new test reveals a genuine discrepancy, in which case this Plan is paused and the discrepancy is reported rather than silently fixed); any change tied to `mcpagent04` (runtime policy reload reversibility) — that issue is still unprocessed (`issues/20260914-103138_mcpagent04_runtime-policy-reload-reversibility.md`), so this Plan's test targets current, unmodified reload behavior, not a corrected future behavior.

## Background
`docs/00_governance_03_issue-and-uncertainty-management.md` `CI-003` ("ADR-003 Decision Details #14 — reload-updates-only-policy-fields claim not verified", Status: open, Severity: Medium) states: "The implementation appears correct based on code inspection of `apply_policy()`, but this has NOT been validated against the actual reload flow." This Plan is the direct implementation-tracking counterpart to that Known Issue entry.

## Problem
Confirmed by direct inspection of `tests/agent/services/test_config_reload.py`:
- The class actually named `TestRuntimeToolPolicyReapplication` (line 439 — the source Issue named it `TestApplyPolicy`, a minor naming discrepancy that does not change the substance of the finding) contains `test_apply_policy_called_with_current_tier_map_and_allowed_tools` (line 454) and three sibling tests, all of which construct `ConfigReloadService` with `ctx = MagicMock()` (line 445) and call `svc._sync_services(...)` directly (lines 456, 464, 469, 476) — bypassing the real trigger entry point entirely.
- The real `/reload` entry point is `ConfigReloadService.apply_config_dict()` (`scripts/agent/services/config_reload.py`, line 215) — confirmed as the only non-test caller of the class, invoked from `scripts/agent/commands/cmd_config.py` line 60. `apply_config_dict()` internally calls `_sync_services()` (line 278).
- Tests that *do* call `apply_config_dict()` (e.g. `test_apply_config_dict_applies_llm_fields_via_registry`, line 836, using the `svc_with_mocked_mcp` fixture at line 816) still run against the same `ctx = MagicMock()` base fixture (line 57) — `ctx.services_required.runtime_tools` is never replaced with a real `RuntimeToolRegistry` instance in any existing test, so `apply_policy()`'s effect and the discovery-skip guarantee are never observed against real registry state through the real entry point.
- `test_reload_does_not_fetch_tools_over_http` (line 472) explicitly documents its own limitation in a comment: "Uses direct `_sync_services` call to avoid MCP discovery complexity."
- `RuntimeToolRegistry`'s constructor (`scripts/shared/runtime_tool_registry.py`, line 37) takes a simple `{tool_name: RuntimeTool}` dict — confirmed constructible directly in a test without live MCP servers, via the existing helper pattern already used in `tests/shared/test_runtime_tool_registry.py` (line 15).

The Issue's core claim is confirmed accurate: no existing test exercises `apply_config_dict()` against a real `RuntimeToolRegistry` instance.

## Reason for change
Per `CI-003`'s own stated Impact: if reload also re-triggered tool discovery, it would violate the invariant that policy changes don't alter tool availability. This is a safety-relevant invariant with no test that would catch a regression introduced anywhere between the real `/reload` trigger and `apply_policy()`'s invocation — only the isolated method and a fully-mocked registry are currently tested.

## Implementation intent
Add one end-to-end test to `tests/agent/services/test_config_reload.py` that: (1) constructs a real `RuntimeToolRegistry` with a small, representative tool set (reusing the construction helper pattern from `tests/shared/test_runtime_tool_registry.py`); (2) wires it into a `ConfigReloadService` instance's `ctx.services_required.runtime_tools` in place of a `MagicMock()`; (3) calls `apply_config_dict()` (the real trigger path) with a config change affecting `tool_safety_tiers`/`allowed_tools`; (4) asserts the real registry's tier/allowed-tools state actually changed; (5) asserts no HTTP client `.get()`/discovery call occurred during the call, extending `test_reload_does_not_fetch_tools_over_http`'s existing intent to the real trigger path.
