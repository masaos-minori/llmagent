## Goal

Prevent prompt injection via memory snippets by adding PII filtering, length limits, and priority marking to the memory injection pipeline.

## Scope

**In-Scope**:
- Wire up `snippet_filter.filter_pii()` in `injection.py` snippet building pipeline
- Wire up `snippet_filter.truncate_snippet()` with configurable max length (default 500)
- Add priority marker to system message in `orchestrator.py`
- Log warnings when snippets are filtered or truncated

**Out-of-Scope**:
- Adding new PII patterns to `snippet_filter.py`
- Changing InjectionPolicy defaults beyond snippet length limit
- Modifying the retriever search logic itself

## Assumptions

1. `snippet_filter.py` is a newly added module not yet integrated into the codebase
2. Regex-based PII detection is sufficient; no need for ML-based PII detection at this stage
3. The 500-character snippet length limit matches the requirement specification
4. Existing callers of `on_user_prompt()` do not depend on unfiltered snippet content

## Implementation Steps

1. **Phase 1: Wire snippet_filter into injection.py**
   - Import `filter_pii` and `truncate_snippet` from `snippet_filter`
   - In `_build_snippets_from_hits`: apply `filter_pii()` then `truncate_snippet()` to each snippet text
   - Add `max_snippet_length` field to `InjectionPolicy` (default 500)
   - Pass policy.max_snippet_length to `truncate_snippet()`

2. **Phase 2: Add priority marker in orchestrator.py**
   - Modify `_handle_memory_injection()` to include a priority marker in the system message content
   - Example: prepend `[PRIORITY: LOW - MEMORY CONTEXT]` before the memory block

3. **Phase 3: Add warning logs**
   - When `filter_pii.was_filtered=True`, log warning with snippet count
   - When `truncate_snippet.was_truncated=True`, log warning with original length
