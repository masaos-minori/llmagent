# Plan: Detect duplicate canonical document specification in unregistered prose (GV-009)

## Goal
Add a heuristic checker that scans `docs/*.md` for prose asserting a document is the
canonical/normative source for a topic or claim type, and flags such unregistered claims
that overlap a registered source in the Canonical Source Registry or another prose claim.
This closes the documented `Partial` gap for GV-009 without changing the registration
process, then mark GV-009 `Existing`.

## Priority
Medium

## Scope
- **In-Scope**:
  - Create a new standalone checker under `tools/` that scans `docs/*.md` for conservative
    canonical-assertion patterns.
  - Match each asserted claim against the Canonical Source Registry (`config/`) by subject
    (path token / `decision_target`) and flag overlaps with a registered source or another
    prose claim.
  - Wire the new warning-level check into the existing governance-docs-consistency CI
    workflow for visibility.
  - Add unit tests with positive (duplicate/unregistered) and negative (benign/incidental)
    fixtures.
  - Update the GV-009 matrix row to `Existing` and clear its follow-up note.
- **Out-of-Scope**:
  - Changing the Canonical Source Registry schema.
  - Changing the behavior of `check_canonical_source_registry.py` (GV-020) or
    `check_canonical_source_conflicts.py` (GV-019).
  - GV-010 (multiple primary sources in the same area) — separate issue.

## Background
`governance_04_documentation-checks.md` maps GV-009 ("Duplicate canonical document
specification") to human review, noting that registered claims are checked by GV-019 while
the remainder is manual. Its status is `Partial`. GV-019 enforces single-normative-source-per-
claim-type only for entries present in the Canonical Source Registry. Prose that asserts a
source is canonical without registering it bypasses GV-019 entirely.

## Problem
An author can state in prose that "X is the canonical source for topic Y" without adding X to
the registry. Such unregistered canonical claims bypass GV-019, so competing or duplicate
canonical specifications can coexist undetected.

## Reason for change
GV-009 is a Warning-level gate; undetected duplicate canonical prose creates ambiguity about
which document governs a given claim type. Automating detection of unregistered canonical
claims closes the documented `Partial` gap.

## Implementation intent
Scan `docs/*.md` with a conservative, reviewed pattern set for sentences asserting
canonical/normative status (e.g. "the canonical source for", "is the normative reference
for", "authoritative source for"). For each match, extract the claimed subject (a path token
or `decision_target` token adjacent to the assertion) and compare it against the registry's
`source_paths` and `decision_target`s and against other prose claims sharing that subject.
Flag overlaps as WARNING. This complements GV-019; it does not redefine what counts as
registered.

## Requirements
- `REQ-001`: The checker scans `docs/*.md` using a conservative, reviewed pattern set that
  avoids false positives on incidental uses of the word "canonical" (including negations such
  as "not treated as the top canonical source").
- `REQ-002`: A prose canonical claim whose extracted subject matches a registered
  `source_paths` entry or `decision_target` is flagged as a WARNING (overlap with a
  registered source).
- `REQ-003`: Two or more prose canonical claims sharing the same extracted subject are flagged
  as WARNING (duplicate unregistered specification).
- `REQ-004`: No WARNING is emitted for the current `docs/` corpus on benign/incidental
  mentions that do not denote a real canonical conflict.
- `REQ-005`: The GV-009 matrix row status changes from `Partial` to `Existing` and its
  follow-up note is cleared.

## Design
The new checker is a standalone CLI following the `check_canonical_source_*.py` convention
(argparse, `--registry`/`--docs` options where relevant, WARNING/ERROR `Issue` results).

1. **Pattern scan.** Compile a conservative, reviewed regex set for canonical assertions:
   "the canonical source for", "is the normative reference for", "authoritative source for",
   plus close variants. Exclude obvious negations (a preceding "not"/"never"/"no") and
   non-assertional uses. Keep the set reviewed and documented (UNK-02).
2. **Subject extraction.** For each match, extract the nearest subject candidate: a path-like
   token (`\w[\w./-]+\.py`, `scripts/...`, `docs/...`) or a `decision_target`-like token
   (`word.word(-word)*`). If none is found, the claim is not matched against the registry
   (fail safe).
3. **Registry overlap (REQ-002).** Load `config/documentation_canonical_sources.toml`. Flag a
   claim whose subject matches any registered `source_paths` entry or `decision_target`.
4. **Duplicate prose (REQ-003).** Group claims by extracted subject across all of `docs/`;
   flag subjects shared by two or more claims.
5. **Reporting.** Emit WARNING findings only; preserve the existing severity/exit contract of
   the sibling canonical tools.
6. **CI wiring.** Add the new script to the trigger paths and the canonical-tool run block in
   `governance-docs-consistency.yml` so findings surface in PRs.

No change to the registry schema or to `check_canonical_source_registry.py` /
`check_canonical_source_conflicts.py` behavior (GV-020 / GV-019).

## Risks
- **Risk**: High false-positive rate from incidental "canonical" usage in prose. →
  **Mitigation**: Conservative reviewed pattern set, negation exclusion, fail-safe
  (unmatched subjects not flagged), and negative fixtures tuned against the current corpus
  (UNK-02, UNK-03).
- **Risk**: Subject-extraction heuristic may mismatch prose subjects against registry entries.
  → **Mitigation**: Token/substring matching scoped to literal subjects; unmatched subjects
  are not flagged (UNK-03).
- **Risk**: The issue's GV-019/GV-020 tool naming is swapped. → **Mitigation**: Read the
  registry TOML directly; do not call either existing tool; note the correction (UNK-01).
