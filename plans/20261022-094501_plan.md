# Plan

## Goal
Remove every remaining reference to the deleted function `read_json_file()` from the governance documents and one tool comment, and make the Glossary examples in "Compatibility and Lifecycle Terminology" free of statements about the status of specific code symbols, so that they cannot go stale with each removal.

## Priority
Medium

## Scope
- **In-Scope**:
  - Rewrite the Example cells of the `Obsolete`, `Migration`, `Operational Fallback`, `Default`, and `Lenient Parsing` Glossary rows so they name no symbol whose status can change.
  - Add one sentence to the Glossary stating that it defines terms and is not a register of code status.
  - Replace the `read_json_file` example in the `governance_04` bullet and the `tools/check_compat_shims.py` comment with a description of the category that names no symbol.
- **Out-of-Scope**:
  - Term and Definition cells; the `Backward Compatibility` and `Dead Code` rows (already generic).
  - An automated Glossary reference check (generalizing is chosen, so `tools/check_glossary_term_classification.py` is untouched).
  - Implementing the context-aware "is this presented as current" check that `governance_04` calls a follow-up.
  - Any behavior change in `tools/check_compat_shims.py`.

## Background
`read_json_file()` and its private helpers were removed from `scripts/rag/ingestion/pipeline_utils.py`; `rg read_json_file docs tools scripts tests` finds exactly three places that still use the name as a live example: the `Obsolete` row in `docs/00_governance/governance_02_documentation-metadata.md`, the context-aware-check bullet in `docs/00_governance/governance_04_documentation-checks.md`, and a comment in `tools/check_compat_shims.py`. A name absent from source belongs to the other category those texts define, so each example now contradicts its own point. The earlier work item for this was archived by a rename-only commit with no content change. The `Migration` row names `db/schema_sql.py::apply_workflow_migrations()`, which the workflow-migration removal Plan (`plans/20261022-093726_plan.md`) deletes. The other symbol-naming examples (`Operational Fallback` names `call_rag_service()`, `Default` names `get_typed`, `Lenient Parsing` names `production_config_validator.py`) name symbols that currently exist (confirmed by search).

## Problem
Glossary rows define terms but their examples state the current status of specific symbols, so they drift with every refactor; one already contradicts the definition it illustrates, and the governance check text and a tool comment repeat the same example.

## Reason for Change
Stale examples in the documents that define the project's vocabulary mislead readers and tooling that treat the Glossary as authoritative, and each future removal repeats the problem. Keeping status out of the Glossary removes the drift at its source.

## Implementation Intent
Keep the Glossary abstract: definitions plus examples that name no symbol whose status can change, and one scope sentence. Replace the `read_json_file` examples in the governance check text and the tool comment with a generic description of the category, since no real example of "a name that remains in source but is no longer the current production path" is known. Generalize the remaining symbol-specific examples rather than guard them with a new check (the smaller change; no tool behavior change). This Plan also covers the Glossary `Migration` example, which the workflow-migration removal Plan would otherwise leave dangling, so that Plan needs no Glossary edit.

## Requirements
- `REQ-001`: Rewrite the `Obsolete` example so it names no function, class, or config key.
- `REQ-002`: Rewrite the `Migration` example so it does not name `apply_workflow_migrations()` or any specific symbol.
- `REQ-003`: Generalize the `Operational Fallback`, `Default`, and `Lenient Parsing` examples so each names no symbol or file whose status can change; no Term or Definition cell changes.
- `REQ-004`: Add one sentence to the Glossary stating that it defines terms and is not a register of code status.
- `REQ-005`: Replace the `read_json_file` example in the `governance_04` removed-name bullet with a description that names no symbol, keeping the rest of the bullet and its "not yet implemented" statement.
- `REQ-006`: Replace the `read_json_file` example in the `tools/check_compat_shims.py` comment with a description that names no symbol; comment-only edit with no behavior change.

## Design
- Path A (three files, no interface or schema change); the validation quality baseline was recorded: `check_compat_shims.py` and `check_glossary_term_classification.py` report no findings, `bandit` is clean, and `check_compat_shims.py` has two functions at complexity grade C that this comment-only edit does not touch.
- The Glossary scope sentence is added as one sentence in the section introduction, not as a new table row, so no Term or Definition cell changes.
- Generalized examples describe the category in words (for example, a superseded function that is still callable) instead of naming code; this keeps the examples correct across refactors and removes the need for an automated reference check.
- Ordering: apply this change before the workflow-migration removal Plan, or in the same change; if the removal lands first, its acceptance command `rg "apply_workflow_migrations|_WORKFLOW_MIGRATIONS" ... docs` fails until this Plan lands.
