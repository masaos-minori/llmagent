## Goal

Add filtering policies for memory snippets before LLM injection to prevent prompt injection via manipulated memory search queries, including PII filtering, length limits, and priority markers.

## Scope

**In-Scope:**
- Add PII/credential filtering layer for memory snippets before injection
- Implement maximum snippet length limit (e.g., 500 characters per snippet)
- Add priority marker to system message indicating lower priority than user messages
- Log warnings when snippets are filtered or truncated

**Out-of-Scope:**
- Modifying the memory retrieval logic itself
- Adding new PII detection patterns beyond standard regex-based detection
- Changing the conversation history compression behavior
- Modifying ephemeral message handling

## Assumptions

1. Standard PII patterns (email addresses, phone numbers, credit card numbers, API keys) are sufficient for initial filtering
2. A 500-character per-snippet limit balances context utility against injection risk
3. Priority marker can be expressed as a special key in the system message content (e.g., `[SYSTEM-PRIORITY:LOW]`)
4. Filtering/truncation should preserve snippet meaning where possible
