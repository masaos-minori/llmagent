# Plan: Fix EventBus ACK and NACK state management

## Goal

Manage delivery state per consumer only, make NACK idempotent per delivery attempt, and make ACK record the first acknowledgement time for existing events exactly once.

## Priority

Medium

## Scope

- **In-Scope**:
  - `scripts/eventbus/delivery_repo.py`: add per-consumer failure count tracking, NACK idempotency, DLQ promotion decision
  - `scripts/eventbus/ack_route.py`: update ACK/NACK handlers for per-consumer semantics, remove debug log
  - `scripts/eventbus/schema.sql`: add per-consumer failure count column to `consumer_delivery`
  - `scripts/db/schema_sql.py`: add migration for existing databases
  - `scripts/eventbus/_constants.py`: add new column constant
  - `scripts/eventbus/dlq.py`: update DLQ promotion logic to use per-consumer failure count
  - `docs/10_adr/ADR-006-eventbus-sqlite-persistence-and-sse-delivery.md`: revise INV-10
  - `docs/24_eventbus/eventbus_12_ack_nack_endpoints.md`: update ACK/NACK documentation
  - `docs/00_governance/governance_03_issue-and-uncertainty-management.md`: update Known Issues
- **Out-of-Scope**:
  - Authorization model changes (separate issue)
  - DLQ model changes beyond per-consumer failure count
  - Health endpoint changes of unrelated servers

## Background

Source: local investigation notes (memo1.md, ISSUE-08), consolidating EVENTBUS-012, EVENTBUS-011, EVENTBUS-014 and three earlier findings. Delivery is at-least-once, so client re-sends are routine.

## Problem

- `nack_event()` increments the failure count on every call, so a re-sent NACK for the same delivery double-counts (EVENTBUS-012).
- `delivery_failure_count` is one value per event row shared by all consumers, so one consumer's repeated NACKs can send the event to the DLQ before other consumers process it.
- The NACK rejection state check (-2) runs under a separate lock acquisition from the NACK itself; if the event is deleted in between, 409 is returned instead of 404 (EVENTBUS-011).
- `events.acked_at` is never written but is read in the NACK WHERE clause and the 409 branch; an unreferenced `ack_event()` remains (EVENTBUS-014).
- ACK for a non-existent event_id commits an orphan `consumer_delivery` row (no foreign key).
- Re-ACK overwrites `acked_at` through `ON CONFLICT DO UPDATE`, losing the first ACK time; events already in the DLQ can still be ACKed.

## Reason for Change

- Non-idempotent NACK moves events to the DLQ earlier than intended under routine retries.
- Shared failure counts defeat the multi-consumer design: one faulty consumer blocks others.
- Reading a never-written column leaves misleading state-transition documentation.
- Orphan rows, overwritten ACK times, and ACKs on DLQ events harm audit and data integrity and violate state-transition rules.

## Implementation Intent

- Per-consumer state in `consumer_delivery` as the single model; no event-level ACK state.
- NACK idempotent per delivery attempt; ACK recorded once, for existing, non-DLQ events.

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| Same NACK sent twice for same delivery attempt | Ignore (idempotent) |
| Consumer A's NACKs | Do not affect consumer B's DLQ decision |
| ACK for non-existent event_id | Return 404, write nothing |
| Re-ACK of same event by same consumer | Keep first `acked_at` via `COALESCE` |
| ACK for DLQ event | Return 409 |
| NACK for already-ACKed event | Return 409 |

### Decision details

1. **Add per-consumer failure count to `consumer_delivery`**: Add `consumer_delivery_failure_count` and `last_nack_attempt` columns to `consumer_delivery` table. Use `last_nack_attempt` for NACK idempotency — ignore a NACK if the attempt ID matches the last one.
2. **Make DLQ promotion per-consumer**: Update `dlq.py` to check `consumer_delivery_failure_count` instead of `delivery_failure_count` for DLQ promotion.
3. **Perform NACK handling in one lock acquisition**: Move the -2 state determination into the same transaction as the NACK increment.
4. **Remove `events.acked_at` column**: Drop the column using the existing `_migrate` approach, remove `ack_event()`, the 409 branch reading the column, and the unused `requeue_event()`.
5. **Fix `ack_event_for_consumer()`**: Verify event existence before writing `consumer_delivery`; keep first `acked_at` via `COALESCE`; return 409 for DLQ events.
6. **Remove debug WARNING log**: Change `logger.warning("DEBUG _do_ack: ...")` to `logger.debug(...)`.
