## Goal
- Fully mask secret values in `agent.secrets_masker._mask_secrets()` regardless of their length, while keeping only the key name in the output, so that no character of a secret value leaks into logs or error reports.

## Priority
High

## Scope
- **In-Scope**:
  - Fix the replacement logic in `scripts/agent/secrets_masker.py` so the entire matched value is masked for any value length, preserving the key name and separator.
  - Add a dedicated unit-test module for `_mask_secrets()`.
  - Update the startup-and-health operations doc to remove the documented leakage limitation and state the final set of masked forms.
- **Out-of-Scope**:
  - Changing which call sites apply the masker (`http_lifecycle.py`, `http_lifecycle_errors.py`, `startup_mcp_starter.py`, `retry_helper.py`).
  - Adding patterns for non-`key=value` credential forms such as `Authorization: Bearer ...`, `Cookie`, or other header shapes.
  - Introducing a general log-redaction framework.

## Background
`_mask_secrets()` is used when the Agent reports MCP subprocess startup failures (stderr tail) and when it logs a failed first startup attempt for an MCP subprocess. It was found while documenting the module; it had no documentation and no tests.

## Problem
The current replacement keeps `match[:10]` and appends `***MASKED***`. The match includes the key name and the `=` sign, so the number of value characters that survive depends on the key length. Observed with the current code: `password=hunter2` becomes `password=h***MASKED***` (one value character leaks), `api_key=sk-1234567890abcdef` becomes `api_key=sk***MASKED***`, `GITHUB_TOKEN=ghp_abcdef123` becomes `GITHUB_TOKEN=ghp_***MASKED***`, and `token=abc` and `secret=x` are returned with the full value visible (the match is shorter than 10 characters). Values that are not written as `key=value` (for example an `Authorization: Bearer ...` header) are not matched at all.

## Reason for change
Secret values must not appear in logs or error reports. A masker that leaks short values and the start of long ones gives a false sense of protection in a security-sensitive path.

## Implementation intent
Change the regex substitution so each pattern captures the value separately from the key-name prefix, and the replacement keeps only the captured prefix (key name + separator) and replaces the captured value with the masked sentinel. This makes masking independent of value length while preserving the helper's public contract (replace secrets in a string) and every call-site signature. Keep one regex pass per pattern and retain the `***MASKED***` sentinel so downstream consumers/tests that look for `"MASKED"` continue to work.

## Requirements
- `REQ-001`: In `scripts/agent/secrets_masker.py`, replace the current `pattern.sub(lambda m: m.group()[:10] + "***MASKED***", ...)` so that the entire matched secret value is masked regardless of length while the key name and separator are preserved. The helper must not raise on arbitrary input, including empty strings, and must stay cheap (one regex pass per existing pattern).
- `REQ-002`: Keep masking scoped to the four existing `key=value` families (`password`/`passwd`/`pwd`, `api_key`/`apikey`, `secret`, `token`, case-insensitive). Do NOT add patterns for bearer/`Authorization`/`Cookie`-style credentials; record this scope decision in the doc.
- `REQ-003`: Add a new unit-test module `tests/agent/test_secrets_masker.py` covering: short values (`token=abc`, `secret=x`) fully masked; long values fully masked; mixed-case keys; text with no secrets returned unchanged; empty string returns unchanged; arbitrary text never raises.
- `REQ-004`: Update the startup-and-health operations doc: remove the "known defect / short values not masked" limitation note and state the final set of masked forms (the four `key=value` families, case-insensitive).

## Design
High-level approach (no code prescribed). Convert each existing pattern from a non-capturing match over the whole `key=value` fragment into a capturing group around the value (`\S+`). Replace with a lambda that keeps `m.group(1)` (the captured key-name + separator prefix) and appends the `***MASKED***` sentinel, discarding the captured value. This makes masking independent of value length, preserves the public contract and call-site signatures, keeps one regex pass per pattern, and introduces no new imports or patterns. `retry_helper._mask_secrets` already delegates to this helper, so the fix propagates transitively to its callers.
