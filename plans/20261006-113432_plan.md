## Goal
Eliminate spurious shutdown log noise caused by same-state lifecycle transitions (e.g., STOPPED→STOPPED) that are harmless during shutdown but produce misleading warnings.

## Priority
Low

## Scope
- **In-Scope**: Suppressing same-state transition warnings during shutdown; adding same-state transitions to the valid transitions table
- **Out-of-Scope**: Changing the lifecycle state machine logic for non-same-state transitions; modifying other lifecycle management behavior; adding new lifecycle states

## Background
The `LifecycleManager` logs warnings when a state transition is invalid. During shutdown, some MCP servers attempt transitions that are invalid per the lifecycle state machine (e.g., STOPPED→STOPPED is not in the valid targets `{STARTING, FAILED}`). The state machine explicitly disallows same-state transitions.

## Problem
Shutdown output includes messages like:
```
Lifecycle: invalid state transition <LifecycleState.STOPPED: 'stopped'> -> <LifecycleState.STOPPED: 'stopped'> for 'X'
```
These occur because the lifecycle state machine does not allow same-state transitions (STOPPED→STOPPED is not in the valid targets `{STARTING, FAILED}`).

## Reason for change
These messages are harmless during shutdown but indicate a mismatch between the lifecycle state machine and shutdown behavior. Two approaches are possible:
1. Suppress same-state transition warnings (quick fix, changes semantics)
2. Add same-state transitions to the valid transitions table (correct fix, preserves semantics)

## Implementation intent
Add same-state transitions to the `_VALID_TRANSITIONS` table in `scripts/agent/lifecycle.py`. This is the preferred approach — it makes the state machine semantically correct rather than hiding the inconsistency.

## Requirements
- `REQ-001`: Same-state transitions (e.g., STOPPED→STOPPED) must not produce warning log messages during shutdown.
- `REQ-002`: Legitimate invalid state transitions (different source and target states) must still produce warnings.
- `REQ-003`: Shutdown must complete normally without spurious log noise.

## Design
**Preferred approach: Option B — Add same-state transitions to the valid transitions table.**

Rationale: Adding same-state transitions to `_VALID_TRANSITIONS` makes the state machine semantically correct rather than hiding the inconsistency. This is the cleaner fix because:
1. It preserves the invariant that the state machine accurately reflects allowed transitions.
2. It avoids suppressing legitimate warnings that might occur in other contexts.
3. It aligns with the principle that the state machine should model reality, not work around it.

**Option A (suppress same-state transition warnings)** is a quick fix that changes semantics — it would suppress warnings even if same-state transitions occurred outside of shutdown, which could mask real issues.

### Implementation details
- In `scripts/agent/lifecycle.py`, add `LifecycleState.STOPPED` to the valid targets of `LifecycleState.STOPPED`:
  ```python
  LifecycleState.STOPPED: frozenset({LifecycleState.STARTING, LifecycleState.FAILED, LifecycleState.STOPPED}),
  ```
- No changes to `scripts/agent/factory.py` are needed since the state machine will now accept the transition.
