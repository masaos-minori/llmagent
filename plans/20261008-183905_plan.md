## Problem
- The Context Constraints say the endpoint "accepts calls authenticated only by an optional Bearer token" (Explicit in ADR-012 line 41), which contradicts ADR-007 INV-09 where every enabled server entry carries a non-empty token and every server verifies it (Explicit in ADR-007).
- The Verification item for INV-02 reads "`git_push` exposes no `force` parameter, so a forced update is unreachable through the normal path" (Explicit in ADR-012). That reasoning ignores refspec syntax in `branch`, which the ADR's own Rationale 1 calls "not a control".
- The tests that do verify it exist: `TestWriteRefAllowlist::test_rejected_branch_forms` rejects `+main`, `feature:main`, `HEAD:main`, `refs/heads/main`, `main~1`, and `TestGitPushRefRejectionBeforeGit::test_rejected_before_snapshot` shows the push is rejected before any GitPython call (Confirmed by repository evidence — `tests/mcp_servers/git/test_git_service_dispatch.py`).
- Security Consequences claim the option-injection vector is closed "by rejecting values that start with `-`", which understates the validator (`GitService._validate_ref_allowlist`, `scripts/mcp_servers/git/git_service.py`) and no longer describes the real check.
- Decision item 2 gives "leading `-`" as the only example of a rejected value, and item 3 and INV-02 do not mention refspec syntax.
- Known Deviations uses a free-form bold heading "MCP-004 — residual known deviation" instead of the `Known Issue` form, and its text differs from the ledger (Explicit in ADR-012 line 185 and `docs/00_governance/governance_03_issue-and-uncertainty-management.md` MCP-004).
- MCP-001 and MCP-002 are not in the ledger any more and `git_server.py` wraps the audit call in `_audit_log_safe`; they must not be cited (Confirmed by repository evidence).

## Reason for change
- A reader trusting the ADR would believe an unauthenticated endpoint is allowed and that forced updates are unreachable only because a field is missing, which is the reasoning the ADR itself rejects.
