# Plan: Add consistency check for _cmds duplication between _repl_loop and _dispatch_line

## Goal
- Unify duplicate _cmds None-checks into a single authoritative location and document the immutability contract

## Priority
Low

## Scope
- **In-Scope**: Unify the _cmds None-check into a single location; document the immutability contract for _cmds after initialization
- **Out-of-Scope**: Adding new command types; changing the command registration mechanism

## Background
Both methods independently guard against _cmds being None. This redundancy is unusual for a value set once during initialization.

## Problem
If _cmds were ever mutated concurrently (even accidentally), the first check would pass but the second might not, leading to inconsistent behavior.

## Reason for change
Code quality concern: duplicated defensive checks suggest uncertainty about ownership. A single authoritative check would be clearer.

## Implementation intent
Remove the redundant check from _dispatch_line and document that _cmds must not be mutated after initialization. Choose the approach that best reflects the actual mutability contract for _cmds.

## Requirements
- `REQ-RIL002-1`: Single authoritative check for _cmds availability
- `REQ-RIL002-2`: Immutability contract documented
- `REQ-RIL002-3`: No behavioral regression
