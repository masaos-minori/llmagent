## Assumptions
1. `DocFile`, `Issue`, `check_port_drift`, `check_tool_name_drift`, and `main` are all importable as
   `from check_mcp_docs_consistency import ...` (bare module name, no `tools.` prefix) under
   pytest. Verified: `tools/check_mcp_docs_consistency.py` lines 53-64 import `DocFile`, `Issue`,
   and the generic checks from `tools._docs_consistency_lib` into its own module namespace, and
   `tests/conftest.py` lines 15-16 unconditionally insert both `scripts/` and `tools/` into
   `sys.path` before any test module executes, so `import check_mcp_docs_consistency` (not
   `tools.check_mcp_docs_consistency`) resolves regardless of `PYTHONPATH`. The sibling file
   `tests/tools/test_check_agent_docs_consistency.py` already uses this exact bare-module,
   re-exported-symbol import pattern (`from check_agent_docs_consistency import DocFile,
   check_broken_internal_links, ...`), confirming it as this test directory's established
   convention, not a guess.
2. `check_port_drift(docs_dir, files, repo_root)` and `check_tool_name_drift(docs_dir, files,
   repo_root)` need a real `repo_root: Path` with `config/agent.toml` and/or
   `scripts/mcp_servers/**/*.py` under it — a `tmp_path`-based synthetic repo root, not the real
   repo — for deterministic, drift-proof fixtures. Verified by reading both functions' full bodies
   (`check_mcp_docs_consistency.py` lines 74-107 and 166-180): `_extract_authoritative_ports` reads
   `repo_root / "config" / "agent.toml"` via `tomllib`; `_extract_live_tool_names` globs
   `repo_root / "scripts" / "mcp_servers"` for `*.py` files and regex-extracts
   `{"name": "..."}`-shaped entries. `docs_dir` itself is unused by either function's body (only
   `files: list[DocFile]` and `repo_root` matter) — `docs_dir` can be any `Path` (e.g. `tmp_path`
   itself) for these two functions' unit tests.
3. `_extract_authoritative_ports`'s doc-name convention is `f"{key.replace('_', '-')}-mcp"` (e.g.
   config key `web_search` → doc name `web-search-mcp`), and it only extracts a port when the TOML
   `url` string ends in `:<2-5 digits>` optionally followed by a trailing quote/whitespace
   (`_URL_PORT_RE`). Verified directly by reading lines 74-107 and cross-checked against
   `config/agent.toml`'s real `[mcp_servers.web_search]` block (`url = "http://127.0.0.1:8004"`),
   which the regex matches.
4. `check_port_drift`'s doc-side match requires the doc-name token (e.g. `web-search-mcp`) and a
   bare 4-digit number **on the same line**, and only flags a mismatch when the mentioned number
   `startswith("80")` (`_DOC_PORT_RE` + the `mentioned.startswith("80")` guard at line 139) — a
   number outside the `80xx` prefix is silently skipped (`continue`), not flagged, regardless of
   whether it matches. This must NOT be conflated with the `is_historical_line()` skip path, which
   is a separate, earlier `continue` (line 131) that skips the whole line before any name/port
   matching — both are independently testable "no issue despite apparent mismatch" cases.
5. `check_tool_name_drift`'s doc-line trigger requires `_TOOL_ENUM_LINE_RE`
   (`(?:ツール|Tools?)\s*[:：]\s*(.+)`) to match, then extracts backtick-quoted identifiers via
   `_BACKTICK_IDENT_RE` from the captured tail only, and skips (does not flag) any backtick name with
   no underscore ("too generic", line 208-209) before checking membership in `live_names`. Verified
   by reading lines 183-224 in full.
6. `main()`'s exit code is `1` only if at least one `ERROR`-severity issue was produced
   (`report_and_exit`, `tools/_docs_consistency_lib.py` lines 411-426); a run producing only
   `WARNING`s exits `0`. Because `check_tool_name_drift` only ever emits `WARNING`, a `--skip
   tooldrift` test **cannot** be verified via `main()`'s return value alone (it would be `0` either
   way) — it must assert on captured stdout (`capsys`) for the presence/absence of the
   `` `<name>` as a tool`` message text. `check_port_drift` emits `ERROR`, so a `--skip portdrift`
   test CAN additionally assert on the return value (`1` → `0`) in addition to/instead of captured
   output. This determines the exact assertion shape for the two `--skip` tests and is not
   interchangeable between the two checks.
7. `discover_md_files(docs_dir, prefix="04_mcp_")` (called unconditionally inside `main()`, line
   264) only picks up files under `docs_dir` whose name starts with `"04_mcp_"`; the `--skip` tests'
   `tmp_path`-based `docs_dir` fixture must therefore create at least one file matching that glob
   (e.g. `04_mcp_99_test.md`) or `main()` prints "No 04_mcp_*.md files found" and exits `0` before
   any check runs. Verified by reading lines 264-267.
8. In a synthetic `tmp_path` repo root, `check_command_drift`, `check_file_path_references`, and
   `check_function_references` (all still wired into `main()`'s default run, lines 276-285) will not
   spuriously add issues that could confuse the `--skip portdrift`/`--skip tooldrift` assertions, as
   long as the fixture's `--skip` tests don't create a `scripts/agent/commands/command_defs_list.py`
   nor a real `scripts/` tree nor put any `scripts/...`/`func()`-shaped backtick reference in the
   doc content: `extract_registered_command_names` returns `None` (file missing) →
   `check_command_drift` returns `[]`; `extract_defined_function_names` returns `frozenset()`
   (`scripts/` dir missing under the synthetic repo root) → `check_function_references` returns
   `[]` early; `check_file_path_references` only flags backtick `scripts/`/`config/`/`docs/`
   path-with-extension references, which the `--skip` test's doc content must simply avoid
   introducing. `check_broken_internal_links` / `check_removed_file_references` only flag markdown
   links / bare `NN_doc_name.md` backtick mentions, also avoidable by controlling doc content.
   Verified by reading all four functions' bodies in `tools/_docs_consistency_lib.py`.

## Design

No architectural change; no production code touched. This is a full test-suite replacement that
targets the module's actual current public surface instead of a deleted catalog-based one.

- **Import surface**: `from check_mcp_docs_consistency import (DocFile, Issue, check_port_drift,
  check_tool_name_drift, main)` (per UNK-01's resolution). Drop every other import.
- **Fixture helper**: keep `_mk_file(rel: str, lines: list[str]) -> DocFile`, matching the existing,
  still-valid generic pattern. Drop `_mk_issues_file` entirely.
- **`check_port_drift` test group** (`TestCheckPortDrift`), each using a `tmp_path`-based synthetic
  `repo_root` with `config/agent.toml` written via `tmp_path / "config" / "agent.toml"`
  (`mkdir(parents=True)` then `write_text(...)`):
  - agree → no issue (doc's `web-search-mcp ... 8004` line matches config's port exactly).
  - disagree → 1 `ERROR` issue with the correct `file`/`line_no`/message substring (doc says `8099`,
    config says `8004`).
  - name present, no 4-digit number on that line → no issue.
  - 4-digit number present but outside `80xx` (e.g. `1234`) → no issue (silently skipped, not an
    assertion of "skipped via is_historical_line" — a separate case, per Assumption 4).
  - `is_historical_line()`-flagged line (e.g. containing "legacy") with an otherwise-mismatched port
    → no issue (line skipped before any name/port matching).
  - missing `config/agent.toml` under the synthetic `repo_root` → `check_port_drift` returns `[]`.
- **`check_tool_name_drift` test group** (`TestCheckToolNameDrift`), synthetic `repo_root` with
  `scripts/mcp_servers/<server>/tools.py` containing a `TOOL_LIST = [{"name": "..."}, ...]`-shaped
  snippet matching `_TOOL_LIST_NAME_RE`:
  - `"Tools: \`file_read\`, \`file_write\`"` where both live in the synthetic `TOOL_LIST` → no issue.
  - `"Tools: \`file_read\`, \`unknown_tool\`"` where `unknown_tool` is absent → 1 `WARNING` issue
    naming `unknown_tool`.
  - `"Tools: \`generic\`"` (no underscore) → no issue (skipped as too generic per Assumption 5),
    even though `generic` is absent from the live set.
  - empty live-tool-name set (synthetic `scripts/mcp_servers/` dir exists but contains no `.py`
    files, or the dir is absent entirely) → `check_tool_name_drift` returns `[]`.
- **`main()` `--skip` test group** (`TestMainSkipHandling`), two tests per Scope/UNK-02:
  1. `--skip portdrift`: build a `tmp_path` "repo" with `config/agent.toml` (one server, one port)
     and a `docs_dir` containing one `04_mcp_99_test.md` file whose only notable content is a
     port-mismatch line (no tool-enum line, no markdown links, no backtick path/func references —
     per Assumption 8). Call `main(["--docs-dir", str(docs_dir), "--skip", "portdrift"])` and assert
     return `0`; call `main([...])` without `--skip` and assert return `1`. `main()` reads
     `repo_root` from `Path(__file__).resolve().parent.parent` (line 258) — **not** from
     `--docs-dir` — so this test necessarily exercises the check against the real repo's
     `config/agent.toml`, unless `main()` is invoked with `monkeypatch` on
     `check_mcp_docs_consistency.Path(__file__)` or the test instead calls `check_port_drift`
     directly for the assertion and only exercises `main()`'s CLI plumbing (the `--skip` flag
     itself excludes the check from `all_issues`) for the "does skip suppress this check" behavior
     — see Implementation step 3 for exactly which approach to use, since `main()`'s hardcoded
     `repo_root` derivation (not parameterized) is a real constraint the requirement's own text does
     not mention.
  2. `--skip tooldrift`: same `docs_dir` pattern, doc content instead has a tool-enum line naming an
     unknown tool; assert via `capsys.readouterr().out` that the WARNING message is absent when
     skipped and present when not skipped (per UNK-02 — return-value assertion does not work here).

## Risks

- **R1 — `main()`'s hardcoded `repo_root` derivation (`Path(__file__).resolve().parent.parent`,
  not parameterized) may make a fully `tmp_path`-isolated `--skip portdrift`/`--skip tooldrift` test
  harder to write than the requirement's text implies**, since it only discusses fixturing
  `check_port_drift`/`check_tool_name_drift` directly, not `main()`'s own repo-root resolution.
  Likelihood: Medium (confirmed via source read, not hypothetical — see Design/Implementation step
  4). Mitigation: **addressed in-plan** — Implementation step 4 specifies the `monkeypatch` fallback
  and requires confirming it experimentally before committing to an approach; no separate issue
  needed since this is a normal implementation-detail decision resolvable without a human, and the
  plan gives the implementer both the constraint and the resolution path.
- **R2 — `rules/toolchain.md` lines 111-127 remain stale after this fix**, continuing to describe a
  removed check set (`startup, failopen, routing, active, toolcount`) and stale `--skip` values
  (`active`, `toolcount`) that no longer exist, misleading any future reader who follows that doc's
  examples verbatim. Likelihood: High (already confirmed stale today, not merely possible).
  Mitigation: **filed as a separate follow-up issue** (see below) per the source requirement's own
  explicit "Documentation Impact" recommendation — updating it is a doc change outside this
  document-only planning phase's and the test-only requirement's scope, so it is tracked
  independently rather than silently left unaddressed.
- **R3 — Partial/inconsistent mechanical rewrite** (e.g. leaving a stray reference to a removed
  symbol, or a test that accidentally depends on the real repo's `config/agent.toml`/`docs/` state
  instead of a `tmp_path` fixture, reintroducing exactly the kind of repo-drift fragility this
  redesign was meant to avoid). Likelihood: Low. Mitigation: Implementation step 5's `grep` check and
  step 6's regression check are already the in-plan mitigation; Assumption 8 documents the specific
  synthetic-fixture content constraints (no stray `scripts/`/`config/`/`docs/` backtick references,
  no markdown links, no bare `.md` filename mentions) needed to keep the new tests fixture-isolated.
- **R4 — Pre-existing zero test coverage for `check_file_path_references` and
  `check_function_references`** (confirmed via `grep -rln` returning no hits across `tests/`)
  is not fixed by this plan, since it is outside the requirement's stated acceptance criteria.
