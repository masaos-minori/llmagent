## Background
`skills/DESIGN.md`'s "Avoid implementation-reference duplication" section
already states: "do not copy exhaustive file lists, method catalogs,
DTO/config-key field tables, or long command/JSON examples into the document
— recommend or write a concise, evidence-grounded summary instead, and point
to the source for exhaustive detail." The source Issue confirmed
`docs/03_rag_02_03_ingestion_pipeline-chunksplitter.md` violates this with a
full `TypedDict` field enumeration, a full example JSON payload, a CLI
argument table, a per-case error-handling table, and a "Canonical
Artifact-Field Contract" section hand-maintaining a 13-row field/validator
table mirroring `scripts/rag/ingestion/pipeline_utils.py`.

The Issue's companion tool (`tools/check_docs_content_policy.py`) was
implemented and merged before this Plan was created. Re-running it during
this Plan's own Step 2/3 verification (`uv run python
tools/check_docs_content_policy.py`, full `docs/` tree, 2026-09-20) confirms
the Issue's cited line numbers for all 5 tool-confirmed files are unchanged:
`chunksplitter.md` (44/188/195/288), `crawler.md` (39/103/125),
`ingester.md` (146/172/224/250), `dto-models_config.md`
(20/34/43/54/63), `error-handling-reference.md` (18). The Issue's list of 11
"no automated finding" files was also re-confirmed: none of them appear in
the current tool output.

## Problem
This kind of content (a) goes stale the moment the underlying type,
validator, CLI, or exception definition changes, since nothing enforces
doc/code agreement, and (b) bloats the RAG-indexed document corpus with
implementation detail that duplicates what code, `--help`, or a schema
already answers authoritatively — lowering the signal-to-noise ratio of
retrieved chunks for design-intent queries.

## Reason for change
Documentation drift risk (these docs restate TypedDict/DTO/CLI/exception
definitions with no automated check against the actual code) and RAG corpus
quality (these design documents are themselves the RAG-indexed source;
padding them with implementation reference reduces retrieval quality for
design-intent questions).

## Implementation intent
For each of the 7 in-scope `docs/*.md` files, replace exhaustive
implementation-reference content with a concise pointer to its actual
canonical source, per category:
- TypedDict/DTO field lists (chunksplitter.md, dto-models_config.md,
  dto-models_data.md, execution-guide.md) → point to the type/dataclass
  definition in the actual `.py` file (verified to exist — see Implementation
  Target Files' Repository Evidence column).
- CLI argument tables (chunksplitter.md, crawler.md, ingester.md) → point to
  the script's own `--help` output, not a hand-maintained table.
- Per-exception handling tables duplicated inside chunksplitter.md,
  crawler.md, and ingester.md → point to the existing single canonical
  table already in `docs/03_rag_05_4-error-handling-reference.md` (which
  those same three docs, plus `03_rag_02_06_ingestion_pipeline-supporting-components.md`,
  already cross-reference by name as "the shared error-handling reference
  table" — see Design). Do not duplicate the table content when replacing;
  a one-line pointer is sufficient.
- Full JSON payload example (chunksplitter.md, dto-models_data.md) → point to
  the TypedDict/dataclass definition; do not restate the JSON shape.
- The "Canonical Artifact-Field Contract" section in chunksplitter.md and the
  "Used by" script/function mapping table in
  `03_rag_02_08_ingestion_pipeline-shared.md` → point to
  `scripts/rag/ingestion/pipeline_utils.py`'s validators and to each
  script's own `from rag.utils import (...)` statement respectively, instead
  of hand-maintaining a mirror table.

Each remediated document retains only: what boundary the data model forms,
whether it is an external public contract or an internal DTO, the
compatibility range that must be preserved, whether it may contain sensitive
information, whether it is persisted or ephemeral, and how missing,
duplicate, or out-of-order data is handled.

Also expand `skills/DESIGN.md`'s "Avoid implementation-reference
duplication" wording to explicitly name TypedDict field lists, HTTP
request/response examples, CLI argument tables, and per-exception handling
tables, alongside its existing "DTO/config-key field tables ... method
catalogs ... command/JSON examples" wording.

## Design
This is a documentation-only Plan (no `scripts/*.py` file is a modification
target) — the Path B architecture/dependency/operational analyses below are
scoped accordingly rather than run as literal Python-import-graph tooling.

- **Path A/B classification**: Path B (8 modification-target files exceeds
  the ≤3-file Path A threshold; no public interface or DB schema change is
  otherwise involved).
- **Architecture analysis**: no import-graph change applies (docs-only).
  Each of the 8 target files' 1:1 relationship to its documented source file
  was confirmed by reading both the doc and (for the newly-discovered
  files) the source it describes — see Implementation Target Files'
  Repository Evidence column.
- **Dependency graphing**: cross-doc reference counts (`grep -rl {filename}
  docs/`) confirm each target file's incoming-link count (see Affected
  areas) — this bounds the blast radius of removing a section other docs
  may link to by heading anchor (see UNK-01).
- **Historical analysis**: total commit counts per file (see Affected
  areas) are moderate (10-15) with no single outlier; none flagged as
  unusually high-churn relative to the rest of the `docs/03_rag_*` corpus.
- **Operational dependency inspection**: N/A — this Plan does not touch any
  running MCP server, database, or network port; `lsof`/`pip-audit` do not
  apply to a documentation-only change.
- **Error-handling table exception** (resolves UNK from source Issue): the
  Issue originally listed `docs/03_rag_05_4-error-handling-reference.md` as
  a 5th tool-confirmed target file. Reading the file (2026-09-20) shows it
  is the pre-existing single canonical table other docs already point to —
  `03_rag_02_03_ingestion_pipeline-chunksplitter.md` cites it for "the
  `ValueError` conditions," `03_rag_02_06_ingestion_pipeline-supporting-components.md`
  section 4.8.1 cites it as "the shared error-handling reference table," and
  its own `## Crawler`/`## ChunkSplitter`/`## RagIngester` sections exist
  specifically to consolidate what would otherwise be duplicated across
  those three docs. Removing its own tables would eliminate the one
  canonical destination Implementation Intent's "point to the source"
  guidance requires the other 3 docs to point to instead. This Plan
  therefore treats it as Out-of-Scope/Reference-only (see Scope, Assumptions)
  — a corrected understanding from the source Issue, not a partial
  implementation of it.
- **Manual spot-check findings** (resolves the source Issue's own
  Unresolved Questions): re-running `tools/check_docs_content_policy.py`
  confirmed the Issue's 11 "no automated finding" files still produce no
  tool warning, but reading all 11 in full surfaced 3 genuine
