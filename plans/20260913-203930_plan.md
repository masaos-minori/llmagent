# Remove dead CrawlTarget DTO and its LanguageCode enum

## Goal
Remove the `CrawlTarget` dataclass (`scripts/rag/models_data.py`) and its
`LanguageCode` enum (`scripts/rag/enums.py`) — both confirmed unused anywhere in the
repository — eliminating the `lang`-field type inconsistency the Issue raised by
removing its sole source rather than unifying types across DTOs that are otherwise
consistent.

## Priority
Low

## Scope
- **In-Scope**: Deleting `CrawlTarget` from `scripts/rag/models_data.py`; deleting
  `LanguageCode` from `scripts/rag/enums.py` and the now-unused

  and the type-inconsistency Constraint bullet from

- **Out-of-Scope**: Changing `ChunkDocument`/`CrawlDocument`/`ChunkRecord`'s `lang:

  the Issue's inconsistency was entirely between them and the now-removed

  `enums.py` (`PipelineStageName`, `HitKind`, `SearchBackend` — see Unknowns, tracked
  separately as they are unrelated to `CrawlTarget`/`lang`)

## Background
The Issue's cited claim
(`docs/03_rag_04_01_dto-models_data.md:102`: "`CrawlTarget.lang` uses the
`LanguageCode` enum, whereas other DTOs use a plain `str` for `lang`") is confirmed
accurate: `CrawlTarget.lang: LanguageCode` (`models_data.py:28`) vs.
`ChunkDocument.lang: str` / `CrawlDocument.lang: str` / `ChunkRecord.lang: str`
(`models_data.py:37,56,71`).

**Re-verified 2026-09-13** (this cycle): `CrawlTarget` itself is entirely unused
anywhere in the repository. A repository-wide search
(`rg "CrawlTarget" scripts/ tests/`) found only its own class definition
(`models_data.py:24`) — no import, instantiation, or reference anywhere else,
including no reference from the actual crawler implementation
(`scripts/rag/ingestion/crawler.py` and related crawler modules, which use their own
internal representations, not `CrawlTarget`). `LanguageCode` (`enums.py:11-15`) is
likewise used only by `CrawlTarget.lang` — removing `CrawlTarget` leaves
`LanguageCode` with zero remaining references.

Given `CrawlTarget` is dead code, the Issue's "type inconsistency" is not a live
validation-logic concern (no code branches on `CrawlTarget.lang`'s type, since no
code ever constructs a `CrawlTarget`) — it exists only in the DTO definitions and
this documentation file. Removing the dead class eliminates the inconsistency at its
source, rather than choosing between the Issue's two proposed alternatives (extend
enum enforcement to the live DTOs, or unify on `str`) — both of which would have
required non-trivial follow-on validation work for a type mismatch that currently
has zero runtime impact.

## Problem
`CrawlTarget` and its `LanguageCode` enum are dead code that also introduces a
documented (and now known to be inconsequential) type inconsistency with the
actively-used `lang: str` DTOs, increasing maintenance burden and risking future
confusion (e.g. a developer writing new crawler code against the unused
`CrawlTarget` shape, or investigating the type mismatch as if it affected live
validation).

## Reason for change
Remove the confirmed-dead `CrawlTarget`/`LanguageCode` pair, which resolves the
Issue's underlying concern (type inconsistency across DTOs) by eliminating its only
source, without touching the actively-used `str`-typed `lang` fields that are
already internally consistent with each other.

## Design
This task is classified as **Path A** (small task): affects 3 files, no public
interface changes beyond removing an already-unused public class/enum (no caller
exists, so removal has zero behavioral impact on any actual caller), no database
schema changes.

This cycle's re-verification confirmed the Issue's type-inconsistency claim accurate
but found the more fundamental fact the Issue did not identify: `CrawlTarget` itself
is entirely dead code. This makes removal — rather than either of the Issue's
proposed type-unification alternatives — the minimal, lowest-risk fix that fully
resolves the inconsistency (its sole source is deleted) without touching any
actively-used DTO.

Key design decisions:
1. Remove `CrawlTarget`/`LanguageCode` together rather than choosing one of the
   Issue's two type-unification alternatives — both alternatives would have
   required deciding how the currently-nonexistent `CrawlTarget` construction sites
   *should* validate `lang`, a speculative design question for code that has no
   callers; removal sidesteps that speculation entirely
2. Do not remove `enums.py`'s other unused enums (`PipelineStageName`, `HitKind`,
   `SearchBackend`) in this same Plan — they are unrelated to the Issue's
   `CrawlTarget.lang` concern; tracked as UNK-01 for a separate decision rather than
   silently expanding this Plan's scope
