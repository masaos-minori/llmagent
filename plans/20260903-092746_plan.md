## Background
This Issue depends on `localremoval` and `loopbackonly` landing first — deleting
configuration files before runtime behavior is migrated could break startup or
remove process-owned configuration required by ADR-002 (source Issue Background).
Neither Plan has been implemented yet (both are `plans/*.md`, not `plans/done/*.md`,
as of this Plan's creation).

## Reason for Change
Even though no artifact exists to delete today, the source Issue's migration
procedure and rollback guidance remain valuable: they give operators a repeatable,
documented sequence to follow once `localremoval`/`loopbackonly`/`mcpauth` land,
and they preempt a future Local-only overlay file being added without a
documented removal path.

## Implementation intent
Add a "Production-Only Migration Procedure" section to `docs/02_deployment.md`
describing: backup current configuration; migrate bind addresses (per
`loopbackonly`) and MCP authentication tokens (per `mcpauth`) together; verify
`ProductionConfigValidator`'s now-unconditional strict validation (per
`localremoval`) passes; perform a full process restart (not `/reload`, since
authentication/MCP-definition/bind-address changes are restart-only per
`mcpauth` REQ-005); verify authentication, discovery, routing, tool-visibility, and
socket binding after restart; verify external connectivity is unavailable; and
document that no separate Local-overlay artifact exists to delete as of this
Plan's creation, with guidance for what deletion process a future overlay file
would need (confirm each candidate's purpose and remaining references before
deleting, mirroring the source Issue's AI Implementation Instruction). Add
release-level rollback guidance (redeploy a prior release; do not represent
rollback as re-enabling a Local runtime profile).
