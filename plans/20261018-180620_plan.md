# Plan: Detect multiple primary canonical sources per area in unregistered prose (GV-010)

## Goal
Extend the GV-009 prose-scan checker to group unregistered canonical/normative prose claims by
area and flag any area for which more than one document is designated as a primary source.
This closes the documented `Partial` gap for GV-010 without changing the registration
process, then mark GV-010 `Existing`.

## Background
`governance_04_documentation-checks.md` maps GV-010 ("Multiple Primary Canonical Sources
within the same area") to human review, noting registered claims are checked by GV-019 and
the rest is manual. Status is `Partial`. This is distinct from GV-009 (duplicate specification
of a single canonical document): GV-010 concerns several *different* documents each claimed as
the primary source for one area.

## Problem
Prose can designate multiple documents as the primary/canonical source for the same area or
subsystem without registering any of them, so competing primary sources coexist undetected
outside the registry's single-normative-source enforcement.

## Reason for change
GV-010 is a Warning-level gate; undetected multiple primary sources per area create ambiguity
about which document governs an area. Automating detection closes the documented `Partial`
gap.

## Implementation intent
Reuse the GV-009 prose scanner rather than duplicating it. Extend it to group
canonical/normative prose claims by area and flag areas with more than one designated primary
source. Reuse the subject/area extraction already defined for GV-009 where possible.

## Design
Extend (do not fork) the GV-009 scanner.

1. **Reuse the scan.** Import/reuse the GV-009 claim-parsing function so the pattern set and
   subject extraction are defined once.
2. **Area grouping (UNK-01).** For each unregistered canonical claim, derive an area key:
   prefer an explicit area/subsystem token in the claim's context; otherwise fall back to the
   claim's `claim_type` or the containing document's area. Ambiguous/unextractable claims are
   left ungrouped (not flagged).
3. **Multi-primary detection (REQ-002).** Within each area group, collect the distinct
   designated documents; flag areas whose group contains two or more distinct documents as
   primary. Single-primary areas are not flagged (REQ-003).
4. **Reporting.** WARNING only; preserve the severity/exit contract.

No change to the registry schema or to `check_canonical_source_registry.py` /
`check_canonical_source_conflicts.py` behavior.

## Risks
- **Risk**: The area-grouping key is inherently fuzzy (UNK-01) and may produce false positives
  or miss real conflicts. → **Mitigation**: Conservative grouping with fail-safe (ungrouped
  claims not flagged); negative fixtures tuned against the current corpus.
- **Risk**: Coupling GV-010 to the GV-009 scanner's API. → **Mitigation**: Reuse the scanner's
  public claim-parsing hook; if the API is unstable, add a thin adapter rather than
  refactoring GV-009.
