# Plan: Migrate EventBus configuration loading to ConfigLoader

## Goal

Refactor EventBus's configuration loading to use `ConfigLoader`, preserving all of EventBus's existing fail-closed validation behavior (cross-field checks, required-token checks, etc. — see `eventbus09`) rather than replacing it with `ConfigLoader`'s defaults.

## Priority
High

## Scope
- **In-Scope**: Migrating EventBus config loading from `tomllib.load()` to `ConfigLoader`; updating CI-001 after verification
- **Out-of-Scope**: Changing EventBus's actual validation policy or supported configuration keys

## Background
`docs/00_governance_03_issue-and-uncertainty-management.md` `CI-001` ("EventBus process reads configuration directly instead of using ConfigLoader") already tracks this exact gap (Status: open, Severity: High). This issue is the implementation-tracking counterpart to that Known Issue entry.

## Problem
Confirmed by direct inspection: `scripts/eventbus/config.py` imports `tomllib` and calls `tomllib.load()` directly; it does not import or use `scripts/shared/config_loader.py`'s `ConfigLoader`. This means EventBus's configuration loading path differs from every other process in the system, and does not benefit from `ConfigLoader`'s process-level file-access restriction (`restrict_to()`) or its shared validation/exception contract.

## Reason for change
ADR-002 requires that all processes load configuration via ConfigLoader to ensure process-level config isolation. EventBus reads its own TOML configuration directly without going through ConfigLoader, violating this invariant.

## Implementation intent
Refactor EventBus's configuration loading to use `ConfigLoader`, preserving all of EventBus's current fail-closed validation behavior (cross-field checks, required-token checks, etc. — see `eventbus09`) rather than replacing it with `ConfigLoader`'s defaults.

## Requirements
- `REQ-001`: Replace `scripts/eventbus/config.py`'s direct `tomllib.load()` call with `ConfigLoader`-based loading.
- `REQ-002`: Preserve EventBus's existing validation behavior (required keys, type checks, cross-field rules) after the migration — do not silently relax any existing check.
- `REQ-003`: Confirm `ConfigLoader.restrict_to()` is initialized appropriately for the EventBus process before production config loading (coordinate with `mcpagent07` if both are implemented in the same session, since that issue also touches `restrict_to()` initialization requirements).
- `REQ-004`: Add or update tests confirming EventBus configuration loads correctly through `ConfigLoader` and that all existing validation error cases still produce the same errors.
- `REQ-005`: Update `CI-001` in `docs/00_governance_03_issue-and-uncertainty-management.md` to reflect the migration once implemented and verified — remove it from the active inventory per that document's own removal policy.

## Design

### Determine Import Strategy (REQ-001)
Current state:
- `.importlinter` `eventbus-is-isolated` contract forbids importing `shared`/`mcp_servers` from `eventbus`
- This was confirmed during eventbus02's implementation

**Decision**: Attempt the migration first. If the `.importlinter` contract blocks the import, document a justified ADR-002 exception rather than abandoning the migration. Rationale:
1. The isolation contract was designed to prevent cross-process secret leakage, not to prevent shared infrastructure code reuse
2. ConfigLoader is infrastructure code, not a secret-bearing module
3. If the contract is too strict, it should be updated rather than the migration abandoned

Two possible approaches:
1. **Relax the contract**: Update `.importlinter.conf` to allow EventBus → shared imports for ConfigLoader specifically
2. **Document exception**: Keep the contract as-is and add an ADR-002 exception noting why EventBus cannot use ConfigLoader

### Migrate Config Loading (REQ-001, REQ-002)
Current state in `load_config()`:
```python
def load_config(path: Path | None = None) -> EventBusConfig:
    p = path or _DEFAULT_CONFIG_PATH
    with p.open("rb") as f:
        data = tomllib.load(f)
    
    # ... validation logic ...
    
    return EventBusConfig(...)
```

**Decision**: Refactor to use ConfigLoader while preserving all validation:

```python
from shared.config_loader import ConfigLoader  # May require .importlinter relaxation

def load_config(config_name: str = "eventbus") -> EventBusConfig:
    """Load and validate the EventBus TOML configuration file."""
    loader = ConfigLoader()
    data = loader.load(config_name)
    
    # All existing validation logic preserved exactly as-is
    # ... validation logic ...
    
    return EventBusConfig(...)
```

In `app.py`'s lifespan handler:
```python
# Before:
config = load_config(get_config_path())

# After:
ConfigLoader.restrict_to("eventbus.toml")
config = load_config("eventbus")
```

### Preserve Validation Behavior (REQ-002)
All existing validation must be preserved exactly:
- Per-key type validation (lines 184-192)
- Auth token non-empty check (lines 194-196)
- Per-role token combination rule (lines 198-206)
- Cross-field validation in `__post_init__` (lines 73-80)
- Single-value validation in `__post_init__` (lines 62-94)

**Decision**: Do not replace any validation logic. The migration changes only the loading mechanism, not the validation policy.

### Confirm restrict_to() Initialization (REQ-003)
Current state: `ConfigLoader.restrict_to()` is called by MCP servers at startup.

**Decision**: Add `ConfigLoader.restrict_to("eventbus.toml")` call in EventBus's lifespan handler before `load_config()` is invoked. This ensures EventBus only reads `eventbus.toml` and cannot access other process configs.

If `mcpagent07` has landed, coordinate with its `restrict_to()` initialization requirements.
