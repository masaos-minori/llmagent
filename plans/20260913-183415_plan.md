## Goal
- Eliminate double-close risk in `WorkflowEngineAdapter.execute_turn` when `_init_workflow_task` creates a new StateStore and the outer finally block also closes it, ensuring single-owner semantics for store lifecycle management.

## Priority
Medium

## Scope
- **In-Scope**: Fix StateStore ownership tracking in `workflow_engine_adapter.py`
- **Out-of-Scope**: Refactoring the entire execute_turn flow, adding new error handling paths

## Background
`_init_workflow_task` manages its own state store lifecycle: if `store=None`, it creates a new StateStore and sets `close_store=True`; if `store` is provided, it sets `close_store=False` to let the caller manage the store. However, `execute_turn` unconditionally calls `self._state_store.close()` in the finally block regardless of ownership.

## Problem
When `existing_task_id=None` (new workflow task), `_init_workflow_task` creates a new StateStore with `close_store=True` and closes it in its own finally block (line 305-306). Then `execute_turn`'s finally block closes `self._state_store` again (line 214), resulting in a double-close.

## Reason for change
Double-close can cause undefined behavior depending on the underlying SQLite connection. While Python's sqlite3 module silently ignores subsequent close() calls, other database backends or future changes could raise exceptions or corrupt state.

## Implementation intent
Pass a flag from `_init_workflow_task` indicating whether it owns the store, and skip the outer close in `execute_turn` when the inner method already closed it. Alternatively, restructure so `_init_workflow_task` returns the store reference along with a boolean indicating ownership.

## Requirements
- `REQ-001`: `_init_workflow_task` must return ownership information about the StateStore it created
- `REQ-002`: `execute_turn` must conditionally close the StateStore based on ownership returned by `_init_workflow_task`
- `REQ-003`: Backward-compatible public API methods (`init_workflow_task`, `activate_workflow`) must preserve existing signatures

## Design
The fix follows the principle of least surprise: the method that creates the store should own its lifecycle. Two approaches are viable:

1. **Return tuple approach**: `_init_workflow_task` returns `(workflow_id, task, store_closed)` where `store_closed` indicates whether the inner method closed the store. `execute_turn` uses this flag to conditionally close.

2. **Ownership attribute approach**: `_init_workflow_task` stores ownership info in a private attribute (e.g., `self._owns_state_store`). `execute_turn` checks this attribute before closing.

Approach 1 is preferred because it avoids mutating instance state and makes ownership explicit in the return value. The backward-compatible public API methods (`init_workflow_task`) would need to either:
- Return the additional `store_closed` flag (breaking change)
- Store ownership in a separate private attribute (non-breaking)

For backward compatibility, Approach 2 is recommended: add `self._owns_state_store = close_store` after setting `close_store`, and check this attribute in `execute_turn`'s finally block instead of returning an additional tuple.
