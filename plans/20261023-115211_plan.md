## Goal
- Make git-mcp, cicd-mcp, rag-pipeline-mcp and web-search-mcp refuse to start when their `auth_token` is empty, as the other six MCP servers already do, through one shared check, and migrate the test suite that currently depends on the empty-token accept-all behavior.

## Priority
Medium

## Scope
- **In-Scope**: A shared `require_auth_token()` helper in `scripts/mcp_servers/server.py`; calling it from the four servers at import time; updating the four server config comments and the transport documentation; moving the test suite to non-empty test tokens and Authorization headers; a test that all ten servers refuse an empty token.
- **Out-of-Scope**: Changing the posture severity of an empty token (kept as WARNING, see UNK-01); replacing the six existing inline checks with the helper (UNK-02); token generation, rotation or Agent-side distribution; EventBus authentication; the posture gate (`mcpstart002`), config-isolation ordering (`mcpstart004`) and audit logging (`mcpstart005`) issues.

## Background
`attach_auth_middleware()` accepts every request when its token is empty; its docstring calls this a testability fallback and relies on Agent startup validation. shell, github, mdq and the three file servers raise `RuntimeError` at import when the token is empty; git, cicd, rag_pipeline and web_search do not. The shared startup flow reports an empty token as WARNING (Plan UNK-06), so the posture gate does not stop them either. `scripts/agent/startup_validation.py` (lines 82-88) rejects an empty token for every server the Agent starts, and `docs/22_mcp/mcp_02_01_endpoints-and-transport.md` calls the accept-all path unsupported in production.

## Problem
With the four tokens set to an empty string, importing each of git, cicd, rag_pipeline and web_search succeeded, an unauthenticated `GET /v1/tools` returned 200, and the posture was `validated = True` with only a `common.auth_token` WARNING; the other six servers failed at import. An unset variable is already rejected by the config loader, so the exposure requires an empty value and a start outside the Agent (`mcp_launcher.py` or a binary run by hand). git-mcp can write when `read_only = false` and cicd-mcp can trigger workflows. Authentication policy is therefore inconsistent, and the test suite pins the empty-token behavior: `tests/conftest.py` sets `MCP_GIT_AUTH_TOKEN`, `MCP_CICD_AUTH_TOKEN` and `MCP_WEB_SEARCH_AUTH_TOKEN` to an empty string, and running the four server test directories with non-empty tokens produced 94 failures across 11 files because requests carry no Authorization header.

## Reason for Change
The safe behavior currently depends on which launcher is used, and loopback binding does not protect against other local processes. One fail-closed rule for all ten servers removes the inconsistency and the dependence on Agent-side validation.

## Implementation Intent
Add one helper that raises the same error the six compliant servers raise, call it from the four non-compliant modules right where they attach the middleware, and migrate the tests to a shared non-empty test token and a shared header constant. Leave the shared posture contract unchanged: the import-time refusal fires before the posture is ever consulted.

## Requirements
- `REQ-001`: `scripts/mcp_servers/server.py` provides `require_auth_token(label, env_var, token)` that raises `RuntimeError` with the message format already used by the six compliant servers when the token is empty.
- `REQ-002`: git, cicd, rag_pipeline and web_search call it before attaching the auth middleware, so an empty token prevents import and therefore startup.
- `REQ-003`: The four server config files document that an empty or missing token prevents startup, matching the wording of the shell and file server configs.
- `REQ-004`: The transport documentation states that every server refuses an empty token, and the "optional Bearer-token" wording in the git and cicd module docstrings is corrected.
- `REQ-005`: `tests/conftest.py` sets non-empty test tokens for git, cicd and web_search, and the 11 affected test files send the shared Authorization header.
- `REQ-006`: A test proves all ten server modules refuse an empty token at import, and a test covers the helper.

## Design
Path B (more than three files; runtime start behavior change). Architecture analysis: `lint-imports` reports all 6 contracts kept; the helper lives in `mcp_servers/server.py`, which each server module already imports, so no new dependency edge appears. Dependency graphing: the four server modules and the ten-server import test are the only consumers; the test migration touches the 11 files that failed in a verification run with non-empty tokens (git 44, cicd 19, web_search 31 failures; 0 for rag_pipeline). The helper reproduces the existing message ("`<label>: auth_token is empty; set <ENV_VAR> to a non-empty value (the server does not start without Bearer authentication)`") so the six compliant servers and the four new ones are indistinguishable to an operator. The tests move to the shared token already used for the other servers (`test-token`) and to `MCP_TEST_AUTH_HEADERS` from `tests/mcp_servers/_auth_headers.py`. Historical analysis (30 days): `server.py` 5 commits, `web_search_server.py` 6, the transport document 16, `tests/conftest.py` 5. Operational dependency: production runs binaries, so a deploy rebuilds them (Phase 5); `mcpstart002` also edits `server.py`, so apply the two changes in sequence.
