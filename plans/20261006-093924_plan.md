## Background
The `CommandValidator` class validates a command name before an HTTP subprocess MCP
server is started. Its `validate()` method resolves the command via PATH, resolves
symlinks, verifies the resolved path is a regular file, and finally checks the
resolved basename against an allowlist (`_DEFAULT_ALLOWED_COMMANDS`). If the basename
is absent, it raises `HttpStartupError` with a `StartupFailure` whose reason contains
"is not in the allowed commands list."

`HttpServerLifecycleManager` holds a second, duplicate allowlist (`_ALLOWED_COMMANDS`)
and passes it to `CommandValidator(allowed_commands=...)` at construction time. Both
allowlists currently contain the same seven entries and omit `uv`.

## Problem
All MCP subprocesses fail to start. AgentREPL startup emits one identical warning per
MCP server:

```
First attempt failed for MCP subprocess 'X': Command 'uv' (resolved to '/usr/bin/uv') is not in the allowed commands list.
```

Every MCP server that launches its subprocess with `uv run` is affected, so no MCP
tool is usable.

## Reason for change
Without `uv` in the allowlists, no MCP subprocess can start. This is a correctness
blocker — the agent cannot use any MCP tool until the allowlist includes `uv`.

## Implementation intent
Add the single string `"uv"` to each of the two existing frozensets, keeping the
`frozenset[str]` annotation and the surrounding literal set unchanged apart from the
one added entry. No logic, constructor, or caller changes are required.

## Requirements
- `REQ-001`: `_DEFAULT_ALLOWED_COMMANDS` in `scripts/agent/http_lifecycle_command_validator.py`
  MUST contain `"uv"` so the default validator accepts `uv` subprocesses.
- `REQ-002`: `_ALLOWED_COMMANDS` in `scripts/agent/http_lifecycle.py` MUST contain
  `"uv"` so the manager injects an allowlist that accepts `uv` subprocesses.
- `REQ-003`: No other command besides `uv` is added to either allowlist.
- `REQ-004`: The `frozenset[str]` type annotations on both symbols are preserved.

## Design
Both allowlists are module/class-level `frozenset[str]` literals that feed the same
single allowlist check in `CommandValidator.validate()` (Check 4). The manager's
`_ALLOWED_COMMANDS` exists only to supply a concrete value to the injected
`CommandValidator`; the validator's `_DEFAULT_ALLOWED_COMMANDS` is the fallback when no
explicit allowlist is passed. Because both must stay consistent (the manager always
passes its copy over the validator's default), the `uv` entry MUST be added to both.

The change is data-only: a one-element addition to each frozenset literal. No control
flow, no new symbol, no interface change. `CommandValidator.validate()` and its four
check order are untouched, so the security model (resolve → realpath → regular-file →
basename allowlist) is unchanged.

## Risks
- **Risk**: Adding `uv` widens the allowlist, marginally increasing the set of
  commands an MCP subprocess may invoke. → **Mitigation**: Only `uv` is added; the
  four-check pipeline (PATH resolve, realpath, regular-file, basename allowlist) still
  gates every command, and no other command is admitted (REQ-003).
- **Risk**: The two allowlists drift apart in a future edit, re-introducing an
  inconsistency. → **Mitigation**: Both are edited in the same change; the shared
  seven-entry baseline makes divergence easy to spot in review.
