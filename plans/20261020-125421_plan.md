## Goal
Make the shipped Event Bus startable without writing a secret into a deployed TOML file by wiring `auth_token` to an `${ENV:...}` reference (with env-ref resolution added to `scripts/eventbus/config.py`, which the issue incorrectly assumes already exists), loading `.env` and fail-fast pre-checking `EVENTBUS_AUTH_TOKEN` in `deploy/setup_services.sh`, and starting the Event Bus under the script's production `uv run` invocation.

## Priority
High

## Scope
- **In-Scope**:
  - `config/eventbus.toml`: replace literal `auth_token = ""` with `auth_token = "${ENV:EVENTBUS_AUTH_TOKEN}"` and document the variable name.
  - `scripts/eventbus/config.py`: resolve `${ENV:...}` for `auth_token` via `shared.config_utils.get_str` before the non-empty check (critical correction — see Verified Understanding).
  - `deploy/setup_services.sh`: load `.env` (reusing `start_agent.sh` semantics) and fail fast on a missing `EVENTBUS_AUTH_TOKEN` before the LLM health gate; start the Event Bus with `uv run "${UV_PROD_FLAGS[@]}"`.
  - `tests/eventbus/test_eventbus_config.py`: regression test that an `${ENV:...}` `auth_token` resolves when set and fails closed when unset.
  - `docs/24_eventbus/eventbus_07_configuration-and-operations.md` (Token Distribution) and `docs/90_deployment/deployment_01_deployment.md` (pre-flight checklist).
- **Out-of-Scope**:
  - Reordering or reclassifying the LLM health gate (Issue `ebops002`).
  - Moving per-role tokens to `${ENV:...}` (operator-set remains the default; see Assumptions).
  - Wiring a publisher/consumer into the agent or the `scripts/agent/eventbus_*.py` clients.
  - Changing Event Bus roles, token semantics, `consumer_authorization` mappings, or the envelope schema.
  - Running the Event Bus as a systemd unit or any supervisor outside `deploy/`.
  - Starting or configuring `embed-llm` / `agent-llm`.

## Background
- Found on 2026-10-19: `/opt/llm/logs/eventbus.log` does not exist, so the deployment path has never started the Event Bus successfully.
- `config/eventbus.toml` ships `auth_token = ""` (line 13) and per-role tokens as `""` (lines 24-28); it contains no `${ENV:...}` reference, unlike every MCP server config, which uses `auth_token = "${ENV:MCP_*_AUTH_TOKEN}"`.
- `scripts/eventbus/config.py::load_config` rejects the empty value: lines 308-309 raise `ValueError("eventbus config 'auth_token' must not be empty.")`, and `EventBusConfig.__post_init__` (lines 126-127) raises `ValueError("auth_token is required but not configured")`. This is intended (fail-closed).
- `deploy/setup_services.sh` lines 133-135 start the Event Bus with bare `python -m eventbus.app`; every other Python step in the same script uses `uv run "${UV_PROD_FLAGS[@]}"` (lines 31, 59, 88). Bare `python` resolves to `/usr/bin/python`, which lacks FastAPI/uvicorn (`ModuleNotFoundError`), so the process dies before binding `127.0.0.1:8015`.
- `deploy/setup_services.sh` contains no `.env` handling; `deploy/start_agent.sh` parses `/opt/llm/.env` (lines 82-97) and pre-checks required variables collected from `agent.toml` plus `*_mcp_server.toml` (lines 102-135). `eventbus.toml` is not in that list.

## Problem
- `load_config(get_config_path())` with `get_config_path() == /opt/llm/config/eventbus.toml` raises `ValueError: eventbus config 'auth_token' must not be empty.` The service cannot load its own shipped configuration.
- Writing a token into the deployed TOML is the only practical path left, but `deploy.sh` rsyncs/re-syncs `config/eventbus.toml` from the repository on every deploy (deploy.sh line 165), so such an edit is silently lost.
- No production module publishes to or subscribes from the Event Bus (`scripts/agent/eventbus_client.py`, `eventbus_subscriber.py`, `eventbus_topic_admin_client.py` are imported only by their own tests; nothing under `scripts/` references port 8015). The service blocks the service, not a currently used feature.

## Reason for Change
- Deployment failure: the documented service-startup script cannot start a service it claims to start.
- Configuration consistency: every other control-plane credential is injected through `${ENV:...}`; this one is a literal empty string in a deployed file.
- Security posture: the current workaround puts a secret in a file that `deploy.sh` re-syncs from the repository, so it is silently lost.
- Usability: the `scripts/agent/eventbus_*.py` clients exist and are tested, but no startable service exists to point them at.

## Implementation Intent
- Follow the existing convention: `auth_token = "${ENV:EVENTBUS_AUTH_TOKEN}"` in `config/eventbus.toml`.
- **Critical correction**: the issue claims `${ENV:...}` expansion "is available without new code" because `config.py::_load_config_from_path` builds config through `shared.config_loader.ConfigLoader`. This is **false**. `ConfigLoader.load()` returns raw parsed TOML (`scripts/shared/config_loader.py` line 145, `tomllib.loads(...)`) with no `${ENV:...}` expansion. Expansion happens only in `shared.config_utils.get_str` / `resolve_env_ref`, which MCP servers call *after* `ConfigLoader().load()`. Therefore setting the reference stores the literal placeholder `"${ENV:EVENTBUS_AUTH_TOKEN}"`, which passes the non-empty check (line 308) and is passed verbatim to `EventBusConfig.auth_token` (line 322) — auth then compares against the placeholder and breaks. The fix MUST add env-ref resolution in `config.py` before line 308. This is resolution, not new validation, so it is consistent with the issue's "do not add validation logic" constraint.
- Give `setup_services.sh` the same `.env` load and required-variable pre-check that `start_agent.sh` implements, scoped to `EVENTBUS_AUTH_TOKEN`, placed before the LLM gate so a missing token fails fast instead of burning ~150s.
- Start the Event Bus with the script's own production `uv run` invocation so it uses the production venv.
- Keep fail-closed: an unset `EVENTBUS_AUTH_TOKEN` still stops the Event Bus with an actionable error.

## Design
Path B (affects > 3 files; touches config, source, deploy script, tests, and docs). The four Path B analyses below ground the design.

**Architecture analysis** (`scripts/eventbus/config.py` imports): only stdlib (`os`, `dataclasses`, `pathlib`, `typing`) and `from shared.config_loader import ConfigLoader`. Adding `from shared.config_utils import get_str` stays within the allowed layer: `.importlinter`'s `eventbus-is-isolated` contract forbids `eventbus` → `agent`/`mcp_servers`/`rag`/`db` but permits `eventbus` → `shared`. Callers `scripts/eventbus/app.py` and `scripts/eventbus/broker.py` import `eventbus.config`; they are unaffected by the internal resolution change.

**Dependency analysis** (call chain): `setup_services.sh` → `uv run python -m eventbus.app` → `eventbus.app` calls `load_config(get_config_path())` → `config.py::load_config` → `_load_config_from_path` → `shared.config_loader.ConfigLoader.load()` (raw TOML) → [NEW] `shared.config_utils.get_str(data, "auth_token")` (expansion) → `EventBusConfig(auth_token=...)` → `__post_init__` fail-closed checks. The single new coupling is `config.py` → `shared.config_utils`, which already exists transitively for every MCP server.

**Historical analysis**: low churn on all targets (last 30 days: `config.py`=3, `eventbus.toml`=1, `setup_services.sh`=4, test=2); single author (Masao SUGIMOTO) across every target → low bus factor. Stable area; the change is well-contained.

**Operational inspection**: no process holds a lock on `eventbus.sqlite` and nothing listens on port 8015 (the service has never been started by the deployment path), so no runtime lock contention to worry about. No dependency upgrade is planned, so `pip-audit` is not required.

**Critical correction (adversarial verification)**: The issue states `${ENV:...}` expansion "is available without new code" and that `config.py` needs "no change" / "do not add validation logic". Repository evidence contradicts this: `ConfigLoader.load()` returns raw TOML (`config_loader.py` line 145); expansion lives only in `shared.config_utils.get_str`, called by MCP servers after load. Setting the reference without resolution stores the literal placeholder, which passes the non-empty check (line 308) and is passed verbatim to `EventBusConfig.auth_token` (line 322), breaking auth. Therefore `REQ-002` adds env-ref *resolution* (not new validation) to `config.py` before line 308 — consistent with the issue's "do not add validation logic" constraint while actually fixing the bug. This is the one place the Plan diverges from the issue's literal "no change needed" claim.
