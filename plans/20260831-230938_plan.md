# Plan: MCP Config Failure Model Alignment

## Goal
Align `McpServerConfig`'s failure-handling fields (`required_in_production`, `required_in_local`, `failure_policy`) with ADR-004's revised Production-only failure model.

## Priority
High

## Scope
- **In-Scope**: Remove `required_in_local` field, simplify `FailurePolicy` enum to FAIL_FAST only, update callers in `mcp_tool_discovery.py` and `startup.py` to use unified `required` field, remove environment-based branching logic.
- **Out-of-Scope**: Changes to `config/agent.toml` (no overrides currently exist), changes to ADR-004 document itself, changes to other MCP server configuration fields beyond failure-handling.

## Background
ADR-004 was revised to establish a Production-only failure model where component criticality is an environment-independent property. The revision introduced Decision #1 (criticality is environment-independent), Decision #3 (only Fail-Fast for safety/integrity failures), and Decision #14 (required vs non-required classification). However, the source code still reflects the pre-revision dual-environment model.

## Problem
Three misalignments between `McpServerConfig` and ADR-004:

1. `required_in_local` field contradicts ADR-004 Decision #1 (component criticality is environment-independent). The issue's claim that "ADR-004 Decision #7 states there is no required/non-required distinction" is incorrect — ADR-004 DOES distinguish between required and non-required components (Decisions #7, #14, #17, #18). However, the distinction must be environment-independent.

2. `FailurePolicy` enum with three values (FAIL_FAST, DISABLE_TOOL, DEGRADED) contradicts ADR-004 Decision #3 which requires Fail-Fast only for safety/integrity failures. Only FAIL_FAST should remain as a valid option.

3. Environment-based branching in `mcp_tool_discovery.py:134` (`cfg.required_in_production if is_prod else cfg.required_in_local`) violates ADR-004 Principle #3 — the environment name does not change failure handling.

## Reason for change
ADR-004 has been revised and the source code must align with its decisions. The Known Issue documented in ADR-004 (`ADR-004-D1-profile-config-model-still-present`) confirms this gap exists.

## Implementation intent
Replace the dual-environment failure model with a single unified model: one `required` field replaces both `required_in_production` and `required_in_local`; `FailurePolicy` simplifies to FAIL_FAST only; callers drop environment-based branching.

## Requirements
- `REQ-001`: Replace `required_in_production` and `required_in_local` with a single `required` field on `McpServerConfig`.
- `REQ-002`: Simplify `FailurePolicy` enum to retain only `FAIL_FAST` value.
- `REQ-003`: Update `mcp_tool_discovery.py` to use unified `required` field without environment-based branching.
- `REQ-004`: Update `startup.py` to reference the simplified `FailurePolicy` enum.
- `REQ-005`: Update tests to reflect the new unified model.
- `REQ-006`: Update ADR-004 Known Issue entry to mark resolution.

## Design
The design follows ADR-004's core principle: component criticality is an environment-independent property. The current dual-field approach (`required_in_production`/`required_in_local`) was introduced before ADR-004's revision and represents a pre-revision artifact.

Key design decisions:
1. **Single `required` field**: Replaces both `required_in_production` and `required_in_local`. Default value is `True` to maintain backward compatibility. This directly implements ADR-004 Decision #1.
2. **FAIL_FAST only**: `FailurePolicy` enum simplifies to contain only `FAIL_FAST`. The other two values (`DISABLE_TOOL`, `DEGRADED`) were added during the pre-revision period and contradict ADR-004 Decision #3. Since no config entries currently use these values, removing them has zero runtime impact.
3. **No environment branching**: `mcp_tool_discovery.py` drops the `is_prod` conditional entirely. The unified `required` field applies uniformly across all environments.
