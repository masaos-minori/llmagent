# Plan

## Goal
Remove the unused `list[subprocess.Popen]` element that `StartupOrchestrator.run()` returns for the spawned HTTP MCP subprocesses, stop `AgentREPL.run()` from unpacking it, and make explicit that subprocess termination is owned exclusively by `lifecycle.shutdown_all()` — eliminating the dead return-value path and its misleading "caller for termination" comment.

Medium

## Background
`StartupOrchestrator.run()` (`scripts/agent/startup.py`) spawns HTTP-subprocess MCP servers via `McpServerStarter.start_servers()` and returns a `list[subprocess.Popen]` as the third element of its result tuple. The comment at `startup.py:88` says "Pass subprocess list to caller for termination". `AgentREPL.run()` (`scripts/agent/repl.py`) unpacks that third element into a local named `_spawned_subprocesses` and never references it again; session cleanup runs in the outer `finally` block via `self._shutdown.close_resources()`, which routes through `lifecycle.shutdown_all()`. Termination therefore happens exclusively through the lifecycle-manager path, never through the returned list.

## Problem
The returned subprocess list encodes a false termination contract: a comment claims the caller terminates the processes, but the caller never touches the list. Ownership of subprocess termination is undocumented and split across two mental models — the dead return-value path and the real lifecycle-manager path. A plausible future refactor could remove subprocess handling from `shutdown_all()` believing the caller already handles it, orphaning the subprocesses with no error.

## Reason for Change
The dead return value and its misleading comment are a latent maintainability hazard. They encode a termination responsibility that does not exist, so removing the dead path and stating the real owner removes the ambiguity at its source without changing any runtime behavior.

## Implementation Intent
Return only `(CommandRegistry, Orchestrator)` from `StartupOrchestrator.run()`, drop the misleading comment, and change `AgentREPL.run()` to unpack the 2-tuple. Keep the internal `_spawned_subprocesses` fields intact (they back rollback bookkeeping and existing field-based tests). Update the four affected files. Do not move termination to the caller and do not alter shutdown timing.

## Requirements
- `REQ-001`: `StartupOrchestrator.run()` returns a 2-tuple `(CommandRegistry, Orchestrator)` and no longer returns the spawned-subprocess list.
- `REQ-002`: `AgentREPL.run()` unpacks only the 2-tuple and contains no reference to any previously returned subprocess list.
- `REQ-003`: The "Pass subprocess list to caller for termination" comment is replaced with text stating that `lifecycle.shutdown_all()` owns subprocess termination (or removed), and no comment asserts a caller-termination contract.

- `REQ-005`: Subprocess cleanup on both normal shutdown and startup-rollback still routes exclusively through `lifecycle.shutdown_all()`.
- `REQ-006`: Existing startup/shutdown unit tests are updated to the 2-tuple contract and pass.

## Design
The change is a pure return-value plumbing reduction with no behavioral delta. `StartupOrchestrator.run()` currently returns `(self._cmds, self._orchestrator, self._spawned_subprocesses)`. The third element is assigned from `self._start_servers()` (which delegates to `McpServerStarter.start_servers()`) and is consumed only by `AgentREPL.run()`'s unpacking, which never reads it. The real termination path is the outer `finally` in `repl.py` → `ResourceShutdownCoordinator.close_resources()` → `lifecycle.shutdown_all()`. We collapse the tuple to `(self._cmds, self._orchestrator)`, keep assigning `self._spawned_subprocesses` for rollback bookkeeping and its tests, and replace the misleading comment with a lifecycle-ownership statement. `McpServerStarter.start_servers()` keeps returning the list so the preserved field stays populated; nothing else reads that return.
