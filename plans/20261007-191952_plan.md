## Goal
- Guarantee that every git-mcp write-tool call leaves exactly one audit record (success, rejection, or failure), return policy rejections as normal `is_error=True` responses instead of HTTP 500, and use only the configuration loaded at startup.

## Priority
High

## Scope
- **In-Scope**:
  - Add `requested_target` and `canonical_target` to the shared `_audit_log()`, `_build_audit_record()`, and `AuditRecord` so the git-mcp audit calls no longer raise `TypeError`.
  - Unify git-mcp `outcome` values to the shared `ok` / `error` / `rejected` vocabulary.
  - Wrap the `dispatch_tool()` call in `call_tool()` with try/except/finally so an exception still records exactly one audit outcome.
  - Count audit-write failures and expose the count in `/health` details.
  - Classify policy rejections (remote not allowed, nothing staged) as a distinct rejection type surfaced as `is_error=True`; keep genuine execution failures as HTTP 500.
  - Report postcondition failures with explicit "state already changed" wording and the resulting state.
  - Pass the startup `_cfg` to `format_pull()` / `format_push()`; stop calling `GitConfig.load()` there.
  - Remove the stdout-based push-rejection marker check and the unreachable `[DENIED]` returns.
  - Add tests that exercise the real `_audit_log()` (no mocking) across every outcome.
  - Update ADR-012, MCP git/audit docs, the health-endpoint docs, and MCP-001 defect tracking.
- **Out-of-Scope**:
  - Ref validation and protected-branch logic (tracked in the separate, already-frozen ref-validation issue `plans/done/20261007-162035_plan.md`).
  - Making `audit_log_path` functional or operating log rotation (reserved/unimplemented; listed as an unresolved question in the issue).
  - Event-loop blocking (separate issue).
  - Changing WHICH operations are rejected — only how rejections are reported and recorded.

## Background
- Source: local investigation notes (memo1.md, ISSUE-03), consolidating MCP-001 (raised from Medium to High) and two earlier findings.
- ADR-012 requires an audit trail for write operations; ADR-002 requires configuration to be loaded once at startup.

## Problem
- `git_server.py` passes `requested_target=` and `canonical_target=` to `_audit_log()`, but the `audit.py` function does not accept them; the resulting `TypeError` is swallowed by `_audit_log_safe()`, so no record is written (Explicit in code — `scripts/mcp_servers/git/git_server.py` passes both arguments; `scripts/mcp_servers/audit.py` does not define them). Only the path-containment rejection route still records.
- `outcome` is passed as `"success"`, while `audit.py` defines `ok` / `error` / `rejected`.
- `dispatch_tool()` treats only `ValueError` as a result-level error; remote rejection, "nothing to commit", and postcondition failure raise `GitServiceError` and become HTTP 500, bypassing auditing (confirmed in `scripts/mcp_servers/dispatch.py` lines 114-121; `git_server.py` audits only after `dispatch_tool()` returns).
- A failed checkout postcondition is reported as a plain failure although the branch switch already happened (`format_output.py` line 158-161 raises after the switch at line 146).
- `format_pull()` / `format_push()` call `GitConfig.load()` on every call (`format_output.py` lines 182, 206), which can diverge from the startup `_cfg`.
- The push postcondition inspects stdout for `[rejected]`, but git reports push results on stderr; real failures surface via exit-code exceptions, so the check is ineffective. Some `[DENIED]...` string returns in `_checkout_op`, `_pull_op`, `_push_op` are unreachable (the WriteProtectionPipeline rejects dirty/detached state before the op runs).

## Reason for change
- The highest-risk write operations (push, pull, checkout) currently leave almost no audit trail, so who did what in which state cannot be reconstructed.
- Tests mocked `_audit_log`, hiding the signature mismatch; auditing is the one feature that must not fail silently.
- A policy rejection surfacing as 500 is seen by the Agent as a transport error, indistinguishable from a tool rejection, and increments health-check failures, which can mark the server unavailable.
- Reporting a plain failure after the state already changed invites a retry that repeats the operation.
- Re-reading configuration per call lets a config-file edit change the effective allow-list at runtime.
- Ineffective checks and dead branches create a false sense of protection.

## Implementation intent
- Every write-tool call produces one audit record in all outcomes.
- Separate "rejected by policy" from "failed during execution"; rejections are ordinary `is_error=True` responses, and 500 is reserved for unexpected internal faults.
- Use only the startup configuration.

## Design
Architecture decisions grounded in Step 5 analysis:
- **Additive audit schema** (`REQ-001`): new params default empty; `AuditRecord` field is `NotRequired[str]`. Preserves `eventbus/audit.py`, `eventbus/auth.py`, and every other MCP server that calls `_audit_log()`. Meets constraint C2 (existing consumers keep working).
- **Rejection classification** (`REQ-005`): `GitPolicyError(GitServiceError)` subclass in `errors.py`, raised by `_authorize_remote()` (remote not allowed) and `format_commit()` (nothing staged). `call_tool()` catches `GitPolicyError` → `CallToolResponse(is_error=True)` + `outcome="rejected"`; catches `GitServiceError` → `outcome="error"` then re-raises so FastAPI's `_on_git_service_error` returns 500. Genuine policy rejections that already surface as `ValueError` (read-only, not-in-allowlist, protected branch, dirty worktree, detached HEAD) are unchanged. This keeps shared `dispatch.py` generic and localizes the git-mcp rejection/execution split. Meets constraint: do not change rejection decisions, only reporting.
- **Exactly-one-record invariant** (`REQ-003`): try/except/finally around `dispatch_tool()` covers success, `ValueError`-result, `GitPolicyError`, and `GitServiceError` paths. Meets constraint C3 (fail closed).
- **Config injection** (`REQ-007`): `GitService` already stores `self._config` (`build_service()` passes `cfg`); `_pull_op`/`_push_op` pass `self._config` to the format functions; `format_pull()`/`format_push()` drop the `cfg or GitConfig.load()` fallback and require `cfg`. Enforces ADR-002 (config loaded once).
- **Postcondition message** (`REQ-006`): enrich the `GitServiceError` text with resulting state; remains an execution failure (HTTP 500).
- **Push failure via exit code** (`REQ-008`): rely on GitPython raising `git.exc.GitError` on non-zero exit (already wrapped as `GitServiceError` by the pipeline); remove the ineffective stdout marker checks.
