## Goal
Make every docs-domain-checking tool that assumes a flat `docs/` layout (a
prefix-only non-recursive glob, or a hardcoded flat-layout path constant)
continue to find its target file(s) once the planned `docs/` folder
reorganization moves them into area subfolders, without changing any filename.

## Priority
High

## Scope
- **In-Scope**: `tools/_docs_consistency_lib.py`'s shared file-discovery and
  cross-domain link/reference helpers; `tools/check_docs_consistency.py`'s one
  rel_path-exact-match constant; `tools/check_dependency_graph_cycles.py`,
  `tools/check_needs_confirmation_inventory.py`,
  `tools/check_known_deviation_sync.py`'s hardcoded governance/ADR path
  constants; `tools/check_adr_structure.py`, `tools/check_adr_reference.py`,
  `tools/check_adr_invariant_matrix.py`'s hardcoded ADR path constants;
  `tools/generate_reference_table.py`'s 5 output-path constants; the 2 test
  files with a real-repository path dependency on the affected files.
- **Out-of-Scope**: physically moving any file under `docs/` (tracked by
  separate per-area issues); removing or shortening any filename prefix; the
  cross-reference resolution change in `tools/check_docs_structure.py`
  (already implemented separately, see Background); fixing the pre-existing,
  unrelated `docs/02_deployment-part2.md` bug in
  `tools/generate_reference_table.py`; the 7 test files confirmed hermetic
  (no real-repository path dependency) during this Plan's verification (see
  Reference Files).

## Background
A separate investigation (2026-09-23) evaluated reorganizing `docs/` into 11
area-based subfolders (`00_governance/`, `01_overview/`, `10_adr/`, `21_rag/`,
`22_mcp/`, `23_agent/`, `24_eventbus/`, `40_shared/`, `41_db/`,
`90_deployment/`, `91_security/`) while keeping every existing filename
unchanged. `docsreorg01`, a separate, already-implemented issue/Plan
(`plans/done/20260923-142045_plan.md`), made `tools/check_docs_structure.py`
folder-independent via a repository-wide basename index. This Plan
(`docsreorg02`) covers the remaining 8 docs-domain-checking tools plus their
shared library, none of which reuse `check_docs_structure.py`'s own
resolution logic.

## Problem
The source Issue (`issues/done/20260923-140602_docsreorg02_...md`) correctly
identified the general problem but its Problem/Required Changes sections
undercounted the true scope in three ways, confirmed by direct source
inspection during this Plan's drafting:

1. **`tools/check_docs_consistency.py` covers 5 domains via 4 call sites, not
   3 domains via 1 call site.** `DOMAIN_PREFIXES` (line 57) maps `agent`,
   `mcp`, `rag`, **and also `deployment`, `overview`** (the Issue's Problem
   section named only the first 3). Beyond the domain-dispatch call in
   `main()` (line 704), two more call sites independently call
   `discover_md_files()`: `check_schema_drift()` (agent domain, lines
   164-166) scans both `90_shared_04_*` and `05_agent_09_*` directly; and
   `check_conf_d_listing()` (overview domain, line 643) scans by prefix `"01"`
   to locate one specific file, `_CONF_D_DOC =
   "01_overview-files-06-misc.md"`, via an exact `rel_path` match.
2. **`tools/generate_reference_table.py` has 5 output-path constants, not 4.**
   The Issue's Problem section omitted `REFERENCE_DOC_EVENTBUS = REPO_ROOT /
   "docs" / "06_eventbus_06_reference-api.md"` (line 70), used identically to
   the other 4 (registered in the same `--type` dispatch dict, line 318).
3. **The Issue's proposed fix ("point `discover_md_files`/path constants
   directly at the new specific subfolder... over making the glob blindly
   recursive across all of `docs/`") would break cross-domain link
   validation.** `check_broken_internal_links()` and
   `check_removed_file_references()` (both in
   `tools/_docs_consistency_lib.py`) each build an "existing files" universe
   via `docs_dir.glob("*.md")` (non-recursive) — used to validate that a link
   or bare-filename mention in ANY domain's docs resolves to a real file
   ANYWHERE in `docs/`. The module's own header comment states this
   explicitly: "Both operate over the full `docs/` directory listing (not
   just the caller's prefix-filtered files) so a link from an agent doc to a
   removed RAG doc is still caught." If `docs_dir` were narrowed to one
   domain's subfolder (the Issue's proposal), this cross-domain guarantee
   breaks — an agent doc linking to a RAG doc would be incorrectly flagged
   as broken. The corrected fix (see Design) instead makes the relevant globs
   recursive, keeping `docs_dir` at the true `docs/` root everywhere.

A downstream consequence of point 3: once `discover_md_files()`'s glob
becomes recursive, every `DocFile.rel_path` computed by a call whose
`docs_dir` stays at the flat `docs/` root changes from a bare filename (e.g.
`"00_governance_01_documentation-policy.md"`) to a directory-qualified path
(e.g. `"00_governance/00_governance_01_documentation-policy.md"`). Exactly 4
places in the codebase compare `rel_path` against a bare-filename constant
for an exact match (confirmed via `rg "\.rel_path\s*=="`):
`check_docs_consistency.py`'s `_CONF_D_DOC`,
`check_dependency_graph_cycles.py`'s `GRAPH_DOC_NAME`,
`check_needs_confirmation_inventory.py`'s `INVENTORY_DOC_NAME`, and
`check_known_deviation_sync.py`'s `_GOVERNANCE_KNOWN_ISSUES_DOC`. Each of
these 4 constants must become directory-qualified too, or the exact-match
lookup silently stops finding its target (the exact "dangerous... nothing
looks broken but the safety net is gone" failure mode the Issue itself
warned about, now shown to also apply to the Issue's own proposed fix if
implemented as originally written).

A fifth, related comparison — `check_needs_confirmation_inventory.py`'s
`doc.rel_path in _GOVERNANCE_META_DOCS` (a 4-entry frozenset of bare
filenames, one of which duplicates `INVENTORY_DOC_NAME`'s value) — has the
opposite fix: `_GOVERNANCE_META_DOCS` must stay bare (its own test,
`tests/tools/test_check_needs_confirmation_inventory.py::TestGovernanceMetaDocsCurrency::test_current_governance_filenames_are_covered`,
independently extracts bare `p.name` values and checks them against this
same set — making the set directory-qualified would break that test's own
logic). The membership check itself is changed to compare basenames instead.

## Reason for change
These 9 tools are exercised by pre-commit hooks (`adr-invariant-matrix`,
`adr-reference-scoped`, `adr-structure` in `.pre-commit-config.yaml` — 3 of
the 9) and/or CI (`check_dependency_graph_cycles.py`,
`check_needs_confirmation_inventory.py` via
`governance-docs-consistency.yml`). If they silently stop finding their
target file after the folder move, the checks they perform (dependency graph
cycle detection, needs-confirmation inventory sync, known-deviation sync, ADR
structure/reference integrity, 5-domain consistency checks) go dark without
raising an error.

## Implementation intent
Prefer making the shared, low-level file-discovery/existing-files-universe
logic in `tools/_docs_consistency_lib.py` recursive (`glob` → `rglob`) over
changing every caller's `docs_dir`/prefix — this is a 2-function, localized
fix that requires zero changes to `check_docs_consistency.py`'s own domain
dispatch logic (`main()`, `DOMAIN_PREFIXES`) and preserves the
cross-domain-link-validation guarantee the module's own header comment
documents. The remaining 8 tools each hold one or more path constants that
either (a) get compared against a now-directory-qualified `rel_path` (needs
the constant's own value updated to match), or (b) are passed directly as
`docs_dir` to `discover_md_files()` for a specific, already-known-final
subfolder like ADR (`docs/adr` → `docs/10_adr`, unaffected by the recursive-glob
change since that subfolder has no further nesting — just needs its own
value updated), or (c) are standalone output-path constants unrelated to
`discover_md_files()` (`generate_reference_table.py`'s 5 `REFERENCE_DOC_*`
constants). Update each per its own category; do not apply a single
mechanical pattern where the underlying mechanism differs.

## Design
**Core mechanism (REQ-001, REQ-002)**: change exactly 3 glob calls in
`tools/_docs_consistency_lib.py` from `.glob(...)` to `.rglob(...)`:
`discover_md_files()`'s `docs_dir.glob(f"{prefix}*.md")`,
`check_broken_internal_links()`'s `docs_dir.glob("*.md")`, and
`check_removed_file_references()`'s `docs_dir.glob("*.md")`. No caller of
`discover_md_files()` that passes the flat `docs/` root needs to change its
`docs_dir`/`prefix` arguments — the prefix string is unaffected by the folder
move (no filename change), so recursive matching against the flat root finds
every prefix-matching file regardless of which subfolder it now lives in.

**Downstream ripple (REQ-003 through REQ-006)**: `DocFile.rel_path` is
computed as `str(p.relative_to(docs_dir))` inside `discover_md_files()`. Once
the glob is recursive and `docs_dir` stays at the flat root, `rel_path`

logic change, in each of the 4 files. The one exception is

a single exact-match constant) — this one gets a logic change instead (basename

subfolder path — these simply get their directory segment updated
(`docs/adr` → `docs/10_adr`) and are unaffected by the recursive-glob change
in REQ-001 (that subfolder has no further nesting to matter).

**Standalone output constants (REQ-010)**: `generate_reference_table.py`'s 5
`REFERENCE_DOC_*` constants have no relationship to `discover_md_files()` at
all — they are write-targets for generated reference tables, resolved
directly by path. Each gets its directory segment updated independently.

**Test updates (REQ-011, REQ-012)**: `test_check_dependency_graph_cycles.py`'s
one real-repo test adds `"00_governance"` to its `doc_path` construction.
`test_check_needs_confirmation_inventory.py`'s two real-repo tests: for
`test_named_docs_exist_on_disk`, change `docs_dir / name` to

bare per Assumptions); for `test_current_governance_filenames_are_covered`,
change `docs_dir.glob("00_governance_*.md")` to

glob scoped to the one known subfolder is sufficient here — no need for

contents, not a repo-wide search).

No production runtime code, schema, or `docs/*.md` content change — this
