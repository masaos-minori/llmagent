# Plan: Reduce cyclomatic complexity of `LlmSseStreamHandler.stream_once`

## Goal
Extract the per-chunk processing loop body of `LlmSseStreamHandler.stream_once`
(`scripts/shared/llm_sse_stream.py:47-132`) into a well-named private static helper so that
`stream_once` drops from cyclomatic-complexity grade C (score 12) to grade B or better, with
zero observable behavior change (streaming, heartbeat-timeout, and finish-reason handling
byte-for-byte identical), guarded by new characterization tests written and passing against
the current implementation *before* the extraction.

- `scripts/shared/llm_sse_stream.py`: extract the `while True:` loop body inside
  `LlmSseStreamHandler.stream_once` (currently lines 85-115) into a new private static

## Design
`LlmSseStreamHandler` (`scripts/shared/llm_sse_stream.py`) is a plain internal helper class
in the `shared` layer with no inheritance and five `@staticmethod`s: `read_next_chunk`,
`stream_once`, `_handle_status`, `_build_payload`, plus the target `stream_once`. Per
`.importlinter`'s documented hierarchy (`shared` is a leaf: `shared → (external only)`, and
the `shared-is-leaf` contract forbids `shared` from importing `agent`/`mcp_servers`/`rag`/`db`),
this module already only imports from within `shared` itself
(`shared.llm_exceptions`, `shared.llm_sse_helpers`, `shared.llm_transport_errors`,
`shared.llm_types`, `shared.sse_parser`, `shared.types`) plus `httpx`/`asyncio`/`logging` —
confirmed via `rg "^from|^import" scripts/shared/llm_sse_stream.py`. Extracting a new private
static helper on the *same class in the same file* adds no new import edge and cannot violate
any `.importlinter` contract; a fresh `PYTHONPATH=scripts uv run lint-imports` run in this
planning pass shows the only broken contract is a pre-existing, unrelated
`eventbus`→`db`/`shared` violation (4 violations, all in `scripts/eventbus/*.py`) that this
plan does not touch and is not expected to change.

`stream_once` is called from exactly one production site,
`scripts/shared/llm_reconnect.py:98`, inside an `await LlmSseStreamHandler.stream_once(...)`
call whose surrounding retry/reconnect logic is explicitly out of scope per the source
requirement. Because the extraction keeps `stream_once`'s external signature and return
tuple identical, `llm_reconnect.py` requires no code change — it is an indirect consumer
whose only exposure to this change is through `stream_once`'s (unchanged) observable
contract, which is exactly what the new characterization tests exist to pin down before the
extraction happens.

Quality baseline gathered in this planning pass (all clean, giving low risk for a
behavior-preserving extraction):
- `radon cc scripts/shared/llm_sse_stream.py -s` → `stream_once` C (12, the only
  above-A method); class B (6); `read_next_chunk` A (3); `_handle_status` A (2);
  `_build_payload` A (2). This confirms the requirement's stated baseline.
- `uv run vulture scripts/shared/llm_sse_stream.py --min-confidence 80` → no findings (no
  dead code currently).
- `uv run bandit scripts/shared/llm_sse_stream.py` → 0 issues across 141 lines.
- `uv run mypy scripts/shared/llm_sse_stream.py` → "Success: no issues found in 1 source
  file" (clean baseline to preserve).

The extraction itself is a textbook "extract loop body into a helper" refactor: the new
helper receives the parser, byte iterator, url, heartbeat/retry flags, and the mutable
accumulators (`content_parts`, `tool_calls_map`, `stat_parse_errors_ref`) it currently closes
over as local variables in `stream_once`, and communicates back either by raising
`LLMTransportError` directly (for the `PREMATURE_EOF` case) or by returning enough
information for the caller to decide whether to `break`. Because Python closures/locals
mean the helper cannot mutate `stream_once`'s `finish_reason` local by side effect alone, the
implementer must have the helper return the (possibly updated) `finish_reason` plus a
break/continue signal — this is the one design decision intentionally left open (UNK-02) and
recorded, not resolved, in this plan.

## Implementation steps

1. **Phase 1: Preparation (characterization tests, behavior lock)**
   - [ ] In `tests/shared/test_llm_sse_stream.py`, inside `TestStreamOnce`, add (or confirm
     already covered by) tests for each of these five edge cases against the
     *current, unextracted* implementation:
     - stream exhausts with `finish_reason` already set (clean completion) — `break` must
       not raise.
     - stream exhausts with `is_done=True` but `finish_reason` still `None`.
     - stream exhausts with `is_done=False` and `finish_reason=None` — must raise
       `LLMTransportError(kind="PREMATURE_EOF", ...)` with `partial_text` from accumulated
       `content_parts` (the existing `test_premature_eof_without_finish_reason_raises` at
       line 262 already covers this exact case — confirm it stays green rather than
       duplicating it).
     - `is_done=True` from `parser.feed` on a chunk that also carries a `finish_reason` —
       loop must break immediately after processing that chunk.
     - multiple chunks processed before either exit condition is hit.
     - `stat_parse_errors_ref` accumulation across multiple chunks, including the reset of
       `parser.stat_parse_errors` to 0 after each accumulation (the existing

## Risks

- **Risk**: The extraction accidentally reorders or alters one of the three exit-condition
  checks (`exhausted`/`is_done`/`finish_reason`), silently changing when `PREMATURE_EOF` is
  raised or when the loop breaks. → **Mitigation**: Phase 1 writes and green-lights all five
  characterization tests *before* touching `stream_once` (behavior lock), and Phase 2 re-runs
  the identical suite immediately after extraction, comparing outcomes 1:1. Likelihood: low.
- **Risk**: `mutmut` remains unavailable (broken install, per UNK-01), so mutation coverage
  cannot mechanically verify the extracted helper's branches. → **Mitigation**: the source
  requirement's own instructions already prescribe a manual branch-by-branch review as the
  documented fallback (Implementation step, Phase 2's last bullet); this plan carries that
  fallback forward and requires it to be written down in the implementation report rather
  than silently skipped. Likelihood: low (already realized; not a probabilistic risk but a
  known, mitigated gap).
- **Risk**: A future contributor calls the new extracted helper directly (bypassing
  `stream_once`'s exception-translation `try`/`except` block around `http.stream(...)`),
  reintroducing untranslated `httpx` exceptions. → **Mitigation**: name the helper with a
  leading underscore (private convention already used by `_handle_status`/`_build_payload`
  in this class) and document in its docstring that it must only be called from within
  `stream_once`'s existing `try` block. Likelihood: low.
- **Risk**: The pre-existing, unrelated `eventbus` `lint-imports` violation is mistaken
  during implementation for a regression caused by this change, wasting investigation time.
  → **Mitigation**: this plan's Design and Validation sections explicitly record the
  pre-existing violation and its 4 findings (all in `scripts/eventbus/*.py`) as the expected
  baseline, so the implementer can diff against it rather than re-diagnosing. Likelihood: low.
