## Goal
Unify the duplicated pre-call health/lifecycle/transport/semaphore gate chain shared by `ToolTransportInvoker.invoke()` (test-only) and `ToolExecutor._raw_execute()` (live path) into a single private helper so the live path cannot silently diverge from the tested one.

## Priority
Medium

## Scope
- **In-Scope**: Extract the shared pre-call gates into one private helper on `ToolTransportInvoker`; route both `invoke()` and `ToolExecutor._raw_execute()` through it; remove the duplicated inline gate blocks from both callers; add a characterization test proving `invoke()` and `_raw_execute()` produce identical results; keep `ruff`, `mypy`, and `bandit` clean.
- **Out-of-Scope**: Any change to the gating policy itself (which conditions are fatal/warning, health states, lifecycle contract); adding new gates; changing retry/timeout/semaphore semantics; altering the health registry or lifecycle protocol interfaces; refactoring unrelated methods in either module.

## Background
Every MCP tool call reaches the network through `shared/tool_executor.py::ToolExecutor._raw_execute()`, which runs a gate chain (`_check_health` -> `_ensure_lifecycle_ready` -> transport resolution -> semaphore -> `_invoke_and_record`). The base class `shared/tool_transport_invoker.py::ToolTransportInvoker.invoke()` repeats the same gates (`_check_health` -> disabled-server check -> lifecycle -> transport resolution -> semaphore -> `_invoke_and_record`). A repository-wide search shows `invoke()` is referenced only inside `tests/shared/` and never from `scripts/`. Both methods already share `_check_health`, `_invoke_and_record`, `_handle_lifecycle_error`, and `_record_transport_error`; only the inline gate sequencing is duplicated.

## Problem
Two independent but near-identical gate implementations exist for the same trust boundary. The rich test suite exercises `invoke()`, while the live `_raw_execute()` path is exercised by fewer, thinner tests. If a guard is added to one copy and forgotten in the other, the divergence is invisible to CI because the two methods are validated separately. Repository evidence confirms the copies are not byte-identical: `invoke()` contains an explicit `startup_mode == StartupMode.NONE` disabled-server gate (`tool_transport_invoker.py` lines 211-216) whereas `_raw_execute()` reaches the disabled server via the generic transport-missing path (`tool_executor.py` lines 116-120), producing a different error message for the same outcome. That concrete divergence is exactly the failure mode the duplication invites.

## Reason for change
The duplication is a latent correctness/maintainability risk at the one place where every MCP call is gated before hitting the network. A gap introduced into the live `_raw_execute()` path would not be caught by `invoke()`'s test coverage, and vice versa. Unifying onto one helper makes future guard edits apply to a single source of truth.

## Implementation intent
Extract the shared gating steps into one private async helper on `ToolTransportInvoker` that returns the first `ToolCallResult` error encountered, or `None` when all gates pass. Both `invoke()` and `ToolExecutor._raw_execute()` delegate to it, keeping the async lifecycle await in the same relative position today. Remove the duplicated inline gate blocks from both callers. Preserve exact current behavior: gate order, HALF_OPEN trial dispatch, disabled-server rejection, lifecycle error normalization, transport-missing error result, per-server-key semaphore application, and which errors become `ToolCallResult` vs which propagate as exceptions.

## Requirements
- `REQ-001`: Introduce one private async gate helper on `ToolTransportInvoker` that runs health, disabled-server, lifecycle, transport-resolution, and semaphore-setup in the current order and returns the first `ToolCallResult` error, or `None` when all gates pass.
- `REQ-002`: Route `ToolTransportInvoker.invoke()` through the shared helper, removing its inline gate block while preserving its public signature and return contract.

- `REQ-005`: Add a characterization test asserting `invoke()` and `_raw_execute()` produce identical results (same `ToolCallResult`, `server_key`, `error_type`) for a representative healthy call and a representative failed call.
- `REQ-006`: Keep `ruff`, `mypy`, and `bandit` clean on all touched files.
