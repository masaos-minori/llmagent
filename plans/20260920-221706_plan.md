## Goal
- Reduce `scripts/agent/stale_detector.py`'s false-positive rate on `docs/*.md`-target
  implementation procedures by (1) excluding known non-symbol prose tokens (tool
  vocabulary, front-matter keys, workflow status values) from `_check_symbol_refs()`,
  and (2) scoping each line-number citation in `_check_line_refs()` to the file it
  actually refers to, rather than always the Target file.

## Priority
Medium

## Scope
- **In-Scope**:
  - Extend `_check_symbol_refs()`'s filtering to exclude a fixed allowlist of
    tool-vocabulary tokens (`Edit`, `Write`, `Read`, `Bash`, `old_string`,
    `new_string`, `replace_all`), CLI tool names (`ruff`, `mypy`, `pytest`, `pyright`,
    `bandit`), common front-matter keys (`title`, `area`, `tags`, `related`,
    `source`), and workflow status values (`Pending`, `In Progress`, `Blocked`,
    `Completed`).
  - Change `_check_symbol_refs()` to also check a symbol against a Reference File's
    content (not only the Target file's) when the symbol appears near a
    backtick-quoted `.py` path other than the Target file — see Design.
  - Change `_check_line_refs()` to resolve each line-number citation's actual scoped
    file (the nearest preceding backtick-quoted `.py`/`.md` path in the same
    sentence/list item) and validate against that file's real line count instead of

  - Add unit tests to `tests/agent/test_stale_detector.py` covering the three

## Background
`code-implementation` Step 3 (Pre-execution Stale Detection) runs
`scripts/agent/stale_detector.py` against every implementation procedure before
allowing implementation to proceed, aborting on any single mismatch. During a
2026-09-20 batch of 22 `docs/*.md`-target procedures, both `_check_symbol_refs()` and
`_check_line_refs()` produced false positives on every procedure, requiring manual
verification each time.

## Problem
Direct reading of `scripts/agent/stale_detector.py` (confirmed current, 396 lines)
verified both root causes the Issue describes still hold:
1. `_check_symbol_refs()` (lines 267-299) extracts every backtick-quoted token via
   `_SYMBOL_RE` (line 40) and only filters `http`-prefixed, path-like, or
   dotted/tilde-prefixed tokens plus a bare `^[a-zA-Z_][a-zA-Z0-9_]*$` shape check
   (lines 280-288) — this excludes none of the confirmed false-positive categories
   (tool names, front-matter keys, workflow status values), and does not distinguish
   a symbol that exists in a cited Reference File from one that exists nowhere.
2. `_check_line_refs()` (lines 231-264) matches every "Line N"/"Lines N-M" occurrence
   in the whole procedure document text via `_LINE_REF_RE` (lines 32-36) and compares
   it unconditionally against `len(source_lines)` for the single Target file passed
   into `from_procedure()` (line 217) — a line citation for a different, correctly-cited
   Reference File is checked against the wrong file's length.

## Reason for change
Per `AGENTS.md` Loop Prevention and `code-implementation` Step 3's "any single
mismatch constitutes stale, abort immediately" rule, a false positive currently costs
as much as a genuine stale reference. A 100% false-positive rate on `docs/*.md`-target
procedures gives the check no signal-to-noise value for that class of procedure and
risks normalizing "manually verify and proceed" as a reflex that could one day mask a
real stale reference.

## Implementation intent
Add a fixed allowlist to `_check_symbol_refs()` for known non-code prose tokens, and
extend both `_check_symbol_refs()` and `_check_line_refs()` to resolve which file a
citation is actually scoped to (the nearest preceding backtick-quoted `.py`/`.md`
path) before validating against that file's content/line count — implemented via
simple regex/string scanning of the procedure text, consistent with the tool's
existing design (no AST parsing).

## Requirements
- `REQ-001`: Add an allowlist of non-symbol prose tokens to `_check_symbol_refs()`
  (tool vocabulary, CLI tool names, front-matter keys, workflow status values) so
  they never produce a `symbol_missing` finding.
- `REQ-002`: Extend `_check_symbol_refs()` to resolve, for each candidate symbol, the
  nearest preceding backtick-quoted `.py` file path in the same paragraph; if that
  path differs from the Target file and the file exists on disk, check the symbol
  against that file's content instead of (or in addition to, if ambiguous) the Target
  file's.
- `REQ-003`: Extend `_check_line_refs()` to resolve, for each line-number citation,
  the nearest preceding backtick-quoted `.py`/`.md` file path in the same
  sentence/list item; if that path differs from the Target file and the file exists
  on disk, validate the citation against that file's actual line count instead of the
  Target file's.
- `REQ-004`: Add unit tests to `tests/agent/test_stale_detector.py` covering: (a) a
  tool-vocabulary/front-matter/status-value term in backticks produces no
  `symbol_missing` finding; (b) a real symbol from a named, existing Reference File,
  cited with a line range valid for that Reference File but invalid for the Target
  file, produces no finding; (c) a genuinely missing/renamed Target-file symbol, and
  a genuinely out-of-bounds Target-file line range, still produce their respective
  findings.

## Assumptions
- A "nearest preceding backtick-quoted `.py`/`.md` path in the same paragraph/sentence"
  heuristic is sufficient to resolve which file a symbol or line citation is scoped
  to, without needing full markdown-structure parsing — consistent with the tool's
  existing simple-regex design and the Issue's own suggested approach ("the nearest
  preceding backtick-quoted `.py`/`.md` path").
- When the nearest preceding path does not exist on disk (e.g. a typo, or a
  conceptual/illustrative path), the check falls back to the Target file's content/
  line count rather than silently skipping the citation — preserves the tool's
  "any single mismatch constitutes stale" safety property for a citation that cannot
  be resolved to a real file.

## Design
Both fixes follow the same pattern: **resolve scope, then validate against the
resolved file** instead of always the Target file. A shared helper,
`_resolve_scoped_file(proc_text: str, match_pos: int, target_file: str) -> str`,
locates the nearest preceding backtick-quoted `.py`/`.md` path within the same
Markdown paragraph (delimited by blank lines) relative to `match_pos`; if none is
found, or the found path does not exist on disk relative to the repository root, it
returns `target_file` unchanged (safe fallback per Assumptions). Both
`_check_symbol_refs()` and `_check_line_refs()` call this helper per-citation and
read the resolved file's content/line count (caching per resolved path within a
single `from_procedure()` call, to avoid re-reading the same Reference File once per
citation) instead of the single Target-file content/`source_lines` passed in today.

The non-symbol allowlist (REQ-001) is a separate, simpler fix: a frozenset of the
Issue's named tokens, checked before the existing `code_symbols` filtering loop in
`_check_symbol_refs()`.

`_check_import_refs()` and `_check_before_blocks()` keep their current Target-file-only
behavior — the Issue reports no false positive against them, and extending scope
resolution to functions with no confirmed problem would be unrequested scope growth.

## Risks
- **Risk**: The paragraph-boundary heuristic for "nearest preceding path" could
  mis-scope a citation in an unusually structured procedure document (e.g. a citation
  separated from its file path by an intervening code block) → **Mitigation**: the
  safe fallback (unresolved scope → Target file) means a mis-scoped citation degrades
  to today's existing behavior (checked against the Target file) rather than silently
  passing — no new false negative is introduced, only the false-positive reduction is
  scoped to the confirmed common case (see UNK-01).
- **Risk**: Reading additional Reference Files per citation could slow down stale
  detection on documents with many citations → **Mitigation**: cache resolved-file
  content per path within a single `from_procedure()` call (Design), so a Reference
  File cited multiple times is read once.
