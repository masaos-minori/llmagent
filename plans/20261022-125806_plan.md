# Plan

## Goal
Remove the unused file-based consumer offset helpers (`scripts/eventbus/offsets.py`) and the `offsets_dir` configuration key from the EventBus, keeping ACK-advanced offsets, the SQLite `consumer_offsets` table, and resume behavior unchanged.

## Priority
Medium

## Scope
- **In-Scope**:
  - Delete `scripts/eventbus/offsets.py` and every test that imports its helpers.
  - Remove `offsets_dir` from the EventBus configuration model, the sample configuration, the test fixtures that construct the configuration, the deploy script's directory creation, and the documents that describe it.
  - Add a test that a configuration still carrying `offsets_dir` is rejected as an unknown key.
  - Remove the stale docstring-baseline entry and regenerate the generated reference block.
- **Out-of-Scope**:
  - Offset storage, monotonic advancement, ACK-advanced offsets, and resume computation.
  - Deleting `/opt/llm/offsets` or any offset file on any host.
  - Editing ADR text (see UNK-01).
  - Other EventBus configuration keys and schema work.

## Background
The legacy offset import was removed earlier; `consumer_offsets` is the only resume source and a read-only inspection of the deployed host on 2026-10-22 found `/opt/llm/offsets` empty and `consumer_offsets` empty. The remaining file-based helpers (`read_offset`, `write_offset`, `_validate_consumer_identity`, `_sanitize_consumer_id`, `CorruptOffsetError`) have no caller under `scripts/`; only tests import them. `offsets_dir` is still a required key of `EventBusConfig`, and the semantics document records the removal of the helpers as an open decision. The owner decided on 2026-10-22 (answer recorded in this session) to remove the helpers and the key.

## Problem
Dead file-format code and a required configuration key remain for a feature without a runtime user. Adversarial verification found a coupling the Issue states only as a constraint: `load_config()` rejects unknown keys, so once the key leaves the known set, the deployed `/opt/llm/config/eventbus.toml`, which still contains `offsets_dir`, makes the service fail to start until the configuration is deployed with the code. Further facts: 26 test files (about 120 references) construct `EventBusConfig(offsets_dir=...)` and must change in the same unit of work; the startup-ignores-files test added earlier loses its meaning once the key is gone; ADR-002 (platform config isolation) and the EventBus persistence ADR mention `offsets_dir` and cannot be edited without the owner's ADR decision.

## Reason for Change
Removing code with no caller lowers maintenance cost and removes a misleading configuration key that operators could mistake for an active resume source.

## Implementation Intent
Apply the owner's decision in one reviewable change set ordered so the repository stays green: the config model and sample file first, the helper module and its tests with the fixture edits, then the documentation, then deployment of code and configuration together (the deploy script copies `config/eventbus.toml` and `scripts/` in one run).

## Requirements
- `REQ-001`: Record the owner's decision (remove the helpers and the key) as the Plan's basis; if it changes, stop and amend this Plan.
- `REQ-002`: Delete `scripts/eventbus/offsets.py` and the tests that exercise it (the file-helper classes of `test_eventbus_offsets.py`, the helper test in `test_eventbus_replay_subscribe.py`), keeping all ACK-advanced offset, SQLite offset, and resume tests.
- `REQ-003`: Remove `offsets_dir` from `EventBusConfig`, the known/required/type key sets, `load_config()`, and `config/eventbus.toml`.
- `REQ-004`: Remove `offsets_dir` from every test fixture that constructs the configuration, delete the startup-ignores-files test, and add a test that a configuration containing `offsets_dir` is rejected as an unknown key.
- `REQ-005`: Remove the `mkdir -p /opt/llm/offsets` line, the stale docstring-baseline entry, and the documentation of the helpers and the key (semantics open decision, operations section, reference sentence and generated block, `rules/env.md`).
- `REQ-006`: Deploy code and configuration together and verify the service starts against the deployed configuration (copy of the deployed database, no offsets directory).
