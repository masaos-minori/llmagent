# Plan: Harden health metrics and remove private metrics API dependencies

## Goal

Return stable degraded responses using supported metrics interfaces rather than reaching into another module's private internals, ensuring the health endpoint remains reliable when dependencies or metrics are unavailable.

## Priority
Medium

## Scope
- **In-Scope**: Health endpoint's metrics access path — replacing private Prometheus API access with supported public interfaces, ensuring graceful degradation on metric-read failures
- **Out-of-Scope**: Unrelated route handler changes, broker health metric additions beyond what the health endpoint currently reads

## Background
The EventBus health endpoint currently depends on accessing another module's underscore-prefixed (private) metrics internals; this issue exposes the needed measurements through a supported interface and ensures a metrics-read failure degrades the health response rather than failing the whole endpoint.

## Problem
The health endpoint (`scripts/eventbus/health_route.py`, via `route_helpers.py`) reads measurements by accessing another module's underscored/private internals rather than a supported public interface, and a metrics-read failure is not confirmed to degrade gracefully rather than failing the entire health check.

## Reason for change
The health endpoint must remain reliable when dependencies or metrics are unavailable.

## Implementation intent
Return stable degraded responses using supported metrics interfaces rather than reaching into another module's private internals.

## Requirements
- `REQ-001`: Expose required measurements through application-owned state or supported public interfaces.
- `REQ-002`: Handle metric-read failures without failing the whole health endpoint.
- `REQ-003`: Add compatibility tests for the metrics implementation used by the project.

## Design

### Replace Private Prometheus API Access (REQ-001)
Current state in `health_route.py`:
```python
# Line 12-14: Importing private metrics objects
from eventbus.route_helpers import (
    _db_lock_contention,
    _db_lock_wait_time,
    _db_query_duration,
    ...
)

# Lines 70-88: Reading private Prometheus internals
def _hist_avg(hist: Any) -> float:
    """Return average observation for a Histogram, or 0.0 if no observations."""
    try:
        samples = hist._samples()  # PRIVATE API — fragile
        s_sum = 0.0
        s_count = 0
        for s in samples:
            if s.name == "_sum":
                s_sum = s.value
            elif s.name == "_count":
                s_count = int(s.value)
        return s_sum / s_count if s_count > 0 else 0.0
    except (AttributeError, TypeError, ZeroDivisionError):
        return 0.0

lock_wait_avg = _hist_avg(_db_lock_wait_time)      # Uses private API
query_dur_avg = _hist_avg(_db_query_duration)       # Uses private API
lock_contention_total = _db_lock_contention._value.get()  # PRIVATE API — fragile
```

**Decision**: Use the public `prometheus_client` API instead of private internals.

For Histogram metrics, use the public `.metrics()` method:
```python
# In route_helpers.py:
from prometheus_client import Histogram

def get_histogram_avg(hist: Histogram) -> float:
    """Return the average observation for a Histogram via the public API.
    
    Returns 0.0 if the histogram has no observations or if the API is unavailable.
    """
    try:
        metrics = list(hist.collect())
        if not metrics:
            return 0.0
        # Sum of sums / sum of counts across all collectors
        total_sum = 0.0
        total_count = 0
        for metric in metrics:
            for sample in metric.samples:
                if sample.name.endswith("_sum"):
                    total_sum += sample.value
                elif sample.name.endswith("_count"):
                    total_count += int(sample.value)
        return total_sum / total_count if total_count > 0 else 0.0
    except Exception:
        return 0.0
```

For Counter metrics, use the public `.metrics()` method:
```python
from prometheus_client import Counter

def get_counter_value(counter: Counter) -> int:
    """Return the current value of a Counter via the public API.
    
    Returns 0 if the counter has no value or if the API is unavailable.
    """
    try:
        metrics = list(counter.collect())
        if not metrics:
            return 0
        for metric in metrics:
            for sample in metric.samples:
                if sample.name == counter._name + "_total":
                    return int(sample.value)
        return 0
    except Exception:
        return 0
```

In `health_route.py`:

### Graceful Degradation on Metric-Read Failures (REQ-002)
The existing `_hist_avg()` function already catches `(AttributeError, TypeError, ZeroDivisionError)` at line 83. However, the new public API approach needs similar protection.

**Decision**: Both `get_histogram_avg()` and `get_counter_value()` catch all exceptions and return safe defaults (0.0 for averages, 0 for counters). This ensures the health endpoint never fails due to metric-read errors.

Additionally, the broker backlog threshold check at line 65 should be guarded:
```python
# Current (problematic):
if max_queue_depth >= broker.backlog_health_threshold:  # broker could be None
    degraded_reasons.append("broker_queue_backlog_high")

# Fix: Move inside the broker guard or add explicit None check
if broker is not None:
    if max_queue_depth >= broker.backlog_health_threshold:
        degraded_reasons.append("broker_queue_backlog_high")
```

### Broker Backlog Threshold Guard (UNK-03)
The current code at line 65 accesses `broker.backlog_health_threshold` outside the `if broker is not None:` guard at line 53. This means if broker is None, this line will raise an AttributeError.

**Decision**: Move the backlog threshold check inside the broker guard:
```python
# Broker health metrics
active_subscribers = 0
max_queue_depth = 0
slow_consumers = 0
overflow_disconnects = 0
duplicate_connection_rejections = 0
if broker is not None:
    active_subscribers = broker.subscriber_count()
    max_queue_depth = broker.max_queue_depth()
    slow_consumers = broker.slow_consumer_count()
    overflow_disconnects = broker.overflow_disconnect_count()
    duplicate_connection_rejections = broker.duplicate_rejection_count()
    # Moved inside the guard:
    if max_queue_depth >= broker.backlog_health_threshold:
        degraded_reasons.append("broker_queue_backlog_high")
```
