## Background
`RagPipeline.__init__` (`scripts/rag/pipeline.py:87`) unconditionally calls `resolve_rag_config(cfg, module_cfg=module_cfg)` on whatever `cfg` object it receives. `resolve_rag_config` (`scripts/rag/config_resolution.py:87`) converts a non-`RagConfigImpl`/non-dict object via `cfg.__dict__` (line 118), fills any field absent from that dict with `_DEFAULTS_FOR_ALL`'s default (`llm_url`/`embed_url` both default to `""`, line 72-73), then raises `ValueError` if `use_search` resolves `True` while `llm_url`/`embed_url`/`rag_db_path` remain empty (lines 145-158). Commit `5e568520` (2026-09-18) already changed the *global* `use_search` default to `False` to resolve exactly this self-contradiction for tests relying on defaults — but the 4 files in this Plan's scope each explicitly set `use_search=True` (or rely on `RagPipelineConfig`'s own separate default of `True`, confirmed via `test_defaults_when_cfg_empty`) in their own minimal fixture, without ever setting `llm_url`/`embed_url`, so they still hit the validation.

## Problem
15 tests fail identically at `RagPipeline.__init__`'s config-resolution step, before any of the test's own HTTP-mode/augmentation assertions run:
- `tests/agent/commands/test_agent_rag.py::TestAugmentHttpMode` (5 tests) — `_make_cfg()`'s `defaults` dict (a `SimpleNamespace`) sets `"use_search": True` but never includes `llm_url`/`embed_url` keys at all.
- `tests/rag/test_pipeline_http_result_kind.py` (4 tests) — `_make_pipeline()`'s `cfg = MagicMock()` explicitly sets `cfg.use_search = True` but never accesses/sets `cfg.llm_url`/`cfg.embed_url`, so they are absent from `cfg.__dict__` when `resolve_rag_config` reads it (a `MagicMock`'s `__dict__` only contains explicitly-assigned attributes, not auto-vivified ones).
- `tests/rag/test_rag_http_mode.py` (4 tests) — same `MagicMock()`-based pattern as the sibling file above (confirmed via Read, `cfg.use_search = True` at line 24, no `llm_url`/`embed_url`).
- `tests/mcp_servers/rag_pipeline/test_rag_pipeline_mcp_service.py::TestServiceStart` (2 tests) — constructs `models_module.RagPipelineConfig(use_mqe=True, use_rrf=True, use_rerank=True, top_k_search=5, top_k_rerank=10)` without `llm_url`/`embed_url`; `RagPipelineConfig`'s own defaults independently default `use_search` to `True` (confirmed via `TestBuildRagCfgAdapter::test_defaults_when_cfg_empty`'s `assert ns.use_search is True` for an empty `RagPipelineConfig()`).

## Reason for change
These 15 tests are meant to exercise HTTP/remote RAG behavior (augmentation, result-kind classification, service startup) that legitimately requires `llm_url`/`embed_url` to be present — the validation they're tripping over is protecting a genuine invariant, and the tests' own minimal fixtures simply never supplied it (likely predating, or never having been reconciled with, the validation's introduction/tightening). Fixing the fixtures (not weakening the validation) restores 15 tests' actual coverage of code they were written to test.

## Implementation intent
Add non-empty placeholder `llm_url`/`embed_url` string values (e.g. matching the existing `rag_service_url`/`rag.local` test-URL conventions already used in each file) to each of the 4 files' own minimal cfg-construction helper, so `resolve_rag_config` no longer finds them empty. Do not touch `resolve_rag_config`, `RagConfigValidator`, or `RagPipelineConfig`'s defaults.
