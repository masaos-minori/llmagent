# Plan: SignalHandler registers minimal fallback on Windows without pywin32

## Goal
- Ensure `SignalHandler.register()` registers a minimal signal handler on Windows even when pywin32 is unavailable, using ctypes as an alternative.

## Priority
Medium

## Scope
- **In-Scope**: Add ctypes-based console control handler fallback when pywin32 is unavailable; improve error messaging
- **Out-of-Scope**: Adding cross-platform signal handling abstraction; changes to POSIX signal handler behavior

## Background
`SignalHandler.register()` in `scripts/agent/signal_handler.py` registers SIGTERM/SIGINT handlers using `loop.add_signal_handler()` on POSIX systems. On non-POSIX platforms, it falls back to Windows console control handlers.

## Problem
When `loop.add_signal_handler()` raises `NotImplementedError`, the fallback path requires pywin32. If pywin32 is not installed, the warning is logged but NO signal handler is registered. This means the agent receives no graceful shutdown notification on Windows without pywin32. Process terminates abruptly, losing in-memory state. No warning is visible to the user about missing signal handling.

## Reason for change
Graceful shutdown is important for data integrity. Without any signal handler on Windows, users lose in-memory state on Ctrl+C. A ctypes-based fallback provides basic functionality without requiring pywin32.

## Implementation intent
Register a minimal fallback handler even without pywin32 using ctypes to call `SetConsoleCtrlHandler` directly. Improve error messaging to clearly indicate the limitation. Document the requirement explicitly.

## Requirements
- `REQ-001`: Signal handler is registered even without pywin32 (via ctypes or similar)
- `REQ-002`: Error message clearly indicates the limitation
- `REQ-003`: Test verifies handler registration on Windows without pywin32
- `REQ-004`: Documentation updated to reflect platform requirements

## Design
### Current Behavior (Verified Against Source)
1. `signal_handler.py` line 61-64: Try `loop.add_signal_handler()` for each signal
2. Line 64-98: On `NotImplementedError`, fall back to Windows console control handler
3. Line 83-87: If pywin32 import fails, log warning but don't register handler
4. Line 97-98: Outer `except Exception: pass` silently swallows all errors

### Proposed Change
```python
for sig in (signal.SIGTERM, signal.SIGINT):
    try:
        loop.add_signal_handler(sig, _sigterm_handler)
    except NotImplementedError:
        try:
            import sys  # noqa: PLC0414 — deferred import: only needed on the NotImplementedError (non-POSIX) fallback path, not at module load time

            if hasattr(sys, "frozen"):
                try:
                    import win32api  # noqa: PLC0414 — Windows-only dependency; a top-level import would break non-Windows platforms
                    import win32con  # noqa: PLC0414 — Windows-only dependency; a top-level import would break non-Windows platforms

                    def _console_ctrl_handler(ctrl_type: int) -> bool:
                        if ctrl_type == win32con.CTRL_CLOSE_EVENT:
                            loop.call_soon_threadsafe(_sigterm_handler)
                        return True

                    win32api.SetConsoleCtrlHandler(_console_ctrl_handler, True)
                    logger.debug(
                        "Registered Windows console control handler for %s",
                        sig,
                    )
                except ImportError:
                    # Fallback to ctypes-based handler
                    try:
                        import ctypes
                        kernel32 = ctypes.windll.kernel32
                        SetConsoleCtrlHandler = kernel32.SetConsoleCtrlHandler
                        SetConsoleCtrlHandler.argtypes = [ctypes.c_void_p, ctypes.c_long]
                        SetConsoleCtrlHandler.restype = ctypes.c_long

                        def _console_ctrl_handler(ctypes_arg: int) -> bool:
                            if ctypes_arg == 0:  # CTRL_CLOSE_EVENT = 0 (defined in wincon.h; also equals CTRL_LOGOFF_EVENT on some systems)
                                loop.call_soon_threadsafe(_sigterm_handler)
                            return True

                        SetConsoleCtrlHandler(_console_ctrl_handler, True)
                        logger.debug(
                            "Registered Windows console control handler (ctypes) for %s",
                            sig,
                        )
                    except Exception as e:
                        logger.error(
                            "Cannot install any signal handler on Windows: %s", e
                        )
                except Exception as e:  # noqa: BLE001 — best-effort Windows fallback registration must not crash startup
                    logger.error(
                        "Failed to set Windows console control handler: %s", e
                    )
            else:
                logger.warning(
                    "Signal handling not available on Windows outside console; "
                    "use Ctrl+C or close the terminal to shut down"
                )
        except Exception:  # noqa: BLE001 — best-effort non-POSIX signal fallback must not crash startup even on unexpected failures
            pass
```

Key changes:
1. Replace the `except ImportError` block with a ctypes-based fallback
2. Use `CTRL_CLOSE_EVENT = 0` constant (Windows API standard)
3. Log success/failure at appropriate levels
4. Keep the outer `except Exception: pass` to prevent startup crashes
