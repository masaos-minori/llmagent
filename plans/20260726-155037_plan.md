## Goal

Prevent silent overwriting of `pending_approval_task_id` and ensure halted tasks are properly rejected when restored from previous approvals.

## Scope

**In-Scope:**
- Add warning logging when `pending_approval_task_id` would be overwritten
- Validate retrieved task status in `_init_workflow_task()` — reject halted tasks
- Ensure `pending_approval_task_id` is cleared immediately after use

**Out-of-Scope:**
- Implementing queue-based approach for multiple concurrent approvals (deferred to future iteration)
- Modifying other workflow task operations
- Adding new database columns or indexes

## Assumptions

1. Single `pending_approval_task_id` field is sufficient for current use case; queue-based approach is deferred
2. Halted tasks should never be automatically restored — they require explicit user action
3. The existing clear-after-use pattern in orchestrator.py (line 197) is correct and should be preserved
