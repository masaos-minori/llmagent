## Goal
- Cut about two minutes from the EventBus test suite by giving `TestSubscribeAuth` a short SSE idle timeout, so its two ~60-second tests finish in a few seconds without changing what they assert.

## Priority
Low

## Scope
- **In-Scope**:
  - Set a short `sse_idle_timeout` (1 second) on the configuration of `TestSubscribeAuth`'s fixture application, assigned after construction.
  - Tighten the 120-second bound in `test_subscribe_with_timeout_disconnect_detection`.
  - Re-run the duration report for the EventBus suite and record any remaining test above about 5 seconds as a follow-up.
- **Out-of-Scope**:
  - Production code and other test modules.
  - Changing what the tests assert about authorization.

## Background
Source: `issues/20261008-155824_ebauthidle01_shorten-the-60-second-idle-waits-in-two-eventbus-auth-tests.md`. After the earlier fix that gave the shared EventBus test helper an optional idle-timeout argument, the EventBus suite runs in about 3 minutes (335 passed, 1 skipped) and two tests in this module dominate it.

## Problem
- `TestSubscribeAuth::test_subscribe_with_valid_consumer_token` and `test_subscribe_with_timeout_disconnect_detection` each take about 60 seconds (Confirmed by repository evidence — the duration report of the slowest tests earlier in this session: 60.05 s and 60.00 s; the next slowest is 6.09 s).
- The class builds its own application in `setup_class()` through `_make_test_app()`, which constructs `EventBusConfig` with the default `sse_idle_timeout` and does not use the shared helper's idle-timeout argument (Explicit in `tests/eventbus/test_eventbus_auth.py`).
- The subscribe route reads `request.app.state.config.sse_idle_timeout` and closes the stream after that many idle seconds (Explicit in code — `scripts/eventbus/subscribe_route.py`), and `TestClient.stream()` waits for the application to finish when the `with` block exits, so the first test's wait and the second test's exit both last one idle timeout.
- The configuration validates `sse_idle_timeout` against `sse_heartbeat_interval` only in its constructor (Explicit in `scripts/eventbus/config.py` lines 152-162), so assigning a smaller value afterwards is permitted; the existing pattern is `object.__setattr__(config, "sse_idle_timeout", 0.5)` (Explicit in `tests/eventbus/test_eventbus_restart_resume.py`).
- The first test asserts only that the stream closes within 120 seconds (Explicit in the test), so the 60-second wait adds no verification value.

## Reason for change
- A shorter suite is run more often and fails faster; the waits add no verification value.

## Implementation intent
- In `TestSubscribeAuth.setup_class()` assign `sse_idle_timeout = 1.0` to the fixture's configuration with `object.__setattr__`, keep every assertion, and lower the bound in the first test from 120 seconds to a value that still fails when the stream does not close (for example 10 seconds).

## Requirements
- `REQ-001`: `TestSubscribeAuth.setup_class()` sets a 1-second `sse_idle_timeout` on its fixture configuration after construction. (`tests/eventbus/test_eventbus_auth.py`)
- `REQ-002`: The bound in `test_subscribe_with_timeout_disconnect_detection` is tightened in line with the short timeout; no assertion about authorization changes. (same file)
- `REQ-003`: Both tests finish in well under 10 seconds, every test of the module passes, and the EventBus suite has no test slower than about 10 seconds; tests above about 5 seconds are listed as a follow-up. (same file)

## Design
The change belongs in `setup_class()` because the class builds one application for all its tests; the other classes of the module build their own apps and are unaffected. The value is assigned with `object.__setattr__` after construction because the configuration object is validated only at construction and is not otherwise mutable in the existing test pattern.

A 1-second idle timeout is the validated minimum (`sse_idle_timeout >= 1.0`). The first test's bound moves from 120 seconds to a value a few times the new timeout, which still detects a stream that never closes.
