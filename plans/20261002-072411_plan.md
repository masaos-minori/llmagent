# Plan: Correct stale governance document path references across docs, tools, skills, and routing

## Goal

Replace stale governance document path references (`docs/00_governance_0N_*`, `docs/governance_0N_*`, `docs/00_governance/00_governance_03_*`) with actual existing paths so that humans, AI agents, and tool docstrings point at existing files.

## Priority

Medium

## Scope

- **In-Scope**: Replace each stale reference with the actual existing path; decide on the directory-less form convention; determine runtime vs. documentation-only uses of stale paths in tools; record exit-status decision for untracked-marker warnings.
- **Out-of-Scope**: Area Canonical Maps rows in the Policy (`canon001`); renaming or moving governance documents; references in `plans/done/`, `implementations/done/`, and `issues/done/`; registering or resolving existing untracked markers in `docs/23_agent/` and `docs/21_rag/`.

## Background

The governance docs were renamed/consolidated into the four-plus-guide files under `docs/00_governance/` (see the dated correction comments in `tools/check_needs_confirmation_inventory.py`). Not every reference was updated during that rename. The old prefixed form `docs/00_governance_0N_*`, the directory-less form `docs/governance_0N_*`, and in `routing.md` the form `docs/00_governance/00_governance_03_*` remain scattered across the repository.

## Problem

Repository search (2026-10-01):
- Old prefixed form `docs/00_governance_0N_*` appears in 16 locations across `tools/` (docstrings/comments only).
- Directory-less form `docs/governance_0N_*` appears 33 times across `docs/` (ADRs, area docs, governance docs themselves).
- `routing.md` line 86 tells agents to register markers in `docs/00_governance/00_governance_03_issue-and-uncertainty-management.md`, which does not exist.

## Reason for change

`routing.md` is the entry point for AI task routing; a nonexistent path there directly misroutes agents. Stale paths in tool docstrings and descriptions make checker rules untraceable to their governing document.

## Implementation intent

Replace each stale reference with the actual existing path, preserving the referenced section names. For the directory-less form, first confirm whether it is an intended convention; if not, correct it, otherwise document the convention once and leave references unchanged. For each `tools/*.py` hit, determine whether it is a comment/docstring or a runtime path; treat runtime uses as bugs requiring a test. Edit only path strings; do not rewrite surrounding text.

## Requirements

- `REQ-001`: Fix the `routing.md` path to the Needs Confirmation Inventory.
- `REQ-002`: Fix all `docs/00_governance_0N_*` references to `docs/00_governance/governance_0N_*`.
- `REQ-003`: Decide on the directory-less `docs/governance_0N_*` form and apply the decision consistently.
- `REQ-004`: For any tool that reads a stale path at runtime, fix it and add a regression test.

## Design

### Approach

Replace each stale reference with the actual existing path, preserving the referenced section names. For the directory-less form, first confirm whether it is an intended convention; if not, correct it, otherwise document the convention once and leave references unchanged. For each `tools/*.py` hit, determine whether it is a comment/docstring or a runtime path; treat runtime uses as bugs requiring a test. Edit only path strings; do not rewrite surrounding text.

### Decision Target Matching Logic

Before processing each error in `_wrap_validation_errors`, add:

```python
if entry.decision_target and entry.decision_target not in err:
    continue
```

This ensures each finding is only emitted for the entry that actually caused the error — no cross-product duplication.

### Marker Classification Rule

After inspecting all five governance docs, classify each "Needs Confirmation" occurrence as either:

1. **Definitional**: Text that defines, discusses, or references the label itself (e.g., "A Needs Confirmation marker indicates...", "See the Needs Confirmation Inventory"). These are exempt.
2. **Unresolved-item marker**: Text that denotes an actual unresolved item (e.g., a table cell containing "Needs Confirmation" as a status value, or a parenthesized annotation like "(Needs Confirmation)"). These are reported.

The classification will be encoded as a regex pattern or section-scoped exclusion list, depending on what the inspection reveals.

### Exit Status Decision

Document the decision on whether untracked-marker warnings should cause a non-zero exit. Based on the issue's observation that "the checker exits 0 even when such warnings exist," and the issue's statement that "Whether warnings should fail verification is Needs confirmation," the decision should be recorded in the plan's Unknowns table and implemented accordingly.
