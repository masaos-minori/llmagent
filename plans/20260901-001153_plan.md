## Goal
- Remove environment-specific ("production or local mode") phrasing from documents that contradict ADR-004's single common failure-handling policy, replacing them with language consistent with the unified approach adopted in the revision.

## Priority
High

## Scope
- **In-Scope**: Updating documents that contain "production or local mode" phrasing or environment-specific failure handling descriptions that conflict with ADR-004 Decision #1 and #3; verifying each affected document against current code.
- **Out-of-Scope**: Modifying ADR-004 itself; adding new tests; changing configuration files.

## Background
ADR-004 was revised to adopt a single common failure-handling policy across all environments. Decision #1 states: "システムは、稼働するすべての環境に対して単一の共通障害処理方針を用いる。環境ごとに異なる障害処理方針を定義しない。" Decision #3 states: "環境名は、起動検証、認証、認可、Allowlist強制、承認制御、Tool所有権要件、Routing要件、リソーススコープ検証、DB整合性要件、Workflow要件、Fail-Fast条件、Fail-Closed条件のいずれも変更しない。"

However, several documents still contain "production or local mode" phrasing that contradicts this unified approach. The original issue (adr004_03) identified only one such document, but evidence shows two documents share the identical problematic phrase, plus additional "local mode" references in other documents.

## Problem
Documents contain environment-specific failure handling descriptions that contradict ADR-004's unified policy:
- Two documents contain the exact phrase "production or local mode" when discussing mcp_tool_discovery failure handling.
- Additional documents contain "local mode" references that describe different behavior per environment.
- Code does NOT use "local mode" terminology — it uses `is_prod` boolean checks, which themselves are a deviation noted in ADR-004 Known Deviations.

## Reason for change
The ADR-004 revision eliminated environment-based distinctions. Documents describing different failure handling based on environment name violate Decision #1 and #3 and create operational confusion about which guarantees apply where.

## Implementation intent
For each affected document:
1. Identify all occurrences of "production or local mode", "local mode", and similar environment-specific failure handling descriptions.
2. Replace with language consistent with ADR-004's unified approach (e.g., "regardless of environment" instead of "regardless of whether it is production or local mode").
3. Ensure consistency across all affected documents.

## Requirements
- `REQ-001`: Documents containing "production or local mode" phrasing must be updated to use unified language consistent with ADR-004 Decision #1 and #3.
- `REQ-002`: No document should describe different failure handling behavior based on environment name.
- `REQ-003`: Updated text must accurately reflect current code behavior (which uses `is_prod` checks, not "local mode" terminology).
- `REQ-004`: Consistency check across all affected documents — no remaining contradictions.
