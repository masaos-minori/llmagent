## Design
Root-cause explanation:
- `test_cross_file_duplication_detected_on_full_docs_tree` runs `tools/check_docs_quality` against the full `docs/` tree, parses `[WARNING] <file>:<line> — Content similarity detected between sections '<a>' and '<b>'` lines, builds the pair set, and asserts it equals the hardcoded `EXPECTED_WITHIN_FILE_PAIRS`.
- `_extract_sections` (`tools/check_docs_quality.py:148`) splits each doc into sections by `#` headings; `_compute_section_similarity` (`tools/check_docs_quality.py:139`) flags pairs whose tokenized bodies exceed the Jaccard threshold (0.85).
- `governance_03` previously contained `#### CI-009` and `#### CI-012` subsections with near-identical body text, producing the reported pair.
- CI-009 was removed in commit `ae00c05e`; CI-012 in commit `0dd59762` (2026-09-28). Current `governance_03` has neither header (grep confirms only CI-014/CI-016 remain under Active Items; line 153 documents the removals). With no sections present, the tool correctly emits no pair — the regression lives in the test's golden set, not the tool.
- Therefore the correct fix is to drop the one stale pair from the frozenset. This is legitimate drift correction, not masking: the referenced sections no longer exist and can never be re-detected.

This directly answers the issue's Implementation Intent dichotomy: doc content changed → update the golden set; leave the tool untouched.
