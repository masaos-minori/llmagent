# Plan: Enforce approval policy in configuration validation

## Goal

Require `require_approval: true` in configuration validation for any workflow that can reach tools needing approval (shell execution, deletion, push, etc.), so a misconfiguration is detected at startup.

## Priority

Medium

## Scope

- **In-Scope**:
  - `config/workflows/default.json`: change `require_approval` to `true`
  - `scripts/shared/production_config_validator.py`: add ProductionConfigValidator rule for `require_approval` on workflows with approval-requiring tools
  - `scripts/agent/workflow/workflow_loader.py`: update `_validate()` to check `require_approval` presence
  - `docs/23_agent/agent_03_03_turn-processing-flow-workflow-engine.md`: update approval-policy descriptions
  - `docs/91_security/security_01_architecture-and-trust-boundaries.md`: update approval-policy descriptions
  - `docs/00_governance/governance_03_issue-and-uncertainty-management.md`: remove AGENT-001 from Known Issues ledger
- **Out-of-Scope**:
  - Fail-closed workflow loading (separate issue)
  - Approval UI changes
  - Changes to approval behavior itself

## Background

Source: local investigation notes (memo1.md, ISSUE-10), from AGENT-001. Documentation calls the approval policy mandatory; no code enforces it.

## Problem

- The default `default.json` sets `require_approval` to false (Explicit in code — `config/workflows/default.json`).
- Documentation says the approval policy is mandatory, but nothing in code enforces it (per investigation notes).

## Reason for Change

- A policy described as mandatory but not enforced is only nominal.
- Tool-level approval gates alone cannot confirm a whole stage's result after execution.

## Implementation Intent

- Detect, at startup, a workflow that allows approval-requiring operations without `require_approval: true`.

## Design

### Decision matrix

| Condition | Outcome |
|---|---|
| Workflow with approval-requiring tools + `require_approval: false` | Reject at startup config validation |
| Workflow with approval-requiring tools + `require_approval: true` | Accept |
| Workflow without approval-requiring tools + `require_approval: false` | Accept (no approval needed) |
| Workflow without approval-requiring tools + `require_approval: true` | Accept (over-provisioned, not an error) |

### Decision details

1. **Define approval-requiring tools list**: In `production_config_validator.py`, define a constant `APPROVAL_REQUIRING_TOOLS` containing tools that require post-execution approval (shell execution, deletion, push, etc.). This list should match the operation categories marked "Required" in `agent_03_03_turn-processing-flow-workflow-engine.md`.
2. **Add ProductionConfigValidator rule**: In `ProductionConfigValidator.validate()`, check that any workflow whose tools intersect with `APPROVAL_REQUIRING_TOOLS` has `require_approval: true`. If not, record an error.
3. **Change `default.json` to `require_approval: true`**: Update the bundled default workflow to comply with the policy.
4. **Update documentation**: Update approval-policy descriptions in agent documents and security_01 to match the enforcement mechanism; remove AGENT-001 from the Known Issues ledger.
