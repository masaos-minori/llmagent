## Problem
- Scope says `Target processes: the Agent process and the ingester process` (Explicit in ADR-010 line 79), but the Agent REPL does not call `RagPipeline` directly (Confirmed by repository evidence — `docs/21_rag/rag_03_01*.md` "Caller" note) and the only construction site is `scripts/mcp_servers/rag_pipeline/rag_pipeline_service.py` line 109, which passes `rag_service_url=""` (Confirmed by repository evidence — `scripts/mcp_servers/rag_pipeline/rag_pipeline_models.py` line 130). The ingester does not call `augment()` (Confirmed by repository evidence — the only `.augment(` call sites are in `rag_pipeline_service.py`).
- Decision item 12 and INV-10 omit `auth_error` and `HttpResultKind.AUTH_ERROR`, although `HttpAugment` maps `auth_error` (Confirmed by repository evidence — `scripts/rag/http_augment.py`, `scripts/rag/models_result.py`).
- Negative Consequences says "Corpus synchronization costs arise", which contradicts Alternative C ("Use different corpora") having been rejected to avoid that cost (Explicit in ADR-010 lines 160-182 and 196).
- The Scope `Target components` line names `AugmentStage` but not `AugmentRefiner`, which carries the HTTP stage (`scripts/rag/augment.py`).

## Reason for change
- The ADR misstates which processes the fallback applies to, which misleads impact analysis, and the vocabulary invariant is incomplete after the ragauth01 change introduced the `auth_error` outcome.

## Implementation intent
- Edit only ADR-010, in English, with evidence labels for code claims and no line numbers or implementation counts.
- Use the memo2.md wording where it still matches the repository, adjusted to keep `AugmentStage` (it exists at `scripts/rag/stages/augment.py`) alongside `AugmentRefiner`.
