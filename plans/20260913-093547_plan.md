# Plan: Agent Output Format Consolidation

## Goal
- Consolidate the three disparate output APIs (`Writer` Protocol, `OutputPort` Protocol, and direct `print()`/`sys.stdout.write()` calls) into a single unified output system, standardize table display, error expression, and stderr routing.

## Priority
High

## Scope
- **In-Scope**:
  - Merge `Writer` Protocol (cli_view.py) and `OutputPort` Protocol (output_port.py) into one unified Protocol
  - Replace `sys.stdout.write()` in export_formatter.py with the unified Protocol
  - Unify table display: replace `_format_mcp_table()` and custom formatting in cmd_config_display.py with `write_table()`
  - Unify error expression: ensure all error messages use `write_error()` consistently
  - Route stderr output through a dedicated channel (stderr-aware writer method)
- **Out-of-Scope**:
  - Adding new output tags beyond what OutputTag currently provides
  - Changing the REPL input layer or readline behavior
  - Modifying workflow/validate.py's independent deployment CLI behavior
  - Adding rich/console/ANSI support (plain text only constraint remains)

## Background
The agent's terminal output layer was built incrementally without a unified design. Four entry points exist: direct `print()` calls (15 locations in cli_view.py), `sys.stdout.write()` (export_formatter.py), Protocol-based output via `CliOutputPort` (8 command files), and standalone `print()` in workflow/validate.py. This fragmentation causes format inconsistencies, makes it difficult to add features like structured logging or file output, and complicates testing.

## Problem
Three output APIs coexist (`Writer`, `OutputPort`, and raw `print()`/`sys.stdout.write()`). Table formatting uses different approaches in different modules. Error messages bypass `write_error()` in some places. stderr routing is inconsistent.

## Reason for change
Without consolidation, adding any new output feature (e.g., structured logging, file output, test doubles) requires modifying multiple incompatible systems. The current state prevents consistent formatting and makes the output layer fragile.

## Implementation intent
Create a single `OutputPort` Protocol that subsumes the responsibilities of both `Writer` and `OutputPort`. Rename `CliOutputPort` to be the sole concrete implementation. Replace direct `print()` calls in cli_view.py with Protocol method invocations. Replace `sys.stdout.write()` in export_formatter.py with the same Protocol. Unify table and error formatting through the Protocol. Add a `write_stderr()` method for proper stderr routing.

## Requirements
- `REQ-001`: All output must go through a single `OutputPort` Protocol with methods covering streaming tokens, progress, warnings, errors, tables, key-value pairs, and stderr
- `REQ-002`: `CliOutputPort` implements the Protocol by writing to stdout/stderr via `print()` and `sys.stderr.write()` respectively
- `REQ-003`: `export_formatter.py` uses the `OutputPort` Protocol instead of `sys.stdout.write()`
- `REQ-004`: `cmd_mcp.py` uses `write_table()` instead of `_format_mcp_table()` and `_format_tool_diagnostics_table()`
- `REQ-005`: `cmd_config_display.py` uses `write_kv()` instead of manual key-value formatting
- `REQ-006`: All error messages use `write_error()` consistently; no raw `write()` for errors
- `REQ-007`: `workflow/validate.py` routes error output to stderr via `write_stderr()`
- `REQ-008`: Existing tests pass after the refactor
- `REQ-009`: No regression in output format for existing users (visual output must remain identical)

## Design
### Architecture decision: Merge into OutputPort, deprecate Writer
The `OutputPort` Protocol (output_port.py) is chosen as the canonical interface because:
1. It already covers slash commands (the most diverse output domain)
2. Its method names are more consistent (`write`, `write_error`, `write_success`, `write_table`, `write_kv`)
3. `Writer` Protocol's methods are streaming-specific (token-by-token), which is a narrower concern
4. The merge strategy: add `Writer`'s streaming methods (`write_token`, `write_turn_start/end`, `write_progress`, `clear_progress`) to `OutputPort`, then have `CLIView` delegate to an `OutputPort` instance instead of implementing `Writer` directly

### Streaming vs. structured output separation
Streaming methods (`write_token`, `write_progress`, `clear_progress`) and structured methods (`write_table`, `write_kv`, `write_error`) share the same Protocol but may have different flush behaviors. This is acceptable — the Protocol defines the contract, not the implementation detail.

### stderr handling
Add `write_stderr(text: str) -> None` to the Protocol. Default implementation writes to `sys.stderr`. This replaces ad-hoc `print(..., file=sys.stderr)` in validate.py. Note: only FATAL errors currently go to stderr in validate.py; OK messages go to stdout. The scope is limited to error output, not all output.

### Test double strategy
After the merge, `tests/test_output_port.py` will include mocks for the merged Protocol. `tests/test_cli_view.py` will mock `OutputPort` instead of `Writer`. `WriterBase` must be preserved as a base class for test doubles (`PartialWriter`, `FullWriter`) — it cannot be removed even if redundant for production code.
