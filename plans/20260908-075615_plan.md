# Plan: Reject Workflow/EventBus recovery targets before running integrity check or VACUUM

## Goal
Move the workflow/eventbus domain-policy rejection (`action="no_recovery_allowed"`) to the top of `recover_corruption()` before `_run_integrity_check()` is called, preventing unintended VACUUM operations on protected domains when they are healthy.

## Priority
High

## Scope
- **In-Scope**: Reordering the control flow in `recover_corruption()` so that workflow/eventbus rejection occurs before any database access; adding regression tests for the HEALTHY-path case.
- **Out-of-Scope**: Changing the domain recovery policy itself (workflow/eventbus remain prohibited from automatic recovery); changing the `unsupported_target` handling; adding new `action` values; modifying documentation under `docs/*.md`; implementing operator-runbook changes (already done per `issues/done/20260903-110306_h0708_fix-workflow-eventbus-manual-recovery-runbook-to-use-backups.md`).

## Background
ADR-008/ADR-011 established that automatic recovery is prohibited for `workflow`/`eventbus` databases. The current implementation only enforces this prohibition in the `CORRUPTION` branch of `recover_corruption()`, after `_run_integrity_check()` has already been called. When a `workflow`/`eventbus` database is `HEALTHY`, the function proceeds to call `_vacuum_db(target)` without any domain-policy check.

## Problem
A scheduler or operator calling `recover_corruption()` uniformly across all four targets will silently run `VACUUM` against `workflow`/`eventbus` whenever they happen to be healthy. The domain-policy boundary enforced for the corruption path is absent for the healthy path.

## Reason for change
The `workflow`/`eventbus` domain-policy check at line 331 of `scripts/db/recovery.py` is control-flow-unreachable for any target whose database is not in `CORRUPTION` or `UNKNOWN` state — the `HEALTHY` branch (lines 296-299) and the `LOCK_CONTENTION`/`PERMISSION_FAILURE`/`INVALID_FORMAT` branch (lines 301-311) both return early before reaching it. This means a healthy `workflow.sqlite`/`eventbus.sqlite` passed to `recover_corruption(target="workflow")` will have `VACUUM` executed against it without any structured rejection.

## Implementation intent
Move the `target in ("workflow", "eventbus")` domain-policy check to immediately after the existing `unsupported_target` check (which is correctly placed before any database access), matching the pattern used by `test_recover_unsupported_target`'s `mock_integrity.assert_not_called()` assertion. Confirm `dry_run` mode also rejects workflow/eventbus before any database access.

## Requirements
- `REQ-001`: `recover_corruption(target="workflow")` returns `action="no_recovery_allowed"` without calling `_run_integrity_check()`, for both healthy and corrupt underlying databases.
- `REQ-002`: `recover_corruption(target="eventbus")` returns `action="no_recovery_allowed"` without calling `_run_integrity_check()`, for both healthy and corrupt underlying databases.
- `REQ-003`: `_vacuum_db()` is never called for `target="workflow"`/`"eventbus"`, regardless of the underlying database's actual state.
- `REQ-004`: New regression tests cover the HEALTHY-underlying-database case for both workflow and eventbus, asserting `_run_integrity_check`/`_vacuum_db` are not called.
- `REQ-005`: Existing tests `test_recover_corrupt_workflow_prohibited`, `test_recover_workflow_uses_correct_db_path`, `test_recover_eventbus_uses_correct_db_path` continue to pass unchanged (or are updated only to reflect the new assert-not-called expectation).
- `REQ-006`: `dry_run` mode also rejects workflow/eventbus before any database access.

## Design
The fix is a minimal control-flow reordering within `recover_corruption()`. The existing `unsupported_target` check (lines ~285-292) already correctly precedes `_run_integrity_check()` (line 295). The workflow/eventbus domain-policy check (currently lines 330-338) must be moved to immediately after the `unsupported_target` check, before the `_run_integrity_check()` call. This ensures that workflow/eventbus databases are rejected before any database access occurs, matching ADR-008/ADR-011's intent.

No new `action` values are introduced. The existing `action="no_recovery_allowed"` value and its detail message are preserved exactly. The change is symmetric between workflow and eventbus — both are treated identically.
