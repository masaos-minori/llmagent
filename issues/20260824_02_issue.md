# [High][tools] `rename_modules.py` hardcodes a nonexistent absolute path and silently no-ops

## Priority
High

## Summary
`tools/rename_modules.py` resolves its repository root from a hardcoded absolute path
(`/home/sugimoto/llmagent`) that does not exist in the current environment
(`/home/masaos/llmagent`). Because the failure is swallowed, the script reports success while
processing zero files.

## Reason for Change
- **Evidence** (Explicit in code, `tools/rename_modules.py:8`): `BASE =
  pathlib.Path("/home/sugimoto/llmagent")` is a hardcoded, user-specific absolute path rather
  than one derived from the script's own location or the current working directory.
- **Evidence** (Operationally observed): `/home/sugimoto/llmagent` does not exist on this
  machine; the actual repository root is `/home/masaos/llmagent`.
- **Evidence** (Explicit in code, `main()` loop): each target directory is checked with `if not
  d.exists(): continue`, so a missing `BASE` means every directory lookup silently continues
  past, and the script finishes with a "Done. Updated 0/0 files." style success message rather
  than an error.
- Impact: a user who runs this script to rename an `mcp_servers/<server>/` module gets no
  indication that nothing happened. The script looks like it succeeded (exit 0, "Done"
  message) while performing zero renames, imports updates, or patch-target updates. This is a
  silent-failure trap for exactly the kind of multi-file mechanical rename this script exists
  to make safe.

## Implementation Intent
- Derive the repository root from the script's own location (e.g. `Path(__file__).resolve()
  .parent.parent`) instead of a hardcoded, environment-specific absolute path, consistent with
  how other scripts in `tools/` compute `ROOT_DIR`/`REPO_ROOT` (see `tools/check_no_compat.py`,
  `tools/gen_reference_table.py`).
- Where the resolved `BASE` (or any directory the script depends on) does not exist, fail loudly
  — non-zero exit and a clear error message — instead of silently skipping and reporting
  success.

## Target Files or Areas
- `tools/rename_modules.py` (module-level `BASE`, `main()`)

## Required Changes
- Replace the hardcoded `BASE = pathlib.Path("/home/sugimoto/llmagent")` with a
  repository-relative resolution.
- Add an explicit existence check on `BASE` (and/or the specific target directory being
  renamed) at the start of `main()` that exits non-zero with a clear error if the path is
  missing, rather than relying on the existing `continue`-based skip inside the loop to mask
  the condition.
- While in this area, resolve the separately-reported dead-code duplication between
  `process_file()` and `main()` (the former lacks the `update_patch_targets()` call the latter
  performs) — either remove the unused `process_file()` or route `main()` through it so there
  is a single source of truth for the per-file update sequence. (Track as part of this issue
  only if trivial; otherwise split into a follow-up.)

## Acceptance Criteria
- [ ] Running the script from a freshly cloned copy of this repository (any path) resolves
      `BASE` correctly without editing the script.
- [ ] If the resolved base or target server directory does not exist, the script exits non-zero
      with an explicit error message naming the missing path.
- [ ] A successful rename run's "Updated N/M files" count reflects actual files scanned, not a
      silently-empty set.

  clear error when the target directory is absent.
- Run `uv run pytest tests/tools/` after the fix.
