# `tools/check_no_compat.py`'s `main()` crashes with `IsADirectoryError` when given a directory as a positional file argument

## Priority
Low

## Summary
`tools/check_no_compat.py`'s `main()` accepts a list of positional file arguments
(`args.files`). When any argument is not empty, the code reads each entry directly via
`Path(f).read_text()` without checking whether `f` is a file or a directory. Passing a
directory (e.g. `scripts/`, `tools/`) as a positional argument raises `IsADirectoryError`
and crashes with exit code 1, instead of either scanning the directory's files or reporting
a clear usage error.

## Evidence
- Confirmed by direct execution: `uv run python -m tools.check_no_compat tools/` and
  `uv run python -m tools.check_no_compat scripts/` both crash with `IsADirectoryError`.
- The default no-args scan path (`args.files` empty -> `dirs_to_scan` glob logic) does not
  hit this code path, so the `no-compat-stubs` pre-commit hook (invoked with
  `pass_filenames: false`) is unaffected by this bug.
- Discovered incidentally while investigating `requires/20260807-095914_require.md` /
  `plans/20260807-100914_plan.md` (the `ROOT_DIR` depth-fix requirement), and explicitly
  deferred as a separate concern to avoid scope creep in that fix, per that plan's Risks
  section.

## Reason for Change
The tool's `--help`/usage does not document that positional arguments must be files, not
directories, and there is no guard against directory input. A user manually invoking the
tool with a directory (a natural thing to try) gets a raw traceback instead of a clear
error or correct behavior.

## Target Files or Areas
- `tools/check_no_compat.py` (`main()`'s positional-file-argument handling)

## Required Changes
- Either: expand any directory argument into its contained files (consistent with the
  default `dirs_to_scan` glob behavior), or: detect a directory argument and exit with a
  clear error message instead of an unhandled exception.
- Decide and document which behavior is intended; add a test covering it.

## Acceptance Criteria
- `uv run python -m tools.check_no_compat <directory>` no longer raises an unhandled
  `IsADirectoryError`.
- A test exists covering the chosen behavior (directory expansion or explicit error).

## Testing Expectations

  positional argument.
- Run `uv run pytest tests/tools/test_check_no_compat.py -v`.

## Out of Scope
- Any change to `ROOT_DIR`, `COMPAT_PATTERNS`, or `DEFAULT_ALLOWLIST` — those are addressed
  separately in `plans/20260807-100914_plan.md`.
