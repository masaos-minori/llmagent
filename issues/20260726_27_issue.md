## エージェント起動フェーズ: 承認フローの競合状態

### Summary

`startup.py:506-534` と `tool_approval.py:115-123` で、`asyncio.to_thread(input, ...)` は同期的な `input()` を別スレッドで実行する。REPLのメインスレッドと並行して実行されるため、タイミングの問題が発生する可能性がある。

### Problem

`tool_approval.py:115-123` で定義：

```python
async def _prompt_user_approval(risk: RiskLevel) -> bool:
    if risk == RiskLevel.HIGH:
        answer = (
            (await asyncio.to_thread(input, "  Execute? [yes/no]: ")).strip().lower()
        )
        return answer == "yes"
    answer = (await asyncio.to_thread(input, "  Execute? [y/N]: ")).strip().lower()
    return answer == "y"
```

`asyncio.to_thread(input(), ...)` は同期的な `input()` を別スレッドで実行する。REPLのメインスレッドと並行して実行されるため、タイミングの問題が発生する可能性がある。

### Affected Files

- `scripts/agent/startup.py:506-534` — 承認フローの実装
- `scripts/agent/tool_approval.py:115-123` — ユーザー入力のプロンプト

### Attack Scenario

1. 承認が必要なツール呼び出しが発生する
2. ユーザーが入力を求めるプロンプトが表示される
3. タイミングの問題により、ユーザーの入力が正しく処理されない
4. 承認が誤って処理される

### Severity

Low — REPLは単一スレッドのイベントループを使用しており、実際の競合は発生しにくい。

### Mitigation

- 承認フローの同期メカニズムを強化する
- タイミングの問題を防ぐためのロックメカニズムを導入する
- 承認フローのテストを追加する
