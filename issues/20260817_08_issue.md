Title: [REFACTOR] Startup banner tool count should come from RuntimeToolRegistry
Labels: priority/low, type/refactor, area/agent

## Summary
`AgentREPL._n_tools` returns the length of the static `tool_definitions` list, which can diverge from the runtime-executable tool set.

## Rationale
- The runtime authority for tools is `RuntimeToolRegistry`, populated from live `/v1/tools` discovery. The static `tool_definitions` list is a compatibility artifact. When discovery excludes a tool (e.g. a schema-2.0 contract failure), the banner still counts it, so the number shown to the operator can overstate what is actually callable.
- Design docs imply the banner reflects the live tool list, which compounds the mismatch.

## Intent
Show the operator the number of tools that are actually available at runtime, and make the doc match that behavior.

## Tasks
- [ ] Source `_n_tools` from `RuntimeToolRegistry` instead of `tool_definitions`.
- [ ] Reconcile the banner description in the design doc with the corrected behavior.

## Acceptance criteria
- The banner count equals the number of tools available at runtime.
- Doc and behavior agree.
