# [High][tools] `manage_frontmatter.py add-missing` writes to `docs/*.md` with no dry-run safety net

## Priority
High

## Summary
`tools/manage_frontmatter.py add-missing` writes to `docs/*.md` by default (no flag required),
and its `--dry-run` option is unreachable because of an argument-passing bug in `main()`. There
is currently no safe way to preview what this subcommand would do before it mutates files.

## Reason for Change
- **Evidence** (Operationally observed): running `uv run python tools/manage_frontmatter.py
  add-missing` with no flags on this repository wrote Front Matter into 49 files under `docs/`
  immediately, with no confirmation prompt and no prior dry-run step performed.
- **Evidence** (Explicit in code, `tools/manage_frontmatter.py:178-207` `cmd_add_missing`): the
  write path (`md_file.write_text(...)`) executes whenever `args.dry_run` is falsy — which is
  the default state when no flag is passed at all, not only when `--fix` is passed. The `--fix`
  flag is declared (`tools/manage_frontmatter.py:163`, `:324`) but never read anywhere in the
  function body.
- **Evidence** (Explicit in code, `tools/manage_frontmatter.py:333-336`): `main()` re-encodes
  `add-missing`'s own parsed flags back into CLI-style strings via
  `f"--{k}"` where `k` comes from `vars(args)` (e.g. `dry_run`, using an underscore, because
  that's argparse's `dest` naming). It then calls `cmd_add_missing(["--dry_run"])`, but
  `cmd_add_missing`'s own `argparse.ArgumentParser` only recognizes the hyphenated form
  `--dry-run`. Reproduced directly: `uv run python tools/manage_frontmatter.py add-missing
  --dry-run` exits with code 2 and `error: unrecognized arguments: --dry_run`.
- Net effect: there is no working preview mode, and the unsafe write path is the one that
  actually runs when a user invokes the subcommand with no flags (the most natural first
  invocation). This is a destructive-by-default CLI for a script that runs against the entire
  `docs/` tree.

## Implementation Intent
- Flip the default to non-destructive: `add-missing` should not write to any file unless the
  caller explicitly opts in (e.g. keep `--fix` as the write-enabling flag, and make its absence
  mean dry-run/report-only).
- Fix the `main()` → `cmd_add_missing()` argument hand-off so `--dry-run` (or whatever the
  chosen opt-in flag is) actually reaches the subcommand parser without a name-mangling bug.
  Prefer removing the round-trip re-encoding entirely (e.g. pass `argv` through directly, or
  have `cmd_add_missing` accept the already-parsed `Namespace`) rather than patching the string
  conversion.
- Keep the rest of the subcommand's file-discovery and Front-Matter-generation logic
  unchanged — this is a safety/argument-wiring fix, not a rewrite of `add-missing`'s content
  logic.

## Target Files or Areas
- `tools/manage_frontmatter.py` (`cmd_add_missing`, `main`)

## Required Changes
- Make no-flag invocation of `add-missing` report-only (no writes), matching the apparent
  original intent of the `--dry-run` flag.
- Require an explicit opt-in flag (e.g. `--fix`) to perform actual writes.
- Fix the `main()` argument round-trip so `cmd_add_missing` correctly receives whichever flags
  the user passed at the top level, without a hyphen/underscore mismatch.
- Re-verify the `dedupe-lists` subcommand's own write behavior for the same class of bug (it
  currently always writes with no flag gating at all — confirm whether that is intentional
  before deciding whether it's in scope here or a separate issue).

## Acceptance Criteria
- [ ] `python tools/manage_frontmatter.py add-missing` with no flags does not modify any file
      under `docs/`.
- [ ] `python tools/manage_frontmatter.py add-missing --dry-run` runs to completion (exit 0)
      and prints a preview without modifying files.
- [ ] `python tools/manage_frontmatter.py add-missing --fix` (or the chosen opt-in flag) is the
      only invocation that writes to files, and does so correctly for files missing Front
      Matter.
- [ ] A regression test exercises both the no-flag/dry-run path (asserts zero file mutation)
      and the explicit write-opt-in path (asserts expected mutation), using temp files rather
      than the real `docs/` tree.

## Testing Expectations
- Add unit tests under `tests/tools/` for `cmd_add_missing` covering: no-flag call performs no
  writes, `--dry-run` performs no writes and exits 0, and the write-opt-in flag performs the
  expected write. Use a temporary directory fixture, not the live `docs/` directory.
- Run `uv run pytest tests/tools/` after the fix.

## Documentation Impact
- None required beyond the script's own `Usage` docstring, which should be updated to state
  that no-flag invocation is safe/non-destructive and name the flag required to write.

## Out of Scope
- Changes to `cmd_dedupe_lists` behavior (flag separately if it needs the same treatment).
- Changes to Front-Matter content-generation logic (`build_frontmatter`,
  `extract_category_from_filename`, etc.).
- Any other `tools/*.py` script.

## AI Implementation Instruction
Keep the change minimal and scoped to argument handling and the write/no-write branch in
`cmd_add_missing` and `main`. Do not rewrite the Front-Matter generation logic. Do not touch
`dedupe-lists` unless explicitly asked. Add tests using temp directories only — never run the
fixed script against the live `docs/` tree as a way of "testing" it. If the intended default
behavior (dry-run vs. fix) is ambiguous, stop and ask rather than guessing.
