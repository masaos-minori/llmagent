# Define one owner for the published_at timestamp

## Priority
Medium

## Summary
Decide whether `published_at` is supplied by the publisher or generated by the server, and make the repository code, schema, tests and documentation state the same model, including how the value is validated.

## Background
Source: `memo-issue.md` item 06 (`published_at` part), re-verified against current source on 2026-10-28.

- `insert_event()` in `scripts/eventbus/event_repo.py` documents `published_at` as "excluded from canonical equality (server-generated)". `Explicit in code`.
- `publish()` in `scripts/eventbus/publish_route.py` reads `published_at` from the request body and stores it unchanged; `schemas/event_envelope.json` lists it as required with `format: date-time`. `Explicit in code`.
- `docs/24_eventbus/eventbus_06_persistence_schema_and_replay.md` says `published_at` is excluded from canonical equality "because it is supplied by the client and may differ between retries", which contradicts the repository docstring. `Explicit in docs`.
- The `events` table also declares `DEFAULT (strftime(...))` for the column, a server-side default that no insert uses. `Explicit in code`.
- No `format_checker` is passed to `jsonschema.validate` anywhere under `scripts/eventbus`, so the `date-time` format is not enforced and any string is accepted. `Confirmed by repository evidence` (search found none).
- Duplicate handling: a retry of the same `event_id` with a different `published_at` is treated as a duplicate (not a conflict) because the field is excluded from equality. `Explicit in code`.
- `tests/eventbus/test_eventbus_publish_contract.py` asserts that a missing `published_at` is rejected and uses fixed timestamps.

## Problem
The code comment, the schema and the documentation disagree on the owner of `published_at`, and the value's format, timezone and clock-skew rules are undefined although consumers and replay sort or display it.

## Reason for Change
The mismatch can mislead a publisher or consumer author about whether the timestamp is trustworthy and whether it can change on retry. No incident is cited; severity is Medium (ambiguous public contract), not High. Nothing makes the change time-sensitive.

## Implementation Intent
Choose one model and apply it everywhere. If the publisher owns the value, correct the repository docstring, enforce the format, and define timezone, skew and future-time rules plus the retry behavior. If the server owns it, stop requiring it in the envelope, set it at insert time, and update persistence, JSONL, replay and the docs. Keep the choice minimal and backward-compatible where possible.

## Target Files or Areas
- `scripts/eventbus/event_repo.py`
- `scripts/eventbus/publish_route.py`
- `schemas/event_envelope.json`

- `scripts/eventbus/schema.sql` (the column default), only if the server-owned model is chosen

## Required Changes
- Record the decision and make `event_repo.py`, the schema, the route and the docs agree.
- Publisher-owned: correct the docstring; validate `date-time` (enable the format checker or an explicit parse); define timezone (UTC), maximum skew and future-time handling; define whether a retry with a different value is a duplicate or a conflict.
- Server-owned: remove the field from the required envelope (or accept and ignore it with a documented deprecation), set it at insert time, and update JSONL, broker notification, replay and DLQ output.
- Update tests for the chosen model.

## Constraints
- Do not change `event_id` idempotency or canonical equality beyond what the chosen model requires.
- Existing publishers must keep working unless the owner approves a breaking envelope change.
- A schema DDL change needs the schema version rules (`tools/check_db_separation.py` and the recreate policy) considered.

## Acceptance Criteria
- Code, schema, tests and docs name the same owner and semantics for `published_at`.
- Malformed values are rejected (publisher-owned) or ignored (server-owned) deterministically.
- Retry behavior with a different `published_at` is documented and tested.

## Testing Expectations
