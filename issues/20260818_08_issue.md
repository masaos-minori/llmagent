# [MEDIUM] Standardize evidence, uncertainty tracking, and area Known Issues

## Priority

Medium

## Background

Evidence Labels are defined, but their application level and format are inconsistent.

Uncertainty markers remain in area documents without corresponding central inventory entries.

Agent, MCP, RAG, EventBus, and Shared/DB Known Issues documents also use different formats.

## Reason for Change

Unclear evidence scope can cause a reader to assume that an entire section is verified when only one statement has been checked.

Unregistered uncertainty can remain indefinitely without an owner or resolution target.

Inconsistent Known Issues formats prevent reliable comparison, filtering, ownership tracking, and automated validation.

## Intent

Create one complete workflow covering:

1. Evidence assignment
2. Uncertainty detection
3. Needs Confirmation registration
4. Known Issue registration
5. Resolution or archival

Use one structured format across all areas.

## Tasks

### Evidence Labels

1. Define individual verifiable claims as the default evidence-label unit.
2. Define justified exceptions.
3. Create a standard evidence block containing:

   - Evidence label
   - Source module or document
   - Symbol or section
   - Test identifier
   - Verification date
   - Notes

4. Prefer symbol, configuration-key, and test references over line numbers.
5. Provide examples for every evidence-label type.

### Needs Confirmation

6. Scan for:

   - `Needs Confirmation`
   - `要確認`
   - `未確認`
   - Equivalent uncertainty markers

7. Generate a complete extraction report.
8. Group duplicate root causes.
9. Distinguish active and resolved findings.
10. Register every active uncertainty in the central inventory.
11. Link each source statement to its inventory entry.

### Known Issues Migration

12. Migrate the following areas to the common template:

    - Agent
    - MCP
    - RAG
    - EventBus
    - Shared/DB

13. Preserve existing IDs and issue substance.
14. Add missing status, severity, type, owner, source, target, evidence, impact, and resolution criteria.
15. Convert EventBus table entries into individual issue entries.
16. Distinguish confirmed design decisions from active defects.
17. Add migration notes.

## Acceptance Criteria

- [ ] Evidence-label granularity is defined.
- [ ] Individual claims are the default evidence unit.
- [ ] A standard evidence block is documented.
- [ ] Stable symbol and test references are preferred.
- [ ] Every uncertainty marker appears in the extraction report.
- [ ] Every active uncertainty has a central inventory ID.
- [ ] Source documents link to inventory entries.
- [ ] All area Known Issues use the common template.
- [ ] Existing IDs are preserved.
- [ ] Issue substance and history are preserved.
- [ ] Confirmed design decisions are not classified as defects.
- [ ] EventBus issues are represented as individual entries.
- [ ] Required metadata is complete.
- [ ] Template and inventory validation pass.

## Validation

1. Verify one code-backed and one test-backed evidence block.
2. Run uncertainty extraction twice and compare results.
3. Verify bidirectional links between sources and inventory entries.
4. Count Known Issues before and after migration.
5. Verify every original ID remains present.
6. Validate all migrated entries.

## Out of Scope

- Resolving open uncertainties
- Resolving Known Issues
- Bulk-labeling every existing sentence
