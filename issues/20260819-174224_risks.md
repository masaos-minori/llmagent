# [Risk] git/github/cicd/db-maintenance tool docs excluded from high-risk-tool policy cross-reference

## Priority
Medium

## Background

`plans/20260819-174040_plan.md` (source requirement:
`requires/done/20260818-221156_require.md`, source issue: `issues/20260818_06_issue.md`)
creates two new cross-cutting documents:

- `docs/00_security_01_architecture-and-trust-boundaries.md`
- `docs/00_security_02_high-risk-tool-common-policy.md`

`docs/00_security_02_high-risk-tool-common-policy.md` explicitly states it governs
file-write, file-delete, shell, git, github, cicd, and DB-maintenance-class MCP tools.
However, the source requirement's `Target files` list only names 19 existing docs to
receive a cross-reference back to the new consolidated docs, and that list omits:

- `docs/04_mcp_04_05_git.md`
- `docs/04_mcp_04_01_web-search-file-read-github.md`
- `docs/04_mcp_04_03_rag-pipeline-and-cicd.md`

## Problem

Without a cross-reference from these three tool-specific docs, an engineer or
implementation AI reading `04_mcp_04_05_git.md`, `04_mcp_04_01_...`, or
`04_mcp_04_03_rag-pipeline-and-cicd.md` in isolation will not be routed to the new
common policy document, even though the common policy document names git/github/cicd
as tools it governs. This is the same fragmentation problem the requirement set out to
fix, left unresolved for these three files.

## Reason for change

The acceptance criterion "Existing docs ... each reference the new consolidated
document(s) as canonical" is only fully satisfied for the 19 files explicitly listed in
the source requirement; git/github/cicd tool docs remain one hop further from the new
canonical source than file-write/file-delete/shell/mdq.

## Implementation intent

A narrow follow-on requirement/plan cycle should add the same short "See also:
`00_security_02_high-risk-tool-common-policy.md`" cross-reference bullet to:
- `docs/04_mcp_04_05_git.md`
- `docs/04_mcp_04_01_web-search-file-read-github.md`
- `docs/04_mcp_04_03_rag-pipeline-and-cicd.md`

No other change is needed — this is purely closing the same cross-reference gap for
three additional files using the pattern already established by
`plans/20260819-174040_plan.md`.
