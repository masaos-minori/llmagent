# Refactor ingester.py — separation of concerns (3/3)

## Priority
Medium

## Summary
Split `scripts/rag/ingestion/ingester.py` (890 lines) into focused modules to reduce cyclomatic complexity, improve testability, and clarify responsibility boundaries between URL ingestion orchestration, embedding, document persistence, file routing, and chunk grouping.

## Background
RagIngester reads `rag-src/chunk/*.json` files generated by ChunkSplitter, generates embeddings via an external service, inserts them into SQLite (documents / chunks / chunks_vec tables), and routes processed files to `rag-src/registered/`. It was designed as a single monolithic class delegating to DocumentManager for document-level operations, but accumulated many responsibilities through incremental additions: group validation, error metadata writing, batch insertion, cache invalidation, and partial failure handling.

## Reason for Change
RagIngester has grown beyond the 400-line threshold defined in `skills/DESIGN.md` File Split Rule trigger condition. Its cyclomatic complexity is high due to nested conditionals in `ingest_url_group` (130+ lines), `_prepare_chunks` (ThreadPoolExecutor + type discrimination), and `_route_chunk_files` (failure-reason-based branching). This makes the class difficult to test in isolation, modify without unintended side effects, and understand for new contributors.

## Problem
The RagIngester class violates the Single Responsibility Principle by combining at least eight distinct concerns into one class:

1. **Configuration/lifecycle** — `__init__`, `close`, `__del__` — config loading, HTTP client lifecycle
2. **Orchestration** — `ingest_all`, `ingest_url_group` — pipeline coordination (60+ lines and 130+ lines respectively)
3. **Embedding** — `_get_embedding` — external embedding service call with retry
4. **Document persistence** — `_get_or_create_document`, `_insert_document`, `_insert_chunk`, `_insert_chunks_batch`, `_validate_lang` — document CRUD operations
5. **Parallel chunk preparation** — `_read_chunk_json`, `_embed_and_store`, `_prepare_chunks` — ThreadPoolExecutor-based parallel embedding
6. **Atomic transaction commit** — `_commit_url_transaction` — BEGIN IMMEDIATE transaction orchestration
7. **Chunk grouping** — `_group_chunks_by_url` — grouping chunks by URL from JSON payloads
8. **File routing** — `_move_to_registered`, `_route_chunk_files`, `_write_error_metadata` — file movement and error metadata

This makes the class hard to understand, test in isolation, and modify without unintended side effects. Specifically:

- `ingest_url_group` alone is 130+ lines with 5+ conditional branches (empty check, format validation, field comparison, chunk index validation, skip detection, prepared/failure split)
- `_prepare_chunks` has nested exception handling across httpx errors, OSError, ValueError, TypeError plus type discrimination on results
- `_route_chunk_files` mixes file movement logic with error metadata writing and retry/failed directory selection based on failure reason strings
- `_commit_url_transaction` handles both document creation/replacement AND chunk insertion in one method
- Cache invalidation logic is embedded in `ingest_all` alongside consistency reporting
- The class has grown beyond the 400-line threshold defined in `skills/DESIGN.md` File Split Rule trigger condition

## Implementation Intent
Extract each concern into its own class/module while preserving RagIngester as a thin facade that composes these components:

1. **IngestOrchestrator** — Pipeline orchestration. Owns `ingest_all`, `ingest_url_group`. Coordinates chunk grouping, embedding, document persistence, and file routing. Returns IngestUrlResult per URL.
2. **EmbeddingService** — External embedding service interaction. Owns `_get_embedding`. Handles HTTP POST to embed URL, response parsing, retry with exponential backoff, empty input guard.
3. **DocumentPersister** — Document CRUD operations. Owns `_get_or_create_document`, `_insert_document`, `_insert_chunk`, `_insert_chunks_batch`, `_validate_lang`. Handles INSERT/DELETE for documents table, INSERT for chunks/chunks_vec tables, lang validation.
4. **ChunkPreparer** — Parallel chunk preparation. Owns `_read_chunk_json`, `_embed_and_store`, `_prepare_chunks`. Uses ThreadPoolExecutor to embed chunks in parallel, returns PreparedChunk or IngestionFailureReason per chunk.
5. **TransactionCommitter** — Atomic transaction commit. Owns `_commit_url_transaction`. Handles BEGIN IMMEDIATE transaction, document creation/replacement, chunk batch insertion, and committed-file routing.
6. **ChunkGroupingService** — Chunk file grouping. Owns `_group_chunks_by_url`. Groups chunk files by URL from JSON payloads, validates URL format.
7. **FileRouter** — File routing after ingestion. Owns `_move_to_registered`, `_route_chunk_files`, `_write_error_metadata`. Moves successful files to registered/, failed files to retry/ or failed/, writes .error.json metadata.
8. **CacheInvalidator** — RAG pipeline cache invalidation. Owns the cache invalidation POST request in `ingest_all`. Separate concern because it's a side effect independent of core ingestion logic.

RagIngester.__init__ wires these components via dependency injection. RagIngester.ingest_all() delegates to ChunkGroupingService for grouping, then iterates URL groups calling IngestOrchestrator.ingest_url_group(). After ingestion, delegates to CacheInvalidator for cache busting.

- Must preserve all existing public method signatures and return types (backward compatibility)
- Must not change any observable behavior (no behavioral regression)
- Must not break existing import paths (e.g., `from rag.ingestion.ingester import RagIngester`)
- Must not introduce circular dependencies between new modules
- The `IngestionFailureReason` enum values must remain identical (PARSE_FAILED, VALIDATION_FAILED, EMBEDDING_FAILED, STORAGE_FAILED, UNEXPECTED_FAILURE, GROUP_VALIDATION_FAILED)
- The `PreparedChunk` frozen dataclass fields must remain identical (doc_id, chunk_index, content, normalized_content, embedding_blob, chunk_type, source_file)
- The `IngestUrlResult` frozen dataclass fields must remain identical (url, n_success, n_failed, skipped, n_embed_failed, failure_reason)
- Embedding retry logic (exponential backoff capped at 10s) must be preserved identically
- File routing rules must be preserved: successful→registered/, embedding-failed→retry/, other-failed→failed/
