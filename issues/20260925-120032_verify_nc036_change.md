# Verify NC‑036 Change Impact

## Background

This issue records the steps needed to validate that the recent adjustment to `scripts/rag/pipeline_service.py::call_rag_service()` correctly removes the in‑process RAG fallback when a JSON parse error occurs.

## Scope of Impact

* **Modified file**: `scripts/rag/pipeline_service.py`
* **Related tests**: any unit or integration tests exercising `call_rag_service()` with a mocked HTTP client that returns invalid JSON.
* **Documentation**: ADR‑010 and the Needs Confirmation inventory entry NC‑036.

## Verification Steps

1. Create a minimal async test harness that mocks `httpx.AsyncClient.post` to return a response whose body cannot be parsed by `parse_http_json`. For example, return a plain string body.
2. Invoke `call_rag_service()` with this mock and capture:
   * logged warning message
   * whether `set_fallback_reason` callback was invoked
   * the returned tuple `(result, status_code, elapsed_ms)`.
3. Assert that `status_code` is `None` and `result` is an empty string; also assert that the callback was **not** called.
4. Run existing tests that previously expected a fallback on parse errors and adjust them accordingly.
5. Ensure no other part of the system depends on receiving a fallback reason for parse errors.

## Acceptance Criteria

* Running the test harness passes without raising exceptions.
* The callback `set_fallback_reason` is never invoked during a parse error scenario.
* The return value matches the contract for an empty result.
* No new runtime errors are introduced.
