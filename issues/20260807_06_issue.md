# Strengthen canonical RAG schema and remove obsolete dimension configuration

## Priority
High

## Suggested Labels
priority-high, rag, database, schema, configuration, cleanup

## Reason for Change
Essential chunk invariants are enforced only by application code, so malformed or duplicate chunks can still enter the canonical tables. Separately, configurable-dimension remnants remain in `RagConfigValidator` even though dimensions are fixed in code, absent from active configuration, and intentionally not runtime-validated.

## Implementation Intent
Put durable data invariants in the canonical DDL and remove legacy configuration paths without adding migration or runtime dimension checks.

## Affected Files
- `db/schema_sql.py`
- `db/create_schema.py`
- `shared/config_validator.py`
- configuration documentation, examples, MCP config, and fixtures
- schema and config-validation tests

## Implementation Scope
- [ ] Add `UNIQUE (doc_id, chunk_index)` to `chunks`.
- [ ] Add `CHECK (chunk_index >= 0)`.
- [ ] Add `CHECK (chunk_type IN ('text', 'code'))`.
- [ ] Add `CHECK (length(content) > 0)`.
- [ ] Remove the `embedding_dim` versus `vec_dim` comparison from `RagConfigValidator`.
- [ ] Remove `embedding_dims`, `embedding_dim`, and `vec_dim` from configuration references, examples, MCP configuration, and test fixtures where present.
- [ ] Do not add these fields to `RagConfig`, `SearchConfig`, or `IngesterConfig`.
- [ ] Keep schema creation based on `QWEN3_EMBEDDING_DIMS = 1024`.
- [ ] Update stale 384-dimension and E5-specific documentation where it describes the current schema or configuration.
- [ ] Recreate databases after the canonical schema change; do not create a legacy-dimension migration.

## Non-Goals
- Do not add runtime checks for 1024 elements, 4096-byte BLOBs, or live database dimensions.
- Do not support multiple embedding dimensions.
- Do not migrate legacy vector tables.

## Acceptance Criteria
- [ ] The database rejects duplicate document indices, negative indices, empty content, and unsupported chunk types.
- [ ] Valid Japanese, English, and code chunks remain insertable.
- [ ] No runtime configuration accepts or compares an embedding dimension.
- [ ] New RAG and session schemas still use 1024 dimensions from the code constant.
- [ ] No runtime dimension-validation feature is introduced.

## Required Tests
- [ ] valid and invalid schema inserts
- [ ] configuration validation without dimension keys
- [ ] fixtures containing removed keys
- [ ] schema recreation at 1024 dimensions

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
