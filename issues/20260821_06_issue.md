**Title:** [Medium][agent][diagnostics] Make encrypted session_diagnostics readable and classify diagnostics.* reload behavior

**Labels:** bug, enhancement, medium-priority, agent, diagnostics, config
**Covers:** M-6, M-8
**Area / Component:** `scripts/agent/diagnostic_store.py`, `scripts/agent/services/config_reload.py`

## Summary
Two diagnostics-subsystem gaps grouped together: encrypted diagnostics cannot be read back, and
`diagnostics.*` changes are silently not applied by `/reload`.

## Rationale (Why this matters — detailed)
- **Write-only encryption (M-6):** `DiagnosticStore.save(encrypt=True)` can encrypt diagnostics, but
  `fetch()` does not decrypt them, so encrypted diagnostic data can never be read back. Diagnostic
  data exists for post-mortem analysis, so a write-only encrypted path is either dead functionality
  or an operational trap that hides the very data operators need after an incident.
- **Silent startup-only config (M-8):** `cfg.diagnostics.*` (`encryption_key`, `retention_days`,
  `sensitive_fields`) are not applied by `/reload`, and this is not surfaced to the operator.
  Changing retention or sensitive-field policy therefore requires a full restart, with no indication
  that `/reload` had no effect — reducing operational flexibility and creating confusion.
- Both concern the diagnostics subsystem's configuration and read/write behavior, so they are natural
  companions in one change with a shared round-trip test.

## Fix Intent (How — detailed)
- **M-6:** Implement a decryption path in `fetch()` using the configured Fernet key, or provide a
  dedicated read/export tool and document it. Define and test the behavior when no key is configured.
  If encryption is not used operationally, reconsider whether the `encrypt=True` path should exist at
  all.
- **M-8:** Either make `diagnostics.*` hot-reloadable, or classify them explicitly as
  `[STARTUP-ONLY]` in the `/reload` output so operators clearly see that a restart is required.

## Sub-tasks
- [ ] (M-6) Decryption/read path for encrypted `session_diagnostics` (+ no-key behavior).
- [ ] (M-8) Hot-reload `diagnostics.*`, or report them as `[STARTUP-ONLY]` in `/reload`.

## Acceptance Criteria
- [ ] Encrypted diagnostics rows can be read back (round-trip test with a configured key).
- [ ] Behavior with no key configured is well-defined and tested.
- [ ] `diagnostics.*` are either applied on `/reload` or clearly reported as startup-only.
