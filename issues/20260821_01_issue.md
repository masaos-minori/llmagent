**Title:** [High][db] Fix recover_corruption() (restore reachability + wrong-DB overwrite) and add explicit workflow_db_path

**Labels:** bug, high-priority, db, data-loss, recovery, config
**Covers:** H-3, L-8
**Area / Component:** `scripts/db/recovery.py`, `scripts/db/config.py`, `config/agent.toml`

## Summary
The last-resort corruption recovery path has two confirmed defects, and the DB path configuration is
incomplete. These are fixed together because both center on resolving DB paths consistently from
`DbConfig` for all four databases.

## Rationale (Why this matters — detailed)
- **Restore never reached on real corruption (H-3, bug 1):** `_run_integrity_check` catches only
  `(sqlite3.OperationalError, ValueError, RuntimeError)`. A malformed/not-a-database file raises base
  `sqlite3.DatabaseError` (a sibling of `OperationalError`), which is not caught and propagates out
  of `recover_corruption`. The exception is raised inside `SQLiteHelper.open()` at
  `PRAGMA journal_mode=WAL` (page-1 read), before `integrity_check` even runs. Even if it were
  caught, the current flow returns `action="error"` when `check_result is None` and never calls
  `_restore_from_backup`. So the exact case that needs a restore (an unreadable/corrupt DB) does not
  restore — the function fails precisely when the DB is most damaged.
- **Wrong-DB overwrite = data destruction (H-3, bug 2):** `_run_integrity_check(db_path, target)`
  ignores its `db_path` argument and opens `SQLiteHelper(target)` (correct DB); `_vacuum_db(target)`
  also uses `target`. But `db_path = rag_db_path if target == "rag" else session_db_path`, and
  `_restore_from_backup(db_path, ...)` runs `shutil.copy2` on `db_path`. Therefore
  `target="workflow"`/`"eventbus"` checks the correct DB but **archives/overwrites `session.sqlite`**.
  `DbConfig` already exposes `workflow_db_path` and `eventbus_db_path`, so the two-way branch is an
  oversight, not missing information. No early rejection exists for unsupported targets, so a
  mistaken `target` silently destroys a healthy production DB.
- **Missing config key (L-8):** `agent.toml` sets `rag_db_path`, `session_db_path`, and
  `eventbus_db_path` but omits `workflow_db_path`, which falls back to the code default
  `/opt/llm/db/workflow.sqlite`. Making the workflow path explicit is the natural companion to H-3's
  four-target resolution and removes an implicit/inconsistent path.
- This function is the only documented "Database Corruption → Restore from backup" path, so its
  correctness directly bounds recoverability and data safety.

## Fix Intent (How — detailed)
1. **Consistent path resolution:** Resolve `db_path` from `target` for all four DBs
   (rag/session/workflow/eventbus) via `DbConfig`, so integrity-check, vacuum, and restore all
   operate on the **same** file. Remove the unused `db_path` parameter from `_run_integrity_check`.
2. **Reject or fully support unsupported targets:** Either support all four targets end-to-end, or
   reject non-rag/session targets early with `ValueError` instead of silently falling back to
   `session_db_path`.
3. **Route corruption into restore:** Add base `sqlite3.DatabaseError` (or base `sqlite3.Error`) to
   the integrity-check except tuple, and change control flow so an unreadable/corrupt DB enters the
   restore branch (returning `no_backup` when no usable backup is provided) rather than returning
   `action="error"`.
4. **Config completeness (L-8):** Add an explicit `workflow_db_path` entry to `agent.toml` matching
   the other DBs.
5. *(Optional, related)* Apply the same except policy to `SQLiteHelper.health_check()`
   (`PRAGMA quick_check`) so `/session health` does not leak exceptions on a corrupt DB.

## Acceptance Criteria
- [ ] A malformed DB image does not propagate an exception; `recover_corruption` returns
      `action in {"restored", "no_backup", "error"}`.
- [ ] With a valid `backup_path`, a corrupt DB is restored (`action="restored"`).
- [ ] `target="workflow"` never reads or writes `session.sqlite`; check, vacuum, and restore all
      operate on `workflow.sqlite`.
- [ ] Passing an unsupported target raises `ValueError` (or is fully supported end-to-end).
- [ ] `agent.toml` includes an explicit `workflow_db_path`; runtime behavior unchanged.
- [ ] Regression tests: malformed image, workflow-target isolation, no-backup path.
