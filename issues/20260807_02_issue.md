# Validate complete chunk groups before embedding or database mutation

## Priority
High

## Suggested Labels
priority-high, rag, ingestion, validation, data-integrity

## Reason for Change
The ingester currently derives document metadata from the first chunk, allows invalid `chunk_index` values to fall back to zero, and does not verify that all files in a URL group belong to the same generated document version. This permits mixed metadata, duplicate indices, missing indices, and incomplete groups to reach embedding or storage.

## Implementation Intent
Define one strict, deterministic validation boundary for the ChunkSplitter artifact contract. Invalid or incomplete groups must fail before the embedding API is called and before any database operation begins.

## Affected Files
- `rag/ingestion/ingester.py`
- `rag/ingestion/pipeline_utils.py`
- chunk artifact models or validators
- relevant validation tests

## Implementation Scope
- [ ] Read every chunk payload in the URL group before embedding.
- [ ] Require `schema_version == "1"`, `artifact_type == "chunk"`, and `created_by == "chunk_splitter"`.
- [ ] Require matching `url`, `source_file`, `title`, `lang`, `etag`, `last_modified`, `fetched_at`, and `chunking_strategy` across the group.
- [ ] Require `chunk_index` to be a non-boolean integer greater than or equal to zero.
- [ ] Remove conversion of invalid `chunk_index` values to zero.
- [ ] Reject duplicate or non-contiguous indices and require `0..chunk_count-1`.
- [ ] Require `chunk_type` to be `text` or `code`.
- [ ] Require non-empty strings for `content` and `source_file`.
- [ ] Require `normalized_content` to be `str | None`.
- [ ] Require every `code_blocks` element to be a string at the crawler-to-chunker boundary.
- [ ] When a completion manifest is present, require its source identity and `chunk_count` to match the actual file set.
- [ ] Return actionable validation errors containing the file name, field, received value type, and reason.

## Non-Goals
- Do not silently support malformed legacy artifacts.
- Do not coerce string indices to integers.
- Do not add languages other than Japanese and English.

## Acceptance Criteria
- [ ] Invalid or inconsistent groups do not call the embedding API and do not modify the database.
- [ ] Valid groups have one metadata identity and unique contiguous indices starting at zero.
- [ ] An invalid artifact reports the exact failing file and field.
- [ ] A manifest/file-count mismatch is rejected before preparation.

## Required Tests
- [ ] missing and incorrect artifact metadata
- [ ] mixed source files under one URL
- [ ] duplicate and missing indices
- [ ] boolean and string indices
- [ ] invalid chunk type
- [ ] empty content
- [ ] manifest count mismatch

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.

- [ ] Acceptance criteria are satisfied.
- [ ] Focused unit tests pass.
- [ ] Relevant integration or regression tests pass.
- [ ] Existing RAG ingestion, search, schema, and consistency tests remain green.
- [ ] Documentation and comments contain no stale or contradictory wording related to this issue.
