# Add mdq.sqlite to the Deployment DB inventory

## Priority
Medium

## Summary
Record `mdq.sqlite` in the Deployment chapter's DB inventory with its path source, owner, initialization, permission, recovery, and monitoring responsibilities, so the Deployment and DB documents describe the same persistent databases.

## Background
Source: finding V24-03 (and the residual of V24-04) in `memo1.md`, the design document review of 2026-10-16. Verified against the repository on 2026-10-16:
- `docs/41_db/db_08_active_databases.md` already lists `mdq.sqlite` (owner `mdq-mcp`, `db_path` in `config/mdq_mcp_server.toml`, schema authority `scripts/mcp_servers/mdq/db_schema.py`, busy timeout, created on first MDQ use).
- `docs/10_adr/adr_02_008_sqlite-4db-separation.md` already states that `mdq.sqlite` is a derived store outside the four platform domains, owned by `mdq-mcp`, rebuilt from the Markdown files by `index_paths` and `refresh_index`, and not backed up or restored by `recover_corruption()` or `rotate_all_dbs()`. This resolves most of finding V24-04.
- `docs/41_db/db_03_architecture_and_schema-migration-and-scaling.md` section 8d records the automatic legacy-schema detection that `create_production_tables()` runs at every MDQ service start.

## Problem
- `docs/90_deployment/deployment_01_deployment.md` section 3.0 (Platform DB Overview) lists only `rag.sqlite`, `session.sqlite`, `workflow.sqlite`, and `eventbus.sqlite`.
- The auto-generated DB Path Reference block in the same file lists the same four databases. It is produced by `tools/generate_reference_table.py --type deployment` (`generate_deployment_reference_table`) from `scripts/db/config.py` and `config/agent.toml`, so it cannot show `mdq.sqlite`, whose path lives in `config/mdq_mcp_server.toml`.
- `deploy/deploy.sh` copies `config/mdq_mcp_server.toml` to the deployed config directory, but the Deployment chapter does not mention `mdq.sqlite` at all, and `deploy/init_db.sh` does not create it (it is created on first MDQ use).
- The Deployment chapter therefore gives operators no statement of the `mdq.sqlite` path, directory permissions, the no-backup and rebuild stance, WAL and capacity monitoring, or the initialization check.
- `ADR-008` does not point to `db_03` section 8d for the migration responsibility of `mdq.sqlite`; the pieces exist in separate documents.

## Reason for Change
A persistent database that is missing from the Deployment inventory can be left out of directory provisioning, permission checks, monitoring, and recovery planning. The facts already exist in the DB and ADR documents; the Deployment chapter must state its part and agree with them.

## Implementation Intent
- Add `mdq.sqlite` to the Deployment DB inventory as a derived store owned by `mdq-mcp`, using the facts already recorded in `db_08`, `ADR-008`, and `db_03` section 8d, and link to them instead of copying their detail.
- Decide, and record, how the DB Path Reference treats a database whose path is outside `config/agent.toml`; keep the generated block generated.
- Keep the documents consistent with each other: do not state a recovery or backup rule that `ADR-008` does not already state.
