**Title:** [Medium][mcp][ops] Define external supervision for crashed MCP servers (post-watchdog)

**Labels:** enhancement, medium-priority, mcp, operations
**Covers:** M-5
**Area / Component:** `agent/factory.py::ensure_ready`, deployment/service units

## Summary
The MCP watchdog (periodic health polling + auto-restart) was removed. A crashed subprocess server
only recovers on the next tool call via `ensure_ready()`, and persistent servers have no automatic
recovery.

## Rationale (Why this matters — detailed)
- Recovery is now purely reactive: a subprocess server with no incoming calls stays down
  indefinitely, and externally-managed (persistent) servers have no auto-recovery at all.
- The failure-modes documentation still lists automatic recovery expectations that no longer hold, so
  operators may assume resilience that does not exist. Availability can degrade silently until a tool
  call happens to trigger `ensure_ready()` or an operator restarts manually.

## Fix Intent (How — detailed)
- Document and require external process supervision (e.g., systemd) for liveness and restart, and add
  it to the pre-production checklist with an explicit restart policy.
- Clearly document recovery expectations for subprocess vs. persistent servers.
- Optionally re-introduce a lightweight health-driven restart for subprocess servers if reactive
  recovery proves insufficient.

## Acceptance Criteria
- [ ] Pre-production checklist requires external supervision with a restart policy.
- [ ] Recovery expectations for subprocess vs. persistent servers are documented and consistent with
      current code (no stale watchdog claims).
