## MCPサーバー起動コマンドがuv run経由であり、実行時に依存関係解決が動的に発生しうる

### Summary

全MCPサーバーの `cmd` 設定は `["uv", "run", "--directory", "/opt/llm", "python", ".../xxx_server.py"]` という形式であり、`uv run` は実行のたびに `pyproject.toml`/`uv.lock` との整合性を検証し、必要なら依存関係の同期処理を行う可能性がある。`/opt/llm` 配下のこれらのファイルへの書き込み権限が本番環境で適切に制限されていない場合、MCPサーバー起動のたびに依存関係が動的に変わりうる。

### Problem

- `config/agent.toml` の全 `[mcp_servers.<key>]` セクション(299, 311, 320, 329, 338, 347, 364, 373, 382, 394行目)で、`cmd` が一律 `uv run --directory /opt/llm python <server>.py` 形式になっている。
- `uv run` はプロジェクトの依存関係が最新でない場合、自動的に依存関係の解決・同期処理を実行する一般的な挙動を持つ。
- これはPythonコード自体の問題ではなく、デプロイ・パーミッション設定に依存する確認事項。

### Affected Files

- `config/agent.toml` — 全 `[mcp_servers.*]` セクションの `cmd` 設定

### Classification

**Informational / Needs confirmation** — 本番デプロイで `/opt/llm/pyproject.toml` および `/opt/llm/uv.lock` の書き込み権限がどのように制限されているか未確認。

### Evidence

- Needs confirmation — `uv run` の実際の起動時挙動(依存関係チェックのコスト・タイミング)、および本番環境でのファイルパーミッション設定。

### Recommended next action

- 本番デプロイにおける `/opt/llm` 配下の書き込み権限設定を確認する。
- 起動時の依存関係解決コストが許容範囲か、また意図しない依存関係変更を防ぐ運用上の対策(lockファイルの読み取り専用化等)が取られているか確認する。
