**Title:** [Medium][config] Fix config/runtime value mismatches: file-read max_read_bytes unit and RagPipelineConfig default divergence

**Labels:** bug, enhancement, medium-priority, config, rag, mcp
**Covers:** M-3, M-7
**Area / Component:** `scripts/mcp_servers/file/read_github_models.py`,
`scripts/mcp_servers/rag_pipeline/rag_pipeline_models.py`, `config/*_mcp_server.toml`

## Summary
Two instances of "the configured value does not equal the enforced value" are fixed together as a
single config-correctness audit.

## Rationale (Why this matters — detailed)
- **Unit mismatch (M-3):** `FileReadConfig.from_dict` treats the TOML `max_read_bytes` value as KB
  (`// 1024`), so a default of `1,000,000` yields an effective limit of `999,424` bytes. The key name
  says bytes but the implementation applies a KB conversion, producing an off-by-unit effective limit
  that misleads operators and invites misconfiguration of read limits.
- **Default divergence (M-7):** Several `RagPipelineConfig` fields (`top_k_search`, `top_k_rerank`,
  `rag_min_score`, `semantic_cache_max_size`, `refiner_max_chars_per_chunk`) have code defaults that
  differ from the operational TOML values. There is no harm while the TOML supplies values, but
  removing/simplifying the TOML silently changes behavior — a maintenance hazard with no single
  source of truth.
- Both are the same class of defect ("declared value vs. enforced value"), so a single audit pass and
  a shared set of value-assertion tests cover them efficiently.

## Fix Intent (How — detailed)
- **M-3:** Pick one unit and make key name and behavior agree — either rename the key to
  `max_read_kb`, or interpret `max_read_bytes` as bytes (remove the hidden `// 1024`). Prefer bytes to
  match the existing key name; backward compatibility may be dropped per project policy. Update docs.
- **M-7:** Align the code defaults with the operational values, or annotate each divergence explicitly
  and centralize the canonical values. Add tests asserting the intended effective values so future
  TOML edits cannot silently change behavior.

## Sub-tasks
- [ ] (M-3) Resolve `max_read_bytes` unit; align key name, behavior, and docs.
- [ ] (M-7) Reconcile `RagPipelineConfig` code defaults with operational TOML; add value-guard tests.

## Acceptance Criteria
- [ ] file-read: configured limit equals the enforced byte limit (no hidden `//1024`); test asserts it.
- [ ] rag-pipeline: code defaults match operational values (or documented rationale per divergence),
      guarded by a test.
