# [Risk] pyproject.toml console-script entries still point at deleted per-domain doc-consistency modules

## Priority
Medium

## Background

`plans/20260820-102217_plan.md` (source requirement:
`requires/done/20260819-215619_require.md`) fixes
`.github/workflows/agent-docs-consistency.yml` and
`.github/workflows/mcp-docs-consistency.yml` so their CI `run:` steps invoke the consolidated
`tools/check_docs_consistency.py --domain <agent|mcp>` entry point instead of the deleted
per-domain scripts `tools/check_agent_docs_consistency.py` / `tools/check_mcp_docs_consistency.py`.

While verifying that fix, a repo-wide search for other references to the two deleted script
paths found that `pyproject.toml` still declares console-script entry points targeting the
same deleted modules:

```
# pyproject.toml
check-mcp-docs = "tools.check_mcp_docs_consistency:main"
check-agent-docs = "tools.check_agent_docs_consistency:main"
```

Neither `tools/check_mcp_docs_consistency.py` nor `tools/check_agent_docs_consistency.py`
exists in the repository (confirmed: `ls tools/check_mcp_docs_consistency.py
tools/check_agent_docs_consistency.py` → both "No such file or directory"). `rules/toolchain.md`
documents `check-mcp-docs` as the expected entry point for the "MCP documentation consistency"
validation step (`uv run check-mcp-docs`), so any engineer following that documented step
would hit an import error at the entry-point level, not a documentation-content warning.

## Problem

`pyproject.toml`'s `[project.scripts]` table has the same "references a deleted per-domain
module" defect that the two CI workflow files had, for the identical two domains (agent, mcp),
but on a different mechanism (Python console-script entry point vs. a CI `run:` step). This
was out of scope for `plans/20260820-102217_plan.md` because `pyproject.toml` is not one of
that requirement's two named target files (`.github/workflows/agent-docs-consistency.yml`,
`.github/workflows/mcp-docs-consistency.yml`).

## Reason for change

`rules/toolchain.md` documents `uv run check-mcp-docs` as a validation step engineers are
expected to run. As currently configured, invoking it (or the analogous `check-agent-docs`,
if such a step is ever documented/used) would fail with a module-not-found error rather than
performing the intended documentation consistency check — the same class of silent breakage
that motivated fixing the two CI workflow files.

## Implementation intent

A narrow follow-on requirement/plan cycle should update `pyproject.toml`'s `[project.scripts]`
table:

```toml
check-mcp-docs = "tools.check_docs_consistency:main"
check-agent-docs = "tools.check_docs_consistency:main"
```

and confirm the consolidated `main()` in `tools/check_docs_consistency.py` can be invoked
without an explicit `--domain` argument for this entry-point use case, or — if `main()`
requires `--domain` to be passed explicitly — determine whether `check-mcp-docs`/
`check-agent-docs` need a small wrapper/default-argument shim instead of a bare `:main`
reference. This determination was not made as part of this risk filing; it is the first task
for whoever picks up this follow-up.

## Acceptance criteria

- [ ] `pyproject.toml`'s `check-mcp-docs` entry point resolves to an importable target and
  performs the MCP-domain consistency check (not a module-not-found error) when invoked via
  `uv run check-mcp-docs`.
- [ ] `pyproject.toml`'s `check-agent-docs` entry point resolves similarly for the agent domain.
- [ ] `rules/toolchain.md`'s "MCP documentation consistency" section is updated if the invocation
  contract changes (e.g. if `--domain` becomes mandatory and a wrapper is introduced).

## Tests

- `uv run check-mcp-docs` (and `check-agent-docs`, if it is actually used anywhere) executes
  without an import/module-not-found error.
- Confirm no other `[project.scripts]` entry in `pyproject.toml` references a deleted `tools/`
  module (repeat the same `ls`/`grep` verification pattern used for this finding).
