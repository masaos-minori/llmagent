# `rules/toolchain.md`'s "MCP documentation consistency" section is stale

## Priority
Low

## Context
Discovered while planning `plans/20260804-105326_plan.md` (test rewrite of
`tests/tools/test_check_mcp_docs_consistency.py`, sourced from
`requires/done/20260804-095904_require.md`). The source requirement's own "Documentation Impact"
section already flagged this as confirmed stale and recommended filing it as a separate follow-up,
explicitly out of scope for that test-only fix. This issue formalizes that recommendation.

## Description
`rules/toolchain.md` lines 111-127 ("MCP documentation consistency" section) read:

```markdown
## MCP documentation consistency

```bash
# Run all checks (startup, failopen, routing, active, toolcount)
uv run check-mcp-docs

# Skip specific checks
uv run check-mcp-docs --skip active --skip toolcount
```

The `check-mcp-docs` entry point is registered in `pyproject.toml`. It verifies:
- Valid startup modes (persistent/ondemand/subprocess)
- No fail-open wording for workflow_allowlist
- Routing authority language consistency
- Active MCP issue cross-references (MCP-01 through MCP-08)
- Tool count consistency against canonical frozensets
```

None of this matches the current `tools/check_mcp_docs_consistency.py` module. That module was
deleted in commit `74906389` ("refactor: remove unsupported MDQ tool/search surface and stale
tool-count doc check") and restored with a completely different design in commit `5e34c14a6`
("fix: restore MCP docs consistency checker and fix stale CI/doc references") — but this section of
`rules/toolchain.md` was never updated to match the restored module.

The current module's actual `--skip` choices (confirmed by reading
`tools/check_mcp_docs_consistency.py`'s `skip_choices` list) are:

```
links, removedfiles, commanddrift, portdrift, tooldrift, filerefs, funcrefs
```

Neither `active` nor `toolcount` exists as a `--skip` value today; passing either would fail
argparse's `choices` validation. The check set the doc describes (startup modes, fail-open wording,
routing authority, active-issue cross-references, tool-count consistency) does not exist in the
current module either — the module now performs:
- `check_port_drift` — doc-mentioned port vs. `config/agent.toml`'s `[mcp_servers.*]` (ERROR)
- `check_tool_name_drift` — backtick-quoted tool name vs. live `scripts/mcp_servers/**/*.py`
  `TOOL_LIST` definitions (WARNING)
- plus the generic checks shared via `tools/_docs_consistency_lib.py`: broken internal links,
  removed-file references, slash-command drift, file-path references, function references.
