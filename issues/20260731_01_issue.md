# Fix Qwen3 embedding dimension contract as a 1024-dimensional code constant

## Priority

High

## Summary

Replace configurable embedding dimensions with a fixed implementation constant for `Qwen3-Embedding-0.6B-Q8_0.gguf`.

The system supports only Qwen3 1024-dimensional embeddings. Therefore, embedding dimensions must not be configurable through TOML files. Both RAG vectors and memory vectors must use the same constant.

## Background

The current implementation still treats embedding dimensions as configuration:

- `DbConfig.embedding_dims` exists and defaults to `384`.
- `build_db_config()` reads `embedding_dims` from `agent.toml`.
- `get_embedding_dims()` returns `build_db_config().embedding_dims`.
- `agent.toml` contains `embedding_dims = 384`.
- `agent.toml` also contains `memory_embed_dim = 384`.
- `ingester.toml` contains `embedding_dims = 384`.

This creates a risk that `chunks_vec` or `memories_vec` is created with `float[384]` instead of `float[1024]`.

## Fix Intent

Make 1024 dimensions an implementation invariant instead of a runtime configuration value.

This reduces configuration drift, removes accidental fallback to 384 dimensions, and aligns the RAG and memory stores with the single supported embedding model.

## Required Changes

- Define a constant, for example:

  `QWEN3_EMBEDDING_DIMS = 1024`

- Update `db/store_protocols.py`.
  - `get_embedding_dims()` must return the constant.
  - `get_embedding_bytes()` should continue to derive bytes from `get_embedding_dims()`.
- Update `db/config.py`.
  - Remove the `embedding_dims` field from `DbConfig`.
  - Remove `embedding_dims=int(cfg.get("embedding_dims", 384))` from `build_db_config()`.
- Update `config/agent.toml`.
  - Remove `embedding_dims = 384`.
  - Remove `memory_embed_dim = 384`.
- Update `config/ingester.toml`.
  - Remove `embedding_dims = 384`.
- Ensure schema creation still uses `get_embedding_dims()`.
- Recreate both vector databases.
  - `rag.sqlite`
  - `session.sqlite`

## Files to Update

- `db/store_protocols.py`
- `db/config.py`
- `config/agent.toml`
- `config/ingester.toml`
- Schema creation path using `create_schema.py`

## Acceptance Criteria

- `get_embedding_dims()` always returns `1024`.
- No TOML file contains `embedding_dims`.
- No TOML file contains `memory_embed_dim`.
- `DbConfig` no longer has an `embedding_dims` field.
- New `rag.sqlite` creates `chunks_vec.embedding float[1024]`.
- New `session.sqlite` creates `memories_vec.embedding float[1024]`.
- No migration from old vector data is implemented.
