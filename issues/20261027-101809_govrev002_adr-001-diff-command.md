# Replace the undefined "diff command" review mechanism in ADR-001 with a verified one

## Priority
Medium

## Summary
ADR-001 states that reviewing a turn "relies on the diff command and the audit log", but no command of that name is defined in the current command documents. Identify the review mechanism the ADR intends and replace the phrase with the formal name of a mechanism that exists, or state the limitation if only the audit log exists.

## Background
- ADR-001 (`adr_02_02_001_agent-workflow-engine-mandatory.md`), Negative Consequences, says: "There is no human checkpoint for the combined result of a turn; reviewing a turn relies on the diff command and the audit log". The phrase "the diff command" appears nowhere else under `docs/`. Evidence: `Explicit in code` (document text; repository-wide search of `docs/`).
- The slash commands registered in the Agent (`scripts/agent/commands/command_defs_list.py`) and documented in `agent_07_03_cli-and-commands-command-registry.md` include `/history`, `/undo`, `/stats` and others, but no diff command. Evidence: `Strongly implied by code` (search of the command definitions and the registry document found no diff entry).
- A `git_diff` tool exists in the Git MCP server (`scripts/mcp_servers/git/git_service.py`). It is a tool call executed by the model, not an operator command. Evidence: `Explicit in code`.
- The Agent audit log is documented in `agent_10_02_operations-and-observability-audit-and-otel.md`. Evidence: `Explicit in code` (document text).
- A review finding hypothesized that a slash command `/diff` was removed in an earlier command cleanup. No evidence of such a removal was found in this investigation. Evidence: `Needs confirmation`.

## Problem
The ADR names a compensating control for the missing approval stage ("no human checkpoint") that cannot be located in the specification. An operator or implementer reading ADR-001 may assume that a review command exists. The ADR's own justification for omitting an approval stage then rests on an undefined mechanism.

Confidence: High that the phrase is undefined in the documents; Low on what it was meant to denote.

## Reason for Change
ADR-001 is an Accepted ADR and a governing document for the workflow design. A compensating control that cannot be identified weakens its Negative Consequences section. Nothing makes the change time-sensitive beyond that.

## Implementation Intent
First determine the intended meaning from the ADR's own context and the command and audit documents. Then replace the phrase with the formal name of an existing mechanism. State precisely what that mechanism lets a reviewer see, because `/history` shows conversation messages and not state changes, and `git_diff` is a model-invoked tool and not a review command. If no existing mechanism covers reviewing the combined result of a turn, state that the audit log is the only review source and record the limitation as a constraint. Do not introduce a new command or a new requirement. Preserve every Decision, Invariant and Approval record of ADR-001.
