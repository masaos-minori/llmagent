# Risk follow-up: docs/adr-index.md's ADR List omits the live ADR-013 and its "deleted" note is wrong

## Priority
Medium

## Context
While planning `issues/20260918-130115_adrref01_decide-reference-class-fate-via-adr.md`
(which registers a new ADR in `docs/adr-index.md`'s ADR List), `docs/adr-index.md` was
read to determine the next available ADR number. Its ADR List table lists ADR-001
through ADR-010, then ADR-012 and ADR-014 — skipping ADR-013 — and a note below the
table states "ADR-013（MCP Tool Availability Model）はADR-003へ統合され、削除された。"
(ADR-013 was merged into ADR-003 and deleted). However,
`docs/adr/ADR-013-eventbus-authentication-authorization.md` currently exists in the
repository and is about EventBus authentication/authorization — an unrelated, live
topic, not "MCP Tool Availability Model". This was not fully mitigated inline in the
source Plan because fixing it would edit content outside that Plan's own scope
(registering a new, unrelated ADR).

## Risk
`docs/adr-index.md` is the canonical ADR list, dependency graph, and invariant
verification matrix per `docs/00_governance_01_documentation-policy.md` ADR Section
Header Standardization ("The ADR list, dependency graph, and invariant verification
matrix are maintained in `adr-index.md`"). A reader relying on this index would
believe ADR-013 does not exist / was deleted, when in fact it is a currently Accepted
ADR governing EventBus authentication. This could cause a future ADR author to
accidentally reuse the ADR-013 number for a new decision (the index's own gap makes it
look "available"), or cause a reviewer checking ADR dependency/coverage to overlook
ADR-013 entirely since it is absent from the ADR List table and Dependency Graph.

## Suggested resolution
Add an ADR List row for ADR-013 (`Event Bus認証・認可` / `docs/adr/ADR-013-eventbus-authentication-authorization.md`,
status per its own Approval section), correct or remove the stale "ADR-013 was merged
into ADR-003 and deleted" note (that description now applies to a different, no-longer-
present decision — verify whether it should instead reference a different retired ID),
and add ADR-013 to the ADR Dependency Graph if it has dependencies, consistent with the
existing entries' format.
