# Make RAG consistency diagnostics complete and non-silent

## Priority
Medium

## Suggested Labels
priority-medium, rag, database, consistency, diagnostics

## Reason for Change
FTS gaps and orphans are currently derived from total-count subtraction, so one missing row and one orphan row can cancel each other out. URL-level diagnostic SQL also catches broad exceptions and silently substitutes empty results, which can make an incomplete check appear clean. Orphan vector URLs cannot normally be reconstructed through a missing chunk join.

## Implementation Intent
Make consistency results describe what was actually checked and detect row-level mismatches even when aggregate totals happen to match.

## Affected Files
- `db/rag_consistency.py`
- `db/models.py` if a diagnostic-error field is required
- consistency tests

## Implementation Scope
- [ ] Count chunks missing from FTS by row-ID set difference.
- [ ] Count FTS rows without matching chunks by row-ID set difference.
- [ ] Collect affected identifiers from the same set-difference queries.
- [ ] Replace broad `except Exception: pass` blocks around URL-level checks with scoped database exceptions.
- [ ] Record failed diagnostic checks in the report or a dedicated diagnostic-error field.
- [ ] Ensure `is_consistent()` cannot return true when a required check could not run.
- [ ] Log the failing diagnostic query category and exception.
- [ ] Use orphan vector chunk IDs as the supported identifier; remove misleading URL-recovery logic unless a real provenance source exists.
- [ ] Keep existing report fields and repair guidance compatible where practical.

## Non-Goals
- Do not add automatic repair in this issue.
- Do not replace atomic ingestion or manifest validation with post-hoc checks.
- Do not modify canonical data during diagnostics.

## Acceptance Criteria
- [ ] One missing FTS row and one orphan FTS row are both reported when total counts are equal.
- [ ] A failed URL-level diagnostic is visible and prevents a clean consistency result.
- [ ] Orphan vector diagnostics do not claim an unavailable URL.
- [ ] All diagnostics remain read-only.

## Required Tests
- [ ] equal-count gap/orphan cancellation
- [ ] URL-level SQL failure
- [ ] orphan vector without a chunk
- [ ] normal consistent database
- [ ] existing gap-only and orphan-only cases

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
