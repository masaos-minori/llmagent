# Implement resilient search fallback and improve SearchDiagnostics

## Priority
High

## Type
Bug fix / Reliability / Observability

## Background
The current SearchStage performs embedding generation first and skips the query when embedding generation fails. As a result, FTS/BM25 search is not executed for that query, even though the repository layer supports FTS search independently.

Vector search and FTS search are also executed in the same error-handling block, making it difficult to distinguish sqlite-vec failures from FTS5 failures.

## Problem
If the embedding service is unavailable or returns an invalid response, the RAG pipeline may return no results even when FTS5/BM25 could still find relevant documents.

This breaks the intended degraded-mode behavior. It also makes operational diagnosis difficult because vector search errors and FTS errors are not separated.

## Fix Intent
The intent is to make retrieval resilient:

- Vector search should be used when embedding generation succeeds.
- FTS search should still run when embedding generation fails.
- Vector and FTS failures should be diagnosed independently.
- The pipeline should be able to indicate whether it ran in hybrid, vector-only, FTS-only, or failed mode.

## Implementation Tasks
- Update SearchStage so that FTS search runs even when get_embedding() fails.
- Split vector_search and fts_search into separate try/except blocks.
- Add diagnostics fields such as:
  - vector_errors
  - fts_errors
  - fts_only_queries
  - vector_only_queries, if useful
- Ensure embedding failure increments embed_failed but does not prevent FTS execution.
- Ensure vector search failure does not prevent FTS results from being returned.
- Ensure FTS failure does not prevent vector results from being returned.
- Update get_diagnostics() to expose the new diagnostic fields.
- Update logs to clearly report hybrid, FTS-only, vector-only, and degraded modes.

## Acceptance Criteria
- When embedding generation fails, FTS search still runs.
- Search results can be returned from FTS-only mode.
- Vector search errors and FTS search errors are reported separately.
- SearchDiagnostics clearly explains degraded search behavior.
- Existing hybrid search behavior remains unchanged when both vector and FTS searches succeed.

## Tests
- Add a test where get_embedding() raises an exception and FTS still returns hits.
- Add a test where vector_search fails but fts_search succeeds.
- Add a test where fts_search fails but vector_search succeeds.
- Add diagnostics assertions for embed_failed, vector_errors, fts_errors, and fts_only_queries.
- Add regression tests to confirm existing Japanese FTS and normalized_content fallback behavior remain unchanged.

## Out of Scope
- Changing the embedding model.
- Changing the FTS5 schema.
- Changing RRF ranking behavior.
