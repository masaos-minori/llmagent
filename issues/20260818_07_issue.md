# [HIGH] Reconcile current specifications, runtime references, and active issue state

## Priority

High

## Background

Current deployment and runtime information is manually repeated across Overview, Deployment, RAG, Agent, Shared/DB, and operations documents.

Potentially conflicting information includes:

- Active Agent LLM models
- Active embedding models
- GGUF filenames
- Embedding dimensions
- Query and passage prefixes
- Dependency-management files
- Current and deprecated CLI commands
- Three-database and four-database descriptions
- Database paths and ownership
- Resolved Needs Confirmation items
- Historical correction notes retained in current specifications
- Duplicate issue metadata fields

## Reason for Change

These inconsistencies affect installation, startup, troubleshooting, backup, recovery, and AI implementation decisions.

Examples of risks include:

- Loading the wrong model
- Creating an embedding-dimension mismatch
- Using a nonexistent dependency file
- Running a deprecated command
- Omitting EventBus storage from backup
- Treating a resolved issue as active
- Treating historical behavior as current behavior
- Generating inconsistent issue reports due to duplicate metadata

## Intent

Separate:

- Current active specification
- Current active configuration
- Non-canonical examples
- Historical behavior
- Resolved issue history
- Active Known Issues
- Active Needs Confirmation items

Current runtime references should be generated from authoritative code or configuration where practical.

## Tasks

### Model and Embedding References

1. Define one canonical source for each active LLM model path.
2. Separate current, example, historical, and environment-specific model references.
3. Confirm and document:

   - Active embedding model
   - GGUF filename
   - Embedding dimension
   - Query prefix
   - Passage prefix
   - Vector encoding
   - Distance metric
   - Configuration ownership
   - Migration requirement when the model changes

4. Remove or mark obsolete model references.
5. Add model and vector-schema dimension validation.

### Dependency References

6. Identify the canonical dependency-management files.
7. Remove references to nonexistent dependency files.
8. Align development, production, and deployment-script procedures.

### CLI References

9. Compare documentation with the runtime command registry.
10. Reconcile current and deprecated commands.
11. Correct `/db`, `/session`, and related operational references.
12. Require each deprecated command to name its replacement or state that no replacement exists.
13. Generate or automatically validate the command reference.

### Database References

14. Reconcile three-database and four-database descriptions.
15. Document:

    - rag.sqlite
    - session.sqlite
    - workflow.sqlite
    - eventbus.sqlite

16. Define for each database:

    - Owning process
    - Configuration source
    - Default path
    - Schema authority
    - WAL policy
    - Lifecycle
    - Backup responsibility

17. Generate the active database reference where practical.

### Active and Resolved Issue State

18. Move resolved Needs Confirmation items to an archive.
19. Preserve original IDs, questions, evidence, resolutions, dates, and history.
20. Keep only active or intentionally deferred entries in the active inventory.
21. Remove duplicate metadata fields and duplicate dates.
22. Rewrite canonical specifications as direct current-state statements.
23. Move historical correction commentary to Git history, ADRs, or resolved issue archives.
24. Add validation for:

    - Unique IDs
    - Required fields
    - Duplicate fields
    - Status values
    - Priority values
    - ISO 8601 dates
    - Resolution evidence
    - Valid source references

## Acceptance Criteria

- [ ] One source defines each active model path.
- [ ] Examples are clearly marked as non-canonical.
- [ ] Historical models are removed from current procedures.
- [ ] The active embedding model is uniquely identified.
- [ ] Model filename, dimension, prefixes, encoding, and distance metric are consistent.
- [ ] Dimension mismatch validation exists.
- [ ] Canonical dependency files are identified.
- [ ] References to nonexistent dependency files are removed.
- [ ] Deployment procedures match deployment scripts.
- [ ] CLI documentation matches the runtime command registry.
- [ ] Deprecated commands are absent from current procedures.
- [ ] Every deprecated command identifies a replacement or explicitly states that none exists.
- [ ] All active databases are documented.
- [ ] Database ownership and backup responsibility are explicit.
- [ ] Overview, Deployment, Shared/DB, and EventBus documents agree.
- [ ] The active Needs Confirmation inventory contains only active or deferred items.
- [ ] Resolved entries are available in an archive.
- [ ] Historical evidence is preserved.
- [ ] Duplicate issue metadata is removed.
- [ ] Current specifications describe current behavior directly.
- [ ] CI validates runtime references and issue metadata.
- [ ] Generated references are deterministic.

## Validation

1. Compare model references with active service configuration.
2. Verify the embedding endpoint returns the documented dimension.
3. Verify the vector schema matches the configured dimension.
4. Run the documented dependency installation in a clean environment.
5. Compare the CLI reference with the runtime registry.
6. Compare the database inventory with schemas and configuration.
7. Verify all resolved inventory items are preserved in the archive.
8. Verify IDs remain unique across active and archived inventories.
9. Search current specifications for obsolete correction language.

## Out of Scope

- Selecting a new model
- Changing the embedding dimension
- Migrating vector data
- Renaming runtime commands
- Merging database files
- Resolving currently open issues
