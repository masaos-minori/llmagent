# Align ETag freshness handling with transaction ownership

## Priority
Medium

## Suggested Labels
priority-medium, rag, metadata, transaction, freshness

## Reason for Change
`ETagManager` compares timestamp strings lexically and commits inside helper methods. Lexical comparison depends on identical timestamp formatting, while helper-level commits can break a caller's intended document-level transaction boundary.

## Implementation Intent
Make freshness ordering explicit and keep transaction ownership at the service or ingestion-operation boundary.

## Affected Files
- `rag/ingestion/etag_manager.py`
- `rag/ingestion/document_manager.py`
- `rag/ingestion/ingester.py`
- ETag tests

## Implementation Scope
- [ ] Parse supported `fetched_at` values as timezone-aware UTC datetimes before comparison.
- [ ] Define explicit behavior for invalid timestamp formats.
- [ ] Remove direct commits from ETag update helper methods.
- [ ] Let the caller own commit and rollback boundaries.
- [ ] Keep null-fill behavior for legacy records without freshness metadata.
- [ ] Ensure the URL-level atomic ingestion work can include metadata updates without hidden commits.

## Non-Goals
- Do not change ETag or Last-Modified semantics beyond transaction and freshness handling.
- Do not add a new metadata database.
- Do not infer missing timestamps.

## Acceptance Criteria
- [ ] Older input cannot overwrite newer metadata.
- [ ] Equal and newer timestamps follow documented behavior.
- [ ] Invalid timestamps follow the documented reject or fallback policy.
- [ ] ETag updates participate in the caller's transaction and can be rolled back.

## Required Tests
- [ ] older, equal, and newer timestamps
- [ ] timezone-offset equivalence
- [ ] missing timestamp
- [ ] invalid timestamp
- [ ] rollback after ETag update

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
