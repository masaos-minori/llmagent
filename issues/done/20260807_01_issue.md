# Refactor RAG ingestion into an atomic URL-level transaction

## Priority
High

## Suggested Labels
priority-high, rag, ingestion, data-integrity, refactor

## Reason for Change
The current ingestion flow can delete an existing document, commit a replacement document row, and then insert chunks through independent database connections and per-chunk commits. If parsing, embedding, or storage fails partway through, the previous searchable document can be lost and the replacement can remain incomplete. The current `(chunk_ok, embed_ok)` result also cannot reliably distinguish parse, validation, embedding, and storage failures.

## Implementation Intent
Treat one URL and its complete chunk set as the smallest commit unit. Keep embedding HTTP calls parallel where useful, but perform all canonical database changes through one connection and one transaction after every chunk has been prepared successfully.

## Affected Files
- `rag/ingestion/ingester.py`
- `rag/ingestion/document_manager.py`
- `db/helper.py`
- relevant ingestion tests

## Implementation Scope
- [ ] Parse and validate the complete URL group before changing the database.
- [ ] Generate all embeddings before deleting or replacing an existing document.
- [ ] Keep HTTP embedding calls parallelizable, but remove database access and commits from embedding workers.
- [ ] Introduce an immutable `PreparedChunk` DTO containing all validated values required for insertion.
- [ ] Replace `(chunk_ok, embed_ok)` with explicit preparation or failure results that distinguish parse, validation, embedding, and storage failures.
- [ ] Use `SQLiteHelper.begin_immediate()` for one URL-level transaction.
- [ ] Inside the transaction, delete the existing vector rows and document, insert the replacement document, then insert all chunks and vectors.
- [ ] Roll back the entire URL update if any database operation fails.
- [ ] Move the complete URL group to `registered/` only after a successful commit.
- [ ] Route retries at URL-group level rather than moving individual failed chunks away from a partially committed document.
- [ ] Preserve the previous searchable document when forced re-ingestion fails.
- [ ] Invalidate the semantic cache only when at least one URL-level corpus transaction commits successfully.
- [ ] Load `rag_pipeline_service_url` once during `RagIngester` initialization instead of reloading `ingester.toml` at the end of a run.

## Non-Goals
- Do not add configurable embedding dimensions.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add legacy vector-dimension migration logic.

## Acceptance Criteria
- [ ] A failed forced re-ingestion leaves the previous document, chunks, FTS rows, and vectors unchanged.
- [ ] A successful URL ingestion commits the document, every chunk, FTS trigger updates, and every vector as one unit.
- [ ] No worker opens a database connection or commits an individual chunk.
- [ ] A URL group with one failed preparation does not modify the database.
- [ ] Files are moved to `registered/` only after commit.
- [ ] All-skipped and all-failed runs do not invalidate the cache.
- [ ] Failure logs and metadata identify parse, validation, embedding, or storage failure unambiguously.

## Required Tests
- [ ] forced re-ingestion with an embedding failure
- [ ] database failure during replacement
- [ ] partial preparation failure
- [ ] successful replacement
- [ ] all skipped
- [ ] all failed
- [ ] cache invalidation success and failure

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
