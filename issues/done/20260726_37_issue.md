## GitHub MCPサービス層にユニットテストを追加 (TASK-H8 / COV-1)

### Summary

GitHub MCPサーバのビジネスロジック一式が21〜47%という低カバレッジ。本来検証されるべき層がカバーされていない。

### Problem

`coverage report` 実測により、以下のファイル群が低カバレッジ:

- `mcp_servers/github/service_file.py` — 21%
- `mcp_servers/github/service_issues.py` — 21%
- `mcp_servers/github/service_pull_requests.py` — 47%
- `mcp_servers/github/service_repository.py` — 47%
- `mcp_servers/github/server_file.py` — 低カバレッジ
- `mcp_servers/github/server_issues.py` — 低カバレッジ
- `mcp_servers/github/server_pull_requests.py` — 低カバレッジ
- `mcp_servers/github/server_repository.py` — 低カバレッジ

### Affected Files

- `tests/test_github_mcp_service.py` — テスト拡張対象
- `scripts/mcp_servers/github/service_*.py` — 対象ファイル群
- `scripts/mcp_servers/github/server_*.py` — 対象ファイル群

### Severity

Medium — カバレッジ目標が不明確だが、ビジネスロジックの異常系が未検証の可能性が高い

### Mitigation

各 `service_*.py` の公開メソッドについて、成功パス・GitHub API異常応答(4xx/5xx)・認可失敗パスの最小テストを追加。既存の `test_github_mcp_service.py` の構成パターンを踏襲

### Acceptance Criteria

- 対象ファイル群のカバレッジが最低70%以上に到達
- 新規テストpass
- `diff-cover`(TASK-H6解決後)で当該変更行のカバレッジ90%以上
