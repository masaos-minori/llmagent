Title: [FEATURE] Implement MCP tool visibility filters (MCP-001 / MCP-002)
Labels: priority/medium, type/feature, area/mcp

## Summary
Two MCP tool-visibility capabilities are documented but not implemented, and one is implemented on only a single server.

## Rationale
- MCP-001: `/v1/tools` is specified to support `include_disabled` / `disabled_code`, but the handler does not implement them, so callers cannot distinguish or request disabled tools as the spec promises.
- MCP-002: only web-search-mcp implements `enabled` / `disabled_reason`; the other servers omit them. The asymmetry means the same disabled-tool concept is observable on one server and invisible on the rest, which confuses operators and any tooling that reads these fields.

## Intent
Make disabled-tool visibility uniform across MCP servers so the `/v1/tools` contract behaves the same everywhere, or narrow the spec to match reality and track the remainder explicitly.

## Tasks
- [ ] Implement `include_disabled` / `disabled_code` on `/v1/tools` (MCP-001), or update the spec and open a tracked follow-up.
- [ ] Implement `enabled` / `disabled_reason` on the remaining servers (MCP-002), or document the single-server support as intentional with a follow-up.

## Acceptance criteria
- `/v1/tools` behavior for disabled tools matches the spec across servers, or the spec is updated to match implementation with a tracked follow-up issue.
