# Remove or align unused RAG configuration DTOs and names

## Priority
Low

## Suggested Labels
priority-low, rag, configuration, typing, cleanup

## Reason for Change
The configuration DTO module describes fields such as `chunk_size` and `batch_size`, while runtime code uses `min_chunk`/`max_chunk` and `embed_workers`. DTOs that are not connected to loading can mislead implementers and allow documentation to drift from actual behavior.

## Implementation Intent
Keep only configuration types that have a real consumer and make retained names match active runtime settings.

## Affected Files
- `rag/models_config.py`
- configuration loaders and consumers
- documentation, examples, and fixtures
- type/import tests

## Implementation Scope
- [ ] Identify all consumers of `MqeConfig`, `FusionConfig`, `RerankConfig`, `SearchConfig`, `ChunkSplitterConfig`, `IngesterConfig`, and `PipelineConfig`.
- [ ] Delete DTOs with no consumers or connect them to a clearly documented file-format boundary.
- [ ] Align `chunk_size` with the implemented `min_chunk` and `max_chunk` model.
- [ ] Align `batch_size` with the implemented `embed_workers` behavior or remove the unused field.
- [ ] Update documentation, examples, fixtures, imports, and tests consistently.
- [ ] Do not introduce `embedding_dims`, `embedding_dim`, or `vec_dim`.

## Non-Goals
- Do not change chunking or concurrency behavior.
- Do not create compatibility aliases without an active consumer.
- Do not redesign the configuration loader.

## Acceptance Criteria
- [ ] Every retained DTO has a concrete consumer.
- [ ] Runtime code, documentation, and DTOs use the same names for active settings.
- [ ] Unused or misleading fields are removed.
- [ ] No dimension configuration fields are introduced.

## Required Tests
- [ ] import/type tests
- [ ] configuration examples
- [ ] fixture loading
- [ ] search for removed field names

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.

## Definition of Done
- [ ] Implementation scope is complete.
- [ ] Acceptance criteria are satisfied.
- [ ] Focused unit tests pass.
- [ ] Relevant integration or regression tests pass.
- [ ] Existing RAG ingestion, search, schema, and consistency tests remain green.
- [ ] Documentation and comments contain no stale or contradictory wording related to this issue.
