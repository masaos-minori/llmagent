### ISSUE-H3: tool_definitions チェックの FATAL 昇格がドキュメントの「常に WARNING」記述と矛盾 `[確認済 / 意図確認要]

優先度: High
対象ファイル: `scripts/agent/services/mcp_tool_discovery.py`, `docs/05_agent_10_01_operations-and-observability-startup-and-health.md`

#### 修正理由
`docs/05_agent_10_01_operations-and-observability-startup-and-health.md` は起動時検証の重大度マッピングとして次のように明記している。

> `tool_definitions` は strict モードでも FATAL にはならない — 常に WARNING にダウングレードされる。

しかし実装 (`scripts/agent/services/mcp_tool_discovery.py`) は、tool_definitions の不一致を含む全ての finding に「統一された重大度スキーム」を適用しており、モジュール docstring 自体がこれを明記している。

```python
# 33-35行目
# Unified severity scheme (drift, tool-definitions, malformed-capabilities):
# `is_fatal = strict or (security_profile == PRODUCTION)`.
```

```python
# 345-358行目
def _is_strict(self) -> bool:
    return bool(getattr(self._ctx.cfg.tool, "tool_definitions_strict", False))

def _is_fatal_severity(self) -> bool:
    return self._is_strict() or (
        self._ctx.cfg.mcp.security_profile == SecurityProfile.PRODUCTION
    )
```

`_check_tool_definitions_finding()` (388-417行目) はこの `_is_fatal_severity()` の結果に応じて `StartupCheckStatus.FATAL` / `WARNING` を出し分けている。すなわち `security_profile=PRODUCTION` であれば `tool_definitions_strict` の値に関わらず tool_definitions の不一致は FATAL 判定となり、`StartupOrchestrator._check_services()` 側でパイプラインが FATAL を含めば起動全体が失敗する。ドキュメントが明言する「strict モードでも FATAL にはならない」という保証とは逆に、本番環境では tool_definitions の不一致だけで起動が失敗し得る。

運用者がこのドキュメントを信頼して「tool_definitions の不整合は起動をブロックしない」と想定していた場合、本番での予期しない起動失敗の原因調査で誤った前提に基づく初動対応を取るおそれがある。

モジュール docstring には「この統一スキームは “strict モードのドリフト検出が無関係な例外ハンドラで無言のうちに skipped に格下げされていた” 旧来の不具合を解消するための意図的な設計変更である」との説明があり、実装側の変更が意図的であった可能性が高い。したがって本 issue はコードのバグ修正ではなく、ドキュメントと実装のどちらを正とするかの意思決定、およびその後の整合作業を対象とする。

#### 修正意図
tool_definitions の FATAL/WARNING 判定について、実際に意図する挙動 (production/strict でも常に WARNING にすべきか、統一スキーム通り FATAL 昇格を許容すべきか) を確定させ、ドキュメントと実装を一致させる。運用者が起動失敗の重大度マッピングを正しく信頼できる状態に戻すことが狙いである。

#### 作業内容
1. tool_definitions の意図する重大度ポリシーを確認する (製品オーナー/運用担当への確認事項)。
2. 確認結果が「常に WARNING」であれば、`_is_fatal_severity()` の適用対象から tool_definitions を除外し、常に `StartupCheckStatus.WARNING` を返すよう `_check_tool_definitions_finding()` を修正する。
3. 確認結果が「統一スキーム (strict/production で FATAL) が正しい」であれば、`docs/05_agent_10_01_operations-and-observability-startup-and-health.md` の該当記述を実装に合わせて更新する。
4. 決定した挙動を固定化するテストを追加する (production かつ tool_definitions 不一致のケースで FATAL/WARNING いずれになるかを明示的に検証する)。

#### 受け入れ条件
- ドキュメントと実装の tool_definitions 重大度判定に関する記述が一致している。
- production かつ `tool_definitions_strict=False` で tool_definitions 不一致が発生した場合の挙動 (FATAL か WARNING か) が一意に定義され、テストで固定化されている。
- 既存テストが通る。
