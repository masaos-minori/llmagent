# UNK-01: Verify whether `BLE001`/`PLC0415` noqa codes are actually enforced by the project's ruff configuration

## Title
`scripts/agent/startup.py` uses `# noqa: BLE001` / `# noqa: PLC0415`, but `pyproject.toml`'s ruff
`select` list does not include those rule families

## Description
While planning a comment-only change to add inline justifications to `# noqa` suppressions in
`scripts/agent/startup.py` (plan: `plans/20260806-105228_plan.md`), it was noticed that
`pyproject.toml` configures:

```toml
[tool.ruff.lint]
select = ["E", "W", "F", "I", "UP"]
```

This selects only pycodestyle errors/warnings (`E`, `W`), pyflakes (`F`), isort (`I`), and
pyupgrade (`UP`). It does not select `BLE` (flake8-blind-except, which provides `BLE001`) or `PLC`
(pylint convention codes, which provides `PLC0415`). `RUF100` (ruff's own unused-noqa detector) is
also not selected.

`tox.ini`'s `lint` environment only runs `ruff format --check` and `ruff check` — no pylint or
flake8 is configured anywhere in the repo (confirmed via `grep` over `pyproject.toml` and
`tox.ini`).

This raises the question of whether `# noqa: BLE001` and `# noqa: PLC0415` comments throughout the
codebase (not just in `startup.py` — the same codes appear in `tests/mcp_servers/mdq/*.py` and
elsewhere) are suppressing a rule that ruff would never have raised in the first place under the
current `select` list, i.e., whether they are inert/decorative rather than functional
suppressions.

## Context
- Discovered during: requirement-to-plan workflow for
  `requires/20260806-103649_require.md` (now at `requires/done/20260806-103649_require.md`).
- Relevant files: `pyproject.toml` (lines 88-91, `[tool.ruff.lint]` section), `tox.ini` (lines
  1-29), `scripts/agent/startup.py` (7 `# noqa` occurrences using `BLE001` and `PLC0415`).
- This is explicitly out of scope for the requirement that surfaced it (which is a narrow,
  comment-text-only change) and is filed here as a non-blocking follow-up per the
  require-to-plan workflow's Step 5 (unresolved, non-blocking unknowns get filed as issues).

## Suggested resolution
- Determine whether `BLE` and `PLC0415`'s rule family are intentionally excluded from
  `[tool.ruff.lint] select` in `pyproject.toml`, or whether they were expected to be included
  (e.g., if the project previously used flake8-blind-except/pylint directly, or a different ruff
  version/config).
- If intentionally excluded: consider whether the `# noqa: BLE001` / `# noqa: PLC0415` comments
  across the codebase should instead cite a code from the actually-selected rule set (or be
  removed if the underlying lint tool never flags that line), to avoid comments that look like
  functional suppressions but are not.
- If unintentionally excluded: consider adding `"BLE"` and/or the relevant `PLC` codes to
  `select`, then re-running `ruff check` project-wide to see what newly surfaces before deciding
  whether to fix or suppress each finding (with a proper justification per
  `rules/coding.md` §Suppression governance).
- This should be scoped as its own requirement/plan, not folded into the current comment-text-only
  change, since it could surface real new lint findings across many files.
