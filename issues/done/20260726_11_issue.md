## [http_lifecycle] MCP subprocess command injection via cfg.cmd

### Summary

`HttpServerLifecycleManager.start()` で MCP サーバーのサブプロセス起動時に構成ファイル由来のコマンドが直接実行される。構成ファイルの所有権が不明確な環境では悪意ある値が含まれる可能性があり、シェルインジェクション vulnerability が存在する。

### Problem

`http_lifecycle.py:230` で `cfg.cmd` が `subprocess.Popen()` に渡されている：

```python
proc = subprocess.Popen(
    cfg.cmd,
    stdout=subprocess.DEVNULL,
    stderr=stderr_fh,
    env=env,
    start_new_session=True,
)
```

コメントには「cmd comes from admin-controlled config」とあるが、構成ファイルの所有権が不明確な環境では悪意ある値が含まれる可能性。特に `cfg.cmd` がリスト形式でない場合（文字列の場合）、シェル経由で展開され、インジェクションされる。

### Affected Files

- `scripts/agent/http_lifecycle.py:230` — `start()` メソッド内の `subprocess.Popen()` 呼び出し
- `shared/mcp_config.py` — `McpServerConfig` の定義

### Attack Scenario

1. 構成ファイルの改ざんにより `cfg.cmd` に `'bash -c "malicious_command"'` のような値が含まれる
2. リスト形式でない場合、シェル経由で展開され、任意コード実行が可能になる
3. サブプロセスは `start_new_session=True` で実行されるため、親プロセスの制御下から外れる

### Severity

Critical — 構成ファイルの改ざんにより任意コード実行が可能。

### Mitigation

- `cfg.cmd` がリスト形式であることを強制し、文字列の場合はシェル展開しないよう明示する
- `shlex.split()` を使用して安全に解析する
- コマンドのホワイトリストを検証する
