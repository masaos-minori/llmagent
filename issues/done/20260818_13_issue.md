# [LOW] Standardize document templates, minimum behavioral contracts, and diagrams

## Priority

Low

## Background

Document structures differ significantly between document classes.

Some sections defer entirely to source code without documenting the responsibility, side effects, failure behavior, concurrency constraints, or security boundary required for design understanding.

Complex ASCII diagrams are also fragile and may be corrupted during concatenation or rendering.

## Reason for Change

Templates improve consistency and make new documents easier to validate.

Minimum behavioral contracts prevent specifications from becoming simple file indexes.

Maintained diagrams improve readability while preserving architectural relationships.

## Intent

Provide reusable templates and minimum design contracts without duplicating full implementation details already available in source code.

## Tasks

### Templates

1. Create templates for:

   - Governance
   - Guide
   - Specification
   - Reference
   - Operations
   - Note
   - Known Issues

2. Include required Front Matter.
3. Identify required and optional sections.
4. Include evidence and related-document conventions.

### Minimum Behavioral Contracts

5. Find sections that only state "refer to the source code."
6. Add, where relevant:

   - Responsibility
   - Input contract
   - Output contract
   - Side effects
   - Failure behavior
   - Idempotency
   - Concurrency constraints
   - Security boundary

7. Avoid duplicating full implementation APIs.

### Diagrams

8. Convert complex ASCII diagrams to Mermaid or approved maintained image assets.
9. Prioritize:

   - Process architecture
   - RAG ingestion flow
   - RAG query flow
   - Workflow approval flow
   - EventBus recovery flow

10. Preserve accessible text alternatives.
11. Verify GitHub rendering.

## Acceptance Criteria

- [ ] Templates exist for all document classes.
- [ ] Templates include required metadata.
- [ ] Required and optional sections are identified.
- [ ] Evidence conventions are included.
- [ ] Public components include minimum behavioral contracts.
- [ ] Full implementation details remain in source code.
- [ ] Priority diagrams render correctly in GitHub.
- [ ] Text alternatives remain available.
- [ ] Documentation guidance links to the templates.

## Validation

1. Create one sample document from each template.
2. Validate required metadata and sections.
3. Review one behavioral contract in every major area.
4. Render all converted diagrams.
5. Verify text alternatives remain usable.

## Out of Scope

- Redesigning the project architecture
- Replacing source-code API documentation
- Generating diagrams from runtime telemetry
