# Add Documentation Drift Detection

## Objective

Add a repeatable process for detecting inconsistencies between implementation and project documentation.

## Reason

The workflow reads project documents but does not systematically compare them with code, configuration, routing, and deployment behavior.

## Intent

Report documentation drift as evidence-based findings without automatically deciding whether the code or document is authoritative.

## Tasks

- Extend Step 3 with Documentation Drift Detection.
- Compare relevant implementation details with:
  - `routing.md`
  - `AGENTS.md`
  - `README`
  - design documents
  - coding and toolchain rules
  - configuration specifications
  - deployment definitions
- Record:
  - document
  - implementation evidence
  - drift description
  - confidence
  - possible source of truth
  - suggested follow-up
- Classify uncertain results as `Unverified` or `Ambiguous Source of Truth`.
- Do not modify documentation unless it is explicitly included in the approved scope.
- Do not automatically treat either documentation or implementation as correct.

## Out of Scope

- Automatic documentation updates
- Repository-wide documentation audits
- Architecture Smell detection
- Deprecated analysis

## Acceptance Criteria

- Documentation Drift Detection is defined.
- Every finding includes evidence and confidence.
- Uncertainty is reported explicitly.
- Documentation changes remain opt-in.
- Adjacent findings do not expand the approved implementation scope.
