## eventbus/db.pyのスキーマ移行にガードテストを追加 (TASK-M2 / EVENTBUS-4)

### Summary

旧スキーマ(`retry_count`列)からの移行テストが存在しない。文字列マッチ判定はSQLiteのエラーメッセージ変更に脆弱。

### Problem

`eventbus/db.py:61-100` (`_migrate`) の移行ロジックが完全に未テスト:

```python
def _migrate(db):
    # 旧スキーマ検出
    if "retry_count" in columns:
        # 移行処理
        db.execute("ALTER TABLE ... ADD COLUMN delivery_failure_count INTEGER")
        db.execute("ALTER TABLE ... ADD COLUMN dlq_requeue_count INTEGER")
```

移行中の例外発生時にDBが破損しないことも未検証。

### Affected Files

- `scripts/eventbus/db.py:61-100` — `_migrate` 移行ロジック
- `tests/test_eventbus_db_migration.py` — 新設

### Severity

High — High-risk-refactor判定。旧スキーマ移行のリグレッション検知不可

### Root Cause

移行再現テストなし

### Mitigation

旧スキーマ(`retry_count`列あり)のSQLiteファイルをfixtureとして用意し、`_migrate`実行後に新カラム(`delivery_failure_count`, `dlq_requeue_count`)が正しく存在すること、既存データが失われないことを検証

### Acceptance Criteria

- 新規テストpass
- 既存データの非破壊を確認

### Dependencies

TASK-H5(eventbusレイヤー独立性修正)より先に実施推奨。同一ファイルへの変更が重なるため
