## [injection][orchestrator] Memory snippet injection influences LLM behavior

### Summary

`on_user_prompt()` で取得されたメモリスニペットが `"role": "system"` メッセージとして会話履歴に注入される。これにより、ユーザーの入力に対して LLM の振る舞いが影響を受ける可能性がある。

### Problem

`orchestrator.py:373-391` で、`MemoryInjectionService.on_user_prompt()` から取得されたスニペットが以下のように注入される：

```python
memory_block = "[Relevant memories]\n" + "\n".join(
    f"- {snippet.text}" for snippet in memory_snippets
)
ctx.conv.history.append(
    {
        "role": "system",
        "content": memory_block,
        "_memory_injected": True,
    }
)
```

`injection.py:110-155` で、`on_user_prompt()` はクエリに基づいてセマンティックおよびエピソードメモリを検索し、スニペットを構築する。これらのスニペットは LLM のシステムコンテキストとして注入されるため、LLM の応答に影響を与える。

さらに、`injection.py:84` および `injection.py:100` では、`entry.summary` が存在しない場合、`entry.content[:100]` がプレフィックスとして使用される。これはコンテンツの先頭100文字のみを切り取ることを意味し、重要な情報が欠落する可能性がある。

### Affected Files

- `scripts/agent/orchestrator.py:373-391` — `_handle_memory_injection()`
- `scripts/agent/memory/injection.py:110-155` — `on_user_prompt()`
- `scripts/agent/memory/injection.py:84`, `100` — スニペット構築ロジック

### Attack Scenario

1. ユーザーが特定のクエリを送信
2. LLM が意図的にメモリ検索をトリガーするクエリを生成
3. 検索結果のスニペットがシステムメッセージとして注入
4. LLM がこれらのスニペットに基づいて、ユーザーの意図とは異なる振る舞いを開始

### Severity

Medium — メモリスニペットが LLM のシステムコンテキストとして注入される。LLM が意図的に検索をトリガーすることで、望ましくないスニペットを注入できる可能性がある。

### Mitigation

- スニペット注入前にフィルタリングポリシーを追加（機密情報、攻撃的な内容など）
- スニペットの最大長を制限し、過度なコンテキスト注入を防ぐ
- システムメッセージの優先度を明示的に設定し、ユーザーメッセージより低い優先度であることを明文化
