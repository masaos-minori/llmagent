# Reset per-run diagnostics and attribute early-return results correctly

## Priority

High

## Summary

Reset per-run diagnostic state at the beginning of RagPipeline.augment() and record accurate diagnostics for early-return paths.

This issue covers stale diagnostics from HTTP remote execution, HTTP empty success, semantic cache hits, and use_search=False.

## Background

RagPipeline.augment() has several execution paths that can return before RagPipeline.run() is called:

- use_search=False
- HTTP remote success
- HTTP remote empty result
- Semantic cache hit

RagPipeline.run() resets some runtime state, but early-return paths can bypass that reset.

HttpAugment produces a StageResult and http_result_kind, but stale state from a previous run may still remain unless augment() resets state before branching.

## Problem

get_diagnostics() may report stale data from a previous execution.

Examples:

- A local run leaves last_stage_results.
- A later HTTP remote success returns early.
- Diagnostics still show the old local run.
- A cache hit returns cached context but diagnostics still show previous search results.
- _http_result_kind may remain from a previous HTTP call.
- use_search=False may return an empty string without clear diagnostics.

## Fix Reason

Diagnostics must describe the latest execution only.

Stale diagnostics can mislead operators, tests, and AI agents into diagnosing the wrong execution path.

## Implementation Intent

Every call to RagPipeline.augment() should start from a clean diagnostic state and record the actual result path taken.

## Required Changes

### 1. Add a reset helper

Add a private helper such as:

- _reset_run_state()

It should reset:

- last_fetch_result
- last_timings
- last_stage_results
- last_search_diagnostics
- _http_result_kind

If _http_result_kind is stored dynamically, remove it or set it to None.

### 2. Call reset at the start of augment()

Call the reset helper before any early return logic.

This must happen before:

- use_search check
- HTTP augment
- semantic cache lookup
- DB open
- local pipeline run

### 3. Record diagnostics for use_search=False

When search is disabled, record a clear diagnostic state.

Recommended values:

- search_status=search_disabled
- empty_result_reason=search_disabled

### 4. Record diagnostics for semantic cache hits

When semantic cache returns a cached result, record that the result came from cache.

Choose one minimally invasive approach:

- Add cache_hit=true to diagnostics
- Or add StageResult with stage_name=SemanticCache and status=success

The implementation should not expose stale search results from a previous run.

### 5. Preserve HTTP diagnostics

When HTTP remote mode is used, keep:

- HttpAugment.stage_result
- http_result_kind
- remote status code
- remote latency
- SearchDiagnostics.result_source
- SearchDiagnostics.http_result_kind

HTTP result "" must remain a valid remote empty success, not fallback.

### 6. Ensure local execution clears prior HTTP state

When local execution runs after a previous HTTP run, HTTP-specific diagnostics from the prior run must not remain unless relevant to the current run.

## Acceptance Criteria

- get_diagnostics() never contains stale stage results from a previous run.
- HTTP remote success does not expose previous local search diagnostics.
- HTTP remote empty result is classified as success, not fallback.
- Semantic cache hit does not expose previous search diagnostics.
- use_search=False produces explicit diagnostics.
- Local run after HTTP run does not retain previous HTTP result kind.
- HTTP run after local run does not retain previous local stage results.
- Diagnostics represent the latest augment() call only.

## Tests Required

Add or update tests for:

- Local run followed by HTTP remote success
- HTTP remote success followed by local run
- HTTP remote empty result
- Local run followed by semantic cache hit
- use_search=False
- HTTP fallback followed by local pipeline execution

## Files to Modify

- scripts/rag/pipeline.py
- scripts/rag/models_result.py
- scripts/rag/http_augment.py
- tests/test_rag_pipeline.py
- tests/test_rag_quality_regression.py

## Out of Scope

- Changing HTTP retry or timeout behavior
- Changing HTTP empty-result semantics
- Refactoring HttpAugment into another class
