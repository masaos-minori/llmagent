# Clarify migration scope, recovery terminology, and approval traceability in ADR-008

## Priority
Medium

## Summary
Clarify `docs/10_adr/adr_02_05_008_db-sqlite-4db-separation.md` without changing migration behavior, database ownership, or recovery policy: narrow the migration exclusion, separate automatic from manual recovery, distinguish authoritative stores from canonical tables, and map amendments to approval evidence.

## Background
Confirmed by reading the current file (Explicit in file):
- Constraints (line 60) define per-DB migration policies (recreate for `rag.sqlite`/`session.sqlite`; forward-only gated migrations for `workflow.sqlite`/`eventbus.sqlite`) while Out of Scope lists "Migration and Schema versioning strategy" broadly.
- INV-01 calls `rag.sqlite` the canonical store for documents, chunks, FTS5, and the Vector Index, while Decision item 20 and the glossary treat FTS5 and the vector index as derived data rebuilt from `chunks`.
- The Recovery Policy Matrix says "none" for the supported recovery source of `workflow`/`eventbus`, while manual operator recovery is documented elsewhere (Decision item 20, `agent_10_01`).
- The dbmig001 Amendment (2026-10-30) cites the task-level approval decision, and the Approval Record states individual approval dates are not recorded.

## Problem
A broad Out of Scope line can undermine a normative decision in the same document. "No recovery source" can be read as prohibiting all recovery. "Canonical store" conflates the authoritative database file with canonical source tables. Which amendments form the current approved decision is not traceable.

## Reason for Change
Readers and implementers need to know which migration decisions the ADR governs. It is Medium because it is a non-critical documentation inconsistency that does not change behavior. Nothing makes it time-sensitive.

## Implementation Intent
Clarify the existing architecture only. State that selecting the recreate versus forward-only policy is in scope, and detailed migration steps and schema-version mappings are delegated. Separate automatic recovery capabilities from manual procedures. Describe FTS5 and vector indexes consistently as derived data inside the authoritative `rag.sqlite`. Map each amendment to the approval evidence that actually exists and state plainly where none exists.
