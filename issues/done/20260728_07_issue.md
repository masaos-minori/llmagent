# Fix document freshness handling and HTTP re-ingestion logic

## Priority
High

## Type
Bug fix / Data freshness / Ingestion reliability

## Background
The ingestion DocumentManager handles existing documents and delegates ETag / Last-Modified updates to ETagManager. However, the current implementation passes a fixed doc_id=0 to ETagManager instead of the actual existing document ID.

Existing HTTP/HTTPS documents are also skipped after metadata update, which can prevent changed HTTP documents from being re-ingested.

## Problem
The freshness metadata update is applied to doc_id=0, which is normally not the actual document. Therefore, the target document's ETag, Last-Modified, and fetched_at may not be updated.

Additionally, changed HTTP documents may be skipped without updating chunks or embeddings unless --force is used.

## Fix Intent
The intent is to make ingestion freshness correct and automatic:

- Existing document metadata must be updated using the correct doc_id.
- HTTP documents should be skipped only when they are unchanged.
- Changed HTTP documents should be re-ingested without requiring --force.
- Existing file:// SHA-256 behavior should remain intact.

## Implementation Tasks
- Replace ETagManager(self._db, 0) with ETagManager(self._db, existing_doc_id).
- Update DocumentManager._update_etag() to accept existing_doc_id.
- Compare incoming ETag and Last-Modified values with stored metadata.
- Define the decision matrix:
  - Unchanged ETag / Last-Modified: update freshness metadata if needed and skip.
  - Changed ETag or Last-Modified: delete the existing document chain and re-ingest.
  - Missing metadata: keep the current conservative behavior, but document it.
- Preserve stale fetched_at protection in ETagManager.
- Review _update_with_freshness() behavior when either etag or last_modified is None.
- Avoid overwriting existing non-null metadata with None unless explicitly intended.

## Acceptance Criteria
- No ETag update path uses doc_id=0.
- Existing HTTP documents with a changed ETag are re-ingested.
- Existing HTTP documents with an unchanged ETag are skipped safely.
- Existing file:// SHA-256 re-ingestion behavior is not broken.
- fetched_at stale update protection still works.
- Metadata is not accidentally overwritten with None unless this is the defined behavior.

## Tests
- Add a unit test proving existing_doc_id is passed to ETagManager.
- Add a test proving doc_id=0 is not used.
- Add a test for unchanged HTTP document skip.
- Add a test for changed HTTP ETag re-ingestion.
- Add a test for Last-Modified-only changes.
- Add a test for stale fetched_at behavior.
- Add a test for partial None metadata update behavior.

## Out of Scope
- Implementing crawler-side conditional HTTP requests.
- Changing the documents table schema.
