## [NC-017] SQLiteSessionStoreの実際の呼び出し元が本調査の範囲では確認できない

### Summary

`SQLiteSessionStore`(`scripts/db/store_impl.py`)は `SessionStore` プロトコルの実装として存在するが、現行のREPL/エージェント実行経路(`AgentSession`)はこれを経由せず `SQLiteHelper` を直接呼び出している。`SQLiteSessionStore` の実際の呼び出し元が調査範囲内では確認できていない。

### Problem

- `docs/05_agent_09_01_data-layer-session-db.md:115,121`:
  > **現在の実装挙動(要確認含む):** `SQLiteSessionStore` は `scripts/db/store_impl.py` に実装され、`db/store_protocols.py` の `SessionStore` プロトコルの実装として存在する。ただし現状のREPL/エージェント実行経路(`agent/session.py` の `AgentSession`)は `SQLiteSessionStore` を経由せず、`SQLiteHelper` を直接呼び出して `sessions`/`messages` を操作している。...`SQLiteSessionStore` の実際の呼び出し元は本調査の範囲では確認できなかった(Needs confirmation)。

### Affected Files

- `docs/05_agent_09_01_data-layer-session-db.md`(§SQLiteSessionStore callers、115-121行目付近)
- `scripts/db/store_impl.py`(`SQLiteSessionStore` 実装)
- `scripts/agent/session.py`(`AgentSession`、直接 `SQLiteHelper` を呼び出す現行経路)

### Classification

**Low** — Dead classの可能性があるが、プロトコル実装として意図的に維持されている可能性もある(テスト用モック差し替え等)。

### Evidence

- Documentation only — ドキュメント上に明示的な `Needs confirmation` ラベルとして記載。

### Recommended next action

- テストコードを含めたコードベース全体で `SQLiteSessionStore` の利用箇所を検索する。
- 呼び出し元が存在しない場合、`AgentSession` が `SessionStore` プロトコル抽象を経由しない設計になっている経緯を確認し、`SQLiteSessionStore` の要否を判断する。
