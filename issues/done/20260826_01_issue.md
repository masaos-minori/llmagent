# Refactoring Analysis Foundation

## Objective

Extend `04_refactor.md` with a structured analysis process for technical debt and responsibility boundaries.

## Reason

The current workflow protects behavior but does not clearly separate discovered problems from approved implementation work. It also lacks a consistent method for analyzing function and class responsibilities.

## Intent

Allow AI to identify and report refactoring opportunities without expanding the approved change scope.

## Tasks

- Define:
  - Finding
  - Candidate
  - Proposal
  - Approved Change
  - Blocked
  - Not Applicable
- State that discovery does not authorize implementation.
- Require evidence for every finding.
- Extend Step 3 with Technical Debt Discovery.
- Support:
  - duplicate logic
  - duplicate validation
  - unclear ownership
  - excessive indirection
  - responsibility concentration
  - testability concerns
- Record for each finding:
  - ID
  - category
  - severity
  - evidence
  - impact
  - recommendation
- Extend Step 3 with Responsibility Analysis.
- Record:
  - responsibilities
  - dependencies
  - side effects
  - state ownership
  - branching
- Report split candidates without implementing them automatically.

## Out of Scope

- Path C
- Architecture Smell detection
- Deprecated analysis
- Automatic fixes

## Acceptance Criteria

- Analysis and implementation are explicitly separated.
- Technical debt findings require evidence.
- Responsibility Analysis is defined.
- Findings do not expand the approved scope.
- Existing safety rules remain unchanged.
