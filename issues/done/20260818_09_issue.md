# [MEDIUM] Clarify mandatory workflow execution and define high-risk approval policy

## Priority

Medium

## Background

WorkflowEngine execution and workflow-definition deployment are mandatory, but human approval is controlled separately by workflow policy.

Current wording may incorrectly imply that mandatory workflow execution requires human approval for every task.

The production approval policy for high-risk operations is also insufficiently defined.

## Reason for Change

Conflating workflow execution with approval creates two risks:

- Approval may be bypassed because a workflow exists.
- Workflow execution may be incorrectly disabled to avoid approval.

High-risk operations require explicit approval rules rather than relying on defaults.

## Intent

Separate three independent concepts:

1. WorkflowEngine execution is mandatory.
2. Workflow-definition deployment is mandatory.
3. Human approval is controlled by workflow policy and risk tier.

## Tasks

1. Update Overview, Deployment, Agent, workflow, and ADR documents.
2. Document `require_approval` behavior.
3. Define production approval requirements for:

   - File writes
   - File deletion
   - Shell execution
   - Git commits and pushes
   - GitHub changes
   - CI/CD execution
   - Database maintenance

4. Map approval requirements to risk tiers.
5. Define local-development exceptions.
6. Define approval, rejection, expiration, missing approval, cancellation, and resume behavior.
7. Ensure workflow definitions and configuration enforce the documented policy.

## Acceptance Criteria

- [ ] Mandatory workflow execution is documented separately from approval.
- [ ] Mandatory workflow deployment is documented separately from approval.
- [ ] Human approval is explicitly policy-controlled.
- [ ] All high-risk operation categories have production approval rules.
- [ ] Approval requirements map to risk tiers.
- [ ] Local exceptions are documented.
- [ ] Rejection, expiration, cancellation, and resume behavior are defined.
- [ ] Configuration or workflow definitions enforce the policy.
- [ ] Automated tests cover mandatory approval categories.
- [ ] All affected documents use consistent terminology.

## Validation

1. Verify startup fails without a workflow definition.
2. Run low-risk and high-risk operations.
3. Test approval, rejection, expiration, and cancellation.
4. Verify local and production profiles separately.

## Out of Scope

- Replacing WorkflowEngine
- Redesigning the workflow schema
