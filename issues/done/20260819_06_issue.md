# [Low] Replace compatibility tests and align documentation with the strict contracts

## Priority

Low

## Summary

Remove tests and documentation that describe or accept deleted compatibility behavior, add explicit rejection coverage, and document only the current strict contracts.

## Reason for Change

Tests that assert acceptance of legacy aliases, missing fields, timestamp fallbacks, or implicit type coercion would force obsolete behavior to remain in the implementation. Documentation that still describes those paths would also mislead maintainers and AI implementation agents into restoring compatibility that is intentionally removed.

Because no legacy data exists and no migration is performed, the repository must describe only the current MCP Schema 2.0 and strict RAG contracts. Historical entries may remain only when clearly marked as unsupported history, not as available aliases or migration paths.

## Implementation Intent

Replace compatibility acceptance tests with rejection tests that lock in the new boundary behavior. Update architecture, API, DTO, Store Protocol, database, and operational documentation so required fields, nullable values, canonical timestamps, unsupported legacy fields, and regeneration procedures exactly match the code.

Do not preserve compatibility solely to reduce test changes.

## Scope

- MCP routing and discovery tests
- RAG ingestion, storage, and schema tests
- MCP Schema 2.0 documentation
- Tool routing documentation
- RAG pipeline documentation
- DTO and Store Protocol documentation
- Database schema documentation
- Deprecated-items documentation

## Implementation Tasks

- [ ] Remove tests that require `ToolRouteResolver` to accept legacy constructor inputs.
- [ ] Remove tests that accept `input_schema`.
- [ ] Remove tests that accept legacy `resource_scope`.
- [ ] Remove tests that accept `/v1/tools` without `schema_version`.
- [ ] Remove tests that accept RAG payloads without mandatory fields.
- [ ] Remove tests for timestamp fallback or null-fill behavior.
- [ ] Remove tests for `chunk_index` coercion or fallback to zero.
- [ ] Remove tests for language, chunk type, strategy, or source-file defaults.
- [ ] Add rejection tests for every deleted compatibility format.
- [ ] Add current-format end-to-end tests.
- [ ] Document the canonical UTC `fetched_at` format.
- [ ] Document mandatory keys separately from nullable values.
- [ ] Document `inputSchema`, `resource_scope_kind`, and `resource_scope_keys` as the only supported MCP fields.
- [ ] Remove migration guidance and compatibility-period language.
- [ ] Update Deprecated Items so historical entries cannot be mistaken for supported aliases.
- [ ] Correct spelling, grammar, identifier casing, and terminology throughout affected documentation.

## Required Rejection Coverage

- `input_schema` without `inputSchema`
- Legacy `resource_scope`
- Missing or unsupported MCP `schema_version`
- Missing RAG `fetched_at`
- Timezone-naive or malformed `fetched_at`
- String, boolean, or negative `chunk_index`
- Missing mandatory fields
- Invalid `chunk_type` or `chunking_strategy`
- Empty `source_file`
- Crawl/chunk `artifact_type` mismatch
- Unknown fields when the selected strict policy rejects them

## Constraints

- Do not document data migration procedures.
- Do not retain compatibility behavior solely to satisfy existing tests.
- Use the exact identifiers and casing implemented in code.
- Keep historical notes clearly separated from supported behavior.

## Acceptance Criteria

- [ ] No test asserts acceptance of a removed compatibility format.
- [ ] Every removed format has an explicit rejection test.
- [ ] Current-format end-to-end tests pass.
- [ ] Documentation matches implemented validation, storage, and timestamp behavior.
- [ ] No stale migration, alias, or fallback guidance remains.
- [ ] Spelling, grammar, and terminology are consistent.
- [ ] The full repository test suite passes.

## Validation

rg -n "backward compat|legacy|input_schema|resource_scope|_update_null_fill|fallback|migration" docs scripts tests
pytest -q
```
