## [repl] Signal handler race condition with shared state

### Summary

シグナルハンドラ `_sigterm_handler()` が共有状態（`shutdown_requested`, `_input_coro`）を直接変更しており、メインループとの間でレースコンディションが発生する可能性がある。

### Problem

`repl.py:542-597` でシグナルハンドラが定義されている：

```python
def _sigterm_handler() -> None:
    self._ctx.conv.shutdown_requested = True
    if self._shutdown_event is not None:
        self._shutdown_event.set()
    if self._input_coro is not None and not self._input_coro.done():
        try:
            self._input_coro.cancel()
        except RuntimeError:
            pass
```

Unix系OSでは `loop.add_signal_handler()` が使用されるが、Windowsでは `loop.call_soon_threadsafe()` が使用される。両者の違いにより、シグハンドラの呼び出しタイミングが異なる。

また、`_repl_loop` で `self._turn_active` フラグが設定・解除されるが、シグナルハンドラはこのフラグを確認していない。シグナルハンドラが実行中にメインループが `self._turn_active = False` を実行すると、状態の不整合が発生する可能性がある。

さらに、`_close_resources()` で `ctx.services` が None の場合にスキップされるが、シグナルハンドラが実行された直後に `ctx.services` が None になる可能性があり、その場合シャットダウンが不完全になる。

### Affected Files

- `scripts/agent/repl.py:542-597` — `_sigterm_handler()`
- `scripts/agent/repl.py:339-379` — `_repl_loop()`
- `scripts/agent/repl.py:245-336` — `_close_resources()`

### Attack Scenario

1. メインループが `self._turn_active = True` を設定
2. シグナルハンドラが実行され `shutdown_requested = True` を設定
3. シグナルハンドラ終了後、メインループが `self._turn_active = False` を実行
4. シャットダウンフラグが設定されたが、`_turn_active` が False になっているため、状態が不整合

### Severity

Low-Medium — シングルスレッドの asyncio ループ内ではシグナルハンドラの実行中は他のコードが実行されないため、実際のリスクは低い。ただし、複数スレッドの環境では問題が発生する可能性がある。

### Mitigation

- シグナルハンドラ内で `self._turn_active` フラグも確認・設定する
- WindowsとUnixでシグナルハンドラの挙動の違いを文書化する
- シャットダウン処理の前に `self._turn_active` が False であることを確認するガードを追加
