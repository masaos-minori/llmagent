## [repl] WAL file backup path traversal vulnerability

### Summary

`_close_resources()` で WAL ファイルのバックアップパスを構築する際、データベースファイルのパスがそのまま使用されており、パストラバーサルの可能性がある。

### Problem

`repl.py:296-314` で WAL ファイルのバックアップが行われる：

```python
db_path = db.execute("PRAGMA database_list").fetchone()[1]
if db_path:
    wal_file = f"{db_path}-wal"
    backup_dir = os.path.dirname(db_path) or "/tmp"
    wal_backup_path = os.path.join(
        backup_dir,
        f"{os.path.basename(db_path)}-wal-backup-{int(time.time())}",
    )
    shutil.copy2(wal_file, wal_backup_path)
```

`PRAGMA database_list` から取得された `db_path` は検証されていない。もしデータベースファイルがシンボリックリンクで、外部ディレクトリを指している場合、WAL ファイルのバックアップ先が予期せぬ場所になる可能性がある。

また、`backup_dir` が `/tmp` のようなシステムディレクトリの場合、他のプロセスが同じ名前のファイルを作成する競合が発生する可能性がある。

### Affected Files

- `scripts/agent/repl.py:296-314` — WAL ファイルバックアップロジック

### Attack Scenario

1. データベースファイルがシンボリックリンクで、外部ディレクトリを指している
2. WAL ファイルのバックアップ先が予期せぬディレクトリになる
3. バックアップ先のディレクトリに書き込み権限がない場合、エラーが発生する

### Severity

Low — シングルユーザー環境ではリスクは低い。ただし、マルチテナント環境やコンテナ環境では問題が発生する可能性がある。

### Mitigation

- `db_path` が正規化された絶対パスであることを確認する
- シンボリックリンクのターゲットを検証する
- バックアップ先のディレクトリが存在することを確認する
