## 起動失敗時、spawn済みMCPサブプロセスを直接terminateするフォールバックが常に空リストで無効化されている

### Summary

`StartupOrchestrator` は起動失敗時にMCPサブプロセスを二重の仕組みでクリーンアップする設計になっているが、片方(`_spawned_subprocesses` を経由した直接 `terminate()`)が実装漏れにより常に無効。`lifecycle.shutdown_all()` が何らかの理由で失敗した場合、起動中にspawnしたサブプロセスが確実に孤立する。

### Problem

- `scripts/agent/startup.py:66` で `self._spawned_subprocesses: list[subprocess.Popen] = []` と初期化されるが、この属性はコード中どこにも `.append()` されていない。
- `scripts/agent/startup.py:128-167` の `_start_servers()` は実際にspawnしたプロセスをローカル変数 `spawned` に蓄積して `return spawned` するが、`run()`(62-89行目)はこの戻り値を代入せずに破棄している。
- `run()` の成功時の戻り値も `return self._cmds, self._orchestrator, []`(89行目)で常に空リスト固定。
- 呼び出し元 `scripts/agent/repl.py:736-748` は次のコメントの通り、成功パス・例外パスの両方でプロセスをterminateするフォールバックを意図している:
  ```python
  # Terminate any subprocesses started during partial startup
  # Check both local variable (success path) and instance variable (exception path)
  all_procs = _spawned_subprocesses
  if hasattr(startup, "_spawned_subprocesses"):
      all_procs = list(all_procs) + list(startup._spawned_subprocesses)
  for proc in all_procs:
      if proc.poll() is None:
          proc.terminate()
  ```
  しかし `_spawned_subprocesses` (戻り値・インスタンス属性とも)が常に空のため、このループは実質何もしない。
- 現状の唯一のクリーンアップ経路は `scripts/agent/startup.py:74-84` の `except` 節が呼ぶ `lifecycle.shutdown_all()`(`_ServerLifecycleRouter` 内部の `_http_procs` 辞書ベースの追跡)であり、これが失敗した場合(78-82行目でログのみ、再raiseなし)、他に孤立プロセスを止める手段が一切ない。

### Affected Files

- `scripts/agent/startup.py` — `StartupOrchestrator.run()` / `_start_servers()`
- `scripts/agent/repl.py` — `AgentREPL.run()` 内の起動呼び出しと `finally` 節(736-752行目付近)

### Classification

**High** — 通常運用では `lifecycle.shutdown_all()` が機能する限り顕在化しないが、多重防御の片方が最初から死んでいる状態であり、最後の砦が機能しない。

### Evidence

- Explicit in code (High confidence) — `_spawned_subprocesses` への代入箇所が存在しないことは `grep` で確認済み。

### Recommended next action

- `_start_servers()` の戻り値を `self._spawned_subprocesses` に代入するよう `run()` を修正する。
- 成功時の戻り値も実際に起動済みのプロセスリストを返すよう修正する(現状 `list[subprocess.Popen]` という型シグネチャが意味を持たないデッドコードになっている)。
- `lifecycle.shutdown_all()` が例外を送出するケース(シグナル処理エラー等)を注入するテストを追加し、`repl.py` 側のフォールバックが実際に機能することを確認する。
