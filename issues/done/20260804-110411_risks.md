# Residual risk: `test_different_subsections_in_load_all_merged` never calls the real `load_all()` merge code

## Priority
Medium

## Context

**Source plan:** `plans/20260804-105925_plan.md`
**Source requirement:** `requires/done/20260804-100530_require.md`
**Related target files:** `tests/shared/test_shared_boundary_conditions.py`
(`TestDictMergeConflictResolution::test_different_subsections_in_load_all_merged`),
`scripts/shared/config_loader.py` (`ConfigLoader.load_all()`, lines 68-94)

## Description

While resolving `tests/shared/test_config_loader.py::TestMergeOrder::test_nested_dict_merge`
(fixing it to call `loader.load_all()` for real, per the sibling plan above), it was discovered
that `load_all()` always iterates over the module-level constant `_BASE_CONFIG_FILES`
(`scripts/shared/config_loader.py:28`), which currently holds a single filename
(`("agent.toml",)`). There is no parameter on `load_all()` to pass alternate filenames.

`tests/shared/test_shared_boundary_conditions.py::TestDictMergeConflictResolution::
test_different_subsections_in_load_all_merged` (lines 37-62) was apparently already written against
this same constraint, and its own in-line comment says so directly:

```python
# load_all merges dict-valued keys one level deep
# We need to manually combine since load_all only loads _BASE_CONFIG_FILES
result_a = loader.load("extra_mcp.toml")
result_b = loader.load("extra_mcp2.toml")
merged: dict[str, Any] = {}
for key, val in result_a.items():
    if isinstance(val, dict) and isinstance(merged.get(key), dict):
        merged[key] = {**merged[key], **val}
    else:
        merged[key] = val
for key, val in result_b.items():
    ...
```

Instead of exercising `ConfigLoader.load_all()` at all, this test calls `loader.load()` twice and
then **hand-copies `load_all()`'s merge algorithm inline** into the test body, asserting against
that hand-rolled copy. The test's own docstring ("Different subsections under the same parent are
merged by `load_all()`") is misleading: it never actually invokes `load_all()`.

## Evidence Missing

Whether this was a deliberate, accepted workaround at the time it was written, or an oversight —
there is no comment or commit message explaining why the sibling plan's now-established technique
(monkeypatching `shared.config_loader._BASE_CONFIG_FILES` via `monkeypatch.setattr(...)`, which
`plans/20260804-105925_plan.md` verified works and is consistent with an existing precedent in
`tests/eventbus_helpers.py:29`) was not used here instead.

## Why this matters

If `ConfigLoader.load_all()`'s real merge logic (`config_loader.py:82-93`) ever regresses — e.g. a
future refactor changes the `isinstance(val, dict) and isinstance(merged.get(key), dict)` condition,
or breaks the `{**merged[key], **val}` merge itself — neither this test nor (before the sibling
plan's fix) `TestMergeOrder::test_nested_dict_merge` would catch it, because this test asserts
against a separately-maintained copy of the algorithm that will not drift in sync with the real
one, and the real one would only be exercised by production code paths that all currently load a
single base file (per the sibling plan's Assumption 3).

## Resolution Path

Rewrite `test_different_subsections_in_load_all_merged` to use the same pattern the sibling plan
introduces for `test_nested_dict_merge`:

```python
def test_different_subsections_in_load_all_merged(
    self, tmp_path: Path, monkeypatch: pytest.MonkeyPatch
) -> None:
    """Different subsections under the same parent are merged by load_all()."""
    (tmp_path / "extra_mcp.toml").write_text(
        '[mcp_servers.server_a]\nurl = "http://localhost:1"\n'
    )
    (tmp_path / "extra_mcp2.toml").write_text(
        '[mcp_servers.server_b]\nurl = "http://localhost:2"\n'
    )
    monkeypatch.setattr(
        "shared.config_loader._BASE_CONFIG_FILES",
        ("extra_mcp.toml", "extra_mcp2.toml"),
    )
    loader = ConfigLoader(config_dir=tmp_path)
    result = loader.load_all()
    assert "server_a" in result.get("mcp_servers", {})
    assert "server_b" in result.get("mcp_servers", {})
```

This exercises the real `load_all()` code path instead of a hand-rolled copy, removing the need for
the `Any`-typed manual merge loop entirely. `test_same_subsection_later_file_wins` and
`test_deep_nested_same_subsection_replaced` in the same class both call `loader.load()` directly (not
`load_all()`) and are unaffected by this issue — only `test_different_subsections_in_load_all_merged`
is the one test whose docstring claims `load_all()` coverage it does not actually have.
