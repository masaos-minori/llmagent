## mcp_servers層: デッドコード疑いと異常系テスト不足 (MCP-1, MCP-2, MCP-3, MCP-4)

### Summary

mcp_servers層にデッドコード疑いの関数、OSError捕捉漏れ、ジョブログ取得の非2xx fail-fastとmax_bytes到達truncationの個別テストが見当たらない。

### Problem

| ID | カテゴリ | 対象 | 説明 |
|---|---|---|---|
| MCP-1 | Missing test coverage(デッドコード疑い) | `mcp_servers/server.py:184-205`(_ensure_error_tracking, _record_tool_error) | 全MCPサーバ実装から呼び出し箇所が0件。テストも無し |
| MCP-2 | Missing negative-path test | `mcp_servers/file/read_business.py:165-193`(read_single_file) | stat()がtry/except外にあり、TOCTOU的OSErrorが未捕捉のまま伝播 |
| MCP-3 | Missing test coverage | `mcp_servers/cicd/service_github_actions_job.py:156-189` | ジョブログ取得の非2xx fail-fastとmax_bytes到達truncationの個別テストが見当たらない |
| MCP-4 | Missing boundary-condition test | `mcp_servers/file/delete_service.py:150-156` | ルート直下の重要ディレクトリ再帰削除への特別ガードなし(要件次第) |

### Affected Files

- `mcp_servers/server.py:184-205` — _record_tool_errorデッドコード疑い
- `mcp_servers/file/read_business.py:165-193` — OSError捕捉漏れ
- `mcp_servers/cicd/service_github_actions_job.py:156-189` — ジョブログ取得テスト欠如
- `mcp_servers/file/delete_service.py:150-156` — 重要ディレクトリガード欠如

### Severity

Medium — MCP-1はデッドコードか将来使用予定かの確認が必要。MCP-2はTOCTOUのリスクがある

### Mitigation

1. MCP-1: 全MCPサーバ実装からの呼び出し箇所を確認し、デッドコードなら削除
2. MCP-2: stat()をtry/exceptで囲みOSErrorを捕捉
3. MCP-3: 非2xx fail-fastとmax_bytes truncationのテストを追加
4. MCP-4: ルート直下の重要ディレクトリ再帰削除ガードの有無を確認

### Acceptance Criteria

- MCP-1: デッドコード確認またはテスト追加
- MCP-2: OSError捕捉後のテスト追加
- MCP-3: 2つのケースにテスト追加
- MCP-4: ガードの有無を確認
