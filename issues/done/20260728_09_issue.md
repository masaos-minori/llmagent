# Fix debug pipeline callback compatibility and remote result observability

## Priority
High

## Type
Bug fix / Debuggability / HTTP observability

## Background
The RAG pipeline supports debug capture through a debug_fn callback. RagPipeline.augment() calls this callback with intermediate results and rrf_config.

RagPipelineMCPService._make_capture_fn() currently defines a callback that accepts only positional arguments.

The HTTP delegate also treats remote empty results as valid final results and does not fall back to the in-process pipeline.

## Problem
The debug pipeline may fail with TypeError because the debug callback does not accept rrf_config.

Additionally, remote_empty is a valid final result, but this behavior needs to be explicit and observable. Otherwise, operators may not understand why the local pipeline did not run.

HTTP mode also uses /v1/call_tool, which returns text only. This means selected hit metadata may be unavailable in remote mode.

## Fix Intent
The intent is to make debug and remote execution paths reliable and transparent:

- Debug callbacks should accept all arguments passed by RagPipeline.
- Remote empty behavior should be explicitly documented and visible in diagnostics.
- HTTP mode should expose selected hits where possible.

## Implementation Tasks
- Update the debug capture callback to accept **kwargs.
- Capture rrf_config when provided.
- Include rrf_config in debug output if the response model supports it.
- Add a test where debug_fn is called with rrf_config.
- Document remote_empty as a valid final result, or add fallback_on_remote_empty if desired.
- Ensure diagnostics show:
  - remote_nonempty
  - remote_empty
  - in_process_fallback
- Decide whether HTTP delegation should call /rag_run_pipeline instead of /v1/call_tool.
- If structured remote responses are supported, populate last_fetch_result using selected_hits.
- If selected_hits are unavailable, expose that in diagnostics.

## Acceptance Criteria
- /rag_debug_pipeline does not fail due to unexpected keyword arguments.
- rrf_config is captured or safely ignored without error.
- Remote empty behavior is documented and tested.
- Diagnostics clearly distinguish remote empty from fallback.
- HTTP mode either returns selected_hits or clearly reports that selected_hits are unavailable.

## Tests
- Add a test for debug_fn(..., rrf_config=...).
- Add an integration-style test for run_debug_pipeline().
- Add tests for remote non-empty, remote empty, and in-process fallback.
- Add a test for HTTP mode selected_hits when a structured response is available.
- Add a test for legacy text-only remote responses.

## Out of Scope
- Redesigning the MCP protocol globally.
- Changing local ranking behavior.
