## CIブランチ名不整合 (TASK-H6 / CI-1)

### Summary

CIの `diff-cover --compare-branch=main` と `.github/workflows/ci.yml` の `branches:[main]` が本リポジトリの実態(`master`)と一致していない。diff-coverはローカルで即エラー、CIのpush/PRトリガーも発火しない可能性が高い。

### Problem

```yaml
# .github/workflows/ci.yml
on:
  push:
    branches: [main]     # mainが存在しない
  pull_request:
    branches: [main]     # mainが存在しない

steps:
  - name: diff-cover gate
    run: uv run diff-cover coverage.xml --compare-branch=main --fail-under=90
```

```bash
# ローカルでも失敗
$ uv run diff-cover coverage.xml --compare-branch=main --fail-under=90
fatal: ambiguous argument 'main...HEAD'
```

### Affected Files

- `.github/workflows/ci.yml` — ブランチ名指定
- `rules/toolchain.md` — `--compare-branch=main` 記載

### Severity

High — CIの「lint」/「test」ジョブがそもそも発火しているか疑義がある。diff-coverゲートが機能していない

### Root Cause

リポジトリのデフォルトブランチが `master` だが、CI設定が `main` を想定している

### Mitigation

以下のいずれかの対応が必要（人間の判断要）:

**Option A**: CI設定・ドキュメントを `master` に統一
- `.github/workflows/ci.yml` の `branches:[main]` を `branches:[master]` に変更
- `rules/toolchain.md` / CIの `--compare-branch=main` を `--compare-branch=master` に変更

**Option B**: リポジトリのデフォルトブランチを `main` に変更してリネーム
- GitHub側のブランチ保護設定・既存PRへの影響も要確認

### Acceptance Criteria

- `uv run diff-cover coverage.xml --compare-branch=<正しいブランチ名>` がローカルで実行可能
- GitHub上でpush/PRに対しCIが実際に起動することを確認

### Dependencies

人間による方針確認が必要。決定後はdiff-coverが機能し、以降のカバレッジ関連タスクの効果測定が可能になる
