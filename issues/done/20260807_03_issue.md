# Correct Japanese, English, and Markdown chunk generation

## Priority
High

## Suggested Labels
priority-high, rag, chunking, japanese, english, markdown, bug

## Reason for Change
Japanese chunk generation mutates `self._result` while returning a separate local `result`, which can raise an error or lose output. English chunk generation removes stopwords before assigning the text to canonical `content`, so the original text is lost. Markdown handling selects heading mode before language handling and sends oversized Japanese sections to the English chunker. Japanese overlap independently slices original and normalized strings, so the paired texts can describe different spans.

## Implementation Intent
Make chunk output deterministic and language-correct while preserving the canonical source text. Original text must remain suitable for LLM context, and normalized text must remain aligned with the same source span for FTS use.

## Affected Files
- `rag/ingestion/chunk_japanese.py`
- `rag/ingestion/chunk_english.py`
- `rag/ingestion/chunk_splitter.py`
- `rag/ingestion/chunk_utils.py`
- chunking tests

## Implementation Scope
- [ ] Remove `self._result` from Japanese chunk generation and keep result mutation local to a single call.
- [ ] Prefer local original and normalized buffers so one document cannot leak state into the next.
- [ ] Preserve original/normalized pairing during accumulation, emission, tail merge, and overlap.
- [ ] Build Japanese overlap from the same sentence-pair units rather than independently slicing two strings by character count.
- [ ] Remove English stopword filtering from the value stored as canonical `content`.
- [ ] Keep English punctuation, negation, word order, articles, and prepositions unchanged.
- [ ] Leave English `normalized_content` as `None` unless a separate retrieval-quality requirement justifies an English normalization design.
- [ ] Separate Markdown heading extraction from language-specific section chunking.
- [ ] Send Japanese Markdown sections to the Japanese chunker and English sections to the English chunker.
- [ ] Retain headings with their corresponding section content.
- [ ] Update misleading module comments that claim Japanese chunking uses shared helpers when it does not, unless this issue actually makes the code shared.

## Non-Goals
- Do not add languages beyond Japanese and English.
- Do not introduce English normalization without an explicit quality requirement.
- Do not change FTS ranking behavior in this issue.

## Acceptance Criteria
- [ ] Japanese text requiring multiple chunks completes without `AttributeError` and returns every expected segment exactly once.
- [ ] Processing consecutive documents with the same splitter does not reuse prior state.
- [ ] Each Japanese original/normalized pair represents the same sentence set, including overlap.
- [ ] English `content` preserves the original selected text.
- [ ] Large Japanese Markdown sections never call the English chunker.
- [ ] Japanese Markdown produces Sudachi-normalized content paired with original content.

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
