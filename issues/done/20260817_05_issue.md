Title: [DOCS] Apply repo-wide documentation hygiene policy
Labels: priority/medium, type/docs, area/docs

## Summary
Apply four mechanical documentation rules across design docs and code docstrings in a single sweep, since they touch overlapping files and share the same review.

## Rationale
- Hard counts ("N tools", "N sub-configs", "N modules") drift the moment the implementation changes; two docstrings already disagree on the sub-config count, and design docs state a sub-config count that no longer matches the code.
- Line-number references rot on every edit; symbol names are stable.
- Concrete `config/*.toml` values restated in docs diverge from code defaults and create two sources of truth.
- Stale Deprecated / Resolved / 解消済み / 解決済み notes describe conditions that no longer exist. One concrete example: a Known Limitation claims `SLASH_COMMANDS` and `_COMMANDS` are managed separately with missing tab-completion entries, but `AgentREPL.SLASH_COMMANDS` now derives from `completion_command_names()`, which is built from `_COMMANDS` (the single source of truth) plus REPL-reserved commands.

## Intent
Remove the classes of documentation that predictably drift, so the docs stay correct by construction rather than by manual re-sync.

## Tasks
- [ ] Remove maintained counts everywhere (design docs and docstrings, including the sub-config counts in `AgentConfig`/module docstrings and the "... tools" counts in github-mcp tool docstrings); keep name enumerations without a number.
- [ ] Replace all source line-number references with class / function / method name references.
- [ ] Remove concrete `config/*.toml` values from design docs; point to the owning config dataclass instead.
- [ ] Delete stale Resolved/Deprecated notes that no longer affect current behavior, including the obsolete `SLASH_COMMANDS`/`_COMMANDS` mismatch limitation; keep "no longer …" notes required to explain current behavior (e.g. single-engine scheduling, no static tool-definitions fallback).

## Acceptance criteria
- No design doc or docstring states a maintained count.
- No design doc references a source line number.
- No design doc restates a concrete `config/*.toml` value.
- No stale resolved/deprecated note remains; behavior-explaining notes are preserved.
