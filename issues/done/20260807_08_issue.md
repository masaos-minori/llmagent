# Harden repository input handling and FTS observability

## Priority
Medium

## Suggested Labels
priority-medium, rag, search, fts, validation, observability

## Reason for Change
Repository methods pass `top_k` directly to SQL, tokenless FTS queries are represented as `MATCH '""'`, and the existing 20-token limit truncates input without exposing that fact. These behaviors make invalid callers and retrieval degradation harder to diagnose.

## Implementation Intent
Make repository boundaries explicit and predictable without changing ranking, token-selection policy, or embedding-dimension behavior.

## Affected Files
- `rag/repository.py`
- search diagnostics models if structured fields are added
- repository and SearchStage tests

## Implementation Scope
- [ ] Add one shared validator for vector and FTS `top_k` inputs.
- [ ] Require `top_k` to be a non-boolean integer greater than zero.
- [ ] Do not introduce an arbitrary maximum without a separate configuration requirement.
- [ ] Return an empty normalized query from `_build_fts_query()` when no usable tokens remain.
- [ ] Return `[]` from `fts_search()` without executing SQL for an empty normalized query.
- [ ] Record original FTS token count, used token count, and truncation status in structured diagnostics or structured debug logging.
- [ ] Keep `_MAX_FTS_TOKENS = 20` and the existing first-token selection behavior unchanged.
- [ ] Keep Japanese and English tokenization behavior unchanged for non-empty queries.

## Non-Goals
- Do not change RRF, BM25 ordering, L2 behavior, or reranking.
- Do not add fixed-1024 runtime checks.
- Do not redesign token selection in this issue.

## Acceptance Criteria
- [ ] Zero, negative, boolean, and non-integer `top_k` values fail before SQL execution.
- [ ] Whitespace-only and punctuation-only FTS queries return `[]` without SQL syntax errors.
- [ ] Queries above 20 tokens expose truncation information.
- [ ] Queries at or below the limit report no truncation.
- [ ] Normal search results remain behaviorally unchanged.

## Required Tests
- [ ] invalid top_k values
- [ ] valid top_k
- [ ] empty and punctuation-only queries
- [ ] Japanese and English non-empty queries
- [ ] 19, 20, and 21-token diagnostics

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.

- [ ] Acceptance criteria are satisfied.
- [ ] Focused unit tests pass.
- [ ] Relevant integration or regression tests pass.
- [ ] Existing RAG ingestion, search, schema, and consistency tests remain green.
- [ ] Documentation and comments contain no stale or contradictory wording related to this issue.
