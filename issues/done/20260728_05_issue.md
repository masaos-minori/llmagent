# Clarify quick `/v1/tools` shape checks if retained

## Priority

Medium

## Summary

If the lightweight name-only `/v1/tools` validation path remains, clarify that it is only a quick shape check and not the authoritative discovery or readiness validation path.

## Background

`repl_health.py` contains lightweight `/v1/tools` validation that checks:

- response is a JSON object
- `tools` field exists
- `tools` is a list
- each tool entry has a valid `name`

This can be useful for quick diagnostics, but it is not sufficient for runtime tool readiness.

## Problem

Name-only validation can be mistaken for authoritative `/v1/tools` validation.

It does not validate:

- description
- input schema
- `enabled_for_llm`
- approval metadata
- write metadata
- serial execution metadata
- resource scope
- safety tier
- capabilities
- duplicate ownership
- RuntimeTool normalization

## Implementation Intent

If retained, the name-only validation path should be explicitly limited to quick diagnostics or compatibility checks.

It must not override or replace `McpToolDiscoveryService`.

## Required Changes

### 1. Rename or document the helper

If retained, use a name or docstring that makes its limited role clear.

Possible names:

- `_quick_validate_tools_response_shape`
- `_validate_tools_response_name_only`
- `_collect_server_tool_names_for_debug`

### 2. Make non-authoritative status explicit

Document that this check:

- is not the registry-building validation path
- is not the startup validation source of truth
- does not validate runtime metadata
- must not override `McpToolDiscoveryService` findings

### 3. Limit usage

Limit usage to:

- lightweight runtime debug
- non-authoritative diagnostics
- backward compatibility checks
- quick connectivity or shape checks

### 4. Avoid startup ambiguity

Startup validation should clearly point to `McpToolDiscoveryService` as authoritative.

## Acceptance Criteria

- Name-only validation is clearly marked as non-authoritative.
- Function names or docstrings make the limited role obvious.
- Startup validation documentation points to `McpToolDiscoveryService`.
- Runtime routing documentation points to `RuntimeToolRegistry`.
- No documentation implies that name-only validation is sufficient for tool readiness.
- Name-only validation does not override rich discovery results.

## Files to Modify

- `agent/repl_health.py`
- MCP discovery documentation
- MCP operations documentation

## Out of Scope

- Startup discovery snapshot persistence
- HTTP transport retry/backoff changes
- `/v1/call_tool` response extension
