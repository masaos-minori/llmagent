## [session] SessionMessageRepository initialization timing issue

### Summary

`AgentSession.__init__` で `SessionMessageRepository(self.session_id)` が初期化されるが、この時点では `self.session_id` は `None`。`start()` メソッドで `session_id` が設定された後、`_message_repo` が再初期化されるが、`save()` や `save_many()` が `start()` よりも前に呼ばれると、`None` セッションIDで保存しようとする。

### Problem

`session.py:35-37` で初期化：

```python
def __init__(self, session_id: int | None = None) -> None:
    self.session_id = session_id
    self._message_repo = SessionMessageRepository(self.session_id)
```

`session.py:128-130` で再初期化：

```python
def start(self) -> None:
    if self.session_id is not None:
        return
    self.session_id = ...
    self._message_repo = SessionMessageRepository(self.session_id)
```

`save()` や `save_many()` が `start()` よりも前に呼ばれると、`None` セッションIDで保存しようとするが、`replace_messages()` ではスキップされる（`session.py:64-68`）。一貫性のない挙動。

### Affected Files

- `scripts/agent/session.py:35-37` — `__init__` 内の初期化
- `scripts/agent/session.py:128-130` — `start()` 内の再初期化
- `scripts/agent/session.py:64-68` — `replace_messages()` 内のスキップ条件

### Attack Scenario

1. `start()` よりも前に `save()` や `save_many()` が呼ばれる
2. `None` セッションIDで保存しようとするが、一貫性のない挙動が発生する
3. データの不整合や予期せぬエラーが発生する

### Severity

Medium — `None` セッションIDを受け取った場合に明示的にエラーを返すか、または遅延初期化する必要がある。

### Mitigation

- `SessionMessageRepository` が `None` セッションIDを受け取った場合に明示的にエラーを返す
- または `AgentSession.__init__` で遅延初期化する
