# [High] Remove legacy MCP routing and pre-Schema 2.0 compatibility

## Priority

High

## Summary

Remove the obsolete `ToolRouteResolver` constructor compatibility, unused routing diagnostic inputs, and all MCP tool-definition compatibility paths that predate MCP Schema 2.0.

## Reason for Change

`ToolRouteResolver.server_configs` exists only to preserve an older constructor signature. The resolver neither stores nor reads this value, and `RuntimeToolRegistry` is already the sole routing authority. Keeping an unused required argument makes the current API misleading and increases the risk that future code incorrectly assumes routing can fall back to static server configuration.

The resolver also accepts `discovery_map` and `known_tools`, although neither affects production routing. `discovery_map` is stored but not used by `resolve()`, while `known_tools` only activates a diagnostic path with no production caller. These inputs enlarge the public API without providing current runtime behavior.

MCP discovery still accepts the legacy `input_schema` alias, the singular `resource_scope` field, and `/v1/tools` responses without a top-level `schema_version`. The current contract is MCP Schema 2.0, whose canonical fields are `inputSchema`, `resource_scope_kind`, and `resource_scope_keys`. Continuing to accept obsolete names can hide server-side schema defects and makes the effective protocol less strict than the documented protocol.

## Implementation Intent

The implementation must establish one unambiguous routing and discovery contract:

- `RuntimeToolRegistry` is the only routing authority.
- `ToolExecutor.server_configs` remains available only for transport construction, lifecycle handling, concurrency setup, and `startup_mode` checks.
- `ToolRouteResolver` receives no static server configuration and exposes no unused diagnostic constructor inputs.
- MCP discovery accepts only canonical Schema 2.0 responses and rejects obsolete or incomplete representations immediately.

This is a direct removal. Do not introduce aliases, compatibility flags, deprecation warnings, fallback routing, or migration logic.

## Scope

- `scripts/shared/route_resolver.py`
- `scripts/shared/tool_executor.py`
- `scripts/agent/services/mcp_tool_discovery.py`
- MCP server `/v1/tools` response builders
- Related tests and fixtures

## Implementation Tasks

- [ ] Remove `server_configs` from `ToolRouteResolver.__init__()`.
- [ ] Remove the unused `McpServerConfig` type import from `route_resolver.py`.
- [ ] Change `ToolExecutor` to construct `ToolRouteResolver` without `server_configs`.
- [ ] Preserve `ToolExecutor.server_configs` and all current transport, lifecycle, concurrency, and startup-mode uses.
- [ ] Remove `discovery_map` from `ToolRouteResolver` and `ToolExecutor`.
- [ ] Remove `_discovery_map` from `ToolRouteResolver`.
- [ ] Remove `known_tools` and `_log_routing_coverage()`.
- [ ] Remove comments, docstrings, fixtures, and tests that refer only to the deleted routing inputs.
- [ ] Require the top-level `/v1/tools` `schema_version` field.
- [ ] Accept only the supported MCP Schema 2.0 version.
- [ ] Reject missing or unsupported schema versions at the server-response boundary.
- [ ] Remove the `input_schema` fallback from entry validation.
- [ ] Remove the `input_schema` fallback from `RuntimeTool` construction.
- [ ] Accept only `inputSchema`.
- [ ] Remove validation and handling of the legacy singular `resource_scope` field.
- [ ] Accept only `resource_scope_kind` and `resource_scope_keys`.
- [ ] Replace legacy acceptance tests with explicit rejection tests.

## Constraints

- Do not remove `server_configs` from `ToolExecutor`.
- Do not remove live MCP discovery or runtime registry wiring.
- Do not restore static configuration or static registry fallback routing.
- Do not add a compatibility period or warnings-only mode.

## Acceptance Criteria

- [ ] `ToolRouteResolver` no longer accepts `server_configs`, `discovery_map`, or `known_tools`.
- [ ] `_discovery_map` and `_log_routing_coverage()` no longer exist.
- [ ] Tool execution still creates transports and enforces `startup_mode` correctly.
- [ ] `RuntimeToolRegistry` remains the sole routing authority.
- [ ] `input_schema`-only definitions are rejected.
- [ ] Legacy `resource_scope` definitions are rejected.
- [ ] `/v1/tools` responses without `schema_version` are rejected.
- [ ] Unsupported schema versions are rejected.
- [ ] Valid MCP Schema 2.0 responses still populate the runtime registry.
- [ ] All affected tests pass.
