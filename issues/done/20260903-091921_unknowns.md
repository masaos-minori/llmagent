# Unresolved blocking unknown: embed_url/llm_url same-host classification for loopback-only enforcement

**Status: Resolved 2026-09-03.** Architecture owner decided: `embed_url`/
`llm_url` are legitimate remote/cross-host endpoints (dedicated embedding/LLM
inference hosts), explicitly out of `loopbackonly`'s scope — option (a) in
Resolution Path below. No same-host migration is required, and no follow-up
infrastructure-change Issue is needed. See `plans/20260903-091921_plan.md` for
the updated Plan text reflecting this decision.

## Summary
`plans/20260903-091921_plan.md` (UNK-01) needs an architecture-owner decision on
whether `embed_url`/`llm_url` should be classified as "Agent-internal same-host
services" (as the source Issue `loopbackonly` names them) requiring migration to
loopback, or as out-of-scope remote endpoints exempt from the loopback-only rule.
Currently both `config/agent.toml` and `config/rag_pipeline_mcp_server.toml` set
`embed_url`/`llm_url` to private-LAN addresses (`192.168.11.238:8081`,
`192.168.11.197:8080`) on hosts different from the Agent process — this directly
contradicts a same-host premise for these two services.

## Evidence Missing
Repository evidence confirms the current (non-loopback) configuration, but there is
no design document, ADR, or Known Issue recording whether this cross-host
deployment is intentional infrastructure (embedding/LLM inference servers
deliberately run on separate, more capable hosts) or a gap the `loopbackonly`
Issue is meant to close. Resolving this requires an infrastructure/architecture
decision, not further code investigation.

## Resolution Path
Architecture owner decides one of: (a) `embed_url`/`llm_url` are legitimately
remote/cross-host and are declared out of `loopbackonly`'s scope, updating that
Issue's Constraints to say so explicitly; or (b) they must migrate to same-host
loopback, in which case a separate infrastructure-change Issue is filed to move the
embedding/LLM inference services onto the Agent's host before any code change
enforces loopback-only for them.

## Blocking Impact
- **Blocking for:** any future extension of `plans/20260903-091921_plan.md`'s
  loopback-enforcement scope to `embed_url`/`llm_url`.
- **Not blocking for:** `plans/20260903-091921_plan.md`'s own Requirements
  (`REQ-001` through `REQ-006`), which are scoped to Event Bus and the MCP server
  base class and do not touch `embed_url`/`llm_url`.
