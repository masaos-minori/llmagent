# Four `except Exception as exc:  # noqa: BLE001` blocks in `_check_services()` lack inline suppression justification

## Priority
Low

## Target files
- `scripts/agent/startup.py` (`StartupOrchestrator._check_services()`, lines 299, 320, 336, 343)

## Background
`rules/coding.md` §Suppression governance states: "Every `# noqa`, `# type: ignore`, and `# nosec`
requires an inline justification. Suppressions without explanation are prohibited."

While processing `requires/20260804-132104_require.md` (RAG consistency check exception
swallowing fix) into `plans/20260804-144001_plan.md`, a check of every `# noqa` in
`scripts/agent/startup.py` found:

```
112:            CommandRegistry,  # noqa: PLC0415 — lazy: deferred to avoid circular import at module level
264:        from agent.repl_health import check_workflow_schema  # noqa: PLC0415
299:        except Exception as exc:  # noqa: BLE001
320:        except Exception as exc:  # noqa: BLE001
336:        except Exception as exc:  # noqa: BLE001
343:        except Exception as exc:  # noqa: BLE001
358:        except Exception:  # noqa: BLE001
```

Only line 112 carries an inline justification (` — lazy: deferred to avoid circular import at
module level`). Line 264 and lines 299, 320, 336, 343 do not. Line 358 is the one being fixed by
`plans/20260804-144001_plan.md` (which adds a justification to it as part of that fix); lines 299,
320, 336, 343 are the four *other* `except Exception as exc:  # noqa: BLE001` blocks in the same
method (security audit-adjacent `readiness`, `mcp_tool_discovery`, `routing_drift`,
`routing_safety_tiers` checks) and are unaffected by that fix.

## Problem
Four `# noqa: BLE001` suppressions in `_check_services()` (lines 299, 320, 336, 343) have no
inline explanation of why the broad `except Exception` catch is intentionally retained there,
violating `rules/coding.md`'s explicit "Suppressions without explanation are prohibited" rule.
Line 264's bare `# noqa: PLC0415` (no justification either) is a second, smaller instance of the
same gap, on a different rule code.

## Reason for change
Consistent suppression governance makes it clear, for every broad-except or lint suppression in
this file, *why* it was judged safe/intentional rather than an oversight — the same reasoning
applied when justifying line 358's suppression in the RAG consistency fix. Leaving four of six
`except Exception as exc:  # noqa: BLE001` blocks unjustified is an inconsistency an auditor or
future maintainer would need to re-derive from scratch.

## Scope note
This was explicitly out of scope for `requires/20260804-132104_require.md` / its resulting plan
(`plans/20260804-144001_plan.md`), whose Implementation instructions state: "do not... modify...
any other check in `_check_services()`" beyond the RAG consistency block. Filing this as a
separate follow-up issue rather than silently leaving the gap unaddressed or bundling an
out-of-scope fix into that plan.

## Implementation intent (for a future requirement/plan cycle)
Add a short inline justification to each of the four `# noqa: BLE001` suppressions at lines 299,
320, 336, 343 (and, optionally, to line 264's `# noqa: PLC0415`), following the same pattern used
at line 112 and the pattern to be introduced at line 358 by `plans/20260804-144001_plan.md` —
i.e. state why the broad `Exception` catch (or PLC0415 deferred-import) is an intentional,
non-fatal design choice for that specific check, not a placeholder.

## Acceptance criteria

  in the file carries an inline justification after an em dash, consistent with the existing
  convention at line 112).
- No change to the exception types caught, control flow, or messages produced by these four
  blocks — this is a comment-only addition.
