## グレースフルシャットダウンのタイムアウトがターン実行中に届いたシグナルには効かない

### Summary

`_repl_loop()` はSIGTERM/SIGINT受信後、進行中のターンを `_GRACEFUL_TIMEOUT`(10秒)で打ち切る設計だが、このタイムアウトはターン**開始前**の `shutdown_requested` の値でのみ決定される。ターン実行の開始直後にシグナルが届いた場合、そのターンには一切タイムアウトが適用されず、LLM呼び出しやツール実行がハングしても無期限に待ち続ける可能性がある。

### Problem

- `scripts/agent/repl.py:485-502` (`_repl_loop`):
  ```python
  self._turn_active = True
  ctx.conv.is_processing = True
  try:
      await asyncio.wait_for(
          self._dispatch_line(line, ctx),
          timeout=_GRACEFUL_TIMEOUT if ctx.conv.shutdown_requested else None,
      )
  ...
  ```
  `timeout` 引数はこの行が評価された一時点の `ctx.conv.shutdown_requested` の値で確定する。`asyncio.wait_for` に一度渡された `timeout=None` は、その後 `shutdown_requested` が `True` に変わっても再評価されない。
- `scripts/agent/repl.py:665-690` (`_sigterm_handler`) のコメントは「`_repl_loop()` already checks `shutdown_requested` after each turn and applies the `_GRACEFUL_TIMEOUT` wait to end the turn」としており、「次のターン開始時にタイムアウトが適用される」ことを前提にしているが、これは「シグナル受信時点で実行中だったターン」には一切適用されない。
- シナリオ: ユーザーがターンを送信した直後(まだ `shutdown_requested=False` の時点で `wait_for(timeout=None)` が確定)にSIGTERM/SIGINTが届くと、`shutdown_requested=True` になっても実行中の `wait_for` は `timeout=None` のまま変わらない。LLM呼び出しやツール実行がハング状態になった場合、`_GRACEFUL_TIMEOUT` による強制打ち切りが機能しない。

### Affected Files

- `scripts/agent/repl.py` — `_repl_loop()`(462-502行目)、`_sigterm_handler`(665-690行目)

### Classification

**High** — 「10秒でグレースフルに打ち切る」という明示された保証が、シグナル到達タイミング次第で完全に無効化される。運用上、コンテナのシャットダウン猶予期間(SIGTERM後の強制SIGKILLまでの待機時間)を超えてプロセスが残り続けるリスクがある。

### Evidence

- Strongly implied by code (Medium confidence) — ロジック自体は静的に確認済みだが、実運用でのハングシナリオの再現は未実施。

### Recommended next action

- `asyncio.wait_for` に入る前に固定のタイムアウトを設定するのではなく、ターン実行タスクを個別に作成した上で `shutdown_event` の到来を監視し、シグナル受信時点から `_GRACEFUL_TIMEOUT` を起算するよう変更する。
- シグナル受信タイミングを変えた統合テスト(ターン実行中にshutdown_requestedをTrueにするケース)を追加する。
