# [Medium] Remove duplicate document-management code and regenerate RAG runtime data

## Priority

Medium

## Summary

Remove the duplicate file-URL handling helper, then rebuild generated RAG runtime data under the strict contracts. No legacy conversion or migration is permitted.

## Reason for Change

`DocumentManager.handle_existing_document()` already contains the active file-URL SHA-256 comparison and replacement decision, while `_handle_existing_file()` duplicates the same behavior. Keeping both paths increases maintenance cost and creates a risk that future fixes update only one implementation.

The strict JSON and database contracts invalidate generated chunk files and databases created under the previous permissive behavior. Because legacy data does not exist and migration is explicitly out of scope, the correct operational action is deletion and deterministic regeneration from current sources.

## Implementation Intent

Keep one authoritative file-URL decision path in `handle_existing_document()`: matching SHA-256 values skip re-ingestion, and different values replace the document. After all strict-contract implementation issues are complete, remove generated runtime artifacts, recreate the database, and run the full pipeline from Crawler through consistency validation.

This task is operational cleanup and regeneration, not data migration.

- `scripts/rag/ingestion/document_manager.py`
- `rag-src/chunk/`
- `rag-src/registered/`
- `rag-src/retry/`
- `rag-src/failed/`
- `rag.sqlite`
- Related tests and operational documentation
