# Remove stale 384, E5, query_prefix, and embed_dim documentation

## Priority

Low

## Summary

Remove outdated comments, docstrings, and configuration comments that reference the previous embedding model assumptions.

## Background

After switching to a Qwen3 1024-dimensional fixed embedding design, references to 384 dimensions, E5 prefixes, `query_prefix`, and `embed_dim` become misleading.

This cleanup should happen after the implementation changes so documentation matches the final design.

## Fix Intent

Avoid future confusion and prevent developers from reintroducing E5 or 384-dimensional assumptions.

## Required Changes

- Remove references to:
  - `384-dimensional`
  - `embedding_dims = 384`
  - `memory_embed_dim = 384`
  - `E5 passage prefix`
  - `E5 query prefix`
  - `query_prefix`
  - `embed_dim = 384`
- Replace with Qwen3-specific wording where useful:
  - Qwen3 embedding
  - 1024-dimensional fixed embedding
  - raw text embedding input

## Files to Update

- `config/agent.toml`
- `config/ingester.toml`
- `scripts/rag/ingestion/ingester.py`
- `scripts/rag/llm_client.py`
- `agent/memory/embedding_client.py`
- Related RAG documentation files if present

## Acceptance Criteria

- No stale 384-dimensional comments remain.
- No E5-specific prefix comments remain.
- No documentation suggests `embedding_dims` or `memory_embed_dim` are configurable.
- Documentation reflects the Qwen3 fixed-dimension design.
