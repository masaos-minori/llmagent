## rag_pipeline /v1/tools に schema_version が欠落 (FAIL-2 / TASK-H2)

### Summary

rag_pipeline MCPサーバの `/v1/tools` エンドポイントが `schema_version` キーを返さない。他の全MCPサーバが付与しているため、スキーマ契約違反。

### Problem

`scripts/mcp_servers/rag_pipeline/rag_pipeline_server.py:163` の `list_tools()` が `{"tools": [...]}` を手組みで返しており、他MCPサーバが付与している `schema_version` キーを含めていない。

```python
# rag_pipeline_server.py (現在)
def list_tools(self):
    return {"tools": [...]}  # schema_versionなし

# 他のMCPサーバ (例: git_server.py)
def list_tools(self):
    return build_tools_response(...)  # schema_version付き
```

### Affected Files

- `scripts/mcp_servers/rag_pipeline/rag_pipeline_server.py:162-166` — schema_version欠落
- `scripts/mcp_servers/server.py:225` — `build_tools_response()` (標準パターン)

### Severity

High — MCPツールディスカバリの契約違反。rag_pipelineサーバのクライアントがスキーマバージョンチェックを行う場合に破綻しうる

### Deterministic

決定論的

### Root Cause

production code bug

### Mitigation

`scripts/mcp_servers/rag_pipeline/rag_pipeline_server.py:163` の `list_tools()` を、他サーバ同様 `build_tools_response()` または同等のパターンで `schema_version` を付与するよう修正

### Acceptance Criteria

- `test_schema_version_present[...rag_pipeline]` がpass
- 既存の `/v1/tools` 利用側に破壊的変更がないことを確認
- `uv run pytest -q` で新規失敗なし、mypy/ruffクリーン
