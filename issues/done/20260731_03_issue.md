# Normalize chunk generation to preserve original text and normalized search text

## Priority

High

## Summary

Unify English, Japanese, and Markdown chunk generation around the same output contract:

- `content`: original readable text
- `normalized_content`: search-normalized text

This matches the SQLite schema and FTS5 trigger design.

## Background

The database schema separates original content and normalized search text:

- `chunks.content`
- `chunks.normalized_content`

The FTS5 trigger indexes:

`COALESCE(normalized_content, content)`

This means chunk generation must preserve original text for LLM context while storing normalized text for FTS search.

Current issues:

- `chunk_english.py` returns only stopword-filtered text, which loses the original text / normalized text separation.
- `chunk_japanese.py` is close to `(original, normalized)` but has internal state inconsistency.
- Markdown heading chunks currently produce empty `normalized_content`.

## Fix Intent

Make the chunk contract language-independent and consistent across text sources.

The result should be easier to reason about:

- LLM context always uses original text.
- FTS5 always prefers normalized text when available.
- Embedding uses original `content`.

## Required Changes

### English chunking

- Update `chunk_english.py` to return:

  `list[tuple[str, str]]`

- Tuple meaning:
  - first item: original text
  - second item: normalized text

- Preserve original text before stopword removal.
- Store stopword-filtered text as normalized text.

### Japanese chunking

- Keep the output contract as:

  `list[tuple[str, str]]`

- Fix internal aggregation to avoid mixed local and instance state.
- Remove `self._result`.
- Use a local `result` list inside `_merge_ja_sentence_pairs()`.

### Markdown heading chunking

- Change `_chunk_markdown_by_heading()` to return:

  `list[tuple[str, str]]`

- For Japanese Markdown chunks, generate Sudachi-normalized text.
- For English Markdown chunks, generate English normalized text.
- Keep original Markdown section text as `content`.
- Keep `chunking_strategy = "heading"`.

### Chunk payload

- Update `chunk_splitter.py` so all text paths write:

  `content = original`

  `normalized_content = normalized or None`

## Files to Update

- `scripts/rag/ingestion/chunk_english.py`
- `scripts/rag/ingestion/chunk_japanese.py`
- `scripts/rag/ingestion/chunk_splitter.py`

## Acceptance Criteria

- English text chunks preserve original readable content.
- English text chunks store normalized search text separately.
- Japanese text chunks preserve original readable content.
- Japanese text chunks store normalized search text separately.
- Markdown heading chunks can produce `normalized_content`.
- `chunk_japanese.py` no longer uses `self._result`.
- `chunks.content` remains suitable for LLM context.
- `chunks.normalized_content` remains suitable for FTS5 indexing.
