## MCPサーバーサブプロセス起動時の環境変数マージに許可リストがなく、cfg.envが任意の変数を無制限に上書きできる

### Summary

`HttpServerLifecycleManager.start()` は親プロセスの全環境変数に `cfg.env` をマージしてサブプロセスに渡すが、`cfg.env` の値に対する許可リスト・拒否リストが存在しない。類似の懸念に対して `shell_mcp_server.toml` には既に `env_denylist` という対策があるのに対し、MCPサーバー自体の起動時envには対応する検証がなく一貫性がない。

### Problem

- `scripts/agent/http_lifecycle.py:224-226` (`HttpServerLifecycleManager.start()`):
  ```python
  env = None
  if cfg.env:
      env = {**os.environ, **cfg.env}
  ```
- `scripts/shared/mcp_config.py:110-119` (`McpServerConfig._validate_cross_fields()`) は `env` のキー・値が `str` であることのみを検証し、値の中身(危険な変数名かどうか)は一切チェックしていない。
- 対比として `config/shell_mcp_server.toml` には次の対策が既に存在する:
  ```
  # env_denylist: glob patterns for env keys removed from req.env (active when env_allowlist is empty)
  env_denylist = ["LD_PRELOAD", "LD_LIBRARY_PATH", "PYTHONPATH"]
  ```
  これはshell実行リクエストのenvに対する対策であり、`config/agent.toml` の `[mcp_servers.<key>].env`(MCPサーバー自体の起動時env)には同様の対策がない。

### Affected Files

- `scripts/agent/http_lifecycle.py` — `start()`(224-226行目)
- `scripts/shared/mcp_config.py` — `McpServerConfig._validate_cross_fields()`(110-119行目)
- `config/shell_mcp_server.toml` — 参考: 既存の`env_denylist`対策

### Classification

**Low** — `cmd`/`env` は管理者制御の設定(admin-controlled config)という前提があるため実運用でのリスクは限定的。ただし、`shell_mcp_server.toml` 側に存在する同種の防御が `agent.toml` の `mcp_servers.*.env` には存在せず、設計上の一貫性がない。

### Evidence

- Explicit in code (High confidence) — 検証ロジックの不在は静的に確認済み。

### Recommended next action

- 意図的に対策不要と判断するならその理由をコメントで明記する。
- 対策する場合は `shell_mcp_server.toml` の `env_denylist` と同様の許可/拒否リストを `McpServerConfig` 側にも導入する。
