# Clarify duplicate search orchestration and semantic-cache mismatch behavior

## Priority
Low

## Suggested Labels
priority-low, rag, search, cache, documentation, refactor

## Reason for Change
`RagPipeline.search_queries()` and `SearchStage` both orchestrate embedding, vector search, and FTS search, which can cause exception and diagnostic behavior to drift. SemanticCache also raises on a dimension mismatch relative to existing entries, but the pipeline does not document whether that should fail the request or degrade to a cache miss. This is a relative cache-consistency question, not a fixed-1024 validation requirement.

## Implementation Intent
Define one canonical search path where possible and document the supported behavior of the remaining cache mismatch case.

## Affected Files
- `rag/pipeline.py`
- `rag/stages/search.py`
- `rag/cache.py`
- search and cache tests
- design documentation

## Implementation Scope
- [ ] Identify all callers of `RagPipeline.search_queries()`.
- [ ] Use `SearchStage` as the canonical path when possible, or document a distinct supported purpose for the direct method.
- [ ] Consolidate diagnostics and exception handling if both paths remain.
- [ ] Keep the cache's relative dimension-consistency check.
- [ ] Decide whether a relative cache dimension mismatch should propagate or degrade to a cache miss.
- [ ] If degraded, log the mismatch and invalidate incompatible cache entries.
- [ ] Do not compare cache entries with `QWEN3_EMBEDDING_DIMS`.

## Non-Goals
- Do not add fixed-1024 runtime validation.
- Do not change vector ranking or FTS behavior.
- Do not redesign the semantic cache eviction policy.

## Acceptance Criteria
- [ ] Every search orchestration path has a documented caller and purpose.
- [ ] Equivalent paths do not diverge in diagnostics or failure handling.
- [ ] Relative cache dimension mismatch behavior is documented and tested.
- [ ] No fixed-dimension runtime validation is added.

## Required Tests
- [ ] existing callers of both search paths
- [ ] embedding failure diagnostics
- [ ] vector/FTS failure diagnostics
- [ ] relative cache dimension mismatch
- [ ] normal cache hit and miss

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
