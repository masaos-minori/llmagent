**Title:** [Low][shared] Unify or explicitly document the unused ToolResultCache vs ToolExecutor internal cache

**Labels:** cleanup, low-priority, shared
**Covers:** L-3
**Area / Component:** `scripts/shared/tool_cache.py`, `scripts/shared/tool_executor.py`

## Summary
`ToolResultCache` (LRU+TTL) is not integrated into `ToolExecutor`, which uses its own OrderedDict
cache with stampede protection, leaving two coexisting cache implementations.

## Rationale (Why this matters — detailed)
- Two cache implementations exist side by side; the standalone `ToolResultCache` is a utility not
  used by the executor. This ambiguity about which cache is authoritative adds cognitive and
  maintenance overhead and can mislead future contributors into modifying the wrong cache.

## Fix Intent (How — detailed)
- Either consolidate to a single authoritative cache, or clearly document `ToolResultCache` as a
  standalone utility intended for future non-stampede use, so the division of responsibility is
  explicit.

## Acceptance Criteria
- [ ] A single authoritative cache exists, or both roles are explicitly documented in code/docstring.
