### ISSUE-M3: 起動時 Readiness Summary で警告のみの状態が「FAIL」と誤表示される `[確認済]

優先度: Medium
対象ファイル: `scripts/agent/startup.py` (`StartupOrchestrator._report_readiness`)

#### 修正理由
`_report_readiness()` は起動完了後に4項目のサマリ行を出力する。うち3行 (security_audit / readiness / mcp_tool_discovery) は「OK 件数が0なら FAIL」という条件で `'OK' if xxx_ok else 'FAIL'` を出力しているのに対し、`rag_consistency` の行だけは `'OK' if rag_ok else 'WARN'` と、同じ条件分岐でも FAIL ではなく WARN を表示している。

```python
lines.append(f"  Security audit: {'OK' if security_ok else 'FAIL'} ({security_fail} fatal, {security_warn} warnings)")
lines.append(f"  Service readiness: {'OK' if mcp_ok else 'FAIL'} ({mcp_fail} fatal, {mcp_warn} warnings, {mcp_skip} skipped)")
lines.append(f"  Tool discovery: {'OK' if tool_disc_ok else 'FAIL'} ({tool_disc_fail} fatal, {tool_disc_warn} warnings, {tool_disc_skip} skipped)")
lines.append(f"  RAG consistency: {'OK' if rag_ok else 'WARN'} ({rag_fail} fatal, {rag_warn} warnings)")
```

`_check_services()` の呼び出し元では、各チェック項目に `add_ok(...)` が呼ばれるのは issue が一つも無かった場合のみであり、warning が1件以上あるが fatal は0件、という「起動は継続するが要確認」の状態では `add_ok` は呼ばれない。この場合 `security_ok` / `mcp_ok` / `tool_disc_ok` は0のままとなり、対応する行は `security_fail`/`mcp_fail`/`tool_disc_fail` が実際には0であるにもかかわらず「FAIL」と表示される。

例えば security_audit で warning が1件のみ検出された場合、出力は次のようになる。

```
Security audit: FAIL (0 fatal, 1 warnings)
```

`docs/05_agent_10_01_...md` の重大度マッピング表では FATAL は「起動を中断する条件」、WARNING は「起動を継続するが確認すべき状態」と明確に区別されている。にもかかわらずこの表示は fatal が0件のときでも「FAIL」という起動中断を連想させる語を使っており、`(0 fatal, ...)` という併記内容と自己矛盾している。運用者がこの一行だけを見て「起動に失敗した」と誤認し、実際には正常に起動して継続稼働しているセッションに対して不要な調査対応を行うおそれがある。

#### 修正意図
4行すべてで、fatal 件数に基づいて OK / WARN / FAIL を一貫した基準で出し分けるようにし、warning のみで起動が継続している状態を FAIL と誤表示しないようにする。

#### 作業内容
1. `_report_readiness()` の security_audit / readiness / mcp_tool_discovery の3行を、`rag_consistency` 行と同じ3値ロジック (fatal 件数 > 0 のときのみ FAIL、fatal が0かつ warning 件数 > 0 のときは WARN、両方0のときのみ OK) に統一する。
2. 各行の表示ロジックに対する単体テストを追加し、fatal=0 かつ warning>0 のケースで「WARN」と表示されることを検証する。

#### 受け入れ条件
- fatal が0件で warning のみの場合、該当行が「WARN」と表示される (「FAIL」ではない)。
- fatal が1件以上の場合のみ「FAIL」と表示される。
- 4行すべてで表示ロジックが統一されている。
- 既存テストが通る。
