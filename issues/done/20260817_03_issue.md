Title: [TECH-DEBT] Remove or justify unreachable dead code paths
Labels: priority/medium, type/tech-debt, area/agent, area/mcp

## Summary
Several members are unreachable in the current design and should be removed or explicitly justified as extension points.

## Rationale
- `route_resolver` accepts `server_configs` / `discovery_map` / `known_tools`, but the dispatch path never reads them; they are diagnostic-only leftovers that imply capabilities the resolver does not use.
- `mcp_health.McpServerHealthRegistry.record_degraded()` and `get_degraded_reason()` lost their caller when the watchdog was removed; `get_degraded_reason()` now effectively always returns None, so any reader is misled.
- `RETENTION_DAYS` has no consumer.
- Dead members raise reviewer cost and invite incorrect assumptions during future changes; removing them keeps the health/routing contracts honest.

## Intent
Eliminate members that cannot execute, so the routing and health contracts reflect only what the system actually does. Retain deliberate utilities.

## Tasks
- [ ] Remove `route_resolver` unused constructor inputs, or annotate each as a deliberate extension point with a short "kept for X" note.
- [ ] Remove `record_degraded()` / `get_degraded_reason()` (and the `_degraded_reasons` bookkeeping they feed) unless a concrete caller is reinstated.
- [ ] Remove the unused `RETENTION_DAYS` constant.

## Out of scope
- `tool_cache.ToolResultCache` — intentionally retained as a standalone utility per its module docstring; do NOT remove.

## Acceptance criteria
- No unreachable member remains without an explicit justification comment.
- Build and tests pass after removal.
