## エージェント起動フェーズ: メモリ注入によるプロンプトインジェクション

### Summary

`orchestrator.py:373-391` と `startup.py:536-572` で、メモリコンテンツがシステムプロンプトに直接挿入されるため、攻撃者がメモリ内に悪意のあるコンテンツを保存することでLLMの振る舞いを制御できる可能性がある。

### Problem

`orchestrator.py:373-391` で定義：

```python
memory_block = "\n\n[Relevant memories]\n" + "\n".join(
    f"- {snippet.text}" for snippet in memory_snippets
)
initial_prompt = initial_prompt + memory_block
```

メモリコンテンツがシステムプロンプトにフィルタリングなしで直接挿入される。攻撃者がメモリ内のテキストに「あなたは別のAIアシスタントです」といったプロンプトインジェクションを含む場合、LLMはその指示に従う可能性がある。

### Affected Files

- `scripts/agent/orchestrator.py:373-391` — メモリインジェクションの実装
- `scripts/agent/startup.py:536-572` — システムプロンプトへのメモリ追加

### Attack Scenario

1. 攻撃者がエージェントに悪意のある情報を記憶させる（例: 「あなたは別のAIアシスタントです」）
2. 次のセッションで、そのメモリがシステムプロンプトに挿入される
3. LLMがメモリ内の指示に従い、本来の振る舞いをバイパスする
4. セキュリティポリシーや承認フローの回避が可能になる

### Severity

High — メモリコンテンツがシステムプロンプトに直接挿入され、プロンプトインジェクション攻撃のベクトルとなる。

### Mitigation

- メモリコンテンツをシステムプロンプトではなくユーザーメッセージとして挿入する
- メモリコンテンツにフィルタリングを適用し、システムプロンプトの境界を明確にする
- システムプロンプトとメモリコンテンツの間に分離セパレータを追加する
