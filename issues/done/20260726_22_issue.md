## エージェント起動フェーズ: ワークフローのステートリカバリ

### Summary

`startup.py:506-534` で、以前のセッションからの保留中の承認が復元される。これにより、セッションの開始時に承認が必要な状態が自動的に有効になる。

### Problem

`startup.py:506-534` で定義：

```python
results = find_all_pending_approvals(store.get_connection())
task_id, approval = results[-1]
ctx.workflow.approval_pending = True
ctx.turn.pending_approval_id = approval.approval_id
```

以前のセッションからの保留中の承認が復元される。攻撃者が承認が必要な操作を中断し、次のセッションで自動的に再開させることで、承認フローをバイパスする可能性がある。

### Affected Files

- `scripts/agent/startup.py:506-534` — 保留中の承認のリカバリ
- `scripts/agent/tool_approval.py:115-123` — 承認フローの実装

### Attack Scenario

1. 攻撃者が承認が必要な操作を開始し、承認前にセッションを中断する
2. 次のセッションで、保留中の承認が自動的に復元される
3. 承認が必要な状態が自動的に有効になり、承認フローがバイパスされる
4. 攻撃者の意図的な操作が承認なしで実行される

### Severity

Medium — 承認が必要な操作がセッション開始時に自動的に再開される可能性がある。承認フローの再評価が必要。

### Mitigation

- 保留中の承認の期限を設定し、一定時間経過後に無効化する
- セッション開始時に承認フローを再評価する
- 保留中の承認の存続期間を制限する
