## os.getpgid()失敗時、spawn済みMCPサブプロセスをterminateせず追跡から外すだけで孤立させる

### Summary

`HttpServerLifecycleManager.start()` は `subprocess.Popen()` 成功直後に `os.getpgid(proc.pid)` を呼ぶが、これが失敗した場合、既にOS上で起動してしまった子プロセスをterminateせず、`_http_procs`/`_http_pgids` 辞書から追跡を外すだけで処理を終える。ログメッセージは「cleaning up」と述べているが、実際にはプロセスの後始末は行われない。

### Problem

- `scripts/agent/http_lifecycle.py:242-255` (`HttpServerLifecycleManager.start()`):
  ```python
  try:
      self._http_pgids[server_key] = os.getpgid(proc.pid)
  except OSError:
      logger.warning(
          "Lifecycle: getpgid() failed for %r pid=%d; cleaning up",
          server_key, proc.pid,
      )
      stderr_fh.close()
      self._stderr_files.pop(server_key, None)
      self._stderr_log_paths.pop(server_key, None)
      self._http_procs.pop(server_key, None)
      self._http_pgids.pop(server_key, None)
      return
  ```
  `proc.terminate()` や `proc.kill()` の呼び出しが一切ない。
- `shutdown_all()`(`scripts/agent/http_lifecycle.py:345-398`)は `_http_procs` 辞書を根拠にクリーンアップ対象を列挙する(370行目 `keys = list(self._http_procs.keys())`)ため、この経路で辞書から除外されたプロセスは以降どこからも終了処理の対象にならない。

### Affected Files

- `scripts/agent/http_lifecycle.py` — `HttpServerLifecycleManager.start()`(242-255行目)

### Classification

**High** — `os.getpgid()` が `ESRCH` 以外の理由(権限問題など)で失敗し、かつプロセスが実際には生存し続けているケースで、孤立プロセスが確実に発生する。既存issue(`issues/20260727_02_issue.md`, `issues/20260727_06_issue.md`)とは異なる発生源だが、症状(孤立MCPサブプロセス)は同種。

### Evidence

- Explicit in code (High confidence) — terminate/kill呼び出しの不在は静的に確認済み。
- Needs confirmation — `getpgid()` がプロセス即時終了以外の理由で失敗する具体的なシナリオの有無。

### Recommended next action

- `except OSError` 節で `pop` する前に `proc.terminate()`(必要なら `proc.kill()`)を呼び、実際にプロセスが後始末されることを保証する。
- `getpgid()` に失敗するケースを注入するテストを追加し、修正後にプロセスが確実に終了することを確認する。
