# Clarify RAG configuration DTO ownership and source of truth

## Priority
Medium

## Type
Design cleanup / Maintainability

## Background
The codebase defines configuration DTOs such as MqeConfig, FusionConfig, RerankConfig, SearchConfig, IngesterConfig, and PipelineConfig.

However, runtime code appears to rely on ConfigLoader, TOML files, raw dictionaries, RagConfig, module_cfg, and service-specific configuration loading.

## Problem
It is unclear whether models_config.py DTOs are active runtime models, future placeholders, or deprecated artifacts.

This can confuse implementation work, validation, and documentation. It also makes it harder to determine which configuration file is authoritative for fields such as embedding_dims, top_k_search, use_rrf, and semantic cache settings.

## Fix Intent
The intent is to make configuration ownership explicit and reduce ambiguity.

## Implementation Tasks
- Search all usages of models_config.py DTOs.
- Decide whether these DTOs should be:
  - adopted as runtime configuration models
  - retained as future-facing DTOs
  - marked as deprecated
  - removed
- If adopted:
  - implement ConfigLoader-to-DTO conversion
  - add validation tests
- If deprecated or removed:
  - update imports and documentation
- Document the authoritative configuration source for:
  - ingestion
  - RAG pipeline
  - RAG MCP service
  - DB settings
  - embedding dimensions
- Remove stale references to obsolete configuration names such as common.toml::embedding_dims.

## Acceptance Criteria
- The authoritative RAG configuration source is documented.
- models_config.py DTO status is clear.
- Runtime behavior and documentation match.
- No stale configuration references remain in user-facing docs or critical docstrings.

## Tests
- Add configuration-loading tests if DTOs are adopted.
- Add regression tests for the embedding_dims source.
- Add validation tests for required RAG settings if DTOs become authoritative.

## Out of Scope
- Full configuration system redesign.
- Changing configuration file names unless separately approved.
