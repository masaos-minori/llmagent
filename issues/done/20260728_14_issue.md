# Add regression tests for high- and medium-priority RAG failure modes

## Priority
Medium

## Type
Test coverage / Regression prevention

## Background
Existing tests cover important FTS and ingestion areas, including:

- Japanese FTS query behavior
- FTS trigger synchronization
- normalized_content fallback
- metadata preservation
- force reinsert behavior
- MCP service helper behavior

## Problem
The current tests do not sufficiently cover the newly identified high-priority and medium-priority failure modes:

- FTS-only fallback when embedding fails
- doc_id=0 ETag update bug
- HTTP document re-ingestion when freshness changes
- MQE failure fallback
- Rerank failure fallback
- debug callback rrf_config mismatch
- failed embedding chunks being moved to registered/
- post-ingest consistency check after DB close
- remote_empty and HTTP selected_hits behavior

## Fix Intent
The intent is to prevent recurrence by adding focused, deterministic regression tests for each known risk.

## Implementation Tasks
- Add SearchStage FTS-only fallback tests.
- Add vector/FTS individual failure tests.
- Add DocumentManager ETag existing_doc_id tests.
- Add HTTP freshness re-ingestion tests.
- Add MQE failure fallback tests.
- Add Rerank failure fallback tests.
- Add rag_debug_pipeline rrf_config tests.
- Add failed embedding chunk retry tests.
- Add DB connection lifetime tests for post-ingest consistency checks.
- Add remote_empty behavior tests.
- Add HTTP selected_hits availability tests if structured remote responses are implemented.

## Acceptance Criteria
- Each high-priority issue has at least one failing-before/fixed-after test.
- Tests do not require external network access.
- Embedding and LLM calls are mocked.
- Tests are deterministic and suitable for CI.
- Existing FTS and ingestion tests continue to pass.

## Tests
This issue is itself a test-coverage task.

## Out of Scope
- Performance benchmarks.
- End-to-end tests requiring a real embedding or LLM server.
