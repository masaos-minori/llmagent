## Summary
Two RAG housekeeping items bundled into one cleanup PR: remove apparently-dead DTOs/config classes,
and finish the intended sharing of `chunk_utils`.

## Rationale (Why this matters — detailed)
- **Dead code (L-1):** `RegisteredDocument` and the `models_config.py` dataclasses (MqeConfig,
  FusionConfig, etc.) show no imports/instantiations outside their own definitions; configuration is
  handled via raw dict access. Dead code adds maintenance burden and confuses the intended
  data/config model (RAG-003, RAG-004).
- **Incomplete refactor (L-6):** `chunk_utils.py` is intended as a shared helper, but
  `ChunkJapaneseMixin` does not import it and keeps its own implementation. This duplicated
  accumulation logic risks divergence in chunking behavior between the shared helper and the Japanese
  mixin.
- Both are RAG-layer cleanups with no behavioral change, so grouping keeps them in a single low-risk
  review.

## Fix Intent (How — detailed)
- **L-1:** Confirm with the owner whether these classes are forward-looking placeholders; if not,
  remove them. Record the decision.
- **L-6:** Refactor `ChunkJapaneseMixin` to use `chunk_utils.py`, completing the intended sharing;
  preserve behavior via tests.
