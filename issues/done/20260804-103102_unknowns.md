## Description

`scripts/rag/models_audit.py` defines two frozen dataclasses, `AuditLogRecord` and
`ApprovalDecision`, that are not imported or referenced anywhere else in the repository
(verified: `grep -rn "from rag.models_audit\|rag\.models_audit\."` across `scripts/` and
`tests/` returns only the definition file itself; no string-literal reference to either
class name exists either, ruling out reflection/registry-based dynamic use).

Git history shows they were added in commit `5ac7b757` as part of a bulk "foundation DTOs"
buildout for `rag/models.py`, under a generic "Audit DTOs" section header, with no linked
design doc, plan, or ticket tying them to a specific planned RAG-side feature. The only
other 2 commits touching the file (`58e2ff32`, `b5d7dede`, and the later split commit
`f6a3d2db`) are pure formatting/refactor changes — no commit has ever added a consumer.

The actively-used, working approval/audit implementation lives entirely in
`scripts/agent/shared/models.py` (`ApprovalDecisionEvent`) and
`scripts/agent/tool_audit.py` / `scripts/agent/tool_approval.py`, which evolved
independently (commit `cb285a1a` replaced a deprecated `ApprovalDecision` TypedDict in
`agent/tool_approval.py` with `ApprovalDecisionEvent`, unrelated to the RAG-side classes).

This circumstantial evidence favors "dead code," but per the requirement's own
Implementation Intent, this is explicitly "a decision for a maintainer/code owner with
project context, not something derivable purely from static analysis." No such decision
can be made within this document-only planning phase.
