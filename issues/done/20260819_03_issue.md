# [High] Make fetched_at mandatory end to end and remove timestamp compatibility behavior

## Priority

High

## Summary

Propagate one canonical UTC `fetched_at` value from Crawler output through every chunk and storage API, then remove all missing-timestamp fallbacks and ETagManager null-fill compatibility behavior.

## Reason for Change

Crawler already records an acquisition timestamp, but the current DTO and ChunkSplitter output discard it. Ingester therefore receives chunks without `fetched_at`, may omit the column during document insertion, and may rely on the database current-time default. Existing Web documents also enter `ETagManager` with `new_fetched_at=None`, which selects a null-fill branch instead of the intended freshness comparison.

This means the stored timestamp can represent database insertion time rather than source acquisition time, and updated HTTP metadata may not replace existing non-null metadata. Invalid timestamps are also handled fail-open: parsing errors are treated as non-stale, allowing malformed values to proceed toward update SQL.

Because no legacy data exists, `fetched_at` must be mandatory at every layer. There must be one strict timestamp contract and one freshness-aware update path.

## Implementation Intent

Generate a canonical UTC timestamp once in Crawler and preserve that exact value through crawler DTOs, chunk metadata, chunk JSON, Ingester, DocumentManager, ETagManager, `DocumentStore`, and SQLite writes.

After propagation is complete, remove every code path that synthesizes, defaults, or tolerates a missing timestamp. ETag updates must fail closed on malformed input and must still update acquisition time when `etag` and `last_modified` are both `null`.

## Implementation Tasks

- [ ] Generate Crawler `fetched_at` in canonical UTC `Z` form.
- [ ] Generate local-file modification time in an explicit UTC form where applicable.
- [ ] Make `fetched_at: str` mandatory in `CrawlDocument` and `ChunkDocument`.
- [ ] Propagate the original crawler timestamp unchanged to every generated chunk.
- [ ] Make Ingester document metadata require `fetched_at: str`.
- [ ] Remove the Ingester INSERT branch that omits `fetched_at`.
- [ ] Make `DocumentManager.handle_existing_document()` require `fetched_at: str`.
- [ ] Make `DocumentManager._update_etag()` require `new_fetched_at: str`.
- [ ] Make `ETagManager.update()` require `new_fetched_at: str`.
- [ ] Add `fetched_at: str` to `DocumentStore.doc_upsert()`.
- [ ] Update `SQLiteDocumentStore.doc_upsert()` to use the supplied timestamp for INSERT and UPDATE.
- [ ] Remove SQLite-current-time replacement from `doc_upsert()`.
- [ ] Remove `_update_null_fill()` from `ETagManager`.
- [ ] Remove the `new_fetched_at is None` branch and null-fill SQL.
- [ ] Reject timezone-naive timestamps.
- [ ] Raise on malformed incoming timestamps.
- [ ] Treat malformed stored timestamps as database consistency errors.
- [ ] Remove fail-open parsing behavior.
- [ ] Replace `fetched_at = COALESCE(?, fetched_at)` with `fetched_at = ?`.
- [ ] Remove the early return that prevents timestamp updates when both HTTP metadata values are `null`.
- [ ] Update `fetched_at` when the incoming timestamp is newer, even if `etag` and `last_modified` are both `null`.
- [ ] Define and test equal-timestamp behavior.
- [ ] Update all callers, protocol implementations, mocks, fixtures, and tests.

## Canonical Timestamp Format

```text
YYYY-MM-DDTHH:MM:SSZ
```

Example:

```text
2026-08-19T03:39:00Z
```

## Constraints

- Do not derive `fetched_at` from database insertion time.
- Do not accept timezone-naive or missing timestamps.
- Do not silently repair malformed timestamps.
- Do not add a compatibility branch, migration, or warning period.
- Preserve stale-update prevention.

## Acceptance Criteria

- [ ] Crawler output always contains canonical UTC `fetched_at`.
- [ ] Every chunk from one crawler record contains the identical timestamp.
- [ ] Ingester, DocumentManager, ETagManager, and DocumentStore require a non-null timestamp.
- [ ] `documents.fetched_at` equals the source crawler timestamp after INSERT and UPDATE.
- [ ] `_update_null_fill()` no longer exists.
- [ ] No application path omits or synthesizes `fetched_at`.
- [ ] Older input does not overwrite newer metadata.
- [ ] Newer input updates `fetched_at` even without HTTP freshness headers.
- [ ] Malformed or timezone-naive timestamps cannot reach update SQL.
- [ ] All affected tests pass.
