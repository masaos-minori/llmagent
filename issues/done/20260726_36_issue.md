## bandit B608 false positiveにnosec注釈を追加 (TASK-H7 / SEC-1)

### Summary

banditがB608（SQLインジェクション疑い）8件を検出しているが、全件が動的WHERE句+プレースホルダのfalse positive。`# nosec` 未注釈のため機械的に検出され続けている。

### Problem

```bash
$ uv run bandit -r scripts/ -c pyproject.toml
8×B608(SQL injection疑い, medium)
```

### Affected Files

| # | 場所 | 実際の構造 |
|---|---|---|
| 1 | `scripts/eventbus/db.py:195` | `IN ({",".join("?" for _ in topics)})` + パラメータ化 |
| 2 | `scripts/eventbus/subscribe_route.py:47` | 同上パターン |
| 3 | `scripts/mcp_servers/mdq/db_grep.py:72` | WHERE句を固定カラム名の断片リストから組立、値は全てparamsでバインド |
| 4 | `scripts/mcp_servers/mdq/health_check.py:35` | STALE_SQL_CONDITION(固定文字列定数)を埋め込み |
| 5 | `scripts/mcp_servers/mdq/mdq_service.py:205` | 同上(where_clauses断片+params) |
| 6 | `scripts/mcp_servers/mdq/mdq_service.py:327` | STALE_SQL_CONDITION埋め込み |
| 7 | `scripts/mcp_servers/mdq/search.py:145` | _build_search_where()が返す固定断片+params |
| 8 | `scripts/mcp_servers/mdq/search.py:156` | 同上 |

### Severity

Medium — 全件ユーザー入力が直接SQL文字列へ混入する経路はなく、値は必ず`?`プレースホルダでバインドされている。ただし`# nosec`未注釈のため機械的にfailする

### Root Cause

nosec注釈漏れ。`scripts/db/maintenance.py:148`・`scripts/db/store_impl.py:258`(db層)には同一パターンに対し既に`# nosec B608`が付与済み

### Mitigation

2.1節の8箇所全てに、`scripts/db/maintenance.py:148`等の既存nosec注釈と同じ形式(理由コメント付き)で `# nosec B608 - ...` を追加

### Acceptance Criteria

- `uv run bandit -r scripts/ -c pyproject.toml` がexit 0(medium/high issue 0件)
- 注釈追加のみで実装ロジック変更なし、既存テスト全てpass
