# Preserve fetched_at metadata and enforce chunk-size invariants

## Priority
High

## Suggested Labels
priority-high, rag, chunking, metadata, validation

## Reason for Change
`fetched_at` exists in the raw input contract and is consumed by the ingester, but it is dropped when crawler JSON becomes `ChunkDocument` and is not written to chunk artifacts. This prevents the existing stale-update guard from receiving normal pipeline data. In addition, `max_chunk` is documented as a maximum but can be exceeded by one long sentence, a large code item, overlap, tail merging, or Markdown settings.

## Implementation Intent
Preserve freshness metadata end to end and make documented chunk-size constraints true for every supported input path.

## Affected Files
- `rag/models_data.py`
- `rag/ingestion/pipeline_utils.py`
- `rag/ingestion/chunk_splitter.py`
- `rag/ingestion/chunk_english.py`
- `rag/ingestion/chunk_japanese.py`
- `rag/ingestion/chunk_utils.py`
- related tests

## Implementation Scope
- [ ] Add `fetched_at: str | None = None` to `ChunkDocument`.
- [ ] Read `fetched_at` in `pipeline_utils.read_json_file()`.
- [ ] Add `fetched_at` to `ChunkMetadata`, `_extract_chunk_metadata()`, and every generated chunk payload.
- [ ] Verify that normal Crawler to ChunkSplitter output reaches RagIngester and `ETagManager` unchanged.
- [ ] Validate ChunkSplitter configuration during initialization: `min_chunk > 0`, `max_chunk >= min_chunk`, and `0 <= chunk_overlap < max_chunk`.
- [ ] Require `md_snippet_max_chars > 0` and ensure Markdown output still obeys the hard maximum.
- [ ] Hard-split an oversized English sentence when sentence boundaries are insufficient.
- [ ] Hard-split an oversized Japanese sentence while preserving original/normalized alignment.
- [ ] Split oversized code items when blank-line boundaries are insufficient.
- [ ] Include overlap within `max_chunk` instead of appending it beyond the limit.
- [ ] Do not merge a short tail into the previous chunk when the merged result would exceed `max_chunk`.
- [ ] Validate the final emitted-chunk invariant before writing files.

## Non-Goals
- Do not change embedding dimensions.
- Do not add a token-based chunking system in this issue.
- Do not add new language detection behavior.

## Acceptance Criteria
- [ ] Crawler-provided `fetched_at` is unchanged in each generated chunk and reaches document insertion or ETag handling.
- [ ] Missing legacy `fetched_at` values remain `None`.
- [ ] Every emitted chunk satisfies `0 < len(content) <= max_chunk`.
- [ ] Invalid numeric configuration fails during splitter initialization with an actionable message.
- [ ] No English, Japanese, Markdown, code, overlap, or tail path bypasses the hard maximum.

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
