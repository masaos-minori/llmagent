# Add FTS query edge-case tests and define safe tokenless-query behavior

## Priority

Medium

## Summary

Add regression tests for FTS query generation edge cases and define safe behavior for tokenless FTS queries.

## Background

_build_fts_query() converts user text into an FTS5 MATCH query.

When no usable tokens are found, it returns an empty quoted query string.

fts_search() then uses that value with MATCH ?.

## Problem

FTS5 query generation is sensitive to edge cases.

The following inputs can easily cause syntax issues or unstable behavior if not tested:

- empty string
- whitespace-only string
- symbol-only string
- input containing double quotes
- Japanese input with no retained content words
- very long token lists exceeding _MAX_FTS_TOKENS

The expected behavior for tokenless queries should be explicit.

## Fix Reason

FTS query generation is part of the retrieval core.

Unstable FTS edge cases can cause avoidable search failures and degrade RAG reliability.

## Implementation Intent

Make FTS query generation stable, predictable, and regression-tested.

## Required Changes

### 1. Add tests for _build_fts_query()

Cover:

- empty string
- whitespace-only string
- symbol-only string
- English input with valid tokens
- input containing double quotes
- input exceeding _MAX_FTS_TOKENS
- Japanese input with valid content words
- Japanese input where tokenization yields no retained tokens

### 2. Add tests for fts_search()

Verify tokenless queries do not crash.

Choose and document one expected behavior:

#### Option A

Execute a safe FTS query and return zero rows.

#### Option B

Skip FTS execution and return an empty list when no usable tokens exist.

Option B is preferred if MATCH behavior for empty quoted queries is considered risky.

### 3. Coordinate with SearchStage isolation

Even if FTS query generation fails, successful vector results must remain available.

This relies on the SearchStage retrieval isolation issue.

## Acceptance Criteria

- Empty query does not raise FTS syntax errors.
- Whitespace-only query does not raise FTS syntax errors.
- Symbol-only query does not raise FTS syntax errors.
- Quote-containing input is safely handled.
- _MAX_FTS_TOKENS behavior is tested.
- Japanese tokenless query behavior is tested.
- Expected tokenless-query behavior is documented in test names or comments.

## Files to Modify

- scripts/rag/repository.py
- tests/test_fts_fallback.py
- tests/test_rag_pipeline_stage.py

## Out of Scope

- Rewriting the full FTS tokenizer
- Changing Japanese POS filtering rules unless required by failing tests
