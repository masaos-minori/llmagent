# Prevent oversized chunks during text and code chunk merging

## Priority

Medium

## Summary

Add handling for oversized items in chunk merging so that generated chunks do not significantly exceed `max_chunk`.

## Background

`merge_text_items()` can leave a single item larger than `max_chunk` without splitting it. This can produce oversized chunks.

Although Qwen3 supports longer context, oversized chunks reduce retrieval precision and make ranking less stable.

## Fix Intent

Keep chunk sizes predictable and aligned with retrieval quality requirements.

This is not a Qwen3 compatibility issue by itself, but it improves retrieval quality after the embedding migration.

## Required Changes

- Define oversized item behavior.
- For text:
  - split by sentence boundary first
  - fall back to character-length splitting
- For code:
  - split by blank lines or structural boundaries first
  - fall back to character-length splitting
- Ensure `chunk_overlap` does not cause final chunks to exceed `max_chunk` unexpectedly.
- Preserve short-tail merge behavior where possible.

## Files to Update

- `scripts/rag/ingestion/chunk_utils.py`
- `scripts/rag/ingestion/chunk_splitter.py`
- `scripts/rag/ingestion/chunk_english.py`

## Acceptance Criteria

- Oversized text items are split.
- Oversized code items are split.
- Chunk overlap does not create unexpectedly oversized chunks.
- Existing normal-sized chunk behavior remains compatible.
