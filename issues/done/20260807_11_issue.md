# Replace numeric ingestion sentinels with explicit URL statuses

## Priority
Low

## Suggested Labels
priority-low, rag, ingestion, typing, error-handling

## Reason for Change
`IngestUrlResult` uses `n_failed = -1` to encode an unexpected URL-level failure. This mixes status with counts, makes totals less reliable, and forces callers to know a hidden sentinel convention.

## Implementation Intent
Represent status explicitly while keeping counts non-negative and meaningful.

## Affected Files
- `rag/ingestion/ingester.py`
- result models if extracted
- summary logging and tests

## Implementation Scope
- [ ] Add an explicit URL ingestion status enum or equivalent typed field.
- [ ] Represent success, skipped, validation failure, embedding failure, storage failure, and unexpected failure without negative counts.
- [ ] Keep success and failure counts non-negative.
- [ ] Update aggregate logging to report status separately from chunk counts.
- [ ] Update tests and any callers of `IngestUrlResult`.

## Non-Goals
- Do not duplicate the detailed per-failure model from the atomic-ingestion issue.
- Do not change retry policy in this issue.

## Acceptance Criteria
- [ ] No result uses `n_failed = -1`.
- [ ] Status and counts are independently readable.
- [ ] Aggregate logging remains accurate for mixed outcomes.

## Required Tests
- [ ] success
- [ ] skipped
- [ ] validation failure
- [ ] embedding failure
- [ ] storage failure
- [ ] unexpected exception
- [ ] mixed-run summary

## Common Constraints
- Preserve support for Japanese and English only.
- Embedding dimensions remain fixed in code at 1024 and are not configurable.
- Do not add runtime validation for exactly 1024 embedding elements or a 4096-byte BLOB.
- Do not add migration logic for legacy vector dimensions; recreate databases after canonical schema changes.
- Keep unrelated refactoring out of this issue.
- Update design documentation only when this issue changes the documented contract.
