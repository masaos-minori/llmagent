# Risk follow-up: check_issue_inventory_conformance.py's flat default doc_path breaks after the docsreorg05 governance-docs move

## Resolution
Resolved — absorbed inline into `plans/20260924-115855_plan.md` as `REQ-003`
(`GOVERNANCE_DOC_PATH` constant fix) and `REQ-004` (real-repo-path regression test),
rather than tracked as a separate, later follow-up. See that Plan's Design, Risks, and
Requirement Traceability sections.

## Priority
Medium

## Context
`plans/20260924-115855_plan.md` (implementing
`issues/20260923-140944_docsreorg05_move-governance-docs-into-new-governance-folder.md`,
`docsreorg05`) moves `docs/00_governance_03_issue-and-uncertainty-management.md` to
`docs/00_governance/00_governance_03_issue-and-uncertainty-management.md`. Three other
tools that read this file by a hardcoded path
(`tools/check_dependency_graph_cycles.py`, `tools/check_needs_confirmation_inventory.py`,
`tools/check_known_deviation_sync.py`) were already updated to expect the
`docs/00_governance/` location by `plans/done/20260923-152824_plan.md` (`docsreorg02`,
landed 2026-09-24). `tools/check_issue_inventory_conformance.py` was added on
2026-09-17 — before `docsreorg02`'s refactor — and was not included in that Plan's
9-tool update list, so it still defaults to the pre-move flat path. This was not fixed
inline by the `docsreorg05` Plan, because the file is outside that Issue's named Target
Files and its Constraints ("do not move any file outside this list" / no content
changes beyond what `docsreorg04` already covers).

## Risk
`tools/check_issue_inventory_conformance.py`'s `main()` defaults `doc_path` to
`Path(__file__).parent.parent / "docs" / GOVERNANCE_DOC_NAME` (a flat path) when no CLI
argument is given. `.github/workflows/governance-docs-consistency.yml`'s "Check issue
inventory conformance" step runs `python tools/check_issue_inventory_conformance.py`
with no argument. Once `docsreorg05` lands and the file no longer exists at the flat
path, this step will raise `FileNotFoundError` and fail the `Governance Docs
Consistency` CI workflow on every push/PR touching `docs/**/*.md`.

## Suggested resolution
Update `tools/check_issue_inventory_conformance.py`'s default `doc_path` to
`DOCS_DIR / "00_governance" / GOVERNANCE_DOC_NAME` (or equivalent), mirroring the
pattern already applied to `tools/check_dependency_graph_cycles.py`'s `GRAPH_DOC_PATH`,
`tools/check_needs_confirmation_inventory.py`'s `INVENTORY_DOC_PATH`, and
`tools/check_known_deviation_sync.py`'s `_GOVERNANCE_KNOWN_ISSUES_PATH`. Land this fix
before or together with `docsreorg05`'s merge to avoid a CI regression window; add
regression test coverage confirming the default resolves to the post-move path
(consistent with `docsreorg02`'s own `tests/tools/test_check_dependency_graph_cycles.py`
/ `tests/tools/test_check_needs_confirmation_inventory.py` real-repo-path test pattern).
