# [High] Replace permissive RAG payload handling with strict crawl and chunk contracts

## Priority

High

## Summary

Separate crawler and chunk payloads into strict schemas, remove all missing-field defaults and implicit type coercion, update the storage API to require current-format chunk metadata, and delete helpers made obsolete by strict parsing.

## Reason for Change

Crawler JSON and chunk JSON currently share `ChunkJsonRaw` even though they represent different pipeline stages and have different valid content rules. The shared permissive reader accepts only `url` and non-empty `content` as truly required, then fills or coerces the remaining values. This behavior allows malformed current-format artifacts to proceed as if they were valid legacy data.

Examples include defaulting a missing language to `"en"`, a missing chunk index to `0`, a missing chunk type or source file to an empty string, and coercing string indexes with `int()`. These fallbacks can misclassify Japanese content, create duplicate chunk indexes, defer errors until database constraint enforcement, or silently lose source traceability.

The same permissiveness exists in `ChunkDocument`, `DocumentStore.chunk_insert()`, and `SQLiteDocumentStore.chunk_insert()`, where mandatory current-format fields still have defaults. With no legacy data and no omission allowed, the JSON boundary, DTOs, Store Protocol, and Store implementation must express the same strict contract.

## Implementation Intent

Create two independent artifact contracts and reject any payload that does not exactly satisfy its current schema. Validation must occur before chunking, embedding, or database access. The implementation must distinguish a missing key from a present key whose value is legitimately `null`.

Crawler payloads must support code-only local Python files, so empty `content` is valid only when `code_blocks` contains at least one string. Chunk payload `content` must always be non-empty.

The keys `etag`, `last_modified`, and `normalized_content` are mandatory where defined, but their values may be `null`. No other mandatory field may be defaulted or coerced.

## Implementation Tasks

- [ ] Replace the crawler/chunk dual-purpose `ChunkJsonRaw` with separate strict payload types.
- [ ] Define `CrawlJsonPayload` and `ChunkJsonPayload`.
- [ ] Define separate `CrawlDocument` and `ChunkDocument` DTOs.
- [ ] Implement `read_crawl_json(path)` and `read_chunk_json(path)`.
- [ ] Remove production use of `read_json_file()` and `_read_chunk_json_raw()` where replaced by strict readers.
- [ ] Remove runtime assumptions based only on `typing.cast()`.
- [ ] Validate required keys, exact types, allowed values, and artifact metadata before downstream processing.
- [ ] Make Crawler always output `etag` and `last_modified` keys, using `null` when unavailable.
- [ ] Require `schema_version == "1"`, `artifact_type == "crawl"`, and `created_by == "crawler"` for crawler payloads.
- [ ] Require `schema_version == "1"`, `artifact_type == "chunk"`, and `created_by == "chunk_splitter"` for chunk payloads.
- [ ] Require crawler `lang` to be `"ja"` or `"en"`.
- [ ] Require crawler `code_blocks` to be `list[str]`.
- [ ] Accept crawler payloads only when `content` is non-empty or `code_blocks` contains at least one item.
- [ ] Require chunk `content` and `source_file` to be non-empty strings.
- [ ] Require chunk `chunk_type` to be `"text"` or `"code"`.
- [ ] Require `chunking_strategy` to be `"text"` or `"heading"`.
- [ ] Require `chunk_index` to be a non-negative JSON integer and explicitly reject `bool`.
- [ ] Remove fallbacks to `""`, `"en"`, `[]`, `0`, and `"text"` for mandatory fields.
- [ ] Remove `_get_str_with_default()`, `_get_int_with_default()`, and `_normalize_chunk_index()`.
- [ ] Remove the `strict=False` artifact-validation path.
- [ ] Move artifact validation into the strict readers and remove `_validate_artifact()` when no longer used.
- [ ] Remove defaults from mandatory DTO fields.
- [ ] Make `chunk_type` and `source_file` mandatory in `DocumentStore.chunk_insert()`.
- [ ] Remove matching defaults from `SQLiteDocumentStore.chunk_insert()`.
- [ ] Update all callers, mocks, fixtures, and tests.
- [ ] Remove `RegisteredDocument` only if repository-wide search confirms it has no current caller.

## Constraints

- Do not add legacy readers, conversion logic, aliases, or fallback values.
- Do not coerce malformed values into valid types.
- Do not use database constraints as the first validation layer.
- Preserve `null` as a valid value for `etag`, `last_modified`, and `normalized_content`.
- Apply one explicit unknown-field policy consistently to both payload types. Under the no-omission and no-legacy policy, rejecting unknown fields is preferred.

## Acceptance Criteria

- [ ] Crawler and chunk artifacts have separate types, DTOs, and readers.
- [ ] ChunkSplitter accepts only crawler artifacts.
- [ ] Ingester accepts only chunk artifacts.
- [ ] Missing mandatory keys are rejected.
- [ ] Invalid value types are rejected without coercion.
- [ ] `chunk_index="1"`, `chunk_index=true`, and negative indexes are rejected.
- [ ] No mandatory field is replaced with an empty string, zero, English, or text strategy.
- [ ] Python source crawler payloads with code-only content produce code chunks successfully.
- [ ] Store Protocol and SQLite implementation signatures match the strict contract.
- [ ] No obsolete parsing or compatibility helper remains in use.
- [ ] All affected tests pass.
