# Document and separate Workflow approval from Tool approval

## Priority

Medium-High

## Summary

Clarify the difference between workflow-level approval and tool-level approval. Make the workflow approval setting explicit in the default workflow configuration.

## Background

The system has two different approval concepts:

1. Workflow approval
   - Implemented by `WorkflowEngine`.
   - Controlled by `WorkflowDef.require_approval`.
   - Suspends execution between `execute` and `verify`.
   - Uses workflow storage and approval records.

2. Tool approval
   - Implemented in the tool execution path.
   - Applies before individual tool calls are executed.
   - Denied tool calls are returned to the LLM as tool messages.

The current default workflow configuration does not explicitly specify `require_approval`.

## Problem

Operators and implementers may confuse these two approval mechanisms.

Potential confusion:

- `/approve` and `/reject` may appear to apply to tool-level approval.
- Workflow approval records in workflow storage may be mistaken for tool denial records.
- Tool approval denial appears in conversation history, while workflow approval is stored in workflow state.
- The default workflow relies on implicit `require_approval = false`.

## Implementation Intent

Make the approval model explicit, understandable, and operationally safe.

## Required Changes

### 1. Explicitly configure workflow approval

Update the default workflow configuration to include:

    "require_approval": false

or, if workflow approval should be enabled:

    "require_approval": true

The intended default should be a conscious decision, not an implicit dataclass default.

### 2. Document Workflow approval

Document the following:

- Workflow approval occurs after execute and before verify.
- Workflow approval is task-level.
- Workflow approval uses workflow storage.
- `/approve` and `/reject` apply to workflow approval.
- Pending workflow approval blocks normal turn processing.

### 3. Document Tool approval

Document the following:

- Tool approval occurs before individual tool execution.
- Tool approval is per tool-call batch or per call, depending on current implementation.
- Tool denial is represented as a tool message in conversation history.
- Tool approval does not create workflow approval records unless explicitly designed to do so.

### 4. Clarify interaction between the two

Document that both approval systems can exist simultaneously but operate at different layers.

## Acceptance Criteria

- `default.json` explicitly includes `require_approval`.
- Documentation explains Workflow approval.
- Documentation explains Tool approval.
- Documentation clearly states that `/approve` and `/reject` are for Workflow approval.
- Documentation explains that tool denial is represented as a tool message.
- Documentation distinguishes workflow approval records from tool denial messages.
- There is no ambiguous use of the term "approval" without a qualifier.

## Files to Modify

- `config/workflows/default.json`
- `agent/workflow/workflow_engine.py`
- `agent/tool_runner.py`
- `agent/commands/cmd_workflow.py`
- Agent workflow documentation
- Agent tool execution documentation

## Test / Review Cases

- Verify default workflow loads with explicit `require_approval`.
- Verify `/approve` and `/reject` documentation points to workflow approval only.
- Verify tool approval denial still appears as tool message.
- Verify no documentation implies that tool approval writes workflow approval records.
