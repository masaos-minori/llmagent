## エージェント起動フェーズ: ワークフロー定義ファイルの存在チェック不足

### Summary

`orchestrator.py:135-140` で、`Exception` をキャッチしているため、予期しない例外もワークローダーの失敗として扱われる。また、`_WORKFLOWS_DIR` のパスが設定可能で、攻撃者が悪意のあるワークフローファイルを配置できる場合、ワークフローエンジンがそれをロードする。

### Problem

`orchestrator.py:135-140` で定義：

```python
try:
    self._workflow_def: WorkflowDef | None = WorkflowLoader().load()
except (WorkflowLoadError, Exception) as exc:
    raise RuntimeError(...)
```

`Exception` をキャッチしているため、予期しない例外もワークローダーの失敗として扱われる。また、`_WORKFLOWS_DIR` のパスが設定可能で、攻撃者が悪意のあるワークフローファイルを配置できる場合、ワークフローエンジンがそれをロードする。

### Affected Files

- `scripts/agent/orchestrator.py:135-140` — ワークフロー定義ファイルの読み込み
- `scripts/agent/orchestrator.py:115-120` — `_WORKFLOWS_DIR` の定義

### Attack Scenario

1. 攻撃者が `_WORKFLOWS_DIR` に悪意のあるワークフローファイルを配置する
2. ワークフローエンジンがそのファイルをロードする
3. ワークフロー内の不正なコードが実行される
4. システムが侵害される

### Severity

Low — ワークフローファイルは通常、管理者のみが配置できる。ただし、設定の検証が必要。

### Mitigation

- ワークフローファイルの整合性を検証する
- 許可されたワークフローのホワイトリストを導入する
- ワークフローファイルの読み込み前にセキュリティチェックを行う
