# [Medium] Enforce URL-group atomicity and strict RAG database constraints

## Priority

Medium

## Summary

Validate complete URL groups before mutation, stop swallowing database constraint errors, and remove database defaults that permit mandatory RAG fields to be omitted.

## Reason for Change

Ingester currently takes document metadata from the first chunk in a URL group and does not prove that the remaining chunks describe the same source version. A mixed group can therefore combine different timestamps, titles, languages, source files, or chunking strategies under one document.

`_insert_chunks_batch()` also catches `sqlite3.IntegrityError` and silently continues. This can convert duplicate indexes or other constraint violations into partial success, even though ingestion is intended to be atomic per URL.

The RAG DDL still provides defaults for mandatory fields such as `fetched_at`, `chunking_strategy`, `chunk_type`, and `source_file`. Once application APIs are strict, retaining these defaults would allow other write paths to bypass the contract and would continue hiding omissions at the database boundary.

## Implementation Intent

Treat each URL group as one immutable ingestion unit. Validate every file before embedding or database mutation, require document-level metadata to match across the group, and roll back the entire transaction on any validation or integrity failure.

Make the database schema reinforce the same no-omission contract as the JSON readers, DTOs, Store Protocol, and Ingester. Since no data migration is required, recreate `rag.sqlite` with the stricter DDL instead of writing a migration.

## Scope

- `scripts/rag/ingestion/ingester.py`
- `scripts/db/schema_sql.py`
- Schema and ingestion tests

## Implementation Tasks

- [ ] Validate every chunk in a URL group before embedding or database mutation.
- [ ] Require matching `url`, `title`, `lang`, `fetched_at`, `etag`, `last_modified`, `source_file`, and `chunking_strategy` across the group.
- [ ] Require matching `schema_version`, `artifact_type`, and `created_by` across the group.
- [ ] Detect duplicate `chunk_index` values before embedding.
- [ ] Decide whether indexes must be contiguous from zero and encode the decision in tests.
- [ ] Remove `sqlite3.IntegrityError` swallowing from `_insert_chunks_batch()`.
- [ ] Roll back the complete URL transaction on validation or constraint failure.
- [ ] Route every file in a failed URL group to `failed/` with useful error metadata.
- [ ] Ensure success counters exclude all rolled-back or failed rows.
- [ ] Remove the default from `documents.fetched_at`.
- [ ] Remove the default from `documents.chunking_strategy`.
- [ ] Remove the default from `chunks.chunk_type`.
- [ ] Remove the default from `chunks.source_file`.
- [ ] Keep all four columns `NOT NULL`.
- [ ] Keep `etag`, `last_modified`, and `normalized_content` nullable.
- [ ] Update schema tests to confirm omitted mandatory columns fail.
- [ ] Verify every application INSERT path supplies all mandatory columns.
- [ ] Recreate `rag.sqlite` from the strict DDL without a migration.

## Target DDL Direction

```sql
fetched_at         TEXT NOT NULL,
chunking_strategy  TEXT NOT NULL,
chunk_type         TEXT NOT NULL,
source_file        TEXT NOT NULL
```

## Constraints

- Do not partially commit a URL group.
- Do not treat constraint failures as successful inserts.
- Do not create an incremental migration for `rag.sqlite`.
- Do not retain database defaults as compatibility or safety fallbacks.
- Do not change nullable behavior for `etag`, `last_modified`, or `normalized_content`.

## Acceptance Criteria

- [ ] Inconsistent group metadata causes the complete URL group to fail.
- [ ] Duplicate chunk indexes are detected before database insertion.
- [ ] Any database integrity error rolls back the entire URL transaction.
- [ ] Failed files are routed consistently and include useful error details.
- [ ] Omitting any mandatory RAG column causes INSERT to fail.
- [ ] Ingester and `SQLiteDocumentStore` supply all mandatory values explicitly.
- [ ] A newly created RAG database passes schema and ingestion tests.
- [ ] Full RAG ingestion succeeds without hidden partial inserts.

## Validation

```bash
rg -n "except sqlite3\.IntegrityError|DEFAULT.*(fetched_at|chunking_strategy|chunk_type|source_file)" scripts tests
pytest -q tests/test_create_schema.py tests/test_db_maintenance.py
pytest -q tests
```
