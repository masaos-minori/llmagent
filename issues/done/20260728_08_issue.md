# Add explicit pipeline fallbacks for MQE and rerank failures

## Priority
High

## Type
Bug fix / Pipeline resilience

## Background
The RAG pipeline runs stages in sequence: MQE, Search, Fusion, Rerank, and Augment. The shared PipelineContext initializes queries, search_results, merged, and reranked as empty lists.

MqeStage returns the original query only when MQE is disabled. If the MQE LLM call fails, the outer pipeline records the stage failure but does not populate ctx.queries.

RerankStage falls back to RRF order only when use_rerank=False. If reranking is enabled and the rerank LLM call fails, the outer pipeline records the failure but does not populate ctx.reranked.

## Problem
If MQE fails, SearchStage may receive no queries and return no results.

If reranking fails, the pipeline may produce no final RAG context even when search and RRF fusion succeeded.

Both cases unnecessarily reduce availability.

## Fix Intent
The intent is to make the pipeline resilient to LLM-side failures:

- MQE failure should fall back to the original query.
- Rerank failure should fall back to RRF-ranked results.
- Fallbacks should be explicit, observable, and tested.
- Empty results should not be confused with internal failures.

## Implementation Tasks
- Add MQE failure fallback:
  - When expand_queries() fails, set ctx.queries = [ctx.query].
  - Record a fallback reason such as mqe_exception.
- Add rerank failure fallback:
  - When cross_encoder_rerank() fails, use ctx.merged.
  - Apply deduplicate_chunks() and rag_top_k.
  - Record a fallback reason such as rerank_exception.
- Decide whether these stage outcomes should be recorded as fallback or failure-with-fallback.
- Update diagnostics to distinguish:
  - use_mqe=False
  - mqe_failed_fallback
  - use_rerank=False
  - rerank_failed_fallback
- Ensure AugmentStage receives usable reranked hits when search and fusion succeed.

## Acceptance Criteria
- MQE failure does not prevent retrieval.
- Rerank failure does not discard RRF results.
- RAG context can still be produced when Search and Fusion succeed.
- StageResult records clear fallback reasons.
- Diagnostics distinguish disabled features from failed fallback features.

## Tests
- Add a test where llm.expand_queries() raises and the original query is used.
- Add a test where MQE failure still allows SearchStage to run.
- Add a test where cross_encoder_rerank() raises and ctx.merged is used.
- Add a test that deduplicate_chunks() is applied during rerank failure fallback.
- Add diagnostics assertions for MQE and rerank fallback reasons.

## Out of Scope
- Changing MQE prompt design.
- Changing rerank prompt design.
- Changing RRF scoring.
