## firejailバイナリ不在時のセキュリティチェックがproduction/local問わず常に起動を止める非対称性

### Summary

`audit_security_defaults()` 内のセキュリティチェックは概ね「production modeのみ致命的、local modeは警告のみ」という一貫した設計だが、`shell_sandbox_backend == "firejail"` かつ `firejail` バイナリがPATH上に見つからない場合だけは、環境を問わず常に `RuntimeError` を送出して起動を止める。他のチェックとの非対称性の意図が確認できない。

### Problem

- `scripts/agent/repl_health.py` の `audit_security_defaults()` 内、他のセキュリティ違反(auth_token欠如、command_allowlist空など)は以下のように `production_mode` の場合のみ致命的にしている:
  ```python
  if production_mode and violations:
      raise RuntimeError(...)
  ```
- しかし516-521行目の firejail バイナリチェックのみ、この分岐がなく常に例外を送出する:
  ```python
  if shell_cfg.sandbox_backend == "firejail" and not _shutil.which("firejail"):
      msg = (
          "shell_sandbox_backend=firejail but firejail binary not found in PATH. "
          "Install firejail or change shell_sandbox_backend in shell_mcp_server.toml."
      )
      raise RuntimeError(msg)
  ```
- ローカル開発環境で `shell_mcp_server.toml` に `sandbox_backend = "firejail"` を指定しているが `firejail` が未インストールの場合、この1点だけが理由でエージェント起動自体が必ず失敗する。

### Affected Files

- `scripts/agent/repl_health.py` — `audit_security_defaults()`(488-521行目付近)

### Classification

**Low / Needs confirmation** — サンドバックが実際に機能しない状態でshellツールを許可することは本質的に危険なため、意図的な設計である可能性が高い。ただし非対称性の理由がコード上に明記されていない。

### Evidence

- Strongly implied by code (Medium confidence) — 動作自体は確認済みだが、意図の有無は未確認。

### Recommended next action

- 意図的な設計であれば、なぜ他のチェックと異なり環境を問わず致命的にしているかを示す1行コメントを追加する。
- 意図的でない場合は、他のチェックと同様に `production_mode` 分岐を追加するか、少なくとも local mode では警告に留める方針を検討する。
