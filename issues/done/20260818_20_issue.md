### ISSUE-L3: RAG / DB スキーマの旧互換経路の整理 `[設計書のみ]

優先度: Low
対象ファイル: `scripts/rag/ingestion/{ingester,document_manager,chunk_splitter,crawler}.py`, `scripts/rag/pipeline.py`, RAG スキーマ DDL, `StateStore`, `SQLiteHelper`, `db/` 配下, eventbus 設定ローダ (いずれも要提供)
集約理由: いずれも DB / スキーマ層の「旧データ・旧スキーマとの互換挙動」であり、スキーマ変更と再インデックス / 再作成の判断を横断的に行う必要があるため 1 issue に集約する。

#### 修正理由
DB / スキーマ層に、旧形式データや旧スキーマを許容するための互換挙動が複数残っている。

- `COALESCE(normalized_content, content)` / `COALESCE(etag, ?)`: 旧チャンク形式や非日本語チャンク (normalized_content が null) を許容するためのフォールバック null 埋めである。
- `mdq.sqlite` の旧スキーマ検出 → DROP → 再作成: 起動時に legacy スキーマを自動検出して作り直す。データ損失リスクを伴う。
- `poll_interval_ms` / `offset_checkpoint_interval` (eventbus): 旧 config が残っていると起動失敗させる後方互換ガードである。
- `workflow.sqlite` のみ増分マイグレーション機構を持ち、他 DB は再作成という非対称がある。

#### 修正意図
旧データ・旧スキーマ互換の前提を棚卸しし、再インデックス / 再作成を前提に縮小できる互換経路を減らす。DB ごとにばらついたマイグレーション方針を整理し、データ損失リスクのある自動 DROP の扱いを明確化することが狙いである。

#### 作業内容
1. `COALESCE` 互換 null 埋めを、再インデックス前提で縮小可能か評価する。
2. `mdq.sqlite` の自動 DROP → 再作成の是非を判断し、必要なら明示的なマイグレーション手順へ置き換える。
3. eventbus の旧 config 起動失敗ガードの存続要否を判断する。
4. DB 間で非対称なマイグレーション方針を整理し、方針を文書化する。

#### 受け入れ条件
- 各互換経路について、維持 / 縮小 / 撤去の判断が下されコードへ反映されている。
- データ損失リスクのある経路に明示的な扱い (手順化または撤去) が定義されている。
- 既存テストが通る。

#### 依存関係
- RAG / DB / eventbus の実装ファイルおよびスキーマ DDL が未提供のため、提供後に確定する。
